### 근본 원인 (2026-08-31 코드 실측)

`StatsController.report()` 가 **placeholder** 다. 집계를 전혀 조회하지 않고 고정 문자열 하나를 돌려준다.

```java

String filename = "stats_report_" + period + ".csv";
String body = "﻿month,labeled,reviewed,approvalRate\n";   // BOM + 헤더 1행. 데이터 행 없음
```

- `StatsService` · `StatsQueryRepository` 호출이 **0건**이다.
- `period`(WEEK|MONTH|QUARTER|YEAR)는 `@Pattern` allowlist 로 검증(CWE-117 방어)만 되고 **파일명에만** 쓰인다. 집계 기간에는 반영되지 않는다.
- 프론트는 정상이다 — `downloadReport`(`features/stat/api.ts`)의 blob 수신과 `handleDownload`(`pages/OverallStatPage.tsx`)의 저장 로직에 결함이 없다. **받은 파일에 내용이 없을 뿐**이다.

즉 사용자가 본 "빈 파일"은 화면·네트워크 결함이 아니라 **서버가 애초에 데이터를 만들지 않는 상태**다.

## §2 변경 요지

1. **형식은 CSV 를 그대로 유지한다.** `text/csv; charset=UTF-8` · UTF-8 BOM 선행 · `.csv` 확장자 — **응답 계약 무변경**.
2. **내용을 화면(SCREEN-021)이 보여주는 5축 전부로 채운다.** 하나의 CSV 안에 **섹션 블록**으로 나열한다(누적 · 처리현황 · 일별작업량 · 이벤트분포 · 작업자별). "화면엔 있는데 파일엔 없다"가 구조적으로 생기지 않게 한다.
3. **집계 조달처는 기존 `StatsService.getOverallSummary()` 하나**다. 리포트용 집계를 새로 유도하지 않는다(두 번째 진실원 금지 — 이 저장소의 반복 결함 패턴).
4. **`period` 가 실제 의미를 갖는다** — `[일별 작업량]` 블록의 창에만 반영(WEEK=7 / MONTH=30 / QUARTER=90 / YEAR=365). FE 는 `MONTH` 고정 전송이라 MONTH=30일이 곧 화면과 동일하다.
5. 프론트는 **안내 문구 1줄**만 손본다(담기는 내용이 최근 1개월치만이 아니게 되므로). 버튼·동선·권한·확장자 전부 그대로.

### 사용자가 명시적으로 기각한 안 (되살리지 말 것)

- **Excel `.xlsx` + 네이티브 차트 (2026-08-31 검토 후 철회)** — 사용자가 "표나 그래프도 넣으면 좋겠다"고 해 한 번 확정했다가, 비용을 확인하고 **CSV 로 되돌렸다**. 철회 사유: `poi-ooxml` 의존성 추가 → `dependencyLocking` 때문에 `gradle.lockfile` 재생성 필수 + **온프렘 반입 매체 파급**(라이선스 인벤토리·용량) + 응답 형식 파괴적 변경. **차트는 포기한 것이 아니라 값을 못 치른 것**이며, 되살리려면 그 비용을 다시 승인받아야 한다.
- **HTML 단일 파일(.html)** — 숫자 재가공·피벗 불가. 발주처 제출물로 부적합.
- **xlsx + CSV 병행** — 구현·테스트·설계 ITEM 두 배 + 화면 버튼 둘로 동선 복잡.
- **기존 헤더 축(`month,labeled,reviewed,approvalRate`) 유지 + 월별 행만 채우기** — 화면이 월별 축을 보여주지 않아 리포트와 화면이 서로 다른 것을 말하게 되고, 월별 GROUP BY 집계를 새로 써야 해 기존 집계 재사용이 불가능하다.
- **작업자별 표만 내보내기** — "전체 구축 현황 리포트"라는 이름에 미달.

- **변경**

  **(1) 응답 계약 — 무변경**
  - `produces = "text/csv; charset=UTF-8"` · `Content-Disposition: attachment; filename="stats_report_{period}.csv"` · **UTF-8 BOM 선행** 전부 그대로 둔다.

  **(2) 본문 구조 — 섹션 블록 5개 (확정 사양)**

  ```
  전체 구축 현황,{생성 기준 일시}

  [누적 학습데이터]
  구분,검수완료,전체
  이미지(장),{approvedImageCount},{cumulativeImageCount}
  영상(건),{approvedVideoCount},{cumulativeVideoCount}

  [처리현황]
  구분,건수
  완료,{approved}
  처리중,{inProgress + reviewPending}
  대기,{pending}
  실패,{rejected}

  [일별 작업량]
  일자,검수완료건수
  {yyyy-MM-dd},{count}        ← period 창 길이만큼(기본 30행)

  [이벤트 유형 분포]
  유형,검수완료,전체
  {label},{approved count},{전체 count}

  [작업자별 현황]
  작업자,라벨,진행,검수,오토라벨(%),반려율(%)
  {name},{labeled},{inProgress},{reviewed},{autoLabelRate},{100 - approvalRate}
  ```

  - 블록 사이는 **빈 줄 1개**로 구분한다. 블록 제목 행은 `[이름]` 한 칸.
  - 첫 행에 **생성 기준 일시**를 넣는다.

  **(3) 각 블록의 값 조달 — `OverallStatSummaryResponse` 필드에서만 가져온다**

  - **[누적]**: 이미지 = `approvedImageCount`(검수완료) / `cumulativeImageCount`(전체), 영상 = `approvedVideoCount` / `cumulativeVideoCount`
  - **[처리현황] — 화면과 동일한 4구간 접기**
    - 완료 = `processing.approved()`
    - 처리중 = `processing.inProgress() + processing.reviewPending()`
    - 대기 = `processing.pending()`
    - 실패 = `processing.rejected()`
    - 근거: `docs/v2-wiki/17-statistics.md` SCREEN-021 ③ ("구 5카드 폐기 → 4구간"). **5값을 그대로 5행으로 펴지 말 것** — 화면과 다른 것을 말하게 된다.
  - **[일별 작업량]**: `dailyCounts` — `{date: "yyyy-MM-dd", count}` 오름차순. **0-fill 된 전량을 그대로** 쓴다(작업 없던 날도 `0` 행 유지 — 연속성이 이 블록의 의미다).
  - **[이벤트 유형 분포]**: `approvedEventDistribution`(검수완료) / `eventDistribution`(전체). 두 목록은 **카테고리 구성·순서가 동일**하고 데이터 없는 카테고리도 `count=0` 으로 포함된다 — **`eventTypeCd` 로 매칭**해 한 행에 나란히 놓는다(**인덱스 위치로 맞추지 말 것**). 표시 이름은 `label`.
  - **[작업자별 현황]**: `workers` 를 **6컬럼**으로 — 작업자(`name`) / 라벨(`labeled`) / 진행(`inProgress`) / 검수(`reviewed`) / 오토라벨(`autoLabelRate`) / 반려율(`100 - approvalRate`).
    - 컬럼 이름·순서·파생 규칙은 화면 `frontend/src/features/stat/components/WorkerStatsTable.tsx`(`NUMERIC_COLUMNS` + 반려율 `<th>`)와 **일치**시킨다. 그 파일의 헤더 라벨은 `작업자 / 라벨 / 진행 / 검수 / 오토라벨 / 반려율` 이다.
    - ⚠ **단위**: 이 화면 축의 `approvalRate`·`autoLabelRate` 는 **이미 백분율(0~100)** 이다(작업자 통계 SCR-STAT-001 의 0~1 과 **의도된 비대칭**). **다시 100 을 곱하지 말 것.** 소수 1자리로 포맷한다.
    - ⚠ `workers` 가 **빈 배열인 것은 자리표시가 아니라 LABELER 배정 행이 0건**이라는 뜻이다(`OverallStatSummaryResponse` javadoc 명시). 헤더 행만 남기거나 화면과 같은 안내 문구("작업자 통계가 없습니다") 한 줄을 넣고, **예외를 던지지 말 것.**

  **(4) `period` 반영 — 리포지토리 변경 불필요**
  - `StatsQueryRepository.findDailyCompletionAll(LocalDateTime since)` 가 **이미 `since` 를 파라미터로 받는다.** 창을 바꾸는 데 쿼리 수정이 필요 없다.
  - `StatsService.buildOverallDailyCounts()` 는 현재 상수 `DAILY_WINDOW_DAYS = 30` 을 직접 쓴다(`StatsService.java:67, 398~409`). **창 일수를 인자로 받는 오버로드**를 만들고, 기존 무인자 호출(=화면 경로)은 **30 을 그대로 넘겨 동작이 1비트도 바뀌지 않게** 한다.

  - ⚠ 0-fill 스켈레톤·윈도우 밖 키 무시 로직은 **그대로 재사용**한다(길이 = 창 일수 보장).

- **주의**
  - ★ **CSV 수식 인젝션 방어 (CWE-1236) — 이번 변경으로 새로 생기는 위험이다.** 지금까지는 본문이 고정 헤더뿐이라 해당이 없었으나, 이제 **DB 에서 온 사람이 쓴 문자열**(작업자 `name`, 이벤트 `label`)이 셀에 들어간다. 값이 `=` · `+` · `-` · `@` · 탭 · 캐리지리턴으로 시작하면 Excel 이 **수식으로 해석·실행**한다. 셀 값을 쓰기 전에 그 선행 문자를 무해화한다(예: 작은따옴표 prefix 또는 해당 문자 제거). **숫자 컬럼은 대상이 아니다**(무해화하면 재가공이 깨진다) — 문자열 컬럼에만 적용한다.
  - ★ **RFC 4180 이스케이프** — 값에 `,` · `"` · 개행이 들어가면 큰따옴표로 감싸고 내부 `"` 는 `""` 로 이중화한다. 이벤트 표시명은 운영자가 관리 화면에서 바꿀 수 있어 쉼표가 들어올 수 있다. **문자열 연결로 대충 만들지 말 것.**
  - **보안 — 파일명에 사용자 입력 미반영**(CWE-117). `period` 는 `@Pattern` allowlist 통과값만 헤더에 넣는다. 본문 어디에도 요청 파라미터를 그대로 echo 하지 않는다.
  - **PII 금지** — 리포트에 토큰·내부 절대경로·개인식별정보를 넣지 않는다. 작업자는 표시명(`name`)까지만(화면과 동일 노출 수준).
  - **메모리(CWE-770)** — 본문 전체를 `String` 하나로 이어붙이지 말고 `StringBuilder`/스트리밍으로 조립한다. `dailyCounts` 는 YEAR=365 까지, `workers`·`eventDistribution` 은 소규모지만 상한 없이 커질 수 있는 축이다. 현 규모(영상 5,000건 목표)에서 실질 위험은 낮으나 **응답을 통째 `String` 으로 들고 있던 기존 형태를 그대로 확대하지 말 것.**
  - **숫자 포맷** — 건수는 정수, 비율(%)은 소수 1자리. 로케일 의존 포맷(천 단위 구분자)을 넣지 않는다 — Excel 재가공 시 텍스트로 떨어진다.
  - `@design API-058` 추적 태그를 리포트 조립 seam 에 심는다.

- **수용기준**
  1. `GET /v1/stats/report?period=MONTH` 응답이 `text/csv; charset=UTF-8` + BOM 선행이고, 블록 5개(`[누적 학습데이터]`·`[처리현황]`·`[일별 작업량]`·`[이벤트 유형 분포]`·`[작업자별 현황]`)를 모두 포함한다.
  2. 누적·처리현황 수치가 같은 시점 `GET /v1/stats/overall` 응답과 **일치**한다(처리현황은 4구간 접기 규칙 적용 후).
  3. `[일별 작업량]` 데이터 행 수가 `period` 에 따라 7/30/90/365 이고, 작업 없는 날도 `0` 행으로 존재한다.
  4. `[이벤트 유형 분포]` 행이 `eventTypeCd` 기준으로 검수완료·전체가 짝지어지고, `count=0` 카테고리도 포함된다.
  5. `[작업자별 현황]` 이 6컬럼이고 비율 값이 0~100 범위(이중 곱하기 없음), `workers` 가 빈 배열이어도 **200 + 헤더 행**을 반환한다(예외 없음).
  6. 작업자명·이벤트명이 `=`/`+`/`-`/`@` 로 시작해도 수식으로 해석되지 않게 무해화되고, `,`·`"`·개행이 든 값이 RFC 4180 로 이스케이프된다.
  7. `period` allowlist 위반은 종전대로 **400 `INVALID_INPUT`**, 비REVIEWER 는 **403**.
  8. `getWorkerSummary()`·`getOverallSummary()` 기존 응답이 **무변경**임을 회귀 테스트로 고정한다.

## §4 영향·리스크

- **하위호환**: **응답 계약 무변경**(Content-Type · 확장자 · BOM · 파일명 규칙 · 상태코드 전부 동일). 바뀌는 것은 **본문 내용**뿐이다.
  - 기존 본문을 `month,labeled,reviewed,approvalRate` 헤더로 파싱하던 소비자가 있다면 깨진다. 실측상 호출부는 **저작도구 프론트 하나**이고 그 프론트는 파싱하지 않고 파일로 저장만 한다.
  - 관제 연동 규격서(`docs/관제-저작도구-데이터연동-규격서-20260805.md`)의 조회 채널은 `V_COMPLETED_VIDEO` **뷰 하나**이고 **이 엔드포인트는 규격에 없다** → 관제 계약면 영향 **없음**.
- **되돌리기**: 커밋 revert 로 원복. 스키마·마이그레이션·의존성 변경이 **없어** 데이터·빌드 롤백 불필요.
- **리스크**
  1. **CSV 수식 인젝션** — 이번 변경으로 새로 열리는 표면이다. §3 「주의」의 무해화가 빠지면 실제 취약점이 된다. **수용기준 6 이 이걸 잡는다.**
  2. **화면↔파일 드리프트** — 앞으로 화면 축이 늘면 리포트도 함께 늘려야 한다. `getOverallSummary()` 단일 조달로 묶어 표면을 최소화한다.
  3. **차트 없음(인지·수용)** — 사용자가 요청했던 그래프는 비용 때문에 이번에 넣지 않는다. 표(행·열)는 Excel 로 열면 정렬·필터가 되고, 필요하면 사용자가 직접 차트를 만들 수 있다.
