# CO-20260903 — 포털 이미지 축 잔재 정리 (단계 ⑥)

- 상태: 착수
- 근거 결정: `ADR-013` v10 · 2026-09-02 사용자 확정(구속) — *"이미지 축은 화면·사양에서 전부 제거한다"*
- 범위: 프론트 (백엔드 축은 후속)

## 1. 왜

포털 업로드는 **신규 접수를 영상만 받는다.** 이미지 업로드는 **폐기**됐고, 사용자가 **세 차례**
지적했는데도 화면에 계속 남아 있었다(시안에 예시 행으로 나타나 검토자에게 「이미지 업로드가 있다」로
읽혔다).

시안·사양 층은 정리했다. **코드에 남은 잔재**가 이번 범위다.

## 2. 무엇을 지우고 무엇을 남기나

**지운다** — 화면·문구·사양에 드러나는 이미지 **접수/자산 축** 전부.
직전 작업이 실측으로 하나 짚었다: 업로드 갈래 헤더의 **`'이미지 1장'`** 문구. 영상 전용이 된 뒤에는
「프레임 1건짜리 영상」에 그 문구가 붙어 **사실과 어긋난다.**

**남긴다** — **자산 종류 코드 값역의 이미지 값**과 **그 직접 투영인 API 응답 enum** 둘뿐이다
(이미 적재된 행의 판독용 — 지우면 계약이 데이터를 표현하지 못한다).

## 3. ★★가장 조심할 것 — 낱말로 훑지 마라

**「프레임 이미지」는 영상에서 뽑은 프레임이라 이 축과 무관하다.** 낱말로 훑어 함께 지우면
**라벨링 캔버스가 깨진다.**

⚠ 전수 조사에서 **26개 항목이 그 오탐으로 걸린 전례**가 있다. 그러니:

- 지우기 전에 **그 자리가 「사용자가 올리는 이미지 자산」인지 「영상에서 뽑은 프레임」인지** 판정하라.
- 판정이 애매하면 **지우지 말고 보고**하라. 남기는 실수는 되돌리기 쉽고 지우는 실수는 아니다.
- **무엇을 지웠고 무엇을 오탐으로 남겼는지 표로 보고**하라.

## 4. 하지 말 것

- **자산 종류 값역·응답 enum 을 건드리지 마라**(§2).
- **결정 기록·변경 이력을 소급 삭제하지 마라.**
- **백엔드를 건드리지 마라** — 다른 에이전트가 작업 중이고, 백엔드 이미지 축은 후속이다.
- 관제 채널을 건드리지 마라.

## 5. 수용 기준

1. 포털 화면에 이미지 **접수·자산** 축이 드러나지 않는다(업로드 자리·문구·안내·예시).
2. **프레임 이미지 축은 온전하다** — 라벨링·캔버스·프레임 목록 무변경.
3. 오탐 판정을 표로 증명한다.
4. 관제 채널 무변경 — 산출물 동치(**기준선은 코드 쓰기 전에** 뜬다).
5. 프론트 전건 통과 · lint 0 errors · 빌드 성공.
