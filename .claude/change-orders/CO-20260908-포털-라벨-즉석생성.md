## §1 배경

### 사용자 확정 (2026-09-08)

> *"포털에 구지 라벨 마스터가 필요할까? 그냥 그때그때 쓰면 되지 않을까 싶어서.
> 다만 라벨 화면에서 필요한 라벨은 그때그때 만들 수 있어야 할거 같아. 포털은"*
> *"대신 불러올때는 기존 라벨정보들을 다 보여주고" — "작업의 라벨정보들"*

⇒ **포털에 라벨 마스터(관리 표·관리 화면)를 만들지 않는다.** 라벨링 화면에서 **그때그때 만들고**, 작업을 열면 **그 작업의 기존 라벨을 다 보여준다.**

### 지금 무엇이 있고 무엇이 없나 (실측)

| 축 | 현재 |
|---|---|
| 업로드 축 저장 | ✅ **이미 자유 입력** — 라벨 **이름만** 저장하고 `labelId` 는 서버가 **의도적으로 `null` 로 비운다** |
| 라벨명 비어 있어도 되나 | ✅ 된다(`V29` 가 원장 제약을 풀었다) |
| 라벨 마스터(`LS_LABEL`) | 전역 공용 표 하나. **소유자·채널 축 없음** |
| 포털 사용자가 마스터에 라벨 **만들기** | ❌ **불가** — 쓰기(POST/PUT/DELETE)는 검수자 전용 |
| **라벨링 화면에서 라벨 만들기** | ❌ **수단 없음** ← **이것이 이 CO 가 채우는 자리** |

서버 코드가 이 설계를 이미 명시한다(`PortalUploadLabelService`):

> *"라벨 마스터 연결(`labelId`)은 **비운다** — 포털 라벨링은 마스터를 참조하지 않는 **자유 입력**이고,
> 이름으로 마스터를 역추정하면 동명·비활성 마스터에 잘못 붙는다.
> 라벨명도 비어 있을 수 있다(V29 가 원장 제약을 푼 이유) — 기본값을 지어 채우지 않는다."*

**즉 서버는 이미 사용자가 원하는 형태다.** 못 하는 것은 화면이다 — `LabelPickerModal` 의 입력칸은 **마스터를 거르는 검색 필터**이지 라벨을 만드는 자리가 아니다.

### ★폐기한 접근 — 되살리지 말 것

**`CO-20260908-업로드라벨-마스터연결-단절` 은 폐기한다.** 그 CO 는 *"창구에 `labelId`·`trackId` 가 없는 것은 결함이고, 사양이 옳고 창구가 못 따라갔다"* 고 단정했는데 **틀렸다.**

- 그 판단의 근거였던 `SCREEN-029` 문장(*"마스터 참조와 트랙 식별자를 … 저장 요청에 되돌려 보낸다"*)은 **데이터마트 원본에서 불러온 라벨**을 가리킨다. 그 자산은 관제 파이프라인에서 왔으므로 연결이 이미 있고, 화면이 그것을 **버리지 않고 보존**하라는 뜻이다.
- **업로드 자산의 라벨은 사용자가 처음부터 그리는 것이라 보존할 연결이 애초에 없다.** 두 축이 다른 것이지 한쪽이 못 따라간 것이 아니다.
- 그 CO 대로 `labelId` 를 왕복시키면 **포털 사용자가 전역 관제 마스터에 묶인다.** 본인 영상에 맞는 라벨이 거기 없으면 여전히 고를 게 없고, 만들 수도 없다(검수자 전용). **문제를 안 푼다.**

⚠ **「`labelId` 를 왕복시켜 색·속성을 살리자」는 안을 다시 꺼내지 말 것.** 위 근거가 그것이 왜 답이 아닌지를 말한다.

## §2 변경 요지

1. **포털에 라벨 마스터를 만들지 않는다** — 새 표·관리 화면 **0**. `ADR-058`(포털 전용 표 최소화)과 정합.
2. **라벨링 화면에서 라벨을 그때그때 만든다** — 이름을 입력해 바로 쓴다.
3. **작업을 열면 그 작업의 기존 라벨을 목록으로 보여준다** — 앞서 쓴 이름을 다시 고를 수 있다. **마스터 없이 재사용이 성립하는 지점**이다.
4. `labelId` 는 계속 **`null`** — 저장 형태 무변경.

★**3번이 이 설계의 핵심이다.** 마스터를 없애면 재사용 수단이 사라질 것 같지만, **그 작업에서 이미 쓴 라벨이 곧 목록**이 되므로 재사용이 된다. 두 번째 객체를 그릴 때 첫 번째에서 만든 이름을 고르면 된다.

## §3 도메인별 변경 상세

### 프론트 (SCREEN-029) — `klid-web-implementer`

- **대상**
  - `frontend/src/features/label/components/LabelPickerModal.tsx` — 지금은 **마스터 선택 전용**
  - 그 모달을 여는 경로(`OverlayLayer` 의 도형 생성 진입)
  - 라벨 목록의 **출처**를 정하는 자리

- **변경**

  1. **업로드 갈래에서 라벨 목록의 출처를 「전역 마스터」에서 「이 작업의 라벨」로 바꾼다.**
     - 그 작업(영상)에서 이미 쓰인 라벨명들 — **중복 제거**해서 목록으로.
     - ⚠ **프레임 하나가 아니라 작업(영상) 전체**여야 한다. 프레임별로만 모으면 다른 프레임에서 만든 라벨이 안 보여 같은 대상에 이름이 갈린다.

  2. **「새 라벨 만들기」 수단을 그 모달에 둔다.** 이름을 입력하면 그 자리에서 쓰고, 그린 뒤에는 1번 목록에 자연히 나타난다(원장에 저장되므로 별도 등록 단계가 없다).
     - ⚠ **지금의 입력칸은 검색 필터다** — 그것을 만들기 겸용으로 바꿀지 별도 자리를 둘지는 구현 판단이나, **검색과 생성이 사용자에게 구분돼야 한다**(「없으면 만든다」가 조용히 일어나면 오타가 새 라벨이 된다).
     - 라벨명 상한 **80자**(`LBL_NM` 컬럼) — 입구에서 막는다. 서버도 `@Size(max = 80)` 로 받는다.
     - **빈 이름을 허용할지**는 구현 판단이 아니다 — 서버는 허용한다(V29). 화면이 굳이 막을 이유는 없으나, **빈 이름 라벨이 목록에 들어가면 고를 수 없는 항목**이 되므로 목록에서는 제외한다.

  3. **색은 이름에서 결정론적으로 배정한다** — 같은 이름이면 항상 같은 색. 마스터 색이 없으니 지어낼 수밖에 없는데, **무작위·순번은 안 된다**(같은 라벨이 프레임마다 다른 색이 된다). 이 저장소에 이미 결정론적 해시 배색 경로가 있으니(`labelColor` 판정기의 하위 순위) **그것을 재사용하고 새로 만들지 않는다.**

  4. **데이터마트 갈래는 종전대로** — 그 자산의 라벨은 관제에서 딸려 온 것이라 마스터 연결이 있고, 화면은 그것을 **보존해 되돌려 보낸다**. 이 CO 는 그 축을 건드리지 않는다.

- **불변**
  1. **저장 형태를 바꾸지 마라** — 업로드 축은 이름만 저장하고 `labelId` 는 `null` 이다. 서버 계약 무변경.
  2. ★**이름으로 마스터를 역추정하지 마라** — 서버 주석이 명시적으로 거부한 것이고, 역해석 함수도 동명·비활성이면 `null` 을 주는 fail-closed 다. **화면에서 우회하지 마라.**
  3. **라벨 표시명·색 판정을 복제하지 마라** — 판정기는 `features/label/utils/labelColor`·`labelDisplayName` 한 곳이다. 넘길 항목만 고르고 판정은 위임한다.
  4. **데이터마트 갈래의 마스터 사이드바·선택 모달을 없애지 마라** — 그쪽은 마스터가 맞다.

- **주의**
  - ⚠ **흡수한 통합 화면은 사양상 「라벨 마스터 사이드바」를 갖는다.** 업로드 갈래에서 그 자리가 **이 작업의 라벨 목록**으로 바뀌는 것이므로, **사양(SCREEN-029)을 먼저 고쳐야 한다**(§6).
  - ⚠ **목록이 비어 있는 것이 정상인 구간이 있다** — 처음 여는 자산은 라벨이 0건이다. 그때 「불러오지 못했다」류로 보이면 안 되고, **만들기로 유도**해야 한다.

### 조달 창구 (필요 시) — DOMAIN-013 · `klid-d013-implementer`

**작업(영상) 단위 라벨명 목록을 화면이 얻을 수단**이 필요하다.

- 현재 업로드 프레임 라벨 조회는 **프레임 단위**다. 작업 전체의 라벨을 모으려면 프레임을 전부 조회해야 하는데, 프레임이 수백~수천이면 성립하지 않는다.
- ⇒ **작업 단위로 distinct 라벨명을 주는 조달이 필요할 가능성이 높다.**
- ★**다만 먼저 확인하라** — 자산 상세 응답이나 기존 창구가 이미 그 정보를 주거나 싸게 줄 수 있는지. **없다고 단정하고 새 창구부터 만들지 마라.**
- 만든다면 **읽기 전용 조회**이며 새 표·새 저장 축을 만들지 않는다(원장에서 도출).

## §4 영향·리스크

- **하위호환**: 저장 형태·서버 계약 무변경. 이미 적재된 업로드 라벨은 그대로 읽힌다.
- **리스크**
  1. **프레임 단위로만 목록을 모으면** 다른 프레임에서 만든 라벨이 안 보여 **같은 대상에 이름이 갈린다.** 그러면 산출물에서 같은 것이 다른 라벨로 나온다.
  2. **검색과 생성이 구분되지 않으면** 오타가 조용히 새 라벨이 된다.
  3. **색을 무작위·순번으로 배정하면** 같은 라벨이 프레임마다 다른 색이 된다.
  4. **데이터마트 갈래까지 자유 입력으로 바꾸면** 그 자산의 마스터 연결이 끊긴다 — 축을 가르지 않으면 이 CO 가 원래 문제를 만든다.

## §5 검증

1. 업로드 자산에서 **라벨을 새로 만들어** 도형에 붙이고 저장한 뒤 재조회하면 그 이름이 유지된다.
2. **작업을 다시 열면 그 작업의 기존 라벨이 전부 목록에 뜬다** — ★**다른 프레임에서 만든 라벨도 포함**된다(리스크 1).
3. 같은 이름의 라벨은 **프레임을 옮겨도 같은 색**이다(리스크 3).
4. 라벨 0건인 자산에서 목록이 비어도 **실패로 보이지 않고 만들기로 유도**된다.
5. 80자 초과 이름은 **입구에서** 막힌다(서버 400 으로 새지 않는다).
6. **데이터마트 갈래 무변경** — 마스터 사이드바·선택 모달이 그대로이고 `labelId`·`trackId` 왕복이 유지된다(`portalLabelMasterTrackRoundTrip.test.tsx` 통과).
7. 저장 payload 에 `labelId` 가 실리지 않는다(업로드 축).

- ★**변이 검증**: 목록 출처를 프레임 단위로 좁히면 RED 인가 · 색 배정을 순번으로 바꾸면 RED 인가 · 데이터마트 갈래를 자유 입력으로 바꾸면 RED 인가.
- ★**시험이 통과하는 시점·상태가 결함이 드러나는 시점·상태와 같은지 확인하라**:

  | 함정 | 시험이 놓치는 것 |
  |---|---|
  | 비동기를 동기로 읽음 | 효과가 반영되기 **전에** 읽는다 |
  | 진입 순서 미재현 | 실사용이 지나는 **전이**를 안 지난다 |
  | 왕복 후 상태 미확인 | 깨지는 **시점 이후**를 안 본다 |
  | 해제만 단언 | 걸리는 쪽을 안 본다 — 애초에 안 걸려도 통과 |

  ⚠ **셋째가 이 CO 의 핵심 축이다** — 「만든 라벨이 유지된다」는 **저장 후 재조회**에서만 드러난다. 만들기 직후 화면 상태만 단언하면 통과해도 아무것도 안 지킨다.
  ⚠ **둘째도 온다** — 「작업을 다시 열면」은 **재진입 전이**를 실제로 지나야 한다.

## §6 관련 설계 ITEM — ★이번엔 진짜 대상이 있다

앞선 두 라운드와 달리 **이건 사양 변경이다.** 화면의 라벨 목록 출처가 바뀐다.

| ITEM | 타입 | 무엇을 어떻게 |
|---|---|---|
| SCREEN-029 | screen_spec | **「라벨 마스터 사이드바」 섹션이 자산 출처로 갈린다** — 데이터마트는 종전대로 마스터, **업로드는 「이 작업의 라벨」 + 새로 만들기**. 목록이 비는 것이 정상인 구간과 그때의 안내도 함께 |
| UC-027 | use_case | 업로드 수동 라벨링 흐름에 **라벨을 그때그때 만드는 단계**가 든다 |
| AC-1070 | acceptance | 위 흐름의 수용기준 |

**★쓰기 전 규율**
- `screen_spec` 은 발주처 산출물이라 **폐기 문구를 본문에 두지 않고 원소째** 고친다(잃는 지식은 `change_summary`). 이 예외는 `screen_spec` 에만.
- **쓰기 전에 `stale`·`stale_reason` 을 기록**한다 — 쓰면 지워진다(해소가 아니라 소실).
- ⚠ **`stale: false` 를 정합의 증거로 읽지 마라** — 전파가 항상 도는 것이 아님이 2026-09-08 실측됐다. **본문 직접 대조**로 판정한다.
- **한글을 `\uXXXX` 로 쓰지 마라.** 전체 교체 전 기준선 길이 확인 + 교체 후 문자 단위 diff.
- ⚠ **`screen_spec` 의 섹션 설명 상한은 1000자**다(타 세션 실측 — **거부로만 알 수 있고 원자 거부라 서버에 아무것도 안 쓰인다**).

**건드리지 말 것**
- **`ADR-013` 을 고치지 마라** — 그 미제공 축은 외부 서버 연동이지 라벨 어휘가 아니다.
