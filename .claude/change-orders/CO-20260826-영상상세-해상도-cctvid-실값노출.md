## §1 배경

사용자 신고: *"영상 상세에 해상도는 항상 '-' 로 표시가 되고있는듯"*.

### 1-1. 결함 ① — 해상도가 항상 「-」 (BE 응답 필드 누락)

데이터는 있는데 서버가 안 내려준다. 층별 실측:

| 층 | 상태 |
|---|---|
| DB | `klid_at.ls_data_meta` 에 `video.resolution` 실재 (dev rawSn=1 → `1920x1440`) |
| BE `VideoDetailResponse` | **`resolution` 필드 없음** — 레코드 전체 필드 목록에 부재 |
| FE `VideoDetail` 타입 | `resolution: string` **선언돼 있음** |
| 화면 2곳 | `video.resolution \|\| '-'` → 항상 `undefined` → **항상 `-`** |

**FE 타입이 BE 에 존재하지 않는 필드를 선언한 계약 드리프트**다. TypeScript 가 이걸 못 잡는 이유는
API 응답을 타입으로 단언하고 나면 없는 필드가 `undefined` 로 조용히 통과하고, `|| '-'` 폴백이 그
사실을 완벽히 가리기 때문이다.

★ **고치는 길이 같은 파일 안에 이미 있다** — `fps` 가 정확히 같은 문제를 겪고 이미 해결됐다.
`VideoFpsResolver` 가 `LS_DATA_META` 의 `video.fps` 를 읽어 응답에 싣는다.
`video.resolution` 은 **같은 테이블·같은 방식**으로 읽을 수 있는데 아무도 읽지 않을 뿐이다.

### 1-2. 결함 ② — CCTV ID 가 조립된 가짜 값

```
VideoDetailPage.tsx  InfoTab
  { label: 'CCTV ID', value: `video-${String(video.id).padStart(4,'0')}` }
```

`rawSn` 으로 **조립한 문자열**이다. DB 실값은 `ls_data_raw.vms_cctv_id`(dev rawSn=1 → `CCTV-001`)이고,
화면 상단 제목(`cctvName`)에는 그 진짜 값이 나온다.

**그래서 같은 화면에 「CCTV-001」(제목)과 「CCTV ID: video-0001」(기본정보)이 동시에 뜬다** — 같은 것을
가리키는 두 값이 다르다. BE 는 `vmsCctvId` 를 응답에 **이미 싣고 있는데**(`VideoDetailResponse`) FE 타입에
그 필드가 없어 화면이 조립값을 쓰고 있다.

## §2 변경 요지

1. BE 영상 상세 응답에 **`resolution` 을 추가**한다 — 조달원은 `LS_DATA_META` 의 `video.resolution`,
   방식은 기존 `fps` 와 동일.
2. FE 가 **`vmsCctvId` 실값을 표시**하게 한다(조립 폐기).

## §3 도메인별 변경 상세

### DOMAIN-003 (영상·프레임 수집) — `klid-d003-implementer`

- **대상 파일·심볼**:
  - `video/dto/VideoDetailResponse` — 필드 추가
  - `video/service/VideoQueryService` — 조립
  - 조달 판정기 — `video/service/VideoFpsResolver` 와 **같은 계층**에 둔다
- **변경**:
  - 응답에 `resolution`(문자열, 미상 시 `null`)을 추가한다.
  - 조달원은 `LS_DATA_META` 의 `META_KEY='video.resolution'` 이며, 판정 지점을 **한 곳**에 둔다
    (`VideoFpsResolver` 와 같은 모양). 값 형식은 적재된 그대로(`{W}x{H}`)를 쓰고 **화면이 재조립하지 않는다.**
  - ⚠ **fps 와 달리 숫자 폴백을 두지 않는다.** fps 는 미상 시 30.0 으로 폴백하는데 그건 마킹
    frameIndex 계산이 서버와 같은 값을 써야 하기 때문이다(계산 입력). 해상도는 **표시 전용**이라
    없는 값을 지어내면 안 된다 — 미상이면 `null` 을 내리고 화면이 「-」로 표시한다.
- **불변**:
  - 기존 필드 **전부 무변경**(추가만 — 하위호환). 기존 `from(...)` 오버로드로 만든 응답은 `null` 이 되어
    기존 소비자가 영향받지 않는다(이 DTO 가 이미 그 관례를 쓴다).
  - `LS_DATA_META` 무변경(읽기 전용). 기술메타 적재 경로 무변경.
- **주의**:
  - `LS_DATA_META` 에는 `video.codec`·`video.bit_rate`·`video.filesize`·`video.duration_ms` 도 함께 있으나
    **이번에는 해상도만 노출한다**(사용자 확정). 확정 디자인(SCREEN-009)이 그 줄에 두기로 규정한 것이
    해상도이며, 나머지를 임의로 더하면 화면이 확정 사양을 앞지른다.
  - `LS_DATA_RAW` 에는 해상도 컬럼이 **없다** — 메타 테이블이 유일한 조달원이다.
  - ⚠ 파생영상(증강·해상도 변환본)의 `video.*` 는 **부모와 같은 값이 정상**이다(비디오를 재인코딩하지
    않고 복사하며 프레임 이미지만 변환하므로). 이것을 결함으로 보고 보정하지 말 것.
- **수용기준**: `video.resolution` 메타가 있는 영상의 상세 응답에 그 값이 실린다. 없는 영상은 `null`.

### 프론트 (SCREEN-009) — `klid-web-implementer`

- **대상 파일·심볼**:
  - `frontend/src/features/video/types.ts` — `VideoDetail`
  - `frontend/src/pages/VideoDetailPage.tsx` — `InfoTab` 메타 그리드 · 헤더 메타 행
- **소비 API 계약**: `GET /v1/videos/{rawSn}`(API-043) — `resolution`(신규, nullable) · `vmsCctvId`(기존, 미사용 중)
- **변경**:
  1. `VideoDetail.resolution` 타입을 서버 계약에 맞춘다(nullable). 두 표시 지점은 기존 `|| '-'` 폴백을 유지.
  2. `CCTV ID` 값을 **`video.vmsCctvId` 실값**으로 바꾸고 `video-${id}` 조립을 폐기한다.
     타입에 `vmsCctvId` 가 없으면 추가한다(BE 는 이미 내려주고 있다).
- **불변**:
  - 상단 제목(`cctvName`) 무변경.
  - 메타 그리드의 **항목 구성·순서 무변경** — 값만 바뀐다.
  - `mono: true` 등 표시 속성 유지.
- **주의**:
  - `vmsCctvId` 가 비어 있는 영상이 있을 수 있다 — 그때는 조립값으로 되돌아가지 말고 `-` 로 둔다
    (없는 식별자를 지어내면 그게 실값처럼 보인다).
- **수용기준**:
  1. `resolution` 을 내려주는 영상에서 헤더·기본정보 두 곳에 그 값이 표시된다
  2. 메타가 없는 영상은 두 곳 다 `-`
  3. `CCTV ID` 가 상단 제목과 **같은 식별자 체계**로 표시된다(dev rawSn=1 → `CCTV-001`)

## §4 영향·리스크

- **하위호환**: 응답 필드 **추가만**. 기존 소비자 영향 0. DB·적재 경로 무변경.
- **되돌리기**: 필드 제거 시 원상 복귀(FE 는 `|| '-'` 폴백이 있어 깨지지 않는다).
- **리스크**:
  - 낮다. 읽기 전용 조회 + 표시 변경이다.
  - ⚠ 다만 `CCTV ID` 표시값이 바뀌는 것은 **사용자가 보던 문자열이 달라지는 것**이므로, 그 값으로
    외부와 소통해 온 운영자가 있으면 혼란이 생길 수 있다. 실제로는 조립값이 어디에도 저장되지 않는
    화면 전용 문자열이라 영향이 없을 것으로 보나, 게이트에서 한 번 확인한다.
