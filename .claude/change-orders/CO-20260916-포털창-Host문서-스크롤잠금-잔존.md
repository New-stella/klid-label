## §1 배경

포털 개발망 Host(38444)에 얹힌 저작도구 화면에서 **창을 한 번 열었다 닫으면 포털 페이지
전체가 새로고침 전까지 스크롤되지 않는다**는 신고가 있었다. 브라우저로 직접 실측했다.

재현 경로 — 저작도구 영역 → 증강 → 「결과 확인」.

| 시점 | `document.body` 클래스 | 계산된 `overflow` | 창 DOM |
|---|---|---|---|
| 열기 전 | `""` | `hidden auto` | 없음 |
| 열었을 때 | `scroll-no` | `hidden` | 있음 |
| **닫은 뒤** | **`scroll-no`** | **`hidden`** | 없음(닫힘은 정상) |

**근본 원인.** 킷(krds-react) `Modal` 의 효과에 **정리 함수가 없다.**

```js
useEffect(() => {
  if (open) { document.body.classList.add("scroll-no"); /* + #wrap 에 inert */ }
  else      { document.body.classList.remove("scroll-no"); }
}, [open]);   // ← return 없음. 「열림 → 닫힘」 전이에서만 되돌린다
```

그런데 우리 화면들은 `open` 을 리터럴 `true` 로 두고 **조건부 렌더로 언마운트**해 닫는다
(`PortalAugmentPage` 결과 확인 · `PortalUploadPage` 삭제 확인 · 증강 요청). 그래서 else
가지가 한 번도 돌지 않는다.

★ **화면이 언마운트로 닫는 것은 옳은 판단이다** — 닫힌 킷 창이 `role="dialog"` 를 문서에
남겨 보조기술이 「창이 둘」로 읽는다(그 근거는 `PortalUploadPage` 주석에 이미 있다).
되돌리지 않는다.

★ **임베드라서 피해 범위가 다르다** — 그 `body` 는 우리 것이 아니라 **Host 문서**다.
독립 앱이면 우리 화면 안에서 끝날 일이 포털 전체를 굳힌다.

⚠ 대조군 — `open` 을 토글하는 화면(마킹 완료 확인)은 **정상이다.** 그것이 이 진단의 근거다.

## §2 변경 요지

- 공용 창 부품 둘(`components/portal/kit/Modal.tsx` · `Dialog.tsx`)이 **언마운트될 때 뒤를 치운다.**
  호출부는 고치지 않는다 — 화면마다 치우게 하면 새 화면이 생길 때마다 빠진다.
- 창이 겹칠 수 있으므로 **세어서 마지막 하나가 사라질 때만** 되돌린다.
- 킷이 `#wrap` 에 거는 `inert` 도 같은 갈래라 함께 되돌린다.
- **킷은 고치지 않는다**(외부 의존).

## §6 설계 반영

**`ADR-070`(임베드에서 문서 전역 상태의 소유권 — Remote 는 자기가 건 것만 되돌린다) 신설.**

`INT-013` 의 「스타일 격리 규약」이 바로 옆 축(Host 를 건드리지 않는 축)인데 **대상이 CSS 뿐**이고,
화면이 실행 중에 문서에 남기는 상태(스크롤 잠금 · `inert` · 포커스 · 전체화면 · 히스토리)는
**어느 항목도 소유하지 않았다.** 그 공백을 메운다.

⚠ **`INT-013` 본문은 고치지 않았다** — 인라인 스펙 19,983자(상한 20,000) · `description`
3,988자(상한 4,000)로 **한 줄도 들어가지 않는다.** 연결은 `ADR-070` 의 참조 필드로 만들었다.

⚠ **IMPREC 을 남기지 못했다** — ADR 타입은 구현 기록 대상이 아니고(`E_NOT_TRACKABLE`),
붙일 만한 다른 ITEM 도 없다. **포털 킷 창 부품이 UI 카탈로그에 하나도 등록돼 있지 않다**
(DS-002 overlay 0건 — 등록된 모달·다이얼로그는 전부 DS-001 관제향). 그것만을 위해 카탈로그
항목을 지어내지 않았다. **별건으로 다룰 부채다.**
