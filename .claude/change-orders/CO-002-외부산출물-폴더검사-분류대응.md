## §1 배경

검수자가 산출물 폴더 경로를 넣으면 **아무것도 저장하지 않고** 무엇이 몇 건 들어오는지·처리할 수 없는
항목이 무엇인지 먼저 보여주는 단계가 필요하다(`AC-041`). 그 미리보기가 알려주는 것 중 가장 중요한 것이
**대응이 정해지지 않은 외부 분류**이며, 그것이 남아 있으면 적재하지 않는다(`AC-042`).

외부 산출물의 분류 이름은 저작도구 라벨 체계와 다르다. 실측 근거 — `LS_LABEL.DTCT_TYPE_CD` 는 DB 제약이
없지만 `LabelMasterService` 가 **COCO 80종만 통과**시키므로 `asphalt`·`water` 같은 1차 산출물 분류를
그 축에 넣을 수 없다. 그래서 별도 대응 테이블이 필요하다.

## §2 변경 요지

- `POST /v1/imports/scan`(`API-205`) — 폴더를 훑어 미리보기를 돌려준다. **쓰기 0**.
- `GET /v1/import-mappings`(`API-209`) · `POST /v1/import-mappings`(`API-210`) ·
  `DELETE /v1/import-mappings/{mpngSn}`(`API-211`) — 분류 대응 목록·확정·해제.
- 처음 보는 분류는 **이름이 비슷한 후보를 제시**하고 사람이 확인해 확정한다. 확정 이후 같은 분류는 자동 연결.

## §3 도메인별 변경 상세

### DOMAIN-017 (외부 산출물 이관) — `klid-d017-implementer`

**대상 파일·심볼**

- 신규 `transfer/controller/ImportScanController` · `ImportMappingController`
- 신규 `transfer/service/ImportScanService` · `ImportMappingService` · `CategoryMatchSuggester`
- 신규 `transfer/repository/LsOtsdCtgryMpngRepository`
- 재사용: CO-001 이 만든 파서·엔티티

**변경**

1. **`API-205` `POST /v1/imports/scan`** — 인가 `REVIEWER`. 바디 `folderPath`(필수) · `videoPath`(선택).
   - ★ **아무것도 저장하지 않는다**(`AC-041`). 트랜잭션 쓰기 0, 파일 쓰기 0.
   - 폴더를 훑어 `{8자리}.jpg` + `{8자리}.json` 페어를 센다.
   - 응답 `data.warnings[]` — 각 `{code, message}`. 최소 두 종류:
     · 짝 문서가 없는 이미지 · 문서 선언 건수(`dataset.total_count`)와 실제 파일 수 불일치.
   - 미확정 분류 목록과 **추천 후보**를 함께 돌려준다.
   - 응답은 `ApiResponse<T>` 래퍼(`{data, message, success, errorCode}`)를 따른다 — 이 도메인 API 7건이
     모두 그렇게 정합돼 있다.
   - 오류: `400`(경로 형식·길이) · `401` · `403` · `404`(폴더 없음).

2. **경로 검증 (보안 — 이 CO 의 최대 리스크)**
   - `folderPath`·`videoPath` 는 **사람이 입력하는 외부 문자열**이다. 경로 이탈(CWE-22)을 반드시 막는다.
   - 허용 루트(스토리지 base) 밖이면 거부한다. **lexical 경로로 검증하고 lexical 경로로 여는 구현 금지** —
     `toRealPath()` 로 실경로를 얻어 검증하고 **그 실경로를 그대로 사용**한다(CWE-59/367).
     이 저장소가 `StorageSubtreePolicy` 로 이미 세운 규칙이며, 그것은 **단일 파일 검증만** 제공하므로
     디렉터리 스캔은 같은 패턴을 참고해 신규 구현한다.
   - 스캔 대상 건수·깊이에 **상한**을 둔다(CWE-770). 상한에 걸리면 조용히 자르지 말고 경고로 알린다.
   - 폴더명·파일명·분류명을 로그에 남길 때 개행·제어문자를 제거한다(CWE-117). 기존 `LogSanitizer` 재사용.

3. **`API-209` `GET /v1/import-mappings`** — 쿼리 `kind`(`LABEL`|`EVNT_TYPE`, 비우면 둘 다) 등.
   대응 목록을 페이징으로 돌려준다. 미연결 항목도 감춘다.

4. **`API-210` `POST /v1/import-mappings`** — 바디 `items[]` · `overwrite:boolean`. 201.
   - 대응 종류(`MPNG_KND_CD`)에 따라 `LBL_ID`(라벨) 또는 `EVNT_TYPE_CD`(이벤트 유형) 하나만 채운다.
   - 같은 `(MPNG_KND_CD, OTSD_CTGRY_CD)` 중복은 `overwrite=false` 면 **409**.
   - ★ **이름만 보고 짐작해 자동 확정하지 않는다.** 추천은 후보 제시까지이며 확정은 사람의 행위다.
     짐작으로 연결하면 다른 분류로 저장되고, 저장된 뒤에는 어느 것이 짐작이었는지 구분할 수 없다.

5. **`API-211` `DELETE /v1/import-mappings/{mpngSn}`** — 204, 본문 없음.
   ⚠ 설계 ITEM 의 204 응답에 `content_type` 키가 남아 있는데 **이건 우리 결함이 아니라 플랫폼 제약**이다
   (서버 zod 스키마가 매 쓰기마다 재삽입한다). 구현은 **본문 없이** 내려보내면 된다.

6. **분류 대응 추천** (`CategoryMatchSuggester`)
   - 외부 분류의 표시 이름(`OTSD_CTGRY_NM`)으로 라벨 마스터·이벤트 유형에서 비슷한 이름을 찾아 후보를 만든다.
   - **fail-closed** — 후보가 0건이거나 동점 다수면 후보를 비우고 사람이 고르게 한다.
     이 저장소의 `resolveLabelIdByName` 이 같은 이유로 fail-closed 다(동명 활성 마스터 0건·2건 이상이면 `null`).

**불변**

- `LabelMasterService` 의 COCO 80종 화이트리스트와 `LS_LABEL.DTCT_TYPE_CD` 축 — 이관 대응은 별도 테이블이고
  그 축에 값을 밀어넣지 않는다.
- `LS_EVNT_TYPE` 의 표시명 그룹핑(`EventTypeDisplayNamePolicy`·`EventTypeService`) — 이벤트 유형 대응이
  표시명을 해석해야 하면 **그 판정기를 재사용**하고 복제하지 않는다.

**주의**

- 미리보기 단계에서 **파일을 열어 파싱하는 비용**이 크다. 폴더 건수가 많으면 트랜잭션을 잡지 않은 상태에서
  처리한다(커넥션 기아 전례가 있다 — 프레임 이미지 서빙이 같은 이유로 트랜잭션 밖 I/O 로 분리돼 있다).

**수용기준**

- `AC-041` — 검사 호출 후 DB·파일시스템에 아무 변화가 없다(행 수·mtime 불변으로 단언).
- `AC-047` — 짝 없는 이미지·건수 불일치가 **경고로** 응답에 담긴다(이 CO 는 경고 산출까지, 적재는 CO-003).
- `AC-043` — 한 번 확정한 대응은 다음 검사에서 미확정 목록에 나오지 않는다.
- 경로 이탈 시도(`../`, 심링크 교체)가 거부된다 — **negative 케이스를 반드시 넣는다**
  (감사가 *"보안 negative AC 0건"* 을 지적했다).

## §4 영향·리스크

- **하위호환**: 전부 신규 엔드포인트라 기존 호출자 영향 0.
- **되돌리기**: 컨트롤러 라우팅 제거로 충분(스키마 변경 없음 — CO-001 소관).
- **리스크**: 경로 검증이 뚫리면 서버 파일시스템 임의 읽기가 된다. 이 CO 에서 가장 무거운 항목이다.
