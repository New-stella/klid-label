# CO-20260901 — 증강 주소 검증을 공용 원천으로 옮긴다

| 항목 | 값 |
|---|---|
| 작성 | 2026-09-01 |
| 대상 도메인 | DOMAIN-007 (데이터 증강 — `augment/`) + 공유기반 `common/config/` |
| 설계 선반영 | **`ADR-046` v10**(대상 넷 → 다섯) · `CLAUDE.md` 「대상 5종」 — 완료 |

## 1. 왜 하는가

2026-08-10 확정(**연동 주소는 스킴 `http`/`https` + 형식만 보고 대역 차단은 하지 않는다**)의 대상 목록에 **증강이 빠져 있었다.** 그래서 시계열(VLM)이 그 정책으로 옮겨간 뒤 **증강만 옛 정책에 남았다.**

```java
public class AugmentUrlPolicy extends ProfileGatedUrlPolicy   // ← 운영에서 HTTPS 강제 + 사설망 차단
```

**같은 성질의 외부 벤더 위탁인데 한쪽만 운영에서 평문 주소를 거부한다.** `AugmentUrlPolicy` 는 원래 *"증강만 스키마만 보는 약한 검증이라 VLM 과 비대칭"* 을 없애려고 만든 창구다 — **방향만 뒤집힌 채 그 비대칭이 되살아났다.**

⚠ **지금 당장 기동이 막히지는 않는다.** `application-stg.yml`·`application-prd.yml` 의 `mode` 기본값이 `noop` 이고 `AugmentApiWebClientConfig` 가 `@ConditionalOnProperty(havingValue="http")` 라, 운영에서는 그 설정 클래스가 뜨지 않아 `validate` 도 돌지 않는다. **`AUGMENT_EXTERNAL_MODE=http` 로 켜는 순간** 평문 벤더 주소에서 기동이 막힌다.

★ `VlmUrlPolicy` javadoc 이 *"증강은 같은 확정 정책의 대상이지만 아직 프로파일 게이팅에 남아 있다 — 이 클래스를 근거로 그쪽을 임의로 바꾸지 말 것, **별도 결정이 필요하다**"* 라고 적어 뒀다. **그 결정이 2026-09-01 에 났다**(사용자 확정).

## 2. 도메인별 변경 상세

### 공유기반 + DOMAIN-007 (`klid-d007-implementer`)

**대상 파일**
- `backend/src/main/java/kr/co/cudo/authoring/common/config/AugmentUrlPolicy.java`
- `backend/src/test/java/kr/co/cudo/authoring/common/config/AugmentUrlPolicyTest.java`
- 설정 파일·환경 템플릿에서 완화 플래그(`authoring.augment.external.allow-insecure-url`) 정리
- `augment/integration/AugmentApiWebClientConfig.java` (주석의 정책 서술)

**변경 — `VlmUrlPolicy` 가 방금 옮겨간 방식을 그대로 따른다**

★ **본을 새로 만들지 말 것.** `VlmUrlPolicy` 가 같은 이관을 이미 끝냈다. 그 구조를 그대로 복제한다:
- `extends ProfileGatedUrlPolicy` 를 떼고, 판정을 **`ExternalUrlPolicy.internalNetwork(PROP_URL)`** 에 위임한다
- 완화 플래그를 **걷어낸다** — 확정 정책이 운영에서도 평문·사설을 허용하므로 **켜든 끄든 결과가 같은 죽은 설정**이 된다. 남기면 「이걸 끄면 엄격해진다」는 잘못된 기대를 준다
- 설정 파일·환경 템플릿에서도 그 키를 함께 지운다

**유지되는 것 (없어지는 것과 구분할 것)**

| 유지 | 없어짐 |
|---|---|
| 비허용 스킴(`ftp`·`file`·`ws`) 거부 · 빈값·형식오류 거부 · placeholder 호스트 거부 · **예약대역(IMDS·링크로컬·ULA·CGNAT·멀티캐스트) 거부** · **https 도 그대로 통과** | HTTPS **강제** · 사설망 차단 · 프로파일 게이팅 · 완화 플래그 |

⇒ 평문 http + 사설대역·루프백은 통과하고 **IMDS 같은 위험 대역은 계속 막는다.** https 동작이 남아 나중에 TLS 전환 시 코드 변경이 0 이다.

**시험**
- `AugmentUrlPolicyTest` 에서 **폐기된 동작**(프로파일 게이팅·완화 플래그·HTTPS 강제)을 무는 케이스를 걷어낸다. ⚠ **살아 있는 동작**(예약대역 거부·스킴 거부·placeholder 거부·https 통과)은 반드시 남긴다
- ★ **평문 http + 사설대역이 이제 통과한다**는 것을 무는 케이스를 **신설**한다 — 이번 변경의 목적이 그것이고, 없으면 되돌아가도 초록이다
- VLM 쪽 시험이 같은 이관에서 20 → 7 건이 된 선례가 있다. **줄어드는 것 자체는 정상이나, 무엇이 왜 줄었는지 근거를 보고할 것**

**불변 (건드리지 말 것)**
- `ExternalUrlPolicy` 본체 — VLM·KPST 가 공유하는 공용 원천이다. 증강 때문에 규칙을 바꾸면 셋이 함께 흔들린다
- `VlmUrlPolicy` · `KpstWebClientConfig`
- `ProfileGatedUrlPolicy` 클래스 자체 — `QuartzClusteringGuard`·`DevProfileGuard`·`DeployedEnvironmentDetector` 가 **그 골격의 ENV 판정 축을 참조**한다(시험 `DeployedEnvironmentDetectorTest` 가 그 정합을 문다). 증강이 상속을 떼는 것과 그 클래스를 지우는 것은 다른 일이다
- 증강 요청·응답 계약, `mode` 토글 동작
- **마이그레이션을 만들지 말 것**

**수용기준**
1. 운영 프로파일에서 평문 http + 사설대역 벤더 주소로 기동이 **성공**한다
2. IMDS(`169.254.169.254`)·링크로컬·placeholder 호스트·비허용 스킴은 **여전히 거부**된다
3. https 주소도 그대로 통과한다
4. 완화 플래그가 코드·설정·템플릿에서 사라진다
5. `ProfileGatedUrlPolicy` 를 참조하는 다른 가드 3종의 시험이 그대로 통과한다

## 3. 인지·수용한 위험 (사용자 확정)

증강 요청 본문에는 **공유 저장소의 비식별 프레임 절대경로가 다수 실린다** — 유출 표면이 시계열보다 넓다. 그럼에도 푸는 근거는 **대역 차단으로 막히는 위험이 아니기 때문**이다(공인망 주소로 바꾸면 그만이다). 이는 `ADR-046` 의 본래 근거와 같다.

## 4. 공유기반 영향

`common/config/` 를 건드리나 **`ExternalUrlPolicy` 본체는 무변경**이라 VLM·KPST 에 영향이 없다. 마이그레이션 없음.
