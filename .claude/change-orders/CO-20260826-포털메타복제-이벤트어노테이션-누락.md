## §1 배경

포털 채널은 저작도구가 써 넣는 동결 메타 복제본(`LS_DATASET_VIDEO_META`)을 **read-only 로 소비**한다. 그런데 그 복제본의 `EVNT_ANNO_CN`(이벤트 어노테이션 동결 payload)이 **항상 NULL** 로 남아 있어, 포털 시스템이 이벤트 어노테이션을 전혀 받지 못하고 있다.

**근본 원인 — 같은 테이블을 쓰는 두 upsert 가 갈렸다.** 2026-08-26 코드 실측:

| 구현 | INSERT 컬럼 수 | `EVNT_ANNO_CN` |
|---|---|---|
| control `LsDatasetVideoMetaRepository(upsertSnapshot)` | 37 | `CAST(:#{#m.evntAnnoCn} AS jsonb)` 로 적재 |
| portal `PortalDatasetVideoMetaRepository(upsertSnapshot)` | **36** | **없음** |

**경위**: control 이 `V128`(2026-07-24)로 이 컬럼을 추가했을 때 포털 복제본 DDL 이 따라오지 않아 두 스키마가 어긋났고, 나중에 발견해 `db/portal/V4` 로 **DDL 만** 붙였다. 그 파일 주석이 추가 사유를 밝히는데, *"복제 경로 4종은 모두 네이티브 쿼리라 이 컬럼을 읽고 쓰지 않으므로 복제 자체는 동작하지만, 같은 엔티티를 쓰는 JPA 파생 조회는 이 컬럼을 SELECT 하므로 42703 으로 깨진다"* 이다. 즉 **"복제하려고" 추가한 것이 아니라 "조회가 깨지지 않게" 추가**한 것이라 복제 로직은 지금도 따라와 있지 않다.

**판정**: 포털 측이 이 값을 필요로 함이 확인되어(2026-08-26 사용자 확정) **결함으로 확정**됐다.

**왜 지금까지 안 잡혔나**: 이 결함은 **DDL 은 맞고 SQL 만 틀린** 형태라, 스키마를 대조하는 검사로는 잡히지 않는다. 두 upsert 가 같은 컬럼 집합을 싣는지 확인하는 장치가 없었다.

## §2 변경 요지

포털 복제 upsert 의 INSERT 컬럼 목록과 VALUES 바인딩에 `EVNT_ANNO_CN` 을 **control 과 동일한 위치·동일한 형태**로 추가한다(`WTHR_NM` 다음, `RVW_CMPL_DT` 앞). 포털 복제본 DDL 에는 이 컬럼이 이미 있으므로 **스키마 변경은 불필요**하고 쿼리만 고치면 된다. 멱등 규약(`ON CONFLICT (RAW_SN, SNPSHT_HASH) DO NOTHING`)은 그대로 유지한다.

함께 **재발 방지 가드**를 넣는다 — 두 upsert 의 INSERT 컬럼 집합이 동일함을 고정하거나, 엔티티 전 필드를 채워 저장하고 재조회해 비교하는 왕복 동등성 테스트.

## §3 도메인별 변경 상세

### DOMAIN-013 (포털) — `klid-d013-implementer`

- **대상 파일·심볼**
  - `backend/src/main/java/kr/co/cudo/authoring/dataset/repository/PortalDatasetVideoMetaRepository.java` — `upsertSnapshot`
  - (대조 기준·수정 대상 아님) `backend/src/main/java/kr/co/cudo/authoring/dataset/repository/LsDatasetVideoMetaRepository.java` — `upsertSnapshot`
  - ★ 이 파일들은 `portal/` 이 아니라 `dataset/` 에 있다. 에이전트 지침 「코드 레이아웃」이 *"`INT-009`·`ERD-026`(메타 단방향 복제)는 `authoring/dataset/` 에 있다 — portal 패키지에서 찾지 말 것"* 이라고 명시한 그 경계 안이다.

- **변경**
  1. `upsertSnapshot` 의 INSERT 컬럼 목록에 `EVNT_ANNO_CN` 을 추가한다. 위치는 control 과 동일하게 `WTHR_NM` 다음, `RVW_CMPL_DT` 앞.
  2. VALUES 절에 대응 바인딩을 같은 위치에 추가한다. 형태도 control 과 동일하게 `CAST(:#{#m.evntAnnoCn} AS jsonb)`.
  3. 이 지점이 **dialect 에 묶인다**는 사실을 주석으로 남긴다(아래 주의 참조).

- **불변(건드리면 안 되는 것)**
  - `ON CONFLICT (RAW_SN, SNPSHT_HASH) DO NOTHING` 멱등 규약 — at-least-once 재복제를 무해화하는 계약이다.
  - `deactivatePrevious` → insert → `activateByHash` 순서와 **활성 1건 불변식**. 이번 변경은 컬럼 추가일 뿐 순서·불변식과 무관하다.
  - control 쪽 `upsertSnapshot` 은 **수정 대상이 아니다** — 이미 올바르며 대조 기준으로만 쓴다.
  - 포털 복제본 DDL(`db/portal/V*.sql` · `deploy/onprem/db/portal-schema.sql`) — 컬럼이 이미 존재하므로 **손대지 않는다**.
  - 발신함(outbox) 적재 로직과 워커의 폴링·재시도·dead-letter 전이 — 이번 변경 범위 밖이다.

- **주의**
  1. **`@PortalRepo` 는 이 리포지토리 하나뿐이다.** 포털 데이터소스로 실제 저장되는 테이블은 `LS_DATASET_VIDEO_META` 1종이며, 이름에 portal 이 들어간 다른 엔티티(`LsPortalUld` 등)는 **전부 control DB** 에 저장된다. 혼동해서 다른 리포지토리를 고치지 말 것.
  2. **dialect 결합 지점이다.** 포털 DB 를 MariaDB 로 바꾸는 별건 검토가 진행 중이며(미착수), 그때 `CAST(... AS jsonb)` 구문이 달라진다. **이번 변경에서 MariaDB 대응을 미리 하지 말 것** — 지금은 PostgreSQL 기준으로 control 과 동형을 맞추고, 주석으로 이 지점이 dialect 에 묶인다는 사실만 남긴다.
  3. **`dataset/` 는 D005·D010 과 공유하는 패키지**다. 메타 복제 계열(`LsMetaReplOutbox`·`MetaReplicationWorker`·`MetaReplicationOutboxService`·`PortalMetaReplicaWriter`·`PortalDatasetVideoMetaRepository`·`MetaReplicationQuartzJob`)만 이 도메인 소관이다. 그 밖의 `dataset/` 파일을 건드리게 되면 임의로 고치지 말고 `notes_for_main.cross_domain` 으로 올릴 것.
  4. 복제본 미구축 환경의 **graceful skip**(테이블 부재 probe) 동작을 깨뜨리지 말 것.

- **수용기준**
  1. 포털 복제 upsert 의 INSERT 컬럼 집합이 control 쪽과 **완전히 일치**한다(37개).
  2. `evntAnnoCn` 이 채워진 동결 메타를 복제하면 포털 복제본 행의 `EVNT_ANNO_CN` 에 **동일한 값**이 적재된다.
  3. `evntAnnoCn` 이 null 인 경우에도 복제가 실패하지 않고 해당 컬럼이 null 로 적재된다.
  4. 같은 `(RAW_SN, SNPSHT_HASH)` 로 재복제해도 중복 행이 생기지 않는다(멱등 유지).
  5. **재발 방지 가드가 추가되어**, 두 upsert 의 컬럼 집합이 어긋나거나 엔티티 필드가 복제에서 누락되면 테스트가 실패한다.

## §4 영향·리스크

- **하위호환**: 컬럼 추가만이며 기존 컬럼의 값·타입·순서는 불변이다. 포털 복제본 DDL 에 컬럼이 이미 존재하므로 마이그레이션이 필요 없고, 기존에 적재된 행은 그대로 남는다(값이 null 인 채로).
- **소급 적용 없음**: 이번 변경은 **앞으로의 복제**부터 값을 싣는다. 이미 복제되어 `EVNT_ANNO_CN` 이 null 인 기존 행은 자동으로 채워지지 않는다. 필요하면 해당 영상의 동결 메타를 다시 복제해야 하며, 그 백필 여부는 이 CO 범위 밖이다(포털 측 필요 시 별건).
- **되돌리기**: 추가한 컬럼과 바인딩을 제거하면 원상 복귀된다. 데이터 손실이 없다(추가만 하고 삭제·변경이 없다).
- **리스크**
  - `CAST(... AS jsonb)` 를 빠뜨리고 평문 바인딩만 하면 타입 불일치로 복제가 실패할 수 있다 — control 과 **동일한 형태**로 맞추는 것이 안전하다.
  - 컬럼 위치를 control 과 다르게 넣으면 두 쿼리를 나란히 읽을 때 대조가 어려워진다(기능상 문제는 아니나 재발 방지 취지에 어긋난다).

## §5 검증

- **자동 테스트**
  - 포털 복제 왕복: 동결 메타를 `evntAnnoCn` 을 채운 상태로 복제 → 포털 복제본 재조회 → 값 일치 단언.
  - null 케이스: `evntAnnoCn` 이 null 이어도 복제 성공.
  - 멱등: 동일 `(RAW_SN, SNPSHT_HASH)` 재복제 시 행 수 불변.
  - **재발 방지 가드**: 두 `upsertSnapshot` 의 INSERT 컬럼 집합 동일성, 또는 엔티티 전 필드 왕복 동등성.
- **기존 회귀**: `MetaReplicationWorkerIT` · `MetaReplicationWorkerFailureIT` · `MetaReplicationUnprovisionedPortalIT` · `PortalMetaReplicaWriterRecencyIT` · `PortalReplicaWriteGuardTest` 가 그대로 통과해야 한다(특히 미프로비저닝 graceful skip).
- **목서버 기동 불요** — DB 계층 변경이라 외부 연동과 무관하다.
