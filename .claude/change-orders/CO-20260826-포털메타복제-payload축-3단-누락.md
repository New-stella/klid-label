## §1 배경

선행 CO(`CO-20260826-포털메타복제-이벤트어노테이션-누락`)가 포털 복제 upsert 의 INSERT 컬럼 누락을 고쳤으나, **증상이 해소되지 않았다.** 복제 경로는 4단인데 그 CO 는 마지막 1단만 지목했고, 앞 세 단계에서도 같은 값이 빠져 있었다.

| 단계 | 지점 | 상태 |
|---|---|---|
| ① 발신함 payload 직렬화 | `DatasetVideoMetaSnapshotService.toPayload` | **결손** |
| ② payload 전송 계약 | `MetaReplicationPayload`(record) | **결손** — 컴포넌트 자체가 없음 |
| ③ payload → 엔티티 복원 | `MetaReplicationWorker.toSnapshot` | **결손** — 빌더 호출 없음 |
| ④ 포털 INSERT | `PortalDatasetVideoMetaRepository.upsertSnapshot` | 선행 CO 에서 수정 완료 |

**실측(2026-08-26)**: `MetaReplicationPayload`·`MetaReplicationWorker` 에 `evntAnnoCn` 출현 **0건**. `toPayload` 는 `wthrNm` 다음 곧바로 `rvwCmplDt` 로 넘어간다.

**중요한 대비** — 같은 클래스 안에서 **동결과 해시는 이 값을 이미 반영하고 있다**: 동결 스냅샷 빌더가 `.evntAnnoCn(frozenEventAnno)` 를 채우고, 해시 입력 맵도 `EVNT_ANNO_CN` 을 포함한다. **오직 발신함 payload 직렬화만 빠졌다.** 즉 값은 동결까지 정상으로 흐르다가 복제 경로 입구에서 끊긴다.

`toPayload` 의 `wthrNm` 줄에는 *"촬영환경 수동값 — 포털 복제 반영"* 주석이 달려 있다. 이 지점이 **"포털로 복제할 것"을 고르는 자리**이며 과거 컬럼 추가 때 갱신된 이력이 있음을 보여준다 — 이번 컬럼에서 그 갱신을 놓친 것이 결손의 실체다.

## §2 변경 요지

발신함 payload 축 3단(`toPayload` → `MetaReplicationPayload` → `toSnapshot`)에 이벤트 어노테이션 동결값을 태워, 동결 시점의 값이 포털 복제본까지 끊김 없이 도달하게 한다. 선행 CO 가 고친 ④ 와 합쳐져 비로소 경로가 완성된다.

함께 **payload 축 재발 방지 가드**를 넣는다 — 엔티티 컬럼 ↔ payload 계약 ↔ 복원 빌더의 커버리지를 고정해, 다음에 컬럼이 늘 때 어느 단이 빠지면 테스트가 실패하게 한다.

## §3 도메인별 변경 상세

### DOMAIN-013 (포털) — `klid-d013-implementer`

- **대상 파일·심볼**
  - `backend/src/main/java/kr/co/cudo/authoring/dataset/service/DatasetVideoMetaSnapshotService.java` — `toPayload`(private)
  - `backend/src/main/java/kr/co/cudo/authoring/dataset/worker/MetaReplicationPayload.java` — record 컴포넌트
  - `backend/src/main/java/kr/co/cudo/authoring/dataset/worker/MetaReplicationWorker.java` — `toSnapshot`

- **변경**
  1. `MetaReplicationPayload` 에 이벤트 어노테이션 동결값 컴포넌트를 추가한다. 위치는 엔티티·INSERT 문과 같은 자리(촬영환경 `wthrNm` 다음, 검수완료일시 `rvwCmplDt` 앞)로 맞춰 세 축의 순서를 일치시킨다.
  2. `toPayload` 에 대응 항목을 같은 위치에 넣는다. 인접 항목들처럼 엔티티 getter 에서 읽는다.
  3. `toSnapshot` 의 빌더에 대응 호출을 추가해 payload 값이 엔티티로 복원되게 한다.
  4. 세 지점에 `@design INT-009` 태그를 남긴다.

- **불변(건드리면 안 되는 것)**
  - ★**동결 스냅샷 생성과 해시 계산에 손대지 말 것.** 둘 다 이미 이 값을 올바르게 반영하고 있다(빌더 `.evntAnnoCn(...)` · 해시 입력 맵 `EVNT_ANNO_CN`). **해시 입력이 바뀌면 재승인 멱등성이 깨져 기존 스냅샷이 전부 다른 해시가 된다** — 이번 변경은 payload 직렬화 축에만 국한된다.
  - 발신함 적재 트리거·워커 폴링 주기·재시도·dead-letter 전이 — 무변경.
  - 선행 CO 가 고친 `upsertSnapshot` — 이미 올바르며 다시 손대지 않는다.
  - 포털 복제본 DDL — 컬럼이 이미 존재한다. 마이그레이션 불필요.
  - 멱등 규약(`ON CONFLICT (RAW_SN, SNPSHT_HASH) DO NOTHING`)과 활성 1건 불변식.
  - 복제본 미구축 환경의 graceful skip.

- **주의**
  1. ★**`toPayload` 는 `dataset/service` 에 있어 D005(검수 승인)·D010(export)과 파일을 공유한다.** 그러나 이 메서드는 **발신함 payload 직렬화 전용 private 헬퍼**이고 발신함 저장 지점 한 곳에서만 호출되며, 동결·해시 축과 분리돼 있다. **그 메서드 밖의 어떤 것도 건드리지 말 것.** 다른 부분을 손대야 할 상황이 오면 `notes_for_main.cross_domain` 으로 올린다.
  2. **payload 는 발신함에 문자열로 적재되는 전송 계약이다.** 이미 적재된 기존 발신함 행에는 이 키가 없으므로, **복원 시 키 부재를 오류로 다루지 말 것**(null 로 복원되어야 한다). 역직렬화가 미지의/누락 키에 관대한지 확인하고, 아니라면 그 관대함을 깨지 않는 방식으로 추가할 것.
  3. **dialect 결합은 이 축에 없다.** 문자열 직렬화라 RDB 문법과 무관하다. 선행 CO 의 SQL 축과 달리 MariaDB 검토의 영향을 받지 않는다. ⚠ **2026-08-28 정정** — 그 MariaDB 검토 자체가 **기각**됐다(포털 DB 도 PostgreSQL 확정). 이 축이 dialect 와 무관하다는 판단은 그대로 유효하다. 근거는 `INT-009`.
  4. 세 축의 **필드 순서를 일치**시킬 것. 순서가 어긋나도 기능은 동작하지만, 다음 사람이 세 파일을 나란히 읽으며 대조하기 어려워진다.

- **수용기준**
  1. 동결 시점에 이벤트 어노테이션이 있는 영상을 승인해 발신함에 적재하면, 그 payload 문자열에 해당 값이 포함된다.
  2. 워커가 그 발신함 행을 처리하면 포털 복제본 행의 해당 컬럼에 **동일한 값**이 적재된다(end-to-end).
  3. 동결값이 null 인 경우에도 적재·복원·복제가 실패하지 않고 컬럼이 null 로 적재된다.
  4. **이 키가 없는 기존 발신함 행**도 오류 없이 처리되고 해당 컬럼이 null 로 적재된다(하위호환).
  5. 해시 계산 결과가 이번 변경 전후로 **동일**하다(재승인 멱등성 보존).
  6. payload 축 재발 방지 가드가 추가되어, 엔티티 컬럼이 늘었는데 payload 계약이나 복원 빌더가 따라오지 않으면 테스트가 실패한다.

## §4 영향·리스크

- **하위호환**: payload 는 발신함에 적재된 문자열이다. 이 변경 이전에 적재되어 아직 처리되지 않은 행에는 새 키가 없으므로 **복원 시 null 로 처리돼야 한다**(수용기준 4). 이것이 깨지면 미처리 발신함이 전부 실패로 돌아 dead-letter 로 간다 — **이번 변경의 최대 리스크**다.
- **해시 불변**: 해시 입력은 이번 변경 대상이 아니다. 만약 해시가 달라지면 기존 동결 스냅샷이 전부 다른 해시로 인식돼 재승인 멱등성이 깨지고 중복 스냅샷이 쌓인다. 수용기준 5 로 고정한다.
- **소급 적용 없음**: 이미 복제되어 값이 비어 있는 행은 그대로 둔다(사용자 확정). 이번 변경은 **이후 동결·복제분**부터 적용된다.
- **되돌리기**: 세 지점의 추가분을 제거하면 원상 복귀된다. 데이터 손실이 없다.

## §5 검증

- **end-to-end**: 동결 → 발신함 적재 → 워커 폴링 → 포털 복제본까지 값이 도달하는지. 선행 CO 의 SQL 축만으로는 확인되지 않던 구간이다.
- **하위호환**: 새 키가 없는 발신함 payload 를 넣고 처리 시 null 복원 + 정상 완주.
- **해시 불변**: 같은 입력에 대해 변경 전후 해시가 동일.
- **기존 회귀**: `MetaReplicationWorkerIT` · `MetaReplicationWorkerFailureIT` · `MetaReplicationUnprovisionedPortalIT` · `PortalMetaReplicaWriterRecencyIT` · `PortalReplicaWriteGuardTest` · `PortalMetaReplicaColumnParityGuardTest`(선행 CO 신설) 전건 통과.
- ⚠ **알려진 검증 한계**: 통합시험의 control/portal 데이터소스가 같은 컨테이너를 가리켜 **물리 분리가 재현되지 않는다**(기존 클래스 javadoc 이 명시). 값 왕복은 검증되나 "별도 물리 DB 로의 복제"는 미재현이다.
