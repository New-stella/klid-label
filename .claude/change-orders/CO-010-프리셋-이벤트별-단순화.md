## §1 배경

### 사용자 지적 (2026-08-25, 화면 확인 중)

> "왜 배회만 코드로 되어있어? 차라리 이벤트명 (코드) 로 다 통일하는게 나을 수 있을 것 같은데?"
> "프리셋 추가할때 프리셋 이름은 불필요한것 같은데. 그냥 이벤트별 하나의 프리셋만 있으면 될거 같아서."
> "프리셋 설정에 설명도 필요없는것 같아. 심플하게 하자."

### 실측으로 확인한 것

**① 프리셋은 이미 이벤트별 1:1 이다.** `LS_LABEL_PRESET.EVNT_TYPE_CD` 에 UNIQUE 제약(`uk_ls_label_preset_evnt`)이 있어 한 이벤트에 프리셋은 하나뿐이다. 그런데 **이름(`PRESET_NM`)이 NOT NULL + UNIQUE 로 따로 있어** 사람이 매번 지어 넣어야 하고, 그 값은 사실상 이벤트명의 중복이다. 설명(`EXPLN`)도 마찬가지로 채워도 읽는 곳이 없다.

**② 이벤트 표시명을 화면이 역해석하고 있다.** 응답(`PresetResponse`)은 **코드만** 주고, 화면이 이벤트 목록으로 맵을 만들어 이름을 찾은 뒤 **없으면 코드를 그대로 노출**한다. 이 때문에 대분류 `08`(배회)만 코드로 표시된다 — 그 대분류가 설정(`eventtype.excluded-class-codes = ["08"]`)으로 **필터 옵션에서 제외**돼 있어 화면이 쓰는 목록에 없기 때문이다.
- ⚠ **이것은 그 설정의 결함이 아니라 역해석 구조의 결함이다.** 제외는 "필터 드롭다운에 안 보인다"는 뜻이고, 그 유형의 영상은 들어올 수 있으며 프리셋도 정상 매칭된다(미노출 코드는 자기 자신이 필터 키가 된다).
- ⚠⚠ **이 저장소가 명시적으로 금지한 패턴이다.** 표시명 판정의 단일 진실원(`EventTypeDisplayNamePolicy`) javadoc 이 *"화면이 폴백을 재현하면 그것이 곧 두 번째 판정이 되어 갈릴 수 있다(이 저장소의 반복 결함 패턴)"* 고 못박는다. 배회가 코드로 나온 것이 정확히 그 증상이다.

**③ 복제 기능은 이 구조와 충돌한다.** `POST /v1/manage/presets/{id}/clone` 은 이름에 「(복사본)」을 붙이고 이벤트를 비운 프리셋을 만든다. 이벤트별 1:1 이면 그렇게 만든 프리셋은 **어느 영상에도 매칭되지 않는 죽은 행**이다(실제로 옛 개발 DB 에 「쓰러짐 (복사본) (복사본)」 같은 잔재가 남아 있었다).

## §2 변경 요지

프리셋을 **「이벤트 + 라벨 목록」** 둘로 줄인다.

1. 이름(`PRESET_NM`)·설명(`EXPLN`)을 **폐지**한다 — 요청·응답·화면·컬럼 전부.
2. 이벤트(`EVNT_TYPE_CD`)를 **필수**로 만든다 — 이벤트 없는 프리셋은 매칭 대상이 없어 존재 이유가 없다.
3. **복제 기능을 폐지**한다 — 이벤트당 하나뿐이라 복제할 자리가 없다.
4. **이벤트 표시명을 서버가 응답에 실어준다** — 화면의 역해석을 걷어낸다. 화면은 `이벤트명 (코드)` 로 렌더만 한다.

## §3 도메인별 변경 상세

### 공유기반 선처리 (메인 직접, Phase 3.5)

- **대상**: `backend/src/main/resources/db/migration/` — 신규 마이그레이션(현재 최신이 `V16` 이므로 `V17`)

  2. `LS_LABEL_PRESET.EXPLN` DROP

- **선결 조건 (Critical)**: `EVNT_TYPE_CD IS NULL` 인 행이 있으면 NOT NULL 전환이 실패한다. 마이그레이션은 **그 행을 먼저 지운다** — 이벤트에 걸리지 않은 프리셋은 어느 영상에도 매칭되지 않는 죽은 행이므로 보존 가치가 없다(§1 ③). 지운 건수를 `RAISE NOTICE` 로 남긴다.

  - 상용: 프리셋 시드가 없어 0건.
- **불변**: `uk_ls_label_preset_evnt`(이벤트 UNIQUE)·`LS_LABEL_PRESET_CODE` 구조·`uk_ls_label_preset_code_lblid` 는 그대로 둔다.
- **주의**: 새 컬럼을 만들지 않으므로 표준용어·표준도메인 판정은 불필요하다(DROP·제약 변경뿐).

### DOMAIN-010 (라벨링/프리셋) — `klid-d010-implementer`

- **대상 파일·심볼**:
  - `preset/entity/LsLabelPreset.java` — 필드 제거
  - `preset/service/PresetService.java` — `create`·`update`·`clone`
  - `preset/controller/PresetController.java` — `PresetRequest`·`PresetResponse`·`clone` 엔드포인트
  - `preset/dto/PresetView.java`
- **변경**:
  1. **요청 계약**: `PresetRequest` 를 `{eventTypeCd, labelIds}` 로 줄인다. `name`·`description` 필드 **삭제**. `eventTypeCd` 에 `@NotBlank` 추가(기존엔 `@Size` 만 있어 선택이었다). `@Size(max=20)` 상한은 **그대로 유지**한다 — 코드값 표준도메인이 진실원이고 컬럼이 20 이다(넓히지 말 것).
  2. **응답 계약**: `PresetResponse` 에서 `name`·`description` **삭제**, **`eventTypeNm`(이벤트 표시명) 추가**. 표시명은 반드시 `EventTypeDisplayNamePolicy` 를 **재사용**해 서버가 채운다 — 여기서 폴백을 재유도하지 않는다.
     - ⚠ **필터 옵션에서 제외된 유형·비수집 유형도 이름이 나와야 한다.** 화면이 못 푸는 코드를 서버가 대신 푸는 것이 이 변경의 목적이므로, 노출 옵션 목록에 의존하는 조회로 구현하면 배회가 그대로 코드로 남는다.
  3. **복제 폐지**: `POST /v1/manage/presets/{id}/clone` 과 `PresetService.clone` 을 제거한다.
  4. ★**서버의 이벤트 유효성 검증 축도 「등록된 전체 유형」으로 바꾼다.** 지금 저장 경로는 **필터 옵션 축**(`EventTypeService.validFilterKeys()`)으로 매핑값을 검증한다. 화면 드롭다운만 등록 전체로 바꾸고 서버를 그대로 두면 **화면에서 고를 수 있는 값을 서버가 400 으로 거부**한다(제외 대분류가 정확히 그 경우다). 두 축을 같은 원천으로 맞춘다 — 등록 여부 판정의 원천은 이미 존재한다(`EventTypeService` 의 "등록된 전체 유형코드(수집/비수집·제외 무관)").
     - ⚠ **필터 화면의 검증은 건드리지 않는다** — 그쪽은 필터 옵션 축이 맞다.
     - ⚠ 수정 경로는 **매핑값이 실제로 바뀐 경우에만** 검증을 다시 하는 기존 성질을 유지한다(그러지 않으면 나중에 제외 대상이 된 이벤트에 이미 매핑된 프리셋이 라벨만 고치려 해도 통째로 편집 불가가 된다).
- **불변**:
  - 라벨 항목 1~20 제한, 라벨이 마스터를 `LBL_ID` 로 실시간 참조하는 구조, 권한(`REVIEWER`), 나머지 URL·상태코드는 그대로.
  - 프리셋 해석(`PresetLabelLookupService`)은 이름을 쓰지 않으므로 **오토라벨 동작에 영향이 없어야 한다**.
- **주의**:
  - ★**이벤트 UNIQUE 위반의 응답을 정해야 한다.** 이름이 없어지면 사용자가 실수로 같은 이벤트에 또 만들 수 있고, 지금은 DB 제약 위반이 500 으로 샐 수 있다. **입구에서 409** 로 거부하고 어느 이벤트인지 알린다.
  - 기존 데이터의 이름·설명은 마이그레이션으로 **사라진다**. 되돌릴 수 없으나 프리셋의 실질(이벤트↔라벨 매핑)은 보존된다.

## §4 영향·리스크

### 하위호환 — ★breaking change 다

응답에서 `name`·`description` 이 **사라지고** 요청에서 `eventTypeCd` 가 **필수가 되며** 복제 엔드포인트가 **404** 가 된다.

- ⚠ **이 저장소의 FE 는 테스트베드이고 납품 FE 는 외부 팀이 별도로 만든다.** 그 팀이 이 API 를 소비하고 있으면 화면이 깨진다. **구현 전에 외부 팀 통보·합의가 필요하다.**
- 관제 계약면·데이터마트 뷰·export 산출물에는 영향이 없다(프리셋은 오토라벨 입력일 뿐 산출물에 실리지 않는다).

### 되돌리기

컬럼 DROP 은 되돌릴 수 없다. 다만 프리셋의 실질(이벤트↔라벨 매핑)은 보존되므로, 되돌리려면 컬럼을 다시 만들고 이름을 새로 채우면 된다(옛 이름은 복구 불가).

### 확정 — 프리셋의 이벤트 드롭다운은 등록된 전체 유형을 쓴다

**필터 드롭다운과 프리셋 드롭다운은 용도가 다르다.** 필터는 "영상을 걸러 본다"이고 프리셋은 "이 이벤트에 무엇을 검출할지 정한다"이다. 제외 대분류 설정(`eventtype.excluded-class-codes`)은 **필터 옵션에서 감추는 것**이지 그 유형의 영상이 안 들어온다는 뜻이 아니며, 들어오면 오토라벨은 돌아야 한다(미노출 코드는 자기 자신이 필터 키가 되어 프리셋이 정상 매칭된다).

따라서 프리셋 화면의 이벤트 선택은 **필터 옵션이 아니라 등록된 전체 유형**(수집·제외 무관)을 쓴다. 그 조회는 이미 존재한다(`EventTypeService` 의 "등록된 전체 유형코드(수집/비수집·제외 무관)" 축). 그러지 않으면 배회 프리셋이 **표시는 되는데 화면에서 수정할 수 없는** 상태가 된다.

⚠ 이 결정은 필터 화면에 영향을 주지 않는다 — 제외 대분류는 필터에서 계속 감춰진다.

### 리스크

- 이벤트 UNIQUE 충돌이 사용자에게 보이는 유일한 오류가 된다 — 409 안내가 없으면 500 으로 샌다(§3 주의).
- CO-009 와 같은 화면·응답을 건드린다. **CO-010 을 먼저 반영하고 그 위에 CO-009 의 R6(프리셋 화면 COCO 매핑 경고)을 얹는 순서**가 자연스럽다.

## §5 검증

- **AC1** — 프리셋을 만들 때 이름·설명 없이 이벤트와 라벨만으로 생성된다.
- **AC2** — 이벤트를 지정하지 않으면 400 으로 거부된다.
- **AC3** — 이미 프리셋이 있는 이벤트로 다시 만들면 409 로 거부되고 어느 이벤트인지 알려준다.
- **AC4** — 프리셋 목록의 각 항목이 `이벤트명 (코드)` 로 표시되며, **필터 옵션에서 제외된 대분류(배회)도 이름이 나온다**.
- **AC5** — 복제 동선이 화면과 API 양쪽에서 사라진다.
- **AC6** — 이 변경으로 오토라벨 동작(프리셋 해석·검출 라벨 매칭)이 달라지지 않는다(회귀 가드).

**최종 검증**: 전 ITEM 재조회 대조 **`replace` opcode 0** · 폐지 잔재 스윕 0건(`PRESET_NM`·`presetNm`·`validFilterKeys`·`clone`·`복제`).
