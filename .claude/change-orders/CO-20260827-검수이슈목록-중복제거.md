## §1 배경

검수자가 반려하며 사유를 쓰면 **그 사유가 객체 탭의 이슈 목록에도 나타난다.** 사용자 원문: *"반려한다음에 사유를 쓰면 객체 이슈목록에 나와. 객체 이슈목록에 나올거면 이슈 메타는 있을 필요가 없잖아."*

### 실제로 벌어지는 일 (전말)

```
객체 탭에서 이슈 추가 모드로 캔버스 라벨을 찍고 검수 의견을 쓴다
  → 반려 시 그 둘이 반려 사유 문자열 하나로 합성되어 서버로 간다
  → 서버가 반려 스레드를 만든다 → 「이슈」 탭에 표시된다
  → 동시에 검수 화면이 그 스레드를 되가져와 → 「객체」 탭 이슈 목록에도 표시된다
```

즉 **같은 데이터가 두 탭에 그려진다.**

### 무엇이 중복이고 무엇이 아닌가 (Critical — 범위를 좁혀 잡는다)

객체 탭 하단 패널(`ReviewMemoPanel`)은 네 부분으로 되어 있고, **성격이 갈린다.**

| 부분 | 성격 | 처리 |
|---|---|---|
| 이슈 추가 모드 토글 | **반려 사유 작성 도구** — 캔버스 라벨을 찍어 지적을 쌓는다 | **유지** |
| 아직 안 보낸 지적 목록 | **반려 사유 초안** — 반려 시 사유 문자열로 합성된다 | **유지** |
| 서버 등록 이슈 목록 | **이슈 탭과 같은 데이터** | **제거** |
| 검수 의견 입력칸 | **반려 사유 작성 도구** — 반려 시 사유에 합성된다 | **유지** |

⚠ 지금은 **아직 안 보낸 지적**과 **서버 등록 이슈**가 **한 목록에 섞여** 그려진다. 목록을 통째로 지우면 검수자가 자기가 쌓은 지적을 확인·수정·삭제할 수단이 함께 사라진다. **서버 등록분만 빼고 초안은 남긴다.**

⚠ **「이슈」 탭을 없애는 방향이 아니다.** 그쪽이 정본이며 댓글·해소·문의 등록이 전부 그 탭에 있다. 없애면 그 기능이 함께 사라진다(사용자 확정: 객체 탭 쪽을 제거).

## §2 변경 요지

1. 객체 탭 하단 패널에서 **서버 등록 이슈 표시분을 제거**한다. 이슈 열람·댓글·해소·문의 등록은 「이슈」 탭이 단독으로 담당한다.
2. 남는 목록이 **반려 사유 초안**임이 드러나게 제목·건수 표기를 고친다(제목이 그대로 「이슈 목록」이면 이슈 탭과 같은 것으로 계속 오해된다).
3. 반려 사유 합성 동작은 **그대로 둔다** — 초안이 반려 시 사유로 합쳐지는 경로는 변경 없다.

## §3 도메인별 변경 상세

### 프론트 (SCREEN-019) — `klid-web-implementer`

- **대상 화면·컴포넌트**
  - `frontend/src/features/review/components/ReviewMemoPanel.tsx` — 목록 구성·제목·건수
  - `frontend/src/pages/ReviewPage.tsx` — 이 패널에 서버 이슈를 넘기던 배선

- **소비 API 계약**: 변경 없음.
  - ⚠⚠ **정정 (2026-08-27 구현 중 실증)** — 착수 시 *"서버 이슈 조회 자체는 「이슈」 탭 배지 건수 계산에 계속 쓰이므로 호출을 없애지 않는다"* 고 적었으나 **근거가 틀렸다.** 배지의 미해소 건수는 그 조회가 아니라 **다른 훅(이슈 스레드 조회)** 으로 계산된다.

- **변경**
  1. 객체 탭 하단 패널이 **서버 등록 이슈를 받지 않게** 하고, 그 표시 분기를 제거한다.
  2. 남은 목록의 제목·건수를 **반려 사유 초안**임이 드러나게 고친다(예: 「반려 사유에 첨부할 지적」). 건수는 초안 건수만 센다.
  3. 빈 상태 안내 문구도 그 성격에 맞게 고친다(현행은 이슈가 하나도 없을 때의 문구다).
  4. 서버 이슈 조회 **모듈 자체는 존치**한다(다른 컴포넌트가 참조). 다만 **이 화면 안의 유일 소비처가 사라져 사문이 된 호출**은 함께 걷어낸다 — 남기면 미사용 오류 + 화면이 쓰지도 않는 요청이 매 진입마다 나간다.

- **불변**
  - **반려 사유 합성 로직을 바꾸지 않는다** — 검수 의견 + 초안 지적이 사유 문자열로 합성되는 형식·순서가 그대로여야 한다. 이 형식은 서버에 저장되는 텍스트라 바뀌면 과거 반려와 표기가 갈린다.
  - 이슈 추가 모드 토글과 캔버스 연동(모드가 켜져 있을 때 라벨 클릭으로 초안이 쌓이는 동작)을 유지한다.
  - **「이슈」 탭은 손대지 않는다** — 댓글·해소·문의 등록·미해소 배지 전부 그대로.
  - 검수 의견 입력칸과 글자수 상한을 유지한다.
  - 첨부파일 준비 중 안내는 이번 범위가 아니다(그대로 둔다).

- **주의**
  - ⚠⚠ **구 주의 「서버 이슈 조회 자체를 지우지 말 것 — 배지가 죽는다」는 폐기.** 실측 결과 배지는 **다른 훅**으로 계산되어 이 조회와 무관하다. 배지 건수는 불변이며 기존 가드가 그것을 고정한다. **이 조치를 「지시 위반」으로 되돌리지 말 것.**
  - ⚠ 그래도 **훅 모듈 자체는 지우지 않는다** — 이 화면 밖에 참조가 남아 있다.
  - ⚠ 초안 목록의 항목 편집·삭제 동작이 서버 이슈와 같은 렌더 경로를 쓰고 있으면, 분리하면서 **초안 쪽 편집·삭제가 끊기지 않는지** 확인한다.

- **수용기준**
  - 반려 후 객체 탭을 열면 **그 반려 사유가 객체 탭에 나타나지 않는다**(「이슈」 탭에만 있다).
  - 이슈 추가 모드로 쌓은 지적은 **객체 탭에서 그대로 보이고 수정·삭제된다**.
  - 반려를 실행하면 검수 의견 + 초안 지적이 **변경 전과 같은 형식의 사유 문자열**로 전송된다.
  - 「이슈」 탭의 미해소 배지 건수가 **변경 전과 동일**하다.
