# CO-20260902 — 포털 라벨링 화면 통합

> 상태: 설계 확정 · 구현 미착수
> 근거: 2026-09-02 사용자 확정 (구속) — *"하나로 합치면 될것 같고. 저장처 내려받기가 라벨링 화면에 있을 필요는 없을 것 같은데"*

## 1. 무엇을 왜

포털에 라벨링 화면이 **둘** 있었다.

| | 포털 라벨링 | 포털 업로드 라벨링 |
|---|---|---|
| 대상 | 데이터마트에서 불러온 영상 | 본인이 올린 영상의 프레임 |
| 저장처 | 포털 전용 오버레이(단방향) | 자기 자산에 그대로 |
| 메타 다섯 축 | 있음 | **없음** |
| 내려받기·내보내기 | 없음 | 있음 |

작도 도구·미제공 범위·캔버스 코어는 **같았다.** 갈린 실질은 「자산 출처」 하나였는데,
그 축이 **메타 다섯 축의 유무**까지 갈라 놓은 것이 어긋난 지점이었다 — 촬영환경·프레임 설명은
본인이 올린 영상에도 붙일 수 있어야 한다. 마킹을 붙이면 더 그렇다.

## 2. 확정

1. **라벨링 화면은 하나다.** 자산 출처와 무관하게 같은 화면에서 라벨링한다.
2. **저장처는 화면이 가르지 않는다.** 서버가 자산 출처로 판정한다 — 데이터마트 자산은 오버레이에,
   본인 업로드 자산은 자기 자산에. 화면은 그 차이를 알 필요가 없다.
3. **내려받기·내보내기를 라벨링 화면에서 뺀다.** 목록 화면이 담당한다.
4. **메타 다섯 축은 통합 화면이 갖는다** — 자산 출처를 가리지 않는다.

## 3. 귀결

- 통합의 바탕은 **기존 포털 라벨링 화면**이다(섹션이 더 완비돼 있고 메타 다섯 축을 이미 갖췄다).
  업로드 라벨링 화면의 고유 요소 중 **프레임 이동**은 흡수하고 **내려받기 두 가지는 목록으로 옮긴다.**
- **업로드 라벨링 화면은 폐기**한다. ⚠ 화면정의서는 폐기 시 다운로더가 별도 보관하므로,
  **상태를 내리기 전에 최종 본문을 한 번 받아 둔다**(보관본은 폐기 처리 *이전* 판이다).
- **경로가 하나로 준다.** 업로드 자산도 이미 공용 원장에 앉으므로 식별자 체계가 같다 —
  자산 식별자 하나로 두 출처를 모두 연다.
- **내 업로드 목록**이 내보내기·원본 내려받기를 받는다.
- **마킹 화면에서 라벨링으로 가는 자리도 통합 화면을 가리킨다.**
- 내비게이션에서 업로드 라벨링 노드가 빠진다.

## 4. 아직 안 정한 것

- 통합 화면이 **자산 출처를 사용자에게 보여줄지** — 저장 방식이 다르므로(원본을 못 고치는 쪽과
  고칠 수 있는 쪽) 사용자가 알아야 할 수도 있다.
- 데이터마트 자산에도 **내려받기를 줄지** — 지금은 없다. 목록으로 옮기면서 축이 드러난다.
