## §1 배경

외부에서 **이벤트 마킹까지 끝낸 영상 묶음**을 백 건 단위로 받는다. 마킹 결과는 영상마다 문서 한 건(JSON)으로 오고, 그 문서가 자기가 가리키는 영상의 파일 이름을 스스로 적어 둔다. 영상 한 건이 수백 MB라 사람이 브라우저로 한 건씩 올릴 수 없고, 문서와 영상이 같은 자리에 나란히 놓여 있다는 보장도 없다(제공처마다 폴더 구조가 다르다).

**설계는 2026-09-03 기준 확정돼 있으나 코드는 0건이다.** 실측:

- `grep "imports/markings" backend/src frontend/src` → 0건
- `ADR-052`·`ADR-053`·`API-216~218`·`SEQ-030` 의 `@design` 태그 → 0건
- `LsMarking` 의 상태 상수에 `RESERVED` 없음(현재 `PENDING`·`VLM_REQUESTED`·`VLM_COMPLETED`·`VLM_FAILED`·`SKIPPED`)
- `transfer/` 패키지는 **라벨링 완료 갈래만** 구현돼 있고 산출물 종류 개념 자체가 없다

즉 이 CO 는 기존 동작 수정이 아니라 **확정된 설계의 최초 구현**이다.

### 기존 이관(라벨링 완료)과 방향이 반대다

| | 라벨링 완료 이관 (구현됨) | 이벤트 마킹 이관 (이 CO) |
|---|---|---|
| 받는 것 | 라벨링이 **끝난** 결과 | **시작점**(마킹)만 |
| 이후 | 검수만 | 비식별 → 마킹 활성 → 배치 → 라벨링 → 검수 (앞 단계 전부) |
| 입력 | 폴더 1개 + 영상 1건 | 폴더 1개 안의 **N쌍**을 재귀로 훑음 |
| 응답 | 동기 | **202 후 비동기 건별** |

`ADR-053` 이 *"두 갈래는 방향이 반대라 계약을 합치지 않으며 화면에서만 갈래를 고른다"* 로 못 박았다. **기존 `API-205`/`API-206` 계약을 건드리지 말 것.**

## §2 변경 요지

1. 산출물 가져오기 화면(`SCREEN-039`) 맨 위에 **「산출물 종류」 select** 를 세운다(기본 = 라벨링 완료). 이벤트 마킹을 고르면 입력·결과 영역이 갈린다. 이관 이력은 두 갈래 공통이라 종류 바깥에 두어 항상 보인다.
2. 창구 3종 신설 — `API-216` 폴더 검사(REVIEWER, 저장 없음) · `API-217` 일괄 적재(**ADMIN**, 202) · `API-218` 진행 조회(REVIEWER).
3. 일괄 작업 원장 2표 신설 — `LS_EBLC_ULD_JOB` + `LS_EBLC_ULD_JOB_ARTCL`(`ERD-032`).
4. 마킹에 **예약 상태 `RESERVED`** 를 도입한다(`ADR-052`). 적재 시 예약으로 만들고, 비식별이 끝나 영상이 `MARKING_READY` 가 되면 활성(`PENDING`)으로 전이시켜 이후 처리를 시작한다. 사람이 마킹을 다시 찍지 않는다.
