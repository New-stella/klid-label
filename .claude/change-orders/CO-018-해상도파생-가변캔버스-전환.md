## §1 배경

사용자가 **"해상도 증강을 할 때 비율이 안 맞으면 좌우에 블랙화면이 씌워지는 것 같다"** 고 보고했다.

관찰은 정확하며, **결함이 아니라 현재 확정 동작**이다. 해상도 파생 프리셋은
`RESL_1080P(1920×1080)` · `RESL_720P(1280×720)` · `RESL_480P(854×480)` 로 **전부 16:9 고정
캔버스**다. 원본이 16:9가 아니면 균일 배율 `min(targetW/srcW, targetH/srcH)` 로 축소·확대한 뒤
**남는 영역을 불투명 검정으로 채운다**(레터박스/필러박스).

- 판정기: `common/util/LetterboxTransform.of(srcW, srcH, targetW, targetH)`
- 칠하는 곳: `video/service/port/Java2DImageResizer.resize` — `g.setColor(Color.BLACK); g.fillRect(...)`
- 라벨 좌표도 **같은 계산기**를 써서 `x' = x*scale + offsetX` 로 변환되므로, 지금 픽셀과 좌표는
  서로 어긋나 있지 않다.

**왜 이렇게 됐나**: 더 이전 구현은 축별 독립 배율(`scaleX=targetW/srcW`, `scaleY=targetH/srcH`)로
목표 프레임에 강제로 늘려 **비-16:9 원본을 왜곡**시켰고, 그게 `E-ISSUE-26` 으로 잡혀 종횡비 보존
+ 레터박스로 바뀌었다.

**문제**: 학습데이터 산출물에 검정 띠가 그대로 들어간다. 학습 노이즈이며, 파생본의 유일한 소비자인
관제·데이터마트로 그대로 나간다.

## §2 변경 요지

프리셋을 **고정 캔버스**가 아니라 **크기 상한**으로 재해석한다.

1. 짧은 변을 프리셋 짧은변(**1080 / 720 / 480**)에 맞춘다.
2. 그 배율로 계산한 긴 변이 프리셋 긴변(**1920 / 1280 / 854**)을 넘으면 **그때만** 박스 피팅으로
   클램프한다(`min` 배율로 하강).
3. 산출 캔버스 = **실제 그려지는 크기**. 패딩을 칠하지 않는다 → `offsetX = offsetY = 0`.

종횡비 보존(균일 배율)은 **그대로 유지**한다. 바뀌는 것은 「남는 영역을 검정으로 채우느냐」 하나다.

## §3 도메인별 변경 상세

### DOMAIN-003 (영상·프레임 수집) — `klid-d003-implementer`

**code_root 확장**: 기본 `video/` 에 더해 **`common/util/LetterboxTransform.java` 1개 파일**을
포함한다(경로는 `common/` 이지만 `main` 소비처가 `video/` 뿐인 실질 전용 클래스다 — 전수 확인함:
`ResolutionPreset` · `ResolutionSnapshotService` · `Java2DImageResizer` 3곳).

- **대상 파일·심볼**
  - `common/util/LetterboxTransform` — 배율·오프셋 단일 계산기 (`of` · `isExactFit`)
  - `video/dto/ResolutionPreset` — `width()`/`height()` 의 의미 재정의
  - `video/service/port/Java2DImageResizer.resize` — 패딩 `fillRect` 제거, 캔버스 크기 변경
  - `video/service/ResolutionSnapshotService` — `targetW`/`targetH`·`scaleX`/`scaleY`·`offsetX`/`offsetY` 산정 (약 133~179행)
  - `video/service/ResolutionSnapshot` — record 필드 의미(javadoc)
  - `video/service/VideoResolutionService` — **동일 해상도 스킵 판정** (약 117행) + "적용 가능 프리셋 0개면 400" (약 125~128행)
  - `video/service/ResolutionPersistService.copyScaledLabels` — 좌표 변환 + 추적성 한계 javadoc
  - `video/dto/ResolutionDerivativeResponse` — `targetW`/`targetH` 가 **실제 산출 크기**를 담도록

- **변경**

  1. **배율·캔버스 계산 규칙 (핵심)**
     `LetterboxTransform` 을 가변 캔버스 계산기로 전환한다. 새 규칙:
     ```
     shortTarget = min(presetW, presetH)     # 1080 / 720 / 480
     longTarget  = max(presetW, presetH)     # 1920 / 1280 / 854
     srcShort    = min(srcW, srcH)
     srcLong     = max(srcW, srcH)

     scale = shortTarget / srcShort
     if (srcLong * scale > longTarget) scale = longTarget / srcLong   # 긴변 상한 클램프

     outW = max(1, round(srcW * scale))
     outH = max(1, round(srcH * scale))
     offsetX = offsetY = 0
     ```
     ⚠ **`min(targetW/srcW, targetH/srcH)` 로 되돌리지 말 것** — 그건 박스 피팅이고, 세로 영상을
     `405×720` 처럼 과소 산출한다(사용자가 명시적으로 기각한 안).

     ⚠ **클램프 분기는 `>` 로 판정하되 부동소수 반올림에 주의한다.** 두 배율 중 작은 쪽을 취하는
     형태(`scale = min(shortTarget/srcShort, longTarget/srcLong)`)로 쓰면 분기 없이 동일 결과가
     나오므로 그 형태를 권장한다 — **단 그것이 「짧은변 우선 + 긴변 상한」과 수학적으로 같음을
     테스트로 고정**할 것(박스 피팅과 혼동하기 쉽다: 박스 피팅은 `min(targetW/srcW, targetH/srcH)`
     로 **축을 원본 방향에 맞추지 않는다**. 새 규칙은 짧은변/긴변으로 **정렬한 뒤** 비교한다).

  2. **클래스명·문서 정합** — `LetterboxTransform` 이라는 이름은 패딩이 사라지면 사실과 어긋난다.
     개명 여부는 **에이전트가 판단하지 말고 그대로 두고**, javadoc 만 새 규칙으로 갱신한다
     (개명은 소비처·테스트·설계 ITEM 을 함께 흔들므로 별도 결정 사항이다). 판단이 필요하면
     `notes_for_main` 으로 올린다.

  3. **패딩 제거** — `Java2DImageResizer.resize` 에서 캔버스를 `outW×outH` 로 만들고
     `drawImage(source, 0, 0, outW, outH, null)` 로 그린다. `fillRect(BLACK)` 는 제거한다.
     ⚠ `BufferedImage.TYPE_INT_RGB` 유지(알파 없음 — 기존과 동일).

  4. **스킵 판정 전환** — `preset.width()==srcW && preset.height()==srcH` 는 가변 캔버스에서
     성립하지 않는다. **`outW==srcW && outH==srcH`**(= 배율 1.0)로 바꾼다.
     ⚠ 반올림 때문에 배율이 정확히 1.0 이 아니어도 산출 크기가 원본과 같아질 수 있으므로,
     **배율 값이 아니라 산출 크기로 판정**한다.
     "적용 가능 프리셋 0개면 400" 규칙과 그 메시지도 새 판정에 맞춰 유지한다.

  5. **응답 DTO** — `ResolutionDerivativeResponse.targetW/targetH` 에 **실제 산출 크기**를 담는다.
     예약 시점에 이미 `VideoResolutionService` 가 첫 프레임 실측으로 `srcW/srcH` 를 얻으므로
     계산 가능하다(신규 조회 불필요).

  6. **추적성 한계 javadoc 정정** — `ResolutionPersistService.copyScaledLabels` 의
     *"매핑 행만 보고 오프셋을 역산할 수 없다 … 오프셋 컬럼 신설은 후속 과제"* 는 **소멸한다**
     (offset 이 항상 0). 그 문단을 새 사실로 갱신하고, 후속 과제 표기를 지운다.

- **불변(건드리면 안 되는 것)**
  - **종횡비 보존(균일 배율)** — 축별 독립 배율(`scaleX≠scaleY`)로 되돌리는 것은 `E-ISSUE-26` 이
    폐기한 왜곡이다. 왜곡 방지 회귀 가드가 있으면 **의도를 유지**하고 기대값만 새 규칙으로 정정한다.
  - `LS_DATA_AUG.AUG_TYPE_CD` 값 3종(`RESL_1080P/720P/480P`)과 부분 유니크 인덱스
    `UK_LS_DATA_AUG_RESL` — 그대로.
  - `LS_DATA_AUG_LBL_MAP.COORD_RECALC_YN/SCALE_X/SCALE_Y` 컬럼 — 그대로 쓴다. **신규 컬럼 금지**
    (offset 이 0이 되어 오히려 이 컬럼만으로 완전 역산이 가능해진다).
  - 업스케일 허용 정책 — 현행 유지(구 `targetH>=srcH` 거부 가드는 이미 제거됨, 되살리지 말 것).
  - 파생 깊이 1 고정(`ADR-023`) · 비식별 신고 무관 정책 · 부모 게이트 3곳 — 무관하므로 손대지 않는다.
  - 비디오 파일은 여전히 **복사만** 한다(재인코딩 없음). 프레임 이미지만 리스케일.

- **주의**
  - **기존 파생본은 재생성하지 않는다**(사용자 확정). 검정 패딩이 든 채 존치하고 **신규 생성부터**
    새 규칙을 적용한다. 백필 마이그레이션을 만들지 말 것.
  - `LetterboxTransform.isExactFit()` 의 유일한 소비처는 테스트 1건이다
    (`ResolutionLetterboxTest`). 새 규칙에서는 offset 이 항상 0이라 **항상 true** 가 되어 의미를
    잃는다 — 제거하거나 의미를 재정의하되, **판단을 `notes_for_main` 으로 올리고 임의 삭제하지 말 것**.
  - 테스트에서 "패딩이 있다 / offset 이 0이 아니다"를 단언하는 케이스는 새 규칙에 맞게 **정정**한다.
    ⚠ 케이스를 **삭제하지 말고** 새 기대값으로 바꾸거나, 폐기해야 한다면 폐기 사유를 명시한다.
    관련 테스트: `ResolutionLetterboxTest` · `ResolutionSnapshotServiceTest` ·
    `ResolutionPersistServiceTest` · `VideoResolutionServiceTest` · `ResolutionFileMaterializerTest` ·

  - `docs/test-cases/` 카탈로그에 해당 케이스가 있으면 **같은 커밋에서** 갱신한다(폐기 표기 포함).

- **수용기준** (`AC-003` 갱신 대상 — Phase 3.6 확정본을 따를 것)
  - 720p 프리셋 기준 산출 크기: `1920×1080 → 1280×720` · `1440×1080 → 960×720` ·
    `640×480 → 960×720` · `1080×1920 → 720×1280` · `2560×1080 → 1280×540`
  - 산출 이미지 어느 픽셀도 패딩으로 채워지지 않는다(경계 픽셀이 원본에서 유래).

## §4 영향·리스크

- **하위호환**
  - **관제 계약면 영향 없음** — `V_COMPLETED_VIDEO.RESL` 은 **비디오 파일 기준**이고 해상도 파생은
    비디오를 **복사만** 하므로 프레임 폭이 가변이 돼도 그 컬럼은 바뀌지 않는다.
    `LS_DATA_AUG.AUG_TYPE_CD=RESL_*` 도 라벨이라 그대로다.
  - `POST /v1/videos/{rawSn}/resolution` 의 **요청 스키마·상태코드는 불변**. 응답 `targetW/targetH`
    의 **값이 달라질 뿐 타입·필드는 불변**(FE 는 표시만 하므로 무영향).
  - 기존 파생본·기존 라벨 좌표는 **손대지 않는다**.
- **되돌리기** — 순수 계산 로직 변경이라 커밋 revert 로 원복된다. 데이터 마이그레이션이 없어
  롤백에 비가역 지점이 없다. 단 **되돌린 뒤 생성된 파생본은 다시 패딩을 갖는다**.
- **리스크**
  - 새 규칙을 박스 피팅으로 잘못 구현하면 세로 영상이 과소 산출된다(사용자가 기각한 안).
  - 스킵 판정을 안 고치면 `preset.width()==srcW` 가 가변 캔버스에서 의미를 잃어, 배율 1.0인
    프리셋이 스킵되지 않고 **원본과 동일한 파생본이 생성**된다.
  - 좌표 변환에서 offset 가산을 남겨두면 라벨이 통째로 어긋난다(offset 이 0이라 실해는 없으나
    죽은 경로가 남는다).

  회수 후 결정.
- **기존 파생본 재생성** — 사용자가 「존치」로 확정했다. 필요해지면 별도 CO.
