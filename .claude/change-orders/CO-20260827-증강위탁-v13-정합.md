## §1 배경

외부 생성형 AI 에 증강을 위탁할 때 보내는 요청 본문이 **낡은 계약 형태**다. 정본은
`docs/연동규격서/생성형AI_API연동정의서_v1.3.pdf`(갱신일 2026-08-12)인데 코드는 그 이전 형태로
보내고 있어, **실벤더에 붙는 순간 요청이 전량 거부된다.**

v1.3 이 바꾼 것은 요청 본문의 구조다. 생성 조건 다섯 항목을 최상위 `mtdt` 객체로 옮기고,
자유 지시문을 별개 최상위 `prompt`(문자열)로 분리했다. 구 객체 형식(`prompt.condition`/
`prompt.text`)과 최상위 `condition` 은 **표준 계약에서 제외**됐고, 명세가 *"prompt 값으로 객체를
전달하지 않습니다"* 를 명시하며 오류표에 `400 INVALID_PARAMETER — 미지원 조합, I2I 입력 파일
누락, mtdt 형식·허용 코드` 가 있다.

**지금 로컬에서 안 터지는 이유**는 목 서버가 옛 계약으로 연기하기 때문이다. 즉 **로컬 테스트를
아무리 돌려도 드러나지 않는다.** 연동 모드 공통 기본값이 `http` 라 local 은 실배선이고
dev/stg/prd 만 명시 `noop` 이다("전 환경 noop" 은 낡은 서술).

코드 실측(2026-08-27):
- `augment/integration/dto/GenAiJobSubmitRequest` 의 `prompt` 가 `Map<String,Object>` 객체
- **`mtdt` 는 backend 전체 grep 0건**
- 같은 파일 javadoc 이 v1.1 을 근거로 인용
- `AugmentSubmitCommand.evntType` 이 **관제 이벤트 유형 코드**(`LS_DATA_RAW.EVNT_TYPE_CD`)를 나른다

## §2 변경 요지

요청 본문을 v1.3 형태로 바꾼다. 생성 조건은 최상위 `mtdt` 로, 자유 지시문은 별개 `prompt`
문자열로 분리한다. 생성 조건 다섯 항목은 자유 문자열에서 **허용 코드 선택**으로 바꾸고, 이벤트
유형도 관제 코드 조달을 그만두고 **요청 화면에서 고른 값을 그대로 중계**한다. 보관값도 나간 값과
같은 분리 형태로 남기고, 목 서버를 v1.3 검증으로 올려 로컬에서 실제로 걸리게 만든다.

## §3 도메인별 변경 상세

### DOMAIN-007 (데이터 증강) — `klid-d007-implementer`

- **대상 파일·심볼**
  - `augment/integration/dto/GenAiJobSubmitRequest` (record)
  - `augment/integration/AugmentPrompts` (조립 단일 지점)
  - `augment/integration/HttpExternalAugmentClient#toRequestBody`
  - `augment/integration/AugmentSubmitCommand` (`evntType` 조달 축)
  - `augment/dto/AugmentRequestRequest.PromptFields` (입력 검증)
  - `augment/service/AugmentRequestService` (정규화·보관)

- **변경**
  1. `GenAiJobSubmitRequest` 에서 `prompt`(Map) 를 걷어내고 **`mtdt`**(구조화 객체) + **`prompt`**
     (String, 최대 1000, 선택) 두 필드로 나눈다. javadoc 근거를 v1.3 으로 바꾼다.
  2. `AugmentPrompts` 가 `mtdt` 를 만든다. **키 집합과 순서를 이 한 곳에서만 정하는 기존 성질을
     유지**한다. 허용 코드는 아래 다섯 축이다.
     - `time` — DAWN · DAY · DUSK · NIGHT
     - `season` — SPRING · SUMMER · AUTUMN · WINTER
     - `weather` — CLEAR · CLOUDY · RAIN · SNOW · FOG · WINDY
     - `terrain` — ROAD · UNDERPASS · RIVER · URBAN · RESIDENTIAL · RURAL · MOUNTAIN · FOREST
     - `severity` — LOW · MEDIUM · HIGH
  3. `HttpExternalAugmentClient#toRequestBody` 는 매핑만 한다. **조건을 재조립하지 않고 중계만
     하는 기존 성질을 유지**한다.
  4. `PromptFields` 를 자유 문자열 검증에서 **허용 코드 검증**으로 바꾼다. 허용 코드 밖 값은 400 이다.
  5. **이벤트 유형 조달을 바꾼다** — 지금은 `LS_DATA_RAW.EVNT_TYPE_CD`(관제 코드)를 나르는데,
     v1.3 허용값은 `FLOOD`·`WILDFIRE` 둘뿐이라 관제 코드를 그대로 보내면 역시 400 이다.
     설계(`INT-008`)가 *"이벤트 유형과 생성 조건은 요청자가 화면에서 고른 값을 그대로 중계한다 —
     관제 이벤트 코드에서 변환하지 않고 증강 종류에서 유추하지도 않는다"* 로 이미 정했으므로,
     **요청 본문에서 받아 중계**한다. `evnt_subtype`(침수 하위 5종, 선택)도 함께 받는다.
  6. 보관(`LS_DATA_AUG.PROMPT_CN`, `VARCHAR(4000)`)을 **생성 조건과 자유 지시문을 분리한 형태**로
     남긴다. 설계가 *"나간 값과 보관값이 갈라지지 않게 한다"* 로 규정한다.

- **★두 축을 섞지 말 것 (사용자 지적 2026-08-27)**

  | 축 | 값 | 조달 |
  |---|---|---|
  | **증강 종류** `AUG_TYPE_CD` | WINTER · NIGHT · RAIN (+ 해상도 `RESL_*`) | 요청 DTO 의 **`types[]` enum**. **관제 코드를 쓰지 않는다** |
  | **이벤트 유형** `evnt_type` | FLOOD · WILDFIRE (벤더 계약값) | **이번에 바꾸는 축** — 지금은 관제 코드 조달, 앞으로는 요청 화면 입력 |

  이름이 비슷해 섞이기 쉬우나 **전혀 다른 값이고 조달처도 다르다.** 한쪽 변경이 다른 쪽으로
  번지면 아래 방어가 깨진다.

- **불변(건드리면 안 되는 것)**
  - **증강 종류(`AUG_TYPE_CD`)를 생성 조건에서도, 이벤트 유형에서도 파생하지 않는다.** 그 값이 유형 판정에 흘러가면
    산출물 경로 순회(CWE-22)와 해상도 네임스페이스(`RESL_` 접두) 침범이 열린다. 유형의 단일
    원천은 요청 DTO 의 별도 `types[]` enum 이다.
  - **다섯 항목 전부 필수는 우리 규칙이라 유지한다.** 벤더 계약은 "최소 1개"지만, 하나라도 비면
    벤더가 어떤 기본값으로 채울지 몰라 결과가 비결정적이 된다(2026-07-31 사용자 확정).
    **더 엄격한 쪽이 의도된 선택**이다.
  - **콜백 축을 건드리지 않는다** — `POST /v1/genai/callback`(무서명 + IP allowlist · 속도 제한 ·
    request_id 3계층)과 job_id 를 벤더가 발급하는 축은 **이미 v1.3 정합**이다.
  - 입력파일 상한(기본 100장/job)과 초과 시 청크 분할, 4xx 비재시도 분류도 그대로다.

- **주의**
  - 기존 적재분(`PROMPT_CN` 에 옛 객체 형태 JSON)을 읽는 경로가 있으면 깨지지 않게 한다.
    조회 응답(`AugmentResultItemResponse.prompt`·`AugmentSummaryResponse`)이 그 값을 그대로 내려준다.
  - 같은 (영상 × 종류) 파생을 구분하는 **유일한 축이 `PROMPT_CN`** 이다(중복 요청 허용 정책).
    폐기 비석(`LsDataAugDscd.promptCn`)도 이 값을 스냅샷으로 들고 있다.
  - 로컬 검증은 목 서버가 v1.3 을 강제해야 의미가 있다(아래 별도 항목).

- **수용기준**
  - 위탁 요청 본문에 `mtdt` 객체가 최상위로 실리고, `prompt` 는 문자열이거나 아예 없다.
  - 허용 코드 밖 생성 조건은 접수 단계에서 400 이다.
  - 이벤트 유형이 요청 본문에서 오고, 관제 코드에서 변환하지 않는다.
  - 보관값을 다시 읽으면 생성 조건과 자유 지시문이 분리된 형태로 나온다.

### 프론트 (증강 요청 화면) — `klid-web-implementer`

- **대상 화면·컴포넌트**: `frontend/src/pages/AugmentRequestPage.tsx` ·
  `frontend/src/features/augment/{types.ts,promptValidation.ts,api.ts,components/}`
- **소비 API 계약**: `POST /v1/augments/request` — 생성 조건 다섯 항목이 **허용 코드 enum**,
  이벤트 유형 필드 신설(`FLOOD`·`WILDFIRE`), 침수일 때만 하위 유형 선택(선택값).
- **변경**
  - 생성 조건 다섯 항목을 자유 입력에서 **드롭다운 선택**으로 바꾼다.
  - **이벤트 유형 선택을 화면에 신설**한다. 지금은 화면에 없고 서버가 관제 코드를 조달하는데,
    설계가 요청자가 고른 값을 중계하라고 규정한다.
  - 하위 유형은 이벤트 유형이 침수일 때만 노출하고 산불이면 보내지 않는다.
  - 타입 주석에 남은 *"연동명세서가 prompt 를 자유 dict 로만 규정하고 허용값 enum 을 정의하지
    않으므로"* 서술을 v1.3 기준으로 고친다 — 지금은 사실이 아니다.
- **불변**: 다섯 항목 전부 필수는 유지. **증강 종류 선택(`types[]`) · 생성 조건 · 이벤트 유형은
  서로 다른 세 축이며 어느 것도 다른 것에서 유추하지 않는다.** 화면에 이벤트 유형 선택이 새로
  생긴다고 해서 증강 종류 선택을 대체하거나 연동시키지 않는다.
- **수용기준**: 허용 코드 밖 값을 보낼 수단이 화면에 없다. 이벤트 유형을 고르지 않으면 제출되지 않는다.

## §4 영향·리스크

- **하위호환**: 저장된 옛 형태 `PROMPT_CN` 을 읽는 조회 경로가 있다 — 깨지지 않게 한다.
  외부 계약면은 아직 실연동이 없어(dev/stg/prd `noop`) **외부에 미치는 파급은 없다.**
- **되돌리기**: 코드 되돌림으로 충분하다. 마이그레이션이 없어 데이터 되돌림이 필요 없다.
- **리스크**
  - 이벤트 유형 조달 축을 바꾸므로 **화면에서 그 값을 받지 못하면 요청이 성립하지 않는다.**
    백엔드 먼저·프론트 뒤 순서를 지키되, 백엔드만 나간 상태로 배포되지 않게 한다.
  - 허용 코드 전환은 화면 동작이 바뀌는 변경이다(자유 입력 → 선택). 2026-07-31 「자유 문자열」
    확정을 되돌리는 것이며 **2026-08-27 사용자 확정**으로 승인됐다.
