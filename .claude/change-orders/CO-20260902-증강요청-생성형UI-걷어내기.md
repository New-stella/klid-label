## §1 배경

증강 요청 화면(`/augment`)에 **생성형 AI 연동 UI 가 들어가 있다**는 지적이 나왔다. 확인해 보니
화면이 우리 어휘가 아니라 **벤더 API 파라미터 모양으로 서 있었다.**

### 우리가 하는 증강이 무엇인가

**이미 이벤트가 찍혀 있는 영상 프레임을 겨울·야간·우천으로 바꾸는 것**이다. 영상을 새로 만들지 않고
프레임 이미지만 변환하며, 라벨은 원본 좌표를 **그대로 승계**한다(`CLAUDE.md` 「증강 = 새 영상」).

### 그런데 벤더의 「이미지 증강」은 다른 것이었다

`docs/연동규격서/생성형AI_API연동정의서_v1.3.pdf` 실측:

- §4.1 **V0 지원 요청 조합** — `GENERATE/T2I`(이미지 생성) · **`AUGMENT/I2I`(원본 이미지 기반 이미지 증강)** ·
  `GENERATE/T2V`(영상 생성). 우리는 두 번째를 쓴다.
- ★ **그 I2I 예시의 입력 파일이 `"/nas-storage/genai/background_images/20260803/xxxx.png"`** 이고
  prompt 가 *"원본 카메라 시점과 도로 구조를 유지하고 비 오는 여름철 야간 도로 침수 장면으로 변경해줘."* 다.
  ⇒ **벤더의 「이미지 증강」은 배경 이미지에 이벤트 장면을 만들어 넣는 것**이다.
- 그래서 `evnt_type`(`FLOOD | WILDFIRE`)이 **세 조합 공통 Required=Y** 다 — **무슨 장면을 만들지** 정하는 값이니까.
  오류표에 `UNSUPPORTED_EVENT_TYPE`(400) = "FLOOD/WILDFIRE 외 evnt_type".
- ⚠ 규격은 **`evnt_type` 이 결과에 어떻게 쓰이는지 한 줄도 설명하지 않는다**(필수라고만 한다).

즉 화면의 침수·산불은 **우리 요구가 아니라 벤더 API 가 장면 생성 축이라 딸려온 것**이다.

### 두 번째 문제 — 증강 종류 카드 3종이 생성 조건과 중복이다

화면은 겨울/야간/우천 카드를 고르게 한 뒤 **생성 조건 5항목(시간대·계절·날씨·지형·심각도)** 도 함께 받는다.
그런데 겨울 = `season:WINTER`, 야간 = `time:NIGHT`, 우천 = `weather:RAIN` 이라 **카드가 조건의 부분집합**이다.
실제로 "겨울"을 고른 뒤 조건에서 계절을 여름으로 바꿀 수 있어 **카드와 조건이 어긋날 수 있다.**
카드는 사실상 조건의 프리셋 역할밖에 하지 못한다.

## §2 변경 요지

1. **이벤트 유형(침수/산불)과 침수 세부 유형을 화면에서 제거**한다. 벤더 필수 필드 `evnt_type` 은
   **서버가 `ETC` 로 고정 송신**하고 `evnt_subtype` 은 보내지 않는다.
2. **증강 종류 카드 3종(겨울/야간/우천)을 「증강 AI」 하나로 합친다.** 처리 종류 카드는 2장
   (증강 AI · 해상도 변경)이 되고, `AUG_TYPE_CD` 는 **단일값 `AUGMENT`** 다.
3. **생성 조건 5항목과 자유 지시문은 화면에 그대로 둔다.** 무엇으로 바꿀지는 그 조건이 정한다.

### ★★ 발주처 원문 확인 (감리 대응 논거)

### ★ 후속 작업자 필독 함정
**`WINTER`·`NIGHT`·`RAIN` 은 생성 조건 enum 에도 같은 낱말로 존재한다**
(`season=WINTER` · `time=NIGHT` · `weather=RAIN`). 여러 ITEM 에 **두 뜻이 한 문서에 섞여 있어**
일괄 치환하면 정상 계약이 깨진다. 반드시 문맥으로 축을 가른 뒤 증강 종류 축만 고칠 것.
