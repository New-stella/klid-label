### 2-1. Host 인계 창구 수용 (F-1)

Host 는 `<Remote authBridge={...} />` 로 마운트한다(포털 인계문서 2026-09-08 §1). 우리
`AuthoringRemote` 는 props 를 받지 않아 그 객체를 **버리고** 있었고, `registerHostTokenHandoff`
를 부르는 **운영 코드가 0건**이었다(시험만 불렀다). 포털 채널 창구에는 스토어 폴백이 없어
(fail-closed) 토큰이 언제나 `null` 이었다.

- 진입점이 `authBridge` 를 받아 등록한다.
- **효과(`useEffect`)로 미루지 않는다** — 미루면 첫 라우트 가드가 토큰 없이 판정해 인증 안내가
  한 프레임 비친다. 대신 `registerHostTokenHandoff` 를 **멱등**으로 만들어(같은 후보면 즉시 반환)
  렌더에서 불러도 안전하게 했다.
  ⚠ 효과로 옮기면 개발 빌드의 재마운트(mount→unmount→mount)에서 **정리가 등록을 앞질러** 창구가
  빈 채로 남는다. 멱등 렌더 호출은 그 구멍이 없다.

### 2-2. 창구 반환 형태를 동기·비동기 모두 수용 (F-2)

`INT-013` 은 창구 **이름 넷**만 확정하고 **반환 형태를 적지 않았다**. Host 는
`Promise<string | null>` 로 구현했고 그 근거를 인계문서 §3-1 에 적어 두었다 —
*"매 호출 취득·캐시 금지"가 성립하려면 갱신이 오가는 «동안» 옛 토큰을 넘기지 않아야 하고,
동기 반환은 정확히 그 죽은 토큰을 넘긴다.*

우리 타입은 동기였다. 실측으로 F-1 만 고쳐 보니:

```
TypeError: e.split is not a function
    at setToken (AuthoringApp-*.js)
```

JWT 해독이 Promise 객체를 받아 죽고 **Remote 가 통째로 내려앉아** Host 화면이 「저작도구를
불러오지 못했습니다」로 바뀌었다. **F-1 만 고치면 지금보다 나빠진다.**

- 인터페이스를 `string | null | Promise<string | null>` 로 **넓혔다**(좁히지 않았다).
  - 내부(관제) 채널은 스토어를 읽으므로 **동기가 정직하다** — 그대로 둔다.
  - 포털 어댑터가 `await` 로 둘을 흡수한다.
- 읽는 쪽은 모듈 함수 `getAccessToken()` **하나**뿐이고 그것이 `Promise` 를 돌려준다.
- **정규화 + 예외 방어**를 그 한 곳에 뒀다 — 문자열도 `null` 도 아니면 토큰 없음으로 접고(형만
  로그, 값은 절대 안 싣는다), 창구가 던져도 삼킨다. 창구는 **Host 가 구현하는 남의 코드**라
  예외가 새어 나가면 부팅이 멈추는데 그건 「토큰이 없다」보다 나쁜 결말이다.
- 호출부 전이: 요청 인터셉터(2곳) · 세션 되맞춤 · 진입 화면.

★ **관제 채널 부팅 순서는 한 틱도 늦추지 않았다.** 되맞춤이 비동기가 되면서
`sync().then(restoreSession)` 로 이으면 관제에서도 hydrate 가 마이크로태스크 뒤로 밀린다.
그래서 순서를 `portalSession.syncPortalSessionThen()` 안으로 옮겨 **포털만 기다리고 그 밖은
동기로 즉시** 이어가게 했다(채널 판정을 `App` 으로 복제하지 않기 위해서이기도 하다).

### 2-3. 브라우저 호출 접두어를 설정으로 (F-4)

백엔드가 응답 **본문에** 절대 경로를 담아 내려주는 자리가 셋이다.

| 자리 | 쓰임 |
|---|---|
| `VideoStreamService` | 마킹 화면 영상 재생 서명 주소 |
| `PortalUploadStreamService` | **포털 업로드 영상 재생** 서명 주소 |
| `ReviewService` | 검수 프레임 이미지 주소 |

셋 다 `"/api/v1/..."` 를 적고 있었다. 이 주소는 브라우저가 `<video src>`·`<img src>` 에 그대로
무는 값이라 **컨트롤러 매핑이 아니라 「앞단 웹서버가 우리에게 넘겨주는 접두어」**여야 한다.
포털 앞단에서 `/api/v1/` 은 **포털 자신의 WAS** 로 가므로, 그대로 두면 재생 요청이 남의
서버로 날아간다.

- `PublicApiPathDefaults`(키·기본값·정규화·조립) + `PublicApiPathGuard`(기동 시 형식 검증) 신설.
- 세 서비스가 `@Value` 로 받아 `join()` 으로 조립.
- **기본값은 종전 리터럴 `/api/v1` 그대로** — 지정하지 않으면 동작이 한 글자도 바뀌지 않는다.
- 서명 입력은 `rawSn`·`exp`·`userNo`·nonce 이고 **경로가 아니라서** 기존 서명 검증이 깨지지 않는다.
- 가드가 막는 것: 스킴·호스트(CWE-601) · `..`(CWE-22) · 질의·조각 · 공백·제어문자(CWE-117).
  요청 시점에 던지면 오타 하나가 500 폭주가 되므로 **배포 시점에 시끄럽게 실패**시킨다.

## §4 불변 (깨뜨리지 말 것)

- **관제 채널 동작 불변** — 창구는 동기 그대로, 부팅 순서도 동기 그대로. 회귀 가드
  `AppSessionBootstrap.test.tsx` 가 그 순서를 값으로 잡는다.
- **포털 채널에 스토어 폴백을 두지 않는다**(fail-closed). 폴백하면 「창구가 아직 없다」가
  「옛 토큰으로 조용히 돌아간다」가 되어, 막으려던 결함이 장애 상황에서만 되살아난다.
- **인계 창구 이름 4종은 포털이 정한 계약**이다. props 이름 `authBridge` 도 마찬가지다.
- **접두어 기본값 `/api/v1` 을 옮기지 않는다** — 그 상수의 존재 이유가 「설정을 안 하면 지금
  그대로」라는 보장이다.
- **컨트롤러 매핑을 접두어 설정으로 바꾸려 들지 말 것** — 컨트롤러가 어디에 붙는지는 WAR
  컨텍스트가 정하고, 이것은 **브라우저가 부를 주소**를 만드는 별개 축이다.
