# CO-20260903 — 증강 위탁을 전 환경 연동으로 되돌린다 (기동 의존 제거)

- 상태: 착수
- 근거: **사용자 지시(2026-09-03)** — *"다 연동으로 둬. 앱 부팅이랑은 연동이 안 되도 상관없잖아?"*
- 범위: 백엔드(`augment/integration` · 환경 설정 · 온프렘 반입 템플릿)

## 1. 무엇이 잘못돼 있나

**나가는 위탁 하나 때문에 앱 전체가 안 뜬다.**

증강 위탁 클라이언트가 **주소가 비어 있으면 기동을 죽인다**:
```
// 정책 위반이면 IllegalStateException → 빈 생성 실패 → 기동 차단(fail-closed).
urlPolicy.validate(baseUrl);
```

벤더 주소가 아직 없으니 **운영·스테이징·개발이 전부 미연동으로 도망갔다.** 원인을 놔두고 증상을 피한 것이다.

⚠ **fail-closed 를 잘못된 자리에 걸었다.** 막아야 할 것은 **잘못된 곳으로 나가는 것**이지 **기동**이 아니다.
**빈 주소는 「아직 안 정해짐」이지 「위험함」이 아니다.**

## 2. ★선례가 이미 이 저장소에 있다 — 새로 발명하지 마라

**시계열 위탁 클라이언트가 올바른 형태다.**

- 주소가 **있을 때만** 정책 검증을 한다 → 빈 값이면 **기동 정상**
- 대신 **미주입이면 전송 자체를 막는** 필터를 뒀다 → 잘못 나갈 일이 없다
- 그 주석이 이유까지 적어 뒀다(주소가 비면 상대 URI 가 되어 **엉뚱한 곳으로 실제 연결이 나간다**)

**증강만 그 형태를 안 따랐다.** 같은 모양으로 맞춰라.

## 3. 할 일

1. **기동 의존 제거** — 주소가 비어도 기동한다. **위험한 주소는 종전대로 기동 차단**(이 축은 유지).
   미주입이면 **전송을 막는다**(시계열과 같은 자리·같은 방식).
2. **전 환경을 연동으로** — 개발·스테이징·운영 설정에서 미연동 기본값을 걷어낸다.
   **온프렘 반입 템플릿 2종**도 같이 고친다.
3. **개발 환경에 목서버 주소를 주입**한다 — 그 방법이 이미 주석에 적혀 있다. 실제 왕복을 돌려 볼 수 있게.
4. **주소 미주입 시의 동선을 정리**한다 — 지금 관제는 접수를 **막고**(별도 게이트) 포털은 **접수만 된다.**
   두 채널이 겹치거나 어긋나지 않게 **한 축으로** 맞추고 근거를 보고하라.

## 4. 하지 말 것

- **위험한 주소 차단을 함께 걷어내지 마라.** 빈 값과 위험한 값은 **다른 것**이다.
- **미연동 모드(토글) 자체를 없애지 마라** — 「나가면 안 되는 환경」을 위한 스위치는 남는다.
  바꾸는 것은 **기본값과 기동 의존**이다.
- **관제 동작을 무르게 하지 마라.** 관제가 지금 접수를 막는 것은 사용자에게 즉시 사유를 주는 장치다.
- 계약에 없는 상태코드를 임의로 만들지 마라.
- 프론트를 건드리지 마라.

## 5. 수용 기준

1. **주소가 비어도 기동한다.** 되돌림 실증(기동 의존을 되살리면 빨개진다).
2. **위험한 주소는 여전히 기동을 막는다.** 되돌림 실증.
3. **미주입 상태에서 위탁이 나가지 않는다** — 엉뚱한 곳으로 연결이 새지 않는다.
4. 개발·스테이징·운영·온프렘이 **전부 연동 기본값**이다.
5. 회귀 무열화 — 기준선 **8,498 / 실패 0 / XML 936**.
