## §1 배경

사용자가 포털 작업 화면에 이벤트 어노테이션·메타 수정/추가가 들어가야 한다고 요청했고, 우리가
`ADR-013` 을 근거로 그것이 미제공이라고 답하자 다음과 같이 정정했다.

> "VLM/메타 미제공은 **연동이** 미제공 되는거지. 관제서버에서 만든 데이터마트를 로드할때는
> 보여져야 하는거고 수정/추가도 사용자가 직접 할 수 있어야해." · "다른 서버랑 연동이 미제공이라고 봐야해"

**ADR-013 v8 전문을 대조한 결과 이 정정이 문서로 뒷받침된다.**

| 검사 | 결과 |
|---|---|
| ADR-013 에 「메타」 등장 | **0회** |
| ADR-013 에 「VLM」 등장 | **2회뿐** — ①`decision_drivers` 1줄 ②**폐기된 구 옵션(2026-06-01)** 의 description 1줄 |
| 현행 `decision.justification` 의 미제공 목록 | 오토라벨링(YOLO)·SAM2 인터랙티브·자동추적·키포인트·트랙 rename/merge·검수·버전관리 — **VLM 도 메타도 없다** |

그런데 코드는 이렇게 주장하고 있었다:

```
frontend/src/pages/label/LabelingPage.tsx (showMeta 선언 위 주석)
// 메타 탭(프레임 설명 + 시계열 메타)은 내부 채널만 노출 — 포털은 VLM/메타 미제공(ADR-013).
```

**ADR 에 없는 것을 ADR 근거로 주장한 주석이다.** 즉 메타 편집 차단은 결정된 적이 없는 제약이
코드에 자리 잡은 것이며, 그 주석이 근거처럼 읽혀 이후 판단을 계속 오도했다.

## §2 변경 요지

포털 범위를 **두 갈래로** 바로잡는다.

1. **없던 제약 제거** — 데이터마트 로드분의 메타·이벤트 어노테이션 **표시 + 사용자 직접 수정/추가**는
   미제공이 아니다. ADR 에 근거가 없으므로 되돌리는 것이 아니라 **바로잡는 것**이다.
2. **실제 정책 개정** — ①「미제공」의 축이 **외부 서버로 나가는 연동**임을 명확히 하고
   ②**포털 업로드 영상에 한해 이벤트구간 마킹 + AI 증강 연동을 제공**하는 예외를 추가한다.

⚠ 이 CO 는 **근거를 확정하는 단계**다. 실제 기능(포털 메타 편집 API·화면, 포털 업로드 영상
마킹·증강)은 후속 CO 에서 만든다. 여기서는 **동작을 바꾸지 않는다**(`showMeta` 플래그는 그대로 둔다).

## §3 도메인별 변경 상세

### 공유기반 선처리

**해당 없음** — 스키마·`common/`·`batch/`·앱 진입점 변경 0.

### 설계 (Phase 3.6 — 이 CO 의 본체)

`ADR-013` 을 v9 로 개정한다. **신규 ADR 을 만들지 않는다** — 이 ADR 은 이미 예외·반전 이력을 본문에
누적해 온 방식이고(2026-07-17 업로드 예외 · 2026-08-03 SAM2 철회), 한 결정이 여러 ADR 로 갈리면
다음 감사가 헛갈린다.

개정 내용:

1. **`decision_drivers` 의 「오토라벨링·VLM·버전관리·검수는 내부 전용」에서 VLM 의 축을 명확히 한다.**
   미제공인 것은 **외부 VLM 서버로 나가는 위탁 연동(호출·콜백)** 이며, 그 결과물(시계열 메타)을
   화면에 **표시하고 사람이 수정/추가하는 것은 미제공이 아니다.**
2. **`justification` 에 「제공한다」를 명시적으로 적는다** — 데이터마트 로드분의 메타(촬영환경·프레임
   설명·개인정보 3필드·시계열 메타)와 이벤트 어노테이션의 **표시 + 사용자 직접 수정/추가**.
   ⚠ 「미제공 목록에 없으니 제공」이라는 소극적 서술로 두지 말 것 — 그러면 다음 사람이 또 막는다.
   실제로 이번 결함이 정확히 그렇게 생겼다.
3. **단방향 원칙을 함께 못박는다** — 포털에서 고친 메타·어노테이션은 `LS_PORTAL_*` 전용 저장소에
   적재하며 **데이터마트·원본(`LS_DATASET_VIDEO_META`·event_annotation 동결본)을 수정하지 않는다.**
   기존 라벨 저장(`LS_PORTAL_USER_LABEL`)과 같은 축이다.
4. **포털 업로드 영상 예외를 추가한다** — 포털 사용자가 업로드한 영상에 한해 **이벤트구간 마킹**과
   **AI 증강 연동**을 제공한다(2026-07-17 자산 업로드 예외의 연장).
5. ★**SAM2·키포인트 미제공과 왜 다른지를 본문에 적는다 (Critical — 안 적으면 되돌려진다).**
   두 축은 성질이 다르다:
   - **SAM2 인터랙티브·키포인트** = 포털 사용자가 **직접 호출하는 추론 엔드포인트**. 외부 채널
     공격면이라 2026-08-03 보안 2차 전수검증에서 HIGH 로 제거됐다. **이 판정은 그대로 유효하며
     이 CO 는 그것을 건드리지 않는다.**
   - **AI 증강 연동** = **서버가 서버로 보내는 비동기 위탁**. 포털 사용자가 외부 추론 엔드포인트를
     직접 때리는 구조가 아니다.
   이 구분을 안 적으면 다음 감사가 **"SAM2 는 막았는데 증강은 왜 여느냐"로 예외를 되돌린다** —
   이 저장소에서 반복된 패턴이다.
6. **`consequences` 갱신** — 포털·내부의 기능 격차가 줄어드는 대신 포털 전용 저장소·API 표면이
   늘어난다는 대가를 적는다.

⚠ **건드리지 않는 것**: SAM2 인터랙티브·자동추적·키포인트·트랙 rename/merge·오토라벨링(YOLO)·
검수·버전관리 미제공은 **그대로 유지**한다. 2026-08-03 보안 판정 서술과 2026-07-15 반전 이력도
지우지 말 것(본문이 명시적으로 보존을 지시한다).

**cascade 예상 하위**: `DOMAIN-013`(도메인 범위 서술) · `SCREEN-029`(포털 라벨링 화면 — 메타 패널
노출 여부 서술이 있으면) · `SCREEN-033`(포털 업로드 화면 — 마킹·증강 동선이 생기면) ·
`UC-024`·`UC-027` · `ROLE-003`(PORTAL_USER 권한 서술)
