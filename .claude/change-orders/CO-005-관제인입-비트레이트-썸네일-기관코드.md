## §1 배경

2026-08-24 관제지원시스템팀이 `ls_data_ingest` 인입 스키마에 대해 8건의 질의를 보내왔다(관제 학습영상 송부 대상 이관 관련). 그중 3건이 스키마·코드 변경이 필요한 실질 결정으로 확정됐다.

1. **`BIT` 컬럼 의미 정정** — 현재 규격서 §10·`LsDataIngest.java` Javadoc·마이그레이션 코멘트 3곳 모두 `BIT`을 "색심도(color depth, 예: `24bit`)"로 명시하고 "비트레이트가 아니다"라고 못박아 두었다. 그런데 2026-07-31 설계 시점에 관제 실DB(PostgreSQL)에서 관측한 `video.bit` 실제값은 `24bit` 형식이 아니라 `bit_rate=2050627` 같은 bps 단위 숫자였다(당시 결론 없이 보류된 모순). 2026-08-24 관제 팀이 별도 질의로 "이 값이 BIT_RATE 아니었냐"고 독립적으로 재확인 요청 — 실측과 관제 측 의심이 수렴해 **비트레이트로 재정의**하기로 확정.
2. **썸네일 경로 컬럼 신설** — 관제가 저작도구 산출 학습데이터를 패키징할 때 썸네일이 필요한데, `klid_at` 스키마 전체에 썸네일 계열 컬럼이 없어 관제 쪽에서 원본 영상 테이블을 별도로 조인해야 하는 불필요한 작업이 발생한다고 요청. `썸네일`은 공통표준단어(6차, 2023-11)에 `THMB`로 이미 등록돼 있어 신규 컬럼으로 수용.
3. **`OG_CD`(기관코드) 재추가** — 이 컬럼은 2026-08-12 관제 팀 자신이 "현행 미사용·공급 불가"로 요청해 `V185`에서 제거됐던 컬럼이다. 2026-08-24 관제 팀이 "관제에서는 해당 데이터를 보유하고 있다"며 반대 방향으로 재요청 — 사용자 확정으로 즉시 재추가.

**함께 검토했으나 변경 없음으로 종결**: "이벤트 발생시각"(구 MariaDB `LS_DATA_RAW.EVNT_BGNG_DT`) — `sht_dt`(촬영일시, 관제 `video.date_created`)와 별도로 받을 필요가 없다고 판단. 저작도구 파이프라인(VLM 시계열·이벤트 어노테이션·마킹) 어디도 절대시각 기준 "이벤트 발생시각"을 쓰지 않고 프레임 상대 위치로 이벤트를 다루며, 저작도구가 생성하는 export JSON(`NiaVideo`, 어노테이션 spec v1.3) 전체 필드에도 `date_created` 하나뿐이고 별도 이벤트 시각 필드가 애초에 없다. **컬럼 신설 없음 — 회신 문서로만 답변.**

## §2 변경 요지

1. `ls_data_ingest."bit"`의 의미론을 색심도 → 비트레이트로 전환하고, `VideoMetaService`가 `video.bit_rate` 메타를 채울 때 인입값을 소스로 활용하도록 변경(현재는 인입값을 쓰지 않고 항상 ffprobe로만 채움).
2. `ls_data_ingest.THMB_FILE_PATH_NM`(썸네일파일경로명, varchar, nullable, 관제 pass-through) 신설 + `V_COMPLETED_VIDEO` 뷰에 LATERAL 조인으로 노출.
3. `ls_data_ingest.OG_CD`(기관코드, VARCHAR(20)) 재추가. **정확히 V185 제거 이전 상태로 복원**(export JSON `NiaVideo.og_cd`는 원래도 항상 null 고정이었고 OG_CD를 export로 배선한 적이 없었음 — 이번에도 배선하지 않는다. 순수 재추가만).

### DOMAIN-003 (영상·프레임 수집) — `klid-d003-implementer`

#### 3-1. BIT → 비트레이트 재정의

- **대상 파일·심볼**:
  - `backend/src/main/java/kr/co/cudo/authoring/video/entity/LsDataIngest.java` — 클래스 Javadoc(44~48행 부근 "매핑 주의" 절), `bit` 필드 Javadoc(342~344행)

  - 신규 마이그레이션(`V16__` 이후 채번) — `COMMENT ON COLUMN ls_data_ingest."bit"` 갱신
  - `docs/관제-저작도구-데이터연동-규격서-20260805.md` §10 및 컬럼표 27행(`BIT`)
- **변경**:
  - `LsDataIngest.bit` 필드 Javadoc을 "비트레이트(bps) 표기. 색심도가 아니다"로 정정.
  - `VideoMetaService.loadIngestMeta`가 `ingest.getBit()`을 숫자로 파싱 시도해 `KEY_BIT_RATE`(`video.bit_rate`)에 채운다. **파싱 실패(숫자가 아닌 값·null)는 예외 없이 skip** — 그 경우 기존 ffprobe 경로가 폴백으로 채운다(현재 `PROBE_KEYS`에 `KEY_BIT_RATE`가 이미 포함돼 있어 probe는 계속 돈다 — 이 동작 자체는 바꾸지 않는다).
  - **우선순위: 인입값 우선, ffprobe는 인입값이 없거나 파싱 실패일 때만 채택.** 관제가 이미 실측한 값이 있는데 ffprobe가 덮어쓰면 중복 추출의 이득이 없다.
  - 마이그레이션은 `COMMENT ON COLUMN` 갱신뿐(컬럼 타입·제약 변경 없음 — varchar(20)는 비트레이트 숫자 문자열도 충분히 수용).
- **불변**: 컬럼명(`bit`)·타입(`varchar(20)`)은 유지 — 이미 관제와 합의된 물리명이라 재협의 비용이 크고, 값의 의미만 바뀌는 것이라 재명명은 대상 아님. `ls_dataset_video_meta.bit_rt`(BIGINT, ffprobe 산출 정본)의 소유권·타입은 무변경 — 인입값은 그 필드를 채우는 **소스 후보 하나**로 편입될 뿐, 구조를 대체하지 않는다.
- **주의(2026-08-24 개정 — 구 "probe 스킵 금지" 폐기)**: `PROBE_KEYS` 6종을 **인입이 전부 유효값으로 채운 영상에서는 probe 를 생략한다**(`needsProbe=false` → NAS 접근·ffprobe 자체를 건너뜀). 이것이 관제 질의 원문("관제가 이미 보유한 값이니 중복 추출을 줄일 수 있다")이 요구한 이득이며, 손실이 없음을 확인했다 — `LS_DATA_RAW.VDO_LEN_SEC` back-fill 은 **병합 결과**의 `duration_ms` 를 쓰므로 인입값으로 그대로 성립하고, 인입 `BIT` 이 없거나 파싱 불가면 6종 미달이 되어 probe 가 정상 폴백한다(영구 결손 없음).
  - ⚠ **구 문구 폐기**: *"probe 자체를 스킵하는 방향 금지 — 인입값이 향후 비어 있는 영상도 있을 수 있어 안전망 필요"*. 그 우려는 **키 단위 판정**(`needsProbe` 가 6종 완비를 요구)이 이미 해소한다. 되돌리지 말 것.
- **수용기준**:
  - 인입 `bit`이 숫자 문자열(예: `"2050627"`)이면 `LS_DATA_META.video.bit_rate`가 그 값으로 채워진다.
  - 인입 `bit`이 null이거나 숫자로 파싱 불가(예: 레거시 `"24bit"` 잔재)면 기존과 동일하게 ffprobe 값이 채워진다.
  - 두 소스가 공존할 때 인입값이 우선한다(ffprobe로 덮어쓰지 않는다).

## §4 영향·리스크

- **하위호환**: 3건 모두 컬럼 추가 또는 nullable 컬럼 재추가라 기존 INSERT·조회 경로에 breaking 없음. `V_COMPLETED_VIDEO`는 컬럼 추가만이라 관제의 기존 SELECT 쿼리(명시적 컬럼 나열이면 무영향, `SELECT *`면 컬럼 하나 늘어남)에 영향 최소.
- **되돌리기**: 각 항목 마이그레이션에 롤백 SQL(V162 규약) 동반. BIT 재정의는 코드 되돌리기(설정 플래그 없이 커밋 되돌리기)로 충분.
- **리스크**:
  - BIT: 관제 `video.bit`가 실제로는 두 성격(일부 영상은 색심도, 일부는 비트레이트)을 섞어 보낼 가능성 — 파싱 실패 시 조용히 skip하고 ffprobe 폴백을 유지하는 것으로 완화.
  - THMB: 관제가 잘못된 경로(존재하지 않는 파일)를 보내도 저작도구가 검증하지 않음(pass-through) — 파일 존재성 검증은 이번 범위 밖.
  - OG_CD: 관제가 실제로 값을 채워 보내기 시작하기 전까지는 전량 null.

## §5 검증

- `LsDataIngest` 관련 기존 단위/통합 테스트 중 "BIT은 색심도라 bit_rate에 안 담는다"를 검증하는 회귀 가드가 있으면 반전.
- `VideoMetaServiceTest`류에 인입 bit 우선순위(인입값 존재 시 채택, 없으면 ffprobe) 케이스 추가.

- 마이그레이션 적용 후 `ddl-auto=validate` 기동 성공 확인(FULL 회귀에 포함).
