## 5. 알려진 잔여 · 인지하고 남긴 것

1. **실렌더(브라우저) 확인 미수행 구간이 있다** — 시험은 구조·문구·토큰 축이고, 실제 화면의
   여백·줄바꿈은 별도 확인이 필요하다.
2. ★**`<th scope="row">` 를 쓰지 못한다** — 시안(SD-024)은 행 제목 칸을 `th scope=row` 로 그렸으나
   표 표면 관례 가드가 파일 안의 `<th>` 를 **전부 열 머리로 보고**(`scope` 를 가르지 않는다)
   헤더 타이포·대문자화·굵기를 요구해, 본문 행 머리를 `th` 로 두면 위반으로 잡힌다.
   형제 화면(`SCREEN-033`)도 같은 이유로 `td` 라 **한 채널 안에서 구조를 맞추는 쪽**을 골랐다.
   ⇒ 가드가 `scope="col"` 만 보도록 좁히는 것은 **별건**이며, 그때 시안대로 되돌린다.
3. ★**표 헤더 색은 `gray-600` 이다 — DS-002 본문(slate-500)과 어긋난다.** 이 배경
   (`bg-secondary-50`) 위에서 500 은 **4.23:1 로 AA 미달**이고 600 이 통과한다. 두 채널 모두에서
   그 경계를 못박은 회귀 가드가 이미 있다. **DS-002 는 상대 정의의 사본이라 우리가 고치지 않고
   상대에 제기할 대상**이며, 선행 CO 가 같은 모순을 이미 기록해 두었다.
4. ⚠ **`stale` 표식 2건이 이번 편집으로 소실됐다** — `SCREEN-028`(사유: `ROLE-003.permissions` 변경 ·
   그전엔 `UC-024.frequency`) · `SCREEN-044`(사유: `UC-027.frequency` 변경). **내 편집은 그 축을
   다루지 않았으므로 해소가 아니라 손실이다.** `SCREEN-033` 때와 같은 형태이며, 남은 전파는
   `STALE-QUEUE-20260907.md` 축에서 별도로 다뤄야 한다.
5. `SCREEN-028`·`SCREEN-044` 의 `implementation` 추적(IMPREC)은 **워크트리 규칙에 따라 유예**한다
   — 머지 후 메인 워크트리에서 회수.

## 1. 표가 답답한 게 아니라 **담을 수 없는 것을 담고 있었다**

증강 목록 한 행이 요구하는 최소 폭:

```
요청 일시 144 + 파일명 400 + 생성 조건 444 + 상태 534 + 조작 114 ≈ 1,636px
본문 최대 폭                                                    = 1,200px
                                                          부족  ≈   436px
```

**열을 어떻게 나눠도 어느 칸이든 반드시 접히거나 잘린다.** 실제로 생성 조건 칸이 최소 폭까지
눌려 **한 글자씩 세로로 흘러내렸고**, 그 행만 여섯 줄로 벌어졌다.

내가 1차로 넣은 `table-fixed` + 줄임표는 **그 부족분을 이용자에게 떠넘긴 것**이다 —
실패 사유를 읽으려면 매번 「결과 확인」을 눌러야 했다. 사용자가 그것을 거부한 것이 옳다.

## 2. Host 원본이 이미 답을 갖고 있었다

`KLID_Portal/src/components/custom/ResultRow.tsx` 주석:

> *"카드는 대표 이미지가 먼저 읽혀야 하는 목록의 것이고, 로우는 **그림이 없어 글자만 남는
> 목록**의 것이다. 그림 없는 카드를 3열로 세우면 칸 안에 텍스트만 남아 카드일 이유가
> 사라지는데, 로우로 눕히면 제목이 왼쪽 한 줄로 줄맞춰 서서 훑는 속도가 붙는다."*

Host 는 **표와 행 목록을 둘 다** 갖고 쓰임을 갈라 놨다. 우리 증강·업로드가 정확히 후자다.

★ **시안 SD-026 도 업로드 목록을 원래 「행」으로 그렸다** — `.file-name` 이 `flex-wrap` 으로
흐르는 짜임이다. **표는 그 시안에서 이탈한 형태였고**(이전 라운드에서 내가 바꿨다) 이번에
되돌아온 것이다. 시안은 말줄임과 `title` 보완을 **명시적으로 거부**한다:

> *"잘리는 꼬리는 확장자다 … 왜 거부됐는지 화면에서 사라진다"*
> *"`title` 속성으로 보완하는 방법은 쓰지 않았다 — 이 폭은 사실상 터치 환경이라 hover 툴팁이
> 뜨지 않고, 게시본 sanitizer 가 지우는 속성 계열이기도 하다"*

| 일시 표기 | `formatPortalDateTime` 신설 — 포털 목록 셋이 공유. 로케일 표기(`2026. 9. 8. 오후 3:09:22`)는 자리폭이 값마다 달라 세로로 훑을 수 없다 |

## 4. ★ Host 원본과 우리 DS-002 사본이 어긋난 지점 셋 — **상대 제기 대상**

우리 `DS-002` 는 상대 정의의 **사본**이라 값을 우리 쪽에서 고치지 않는다. 아래는 Host 가
2026-08-24 에 확정했는데 사본에 넘어오지 않은 것들이다.

| 축 | 우리 사본 | Host 원본 |
|---|---|---|
| 표 머리 | `bg-secondary-50`(코발트 틴트) · 14 · 500 | **면 slate-50 · 13 · 400 · slate-600** |
| 행 hover | *"DS-002 가 규정하지 않는다"* → 중립 50단 | **주색 최옅단으로 짚는다 (규정돼 있음)** |
| 빈 상태 | py 48 | **본문 py 80 / 카드 안 56 / 표 안 24** |

⚠ 넷째가 하나 더 있다 — **Host 의 목록 행 메타 글자색(gray-50 = 우리 500단)은 그 행의 hover
면 위에서 4.01:1 로 AA 미달**이다(대비 가드 실측). 사본이라 해서 미달을 그대로 옮기지 않고
600단으로 올렸다. 이것도 상대 제기 대상이다.
