# CO-20260903 — 포털 라벨링 화면 통합 (단계 ⑤)

- 상태: 착수
- 근거 결정: `NAV-002` v17 · `SCREEN-029` · `SCREEN-034`(폐기되는 쪽) · `CO-20260902-포털-라벨링화면-통합.md`
- 범위: 프론트 전용

## 1. 왜

포털에 라벨링 화면이 **둘**이다 — 데이터마트 로드분을 다루는 화면과 업로드 자산을 다루는 화면.
둘이 하는 일이 같은데 화면이 갈려 있어 사용자가 같은 작업을 두 자리에서 배운다.

`NAV-002` v17 이 이미 **업로드 자산 라벨링을 폐기된 목적지**로 표기했다 —
*"업로드 자산 라벨링 화면이 포털 라벨링 화면으로 합쳐져 별도 목적지가 없어졌다"*.

## 2. 무엇을 한다

1. **업로드 자산 라벨링을 포털 라벨링 화면으로 합친다.** 준비 완료 자산은 **내 업로드 목록의 행을
   눌러** 통합 화면으로 들어간다.
2. 폐기되는 경로에 대한 **되돌아갈 자리를 만들지 않는다.**
3. **저장처·내려받기를 라벨링 화면에 두지 않는다** — 그 축은 목록 화면이 갖는다.

⚠ **두 화면의 기능 합집합을 유지하라.** 한쪽에만 있던 기능을 조용히 떨어뜨리지 마라 —
어느 쪽에 있던 것을 어떻게 처리했는지 **표로 보고**하라.

## 3. 하지 말 것

- **탭에 이 화면을 넣지 마라** — 목적지가 아니라 목록에서 들어가는 자리다(몰입 편집).
- 관제 채널을 건드리지 마라.
- 백엔드를 건드리지 마라(**다른 에이전트가 지금 백엔드를 고치고 있다**).

## 4. 수용 기준

1. 포털 라벨링이 **한 화면**이고, 데이터마트 로드분과 업로드 자산을 **둘 다** 다룬다.
2. 폐기된 경로로 들어가도 사용자가 막히지 않는다(처리 방식은 판단하고 근거를 보고).
3. **기능 누락 0** — 합집합 표로 증명.
4. 관제 채널 무변경 — 산출물 동치 또는 되돌림 실증.
5. 프론트 전건 통과 · lint 0 errors · 빌드 성공.
