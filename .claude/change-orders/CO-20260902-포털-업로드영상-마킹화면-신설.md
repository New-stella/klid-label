# CO-20260902 — 포털 업로드 영상 마킹 화면 신설

> 상태: 설계 확정 · 구현 미착수
> 근거: 2026-09-02 사용자 확정 (구속). `ADR-013` 이 유일하게 「미확정」으로 남겨 뒀던 축이 닫혔다.

## 1. 무엇을 왜

포털 사용자가 **본인 영상을 올리면 이벤트 구간을 마킹하고, 그 마킹 위치로 프레임을 추출**한다.
사용자 원문: *"개인 영상을 업로드할때만 쓰고 마킹한 영상의 프레임을 추출하는데 사용하는거야. 자동/수동 둘다 지원해야하고."*

### 확정 5가지

| # | 확정 | 비고 |
|---|---|---|
| 1 | **마킹은 별도 화면**이다 | 라벨링 화면 안의 모드가 아니다 |
| 2 | **마킹의 쓰임은 프레임 추출 위치 지정**이다 | 외부 시계열 위탁·검수와 무관 |
| 3 | **자동·수동 둘 다** 제공한다 | 자동 = 프레임 간격 일괄 · 수동 = 시점 지정 |
| 4 | **마킹을 거쳐야 프레임이 추출된다** | 업로드 직후 자동 추출은 폐지 |
| 5 | 저장은 **기존 마킹 원장 재사용** | 포털 전용 표를 새로 만들지 않는다 |

### ★ 파이프라인이 바뀐다 (가장 중요한 귀결)

```
[구]  업로드 → (즉시) 고정 간격 프레임 추출 → 준비 완료 → 라벨링
[신]  업로드 → 마킹(자동/수동) → 마킹 위치로 프레임 추출 → 준비 완료 → 라벨링
```

- **낭비 추출도 재추출도 없다** — 마킹이 추출보다 앞서므로 뽑았다 버리는 프레임이 생기지 않고,
  이미 붙은 라벨을 어떻게 할지 정할 일도 없다. 그래서 이 순서를 골랐다.
- **자동 마킹이 기본값**이라 사용자가 간격만 그대로 두면 **구 동작과 같은 결과**가 나온다.
  즉 기존 「고정 간격 추출」은 사라지는 것이 아니라 **자동 마킹의 기본 동작으로 흡수**된다.
- ⚠ 그 대가로 **상태 흐름의 의미가 바뀐다.** 업로드됨 상태가 이제 「추출을 기다리는 중」이 아니라
  **「마킹을 기다리는 중」**이다. 목록 화면이 그 상태에서 무엇을 하라고 안내할지 다시 정해야 한다.

## 2. 내부 마킹 화면에서 가져오는 것과 버리는 것

내부 채널 마킹 화면을 원본으로 삼되 **포털에서 성립하지 않는 축을 걷어낸다.**

| 가져온다 | 버린다 | 왜 버리나 |
|---|---|---|
| 영상 재생(구간 탐색·배속) | **비식별 영상 서빙** | 본인 데이터라 비식별을 하지 않는다 — 원본을 재생한다 |
| 마킹 타임라인 | **비식별 누락 신고** | 마스킹을 한 적이 없어 빠졌다고 신고할 대상이 없다 |
| 자동·수동 모드 전환 + 간격 입력 | **검증 질문 선택** | 질문은 관제 인입 이벤트 유형에 매이는데 이 경로엔 그 값이 없다 |
| 마킹 목록·선택 | **위탁 배치 기동** | 포털에는 외부 시계열 위탁이 없다 |
| 단축키 | **작업 배정·검수 연계** | 포털에 검수가 없다 — 인가는 소유자 판정 하나 |

**진입 차단 축도 갈아끼운다** — 내부는 「비식별 완료 + 배치 단계」 2축인데,
포털은 **「업로드 완료 + 본인 자산」** 이다.

⚠ `<video>` 가 인증 헤더를 못 싣는 제약은 채널과 무관하므로 **서명 주소 발급 방식은 그대로 필요**하다.

## 3. 신설·개정 대상

### 신설
- 화면 1건 — 포털 업로드 영상 마킹 화면. 경로는 라벨링 화면과 형제 자리(`…/{자산}/marking`).
- 창구 4건 — 영상 스트리밍(구간 요청) · 스트리밍 서명 주소 발급 · 마킹 저장(추출을 함께 시작) · 마킹 조회(재진입).
  ⚠ 넷 다 포털 축에 **하나도 없다.** 내려받기 창구는 있으나 그건 첨부 다운로드라 재생에 못 쓴다.
- 시안 1건 — 포털 디자인 시스템 축.

### 개정
- 라벨링 화면 — 마킹 섹션을 **빼고** 마킹 화면 진입만 남긴다.
- 업로드 목록 화면 — 업로드됨 상태 행에 **마킹 액션** 추가. 상태 안내 문구 조정.
- 내비게이션 — 노드 1건 추가하되 **이동 탭에 노출하지 않는다**(목록에서 들어가는 자리).
- 셸 — 신설 화면 적용 대상 판정. ⚠ 조사 중 **기존 드리프트 발견**: 같은 성질의 라벨링 편집 화면 하나가
  적용 목록에 있는데 다른 하나는 빠져 있다. 함께 판정한다.
- 결정서 — 「마킹 저장 모델 미확정」 서술을 이번 확정으로 닫는다.
- 마킹 원장 — 사용자 식별자 폭을 넓힌다(라벨 원장에 이미 같은 조치를 한 선례가 있다).
- 사용례·수용기준 — 마킹 단계를 파이프라인 순서에 맞게 옮긴다.

## 4. 회복 경로 — 지우고 다시 올린다 (2026-09-02 확정, 구속)

> "마킹 잘못했으면 다시 올리겠지?"

**재마킹·재추출 기능을 만들지 않는다.** 마킹을 잘못했으면 **자산을 지우고 다시 올린다.**
본인이 올린 자산이고 보존기간도 짧아 재업로드 비용이 기능을 새로 만드는 비용보다 싸다.

귀결:

- **이미 추출이 끝난 자산의 재마킹 저장은 거부**한다. 거부 사유에 회복 경로(재업로드)를 명시한다.
- ★**「마킹 완료」가 되돌릴 수 없는 조작이 된다.** 누르는 순간 추출이 시작되고 회복 경로가
  재업로드뿐이므로, **완료 직전 확인 단계가 이 설계의 필수 조건**이다. 선택 사항이 아니다.
- ⚠ **마찰 하나를 인지·수용한다**: 자산 삭제는 **추출 중에는 거부**되므로, 마킹을 잘못한 사용자는
  **추출이 끝날 때까지 기다렸다가** 지우고 다시 올려야 한다. 그 대기 구간에 무엇을 보여 줄지가
  안내에 있어야 한다.

## 5. 아직 안 정한 것

- 마킹 화면 진입 자리를 **업로드 목록에만** 둘지, 라벨링 화면에서도 되돌아갈 수 있게 할지.
- 자동 마킹 간격의 단위 — 내부는 프레임 수, 포털의 기존 설정은 초다. 어느 쪽으로 통일할지.
