## §1 배경

이관은 **누가 언제 어떤 폴더를 가져와 몇 건이 들어왔는지**가 남아야 한다. 그 기록은 감사 목적만이 아니라
같은 산출물을 두 번 가져오려 할 때의 **거부 근거**이기도 하다(`AC-044`).

그리고 이 도메인은 사람이 쓰는 진입점이 **관리 화면 하나**뿐이다(`SCREEN-039`, `/manage/imports`).
경로 입력 → 미리보기 확인 → 적재의 3단 흐름을 한 화면에서 순서대로 밟는다.

## §2 변경 요지

- `GET /v1/imports`(`API-207`) 목록 · `GET /v1/imports/{trnsfSn}`(`API-208`) 상세.
- `SCREEN-039` `/manage/imports` — 5개 구획(가져오기 입력 · 미리보기 · 분류 대응 확정 · 적재 실행 · 이관 이력).

## §0 착수 전 선결 판정 (2026-08-20 CO-002 에서 이월)

**확정된 대응을 보고 지울 화면 자리가 없다.** `API-209`(목록)·`API-211`(해제)를 만들었는데
관리 화면의 「분류 대응 확정」 섹션에는 **「미등록 분류 목록」 표와 「대응 확정」 버튼뿐**이라
그 두 통로를 그리거나 부르는 요소가 없다. 게다가 그 섹션은 *"한 번 확정한 대응은 이 표에 다시 나오지
않는다"* 고 못박으므로 **확정 뒤에는 대응이 화면 어디에도 나타나지 않는다.**

⚠ 이 저장소가 이미 겪은 패턴이다 — API 는 있는데 화면에 진입점이 없어 **도달 경로가 0** 이던 사례.
그때도 "구현됨"으로 집계되고 있었다.

**함께 판정할 것 — 비식별 완료 기록에 화면 진입점이 아예 없다 (2026-08-20 발견)**

비식별 완료 기록 통로를 만들었는데 **이 화면이 그것을 소비하지 않는다** — 소비 목록에도 없고
본문에 언급이 0건이다. 즉 **영상 파일 없이 프레임만 이관한 원본의 승인 보류를 사람이 풀 수단이
화면에 없다.**

⚠ 이 CO 에 이미 적힌 「확정된 대응을 보고 지울 자리가 없다」와 **같은 계열**이다 —
API 는 있는데 화면에 진입점이 없어 **도달 경로가 0** 인 패턴. 이 저장소가 이미 한 번 겪었다.

**착수 시 함께 판정할 것**
1. 비식별 완료 기록의 **진입점을 이 화면에 둘지** — 이력 목록에서 그 영상을 골라 여는 형태가 자연스럽다.
2. **이름이 맞는 파일이 없어 비워 둔 프레임 수**를 사람이 보는 자리 — 지금은 응답 필드로만 알린다.
   그 수가 0 이 아니면 **그 영상의 산출물에 비식별 이미지가 빠진 채로 나간다.**

**함께 판정할 것 — 대응 표의 두 열이 이벤트 축에서 같은 값이 된다**

「분류 대응 확정」 표가 **「외부 분류 코드 / 외부 표시 이름」 두 열**인데, **이벤트 축은 코드가 없어
이름이 곧 코드 자리**에 들어간다. 따라서 이벤트 축 행에서는 **두 열이 같은 값**을 보인다.
설계에는 그 사실을 서술로 적어 두었고 **열 구조는 손대지 않았다** — 열 병합·조건부 표시로 바꿀지는
화면 구성 변경이라 CO-004 에서 판정한다.

**착수 시 먼저 판정할 것**
1. 「확정된 대응 관리」를 같은 화면의 섹션으로 둘지, 별도 화면으로 뺄지.
2. 해제에 확인 절차를 둘지 — 되돌리면 그 분류가 다시 미확정이 되어 **적재가 막힌다**(파괴적 조작에 준한다).
3. 목록은 쪽 나눔 계약이므로 쪽 이동 요소가 필요하다(같은 화면의 「가져온 내역」이 이미 그 선례를 갖는다).

★ **판정 뒤 화면 ITEM 을 먼저 고치고** 프론트를 구현한다. 관리 화면 ITEM 은 현재 `API-209` 변경 전파로
stale 이며, **이 갭을 닫기 전에는 그 표식을 지우지 않는다** — 지금 stale 인 것이 정확한 상태다.

## §3 도메인별 변경 상세

### DOMAIN-017 (외부 산출물 이관) — `klid-d017-implementer`

**대상 파일·심볼**

- 신규 `transfer/controller/ImportHistoryController` · `transfer/service/ImportHistoryQueryService`
- 재사용: CO-001 의 `LsOtsdDatstTrnsfHstry`, CO-003 의 이력 기록

**변경**

1. **`API-207` `GET /v1/imports`** — 인가 `REVIEWER`. 쿼리 `page`(기본 0, 최소 0) · `size` 등.
   - **페이징 필수**(이 저장소 API 규칙 — 페이징 없는 전체 조회 금지).
   - 정렬은 **시간축 단일 기준**이다. 상태 우선순위를 `ORDER BY CASE` 로 섞지 않는다(구속 정책).
   - 정렬 키를 받는다면 **allowlist 매핑으로만** 해석하고 개수 상한을 둔다(CWE-89 / CWE-770).
   - ⚠ 신규 엔드포인트이므로 미등록 정렬 키 정책은 **strict(400)** 로 잡아도 하위호환 문제가 없다
     (기존 엔드포인트의 strict/lenient 비대칭은 "변경 전에 200 이었는가"가 근거이며, 신규는 그 부채가 없다).

2. **`API-208` `GET /v1/imports/{trnsfSn}`** — 경로 변수 `trnsfSn`(최소 1). 없으면 404.
   - 상세에는 그 이관으로 만들어진 영상 식별번호·프레임 수·라벨 수·경고를 담는다.
   - ⚠ **절대 경로를 그대로 노출하지 않는다** — 서버 파일시스템 구조가 새면 경로 탐색의 단서가 된다.
     이 저장소는 관제 통지에서도 *"파일 이름만, 절대 경로는 담지 않는다"*(CWE-359)를 지키고 있다.
     이력에 남긴 원본 폴더 경로를 화면에 보여줘야 한다면 **REVIEWER 한정 + 감사 로그**로 좁힌다.

**불변**

- `ApiResponse<T>` 래퍼와 표준 오류 템플릿.
- 이관 이력 행은 **사후 수정하지 않는다**(감사 기록의 성질).

**수용기준**

- 이관 2건 후 목록이 시간 역순으로 2건, 페이징이 동작한다.
- 없는 `trnsfSn` 은 404.
- 응답 어디에도 스토리지 절대 경로가 그대로 실리지 않는다.

### 프론트 (SCREEN-039 `/manage/imports`) — `klid-web-implementer`

**대상 화면·컴포넌트**

- 신규 페이지 `frontend/src/pages/...` (관리 화면 라우팅 `/manage/*` 아래).
- ⚠ **DOMAIN-017 화면 키트가 아직 없다**(`docs/screen-design/` 에 해당 도메인 없음).
  사양은 **구현 키트의 `screen_spec/SCREEN-039`** 를 읽는다. 고충실 시안(SD)도 0건이므로
  기존 관리 화면들의 확립된 패턴·디자인 토큰을 따른다.

**소비 API 계약** — `API-205` · `API-206` · `API-207` · `API-208` · `API-209` · `API-210` · `API-211`
(전부 `REVIEWER` · `ApiResponse<T>` 래퍼)

**변경** — 5개 구획을 순서대로 밟는 단일 화면

1. **가져오기 입력** — 산출물 폴더 경로(필수) · 원본 영상 경로(선택) ·
   **비식별 여부 선택(기본값은 원본 쪽)**.
   ★ *"비식별이 끝난 것"* 으로 고를 때 **경고를 보여준다** — 잘못 고르면 비식별되지 않은 화면이
   학습데이터로 나가고 승인 이후에는 되돌릴 수단이 사실상 없다.
2. **미리보기** — `API-205` 결과(영상 정보 · 프레임 수 · 라벨 수 · 경고).
   ★ **경고는 적재를 막지 않는다**는 것이 사용자에게 분명해야 한다(`AC-047`).
   "이 사항들은 적재를 막지 않습니다" 식으로 프레이밍한다.
3. **분류 대응 확정** — 미확정 분류에 후보를 제시하고 사람이 고른다(`API-209`/`API-210`).
   ★ **미확정이 남아 있으면 적재 버튼을 비활성**한다(`AC-042`). 서버가 막기 전에 화면이 먼저 알린다.
4. **적재 실행** — `API-206`. 중복이면 409 + 기존 영상 식별번호를 사용자에게 그대로 보여준다.
5. **이관 이력** — `API-207`/`API-208`. 페이징.

**불변**

- 백엔드 응답 계약을 소비만 한다. **FE 가 성공 조건을 재유도하지 않는다**(생산자가 보장하는 것을
  소비자가 다시 계산하면 드리프트가 난다 — 이 저장소의 확립된 규칙).
- 접근성(WCAG 2.1 AA)·반응형은 기존 관리 화면 기준을 따른다.

**수용기준**

- 미확정 분류가 있으면 적재 버튼이 비활성이고 사유가 보인다.
- 경고가 있어도 적재가 진행되며, 경고가 "차단"으로 읽히지 않는다.
- 비식별 여부를 "끝난 것"으로 바꾸면 경고가 뜬다.
- 409 응답 시 기존 영상 식별번호가 사용자에게 노출된다.
