## §1 배경

관제가 인입하는 영상 중 **생성형 AI 로 만든 영상**(`LS_DATA_INGEST.SRC_TYPE='GENERATED'` → `LS_DATA_RAW.SRC_TYPE` 로 복사)은 실제 사람·번호판이 찍힌 영상이 아니라 비식별이 필요 없다. 그런데 지금은 적재 직후 **출처와 무관하게 모든 영상**을 외부 비식별 솔루션(KPST)에 위탁한다(구속 정책 「전체 영상 비식별 후 마킹 — 무조건 자동 실행」). 생성형 영상도 위탁 비용·대기 시간을 치른다.

**비식별을 단순히 건너뛸 수는 없다.** 뒤 단계가 전부 「비식별 완료 표시 + 비식별 영상 파일」을 전제로 짜여 있다(코드 실측).

| 소비처 | 전제 | 건너뛰기만 하면 |
|---|---|---|
| 마킹 진입·잔여 배치 트리거(`MarkingGuards`·`MarkingBatchBridge`) | `LS_DATA_RAW.DE_IDENT_YN='Y'` | 412 · 배치 미기동 |
| 마킹 화면 영상 재생(`VideoStreamService`) | `'Y'` + 비식별 이력 최신 성공 행의 파일 경로 | 404 (원본 폴백 없음) |
| 프레임 추출(`FfmpegFrameExtractor`) | 비식별 이력 최신 성공 경로 | 원본 벌만 추출 → 산출물 비식별 벌 결손 |
| 증강·해상도 파생(`DerivativeSourceVideoResolver`) | 부모의 비식별 이력 경로 | 404 |
| 관제 조회 뷰 `V_COMPLETED_VIDEO` | `DE_IDNTF_FILE_PATH_NM` | 관제가 영상 파일을 찾지 못함 |

또 재생·추출이 허용하는 비식별 영상 위치(`VideoArtifactRootResolver.readableDeidVideoBases`)는 `{deid_base}/videos/{rawSn}` · `dirname(원본)/{rawSn}/deid` · 파생 서브트리뿐이라, **원본 경로를 이력에 적는 방식은 경로 검사에서 거부된다.**

## §2 변경 요지

- 설정 `authoring.deidentify.excluded-src-types`(쉼표 구분 복수, 기본 `GENERATED`)에 든 출처유형 영상은 KPST 에 위탁하지 않는다.
- 대신 원본 영상을 **비식별 영상 쓰기 위치에 복사**하고, 비식별 이력(`LS_DEIDENT_PROC_LOG`)에 **성공 행 + 요청종류코드 `EXCLUDED`(비식별 제외)** 를 남긴 뒤 `DE_IDENT_YN='Y'` → `MARKING_READY` 로 기존 동기 완료 흐름을 탄다.
- 뒤 단계는 **코드 변경 없이** 그대로 동작해야 한다. 신규 상태값·컬럼 없음.

## §4 영향·리스크

- **하위호환**: API·뷰 스키마 무변경. 관제 뷰의 `DE_IDNTF_YN='Y'` 가 제외 영상에도 서지만 **관제와 무관** — 2026-09-14 관제 회신(비식별 작업은 전부 저작도구로 이관, 관제는 이 값으로 판단하지 않음 · `GENERATED` 는 기존에도 생성형 AI 서버 산출물에만 전달 · 관제 수정 없음). 기존 적재 영상은 영향 없음(소급 없음).
- **되돌리기**: 설정을 빈 값으로 두고 재기동하면 이후 적재분은 전부 KPST 위탁. 이미 제외 처리된 영상은 이력 `REQ_KND_CD='EXCLUDED'` 로 조회해 필요 시 재비식별 경로로 회수.
- **리스크(인지·수용, 사용자 확정)**: 관제가 실제 CCTV 영상을 `GENERATED` 로 잘못 넣으면 마스킹 없는 영상이 마킹 화면·산출물·관제로 흐른다. 회수 지점은 **검수**다 — 검수자가 비식별이 필요하다고 판단하면 비식별 누락 신고 → 외부 재비식별 → 해소. 승인 이력이 있는 영상은 신고를 받지 않는 기존 정책이 그대로라 **승인 이후와 그 파생본은 회수 경로 밖**이다(2026-09-14 사용자 확정 — 라운드 중 정정). 설정 오기로 `ORIGINAL` 을 넣으면 전 영상이 비식별 없이 흐른다 — 기동 검사는 두지 않기로 했으므로 **문서 경고와 기동 INFO 로그**가 유일한 방어다.
- **저장 공간**: 제외 영상 1건당 원본 크기만큼 추가 사용.
