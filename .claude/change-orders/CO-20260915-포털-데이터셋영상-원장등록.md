## §1 배경

포털 학습데이터 상세 → 저작도구 → 라벨링 흐름(사용자 확정 2026-09-15)의 서버 쪽이 비어 있다.

- 소재 가져오기(`/v1/portal/datasets/{id}/materials`, API-248·249)는 **배포 압축본을 우리 작업영역에 풀기까지만** 한다.
- 화면(SCREEN-046 데이터셋 영상 구역)은 이미 구현돼 **`GET /v1/portal/datasets/{datasetId}/videos`(API-253)** 를 부르지만 서버 창구가 없다.
- 포털 라벨링 화면(SCREEN-029, `PortalLabelService` 데이터마트 경로)은 **원장에 있는 영상·프레임만** 연다.

### 사용자 확정 (게이트①, 2026-09-15)

| # | 결정 |
|:-:|---|
| ① | zip 구성은 **우리 검수 승인 산출물 구조로 가정**한다(프레임마다 `NNNN.jpg` + `NNNN.json`, NIA 문서). 가정임을 ADR 에 명시하고, 구조가 다르면 **등록 실패로 알린다**. 샘플을 받으면 맞춰 고친다 |
| ② | 새 출처 구분값 **`SRC_TYPE='PORTAL_DATASET'`** 으로 포털 라벨링 검사를 통과시킨다 — **검수 상태(APPROVED)를 꾸며 넣지 않는다**(관제 뷰·통지·산출물 연동이 반응하지 않게) |
| ③ | 등록은 **소재 준비 직후 같은 백그라운드 작업이 자동으로** 이어 한다 |
| ④ | 데이터셋 번호 ↔ 영상 연결은 **영상 메타(`LS_DATA_META`)** 에 기록한다 — 새 테이블 없음(ADR-058 방향) |

### 코드 실측 (조사 2026-09-15 — 계획을 바꾼 사실)

1. **프레임 이미지 서빙 경로 검사** — 포털 이미지 서빙(`PortalLabelService.serveFrameImage`)은 `LS_DATA_SRC.DE_IDNTF_SRC_FILE_PATH_NM` 만 읽고 `StorageSubtreePolicy.verifyDeidentifiedFile` 로 **`{deid base}/frames/deid/**` 또는 `videos/**` 하위**만 허용한다. 소재 작업영역(`{portal storage}/materials/…`)은 **통과하지 못한다(403)**. ⇒ 등록 시 프레임 이미지를 **`StorageSubtreePolicy.deidFramesDir(rawSn)` 로 복사**한다.
2. **포털 게이트 전부가 APPROVED 판정** — `PortalLabelService.isExposedToDatamart`(:756) 하나를 6개 창구가 쓰고, `PortalWorkTargetResolver.originOf`(:124-136)·`PortalUserWorkService`(:101 `exposedToDatamart`) 도 같은 축이다.
3. **내부 작업 범위 누출** — `InternalWorkScope`(video/repository :60-89)는 `PORTAL_ULD` **만** 제외한다. 그대로 두면 `PORTAL_DATASET` 행이 작업보드·배정·통계·증강 조회에 섞인다.
4. **출처값에 DB 제약이 없다** — `SRC_TYPE` 는 varchar(20) nullable, CHECK 없음. `PORTAL_ULD` 도 **자바 상수만** 추가됐다 ⇒ **마이그레이션 불필요**.
5. **NIA → 원장 역변환기가 없다** — 산출 레코드(`dataset/export/json/NiaAnnotationDoc` 외)는 재사용 가능. 가장 가까운 선례는 외부 이관 `transfer/service/ImportPersistTxService.persist`(RAW·SRC·LBL·META 적재, `LsDataLbl.createRestored`).
6. **배포 zip 에는 영상 파일이 없다** — 소재 조달은 `DEPLOYMENT_ZIP` 만 복사한다(영상은 포털이 `DATASET_VIDEO` 로 따로 보관).

## §2 변경 요지

1. **등록 단계 신설** — 소재 해제본(`materials/{datasetId}/current/content/`)을 읽어 영상 단위로 `LS_DATA_RAW`(SRC_TYPE=PORTAL_DATASET) · `LS_DATA_SRC`(비식별 프레임 폴더로 이미지 복사) · `LS_DATA_LBL`(배포본의 기존 라벨 = 원본) · `LS_DATA_META`(portal.dataset_id 등)를 적재한다. 소재 준비 직후 같은 러너가 이어 한다. 등록 상태는 해제본 옆 **상태 파일**로 표현한다(조달 상태와 같은 방식 — 원장 표 없음).
2. **데이터셋 영상 목록 창구(API-253)** 구현 — 등록 상태 + 페이지 + 요청 사용자 기준 `entrySrcSn`·`lastSavedAt`.
3. **포털 작업 가능 판정 확장** — 「검수 완료(APPROVED)」 **또는** 「출처 PORTAL_DATASET」 을 포털 데이터마트 경로의 허용 조건으로 하나의 판정 지점에 모은다.
4. **내부 작업 범위에서 PORTAL_DATASET 제외.**

     - ZIP 구성은 기존과 같다 — `{rawSn}/frames/NNNN.jpg`(비식별 프레임) + `NNNN.json`. **영상 파일은 없으니 빠진다**(기존 규칙 「있을 때만」 그대로).
     - 본인 저작물 0건이면 410, 신고 구간 412 — 판정 순서 무변경(미노출 거부 자리의 조건만 공용 판정으로).
- **불변**: 소재 조달 동작·경로 재검증·원본 zip 불변 · `PORTAL_ULD` 소유자 검사 · 사용자 저장은 기존대로 `LS_PORTAL_USER_LABEL` 오버레이(원본 `LS_DATA_LBL` 불변) · 관제 연동(뷰·통지·산출물) 무반응.
- **주의**
  - `LS_DATA_LBL` 에 `src_sn` FK 가 없다 — 등록 실패 롤백 시 라벨도 같은 트랜잭션에서 사라지게 한다.
  - 번호 충돌 — 포털의 `API-132` 는 우리 `API-132` 가 아니다. 경로·역할로 적는다.
  - 로그에 내부 절대경로·파일명 원문을 남기지 않는다(CWE-209/117) — datasetId·videoKey 해시·건수만.
- **수용기준**
  - 가정 구조 샘플(시험용 zip 픽스처)로 영상 2·프레임 N·라벨 M 이 적재되고, 목록 창구가 DONE + 두 행을 준다.
  - 구조가 다른 해제본은 FAILED + 원장 적재 0.
  - 같은 데이터셋 재등록 시 행이 늘지 않는다(멱등).
  - 등록된 영상의 `GET /v1/portal/frames/{srcSn}/labels`·이미지 서빙·`PUT` 저장이 **200**, 원본 `LS_DATA_LBL` 은 저장 후에도 불변.
  - READY 전 목록 409 · PORTAL_USER 아님 403.
  - `orgnl/` 이미지는 어떤 경로로도 복사·서빙되지 않는다.
  - 등록 영상에 `LS_RAW_DATA_STATUS` 행이 생기지 않는다(관제 뷰 비노출).

## §4 영향·리스크

- **하위호환**: 신설 창구 · 신설 상수. 기존 게이트는 **허용 조건을 넓히기만** 한다(APPROVED 판정 불변).
- **되돌리기**: 러너의 등록 호출을 끄면 등록이 멈춘다(설정 토글 `portal.materials.registration.enabled` 기본 true 권장). 등록된 행은 `src_type='PORTAL_DATASET'` 로 식별해 지울 수 있다(LS_DATA_LBL 은 src_sn 기준 명시 삭제 필요).
- **리스크**
  - **가정 구조가 틀리면 등록이 전부 FAILED** — 사용자 확정으로 수용. 샘플 수신 시 파서만 고친다.
  - 판정 확장이 넓히는 자리를 놓치면 PORTAL_DATASET 영상이 일부 창구에서 403 — 목록 창구가 준 `entrySrcSn` 으로 라벨링 전 창구 왕복을 시험으로 고정한다.
  - **알려진 공백(이번 범위 밖)**: ① 포털 정리 트리거(데이터셋 코드+버전)와 등록 행(데이터셋 번호) 연결 수단 없음 — 오래된 등록 행 정리 없음 ② 저장 오버레이 보존기간 만료는 기존 규칙대로 적용된다. ~~ZIP 내려받기 403~~ → 이번 범위에 포함(§3 D013 6번, 사용자 확정).
  - **포털향에는 검수·승인 흐름이 없다**(사용자 확인 2026-09-15) — 데이터셋 영상의 허용 근거는 승인이 아니라 출처다. APPROVED 판정은 관제향에서 넘어온 기존 데이터마트 경로를 위해 남긴다.
