## §1 배경

CO-002 의 미리보기에서 확인이 끝나면 실제 적재가 일어난다. 적재된 영상은 **곧바로 검수 대기**가 되며
(작업자 제출 단계가 없다), 승인 이후는 저작도구가 원래 갖고 있던 경로를 그대로 탄다
(버전 스냅샷 → export → 관제 `TASK_COMPLETED`).

적재는 관제 인입 원장(`LS_DATA_INGEST`)을 **거치지 않는다**(`ADR-048`). 인입 원장은 관제가 보낸 것을
기록하는 자리이므로 저작도구가 스스로 넣으면 그 기록이 사실과 달라진다.

## §2 변경 요지

- `POST /v1/imports`(`API-206`) — 실제 적재. 영상·프레임·라벨·메타를 만들고 검수 대기로 넣는다.
- 원본으로 받은 영상은 승인 보류 플래그가 서고, **영상이 있으면 비식별 파이프라인을 탄다.**
- **신규 API 1건** — 영상이 없어 내부 처리가 불가능한 원본에 대해, 외부 비식별 산출물 경로를 받아
  실제 파일을 검증한 뒤 플래그를 내린다.
- `acknowledgedWarnings` 의 **거부 조항을 폐기**한다(`AC-047` 우선).

**변경**

2. **★ `acknowledgedWarnings` 의 거부 조항 폐기** (2026-08-19 사용자 확정)
   - 현재 설계 본문은 *"확인하지 않은 경고가 남아 있으면 거부한다"* 인데, 이는 `AC-047`
     (*"적재는 거부되지 않는다"*)과 **정면으로 충돌**하고 확정 요구 R8·R9(*"경고 후 적재"*)와도 어긋난다.
   - **경고는 적재를 막지 않는다.** 필드는 감사 기록용으로만 남기거나 폐기한다.

     **실제 파일 기준 적재 + 경고**(R9).

3. **중복 거부** (`AC-044`) — 같은 산출물을 두 번 가져오면 **409** + 기존 영상 식별번호를 안내한다.
   - 보장은 `LS_DATA_RAW.VMS_CLIP_ID` 의 UK 제약이다(`IMPORT-{폴더식별자}-{dataset.identifier}`).
   - ⚠ **기존 영상번호를 어디에 담을지가 미해결**이다 — 표준 오류 템플릿의 `data` 는 `null` 이라 자리가 없다.
     Phase 3.6 에서 확정한다(`message` 에 싣는 안 / 예외적으로 `data` 를 채우는 안).

4. **적재 내용**
   - 영상 1건(`LS_DATA_RAW`, `SRC_TYPE='IMPORTED'`) + 프레임 N건(`LS_DATA_SRC`) + 라벨(`LS_DATA_LBL`).
   - 영상 파일 배치는 **CO-001 §3 의 `deidentified` 분기표**를 따른다(비식별본이면 비식별 영상 자리에
     앉히고 파이프라인을 타지 않는다 / 원본이면 원본 자리에 앉히고 파이프라인을 탄다).
   - **착지점 없는 `video` 필드는 `LS_DATA_META` 에 원문 보관**한다 — `coordinates` · `location` ·
     `cctv_height` · `cctv_azimuth` · `cctv_mng_no` · `data_source` · `event_log`. 버리면 못 되돌린다.
   - ★ **원천 개인정보 3필드도 `LS_DATA_META` 원문 보관**(2026-08-19 사용자 확정).
     산출물은 `video.anonymity`·`pseudonymity`·`privacy_included` 와 `image.*` 를 **양축 모두** 준다.
     현재 원천 축 착지 컬럼은 `LS_DATA_INGEST` 에만 있는데 이관은 인입 행이 없다. 신규 컬럼을 만들지 않고
     원문 보관 + **`ExportPrivacyPolicy` 에 이관 분기**를 더한다.
     ⚠ 판정은 **`ExportPrivacyPolicy` 한 곳**에서만 한다(복제 금지 — 이 저장소가 같은 결함을 이미 겪었다).
   - 이벤트 3계층(`event_level1~3_name`)과 `stdg_cd` 는 CO-001·CO-002 의 대응·팩토리를 통해 반영한다.
   - **이관 이력**(`LS_OTSD_DATST_TRNSF_HSTRY`)에 언제·누가·어떤 폴더를·몇 건 가져왔는지 기록한다.

5. **검수 직행** (`AC-045`)
   - ★ **배정 없이 검수가 가능하다** — 코드 실측: `ReviewService.startReview` 는 `LS_TASK_ALTMNT` 를
     조회하지 않고 `ReviewQueryRepository.search` 도 배정과 JOIN 하지 않는다. **상태 행만 `PENDING` 으로
     만들면** 검수 시작·목록 노출이 성립한다(작업자명만 빈칸).
   - ⇒ 코드 변경이 거의 없다. `LS_RAW_DATA_STATUS` 행을 `PENDING` 으로 생성하는 것으로 끝난다.
   - 작업자 배정은 **선택**이다(R6).

6. **신규 API — 비식별 완료 기록** (`ADR-048` 이 요구한 *"비식별 완료를 기록하는 별도 행위"*)
   - 대상: **영상이 없어 내부 비식별을 돌릴 수 없는 원본 이관 영상**.
   - 외부에서 비식별한 산출물(프레임·영상) 경로를 받아 **실제 파일 존재를 검증한 뒤에만**
     `DE_IDNTF_SRC_FILE_PATH_NM`(·비식별 영상 경로)을 채우고 `DE_IDNTF_CMPTN_YN='Y'` 로 내린다.
   - ★ `ADR-048` 이 명시한 위험을 그대로 막는다 — *"비식별 완료를 기록하는 행위가 실제 처리 여부를
     확인하지 않고 기록만 바꾸는 수단이 되면, 처리되지 않은 산출물이 승인될 수 있다."*
     **파일 검증 없는 플래그 변경 경로를 만들지 않는다.**
   - 경로 검증은 CO-002 와 같은 규칙(`toRealPath()` 검증 + 그 실경로 사용).
   - ⚠ **`AC-044` 중복 거부와 충돌하지 않는다** — 재이관이 아니라 별도 엔드포인트다.
   - 엔드포인트 번호·경로·인가는 Phase 3.6 에서 `API-212` 로 신설해 확정한다.

**불변**

- `LS_DATA_INGEST` 에 쓰지 않는다. 저작도구가 그 테이블을 쓰는 통로는 내부 업로드 1곳뿐이며
  `LsDataIngestWriteGuardTest` 가 이를 기계적으로 고정한다 — **그 가드를 우회하거나 완화하지 않는다.**
- 승인 이후 경로(버전 스냅샷 · export · `TASK_COMPLETED`)는 기존 그대로 탄다(R7). 새 분기를 만들지 않는다.
- `ReviewService` 의 기존 게이트 순서(인가 → `'F'` 게이트 → 상태 전이 → 라벨 게이트)를 바꾸지 않는다.
- `ExportPrivacyPolicy` 의 기존 4칸 판정(`video`/`image` × `orgnl`/`deid`)과 상수는 유지하고 **분기만 추가**한다.

**주의**

- 적재는 **파일 I/O + 다건 INSERT** 다. 커넥션을 쥔 채 NAS I/O 를 하지 않는다(커넥션 기아 전례).
  스캔·파싱은 트랜잭션 밖, 영속화만 트랜잭션 안(`ImportPersistTxService` 분리).
- 대량 INSERT 는 1건씩 `save` 하지 말고 `saveAll`/배치로 한다.
- 부분 실패 시 **영상만 만들어지고 프레임이 없는 상태**가 남지 않게 한다 — 실패하면 통째로 롤백한다.

**수용기준**

- `AC-044` — 같은 산출물 재적재 시 409 + 기존 영상 식별번호 안내.
- `AC-045` — 적재 직후 배정 없이 검수 목록에 뜨고 검수 시작이 가능하다.
- `AC-046` — 원본 이관 영상은 승인이 412. 비식별 완료가 기록되면 승인이 정상 진행되어 산출물·통지가 나간다.
- `AC-047` — 짝 없는 이미지·건수 불일치가 있어도 적재가 성공하고, 프레임 수가 **실제 파일 수**와 같다.
- 산출물의 `video`/`image` 원천 PII 3필드가 `LS_DATA_META` 에 원문으로 남고 export 에 반영된다.

## §4 영향·리스크

- **하위호환**: 신규 엔드포인트 + 신규 `SRC_TYPE` 값. 기존 검수·export·통지 경로는 그대로 재사용하므로
  **그 경로에 이관 영상이 처음 흘러들어간다**는 점이 실질 위험이다.
- **되돌리기**: 적재분은 `SRC_TYPE='IMPORTED'` 로 식별 가능하다. 단 **승인·통지가 나간 뒤에는 되돌리지
  않는다**(이 저장소의 구속 원칙 — 승인된 학습데이터는 되돌리지 않는다).
- **리스크**:
  - `RAW_FILE_PATH_NM` 이 잘못되면 export 가 **조용히 FAILED** 로 마감된다(CO-001 §4 참조).
  - 원천 PII 판정을 `ExportPrivacyPolicy` 밖에 복제하면 화면 값과 파일 값이 갈린다(전례 있음).
  - 비식별 완료 기록 API 가 파일 검증 없이 플래그만 바꾸면 **비식별되지 않은 산출물이 관제로 나간다.**

### ★critical — 시험이 전부 green 인데 수용기준이 깨져 있었다

이관 프레임을 `imports/{식별자}/frames/…` 에 저장했는데, 비식별 산출물 판정의 **단일 진실원**은
**`frames/deid/**` 또는 `videos/**`** 접두를 요구한다.

**왜 접두가 판별자인가** — 원본 기준경로와 비식별 기준경로가 **같은 디렉터리일 수 있어**
접두 자체가 축을 가른다. `imports/…/frames/` 는 **어느 축인지 말하지 않는다.**
⇒ 새 설계 결정이 아니라 **기존 규약 위반**이었다.

**귀결(둘 다 `AC-046` 위반)**: ①비식별 완료로 가져온 영상의 산출물이 **전 프레임 거부 → 실패 마감**
→ 관제 통지가 안 나가고 실패 회수기가 **영구 재시도** ②같은 영상의 **프레임 이미지 403** —
CO-002 의 `IMPORTED` 예외는 비식별 경로가 **비어 있을 때만** 타서 이 경우를 못 잡는다.
**그 분기가 막으려던 "검수 화면 백지"가 그대로 발생했다.**

**왜 시험이 못 잡았나** — `transfer` 시험 13건 중 **적재 이후 산출물·프레임 서빙까지 잇는 것이 0건**이었다.
그래서 회귀 가드를 **「적재 → 프레임 이미지 200 → 승인 → 산출물 성공 마감」** 통합으로 요구했다.
경로 문자열만 단언했으면 같은 결함이 다시 통과한다.

⚠ **판정기를 넓히지 않았다** — 접두 목록을 넓히면 원본과 비식별을 구분하는 유일한 수단이 무너진다.
판정기가 앞 두 세그먼트만 보므로 잎은 자유이고, 따라서 `rawSn` 없이도 규약을 만족한다.

### ★critical 을 닫다가 드러난 것 — 상대경로 기준경로가 조용히 깨진다

기준경로 설정이 **상대경로면** 저장값도 상대경로가 되고, 소비측이 base 아래에서 **다시 해석**해
경로가 두 번 겹친다. 파일은 실제로 옮겨져 있는데 판정이 **`MISSING` 으로 조용히 떨어진다.**
기존 프레임 생산자 둘이 이미 base 를 절대경로로 펴는 **관례를 코드로만** 갖고 있어 같은 관례를 따랐다.
⚠ **운영 설정은 절대경로라 로컬·시험에서만 드러난다** — 반대로 시험 설정만 절대경로로 바꿔 넘어가면
결함이 그대로 남는다.

### 그 밖에 닫은 것

- **동시 적재가 먼저 성공한 쪽의 파일을 지웠다** — staging 이 요청 단위가 아니라 **식별자 단위**라
  두 요청의 목적지 집합이 **같다.** 보상 범위를 "이번에 만든 파일"로 좁히는 것만으로는 안 닫히고,
  **먼저 커밋한 주인이 있으면 아예 지우지 않는** 조건이 함께 필요했다.
- **커밋 뒤 실패가 커밋된 행의 파일을 지웠다** — 보상을 커밋 이전 실패로 좁히고, 이력 마감 실패는
  **트랜잭션 밖에서** WARN 으로 흡수한다(안에서 잡으면 롤백 표시가 서 있어 경계에서 다시 터진다).
- **비식별 완료 기록이 0바이트 파일로 통과**했다 — 배치 경로와 같은 강도(존재 + 크기 초과)로 맞췄다.

### 변이 검증에서 배운 것 (기록)

`Files.move(…, REPLACE_EXISTING)` 는 목적지가 바로가기여도 **따라가지 않고 링크를 교체**한다.
따라서 "목적지 추종"을 잡는 시험은 **원자 이동 유무 변이에 반응하지 않는다** — 그 시험이 지키는 것은
"목적지를 직접 열지 않는다" 쪽이다. **변이를 하나만 돌리면 무엇을 지키는 시험인지 오인해,
정작 원자성 축에는 가드가 없는데 있다고 믿게 된다.**
