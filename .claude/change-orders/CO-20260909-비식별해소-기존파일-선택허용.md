## 1. 무엇을 / 왜

비식별 누락 신고를 해소할 때 고를 수 있는 산출물 후보에서 **기존 파일(신고 이전부터 있던 것,
지금 쓰고 있는 비식별 영상 포함)도 선택할 수 있게** 한다.

지금은 「신고 이후에 만들어진 산출물」만 고를 수 있어, 외부 비식별 프로그램이 새 파일을 내놓기
전에는 해소를 끝낼 방법이 없다. 그 결과 그 영상은 작업락 + `DE_IDNTF_YN='F'` 로 묶인 채 남는다.

## 2. 지금 어떻게 동작하나 (2026-09-09 실측)

**화면** — 관리 > 비식별 신고 > [해소] → 「재비식별 산출물 선택」 창

246 dev 영상 #18 의 해소 창에는 후보가 한 건(`demo-mark-c-1787649357-mask.mp4`) 있는데
「현재 사용 중 · 선택 불가」 로 잠겨 있고 안내가 이렇게 뜬다:

> 신고 이후에 만들어진 정상 영상 파일이 아니라 선택할 수 없습니다. 외부 솔루션으로 비식별을 다시 수행해 주세요.

그래서 [해소 처리] 버튼이 `disabled` 인 채로 남아 해소가 끝나지 않는다.

**판정 코드** — `label/service/DeidentArtifactCandidateFinder`

```java
boolean timeOk   = reportTime != null && (modifiedAt.isAfter(reportTime) || procAfterReport);
boolean eligible = timeOk && DeidentArtifactIntegrity.isValidVideoArtifact(path.toString());
```
`procAfterReport` = 최신 SUCCESS 비식별 처리 시각이 신고시각보다 뒤인가.

## 3. 도메인별 변경 상세

### DOMAIN-012 (비식별화) — 백엔드

**대상**
- `backend/src/main/java/kr/co/cudo/authoring/label/service/DeidentArtifactCandidateFinder.java`
- `backend/src/main/java/kr/co/cudo/authoring/label/service/DeidentReportService.java` (수락 판정)
- `backend/src/main/java/kr/co/cudo/authoring/label/dto/DeidentCandidateResponse.java` (필요 시)

**바꿀 것**
- 후보의 `eligible` 에서 **시간 조건(`timeOk`)을 뺀다.** 무결성만으로 판정한다.
- 해소 수락(`resolve`)도 같은 축으로 맞춘다 — 시간 조건 때문에 409 로 거부하던 경로를 없앤다.
- **판정 지점을 한 곳에 모은다.** 되돌릴 때 한 자리만 보면 되도록.
- 응답에 「신고 이후에 만들어졌는가」를 **표시용 값으로는 남긴다**(선택 가능 여부와 분리).
  화면이 「현재 사용 중」·「신고 이전 파일」을 계속 구분해 보여줄 수 있어야 한다.

**바뀌면 안 되는 것 (불변)**
- **무결성 검사는 그대로다** — `DeidentArtifactIntegrity.isValidVideoArtifact` 불통과 파일은
  여전히 고를 수 없다. 깨진 파일로 신고를 닫는 것은 요청 범위가 아니다.
- **경로 순회 방어(CWE-22) 그대로** — 선택값으로 경로를 조립하지 않고 **목록이 곧 허용목록**이다.
  조회와 수락이 같은 열거 코드를 쓰고, 키는 언제나 basename 이다.
- 해소의 **원자 클레임**(OPEN→RESOLVED 조건부 UPDATE, 영향행수 1 인 성공자만 후속) 그대로.
- 해소 시 발행하는 이벤트 3종과 단계별 재개 규칙 그대로.

### 프론트엔드

**대상** — `frontend/src/features/deident/components/DeidentResolveDialog.tsx`

**바꿀 것**
- 안내 문구를 **무결성 기준으로 바꾼다** — *"신고 이후에 만들어진 정상 영상 파일이 아니라…"* 를
  *"정상적으로 열리는 영상 파일이 아니라 선택할 수 없습니다…"* 로.
- **「현재 사용 중」 표시는 남긴다** — 고를 수는 있되 그것이 지금 쓰이는 파일임은 보여야 한다.
- 「신고 이전 파일」 구분 표시를 **새로 단다** — 선택은 막지 않는다.

⚠ **잠금 자체와 「선택 불가」 배지는 걷어내지 않는다.** 이 CO 초안은 *"「선택 불가」 배지와 안내를
걷어낸다"* 라고 적었으나 그것은 §5 회귀 가드 #3(*무결성 불통과 파일은 여전히 선택 불가*)·
`SCREEN-032` v29(*정상적인 영상 파일이 아닌 후보를 거르는 축은 그대로다*)와 **충돌한다.**
문면대로 지우면 **잠긴 라디오에 아무 설명이 없는** 상태가 된다. 그래서 **문구만** 갈아 끼운다.
(대상 서술은 폐기되는 축을 기준으로 쓰여, 같은 UI 요소가 남는 축에도 쓰이면 함께 지우라는 것처럼
읽힌다 — **대상 서술과 회귀 가드가 어긋나면 가드 쪽이 사양이다.**)

## 4. 인지·수용한 대가 ★

**이 시간 조건은 「신고 대상이 된 바로 그 파일로 신고를 닫는 것」을 막으려고 있던 것이다.**
풀면 **재비식별을 실제로 수행하지 않고도 해소가 가능해진다.** 즉 마스킹 누락이 남은 산출물이
정상(`DE_IDNTF_YN='Y'`)으로 되돌아갈 수 있고, 그 영상은 다시 라벨링·검수·산출물·관제 통지 경로를
탄다.

사용자가 이 대가를 알고 지시한 것이며, 그래서 **되돌리기 쉽도록 판정 지점을 한 곳에 모은다.**

## 5. 회귀 가드 요구

1. 기존 파일(`mtime <= 신고시각`, `procAfterReport=false`)이 후보로 나오고 **선택 가능**하다
2. 그 파일을 골라 해소하면 신고가 실제로 해소된다 — `DE_IDNTF_YN` 복구 · 신고 상태 전이 · 작업락 해제
3. **무결성 불통과 파일은 여전히 선택 불가다** (이 축은 안 풀린다 — 양성 대조)
4. 경로 순회 방어 그대로 — `../x`·절대경로·심링크명은 어떤 후보와도 같아지지 않는다
5. 재-resolve 는 종전대로 409 (원자 클레임 불변)
