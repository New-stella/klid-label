## §1 배경

PR #158 이 관리 기능을 `/admin/*` 로 모으고 진입에 관리자 자격을 요구하게 했다. 그런데 **좌측 메뉴에는
그 다섯 화면이 그대로 펼쳐져 있다** — 검수자로 로그인하면 사용자 관리·연동 서버 주소·파일 업로드·
패스워드 교체·위험 액션이 전부 보인다. 눌러도 진입 화면으로 튀므로 기능상 새는 곳은 없지만,
**「관리 영역을 분리했다」는 그림과 화면이 다르다**(사용자 지적, 2026-08-28).

지금 이렇게 된 것은 실수가 아니라 **의도된 타협**이다. `Lnb.tsx` 가 못박아 두었다 —
*"★유효창을 메뉴 노출 조건으로 쓰지 않는다. 유효창은 관리자 페이지에 들어가 패스워드를 넣어야
열리는데 그것을 노출 조건으로 삼으면 **들어갈 길 자체가 사라진다**."* 즉 그냥 숨기는 것은 답이 아니고,
**진입 경로를 남긴 채 목록을 접어야** 한다.

함께, 「산출물 가져오기」(`/manage/imports`)가 **「업로드」 그룹에 혼자 남아 있다.** 이 화면은 서버 폴더를
훑어 학습데이터를 들여오는 자리라 성격이 관리 행위인데, 관리자 유효창 없이 검수자 권한만으로 열리고
적재까지 실행된다. 파일 업로드(`/admin/uploads`)가 이미 관리자 페이지로 옮겨간 것과 **같은 축에서
어긋나 있다.**

## §2 변경 요지

1. 좌측 메뉴에서 「관리자」 그룹의 항목 나열을 없애고 **「관리자 페이지」 한 줄**만 맨 아래에 둔다.
   누르면 진입 화면(`/admin`)으로 가고, 자격을 확인하면 **관리자 페이지 안에서** 하위 화면을 고른다.
2. 「산출물 가져오기」를 `/manage/imports` → **`/admin/imports`** 로 옮기고 「관리자」 소속으로 만든다.
   화면 진입에 유효창을 가산하고, **적재 실행·매핑 저장 창구에 서버 게이트**를 붙인다.
3. 「업로드」 그룹은 항목이 비어 사라진다.

## §3 도메인별 변경 상세

### 프론트 (NAV-001 · SCREEN-039 · SCREEN-040)

- **대상 파일·심볼**
  - `frontend/src/components/layout/Lnb.tsx` — `MENU` 의 「업로드」·「관리자」 그룹, `registerManualUploadMenu`
  - `frontend/src/router/index.tsx` — `manage/imports` 라우트, `AdminRoute` 하위
  - 관리자 페이지 내부 내비게이션(신규) — 진입 후 하위 6개를 고르는 자리
- **변경**
  - 「관리자」 그룹을 **항목 1개**(`관리자 페이지` → `/admin`)로 접는다. 하위 5개는 좌측 메뉴에서 뺀다.
  - 「업로드」 그룹을 없앤다(항목이 「산출물 가져오기」 하나뿐이고 그것이 관리자로 옮겨간다).
  - `manage/imports` 라우트를 `admin/imports` 로 옮기고 `AdminRoute`(역할 가드 **바깥** · 유효창 **안쪽**)로 감싼다.
  - 관리자 페이지 안에 하위 화면 목록을 둔다 — 사용자 관리 · 연동 서버 주소 · **산출물 가져오기** ·
    파일 업로드(토글) · 패스워드 교체 · 위험 액션.
- **불변**
  - ★**진입 경로를 없애지 않는다.** 「관리자 페이지」 한 줄은 **유효창 보유 여부와 무관하게** 보인다 —
    노출 조건으로 삼으면 들어갈 길이 사라진다(`Lnb.tsx` 가 이미 못박은 규칙).
  - ★**진입 화면(`/admin`) 자신에게는 `AdminSessionGuard` 를 걸지 않는다** — 자기 자신으로 무한히 되돌아간다.
  - 역할 가드가 **바깥**, 유효창이 **안쪽**이라는 순서. 뒤집으면 「패스워드를 아는 사람이 관리자」가 된다.
  - `allow` 는 라우트 가드와 **같은 조건**이어야 한다 — 갈리면 「메뉴는 없는데 주소로는 들어가진다」가 된다.
  - 파일 업로드의 `isDevUploadEnabled()` 토글 판정은 그대로. 라우트와 메뉴가 **같은 판정**을 써야 한다.
  - 구 주소 `/manage/imports` 로 들어오면 새 주소로 보낸다(북마크 보존).
- **수용기준**
  - 검수자로 로그인하면 좌측 메뉴에 관리자 하위 화면 이름이 **하나도 보이지 않는다**.
  - 「관리자 페이지」 한 줄은 유효창이 없어도 보이고, 누르면 `/admin` 진입 화면이 열린다.
  - 자격 확인 후 관리자 페이지에서 「산출물 가져오기」로 갈 수 있다.
  - `/admin/imports` 를 주소로 직접 열면 유효창이 없을 때 `/admin` 으로 바뀌고, 확인 후 **원래 가려던
    `/admin/imports` 로 되돌아온다**.
  - 구 주소 `/manage/imports` 가 새 주소로 이어진다.

### DOMAIN-017 (외부 산출물 이관) — `transfer/`

- **대상 파일·심볼**
  - `transfer/controller/ImportController` — `POST /v1/imports` (적재 실행)
  - `transfer/controller/ImportMappingController` — `POST /v1/import-mappings` (매핑 저장)
- **변경**: 두 **쓰기** 창구에 `@RequiresAdminSession` 표식을 붙인다.
- **불변**
  - ★**조회에는 붙이지 않는다** — `ImportBrowseController`(`GET /v1/imports/folders|files`) ·
    `ImportHistoryController` · `ImportMappingController` 의 `GET`. 조회까지 막으면 화면이 열리자마자
    빈 채로 죽는다(ADR-046 의 「조회는 검수자 권한만으로」).
  - ★**`POST /v1/imports/scan` 에는 붙이지 않는다.** POST 지만 **아무것도 저장하지 않는다**고
    `AC-041` 이 규정하고 컨트롤러 javadoc 이 그것을 명시한다 — 성격이 조회다.
  - ★**표식은 메서드에 붙인다.** 클래스에 붙이면 그 안의 `GET` 까지 함께 잠긴다(PR #158 되돌림 실증에서
    이미 「조회가 통째로 사망」으로 확인된 실패 양식).
  - `POST /v1/videos/{rawSn}/deident-complete`(`ImportDeidentCompleteController`)는 **이번 범위 밖**이다 —
    경로 축이 `/v1/videos` 이고 비식별 해소 동선이라 이 화면 소속인지 별도 확인이 필요하다.
- **수용기준**
  - 유효창 없이 `POST /v1/imports` → **403** + 재인증 안내 문구.
  - 유효창을 실으면 → 기존과 같은 결과(계약·응답 스키마 불변).
  - 유효창 없이 `GET /v1/imports/folders`·`/files`·이력 → **200**.
  - 유효창 없이 `POST /v1/imports/scan` → **200**.

## §4 영향·리스크

- **하위호환**: 화면 주소가 바뀐다(`/manage/imports` → `/admin/imports`). 리다이렉트로 흡수한다.
  **BE API 경로는 그대로다**(`/v1/imports`) — 이 변경의 축은 화면 배치와 게이트이지 창구 개명이 아니다.
- **운영 동선이 한 단계 늘어난다** — 산출물 가져오기를 쓰려면 관리자 자격 확인을 먼저 거친다.
  유효창은 기본 10분이라 긴 적재 도중 만료될 수 있다. ⚠ **적재 실행 시작에만 요구**되고 진행·조회에는
  요구되지 않아야 한다(업로드 이어올리기와 같은 비대칭 근거).
- **되돌리기**: 메뉴·라우트는 파일 두 개라 쉽다. 서버 표식은 붙인 메서드에서 떼면 된다.

- LogiCraft 는 **MCP 도구 대신 `lc.py` HTTP 채널**로 쓴다(메인 워크트리 루트에 있고 `sys.path` 로 잡는다).
  전사 단계가 없어 한글 손상이 원천 차단된다.
- 기준선은 **REST `kit-export`** 로 받는다 —
  `GET {API_BASE}/projects/4ece2c3f-8e99-46f5-9580-71108a76e578/kit-export?ids=A,B`.
  `API_BASE` 는 MCP URL 에서 끝의 `/mcp` 를 뗀 것.
- 편집 절차: 기준선 받기 → **파이썬 치환으로 기대본 생성**(각 치환 `count==1` assert) → `update_item`
  (`data_mode=replace` + `base_version`) → **재조회 후 문자 단위 diff**(`equal` 외 opcode 0) →
  희귀 음절 스캔. 기대본을 손으로 조립하지 말 것.
- ⚠ **`screen_spec` 을 고치면 정적 렌더가 즉시 낡는다.** `source_hash` 는 `sections` 의 sha256(compact JSON)
  이며, 재생성기는 `docs/screen-design/klid-authoring-screens/bin/generate-wireframes.py`

  `upload_static_render`(`sections: []`·`description: ""` 를 **명시**해야 기존 값이 지워지지 않고 유지된다).
  `SCREEN-039`·`SCREEN-040` 둘 다 렌더를 갖고 있으므로 **이번에 재게시가 필요하다.**
- 이번 라운드 스크립트는 세션 scratchpad 에 있다(`nav_edit.py`·`verify_nav.py`). 사라졌으면 위 절차대로

## §8 이 CO 범위 밖 — 다음 CO 로 넘긴 것

사용자 등록/승인 시나리오. 2026-08-28 논의에서 확정한 사실만 남긴다.

- 지금 「등록 안 된 사용자가 진입할 때 등록」의 정체는 **역할 자가부여**다(`POST /v1/auth/role-claim`).
  본인이 관리자 공유 패스워드를 넣고 **자기 역할을 고른다**. 그래서 **그 패스워드를 아는 사람은
  누구나 검수자**가 되며, 코드 javadoc 이 그것을 「인지·수용한 잔여 위험」으로 적어 두었다.
- **관리자가 미리 등록하는 방식은 지금 형상에서 성립하지 않는다.** 사용자 마스터 PK(`USER_NO`)가
  관제가 발급하는 번호이고, **진입 전에는 알 수 없다.**
- ★**계정(`userId`)을 매칭 키로 쓸 수 없다** — 그 값은 JWT 클레임이 아니라 **요청 바디**로 오는
  위조 가능한 표시 정보다(`RoleClaimRequest` 주석이 「표시용」이라고 명시, 선택 필드). 매칭 키로 삼으면
  아무나 남의 계정으로 등록된 역할을 가로챈다(`USER_NO` 를 바디로 안 받는 이유와 같은 종류 — CWE-639).
- 서명돼 오는 것은 `sub`(=관제 번호) · `role` · `channel` · `exp` · `name` 뿐이다.
- ⇒ 갈림 둘: **(A) 관제에 계정·이메일을 JWT 클레임에 실어 달라 협의**하면 사전 등록이 성립한다.
  **(B) 협의 전까지는 승인 모양** — 진입이 알려주는 `sub` 로 대기 행을 만들고 관리자가 승인.
- **우리 PK 분리**(우리 surrogate PK + `관제사용자번호` UNIQUE·nullable)는 (A)(B) 어느 쪽이든 이득이다.
  지금은 PK 가 관제 번호라 「번호를 모르면 행 자체를 못 만든다」가 구조적 제약이다.
- ⚠ **자가부여를 없애면 안 된다.** 최초 REVIEWER 를 만들 경로가 사라져, 예전에 `/dev/login` 을
  부트스트랩으로 쓰던 더 위험한 자리로 되돌아간다(2026-08-04 확정에 「되돌리지 말 것」이 붙어 있다).
  좁힌다면 **REVIEWER 0명일 때만 열리는 부트스트랩 전용**이 후보다.
