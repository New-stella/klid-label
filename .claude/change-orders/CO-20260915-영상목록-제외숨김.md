## §1 배경

### 사용자가 제기한 것

잘못 들어온 영상과 시험 데이터가 목록에 계속 남아 실제 작업 대상을 가린다. 지울 수는 없다 — 관제가 보낸 자산이고 이미 배치·통지를 탄 것도 있다. **보이지 않게만** 하고 싶다.

### 지금 그런 수단이 없다 (실측)

`LS_DATA_RAW` 의 현재 컬럼 전수를 확인한 결과 **가시성 축이 없다.** `PRVC_YN`·`DE_IDENT_YN`·`*_INCL_YN` 은 전부 **개인정보 성질 선언**이지 「이 영상을 화면에서 뺀다」가 아니다.

가시성에 가장 가까운 것은 컬럼이 아니라 **술어**로 존재한다 — `DerivativeWorkEligibility`(미검수 파생 배제)와 `InternalWorkScope`(포털 채널 배제). 둘 다 **세 형태**(`Q타입` 버전 · `rawSn` 상관 버전 · JPQL 문자열 조각)를 제공하며, **이번 신규 술어가 그대로 따를 형태**다.

### 가장 가까운 선례는 프레임 단위 논리 폐기다

`LS_DATA_SRC.DSCD_YN`(폐기여부)이 **행을 지우지 않고 표시만 해서 산출물에서 빼는** 구조를 이미 갖고 있다. 네 요소를 그대로 참고한다.

| 요소 | 선례가 하는 일 |
|---|---|
| 쓰기 | **단일 지점** — 조건부 원자 UPDATE(`WHERE ... AND 값 <> :새값`), **반환 행수가 곧 「실제로 바뀌었는가」**. 같은 값 재전송은 멱등 무변경이고 감사도 남기지 않는다 |
| 판정 기준 | 행 락 이후의 **DB 현재 값**을 다시 읽는다(1차 캐시 금지) |
| 감사 | 작업 이벤트 원장에 전용 이벤트 종류 두 개(폐기·복원) |
| 조회 배제 | 배제 술어를 **상수 한 곳**에 두고 전 호출부가 공유 — *"호출부마다 비교를 재구현하면 한 곳만 빠져도 폐기한 것이 그대로 나간다"* |

### 배정을 푸는 창구가 없다 — 이번에 드러난 별건

「배정된 영상은 제외를 거부하고 먼저 배정을 풀게 한다」로 정했는데, **배정을 푸는 수단이 존재하지 않는다.**

배정 쓰기 창구는 한 곳뿐이고 그 안에 **생성과 재배정 둘만** 있다. 삭제 창구도, 리포지토리의 삭제 호출도 없다. 배정표에는 **상태·활성 컬럼조차 없어** 배정은 행이 있거나 없거나뿐이다 — 즉 **행을 지우는 것 말고는 푸는 방법이 없는데 그 창구가 없다.**

⇒ 그래서 이번 CO 가 **배정 해제 창구를 함께 신설**한다. 없는 것 자체가 이미 결함에 가깝다 — 잘못 배정했을 때 되돌릴 길이 재배정뿐이라 **배정 자체를 취소할 수 없었다.**

## §2 변경 요지

1. **영상에 「제외」 표시를 둔다** — 행을 지우지 않고 표시만 하며 **되돌릴 수 있다.**
2. **세 목록에서 제외분이 보이지 않는다** — 영상 처리 현황 · 작업 목록 · 검수 목록.
3. **「제외됨 N건」을 상시 표시**하고, **누르면 제외분만 보는 화면으로 전환**한다. 거기서 복원한다.
4. **배정된 영상은 제외를 거부**하고, 그 거부가 막다른 길이 되지 않도록 **배정 해제 창구를 신설**한다.
5. **누가·언제·왜**를 작업 이벤트 원장에 남긴다.
6. **화면 시야 밖으로는 새지 않는다** — 배치·관제 통지·데이터마트 뷰·산출물·관제 pull 은 **전부 무변경**.

## §3 도메인별 변경 상세

### 공유기반 선처리 (메인 직접, Phase 3.5) — `db/migration/V39`

> ⚠ 현재 최대 마이그레이션 = `V38__add_actor_role_cd_to_ls_task_evnt_log.sql`. **신규는 `V39`.**

**① 제외 표시 컬럼 — `LS_DATA_RAW.EXCL_YN`**

**표준용어 판정 완료 (CSV 정본 grep, 재조사 불요)**

| 축 | 값 | 출처 |
|---|---|---|
| 용어 | **제외여부** | **행안부 공통표준용어 1차(2020-08)** — *"따로 떼어 내어 한데 헤아리지 않았는지 여부"* |
| 물리명 | **`EXCL_YN`** | 같은 행 |
| 도메인 | **여부C1** — `CHAR(1)`, 값역 `Y`/`N` | 같은 행 |

- **1순위(행안부 공통표준)에 그대로 있어 신규 등록이 필요 없다.** 사업표준용어에는 이 개념이 **0건**이다.
- ⚠ **`HIDE`·`EXPSR` 를 쓰지 않는다.** 공통표준단어에 숨김(`HIDE`)·노출(`EXPSR`)이 있고 「메뉴숨김여부(`MENU_HIDE_YN`)」·「노출여부(`EXPSR_YN`)」 같은 용어도 있으나, **사용자가 쓴 말이 「제외」**이고 그 용어가 1순위에 실재한다. 같은 개념에 두 이름을 만들지 않는다.
- ⚠ **`{대상}_EXCL_YN` 꼴로 늘리지 않는다**(통계제외여부·점검제외여부 같은 파생형이 표준에 있으나) — 이 컬럼이 앉는 표가 이미 영상 원장이라 대상이 자명하고, 파생형을 쓰면 **그 합성 용어를 새로 등록**해야 한다.

```
ALTER TABLE ls_data_raw
    ADD COLUMN IF NOT EXISTS excl_yn character(1) NOT NULL DEFAULT 'N';
```
+ `COMMENT ON COLUMN` — **뜻을 못박는다**: *"제외여부 — 이 영상을 저작도구 화면 목록에서 뺄지에 대한 사람의 판정. Y=제외 / N=표시(기본값). 행을 삭제하지 않고 표시만 한다(복원 가능). **화면 시야만이며 배치·관제 통지·데이터마트 뷰·학습데이터 산출물에 영향을 주지 않는다.** 행안부 공통표준용어 제외여부(EXCL_YN) + 공통표준도메인 여부C1."*

★ **`NOT NULL DEFAULT 'N'` 로 둔다** — nullable 로 두면 전 조회부가 `COALESCE` 를 재구현해야 하고 한 곳만 빠져도 제외한 영상이 샌다. 기존 행은 기본값으로 전부 `'N'`(=표시)이 되므로 **적용 즉시 동작이 바뀌지 않는다.**

**② 감사 이벤트 종류 둘 — 마이그레이션 불요**

`LS_TASK_EVNT_LOG.EVNT_TYPE_CD` 에 **값 제약이 없다**(`character varying(20) NOT NULL`, CHECK 없음 — 직전 라운드에서 원 DDL 실측). 상수만 더하면 된다.

- **`VIDEO_EXCLUDE`**(13자) · **`VIDEO_RESTORE`**(13자) — 20자 상한 안.
- `RAW_DATA_ID`(영상) · `ACTOR_USER_NO`(누가) · `ACTOR_ROLE_CD`(그 시점 역할, `V38`) · `OCRN_DT`(언제) · `RSN`(왜, 500자)가 **이미 다 있다.**
- ⚠ **사유(`RSN`) 취급이 프레임 폐기 선례와 다르다.** 선례는 `RSN` 에 토큰 하나만 싣고 자유 문구를 금지하는데, 이번은 **「왜」가 사용자 확정 요구**라 자유 문구를 받는다. 대신:
  - **제외 시 사유 필수 · 복원 시 선택**(사유 없이 제외하면 「왜」가 남지 않는다).
  - **개행·제어문자 제거 + 500자 상한**(로그 인젝션 CWE-117 · DB 오류로 새는 것 차단).
  - 화면 안내에 **개인정보를 적지 말 것**을 명시.

**③ 온프렘 반영 — 빠뜨리면 현장 기동이 실패한다**

온프렘은 Flyway 를 쓰지 않는다. **같은 파일명으로 바이트 그대로** 두 곳에 반영한다.
- `deploy/onprem/db/incremental/V39__....sql` (복사 — **손으로 다시 쓰지 말 것**)
- `deploy/onprem/db/schema.sql` (`ls_data_raw` 정의에 컬럼 추가)

회귀 가드 `OnpremIncrementalSyncTest` 가 존재·**바이트 일치**·역방향을 결박하므로 빠뜨리면 시험이 빨개진다. ⚠ 그 가드는 `schema.sql`(신규 설치 덤프)은 **검사하지 못한다** — 증분을 맞췄다고 덤프까지 맞았다고 여기지 말 것.

**새 final 클래스 하나가 판정을 소유한다.** 이름 후보 `VideoExclusionScope`. `DerivativeWorkEligibility`·`InternalWorkScope` 와 **똑같이 세 형태**를 제공한다.

### DOMAIN-003 (영상·프레임 수집) — 제외·복원 창구 + 영상 목록

**(가) 제외·복원 창구 신설**

- 인가 **검수자 이상**(`hasRole('REVIEWER')` — 역할 계층으로 관리자도 통과한다. 관리자 전용으로 좁히지 **않는다**).
- 같은 URL 에 쿼리 파라미터로 행위를 가르지 않는다(이 저장소 규약) — **제외와 복원을 별개 창구**로 둔다.
- **쓰기 단일 지점**을 두고 프레임 폐기 선례를 그대로 복제한다:
  - 조건부 원자 UPDATE(`... AND EXCL_YN <> :새값`) → **반환 행수로 변경 여부 판정**
  - 같은 값 재전송은 **멱등 무변경**이고 감사도 남기지 않는다
  - 변경된 경우에만 `LS_TASK_EVNT_LOG` 기록
- ★**배정 존재 시 거부** — 그 영상에 활성 작업자 배정이 있으면 제외를 거부하고 **「먼저 배정을 해제하세요」**로 안내한다. 응답 코드는 **409**(일시 조건 — 배정을 풀면 된다).
  - 판정과 삭제 사이 창을 막기 위해 **조건을 최종 UPDATE 문에 함께 박는다**(배정 존재 여부를 EXISTS 로). 사전 조회만으로는 그 사이에 배정이 생길 수 있다.
- **복원에는 배정 조건이 없다**(제외된 영상엔 배정이 없으므로 성립할 자리가 없다).

**(나) 영상 목록에서 제외분 배제 + 「제외됨 N건」**

- **조건 조립 지점이 두 곳에 텍스트로 복제돼 있다** — 목록 JPQL 과 count JPQL. **술어 조각 상수로 넣어 양쪽에 함께 붙게** 할 것(한쪽만 붙이면 건수와 내용이 어긋난다).
- 이 화면은 **별도 집계 엔드포인트가 없고** 화면이 `totalElements` 만 쓴다 ⇒ 「제외됨 N건」은 **페이지 래퍼에 키 하나를 더해** 싣는다.
  - ★선례를 그대로 따른다 — `ReviewListPage`(`PageImpl` 상속 + 커스텀 직렬화). *"응답 본문을 다른 모양으로 감싸면 `content`·`totalElements` 같은 기존 페이지 계약이 통째로 바뀐다. 상속으로 속성 하나만 더하면 기존 키·타입·의미가 그대로 남고 새 키 하나가 는다"*
  - **키 이름은 상수 한 곳**에만 둔다.
  - **행이 0건인 페이지에서도 값이 실려야 한다** — 제외분만 남은 상태에서 화면이 건수를 모르면 되돌아갈 길을 안내하지 못한다.
- **「제외분만 보기」 파라미터** — 신규 optional 파라미터 하나. **기본값 불변**(안 보내면 종전과 같이 제외분이 빠진 목록). 값역은 **표시분만 / 제외분만** 두 갈래로 충분하다(둘 다 보기는 요구에 없다 — 섞이면 어느 것이 제외분인지 행마다 구분해야 한다).

**불변 (반드시 지킬 것)**
- **배치 경로에 술어를 넣지 않는다** — 스테일 회수 스윕과 단계 진행 전부. 넣으면 제외한 영상의 파이프라인이 멈춘다.
- **관제 통지 조립·학습데이터 산출·관제 pull 에 넣지 않는다.**
- ★**콘텐츠 해시 입력에 `EXCL_YN` 을 넣지 않는다.** 넣으면 제외를 토글하는 것만으로 산출물 해시가 바뀌어 **불필요한 재산출과 수정 통지**가 나간다.
- **통계 대시보드에 넣지 않는다** — 그쪽은 「자산 총량」 축이라 화면 숨김과 다른 축이다.
- **포털 목록에 넣지 않는다** — 다른 채널이다.

### DOMAIN-015 (작업 배정) — 배정 해제 창구 + 작업 목록

**(가) ★배정 해제 창구 신설**

- 인가 **검수자 이상**(배정 생성·재배정과 같은 축).
- 배정표에 상태 컬럼이 없으므로 **행을 지운다.**
- **이력은 남는다** — 작업 이벤트 원장에 해제 이벤트를 기록한다(배정·재배정이 이미 그 자리에 남고 있다). 이벤트 종류 신규 **`UNASSIGN`**(8자).
  - `SUBJECT_USER_NO` 에 해제된 작업자를 싣는다(재배정이 `PREV_USER_NO`·`SUBJECT_USER_NO` 를 쓰는 방식과 정합).
- **되돌리려면 다시 배정한다** — 해제 취소 창구를 따로 두지 않는다.
- ⚠ **작업 결과(라벨·이력)는 지우지 않는다.** 배정만 푼다 — 그것이 「해제」의 뜻이다.
- ✅ **확정(게이트②)**: **검수 대기·검수 중·승인 상태는 배정 해제를 거부**한다(409). 배정이 그 워크플로의 전제이고, 풀면 검수 흐름이 주인 없는 상태가 된다. 해제가 열리는 것은 **아직 검수로 넘어가지 않은 배정**뿐이다.
- 그 결과 **작업이 진행된 영상은 제외할 수 없다** — 배정을 못 풀기 때문이다. 이것은 의도다: 제외의 대상은 「잘못 들어온 것·시험 데이터」이지 실제로 작업한 자산이 아니다.

**(나) 작업 목록에서 제외분 배제 — 축이 둘이다**

- **검수자 축** — 조건 조립 단일 지점 한 곳에 술어를 넣으면 **목록·count·KPI 집계·이벤트유형 옵션 네 경로**가 한 번에 덮인다. 구동 테이블이 영상 원장이므로 `notExcluded(raw)` 형태.
- **작업자 축** — 구동 테이블이 **배정 행**이라 `notExcludedByRawSn(...)` 상관 형태. 여기 한 곳이 **목록·count·이벤트유형 옵션 세 경로**를 덮는다.
  - ★**작업자 축은 「구조적으로 도달 불가」한데도 붙인다.** 배정된 것은 제외를 거부하므로 제외된 영상에는 배정이 없고, 따라서 배정 기준 목록에는 원래 나타나지 않는다. 그럼에도 붙이는 이유는 **거부 판정이 뚫렸을 때의 마지막 방어**이고 비용이 술어 한 줄이기 때문이다.
  - ⚠ 작업자 축 KPI 는 **서버 집계가 아니라 화면이 현재 페이지 행을 세는 방식**이다(작업자는 검수자용 집계 창구를 부를 수 없다). 목록이 줄면 카드도 줄지만 **원래 전체 기준이 아니라 페이지 기준**이며 이번 CO 가 그것을 고치지 않는다.
- **작업자 축에는 「제외됨 N건」을 싣지 않는다** — 작업자는 제외 권한이 없고 제외된 영상이 그 목록에 나타날 일도 없다.

**(다) 집계 불변식 주의**

두 축 모두 집계에 **버킷 합 = 전체 건수** 불변식이 걸려 있다(어긋나면 예외로 죽는다). 제외 술어는 **조회 조건에만** 붙이고 버킷 판정식은 건드리지 말 것 — 그러면 불변식이 유지된다.

---

### DOMAIN-005 (검수) — 검수 목록에서 제외분 배제

- 조건 조립 단일 지점 한 곳이 **목록·count·KPI 집계 세 경로**를 덮는다.
- ★**구동 테이블이 영상 원장이 아니라 검수 워크플로 상태 표다.** 따라서 `notExcludedByRawSn(...)` **상관 EXISTS 형태가 필수**다.
- ⚠ 같은 자리에 *"채널 술어를 붙이지 않는다 — 의도된 것이다"* 라는 기존 주석이 있다. 그 근거는 **「포털 자산은 이 표에 행이 영영 생기지 않아 구조적으로 도달 불가」**인데, **제외 축에는 그 논리가 적용되지 않는다**(제외한 영상도 상태 행을 이미 갖고 있다). **붙여야 한다.**
- 「제외됨 N건」은 **기존 집계 창구(`/reviews/summary`)에 필드 하나를 더해** 싣는다 — 그 창구가 이미 목록과 같은 조건 조립을 공유하므로 **조건 드리프트가 생기지 않는다.**

---

### 프론트 — SCREEN-008 · SCREEN-012 · SCREEN-018

- **제외 버튼**(행 단위) — 검수자 이상에게만 보인다. 누르면 **사유 입력 + 확인** 모달.
  - ⚠ 되돌릴 수 있는 작업이지만 **화면에서 사라지는** 작업이라 확인 단계를 둔다.
  - 배정된 영상이면 **버튼을 미리 비활성 + 사유를 툴팁**으로 알린다(409 를 받고 나서야 아는 동선을 만들지 않는다).
  - ✅ **실측 확정(게이트②)**: 영상 목록 응답에 **배정 식별자·작업자·배정 상태가 이미 실린다.** 서버에 필드를 더할 필요가 없고, **배정 해제 버튼도 이 화면에서 바로 열 수 있다**(배정 식별자를 이미 갖고 있다).
- **「제외됨 N건」 상시 표시** — 0건이어도 표시한다(감춘 사실 자체가 드러나야 한다는 것이 확정 요구다). 누르면 **제외분만 보기**로 전환하고, 그 상태에서 **복원 버튼**이 나온다.
- **제외분 보기에서는 배정·검수 동작을 노출하지 않는다** — 제외된 것을 작업 대상으로 만들 수 있으면 제외가 무의미해진다.
- **배정 해제 버튼** — 검수자 작업 목록의 배정 행에서. 재배정 모달과 **같은 자리**에 둔다.
- 값역·문구는 **서버 응답을 그대로 쓴다**(화면이 숫자·문구를 따로 적으면 설정이 바뀔 때 한쪽만 고쳐진다 — 직전 라운드의 일괄 승인 상한이 같은 이유로 서버 값을 쓴다).

| 결박하는 것 | 이번 변경의 영향 |
|---|---|

신규 파라미터는 **전부 optional · BE 기본값 불변**.

## §5 이 라운드의 범위 밖

- **사용자 삭제·이름 수정(관리자 전용)** — 별도 CO. 구속 결정은 이미 굳어 있다(실삭제 · 관리자 삭제 불가 · 역할·배정 동반 삭제 필수 · 감사 원장 보존).
- **작업자 축 KPI 를 서버 집계로 옮기는 것** — 선행 한계이며 이번 CO 가 만든 것이 아니다.
- **라벨링 화면 진입을 제외가 막는 것** — **막지 않는다.** ①「화면 시야만」이 구속 결정이고 ②배정된 것은 제외를 거부하므로 작업자는 배정 존재 판정에서 이미 막히며 ③막으면 「제외분만 보기」에서 상세로 들어가는 길까지 함께 닫힌다. ⚠ 그 결과 **검수자가 주소를 직접 넣으면 제외된 영상의 상세가 열린다** — 인지·수용한 비대칭이다.

## §5-1 설계 선반영 중 확정된 것 (라운드 1~3A)

| # | 확정 | 근거 |

## §5-1c 검증에서 배운 것 (다음 라운드에도 적용)

- ★**평문으로 번호를 적어도 링크가 생기지 않는다.** 잇는 방법은 셋뿐이고 그중 **결정문 쪽 참조 배열 추가**만 본문을 더럽히지 않는다. 나머지 둘은 위키 문법을 납품 산출물에 남기거나 단일값 칸을 덮어써 **기존 근거를 지운다.**
- ★**병렬 담당은 서로를 못 본다.** 이번에 **경로가 어긋나고**(제외/복원) **같은 키가 두 창구에 들어가고**(건수) **표시 자리가 갈렸다**(세 화면). 전부 묶음 회수 직후 **메인이 교차 확인**해서 잡았다. ⇒ **묶음마다 교차 확인은 선택이 아니다.**
- ★**지시의 빈틈을 담당이 물어 온 것이 두 번 다 옳았다** — 「값 목록은 건드리지 말 것」이 **값의 존재**를 두고 한 말인지 **라벨 문구**까지인지 갈리는 자리였다. 추측으로 고쳤으면 지시 위반이고, 안 물었으면 드리프트가 남았다.
- ★**「구현 상태」가 실제보다 높게 보이는 구간이 생긴다** — 설계가 앞서는 동안 창구들의 구현 상태는 **직전 구현**을 가리킨다. 구조적 귀결이며 **구현 라운드가 추적 기록으로 갱신**한다. 드리프트로 집계하지 말 것.

## §5-1d ★한글 손상이 실제로 났다 — 바이트 대조가 값을 한 기록

수용기준 한 건의 첫 쓰기에서 **세 곳이 깨졌다**: **`뻔`→`범`** · **`곧`→`곱`** · `의` 한 글자 삽입.

★**결정적인 사실**: **`뻔`→`범` 은 길이가 같아 글자수 대조로는 잡히지 않았고, 문자 단위 대조만이 잡았다.**

- 이것이 이 저장소가 겪어 온 사고 유형 그대로다 — **깨진 글자가 아니라 멀쩡해 보이는 다른 한글**이 되어 **통독을 그냥 통과한다.**
- 담당이 **쓰기 전에 기대본을 파일로 굳혀 둔 덕에** 잡혔고 다음 판에서 교정해 잔재 0을 확인했다.
- ⇒ **이번 라운드 내내 강제한 바이트 대조가 값을 했다.** 없었으면 발주처 산출물에 그대로 실렸다.

**앞으로도 그대로 지킬 것**: ①기대본을 **쓰기 전에** 파일로 굳힌다 ②쓴 뒤 재조회해 **문자 단위**로 비교한다 ③**글자수·희귀 음절만으로 판정하지 않는다**(새로 쓴 산문은 음절이 거의 전부 유일해 희귀 음절 스캔의 신호가 약하다).

## §5-1f ★메인이 배선하다 링크 7건을 지웠다 — 복구했고, 규율은 오케스트레이터에게도 적용된다

**무엇을 했나** — 라운드 마무리 배선에서 검증·사용례 링크 배열에 **기존 값을 확인하지 않고 전체 교체(`set`)** 를 썼다. 그 결과 링크 **7건이 사라졌다**:
- 영상 처리 현황 화면 — **적재 사용례 1건 + 적재 축 수용기준 2건**
- 검수 목록 화면 — ★**직전 라운드(검수 점유·일괄 검수완료)의 수용기준 4건**

**왜 났나** — 처음 `add`(추가) 연산을 썼더니 **「배열이 아니다」** 오류가 났다(그 필드가 비어 있어 아예 없었다). 그래서 `set` 으로 바꿨는데, **비어 있던 ITEM 에서만 참이던 조건을 전부에 적용**했다.

**무엇이 잡아냈나** — 응답의 **`removed: 3`·`removed: 4`**. **성공 응답 안에 섞여 있어** 그냥 넘어갈 수 있었다. 복구 근거는 **로컬 키트 스냅샷**이었다 — 서버는 이미 덮여 있어 옛 값을 알 길이 없었다.

⇒ **다음부터 지킬 것**
1. 배열 링크 필드는 **쓰기 전에 현재 값을 읽는다.** 비어 있으면 `set`, 아니면 **합집합**으로 쓴다.
2. **쓰기 응답의 `removed` 가 0 인지 반드시 본다.** 0 이 아니면 **의도한 삭제인지 확인하기 전에 다음으로 넘어가지 않는다.**
3. **로컬 키트 스냅샷이 유일한 복구 근거**가 되는 경우가 있다 — 그래서 키트를 최신으로 유지하는 것이 보험이다.

★**이 라운드 내내 모든 담당에게 「배열 원소 삭제 금지 — 추가만」을 강제했고 담당들은 전부 지켰다. 어긴 것은 메인이다.** 오케스트레이터가 규율 밖에 있지 않다.

★★**같은 날 메인이 규율을 두 번째로 어겼다** — 결정문 참조를 배선하며 **한글 제목을 유니코드 이스케이프로** 적었다. 이 프로젝트가 명시적으로 금지하는 바로 그것이고, 이번 라운드 내내 담당들에게 매번 강제한 규칙이다.
- **결과는 무사했다** — 왕복 검증에서 36건 전건 정상이었다.
- ⚠ **그러나 그것이 면죄가 아니다.** 그 규칙이 있는 이유는 **틀려도 눈에 보이지 않기** 때문이다(`뻔`→`범` 처럼). **검증을 돌리지 않았으면 확인할 길이 없었다.**
- ⇒ **메인도 쓰기 전에 같은 절차를 밟는다**: 한글을 직접 쓰거나, 불가피하면 **생성 + 왕복 검증**.

## §5-1e 서버가 준 번호는 연속이 아니다

이 라운드의 수용기준 실제 번호는 **`AC-1121`·`AC-1122`·`AC-1123`·`AC-1124`·`AC-1125`·`AC-1126`·`AC-1127`** 인데, **병렬로 돈 두 담당이 번갈아 받아 가 연속이 아니다**(한 담당이 1121·1124·1125·1126, 다른 담당이 1122·1123·1127).

⚠ **번호를 연속으로 가정해 「AC-1121~1127」 식으로 인용하지 말 것.** 직전 라운드에도 장부가 번호를 앞질러 적어 실제와 어긋난 일이 있다. **ID 는 서버가 정한다.**

## §5-2 이번 라운드에서 드러난 별건 (이 CO 범위 밖)

- **영상 목록 창구의 응답 스키마가 낡았다** — 실제 응답에 배정 식별자·작업자·작업자명·배정 상태·비식별 여부·비식별 상태 **6필드가 있는데 설계에는 없다.** 이번 담당이 추정으로 채우지 않고 드러내기만 했다(옳은 판단). 별도 정합 건.
- ★**검수 목록 창구 본문이 상한에 1자 남았다**(3,999/4,000). 다음에 무언가를 더하려면 **산문 압축이 아니라 항목 설명 쪽으로 옮기는 설계가 선행**돼야 한다.
- **`ADR-067` 의 「해제」는 점유 해제**라 이번 「배정 해제」와 낱말이 같다. 축이 다르다는 한 줄 구분이 필요하다.
- **`CDIAG-007`**(작업 배정 도메인 모델)에 신규 이벤트 3종이 없고 **배정 삭제 연산 자체가 없다**(이미 낡음 표식).
- ★**낡음 표식 소실 — 별건 큐로 회수해야 한다**: `ADR-067` 을 고칠 때 그 ITEM 이 들고 있던 낡음 사유 **「`ERD-014` 의 테이블 축 변경 — 참조」가 쓰기로 초기화**됐다. 이번 편집(낱말 구분)은 그 축을 다루지 않았으므로 **해소가 아니라 소실**이다. `ERD-014` 를 참조하는 형제 전수를 뒤져 **그 사유를 아직 들고 있는 ITEM 이 0건**임을 확인했다 — 즉 **이 줄 말고는 남은 흔적이 없다.**
  ⇒ 잔여 작업: **`ADR-067` 과 `ERD-014` 의 테이블 축 대조.**
  ⚠ 이것은 이 저장소의 알려진 함정이다(**쓰면 낡음 표식이 지워진다**). 앞으로도 **쓰기 전에 표식과 사유를 기록하고, 이번 축과 무관한 사유면 별건으로 옮긴 뒤** 쓸 것.
- **영상 처리 현황 화면에 창구 계약이 소유할 숫자가 더 있다** — ①**검색어 길이 상한**(영상 목록 창구가 소유할 값) ②**상태코드 「N종·N개」 개수 표기**. ★②는 이 저장소가 **명시적으로 경고하는 패턴**이다(값역이 늘면 그 숫자를 인용한 층이 **동시에** 틀린다).
  ⇒ **이번 축이 아니라 손대지 않았다.** 제외 축과 무관한 것을 고치기 시작하면 CO 경계가 계속 번진다.
  ⚠ **마킹 프레임 기본 간격은 대상이 아니다** — 상한이 아니라 **화면이 제시하는 기본값**이고, 같은 자리가 이미 「상한은 서버가 백스톱」이라고 숫자 없이 적어 일관적이다.
- ★**설명 칸이 상한에 닿는 ITEM 이 늘고 있다** — 이번 라운드에만 셋이다: 검수 목록 창구(**여유 1자**) · 작업 배정 도메인 모델(**여유 14자**) · 검수 화면의 한 섹션(상한 초과로 쓰기가 한 번 거부됨).
  ⇒ 다음에 무언가를 더하려면 **산문을 항목 설명 쪽으로 내리는 구조 정리가 선행**돼야 한다. 그때그때 문장을 접어 자리를 만드는 방식은 **접을 문장이 떨어지는 순간 사양이 잘린다.**
  ⚠ 이번 라운드는 세 곳 모두 **덜어낸 것이 중복 문장뿐**이고 잃은 사양이 없음을 담당들이 대조로 증명했다 — 다음에도 그러리라는 보장은 없다.
- ★**정적 렌더 미러 세 벌이 낡았다** — 화면 사양이 앞서 나갔다. **`SCREEN-018` 미러는 이번 라운드 이전부터** 낡아 있었다(섹션 4개인데 사양은 7개 — **직전 라운드의 검수 점유·일괄 승인이 통째로 빠져** 있다). `SCREEN-008` 미러는 **편집 직전까지 정확히 최신**이었고 이번 쓰기로 낡았다(해시 대조로 확정).
  ⚠⚠ **미러를 정본으로 읽지 말 것** — 파일 이름이 정본과 같아서 **아홉 판 전 사양을 현재 사양으로 읽은 사고**가 이 저장소에 있었다.
- **고충실 시안 세 벌**(`SD-001`·`SD-003`·`SD-013`)도 화면 사양보다 낡았다. 제외·복원 동선, 「제외됨 N건」, 배정 해제와 그 확인 창이 그림에 없다.
  ⇒ 미러 재생성과 시안 재게시는 **그림을 다시 그리는 작업**이라 설계 반영과 축이 다르다. **묶어서 별건**으로 돈다.
- **`DFEAT-006`·`SCREEN-012` 의 수용기준 연결이 비어 있다** — 이번에 만든 수용기준을 그 층에 이어야 결박이 성립한다.
- ⚠ **검증 환경 함정** — 병렬 담당들이 스크래치패드를 공유해 `expected.txt` 같은 흔한 파일명이 **서로 덮어써졌다**(한 담당이 실제로 겪고 보고). **묶음 단위로 메인이 독립 재검증해야 한다.**
- ★★**화면 키트의 조용한 누락은 구조적이며 경고만으로는 막히지 않았다 (키트 SYNC 중 실측)** — 통합 화면 키트에 이번 라운드의 **수용기준 7·창구 3·사용례 1이 pin 에 없어 빠져** 있었고, **직전 검수 축 라운드분(수용기준 9·창구 5·부품 3)도 같이** 빠져 있었다.
  원인은 그 키트의 **미판정 목록에 비기능 요구만 올라오는 구조**다 — pin 화면이 새 창구·수용기준을 물어도 그것이 목록에 드러나지 않는다. 직전 라운드가 이 재발을 **경고로 적어 두었는데도 그대로 재발했다.**
  ⇒ 잡는 방법은 하나뿐이다: **pin 항목의 서버 링크를 pin 과 차집합한다.** 게다가 **한 번으로 닫히지 않는다** — 두 번 떠서 네 건을 더 찾았다.
  ⚠ 이것을 「다음에 조심한다」로 남기면 또 재발한다. **매 SYNC 의 고정 검사로 넣어야 한다.**
- **`DS-002` 가 통합 화면 키트 pin 밖이다** — 활성 디자인 시스템인지 확인하지 않아 판정을 미뤘다. 활성이면 승격, 비활성이면 기각이다.
