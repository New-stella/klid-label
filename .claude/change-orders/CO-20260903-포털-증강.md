# CO-20260903 — 포털 증강 (요청 · 현황 · 결과 · 후속 · 내려받기)

- 상태: 착수
- 근거 결정: `ADR-013` v10 · `SCREEN-044` v6 · `SCREEN-033` · `API-232`·`API-233`·`API-157`·`API-159`
- 범위: 백엔드(`portal/` · `augment/` 재사용) + 프론트(`SCREEN-044` 신설 · `SCREEN-033` 액션 추가)
- ⚠ 설계 **선반영 완료** — 이 CO 는 ITEM 을 고치지 않는다.

## 1. 왜 지금인가

**본문 상단 이동 탭의 「증강」이 지금 404 로 간다.** 탭을 화면보다 먼저 세운 결과이며,
**머지 전에 이 화면이 서야** 사용자가 누르고 막히지 않는다.

## 2. 관제 증강과 무엇이 다른가 (구속)

| 축 | 관제 | 포털 |
|---|---|---|
| 요청 자격 | 검수 완료 영상 · 검수자 전용 | **본인이 올린 영상** |
| 결정 단계 | 채택/반려(검수자) | **없다** — 검수가 없어 그 개념 자체가 없다 |
| 결과 회수 | 검수·등재 흐름 | **확인 · 후속 작업 진입 · 내려받기** |
| 대상 | — | **데이터마트에서 불러온 영상은 대상이 아니다** |

⚠ **채택·반려를 만들지 마라.** 검수자 결정 축을 포털이 쓰지 않는다 — 그 술어를 재사용하면
**포털 파생본이 전부 사라진다**(그 승인 행이 영영 안 생긴다).

⚠ **결과물은 요청한 본인에게만** 제공되고 **데이터마트·원본을 수정하지 않는다.**

## 3. 자리 배치 (같은 행위를 두 화면에 두지 않는다)

- **요청을 거는 자리** = 포털 업로드 화면의 **자산별 액션**
- **현황·결과·후속 진입·내려받기** = 증강 화면
- **라벨링 자체** = 포털 라벨링 화면. 증강 화면은 **그리로 가는 진입만** 갖는다
- 증강 화면에는 대상 영상을 고르러 가는 **링크만** 둔다

## 4. 증강 입력 — 되돌리지 말 것

**비식별본이 있으면 반드시 비식별본, 없으면 그 자산의 원본.** 조달처를 먼저 정하고 **거기서 못
구하면 실패**한다 — 「있으면 비식별본, 없으면 원본」 형태로 적으면 산출물이 사라졌을 때 **조용히
원본으로 흘러** 관제 원본이 위탁으로 나간다.

포털 자산은 비식별 단계가 없어 원본 한 벌뿐이고, 그것이 정상이다.

## 5. 하지 말 것

- **채택/반려 결정 단계를 만들지 마라**(§2).
- **파생 등재 게이트를 포털 목록에 재사용하지 마라** — 검수자 결정 축을 요구한다.
- **관제 증강 경로를 무르게 하지 마라.** 특히 요청 자격(검수 완료)은 **그대로 선다.**
- 상태 표시 값을 **이 산출물이 정하지 않는다** — 사양이 그렇게 적었다. 기존 표기 관례를 따르라.
- 결과물 저장 루트는 **그 배포본의 저장 루트**를 따른다. 채널 분기를 코드에 만들지 마라.

## 6. 수용 기준

1. 포털 회원이 **본인 업로드 영상**에 증강을 요청하고, 현황을 보고, 결과를 확인하고,
   **후속 작업으로 가고**, 내려받을 수 있다.
2. **데이터마트 로드분은 대상이 아니다** — 요청 자리에 뜨지 않는다.
3. **채택/반려가 없다.**
4. **관제 증강 무변경** — 소스 동치 또는 되돌림 실증.
5. **탭의 증강 목적지가 404 가 아니다.**
6. 회귀 무열화 — 백엔드 기준선 **8,452 / 실패 0 / XML 933** · 프론트 **536 파일 / 4,568건**.
