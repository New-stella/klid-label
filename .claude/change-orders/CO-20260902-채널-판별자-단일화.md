# CO-20260902 — 채널 판별자를 한 곳으로 모은다

- 상태: ✅ 완료 (2026-09-02)
- 근거 결정: `ADR-058`(포털 전용표 공용원장 흡수) · `ERD-028`
- 관련 장부: `CO-20260902-포털-전용표-공용원장-흡수.md`

## 1. 왜

흡수로 포털 업로드 자산이 공용 영상 원장에 함께 앉았다. 그래서 **「이 영상이 어느 채널의
자산인가」** 를 묻는 술어가 조회 경로마다 필요해졌다.

지금 그 술어가 **네 가지 형태로 흩어져** 있다. 형태가 다르니 새 조회 경로를 만드는 사람이
「여기도 붙여야 하나」를 스스로 판단해야 하고, **한 번 잊으면 남의 자산이 조용히 섞인다** —
오류로 드러나지 않고 결과 건수만 늘어나는 축이다.

⚠ **이건 흡수가 만든 비용이 아니다.** 포털향 배포본은 **데이터마트 로드분(관제 유래)과 포털
업로드분을 한 표에서** 다룬다(포털 라벨 화면이 승인 자산을 이 원장에서 읽는다). 표를 갈랐어도
그 공존은 남았을 것이므로, 이 술어는 **원래 있어야 했던 것**이다.

## 2. 지금 흩어진 자리 (실측)

| # | 자리 | 형태 |
|---|---|---|
| ① | `LsDataRaw.isPortalUpload()` | Java 판정 헬퍼 — **이미 있다** |
| ② | `InternalWorkScope.internal(...)` · `internalByRawSn(...)` | QueryDSL 2형태 — 사용처 2곳 |
| ③ | `VideoRepository`(멈춘 처리 회수) | **JPQL 안에 문자열로 직접** 박음 |
| ④ | `DerivativeSourceVideoResolver.sourceOf` | ①이 있는데 **상수를 직접 비교** |
| ⑤ | `PortalUploadLedger.SRC_TYPE` | 같은 값의 **두 번째 이름**(별칭 상수) |

### ★ 더 중요한 것 — 우연히 안 섞이는 자리

아래는 **막아서가 아니라 우연히** 포털 행을 안 집는다. 조건이 하나만 바뀌면 섞인다.

| 자리 | 왜 지금은 안 섞이나 |
|---|---|
| 통계 — 이벤트 유형별 영상·프레임 분포 | `이벤트 유형이 비지 않음` 조건이 **우연히** 거른다. 포털 자산에 그 값이 채워지는 순간 섞인다 |
| 통계 — 상태별 분포 2건 | 검수 상태 표를 조인해 걸러진다(포털엔 그 행이 없다) |
| 검수 목록 — 이름 검색 | 바깥 조회가 검수 상태 표에서 출발해 걸러진다 |

⚠ **뒤 두 줄은 구조적 배제라 그대로 둬도 된다.** 첫 줄은 **우연**이라 다르다.

## 3. 무엇을 한다

### ① 형태를 갖춘다 — 판별자는 `InternalWorkScope` 한 곳이 소유한다

지금 QueryDSL 두 형태만 있어서, **JPQL 로 쓴 조회는 갈 곳이 없어 문자열을 직접 박았다.**
JPQL 조각 형태를 하나 더 만들어 그 자리를 없앤다.

- 선례가 이미 있다 — 폐기 프레임 제외 술어가 **별칭 고정 문자열 조각**으로 살면서 여러 조회에
  붙는다. **같은 모양을 따른다**(새 방식을 발명하지 않는다).
- 별칭은 **고정**하고 그 사실을 주석에 남긴다(선례와 동일).

### ② 흩어진 넷을 그 한 곳으로 돌린다

- ③ JPQL 인라인 → 새 조각으로
- ④ 상수 직접 비교 → **이미 있는 판정 헬퍼**로
- ⑤ 별칭 상수 → ★**없애지 않는다 (2026-09-02 구현 중 반전 · 근거 있음)**

  > 처음 지시는 「없앤다 — 같은 값에 이름이 둘이면 한쪽만 바뀐다」였다. **그 근거가 이 자리에서는
  > 성립하지 않는다.** 별칭은 사본이 아니라 **소유자 상수에 위임**하는 것이라 값이 갈라질 수 없고,
  > 그 파일 주석이 이미 「재선언하지 말고 참조한다」를 못 박아 뒀다.
  >
  > ★**게다가 없애면 §3-④ 가드가 약해진다.** 별칭을 쓰는 자리가 **26곳**이라, 전부 소유자 상수로
  > 옮기면 가드 허용 목록이 **3파일 → 5파일**로 넓어져 그 세 파일이 **영구 면제**된다. 별칭을 두면
  > 그 26곳은 가드가 보는 토큰을 **아예 갖지 않는다.**
  >
  > ⇒ **목적(잊기 어렵게)에 비추어 두는 쪽이 낫다.** 수용 기준 1·4 는 별칭을 둔 채로 충족된다.

### ③ 우연을 구조로 바꾼다

통계의 **이벤트 유형별 영상·프레임 분포** 두 건에 채널 축을 명시한다.
⚠ **나머지 「구조적 배제」에는 붙이지 않는다** — 이미 걸러지는 자리에 술어를 더하면 읽는 사람이
그 조인이 하는 일을 못 읽게 되고, 조회 계획만 무거워진다. **대신 왜 안 붙였는지 주석으로 남긴다.**

### ④ 잊기 어렵게 만든다 — 이게 이번 작업의 핵심이다

넷을 한 곳으로 모아도 **다음 사람이 새 조회를 만들 때 붙이는 것을 잊으면** 원점이다.
그러니 **판별자 값 문자열이 소유자 밖에서 다시 나타나면 실패하는 시험**을 둔다.

- 대상은 **동작하는 코드**다. 주석·옛 표 이름(`LS_PORTAL_ULD…`)은 대상이 아니다 — 그건 같은
  글자를 갖지만 다른 축이다(이 글자로 훑으면 **주석까지 잡혀 오탐**이 난다. 실측으로 확인).
- 시험은 **이름 붙이기 전에 일부러 깨뜨려** 실제로 잡는지 본다(가드가 조용히 일을 멈추는 것이
  이 저장소의 반복 결함이다).

## 4. 하지 말 것

- **판별자 값 자체를 바꾸지 마라.** 이미 적재된 행이 그 값을 갖는다.
- **`InternalWorkScope` 를 파생 등재 게이트와 합치지 마라** — 묻는 것이 다르다(그 클래스 주석이
  이미 못 박아 뒀다).
- **소유자 식별자를 여기로 끌어오지 마라.** 가시 범위(채널)와 소유(사용자)는 다른 축이고,
  비가역 삭제만 셋을 모두 요구한다.
- **「관제다」로 적지 마라 — 「포털이 아니다」로 적는다.** 과거 행은 출처 값이 비어 있어,
  긍정형으로 적으면 정상 영상이 통째로 사라진다.
- **구조적으로 배제되는 자리에 술어를 덧붙이지 마라**(위 §3-③).

## 5. 수용 기준

1. 판별자 값 문자열이 **소유자 한 곳** 밖의 동작 코드에 없다.
2. 멈춘 처리 회수·작업목록·배정목록의 **동작이 무변경**이다.
3. 통계 두 건이 포털 자산을 **구조적으로** 배제한다.
4. 새 조회가 판별자를 직접 박으면 **시험이 실패한다**(가드가 실제로 잡는 것을 확인).
5. 전체 회귀 무열화 — 기준선 **8,388건 / 실패 0 / 오류 0 / 건너뜀 5**.

## 6. 관련 설계 ITEM

**설계 변경 없음.** 이번 작업은 `ADR-058` 이 이미 확정한 「출처 판별자로 가른다」를 **코드 안에서
한 곳으로 모으는 것**이라 새 사양이 없다. 대상 클래스에 `@design ADR-058`·`@design ERD-028`
태그가 이미 있다.

## 7. 구현 로그

**2026-09-02 완료.** 전체 회귀 **8,393건 / 실패 0 / 오류 0 / 건너뜀 5**(XML 925) — 기준선 8,388/924
대비 정확히 **+5건 · +1 XML**(신규 가드 클래스)이라 무열화다.

- A. JPQL 조각 신설 — 선례(폐기 프레임 제외 술어)와 **같은 모양**(별칭 고정 + 앞뒤 공백 보장).
- B. 인라인 JPQL → 조각 / 상수 직접 비교 → 판정 헬퍼. **fail-closed 기본값 보존.**
- C. 통계 두 건에 조각 부착(세 소비자 모두 별칭이 같아 **조각 변형 불요**). 구조적 배제 3자리에는
  **붙이지 않고** 「일관성을 이유로 붙이지 말 것」을 주석에 명시.
- D. 가드 신설 — **두 축**(값 리터럴 / 상수명)이다. 값 축만 두면 상수 직접 참조 재발을 못 잡고,
  상수 축만 두면 새 쿼리가 값을 하드코딩할 때 못 잡는다. 공허성 방지 2건 + 조각 계약 1건 포함.
- **변이 3회 실측** — 허용 밖 참조 주입(위반 파일명까지 지목) · **오탐 검사(초록이어야 정상)** ·
  소유자가 판정을 놓았을 때 공허해지는지. 셋 다 기대대로.

### ⚠ 범위 밖에서 드러난 것 — 별건

동시성 시험 하나가 **1차 회귀에서 실패했다가 재실행·격리에서 통과**했다(승인 자동 전이의
「정확히 1건 성공」이 **2건**으로 나왔다). 이 작업과 무관하다는 근거는 셋이다 — 격리 통과 ·
2차 통과 · 그 호출 경로에 이번에 만진 타입이 **0건**.

⚠ **그렇다고 무해하다는 뜻은 아니다.** 겹치지 않았다면 뒤엣것이 충돌로 거절돼야 하는데 **둘 다
성공**했다면 조건부 전이가 실제로 새는 것일 수 있다. **근본 원인 미확인**이며 별건으로 남긴다.
