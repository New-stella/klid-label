# 12. GPU 준비 상태 점검 — 델타가 아직 안 깔린 장비를 GPU 로 돌리기

대상은 **서버 B(ai)** 한 대다. WAS·웹·DB 는 이 문서와 무관하다.

이 패치 매체에는 **GPU 휠이 들어 있지 않다.** 휠만 3.5GB 를 넘어 패치와 함께 다니면
패치 자체를 옮기기 어려워진다. 여기 있는 것은 **지금 상태를 읽는 수단**과 **절차**다.

---

## 0. 먼저 이것부터 — 지금 GPU 로 돌고 있는가

```bash
# 서버 B 에서 (아무것도 바꾸지 않는다)
<델타 매체>/scripts/check-gpu-readiness.sh
```

네 가지를 각각 읽고 한 줄로 판정한다.

| 보는 것 | 왜 |
|---|---|
| ① 장치·드라이버 | 드라이버는 커널 모듈이라 **우리가 넣을 수 없다** |
| ② 설치된 휠 | `torch 2.x+cpu` 인지 `+cu126` 인지 — **이름 끝에 박혀 있다** |
| ③ 런타임 실측 | 설정이 아니라 **실제로 잡히는지** |
| ④ 설정값 | `AI_DEVICE=cuda` 인지 |

종료코드 `0` 이면 이미 GPU 다. `1` 이면 화면에 적힌 조치를 순서대로 한다.

> ★ **왜 네 가지를 따로 보는가.** 하나만 봐서는 알 수 없기 때문이다.
> 설정이 `cuda` 인데 휠이 CPU 판이면 **그대로 CPU 로 돈다**. 휠이 CUDA 판인데 드라이버가
> 낮아도 **그대로 CPU 로 돈다**. 어느 경우든 서버는 정상 기동하고 헬스체크도 통과한다.

---

## 1. ★★ 이 전환의 실패는 조용하다

**GPU 로 안 돌아도 아무 오류가 없다.** 화면도 뜨고 추론도 되고 응답도 200 이다.
느려질 뿐이고, 그 느림은 「원래 이 정도인가 보다」로 넘어간다.

그래서 이 문서는 **성공을 눈으로 확인하는 절차**를 마지막에 둔다. 건너뛰지 마라.

---

## 2. 필요한 것 넷 — 하나라도 빠지면 CPU 로 돈다

### ① NVIDIA 드라이버 — **우리 소관이 아니다**

커널 모듈이라 pip 로 해결되지 않는다. 게다가 이 장비는 관제지원시스템과 공동 배치라
**우리가 드라이버를 덮어쓰면 안 된다.** 장비 담당에게 요청한다.

- CUDA 12 계열 휠을 쓰므로 드라이버 **525 이상**이 필요하다.
- 확인: `nvidia-smi` 가 응답하고 `Driver Version` 이 525 이상.

### ② torch 를 CUDA 판으로 교체 — **델타 매체가 필요하다**

폐쇄망이라 pip 가 인터넷에서 받을 수 없다. 미리 조달한 델타를 반입해야 한다.

```
klid-onprem-gpu-delta-<커밋>.tgz     약 3.5GB
```

⚠ **자료실 파일 1건 상한이 3GB 라 두 권으로 나눠 올린다.**

```bash
# 보내는 쪽 (이미 나눠 둔 것이 있으면 그대로 쓴다)
split -b 1900m klid-onprem-gpu-delta-<커밋>.tgz klid-onprem-gpu-delta-<커밋>.tgz.part-

# 받는 쪽
cat klid-onprem-gpu-delta-<커밋>.tgz.part-* > klid-onprem-gpu-delta-<커밋>.tgz
sha256sum -c klid-onprem-gpu-delta-<커밋>.tgz.sha256
tar xzf klid-onprem-gpu-delta-<커밋>.tgz
```

### ③ onnxruntime → onnxruntime-gpu — **패키지 이름 자체가 다르다**

같은 패키지의 GPU 옵션이 아니라 **별개 패키지**다. 이름이 다르므로 `pip install --upgrade`
로는 절대 바뀌지 않는다. 델타의 적용 스크립트가 지운 뒤 다시 넣는다.

### ④ `AI_DEVICE=cuda`

`/etc/klid/ai-server.env` 에서 바꾸고 ai-server 를 재기동한다.

---

## 3. 적용

```bash
# 서버 B 에서, 풀어 둔 델타 폴더 안에서
sudo ./scripts/apply-gpu.sh --check        # 바꾸지 않고 현황만
sudo ./scripts/apply-gpu.sh --set-device   # 교체 + AI_DEVICE=cuda 까지
sudo systemctl restart klid-ai-server
```

`--set-device` 없이 돌리면 **휠만 바뀌고 설정은 그대로**다. 그 상태는 CUDA 판이 깔린 채
CPU 로 도는 형상이라, 디스크만 더 쓰고 얻는 것이 없다.

---

## 4. 확인 — 여기를 건너뛰면 전환했는지 알 수 없다

```bash
<델타 매체>/scripts/check-gpu-readiness.sh        # 종료코드 0 이어야 한다
nvidia-smi                      # 추론 중에 프로세스가 잡혀야 한다
```

**셋이 모두 맞아야 전환된 것이다** — 휠이 `+cu126`, `torch.cuda.is_available()` 이 True,
`AI_DEVICE=cuda`. 하나라도 어긋나면 CPU 로 돌고 있다.

추론을 한 번 돌리면서 `nvidia-smi` 에 프로세스가 잡히는지 보는 것이 가장 확실하다 —
앞의 셋은 「돌 준비가 됐다」이고, 이것만이 「실제로 돌았다」이다.

---

## 5. 되돌리기 — 설정만 되돌리는 것은 절반이다

`AI_DEVICE=cpu` 로 바꾸면 **CPU 로 돈다.** 다만 설치된 휠은 CUDA 판 그대로라
디스크를 약 6GB 더 쓴다. 완전 복귀는 재설치다.

급히 되돌려야 하면 설정만 바꾸는 것으로 충분하다 — 동작은 정상이고 용량만 손해다.

---

## 6. ⚠ 라이선스 표면이 바뀐다

CUDA 런타임 휠이 들어오면서 NVIDIA 재배포 조건이 붙는다. 델타 매체의 `licenses/` 를
반입 고지에 **함께 넣어야 한다**. 델타만 넣고 고지를 빠뜨리지 마라.
