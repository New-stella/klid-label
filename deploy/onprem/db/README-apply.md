# DB 작업 — 이 폴더 하나면 됩니다

**DB 서버에서 직접 작업합니다.** 응용 서버에는 `psql` 이 없고, 매체 전체를 DB 서버로 옮길
이유도 없습니다. **이 `db/` 폴더만 복사**하면 도구까지 함께 옵니다.

```bash
# 응용 서버에서
scp -r onprem/db root@<DB서버>:/root/klid-db
```

## 들어 있는 것 — 성격이 다른 둘

| | 무엇 | 언제 |
|---|---|---|
| `schema.sql` | **전체** — 표·뷰·시퀀스·제약·주석·시드 | 빈 데이터베이스를 세울 때 **한 번** |
| `incremental/V*.sql` | **증분** — 그 이후 변경 | 이미 선 데이터베이스에 얹을 때 **매 회차** |

⚠ **전체 파일은 그 시점까지의 증분을 이미 품고 있습니다.** 전체를 넣은 뒤 같은 증분을 다시
실행하면 멱등하지 않은 문장에서 실패합니다. `--schema` 가 그 증분들을 **적용된 것으로
기록**하므로 다음 회차에 다시 실행되지 않습니다.

## 접속값 — 한 번만 적어 두면 됩니다

이 폴더에 `db.env` 를 만들어 두면 다음부터 아무것도 안 칩니다.

```bash
cat > db.env <<'ENV'
CONTROL_DB_HOST=10.177.199.148:19999,10.177.199.149
CONTROL_DB_PORT=19999
CONTROL_DB_NAME=klid_system_pg_prod
CONTROL_DB_USERNAME=postgres
CONTROL_DB_PASSWORD=········
DB_SCHEMA=klid_at
ENV
chmod 600 db.env
```

⚠ `CONTROL_DB_HOST` 는 **응용 서버 설정에 적힌 값을 그대로** 붙여 넣으면 됩니다 —
`host:port,host` 형태여도 스크립트가 알아서 나눕니다. 비밀번호는 환경변수로만 넘어가
**명령 이력에 남지 않습니다.**

같은 장비에 `/etc/klid/application.properties` 가 있으면 그것도 자동으로 읽습니다.

## 하는 일

```bash
./apply.sh --status      # 현황만 (아무것도 안 바꿈)
./apply.sh --dry-run     # 적용 예정 증분 목록
./apply.sh               # 미적용 증분 적용
./apply.sh --schema      # 빈 DB 를 전체 스크립트로 세운다 (최초 1회)
```

## 이 스크립트가 대신 막아 주는 것

**① `search_path`** — 증분 SQL 은 스키마를 한정하지 않습니다. `search_path` 가 `klid_at` 이
아니면 `CREATE TABLE IF NOT EXISTS` 가 **`public` 에 빈 표를 만들고 오류를 내지 않습니다.**
앱은 `klid_at` 을 보므로 그 표는 영원히 비어 있고 아무도 모릅니다.
(전체 파일은 객체명이 한정돼 있어 이 함정이 없습니다 — 그래서 둘의 처리가 다릅니다.)

**② 접속 주소** — `host:port,host` 를 그대로 넘기면 클라이언트가 읽지 못합니다.
호스트와 포트로 갈라 넘기고, **쓰기 가능한 노드**를 고릅니다(대기 노드에 붙으면 DDL 이
read-only 오류로 시끄럽게 실패합니다 — 조용한 것보다 낫습니다).

**③ 중복 적용** — 한 파일이 한 트랜잭션이자 한 세션입니다. 실패하면 그 파일이 통째로
되돌아가고 뒤 번호는 실행되지 않습니다. 여러 노드에서 동시에 돌려도 한 번만 적용됩니다.
이미 적용된 파일의 **내용이 바뀌었으면 멈춥니다**(sha256 대조).

**④ 빈 DB 에 증분** / **선 DB 에 전체** — 둘 다 거부합니다. 섞으면 되돌릴 수 없습니다.

## 적용 이력

`klid_at.ls_schm_aplcn_hstry` 에 남습니다(파일명·버전·sha256·상태·적용자·일시).
**설치 도구가 소유하고 앱은 읽지 않습니다.** 나중에 「어디까지 반영됐나」를 물으면 이 표가
답합니다 — 수행자의 기억에 기대지 않습니다.

## 백업

**이 스크립트는 백업을 뜨지 않습니다.** 용량·시점·보관 정책이 현장 소관이고, 임의로 뜨면
디스크를 채우거나 「백업이 있다」는 잘못된 안심을 줍니다. 변경 전에 **확인만 묻습니다.**
증분은 앞으로만 갑니다 — 되돌려야 하면 그 백업이 유일한 수단입니다.
