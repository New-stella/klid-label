> 이 폴더의 파일은 `deploy/` 의 원본과 **같은 실체**다(하드링크). 지워도 원본은 남고,
> 원본을 지워도 이것은 남는다. 둘 중 하나만 지운다고 용량이 줄지 않는다.

## 0. 옮기기 전과 후에 반드시

```bash
shasum -a 256 -c SHA256SUMS      # 리눅스는 sha256sum -c SHA256SUMS
```

**복사 직후 한 번, 현장에 도착해 한 번** 돌린다. 매체 복사는 조용히 깨진다 —
설치가 실패해야 알게 되면 그때는 되돌릴 수단이 없다.

## 1. CPU판 — 항상 먼저

```bash
tar -x -z -f 01-CPU판-klid-onprem-bf737741.tgz
cd onprem
less docs/03-install.md          # 설치 절차의 정본
```

★ **`onprem/` 폴더 전체가 설치 단위다.** 그 안이 자기완결이라 이 저장소를 따로 가져갈 필요가 없다.
반대로 **git clone 으로는 못 받는다** — 산출물·모델·RPM 이 형상관리 대상이 아니라
받아 봐야 **껍데기(104 파일)** 다. 실제 매체는 **6,650 파일**이다.

## 2. GPU 델타 — GPU 장비에 올릴 때만

조각 둘을 **순서대로 이어 붙여** 하나로 만든 뒤 푼다.

```bash
cat 02-GPU델타-1of2.tgz.part-aa 02-GPU델타-2of2.tgz.part-ab > gpu-delta.tgz
tar -x -z -f gpu-delta.tgz
```

⚠ **쪼갠 이유는 전송 한도 때문이지 내용이 둘이어서가 아니다.** 반드시 이어 붙여야 열린다.
CPU판을 먼저 설치한 **뒤에** 적용한다 — 델타는 이름 그대로 차분이라 단독으로는 쓸 수 없다.

## 3. 이 판에 무엇이 들어 있나 (직전 판 대비)

- **AI 장비를 화면에서 여러 대 등록·관리한다** — 관리자 메뉴 「연동 서버 주소」.
  AI 추론과 외부 시계열 분석 두 축이 주소 한 칸에서 **장비 목록**으로 바뀌었다.
  그 목록이 주소의 진실원이고, 설정값은 그 유형이 비어 있을 때 **최초 1회 씨앗**으로만 쓰인다 —
  **화면에서 바꾼 주소는 재기동으로 되돌아가지 않는다.**
- **상태점검·부하 관측이 기본으로 켜진다.** ⚠ 이것을 끄면 장비를 여러 대 등록해도
  **요청이 항상 한 대로만 간다**(관측값이 전부 0으로 같아져 순서가 고정된다).
  **아무 오류도 나지 않으므로 끄지 말 것.**
- **관리자 공유 패스워드에 기본값이 생겼다 — 평문 `admin`.**
  종전에는 비워 두면 아무도 관리자가 되지 못하는데 기동·상태점검·스모크가 전부 통과해
  **그 상태에 아무 신호가 없었다.**
  ⚠⚠ **널리 알려진 값이다. 최초 관리자를 만든 직후 운영 화면에서 반드시 바꾼다.**
- 스키마 마이그레이션 1건(`V26`) — 제약을 없애기만 하는 변경이라 **구 산출물에 무해**하다.
  컬럼이 사라지는 변경과 달리 배포 순서를 가리지 않는다.

## 4. 설치 후 반드시 확인할 것 — 기동 성공은 판정이 아니다

폐쇄망에서 빠진 것은 대체로 **조용히** 드러난다. 상세는 `onprem/docs/05-run-verify.md`.

- **대용량 업로드** — WAS 설정 이관이 실제로 반영됐는지 확인하는 유일한 수단
- **AI 분할·추적의 응답 내용** — 모델이 없어도 정상 응답처럼 보인다
- **영상 처리 도구로 한 장면 실제 추출·판독** — 설치 여부만 보면 통과처럼 보인다
- **테이블 개수 73** — 스키마가 비어도 앱은 기동에 성공한다
- **AI 장비 목록에 장비가 보이고 「최근 점검」이 갱신되는지**
  장비가 보이는 것과 관측되고 있는 것은 다르다. 관측이 멈춰 있어도 요청은 한 대로 흘러
  정상처럼 보인다 — **이 확인이 유일한 발견 수단이다.**
  ⚠ 시계열 주소를 비워 두고 설치했다면 그 축은 **장비 0대가 정상**이다.
