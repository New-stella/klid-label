## 1. 교차 도메인 클러스터 — **여기부터 손댄다** (중복 제거됨)

각 클러스터는 **한 번 고치면 여러 도메인의 P0 가 함께 닫힌다.** 괄호는 영향 도메인.

### C1. 활성 ADR 이 폐기 정책을 담고 있다 — **5건** (P0)

가장 위험한 클러스터다. **ADR 은 "되돌리지 말 것"의 근거 문서인데, 그 근거 자체가 폐기 모델이면 다음 세션이 정당하게 폐기 정책을 되살린다.**

| ADR | 담긴 폐기 정책 | 발견 도메인 | 특징 |
|---|---|---|---|
| `ADR-008` | 마킹 파이프라인 구 순서 | D011 | **stale·policy 두 차원이 독립 재확인** |
| `ADR-006` | — | D012 | |
| `ADR-022` | — | D012 | |
| `ADR-032` | — | D012 | |
| **`ADR-026`** | 포털 SAM2 | D013 | ★**고립(링크 0)이라 더 위험** — cascade 로 안 잡힌다 |

⇒ **처방**: 5건 본문을 현행으로 정정하되 `ADR-026` 은 **고립 해소가 선행**돼야 한다.

### C2. 구속 정책이 ADR 로 정형화되지 않았다 — **세 도메인이 서로 다른 형태** (P0/P1)

| 도메인 | 형태 | 처방 |
|---|---|---|
| **D014** | 확정 정책 3건의 **ADR 이 0건** | ADR 신규 등록 |
| **D015** | ADR **8축 보유**인데 **인용 1건** — `ADR-038`·`ADR-045`·`ADR-003` **완전 고립**(양방향 0) | **배선** |
| **D016** | 인용 관행은 있는데(`ADR-007` 5건) **17축 중 12축에 ADR 자체가 없다** | ADR 신규 등록 |

★ D016 policy 감사자의 진단이 이 클러스터의 요지다 — *"정책5(재생성·통지 트리거)는 2026-08-07 구속인데 ADR 로 정형화되지 않아, `CDIAG-013`·`SEQ-010`·`CMP-009` 가 구 트리거를 유지해도 **막을 근거 문서가 없다**."*

⇒ **"ADR 부재"와 "ADR 고립"은 처방이 다르다** — 전자는 등록, 후자는 배선. 합쳐 세지 말 것.

### C3. 검수 종결 상태값 `COMPLETED` 잔존 (P0)

확정 정책은 **`APPROVED`** 이고 *"`LsRawDataStatus.STTS_COMPLETED` 로 전이하는 코드는 한 곳도 없다"*(CLAUDE.md 가 **자기 드리프트로 명시 정정**한 항목).

- **D005 — 6곳 잔존**(지배적 결함 1)
- **D006 — 잔존**(지배적 결함 4)
- **D015 `STATE-001`** — `PROCESSING → COMPLETED` 전이를 그린다(**존재하지 않는 전이**)
- **D016 `AC-022`** — *"승인 시 `LS_RAW_DATA_STATUS` **COMPLETED** 전이"*

### C4. `STATE-001` — 프로젝트 유일 상태 다이어그램이 **도메인 축 없이 방치**됐다 (P0)

`get_item_schema(diagram_state)` 실측: **`depicts_dfeats` 필드가 스키마에 아예 없고**, `belongs_to_domain` 은 **가용한데 미설정**이며 `referenced_items` 도 `[]`. ⇒ **어느 도메인 감사에도 구조적으로 걸리지 않아 2026-06-02 이후 방치**됐다.

그 사이 쌓인 드리프트(D011·D012·D015·D016 이 각각 발견):

1. **현행과 폐기가 뒤집혀 있다** — *"▣ 신 설계(타깃, **planned**): 비식별화가 마킹 선행 자동 단계로 이동 … **현재 코드는** 마킹(원본) 트리거→VLM→비식별 순(**구 순서**)"*. 실제로는 비식별 선두가 **구현 완료**다. ★**`CMP-001` v4 는 같은 사유로 이미 정정됐다 — STATE 만 남았다.**
2. **두 축 혼재 + 존재하지 않는 전이**(C3).
3. **재배정 전이 부재**(D015 1급 조작).
4. **`terminal_states=["APPROVED"]` + "이후 전이 불가" 불변식** ⇒ ★**D016 의 `TASK_MODIFIED` 가 원천 봉쇄된다**(`DFEAT-046` 은 *"재검수에서 승인될 때"* 발송). `REVLT` 문자열 **0건**.

⇒ **처방 순서**: 축 분리(배치 축 vs 워크플로 축) → 도메인 귀속 → 내용 정정. ⚠ **축 분리 없이 한 도메인으로 귀속시키면 다른 축의 드리프트가 이번엔 그 도메인 감사에서 빠진다.**

## 5. 수정 순서 의존 — **순서를 틀리면 헛수고가 된다**

1. **`belongs_to_domain`/`realizes_dfeats` → 그 다음 AC** (C8) — 먼저 AC 를 만들면 어느 도메인에도 붙지 않는다. **D012·D013·D014·D015·D016 5연속.**
2. **ADR 먼저 → 그 다음 코드/ITEM** (C1·C2) — 근거가 폐기 모델인 채로 하위를 고치면 다음 세션이 되돌린다.
3. **`STATE-001` 은 축 분리 → 귀속 → 내용 정정** (C4) — 순서를 바꾸면 배치 축 드리프트가 다른 도메인 감사에서 빠진다.
4. **`ERD-027.STTS_CD` 는 마이그레이션 먼저 → ERD 동조** (C7) — 실물이 20 이라 ERD 만 고치면 ERD↔DB 드리프트가 된다.
5. **`ERD` 수정 시 `CDIAG`·`SCREEN` 동시 cascade** — D015 `EVNT_TYPE_CD` 가 **ERD 5 / SCREEN 8 / 실물 11** 로 삼중 분기다.
6. **`INT-007`(정본) → 나머지 6건** (C5) — 정본이 이미 정정돼 있으니 그것을 복사하면 된다.

## 6. 검사 사각 — **이 감사가 못 본 것** (수치와 함께 읽어야 한다)

> **"0건"은 그 검사기의 시야다.** 아래를 모른 채 위 수치를 읽으면 안 된다.

### 6-1. 층 커버리지 — **7개 층 중 2~3개만 봤다**

| 층 | 상태 |
|---|---|
| ① ITEM 본문 | ✅ 전 도메인 |
| ② 정적 렌더 미러 | ⚠ **극히 부분적** — D014·D015 에서 몇 건만 열었다. D016 은 `screen_spec` 0건이라 **구조적 부재**(`list_static_renders` 는 `item_id` 가 `^SCREEN-\d+$` 로 제한돼 **호출 자체가 불가**) |
| ③ 링크·역참조 | ✅ 대부분 |
| ④ 로컬 키트 스냅샷 | ❌ **거의 안 봤다** |
| ⑤ 위키 `docs/v2-wiki/` | ❌ **안 봤다** |
| ⑥ 테스트케이스 `docs/test-cases/` | △ D011~D016 만 |
| ⑦ 구현 코드 | △ D015·D016 schema/test_scenario 만 |

★ **`source_hash` 오라클의 사각** — `sections` 의 sha256 이라 **`route`·`purpose` 축 stale 을 구조적으로 못 잡는다**(D015 `SCREEN-012` 가 미러에 폐기 경로 `/tasks` 를 계속 게시한 것이 실증).

### 6-2. 플랫폼 미materialize — **우리가 고쳐도 해소되지 않는다**

| 축 | 상태 | 근거 |
|---|---|---|
| `links.unresolved` | **읽기 경로 없음**(쓰기 응답 전용) → 전부 **대리 측정** | |
| `brownfield.decided_by` | 그래프에 안 나타남 | `get_neighbors` 만으로 ADR 인용을 판정하면 **틀린다** |
| **`EVT→EVT` 체인** | **선언 3건 · 간선 0건** | ★타 도메인 대조군 `EVT-001` 도 동일 ⇒ 구속 정책 「`EVT-006`→`EVT-009`→`EVT-003`」 직렬화가 **`analyze_impact` 로 전파되지 않는다** |
| `used_by_domains`(INT→DOMAIN) | 미materialize | 반면 **`implements_domains`(MOD→DOMAIN)는 정상** |

⇒ **역방향 선언 필드가 축마다 동작이 달라, 필드 하나만 보고 링크 부재를 결론내면 안 된다.**

### 6-3. 도메인 축이 없어 구조적으로 빠지는 타입

`integration_spec` · **`diagram_state`**(스키마에 `depicts_dfeats` 없음) · `diagram_c4_component` · **고립 ADR**(링크 0). ⇒ **도메인 스코프 감사로는 영원히 안 걸린다** → 별도 **전역 타입 스윕 라운드** 권고.

### 6-4. 도구·조회 제약

- **`kit-export` 는 deprecated ITEM 을 반환하지 않는다** — `--ids` 로 명시해도 0건(D016 `API-077` 이 본문 전수 검사에서 빠짐).

**5회 뚫렸고 매번 "그 축이 없어서"였다.**

### 6-6. 감사자 자기보고의 한계 — **내가 전제를 10회 틀렸다**

그중 **절반은 앞선 감사자의 "부재" 보고를 검증 없이 다음 차원 프롬프트에 전제로 넘긴 것**이다(D011 에서 규칙까지 세웠는데 **D015 에서 재발**). 특히:

- D015 stale 감사자가 *"use_case·test_scenario·nfr 0건"* 이라 보고했으나 **`UC-029`·`UC-020` 실재**(필터 함정).
- D015 stale 감사자가 `SD-003.data` 를 *"`{status:"draft"}` 뿐"* 이라 보고했으나 **키 8개·679자**(`data` 최상위 `status` 키 오독).
- D015 acceptance 감사자가 *"`belongs_to_domain` 은 스키마상 불가능"* 이라 주장했으나 **대조군이 반증**.
- D016 content 감사자가 **schema 감사자의 `ERD-021` 파일 경로 소견을 grep 으로 철회**시켰다.

⇒ **표준 규칙으로 승격**: ①어느 감사자의 "0건"이든 **그 감사자 소관 차원 밖이면 전제로 쓰지 않는다** ②*"스키마상 불가능"* 주장은 **반드시 대조군**(그 필드를 실제로 가진 ITEM)을 확인한 뒤 받는다 ③프롬프트의 "이미 확정된 사실"에는 **원문 인용이 있는 항목만** 넣는다.

## 7. 프로세스 권고

1. **일괄 "재확인" 스탬프를 쓰지 마라.** 무변경 확인은 **`status`-only 콜**로 하고, 굳이 리비전을 남긴다면 `change_summary` 에 **무엇을 무엇과 대조했는지**를 적는다. 지금 문구(*"바꿀 내용이 없어"*)는 **대조 범위를 남기지 않아** 나중에 그 스탬프가 옳았는지 검증할 수 없고, 실제로 **덮어확정**(기존 드리프트를 "확인"으로 확정)을 만들었다.
2. **스윕은 대상 전수를 먼저 확정하고 돌려라.** `STTS_CD` 20→16 스윕이 감사 **하루 전**에 돌았는데 `ERD-027` 만 빠졌다.
3. **`stale` 플래그를 결함 탐지에 쓰지 마라**(§0-①).
4. **ITEM 을 고쳤으면 그 화면의 렌더를 같은 작업 안에서 재생성**하라. 안 하면 미러가 즉시 낡고, `source_hash` 로는 `route`·`purpose` 축을 못 잡는다.
5. **`description` 을 고쳤으면 구조화 배열(`components`·`relationships`·`classes`)도 같이 고쳐라**(C9 — 세 ITEM 이 같은 병).
6. **결번 처리 시 상위·하위를 함께 점검**하라 — D016 은 결번 하나로 **REQ 층 요구와 DFEAT 층 책임이 동시에 증발**했다.
7. **스킬 룰 파일을 이 프로젝트용으로 교체**하라(§0-④). 지금은 `policy` 룰 10개 중 **2개만 유효**하다.
8. **도메인 축 없는 타입을 위한 전역 스윕 라운드**를 별도로 돌려라(§6-3).

## 10. 이 감사가 **결함이 아니라고 판정한 것** (재보고 금지)

- `[폐기]` 제목 접두 · **deprecated → active 방향 참조**(반대 방향만 결함) · 논리 ERD 부재 · `status=new` 의 `legacy_source` 부재
- 계약 어휘(컴포넌트·엔티티 이름, `…Request`/`…Response`/`…Dto`/`…Payload`, DB 물리명, 관제 API 번호 `API-251`/`API-285`)
- **마이그레이션 버전 번호 단독**(`V44`·`V114`·`V138` 등) — 관제가 실제로 SELECT 하는 **스키마 계약면 세대 식별자**라 외부 독자에게도 참. 반면 **커밋 해시는 오염**
- `vlm.accuracy` 가 마트·export 에 없는 것(**R12 — 의도**) · 관제 pull API 의 `LS_DATA_META` 전 행 반환(**다른 채널**) · `LabelContentHasher` 의 `VDSC` 블록이 게이트하지 않는 것(**의도·유지**)
- `NFR-004`(외부 API 연동 복원력) `deprecated` — **사용자 확정**(*"요구사항이 아니라 기술 방침"*)
- `NEXT_RTRY_DT` 공존 — CLAUDE.md 가 **"전역 치환 금지"** 로 못박음
- `EVENT_APPROVE` 는 자바 상수명, **DB 저장값은 `APPROVE`**
- `DFEAT-046.implemented_by_endpoints` 공란 — **outbound push 라 우리 쪽 엔드포인트가 없는 것이 정상**
