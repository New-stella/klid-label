## 테스트베드 전용 기능 목록 (합집합 원칙으로 포함시킨 것)

- **SCREEN-011 NowClock(초단위 자동 갱신 시계)**: 납품 FE에는 없고 테스트베드에는 실존. 컴포넌트를 삭제하지 않고 `[폐기]` 표시 + 대체 방식(새로고침 버튼의 정적 시각 병기) 설명을 병기해 보존.
- **SCREEN-020 WorkerNameSub(조회 대상 작업자명 서브타이틀)**: 납품 FE는 렌더하지 않지만(참조 0건) 테스트베드는 `data?.workerName` 을 실제로 렌더한다(`WorkerStatPage.tsx`). API 필드(`workerStat.workerName`) 자체는 두 구현 모두 응답에 갖고 있어, 컴포넌트를 삭제하지 않고 "구현에 따라 렌더 여부가 다르다" 각주로 보존.
- **SCREEN-020 자동 폴백(`selectedWorkerId ?? workers[0]?.id`)**: 테스트베드 실존 확인. 다만 이건 "추가 기능"이 아니라 납품 FE의 EmptyState 패턴과 상충하는 반대 동작(같은 관심사의 다른 해법)이라 구조는 납품 FE(EmptyState)를 따르고, 구 방식은 설명 각주로만 남겼다(별도 컴포넌트로 승격하지 않음 — P2 "같은 기능을 다르게 표현하면 납품 FE 모양을 따른다" 적용).

## 신규 등록 SCREEN ID

- **SCREEN-036** — 공지 작성 화면 (`/notice/new`, REVIEWER 전용, `ROLE-001`, consumes API-097)
- **SCREEN-037** — 공지 수정 화면 (`/notice/:id/edit`, REVIEWER 전용, `ROLE-001`, consumes API-096/098/106/108, 첨부파일 관리 포함)

두 화면 모두 `static_renders`(정적 HTML 와이어프레임)는 이번 라운드에서 첨부하지 않았다 — LogiCraft가 `SCREEN_STATIC_RENDER_MISSING` 경고를 반환했다(아래 "남은 것" 참조).

## 미확인·남은 것

1. **static_renders(와이어프레임 HTML) 미첨부** — 신규 SCREEN-036/037은 `sections` 메타만 등록했고 정적 HTML 프리뷰(`upload_static_render`)는 만들지 않았다. LogiCraft가 이를 "미완성 산출물"로 안내한다. 이번 작업 범위는 텍스트 사양 정정이라 시각 자산 제작은 포함하지 않았다.
2. **SCREEN-030/031의 기존 static_renders(구 `edit-modal`/`main` 렌더)** — `sections`(텍스트 사양)는 정정했지만, 이미 업로드된 정적 HTML 파일 자체(예: SCREEN-030의 `edit-modal.html`)는 재생성하지 않았다. 실제 화면과 다른 옛 모달 그림이 계속 노출될 수 있다.
3. **SCREEN-032 번호 체계 불일치(CONFLICT-F20 원인)** — "LogiCraft SCREEN-032 ITEM(비식별 신고 관리, `/manage/deident-reports`)이 프로젝트 고유 KLID-AT-SC 번호 체계와 어긋난다"는 근본 원인은 이번 작업 범위 밖(사용자 논의 후 별도 처리 필요, F 리포트 원문의 조치 제안 (b) 항목).
4. **GAP-F00(정본 구현 미명시)** — 개별 finding은 전부 정정했지만 "화면정의서 상단에 정본 구현(납품 FE)을 명시"하는 별도 조항/필드는 추가하지 않았다(스키마에 그런 필드가 없고, 개별 서술이 이미 납품 FE 기준으로 정정됐기 때문에 실질적으로 해소됐다고 판단).
5. SCREEN-021 "작업자별 현황 테이블" 정렬 축(완료·라벨 헤더 클릭 정렬)의 정확한 내부 컬럼 id는 코드까지 대조하지 않았다(F 리포트에 flag된 항목이 아니라 범위 밖으로 판단, 라벨 텍스트만 확인).
