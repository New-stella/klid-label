## 오타 관련 사고와 조치 (기록)

작업 중 두 종류의 한글 오타가 발생해 즉시 발견·수정했다.

1. **입력 실수형**: "눌러야"→"누러야/누리야", "상태"→"상택", "연다"→"염다" (SCREEN-012). 패치로 정정 완료.
2. **유니코드 이스케이프 오류형(CLAUDE.md 경고 사례와 동일 패턴)**: SCREEN-019에서 "펼치다"→"파치다", "합쳐지다"→"함쳐지다", "곧바로"→"곳바로", "뜬다"→"뜼다"(1차 정정 시도에서 재발). `\uXXXX` 이스케이프를 손으로 생성하면서 코드포인트가 한 자리 어긋난 사례로, 재정정 시 파이썬으로 왕복 검증 후 반영해 해소했다. 이후 유사 수정은 이스케이프 대신 리터럴 한글 입력으로 전환.

## 남은 것 / 후속 필요
- **GAP-C07 (SCREEN-018) 미확정 부분**: `ACTION_META`의 `ASSIGNED` 상태 키가 실제 검수 목록 응답에서 도달 가능한지 BE 매핑 확인이 필요하다(감사 시점 확신도 low, 이번 수정에서는 단정하지 않음).
- **static_renders 정적 와이어프레임 HTML은 갱신하지 않았다**: 세 화면 모두 `data.sections`만 갱신했고, `static_renders[].sections`(구 스냅샷)와 실제 HTML 렌더는 이번 작업 범위 밖이라 sections 변경분과 어긋난 상태로 남아있다(LogiCraft가 stale 배지로 자동 표시). 필요 시 별도 라운드에서 `upload_static_render`로 재생성 권장.
- **legacy_source 경고**: 세 화면 모두 `BROWNFIELD_REUSE_WITHOUT_SOURCE` 경고(브라운필드 1차 식별자 미기재)가 update_item 응답에 지속 노출되나, 이는 배치 C 감사 범위 밖의 기존 미기재 사항이라 이번 작업에서 채우지 않았다.
