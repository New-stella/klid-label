### 복구 조치

**SCREEN-024 (v8 → v9)**
- `Button 검색` — **오삭제였다.** 검색어는 입력 즉시 반영되지 않고 Enter 또는 검색 버튼으로 확정하는 방식이라 버튼이 실재한다. 근거 없이 빠졌으므로 원복.
- `Select 상태`·`Button 비활성화/활성화` — 계정 활성 상태 변경이 이 시스템 책임이 아니게 되며 폐기된 요소. **삭제 대신 `[폐기]` 표기로 보존.** 같은 축의 확인 다이얼로그 섹션은 이미 `[폐기]` 로 남아 있어 표기 방식을 일치시켰다.

**SCREEN-025 (v7 → v8)**
- `Dialog 위험 액션 확인 다이얼로그` **복구**. 제거된 상태에서는 시스템 초기화·배치 큐 초기화·캐시 삭제가 **확인 절차 없이 즉시 실행되는 사양**이 된다. 파괴적 액션의 확인 단계는 구현 진척과 무관한 설계 요구다.
- 같은 섹션의 구현상태 서술 제거 — 세 버튼의 `note` 가 *"클릭 핸들러가 연결되어 있지 않아 현재는 아무 동작도 하지 않는다"* 였다. 각 액션이 무엇을 하고 어떤 확인을 거치는지로 교체.
- 섹션명 `위험 액션 (placeholder)` → `위험 액션`.

## ⑨ 와이어프레임 재생성 — 결정론적 생성기로 전환

### 문제

`static_renders` 는 손으로 작성돼 있었고, 이번 라운드에서 섹션을 대폭 고치자 **23건 중 11건이 stale** 이 됐다. 게다가 5건은 와이어프레임이 아예 없었다(`SCREEN-006 · 007 · 035` + 신규 `036 · 037`).

부수 문제로 `static_renders[].sections` 미러가 `data.sections` 와 따로 표류해 **한 ITEM 안에 두 개의 진실원**이 생겼다. 스키마 가이드를 확인하니 **page 렌더의 `sections` 는 원래 비우는 것이 표준**(ITEM-level fallback)이었다 — 애초에 채우지 말았어야 할 필드였다.

### 조치 — 생성기

`docs/screen-design/klid-authoring-screens/bin/generate-wireframes.py`

`data.sections` 만 입력으로 받아 `wf-*` 표준 클래스로 렌더한다. **LLM 개입 0, 같은 입력이면 항상 같은 출력.**

- 섹션당 `wf-card` + 메타 칩(role/layout/API) + `섹션 상세` 링크
- 컴포넌트 타입별 마크업(Input/Select/Table/Chart/Dialog/… 42종 enum 대응)
- 본문 끝에 섹션마다 `wf-sec-detail-modal` — 설명 · Components(+**검증규칙·바인딩·트리거 API·상태**) · API · Feature
- `wireframe.css` link 는 넣지 않는다(서버 sanitize 가 자동 주입)

28건 생성, 전부 200KB 제한 이내(최대 `SCREEN-005` 53KB).

### 업로드

⚠️ REST 엔드포인트(`POST /projects/{id}/items/{SCREEN}/static-render`)는 **세션 인증만 받아 API 키로는 401** 이다. MCP `upload_static_render` 를 써야 한다. `sections` 파라미터는 보내지 않아 ITEM-level 단일 참조로 정리했다.

### 검증 — 원본 대조
