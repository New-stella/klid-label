## 정책 위반 재확인 — SCREEN-025 “YOLO” 카드 제목

지시받은 조치는 “‘YOLO 추론 파라미터 카드’ → ‘AI 탐지 추론 파라미터’로 정정”이었다. 실제 화면을 확인해보니:
- 이 화면의 **다른 부분**(예: 배치 처리 단계 표시)은 이미 “기술 모델명을 사용자 노출 문구에 쓰지 않는다”는 정책을 지키고 있었다(예: “AI 탐지”라는 표현을 이미 사용 중).
- 그런데 이 설정 카드 제목 자체는 실측 시점에 **여전히 “YOLO 추론 파라미터”라는 문구를 실제로 표시하고 있었다** — 즉 이 카드만 정책을 지키지 않는 상태였다.

정의서(설계 사양)는 “무엇을 만들어야 하는가”를 담는 문서이므로, 이미 확정된 정책(사용자 노출 문구에 기술 모델명 금지)을 기준으로 **“AI 탐지 추론 파라미터”가 맞는 사양**이라고 판단해 그 문구로 반영했다. 다만 이는 현재 화면이 실제로 보여주는 문구와 다를 수 있다는 뜻이므로, **이 화면(설정 카드 제목)이 정책을 지키도록 코드를 맞추는 별도 수정 작업이 필요하다.** (이 파일은 설계 산출물만 다루므로 코드 수정은 하지 않았다.)

## 남은 것 (이 배치에서 다루지 않음)

1. **SCREEN-025 시스템 설정 카드 제목의 실제 코드가 정책을 위반한다** — 설계는 정정했으나 코드(카드 제목 문구)가 아직 “YOLO”를 노출한다. 코드 수정 필요.
2. **SCREEN-025 IoU 임계값 화면 슬라이더 범위**가 서버 허용 범위보다 넓다 — 화면 슬라이더 하한을 30으로 좁히는 코드 수정 검토 필요.
3. **SCREEN-025 위험 액션 버튼 3종**이 완전히 무반응이다 — 이관 전까지 최소한 확인 다이얼로그만이라도 넣을지, 버튼을 숨길지 결정 필요.
4. **SCREEN-035 implementation 필드**가 실제 구현 상태와 맞지 않는다(설계상 “아직 계획” vs 실제로는 코드 존재) — 이번 배치에서는 손대지 않았으니 별도로 정정 필요.
5. **SCREEN-035 static_renders 미등록** — 사용자가 인지하고 있는 낮은 우선순위 항목, 별도 작업으로 등록 필요.
6. **SCREEN-032 DISMISSED 상태 도달 가능성** 미확인 — 확인 후 필요하면 상태 탭·컬럼 사양에 반영.
7. **SCREEN-025 저장 실패 서버 메시지 원문** 미확인 — 확인 후 필요하면 validation 문구 보강.
