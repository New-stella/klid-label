## 1. 구속 규칙 — 위반은 결함이다

### P0 — LogiCraft ITEM 본문은 **설계(사양)만** 담는다
판정 한 줄: **"이 문장이 이 저장소를 모르는 제3자에게도 참인가?"**
- 예 → ITEM 본문 · 아니오(지금 작업하는 사람에게만 의미) → 로컬 `reports/**`

| 층 | 담는 것 |
|---|---|
| ITEM 본문(`data`) | 동작·상태분기·검증규칙·권한·props 계약 등 **사양** |
| `change_summary` | 무엇을 → 무엇으로 + **설계 근거** (리포트명·finding 코드 금지) |
| 로컬 `reports/**` | 작업 맥락·감사 이력·근거 파일 경로·**구현 상태**·미확인 목록 |

**본문 금지어**: 레포명(`klid-label-frontend`·`upload-ui`·"테스트베드"·"납품 FE") · 코드 파일명(`*.tsx`/`*.ts`/`*.java`…) ·
커밋 해시 · finding 코드 · 구현상태("미구현"·"코드에서 제거"·"아직 구현") · 감사 이력.
**`implementation` 필드는 건드리지 않는다.**

> 컴포넌트 **이름**(`FrameNavigator`·`StatusBadge`)은 금지 대상이 아니다 — 카탈로그의 사양 어휘다.
> 금지되는 건 **파일 경로·확장자**다.

### P2 — 기능은 합집합, 구조·명칭은 기준 구현
- **기능·동작** = 기존 정의서 ∪ 두 프론트엔드 구현. **어느 한 곳에만 있어도 포함**한다.
- **구조·명칭·동선** = 기준 구현(`/Users/ck/orca/klid-label-frontend`) 기준. **같은 기능의 표현이 갈릴 때만** 적용.
- 본문에는 "어느 쪽 기준"인지 **쓰지 않는다**(P0 위반). 결과 사양만 쓴다.

### P8 — 배열 원소를 조용히 지우지 않는다
- 폐기 항목은 `[폐기] ` 접두 + **"두지 않는다"(설계 결정)** 형태로 남긴다. "없어졌다"(구현 상태) ❌
- 개명·통합으로 원소가 사라지면 **`change_summary`에 옛 이름 → 새 이름을 반드시 적는다.**
- 검증기 `uiloss`가 사라진 원소를 이름까지 전부 나열한다. 나열된 항목은 한 건씩 의도를 확인한다.

### 한글 — 유니코드 이스케이프 금지
`\uXXXX`로 한글을 쓰지 않는다. 지난 라운드에서 `스텝→스템`·`플레이스홀더→플레이스홍더`·`펼치다→파치다`
류 손상이 여러 배치에서 반복 발생했다. **깨진 글자가 아니라 읽히는 다른 한글**이라 육안으로 안 잡힌다.

### 추정 금지
- 코드를 **열어서 확인한 것만** 쓴다. 이름이 비슷하다고 동작을 넘겨짚지 않는다.
- 확인할 수 없으면 **비워 두고 배치 보고서에 "정보 부족"으로 남긴다.** 그럴듯한 일반론을 채우지 않는다.

## 2. 판정 프레임워크 (UI-055·UI-060에서 확립 — 그대로 따른다)

각 ITEM을 **4방향 대조**한다:

```
카탈로그 ITEM  ↔  기준 구현 코드  ↔  대조 구현 코드  ↔  그 컴포넌트를 쓰는 SCREEN 사양
```

- 기준 구현: `/Users/ck/orca/klid-label-frontend/src`
- 대조 구현: `/Users/ck/orca/workspaces/klid-label/upload-ui/frontend/src`
- SCREEN 사양: `docs/screen-design/klid-authoring-screens/.staging/screen_spec/_raw/SCREEN-*.json`

### 필드별 작업 기준

| 필드 | 기준 |
|---|---|
| `description` | 위치(좌/중/우)·상태 분기·**두지 않기로 한 것**·비활성 조건까지. "무엇을 보여주나"가 아니라 "어떻게 동작하나" |
| `props_schema` | 두 구현의 **합집합**, 명칭은 기준 구현. 각 prop에 `description` 필수 — 이름만으론 계약이 안 선다 |
| `tags` | 틀린 분류는 제거한다(`dark` 등). 태그는 사양이 아니라 검색 분류축이라 P8의 `[폐기]` 대상이 아니다 |
| `accessibility_notes` | 키보드 도달·`aria-*`·포커스·스크린리더 안내. **코드에서 확인된 것만** |
| `usage_example` | 어떤 화면·맥락에서 쓰는지 + 쓰면 안 되는 경우 |
| `variants` | 실제로 분기가 있을 때만. 없으면 비운다(억지로 만들지 않는다) |
| `referenced_by_screen_ids` | 그 컴포넌트를 실제로 쓰는 SCREEN. 공통 컴포넌트도 채운다 |
| `implements_in_module_ids` | **건드리지 않는다** — `code_module` 연결은 별건(RESUME 4-4) |

### 확립된 판례

1. **중복 진입점은 사양에서 하나로 정리한다.** 저장 버튼이 헤더·도구바 양쪽에 있으면 진행 표시와
   잠금 판정이 갈린다 → 헤더는 상태만, 진입점은 도구바+단축키.
2. **boolean 플래그보다 사유를 실은 코드값.** `saveDisabled: boolean` → `lockSttsCd: 'NONE' | 'LOCKED_FOR_REDEIDENT'`.
   비활성 판정이 한 축에서 나온다.
3. **"두지 않는다"는 명시적으로 적는다.** 안 적으면 다음 사람이 "빠뜨린 것"으로 보고 되살린다.
4. **개명은 삭제가 아니다.** `dirty→isDirty`처럼 바뀌면 `change_summary`에 대응을 남긴다.

## 7. ★ 라운드 중 확정된 추가 구속 규칙

### R1 — `status` 를 바꾸지 않는다 (실측으로 확인된 함정)

`update_item(status: "deprecated")` 로 바꾼 ITEM 은 **배치 export 에서 통째로 사라진다.**

- `--types ui_component` 전체 요청 → 빠짐
- **`--ids "UI-059,..."` 로 식별자를 명시해도 `서버 0건`** — 필터가 무조건적이라 우회 불가
- 반면 `find_ui_component` 는 정상 반환 → **키트 표면에서만 사라지는 비대칭**

**왜 치명적인가**: 이 라운드의 검증기 4종은 전부 키트 staging 을 입력으로 받는다. deprecated 가 되는
순간 오염·한글손상·감소 검사에서 **조용히 빠진다.** 카탈로그 개수도 줄어(97→94 실제 발생) 다음
라운드가 "콘텐츠 유실"로 오판한다. 그리고 다음 사람이 그 항목을 못 보면 **같은 것을 다시 만든다.**

**규칙**: 폐기는 **제목 `[폐기] ` 접두 + 본문 "두지 않는다"** 로만 남기고 `status` 는 `draft` 유지.
서브에이전트 프롬프트에 이 금지를 **명시**해야 한다(지시 없으면 스스로 판단해 바꾼다 — 실제 4건 발생).

**검출**: 매 Wave 종료 시 개수 대조 + 다운로더 출력의 `삭제 N` 확인.
```bash
comm -23 <(ls baseline/before_raw_ui | sed 's/.json//' | sort) \
         <(ls .staging-ui/ui_component/_raw | sed 's/.json//' | sort)
```

**최종 스윕 대상**: `UI-075`(F5 가 deprecated 로 바꿈 — 되돌릴 것). `UI-059`·`UI-061`·`UI-068` 은 처리 완료.

### R2 — 화면 사양(SCREEN)이 컴포넌트 사양보다 앞선다

같은 요소의 위치·존재 여부가 갈리면 **SCREEN 사양이 이미 확정한 쪽**을 따른다. 구현 코드는
확정 사양을 아직 못 따라잡았을 수 있다(실제로 대조 구현이 그랬다).

라운드 중 이 규칙으로 잡은 것:
- **`objectCount`** — SCREEN-005 v22 가 `[폐기] N개 객체` + "우측 패널 '객체' 탭 목록 상단에 둔다"로
  확정했는데, 대조 구현만 보고 헤더 사양에 필수 props 로 넣었다가 제거.
- **저장 진입점** — SCREEN-005 는 헤더·좌측 도구바의 저장을 **둘 다 폐기**하고 **캔버스 상단 옵션바**
  한 곳으로 못박았다. 그런데 `UI-055`·`UI-053` 이 "도구바"라고 적고 있었다(대조 구현 주석이
  "유일한 저장 진입점"이라 적힌 것을 그대로 옮긴 결과). 기준 구현도 상단 옵션바가 저장을 갖는다.

### R3 — 책임을 이관하면 수신처를 반드시 확인한다

"A 에 두지 않는다"를 적었으면 **B 가 그 책임을 실제로 명시하는지** 확인한다. 안 하면 그 기능이
사양에서 통째로 증발한다. 이관 3건 확인 완료: 프레임 이동(헤더→`FrameNavigator` / 검수헤더→`ReviewFrameTimeline`),
승인·반려(액션바→헤더).

## 9. `docs/test-cases` 동기화 — 검토 결과 (2026-08-07)

**결론: 이번 라운드로 인한 변경 대상이 없다.** 근거를 남겨 다음 사람이 같은 검토를 반복하지 않게 한다.

1. **이번 라운드는 코드 동작을 바꾸지 않았다.** 사양을 코드에 맞춘 것이라 테스트 기대결과가 달라진 건이 0이다.
2. **개명 8건·폐기 6건 중 카탈로그에 등장하는 것은 2건뿐**이고(`LabelSidebar` 5회 · `PrivacyBadge` 4회)
   **둘 다 이미 "폐지·삭제"로 정확히 기록**돼 있다(`PrivacyBadge` 는 회귀 가드 `TC-FE-316~319` 까지 등재).
   나머지 12건은 카탈로그에 한 번도 등장하지 않는다.
3. 이번에 잡은 사양 오류가 테스트에 반영돼 있는지 표적 확인했다 — **배치 단계 수 서술 0건**(카탈로그만 5단계로
   틀려 있었고 테스트는 애초에 그 축을 다루지 않는다).

### ⚠ 다만 이 검토에서 별건 하나가 드러났다 — **저장 진입점의 코드 드리프트**

| 층 | 저장 버튼 위치 |
|---|---|
| 화면 사양 `SCREEN-005` v22 | **캔버스 상단 옵션바** (헤더·좌측 도구바의 저장은 둘 다 `[폐기]` 명시) |
| 기준 구현 | **캔버스 상단 옵션바** (상단 바 컴포넌트가 저장 핸들러 보유) |
| 대조 구현 | **좌측 도구바** — 캔버스 상단 옵션바 자체가 없다 |

`docs/test-cases` 회차 25(H 회차 19)는 대조 구현 기준으로 *"헤더 제거 → 좌측 도구바로 일원화"* 를 기록했고
셀렉터도 `label-toolbar-save` 다. **그 기록은 대조 구현에 대해 정확하다** — 카탈로그 오류가 아니다.

즉 이건 **문서 문제가 아니라 코드가 확정 사양을 아직 따라잡지 못한 것**이다. 카탈로그(`UI-053`·`UI-055`)는
사양·기준 구현을 따라 **캔버스 상단 옵션바**로 정정했다. 대조 구현을 사양에 맞출지는 **별건**이며,
맞추기로 하면 그때 `docs/test-cases` 의 셀렉터·위치 서술이 함께 갱신 대상이 된다.
