## 5. 카테고리별 핵심 내용

### 5.1 ECR — 시스템 장비 구성 (20건)
- 도입장비 규격·수량 RFP 준수, 확약서 제출, 결함 제품 교체, 반출입·완전삭제 절차 → **HW 도입/설치 사업자 책임** (타시스템-인프라)
- **공통 채택분**:
  - `RQ-ECR-03-01` 시스템 SW(WEB/WAS/DB)는 **공개 소프트웨어 활용** — 아키텍처 baseline
  - `RQ-ECR-03-04` 도입 SW 최신 버전 적용 (발주기관 협의)
  - `RQ-ECR-05-03` 국가정보자원관리원 도입 HW/SW 사양 기반 설계 — **장비 도입이 8월 이후라 개발환경 선확보 필요**

### 5.2 PER — 성능 (15건) ★정량 기준 다수
| ID | 기준 | 중요도 |
|----|------|:---:|
| RQ-PER-01-03 / 02-02 | **페이지 응답속도 3초 이하** (초과 시 발주기관 협의) | 상 |
| RQ-PER-03-01 | **10초 이상 지연 예상 작업** → 팝업·프로그레스바 안내 + 취소 기능 | 중 |
| RQ-PER-04-01/02 | 입력 형식 오류·CRUD 오류 **3초 이내** 오류 메시지 | 중 |
| RQ-PER-05-03 | CPU·메모리 **평균사용률 80% 이하** (모의추정 기준) | 상 |
| RQ-PER-05-04 | 로그아웃 시 세션 종료 처리 | 중 |
| RQ-PER-05-05 | DB 커넥션 풀 최적화 | 중 |
| RQ-PER-05-06 | 메모리 누수 등 자원 효율 문제 방지 | 중 |
- 그 외: 성능테스트·개선 계획 수립(01-01, 상), 로그/도구 기반 성능 모니터링(01-02), 페이지 용량 감축 최적화(02-01), 단계별 성능·부하 테스트 지속 실시(05-02, 상)

### 5.3 SIR — 인터페이스 (23건)
- **UX/UI 표준(SIR-01~06)**: UI/UX 표준·설계가이드 수립, HTML5 웹표준·크로스브라우징(Active-X 불가), 반응형 웹 **1024×768 ~ 1920×1080 지원**, 수평스크롤 배제, 브레드크럼·퀵메뉴·사이트맵, 온라인 도움말 + 현행화, 일관된 오류/확인 메시지
- **연계(SIR-07~11, 중요도 상 다수)**:
  - 개방형 연계기술(API) + **발주기관/수요기관 표준연계모듈** 사용 (07-01, 09-01)
  - W3C 표준 XML 문서형식 연동 (09-02)
  - **연계데이터 정합성** — 연계 단계별 검증 방안, 행정정보 연계 표준 준수 (10-01/02, 담당=관제지원)
  - 연계 명세(대상·범위·방식·주기·건수) 제시 + 성능 영향 고려한 갱신주기 + 개발/테스트 환경 검증 후 이관 (11-01)

### 5.4 TER — 테스트 (33건, 정밀화 미기재)
- 테스트 일정·방안(단위/통합/시스템/인수) 수립, 실데이터(오류 데이터 포함) 테스트, 유형별 테스트 계획서
- **단위테스트(TER-02)**: 결함유형·심각도·추세 분석 + 시험 커버리지(유스케이스 기준 %)
- **통합테스트(TER-03)**: **2회 이상 실시**, 지자체별 실운영 데이터 생성, 정상/예외/오류 시나리오, 접근권한 적절성, 대내·대외 연계 업무흐름 검증
- **성능/부하(TER-04/05)**: 목표성능 정의 → 미달 시 튜닝·재시험, 성능검증도구 도입, **암호화 적용 전·후 성능 비교**·저하 대응
- **인수테스트(TER-06)**: 요구사항별 적합/부적합 판정 가능한 테스트·데이터, 하자 보완 반복, 별도 문서 승인으로 완료

### 5.5 QUR — 품질 (19건)
- 품질보증 방안·인증 증빙·GS인증(도입 SW) — 사업 관리 영역
- `RQ-QUR-02-01/02` (상): RFP 요구사항 **전건 구현** + 변경관리 절차로 baseline 관리, 테스트로 충족 평가 → 요구사항 추적성(RTM)
- **`RQ-QUR-03-01/02` (상, 담당=타시스템/저작도구)**: 학습데이터 수집~제작~검수 단계별 품질관리 기준 + 종류·제작방법별 기준 수립 → **저작도구(본 시스템) 책임** (§8)
- **가용성(QUR-05, 상)**: **24시간/365일 무중단** 운영, 채널 간 동일 결과, 백업·장애복구 절차
- 상호운용성(QUR-06, 상): 인터페이스 데이터 정합성·무결성 검증
- 유지관리성(QUR-07): 설치/제거 문서, 문의 대응, 인수인계
- 모듈화(QUR-08, 상): 재사용·확장 위한 모듈화 + 상호운용·이식성, 정보 항목 중복 개발 방지, 프로세스 중심 매뉴얼

### 5.6 PSR — 프로젝트 지원 (36건)
- **운영(PSR-02, 담당=관제지원 4건)**: 장애예방·백업·보안 운영규정(비상 대비), 안정성·신뢰성 + 신속 대응체계, 개발/운영 환경 구성·포팅, **최소 인력 운영 자동화** + 운영자 역할 기반 기능 설계
- **하자보수(PSR-03)**: 검사 완료일로부터 **무상 12개월**, 개발 직접투입 인력의 지속 지원, **장애접수 후 8시간 이내 조치**, 분야별/등급별 지원 계획
- 교육(PSR-04)·교육자료(PSR-08): 교육훈련 계획, 사용자/관리자 매뉴얼 작성·현행화, 화면 단위 사용법, 홍보 동영상
- **기술이전(PSR-05)**: 기술이전 계획, 무상하자보수 기간 기능보완 기술지원(추가 비용 사업자 부담), **기존 시스템 영향 없는 별도 개발환경**(상), 오픈 후 안정화 지원(상)
- 업그레이드(PSR-06)·패치(PSR-07): 확장 가능 구조, 마이너 버전 협의 패치 (담당=관제지원)
- 지재권(PSR-09): 산출물 **발주기관-사업자 공동 소유**(균등 지분), 이미지·폰트 저작권 사업자 부담, 타 기관 공동활용 없음

### 5.7 DAR — 데이터 품질 (12건, 중요도 상 위주)
- `DAR-01` 데이터 표준사전(단어·용어·도메인·코드) 제정 + **범정부 표준(공공DB 표준화 지침·공통표준용어) 준수** + **학습데이터 유형별·라벨링 방식별 표준 수립**
- `DAR-02` 표준 변경이력 관리 + 표준사전↔데이터 항목 일치 주기 점검
- `DAR-03` 주제영역·개념·논리·물리 모델 설계, 명명규칙·DB Object 기준
- `DAR-04` 설계자·개발자·발주기관·전문가 참여 단계별 모델 검증 (완전성·정규화·중복)
- `DAR-05` DB↔물리모델 형상 일치 주기 점검
- `DAR-06` 값 검증·오류 입력 방지 + 업무규칙(BR) 정의 / **`DAR-06-02` 학습데이터 진단·원본 정합성 검증(공공데이터 품질진단 기준) → 담당=저작도구** (§8)
- `DAR-07` 데이터 관리체계(조직·역할·절차 + 표준준수율·현행화율·오류율 지표), 연계데이터 목록 정의·정기 정합성 검증
- `DAR-08` 메타데이터 관리시스템·중앙메타시스템 등록·현행화, 공공데이터 포털 개방(파일/API) 지원

### 5.8 PMR — 프로젝트 관리 (43건, 정밀화 미기재 — 사업수행 보안·관리)
- 보안관리 일반(국가 정보보안 기본지침 준용), **누출금지 대상정보** 유출 시 부정당업체 제재
- 참여인원: 보안서약서·보안교육·종료 시 완전삭제 + 보안확약서
- 문서/자료: 지정 위치(파일서버) 저장, 개인 PC·웹하드·개인 메일 금지, 외부 메일 시 암호화(**비밀번호 9자리 이상**)
- 사무실/장비/네트워크: 출입통제·월 1회 보안점검, 장비 반출입 대장·매체제어(포트락), 인터넷 연결 원칙 금지·무선 통제
- 기능점수(FP) 산정서(간이법) 제출, 착수계획서(WBS) 10일 이내, 주간/월간 보고, 산출물 버전관리
- 변경관리(변경요청서 승인), 위험관리(위험관리대장), 검사·검수(하자 보완 반복)
