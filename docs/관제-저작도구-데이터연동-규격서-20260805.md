# 관제지원시스템 ↔ 학습데이터 저작도구 — 데이터 연동 규격서

**작성일** 2026-08-05 · **작성** 저작도구팀 · **상태** 설계안(협의 요청)

---

## 1. 문서 목적

두 시스템은 아직 연동 전이며, 본 문서는 **연동 규격을 확정하기 위한 설계안**이다.
방향이 서로 다른 두 가지를 함께 다룬다.

| | 목적 | 해당 절 |
|---|---|---|
| **관제 → 저작도구** | 학습데이터를 **만들 수 있도록 영상과 메타를 전달**한다 | §3 |
| **저작도구 → 관제** | 완성된 학습데이터로 **`datasets`·`dataset_versions` 를 채운다** | §4·§5·§6 |

전달 수단은 3개 채널이다.

| 채널 | 방향 | 수단 | 본 문서 |
|:--:|---|---|:--:|
| ① **인입** | 관제 → 저작도구 | 관제가 `LS_DATA_INGEST` 테이블에 **직접 INSERT** | §3 |
| ② **통지** | 저작도구 → 관제 | REST (`notify-completed` / `notify-updated`) | §4 |
| ③ **조회** | 저작도구 → 관제 | 저작도구 DB 뷰 `V_COMPLETED_VIDEO` **SELECT** | §5 |

> **§3(인입 테이블 명세)은 이번에 처음 전달하는 규격이다.** 관제 측에서 이 표를 기준으로
> INSERT 문을 구성하면 된다. **인입 신규 요청은 §3-3 의 1건뿐**이며 그마저 §7-D 의미 확인이 선행된다 —
> 나머지는 현행 규격으로 충족된다.

## 2. 연동 흐름

```
[관제]  학습용 영상 선정
   │
   │  ① INSERT → klid_at.LS_DATA_INGEST                    (§3)
   ▼
[저작도구]  적재 → 비식별 → 마킹 → 프레임추출 → 오토라벨링 → 라벨링 → 검수
   │
   │  검수 승인(APPROVED) 시점
   │
   ├─ ② POST /api/data-set/v2/jobs/{job_id}/notify-completed   (§4-1)
   │     (승인 후 수정 시 notify-updated)                        (§4-2)
   ▼
[관제]  통지 수신 → ③ SELECT V_COMPLETED_VIDEO (§5)
        → datasets / dataset_versions 적재 (§6)
        → 산출 폴더·영상 파일 픽업 → 패키징
```

**작업 단위 = 영상 1건.** 저작도구 영상 식별자 `RAW_SN` 이 관제 `datasets.job_id` 가 된다.

## 3. 인입 테이블 명세 — `LS_DATA_INGEST`

**스키마** `klid_at` (PostgreSQL) · **INSERT 주체** 관제지원시스템

관제가 학습용으로 선정한 영상 1건당 1행을 INSERT 한다.
저작도구 주기 배치가 `PRCS_STTS_CD='PENDING'` 행을 픽업해 파이프라인에 태운다.

**관제가 기입하는 35개는 두 갈래로 쓰인다** (나머지 8개는 저작도구 운영 컬럼 — §3-1-1).

| 쓰임 | 개수 | 내용 |
|---|:-:|---|
| **저작도구 파이프라인 구동** | 24 | 영상 파일을 읽고(경로·파일명), 비식별·프레임추출·라벨링을 수행하며,<br>산출 어노테이션 JSON 의 영상 메타(해상도·FPS·위치·CCTV 제원 등)를 채운다 |

### 3-1-1. ✗ 컬럼에 값을 넣으면 (주의)

`✗` 8개는 저작도구가 채우는 **인입 처리 운영 컬럼**이며 `datasets`·`dataset_versions` 와 무관하다.
다만 두 가지는 값을 넣으면 실제로 문제가 된다.

| 컬럼 | 값을 넣으면 |
|---|---|
| **`PRCS_STTS_CD`** | ⚠ 저작도구 배치는 `'PENDING'` 행만 픽업한다. 다른 값이면 **그 영상은 영영 처리되지 않는다**(오류 없이 조용히 누락) |
| `RCPTN_SN` | `GENERATED BY DEFAULT AS IDENTITY` 라 값을 주면 그대로 들어가지만, 시퀀스가 따라오지 않아 이후 **PK 충돌**이 난다 |

**관제가 조회에 활용할 수 있는 컬럼**

- `RAW_SN` — 적재 후 기록되므로 **인입 행 ↔ 이후 통지(`job_id`)** 역추적에 쓸 수 있다
- `PRCS_STTS_CD` · `ERR_MSG` — 인입한 영상이 정상 처리됐는지, 실패했다면 왜인지 확인할 수 있다

### 3-2. `SRC_TYPE` 허용값 (중요)

저작도구는 **allowlist 를 통과한 값만** 내부 테이블로 복사한다. 목록 외 값은 무시된다.

| 값 | 의미 |
|---|---|
| `ORIGINAL` | 일반 원본 영상 |
| `RELAY` | 중계서버 경유 수집 영상 |
| `GENERATED` | **생성형 AI로 제작된 영상** |
| `USER_ULD` | 사용자 업로드 |
| ~~`AUGMENTED`~~ | *(저작도구 내부 증강 파생본 전용 — 관제가 INSERT 시 사용하지 않음)* |

**★ `GENERATED` 는 관제 `datasets.gen_ai_yn` 의 판정 근거다.** 저작도구는 아래 규칙으로 산출한다.

```
gen_ai_yn = SRC_TYPE IN ('GENERATED', 'AUGMENTED') ? 'Y' : 'N'
```

- `GENERATED` — 관제가 AI로 제작해 인입한 영상
- `AUGMENTED` — 저작도구가 만든 증강 파생본(WINTER/NIGHT/RAIN) 및 **해상도 변경 파생본**

→ **AI로 생성한 영상을 인입할 때 `SRC_TYPE='GENERATED'` 로 넣어 주셔야** `gen_ai_yn` 이
정확히 채워진다. `ORIGINAL` 로 들어오면 저작도구는 이를 구분할 수단이 없다.

### 3-3. 신규 요청 항목

저작도구가 관제 테이블을 채우려면 필요하나 **현재 인입 규격에 없는 값**이다.

| 컬럼(안) | 타입(안) | 소비처 | 요청 사유 |
|---|---|---|---|
| `RPRS_DATA_SHP_CN` | text | `dataset_versions.rprs_data_shp` | **의미 확인 선행** — §7 확정항목 D 참조 |

## 4. 통지 규격 (저작도구 → 관제 REST)

공통: 헤더 `x-access-token` · Content-Type `application/json`

### 4-1. 최초 완료 통지 — `POST /api/data-set/v2/jobs/{job_id}/notify-completed`

검수 승인(APPROVED) 시점에 영상 1건당 1회 발송한다.

| 필드 | 타입 | 필수 | 값 |
|---|---|:-:|---|
| `job_id` | string(≤100) | ✔ | 영상 ID (`LS_DATA_RAW.RAW_SN`) |
| `event_type_cd` | string | ✔ | 인입 `EVNT_TYPE_CD` |
| `evnt_cls_cd` | string(≤2) | ✔ | 인입 `EVNT_CLSF_CD` |
| `evnt_ctgry_cd` | string(≤4) | ✔ | 인입 `EVNT_CTGRY_CD` |
| `lclgv_cd` | string | ✔ | 인입 `LCLGV_CD` |
| `lclgv_nm` | string | — | 인입 `LCLGV_NM` |
| `duration_sec` | integer(≥0) | ✔ | 영상 길이(초) |
| `image_count` | integer(≥0) | ✔ | **추출·라벨링된 프레임 수** (영상 전체 프레임 수 `FRME_CNT` 와 다름) |
| `gen_ai_yn` | `Y`\|`N` | ✔ | §3-2 규칙 |

응답 `202` — `{ dataset_version_id(uuid), status:"packaging" }`

### 4-2. 수정 통지 — `POST /api/data-set/v2/jobs/{job_id}/notify-updated`

검수 완료 후 라벨·메타가 수정되어 **산출물을 재생성**했을 때 발송한다(새 버전).

| 필드 | 타입 | 필수 | 값 |
|---|---|:-:|---|
| `job_id` | string | ✔ | 영상 ID |
| `changed_items.images[]` | string[] | ✔ | 변경 이미지 파일명 (`{프레임번호 4자리}.jpg`) |
| `changed_items.jsons[]` | string[] | ✔ | 변경 JSON 파일명 (`{프레임번호 4자리}.json`) |
| `ver_expln` | string | — | 이번 버전 설명 (예: `"라벨 수정 3건"`) |
| `data_info` | object | — | 구축 메타 갱신 — **§7 확정항목 E (키 스키마 미정)** |

응답 `202` — `{ dataset_version_id(uuid), version, status:"packaging" }`

> **통지는 메타·변경 목록만 전달한다.** 라벨 좌표·메타 본문은 포함하지 않으며,
> 관제는 §5 뷰와 산출 폴더에서 상세를 가져간다.

### 5-2. 개인정보 3필드 — 두 기준을 함께 제공한다

뷰는 개인정보 포함 여부를 **비식별 기준**과 **원천 기준** 두 벌로 내보낸다.

| 구분 | 컬럼 | 판정 대상 | 용도 |
|---|---|---|---|
| **비식별 기준** | `ANONY_INCL_YN` · `PSDO_INCL_YN` · `PRVC_INCL_YN` | 저작도구가 산출한 **비식별 영상** | **`dataset_versions` 적재용** |
| **원천 기준** | `SRC_ANONY_INCL_YN` · `SRC_PSDO_INCL_YN` · `SRC_PRVC_INCL_YN` | 관제가 인입한 **원천 영상** | 참고·대조용 |

#### 비식별 기준 (적재 대상)

학습데이터로 배포되는 것은 비식별 영상이므로, `dataset_versions` 의 3필드는 **이 값을 쓴다.**

| 컬럼 | 의미 |
|---|---|
| `ANONY_INCL_YN` | 비식별 영상에 **익명처리된 정보**가 포함되는가 |
| `PSDO_INCL_YN` | 비식별 영상에 **가명정보**가 포함되는가 |
| `PRVC_INCL_YN` | 비식별 영상에 **개인정보**가 포함되는가 |

사업 어노테이션 표준의 `video.anonymity` / `video.pseudonymity` / `video.privacy_included`
와 **같은 축**이라, 저작도구 산출 JSON 과 뷰의 값이 일치한다.
값은 검수 과정에서 작업자·검수자가 영상 단위로 입력한 판정을 따른다.

#### 원천 기준 (참고 제공)

**관제가 인입 시 보낸 값**(`LS_DATA_INGEST.ANONY_INCL_YN` 등)을 그대로 돌려준다.
비식별 처리 전후를 대조할 수 있도록 제공하는 것이며, 저작도구가 가공하지 않는다.

⚠ **파생영상(증강 · 해상도 변경)은 `NULL` 이다.**
파생본은 부모의 **비식별 영상을 복사**해 만든 것이라 대응하는 원천 영상이 존재하지 않으며,
인입 행도 없다(§5-5 "파생영상에는 원본 영상이 없다"와 같은 이유로 `ORGNL_VDO_PATH_NM` 도 NULL).

```
SRC_*_INCL_YN = (ORGNL_RAW_SN IS NULL) ? 인입값 : NULL
```

### 5-3. `DATST_NM` · `DATST_EXPLN` 의 값 규칙

관제 `datasets.name` · `description` 은 둘 다 **NOT NULL** 이나 값 규격이 정의되어 있지 않다.
기존 데이터셋의 적재 사례(`"교통사고 데이터셋 구축"`)를 따라 **동일한 형식**으로 채운다.

| 컬럼 | 값 | 예시 |
|---|---|---|
| `DATST_NM` | `{이벤트명} 데이터셋 구축` | `교통사고 데이터셋 구축` |
| `DATST_EXPLN` | `{이벤트명} 데이터셋 구축` | `교통사고 데이터셋 구축` |

- `{이벤트명}` 은 관제가 인입 시 전달한 `LS_DATA_INGEST.EVNT_NM` 값이다.
- 두 컬럼에 **같은 값**이 들어간다(기존 적재 사례와 동일).
- 저작도구 산출 어노테이션 JSON 의 `dataset.name` 도 **같은 규칙으로 통일**한다.
- `DATST_NM` 은 **`varchar(200)`**, `DATST_EXPLN` 은 **`varchar(4000)`** 이다.
- `DATST_NM` 은 접미사 `' 데이터셋 구축'`(8자)을 포함한 길이이므로 **이벤트명이 192자를 넘으면
  200자에서 잘려 나간다**(192자까지는 전량 보존). `DATST_EXPLN` 은 상한이 커 절단되지 않는다.

> 다른 명명 규칙이 필요하면 회신 바란다(§7-B).

### 5-4. `IMG_YN` · `VDO_YN` 의 산출식

저작도구가 산출물 실재 여부로 판정해 채운다. 관제가 별도로 계산할 필요 없다.

| 컬럼 | 산출식 | 의미 |
|---|---|---|
| `IMG_YN` | `FRME_CNT > 0` → `Y` | 산출 폴더에 **프레임 이미지·JSON 이 존재**하는가 |
| `VDO_YN` | `DE_IDNTF_FILE_PATH_NM IS NOT NULL` → `Y` | **비식별 영상 파일이 존재**하는가 |

> 두 값은 **산출 시점 기준**이며, 패키징 결과가 아니다. 관제가 zip 을 구성한 뒤의 상태를
> 뜻하는 것이라면 회신 바란다(§7-G).

### 5-5. 파생영상 취급 (증강 · 해상도 변경)

저작도구는 원본에서 **파생영상**을 생성하며, 각 파생본은 **독립된 `RAW_SN`** 을 갖고
검수를 거쳐 **별도의 완료 통지**로 나간다. `ORGNL_RAW_SN` 으로 부모를 참조한다.

| 파생 종류 | 내용 |
|---|---|
| 증강 | 외부 생성형 AI로 WINTER / NIGHT / RAIN 프레임 생성 |
| 해상도 변경 | 프레임 이미지를 표준 해상도 3종으로 리스케일 |

**★ 파생영상에는 원본 영상이 없다 — 비식별 영상만 있다.**
파생 비디오는 부모의 **비식별 영상을 복사**한 것이므로:

- `ORGNL_VDO_PATH_NM` = **NULL**
- 비디오 픽업은 **`DE_IDNTF_FILE_PATH_NM`** 으로 한다
- `RESL`·`FPS` 등 비디오 기술메타는 **부모와 동일**하다(비디오는 재인코딩하지 않고 복사하며,
  변환 대상은 프레임 이미지뿐). 해상도 파생의 목표 해상도는 비디오가 아니라 **프레임 이미지**에
  적용된다

### 5-6. 파일 경로 규약

| 대상 | 경로 출처 |
|---|---|
| 학습데이터 산출 폴더 | `OUTPUT_PATH_NM` (영상 루트) → 하위 `v{n}/` 버전 폴더 |
| 비식별 영상 | `DE_IDNTF_FILE_PATH_NM` **값 그대로** |
| 원본 영상 | `ORGNL_VDO_PATH_NM` (파생영상은 NULL) |

> ⚠ **비식별 영상 파일명은 고정이 아니다.** 외부 비식별 솔루션이 파일명을 정하므로
> 영상마다 다르다(예: `001.mp4` → `001-mask.mp4`). **경로를 조합·추측하지 말고
> `DE_IDNTF_FILE_PATH_NM` 값을 그대로 사용**해야 한다.

### 5-7. 비식별 누락 신고 구간 (`DE_IDNTF_YN='F'`)

작업자가 비식별 처리 누락을 발견해 신고하면 해당 영상은 재처리 대기 상태가 된다.

- **검수 완료·통지된 영상은 이 구간에도 뷰에서 사라지지 않는다.** 관제가 보던 행이
  예고 없이 없어지지 않도록 한 정책이다.
- 저작도구는 `DE_IDNTF_YN` 을 그대로 노출하므로 **관제가 필요하면 자체 판단**할 수 있다.
- 신고 접수 시 `notify-updated`, 해소 시 산출물 재생성 후 재통지가 나간다.

## 7. 확정 필요 항목

### A. 개인정보 3필드 — **비식별 기준으로 적재한다** *(저작도구 확정 · 통보)*

`dataset_versions.anony_incl_yn` / `psdo_incl_yn` / `prvc_incl_yn` 에는
뷰의 **비식별 기준 3컬럼**(`ANONY_INCL_YN` 등)을 넣으면 된다 — 학습데이터로 배포되는 것이
비식별 영상이기 때문이다.

**원천 영상 기준 값도 함께 제공**하므로(`SRC_*_INCL_YN`), 비식별 처리 전후를 대조하거나
관제 측에서 별도 용도로 쓸 수 있다. 상세는 §5-2.

> 관제 ERD 설명이 `PRVC01 익명` / `PRVC02 가명` / `PRVC03 원본` 으로 표기되어 있어,
> 만약 이 컬럼의 의도가 **"패키지에 어떤 산출 벌이 포함되는가"**(구성물 축)라면
> 위 값과 의미가 달라진다. **다른 기준이 필요하면 회신 바란다.**

### B. `datasets.name` · `description` — **기존 적재 형식을 따른다** *(저작도구 확정 · 통보)*

두 컬럼 모두 **NOT NULL** 이나 값 규격이 문서화되어 있지 않아, **기존 데이터셋의 적재 사례**
(`"교통사고 데이터셋 구축"`)를 참고해 아래로 확정했다.

| 컬럼 | 값 |
|---|---|
| `name` | `{이벤트명} 데이터셋 구축` |
| `description` | `{이벤트명} 데이터셋 구축` (동일 값) |

`{이벤트명}` 은 관제가 인입 시 전달한 `EVNT_NM` 이므로, **인입 항목 추가는 불필요**하다.
상세는 §5-3.

> 다른 명명 규칙이 있으면 회신 바란다.

### C. `curator_id` (uuid, NOT NULL)

ERD 정의는 **"최초 통지 user_id"** 로 저작도구 검수자를 가리키나, 저작도구 계정 축은
`USER_NO`(bigint) / `USER_ID`(varchar 20) 로 **UUID 를 보유하지 않는다.**

- **(a)** 관제가 자체 채움 / **(b)** 저작도구가 `user_id` 문자열 제공 후 관제가 매핑 /
  **(c)** 컬럼 타입 변경 — 중 선택 요청

### D. `dataset_versions.rprs_data_shp` 의 의미

논리명 `대표데이터형태` 외 설명이 없어 무엇을 담는지 파악하지 못했다.

- (a) 대표 이미지/썸네일 경로 / (b) 데이터 형상 설명 문장 / (c) 스키마·구조 정의 / (d) 그 외

### E. 수정 통지 `data_info` 의 키 스키마

`type: object` 로만 정의되어 있고 키 목록이 없다.

- (a) 키 이름이 DB 컬럼명(`data_etbl_nocs`·`data_etbl_cpct`)과 동일한가?
- (b) `data_etbl_yr` 도 포함되는가? (c) 그 밖의 키가 있는가?

### F. 관제 테이블 표준용어·도메인 정합

관제 `datasets` / `dataset_versions` 컬럼을 **사업표준단어(471)·사업표준도메인(45)·행안부
공통표준단어(3,284)·공통표준도메인(123) 정본 전량**과 대조한 결과 아래가 표준과 어긋난다.
정정 여부를 회신 바란다(저작도구는 어느 쪽이든 맞춘다).

| 컬럼 | 현행 | 표준 | 비고 |
|---|---|---|---|
| `datasets.evnt_type_cd` | varchar(**32**) | 도메인 **코드V20** | 인입 `EVNT_TYPE_CD` 는 20 이라 **양측 길이가 어긋난다** |
| `datasets.name` | 물리명 `name` | **`NM`** | `NAME` 은 사업·공통 양쪽 미등록. 같은 테이블군의 `dataset_versions.ver_expln` 은 이미 표준 약어를 쓰고 있다 |
| `datasets.description` | 물리명 `description` | **`EXPLN`** | `DESCRIPTION` 양쪽 미등록. 상동 |
| `datasets.job_id` | varchar(100) | 사업표준용어 `작업아이디` 도메인 **수I11** | 저작도구는 `RAW_SN`(bigint)을 보낸다. 표준(정수)을 따를지 현행 문자열을 유지할지 |
| `datasets.vdo_len` | integer | 사업표준용어 `영상길이` 도메인 **시분초C6** | 저작도구는 **초 단위 정수**를 보낸다. 현행 integer 가 의도라면 표준용어 도메인 쪽 정정이 필요하다 |
| `dataset_versions.data_etbl_yr` | varchar(100) | 사업표준용어 `데이터구축년도` 도메인 **내용V1000** | 연도인데 도메인이 `내용V1000` 으로 등록돼 있어 **등록값 자체가 부적합**해 보인다. §H 와 함께 회신 바란다 |

> `datasets.name` 의 **길이**는 별건이다 — 공통표준용어 `데이터셋명`(`DATST_NM`) 도메인은 `명V200`(200)인데
> 관제는 varchar(500)이다. 200 으로 맞출지 500 을 유지할지 함께 회신 바란다.

### G. `img_yn` / `vdo_yn` — **저작도구가 산출해 제공한다** *(저작도구 확정 · 통보)*

저작도구가 **산출물 실재 여부**로 판정해 뷰로 내보낸다(§5-4). 관제가 별도 계산할 필요 없다.

| 컬럼 | 산출식 |
|---|---|
| `IMG_YN` | 프레임 이미지·JSON 산출분이 있으면 `Y` |
| `VDO_YN` | 비식별 영상 파일이 있으면 `Y` |

> 다만 이 값이 **관제 패키징(zip 구성) 결과**를 뜻하는 것이라면 저작도구가 알 수 없는 영역이다.
> 그런 의미라면 회신 바란다.

### H. `data_etbl_*` 산정 기준

- `data_etbl_yr`(구축 연도) — **검수 완료 연도**가 맞는가? 형식(`2026` / `2026년`)?
  타입이 varchar(100)인 이유(다년도 표기 허용?)
- `data_etbl_nocs`(구축 건수) — **프레임 수**가 맞는가? `datasets.img_nocs` 와 중복되는데 의도인가?
- `data_etbl_cpct`(구축 용량) — **산출 폴더 총 바이트**가 맞는가?

### I. `dataset_versions.lbl_type` · `lbl_fmt` 의 값 규격

두 컬럼 모두 varchar(256)인데 **어떤 값을 기대하는지 규격이 없다.** 저작도구가 임의로 채우면
관제 쪽 해석과 어긋나므로 확정 바란다.

| 컬럼 | 저작도구 산출(안) | 확인 요청 |
|---|---|---|
| `lbl_type` | 영상에서 실제 쓰인 **라벨 형태의 집합**을 콤마로 — 예 `BBOX,POLYGON` | 복수 나열이 맞는가? 구분자는 콤마인가? 값 표기는 대문자 코드(`BBOX`·`POLYGON`·`SEGMENTATION`·`KEYPOINT`)로 맞는가? |
| `lbl_fmt` | 산출 JSON 의 **포맷명** — 예 `NIA-COCO-JSON` | 기대하는 표기가 있는가? 포맷 **버전**(현재 `1.3`)을 이 값에 포함해야 하는가? |

> 포맷 버전은 산출 JSON 의 `info.version` 에 이미 들어 있어 저작도구는 이 컬럼에 넣지 않았다.
> 관제가 컬럼 단독으로 버전을 판별해야 한다면 표기 규칙을 알려 주기 바란다.
