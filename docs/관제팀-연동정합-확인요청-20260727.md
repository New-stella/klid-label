# 저작도구 ↔ 관제지원 연동 정합 확인 요청

> 작성: 2026-07-27 | 저작도구 측 → 관제지원 측
> 근거: LogiCraft `KLID 2차 - 관제지원시스템 고도화` — `EXTSYS-006` / `INT-015~018` / `API-251`·`API-285` / `ADR-067` / `ERD-010`

## 배경

LogiCraft에 공유해 주신 관제지원 설계를 확인했습니다. **연동 규격은 저작도구가 관제 정의에 맞추는 방향**으로 진행하려 합니다.

현재 저작도구 구현과 관제 정의를 1:1 대조한 결과, 통지 경로·페이로드·인증이 서로 달라 **지금 상태로는 연동이 성립하지 않습니다.** 저작도구 쪽을 고치면 대부분 해소되나, 몇 가지는 관제 측 확인이 있어야 방향을 정할 수 있어 문의드립니다.

## B. 확인 부탁드립니다 (답변 전까지 저작도구 작업이 막힙니다)

### B-1. 관제 워커가 저작도구 산출물을 가져가는 방식 ★ — **✅ 답변 수신 (2026-07-27)**

> **관제 회신**: **영상 원본 경로 하위에 폴더를 구축해도 된다.** 원본 영상을 다른 용도로 쓰지 않으므로 충돌 없음.
>
> **저작도구 반영**: 산출 루트를 **`{원본 영상 디렉터리}/{rawSn}/`** 으로 확정합니다(아래 트리의 `{산출루트}` = 원본 영상이 있는 디렉터리). 원본 영상 파일은 그 바로 위 형제로 이미 존재하므로 **복사하지 않습니다.**
> 픽업 방식 (a)/(b) 는 아직 확정 회신을 못 받았으므로 **양쪽 다 성립**하도록 `EXPORT_PATH_NM`(폴더 경로) 과 **비식별 영상 경로 컬럼**을 뷰에 함께 제공하겠습니다. 아래 표는 참고용으로 남깁니다.

저작도구는 검수 승인 시 아래 구조로 산출물을 만듭니다. 파일의 **소유 주체가 3종으로 다릅니다.**

```
{산출루트}/{rawSn}/
    deid/{비식별영상파일}            ← 비식별 솔루션이 산출. 위치는 저작도구가 지정하나 파일명은 아래 참조
    v1/orgnl/frame-N.jpg | .json    ← 저작도구 산출 실파일
    v1/deid/frame-N.jpg  | .json    ← 저작도구 산출 실파일
    v2/...                          ← 재승인 시 버전 누적 (모든 버전 보존)
```

> ⚠ **비식별 영상 파일명은 고정이 아닙니다.** 저작도구가 지정하는 것은 **출력 디렉터리까지**이고, 파일명은 비식별 솔루션이 정합니다(예: 원본 `001.mp4` → `001-mask.mp4`). **파일명을 고정으로 가정하지 마시고**, 저작도구가 `V_COMPLETED_VIDEO` 에 추가 제공할 **비식별 영상 경로 컬럼**을 사용해 주십시오. 저작도구도 `LS_DEIDENT_PROC_LOG.DE_IDNTF_FILE_PATH_NM` 에 기록된 실제 경로를 그대로 씁니다.

- **원본 영상은 이 트리에 넣지 않을 예정**입니다. 원본은 관제 소유 자산이고, 경로는 이미 `V_COMPLETED_VIDEO.ORIGINAL_VIDEO_PATH` 로 제공하고 있습니다. 또한 비식별되지 않은 원본을 산출 폴더에 노출하지 않는 편이 개인정보 보호 관점에서 안전하다고 판단했습니다.
- **원본 영상도 이 폴더 안에 실파일로 있어야 한다면 알려주십시오.** 그 경우 복사가 필요하며 용량 정책(보존 기간·상한) 협의가 필요합니다.

**확인 요청**: 관제 워커가 어느 방식인지 알려주시면 그에 맞추겠습니다.

| 방식 | 저작도구 대응 |
|---|---|
| (a) 폴더 하나를 통째로 픽업 (rsync/cp 등) | 위 `{rawSn}` 루트 경로 1개를 `V_COMPLETED_VIDEO.EXPORT_PATH_NM` 으로 제공하겠습니다 |
| (b) DB에서 경로를 읽어 파일별 픽업 | 뷰에 **비식별 영상 경로 컬럼을 추가**해 드리겠습니다 (현재 어느 뷰에도 미노출 상태입니다) |
| (c) 원본 영상까지 폴더 안에 실파일 필요 | 복사 방식 + 용량 정책 협의 필요 |

### B-2. `INT-017`(저작도구 NAS 공유 마운트)이 현재도 유효한 설계인지

`ERD-010`(물리 ERD, v45) 에는 저작도구 NAS 경로를 담는 컬럼이 없어, 관제가 실제로 저작도구 NAS를 스캔하는 구조인지 확인이 필요합니다. 유효하다면 B-1 (a) 로 진행하면 됩니다.

### B-3. `INT-018`(저작도구 DB `LS_DATA_*` JDBC fetch)이 현재도 유효한지

`ERD-010` 전문에 `LS_` 참조가 **한 건도 없어** 확인 부탁드립니다.

- **유효하다면**: 저작도구가 읽기 전용 계정 + 조회 규격(테이블·컬럼 가이드)을 제공하겠습니다. 다만 사전에 공유드릴 사항이 있습니다.
  - 실제 테이블은 `LS_DATA_*` **15개**입니다 (`ADR-067` 의 "9테이블" 과 상이).
  - **비식별 영상 경로는 `LS_DATA_*` 가 아니라 `LS_DEIDENT_PROC_LOG.DE_IDNTF_FILE_PATH_NM`** 에 있습니다. (`ADR-067` 리스크 항목의 "비식별 영상 경로 필드 명확화 필요" 에 대한 답입니다.)
  - 관제가 조회하시는 `V_COMPLETED_VIDEO` 의 원천은 `LS_DATA_RAW` 가 아니라 `LS_DATASET_VIDEO_META` 입니다.
- **유효하지 않다면**: 통지 API + B-1 픽업만으로 정리되어 양측 모두 단순해집니다.

### B-4. 인증 — JWT 발급 주체

`x-access-token` 에 실을 JWT는 **관제서버가 발급한 토큰**을 사용하는 것으로 이해하고 있습니다. 저작도구는 자체 JWT 발급 기능이 없으며, 관제/포털이 발급한 토큰을 검증만 하는 구조입니다.

`ADR-027` 에 "저작도구 발급 access JWT (tokenType=authoring)" 로 기재되어 있어 확인 부탁드립니다. 실제 적용 일정은 이후 별도 협의드리겠습니다.

## C-7. 개인정보 제공 항목 고지 — 검수자 성명

저작도구가 제공하는 조회 API `GET /v1/tasks/{rawSn}/summary` 응답에 **검수자 성명(`reviewerName`)** 이 포함됩니다. 성명은 단독으로 개인정보에 해당하므로, 관제 측 개인정보 처리 항목에 반영이 필요한지 확인 부탁드립니다.

- 통지 페이로드(`notify-completed` / `notify-updated`)에는 **개인정보가 포함되지 않습니다** — 6필드 평면 구조(`job_id`·`event_type_cd`·`lclgv_cd`·`lclgv_nm`·`duration_sec`·`image_count`)와 변경 파일명 리스트뿐입니다.
- 성명이 실제로 필요하지 않으시면 내부 사용자 번호(`reviewerUserNo`)로 교체하거나 마스킹 제공이 가능합니다. 회신 주시면 반영하겠습니다.

## D. 저작도구 측 변경 예고

- **`V_COMPLETED_VIDEO.EXPORT_PATH_NM` 의 값이 바뀝니다.** 컬럼명·타입은 그대로이며 경로 문자열만 달라집니다. 이 값을 사용 중이시면 참고 부탁드립니다.
- 비식별 영상이 산출 트리 안(`{rawSn}/deid/`)으로 이동합니다. 기존 경로를 참조 중인 곳이 있으면 알려주십시오.

### D-3. ★ `V_COMPLETED_VIDEO.PRVC_TYPE_CD` / `PRVC_YN` 의 **노출값이 뒤집힙니다** (2026-07-31 추가 — 협의 요청)

- **무엇이 바뀌나**: 저작도구가 영상을 적재할 때 개인정보 처리 유형(`LS_DATA_RAW.PRVC_TYPE_CD`)의 **폴백 기본값을 `ANONY` → `PRVC` 로 변경**했습니다. `PRVC_YN` 은 이 값에서 파생되므로 함께 `N` → `Y` 로 바뀝니다. 데이터마트 적재용 뷰 `V_COMPLETED_VIDEO`(V138)가 두 값을 그대로 노출하므로, **관제 측이 보는 값이 뒤집힙니다.**
  | 뷰 컬럼 | 변경 전(신규 적재 기본) | 변경 후(신규 적재 기본) |
  |---|---|---|
  | `PRVC_TYPE_CD` | `ANONY` | **`PRVC`** |
  | `PRVC_YN` | `N` | **`Y`** |
- **왜 바꾸나**: 관제팀 확인 결과 **관제서버가 `MNG_CLIP_EVNT_LST.PRVC_TYPE_CD` 를 실제로 채워 보내지 않습니다**(컬럼은 ERD-024 에 있으나 데이터 없음). 값이 없는 원천영상을 `ANONY`(비식별 불요)로 보면 **마스킹 전 원본이 열리는 방향**으로 기울므로, 입력이 없으면 "개인정보가 있고 익명처리되지 않은 것"으로 보는 **fail-closed** 로 바꿨습니다. 관제가 값을 채워 보내면(`ANONY`/`PRVC`/`PSDO`) **그 값을 그대로 존중**합니다 — 폴백은 값이 없을 때만 적용됩니다.
- **적용 범위**: **신규 적재분부터**입니다. **기존 행은 백필하지 않습니다**(이미 관제로 통지·적재된 영상의 값을 소급해 뒤집지 않기 위함).
- **확인 부탁드립니다**: ① 관제 측에서 이 두 값을 분기 조건으로 쓰고 계신 곳이 있는지 ② 있다면 `PRVC` 기본값으로 동작에 문제가 없는지 ③ 관제가 `PRVC_TYPE_CD` 를 채워 보낼 계획이 있는지(있다면 폴백은 사실상 쓰이지 않게 됩니다).
- 참고: 저작도구의 학습데이터 산출 JSON(`video.privacy_included` 등)도 같은 원천을 씁니다. 원본(`orgnl`) 산출물은 "개인정보 있음", 비식별(`deid`) 산출물은 "없음"으로 나갑니다.

# E. 2026-08-05 추가 — 관제 공유 테이블(`MNG_*`) 전면 제거에 따른 협의 요청

## 전제 — 무엇이 달라졌는지 한 문단으로

저작도구가 관제 스키마를 조회하던 마지막 경로를 모두 제거했습니다(마이그레이션 `V165`·`V167`·`V168`·`V169`). 저작도구가 매핑·조회하던 `MNG_*` 9종이 전부 사라졌고, 백엔드 소스에 남은 `MNG_` 문자열은 주석뿐입니다(실행 참조 0건).

그 결과 **관제가 저작도구 DB의 수신 원장 `LS_DATA_INGEST` 에 직접 INSERT 하는 평면 1행이 유일한 입력**이 되었습니다. 예전에 저작도구가 관제 마스터를 조인해 채우던 값들(CCTV명·좌표·지자체명·파일형식·이벤트유형·이벤트 분류/카테고리)은, 이제 관제가 그 1행에 실어 보내지 않으면 **채워질 방법이 없습니다.** 아래는 그중 관제 측 조치가 필요하거나 값의 정의를 함께 정해야 하는 항목입니다.

> 참고: `docs/관제팀-공유테이블-변경금지-가이드.md` 는 `V165` 시점까지만 갱신되어 있어, 그 문서가 "보호 대상"으로 적어 둔 나머지 테이블도 지금은 저작도구가 참조하지 않습니다. 공유테이블 관련 최신 내용은 이 E 절이 정본입니다(E-8 참조).

## E-1. 이벤트유형코드 `EVNT_TYPE_CD` — 20자 상한, `EVNT_ID` 와 다른 값

**무엇이 바뀌었나.** `V166` 이 `LS_DATA_INGEST.EVNT_TYPE_CD VARCHAR(20)` 을 신설했고, `V167` 이 구 경로(`MNG_CLIP_EVNT_LST` 를 `EVNT_ID` 로 조인해 유형코드를 해석하던 과도기 폴백)를 제거했습니다. 지금 이벤트유형코드의 원천은 **인입 평면값 하나**입니다.

**길이는 20자입니다.** 저작도구가 이 코드를 담는 컬럼은 전부 표준도메인 코드V20(=`VARCHAR(20)`)으로 정렬되어 있습니다 — `LS_DATA_INGEST` · `LS_DATA_RAW` · `LS_EVNT_TYPE` · `LS_DATASET_VIDEO_META` · `LS_LABEL_PRESET` 등 전 테이블 실측 확인했습니다. 과거 32자였던 컬럼은 남아 있지 않습니다(정렬은 `V107` 에서 완료).

## E-8. 참고 — 공유테이블 스키마 보호 요청은 철회합니다

`V165` · `V167` · `V168` · `V169` 로 저작도구가 매핑·조회하던 `MNG_*` 9종이 모두 제거되었고, 백엔드 소스에 남은 `MNG_` 문자열은 전부 주석입니다(실행 참조 0건). 따라서 이전에 전달드린 `관제팀-공유테이블-변경금지-가이드.md` 의 요청 사항 — 컬럼 drop/rename/타입 변경 금지, 복합 PK 구조 보호, `MNG_RESOURCE_CCTV` 조인키 보호 — 은 **저작도구 때문에 지키실 필요가 없어졌습니다.**

사용자 마스터도 저작도구 소유 테이블(`LS_ACNT_USER`)로 이관되어(`V169`) 관제 계정 테이블을 읽지 않습니다. 사용자 표시 정보(아이디·이름)는 관제가 브라우저로 인계하는 값에서 역할 클레임 시점에 자동 등록됩니다.

## E 절 회신 요청

- **먼저 확인 부탁드리는 것**: **E-1**(20자 상한 · `EVNT_ID` 와 구분 · 코드 목록 공유)과 **E-6**(3필드에 명시적 `NULL` 금지). 이 둘은 값이 어긋나면 **영상 인입 자체가 실패**하거나 **학습데이터 산출물이 비는** 항목입니다.
- **송신 항목 추가만 필요한 것**: E-2(좌표·CCTV명) · E-4(대분류) · E-5(카테고리·유형명).
- **정의 확정만 주시면 저작도구가 맞추는 것**: E-3(지역명 입도).
- **관제 측 작업 없음**: E-7(뷰 스키마 무변경 — 영향 여부만 확인) · E-8(보호 요청 철회).
