## 1. v3.5 제1권 구조 (원문 확인)

- **3권 구성**: 제1권 품질관리 가이드(프레임워크·지표) / 제2권 데이터 구축 가이드 / 제3권 생성형AI 데이터 품질관리(v2.0).
- **생애주기 3단계**(p.23-24): **준비·계획 → 구축 → 운영·활용**. 산출물 흐름: 데이터셋 정의 → 원시데이터 → 원천데이터(정제) → **가공데이터**(라벨링) → 학습데이터셋.
- **품질검사 절차**(p.29-31): ①검사대상 정의 ②품질검사(준비성·완전성·유용성·적합성·정확성·유효성) ③결과분석 ④개선 ⑤품질통제 — 피드백 루프. **1-Cycle 자가점검**(샘플 1%→초기 10%→중간 30%→최종 100%) + **제3자 품질검증**.
- **v3.1→v3.5 용어 변경**(p.6-7): 라벨링데이터→**가공데이터**, 데이터 정확성→**가공데이터 정확성**, 통계적 다양성→**다양성**, 최종데이터 품질점검→**최종데이터 1-Cycle 자가점검**. 의미정확성에 **바운딩박스/3D모델링/분류 정확성** 신설 + IoU·MOTA·PCK·ROUGE·BLEU·EM 측정지표 추가.

## 2. 우리 저작도구의 실제 검수/품질 메커니즘 (코드 기준)

| 메커니즘 | 위치 | 동작 |
|---|---|---|
| **검수 상태머신** | `review/service/ReviewStateMachine` | PENDING→IN_REVIEW→APPROVED/REJECTED→(재제출)PENDING |
| **품질 충돌 검사** | `quality/service/QualityCheckService` + `common/util/QualityConflictDetector` | auto(GT) vs manual(DS) **IoU greedy 매칭** 후 4유형 분류 |
| 충돌 유형 | `common/util/ConflictType` | `MISSING`·`EXTRA`·`MISMATCHING_LABEL` = ERROR(export 차단), `LOW_OVERLAP` = WARNING |
| 임계값 | `QualityConflictDetector` | 매칭 하한 **IoU 0.4**, LOW_OVERLAP 경고 **IoU 0.8** (CVAT ComparisonParameters 유래 — 우리 자체 기준, NIA 규정 아님) |
| Export 게이트 | `QualityCheckResult.blocked` | ERROR 1건이라도 있으면 `blocked=true` |
| 검수 소통 | `review/service/IssueThreadService` | 검수자↔작업자 이슈 스레드 + REJECTION 이력 |
| 버전 확정 | `VersionService.commitApproved` | APPROVED 시 라벨 전체 스냅샷 |
| 비식별 품질 | `LS_DATA_RAW.DE_IDENT_YN`/`PRVC_YN` + `LS_DEIDENT_REPORT` | 개인정보 노출 발견 시 라벨삭제+재비식별 |
| 시계열 메타 검수 | `LS_DATA_META_REVIEW` | VLM 메타 승인/반려 |

> ⚠️ **핵심**: 우리 `QualityConflictDetector`는 **auto 라벨 vs manual 라벨 "충돌"을 탐지**(CVAT GT Job 포팅)한다. 이는 NIA "의미 정확성"이 요구하는 **참값(GT) 대비 Fβ/정밀도/재현율 정량 채점과 다르다.** 우리 IoU 0.4/0.8은 매칭·경고용 내부 파라미터일 뿐, NIA 지표 산출이 아니다.

## 4. 갭 & 조치 (원문 대조 후 재정의)

### 4-1. GT 대비 정량 정확도 지표(Fβ) 산출 부재 (P1, 최우선) 🔴
- **정정된 핵심 갭.** NIA "의미 정확성"은 bbox를 **Fβ(정밀도·재현율, 오류 4종 계수)**로 채점. 우리는 auto-vs-manual **충돌 나열**만 하고 **점수(%) 미산출**.
- 다행히 오류 4종이 우리 ConflictType과 **1:1 매핑**됨:
  | NIA 오류 | 우리 ConflictType |
  |---|---|
  | 분류오류 | MISMATCHING_LABEL |
  | 영역오류 | LOW_OVERLAP |
  | 객체누락 | MISSING |
  | 불필요객체 | EXTRA |
- **조치**: `QualityCheckResult`에 원문 산식대로 **정밀도·재현율·Fβ 집계** 추가(오류 4종 카운트는 이미 있음). p.127 산식 그대로 구현 → 검수 대시보드 정량 리포트화. **저비용·고효과**(카운트 재활용).

### 4-2. 구문 정확성 % 산출 (P1) 🔴
- 구조/형식 정확성 `정확도%=(전체속성−오류)/전체속성×100` 미산출.
- **조치**: 스키마 검증 결과를 카운트해 정확도% 리포트. 기준선 예시 99.5%.

### 4-3. 다양성(구성비 중첩률) + 형식성(파일 전수검사) (P2) 🔴🟡
- 다양성: 목표분포 대비 클래스·시간대·계절·이벤트 분포 **구성비 중첩률**(p.121) 미산출. **CCTV는 v3.5가 명시한 촬영기기 다양성 대상**(p.190).
- 형식성: 파일 유효성/해상도/프레임레이트 전수검사 없음.
- **조치**: 검수완료 집계 View 위에 분포 통계 + 파일 무결성 배치. SFR-16/17 달성추적과 연계.

### 4-4. 트래킹 정확도(MOTA) (P2) 🔴
- 영상 트래킹은 MOTA(목표 예시 90 이상). 우리는 `TRCK_ID`만, 정확도 미산출.
- **조치**: 트랙 보간 결과에 MOTA 계산(필요 시 GT 트랙 대비).

### 4-5. 1-Cycle 자가점검 단계별 샘플링 (P3) 🟡
- NIA는 샘플 1%→초기 10%→중간 30%→최종 100% 단계 검수. 우리는 전건 검수(개념 없음).
- **조치**: 대량 구축 시 단계별 샘플 검수 옵션 검토(현재 전건도 기준 충족은 함).

### 4-6. 정량 목표값은 "예시" — 사업 기준서로 확정 (운영) ⚪
- v3.5 정량목표는 전부 **"예시, 과제별 상이 적용 가능"**. 실제 컷은 **품질지표 기준서(제3자 검증기관 합의)**로 확정.
- **조치**: 본 사업 품질지표 기준서 확보 시 우리 검수 PASS 임계를 그 값으로 파라미터화(`LS_SYSTEM_CONFIG`).
