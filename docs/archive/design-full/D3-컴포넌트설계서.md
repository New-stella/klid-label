# D3 컴포넌트 설계서

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-UC/CO/DC/SD/SC/AC/EN/ERD/TB/II/IC/IF/UCD/ACT 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. 범위는 시작 ID만 전체형으로(예: `KLID-AT-UC-001~013`). ※ 요구사항(RQ-SFR-NN-NN)·시스템시험(KLID-ST-NNN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 설계 클래스 모형에서 도출한 클래스들을 C&V(공통성과 변경성) 기준에 따라 그룹핑하여 컴포넌트를 식별하여 패키지도를 작성하고 식별한 컴포넌트의 내부 클래스 및 인터페이스의 명세를 기술한다.

## 작성 방법
> 클래스를 그룹핑하여 도출한 컴포넌트의 패키지도를 작성하고, 식별한 컴포넌트의 목록을 작성한다. 또한 각각의 컴포넌트에 포함하고 있는 내부 클래스들을 명세하고, 인터페이스는 사용자에게 제공하는 오퍼레이션별로 상세한 명세를 작성한다.

> **컴포넌트 도출 원칙**: 컴포넌트는 유스케이스 실현 단위로 도출하며 **유스케이스 1건당 컴포넌트 1건(UC ↔ CO 1:1)** 이다. 활성 유스케이스 18건당 컴포넌트 1건을 식별하고, 컴포넌트 번호는 실현 유스케이스 번호와 정렬한다(예: KLID-AT-CO-003 ↔ KLID-AT-UC-003). 유스케이스 결번(KLID-AT-UC-012/014/015/017/020)에 맞춰 컴포넌트 번호도 결번 처리한다. 도메인 단위로 컴포넌트를 묶지 않는다. 공통 기반 요소는 별도 컴포넌트로 식별하지 않고, 이를 사용하는 컴포넌트의 내부 클래스로 **동일 설계 클래스 ID(KLID-AT-DC-NNN)** 를 교차 참조한다(중복 정의 금지).
>
> **내부 클래스 ID 일관성 (Critical)**: 본 산출물의 내부 클래스 ID(IC)는 **클래스설계서(D1)의 설계 클래스 ID(KLID-AT-DC-NNN)와 동일 체계**를 사용한다. 동일 클래스는 D1·D3·엔티티관계모형설계서(D8) 전반에서 같은 ID를 가지며, 컴포넌트별로 독자 번호를 부여하지 않는다.

## 1. 컴포넌트 구조도

> **⟳ 유스케이스별로 1개씩 반복 작성한다.** 다이어그램은 **시스템(해당 유스케이스 범위)을 구성하는 컴포넌트 박스(«component») 사이의 의존관계(dependency)** 를 계층(Biz Logic·Integration)으로 구분해 표시한다. 박스 = 컴포넌트, 점선 화살표 = 컴포넌트 간 의존이다. 액터·외부 시스템은 외부 박스로 표기한다. 컴포넌트의 **내부 클래스는 본 구조도에 분해해 그리지 않으며**, 「3. 컴포넌트 명세 → 내부 클래스 표」에 텍스트로 기재한다.

## 항목 설명

### 컴포넌트 구조도
> 유스케이스별로 작성한다.

- **컴포넌트 ID**: 컴포넌트별로 유일한 ID를 부여하여 기입한다.
- **컴포넌트명**: 컴포넌트 이름을 부여하여 기입한다.
- **관련 유스케이스 ID**: 본 산출물이 관련되는 "유스케이스 명세서"의 유스케이스 ID를 기입한다. (컴포넌트 ID와 1:1 — 유스케이스 1건당 컴포넌트 1건)

### 컴포넌트 목록
> 유스케이스별로 작성한다.

- **컴포넌트 ID**: 컴포넌트 ID를 기입한다.
- **컴포넌트명**: 컴포넌트 이름을 기입한다.
- **개요**: 컴포넌트에 대한 설명을 간략히 기입한다.
- **관련 유스케이스 ID**: 본 산출물이 관련되는 "유스케이스 명세서"의 유스케이스 ID를 기입한다. (컴포넌트 ID와 1:1 — 유스케이스 1건당 컴포넌트 1건)

### 컴포넌트 명세
> 컴포넌트별로 작성한다.

- **컴포넌트 ID / 컴포넌트명 / 컴포넌트 개요**: 컴포넌트 식별자·이름·설명을 기입한다.
- **내부 클래스 ID / 명 / 설명**: 컴포넌트에 속한 내부 클래스를 기입한다. 내부 클래스 ID는 설계 클래스 ID(D1)와 동일 체계로 일관성을 가진다.
- **인터페이스 클래스 ID / 인터페이스명 / 오퍼레이션명 / 구분**: 컴포넌트가 제공(Serviced)·요청(Required)하는 인터페이스와 오퍼레이션을 기입한다.

### 인터페이스 명세
> 인터페이스별로 오퍼레이션 개수만큼 작성한다.

- **인터페이스 ID / 인터페이스명 / 오퍼레이션명**: 인터페이스 식별자·이름·오퍼레이션명을 기입한다.
- **오퍼레이션 개요**: 오퍼레이션이 제공·요청하는 서비스의 기능 및 역할을 기술한다.
- **사전조건 / 사후조건**: 오퍼레이션 작동 전·후에 항상 참이어야 하는 조건을 기술한다.
- **파라미터 / 반환값**: 오퍼레이션의 파라미터와 반환값을 업무 의미 단위로 기술한다.
