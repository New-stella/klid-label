## 1. 작성 목적 / 2. 작성 방법 (PDF 원문)

### 작성 목적 (원문 그대로)
> 총괄시험 계획서와 통합시험 시나리오에 따라서 수행한 시험 결과를 기술한다.

### 작성 방법 (원문 그대로)
> 유스케이스별로 통합 시험 시나리오를 기술하고 시나리오에 대한 시험 케이스를 기술하며 시험 예상결과와 시험결과를 비교한다.

## 4. 항목 설명 (전 항목 — PDF 원문)

- **시험 시나리오**: 설계단계의 "통합시험 시나리오"의 시험 시나리오를 **현행화**하고, 통합시험을 수행한다.
- **시험 케이스**: 설계단계의 "통합시험 시나리오"의 시험 케이스를 **현행화**하여 시험을 수행 후, **시험결과를 기록**한다.

### 케이스 표 컬럼별 의미 (양식·사례 기준)
- **순번**: 절차 순서 번호 (1, 2, …)
- **업무처리내용**: 해당 순번의 처리 행위 (예: "실시간 자금결제 조회", "결제리스크 조회")
- **시험항목**: 시험 대상 항목 (예: "실시간 모니터링")
- **사전조건**: 시험 전 충족 조건 (예: "자금결제처리부 …")
- **입력자료**: 입력값. 사례에서 `[기래일자]`(거래일자), `[자금종류]`, `[금융기관] "1"`, `"9999"` 등 키-값 나열
- **예상결과**: 기대 동작 (예: "입력자료에 해당하는 목록이 디스플레이 …")
- **화면ID**: 연관 화면 식별자 (예: LL_UC_020)
- **시험결과**: 실제 수행 결과 — 예상결과와 비교 기재 (예: "예상결과와 동일(화면 별첨)")
- **비고**: 부가 기재

## 5. 작성 사례 요점 (실제 값/패턴)

PDF 작성 사례(POS/금융 도메인) 발췌:
- 시나리오 헤더: `시험시나리오 ID = LL_IT_TS_030`, `시험시나리오명 = 결제 조회`, `시험시나리오설명 = 자금결제내역을 조회한다.`, `관련 유스케이스ID = SS_UCD_010-01`.
- 케이스 목록: `LL_IT_TC_030 실시간조회`, `LL_IT_TC_040 수시조회`. 시험 절차는 "1. 실시간 자금결제 조회 / 2. 대기가래등록 조회 / 3. 일중당좌대출 조회 / 4. 마감시간대별 결제증감 조회".
- 케이스 표(1차, LL_IT_TS_030 / LL_IT_TC_030): 순번 1 = "실시간 자금결제 조회"(시험항목 "실시간 모니터링"), 순번 2 = "결제리스크 조회". 입력자료에 `[기래일자]`, `[자금종류]`, `[금융기관] "1"`, `"9999"` 등.
- **시험결과 기입 패턴**: "예상결과와 동일(화면 별첨)" — 즉 실측/증빙은 **화면 캡처를 별첨**으로 연결, 셀에는 판정 문구.
- 화면ID는 `LL_UC_020`처럼 유스케이스/화면 ID 기재.

## 6. 함정 / 주의

- **"시험 절차"는 단일 컬럼이 아니라 `순번`+`업무처리내용` 2개 하위 컬럼으로 split된 병합 헤더** — 표 작성 시 누락 주의.
- 시험 시나리오 표의 "시험 절차" 컬럼(번호 나열식)과 시험 케이스 표의 "시험 절차"(순번/업무처리내용 split)는 **다른 표·다른 구조**. 혼동 금지.
- 헤더박스 식별 코드는 **T1** (설계단계 D10과 다름). 단계명 = "시험".
- **현행화 사슬(Critical)**: T1은 **D10 통합시험 시나리오**(설계단계)의 시험 시나리오·케이스를 **현행화**하여 동일 ID를 유지한 채 **시험결과 컬럼만 채우는** 산출물이다. 시나리오/케이스를 새로 창작하지 않는다. 사슬: `D10(통합시험 시나리오, 설계) → 통합시험 수행 → T1(통합시험 결과서, 시험단계, 결과 현행화)`.
- 시험결과 셀에 실측 전체를 욱여넣기보다, 판정 문구 + "화면 별첨" 식으로 증빙을 별첨 연결하는 것이 사례 패턴.
- 관련 ID 컬럼이 양식상 "관련 유스케이스ID"이므로 T1 시나리오는 유스케이스 기준 추적이 원칙.

## 7. KLID 프로젝트 적용 메모

> 기존 KLID 적응(D10 현행화·ID 동일 유지·증빙 별첨) 보존 + 본 단계 추가.

### KLID 적응 보존
- **D10 현행화 산출물** — 시나리오·케이스 ID는 D10과 동일 유지, 결과만 추가. 증빙은 별첨으로 연결.
- 사슬: D10 통합시험 시나리오 → 통합시험 수행 → T1 결과 현행화.

### KLID 도메인 적용
- **관련 유스케이스ID**: 저작도구 유스케이스(UC-018 관제 학습용 적재, 마킹→배치 파이프라인, 라벨링, 검수 승인, 비식별 신고/resolve 등)를 기준으로 시나리오 단위 추적.
- **통합 시나리오 후보** (영상 1건 = 작업 단위):
  - 적재→선두 비식별→MARKING_READY 전이 (`VideoIngestedEvent → IngestDeidentifyBridge → AsyncDeidentifyRunner → DeidentifyStep`)
  - 마킹 완료→잔여 배치(VLM→프레임추출→YOLO→SAM2→보간) (`MarkingCompletedEvent → MarkingBatchBridge`)
  - 라벨 저장(임시저장, `LS_DATA_LBL` upsert) / 검수 승인(`ReviewService.approve` → `LS_LABEL_VERSION` 스냅샷 + `COMPLETED` 전이 + `TASK_COMPLETED` 통지)
  - 비식별 신고→락→라벨 삭제→resolve (WORKER/REVIEWER)
- **화면ID**: 저작도구 화면 ID(마킹/라벨링/검수/관리 `/manage/*`)를 기재.
- **증빙(별첨)**: konva 캔버스 라벨링 결과, 배치 상태 전이 로그, 통지 페이로드(PII·토큰·원본 비-비식별 이미지 미포함) 등을 별첨.
- **시험결과 판정 시 보안 가드 확인**: 비식별 미완료 시 스트리밍 NOT_FOUND(원본 노출 차단), 본인 배정 외 프레임 편집 403, mock SAM2 응답 FE 자동적용 차단 등 가드 동작을 시험결과에 명시.
