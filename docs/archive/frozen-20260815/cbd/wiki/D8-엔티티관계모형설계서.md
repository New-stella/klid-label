# D8 엔티티 관계 모형 설계서 (CBD 표준 산출물 위키)

> 출처: NIA CBD 가이드(2011.12) docs/CBD.pdf 인쇄면 p.83~88
> 대응: 타 방법론 "데이터모형설계서", 범정부 EA "DV4 논리데이터모델"

## 1. 작성 목적 / ## 2. 작성 방법 (PDF 원문)

### 1. 작성 목적 (원문)
시스템의 요구사항을 만족하기 위한 주요 엔티티 및 엔티티간의 관계를 표현하고 엔티티에 대한 명세를 기술한다.

### 2. 작성 방법 (원문)
**논리적 데이터 모델링**을 통한 엔티티 관계 모형도(ERD)를 작성하여 엔티티를 식별한다. 작성한 엔티티 관계 모형도와 **개념적 클래스도를 비교하여 볼 필요가 있다. ERD에서는 엔티티가 모두 속성을 가져야하나 개념 클래스는 속성이 없는 기능만을 가진 클래스가 존재할 수 있다.** 식별한 엔티티는 각각 상세한 명세를 작성한다.

## 4. 항목 설명 (원문 — 전 항목)

### 엔티티 관계도(ERD)
- **ERD ID**: ERD별로 유일한 ID를 부여하여 기입한다.
- **ERD 명**: ERD의 이름을 부여하여 기입한다.

### 엔티티 명세서
- **엔티티 ID**: 엔티티별로 유일한 ID를 부여하여 기입한다.
- **엔티티명**: 도출된 엔티티의 명칭을 기입한다.
- **엔티티 설명**: 엔티티에 대한 간단한 설명을 기술한다.
- **속성명**: 엔티티 속성의 내용과 특성을 인식할 수 있는 명칭을 기술한다.
- **동의어**: 동일한 의미로 사용되지만 하나의 용어로 표준화되지 못한 속성명을 기술한다.
- **타입**: 속성의 타입을 문자, 숫자, 날짜 등으로 기술한다.
- **길이**: 속성의 최대 허용 길이를 기술한다.
- **NOT NULL**: 필수항목 여부를 기술한다.
- **PK (Primary Key)**: 주키를 의미한다.
- **FK (Foreign Key)**: 외래키를 의미한다.
- **INX (Index)**: 인덱스를 의미한다.
- **기본값**: 속성의 기본값이 있는 경우에 그 값을 기재한다.
- **제약조건**: 속성의 특이한 제약조건이 있는 경우 기재한다.

> 참고: 위 양식 헤더박스는 "관련 클래스 ID / 관련 클래스명" 행을 포함하나, PDF 본문 항목 설명에는 해당 항목의 별도 정의 문단이 없다(양식 표에만 등장). 의미는 D1 설계 클래스와의 연계 식별자.

## 5. 작성 사례 요점 (실제 값/패턴 + 산출물코드)

- ERD: `ERD ID = JJ_ERD_040`, `ERD 명 = 거래중계` — OTP정보·핵심접속OTP정보·USIM정보 등 다수 엔티티 박스(속성 나열)와 관계선으로 구성된 다이어그램.
- 엔티티 명세 사례:
  - 엔티티 ID `JJ_EN_110`, 엔티티명 `기관거래`.
  - 관련 클래스 ID `JJ_DC_090`, 관련 클래스명 `기관거래`.
  - 엔티티 설명: 외부 기관과의 송수신되는 거래내역을 저장.
  - 속성:
    - `거래일자` | CHAR | 8 | NOT NULL Y | PK Y
    - `일련번호` | INTEGER | 8 | NOT NULL Y | PK Y
    - `기관코드` | CHAR | 4 | NOT NULL Y
- 코드 체계: ERD `JJ_ERD_NNN`, 엔티티 `JJ_EN_NNN`, 연계 클래스 `JJ_DC_NNN`.

## 6. 함정 / 주의

- **논리 모델 레벨** — 타입은 "문자/숫자/날짜" 수준 또는 논리 타입(CHAR/INTEGER 등 사례 표기)으로 기술. **물리 컬럼명·DBMS 물리 타입·테이블스페이스 등은 D9(물리 모델) 영역**이며 D8과 혼동 금지.
- **관련 클래스 ID/명은 헤더 필수 행** — D1 설계 클래스와 동일 식별 체계로 연계(엔티티↔클래스 추적). 임의 번호 부여 금지.
- 속성 표 10컬럼 전부 작성 — 동의어·INX 컬럼도 누락 없이 채움(해당 없으면 공란/N).
- 개념 클래스와 비교: 개념 클래스는 속성 없이 기능만 가진 것이 존재할 수 있으나, **ERD 엔티티는 모두 속성을 가져야 함**.

## 7. KLID 프로젝트 적용 메모

- **관련 클래스 ID/명**: D1 설계 클래스 ID(`KLID-AT-DC-NNN`)와 **동일 체계**로 매핑(독자 번호 부여 금지). D1 미정의 엔티티는 `- ※` + 사유 명시.
- **추적 사슬 유지**: 속성 표에 더해 KLID는 관련 유스케이스 ID 행을 둬 R1→R2→D1→D8→D9 추적 사슬을 잇는다.
- **코드 체계**: ERD `KLID-AT-ERD-NNN`, 엔티티 `KLID-AT-EN-NNN`(사례 `JJ_ERD/JJ_EN` 대응).
- **공유 스키마 처리**: 관제서버 재사용 MNG_* 테이블에 대응하는 엔티티는 진실원을 LogiCraft ERD-024(관제 공유 클립 ERD)에 두고, D8/D9 산출물 비대상으로 "공유(READ)" 비고 표기(`MNG_*` prefix 자동 제외 규칙). 저작도구 전용 LS_* 엔티티만 D8에 정식 등재.
- **논리/물리 분리**: D8은 논리 타입(문자/숫자/날짜), 물리 PostgreSQL 타입(VARCHAR/INTEGER/TIMESTAMP/BYTEA 등)은 D9에서 적응.
