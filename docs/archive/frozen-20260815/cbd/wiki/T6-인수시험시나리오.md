# T6 인수시험 시나리오 (CBD 표준 산출물 위키)

> 출처: docs/CBD.pdf 인쇄면 p.166~170 (§4.6 인수시험 시나리오). 산출물 코드 **T6**, 단계명=**시험**.

## 1. 작성 목적 (PDF 원문)

> 각 응용 프로그램의 단위 프로그램 내에서의 작업 흐름 연계, 단위 프로그램간의 상호 연동 및 대내외 인터페이스를 포함한 사용자 요구사항을 만족하는지를 **발주자가 최종 인수를 위하여 검증**한다.

핵심: 인수시험은 통합시험(D10/T1)을 넘어, **발주자(고객)가 최종 인수 의사결정을 내리기 위해** 사용자 요구사항 충족 여부를 검증하는 시험이다.

## 2. 작성 방법 (PDF 원문)

> **요구사항 ID를 기준으로** 시험시나리오와 시험케이스를 기술한다.

- 통합시험이 유스케이스(UC) 기준인 것과 달리, 인수시험은 **요구사항 ID 기준**으로 시나리오·케이스를 구성한다. (추적 기준이 다름)

## 4. 항목 설명 (PDF 원문 — 전 항목 누락 금지)

### ◼ 시험 시나리오
- **시험 시나리오 ID**: 시험 시나리오에 대한 유일한 ID를 부여하여 기입한다.
- **시험 시나리오명**: 시험 시나리오의 명칭을 기입한다.
- **시험 시나리오 설명**: 시험에 대한 간략한 설명을 기술한다.
- **관련 요구사항 ID**: 본 산출물이 관련되는 "사용자 요구사항 정의서"의 요구사항 ID를 기입한다.
- **시험 케이스 ID**: 시험 시나리오에 포함된 시험 케이스에 대한 식별자를 부여하여 기술한다.
- **시험 케이스 설명**: 시험 케이스의 간략한 설명을 기술한다.
- **시험 절차**: 시험 케이스별 시험을 수행하는 절차를 기술한다.
- **시나리오 설명**: 시험 절차의 각 단계별 실행 시나리오를 기술한다.
- **(시나리오 설명/비고)**: 기타 고려사항 등을 기술한다.

### ◼ 시험 케이스
- **차수**: 시험 시나리오별 시험을 수행한 횟수를 기술한다.
- **시험 시나리오 ID**: 인수 시험 시나리오 ID를 기입한다.
- **시험 케이스 ID**: 시험 케이스 ID를 기술한다.
- **순번**: 시험 케이스별 업무 처리의 순서번호를 기입한다.
- **업무처리 내용**: 시험 케이스별 업무처리 내용을 기술한다.
- **시험항목**: 시험 데이터 및 시험 수행내용을 기술한다.
- **사전조건**: 시험 수행 사전 조건을 기술한다.
- **입력자료**: 시험을 위해 입력하는 값을 기술한다.
- **예상결과**: 시험이 성공적으로 수행되었을 경우의 예상 결과를 기술한다.
- **화면 ID**: 시험을 수행하는 화면 ID를 기술한다.
- **시험결과**: 시험결과서로 활용될 경우 실제 시험을 수행한 결과를 기술한다.
- **비고**: 기타 참조할 만한 사항을 기술한다.

## 6. 함정 / 주의

- **추적 기준이 통합시험과 다름**: 통합시험 시나리오(D10/T1)는 유스케이스(UC) 기준이지만, 인수시험은 **요구사항 ID 기준**으로 시나리오를 묶는다. 사용자 요구사항 정의서의 전 요구사항이 인수시험으로 커버되는지 추적해야 한다.
- **시험팀·환경**: 인수시험은 **고객(발주자) + 프로젝트 시험팀**이 **계약서·합의된 (사용자 요구사항) 정의서를 기준으로 운영환경**에서 수행하는 시험이다. 단위/통합시험(개발팀·개발환경)과 시험 주체·환경·근거가 구분된다.
- **사슬**: T6 인수시험 시나리오 → 실제 수행 결과는 **T7 인수시험 결과서**로 현행화·기록된다(시험결과 컬럼 채움).
- "시험결과" 컬럼은 시나리오 단계에서는 비워두거나(시나리오 전용), 결과서로 활용 시 채운다(원문: "시험결과서로 활용될 경우 실제 시험을 수행한 결과를 기술").
- 표 컬럼명·하위 컬럼 구조(시험 절차 = 순번 + 업무처리내용)를 임의로 합치지 말 것.

## 7. KLID 프로젝트 적용 메모

- 인수시험은 **요구사항 ID 기준** 추적(발주자 인수 관점) — UC 기준의 D10/T1(통합시험)과 구분된다. 시험 주체는 고객(D6 시험계획 비교표 참조).
- **시험팀·근거·환경 사슬**: 인수시험 = 고객 + 프로젝트 시험팀이 계약서·합의된 사용자 요구사항 정의서를 기준으로 **운영환경**에서 수행. 결과는 T7로 현행화.
- KLID 관련 요구사항 ID는 R1 실존 `RQ-SFR-NN-NN`(기능 전수 커버) + 비기능 인수 항목은 `NFR-NNN`을 매핑한다.
- KLID 인수시험 케이스 코드 체계 권장: **`KLID-AT-T6-NNN`** (AT=Authoring Tool, T6=인수시험 시나리오). 시험 시나리오/케이스는 PDF 패턴(`_TS_`/`_TC_`)을 KLID 접두사로 치환해 운용 가능.
- 화면 ID는 KLID 화면 정의(SCR-*)와 연계, 입력자료/예상결과는 라벨링·검수·배치 도메인 실제 데이터 기준으로 기술한다.
