# D2 사용자 인터페이스 설계서 (CBD 표준 산출물 위키)

> 출처: NIA CBD 가이드(2011.12) docs/CBD.pdf 인쇄면 p.32~43 (설계 단계 2.2 사용자 인터페이스 설계서)

표준산출물 분류상 D2는 「사용자 인터페이스 설계서」이며, 다른 방법론의 "사용자화면정의서 / 화면설계서 / 메뉴구성도 / 인터페이스 상호작용 명세서"에 대응한다. UI 구조도(메뉴) → 화면·출력물 목록 → 화면 상세 설계로 구성된다.

---

## 1. 작성 목적 (PDF 원문)

> 시스템이 제공하는 사용자 인터페이스의 전체 구조와 메뉴 형식, 화면 목록과 화면의 상세 설계 내역을 기술한다.

---

## 2. 작성 방법 (PDF 원문)

> 전체 시스템에 대한 사용자 인터페이스의 구조를 사용자에게 제공하는 메뉴 형식으로 기술하고, 화면 및 출력으로 구분하여 목록을 작성하며, 화면의 상세 설계의 내용을 화면별로 기술한다.

### 3.1 사용자 인터페이스 구조도 (전체 시스템 1개)

큰 단일 표(또는 트리)로, 최상위레벨에서 Top-down으로 메뉴 계층을 표현한다. 사례 컬럼 구조:

| 컬럼명 | 의미 |
|--------|------|
| 업무 영역 (Level 1) | 최상위 메뉴(업무 영역) |
| Level 2 | 2단계 메뉴 |
| Level 3 | 3단계 메뉴 |
| Level 4 | 4단계(최하위/기능) 메뉴 |

→ 이 다이어그램(표)이 표현하는 것: 시스템 전체의 메뉴 형식 = 메뉴구성도. 시스템 규모가 크면 서브시스템으로 나누어 작성 가능.

| 관련 유스케이스 ID | "유스케이스 명세서"의 유스케이스 ID |

### 3.3 화면 상세 설계 (화면별 작성)

헤더박스 + 화면 이미지/와이어프레임 + 입출력 항목 표 + 처리 내용 + 기술적 고려사항.

헤더박스:

| 컬럼명 | (옆 칸) | 의미 |
|--------|---------|------|
| 화면ID | 화면명 | 관련 화면 ID / 명 |
| 관련 유스케이스 ID | (행 전체) | "유스케이스 명세서"의 유스케이스 ID |
| 관련 시퀀스도 ID | (행 전체) | "**클래스 설계서(D1)**"의 시퀀스도 ID |
| 화면유형 | 메뉴경로 | 입력/조회/갱신/삭제 등 / 메뉴 깊이 경로 |
| 화면개요 | (행 전체) | 화면의 목적 및 기능 간략 기술 |

화면 이미지(와이어프레임/캡처) 영역이 헤더박스 아래에 위치.

**입출력 항목** 표:

| 컬럼명 | 의미 |
|--------|------|
| 항목명 | 화면 입출력 항목을 식별할 수 있는 명칭 |
| 컨트롤명 | 화면을 구현하는 컨트롤의 명칭 |
| 타입 및 길이 | 항목의 데이터 타입과 최대 길이 |
| 속성 | I/O/RO/E/H 중 두문자(앞글자) |
| Validation Check | 항목의 입력 오류를 체크할 수 있는 입력 범위 |

표 하단 범례(원문): `*속성 I:Input, O:output, R:ReadOnly E:Editable H:Hidden`

**처리 내용**: 화면이 처리하는 업무 내용 + 관련 시퀀스도 ID 기재.
**기술적 고려사항**: 화면 구현에 필요한 기술적 요소 고려사항.

## 4. 항목 설명 (전 항목 — PDF 원문)

### ■ 사용자 인터페이스 구조도
- 전체 시스템에 대하여 한 개를 작성한다. **최상위레벨에서 Top-down으로** 작성되며, 시스템의 규모가 큰 경우 서브시스템으로 나누어 작성할 수 있다.

### ■ 사용자 인터페이스 목록
- **화면 ID**: 화면별로 유일한 ID를 부여하여 기입한다.
- **화면명**: 화면을 식별할 수 있는 명칭을 기입한다.
- **관련 유스케이스 ID**: 본 산출물이 관련되는 "유스케이스 명세서"의 유스케이스 ID를 기입한다.
- **출력물 ID**: 출력물이 있을 경우 출력물별로 유일한 ID를 부여하여 기입한다.
- **출력물명**: 출력물을 식별할 수 있는 명칭을 기입한다.

### ■ 화면상세설계
- **화면 ID**: 관련된 화면ID를 기입한다.
- **화면명**: 관련된 화면명을 기입한다.
- **관련 유스케이스 ID**: 본 산출물이 관련되는 "유스케이스 명세서"의 유스케이스 ID를 기입한다.
- **관련 시퀀스도 ID**: 본 산출물이 관련되는 "클래스 설계서"의 시퀀스도 ID를 기입한다.
- **화면유형**: 화면 데이터 처리 방식에 따라 입력, 조회, 갱신, 삭제 등으로 표시한다.
- **메뉴 경로**: 메뉴 경로 파악을 위하여 메뉴의 깊이를 표시한다.
- **화면 개요**: 화면의 목적 및 기능에 대하여 간략하게 기술한다.
- **항목명**: 화면의 입출력 항목을 식별할 수 있는 명칭을 기입한다.
- **컨트롤명**: 화면을 구현하는 컨트롤의 명칭을 기술한다.
- **타입 및 길이**: 항목의 데이터 타입과 최대 길이를 기술한다.
- **속성**: 항목의 속성을 Input(I), Output(O), ReadOnly(RO), Editable(E), Hidden(H) 중 선택하여 **두문만(앞글자)을 기술**한다.
- **Validation Check**: 항목의 입력 오류를 체크할 수 있는 입력 범위를 기술한다.
- **처리 내용**: 화면이 처리하는 업무 내용을 기술하며, 관련 시퀀스도 ID를 기재한다.
- **기술적 고려사항**: 화면을 구현하기 위하여 필요한 기술적 요소에 대한 고려사항을 기술한다.

## 5. 작성 사례 요점 (PDF 원문 값 + 산출물코드)

PDF 사례는 자금이체 시스템(서브시스템 SS) 원화자금이체신청 기준.

- **UI 구조도**: 업무 영역(Level 1) "총액 결제시스템/혼합형 결제시스템" → Level 2 "실시간 시스템/수시결제 시스템/여신 시스템" → Level 3 "실시간 조회내역/실시간 처리/차액 처리/집중 처리" → Level 4 "실시간 부채, 모니터링 클라이언트에 데이터 Push, 실시간자금결제내역조회, 차액결제자료처리 …" 메뉴 트리 표.

- **화면 목록(SC)**:

  | 화면 ID | 화면명 | 관련 유스케이스 ID |
  |---|---|---|
  | SS_SC_010-01 | 원화자금이체신청 | SS_UCD_010-01 |
  | SS_SC_010-02 | 원화자금이체신청 현단말기에서 승인 | SS_UCD_010-01 |
  | SS_SC_010-03 | 원화자금이체신청책임자 단말기에서 승인 | SS_UCD_010-01 |
  | SS_SC_010-04 | 원화자금이체신청 처리결과 | SS_UCD_010-01 |

- **출력물 목록(PR)**:

  | 출력물 ID | 출력물명 | 관련 유스케이스 ID |
  |---|---|---|
  | SS_PR_010-01 | 원화자금이체신청 처리결과 인쇄 | SS_UCD_010-01 |
  | SS_PR_010-01 | 수취인지정자금이체신청 처리결과 인쇄 | SS_UCD_010-01 |

- **화면 상세 설계**: 헤더 `화면ID SS_SC_010-01 / 화면명 원화자금이체신청 / 관련 UC SS_UCD_010-01 / 관련 시퀀스도 ID SS_SD_010-01 / 화면유형 입력 / 메뉴경로 "수신/총액결제/원화자금이체/원화자금이체신청" / 화면개요 "망 참가기관이 개설된 당좌예금계좌를 통한 자금거래 결제를 처리하는 화면"`.
  - 입출력 항목 예: `거래일자 | sTrDate | Char(8) | I/R | 필수항목, 입력불가`, `신청기관 | sAskCorpAcc | Char(4) | I/E | 필수항목`, `계정개설처 | nt | … | … | …`, `순번 | sIndex | Number(5) | O/R | …`, `책임자 | sAuthUserNo | Char(8) | IO/E | 필수항목`.
  - 처리 내용: 이벤트별 흐름 — "화면시작 / 추가 / 그리드선택 / 책임자 단말기에서 승인 / **현단말기에서 승인(SS_SD_010-01)**" 처럼 **시퀀스도 ID 인용**.
  - 기술적 고려사항: "Database 상황은 xxx Database를 모니터링할 경우이다 … Session수(Lock 모니터링 제외)" 등 환경 의존 요소.

**산출물코드 체계(사례)**: SC=화면(`SS_SC_NNN-NN`), PR=출력물(`SS_PR_NNN-NN`), 관련 UC=`SS_UCD_NNN`, 관련 SD=`SS_SD_NNN`(D1 시퀀스도 ID).

## 6. 함정 / 주의

- **관련 시퀀스도 ID는 필수 헤더 행** + **처리 내용에도 시퀀스도 ID 인용** — 두 곳 모두 채워야 D1(클래스 설계서)과의 추적성이 끊기지 않는다(비워두기 금지).
- **속성 코드는 두문자만**: I/O/RO/E/H. 복합 표기 가능(사례: `I/R`, `I/E`, `O/R`, `IO/E`). 표 하단 범례를 반드시 명시.
- **구조도는 전체 시스템 1개**(화면 상세처럼 반복 작성하지 않음). 단, 규모 크면 서브시스템 단위 분할 가능.
- **출력물은 "있을 경우"만** — 출력물 없는 화면은 2.2 비워둠. 사례처럼 동일 ID 중복 기재 오류 주의(SS_PR_010-01 2회 등장은 원문 사례의 채번 오류 양상 — 실제 작성 시 유일 ID 유지).
- 화면유형은 입력/조회/갱신/삭제 등 데이터 처리 방식 기준으로 표기.
- **'타입 및 길이' 칸 = 실제 DB/SQL 코드형 타입(+길이)** — `VARCHAR(n)`·`INT`·`BIGINT`·`NUMERIC(p,s)`·`BOOLEAN`·`DATE`·`TIMESTAMP`, 구조형(목록/객체/통계)=`JSONB`(PDF 예제 `Char(8)`/`Number(5)` 양식). ❌ 한글 추상라벨(`코드`/`목록`/`통계·분포`/`키-값`)·서술괄호(`(목록 선택)`·`(백분율)`) 금지 → 값-도메인은 Validation(허용값)에, 구조 설명은 비고로.
- **Validation Check 칸 = 입력 검증 범위만**(필수/길이/범위/허용값). ❌ 동작 서술·출력물ID(`KLID-AT-OUT-*`)·상태 서술 금지 — 그런 내용은 처리 내용으로.

## 7. KLID 프로젝트 적용 메모

- **ID 체계**: 본 프로젝트 산출물 ID는 `KLID-AT-XX-NNN` 체계. 화면은 `KLID-AT-SC-NNN`, 출력물은 `KLID-AT-PR-NNN`로 채번한다.
- **관리 화면 URL은 `/manage/*`** — 메뉴경로/구조도는 실제 라우트 기준으로 Top-down 작성한다.
- **R1 UC 매핑 화면만 수록**: 화면 목록은 R1 요구사항 유스케이스에 매핑되는 화면만 등재한다.
- **관련 시퀀스도 ID 필수**: D1(클래스 설계서)의 `KLID-AT-SD-NNN`을 헤더 + 처리 내용 양쪽에 기재(KLID D2 작성 품질 규칙).
- **속성 코드 표기**: I/O/RO/E/H 약어, 복합 표기 허용(`I/R`, `IO/E` 등).
- **KLID 주요 화면 예**: 마킹 화면(비식별 영상 스트리밍 + 배속 + 단축키), 라벨링 캔버스(konva.js — BBox/Polygon/SAM2 분할·Track), 검수 화면(REVIEWER 승인/반려), 작업 배정 화면, 시스템 설정 화면, 포털 라벨 Load 화면. 각 화면유형(입력/조회/갱신/삭제)과 메뉴경로를 정확히 매핑한다.
- **접근성·반응형**: 포털 화면은 반응형 웹(PC/태블릿/모바일) + WCAG 2.1 AA를 기술적 고려사항에 기재한다.
