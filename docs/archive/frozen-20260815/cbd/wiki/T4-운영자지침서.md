# T4 운영자 지침서 (CBD 표준 산출물 위키)

> 출처: docs/CBD.pdf 인쇄면 p.153~159 (§III.4.4 운영자 지침서). 헤더박스 단계명=시험.

## 1. 작성 목적

(PDF 원문 그대로)

> 개발한 시스템을 운영자가 효과적으로 관리와 운영을 할 수 있도록 시스템 관리 및 운영에 대한 지침을 기술한다.

## 2. 작성 방법

(PDF 원문 그대로)

> 개발 시스템의 관리 및 운영 측면에서 시스템의 지속적인 관리가 가능하도록 상세하게 작성하며 이해하기 쉽고 구체적인 언어표현을 사용한다. 운영자지침서의 경우 시스템의 특성에 따라 기술하는 항목이 차이가 많이 발생할 수 있으므로 내용이 빠지지 않도록 관련항목을 수정하여 사용한다.

## 4. 항목 설명 (PDF 원문 전 항목 — 누락 금지)

- **개요**: 시스템의 운영자 측면의 전체적인 개요를 기술한다.
- **시스템 설치**: 하드웨어, 소프트웨어, 네트워크를 포함한 시스템의 구성, 시스템 설치 절차 등의 내용을 화면 캡처를 이용하여 운영자가 쉽게 사용할 수 있도록 기술한다.
- **시스템 운용**: 자료 관리, 백업 관리, 장애 내역 및 복구 절차 등의 내용을 화면 캡처를 이용하여 운영자가 쉽게 사용할 수 있도록 기술한다.
- **사용 지침**: 시작 및 종료 방법과 공통적인 내용을 화면 캡처를 이용하여 운영자가 쉽게 사용할 수 있도록 기술한다.
- **기능별 사용법**: 기능 이름, 기능 설명, 주의 사항, 오류 메시지 및 해결 방법 등을 빠짐없이 완전하고 일관된 언어표현으로 화면 캡처를 이용하여 이해하기 쉽게 기술한다.
- **부록**: 기타 필요사항 등을 제공한다.

## 5. 작성 사례 요점 (PDF 실제 값/패턴)

PDF 사례는 "상황보고 저작기"(CBD 방법으로 개발된 웹기반 시스템) 운영자 지침서다.

- **1. 개요**: "수동으로 작성하는 방식의 상황도를 자동화하여 정확하고 빠른 지휘관의 판단결심을 제공하는 상황보고 저작기를 … 운용……"
- **2.1.1 시스템 구성도**: `클라이언트(WebBrowser) ―HTTP→ 상황도 서버(IIS) ―TCP/IP→ 데이터베이스 서버(DBMS)` 노드 다이어그램.
- **2.1.2 하드웨어 구성 표** — `구분 | 사양`:
  - 클라이언트: PC Pentium 3 / CPU 700MHZ 이상 / RAM 512M 이상 / HDD 30GB
  - Web Server + 어플리케이션 서버: CPU 2*700/100MHZ / RAM 1GB
  - 데이터베이스 서버: CPU 2*700/100MHZ / RAM 1GB
- **2.1.3 소프트웨어 구성 표** — `구분 | 설치 프로그램`: 클라이언트(OS 2000 Professional + .NET FrameWork), Web/App 서버(2000Server + .FrameWork), DB 서버(2000Server + DBMS 2000).
- **2.1.4 네트워크 구성**: LAN 기반 서버-단말 통신, 스위칭허브로 병목 해소·대역폭 유지(단말당 10Mbps 고정 대역폭, 포트-단말 1:1 연결).
- **2.2 시스템 설치 절차**: `1) .FRAMEWORK 설치` → ① 실행파일 클릭, ② "설치하겠습니까?" 메시지에 【예】 클릭.
- **3.1 자료 관리**: 주기적 서버 하드디스크 예비용량 점검, 백업(DB + 파일 백업), 파일 백업은 원본 영향 없이 복제 저장, 과도한 복사본 유지 지양.
- **3.2 백업 관리**: 백업 주기(일주일 1회 DB 백업, 로그는 날마다), 파일 백업 방법(윈도우 탐색기로 상황도/투명도/브리핑 FILE 디렉토리 검색 → 압축하기).
- **3.3 장애 내역 및 복구 절차**: 1) Server O/S·DB 오류 → 업체 유지보수, 2) 개별 PC 네트워크 오류 → 케이블 훼손/LAN 카드 연결 확인·교체·허브(Hub) 연결상태 확인.
- **4.1 시작 및 종료 방법**: ① 서버컴퓨터 파일 중 `StartRemote.exe` 클릭, ② …. **4.2 공통 사항**: 해당사항 없음.
- **5.1 사용자 계정관리** (기능별 사용법 사례):
  - 5.1.1 기능 설명: 사용자 추가/수정/삭제. ① 조회(미입력 시 전체 조회), ② 수정("수정을 하시겠습니까?" 확인).
  - 5.1.2 주의 사항: 해당사항 없음.
  - 5.1.3 오류 메시지 및 해결 방법 표 — `오류 메시지 | 원인 | 처리 방법`: "ID가 중복되었습니다." / 서버 DB의 ID와 입력 ID 동일 / 등록 아이디 변경 또는 시스템 관리자에게 문의.

## 6. 함정 / 주의

- **T3 사용자지침서와 구조가 매우 유사**하나, T4는 **2.시스템 설치 + 3.시스템 운용(자료/백업/장애복구)** 섹션이 추가된 *운영자 관점*이다. 두 산출물을 같은 내용으로 복붙하지 말 것.
- 항목 설명 모두 "화면 캡처를 이용하여" 기술하라고 명시 — 운영 절차는 스크린샷 동반 권장.
- 작성 방법에 "시스템 특성에 따라 항목 차이 큼 → 관련항목 수정 사용" 명시. 목차는 고정이 아니라 시스템 맞춤 가감 가능.
- 백업/장애복구는 사례 수준이 얕다("……" 다수). 제출본에서는 실제 운영 절차로 구체화 필요.
- 사례 헤더박스에 `프로젝트명 / 개발 시스템명` 행이 추가됨 — 빈 양식과 다르니 실제 제출 양식 확인 필요.

## 7. KLID 프로젝트 적용 메모

- **개요(§1)**: 본 도구는 독립 시스템이 아니라 관제서버(내부)/포털(외부) 토큰을 인계받아 동작하는 학습데이터 저작도구임을 운영자 관점에서 기술. 독립 로그인 UI 없음(JWT 인계).
- **시스템 구성도(§2.1.1)**: `FE(React/Vite) ―HTTP→ BE(Spring Boot) ―WebClient→ ai-server(FastAPI, YOLO/SAM2/VLM)` + `BE ―JDBC→ PostgreSQL(klid_at)` + 외부 연동(비식별 서버, 관제서버 outbound 통지, 포털 DB). 듀얼 데이터소스(Control/Portal EntityManager).
- **하드웨어/소프트웨어 구성(§2.1.2~3)**: ai-server는 GPU Worker(YOLO/SAM2 추론) 필요 — GPU 사양 명시. BE는 Java 17 + Spring Boot 3.3, Quartz PostgreSQL JobStore. **단일 인스턴스 서비스 배포(Docker/Pod 미사용, Quartz 클러스터 미적용)**, ai-server만 다중 인스턴스 수평 확장.
- **시스템 설치 절차(§2.2)**: Flyway 마이그레이션(LS_* 자체 관리 / MNG_* 공유는 validate), 환경변수 주입(`SPRING_PROFILES_ACTIVE`, `CONTROL_DB_*`, `PORTAL_DB_*`, `JWT_SECRET`, `AI_SERVER_URL`, `STORAGE_*` 등) 절차 반영.
- **시스템 운용(§3)**: 자료 관리=영상 원본/비식별본 별도 경로 저장·암호화, 배치 파이프라인(비식별→마킹→VLM→프레임추출→YOLO/SAM2→보간) 모니터링. 백업 관리=DB 스냅샷(LS_LABEL_VERSION) + 영상 파일. 장애 복구=배치 실패 재처리 정책(최대 재시도/실패 알림), 비식별 실패(`DE_IDENT_YN='F'`) 수동 재비식별 절차, 외부 API 서킷브레이커(Resilience4j) 상태 점검. Micrometer/Prometheus 메트릭·Actuator health 운영 포인트.
- **기능별 사용법(§5)**: 관리 화면(`/manage/*`, REVIEWER 권한) — 작업 배정/재배정, 시스템 설정(TTL 캐시), 검수 워크플로우 운영 항목.
- ⚠ **보안(security.md)**: 운영 절차/스크린샷에 JWT·DB 비밀번호·개인정보 노출 금지. 로그 마스킹(Logback MaskingPatternLayout) 운영 가이드 포함. 환경변수는 키만 기재, 값(시크릿)은 미기재.
- KLID 산출물 ID 컨벤션: **KLID-AT-T4-NNN** 형식으로 운영자 지침서 항목 식별.
