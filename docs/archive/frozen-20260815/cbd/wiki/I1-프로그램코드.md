> 출처: docs/CBD.pdf 인쇄면 p.127~129 (구현단계 3.1 프로그램 코드). 단계명=구현.

## 1. 작성 목적 (PDF 원문)

설계 명세서에서 기술한 프로그램 코드에 대한 물리적인 형상과 코드 관리를 위한 명세를 기술한다.

## 2. 작성 방법 (PDF 원문)

프로그램 코드의 프로그램 목록을 기술한다.

## 4. 항목 설명 (PDF 원문 — 전 항목)

프로그램 목록:

- **서브시스템명**: 본 프로그램파일이 관련되는 서브시스템명을 기입한다.
- **프로그램파일 ID**: 프로그램 파일의 ID를 부여하여 기입한다.
- **프로그램파일명**: 프로그램 파일 명칭을 기입한다.
- **비고**: 기타 참조할 만한 사항을 기술한다.

> PDF에는 위 4개 항목 외 별도 항목 설명 없음 (소스코드는 항목 설명 대상 아님 — 제출물).

- 2. 프로그램 소스코드는 "(소스코드 제출)"로 갈음.

## 6. 함정 / 주의

- "프로그램파일" 상위 헤더 아래 ID·파일명 2컬럼 구조를 단일 컬럼으로 축약하지 말 것.
- 소스코드 본문을 산출물 표에 붙여넣지 않음 — 형상/목록 명세 + 소스 별도 제출이 표준.
- ID는 설계단계 산출물(설계 명세서·DP 등)의 식별자와 일관되게 부여 — 추적성 단절 주의.
- 단계명은 "구현" 고정.

## 7. KLID 프로젝트 적용 메모

- KLID는 모노레포(`backend/` Spring Boot + `ai-server/` FastAPI + `frontend/` React)이므로 서브시스템명을 backend/ai-server/frontend 또는 도메인(label·marking·review·deident 등)으로 구분해 목록화한다.
- 실제 소스는 git 저장소 제출로 §2(소스코드 제출)를 갈음. 목록은 배포/모듈 단위로 간결하게 기재.
- 프로그램파일 ID는 KLID 추적 코드 체계(`KLID-AT-XX-NNN`)와 정합되게 부여하고, R3 추적표의 "파일 ID"가 본 산출물 ID를 인용하도록 연결.
- 파일별 정보 부족 항목(승인자 등)은 비워두고 보완 필요로 표시.
