## 1. 작성 목적 (PDF 원문)

> 초기 데이터 구축 시 단시일에 대량의 데이터를 이행함에 있어 신속하고 안정적인 데이터 이행을 위하여 체계적인 절차를 수립하여 구축 시 발생할 문제점을 사전에 차단하기 위한 계획을 수립한다.

## 2. 작성 방법 (PDF 원문)

> 업무그룹별 전환계획이 필요한 경우와 전체 미니프로젝트를 통합하여 전환하는 경우를 구분하여 계획을 수립한다. 업무그룹별로 전환하는 경우에는 전체적인 전환 완전성을 검증한다.

## 5. 작성 사례 요점 (PDF 사례 p.108~126의 실제 값/패턴)

사례 시스템: **OO물류 통합정보 시스템** (현행 C/S·1단계 시스템 → 신 통합정보시스템 전환).

### 5.1 개요 (p.108~109)
- **1.1 목적**: "기존 현행 시스템(C/S, 1단계 시스템) 자료를 취합·선정하여 정확한 형태·내용으로 재구성하며 일정 및 전환 절차에 따라 새로운 업무 수행 체계로 전환."
- **1.2 범위**: 현행 OO물류시스템 자료를 원래 상태 그대로(순수데이터) 혹은 가공을 통해 가져오는 자료 포함.
- **1.3 참조문서**: 현시스템현황(환경구성도·응용시스템 H/W·N/W 구성도·모형도·운영환경·장비사양 / 현행시스템 DB목록·TABLE목록·TABLE명세서·코드집) + 신시스템현황(신 시스템 환경구성·소프트웨어 구성도 / 신규테이블목록·테이블 매핑내역서·데이터 매핑내역서 / 신 시스템 코드집).

### 5.2 중점 목표와 구축 전략 (p.109~110)
- **중점 목표**: "현재 운용되고 있는 C/S 시스템을 대체하여, 1단계 시스템에 업무 중단 없이 완벽·신속하게 데이터를 전환."
- **구축 전략**: ① 데이터전환 협의체제 운영(모델러·DBA·유지보수팀 협의체) ② 자료정비 및 절차 표준화(정비대상 선정·과거자료 사전구축·전환 자동화) ③ 철저한 사전모의 시험(전환프로그램/시험환경 별도 구축, 전환 시나리오 개발, 반복 시험으로 절차 최적화).
- **구축 방법**: 전산관리소·지방국 산재 데이터를 각 서버에서 전환 후 압축·전송하여 신시스템 업무통합 DB에 로드.

### 5.3 전환 조직 및 역할 (p.110, 표 ②)
- 구분: **사업추진단 / 프로젝트 관리자 / 전환부문 / 기반기술부문(DBA 포함) / 응용시스템 부문**. 각 구분별 책임·역할을 불릿으로 기술 (예: 사업추진단 = 초기데이터 구축 범위 결정·데이터 파일화·사전 자료정비·구축데이터 검증·비상사태 시 업무협조 요청).

### 5.4 전환 작업 수행 타스크 (p.111~112, 표 ③)
- 단계: **분석단계 → 설계단계 → 구현시험 → 전개단계**. 각 작업에 시작/종료일(예: 전환계획수립 03-06-23~03-07-12)과 산출물(현행시스템 상세현황·DB목록·TABLE명세서/목록·코드집, 신규테이블 목록, 테이블·데이터 매핑 내역서, 신규/누락 항목 명세서, 전환 프로그램 목록/명세서, 전환 절차서, 데이터 전환 지침서, 최종 이행 결과서·전환 완료 확인서).

### 5.5 전환 상세 데이터 (p.112~114)
- 전환대상은 **코드성 데이터 + 가공 데이터 + 신규 생성 데이터**. 주로 RDB 형태 전산관리소(HOST)의 실사용 디스크 데이터, **백업 보관분은 전환 제외**.
- 신규시스템 기준 집계 예: 판매관리 테이블 총수 25 (전환팀 14 / 응용팀 11, 초기구축 25 / OPEN후 0, 코드성 11 / 통계성 4 / 기타 10).
- 구 시스템 테이블 ID 예: phts2015(주문정보)~phts2065(접수국입금미처리정보). 신규 테이블 ID 예: PBSAT0010(BSM_판매관리접수)~PBSCT0140.

### 5.6 데이터 매핑 내역서 (p.118, 표 ⑭ — 핵심)
- 산출물 형태 예: 업무시스템=통합접수 / 테이블ID=PRCTT0020 / 테이블명=고객정보.
- 본문 행 예:
  - 신시스템 `고객번호 VAR2(10)` → 현행 (없음) → 전환내용 **구분=신규, 전환기준="용국기호 + 일련번호로 신규생성"**.
  - 신시스템 `고객명 VAR2(04)` → 현행 `POTTPIJE / 인가자정보 / 승인자명 / VAR2(10)` → 전환내용 **구분=전환, 전환기준=MOVE**.

### 5.7 전환 수행 도구·순서 (p.115~120)
- **작업순서 흐름도**(5.1): 전환대상 선정 → 신·구데이터 매핑 → 전환프로그램 설계/구현/시험 → 대상 데이터 추출·전환작업 → 검증·오류처리 → 데이터 Load → 검증·오류처리.
- **SAM-File 작성**(5.4.3.1): Pro*C 추출 프로그램. 순서 = 추출 구동 → RDB 추출 → 오류체크 → 오류발행 → SAM File 생성. Not Null 누락 시 Default 자동부여, 유효범위 초과 오류처리.
- **DB LOAD**(5.5): SQL*Loader로 SAM File → 신Table 이관. 부적합 데이터 내역 생성·사후처리. Constraint·FK로 소량 발생분은 Load 후 Insert문 처리.

### 5.8 전환결과 검증 및 오류처리 (p.121~122, 표 ⑮)
- 오류 유형별 수행주체: **입력 데이터 자체 오류**(현업/응용/전환팀), **입력 프로그램 오류**(응용팀), **데이터 전환 프로그램 오류**(전환팀).
- 검증 대상: 전환자료 vs 근거자료 일치 / 코드 Master 존재 / 테이블 간 일관성·관리항목 확인.
- 검증 방법: 입출력 파일·건수 검토, 신·구 값 일치 비교, 보고서 활용, 통계·요금계산 수치 대비, 고객번호 관련 보고서를 원본 SAM File과 신Table에서 각각 출력해 비교.

### 5.9 최종 전환 작업 일정 (p.122~124, 표 ⑯⑰)
- 단계: ① 사전준비작업 ② 데이터전환 ③ 신테이블 LOAD ④ 전환 후 사후작업. 전환팀/DBA·응용팀 작업 분담.
- 세부 일정은 **D-3 → D-2 → D-1 → D** 시점별 마킹(테이블 Space 생성 → PK/FK/SP 생성 → 데이터 전환 → Load → Index·Analyze·Cold 백업).

### 5.10 기타 (p.124~126)
- **6.1 신규데이터 처리 방안**: 대량·전산 Logic 가능 = 일괄처리 / 소량·판단 필요 = 수작업(규칙 정해지면 프로그램 일괄). 활용방법 = 입력화면 또는 Excel Tool.
- **6.2 초기데이터 수집 구축**: 수집 대상 테이블(운송용기 PTTCT0010, 자동화설비 POETT0010 등), 수집 구축 절차(①안 작성·보고 → ②공문발송 → ③취합통보 → ④사전승인 → ⑤데이터 로드), 수집 형태=엑셀파일·문서서류양식.
- **6.3 비상대책 안**: 비상요건(전환자료 저장매체 부족·전환장비 사용불가·H/W·N/W 장애)별 내용·대책(여유분 확보, 업체 비상연락망 가동).

## 6. 함정 / 주의

- ★ **초기데이터·전환데이터가 없는 신규 구축 프로젝트는 D12 생략 가능** — 가이드 §I.3 산출물 적용 기준. 전환 대상 레거시 DB가 없으면 작성 의무 없음.
- D12는 **고정 컬럼 양식이 아니라 서술형 목차(1.~6.) 산출물**이다. §3.4의 표들은 "사례에서 등장한 표"이며, 프로젝트 특성에 맞춰 가감한다 (추정 컬럼 추가 금지 — PDF에 있는 컬럼만 사용).
- 작성 방법(§2): 업무그룹별 전환과 통합 전환을 구분하고, 업무그룹별이면 **전체 전환 완전성**을 별도 검증해야 한다.
- 백업 보관분·보관연수 경과분은 전환 대상에서 제외(p.113) — 전환 범위 정의를 명확히 할 것.
- 검증은 신·구 값 일치뿐 아니라 **코드 Master 존재·테이블 간 일관성**까지 확인(p.121). 단순 건수 일치만으로 완료 판정 금지.
- 신규 생성 데이터(전환기준=신규)는 매핑 내역서에 **생성 규칙**(예: "용국기호+일련번호")을 명시해야 한다(p.118).
- 사례의 날짜·테이블ID·담당자명은 모두 예시값이며, 실제 작성 시 프로젝트 값으로 대체.

## 7. KLID 프로젝트 적용 메모

> 기존 wiki의 KLID 적응 결론을 보존·정합: **KLID 저작도구는 신규 구축이므로 전환 대상 레거시 DB가 없음 → 전환(§2~5) 부분은 해당 없음.** 다만 코드성/초기데이터(§6.2)는 존재하므로 축소 작성 여지가 있다.

### 7.1 KLID-AT-D12-001 — 전환 데이터: 해당 없음 (생략 가능)
- KLID 저작도구(`klid_at` 스키마, LS_* 테이블)는 신규 구축이다. **현행 시스템 → 신시스템 데이터 전환 시나리오가 없다.**
- 관제서버 MNG_* 공유 테이블은 인프라가 제공하고 저작도구는 `ddl-auto=validate`로 **읽기 참조만** 하므로, "현행 → 신" 전환(추출·SAM·Load·매핑) 대상이 아니다. → §2 중점목표 ~ §5 전환 상세 절차, §6.1 신규데이터 처리, §6.3 비상대책은 **해당 없음**.
- 결론: 전환 데이터 기준으로는 **D12 생략 가능**(가이드 §I.3).

### 7.2 KLID-AT-D12-002 — 초기데이터(코드성·시스템 설정): 존재 → §6.2 중심 축소 작성 가능
- KLID에 존재하는 초기데이터 후보 (Flyway 마이그레이션으로 적재되는 LS_* 코드성/설정 데이터):
  - **코드 마스터류**: 라벨 클래스/속성 마스터 코드, 이벤트 타입 코드, 작업/검수 상태 코드(`dataSttsCd`: PENDING/MARKING_READY/PROCESSING/ASSIGNED/COMPLETED/FAILED 등), 역할 코드(REVIEWER/WORKER/PORTAL_USER).
  - **시스템 설정**: 시스템 설정 항목(`sysconfig` — 비식별/배치/AI 서버 파라미터, Caffeine TTL 60s 대상 설정값), 표준 해상도 화이트리스트(RES_1080P/RES_720P/RES_480P).
  - 적재 경로: 코드 기반 데이터는 **외부 시스템에서 수집·전환하는 것이 아니라 Flyway `db/migration` SQL로 초기 적재**된다 (CBD 사례의 "Excel Tool 수집·공문 취합" 절차와 다름).
- 작성 판단:
  - **정석안**: D12를 §6.2(초기 데이터 수집 구축) 중심으로 축소 작성 — 수집 대상 테이블 목록(코드 마스터·시스템 설정 LS_* 테이블), 구축 방법(Flyway 마이그레이션), 검증(`ddl-auto=validate` + 마이그레이션 재실행 멱등성)으로 대체.
  - **효율안(생략)**: 전환·수집 모두 Flyway로 코드화되어 별도 절차 문서가 불필요하다면, 가이드 §I.3에 따라 D12 전체 생략 + 다른 산출물(예: D8/D9 데이터 설계, 마이그레이션 SQL)로 추적.
  - → 어느 쪽인지는 **사업 산출물 합의 필요 (PDF/계약 기준 확인 필요)**. 본 위키는 두 안을 병기한다.

### 7.3 KLID-AT-D12-003 — 데이터마트 적재 View는 전환 대상 아님
- `klid_at` 4종 View(`V_COMPLETED_VIDEO/FRAME/LABEL(_ATTR)/META`)는 검수 완료 영상을 관제서버가 SELECT하는 **단방향 노출 인터페이스**이며, CBD §5의 "현행→신 데이터 전환(SAM/Load)"과 무관하다. D12에 포함하지 않는다(D8/D9 또는 연동규격서 영역).
- 관제서버 `TASK_COMPLETED`/`TASK_MODIFIED` 통지도 전환이 아닌 **이벤트 통지**이므로 D12 비대상.

### 7.4 작성 시 KLID 매핑 가이드
- §3.2 헤더박스: 시스템명=학습데이터 저작도구, 서브시스템명=해당 도메인, 단계명=설계.
- 작성한다면 §6.2 초기데이터 수집 표(표 ⑱)를 LS_* 코드/설정 테이블 목록으로 채우고, "수집 형태=Flyway 마이그레이션 SQL", "구축주체=저작도구팀"으로 적응.
- 사례의 전환 조직(전환팀/DBA/응용팀/유지보수팀)·D-3~D 전환 일정·SAM/SQL*Loader 절차는 KLID에 **해당 없음** → 작성 시 삭제(추정 채움 금지).
