## 1. 작성 목적 (PDF 원문)

단위시험 케이스에 따라 수행한 단위시험의 수행 결과를 기술한다.

## 2. 작성 방법 (PDF 원문)

작성한 단위시험 케이스에 따라 시험을 수행하고 시험 결과를 기술하며, 예상결과와 비교하여 단위시험의 판정 결과를 작성한다.

### 3-4. D11 단위시험 케이스와의 관계

- I2는 설계단계 산출물 **D11 단위시험 케이스**의 케이스부(케이스 ID / 케이스명 / 작업권한 / 시험데이터 / 시험항목 및 처리절차 / 예상결과 및 검증방법)를 **그대로 현행화**하고, 우측에 "시험결과" 컬럼군을 채워 완성하는 결과 현행화 산출물이다.

## 4. 항목 설명 (PDF 원문 — 전 항목)

- 설계단계 산출물인 "단위시험 케이스"를 **현행화**하여 시험을 수행한 후, 시험결과(**수행일, 수행자, 결과, 결함내용, 결함조치완료여부**)를 기록한다.

> PDF 항목 설명은 위 1문장이며, 시험결과 5요소(수행일·수행자·결과·결함내용·결함조치완료여부)를 명시한다.

- 케이스 ID 패턴: `TC_01_010` (TC + 그룹 + 일련).
- pass 케이스는 결함내용/조치여부 `-`.
- **fail 케이스**는 결함내용을 별첨 참조로 표기 가능하고, 결함조치여부에 조치완료일(예: `10.27 완료`)을 기재 — 조치완료까지가 산출물 완성 조건.
- 예상결과/검증방법에 SQL(`SELECT * FROM …`)을 검증 수단으로 명시.

## 6. 함정 / 주의

- **D11 → I2 사슬**: I2는 D11 단위시험 케이스의 결과 현행화 산출물. 케이스 본문을 임의로 바꾸지 말고, 케이스 변경이 필요하면 **D11도 함께 갱신**해 정합성 유지.
- 시험결과 5요소(수행일/수행자/결과/결함내용/결함조치완료여부) **누락 금지**.
- fail 케이스를 결함내용·조치여부 공란으로 남기면 미완성 — 조치 후 완료 기록까지가 완료.
- 단계명은 "구현" 고정. 관련 컴포넌트 ID·관련프로그램 ID는 헤더부에 함께 기재.

## 7. KLID 프로젝트 적용 메모

- KLID는 JUnit 5 + Testcontainers(PostgreSQL) 단위/슬라이스 테스트가 단위시험의 실체. 테스트 메서드명은 한글 서술형(`@DisplayName("본인_배정이_아닌_프레임_편집_시_403")`)이므로 케이스명/케이스 ID와 매핑해 현행화한다.
- 설계단계 D11(단위시험 케이스)의 케이스를 그대로 현행화하고, 케이스 변경 시 D11도 갱신 — 사슬 단절 주의.
- 관련 컴포넌트 ID·관련프로그램 ID는 I1 프로그램 코드 목록 ID 및 KLID 추적 코드(`KLID-AT-XX-NNN`)와 정합되게 인용.
- fail 케이스는 결함 조치 후 완료(수행일·조치완료여부) 기록까지가 산출물 완성 조건.
