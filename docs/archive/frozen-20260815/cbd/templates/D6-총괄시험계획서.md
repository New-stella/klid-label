## 항목 설명

- **시험 대상 시스템**: 시험의 대상이 되는 시스템, 하드웨어 및 응용시스템 구성도를 기술한다.
- **가정 또는 제약사항**: 시험 수행 시 고려되어야 할 제약사항 등을 기술한다.
- **시험 전략**: 단위, 통합, 시스템, 인수 시험에 대한 시험 범위, 수행방법 등에 대해 기술한다.
- **시험 실행 계획**: 단위, 통합, 시스템, 인수 시험에 대한 수행절차, 툴사용계획, 시험환경, 조직 및 역할, 수행상세일정, 관련산출물 등을 기술한다.

## 작성 시 참고사항

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID`
> - 서브시스템 ID (저작도구): `AT`
> - 산출물 파일명: `KLID_AT_총괄시험계획서_Rev {버전}`
> - 본 산출물에서 참조하는 ID:
>   - 단위시험 ID: `KLID-AT-UT-NNN` — D11 참조
>   - 통합시험 시나리오 ID: `KLID-IT-TS-NNN` — D10 참조
>   - 시스템시험 ID: `KLID-ST-NNN` — D7 참조
>   - 요구사항 ID: `RQ-SFR-NN-NN`(기능) · `NFR-NNN`(비기능) — R1 실존 ID만
>
> - 시험 대상 시스템: 학습데이터 저작도구(backend Spring Boot + ai-server FastAPI + frontend React), PostgreSQL
> - 시험 환경: local(PostgreSQL Docker/Testcontainers), dev, stg, prd 4개 환경 — CLAUDE.md 환경별 접속 정보 참조
> - 단위시험: JUnit 5 + Testcontainers(PostgreSQL), pytest(ai-server)
> - 통합시험: API 통합 테스트(Spring Boot Test), 외부 연동(ai-server, 비식별 솔루션, 외부 VLM, 외부 증강, 관제서버 통지) Mock/실연동
> - 시스템시험: 성능(배치 처리량), 보안(OWASP), 부하 테스트
> - 인수시험: 발주자(지방정부) 주도, 운영 환경에서 수행
> - 시험 조직: 프로젝트 시험팀, 응용개발팀, 시험환경구축팀 역할 구분
