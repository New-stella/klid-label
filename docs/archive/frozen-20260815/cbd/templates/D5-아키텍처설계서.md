# D5 아키텍처 설계서

## 작성 목적
> 시스템의 품질을 확보하기 위하여 전체시스템에 대한 청사진으로서의 아키텍처를 작성한다. 소프트웨어 아키텍처는 개발 대상 응용 소프트웨어에 대한 아키텍처이며, 시스템 아키텍처는 응용 소프트웨어와 이에 상호작용하는 환경 및 네트워크가 포함된 아키텍처를 의미한다.

## 작성 방법
> 소프트웨어 아키텍처는 선정된 아키텍처 패턴을 중심으로 컴포넌트와 상호작용하는 커넥션 및 가시적인 속성을 표현한다. 시스템 아키텍처는 개발 대상시스템과 상호작용하는 하드웨어, 시스템 소프트웨어 및 네트워크와의 관계를 표현한다. 아키텍처 요구사항 및 구현방안은 아키텍처 관점에서의 시스템의 품질, 보안, 성능, 장애복구 등의 요구사항과 이에 대한 구현방안을 기술한다.

## 항목 설명

- **소프트웨어 아키텍처**: 소프트웨어 아키텍처를 기입한다.
- **시스템 아키텍처**: 시스템 아키텍처를 기입한다.
- **아키텍처 요구사항 및 구현방안**: 아키텍처 관점에서 시스템에 크게 영향을 주는 품질, 보안, 성능, 장애복구 등의 요구사항 및 구현방안을 기술한다.
  - **요구사항 ID**: "사용자 요구사항 정의서"의 관련된 요구사항 ID를 기술한다.
  - **요구사항 내용**: 요구사항 내용을 상세하게 기술한다.
  - **구현방안**: 요구사항 구현방안을 상세하게 기술한다.

## 작성 시 참고사항

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID`
> - 서브시스템 ID (저작도구): `AT`
> - 산출물 파일명: `KLID_AT_아키텍처설계서_Rev {버전}`
> - 본 산출물에서 참조하는 ID:
>   - 요구사항 ID: **R1 사용자요구사항정의서·R3 요구사항추적표에 실존하는 비기능 ID만** (Critical — 작성 전 R1/R3 문서 대조 필수, 사용자 확정 규칙 2026-07-14). LogiCraft에만 존재하는 ID·sub_id 매핑분은 제외한다. 필요 시 `RQ-SFR-NN-NN` (기능) — R1 참조. 결번 존재 — 연속번호 날조 금지. 나열 순서 = R1 비기능 표 순서
>   - 컴포넌트 ID: `KLID-AT-CO-NNN` — D3 참조
>
> - 소프트웨어 아키텍처(§1): 본 프로젝트는 Spring Boot 3.3 + React + FastAPI 3-tier 구조. Presentation Layer(React/Vite), Business Layer(Spring Boot — Controller/Service/Repository), Data Layer(PostgreSQL + Flyway), AI Layer(ai-server — YOLO/SAM2/VLM, Stateless 추론). 다이어그램은 ` ```html ` 펜스 정적 HTML 레이어 배치도 표준(hwpx 렌더 — Mermaid는 폴백)
> - 시스템 아키텍처(§2): `docs/architecture/` 디렉토리의 기존 아키텍처 문서와 CLAUDE.md의 환경별 접속 정보를 참조한다. PostgreSQL(`klid_at` 스키마, MNG_* 공유 validate)·Quartz PostgreSQL JobStore. **물리 배치(2026-07-14 확정)**: 주 서버 2노드 Active-Active 이중화(관제서버 공동 배치, Quartz 클러스터링으로 잡 중복 방지)·DB 별도 서버(이중화)·NAS 별도 서버(공유 마운트)·연동 서비스(비식별솔루션·VLM·증강·포털) 각각 별도 서버. ai-server는 주 서버 내 별도 프로세스(무상태, GPU 탑재 명시 안 함). 구성도 화살표는 고대비 라벨 스타일로 강조. **하위절 구성(발주처 보완요청 반영 — Rev2 v1.7~1.8 확정)**: 2-1 하드웨어 구성 및 망 연계(서버 관점) / 2-2 인터페이스 구성(D4 요약) / 2-3 주변 시스템 연계 관계 / 2-4 권한 인증 방안 및 사용 프로세스 / 2-5 소프트웨어 구성요소 종류·버전·설치 경로 — 재생성 시 기존 문서에서 이관·유지(임의 삭제 금지)
