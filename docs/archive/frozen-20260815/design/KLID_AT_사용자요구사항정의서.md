## 항목 설명

- **요구사항 ID**: 요구사항별로 유일한 ID를 부여하여 기입한다.
- **요구사항명**: 도출된 요구사항을 요약할 수 있는 명칭을 기입한다.
- **구분**: 도출된 요구사항을 정보시스템 개요 및 기능목록, 기능 요구사항, 성능 요구사항, 품질 요구사항, 인터페이스 요구사항, 데이터 요구사항, 운영 요구사항, 제약사항 중에서 선택하여 기재한다. (※ "제안요청서의 요구사항 작성가이드"의 요구사항 구성요소 참조)
- **요구사항 설명**: 사용자 요구사항을 구체적이고 상세하게 기술한다.
- **요구사항 출처**: 요구사항이 제시된 문서에 대하여 문서번호와 문서명을 기술한다.
- **제약사항**: 요구사항이 수행되기 위하여 필요로 하는 법적 또는 기술적인 조건을 기술한다.
- **중요도**: 해당 요구사항의 전체 시스템 구현 측면에서의 중요도를 기술한다. (상, 중, 하 중에서 선택)
- **검수 기준**: 요구사항을 구현한 후 구현에 대한 품질을 정량적 또는 정성적으로 측정할 수 있는 기준을 기술한다.
- **해결방안**: 요구사항의 해결방안을 구체적으로 기재한다.
- **비고**: 위의 항목에 포함되지 않으나, 고려해야할 사항이 있으면 기술한다.
- **분류 / 목표값 / 측정방법** (비기능 요구사항 표 전용): 비기능 요구사항의 품질 특성 분류, 달성해야 할 정량·정성 목표, 목표 달성 여부를 확인하는 방법을 기술한다.

>   - 비기능 요구사항 ID: `NFR-NNN` — 본 정의서 확정 범위는 `NFR-008`~`NFR-021` (예: `NFR-011`), 「본문 — 비기능 요구사항(NFR)」 별도 표. `NFR-001`~`NFR-007`은 기준선에서 제외되었다(부록 3 참조).
>   - 발주처 원본 비기능 ID(`RQ-QUR-NNN-NN` / `RQ-SER-NNN-NN` / `RQ-PER-NNN-NN` / `RQ-DAR-NNN-NN` / `RQ-COR-NNN-NN`)는 비기능 요구사항 표의 비고 칸에 병기한다.
> - 후속 산출물(R2·R3·D1~D5 등)이 인용하는 요구사항 ID는 **본 정의서에 실존하는 ID만** 사용한다.

## 부록 — 빈 셀·결번·범위 처리 사유

### 1. 빈 셀(`-`) 처리 사유

| 위치 | 사유 |
|------|------|
| 제·개정 이력 작성자·승인자 | 초기 생성 기준선으로 담당자 배정 전이며, 확정 시 보완한다. |

### 2. 요구사항 ID 결번

- 기능 요구사항은 발주처 원본 체계(`RQ-SFR-NN-NN`)를 그대로 사용하므로 원본에 존재하나 저작도구 책임이 아닌 항목은 **결번**으로 남는다. 결번은 임의로 메우지 않으며 후속 산출물도 동일하게 결번을 유지한다.
- 확정 결번(저작도구 범위 외로 결정되어 본 정의서에서 제외한 항목): `RQ-SFR-06-04`(이미지·영상 생성 프롬프트 편의성 개선 — 외부 생성 시스템 책임), `RQ-SFR-08-06`(데이터마트 동기화 — 데이터마트는 외부 제공 시스템 책임), `RQ-SFR-09-06`(개인정보 보호대책 — 보안 영역 책임), `RQ-SFR-09-07`(개인정보 유형 분류체계 구축 — 외부 시스템 책임).
- 다만 검수 완료 후 수정 발생 시 상위 시스템으로 보내는 완료·수정 통지는 버전관리(`RQ-SFR-08-04`·`RQ-SFR-08-05`) 흐름의 운영 책임으로 유지된다.
- 비기능 요구사항은 `NFR-008`~`NFR-021` 이 연속이며 그 구간에 결번이 없다. 앞 구간 `NFR-001`~`NFR-007`은 기준선에서 제외한 결과로 비어 있으며, 이는 항목 누락이 아니다(제외 사유는 부록 3 참조). 제외된 번호는 재사용하지 않는다.

### 3. 비기능 요구사항 제외 항목(`NFR-001`~`NFR-007`)

본 정의서 초안에 있던 아래 7건은 **저작도구가 자체 도출한 운영·설계 기준**이며 발주처 요구사항(제안요청서·보완요청)에서 유래한 항목이 아니므로, 발주처 요구사항 기준선에서 **제외**하였다. LogiCraft 요구사항 그래프의 해당 ITEM 7건도 같은 근거로 **폐기(deprecated) 처리**하였다(2026-08-06). 이는 요구사항 누락이 아니라 기준선 정의 범위를 발주처 유래 항목으로 한정한 결과다.

| 제외 ID | 요구사항명 | 대체 반영 위치 |
|--------|---------|-------------|
| NFR-001 | 배치 파이프라인 처리량 | D5 아키텍처설계서 §1·§2(배포 토폴로지·처리 흐름) 및 §3 서술형 장애복구 2절 |
| NFR-002 | 이미지 학습데이터 처리 규모 | 기능 요구사항 `RQ-SFR-16`이 동일 요구(이미지 10만 장 구축)를 이미 보유 |
| NFR-003 | 영상 학습데이터 처리 규모 | 기능 요구사항 `RQ-SFR-17`이 동일 요구(30초 이상 영상 5,000건 구축)를 이미 보유 |
| NFR-004 | 외부 API 연동 복원력 | D5 아키텍처설계서 §1·§2(외부 연동 구성) 및 §3 서술형 장애복구 2절 |
| NFR-005 | 민감정보 보호 | 프로젝트 코딩 표준(보안·로깅 규칙). 발주처 유래 보안 요구는 `NFR-013`·`NFR-014`·`NFR-020`·`NFR-021`이 담당 |
| NFR-006 | 포털 웹 접근성 | **대체 보유처 없음** — 요구사항 그래프상 웹 접근성(WCAG 2.1 AA)을 명시한 유일한 항목이었으므로 요구사항 기준선에서는 소멸하였다. 근거는 프로젝트 표준 및 착수(kickoff) 기록에 존치하며, 반응형 웹 제공 요건은 `NFR-015`(웹표준·크로스브라우징)가 부분적으로 포함한다 |
| NFR-007 | 메트릭·추적성 | 프로젝트 관측성 표준(메트릭·추적 식별자 규칙) |

> 제외 근거 문서: D5 아키텍처설계서 Rev2 v1.9(2026-07-14) 기록된 사용자 결정 — "§3은 R1·R3 실존 발주처 유래 항목만 기술하고 자체 도출분 `NFR-001`~`NFR-007`은 제외".

### 4. 범위 외(제외) 항목

- **데이터마트**: 마트 구축·검색·다운로드는 외부 제공 시스템 책임이며, 저작도구는 라벨링·검수·버전관리까지 담당한다.
- **생성형 AI 본체 / 영상 합성 모델 본체 / 시계열 메타 분석 모델 본체**: 모델 학습·조정·프롬프트 관리는 외부 시스템 책임이며, 저작도구는 연동·결과 검수만 담당한다.
- **학습데이터셋 내보내기(Export) 유통**: 저작도구는 검수 승인 시점의 산출물 생성까지 담당하고, 배포·유통은 외부 책임이다.

### 5. 후속 산출물 기준선(baseline)

- 본 정의서에 확정된 **기능 요구사항 22건**(`RQ-SFR-06-03`, `RQ-SFR-07-01`~`07-03`, `RQ-SFR-08-01`~`08-05`, `RQ-SFR-09-01`~`09-05`, `RQ-SFR-11-04`~`11-06`, `RQ-SFR-11-08`~`11-10`, `RQ-SFR-16`, `RQ-SFR-17`)과 **비기능 요구사항 14건**(`NFR-008`~`NFR-021`)이 후속 산출물이 인용할 수 있는 요구사항 ID의 전부다.
- 제외된 `NFR-001`~`NFR-007`은 기준선에서 빠졌으므로 후속 산출물이 인용하지 않는다(부록 3 참조).
- 본 정의서에 없는 요구사항 ID를 후속 산출물에서 신규로 사용하지 않는다.

### 6. 문서 간 사용관계 링크

- 본 정의서는 요구사항 기준선(baseline) 문서로, 다른 저작도구 설계 산출물을 참조(사용)하는 관계가 없다. 참조 방향은 후속 산출물(유스케이스명세서·요구사항추적표 등)에서 본 정의서를 인용하는 단방향이므로 본 문서에는 사용관계 링크를 두지 않는다.
