## 1. 문서 정체

`D11-R1 단위시험 절차서`(전체)의 **파생 변형본**. 전체본에서 예외·경계·권한·검증 케이스를 제외하고 **각 기능의 정상 동작(happy-path) 케이스만** 추린 뒤, 아래 두 축으로 재편했다.

- **컴포넌트(CO) 단위 재편**: 케이스 ID = `KLID-AT-UT-{컴포넌트번호}-NN` (블록마다 01부터 순번)
- **UI 절차본(개정 v4.0~5.0)**: 시험항목·처리절차를 실제 UI 동선(`번호 단계 + ':' 상세`, D2 근거)으로 기술. 화면 없는 배치/내부/콜백은 기능 트리거 절차로 표기. 예상결과·검증방법은 D8/D9 실측 키 기반 확인 SELECT로 기술.

블록 머리표 = `단위시험ID · 설명 · 관련 컴포넌트 ID(KLID-AT-CO-NNN) · 관련 프로그램 ID(KLID-AT-IF-NNN)`.
외부 연계 컴포넌트는 D4 송수신 프로그램 ID(II-NNN) 병기.
케이스표 컬럼 = `케이스 ID · 케이스 명 · 작업 권한 · 시험 데이터 · 시험항목 및 처리절차 · 예상결과 및 검증방법 · 시험 결과(공란)`.

## 4. ⚠ 편집 시 정합성 이슈 (우선순위 순)

### (P1) UT-007 '설명'에 고아 불릿 잔존 — 커밋 변경과 직접 충돌
- 위치: UT-007 블록 설명(문서 line 115 부근)
- 내용: `- 라벨 삭제 등 변경 이력을 프레임 단위로 적재하고 최신순으로 조회한다.`
- 문제: 이 불릿이 검증하던 **007-02(삭제 audit) 케이스가 5.0에서 제거**됐는데 설명은 남아, **대응 케이스 없는 서술**이 됨.
- 연동: 같은 블록 출처 문구(line 117)도 `UT-18 … 검수 승인 스냅샷·이력 케이스`로 "이력"을 여전히 언급.
- 조치안: 설명에서 해당 불릿 삭제(남은 케이스 = 스냅샷 + 통지), 출처의 "이력" 표현 정리.

### (P2) UT-002 출처 stale
- 위치: UT-002 블록 출처(line 55 부근)
- 내용: `D11 UT-03(외부 증강) 중 라벨 보존율 계산 케이스.`
- 문제: 보존율 계산 케이스는 개정 4.3에서 제거됨. 블록이 "새 영상 등록"으로 용도 변경됐으므로 출처 문구가 실제 내용과 어긋남.

### (P3) UT-013은 유일한 설계 전용 블록
- `[설계]` 표기. 비식별 옵션 키 `ConfigKeys` 미등록 → 위탁이 기본값 고정(masking_type=0·db_save=0·masking_range=1·exp_quality=0·exp_format=1)이라 실동작 케이스 아님.
- "기능 정상동작 한정" 문서 내 예외. 집계·승격 시 실구현 26케이스와 구분 필요. 옵션 키 등록 시 UT-26 패턴 실테스트로 승격 예정.

### (P4) 메뉴 경로 `>` 표기 혼재
- 일부 `&gt;` HTML 엔티티(line 47·149 등), 일부 `>` 원문자(line 71 등). 편집 시 정규화 여지.

## 5. 참조 체계 요약

- **CO-NNN**: D3 컴포넌트설계서 컴포넌트 ID
- **IF-NNN**: D3 컴포넌트설계서 인터페이스 ID (관련 프로그램 ID 칸)
- **II-NNN**: D4 송수신 프로그램 ID (외부 연계 시 병기)
- **SC-NNN / SD-NNN**: D2 화면/화면동선 (UI 절차 근거)
- **검증 근거**: D8(테이블/컬럼)·D9(상태·코드) 실측 키 기반 SELECT
