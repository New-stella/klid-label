# D11-R1 단위시험 절차서 — 쉬운 설명본 (기능 정상동작 한정 · 컴포넌트 기준)

## 작성 목적
> 본 문서는 `D11-R1-단위시험절차서-기능정상.md`(원본)의 내용을 **개발 용어(클래스명·테이블/컬럼명·상태코드)를 모두 일상어로 풀어** 옮긴 것이다. 전체본에서 예외·경계·권한·검증 케이스를 빼고 **각 기능이 정상적으로 동작하는 케이스만** 추린 기능 검증용이며, 처음 보는 사람도 "무엇을 확인하는 시험인지"를 바로 이해할 수 있도록 문장을 다시 썼다. 추적을 위해 케이스ID·요구사항ID·유스케이스(UC)·컴포넌트(CO) 식별자는 그대로 유지한다. 활성 R1 기능 유스케이스 18종은 모두 정상 동작 케이스를 1건 이상 보유한다. 본 판본은 단위시험을 **컴포넌트(CO) 단위 블록**으로 재편하고, 케이스 ID를 `KLID-AT-UT-{컴포넌트번호}-NN`로 부여한 컴포넌트 기준본이다.

### 이 문서 읽는 법
- **블록 머리표**: 각 블록은 [단위시험ID · 설명 · 관련 컴포넌트 ID · 관련 프로그램 ID] 표로 시작한다. 단위시험ID는 관련 컴포넌트 번호와 1:1로 일치한다(`KLID-AT-UT-{컴포넌트번호}`). 설명 칸에 요구사항ID·UC를 보존했고, 관련 프로그램 ID 칸에는 원본 클래스명 대신 쉬운 기능 설명을 넣었다.
- **케이스 ID**: 각 블록 안에서 `KLID-AT-UT-{컴포넌트번호}-01`부터 순번으로 부여한다.
- **상태/판정 용어 풀이** (원본의 숫자 코드 → 본 문서의 표현):
  - 성공 처리됨 = 요청이 정상 수행됨(원본 200/201)
  - 잘못된 입력으로 거부됨 = 형식·범위·허용목록 위반(원본 400)
  - 권한 없는 사용자 차단됨 = 역할 권한 부족(원본 403) 등.
- **역할**: 검수자 = 검수·관리 권한자(원본 REVIEWER), 작업자 = 라벨링 작업자(원본 WORKER).
