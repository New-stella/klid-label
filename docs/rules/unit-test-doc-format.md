# 단위시험 문서 — 「예상결과 및 검증방법」 작성 형식 (구속)

> 2026-09-09 사용자 확정. 근거는 **같은 컨소시엄이 실제로 제출한 통합플랫폼(KLID-PF) 단위시험
> 결과서**다(사용자가 실물 화면을 보여 줌). 우리 D11 이 그 형식에서 크게 벗어나 있었다.

## 판정 한 줄

**시험을 수행하는 사람이 화면에서 볼 수 있는 것만 쓴다. 화면으로 판정이 안 되는 것만 쿼리를 붙인다.**

## 형식

번호를 매긴 짧은 문장. `~한다` 로 끝난다. 한 항목 한 문장.

```
1. 요청이 접수되면 증강 결과 화면으로 이동하고 성공 알림을 노출한다.
2. 증강 요청·결과 목록에 해당 요청이 '처리 대기' 상태로 표시된다.
```

화면으로 판정할 수 없을 때만 마지막에 쿼리를 덧붙인다.

```
3. (DB) `SELECT MARK_MODE_CD, MARK_CN FROM LS_MARKING WHERE RAW_SN={영상번호}`
   → 1건. 모드와 마킹 목록이 저장돼 있다.
```

### 제출본 실제 예시 (KLID-PF 단위시험 결과서)

> 1. 현재 비밀번호 미일치 얼럿 메시지를 노출한다.

> 1. 유효성 필드 하단에 유효성 문구를 노출한다.  2. 해당 필드로 focus 를 이동한다.

이 두 줄이 기준이다. **SQL·클래스명·상태코드가 하나도 없다.**

## 쓰지 않는 것 (이번에 실제로 들어가 있던 것들)

| 넣지 말 것 | 실제로 있던 예 |
|---|---|
| 클래스·이벤트·메서드 이름 | `MarkingCompletedEvent 발행` · `AiServerClient.segment 호출 발생` |
| DTO·응답 객체 이름 | `AugmentRequestResponse(jobId·requestedAt·videoCount=1)` |
| HTTP 상태코드 | `HTTP 201 Created` · `200 반환` |
| 구현 용어 | `@Async 배치라 즉시 아님` · `setScale 4` · `AFTER_COMMIT` · `멱등키` |
| 내부 식별자 표기 | `{저장 라벨 PK}` · `DATA_LBL_SN` 같은 조인 키 나열 |
| 위 내용을 되풀이하는 `검증:` 줄 | 칸 끝마다 있던 중복 요약 |

⚠ **컬럼명·테이블명은 쿼리 안에서만** 쓴다. 산문에 `LBL_TYPE_CD='POLYGON'` 처럼 흩뿌리지 않는다.

## 함께 지킬 것

- **쿼리를 넣을 땐 그 테이블이 아직 살아 있는지 확인한다.** 이번에 낡은 참조가 실제로 있었다 —
  `LS_RESOLUTION_EXPORT`(폐기) · `PARENT_RAW_SN`(→`ORGNL_RAW_SN`) · `LS_DATA_LBL_AI_INFO`(흡수) ·
  `V_COMPLETED_LABEL`(제거). 쿼리를 줄이면 이 위험도 함께 준다.
- **「기능 정상동작 한정」 판본에는 거부·오류 케이스를 쓰지 않는다.** 범위 밖이다.
- 길이 기준은 **한 칸 150자 안팎**이다. 재작성 전 평균이 337자였다.
