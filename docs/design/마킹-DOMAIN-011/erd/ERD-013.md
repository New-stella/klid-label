2차 신규 마킹 도메인 (DFEAT-039)

#### status

new

- **description**: 영상별 자동/수동 이벤트 식별 마킹 정보. 영상 1건(RAW_SN)에 대해 N건의 마킹이 생성될 수 있으며, 마킹 완료 시 VLM 시계열 위탁 요청에 반영되는 축은 셋이다 — 프레임 선택은 frame_policy(프레임 선택 정책)로, 질문 선택(VRFC_EVNT_QSTN_SN)은 추가 질문 축 요청의 prompt 로, 검증 이벤트 유형 선택(VRFC_EVNT_TYPE_CD)은 묘사 축 요청의 event_type 2순위 조달로 나간다. event_type 조달 순서는 관제 인입 값 → 마킹에서 작업자가 고른 값 → null 이다. 다만 관제 값이 없어 화면이 유형 선택을 노출한 영상에서는 작업자가 유형을 고르지 않으면 마킹을 완료할 수 없어, 마킹 화면을 거치는 경로는 마지막 null 에 도달하지 않는다 — 그 폴백이 남는 자리는 마킹 화면을 거치지 않는 경로와 이 칸이 생기기 전에 저장된 기존 행이며, 그때도 값을 지어내지 않고 null 로 보낸다. 이벤트명·영상 경로·마킹 원문 배열은 위탁 규격 밖이라 싣지 않는다. 상태 전이: RESERVED → PENDING → VLM_REQUESTED → {VLM_COMPLETED | VLM_FAILED}, PENDING/VLM_REQUESTED → SKIPPED(배치 skip 종결. 비식별 신고 해소 후 재마킹 시 활성 마킹을 종결시켜 부분 유니크 제약 UK_LS_MARKING_RAW_ACTVTN(RAW_SN, WHERE STTS_CD IN ('PENDING','VLM_REQUESTED'))을 해제하는 경로 포함), RESERVED → SKIPPED(적용하지 못한 예약을 마감하는 경로). RESERVED 는 외부에서 받은 마킹을 영상 적재 시점에 담아 두는 시작 상태이며 그 부분 유니크 제약이 보는 값이 아니다. 2026-09-02 확정으로 포털 업로드 영상의 이벤트구간 마킹도 이 표를 재사용한다 — 포털 채널 전용 마킹 표를 새로 두지 않는다. 다만 그 경로의 마킹은 쓰임이 다르다 — 프레임을 어느 지점에서 뽑을지 정하는 것이고, 저장이 곧 추출의 시작이며 외부 시계열 위탁·검수와 무관하다. 그래서 위탁 축의 상태값과 예약 상태는 그 경로에서 쓰이지 않고, 검증 이벤트 질문도 고르지 않는다(그 경로에는 관제 인입 이벤트 유형이 없다). 이벤트명과 영상 파일 경로명 두 칸은 두지 않는다 — 영상 행의 값을 베껴 둔 중복이었고 포털 경로에는 둘 다 채울 값이 없었다. 마킹 응답의 두 값은 영상 행에서 조달한다. 그 경로에서 쓰이지 않는 상태값(위탁 축 셋과 예약)은 쓰이지 않을 뿐 값을 없애지 않는다 — 없애면 내부 채널의 기존 행이 판독 불가가 된다.

2차 신규 마킹 도메인 (DFEAT-039)

### 2026-09-02 — 포털 업로드 영상 마킹이 이 원장을 재사용한다
- 포털 채널 전용 마킹 표를 두지 않기로 확정되어 이 원장이 두 채널의 마킹을 함께 담는다.
- 등록 사용자 번호를 숫자에서 문자 100자로 넓혔다. 포털이 발급한 토큰의 주체 식별자를 담아야 하고, 좁게 잡으면 서로 다른 사용자가 같은 값으로 잘려 인가가 조용히 어긋난다. ⚠ 라벨 원장의 같은 컬럼에 이미 같은 조치가 돼 있다는 서술은 사실이 아니었다 — 그 컬럼은 아직 숫자다. 전용 표 흡수가 계획한 것을 이미 된 것처럼 적은 것이며, 그 흡수 때 함께 넓혀야 한다.
- 컬럼을 지우거나 이름을 바꾸지 않았고 상태 값 집합도 그대로 두었다. 포털 경로에서 쓰이지 않는 값(위탁 축 셋과 예약)이 있다는 사실만 서술로 남겼다 — 값을 없애면 내부 채널의 기존 행이 판독 불가가 된다.
- 두 칸은 두지 않기로 확정돼 제거했다 — 영상 행의 값을 베껴 둔 중복이었다.

### 2026-09-07 — 마킹이 위탁에 기여하는 축이 셋으로 늘었다
- 검증이벤트유형코드(VRFC_EVNT_TYPE_CD, varchar(20), nullable) 한 칸을 더했다. 관제가 검증 이벤트 유형을 보내지 않은 영상에서 작업자가 마킹 화면에서 고른 값을 담는다. 물리명과 폭은 인입 원장의 같은 칸에 맞췄으므로 신규 용어 등록은 필요 없다.
- 「위탁은 frame_policy 로만 구성된다」는 단언이 더는 참이 아니라 표 설명과 이벤트명 칸의 서술을 고쳤다 — 프레임 선택은 frame_policy 로, 질문 선택은 추가 질문 축 요청의 prompt 로, 검증 이벤트 유형 선택은 묘사 축 요청의 event_type 으로 나간다.
- 검증 이벤트 질문 칸의 조달 서술도 확정 규칙에 맞췄다. 유형이 미수신이어도 마킹 선택값이 있으면 그 질문을 쓴다 — 유형 선택 칸이 생겨 그 선택이 가능해졌기 때문이다. 구 서술 「유형이 미수신이면 질문을 고를 수 없으므로 비워 둔다」는 폐기다.
- 컬럼을 지우거나 이름을 바꾸지 않았고 기존 칸의 자료형·제약도 그대로다. 질문 칸에 물리 외래키를 두지 않는 근거도 그대로다 — 질문 목록은 전체 교체로 저장되어 가리키던 행이 사라지는 것이 정상 동선이라 참조 무결성을 판정기가 갖는다.

## description

영상 마킹(LS_MARKING) 물리 ERD. 선두 비식별이 끝난 영상을 대상으로 진행하는 자동/수동 이벤트 식별 마킹 정보를 보관한다. 자동(AUTO) 모드는 프레임간격수(FRME_INTV_NOCS) 기반으로 marks(프레임 인덱스/타임스탬프)를 생성하고, 수동(MANUAL) 모드는 작업자가 키보드 단축키로 선택한 marks 배열을 저장한다. 마킹 완료 이벤트를 트랜잭션 커밋 이후에 받아 잔여 배치(VLM 시계열 위탁 → 프레임 추출 → 오토라벨링 → 트랙 보간)를 트리거한다. 행안부 공통표준 약어 정합 적용(EVENT_NAME→EVNT_NM, MARKS→MARK_CN, STATUS→STTS_CD 등). (V45 신설) + JPA 엔티티 LsMarking. 2026-09-02 확정으로 포털 업로드 영상의 이벤트구간 마킹도 이 원장을 재사용한다 — 포털 채널 전용 마킹 표를 두지 않는다. 그 경로는 비식별 단계가 없어 「선두 비식별이 끝난 영상을 대상으로 한다」는 전제가 서지 않으며, 마킹 완료가 여는 것도 잔여 배치가 아니라 그 영상의 프레임 추출 하나다. 그 경로의 소유자 식별자를 담기 위해 등록 사용자 번호의 자료형을 숫자에서 문자 100자로 넓힌다 — ⚠ 라벨 원장의 같은 컬럼에 이미 같은 조치가 돼 있다는 서술은 사실이 아니었다 — 그 컬럼은 아직 숫자다. 전용 표 흡수가 계획한 것을 이미 된 것처럼 적은 것이며, 그 흡수 때 함께 넓혀야 한다. 2026-09-07 확정으로 마킹이 시계열 위탁에 기여하는 축이 셋(프레임 선택·질문 선택·검증 이벤트 유형 선택)으로 늘어 검증이벤트유형코드(VRFC_EVNT_TYPE_CD) 한 칸을 더한다 — 관제가 그 유형을 보내지 않은 영상에서 작업자가 고른 값을 담는 자리이며, 묘사 축 위탁의 event_type 조달 순서는 관제 인입 값 → 이 칸 → null 이다.
