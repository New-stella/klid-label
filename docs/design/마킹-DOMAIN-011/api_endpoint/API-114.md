#### description

성공 — 서명 URL + 만료시각. ApiResponse 래퍼. 이때 서명 URL 과 함께 nonce 쿠키 klid_stream_nonce 를 Set-Cookie 로 발급한다. 이 쿠키는 서명 검증의 필수 입력이며 브라우저가 스트림 요청에 자동으로 실어 보낸다. 값은 발급 대상 사용자에 바인딩되어 봉인된 형태이고, 서명 입력에 쓰이는 원본 nonce 는 URL 에도 응답 본문에도 실리지 않는다. 속성은 HttpOnly, SameSite=Lax, Max-Age 3600초이며 Path 는 스트림 경로로 한정한다. Secure 는 배포 설정으로 결정하며 기본은 부여하지 않는다. 요청에 이미 유효한 nonce 쿠키가 있으면 그대로 재사용하고, 없거나 봉인 검증에 실패하면 새로 발급한다.

## description

인증된 내부 사용자(REVIEWER/WORKER)가 호출하면 짧은 TTL HMAC 서명 쿼리가 붙은 스트림 URL을 반환한다. <video> 엘리먼트가 Authorization 헤더를 못 붙여 401이 나는 문제를 우회하기 위한 것으로, JWT 본문은 URL에 노출되지 않는다. 발급 요청자 subject(userNo)를 서명에 바인딩해 타 사용자 URL 재사용을 차단한다(CWE-284). 서버 서명 시크릿 미설정 시 503. 서명 입력에는 URL 에 실리지 않는 nonce 가 섞이며, 그 nonce 는 발급 응답의 klid_stream_nonce 쿠키로만 전달된다. URL 만 확보한 제3자가 재사용하지 못하게 하는 클라이언트 바인딩 장치다. HttpOnly 는 스크립트가 nonce 를 탈취해 URL 재사용에 붙이는 경로를 차단하고, SameSite=Lax 는 크로스사이트 요청에 쿠키가 부착되지 않게 한다(동일 오리진 재생은 정상). Path 를 스트림 경로로 한정하는 것은 다른 API 요청에 불필요하게 실려 나가지 않게 하기 위함이다. Secure 는 HTTPS 로 서비스되는 배포에서 켜는 것을 권장하나, 평문 HTTP 로 서비스되는 배포에서 부여하면 브라우저가 쿠키를 저장하지 않아 서명 검증이 전량 실패한다. 응답의 url 은 API 기준 경로이며 배포 접두(컨텍스트 경로)를 포함하지 않는다. 발급 측은 자신이 어느 컨텍스트 아래에 배포되는지 알 수 없으므로 접두를 붙이지 않으며, 최종 요청 주소는 소비 측이 자신이 아는 배포 접두를 그 값 앞에 붙여 구성한다. 이 URL 은 인증 헤더를 실을 수 없는 재생 요소가 그대로 사용하는 값이라, 소비 측이 배포 접두를 붙이지 않으면 요청이 이 API 의 경로 공간을 벗어나 같은 오리진에 배치된 다른 시스템의 경로로 나가고 영상이 재생되지 않는다. 앱이 베이스 경로 없이 루트에 서비스되는 배포에서는 두 주소가 우연히 일치해 이 어긋남이 드러나지 않으므로, 베이스 경로 아래에 서비스되는 배포에서만 나타나는 조건임에 주의한다. 발급된 URL 로 재생이 실패했을 때 소비 측은 재발급과 재시도를 무한히 반복하지 않는다. 재시도 횟수에 상한을 두고 상한에 이르면 중단해 사용자에게 실패를 알리며, 구체적 상한값은 구현 판단에 맡긴다.
