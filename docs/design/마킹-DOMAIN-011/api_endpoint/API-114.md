#### description

성공 — 서명 URL + 만료시각. ApiResponse 래퍼. 이때 서명 URL 과 함께 nonce 쿠키 klid_stream_nonce 를 Set-Cookie 로 발급한다. 이 쿠키는 서명 검증의 필수 입력이며 브라우저가 스트림 요청에 자동으로 실어 보낸다. 값은 발급 대상 사용자에 바인딩되어 봉인된 형태이고, 서명 입력에 쓰이는 원본 nonce 는 URL 에도 응답 본문에도 실리지 않는다. 속성은 HttpOnly, SameSite=Lax, Max-Age 3600초이며 Path 는 스트림 경로로 한정한다. Secure 는 배포 설정으로 결정하며 기본은 부여하지 않는다. 요청에 이미 유효한 nonce 쿠키가 있으면 그대로 재사용하고, 없거나 봉인 검증에 실패하면 새로 발급한다.

## description

인증된 내부 사용자(REVIEWER/WORKER)가 호출하면 짧은 TTL HMAC 서명 쿼리가 붙은 스트림 URL을 반환한다. <video> 엘리먼트가 Authorization 헤더를 못 붙여 401이 나는 문제를 우회하기 위한 것으로, JWT 본문은 URL에 노출되지 않는다. 발급 요청자 subject(userNo)를 서명에 바인딩해 타 사용자 URL 재사용을 차단한다(CWE-284). 서버 서명 시크릿 미설정 시 503. 서명 입력에는 URL 에 실리지 않는 nonce 가 섞이며, 그 nonce 는 발급 응답의 klid_stream_nonce 쿠키로만 전달된다. URL 만 확보한 제3자가 재사용하지 못하게 하는 클라이언트 바인딩 장치다. HttpOnly 는 스크립트가 nonce 를 탈취해 URL 재사용에 붙이는 경로를 차단하고, SameSite=Lax 는 크로스사이트 요청에 쿠키가 부착되지 않게 한다(동일 오리진 재생은 정상). Path 를 스트림 경로로 한정하는 것은 다른 API 요청에 불필요하게 실려 나가지 않게 하기 위함이다. Secure 는 HTTPS 로 서비스되는 배포에서 켜는 것을 권장하나, 평문 HTTP 로 서비스되는 배포에서 부여하면 브라우저가 쿠키를 저장하지 않아 서명 검증이 전량 실패한다.
