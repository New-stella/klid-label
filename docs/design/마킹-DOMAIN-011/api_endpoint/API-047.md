## description

영상에 이벤트 시점 마킹을 생성한다. 자동 모드는 프레임 간격으로 마킹 지점을 산출하고, 수동 모드는 요청에 담긴 마킹 지점 배열을 그대로 저장한다.

[사전 조건] 대상 영상의 배치 단계가 마킹 대기이고 비식별이 완료돼 있어야 한다. 작업자는 본인에게 배정된 영상만, 검수자는 전체 영상에 접근한다. 같은 영상에 활성 마킹이 이미 있으면 거부한다.

[응답의 배치 트리거 결과] 마킹 저장이 성공하면 마킹 완료 이벤트가 트랜잭션 커밋 이후 잔여 배치(시계열 위탁 → 프레임 추출 → 오토라벨링 → 트랙 보간)를 비동기로 시작한다. 응답의 batchTriggered 는 그 시작이 실제로 개시됐는지를, batchSkipReason 은 개시되지 않았을 때의 사유를 알린다 — 영상을 찾지 못함 · 이미 처리 중이거나 처리가 끝난 영상 · 비식별이 완료되지 않은 영상 · 이미 다른 경로로 큐잉된 영상이 그에 해당한다. 배치가 개시되지 않으면 그 마킹은 종결 처리되며, 배치 개시 여부는 마킹 저장의 성공 여부를 바꾸지 않는다. 두 필드는 선택값이라 판정이 이뤄지지 않은 경로에서는 비어 있다(기존 소비자 하위호환).

[마킹 질문 선택] vrfcEvntQstnSn 은 작업자가 고른 검증 이벤트 질문의 일련번호이며 선택값이다. 값이 없거나 그 영상의 검증 이벤트 유형에 속하지 않는 질문이면 서버가 그 유형의 첫 번째 질문으로 되돌린다 — 화면 입력을 신뢰하지 않으며 400 으로 거부하지 않는다. 질문이 없다고 마킹이 막히지는 않는다. ★고른 질문은 기록에만 쓰이지 않는다 — 추가 질문 축의 위탁 요청 본문(prompt)에 그 문구가 그대로 실려 나가며, 위탁 시점에 조달해 원장에 보관하고 결과 수신 시 재조달하지 않는다. 검증 이벤트 유형이 미수신이면 관제 값이 없으므로 마킹 화면이 유형 선택을 노출하고, 작업자가 유형을 고르면 그 유형의 질문 목록이 따라온다 — 유형이 미수신이어도 마킹에서 고른 질문이 있으면 그 질문을 쓴다. 유형도 선택도 없어 실을 문구를 얻지 못하면 추가 질문 축 위탁만 건너뛰고 묘사 축 위탁은 그대로 나간다. 마킹을 거치지 않는 경로는 언제나 그 유형의 첫 번째 질문을 쓴다. 고를 질문 목록은 영상 단건 조회 응답에서 조달한다.

[검증 이벤트 유형 선택] 관제 인입에서 검증 이벤트 유형을 수신하지 못한 영상에서는 마킹 화면이 유형 선택을 노출하며, 그 영상에서는 유형을 고르지 않으면 마킹을 완료할 수 없다. 근거는 위탁 본문에 싣는 질문 문구가 어느 마킹 방식에서도 반드시 값을 갖는다는 데 있다 — 수동은 작업자가 직접 고르고, 자동은 그 유형의 첫 번째 질문이 자동으로 선택된다. 질문을 고르려면 유형이 먼저 정해져야 하므로 유형 선택은 질문이 성립하기 위한 전제이며, 유형을 비운 채 완료하면 그 영상은 질문도 시계열 메타도 영영 받지 못한 채 종결된다. ★이 필수는 화면 축이고 요청 스키마 축이 아니다 — vrfcEvntTypeCd 는 요청 스키마에서 선택 필드로 두며 required 목록에 올리지 않는다. 관제 값이 있는 영상은 애초에 이 필드를 보내지 않으므로 required 로 올리면 그 영상들의 마킹이 전부 거부된다. 두 축을 섞지 말 것. 거부는 완료 조작 자체를 막는 방식이 아니라 완료를 눌렀을 때 사유를 알리고 제출만 막는 방식이며, 마크가 한 건도 없을 때와 같은 방식이다 — 상세는 화면 사양이 갖는다. 요청이 이 필드를 비운 채 도착해도 서버는 400 으로 거부하지 않으며, 유형도 선택도 없어 실을 문구를 얻지 못할 때의 처리는 위 [마킹 질문 선택] 이 정한 그대로다.
