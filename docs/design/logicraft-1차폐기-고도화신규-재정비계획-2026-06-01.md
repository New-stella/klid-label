## 1. 배경 / 원칙

- 본 프로젝트는 **brownfield 고도화**: 1차(상용·타 개발사·**MariaDB**)를 LogiCraft 베이스라인으로 적재 → 고도화 RFP(영상단위·**PostgreSQL**) 개발 중.
- 현재 ERD가 "어정쩡 정합"으로 1차인데 `dbms=postgresql`로 바뀌고 PJT 컬럼만 부분 마킹돼, **1차/고도화 구분 불명**.
- **재정비 원칙**:
  - **1차 = MariaDB 원형 그대로 + `status=deprecated`** (이력 보존, 손대지 않음)
  - **고도화 = PostgreSQL + `status=draft/approved`, brownfield `new`/`modified`** (현재 코드 기준)
- **진실원**:
  - 1차 원형 → `docs/dev-db-schema-2026-04-23.md` (klid_system@192.168.102.101:13307, MariaDB)
  - 고도화 → `backend/src/main/resources/db/migration/*.sql` (PostgreSQL) + JPA 엔티티

## 6. 실행 순서 / 방법

1. **Phase 1 — 1차 ERD 폐기** (ERD-002/003/005/006/009 + 001): `dev-db-schema`에서 MariaDB 원형 컬럼 추출 → `update_item(data_mode=replace, status=deprecated, dbms=mariadb)`. base_version 확인 필수.
2. **Phase 2 — 공통 ERD 분리** (ERD-004/007/008): 기존을 1차 deprecated로 정리 + 고도화 PostgreSQL ERD 신규 create.
3. **Phase 3 — 고도화 신규 ERD 생성** (§2-C): 코드 마이그레이션 PostgreSQL 컬럼 추출 → 도메인별 `create_item(type=erd, brownfield=new)`.
4. **Phase 4 — domain / domain_feature 정비**: deprecated 확정 + title 정정 + stale 해소.
5. 각 Phase는 **도메인 단위 서브에이전트**로 분담 가능(추출·등록), 단 create/update 값은 진실원(문서/코드)에서만 — **AI 임의 추정 금지**.

## 7. 리스크 / 가드

- **데이터 오염 방지**: 모든 create/update는 dev-db-schema(1차)·코드(고도화)에서 값 추출. 추정 금지.
- **동시성**: update_item base_version = 현재 current_version 일치 필요(불일치 시 재조회).
- **createdBy 주의**: 신규 create는 현재 세션 계정(a35a8f7c)으로 찍힘 — 정상(고도화는 우리 작업).
- **되돌리기**: ERD update 전 현재 data를 백업(get_item 결과 보존) 후 진행.
- **승인 보류**: 본 작업은 draft 정비까지. approved 전이는 사용자 확인 후.
