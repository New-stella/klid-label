## description

소규모 서브시스템 3종 그룹.

(1) 작업배정: AssignmentController(/v1/assignments) → AssignmentService 가 REVIEWER→WORKER 배정·재배정·이력을 처리. 목록은 시간축 단일 정렬이고 필터·집계는 BE 에서 전체 기준으로 처리하며 정렬키는 allowlist 로만 해석한다. ⚠ 미등록 정렬키 응답은 작업목록 strict(400) / 검수목록 lenient(200 폴백) 로 다르며 이는 하위호환 근거에 따른 의도된 비대칭이다.

(2) 포털: ★로드·저장 / 자산 업로드 / 내려받기 축으로 갈린다. PortalLabelController(/v1/portal)→PortalLabelService 가 데이터마트 영상 라벨 Load·사용자별 적재(원본 미수정)를 맡는다 — 조회·저장 응답과 저장 요청이 라벨 마스터 참조와 트랙 식별자를 함께 나르고 화면은 그 둘을 표시하지 않은 채 되돌려 보낸다(편집 수단이 아니라 저장 왕복에서 끊기던 원본 연결을 지키는 장치이며, 트랙 번호 변경·병합은 포털에 두지 않는다). PortalUploadController/PortalTusUploadController/PortalUploadLabelController(/v1/portal/uploads)가 본인 자산 업로드·프레임 추출·수동 라벨링을 맡는다(ADR-013 예외, LS_PORTAL_* 전용·내부 파이프라인과 분리). 업로드 영상은 PortalVideoUploadedEvent(EVT-012) → PortalFrameExtractBridge 로 프레임을 뽑는다. PortalDatamartDownloadController(/v1/portal/datamart)는 본인 작업 데이터 묶음 내려받기를 맡고, 조회 단계(PortalDatamartDownloadTxService)와 산출 단계(PortalDatamartDownloadService)가 트랜잭션 경계로 갈린다 — 산출물은 검수 승인 학습데이터 산출물과 같은 구조라 프레임마다 이미지와 짝을 이루는 어노테이션 문서를 내며, 영상 단위로 라벨을 모아 담던 단일 문서는 두지 않는다. 이미지와 문서가 가리키는 경로는 비식별 기준이고 원본 폴백이 없다.

(3) 관제 통지: ★export 직렬화가 끼어 있다. ReviewApprovedEvent(EVT-006) → DatasetExportBridge 가 export 전량 재생성 → DatasetExportCompletedEvent(EVT-009) → ControlNotifyEventListener 가 받아 ControlNotifyService.sendCompleted→ControlNotifyClient 로 outbound 통지(완료 통지는 디바운스를 거치지 않는다), 실패 시 Fallback 재등록. TaskModifiedEvent 는 TaskModifiedAccumulateListener 가 윈도우에 축적하고, 같은 이벤트가 ReviewRecheckMarkListener 를 통해 재검토 표시(REVLT_YN)를 세워 만료 flush 를 보류시킨다 — 재생성과 수정 통지는 검수자가 그 수정을 다시 승인해 표시가 해제된 뒤 디바운서가 낸다. TaskQueryController(/v1/tasks)는 관제 inbound 조회 API 로, 신고 구간에는 라벨 본문 조회가 412 로 차단된다.

컴포넌트·관계는 실제 생성자 의존성에서 도출.
