## description

작업 목록 화면에서 일어나는 조회·필터링·배정 흐름의 시퀀스 다이어그램. 같은 화면을 두 역할이 공유하지만 조회 경로가 갈린다 — WORKER 는 GET /v1/assignments 로 본인 배정분만 보고, 그 범위는 화면이 아니라 서버가 강제한다(AssignmentService.scopeForActor 가 요청에 실린 workerId 를 버리고 토큰 주체로 고정한다). REVIEWER 는 GET /v1/tasks/board 로 배치 완료 영상 전체를 보며 이 경로는 미배정 영상을 노출하므로 REVIEWER 만 통과한다. 정렬은 시간축 단일 기준이고 정렬 키는 허용 목록으로만 해석한다. 허용 목록 밖 키를 받았을 때 작업 목록은 400 으로 거부하고 검수 목록은 그 키만 버린 뒤 기본 정렬로 200 을 돌려주는데, 두 엔드포인트가 서로 다른 해석 모드를 쓰는 것은 의도된 것이며 하나로 통일하지 않는다. 이벤트 유형 필터는 이벤트 코드를 그대로 받되 표시명이 같은 코드들을 한 그룹으로 확장해 매칭하고, 목록·KPI 집계·필터 옵션이 EventTypeFilterSupport 라는 같은 판정 지점을 통과하므로 셋의 대상 집합이 어긋나지 않는다. KPI 집계는 필터 결과 전체를 세며 현재 페이지 안에서 세지 않는다. 배정은 REVIEWER 만 수행할 수 있고 단건과 일괄이 같은 요청을 탄다 — POST /v1/assignments 가 rawDataIds 배열을 받아 한 트랜잭션 안에서 각 건에 LS_TASK_ALTMNT 행(TASK_TYPE_CD='LABELER')을 넣고 LS_RAW_DATA_STATUS 를 ASSIGNED 로 올린 뒤 LS_TASK_EVNT_LOG 에 ASSIGN 을 남긴다. 재배정은 새 행을 쌓지 않고 기존 행의 작업자만 바꾸며, 누가 누구에게서 누구로 옮겼는지는 LS_TASK_EVNT_LOG 의 REASSIGN 행이 이전 작업자와 함께 보관한다 — 배정 이력 조회가 읽는 것도 이 이벤트 로그 한 곳이다.
