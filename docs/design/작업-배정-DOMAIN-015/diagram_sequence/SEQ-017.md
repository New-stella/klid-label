        asgnSvc-->>asgnCtrl: 검수 대기·검수 중·승인이면 거부한다 — 배정이 그 워크플로의 전제라 풀면 검수 흐름이 주인 없는 상태가 된다
        asgnCtrl-->>reviewer: 409 Conflict — 작업이 진행된 영상은 배정을 풀 수 없고 그래서 제외도 할 수 없다(의도한 귀결)

    alt 허용 목록 밖 정렬 키 / 이벤트 유형 옵션 절단 / 배정 이력 조회

        boardSvc->>exclGate: 옵션 스캔 대상에도 같은 판정을 붙인다 — 목록에 없는 영상의 이벤트 유형이 필터에 남지 않는다
        boardSvc->>evtFilter: foldOptions(scannedCodes, 상한) — 표시명이 같은 코드를 한 옵션으로 접는다
        evtFilter-->>boardSvc: 접은 뒤에도 상한을 넘으면 잘라내고 절단 표식을 세운다(접기 전에 판정하지 않는다)
        boardSvc->>boardCtrl: 옵션 목록 + 절단 표식
        boardCtrl-->>reviewer: 200 OK — 절단 안내 문구를 필터 하단에 노출한다
        reviewer->>asgnCtrl: GET /v1/assignments/{assignmentId}/history
        asgnCtrl->>asgnSvc: getHistory(assignmentId, actor)
        asgnSvc->>asgnSvc: WORKER 면 본인 배정이 아닐 때 차단한다

        asgnSvc-->>asgnCtrl: 이력 응답
        asgnCtrl-->>reviewer: 200 OK
    end

## description

작업 목록 화면에서 일어나는 조회·필터링·배정 흐름의 시퀀스 다이어그램. 같은 화면을 두 역할이 공유하지만 조회 경로가 갈린다 — WORKER 는 GET /v1/assignments 로 본인 배정분만 보고, 그 범위는 화면이 아니라 서버가 강제한다(AssignmentService.scopeForActor 가 요청에 실린 workerId 를 버리고 토큰 주체로 고정한다). REVIEWER 는 GET /v1/tasks/board 로 배치 완료 영상 전체를 보며 이 경로는 미배정 영상을 노출하므로 REVIEWER 만 통과한다. 정렬은 시간축 단일 기준이고 정렬 키는 허용 목록으로만 해석한다. 허용 목록 밖 키를 받았을 때 작업 목록은 400 으로 거부하고 검수 목록은 그 키만 버린 뒤 기본 정렬로 200 을 돌려주는데, 두 엔드포인트가 서로 다른 해석 모드를 쓰는 것은 의도된 것이며 하나로 통일하지 않는다. 이벤트 유형 필터는 이벤트 코드를 그대로 받되 표시명이 같은 코드들을 한 그룹으로 확장해 매칭하고, 목록·KPI 집계·필터 옵션이 EventTypeFilterSupport 라는 같은 판정 지점을 통과하므로 셋의 대상 집합이 어긋나지 않는다. KPI 집계는 필터 결과 전체를 세며 현재 페이지 안에서 세지 않는다. 배정은 REVIEWER 만 수행할 수 있고 단건과 일괄이 같은 요청을 탄다 — POST /v1/assignments 가 rawDataIds 배열을 받아 한 트랜잭션 안에서 각 건에 LS_TASK_ALTMNT 행(TASK_TYPE_CD='LABELER')을 넣고 LS_RAW_DATA_STATUS 를 ASSIGNED 로 올린 뒤 LS_TASK_EVNT_LOG 에 ASSIGN 을 남긴다. 배정의 대상은 작업자뿐이며 검수자 배정 행은 만들지 않는다 — 검수는 배정 없이 전체 대기열에서 집어간다. 재배정은 새 행을 쌓지 않고 기존 행의 작업자만 바꾸며, 누가 누구에게서 누구로 옮겼는지는 LS_TASK_EVNT_LOG 의 REASSIGN 행이 이전 작업자와 함께 보관한다 — 배정 이력 조회가 읽는 것도 이 이벤트 로그 한 곳이다. 이 목록에는 제외 축이 함께 걸린다 — 영상에 제외 표시가 붙으면 작업 목록에서 빠지며, 목록·전체 건수·KPI 집계·이벤트 유형 옵션이 같은 한 곳의 판정을 공유한다. 경로마다 따로 판정하면 한 곳만 빠져도 제외한 영상이 화면에 새기 때문이다. 작업자 축은 배정 행을 기준으로 읽으므로 영상 쪽을 상관 조회해 판정한다. 제외 판정은 조회 조건에만 붙이고 집계의 버킷 판정식은 건드리지 않아 버킷 합과 전체 건수가 계속 맞는다. 제외는 저작도구 화면 시야까지이며 배치 파이프라인·관제 통지·데이터마트 조회 뷰·학습데이터 산출물은 이 판정을 통과하지 않는다. 배정을 되돌리는 수단도 재배정 하나뿐이었는데 해제가 더해졌다 — DELETE /v1/assignments/{assignmentId} 는 요청 본문 없이 배정만 풀고 작업 결과(라벨·이력)는 지우지 않으며, 누가·그 시점 역할·언제가 LS_TASK_EVNT_LOG 에 UNASSIGN 으로 남는다(사유는 받지 않는다). 검수 대기·검수 중·승인 상태의 배정은 해제를 거부하고 반려된 배정은 풀 수 있다. 해제를 취소하는 창구는 없으며 되돌리려면 다시 배정한다. 배정이 있는 영상은 제외가 거부되므로 해제가 제외의 앞단에 있고, 제외된 영상은 배정 대상이 되지 않는다.
