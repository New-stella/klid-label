## description

배정 목록의 이벤트유형 셀렉트 옵션을 중복 없이 오름차순으로 반환한다. 응답 형태는 작업목록의 동일 목적 조회와 같다(화면 공용 컴포넌트).

[인가 축이 조회 범위를 정한다] 검수자는 전체 배정을, 작업자는 본인 배정분만 기준으로 옵션을 받는다. workerId 는 검수자가 특정 작업자를 볼 때만 유의미하며 작업자 요청에서는 무시된다 — 그렇게 하지 않으면 다른 사람의 배정 현황을 옵션 목록으로 엿볼 수 있다.

[페이징이 없다 — 의도된 예외] 코드값 셀렉트 성격이라 화면이 전량을 한 번에 받아야 하고, 무제한 조회는 상한으로 방어한다. 상한을 넘으면 잘라서 반환하되 truncated 로 그 사실을 알린다 — 벌거벗은 배열로 내려주면 절단이 드러나지 않아 '그 유형의 영상이 없다'고 오인하게 된다.

[제외된 영상 배제 — 방어적] 제외 표시가 선 영상은 이 옵션에서도 뺀다(ADR-069). 이 창구는 같은 축의 목록 조회와 조건 조립을 공유한다 — 목록이 제외분을 빼는데 옵션이 빼지 않으면 옵션에서 고른 값으로 필터했을 때 0건이 나온다.

이 창구가 구동하는 대상은 영상 원장이 아니라 배정 행이므로, 제외 판정은 배정 행에 영상을 직접 이어 붙여서 하지 않고 그 영상 쪽을 상관 조회해서 한다 — 직접 이어 붙이면 배정 한 건이 여러 행으로 늘어난다.

★ 그런데 이 축에는 제외된 영상이 구조적으로 나타날 수 없다. 배정이 있는 영상은 제외가 거부되고, 이 축은 배정 행이 있어야 나오기 때문이다. 그럼에도 판정을 붙이는 이유는 거부가 뚫렸을 때의 마지막 방어다 — 비용은 조건 하나뿐이고, 붙이지 않았다가 거부 판정에 구멍이 나면 제외한 영상의 유형이 작업자 화면의 선택지로 샌다. 「도달 불가하니 빼자」로 되돌리지 말 것.

[이번에 건드리지 않는 것] 표시명이 같은 유형코드를 옵션 한 건으로 접는 규칙과 그 대표코드 산출, 절단은 접은 뒤에 판정한다는 순서, 미등록·비규격 코드를 버리지 않는다는 원칙은 그대로다. 인가 축(작업자는 본인 배정분만, 요청의 작업자 지정은 무시)과 응답 형태·상한도 그대로다.
