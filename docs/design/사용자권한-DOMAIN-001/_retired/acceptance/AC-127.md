# 최초 관리자를 만들 경로가 항상 존재한다

## notes

이 기준은 **도달 가능성**을 지킨다. 부트스트랩 창구의 조건이 아무리 옳아도 그 앞의 다른 장치가 요청을 막으면 시스템에 관리자를 만들 경로가 0개가 된다.

실제로 그 교착이 났다. 진입 시 자동 등록이 **같은 요청의 앞단에서** 작업자 역할을 부여했고, 창구는 역할 보유자를 거절했다. 두 장치가 각각은 규정대로였는데 합쳐지자 정규 경로가 사라졌다. 이미 운영 중인 시스템에서는 자동 등록과 무관하게 같은 결과가 난다 — 그곳에는 역할 없는 사용자가 애초에 없다.

★**시험 표본이 이 기준의 절반이다.** 역할 행이 인위적으로 유지되는 표본(역할 코드가 알려진 집합 밖이라 해석이 항상 비어 있는 사용자)으로 이 창구를 치면 자동 등록이 일어나지 않아 **교착이 재현되지 않는다.** 반드시 **저장소에 행 자체가 없는 사용자**로 검증한다. 실제로 그런 표본 교체 때문에 이 결함이 전건 통과 상태로 숨어 있었다.

창이 닫힌 뒤(관리자 1명 이상)에는 역할 보유자를 거절하는 것이 옳다 — 그때는 관리자가 역할을 부여하는 경로가 존재하기 때문이다.

## priority

critical

## scenario

### then

- 둘 다 성공해 관리자가 된다
- 이미 역할이 있던 사용자는 그 역할이 관리자로 교체된다
- 요청 전에 다른 창구를 먼저 호출해 작업자로 자동 등록된 뒤에도 여전히 성공한다
- 관리자가 한 명 생긴 뒤에는 같은 요청이 모두 거절된다
- 창이 닫힌 뒤에는 역할 보유자도, 역할이 없는 사용자도 이 창구로 역할을 얻지 못한다

### when

- 역할 행이 저장소에 없는 내부 사용자가 관리자 패스워드로 자가부여를 요청한다
- 또는 이미 검수자·작업자인 사용자가 같은 요청을 한다

### given

- 시스템에 관리자가 한 명도 없다

## statement

관리자가 0명인 시스템에서는 어떤 내부 사용자든 — 역할이 없든 이미 검수자·작업자든 — 관리자 패스워드로 최초 관리자가 될 수 있다.
