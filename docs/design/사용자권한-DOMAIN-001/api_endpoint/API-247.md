- 실패는 거절(401)과 일시 장애(503) 두 갈래로만 나눈다. 브라우저의 로그아웃·유지 결말이 이 구분에 달려 있다.

## description

관제 채널 화면이 관제 세션을 연장할 때 저작도구 서버가 관제지원 계정 서비스의 갱신 창구를 대신 호출해 새 토큰 쌍을 돌려주는 중계 창구다. 브라우저는 관제 계정 서비스를 직접 부르지 않고 이 창구만 부른다. 호출 대상 연동점은 [[INT-015]] 이고, 저작도구 서버를 경유한다는 결정의 근거는 [[ADR-012]] 다.

★ 저작도구 로그인 검사를 하지 않는다 — access 토큰이 이미 만료돼 요청이 401 로 돌아온 뒤의 재시도 경로에서도 갱신해야 하기 때문이다. security 가 비어 있는 것은 누락이 아니라 사양이다. 자격증명은 요청 본문의 refresh 토큰 하나이며, 그것이 유효한지는 저작도구가 아니라 관제가 판정한다. 관제로 보내는 호출은 연동점 계약대로 그 refresh 토큰을 관제 갱신 창구의 인증 헤더에 싣는다.

★ refresh 토큰은 요청 본문으로만 받는다. 인증 헤더에 refresh 토큰을 실은 요청은 저작도구 인증 필터가 거부한다 — 종류가 refresh 인 토큰은 저작도구 API 인증에 쓰지 않는다([[ADR-063]] ⑦). 이 창구는 로그인 검사를 하지 않으므로 헤더의 토큰에 의존하지 않는다.

★ 호출 대상 주소는 설정이 정한다. 요청이 대상 주소·경로를 바꿀 수단은 없다 — 본문에는 refresh 토큰 외의 입력을 받지 않는다.

★ 관제 주소는 관제 계정 창구 주소 설정(`authoring.control-account.url`)만 쓴다 — 관제 웹서버 또는 계정 창구를 가진 WAS 의 주소이며, 관제 통지 수신처 주소로 대체하지 않는다(폴백 없음). 배포 기본값이 비어 있으므로 관제 채널 배포본은 설치 때 반드시 설정한다. 관리자가 설정 화면에서 바꾼 값은 재기동 없이 다음 호출부터 반영된다. 설정이 비어 있으면 관제를 호출하지 않고 503(일시 장애)으로 끝나며, 관제 장애가 아니라 설정 상태이므로 서킷 실패로 세지 않는다.

폐기(2026-09-14): 관제 통지 수신처 주소 설정([[INT-007]]) 재사용 — 관제는 계정 창구와 데이터셋 창구를 서로 다른 WAS 에 두므로, 한 주소를 나눠 쓰면 WAS 에 직접 연결했을 때 한쪽이 404 가 된다.

★ 관제 통지와는 분리돼 있다. 관제 통지 활성화 토글과 무관하게 동작하므로, 통지 토글이 꺼진 배포에서도 이 창구는 정상 동작한다. 관제 계정 창구로 나가는 요청의 `x-access-token` 헤더에는 요청 본문으로 받은 사용자의 refresh 토큰만 싣고, 관제 통지용 서비스 토큰은 싣지 않는다. 장애 격리(서킷 브레이커)는 관제 통지와도, 로그아웃 중계([[API-246]])와도 따로 둔다 — 갱신 서킷이 열려도 로그아웃 중계는 나간다.

★ 관제 채널 배포본에만 있는 창구다. 포털 채널 배포본에는 이 창구가 없어 404 가 난다 — 포털 채널은 Host 가 세션을 소유하므로 저작도구가 세션을 연장할 일이 없다.

성공하면 관제 응답의 새 access 토큰과 새 refresh 토큰을 그대로 옮겨 돌려준다. 저작도구 서버는 토큰을 저장하지 않는다 — 저장은 브라우저가 관제와 같은 키·같은 형식으로 한다.

★ 비멱등이다. 호출마다 관제가 refresh 토큰을 교체하므로 같은 refresh 토큰으로 다시 부르면 결과가 달라진다. 저작도구 서버는 관제 호출을 자동 재시도하지 않는다.

실패는 두 갈래로만 나뉜다 — 관제가 거절했으면 401, 관제에 닿지 못했거나 응답을 해석할 수 없거나 관제 계정 창구 주소가 비어 관제를 호출하지 않았으면 503 이다. 브라우저는 401 을 「거절」로 받아 즉시 로그아웃하고(단 저장소를 다시 읽어 다른 탭이 이미 갱신했으면 그 토큰으로 계속한다), 503 을 「일시 장애」로 받아 현재 토큰을 유지한다. 두 갈래를 섞으면 일시 장애에 사용자를 내보내거나 거절된 세션을 붙잡는다. 이 결말의 수용기준은 [[AC-1104]] · [[AC-1106]] 이다.

보안 — 요청과 응답의 토큰 원문을 로그에 싣지 않는다. 관제가 돌려준 오류 문구를 응답에 그대로 싣지 않고 오류 코드로만 구분한다.

★ 성공 판정은 sessionToken 하나로 한다. 관제가 error 0 과 session_token 은 주면서 refresh_token 을 주지 않는 경우가 성공에 포함되며, 그때 응답의 refreshToken 은 null 이다(키는 남는다). 그 세션은 더 갱신할 수 없으므로 브라우저는 새 access 토큰만 저장하고 refresh 칸을 비운 뒤 만료 시각에 로그아웃한다 — 일시 장애로 보아 갱신을 되풀이하지 않는다. 결말 수용기준은 [[AC-1106]] 이다.
