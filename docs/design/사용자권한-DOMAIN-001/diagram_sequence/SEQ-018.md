## description

사용자 관리 화면에서 REVIEWER 가 사용자를 조회하고 역할을 바꾸는 흐름의 시퀀스 다이어그램. 이 시스템은 자체 로그인 화면이나 자체 인증 엔드포인트를 두지 않는다 — 관제서버가 발급한 JWT 를 인계받아 JwtAuthenticationFilter 가 서명·발급자·만료를 검증하고 주체·채널·이름 클레임만 읽는다. 인가 역할은 토큰의 역할 클레임에서 읽지 않고 저작도구가 소유한 LS_USER_ROLE 에서 다시 조회하며, 그 값이 인가의 단일 진실원이다. 사용자 행은 관리 화면이 만들지 않는다 — 역할 자가부여 시점의 원자 upsert 가 유일한 생성 지점이라, 역할을 받은 적 없는 사람은 이 목록에 나타나지 않는다. 자가부여는 관리자 공유 패스워드로 보호되고 시도 횟수가 제한되며 REVIEWER 와 WORKER 를 부여할 수 있고 PORTAL_USER 는 거절한다. 따라서 관리자 지위는 별도 역할이 아니라 그 공유 패스워드를 아는 사람이며, 시스템에 ADMIN 역할은 존재하지 않고 관리 권한은 REVIEWER 에 통합되어 있다. 목록 조회는 이름·아이디·전자우편 부분일치와 역할 필터를 받고 정렬은 사용자 번호 오름차순으로 고정되어 호출자가 바꿀 수 없다. 역할 필터는 조회된 페이지 안에서 적용되므로 필터를 걸면 전체 건수가 실제 일치 건수보다 클 수 있다. 역할 변경은 값을 화이트리스트로 재검증한 뒤 원자 upsert 로 반영하고, 현재 값과 같으면 갱신을 건너뛴다. 바뀐 경우에는 커밋 이후에 역할 캐시를 무효화한다 — 커밋 전에 지우면 동시 요청이 옛 역할을 다시 캐시에 담아 권한 강등이 즉시 반영되지 않는다. 계정 활성 여부는 외부 시스템이 소유한 값이라 이 화면에서는 읽기 전용으로만 보인다.
