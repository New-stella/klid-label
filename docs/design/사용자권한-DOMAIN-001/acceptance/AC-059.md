# 역할 변경의 효력은 커밋된 뒤에 생긴다

## notes

커밋 전에 캐시를 비우면 동시에 들어온 요청이 아직 커밋되지 않은 옛 값을 다시 캐시에 채워, 변경이 저장됐는데도 옛 역할로 판정되는 상태가 남는다. 이 기준의 축은 무효화를 하느냐가 아니라 언제 하느냐다.

## priority

high

## scenario

### then

- 커밋 전에는 캐시가 비워지지 않는다
- 커밋된 뒤에 들어오는 요청부터 낮춰진 역할로 판정된다

### when

- 그 변경이 커밋되기 전에 같은 사용자의 다른 요청이 들어온다

### given

- 검수자가 어떤 사용자의 역할을 낮추는 변경을 저장한다
- 검수자가 관리자 패스워드로 연 유효창이 아직 유효하다

## statement

역할 변경에 따른 인가 역할 캐시 무효화는 변경이 커밋된 뒤에 일어나며 커밋 전에는 캐시를 비우지 않는다.
