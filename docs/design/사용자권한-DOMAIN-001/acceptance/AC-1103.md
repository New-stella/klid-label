# 포털 서버간 연동 인증 거부 — 축 격리와 사전 공유 키 축 두 창구의 키 거부·미설정 시 닫힘 (negative)

## notes

연동의 인증 축과 창구 구성과 어휘는 [[INT-014]] 가 소유한다. 이 수용기준은 그 규칙이 지켜지는지를 검증할 뿐 계약을 복제하지 않는다. [갱신] 사전 공유 API 키 축의 창구는 배포본 정리 삭제 트리거 수신과 일일 저작 집계 제공 둘이고 둘이 같은 키를 쓰며, 그 두 창구에 대해서는 구 서술의 「기존 인증 인계 축의 대칭 서명키를 그대로 쓴다」가 해당하지 않는다. 사용자 컨텍스트 축에 대해서는 그 서술이 그대로 유효하다. 어느 축이든 값 자체는 배포 시점 설정으로 남아 있다 — 설정값이라 검증 자체를 막지 않는다.

## priority

critical

## scenario

### then

- 사용자 주체 토큰만으로는 사전 공유 키 축의 두 창구 어느 쪽에도 진입하지 못한다
- 키가 실리지 않은 요청은 두 창구 어느 쪽에서도 거부된다
- 설정된 값과 다른 키를 실은 요청은 두 창구 어느 쪽에서도 거부된다
- 사전 공유 키가 설정되지 않았으면 어떤 요청으로도 두 창구 어느 쪽에도 진입하지 못한다
- 키 비교에 걸리는 시간이 키 값에 따라 갈리지 않으며 이는 두 창구 모두에 해당한다
- 사전 공유 키 축의 두 창구에는 주체 축 판정이 없어 축 불일치라는 사유로 거부되는 경우가 없다
- 토큰이 없거나 서명이 맞지 않거나 만료됐으면 인증 실패로 거부한다
- 인증 실패와 축 불일치는 서로 다른 응답으로 구분된다
- 거부 응답에 내부 경로와 예외 흔적과 저장 구조가 없다

### when

- 사용자 주체 토큰만 실어 사전 공유 키 축의 두 창구를 각각 부른다
- 키를 싣지 않고 사전 공유 키 축의 두 창구를 각각 부른다
- 설정된 값과 다른 키를 실어 사전 공유 키 축의 두 창구를 각각 부른다
- 사전 공유 키를 설정하지 않은 채로 사전 공유 키 축의 두 창구를 각각 부른다
- 토큰 없이 또는 서명이 맞지 않는 토큰으로 포털 사용자 채널의 창구를 부른다

### given

- 포털 사용자 채널의 창구는 사용자 주체 토큰으로 부른다
- 사전 공유 API 키 축의 창구는 배포본 정리 삭제 트리거 수신과 일일 저작 집계 제공 둘이며 둘 다 같은 키로 부르고 그 키에는 주체 클레임이 없다
- 두 축의 창구가 서로 다른 경로 접두 아래 있다
- 사전 공유 키 값이 배포 설정으로 주어진다

## statement

포털 채널의 창구는 인증 축이 갈리며, 각 축의 거부는 그 축이 실제로 쓰는 수단으로 판정한다.

사용자 컨텍스트 축 — 포털 사용자 채널의 창구는 사용자 주체 토큰으로 부른다. 그 토큰으로 다른 축의 창구를 부르면 거부한다. 토큰 주체를 자원 소유자와 견주어 접근을 가르는 창구에 그 비교가 성립하지 않는 토큰이 닿으면 비교가 의미를 잃은 채 통과하므로, 축이 다른 토큰은 창구에 닿기 전에 막는다.

사전 공유 API 키 축 — 이 축의 창구는 배포본 정리 삭제 트리거 수신([[API-244]])과 일일 저작 집계 제공([[API-243]]) 둘이며 둘 다 같은 사전 공유 API 키로 부른다. 아래 규칙은 두 창구에 똑같이 성립하므로 창구별로 따로 적지 않는다 — 이 축에 창구가 더 늘어도 같은 자리가 다시 비지 않게 하려는 것이다. 키가 실리지 않았거나 키 값이 다르면 거부한다. 키가 설정되지 않았으면 그 창구는 어떤 요청으로도 열리지 않는다 — 값이 없을 때 열리는 것이 아니라 닫히는 방향이어야 한다. 키 비교는 걸리는 시간이 값에 따라 달라지지 않는 방식으로 한다. 비교 시간이 값에 따라 갈리면 그 차이가 키를 한 자리씩 맞혀 나가는 단서가 된다.

[갱신] 이 축의 창구에는 주체 축 판정이 없다. 그 키에는 주체 클레임이 없기 때문이다. 다만 두 창구의 경위는 서로 다르다 — 정리 삭제 트리거 수신은 주체 클레임을 갖는 토큰에서 이 수단으로 바뀐 것이고, 일일 저작 집계 제공은 미확정이던 수단이 이 축으로 확정된 것이라 판단이 뒤집힌 것이 아니다. 그래서 구 서술의 「시스템 주체 토큰이 포털 사용자 채널의 창구에 들어가지 못한다」와 「시스템 계정 주체 식별자 목록이 비면 아무도 시스템 주체가 아니다」는 이 축의 창구 기준으로 검증할 대상 자체가 사라졌다. 격리를 푼 것이 아니라 격리할 대상이 없어진 것이다 — 그 규칙이 막던 위험은 시스템 계정 토큰이 포털 사용자 권한을 얻는 것이었는데, 이 축의 창구에서는 그 토큰 자체가 쓰이지 않기 때문이다. 값이 없을 때 닫힌다는 성질은 목록 축에서 키 축으로 그대로 이어진다.

인증이 성립하지 않아 거부하는 것과 인증은 됐으나 축이 달라 거부하는 것은 서로 다른 사유이므로 같은 응답으로 뭉뚱그리지 않는다. 거부 응답에 내부 경로와 예외 흔적과 저장 구조를 싣지 않는다.

### notes

2026-09-09 라운드 — 검증 범위를 창구 하나에서 사전 공유 API 키 축 전체로 넓혔다. 작성 시점에는 일일 저작 집계 제공 창구의 인증 수단이 미확정이라 범위에 넣을 근거가 없었고, 포털 2차 회신으로 그 창구가 정리 삭제 트리거 수신과 같은 수단·같은 키로 확정되면서 근거가 생겨 넓힌 것이다. 범위를 창구별이 아니라 축 기준으로 적은 것은 이 축에 창구가 더 늘어도 같은 자리가 다시 비지 않게 하려는 것이다. 사용자 컨텍스트 축의 주체 격리 검증은 저작 현황 요약 창구에서 그대로 유효하므로 함께 유지한다 — 두 축이 한 수용기준 안에 공존하는 것이 현재 사양이다.

[갱신] 2026-09-09 후속 — 추적 축의 하위 작업 둘이 본문과 다른 말을 하고 있어 성격 표기로 닫았다. 하나는 폐기된 주체 목록 축이 본문에서만 표기되고 하위 작업에는 살아 있던 것이고, 다른 하나는 채널 축 거부가 포털 채널 배포본에서는 성립하지 않게 된 것이다. 지금 한 이유는 채널 판정 축 결정의 전파 표식이 네 차례 지워져 상기시켜 줄 장치가 남아 있지 않았기 때문이다 — 표식에 기대지 못하므로 그 결정과 이 수용기준을 직접 대조해 어긋난 자리를 찾아 닫았다. 본문과 시나리오는 이미 정합해 손대지 않았다.
