# 관제 통지 x-access-token 은 발송 시점에 관제 규칙으로 발급된다

## notes

근거: ADR-063 v4 결정 ⑥, CO-20260905-관제통지-토큰-발송시점발급 §3, 구현 ControlNotifyTokenProvider(발송 시점 ExchangeFilterFunction 동적 발급), QA HS256 실단언, 246 실왕복 notify-completed=422(인증 통과)·무토큰=401.

## priority

high

## scenario

### then

- 각 요청의 x-access-token 은 발송 시점에 새로 발급된 JWT 다
- 토큰 헤더/클레임이 alg=HS256, iss=klid-auth, exp=now+token-ttl-seconds(기본 300s, 미래)를 만족한다
- 토큰은 공유 JWT_SECRET 로 HMAC 서명돼 있다
- 두 통지의 토큰 문자열이 서로 다르다(jti 고유)
- 관제 실왕복에서 notify-completed 는 422(인증 통과)이고 무토큰 요청은 401 이다

### when

- 저작도구가 notify-completed 와 notify-updated 를 각각 발송한다

### given

- 관제 통지가 활성화되어 있다(authoring.control-notify.enabled=true)
- 정적 토큰 override(authoring.control-notify.token)가 설정돼 있지 않다
- 공유 서명 시크릿(JWT_SECRET)이 설정돼 있다

## statement

관제 아웃바운드 통지(notify-completed/notify-updated)의 x-access-token 은 발송 시점에 매번 새로 발급되며 alg=HS256(HS512 아님)·iss=klid-auth·exp=now+token-ttl-seconds(설정, 기본 300s, 미래)·공유 JWT_SECRET HMAC 서명을 만족한다.
