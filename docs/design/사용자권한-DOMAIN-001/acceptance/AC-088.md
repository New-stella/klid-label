# 역할이 배정되지 않으면 인증을 통과해도 기능에 닿지 못한다

## notes

인증 여부만 요구하는 통제는 이 사용자를 막지 못한다 — 토큰이 유효하면 역할이 없어도 인증은 통과하기 때문이다. 그래서 통제 조건에 인증 여부만 두는 것은 열어 두는 것과 같고, 역할을 함께 요구해야 닫힌다. 새 경로를 추가할 때 이 구분을 놓치기 쉬워 기준으로 못박는다.

## priority

critical

## scenario

### then

- 거부된다
- 인증을 통과했다는 이유만으로 통과하는 경로가 없다

### when

- 아무 기능이나 호출한다

### given

- 토큰은 유효하지만 저작도구에 역할이 배정되지 않은 사용자가 있다

## statement

인증은 통과했으나 역할이 배정되지 않은 사용자는 어떤 기능에도 닿지 못하며, 접근 통제는 인증 여부만 요구하지 않고 반드시 역할을 요구한다.
