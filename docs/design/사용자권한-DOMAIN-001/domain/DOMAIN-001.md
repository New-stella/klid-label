## description

사용자 식별·역할 기반 접근제어(RBAC)·메뉴별 접근 권한을 담당하는 도메인. 영상/작업 단위 권한 배정(REVIEWER→WORKER 할당)의 실현체는 DOMAIN-015(작업 배정)에 있다 — 이 도메인은 그 배정에 쓰이는 역할·권한 축만 정의한다.

[인증 — 독립 로그인 UI 없음] 저작도구는 자체 로그인을 가지지 않고 관제서버(내부)·포털서버(외부)가 발급한 JWT 를 인계받아 검증한다(토큰 필터 → 클레임 추출 → 보안 컨텍스트 적재 순으로 처리). 토큰 인계 수단은 채널마다 갈린다(ADR-012) — 관제 채널은 호스트와 동일 출처를 공유하므로 브라우저 스토리지로 JWT 를 인계받고, 포털 채널은 Host 가 주입한 인계 창구에서 토큰을 얻어 API 호출 시 전용 요청 헤더로 실어 보내며 접근 토큰을 브라우저 저장소에 두지 않는다(창구 규약은 INT-013 이 소유한다). URL 쿼리파라미터 전달은 어느 채널에서도 쓰지 않는다. 두 채널 모두 동일 발급 서버라 검증 로직은 단일이고, role + channel 클레임으로 권한을 분기한다. 세션 만료 시 각 상위 시스템 로그인 페이지로 리다이렉트한다.
(1차 SweetK 시스템의 GPKI 연동은 2차 구조가 아니다 — brownfield 맥락으로만 유효.)

[관리 기능 진입 — 인계 위에 가산되는 자체 유효창] 인계 토큰이 준 역할만으로는 관리 기능의 쓰기에 이르지 못한다. 관리자 공유 패스워드를 대조해 그 사람에게 잠깐 열리는 단기 유효창이 함께 요구되며, 이것이 이 도구가 스스로 발급·검증·만료시키는 유일한 자체 세션이다. 유효창은 역할을 올리지 않는다 — 인가는 대체되지 않고 가산되므로 인계 토큰의 역할 권한은 그대로 필요하다. 조회에는 요구되지 않는다. 대조하는 자격은 운영 중에 교체할 수 있고, 교체하면 그 전에 발급된 유효창이 모두 무효가 된다.

[역할 — 관리자·검수자·작업자·포털회원] ADMIN(관리자) · REVIEWER(검수자) · WORKER(라벨링 작업자) · PORTAL_USER(포털 회원)을 둔다(ADR-055). 계층은 관리자에서 검수자로 가는 한 단계뿐이다 — 관리자가 검수자 권한을 물려받아 검수·배정을 그대로 수행하므로 겸직을 위해 계정을 둘 가질 필요가 없다. 작업자를 계층에 넣으면 작업자 전용으로 열린 자리에 관리자·검수자가 흘러들고, 포털 회원을 넣으면 채널이 달라 외부 채널 사용자가 내부 권한을 얻으므로 그 둘은 계층에 넣지 않는다. 관리 화면 주소는 소유 역할로 갈린다 — 관리자 소유는 /admin/*, 검수자 소유는 /manage/*. 1차의 '업로더' 역할은 폐기됐다 — 영상 1차 적재는 사람이 올리는 것이 아니라 관제 인입이고(ADR-042), 생성 AI 업로더 검토는 외부화됐다(ADR-004).

[역할축의 단독 소유자] 역할은 저작도구 소유 테이블 LS_USER_ROLE(V75)가 단독으로 갖는다. 관제 공유 계정권한 테이블 2종은 런타임 참조 0 인 죽은 테이블이어서 V165 로 삭제됐다.

[★사용자 마스터 — 인증 통과 시 작업자로 자동 등록 (ADR-055)] 기존엔 관제 공유 테이블을 조인해 사용자명을 얻었으나, 그 테이블을 채우는 코드가 양쪽 어느 곳에도 없어 사실상 비어 있었다. 앞으로는 인증을 통과한 내부 채널 진입자에게 역할이 없으면 그 시점에 사용자 행과 작업자 역할을 만든다. 이미 부여된 역할은 덮어쓰지 않는다 — 관리자가 지정한 역할이 되돌려지면 안 되기 때문이다. 이로써 배정하려면 대상자가 먼저 역할을 자가부여해야 목록에 뜨던 제약이 함께 풀린다. 사용자 번호는 인계 토큰의 주체 값에서 오므로 위조할 수 없고, 계정 표시값(계정 ID·이름)은 요청으로 전달되는 표시용 값이라 위조해도 자기 행 이름만 바뀐다.

[★자가부여는 관리자 부트스트랩 전용 (ADR-055)] 역할 자가부여 창구는 관리자가 0명일 때만 열리고 부여 역할은 관리자로 고정된다 — 요청이 다른 역할을 지정해도 결과를 바꾸지 못하며, 관리자가 한 명이라도 생기면 창구가 닫혀 그 뒤에는 관리자 패스워드를 알아도 역할을 얻을 수 없다. 창이 열려 있는 동안에는 이미 역할을 가진 사람도 관리자가 될 수 있다 — 그 완화가 없으면 최초 관리자를 만들 사람이 아무도 없다(진입 시 자동 등록이 같은 요청에서 작업자 역할을 부여해 뒤이은 판정에 걸린다). 마지막 관리자의 강등·비활성은 거부한다 — 관리자가 0명이 되면 그 창이 다시 열리기 때문이다. 이후 역할 부여는 관리자가 사용자 관리에서 관리자·검수자·작업자·포털 중 하나로 지정한다. 잔여 위험은 인지·수용한다 — 최초 부트스트랩 1회에 한해 관리자 패스워드를 아는 사람이 관리자가 되고, 관리자를 전부 잃으면 저장소를 직접 고치는 것이 유일한 복구 경로다.

## ubiquitous_language

### [1]

- **term**: 검수자(REVIEWER)
- **meaning**: 작업 결과를 검토해 승인/반려하며 작업 배정·시스템 설정·라벨 마스터 관리 권한을 보유하는 역할. 사용자 관리는 이 역할에 없다 — 관리자가 소유한다. UI 호칭은 '검수자'로 통일하고 검수자 소유 관리 화면 URL 은 /manage/*

### [2]

- **term**: 라벨링 작업자(WORKER)
- **meaning**: 배정된 영상의 프레임에 라벨링을 수행하고 검수를 제출하는 역할

### [3]

- **term**: 포털 회원(PORTAL_USER)
- **meaning**: 데이터마트 영상 선택·기존 라벨 확인·본인 자산 업로드와 수동 라벨링을 수행. 오토라벨링·검수·버전관리는 없다

### [4]

- **term**: 인계 토큰
- **meaning**: 관제·포털이 발급해 저작도구로 넘겨주는 JWT. 인계 수단은 채널마다 달라 관제 채널은 브라우저 스토리지, 포털 채널은 Host 가 주입한 인계 창구를 쓴다. 저작도구는 검증만 하고 발급하지 않는다

### [5]

- **term**: 역할 클레임
- **meaning**: 관리자가 0명일 때만 열리는 부트스트랩 창구. 관리자 패스워드를 대조해 자신에게 관리자 역할을 부여하며, 관리자가 한 명이라도 생기면 닫힌다(ADR-055)

### [6]

- **term**: 작업 배정
- **meaning**: REVIEWER 가 WORKER 에게 영상 단위로 작업을 할당하는 행위(별도 배정 담당자 역할 없음)

### [7]

- **term**: 관리자(ADMIN)
- **meaning**: 관리 기능을 소유하는 역할. 사용자 관리에서 다른 사용자에게 관리자·검수자·작업자·포털 역할을 지정한다. 검수자 권한을 계층으로 물려받아 검수·배정도 그대로 수행한다. 관리 메뉴는 역할로 갈려 검수자에게는 보이지 않는다. 관리자 소유 관리 화면 URL 은 /admin/*
