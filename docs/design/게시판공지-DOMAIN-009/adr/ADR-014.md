# 게시판(공지·가이드라인) 재도입 — ADR-011 번복, v2 신규 재구현

## context

ADR-011(2026-06-01)은 게시판·공지 기능을 고도화 범위 외로 폐기했다. 그러나 운영 관점에서 작업 규칙·라벨링 가이드라인을 도구 내에서 전달할 채널 부재가 확인되어, R1 요구사항 외 추가 결정으로 게시판(공지·가이드라인)을 재도입했다(2026-06-05). 폐기 결정의 번복이므로 본 ADR로 정형화하고 ADR-011을 supersede 한다.

## deciders

- ck.park (프로젝트 담당)

## decision

### chosen_option

v2 신규 재구현 (채택)

### justification

가이드라인 전달은 라벨링 품질에 직결되는 운영 요구이며, v1 복원은 권한·DB 컨벤션 충돌로 부적합. v1 테이블(LS_NTC_BBS/LS_ATCH_FILE, ERD-006)은 계속 미사용(폐기 유지)하고 v2 신규로 재구현한다. R1 외 추가 임을 산출물(위키 v1-gap 체크리스트)에 명시한다.

## decision_drivers

## considered_options

### 폐기 유지 (외부 채널로 공지)

**cons**:

- 작업 맥락 밖 전달 — 가이드 접근성 저하
- 이력·첨부 관리 불가

**pros**:

- 범위 최소화 유지

- **description**: ADR-011 유지, 공지는 메신저·이메일 등 외부 채널 의존

### v1 게시판 복원 (LS_NTC_BBS 재사용)

**cons**:

- v1 스키마가 ADMIN 권한 모델 기반 — v2 REVIEWER 통합(ADR-003)과 충돌. ⚠ 이 비교 근거가 인용한 v2 권한 모델은 뒤집혔다 — ADR-055 가 ADR-003 을 대체해 관리자 역할(ADMIN)을 다시 두었으므로 이 충돌 사유는 현재 성립하지 않는다. 당시 비교 근거로 남겨 둔다.
- MariaDB 원형 컬럼 컨벤션 불일치(ADR-010)

**pros**:

- 기존 스키마 활용

- **description**: 1차 테이블·화면(SKKLID-UI-02-03/03-06) 그대로 복원

### v2 신규 재구현 (채택)

**cons**:

- R1 외 범위 추가

**pros**:

- v2 권한·컬럼 컨벤션 정합
- 발행 상태로 WORKER 노출 제어
- 첨부 보안(확장자 allowlist·UUID 저장명)

- **description**: LS_NOTICE/LS_NOTICE_ATTACH 신규 테이블(V56) + REVIEWER 전용 작성·DRAFT→PUBLISHED 발행 상태·첨부 UUID 안전 저장
