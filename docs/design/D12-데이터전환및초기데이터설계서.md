# D12 데이터 전환 및 초기데이터 설계서

> **ID 표기 규칙(공통)**: 본 산출물이 참조하는 모든 ID(KLID-AT-DB/TB/EN/ERD 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `TB-001`) 약식 표기 금지. 범위는 시작 ID만 전체형으로(예: `KLID-AT-TB-001~039`). ※ 요구사항(RQ-SFR-NN-NN)·Flyway 버전(V1~V77) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 초기 데이터 구축 시 단시일에 대량의 데이터를 이행함에 있어 신속하고 안정적인 데이터 이행을 위하여 체계적인 절차를 수립하여 구축 시 발생할 문제점을 사전에 차단하기 위한 계획을 수립한다.

## 작성 방법
> 1차 사업(레거시 MariaDB)에서 2차 사업(PostgreSQL)으로 이관되는 **영상·라벨 데이터 전환**과, 신규 구축 스키마(LS_*)에 초기 적재되는 **코드성·설정 데이터**를 구분하여 계획을 수립한다. 전환 대상 데이터는 업무그룹(영상/프레임/라벨/상태/배정/이슈/증강)별로 매핑·검증하고, 전체 전환 완전성을 STEP 5 검증으로 확인한다.

## 1. 개요

### 1.1 목적
1차 사업에서 축적된 **영상 목록과 라벨링 결과**를 2차 저작도구(PostgreSQL)로 손실 없이 이관하고, 신규 구축 스키마에 서비스 개시에 필요한 **코드성·설정 초기 데이터**를 안정적으로 적재하기 위한 전환 대상·매핑·절차·검증·비상대책을 정의한다.

### 1.2 범위
1차 현행 저작도구 자료(영상·프레임·라벨)를 원상태(순수데이터) 또는 가공(좌표 포맷 변환·단위 변환·차원 축소)을 거쳐 2차로 가져오는 자료를 포함한다. 백업 이력 누적분(`LS_DATA_LBL_HSTRY` 168만), 공용 계정(MNG), 시계열 메타(v1 실적 0건)는 전환 범위에서 제외한다.

### 1.3 참조문서

| 시스템 | 구분 | 문서명 | 용도 |
|--------|------|--------|------|
| 현행(v1) | 전환분석 | `docs/v2-wiki/23-v1-v2-db-migration.md` | 실DB 검증 컬럼 매핑·건수·GAP 정책 정본 |
| 현행(v1) | DB현황 | v1 실DB 조사 결과(wiki/23 §0~1) | 전환 원천 스키마·테이블·건수 |
| 신(v2) | 데이터설계 | D8 엔티티관계모형설계서 / D9 데이터베이스설계서 | 신 스키마 테이블 ID·컬럼·제약 |
| 신(v2) | 스키마정본 | `backend/.../db/migration/V*.sql` | 신 스키마·초기데이터 구조 정본(충돌 시 코드 우선) |
| 전환도구 | 절차 | `docs/migration/v1-to-v2/README.md` | 폐쇄망 전환 Runbook(STEP 0~5) |
| 전환도구 | 프로그램 | `01_export_mysql.sh` / `02_load_transform.sql` / `03_verify.sql` | 추출·변환·검증 |
| 초기데이터 | 시드 | `deploy/onprem/scripts/seed-mng-event-type.sh` | 온프렘 독립 DB용 이벤트 타입 초기 적재 |

## 2. 중점 목표와 구축 전략

### 2.1 중점 목표
- **라벨 손실 0**: v1 라벨 결과 전량을 좌표·타입·트랙 정보 보존하여 이관(무매핑 클래스는 자동 신규 추가, 가드로 조용한 손실 차단).
- **차원 축소 정합**: v1 프로젝트(`LS_PJT`) 단위 → v2 영상(`RAW_SN`) 단위 collapse 시 상태·배정을 정확히 재구성.
- **멱등·롤백 보장**: 전환 프로그램은 단일 트랜잭션으로 실패 시 전체 롤백, 오프셋 PK로 재실행·정리 가능.
- **폐쇄망 무결성**: 인터넷·외부 라이브러리 없이 표준 클라이언트(`mysql`+`psql`)만으로 전 과정 수행.

### 2.2 구축 전략

| 제약 | 대응 |
|------|------|
| 인터넷 없음 / pip·apt 불가 | `pgloader`·Python 드라이버 미사용 — **`mysql`+`psql` 표준 클라이언트만** |
| 에어갭(망분리) | 중간 산출물을 **TSV 파일**로 떨궈 승인 반입(USB 등)으로 이동 |
| 크로스 엔진(MySQL→PG) | 단일 SQL 직접 조인 불가 → **PG 스테이징 적재 후 PG SQL로 변환** |
| 실데이터 상이 | 라벨 클래스·건수가 환경마다 다름 → 변환 SQL은 값 하드코딩 없이 스테이징에서 유도, **의미 매핑만 운영자 검토** |

### 2.3 구축 방법
5단계 파이프라인: **① v1 export(TSV) → ② 파일 반입 → ③ PG 스테이징 적재 → ④ 변환·적재 → ⑤ 검증**. 초기 데이터는 신규 스키마 구축(Flyway 마이그레이션) 시점에 SQL로 함께 자동 적재(§6.2).

| 저작도구 | 증강 | 8 | (증강) | LS_DATA_AUG | 원천 LS_DATA_AUG, 경로 컬럼 부재→경로 손실 |

> 테이블 ID(KLID-AT-TB-NNN)는 D9 §3 명세를 정본으로 참조한다.

## 5. 전환 상세 절차

### 5.1 데이터 전환 작업순서

```
전환대상 선정
  → 신·구 데이터 매핑(§5.3)
  → 전환 프로그램 설계·구현·시험(export/transform/verify)
  → v1 대상 데이터 추출(TSV) 및 파일 반입
  → PG 스테이징 적재 + 변환·적재(단일 트랜잭션)
  → 검증 및 오류처리(03_verify + 화면 역렌더 대조)
  → (FAIL 시) 롤백·원인 교정·재수행
```

#### 5.3 신·구 데이터 매핑 작업

데이터 매핑 내역서(핵심)는 신시스템(항목명·타입) ↔ 현행시스템(테이블ID·테이블명·항목명·타입) ↔ 전환내용(구분·전환기준) 형태로 작성한다. 상세는 wiki/23 §1~2 정본. 주요 항목은 다음과 같다.

**업무시스템: 저작도구 / 테이블ID: KLID-AT-TB-001 / 테이블명: LS_DATA_RAW(영상)**

| 신시스템 항목명 | 타입 | 현행 테이블ID | 현행 항목명 | 타입 | 구분 | 전환기준 |
|------|------|---|------|------|:---:|------|
| vms_clip_id | VARCHAR NOT NULL UK | - | (없음) | - | 신규 | 합성키 `'LEGACY-'‖DATA_RAW_SN`(GAP①, UK 충돌 0·출처추적) |
| vms_cctv_id | VARCHAR NOT NULL | LS_DATA_RAW | VMS_CCTV_ID | (대부분 NULL) | 전환 | NULL→기본값 `'UNKNOWN'` |
| raw_file_path_nm | VARCHAR(500) | LS_DATA_RAW | RAW_FILE_PATH | VARCHAR(1000) | 전환 | MOVE(⚠ 500자 초과분 확인) |
| vdo_len_sec | INT(초) | LS_DATA_RAW | VDO_LEN | INT(ms) | 전환 | **÷1000**(v2 계약, 직접복사 시 1000배 오적재) |
| vdo_len_ms | INT(신설 V67) | LS_DATA_RAW | VDO_LEN | INT(ms) | 신규 | 원본 ms 보존(이관본만) |
| prvc_type_cd | VARCHAR(16) NOT NULL | - | (없음) | - | 신규 | 기본값 부여 |
| data_stts_cd | VARCHAR(32) NOT NULL | LS_PJT_DATA_STTS | (상태 별도) | - | 전환 | 확장 A로 실상태 매핑 |
| (버려짐) | - | LS_DATA_RAW | FILE_FMT/FPS/FRM_CNT/WDTH/HGT/GPS/CODEC 등 | - | 삭제 | 이관 안 함(GAP③ — 공용 MNG 진실원) |

**테이블명: LS_DATA_LBL(라벨 결과) — 좌표 포맷 변환(Critical)**

| 타입 | v1 `POINT`(실측) | v2 `point_cn`(실측) | 구분 | 전환기준 |
|------|------|------|:---:|------|
| BBOX | `{"x":..,"width":..,"y":..,"height":..}` | `[[x1,y1],[x2,y2]]` | 전환 | `[[x,y],[x+width,y+height]]` |
| POLYGON | `[{"x":..,"y":..}, …]` | `[[x,y], …]` | 전환 | 각 `{x,y}`→`[x,y]` |

> v1/v2 좌표 JSON 표현이 다르므로 단순 복사 시 캔버스에서 깨진다. 라벨당 1회 파싱→재직렬화하며, 검증은 §5.6 역렌더 대조.

**GAP 정책(확정)**

| GAP | 대상 | 정책 |
|:---:|------|------|
| ① | `vms_clip_id` | 합성키 주 경로(라벨 영상 99.7%가 관제 미연결 큐레이션셋). 조인되는 6~17건만 선택적 실 CLIP_ID |
| ② | 라벨 클래스 | 의미 매핑 + v2에 없는 클래스 자동 신규 추가, **타입(BBOX/POLYGON) v1 유지**. 손실 0. 매핑 누락 시 02 §5-b 가드가 트랜잭션 ABORT |
| ③ | 영상 메타 | 코덱·해상도·FPS·GPS 등 **이관 안 함**(공용 MNG 진실원) |
| ④ | 증강 경로 | v2에 파일경로 컬럼 부재 → `AUG_FILE_PATH` 손실(발생 사실만 보존) |

> **ID 매핑**: 영상·라벨은 오프셋(`+raw_off`/`+lbl_off` 등, 현재 v2 max PK보다 크게), 프레임·라벨클래스는 명시 대응표(프레임=(영상,프레임) dedup, 클래스=이름+타입 dedup). 상태는 `raw_data_id=raw_sn`(공유), 배정/이슈/증강은 별도 오프셋. 신규 생성 항목(구분=신규)은 위 전환기준에 **생성 규칙**을 명시했다.

#### 5.4 현행시스템 데이터 전환

- **5.4.1 운용환경**: 폐쇄망. v1 측 `mysql` 클라이언트, v2 측 `psql` 클라이언트만 사용. 중간 산출물은 TSV(JSON POINT 보존 위해 CSV 아닌 TSV, NULL=`\N`).
- **5.4.2 전송 흐름도**: v1(MySQL) `01_export_mysql.sh` → `./out/*.tsv`(7개: raw/src/lbl/pjt_lbl + stts/issue/aug) → 승인 반입(USB) → v2(PG) `\copy` 스테이징 적재.
- **5.4.3 전환 데이터 생성**: `01_export_mysql.sh <host> <port> <user> klid_system ./out` 실행. STEP 0 사전 점검(`DESCRIBE`로 컬럼 존재 확인, 라벨 클래스 전체 목록 조회로 의미 매핑 검토 근거 확보)을 선행한다. Not Null·유효범위는 변환 단계에서 기본값 부여·가드 처리한다.

#### 5.5 DB LOAD 및 데이터 입력

`02_load_transform.sql`을 **단일 트랜잭션**으로 실행한다. psql 변수로 TSV 경로(`:dir`)와 6개 ID 오프셋(`raw_off`/`src_off`/`lbl_off`/`asgn_off`/`issue_off`/`aug_off`)을 전달한다. 실행 전 상단 `mig_label_name_map` 의미 매핑을 환경 데이터에 맞게 검토·수정한다(예: `fallen_person→fallen-person`, `two_wheeler→motorbike`). 배정·이슈 작성자는 `mng_acct_user`에 사용자(v1 `REG_ID`)가 적재돼 있어야 매칭되며, 비어 있으면 배정만 누락(NOTICE 보고)되고 상태·라벨 이관은 정상 진행된다. Constraint·FK 위반 소량 발생분은 스테이징에서 유도·정정 후 재적재한다.

#### 5.6 전환결과 검증 및 오류처리

`03_verify.sql`을 **02와 동일한 6개 오프셋 변수**로 실행한다(미전달 시 WHERE 절 오작동으로 검증 무효). 모든 검증 항목이 `OK`여야 하며, 단순 건수 일치뿐 아니라 코드 Master 존재·테이블 간 일관성까지 확인한다.

| 검증 항목 | 판정 기준 |
|------|------|
| 건수 정합(영상/프레임/라벨 원천=적재) | 원천 대비 이관 건수 일치 |
| 좌표 역렌더 대조 | 무작위 N건 캔버스 위치가 v1과 동일 |
| 상태 collapse 정합 | 동일 영상 다중 PJT → 가장 진행된 상태 채택 확인 |
| 클래스 코드 Master 존재 | 미매핑 클래스는 자동 신규 추가(가드로 ABORT 없음) |
| 테이블 간 일관성 | 라벨→프레임→영상 참조 무결성, 배정·이슈 재연결 확인 |
| NAS 경로 서빙 | 저장 절대경로가 `STORAGE_RAW_PATH`(`/nas-storage`)로 시작 |

**오류 처리 수행주체**

| 오류 처리 | 수행주체 |
|------|------|
| 입력 데이터 자체 오류(v1 원천 값 오류) | 저작도구 개발팀(현업 확인 필요 시 관제팀 협조) |
| 의미 매핑 오류(라벨 클래스) | 저작도구 개발팀 |
| 데이터 전환 프로그램 오류(변환 로직·오프셋) | 저작도구 개발팀 |
| 사용자 매핑 공백(REG_ID 미적재) | 관제(계정)·저작도구 개발팀(재배정) |

`FAIL` 이면 이관분(오프셋 PK, `WHERE raw_sn >= :raw_off` 등)·스테이징을 삭제(cleanup 블록 활성)하고 원인 교정 후 재수행한다.

#### 5.7 최종 데이터 전환 시 전환 작업 일정

**5.7.1 단계별 주요내용**

| 작업단계 | 작업단계 설명 | 작업 내용(전환팀) | 작업 내용(DBA/응용팀) |

## 6. 기타

### 6.1 신규 데이터 처리 방안
전환 후 발생하는 신규 영상은 2차 정상 파이프라인(관제 학습용 설정 → 주기 배치 픽업 → 선두 비식별 → 마킹 → 배치)으로 적재되며 전환 대상이 아니다. 전환분과 신규분은 오프셋 PK 경계로 식별 가능하다.

### 6.2 초기 데이터 수집 구축

신규 스키마 구축(Flyway `db/migration` 마이그레이션) 시점에 코드성·설정 데이터가 **SQL로 자동 적재**된다. 수집 형태=Flyway 마이그레이션 SQL, 구축주체=저작도구팀, 구축시기=초기구축, 멱등(ON CONFLICT DO NOTHING). CBD 사례의 "Excel Tool 수집·공문 취합" 절차와 다르다.

**초기데이터 수집 대상**

| 시스템명 | 순번 | 테이블ID | 테이블 명 | 비고 |
|--------|:---:|---|---------|------|
| 저작도구 | 1 | (코드) CM_CODE | 검수/작업 상태 코드 | PENDING/IN_REVIEW/APPROVED/REJECTED, BATCH_QUEUED (V3, V50) |
| 저작도구 | 2 | (설정) LS_SYSTEM_CONFIG | YOLO 추론 파라미터 | CONF=25·IMGSZ=1280·IOU=50 (V17, V19) |
| 저작도구 | 3 | (설정) LS_SYSTEM_CONFIG | 폴리곤 단순화 | POLYGON_SIMPLIFY_TOLERANCE=1.0 (V54) |
| 저작도구 | 4 | (코드) LS_USER_ROLE | 저작도구 역할 | REVIEWER/WORKER/PORTAL_USER, MNG에서 화이트리스트 이관 (V75) |

**초기데이터 상세 구축 내용**

| 구분 | 내역 | 비고 |
|------|------|------|
| 구축 방법 | Flyway 마이그레이션 SQL(V0~V77) 자동 적재 | 애플리케이션 기동 시 |

### 6.3 데이터 전환 시 비상대책 안

| 비상 유형 | 내용 및 대책 |
|------|------|
| 변환 중 오류/중단 | 단일 트랜잭션 → 전체 롤백. 오프셋 PK로 이관분만 식별·삭제 후 재수행 |
| 의미 매핑 오류(클래스) | 재실행 전 cleanup 블록 활성화 → 매핑 수정 후 재적용. 미매핑은 §5-b 가드가 ABORT하여 조용한 손실 차단 |
| 좌표 깨짐 | STEP 5 역렌더 대조 필수. FAIL 시 변환 로직 교정 |
| NAS 실파일 미이전 | DB 경로만으로 서빙 시 404 — 실파일 이전(인프라)과 경로 정합(`STORAGE_RAW_PATH=/nas-storage`) 선확인 |
| 사용자 매핑 공백 | 배정만 누락(NOTICE 보고)되고 상태·라벨은 정상 이관 — 개시 후 재배정으로 보완 |
| cut-over 지연 | 리허설(스테이징) 결과로 소요시간 사전 측정, 점검 창(window) 초과 시 롤백 후 재계획 |
| 전환장비·저장매체 장애 | 반입 매체 여유분 확보, DBA·인프라 비상연락망 가동 |
