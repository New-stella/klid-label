# LS_* 컬럼 행안부 표준 정합 — 진행 상태 / 재개 노트

> 생성일: 2026-05-30 / 작성: claude
> 이 문서는 세션이 끊겨도 작업을 재개하기 위한 단일 진실원이다.

## 사용자 확정 결정 (Decision Log)

1. **표준 우선순위**: ① 정부 공통표준용어 → ② 사업 단어 조합 → ③ 사업 도메인 → ④ 없으면 사업 자체용어(사업사전 등록).
2. **범위**: 저작도구 소유 **LS_\*** 테이블의 비표준(영어식) 컬럼을 **풀스택 전면 표준화**(DB SQL → JPA 엔티티 → DTO → API JSON → FE 타입 → 테스트 → 문서).
3. **신규 시스템**: 아직 미배포 → 하위호환/기존데이터 불필요. **ALTER 아니라 CREATE TABLE SQL 직접 수정**. 기존 스케줄러 등 신경쓸 것 없음(단 QRTZ 컬럼명 자체는 Quartz 라이브러리 하드코딩이라 변경 불가).
4. **일시 컬럼 통일**: LS_ 전체 → 등록일시 `REG_DT` / 수정일시 `MDFCN_DT`. (CREATED_AT/UPDATED_AT/REGISTERED_AT/UPD_DT/CRT_DT 전부 정정)
5. **파일경로**: gov 완전일치 `FILE_PATH_NM`(term:11953) 채택. 한정어 붙이면 `RAW_FILE_PATH_NM` 식.
6. **gov 미존재 기술용어**: 사업사전 등록 후 사용.

## gov 확정 표준약어 (조회 실측)

- 완전일치 용어(term): 파일명 `FILE_NM`(11961) · 파일크기 `FILE_SZ`(11983) · 파일경로명 `FILE_PATH_NM`(11953) · 촬영일시 `SHT_DT`(11003) · 동영상재생시간 `VDPLY_HR`(3024, ※초 단위면 영상길이 VDO_LEN 검토)
- 표준단어 조합: 상태 STTS · 사유 RSN · 설명 EXPLN · 값 VL · 내용 CN · 명 NM · 발생 OCRN · 완료 CMPTN · 처리 PRCS · 오류 ERR · 재시도 RTRY(2201) · 횟수 NMTM(3252) · 건수 NOCS · 크기 SZ · 외부 OTSD · 적용 APLCN · 색상 COLR · 프레임 FRME · 경로 PATH · 정렬 SORT_SEQ(배포본) · 코드화 *_CD
- 표준 적용 규칙: 상태 `STATUS/STATE`→`STTS_CD` · 사유 `*_REASON`→`*_RSN` · 설명 `DESCRIPTION`→`EXPLN` · 정렬 `SORT_NO/SORT_ORDER`→`SORT_SEQ` · JSON/페이로드 `*_JSON/PAYLOAD/POINTS/MARKS`→`*_CN` · 유형 `*_TYPE`→`*_TYPE_CD`

## 도메인 작업 표준 절차 (sysconfig에서 검증됨)

1. 해당 도메인 SQL(CREATE+시드+인덱스) Read 후 컬럼명 표준화
2. 엔티티 @Column(name) + 필드명 + 게터 호출처 + 생성자
3. DTO record 필드 (= API JSON 키 변경됨) + from() 매핑
4. 서비스/QueryDSL/@Query 의 게터·컬럼 참조
5. BE 테스트 jsonPath/필드 참조
6. **FE**: 해당 도메인 types.ts/api.ts/컴포넌트/테스트에서 바뀐 JSON 키 추적 (도메인마다 변환계층 유무 다름)
7. build-validator 에이전트로 compileJava+test 검증
8. 이 문서 도메인 현황 갱신

## ⏸ 현재 작업 지점 (2026-05-30 세션)

- **sysconfig 완료** (빌드/테스트 PASS, 커밋 안 함).
- **다음 작업 중이던 배치**: auth + batch-proclog + deident 3개 백엔드 전용 도메인.
  - 위임 에이전트(developer-refactor)가 Edit 권한 없어 실패 → **메인이 직접 수정해야 함**.

    - LS_BATCH_PROC_LOG: `REQ_PAYLOAD`→`REQ_PAYLOAD_CN`, `RES_PAYLOAD`→`RES_PAYLOAD_CN` (엔티티 `batch/status/LsBatchProcLog.java`)
    - LS_DEIDENT_REPORT(`label/entity/LsDeidentReport.java`)+LS_DEIDENT_PROC_LOG(`batch/entity/LsDeidentProcLog.java`): `ORGN_FILE_PATH`→`ORGN_FILE_PATH_NM`, `DE_IDNTF_FILE_PATH`→`DE_IDNTF_FILE_PATH_NM`; REPORT만 `REASON`→`RSN`
  - SQL: V22(auth), V12(batch), V21(deident report), V29(deident proc log)
  - 검증: `cd backend && ./gradlew compileJava compileTestJava -q` + `--tests '*Deident*' '*WorkLock*' '*BatchStatus*'`
- **중요 교훈**: developer-refactor 에이전트는 Edit 미보유 → 코드수정 위임은 `developer-tdd`/`developer-hotfix`(Write/Edit 보유) 쓰거나 메인이 직접.

## 재개 시 첫 행동

1. 사용자에게 기술용어 약어(IDMP_KEY/VER_HASH/CLBK/INTV/RTRY_NMTM 등) 확정받기.
2. `program_glossary_create` 로 등록.
3. 도메인 단위로 SQL→엔티티→DTO→FE 수정, 각 도메인 후 `./gradlew compileJava` (또는 QA Agent) 로 검증.
