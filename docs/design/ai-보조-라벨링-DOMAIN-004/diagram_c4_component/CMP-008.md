## description

배치 VlmTimeseriesStep 이 VlmClient 로 외부 VLM 에 시계열을 위탁하고, 외부 VLM 이 POST /v1/vlm/callback 콜백(VlmResultController → VlmResultService)으로 결과를 회신하면 LS_DATA_META 적재 + 검수큐(LS_DATA_META_REVIEW) 진입. MetaController(/v1)→MetaService 가 메타 조회·수정·검토를 다룬다.

[★위탁은 논블로킹 제출] VlmTimeseriesStep 은 ACK 왕복 동안 파이프라인 스레드를 점유하지 않는다 — 상관키 원장 행(ISSUED)과 마킹 PENDING→VLM_REQUESTED 를 각각 선커밋한 뒤 subscribe 만 하고 즉시 반환한다. 수락(ACK)은 전용 풀에서 VlmSubmitOutcomeRecorder 가 원장을 ISSUED→ACCEPTED 로 전이시켜 기록한다. 선커밋 덕분에 ACK 보다 콜백이 먼저 도착해도 역조회가 성립한다.

[미결 회수 — 임계가 두 개] 아무 신호도 없으면 VlmSubmitPendingSweeper 가 유일한 회수 경로다. ACK 창(기본 30분 — 원장 ISSUED)과 콜백 창(기본 360분 — 원장 ACCEPTED)을 구분하며, 하나로 덮으면 정상 위탁을 빼앗는다. 2노드 중복 재위탁은 조건부 UPDATE 원자 클레임으로 막는다.

[신고 구간 보류] 외부로 나가는 media.path 가 비식별본인데 신고는 바로 그 비식별본의 마스킹 실패를 뜻하므로, 신고 구간에는 위탁을 실패가 아니라 보류(SKIPPED + 사유 적재)한다. 보류는 스스로 재개되지 않으므로 해소 시 DeidentGateReopenedEvent → VlmResumeBridge 가 그 기록을 근거로 재위탁한다(멱등 조건: 시계열 메타 0건).

⚠ 구 서술 '/v1/vlm/result 콜백' 은 코드에 없는 경로라 폐기했다. 컴포넌트·관계는 실제 생성자 의존성에서 도출.
