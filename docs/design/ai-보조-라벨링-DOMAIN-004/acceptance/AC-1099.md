# 장비 상태점검의 실패·복귀 임계는 계통마다 따로 둔다

## evidence

_(empty)_

## priority

high

## scenario

### then

- 각 계통의 이용불가 전이는 그 계통에 준 연속 실패 임계로 판정된다
- 각 계통의 가용 복귀는 그 계통에 준 복귀 임계로 판정된다
- 한 계통의 임계를 바꿔도 다른 계통의 판정 기준은 그대로다
- 두 계통에 서로 다른 값이 들어가 있어도 각자 자기 값으로 판정된다
- 바꾼 값이 운영 중에 그 계통의 다음 판정부터 반영된다

### when

- 두 계통에 서로 다른 연속 실패 임계를 준다
- 두 계통에 서로 다른 복귀 임계를 준다
- 한 계통의 연속 실패 임계만 바꾼다
- 한 계통의 복귀 임계만 바꾼다
- 운영 중에 임계를 바꾼다

### given

- 장비 원장에 오토라벨링 추론 유형과 외부 시계열 분석 유형의 장비가 각각 등록돼 있다
- 두 계통 모두 상태점검 대상이며 연속 실패 임계와 복귀 임계를 계통마다 지정할 수 있다

## statement

장비 상태점검이 장비를 이용불가로 내리는 연속 실패 임계와 다시 가용으로 되돌리는 복귀 임계는 계통마다 따로 둔다. 오토라벨링 추론과 외부 시계열 분석은 성질이 다르다 — 앞은 우리가 배포한 서버이고 뒤는 외부 벤더의 서비스라 응답 특성도, 우리가 손댈 수 있는 범위도 같지 않다. 따라서 두 계통은 서로 다른 값을 가질 수 있어야 하고, 한 계통의 임계를 조이거나 늦춰도 다른 계통의 판정 기준은 움직이지 않아야 한다. 임계를 하나로 공유하면 한쪽에 맞추려는 조정이 다른 쪽까지 함께 끌고 가 고치려던 쪽만 고칠 수가 없다. 두 임계 모두 운영 중에 조정할 수 있어야 한다. 검증하는 것은 임계의 특정 값이 아니라 이 성질이다 — 계통마다 다른 값을 줄 수 있는가, 그리고 한쪽을 바꾼 것이 다른 쪽으로 새지 않는가. 대가는 조정할 설정 항목이 느는 것이며 인지하고 수용한 것이다.
