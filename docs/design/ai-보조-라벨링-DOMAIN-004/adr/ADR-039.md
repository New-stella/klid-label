# dev 로그인/파일 업로드 — 운영 빌드 env 토글 허용(fail-closed, 기본값은 축마다 다르다)

## context

관제 미기동 폐쇄망 브링업 시나리오에서 관제 로그인 인계 없이 저작도구를 단독 기동/검증할 방법이 필요했다.

## decision

### chosen_option

env 토글로 조건부 허용(채택)

### justification

dev 로그인과 파일 업로드를 운영 빌드에서도 환경변수 토글로 켤 수 있게 허용한다. 값이 지정되지 않으면 켜지지 않는다(fail-closed).

★두 축의 기본값이 갈렸다(2026-08-24 갱신). 이 결정이 정한 것은 「토글로 게이팅한다·값이 없으면 안 켜진다·환경변수로 되돌릴 수 있다」는 구조이며, 그 구조 안에서 각 축의 기본값은 따로 고른다.

dev 로그인은 여전히 기본 OFF 다. 그 경로는 인증 없이 임의 권한 토큰을 발급하므로 운영에서 켜지면 인증 체계 전체가 우회된다. 운영 계열 프로파일에서는 이 토글이 켜져 있으면 부팅 자체를 거부해, 설정 실수가 배포 시점에 드러나게 한다. 폐쇄망 브링업에서만 임시로 켠다.

파일 업로드는 운영 상시 기능이 됐다. 외부에서 받은 영상을 운영자가 직접 올리는 동선이 실재하고, 그 경로는 검수자 인가 뒤에 있어 인증 우회 표면이 아니다. 운영 프로파일에서 기본 ON 이며 부팅 거부 대상이 아니다. 비노출로 되돌리려면 화면 쪽 빌드 플래그와 서버 쪽 토글을 함께 꺼야 한다 — 한쪽만 끄면 화면만 남거나 요청만 거부되어 원인을 찾기 어렵다.

⚠ 구 기재 폐기: "기본 OFF, fail-closed다"를 두 축에 공통으로 적었으나 파일 업로드에서는 더 이상 사실이 아니다. fail-closed(값이 없으면 안 켜진다)는 두 축 모두 유효하고, 기본값이 갈린 것이다.

## consequences

### risks

- dev 로그인 토글이 실수로 켜진 채 운영에 배포되면 인증이 우회된다 — 운영 계열 프로파일의 부팅 거부가 그것을 막는다
- 파일 업로드는 운영에서 열려 있으므로 그 경로의 인가(검수자)와 업로드 크기 상한이 실질적인 방어선이다

### negative

- 운영 예외 경로 추가 — dev 로그인은 실수로 운영에 노출되지 않도록 기본값 OFF 와 부팅 거부가 전제다
- 두 토글의 기본값이 달라 「dev 토글」로 뭉뚱그려 읽으면 한쪽에 거짓이 된다 — 축을 갈라 확인해야 한다

### positive

- 관제 미기동 폐쇄망 브링업 시나리오에서 저작도구 단독 기동·검증 가능
- 외부에서 받은 영상을 운영자가 직접 올리는 동선이 운영에서 성립한다
