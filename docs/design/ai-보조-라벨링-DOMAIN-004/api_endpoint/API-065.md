## description

외부 VLM 서버가 시계열 검증 결과를 콜백으로 전송한다(벤더 확정 계약 정합).

[results 는 배열이 아니라 객체다] 일치도(accuracy, 0~1)와 검증 서술 전문(description, 최대 2000자) 한 벌이다. 구간별 항목을 배열로 받던 구 규격은 폐기됐다 — 요구가 '시계열을 전문 한 건으로 보여주고 편집 가능하게'였고, 검증 호출이 '그 이벤트가 실제로 있었는가(일치도)'와 '무엇이 보이는가(서술)'를 한 벌로 돌려주기 때문이다. 벤더가 구 배열을 보내면 관대하게 받아주지 않고 400 으로 거부한다. 무단 하위호환은 벤더 쪽 버그를 숨긴다.

[적재 키 규격] 서술은 vlm.description 으로, 일치도는 vlm.accuracy 로 영상 단위 메타에 upsert 된다. 검수 큐에 들어가는 것은 vlm.description 한 건뿐이고 vlm.accuracy 는 화면 표시 전용이다 — 화이트리스트 방식이라 vlm 계열 키가 늘어도 검수 큐와 데이터마트 뷰로 새지 않는다. 이미 적재된 구 구간 키 행은 작업 결과라 삭제하지 않고 읽기 전용으로 함께 보여준다.

[무서명 콜백을 3계층으로 방어한다] 벤더 규격상 콜백에 서명 헤더가 없어 서명 검증을 요구할 수 없다. 대신 ①호출 IP 허용목록(운영·검증 환경은 명시 설정을 강제한다) ②실패 IP 분당 횟수 제한과 본문 크기 상한 ③위탁 시 저작도구가 발급한 요청 식별자만 처리하는 게이트로 막는다. 콜백 본문에 영상 식별자가 없어 요청 식별자로 원장에서 역조회한다.

[상태별 처리] completed 는 결과를 적재하고 대기 중이던 마킹을 완료로 전이한다. failed 는 적재 없이 오류만 남기고 마킹을 실패로 전이해 고착을 푼다. 같은 요청 식별자를 다시 받으면 멱등 스킵하며 응답의 적용 여부 필드로 그 사실을 알린다.

[전부 한 트랜잭션이다] 요청 식별자 원장의 처리 완료 표시까지 같은 트랜잭션이라, 중간에 실패하면 함께 롤백되어 벤더 재전송으로 복구된다.
