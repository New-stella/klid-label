## description

AI 추론·외부 시계열 분석 장비의 노드 원장을 다루는 관리 창구다. 이 원장이 장비 주소의 진실원이며, 배포 설정값은 원장이 비어 있을 때 최초 1회 씨앗으로만 쓰인다.

주소 검증은 진실원이 옮겨갔다고 사라지지 않는다 — 저장되는 주소에도 스킴(http 또는 https)·형식·예약 대역 거부가 그대로 걸린다. **평문 http 와 사설 대역은 통과가 정상이다**(대역 차단은 폐기됐다). 거부되는 것은 클라우드 메타데이터·링크로컬 같은 예약 대역과 비허용 스킴·형식 위반이며, 거부 사유에 입력 원문·호스트·해석 결과를 싣지 않는다 — 실으면 그 응답이 내부망을 훑는 수단이 된다.

장비 유형은 추론(탐지·분할·추적)과 외부 시계열 분석 둘이며 유형마다 여러 대를 둘 수 있다. 부하를 세는 축이 유형마다 다르다 — 추론은 동기 호출이라 큐 길이가 곧 부하지만, 시계열은 위탁 후 콜백이라 큐를 볼 수 없어 우리 원장의 미결 위탁 수를 센다.

이 원장이 담는 범위를 가르는 축은 「AI 위탁인가」가 아니라 「고를 대상이 여럿인가」다. 추론과 외부 시계열 분석은 같은 유형의 장비를 여러 대 두고 그중에서 고르므로 원장이 진실원이어야 한다. 반면 외부 증강 벤더는 보낼 곳이 한 곳뿐이라 고를 일이 없어 이 원장에 두지 않으며, 그 주소는 연동 서버 주소 설정 칸이 진실원이다. 증강도 외부 AI 위탁이 맞다 — 가르는 축이 다를 뿐이다.

증강을 이 원장으로 옮기려면 다음이 함께 갖춰져야 한다 — 보낼 곳이 여럿이 되는 것, 그리고 그 벤더 규격에 서버가 지금 일을 받을 수 있는지를 묻는 창구가 생기는 것이다. 지금 그 규격이 제공하는 창구는 작업 단위(위탁·그 작업의 상태·결과·취소)뿐이라 서버 자체의 여유를 묻는 자리가 없고, 그래서 원장에 넣어도 상태점검을 할 수단이 없다. 작업 상태 창구를 대신 찔러 상태점검으로 쓰지 않는다 — 규격에 없는 사용법이라 그 응답을 장비 상태로 읽으면 멀쩡한 장비가 상시 나쁨으로 굳는다.

조회는 검수자 권한만으로 된다 — 관리 화면의 목록을 읽는 경로이고, 막으면 장비 상태를 확인할 길이 없어진다. 유형으로 걸러 볼 수 있으며 지정하지 않으면 전부 돌려준다. 행마다 식별자·이름·주소·유형·상태·최근 점검 시각·연속 실패 수·연속 성공 수와 용도별 부하를 담는다.
