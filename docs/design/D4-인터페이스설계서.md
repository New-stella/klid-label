# D4 인터페이스 설계서

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-UC/CO/DC/DCD/SD/SC/AC/EN/ERD/TB/II/IC/IF/UCD/ACT 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. 범위는 시작 ID만 전체형으로(예: `KLID-AT-II-001~008`). ※ 요구사항(RQ-SFR-NN-NN)·시스템시험(KLID-ST-NNN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 시스템의 내.외부 인터페이스를 식별하고 인터페이스의 명세를 기술한다.

## 작성 방법
> 식별된 인터페이스를 송신측과 수신측으로 구분하여 기술하고 송.수신간의 인터페이스 방식을 기술하며, 데이터 송신 시스템과 수신 시스템간의 데이터 저장소와 속성 등의 상세 내역을 기술한다.

> ※ AI 추론(YOLO 객체탐지·추적, SAM2 분할·추적) 호출은 저작도구가 자체 운영하는 **내부 추론 인프라(ai-server)** 로, 저작도구 ↔ ai-server 가 별도 프로세스로 HTTP/REST 호출되는 시스템 간 연동이므로 **KLID-AT-II-009~012 내부 인터페이스로 본 목록에 포함**한다(v1.4 — 구 '외부 인터페이스에서 제외' 결정 대체). 컴포넌트 설계서(D3)는 동일 연동의 내부 구조를 상세화한다. ai-server 의 `POST /infer/vlm/verify-objects`(VLM 객체 검증)는 본 목록에서 제외한다(작성 결정).

#### KLID-AT-II-003 — VLM 시계열 위탁

> **인터페이스 설명**
>
> - **연동 목적**: 마킹까지 끝난 **비식별 영상**을 외부 Video VLM 에 보내, 영상 속 상황을 **시간 구간별 자연어로 묘사(describe)** 받아 시계열 메타로 적재한다. 사람이 프레임을 일일이 서술하지 않아도 "몇 초~몇 초 구간에 무슨 상황인지"가 자동 생성되며, 이후 REVIEWER 검수를 거쳐 학습데이터 메타로 확정된다.
> - **벤더 규격**: **IntelliVIX Video VLM API v2.0.1**(IntelliVIX AI연구소, 2026-06-15 확정계약). 벤더는 추론 2종 — 이벤트 검증 `POST /v1/videovlm/verify`(정확도+설명)와 상황 묘사 `POST /v1/videovlm/describe`(구간별 묘사) — 및 가용성 조회 `GET /v1/videovlm/status`(ready/busy)를 제공하나, 본 인터페이스는 **describe 만** 사용한다(verify 는 후속 범위). **API: `POST /v1/videovlm/describe`**.
> - **처리 흐름**: 마킹 완료 → describe 위탁(`media.source_type=path`, `media.path`=비식별 영상 경로, `frame_policy`) → 벤더가 **수락만 동기 응답**(`{request_id, status:"accepted"}`) → 실제 묘사 결과는 벤더가 `callback_url` 로 **비동기 콜백**(KLID-AT-II-004) → 구간별 묘사를 `LS_DATA_META` 에 적재 후 검수 대기.
> - **프레임 정책**: `media.type=video` 이며 `frame_policy.mode` 는 `frame_interval`(초당 `framerate` 기준 간격 추출) 또는 `frame_selected`(지정 프레임, 최대 8장). **Video VLM 은 1회 추론 최대 8프레임**이라 초과분은 sliding window(window=stride=8)로 분할 분석한다(벤더 규격).
> - **상관관계·멱등**: 위탁 시 발급한 `request_id` 로 위탁↔콜백을 매칭(대상 영상 `RAW_SN` 대응, 기존 idempotency ledger 재사용)하며 동일 `request_id` 재수신은 스킵한다.
> - **주의**: describe 규격은 이벤트 유형(`event_type`)·마킹 시점을 입력받지 않으므로 마킹 이벤트 컨텍스트(`eventName`·`marks`)는 전송하지 않는다(이벤트 검증이 필요하면 별도 verify — 본 범위 외). 현재 클라이언트는 계약 확정 전 스텁으로 `VLM_CLIENT_ENABLED` 기본 false(후속 구현 교체 대상).

## 부록 — 데이터 부재/매핑 사유

### 빈 셀(`-`) 사유

- **수신번호 (전 인터페이스)**: 상대 시스템의 인터페이스 채번 체계를 본 산출물 작성 시점에 보유하지 않음 — 외부 연동 확정 시 보완.
- **수신 상대 담당자 (외부 연동)**: 시스템 간 양방향 인증 연동이 미운영 상태로 외부 시스템 담당자가 미지정 — "미정 — 연동 시 확정" 표기. 콜백 수신(KLID-AT-II-004·006)의 수신측은 저작도구 검수 담당으로 처리. **비식별(II-001·II-002)은 예외로 KPST 실연동이 구현·운영되어 "연동 완료(KPST) — 담당자 성명 확인 필요"로 표기**한다(상대측 실무담당자 성명만 미확보).
- **데이터타입 길이 (대부분)**: 송수신이 데이터베이스 고정 길이가 아닌 구조화 메시지(JSON) 또는 파일 경로/이진 첨부 기반이라 단일 고정 길이가 성립하지 않음 — 길이 미상으로 `-` 표기(고정 길이 항목만 수치 기입).
- **송신 프로그램 ID (KLID-AT-II-008)**: 송신측이 외부 데이터베이스(포털 DB)로 프로그램 단위가 아닌 데이터 저장소 직접 조회 — `-`.

### 관련 요구사항 ID 매핑 근거

- KLID-AT-II-001·002 ↔ RQ-SFR-09-01: 영상 비식별 처리(개인정보 보호).
- KLID-AT-II-003·004·007 ↔ RQ-SFR-08: 저작도구 핵심 기능(외부 VLM 시계열 연동·관제 통지가 흡수됨).
- KLID-AT-II-005·006 ↔ RQ-SFR-07-01: 생성형 AI 외부 증강(WINTER/NIGHT/RAIN).
- KLID-AT-II-008 ↔ RQ-SFR-19: 포털 채널 데이터 Load.
- KLID-AT-II-009·010·011·012 ↔ RQ-SFR-08: 저작도구 핵심 기능(오토라벨링 YOLO 탐지·추적, SAM2 분할·추적 — SFR-08-01 라벨링 정확도 향상 포함).

> 위 매핑은 R1 사용자요구사항정의서의 실존 요구사항 ID를 근거로 한다. R1에 직접 대응 항목이 없으면 `-`로 두며 의사값을 채우지 않는다.

### 비식별(II-001·II-002) 코드 정합 사유

- 비식별 위탁·폴링은 KPST 비식별 솔루션과 실연동(구현·운영)되므로 명세의 속성·필수여부·속성 설명을 **실제 구현 코드**(`KpstDeidentifyClient`, `KpstProjectRequest`, `KpstProgressRequest`, 규격 정본 `docs/v2-wiki/22-deid-solution-api.md`)에 정합한다.
- **공유 마운트(no-copy) 모델**: 위탁은 원본 경로(`input_path`)를 `POST /project` 에 직접 참조시켜 업로드 단계가 없고, 결과는 KPST 가 결과 경로(`export_path`)에 직접 산출해 다운로드 단계도 없다. 따라서 II-001 명세에서 영상 파일 업로드(BYTEA)·`multipart` 전달을 제거하고 전달방식을 `HTTP/REST(JSON)` 으로 정정한다.
- **선택 코드 필드**: `masking_type`·`db_save`·`masking_range`·`exp_quality`·`exp_format` 은 규격 기본값이 존재하는 선택 필드로 필수여부 `선택` 으로 표기한다(§22.4 부록 A 기본값).

### 관제통지(II-007) 코드 정합 사유

- 관제서버 완료/수정 통지는 `ControlNotifyClient`(단방향 outbound)로 실구현되어, 명세를 실제 페이로드 record 두 종(`TaskCompletedPayload`·`TaskModifiedPayload`)에 정합한다.
- **공통 필드**(`eventType`·`rawSn`·`requestId`)는 `필수`, **이벤트별 필드**는 `조건부` 로 표기한다 — 완료 통지: `reviewerName`·`approvedAt`·`totalFrames`·`labeledFrames` / 수정 통지: `lastModifiedAt`·`frameIds`(Long Array)·`changeTypes`(String Array).
- 기존 추상 표기(단일 `변경 요약 카운트`)는 실제 필드 셋과 상이해 제거하고, 특히 누락돼 있던 `changeTypes`(변경 종류 목록: LABEL_ADDED/UPDATED/DELETED·META_UPDATED)를 추가한다.
- 라벨/메타 본문·PII·토큰·원본(비-비식별) 이미지 경로는 페이로드에 포함하지 않는다(CWE-359).

### 데이터 저장소명 정정 사유 (v1.2)

- v1.1 까지 '데이터 저장소명' 에 남아 있던 메시지/행위명(비식별 위탁 요청·진행 조회·관제 통지·증강 영상 등)은 본 항목 정의("엔티티 또는 파일명")와 맞지 않아, 각 인터페이스가 실제 읽고/쓰는 데이터 저장소로 정정한다.
- **저작도구 측(실 테이블 확인)**: II-001·002 `LS_DEIDENT_PROC_LOG` / II-003 `LS_MARKING`·`LS_DATA_RAW` / II-004 `LS_DATA_META`·`LS_DATA_META_REVIEW` / II-005 `LS_DATA_RAW` / II-006 `LS_DATA_AUG`·`LS_DATA_RAW` / II-007 `LS_RAW_DATA_STATUS`·`LS_DATA_RAW` / II-008 `LS_PORTAL_USER_LABEL`. (엔티티 `@Table` 매핑 기준)
- **외부 시스템 측**: KPST·외부 VLM·외부 증강·관제서버·포털 DB 는 저작도구가 스키마를 소유하지 않으므로 논리 저장소명 + 시스템명(예: "비식별 프로젝트 (KPST)", "포털 영상·라벨·메타 (포털 DB)")으로 표기한다.

### AI 추론(ai-server) 내부 인터페이스 포함 사유 (v1.4)

> supersedes: 구 "AI 추론 연동은 내부 인프라라 외부 인터페이스 목록에서 제외" 결정을 대체 — AI 추론 호출을 KLID-AT-II-009~012 **내부 인터페이스**로 본 목록에 포함한다. 근거: 저작도구(Spring Boot) ↔ ai-server 는 별도 프로세스로 HTTP/REST 호출되는 시스템 간 연동이라, 인터페이스 설계서에 명시하는 것이 실동작에 부합한다.

- 객체탐지·분할·추적 추론(YOLO/SAM2)은 저작도구가 자체 운영·배포하는 **내부 추론 인프라(ai-server)** 로, 인증·DB 없는 **무상태(stateless) 추론**만 수행한다. 저작도구가 `AiServerClient`(Resilience4j 타임아웃·재시도·서킷브레이커)로 호출한다.
- **엔드포인트**: II-009 `POST /infer/yolo/predict` · II-010 `POST /infer/yolo/track` · II-011 `POST /infer/sam2/segment` · II-012 `POST /infer/sam2/track`.
- ai-server 무상태 특성상 수신측 '데이터 저장소명'은 영속 저장소가 없어 "추론 입력 (무상태)"로 표기한다. 이미지 입력은 base64 문자열(길이 미상 `-`), 좌표(points/box/polygon)는 JSON 수치 배열이다.
- ai-server 는 `POST /infer/vlm/verify-objects`(VLM 객체 검증)도 노출하나 본 목록에서는 **제외**한다(작성 결정). 시계열 VLM(KLID-AT-II-003·004)과는 별개 기능이다.
- 컴포넌트 설계서(D3)는 동일 연동의 내부 컴포넌트 구조를 상세화한다.

### 외부 양방향 연동 정책 메모

- 관제서버/외부 학습데이터 시스템과의 양방향 통합(시스템 간 자동 연동)은 현재 미운영한다. 본 산출물의 관제 연동(KLID-AT-II-007)은 저작도구가 관제서버로 통지를 보내는 단방향 송신과, 관제서버가 상세를 가져가는 조회 인터페이스 제공으로 구성되며, 재구축 시 별도 설계가 필요하다.
