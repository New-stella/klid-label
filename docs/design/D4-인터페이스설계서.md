# D4 인터페이스 설계서

## 작성 목적
> 시스템의 내·외부 인터페이스를 식별하고 인터페이스의 명세를 기술한다.
> 본 산출물은 R1 사용자 요구사항 정의서(SFR-06~09, 16개)에 매핑된 R2 유스케이스와 직접 관련된 내·외부 인터페이스만 대상으로 한다. 마킹(UC-001)·포털 업로드·사용자/권한 등 R1 무관 인터페이스는 제외한다. (구 RQ-SFR-09-06/07은 2026-06-02 범위 외 삭제 — 인터페이스 매핑 없어 본 명세 내용 불변)

## 작성 방법
> 식별된 인터페이스를 송신측과 수신측으로 구분하여 기술하고 송·수신 간의 인터페이스 방식을 기술하며, 데이터 송신 시스템과 수신 시스템 간의 데이터 저장소와 속성 등의 상세 내역을 기술한다. 송수신 데이터 속성은 실제 코드(`common/client/dto/*`, `webhook/dto/*`, `controlnotify/dto/*`)의 DTO 필드를 기준으로 도출한다.

> - 실제 코드의 콜백 경로는 `/v1/vlm/result`이며(요구사항 식별 시 표기된 `/v1/webhook/vlm-result`와 다름), 본 산출물은 코드 기준 경로를 따른다.

## 2. 인터페이스 명세

> 인터페이스별로 송신/수신 시스템의 데이터 저장소·속성·타입·길이를 좌우 대조 형태로 기술한다. 속성·타입은 실제 DTO 필드(JSON 직렬화명 우선)를 기준으로 한다. `List`/중첩 record는 배열 항목 속성을 들여쓰기(└)로 표기한다. 숫자형(Integer/Double/Long)·구조형(record/List)은 길이를 `—`(수치형) / `N`(가변·구조형)으로, 문자열은 설계 권장 최대 길이로 표기한다.

## 항목 설명 (요약)

- **전달 처리형태**: ai-server 추론(II-001~004)은 Online(동기), VLM·비식별·증강 위탁(II-005, II-007, II-012)은 Online(비동기 요청+콜백), 콜백 수신(II-006, II-008, II-009)은 Online(비동기 콜백), 관제서버 통지(II-010, II-011)는 Online(비동기 단방향 outbound)이다. 증강 위탁(II-012)은 현 단계 외부 미연결 best-effort placeholder다.
- **전달 인터페이스방식**: 모두 HTTP REST/JSON. 외부 연동은 Resilience4j(타임아웃·재시도·서킷브레이커) 적용. 위탁 요청은 `X-Idempotency-Key` 헤더로 멱등 보장.
- **관련 요구사항 ID**: R1 사용자 요구사항 정의서의 `RQ-SFR-NN-NN`. R2 유스케이스명세서 매핑(UC-002·004·005·006·009·011)을 경유한다.
- **콜백 수신 보안**: 콜백/통지는 `HmacWebhookFilter`(HMAC 시그니처 + timestamp + idempotencyKey allowlist)로 보호. 양방향 M2M 인증은 deprecated. 페이로드에 PII·토큰·원본(비-비식별) 이미지 포함 금지.

## 작성 시 참고사항

> - 인터페이스 식별 기준: `backend/.../common/client/`의 외부 연동 클라이언트 — AiServerClient(ai-server), VlmClient(외부 VLM 위탁), DeidentifyClient(외부 비식별 위탁), ControlNotifyClient(관제서버 통지) + `webhook/`의 콜백 수신 컨트롤러(VlmResultController·DeidentifyResultController·AugmentResultController). 단, 증강 위탁 클라이언트 `ExternalAugmentClient`는 `common/client`가 아닌 도메인 패키지 `augment/integration/ExternalAugmentClient.java`에 위치한다(INT-008).
> - 송수신 데이터 명세는 실제 DTO 코드 기준: `common/client/dto/`(YoloRequest/Response, YoloTrackRequest, Sam2Request/Response, Sam2TrackRequest/Response, VlmTimeseriesRequest/Response, DeidentifyRequest/Response, ControlNotifyRequest), `webhook/dto/`(VlmResultRequest, DeidentifyResultRequest, AugmentResultRequest), `controlnotify/dto/`(TaskCompletedPayload, TaskModifiedPayload).
> - JSON 직렬화명 표기: ai-server DTO는 `@JsonProperty` 스네이크케이스(image_b64, conf_threshold, track_id, frame_no 등)를 그대로 기재했다. 그 외 DTO는 record 필드명(camelCase)을 사용한다.
> - ID 체계: 인터페이스 번호 `KLID-AT-II-NNN`, 관련 요구사항 ID `RQ-SFR-NN-NN`.
> - 길이 표기: 수치형은 `—`, 가변·구조형(record/List)은 `N`, 문자열은 설계 권장 최대 길이.
> - 범위 제외: ai-server `/infer/vlm/verify-objects`(VlmVerifyRequest/Response, 객체 분류 검증)는 시계열 메타 본체가 아닌 라벨 품질 보조 추론으로, R1 시계열 요구사항(외부 VLM 위탁)과 별개이며 마킹·배치 내부 보조에 해당하여 본 명세에서는 핵심 인터페이스로 다루지 않는다.
