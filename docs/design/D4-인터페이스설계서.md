# D4 인터페이스 설계서

> **ID 표기 규칙(공통)**: 본 산출물의 AT 산출물 ID(KLID-AT-II 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `II-001`) 약식 표기 금지. 범위는 시작 ID만 전체형으로(예: `KLID-AT-II-001~004`). ※ 요구사항(RQ-SFR-NN-NN·NFR-NNN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 시스템의 내·외부 인터페이스를 식별하고 인터페이스의 명세를 기술한다.

## 작성 방법
> 식별된 인터페이스를 송신측과 수신측으로 구분하여 기술하고 송·수신 간의 인터페이스 방식을 기술하며, 데이터 송신 시스템과 수신 시스템 간의 데이터 저장소와 속성 등의 상세 내역을 기술한다.

> **목록 비고**
> - 관련 요구사항 ID 중 NFR-004(외부 API 연동 복원력)·NFR-005(민감정보 보호)는 R1 「본문 — 비기능 요구사항(NFR)」 표의 항목으로, NFR-004 설명에 비식별·AI 추론 서버·VLM·증강·관제통지 연동이, NFR-005 설명에 관제 통지 페이로드 PII 금지가 명시되어 있다.
> - 수신번호(수신 시스템 측 인터페이스 번호)는 상대 시스템(외부 솔루션·관제서버·포털)의 인터페이스 채번을 보유하지 않아 전체 `-` — 연동 계약/협의 시 확정한다.
> - KLID-AT-II-010/011 은 동일 클라이언트(ControlNotifyClient)·동일 엔드포인트(`/api/v1/notify`)를 사용하며, 요청 래퍼 `ControlNotifyRequest.eventType`(TASK_COMPLETED / TASK_MODIFIED)으로 구분한다.
> - KLID-AT-II-006/008/009 콜백 수신 엔드포인트는 `HmacWebhookFilter`(HMAC 시그니처 + timestamp + idempotencyKey allowlist)로 보호한다. 양방향 M2M 인증은 미운영.
> - KLID-AT-II-012(증강 생성 위탁, 송신)와 KLID-AT-II-009(증강 결과 콜백, 수신)는 한 쌍이다. 위탁 호출은 호출자 트랜잭션에 외부 실패를 전파하지 않는다(best-effort 설계).
> - **해상도 변경(RESOLUTION)은 외부 위탁이 아닌 저작도구 내부 기능**이다(RQ-SFR-06-03) — 표준 하위 해상도 화이트리스트(RES_1080P/720P/480P)로 프레임 이미지셋만 다운스케일 제공(라벨 좌표 미제공)하므로 외부 인터페이스가 아니며 본 목록에서 제외한다.
> - 비식별 누락 신고(마킹 단계 rawSn 기준·라벨링 단계 srcSn 기준)는 내부 화면→백엔드 호출로 외부 인터페이스가 아니다(본 목록 제외). 신고 후 비식별화는 작업자/검수자가 외부 솔루션으로 수동 수행한다.

## 2. 인터페이스 명세

> 인터페이스별로 1개씩 반복 작성한다. 표의 각 행은 **전달(송신) 데이터의 속성 1건**이며, 송신측 데이터 저장소·속성과 그 데이터가 적재·처리되는 수신측 데이터 저장소·속성을 좌우 대조한다. 동기 응답(수락 확인·추론 결과 등) 규격은 표 하단 비고에 기술한다. 속성·타입은 연동 데이터 규격(DTO) 필드(JSON 직렬화명 우선)를 기준으로 하며, `List`/중첩 구조는 배열 항목 속성을 `└`로 표기한다. 숫자형은 길이를 `—`, 가변·구조형(record/List)은 `N`, 문자열은 설계 권장 최대 길이로 표기한다. 수신측 적재 테이블(LS_*)의 물리 컬럼 명세는 D9 데이터베이스설계서를 따른다.

## 항목 설명 (요약)

- **전달 처리형태**: AI 추론 호출(KLID-AT-II-001~004)은 Online(동기), VLM·비식별·증강 위탁(KLID-AT-II-005/007/012)은 Online(비동기 요청+콜백), 콜백 수신(KLID-AT-II-006/008/009)은 Online(비동기 콜백), 관제서버 통지(KLID-AT-II-010/011)는 Online(비동기 단방향 송신), 포털 DB Load(KLID-AT-II-013)는 Online(조회/JDBC)이다.
- **전달 인터페이스방식**: AI 추론 서버·VLM·비식별·증강·관제는 HTTP REST/JSON, 포털은 JDBC(듀얼 데이터소스). 외부 HTTP 연동은 Resilience4j(타임아웃·재시도·서킷브레이커)를 적용하고(NFR-004), 위탁 요청은 `X-Idempotency-Key` 헤더로 멱등을 보장한다.
- **콜백 수신 보안**: 콜백 수신 엔드포인트는 `HmacWebhookFilter`(HMAC 시그니처 + timestamp + idempotencyKey allowlist)로 보호한다. 양방향 M2M 인증은 미운영이며, 관제 통지는 인계토큰/IP 화이트리스트로 보호한다. 페이로드에 PII·토큰·원본(비-비식별) 이미지 포함 금지(NFR-005).
- **관련 요구사항 ID**: R1 사용자요구사항정의서에 실존하는 ID만 기재한다 — 기능 요구사항은 RQ-SFR-NN-NN, 직접 대응 기능 요구사항이 없는 외부 연동은 R1 비기능 요구사항 표의 NFR-004(외부 API 연동 복원력)·NFR-005(민감정보 보호)로 연결하고, 그것도 없으면 `-`(부록 사유).

## 작성 시 참고사항

> - **ID 체계**: AT 인터페이스 번호 `KLID-AT-II-NNN`(전체형), 요구사항 `RQ-SFR-NN-NN`·`NFR-NNN`(원형 유지).
> - **JSON 직렬화명 표기**: AI 추론 서버 연동 DTO 는 스네이크케이스 직렬화명(image_b64, conf_threshold, track_id 등) 그대로 기재한다. 그 외 DTO 는 필드명(camelCase) 기준.
> - **길이 표기**: 수치형 `—`, 가변·구조형(record/List) `N`, 문자열은 설계 권장 최대 길이.
> - **비식별 선두 파이프라인**: 영상 적재 → 비식별화(전체 영상, KLID-AT-II-007/008) → 마킹(비식별 영상 대상) → VLM 시계열(KLID-AT-II-005/006) → 프레임 추출(원본+비식별 2벌) → 오토라벨링(KLID-AT-II-001~004, 원본만 실행·좌표 공유) 순서를 설계 기준으로 한다.
> - **범위 분리(해상도 변경 내부화)**: 해상도 변경(RQ-SFR-06-03)은 외부 위탁 대상이 아닌 저작도구 내부 기능 — 표준 하위 해상도 화이트리스트 다운스케일 이미지셋 제공(라벨 좌표 미제공). 따라서 외부 증강 위탁(KLID-AT-II-012)·증강 결과 콜백(KLID-AT-II-009)의 증강 유형은 WINTER/NIGHT/RAIN 3종이다.
> - **양방향 M2M 미운영**: 관제/포털 양방향 통합 API·M2M 인증 인프라는 미운영. 예외로 저작도구→관제 단방향 통지(KLID-AT-II-010/011)는 인계토큰/IP 화이트리스트로 보호하여 유지한다.
