# 관제서버 연동 — 양방향 M2M 폐기, 단방향 outbound 통지 채택

## context

1차·초기 고도화 구상은 관제서버·외부 학습데이터 시스템과 양방향 M2M 통합(송수신 API + M2M 인증 인프라)을 가정했으나, 운영 보안·복잡도로 deprecated되었다. 고도화는 저작도구→관제서버 단방향 outbound 완료/수정 통지(TASK_COMPLETED/TASK_MODIFIED, 수정 요약만 · 본문 미포함)와 관제가 호출하는 inbound 조회 API만 제공한다. 통지는 인계 토큰 또는 IP 화이트리스트로 보호하며 양방향 M2M 인증은 부활하지 않는다.

## deciders

- 박찬기
- 김현욱

## decision

### chosen_option

단방향 통지 + inbound 조회(채택)

### justification

양방향 M2M 인증을 부활하지 않고, 저작도구→관제서버 단방향 통지(요약만) + 관제 조회 API로 설계한다. 보안·결합도·PII 노출을 최소화한다.
