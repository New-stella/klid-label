# 관제 학습용 영상 인입 픽업

## status

active

## protocol

jdbc

## auth_type

none

## direction

inbound

## data_format

other

## description

관제서버가 학습 대상 영상을 저작도구로 넘기는 인입 경로다. 관제가 저작도구 소유 인입 원장(LS_DATA_INGEST)에 평면 1행을 직접 INSERT 하고(PRCS_STTS_CD='PENDING'), 저작도구의 주기 배치가 미처리 행을 폴링해 원시 데이터 테이블(LS_DATA_RAW)로 적재한다. 적재된 영상은 곧바로 비식별 단계로 넘어간다.

## 실측 계약
- 인입 주체는 관제이고 픽업 주체는 저작도구다. 저작도구가 관제를 호출하는 구간은 없다.
- 파일 본문은 오가지 않는다. 행에 실린 경로로 공유 저장소에서 읽는다.
- 상태 전이: PENDING → PROCESSING → DONE 또는 FAILED.
- 발화 주기: 기본 60초(authoring.control.training-scan.interval-sec). 기동 30초 뒤 첫 발화이며, authoring.control.training-scan.enabled 를 false 로 두면 잡 자체가 등록되지 않는다.

## 중복 적재 방어 3겹 — 서로 대체하지 않는다
1. 같은 노드 안의 동시 발화는 잡의 동시 실행 금지 설정이 막는다.
2. 두 노드가 같은 시각에 발화하는 것은 스케줄러 클러스터 모드가 막는다.
3. 두 실행이 같은 행을 각자 집는 잡 내부 경합은 조건부 UPDATE 원자 클레임이 막는다. 상태 술어가 그 사이 종결된 행의 재착수도 함께 막는다.

## 재시도·정체 회피
실패하면 시도 횟수가 오르고 종결 상태로 남으며, 재개 여부는 재큐가 정한다. 파일이 아직 도착하지 않은 행은 차기 재시도 시각을 뒤로 밀어 후보에서 빠지게 한다 — 그러지 않으면 그 행이 앞자리를 차지한 동안 뒤의 정상 인입이 픽업되지 못한다. 미도착 대기 상한은 기본 24시간이며(authoring.control.training-scan.not-arrived-timeout-hours) 그 기준 시각은 관제가 준 수신 일시가 아니라 저작도구가 미도착을 처음 관측한 시각이다. 관제가 과거 시각을 명시해 넣으면 도착하자마자 상한을 넘겨 첫 픽업에서 종결되기 때문이다.

## 구 방식은 폐지됐다
관제 공유 클립 마스터를 저작도구가 훑어 가져가던 방식은 적재 주체가 반전되면서 폐지됐고, 그 공유 테이블은 실제로 삭제됐다. 지금 이 경로가 유일한 인입 통로다.

## retry_policy

실패 시 시도 횟수 증가 후 종결하고 재개는 재큐가 결정한다. 파일 미도착 행은 차기 재시도 시각을 뒤로 밀어 후보에서 제외하며, 미도착 대기 상한은 기본 24시간이다.
