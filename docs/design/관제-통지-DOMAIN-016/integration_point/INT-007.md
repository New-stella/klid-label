### notes

**아웃바운드(저작도구→관제) 통지에는 인증 헤더가 없다** — 통지 요청은 Content-Type 만 설정하며 Authorization 등을 부착하지 않는다. ⚠ 관제 정본은 `x-access-token` 을 필수로 요구하므로 현재 상태로는 401 이 된다.
반면 **인바운드 조회 API**(`GET /v1/tasks/{rawSn}/summary|labels|meta`)는 bearer JWT + REVIEWER·WORKER 역할 인가 + 영상 접근권 검증(IDOR 방지)으로 보호된다 — 방향별 인증 체계가 다르다.
사용자 확정(2026-07-27): **JWT 는 관제서버가 발급한 것을 사용**하며 저작도구는 발급하지 않는다 — 관제 ADR-027 의 '저작도구 발급 JWT' 표현은 관제 측 부정확이므로 협의 시 정정 요청 대상. 인증 방식 적용은 차후 진행.

## description

저작도구가 검수 완료(`TASK_COMPLETED`)·검수후 수정(`TASK_MODIFIED`)을 관제서버로 push 하는 **단방향 outbound 통지**. 관제는 수신 후 저작도구 inbound 조회 API 또는 데이터마트 뷰로 상세를 가져간다. 통지 단위는 **영상 1건**(RAW_SN)이며 라벨·메타 본문은 싣지 않는다.

## ★★ 계약 전면 교체 완료 — 관제 정본과 경로·페이로드 정합
구 단일경로 `POST /api/v1/notify`(eventType 으로 완료/수정 구분) + 2단 중첩 `ControlNotifyRequest` DTO 는 **폐기**되었다. 현재:

| 통지 종류 | 경로(관제 API 대응) | 페이로드 |
|---|---|---|
| 완료 | `POST {base}/api/data-set/v2/jobs/{job_id}/notify-completed`(관제 API-251) | `TaskCompletedPayload` 평면 **required 필드**: `job_id`·`event_type_cd`·`evnt_cls_cd`·`evnt_ctgry_cd`·`lclgv_cd`·`lclgv_nm`·`duration_sec`·`image_count`·`gen_ai_yn` + **선택 `output_ver_no`** |
| 수정 | `POST {base}/api/data-set/v2/jobs/{job_id}/notify-updated`(관제 API-285) | `TaskModifiedPayload`: `job_id` + `changed_items{images[], jsons[]}`(변경 파일명 리스트, `{FRM_NO 4자리 zero-pad}.jpg`/`.json`) + **선택 `ver_expln`·`output_ver_no`** |

→ 경로·필드명이 관제 정본과 **정합 완료**(구 등록의 "경로 불일치→404 / 페이로드 교집합 0→422" 서술은 해소됨). job_id 는 `RAW_SN` 을 문자열로 표기한 값이다.

## ★ 미확정 — 인증 (B-4, 관제 회신 대기)
관제 정본은 `x-access-token` 헤더를 요구하나, 현재 통지 요청은 **Content-Type 만 설정하고 Authorization 등을 부착하지 않는다** — 현재 상태로 관제 서버에 붙이면 401 이 예상된다. `x-access-token` 발급 주체가 관제서버 발급 토큰인지 저작도구 발급 authoring JWT 인지 저작도구(사용자)와 관제 ADR-027 서술이 상충해 **미확정**이다. → auth_type 은 현재 코드 실측대로 `none` 을 유지하며, 확정 전까지 `x-access-token(관제 발급 예정, 미확정)` 으로 등록하지 않는다.

## 인바운드 조회 API
`GET /v1/tasks/{rawSn}/summary|labels|meta` — JWT + REVIEWER·WORKER 역할 인가 + 영상 접근권 검증(IDOR 방지)으로 보호.

## 수신처 주소 — 통지 전용
통지 경로의 `{base}` 는 관제 통지 수신처 주소(설정 키 `authoring.control-notify.url`)가 정한다. 관리자가 연동 서버 주소 설정에서 바꾼 값은 재기동 없이 다음 호출부터 반영된다.
- **이 주소는 통지만 쓴다.** 관제 채널 세션 중계(갱신 `POST {관제}/api/account/auth/refresh` · 로그아웃 `POST {관제}/api/account/auth/logout`, [[INT-015]])는 이 주소를 쓰지 않고 별도 연동 주소 「관제 계정 창구」(설정 키 `authoring.control-account.url`)를 쓴다. 두 주소는 서로를 대신하지 않는다(폴백 없음).
- **넣을 값**: 관제 웹서버 주소, 또는 관제 데이터셋 창구(`/api/data-set/`)를 가진 WAS 주소. 관제는 계정 창구(`/api/account/`)와 데이터셋 창구를 서로 다른 WAS 에 두므로, WAS 에 직접 붙이면 그 WAS 에 없는 창구의 경로는 404 가 된다.
- 통지 인증·활성화 토글·재시도와 장애 격리·페이로드 계약은 이 주소 분리와 무관하다.

## ★★ 관제 협의 대상 (BREAKING)
이 계약 전면교체는 관제 측 수신 엔드포인트·파서를 새 계약(2경로·평면 페이로드)에 맞춰 재구현해야 성립한다. 구 단일경로/2단 중첩 계약을 기대하던 관제 로직이 있다면 **파손**된다. 인증 헤더(B-4) 미확정 상태로는 관제 프로덕션 연동이 불가능하다 — **관제 협의 대상**.

## 해소된 갭 (job_id 타입·image_count)
- **job_id 타입 — 해소.** 수신측이 문자열 업무키를 유지하기로 확정했고, 발신측은 `RAW_SN` 을 문자열로 표기해 보낸다.
- **image_count 타이밍 — 해소.** 완료 통지는 산출이 성공(SUCCEEDED/PARTIAL)으로 확정된 뒤에만 발송되므로, 통지 시점에 프레임수가 미확정인 구간은 없다. 산출이 실패하면 통지 자체가 보류되고 재산출 성공 시점에 발송된다.

## 필드 유무 규약 (비대칭 — 의도된 설계)
- **required 필드는 값이 없어도 키를 남긴다**(명시적 `null`). 키를 빼면 수신측 검증에서 전량 거부된다.
- **선택 필드는 값이 없으면 키를 생략한다**(`ver_expln`·`output_ver_no`). 특히 `output_ver_no` 가 없으면 수신측은 **"산출물 변경 없음 — 재픽업 불요"** 로 처리한다.
- `output_ver_no` 는 그 통지가 대응하는 **산출 버전 폴더 번호**다. 재승인 1건이 새 폴더 1개와 통지 1건에 대응하므로 수신측이 통지↔폴더를 추적할 수 있다.
