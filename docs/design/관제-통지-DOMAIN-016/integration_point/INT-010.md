## description

관제서버가 검수 완료(APPROVED) 영상의 학습데이터를 데이터마트로 가져가기 위해 픽업하는 경로. 저작도구는 `klid_at` 스키마에 4종 View(`V_COMPLETED_VIDEO`/`V_COMPLETED_FRAME`/`V_COMPLETED_LABEL_CHANGE`/`V_COMPLETED_META`)를 DB 계정으로 노출하고, 관제가 이를 SELECT 한다. 기존 EXTSYS-005/INT-007 등록에는 outbound 통지(INT-007)와 inbound 조회 API만 명시돼 있었고 이 View 픽업 표면 자체가 별도 ITEM 으로 없었다.

## 확정된 부분
- `V_COMPLETED_VIDEO.OUTPUT_PATH_NM`(개명 전 `EXPORT_PATH_NM`) 이 가리키는 export 산출 루트는 **`{원본영상디렉터리}/{rawSn}/`**(관제 회신, 2026-07-27) — co-locate 모델로 확정.
- 라벨 본문은 V114(ADR-037) 뷰 슬림화 이후 뷰에 없음 — export 폴더 JSON 이 유일한 출처(`V_COMPLETED_LABEL_CHANGE`는 변경점만).
- 비식별 영상 경로는 `V_COMPLETED_VIDEO.DE_IDNTF_FILE_PATH_NM`(V138)로 노출.
- 검수 완료·통지된 영상은 어떤 사유(비식별 신고 등)로도 뷰에서 감추거나 경로를 비우지 않는다(2026-07-28 확정 정책).

## ★ 미확정 — 관제 워커의 실제 픽업 방식 (§6 B-1, 회신 대기)
관제 워커가 (a) export 루트 폴더를 통짜로 픽업(rsync/cp 류)하는지, (b) DB에서 파일별 경로를 읽어 개별 fetch 하는지 **미회신**이다. 이 프로토콜 상세는 회신 전까지 등록하지 않는다 — 본 ITEM 은 "View 4종을 통해 관제가 데이터를 가져간다"는 확정 사실만 담는다.

## ★ 미확정 — 관제 정본 대응 ITEM (§6 B-2/B-3)
관제 LogiCraft 정본의 `INT-017`(NAS 공유마운트)·`INT-018`(LS_DATA_* JDBC 직접조회)이 이 빈틈에 대응하는 것으로 추정되나 **유효성 미회신**. 우리 실제 `LS_DATA_*` 테이블은 15개(관제 ADR-067의 "9테이블" 서술과 불일치)이며, 비식별 영상 경로는 `LS_DEIDENT_PROC_LOG.DE_IDNTF_FILE_PATH_NM`(LS_DATA_* 밖)에 있다.

## 뷰에 일치도 값이 없는 것은 의도다
시계열 메타 중 일치도(`vlm.accuracy`)는 검수 대기열에 넣지 않으므로 검토 행을 내부 조인하는 `V_COMPLETED_META` 에 구조적으로 닿지 않고, 학습데이터 산출 JSON 에도 넣지 않는다. 뷰에 나오지 않는 것이 결함이 아니므로 이 값을 노출하려고 뷰를 고치지 않는다.
