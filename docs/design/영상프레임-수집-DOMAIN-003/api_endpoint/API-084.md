### klid_stream_nonce

- **in**: cookie

**schema**:

#### type

string

- **required**: false
- **description**: 재생 요소 호출(부분 요청 포함)의 인증 판정 수단인 클라이언트 바인딩 쿠키. 서명 URL 발급 API 가 응답과 함께 내려주며(HttpOnly), URL 에 실리지 않는다. 서버는 봉인을 서버 비밀로 검증해 발급자를 복원하고 그 발급자로 영상 단위 인가를 매 요청 다시 판정한다. 재생 요소 호출에서는 필수이며 부재·봉인 검증 실패·다른 사용자에게 발급된 쿠키는 401 로 거부한다(fail-closed). Authorization 헤더로 직접 호출할 때는 사용하지 않으므로 스키마상 required 로 두지 않는다.

## description

영상 파일을 HTTP Range 지원으로 스트리밍한다(마킹 화면 배속 재생용). 인증된 사용자. 호출 방식은 둘 중 하나다 — ①Authorization 헤더의 JWT(REVIEWER/WORKER)로 직접 호출, ②재생 요소가 역할 게이트된 GET /v1/videos/{rawSn}/stream-url 에서 발급받은 주소로 호출(Authorization 헤더 없음). ②의 인증은 발급 창구가 함께 내려준 클라이언트 바인딩 쿠키(klid_stream_nonce) 하나로 판정한다. 부분 요청(Range)을 포함한 매 요청마다 쿠키의 봉인을 서버 비밀로 검증해 발급자를 복원하고, 그 발급자로 영상 단위 인가(REVIEWER 는 전체, WORKER 는 본인 배정분)를 요청 진입부에서 다시 판정한다. 인가는 캐시 뒤가 아니라 진입부에서 판정하므로 캐시가 적중해도 인가를 건너뛰지 않는다. 쿠키가 없거나 봉인 검증에 실패하거나 다른 사용자에게 발급된 쿠키이면 401 로 거부한다(fail-closed). ②의 주소에는 발급 창구가 붙인 서명 쿼리(만료 시각 · 발급자 · 서명)가 계속 실려 오지만 재생 구간의 인증 수단으로 쓰이지 않는다 — 만료 시각이 지났더라도 유효한 쿠키가 동반되면 요청은 통과하고, 서명 쿼리만 있고 유효한 쿠키가 없으면 거부된다. 따라서 주소만 확보한 제3자는 재생할 수 없다. ①의 Authorization 헤더 직접 호출은 이 쿠키를 필요로 하지 않는다. 인증 방식과 무관하게 다음은 종전대로 적용된다 — 비식별이 완료되지 않은 영상의 재생 거부(404, 원본 노출 차단), 비식별 누락 신고가 열린 영상의 재생 차단, 원본 재생은 REVIEWER 가 명시할 때만 허용, Range 부분 응답(206). 포털 업로드 영상의 재생도 같은 인증 축(클라이언트 바인딩 쿠키 판정)을 따른다.
