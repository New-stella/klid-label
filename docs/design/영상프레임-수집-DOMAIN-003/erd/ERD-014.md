(RAW_DATA_ID, USER_NO, TASK_TYPE_CD) 유니크로 중복 배정 차단. (V36 신설, V9 개명) + JPA 엔티티 LsTaskAssignment. 배정 해제 창구가 신설되어 이 표의 행은 삭제될 수 있다 — 지금까지는 배정을 되돌리는 수단이 재배정뿐이었고 상태·활성 칸도 없어 배정은 행이 있거나 없거나뿐이었다. 해제는 배정만 풀며 그 작업의 결과(라벨·이력)를 함께 지우지 않는다. 해제 사실은 작업 이벤트 로그에 해제 이벤트로 남으며 배정이 풀린 작업자를 대상 사용자 칸에 싣는다. 되돌리려면 다시 배정한다 — 해제 취소 창구를 따로 두지 않는다. 검수 단계에 들어간 배정(검수 대기·검수 중·승인)은 해제가 거부된다 — 배정이 그 워크플로의 전제라 풀면 검수 흐름이 주인 없는 상태가 된다.

#### RSN

- **type**: varchar(500)
- **unique**: false
- **nullable**: true
- **description**: 이벤트 사유. 쓰임이 이벤트 종류마다 다르다 — 검수 반려(REJECT)는 반려 사유 문구가 필수이고, 프레임 폐기·복원(FRAME_DISCARD·FRAME_RESTORE)은 정해진 식별자 하나만 싣고 자유 문구를 담지 않으며, 시작 회차 적용(START_VERSION_APPLY)은 회차 번호를 담는다. 감추는 쪽만 사유를 남긴다 — 영상 제외(VIDEO_EXCLUDE)는 「왜 뺐는가」가 확정 요구라 자유 문구를 받으며 필수이고, 영상 복원(VIDEO_RESTORE)과 배정 해제(UNASSIGN)는 사유를 받지 않는다. 감춘 이유가 없으면 되돌릴지 판단할 근거가 없고, 되돌리는 쪽은 사유가 없어도 사실이 왜곡되지 않는다. 복원·해제는 지우는 방식 창구라 본문을 두지 않으며, 사유를 주소에 실으면 접근 기록에 개인정보가 남는다. 자유 문구는 개행·제어문자를 제거하고 컬럼 폭 안으로 길이를 제한해 담으며 개인정보는 적지 않는다(화면이 그 점을 안내한다). 그 밖의 이벤트는 NULL.

## description

작업 배정 고도화 ERD. 작업 단위 = 영상 1건(LS_DATA_RAW.RAW_SN, 본 ERD 에서는 RAW_DATA_ID 로 참조). 검수자가 작업자에게 라벨링 작업을 영상 단위로 배정하고, 재배정을 포함한 작업 라이프사이클 이벤트(배정·재배정·검수 시작·검수 제출·승인·반려)를 누적한다. 검수자에게는 배정하지 않는다 — 검수는 배정 없이 전체 대기열에서 집어가므로 배정을 인가 축으로 쓰지 않으며, 지금 누가 그 영상을 검수 중인지는 작업 이벤트 로그의 검수 시작 이벤트로 표현한다. (V36 신설, V9 개명) + JPA 엔티티 LsTaskAssignment/LsTaskEventLog. 재배정 전용 이력 테이블은 두지 않는다 — 재배정은 작업 이벤트 로그에 이전·신규 담당자와 수행자를 담아 같은 사실을 이미 남기고, 배정 이력 조회도 영상 식별자로 그 로그를 읽는다. 두 곳에 같은 사실을 쓰면 한쪽만 갱신될 때 서로 어긋난다. 영상을 지우지 않고 화면 목록에서만 제외하기로 한 결정(ADR-069)에 따라 영상 제외·복원과 배정 해제도 작업 이벤트 로그에 누적한다. 그 이벤트 유형 컬럼에는 값 제약이 없어 값역을 넓히는 것은 스키마 변경이 아니다. 배정 해제 창구가 생겨 배정 표의 행은 삭제될 수 있으며, 해제해도 작업 결과는 남고 이력은 이벤트 로그에 남는다.
