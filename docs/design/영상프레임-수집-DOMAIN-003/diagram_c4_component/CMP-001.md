## description

배치 파이프라인 컴포넌트 구조.

[단계 순서] ①비식별(DeidentifyStep, 전체 영상·마킹 선행) → [작업자가 비식별 영상에서 마킹] → ②VLM(VlmTimeseriesStep) → ③프레임추출(마킹위치 원본+비식별 2벌) → ④YOLO(원본만) → ⑤SAM2 → ⑥트랙보간.
★구 divergence 해소: 이전 본문은 '현재 코드는 구 순서(VlmTimeseriesStep → DeidentifyStep) 구현, 비식별 선두는 planned' 라고 적었으나 재배치가 완료됐다. 단계 구성은 선언적 파이프라인(BatchStep/BatchContext/BatchPipeline/BatchPipelineConfig)이 소유하며 pre-marking=[DEIDENTIFY], post-marking=[MARKING, VLM, FRAME_EXTRACT, YOLO, SAM2, INTERPOLATE] 로 나뉘고 List.of(...) 한 곳에서 재배치된다. 각 단계는 isEnabled(ctx) 조건부 실행을 지원한다.

[트리거] 선두 비식별은 적재 직후 VideoIngestedEvent(EVT-005) → IngestDeidentifyBridge(AFTER_COMMIT) → AsyncDeidentifyRunner. 잔여 배치는 마킹 완료(MarkingCompletedEvent, EVT-001) → MarkingBatchBridge(AFTER_COMMIT) → AsyncBatchRunner 또는 Quartz(BatchQuartzJob)가 BatchOrchestrator.process(rawSn) 구동. 각 Step 은 REQUIRES_NEW, 실패 시 BatchRetryQueue 재처리.

[★외부 위탁은 논블로킹 제출] VlmTimeseriesStep 은 .block(45s) 로 파이프라인 스레드를 붙잡지 않고 subscribe() 로 제출만 개시한다(구 방식은 외부가 느려지면 core 2 짜리 배치 풀이 통째로 마른다). 수락 여부는 완료 핸들러가 비동기 기록하고, 아무 신호도 없으면 미결 스위퍼가 회수한다. ⚠미결 임계는 ACK 창(기본 30분)과 콜백 창(기본 360분) 두 개이며 하나로 덮으면 정상 위탁을 빼앗는다.

[신고 구간 보류] 비식별 누락 신고 중인 영상은 VLM 위탁을 실패가 아니라 보류(SKIPPED + 사유 적재)하고, 해소 시 DeidentGateReopenedEvent(EVT-007) → VlmResumeBridge 가 재위탁한다. 보류는 스스로 재개되지 않으므로 이 배선이 없으면 시계열 메타가 영구 결손된다.

컴포넌트·관계는 실제 생성자 의존성에서 도출(SEQ-001 시퀀스 참조).
