## description

UC-018 영상 적재의 컴포넌트 구조. ★ADR-042 로 적재 주체가 반전됐다 — 관제서버가 LS_DATA_INGEST 에 직접 INSERT 하고, 저작도구는 그 테이블을 폴링해 적재한다. 구 구조(관제 공유 MNG_CLIP_MASTER.JOB_DMND_YN='Y' 후보를 READ 해 픽업)는 폐기됐고 해당 Repository 2종도 삭제됐다.

[흐름] Quartz Job(ControlTrainingVideoScanJob, @DisallowConcurrentExecution, 1회/분) → ①좀비(PROCESSING 고착) 회수를 스캔 앞에 수행해 회수된 행이 같은 tick 에 바로 처리되게 한다(회수 실패는 흡수해 그 tick 의 정상 적재를 막지 않는다) ②TrainingVideoIngestService.scanAndIngest 가 미처리 행을 배치 조회(상한 100) ③행별로 TrainingVideoIngestTx(REQUIRES_NEW 독립 트랜잭션)이 원자 클레임 후 LS_DATA_RAW(PENDING) 적재 ④VideoIngestedEvent(EVT-005) 발행 → 선두 비식별 파이프라인으로 이어진다.

[★4노드 Active-Active 안전장치] Quartz 클러스터링은 트리거 중복 발화만 막고 잡 내부 레이스는 막지 않는다. 그래서 후보 선점을 조건부 UPDATE 로 원자 클레임하고, 클레임 후 죽은 노드 때문에 PROCESSING 으로 고착된 행은 타임아웃 기반 회수가 되살린다.

[부분 실패 격리] 행별 적재를 REQUIRES_NEW 로 분리해 한 건의 실패가 나머지 tick 을 깨뜨리지 않는다. 식별자·파일경로 gap 은 skip(WARN), 멱등은 VMS_CLIP_ID 조회 + UK 위반 catch 이중 방어다.
