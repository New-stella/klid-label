# 촬영환경·개인정보 메타 수동입력 신설(+self-fill 자동파생 폐기)

## context

R1 요구사항에 없는 촬영환경(날씨/시간대/계절, 영상단위)·개인정보(익명/가명/PII포함, 프레임단위) 메타를 라벨링 메타탭에서 수동 입력하도록 신규 추가 결정했다. 이후 '촬영시각 규칙 기반 자동 파생(self-fill)'이 여름 18:00 촬영분을 야간(NGT)으로 오분류하는 등 오류가 실증되어 제거되었다.

## decision

### chosen_option

수동 입력 + 미입력은 null(미상) 유지(채택)

### justification

촬영환경(WTHR_NM/DAY_NGT_CD/SESN_CD)·개인정보(ANONY/PSDO/PRVC_INCL_YN) 메타를 라벨링 화면에서 WORKER/REVIEWER가 수동 입력·저장한다(R1 요구 외 추가). 미입력은 자동 파생하지 않고 null(미상) 유지하며, 레거시 self-fill 동결값은 정정 백필한다. ★ 추가 확정(2026-08-03) — 개인정보 축이 두 개로 분화되고 export 판정 정책이 반전됐다. ① 저장소가 두 입도다: 프레임 축 LS_DATA_SRC.*_INCL_YN(V130)에 더해 영상 축 LS_DATA_RAW.*_INCL_YN(V163)을 신설하고 화면(GET/PUT /v1/videos/{rawSn}/privacy-meta)을 붙였다. export JSON 의 video 블록은 영상 축을, image 블록은 프레임 축을 읽는다 — 두 값이 달라도 모순이 아니다('영상 어딘가엔 있지만 이 프레임엔 없다'는 서로 다른 입도의 사실). ② export 판정은 원천(orgnl)·비식별(deid) 두 축을 모두 대상으로 한다(2026-08-04 확정 — 구 '원천은 판정하지 않고 3필드 전부 null' 은 폐기): 비식별 산출물은 수동값 우선·미입력 시 기본값(Y/N/N)이고, 원천 산출물은 video 블록이 관제 인입값(LS_DATA_INGEST 의 익명·가명·개인정보 포함여부 3컬럼)을 그대로 싣되 관제가 보내지 않은 필드는 지어내지 않고 null 로 두며, image 블록은 프레임 단위 원천 판정 데이터가 존재하지 않으므로 정책 상수(N/N/Y)를 싣는다. 원천에도 값을 싣는 이유는 export JSON 이 다시 읽혀 적재되는 자산이라 null 이면 '판정하지 않았다'와 '값이 유실됐다'가 구분되지 않기 때문이다. 두 블록의 원천값은 같아 보여도 출처가 달라 갈릴 수 있고(관제가 개인정보 포함여부를 N 으로 보내면 video 는 N, image 는 상수 Y) 이는 모순이 아니라 입도가 다른 사실이므로 통합하지 않는다. 판정 로직은 ExportPrivacyPolicy 한 곳에서만 정하고 두 화면의 프리필도 같은 상수를 참조한다(복제 금지). ③ 파생영상은 부모의 영상 축 판정을 생성 시점 1회 계승한다(copyPrivacyMetaFrom) — 계승하지 않으면 image='Y'/video='N' 로 갈려 개인정보가 과소 신고된다. ④ 영상 축 PUT 은 동시 승인과 직렬화되고(rawSn advisory lock) 비식별 신고 구간에 412 로 차단되며 LS_TASK_EVNT_LOG 에 행 단위 감사를 남긴다(판단값 Y/N 은 남기지 않는다 — CWE-359). ⚠ 구 정책(2026-07-31, 원천=개인정보 있음 + ORIGINAL 한정 수동 override / 비식별=상수 고정 + 수동값 무시)은 정확히 반대였으며 폐기됐다 — 되돌리지 말 것.

## consequences

### risks

- 영상 축 값은 라이브 LS_DATA_RAW 에만 있고 동결 스냅샷이 없으므로, 승인된 영상을 고친 뒤 재검수에서 승인될 때 산출물 전량 재생성과 산출 내용 해시 입력 편입이 세트로 필요하다 — 하나만 빠지면 저장은 됐는데 산출물이 안 바뀌는 결함이 된다
- [해소] ADR-042 의 'export 원천 개인정보 판정을 관제 인입값 기반으로 전환' 이 구 확정('원천은 판정하지 않고 null')과 정면 충돌하던 항목 — 2026-08-04 확정으로 관제 인입값 기반 판정이 채택되어 충돌이 없어졌다. 남는 제약은 관제가 보내지 않은 필드를 지어내지 않고 null 로 두는 것이다.

### negative

- R1/R3 요구사항정의서에 없는 항목이므로 '요구사항 외 추가' 명시 및 v1-wiki 19 갭체크리스트 갱신 필요
- 작업자 수동 입력 부담 발생
- 프론트는 사용자가 직접 고르지 않은 필드를 null 로 전송해야 함 — DERIVED 프리필을 그대로 되돌려 보내면 상수가 사람의 판정으로 승격되며 백엔드는 출처를 알 수 없어 막지 못함
- 원천 축에 관제 인입값과 정책 상수가 실리면서 '관제가 실제로 N 이라 판정한 것'과 '기본값이 N 인 것'이 값만으로는 구분되지 않는다 — 인지하고 수용한 대가다

### positive

- 규칙기반 자동파생의 오분류(여름 18:00→야간 오분류 등) 문제 제거
- 불확실한 값을 명시적으로 미상(null) 처리해 데이터 신뢰도 향상
- 개인정보 판정이 '사람이 입력한 사실' 기반으로 수렴 — 영상 축 저장소(V163) 신설로 비식별 산출물에서도 수동값 override 가 가능해졌고, 구 정책이 override 를 막았던 근거(프레임 수동값을 태울 원천이 video 블록에 없음)가 소멸
- 판정 상수를 ExportPrivacyPolicy 단일 원천으로 묶어 화면 표시값과 산출물 값의 어긋남(프레임 패널은 N 인데 deid export 는 Y) 제거
- 원천 축에도 값을 실어 export JSON 을 다시 읽어 적재할 때 '판정하지 않았다'와 '값이 유실됐다'가 구분된다

## considered_options

### 촬영시각 규칙 기반 자동 파생(self-fill, 구 로직, 폐기)

**cons**:

- 여름 18:00 촬영분이 야간(NGT)으로 오분류되는 등 규칙기반 파생의 정확도 결함 실증

**pros**:

- 작업자 입력 없이 자동 채움

- **description**: 촬영환경 메타(날씨/시간대/계절)를 촬영시각 규칙으로 자동 파생

### 수동 입력 + 미입력은 null(미상) 유지(채택)

**cons**:

- 작업자의 수동 입력 부담 발생
- R1/R3 요구 외 추가 기능이라 문서 동기화 필요

**pros**:

- 규칙기반 오분류 문제 제거
- 정확한 값만 기록되고 불확실한 값은 명시적으로 미상 처리

- **description**: 촬영환경(WTHR_NM/DAY_NGT_CD/SESN_CD)·개인정보(ANONY/PSDO/PRVC_INCL_YN) 메타를 라벨링 화면에서 WORKER/REVIEWER가 수동 입력·저장. 미입력은 자동 파생하지 않고 null(미상) 유지
