# UC-011 선두 비식별 실패 후 배치 재시작 — 건별·일괄 접수(stage=PENDING·선점 없음)→선두 비식별 1회 재수행→비식별 완료·마킹 준비·잠금 해제, 미실패 영상 불변·자동 재시도 없음 (happy)

## notes

축 판정 — 이 기준은 정상 경로(happy)다. 출처 UC-011 의 대안 흐름 「선두 비식별 실패 후 배치 재시작」 1·4~6·8 단계에 대응한다. 거부(2·3 단계)와 잠금 해제(7 단계)는 각각 별도 기준으로 나눴다 — 한 기준에 몰면 어느 단언이 깨졌는지 시험 결과로 가릴 수 없다.
선두 비식별 단계 자체의 위탁·복사·완료 판정은 AC-1063 이, 그 실패 종결의 영상 상태는 AC-1064 가 정한다. 이 기준은 그 단계를 「다시 태우는 진입」만 다룬다.
★시험을 짤 때 빠지기 쉬운 자리 — ①비식별이 실패하지 않은 영상의 기존 재시작 시험을 그대로 돌린다(형상 판정이 넓어져 기존 영상을 잘못 끌어들이면 여기서 깨진다) ②일괄 전건 거부 사례를 화면 시험으로도 결박한다(응답만 보면 결과 창이 안 뜨는 결함이 통과한다) ③접수 응답의 stage 값을 실제로 읽어 PENDING 인지 본다.

## priority

high

## scenario

### then

- 건별 재시작 응답은 200 이고 본문은 {rawSn, stage} 이며 stage 는 PENDING 이다
- 접수 시점에 배치 단계가 PROCESSING 으로 바뀌지 않는다
- 같은 영상에 대한 영상 단위 작업 잠금이 정확히 1건 생기고, 선두 비식별 단계가 정확히 1회 다시 수행된다
- 다시 수행되는 단계는 적재 직후와 같다 — 출처유형이 처리 시점 제외 목록에 들면 원본 복사로, 아니면 외부 솔루션 위탁으로 처리된다
- 요청 처리 중에 영상 비식별 여부가 'N' 으로 되돌아가지 않는다
- 성공하면 영상 비식별 여부가 'Y', 배치 단계가 MARKING_READY 가 되고 그 작업 잠금이 해제된다
- 일괄 재시작에 섞인 선두 비식별 실패 영상도 건별과 같은 결과(접수 성공 1건 · 선두 비식별 1회 재수행)가 나온다
- 같은 일괄 요청의 배치 실패 영상은 종전대로 마킹 이후 단계가 재기동된다
- 일괄 요청이 한 건도 접수되지 못해도 응답은 200 이고 결과에 접수 0건과 건별 거부 사유가 실리며, 영상 목록 화면은 결과 창에 접수 0건과 그 사유를 보인다
- 비식별이 실패하지 않은 영상의 재시작 판정·응답·재기동 동작은 이 결정 이전과 같다
- 선두 비식별 단계가 실패해도 시스템이 스스로 재시작을 다시 걸지 않는다 — 자동 재시도·주기 회수·스케줄이 없다
- 재위탁 사례에서 외부 솔루션이 위탁을 수락한다 — 같은 이름의 프로젝트가 이미 있다는 이유로 거부되지 않는다
- 다시 위탁한 프로젝트 이름은 앞선 회차의 이름과 다르고(이번 회차 비식별 처리 이력 번호가 붙는다, 영문·숫자만), 세 번째 위탁의 이름도 앞선 두 이름과 다르다
- 그 영상의 첫 위탁 프로젝트 이름은 raw{영상번호} 그대로이고, 재위탁 전에 이전 프로젝트 삭제가 호출되지 않는다

### when

- 검수자가 영상 상세의 배치 실패 패널에서 재시작을 누른다(건별 재시작)
- 검수자가 영상 목록에서 여러 영상을 골라 일괄 재시작한다
- 비동기로 넘어간 선두 비식별 단계가 성공으로 끝난다
- 비식별이 실패하지 않은 영상에 재시작을 요청한다
- 재위탁 사례의 영상을 배치 재시작하고, 그 재수행이 다시 실패한 뒤 한 번 더 재시작한다

### given

- 검수자(관리자는 역할 계층으로 포함)로 인증돼 있다
- 대상 영상은 선두 비식별 단계가 실패해 영상 비식별 여부 'F' · 배치 단계 PENDING 이며, 파생영상이 아니고 승인 이력·열린 비식별 누락 신고·진행 중인 비식별 위탁·다른 요청이 잡은 같은 영상의 작업 잠금이 없다
- 일괄 사례에서는 같은 요청에 마킹 이후 단계가 실패로 고착된 배치 실패 영상이 함께 있다
- 비교 사례로 비식별이 실패하지 않은 영상이 있다
- 재위탁 사례로, 외부 위탁이 한 번 나간 뒤 진행 상태 폴링 실패 · 처리 시한 초과 · 수락 응답 미관측 회수 중 하나로 실패해 같은 형상(비식별 여부 'F' · 배치 단계 PENDING)에 머문 영상이 있다

## statement

선두 비식별 단계가 실패해 마킹 준비에 이르지 못한 영상(영상 비식별 여부 'F' 이고 배치 단계가 PENDING 인 영상)을 검수자가 배치 재시작하면, 적재 직후와 같은 선두 비식별 단계를 한 번 다시 수행해 마킹에 들어갈 수 있게 된다. 비식별 실패도 배치 실패로 보며, 새 창구나 새 버튼 없이 기존 건별 재시작 [[API-167]] 과 일괄 재시작 [[API-199]] 이 이 영상을 받는다 — 영상 상세 [[SCREEN-009]] 의 배치 실패 패널 재시작 버튼과 영상 목록 [[SCREEN-008]] 의 일괄 재시작이 그 진입점이다.

건별 재시작은 200 으로 {rawSn, stage} 를 돌려주며 stage 는 접수 시점의 실제 단계인 PENDING 이다 — 이 경로는 배치 단계를 PROCESSING 으로 선점하지 않으므로 PENDING 은 오류가 아니다. 접수만 요청 안에서 하고 실행은 비동기로 넘긴다. 다시 수행하는 단계는 외부 솔루션 위탁이거나 출처유형 제외에 따른 원본 복사이며, 어느 쪽인지는 처리 시점 설정으로 판정한다. 성공하면 영상 비식별 여부가 'Y', 배치 단계가 MARKING_READY 가 되고 이 요청이 잡은 영상 단위 작업 잠금이 풀린다. 재시작 요청이 영상 비식별 여부를 'N' 으로 되돌리지는 않는다.

일괄 재시작에 이 영상이 섞여도 건별과 같은 판정·같은 결과가 나오고, 같은 요청에 섞인 배치 실패 영상(마킹 이후 단계가 실패로 고착된 영상)은 종전대로 마킹 이후 단계를 재기동한다. 한 건도 접수되지 못해도 일괄 응답은 200 이며 건별 결과에 접수 0건과 각 건의 거부 사유가 실리고, 영상 목록 화면은 그 결과를 결과 창에 보인다.

외부 위탁이 한 번 나간 뒤 실패한 영상(진행 상태 폴링 실패 · 처리 시한 초과 · 수락 응답을 관측하지 못한 회수)도 재시작하면 외부 솔루션이 다시 위탁을 수락한다. 다시 위탁할 때는 이번 회차 비식별 처리 이력 번호를 붙인 프로젝트 이름(예 raw44r57, 영문·숫자만)을 써 앞선 회차와 겹치지 않으므로, 같은 이름 프로젝트가 있다는 이유로 거부되지 않는다. 그 영상의 첫 위탁 이름은 종전대로 raw{영상번호} 이고, 재시작은 이전 프로젝트를 지우지 않는다(이름 규칙 [[INT-004]]).

비식별이 실패하지 않은 영상의 재시작 동작·응답은 이 결정 이전과 같다. 자동 재시도·주기 회수·스케줄은 없다 — 사람이 재시작을 요청할 때만 선두 비식별 단계가 다시 돈다([[ADR-006]] 의 「자동 재비식별 큐를 두지 않는다」와 양립한다). 거부 조건은 예외 기준([[AC-1134]])이, 실패 종결에서의 잠금 해제는 잠금 기준([[AC-1135]])이 정한다.
