# D1 클래스 설계서

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-UC/DC/DCD/SD/UCD 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. ※ 요구사항(RQ-SFR-NN-NN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 소프트웨어 관점이나 설계 관점에서의 클래스 모형을 작성한다.

## 작성 방법
> 설계 클래스를 도출하기 위하여 우선 유스케이스별로 시퀀스도를 작성하며, 여기에서 도출된 객체 및 클래스를 연관관계를 이용하여 유스케이스별로 클래스도를 작성한다. 설계 클래스도에서는 클래스명, 속성 및 오퍼레이션을 명확하고 구체적으로 표현하여야 하고 각각의 클래스는 상세한 명세를 기술한다.

> - **설계 클래스도(DCD)·시퀀스도(SD) ID ↔ 유스케이스(UC) ID는 1:1**: DCD·SD 번호는 실현 유스케이스 번호와 정렬한다(KLID-AT-DCD-001/KLID-AT-SD-001 ↔ KLID-AT-UC-001, …, KLID-AT-DCD-026/KLID-AT-SD-026 ↔ KLID-AT-UC-026). R2 유스케이스 결번(KLID-AT-UC-012/014/015/017)에 맞춰 **KLID-AT-DCD-012/014/015/017·KLID-AT-SD-012/014/015/017도 결번**이다. ※ UCD(유스케이스 다이어그램)는 유스케이스가 아니며 반복 단위가 아니다.
> - **근거 우선순위**: R1 v1.17 + 현행 코드 기준. 도메인 모델 다이어그램과 코드가 충돌하면 코드 기준으로 기술한다.
> - 시퀀스 다이어그램은 Mermaid `sequenceDiagram` 표기로 작성한다. SD ID는 본 문서 자체 채번(SD 번호 = 실현 UC 번호)이다. (영상수집 파이프라인 교차 시나리오는 R1 UC 미실현으로 본 설계서 범위 외)
