# D1 클래스 설계서

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-UC/CO/DC/DCD/SD/SC/AC/EN/ERD/TB/II/IC/IF/UCD/ACT 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. 범위는 시작 ID만 전체형으로(예: `KLID-AT-UC-001~013`). ※ 요구사항(RQ-SFR-NN-NN)·시스템시험(KLID-ST-NNN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 소프트웨어 관점이나 설계 관점에서의 클래스 모형을 작성한다.

## 작성 방법
> 설계 클래스를 도출하기 위하여 우선 유스케이스별로 시퀀스도를 작성하며, 여기에서 도출된 객체 및 클래스를 연관관계를 이용하여 유스케이스별로 클래스도를 작성한다. 설계 클래스도에서는 클래스명, 속성 및 오퍼레이션을 명확하고 구체적으로 표현하여야 하고 각각의 클래스는 상세한 명세를 기술한다.

## 2. 시퀀스도

> **⟳ 유스케이스별로 1개씩 반복 작성한다.** (시퀀스도 번호 = 실현 유스케이스 번호 동조, 결번 동조)

### 2.1 KLID-AT-SD-001 — 증강 영상 생성 요청

| 시퀀스도 ID | KLID-AT-SD-001 | 시퀀스도명 | 증강 영상 생성 요청 (REVIEWER 요청 → 외부 위임) |
|---------|---|-------|---|
| 관련 유스케이스 ID | KLID-AT-UC-001 |
| 주요 액터 | 검수자(REVIEWER), 생성형AI서비스[외부] |
| 주요 클래스 | AugmentController, AugmentRequestService, LsRawDataStatusRepository, ExternalAugmentClient |

```mermaid
sequenceDiagram
    autonumber
    actor RV as 검수자(REVIEWER)
    participant AC as AugmentController
    participant ARS as AugmentRequestService
    participant DB as LsRawDataStatusRepository
    participant EX as ExternalAugmentClient
    RV->>AC: POST /v1/augments/request (videoIds, types)
    AC->>ARS: request(req, actor)
    ARS->>ARS: requireReviewer(actor)
    ARS->>ARS: videoIds/types distinct 정규화
    ARS->>DB: findByRawDataIdIn(videoIds)
    DB-->>ARS: 상태 목록
    alt 미검수(APPROVED 아님) 포함
        ARS-->>AC: NOT_REVIEWED (blockedVideoIds)
        AC-->>RV: 400 + blockedVideoIds
    else 전부 APPROVED
        ARS->>EX: requestAugment(videoIds, types) (best-effort)
        EX-->>ARS: ack (실패 시 warn 로그만)
        ARS->>ARS: jobId 발급 (AtomicLong)
        ARS-->>AC: AugmentRequestResponse(jobId, counts)
        AC-->>RV: 200 OK
    end
```

## 부록 — 빈 셀·결번·생성 기준 사유

- **빈 셀 처리**: 본 산출물에는 추측으로 채운 셀이 없으며, 존재하지 않는 값은 `-`로 표기하였다(예: 인터페이스/요청 진입점 클래스의 속성 부재). `KLID-AT-DC-004`(Repository 인터페이스)·`KLID-AT-DC-035`(요청 진입점)는 속성이 없어 해당 표를 비움 표기하였다.
