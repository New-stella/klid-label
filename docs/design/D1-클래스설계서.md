# D1 클래스 설계서

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-UC/DC/DCD/SD/UCD 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. ※ 요구사항(RQ-SFR-NN-NN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 소프트웨어 관점이나 설계 관점에서의 클래스 모형을 작성한다.

## 작성 방법
> 설계 클래스를 도출하기 위하여 우선 유스케이스별로 시퀀스도를 작성하며, 여기에서 도출된 객체 및 클래스를 연관관계를 이용하여 유스케이스별로 클래스도를 작성한다. 설계 클래스도에서는 클래스명, 속성 및 오퍼레이션을 명확하고 구체적으로 표현하여야 하고 각각의 클래스는 상세한 명세를 기술한다.

> **CBD 4섹션 반복 구성 안내**
> - 본 산출물은 **유스케이스(UC)** 단위로 §1 설계 클래스 목록·§2 시퀀스도·§3 설계 클래스도를, **클래스** 단위로 §4 설계 클래스 정의를 반복 작성한다(전역 통합 금지). 작성 방법 원문 기준: "유스케이스별로 시퀀스도를 작성하며 … 유스케이스별로 클래스도를 작성한다".
> - **설계 클래스도(DCD)·시퀀스도(SD) ID ↔ 유스케이스(UC) ID는 1:1**: DCD·SD 번호는 실현 유스케이스 번호와 정렬한다(KLID-AT-DCD-001/KLID-AT-SD-001 ↔ KLID-AT-UC-001, …, KLID-AT-DCD-016/KLID-AT-SD-016 ↔ KLID-AT-UC-016). R2 유스케이스 결번(KLID-AT-UC-012/014/015)에 맞춰 **KLID-AT-DCD-012/014/015·KLID-AT-SD-012/014/015도 결번**이다. ※ UCD(유스케이스 다이어그램)는 유스케이스가 아니며 반복 단위가 아니다.
> - **근거 우선순위**: R1 v1.17 + 현행 코드 기준. 도메인 모델 다이어그램과 코드가 충돌하면 코드 기준으로 기술한다.
> - 시퀀스 다이어그램은 Mermaid `sequenceDiagram` 표기로 작성한다. SD ID는 본 문서 자체 채번(SD 번호 = 실현 UC 번호)이다. (영상수집 파이프라인 교차 시나리오는 R1 UC 미실현으로 본 설계서 범위 외)

## 2. 시퀀스도

> **⟳ 유스케이스별로 1개씩 반복 작성한다.**
> **SD ID = 실현 UC 번호** (KLID-AT-SD-001 ↔ KLID-AT-UC-001, …). R2 UC 결번에 동조하여 **KLID-AT-SD-012/014/015는 결번**이다.

### 2-1. KLID-AT-SD-001 — 증강 영상 생성 요청

| 시퀀스도 ID | KLID-AT-SD-001 | 시퀀스도명 | 증강 영상 생성 요청 |
|---------|---|-------|---|
| 관련 유스케이스 ID | KLID-AT-UC-001 |
| 주요 액터 | 검수자(REVIEWER) | 주요 클래스 | AugmentController, AugmentRequestService, LsRawDataStatusRepository, ExternalAugmentClient |

```mermaid
sequenceDiagram
    autonumber
    actor RV as 검수자(REVIEWER)
    participant AC as AugmentController
    participant ARS as AugmentRequestService
    participant DB as PostgreSQL (LS_RAW_DATA_STATUS)
    participant EX as ExternalAugmentClient (외부 SFR-07)

    RV->>AC: POST /v1/augments/request (videoIds, types)
    AC->>ARS: request(req, actor)
    ARS->>ARS: requireReviewer(actor)
    ARS->>ARS: videoIds/types distinct 정규화
    ARS->>DB: findByRawDataIdIn(videoIds)
    DB-->>ARS: 상태 목록
    alt 미검수(APPROVED 아님) 영상 포함
        ARS-->>AC: NOT_REVIEWED (blockedVideoIds)
        AC-->>RV: 400 + blockedVideoIds
    else 전부 APPROVED
        ARS->>EX: requestAugment(videoIds, types) (best-effort)
        EX-->>ARS: ack (실패 시 warn 로그만)
        ARS->>ARS: jobId 발급 (AtomicLong)
        ARS-->>AC: AugmentRequestResponse(jobId, requestedAt, counts)
        AC-->>RV: 200 OK (jobId)
    end
```

### 2-2. KLID-AT-SD-002 — 증강 결과 수신·등록

| 시퀀스도 ID | KLID-AT-SD-002 | 시퀀스도명 | 증강 결과 수신·등록 |
|---------|---|-------|---|
| 관련 유스케이스 ID | KLID-AT-UC-002 |

```mermaid
sequenceDiagram
    autonumber
    participant EX as 외부 생성형 AI (SFR-07)
    participant ARC as AugmentResultController
    participant ARS as AugmentResultService
    participant LG as WebhookIdempotencyLedger
    participant DB as PostgreSQL

    EX->>ARC: POST /v1/augments/result (HMAC, idempotencyKey, originAugSn, augType, status)
    ARC->>ARS: handle(req)
    ARS->>LG: isIssued(idempotencyKey)
    alt 미발급 키
        ARS-->>ARC: UNAUTHORIZED
        ARC-->>EX: 401
    else 발급된 키
        ARS->>LG: isProcessed(idempotencyKey)
        opt 이미 처리됨
            ARS-->>ARC: applied=false (멱등 스킵)
        end
        ARS->>ARS: validateFilePath(resultFilePath) (SSRF)
        ARS->>DB: findById(originAugSn)
        DB-->>ARS: LsDataAug
        ARS->>ARS: augType 일치 검증 (불일치 시 409)
        ARS->>DB: LsDataAug 상태 전이 + 멱등 컬럼 save
        opt status=SUCCESS (ACCEPTED)
            ARS->>DB: createFromAugment 새 LsDataRaw(PARENT_RAW_SN, PENDING)
            ARS->>DB: 프레임 saveAll (LS_DATA_SRC)
            ARS->>DB: 라벨 findBySrcSnIn + copyForNewSrc saveAll
            ARS->>DB: 메타 saveAll (LS_DATA_META)
        end
        ARS->>LG: markProcessed(idempotencyKey)
        ARS-->>ARC: applied=true
        ARC-->>EX: 200 OK
    end
```

### 2-3. KLID-AT-SD-003 — 해상도 변경 수행

| 시퀀스도 ID | KLID-AT-SD-003 | 시퀀스도명 | 해상도 변경 |
|---------|---|-------|---|
| 관련 유스케이스 ID | KLID-AT-UC-003 |

```mermaid
sequenceDiagram
    autonumber
    actor RV as 검수자(REVIEWER)
    participant VC as VideoController
    participant VRS as VideoResolutionService
    participant SRC as LS_DATA_SRC (원본 프레임)
    participant RZ as Java2DImageResizer
    participant FS as 스토리지(다운스케일 출력 디렉토리)
    participant VP as VideoResolutionPersister (REQUIRES_NEW)
    participant DB as PostgreSQL (LS_RESOLUTION_EXPORT)

    RV->>VC: POST /v1/videos/{rawSn}/resolution {preset}
    VC->>VRS: changeResolution(rawSn, request, regId)
    VRS->>DB: APPROVED + 비-증강본 검증
    alt 미검수(409) / 증강본(400) / 프레임 0건(400)
        VRS-->>VC: 4xx
        VC-->>RV: 오류 응답
    else 검증 통과
        VRS->>DB: 동일 영상+해상도 EXPORT 중복 사전체크
        VRS->>SRC: 첫 프레임 실측 해상도 조회
        SRC-->>VRS: srcW, srcH
        alt 업스케일(목표 H >= 원본 H) 400
            VRS-->>VC: 400
            VC-->>RV: 오류 응답
        else 다운스케일 가능
            VRS->>VRS: Semaphore(fair) 슬롯 획득 (초과 429)
            VRS->>FS: 출력 디렉토리 멱등 초기화
            loop 프레임 청크(500)
                VRS->>SRC: 원본 프레임 경로 조회 (CWE-22 검증)
                VRS->>RZ: 종횡비 보존 다운스케일
                RZ->>FS: 다운스케일 이미지 저장
```
