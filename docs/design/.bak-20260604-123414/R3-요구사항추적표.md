# R3 요구사항 추적표

> **ID 표기 규칙(공통)**: 본 산출물의 AT 산출물 ID(UC/AC/SC/CO/EN/TB 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. 범위는 시작 ID만 전체형으로(예: `KLID-AT-UC-001~013`). ※ 요구사항(`RQ-SFR-NN-NN`)·비기능(`NFR-NNN`)·시스템시험(`KLID-ST-NNN`)·LogiCraft 그래프 원본(`SCREEN-NNN`·`MOD-NNN`·`ERD-NNN`·`CMP-NNN`·`FEAT-NNN`·`API-NNN`)은 각 체계 원형을 유지한다.

## 작성 목적
> 시스템의 요구사항을 도출하여 개발의 각 단계별로 작성한 산출물이 일관성을 가지는지를 추적할 수 있도록 각 단계별 산출물의 추적성을 관리하기 위하여 작성한다.

## 작성 방법
> 사용자 요구사항 정의서(R1)로부터 시작하여 분석(R2 유스케이스·검수기준), 설계(화면/컴포넌트/테이블), 구현(코드 모듈), 시험(검수기준)의 각 단계별 산출물에 ID를 식별하고, 전단계 산출물과 후속단계 산출물 간의 연계관계를 매핑하여 산출물이 단계별로 끊어지지 않고 추적되도록 한다. 모든 매핑은 **LogiCraft 그래프의 `get_neighbors`(직접 연결 이웃)만으로** 연결하였다 — 추측·임의 ID 부여 금지. 연결이 끊긴 셀은 `-`로 표기하고 §4 부록에 사유를 명시한다.

## 1. 개요

### 1.1 추적 대상 산출물 및 ID 체계 (LogiCraft 그래프 진실원)

| 단계 | 산출물 | LogiCraft 타입 | ID 형식(표기) | 출처 |
|------|--------|----------------|---------------|------|
| 분석 | 사용자 요구사항(기능) | requirement | `RQ-SFR-NN-NN` (LogiCraft `REQ-NNN`) | R1 |
| 분석 | 사용자 요구사항(비기능) | nfr | `NFR-NNN` | R1 |
| 분석 | 기능(연결 허브) | feature | `FEAT-NNN` | 그래프 |
| 분석 | 유스케이스 | use_case | `KLID-AT-UC-NNN` (그래프 `UC-NNN`) | R2 |
| 분석/시험 | 검수기준(Acceptance) | acceptance | `KLID-AT-AC-NNN` (그래프 `AC-NNN`) | 그래프 |
| 설계 | 사용자 인터페이스(화면) | screen_spec | `SCREEN-NNN` | D2 |
| 설계 | 컴포넌트(C4) | diagram_c4_component | `CMP-NNN` | D3 |
| 설계 | 데이터베이스(ERD) | erd | `ERD-NNN` | D9 |
| 구현 | 프로그램 코드 모듈 | code_module | `MOD-NNN` | backend/ai-server/frontend |
| 구현 | 단위시험 | — | `KLID-AT-UT-NNN` | **미작성(후속)** |
| 시험 | 통합시험 시나리오 | — | `KLID-IT-TS-NNN` | **미작성(후속)** |
| 시험 | 시스템시험 시나리오 | — | `KLID-ST-NNN` | **후속(D7)** |

> **그래프 토폴로지 주의**: LogiCraft 그래프에서 `requirement`는 `use_case`에 직접 연결되지 않고 **`feature`(`FEAT-NNN`)를 허브로** 연결된다(`requirement ←implements← feature →realizes→ use_case`). 화면(`screen_spec`)·코드모듈(`MOD`)은 `feature`/`use_case`가 `references`/`realizes`로, 테이블(`ERD`)·컴포넌트(`CMP`)는 `domain`(`belongs_to_domain`)을 경유해 연결된다. 검수기준(`AC`)은 `use_case`에서 `derived_from`으로, 요구사항(`REQ`)에서 `verifies`로 연결된다. 본 표의 각 셀 ID는 모두 이 경로의 직접 이웃에서 추출한 것이다.

### 1.2 행(Row) 구성 원칙
- 본문 추적표(§2)의 행은 **R1에 등재된 활성 SFR 기능 요구사항 15건**(`RQ-SFR-06-03`~`RQ-SFR-09-05`, LogiCraft `REQ-001`·`REQ-003`~`REQ-016`)으로 구성한다.
  - **건수 주석(active 15 / 전체 18)**: LogiCraft `requirement`는 총 18건이며, 그중 3건(`REQ-002`=`RQ-SFR-06-04` 프롬프트 편의성, `REQ-017`=`RQ-SFR-09-06` 개인정보 보호대책, `REQ-018`=`RQ-SFR-09-07` 개인정보 유형 분류체계)은 **deprecated**(외부 생성 시스템/보안·인프라 책임)되어 추적 대상에서 제외된다. 따라서 본문 추적 대상은 **active 15건**이다.
- 비기능 요구사항(`NFR-001`~`007`)은 §4.4에 별도 추적한다.
- 화면은 `screen_spec`, 컴포넌트는 `diagram_c4_component`, 테이블은 `erd`를 LogiCraft 그래프 진실원으로 한다.
- 매핑 근거: 각 `REQ`·`FEAT`·`UC`·`AC`·`DOMAIN`·`MOD`·`SCREEN`에 대해 `get_neighbors`로 조회한 **직접 연결 링크만** 사용하였다(2026-06-02 그래프 스냅샷 기준).

## 3. 추적성 분석

### 3.1 단계별 연결률 (active SFR 15건 기준)

> 분모 15 = 추적 대상 활성 SFR 기능 요구사항. "연결"은 해당 단계에 **활성(non-deprecated) 산출물이 1건 이상** 직접 연결된 경우다. 괄호는 직전 버전(09-03/09-05 복구 전) 대비 변화.

| 단계 | 산출물(타입) | 연결 건수 | 연결률 | 비고 |
|------|--------------|:---------:|:------:|------|
| 분석 | 기능(FEAT) | 15 / 15 | 100% | 전건 feature 보유 |
| 분석 | 유스케이스(UC) | 15 / 15 | **100%** (← 87%) | **09-03·09-05 복구**(UC-016 신규 연결) — 전건 UC 보유 |
| 분석/시험 | 검수기준(AC) | 15 / 15 | **100%** (← 87%) | **09-03·09-05 복구**(AC-016 신규 연결, REQ-014/016 verifies) |
| 설계 | 화면(SCREEN) | 13 / 15 | **87%** (← 73%) | **09-03·09-05 복구**(UC-016→SCREEN-009/008). 잔여 `-`: 08-06(시스템 UC, 화면 부재 정상)·09-01·09-02(비식별 처리/연동 사용자 화면 미연결) |
| 설계 | 컴포넌트(CMP) | 15 / 15 | 100% | 전건 C4 컴포넌트 보유(domain 경유) |
| 설계 | 테이블(ERD) | 15 / 15 | 100% | 전건 ERD 보유(domain 경유) |
| 구현 | 코드모듈(MOD) | 15 / 15 | 100% | 전건 code_module 보유 |
| 구현 | 단위시험(UT) | 0 / 15 | 0% | LogiCraft 미모델링(후속) |
| 시험 | 통합시험(IT-TS) | 0 / 15 | 0% | LogiCraft 미모델링(후속) |
| 시험 | 시스템시험(ST) | 0 / 15 | 0% | LogiCraft 미모델링(후속, D7) |

> **개선 요약**: 09-03/09-05 추적성 복구로 **유스케이스 87%→100%, 검수기준 87%→100%, 화면 73%→87%** 로 상승했다. 잔여 화면 단절은 08-06(성격상 부재)·09-01·09-02(2건) 뿐이다.

### 4.3 ★ 핵심 결론 — RQ-SFR-09-03 / 09-05 비식별 결과 검토 추적성 복구

본 절은 작성 지시에서 명시 검증을 요청한 항목이다. LogiCraft 그래프 `get_neighbors` 직접 조회 결과를 그대로 기록한다.

**복구된 추적 체인** (2026-06-02 그래프 스냅샷):

```
REQ-014 (RQ-SFR-09-03, active)  ┐
REQ-016 (RQ-SFR-09-05, active)  ┘
   ↑ implements (strong)
FEAT-006 「비식별 처리 상태·이력 확인 (경량)」 — deprecated → approved 재활성
   ↑ realizes (strong)
UC-016 「비식별 처리 상태·이력 확인」 (approved, 신규)
   → references (weak) → SCREEN-009 「영상 상세 화면」(/video/:id, PrivacyBadge·BatchStageIndicator)
   → references (weak) → SCREEN-008 「영상 처리 현황 화면」(/video/status, StageBadge)
   ← derived_from (medium) ← AC-016
AC-016 「비식별 처리 상태·이력 화면 확인」 (approved, 신규)
   → verifies (strong) → REQ-014 / REQ-016
   → derived_from (medium) → UC-016
```

| 검증 대상 | 그래프 상태 | 결론 |
|-----------|------------|------|
| `FEAT-006` (비식별 처리 상태·이력 확인 경량) | **approved** (재활성, "REQ-014/016 활성 추적성 복원") | 활성 기능 — `implements` REQ-014/016, `realizes` UC-016 |
| `UC-016` (비식별 처리 상태·이력 확인) | **approved** (신규, "UC-012 dep 대체 — 저작도구 보유 경량 상태·이력 가시성 UC") | 활성 유스케이스 — SCREEN-009/008 참조 |
| `AC-016` (비식별 처리 상태·이력 화면 확인) | **approved** (신규) | 활성 검수기준 — REQ-014/016 `verifies`, UC-016 `derived_from` |
| `SCREEN-009` (영상 상세 화면) | active(draft, implemented 100%) | 기본정보 탭에 PrivacyBadge·BatchStageIndicator로 비식별 단계·분류 노출 |
| `SCREEN-008` (영상 처리 현황 화면) | active(draft, implemented 100%) | StageBadge로 배치 비식별 단계(DEIDENTIFY) 진행/실패 노출 |
| `REQ-014`(09-03)·`REQ-016`(09-05) | active(draft) | FEAT-006(implements)·AC-016(verifies) backward 링크 보유 — 분석·검수 추적성 복원 |

**결론**:
1. **RQ-SFR-09-03·09-05 추적성 복구 완료**. 직전 버전에서 "active 요구사항인데 분석(UC)·검수(AC)·화면 산출물이 모두 deprecated/orphan이라 추적이 끊긴" 비정합 상태였으나, **경량 UC-016 재정의 + AC-016 신규 + FEAT-006 재활성**으로 분석·검수·화면 추적성이 모두 복원되었다.
2. 복구된 책임 범위는 저작도구가 실제 보유한 **경량 비식별 가시성** — ①외부 비식별 SW 결과 콜백 수신(POST /v1/deidentify/result), ②영상 단위 비식별 처리 상태(`DE_IDNTF_YN`) 갱신 및 영상 상세/현황 화면 표시, ③처리 이력(`LS_DEIDENT_PROC_LOG`) 기록 — 에 한정된다.
3. **deep 검토(외부 위탁)**: 원본/비식별 좌우 비교 등 deep 검토·검증 UI와 처리 이력 상세 조회 전용 화면/API는 외부 비식별 솔루션 프로그램으로 이관(범위 외)된다. 이에 대응하는 `UC-012`(deep 검토)·`SCREEN-016`(비식별 목록)·`SCREEN-017`(비식별 상세)·`API-051`/`API-052`(이력 상세 조회)는 **deprecated 유지**된다 — 본 표 추적 대상에서 정상적으로 제외(외부 이관, 비정합 아님).
4. **AC-012 orphan 해소**: 종전 orphan이던 `AC-012`(비식별 결과·이력 검토, deep 검토 대상)는 검증 대상 UC-012가 외부 이관 deprecated되었으므로 **deprecated 처리**되었다(저작도구 보유 경량 검증은 AC-016이 대체). 더 이상 폐기 UC에 매달린 고립 AC가 아니다 → orphan 해소.

> **참고 — deprecated 동반 산출물**: `RQ-SFR-09-06`(REQ-017)·`RQ-SFR-09-07`(REQ-018) 및 그 UC(`UC-014`/`UC-015`)·AC(`AC-014`/`AC-015`)는 보안·인프라 책임으로 일괄 deprecated되어 본 표 추적 대상에서 정식 제외되었다(요구사항 자체가 폐기 → 비정합 아님). 저작도구의 민감정보 보호 책임은 `NFR-005`로 유지된다(§4.4).
