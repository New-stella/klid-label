# R3 요구사항 추적표

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-UC/CO/DC/DCD/SD/SC/AC/EN/ERD/TB/II/IC/IF/UCD/ACT 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. 범위는 시작 ID만 전체형으로(예: `KLID-AT-UC-001~016`). ※ 요구사항(RQ-SFR-NN-NN·NFR-NNN)·시스템시험(KLID-ST-NNN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 시스템의 요구사항을 도출하여 개발의 각 단계별로 작성한 산출물이 일관성을 가지는지를 추적할 수 있도록 각 단계별 산출물의 추적성을 관리하기 위하여 작성한다.

## 작성 방법
> 사용자 요구사항 정의서로부터 시작하여 분석, 설계, 구현, 시험의 각 단계별 산출물에 ID를 식별하고 전단계 산출물과 후속단계 산출물간의 연계관계에 매핑 작업을 하여 산출물이 단계별 연관관계가 끊어지지 않고 추적할 수 있도록 한다.

> R1 사용자 요구사항 정의서(제출본)의 기능 요구사항 14건(RQ-SFR-06-03, 07-01~03, 08-01~05, 09-01~05)을 시작점으로, R2 유스케이스 명세서 부록 A의 요구사항→유스케이스 매핑을 기준 삼아 화면(D2)·컴포넌트(D3)·엔티티(D8)·검수기준(R2 §5)·시스템시험 시나리오(D7)까지 추적 체인을 연결한다. 시스템시험 열은 D7 시스템시험 시나리오의 「유스케이스→시험 시나리오 매핑」을 인용한다. 단위시험 열은 D11 단위시험 케이스의 「관련 R2 UC」 재정렬(2026-06-09) 결과 **현행 UC에 직접 대응하는 단위시험(UT)이 있는 행만** 해당 UT ID로 보강하였다(D11은 컴포넌트 단위 시험이라 인프라/공통 컴포넌트로만 검증되는 일부 UC는 직접 대응 UT가 없어 `-` 유지, 부록 B 참조). 통합시험 시나리오 열은 미작성 상태이므로 `-`로 표기한다. 보완요청(2026-06-09)에 따라 신규 기능 요구사항 8건(RQ-SFR-11-04/05/06/08/09/10·16·17)을 추가하였다. 신규 요구사항이 매핑하는 UC-018·019·021·022·023은 D11 단위시험이 미작성이므로 단위시험·통합시험·시스템시험 열 모두 `-`이다(※6).

## 부록 B. 단절 셀(`-`) 사유

| 단절 위치 | 성격 | 사유 |
|---------|------|------|
| KLID-AT-UC-011 화면 셀 (RQ-SFR-09-02 등) | 성격상 부재 | 비식별 처리 요청은 배치 파이프라인·외부 솔루션 콜백 기반 흐름으로 전용 화면이 없다(D2 §2.1 주석). 누락 신고·해소 화면은 KLID-AT-UC-016의 KLID-AT-SC-005 신고 모달로 제공된다. |

| NFR-001~003·006 횡단 유스케이스 셀 | 성격상 부재 | 배치 처리량·처리 규모·포털 접근성은 R1에 전용 기능 요구사항(SFR)이 없는 운영 워크플로우·포털 채널에서 실현되어 R1 한정 본 추적표 유스케이스로 분해되지 않는다(R2 부록 A·C). |
| NFR-006 시스템시험 셀 | 성격상 부재 | 포털 웹 접근성(WCAG 2.1 AA)은 R1 기능 요구사항 한정 유스케이스 범위 밖이며, 접근성 점검·수동 검수는 별도 포털 채널 시험 항목으로 관리한다(D7 부록 B ※4). |
| KLID-AT-UC-013 단위시험 열 (RQ-SFR-09-04) | 성격상 부재(컴포넌트 시험 범위 밖) | D11은 컴포넌트 단위 시험이라 일부 UC는 직접 대응 UT가 없다. KLID-AT-UC-013(비식별 옵션 설정)은 외부 비식별 솔루션 옵션 설정 컴포넌트의 단위시험이 D11에 별도 블록으로 존재하지 않는다(UT-026 시스템 설정은 YOLO·배치·폴리곤 단순화 설정만 검증). 거짓 링크 금지 원칙에 따라 단위시험 열을 `-`로 유지한다(§1 ※5). |
| 전 행 단위시험 열(KLID-AT-UT) | **완료(재정렬 반영)** | D11 단위시험 케이스(2026-06-09 v1.1)의 「관련 R2 UC」를 현행 R2 유스케이스 체계(KLID-AT-UC-001~016)로 재정렬 완료함에 따라, 현행 UC에 **직접 대응하는 단위시험(UT)이 있는 행**의 단위시험 열을 D11 UC↔UT 매핑으로 보강하였다. D11은 컴포넌트 단위 시험이라 인프라/공통 컴포넌트로만 검증되는 UC(예: KLID-AT-UC-013)는 직접 대응 UT가 없어 `-`를 유지한다. (UC→UT 매핑: UC-001/002/010→UT-003·UT-020, UC-003→UT-022, UC-004→UT-011·UT-014, UC-005→UT-010·UT-014, UC-006→UT-026, UC-007/008→UT-018, UC-009→UT-019, UC-011→UT-007·UT-020, UC-016→UT-015) |
| 전 행 통합시험 시나리오 열(KLID-IT-TS) | 후속 미작성 | 통합시험 시나리오 산출물(통상 D10)이 아직 작성되지 않았다. **보강 마일스톤**: 통합시험 시나리오 작성 완료 시, 해당 산출물의 UC↔통합시나리오 매핑을 본 추적표의 통합시험 열에 보강한다. |
| 신규 요구사항(RQ-SFR-11-04/05/06/08/09/10·16·17) 시험 열 전체 | 후속 미작성(보완요청 신규 항목) | 보완요청으로 추가된 기능 요구사항 8건에 대응하는 단위시험·통합시험·시스템시험 산출물이 아직 작성되지 않았다(※6). 단, RQ-SFR-11-05·11-09의 UC-001/002/010 행은 기존 R1 활성 UC가 신규 요구사항으로 재매핑된 경우로 기존 D11 UT(UT-003·UT-020)를 재활용할 수 있어 해당 행 단위시험 열에 기입하였다. 나머지 신규 전용 UC(018·019·021·022·023)는 D11 미작성. **보강 마일스톤**: 신규 UC 대응 단위시험(D11 보완)·통합시험·시스템시험 작성 완료 시, 해당 UC 행의 시험 열을 보강한다. |

> ℹ 시스템시험 시나리오 열(KLID-ST)은 D7(시스템시험시나리오) 작성 완료에 따라 보강되었고, 단위시험 열(KLID-AT-UT)은 D11 「관련 R2 UC」 재정렬(2026-06-09) 완료에 따라 보강되었다. v1.2(2026-06-09)에서 보완요청 신규 요구사항 8건 추적 행이 추가되었다. 잔여 단절은 통합시험(미작성) 전 행, 직접 대응 UT 성격상 부재인 KLID-AT-UC-013 단위시험 1셀, 신규 요구사항 대응 UC(018/019/021/022/023) 시험 열 전체이며, 각 사유를 위 표에 명시하였다.

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID` / 서브시스템 ID(저작도구): `AT`
> - 본 산출물에서 참조하는 ID:
>   - 요구사항 ID: `RQ-SFR-NN-NN`(기능), `NFR-NNN`(비기능) — R1 사용자 요구사항 정의서(제출본) 실존 ID
>   - 유스케이스 ID: `KLID-AT-UC-NNN` — R2 유스케이스 명세서 참조
>   - 화면 ID: `KLID-AT-SC-NNN` — D2 사용자 인터페이스 설계서 참조
>   - 컴포넌트 ID: `KLID-AT-CO-NNN` — D3 컴포넌트 설계서 참조
>   - 엔티티 ID: `KLID-AT-EN-NNN` — D8 엔티티관계모형 설계서 참조
>   - 검수기준 ID: `KLID-AT-AC-NNN` — R2 유스케이스 기술서 「관련 AC」 참조
>   - 시스템시험 시나리오 ID: `KLID-ST-NNN` — D7 시스템시험 시나리오 참조
>   - 단위시험 ID `KLID-AT-UT-NNN` — D11 단위시험 케이스 참조(UC 체계 정합 완료, 2026-06-09 보강) / (미작성) 통합시험 시나리오 ID `KLID-IT-TS-NNN`
> - R1(사용자 요구사항 정의서 제출본)의 요구사항 ID를 시작점으로 하여 R2(유스케이스)·D2(화면)·D3(컴포넌트)·D8(엔티티)·검수기준(AC)·D7(시스템시험)까지 추적 체인을 연결한다.

> - 본 추적표는 R2 유스케이스 명세서 부록 A(요구사항→유스케이스 전수 매핑)와 D7 시스템시험 시나리오의 유스케이스↔시나리오 매핑을 정합 기준으로 삼아, R1 기능 요구사항 14건 전수와 비기능 요구사항 7건을 추적한다.
