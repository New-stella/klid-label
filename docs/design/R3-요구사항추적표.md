# R3 요구사항 추적표

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-UC/CO/DC/DCD/SD/SC/AC/EN/ERD/TB/II/IC/IF/UCD/ACT 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. 나열·범위 모두 각 ID를 전체형으로 표기한다(예: `KLID-AT-UC-001 ~ KLID-AT-UC-013`). ※ 요구사항(RQ-SFR-NN-NN)·시스템시험(KLID-ST-NNN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 시스템의 요구사항을 도출하여 개발의 각 단계별로 작성한 산출물이 일관성을 가지는지를 추적할 수 있도록 각 단계별 산출물의 추적성을 관리하기 위하여 작성한다.

## 작성 방법
> 사용자 요구사항 정의서(R1)로부터 시작하여 분석(R2 유스케이스), 설계(D1 클래스·시퀀스, D2 화면, D3 컴포넌트·인터페이스, D8 엔티티, D9 테이블)의 각 단계별 산출물에 ID를 식별하고 전·후속 단계 산출물 간의 연계관계를 매핑하여 추적성이 끊어지지 않도록 한다.

## 1. 추적 대상 범위

- **기능 요구사항(SFR)**: R1 v1.17 활성 **14건** — RQ-SFR-06-03, RQ-SFR-07-01 ~ RQ-SFR-07-03, RQ-SFR-08-01 ~ RQ-SFR-08-05, RQ-SFR-09-01 ~ RQ-SFR-09-05
- **비기능 요구사항(NFR)**: **7건** — NFR-001 ~ NFR-007 (별도 표, 5절)
- **추적 체인**: 요구사항(RQ-SFR) → 유스케이스(R2 UC) → 인수기준(R2 AC) → 화면(D2 SC) → 시퀀스(D1 SD) → 클래스(D1 DC) → 컴포넌트(D3 CO) → 인터페이스(D3 IF) → 엔티티·테이블(D8 EN/D9 TB) → 시험(UT/IT/ST)
- **시험 단계(UT/IT/ST)는 전 행 `-`** — D6 총괄시험계획서 및 단위/통합/시스템시험 시나리오(UT/IT/ST)는 본 생성 범위(R1·R2·D1·D2·D3·D8·D9)에 포함되지 않음. 부록 「검증 노트」 참조.
- **검증 소스(이중 확인)**: ① LogiCraft 그래프(project_id 4ece2c3f-8e99-46f5-9580-71108a76e578) REQ→FEAT→UC(`realizes`)·AC(`verifies`/`covered_by`) 링크 실측, ② 방금 생성된 R2·D1·D2·D3·D8·D9 문서의 매핑표 교차 확인. 두 소스 일치 항목만 본문 기입, 불일치·단절은 부록에 기록.

## 3. 단계별 연결률 통계

> 활성 기능 요구사항 **14건** 기준. 각 단계 산출물 ID가 1건 이상 매핑된 요구사항 수 / 14.

|----------|-------|:----------------:|:------:|------|
| 분석 — 유스케이스 | R2 UC | 14 / 14 | 100% | 전 요구사항 UC 보유 |
| 분석 — 인수기준 | R2 AC | 14 / 14 | 100% | 전 요구사항 AC 보유 |
| 설계 — 화면 | D2 SC | 14 / 14 | 100% | 전 요구사항 화면 보유 |
| 설계 — 시퀀스 | D1 SD | 14 / 14 | 100% | 전 요구사항 시퀀스 보유 |
| 설계 — 클래스 | D1 DC | 14 / 14 | 100% | 전 요구사항 클래스 보유 |
| 설계 — 컴포넌트 | D3 CO | 14 / 14 | 100% | 전 요구사항 컴포넌트 보유 |

### A-2. KLID-AT-UC-009(데이터마트 수정 통지) — 매트릭스 비포함

- KLID-AT-UC-009(데이터마트 수정 통지, TASK_MODIFIED)는 원 대응 요구사항 **RQ-SFR-08-06**이 R1 v1.16에서 **범위 외(deprecated)** 처리(데이터마트 동기화 본체는 외부 관제서버 책임)되어, 직접 대응하는 활성 요구사항 ID가 없으므로 **2절 요구사항 매트릭스에 행으로 포함하지 않는다.**
- 단, 본 통지 유스케이스는 **검수 완료 후 라벨/메타 수정 흐름(버전관리 연계)**으로 실제 운영 유지되며, 산출물은 정상 보유한다: KLID-AT-AC-009, KLID-AT-SC-005·KLID-AT-SC-015·KLID-AT-SC-019, KLID-AT-SD-010(KLID-AT-DCD-003), KLID-AT-DC-032 ~ KLID-AT-DC-037, KLID-AT-CO-005·KLID-AT-CO-007, KLID-AT-IF-013·KLID-AT-IF-014, KLID-AT-TB-036(LS_CONTROL_NOTIFY_FALLBACK). LogiCraft 그래프상 UC-009는 `approved`·非deprecated 상태로 존속함을 확인.
- 근거: R2 §3 ※1, LogiCraft REQ-011(deprecated) / KLID-AT-UC-009(approved) 이중 확인.

### A-3. 범위 외(시험 단계 전 행 `-`)

- D6 총괄시험계획서, 단위시험(UT), 통합시험 시나리오(IT), 시스템시험 시나리오(ST)는 이번 생성 범위(R1·R2·D1·D2·D3·D8·D9)에 포함되지 않아 전 행 `-` 처리. 추후 시험 산출물 생성 시 본 표의 시험 3개 컬럼을 채워 추적 체인을 완결한다.
- 구현(프로그램 코드 파일 ID) 컬럼은 LogiCraft code_module(MOD-*)·implementation_record로 별도 관리되며 본 분석·설계 추적표에는 포함하지 않음(설계 단계까지가 본 표 범위).
