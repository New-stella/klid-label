## description

증강·해상도 모두 새 영상(RAW_SN)을 생성하는 파생 경로다.

[외부 증강] AugmentController(/v1/augments)가 AugmentRequestService(요청)·AugmentReviewService(결과 검수)를 조합한다. 요청은 (영상 × 종류) 건마다 PENDING 행을 저장한 뒤 AugmentRequestedItemEvent(EVT-011)를 발행하고, AugmentRequestBridge 가 AFTER_COMMIT 으로 받아 AugmentJobSubmitService 로 비식별 프레임 100장 단위 분할 위탁한다(ExternalAugmentClient). 롤백 시 리스너가 발화하지 않아 DB 행 없이 외부 위탁만 나가는 일이 없다. 결과는 콜백(GenAiCallbackController → GenAiCallbackService → AugmentResultService)으로 회신되며, 새 영상 등록 이후 프레임 추출은 AsyncAugmentFrameRunner 가 비동기로 이어받는다. 생성조건 5필드(prompt)는 이벤트에 실려 전달되고 PROMPT_CN 에 원문 보관된다.

[반려·폐기·실삭제] AugmentReviewService.reject() 가 AugmentDiscardService 로 폐기 표식을 위임하고, AugmentDiscardPurgeSweeper(배치)가 유예 경과분을 DB 행·생성 파일까지 실삭제한다(ADR-045).

[★중복 요청 허용(ADR-044)] BE 는 같은 (영상 × 종류) 재요청을 차단하지 않는다. 사전 조회 가드·409·유니크 인덱스가 모두 제거됐으며 연타 방어는 FE 책임이다. 파생 식별자는 시각이 아니라 증강 행 PK(DATA_AUG_SN)로 유일화한다.

[★두 상태축 분리(ADR-045)] 생성 결과는 AUG_PROC_STTS_CD(웹훅 소유), 사용·폐기 결정은 LS_DATA_AUG_RVW.RVW_STTS_CD 가 소유한다. AugmentReviewService 는 aug 행의 상태를 건드리지 않고 리뷰 행만 쓴다. 작업목록 등재 게이트도 리뷰 축으로 판정하며, 해상도 파생은 검수 대상이 아니라 명시적 통과 예외다.

[해상도 파생] VideoResolutionService 가 3단계(예약 ResolutionReservationPersister → 비동기 확정 AsyncResolutionRunner → 영상·라벨 저장 ResolutionPersistService)로 다룬다. 외부 위탁이 없는 내부 ffmpeg 리스케일이며 라벨 좌표를 배율로 재계산해 적재한다(업스케일 포함).

[부모 게이트] 파생 생성은 원본 비식별 신고와 무관하다 — 게이트는 'N'(비식별 미수행)만 막고 'F'(신고)는 통과시키며, 산출물 실재 검증이 fail-closed 로 뒤를 받친다. 막는 것은 외부 위탁(요청·전송) 뿐이다.

[★파생 깊이 1 고정(ADR-023)] 파생본(ORGNL_RAW_SN non-null)은 증강 요청 대상이 될 수 없다(400). 해상도 경로는 이미 막고 있었고 증강 경로만 안 막혀 있던 비대칭을 해소한 것이다.

컴포넌트·관계는 실제 생성자 의존성에서 도출.
