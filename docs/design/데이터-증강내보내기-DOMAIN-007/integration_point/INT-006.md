### notes

무서명(명세서 v1.3 규격 — 웹훅에 서명·인증 헤더 자체가 없다. v1.1 이래 이 축은 바뀌지 않았다). 대체 3계층: ① IP allowlist `webhook.genai.allowed-ip-cidrs` — **비어 있으면 전면 차단**(fail-closed)이고 기동은 통과한다. 시계열(INT-003)은 비어 있으면 미적용이되 운영 프로파일(stg/prd)에서는 기동을 막는다. ([폐기] 기동 시 배선 검증 — ADR-062 가 대체한다. 아래 ★ 절) ② rate limit + 본문 size cap(1MB — 웹훅 게이트 필터의 무서명 가드 경로) ③ request_id 발급 게이트(`LS_DATA_AUG_JOB.IDMP_KEY` 에 있는 키만 처리, 최종 방어선). 게이트 필터 통과 증거 없이 수신 엔드포인트에 도달하면 401.

★ ① 허용 목록 값 형식 (2026-09-14 확정)
- 값: 쉼표(,)로 나열한 IPv4·IPv6 주소 리터럴 또는 그 CIDR 표기. IPv6 는 `::` 압축 표기를 포함한 표준 텍스트 표기(RFC 4291 §2.2)를 받는다. 예: `10.0.0.0/8`, `203.0.113.5`, `2001:db8::/32`, `::1`.
- 전면 허용은 명시적으로 적는다: IPv4 전체 `0.0.0.0/0`, IPv4·IPv6 전체 `0.0.0.0/0,::/0`.
- 호스트명은 받지 않는다. 기동 시 DNS 해석 결과가 고정돼 설정한 대역과 실제로 매칭하는 대역이 조용히 달라지기 때문이다.
- 형식이 틀린 값이 하나라도 있으면 프로파일과 무관하게 기동을 막는다. 틀린 값만 버리고 기동하면 방어가 조용히 꺼진 채 운영된다. 이 기동 차단은 ADR-062 가 위탁 시점으로 옮긴 짝 맞춤 검증(목록이 비었는지)과 별개이며 기동 시점에 판정한다.
- 빈 값·`none` 은 전면 차단(fail-closed)이다 — 이 의미는 바뀌지 않는다.
- 배포 기본값은 `0.0.0.0/0` 이다(외부 유입 차단은 인프라 방화벽이 담당한다). IPv6 발신까지 받으려면 `0.0.0.0/0,::/0` 으로 둔다. 단 이 기본값은 온프렘 설치 템플릿이 채워 주는 값이고, 애플리케이션 프로파일 자체의 기본값은 비어 있다 — 템플릿을 쓰지 않는 배포에서 값을 비우면 위의 전면 차단(fail-closed)이 그대로 적용된다(기동은 통과한다).

★ 판정 시점 이동 (ADR-062, 2026-09-03 승인) — 위 ①의 「기동 시 배선 검증」은 폐기한다.
- [폐기] 기동 시 배선 검증: 증강 위탁 주소는 주어졌는데 콜백 허용 주소 목록이 비어 있으면 기동을 막던 짝 맞춤 검증.
- 대체 서술: 그 짝이 맞지 않아도 기동은 통과한다. 대신 증강 위탁을 걸려는 순간 거부한다. 기동 시에는 오류 수준 기록만 남는다.
- 근거: 이 짝 맞춤이 지키는 것은 「위탁을 건 뒤 열리는 콜백 수신구」다. 위탁을 걸지 않으면 그 위험 자체가 없다. 그래서 판정을 위탁 시점으로 옮겨도 보호가 그대로 유지된다.

⚠ 성격이 다른 두 가지를 구분한다 — 「전면 차단도 함께 폐기됐다」로 읽지 말 것.
- 기동 시 배선 검증(주소는 있는데 허용 목록이 비었다고 기동을 막는 것): ADR-062 대상이며 위탁 시점 거부로 옮긴다.
- 콜백 수신 자체의 전면 차단(허용 목록이 비면 들어오는 콜백을 받지 않는 런타임 동작): ADR-062 대상이 아니며 그대로 유지한다. 아무나 콜백을 보낼 수 있게 되는 것을 막는 런타임 방어라 ADR-062 와 충돌하지 않는다.

세 설정 키(`webhook.vlm.allowed-ip-cidrs` · `webhook.genai.allowed-ip-cidrs` · `webhook.trusted-proxy-cidrs`)의 값 형식과 빈 값 동작은 SETT-001 이 단일 진실원이다. 위 ★ ① 절은 그 가운데 이 연동이 쓰는 키의 서술이다.

## data_format

## description

`POST /v1/genai/callback` 이 외부 증강 결과를 웹훅으로 수신 → 새 영상(RAW_SN, **`ORGNL_RAW_SN`** 으로 원본 참조 — V82/V95 표준용어) 등록·원본 라벨 verbatim 복사·PENDING 시작.

수신 대상은 증강 축 단일값(AUGMENT)이다. 구 WINTER/NIGHT/RAIN 은 이미 만들어진 파생본에 남아 있어 보존한다(백필하지 않는다) — 조회·표시 경로는 옛 값과 새 값을 모두 견뎌야 한다(ADR-059).

## ★★ 경로·인증·페이로드 전면 교체 완료 (구 /v1/aug/callback+HMAC 폐기)
구 경로 `POST /v1/aug/callback`(HMAC 서명 필수, secret `webhook.hmac.secret.augment`) + 내부 자체 채움(self-fill) 콜백 시뮬레이터는 **폐기**되었다. 신 경로 `POST /v1/genai/callback` — 「생성형 AI API 연동명세서 v1.3」§4.5 그대로 준수, **무서명**(명세서상 웹훅에 서명·인증 헤더 자체가 없음).

## 페이로드 (GenAiCallbackRequest, snake_case)
`request_id`(≤128, `^[A-Za-z0-9_-]+$`, 우리가 발급한 job 단위 멱등키 = `LS_DATA_AUG_JOB.IDMP_KEY` 의 echo) · `job_id`(≤200, 외부가 202 응답으로 발급) · `status`(RUNNING|SUCCEEDED|FAILED) · `progress`(0~100) · `current_step`(≤20) · `updated_at`(≤64) · `results[]`(SUCCEEDED 시, 최대 100건: `generated_data_id`·`media_type`(IMAGE|VIDEO)·`output_file_path`(≤500)·`checksum`) · `error_code`(≤50, FAILED 시)·`error_message`(≤1000, FAILED 시).
- 계약이 보장하는 발사는 **작업이 SUCCEEDED 또는 FAILED 로 처음 종료되는 시점 1회**이며, 전송이 실패해도 **재시도하지 않는다**(상대 서버 로그에만 남는다). `CANCELED` 발사 여부와 본문의 `results[]` 포함 여부는 계약이 보장하지 않는다.
- 그래서 **콜백은 유일한 회수 수단이 아니다** — 종결은 상태 조회(INT-008)로도 회수할 수 있어야 하고, 실제로 진행률 표시는 콜백이 아니라 폴링이 조달한다.
- 수신부는 **더 자주 와도 견딘다** — 진행 중 상태(`RUNNING`)나 동일 페이로드 중복 도착을 오류로 보지 않고 멱등 흡수한다. 계약이 요구하는 최소 집합보다 관대한 것은 위반이 아니며, 상대 배포본이 진행 알림을 함께 보내는 경우를 견디기 위한 것이다.
- 미지 필드는 무시한다(외부 필드 추가에 강건).

## 응답·멱등
`applied`(실제 반영 여부) 필드로 회신 — 멱등 흡수(DUPLICATE)·롤업 보류(DEFERRED)는 `applied:false`(구 구현은 이 경우도 true 를 반환해 외부가 정상 인계로 오해하던 결함 수정). **정책 보류(WITHHELD_*)는 2026-07-29 폐기** — 부모가 비식별 신고('F') 구간이어도 파생 생성은 진행하며, 부모를 물리적으로 쓸 수 없는 경우(비식별 미완료·부모/프레임 부재)는 보류가 아니라 REJECTED 로 즉시 실패 확정한다.

## 상태 전이
SUCCEEDED→ACCEPTED, FAILED→REJECTED(PENDING 가드 — 종결 상태에서는 되돌리지 않음).

## RESOLUTION(해상도)은 대상 아님
해상도 변경은 외부 콜백 대상이 아니다(저작도구 내부 기능, ADR-018).
