## description

## ★★ 위탁 계약
`authoring.augment.external.mode=http` 일 때 실제 HTTP 위탁이 수행된다(공통 기본값이 http 라 local 은 오버라이드 없이도 활성):
- `POST {증강 위탁 base-url}/api/genai/jobs`
- 요청 본문(v1.3): `request_id`·`request_channel`(=AUTHORING 고정)·`request_user_id`·`evnt_type`(FLOOD|WILDFIRE)·`evnt_subtype`(침수 전용, 선택)·`operation_type`(=AUGMENT 고정)·`generation_mode`(=I2I 고정)·`input_files[]`(sequence,file_path)·`mtdt`(허용 코드로 닫힌 생성 조건 5항목, 최소 1개)·`prompt`(자유 지시문 문자열 ≤1000, 선택)·`callback_url`. 생성 조건과 자유 지시문은 최상위에서 분리해 전달하며 구 객체 형식(`prompt.condition`/`prompt.text`)은 계약에서 제외됐다. 이벤트 유형과 생성 조건은 요청자가 화면에서 고른 값을 그대로 중계한다 — 관제 이벤트 코드에서 변환하지 않고 증강 종류에서 유추하지도 않는다(유형의 단일 원천은 요청 본문의 별도 `types[]` enum 이다). 전송한 원문은 `LS_DATA_AUG.PROMPT_CN` 에 생성 조건과 자유 지시문을 분리한 형태로 함께 보관해 나간 값과 보관값이 갈라지지 않게 한다
- 헤더 `Idempotency-Key`: `request_id` 값을 그대로 부착(명세서상 선택 헤더이나 우리 클라이언트는 항상 부착해 재시도 안전성 확보)
- 202 응답 `GenAiJobAcceptedResponse`{request_id, job_id, status=RECEIVED} — request_id echo 일치 + status=RECEIVED + job_id non-blank 를 검증(하나라도 어긋나면 EXTERNAL_API_ERROR). **job_id 는 외부(벤더)가 발급**하며 이후 콜백(INT-006)의 상관관계 키가 된다.
- 인증 없음(계약에 인증 계층 자체가 없다).
- 4xx 는 비재시도 오류로 분류해 재시도·서킷 집계에서 제외(요청이 이미 외부에 도달했을 수 있는 결정적 오류 재시도 방지).
- 입력파일 상한 100장/job(`authoring.augment.external.max-input-files` 로 조정 가능) — 초과 시 여러 job 으로 청크 분할해 위탁한다.

## 환경별 실배선
| 환경 | mode | 실질 |
|---|---|---|
| local | 오버라이드 없음(공통 기본값 http 상속) | **실배선** — mock-server(:9400) 대상 |
| dev/stg/prd | `noop`(명시 오버라이드) | 미연동 |

⚠ **미연동 모드에서는 요청을 접수하지 않는다 (ADR-049)** — 연동이 설정되지 않았으면 요청 시점에 거부한다. 구 동작은 접수만 하고 외부로 보내지 않아 요청이 진행 중으로 보이다가 한참 뒤 만료 회수로 실패 종결됐고, 그 환경에서 증강을 쓸 수 없다는 사실을 요청자가 즉시 알 수 없었다. 미전송 동작 자체는 그대로이며 접수 단계 거부만 더한 것이다.
