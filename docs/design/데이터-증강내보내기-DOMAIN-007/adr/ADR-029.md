# 외부 HTTP 위탁 서비스는 트랜잭션 애노테이션 무보유 원칙

## context

AugmentJobSubmitService의 클래스레벨 @Transactional(readOnly)가 '커넥션 미보유' 의도를 무력화했다 — 위탁 2건이 병렬 실행되면 서로의 2번째 커넥션을 기다려 풀 데드락(30초 타임아웃 동안 무관한 작업까지 대기)이 발생했다.

## decision

### chosen_option

트랜잭션 애노테이션 일절 미보유(채택)

### justification

외부 HTTP 왕복(위탁) 구간 동안 트랜잭션 애노테이션을 일절 갖지 않는다(NOT_SUPPORTED도 부적합 — EntityManager가 스레드 바인딩돼 커넥션 미반납). 회귀가드는 isSynchronizationActive()+getResource(controlEmf) 두 축으로 관측한다. 이 원칙은 다른 외부위탁 서비스 신설 시에도 동일 결함 재발 우려가 있어 가이드라인화가 필요하다.

## brownfield

### notes

이 원칙을 일반 가이드라인으로 ADR화할지, 해당 서비스 국소 결정으로 남길지는 표현 범위 조정이 필요하다는 gap-adr의 확인필요 사항을 반영해 등록함(다른 외부위탁 서비스 신설 시 재검토 여지 명시).

## consequences

### risks

- 트랜잭션 경계 밖에서 실행되는 코드가 늘어나며 부분 실패 시 정합성 처리를 서비스가 직접 책임져야 함

### negative

- 다른 외부위탁 서비스 신설 시 동일 결함(클래스레벨 @Transactional 습관적 적용) 재발 우려 — 가이드라인화 필요

### positive

- 외부 위탁 병렬 실행 시 커넥션 풀 데드락 제거

## considered_options

### @Transactional(readOnly) 클래스레벨 유지(구, 결함)

**cons**:

- 위탁 2건 병렬 실행 시 서로의 2번째 커넥션을 기다려 풀 데드락 발생

**pros**:

- 코드 일관성(다른 서비스와 동일 패턴)

- **description**: 외부 HTTP 위탁 구간에 @Transactional(readOnly)를 유지

### @Transactional(NOT_SUPPORTED) 적용(1차 시도, 실패)

**cons**:

- EntityManager가 스레드에 바인딩돼 커넥션이 반납되지 않아 데드락 해소 안됨(실측 실패)

**pros**:

- 트랜잭션 참여는 배제

- **description**: 전파속성을 NOT_SUPPORTED로 바꿔서 트랜잭션 참여를 배제

### 트랜잭션 애노테이션 일절 미보유(채택)

**cons**:

- 회귀가드가 필요(isSynchronizationActive()+getResource(controlEmf) 두 축으로 관측)

**pros**:

- 커넥션을 실제로 점유하지 않아 데드락 원천 차단

- **description**: 외부 HTTP 왕복(위탁) 구간 동안 트랜잭션 애노테이션을 일절 갖지 않는다
