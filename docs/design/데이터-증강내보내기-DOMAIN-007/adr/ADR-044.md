# 증강 중복 요청 허용 — '요청 1회 = 파생영상 1건' dedup 계약 철회 (ADR-028 supersede)

## context

ADR-028 은 '같은 종류를 또 만들 이유가 없다'를 전제로 활성상태(PENDING/ACCEPTED) 부분 유니크 인덱스로 증강 재요청을 DB 레벨에서 차단했다. 사용자가 그 전제를 부정했다 — '증강 이미지가 요청때마다 다르게 나올텐데 원하는 이미지가 안 나오면 동일하게 다시 요청할 수도 있다'. 생성형 증강은 결과가 매번 달라지므로 동일 조건 재요청이 정당한 운영 동선이며, 차단은 그 동선을 막는 결함이다.

## deciders

- 프로젝트 PM (ck.park)

## decision

### chosen_option

BE 차단 전면 철회 — 중복 요청 허용(채택)

### justification

중복 증강 요청을 BE 가 차단하지 않는다. 제거 대상 4종 — ① 서비스 사전 조회 가드 ② 409 응답·안내 문구 ③ 부분 유니크 인덱스 UK_LS_DATA_AUG_ACTVTN(V143 생성 → V153 DROP) ④ 술어 미러 상수 LsDataAug.ACTIVE_STATUSES. 속도 제한(RateLimiter)도 두지 않는다 — 자원 소모(CWE-770)는 사용자가 인지·수용한 잔여 위험이며 '보안 강화' 명목으로 되살리지 않는다. 중복 허용의 귀결로 같은 (영상×종류) 파생이 여러 건 공존하므로, 결과물 구분의 유일한 축인 LS_DATA_AUG.PROMPT_CN(요청 시 생성조건 원문, V153 신설)을 조회 경로에서 반드시 노출한다. 파생 영상 식별자(VMS_CLIP_ID)도 시각이 아니라 증강 행 PK(DATA_AUG_SN) 로 유일화한다 — 시각 기반이면 동시 콜백이 같은 밀리초에 충돌해 UK_LS_DATA_RAW_VMS_CLIP 위반으로 결과물이 유실된다. 해상도 파생의 UK_LS_DATA_AUG_RESL(V125, RESL_ 접두)은 별개 계약이라 유지한다 — 해상도는 외부 위탁이 없는 내부 결정론적 리스케일이라 같은 프리셋을 두 번 만들 이유가 없다.

## consequences

### risks

- 자원 소모(CWE-770)는 사용자가 인지·수용한 잔여 위험이다. RateLimiter 를 '보안 강화' 명목으로 되살리지 말 것
- 차단을 다시 도입하려면 인덱스 재생성 전에 활성 중복(PENDING·ACCEPTED) 선정리가 필요하다(절차는 V143/V153 주석)

### negative

- 같은 (영상×종류) 파생이 여러 건 공존 — 조회 화면이 PROMPT_CN 을 노출하지 않으면 구분 불가
- 서버측 요청 속도 상한이 없음

### positive

- 원하는 생성 결과가 나올 때까지 재요청하는 운영 동선 복원
- 409 상태별 분기 안내 등 차단 부수 구현 제거
- 해상도 파생 계약(UK_LS_DATA_AUG_RESL)과 성격이 다름을 명시적으로 구분

## decision_drivers

- 생성형 증강은 동일 입력에도 결과가 달라 재요청이 정당한 운영 동선
- 연타(오조작) 방어는 프론트 버튼 비활성화로 충분
- 해상도 파생은 내부 결정론적 리스케일이라 성격이 다름

## considered_options

### 활성상태 부분 유니크 인덱스 유지(ADR-028, 폐기)

**cons**:

- 생성 결과가 마음에 안 들 때 다시 요청하는 정당한 동선을 차단
- 전제('또 만들 이유가 없다')가 사실과 다름

**pros**:

- 파생 트리·스토리지 증가 억제

- **description**: AUG_PROC_STTS_CD IN (PENDING, ACCEPTED) 에 대해 (SRC_SN, AUG_TYPE_CD) 부분 유니크로 중복을 차단하고 위반 시 409.

### 중복 허용 + 속도 제한(RateLimiter) 병행

**cons**:

- 정당한 연속 재요청도 막힐 수 있음
- 사용자가 자원 소모를 인지·수용함

**pros**:

- 자원 소모 상한 확보

- **description**: 중복은 허용하되 자원 소모(CWE-770) 방어를 위해 요청 속도 제한을 둔다.

### BE 차단 전면 철회 — 중복 요청 허용(채택)

**cons**:

- 같은 (영상×종류) 파생이 여러 건 공존해 구분축이 필요
- 자원 소모 상한이 서버측에 없음(사용자 수용 잔여 위험)

**pros**:

- 재요청이라는 정당한 운영 동선이 복원됨
- 차단 관련 분기(409 상태별 안내 등) 제거로 구현 단순화

- **description**: 같은 (영상 × 증강 종류)를 몇 번이든 다시 요청할 수 있게 한다. 서비스 사전 조회 가드·409 응답·부분 유니크 인덱스·술어 미러 상수를 모두 제거하고, 연타 방어는 프론트 단독 책임으로 둔다.
