# 작업 단위를 프로젝트에서 영상 1건(RAW_SN)으로 전환

## context

1차(상용·타 개발사) 베이스라인은 '프로젝트' 단위로 작업·배정·통계·권한을 구성했다. 고도화 RFP는 영상/이미지 단위 라벨링·검수·완료 통지를 요구하며, 작업 식별자가 프로젝트가 아닌 영상 1건(LS_DATA_RAW.RAW_SN)이어야 관제서버 데이터마트 동기화(영상 1건=1 row)와 정합한다. 프로젝트 단위 잔재(LS_PJT_*, 프로젝트 생성/관리/배정)는 고도화 코드에서 영상 단위 테이블(LS_RAW_DATA_STATUS, LS_TASK_ALTMNT)로 대체되었다.

## deciders

- 박찬기
- 김현욱

## decision

### chosen_option

영상 1건 단위 전환(채택)

### justification

고도화 RFP·관제 동기화 요구와 정합하며 완료/수정 통지를 영상 단위로 단순화할 수 있다. 프로젝트 개념은 폐기하고 RAW_SN을 단일 작업 식별자로 사용한다.

## consequences

### risks

- 코드 마이그레이션 과도기 LS_PJT_* 잔존(별도 DROP 결정 필요)

### negative

- 1차 LS_PJT_* 테이블·화면·DFEAT 폐기 필요

### positive

- 영상 단위 완료/수정 통지(TASK_COMPLETED/MODIFIED) 가능
- 데이터마트 UPSERT 단위 정합
- 프로젝트 관리 화면/권한 모델 제거로 단순화

## considered_options

### 프로젝트 단위 유지(1차 모델)

**cons**:

- 관제 동기화 단위(영상)와 불일치
- 영상 단위 완료 통지 곤란
- 미사용 프로젝트 관리 UI 유지비용

**pros**:

- 1차 자산 재사용

- **description**: LS_PJT 중심으로 프로젝트 생성→단계→배정 유지

### 영상 1건 단위 전환(채택)

**cons**:

- 1차 프로젝트 테이블/화면 폐기 필요
- 과도기 LS_PJT_* 잔재 정리 부담

**pros**:

- 관제 데이터마트 1영상=1row 정합
- 완료/수정 통지 영상 단위
- 운영 단순화

- **description**: 작업 식별자=RAW_SN, LS_RAW_DATA_STATUS/LS_TASK_ALTMNT 영상 단위 배정·검수
