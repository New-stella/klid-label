# VLM·증강 콜백 무서명 규격 전환 + 3계층 방어(IP allowlist·rate limit·request_id)

## context

구 설계는 콜백에 HMAC 서명을 요구했으나, 벤더(IntelliVIX VLM, 생성형AI 증강)의 확정 계약이 무서명 규격임이 드러났다. ★이 무서명 판정은 우리가 받는 콜백(인바운드) 축에 한한다 — 우리가 보내는 위탁(아웃바운드)에는 별도 인증이 있으며 그것은 이 결정의 대상이 아니다.

## decision

### chosen_option

무서명 전환 + IP allowlist/rate limit/request_id 3계층 방어(채택)

### justification

VLM 콜백(POST /v1/vlm/callback)·증강 콜백(POST /v1/genai/callback) 모두 무서명으로 전환한다(HMAC 제거). 대신 IP allowlist + rate limit + request_id 발급 게이트 3계층으로 방어하며, 증강은 IP allowlist 미설정 시 fail-closed, VLM은 미설정 시 완화된다. '2026-07-07 승인'으로 명시된 공식 승인 결정이다.

## brownfield

## consequences

### risks

- IP allowlist 미설정 시(특히 VLM 쪽 완화 정책) 무서명 콜백이 스푸핑에 노출될 위험

### negative

- HMAC 서명이라는 1차 방어선을 상실 — IP allowlist·rate limit 설정에 전적으로 의존

### positive

- 벤더 확정 계약(무서명)과 정합해 실제 연동이 가능해짐
- 3계층 compensating control로 서명 부재를 보완

## considered_options

### HMAC 서명 요구 유지(구 설계)

**cons**:

- 벤더(IntelliVIX VLM, 생성형AI 증강) 확정 계약이 무서명 규격이라 연동 자체가 불성립

**pros**:

- 요청 위변조 방지가 규격 자체에 내장

- **description**: 콜백에 HMAC 서명을 요구하고 미서명 요청은 거부

### 무서명 전환 + IP allowlist/rate limit/request_id 3계층 방어(채택)

**cons**:

- 증강은 IP allowlist 미설정 시 fail-closed, VLM은 미설정 시 완화 — 설정 누락 시 방어 수준 차이 발생

**pros**:

- 벤더 확정 규격과 정합해 연동 가능
- 다층 방어로 서명 부재를 보완

- **description**: HMAC 제거하고 벤더 규격에 맞춰 무서명 콜백을 수신하되, IP allowlist + rate limit + request_id 발급 게이트로 compensating control을 구성
