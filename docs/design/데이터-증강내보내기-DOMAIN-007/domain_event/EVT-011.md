## description

증강 요청 건별 이벤트. 증강 요청 처리가 (영상 × 증강 종류) 건마다 PENDING 행을 저장한 뒤 발행한다.

[AFTER_COMMIT 인 이유] 소비자가 커밋 이후에만 수신해 요청 트랜잭션이 실제로 커밋된 다음에만 위탁 제출(비식별 프레임 100장 단위 분할)을 수행한다. 요청 트랜잭션이 롤백되면 소비자가 발화하지 않으므로 LS_DATA_AUG 행 없이 외부 위탁만 나가는 일이 없다.

[★2026-07-31 — prompt 를 함께 싣는 이유] REVIEWER 가 입력한 생성조건 5필드(time/season/weather/terrain/severity)가 가공 없이 외부로 나가는데, 위탁은 커밋 이후 다른 스레드에서 일어난다. 발행 시점에 조립한 dict 를 그대로 옮겨 DB 적재 원문(LS_DATA_AUG.PROMPT_CN)과 외부로 나가는 값이 같은 출처가 되게 한다 — 위탁 측에서 DB 를 다시 읽어 재조립하면 두 벌이 되어 어긋난다. prompt 는 방어적 복사로 불변화하며 키 순서를 보존한다(명세서 샘플과 대조 용이).

[중복 요청] 같은 (영상 × 종류)를 몇 번이든 다시 요청할 수 있다(ADR-044). 결과물 구분축은 PROMPT_CN 이고 파생 식별자(VMS_CLIP_ID)는 증강 행 PK(DATA_AUG_SN)로 유일화한다 — 시각 기반이면 동시 콜백이 같은 밀리초에 충돌해 결과물이 유실된다.

[발행] 증강 요청 접수 트랜잭션 안에서 건별로 발행한다.
[소비] 요청 커밋 이후(AFTER_COMMIT) 외부 위탁 제출이 수신한다.
