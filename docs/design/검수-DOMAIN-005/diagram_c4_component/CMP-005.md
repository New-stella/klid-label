## description

검수 목록·상세·프레임·이슈·제출·시작·승인(=작업완료)·반려. ReviewController(/v1)가 ReviewService 를 호출하고 ReviewService 는 ReviewStateMachine 으로 상태 전이를 검증한다. 검수자 1인이 승인할 때까지 반려↔재제출을 반복하는 단일 검수이며(ADR-002), 별도 관리자 확인 요청 경로는 없다. ⚠ 당초 근거였던 '별도 ADMIN 역할이 없어 확인을 요청할 상대가 없다'(ADR-003)는 전제는 무효다 — ADR-055 가 관리자 역할을 신설해 그 결정을 뒤집었고, 관리자는 검수자 권한을 계층으로 물려받는다. 전제가 무효가 된 것과 기능을 되살리는 것은 다른 축이라 '관리자 확인 요청'을 두지 않는다는 결론은 그대로 유지한다. 재도입 여부는 ADR-060 이 결정했다 — 관리자 역할이 신설된 뒤에도 「관리자 확인 요청」 창구를 두지 않는다. 가장 큰 근거는 겸직이다 — 관리자는 검수자 권한을 계층으로 물려받아 검수·배정을 그대로 수행하므로 검수 판단에 관한 한 올려보낼 위가 없다. 즉 이 창구는 대체된 것이 아니라 성립하지 않는다.

[★승인 후 연쇄 — 순서 보강] 승인 시 ①VersionService 로 라벨 전체 스냅샷 생성 ②ReviewApprovedEvent(EVT-006) 발행. ⚠ 구 본문은 이 이벤트가 곧 관제 통지로 이어진다고 적었으나, 실제 수신자는 DatasetExportBridge 다 — export 폴더를 새 버전으로 전량 재생성한 뒤 DatasetExportCompletedEvent(EVT-009)가 발행되고, 그제서야 ControlNotifyEventListener 가 TASK_COMPLETED 를 보낸다. 통지가 먼저 나가면 관제가 구 버전 폴더를 픽업한다. export 실패 시 통지는 보류되고 DatasetExportFailureRecoverer 가 재산출 성공 후 재개한다.

[승인 전제조건] 승인에는 전제조건이 있다 — 검수 워크플로 상태의 비식별화완료여부가 완료여야 한다. 미완료이면 ReviewService 가 상태 전이 이전에 승인 요청을 거부하므로, 그 요청에서는 ReviewStateMachine 의 상태 전이도 VersionService 의 라벨 버전 스냅샷도 ReviewApprovedEvent 발행과 그 뒤의 학습데이터 산출물 재생성도 관제 통지도 하나도 시작되지 않는다. 이 값은 기본이 완료라, 외부에서 이미 라벨링이 끝난 산출물을 가져오는 경로로 원본이라고 지정해 들어온 영상만 미완료로 시작한다 — 그 경로와 무관한 기존 영상은 이 전제조건 때문에 막히지 않는다. 막는 범위는 검수 승인 하나뿐이다 — 라벨 조회·프레임 이미지·영상 스트리밍·학습데이터 산출물 생성 경로는 이 값으로 닫지 않으며, 그 통로들을 함께 닫는 것은 비식별 누락 신고라는 별개 축이다.

컴포넌트·관계는 실제 생성자 의존성에서 도출.

[★검수 자격 — 배정이 아니라 역할과 점유] 검수는 배정 없이 전체 대기열에서 집어간다. 검수 목록은 검수 권한을 가진 누구에게나 검수 대기 전체를 보여주고 자격은 역할이 정하며, 검수자를 영상에 배정하는 절차를 두지 않는다 — 배정의 대상은 작업자뿐이다. ⚠ ReviewService 가 배정 저장소를 무는 간선은 남지만 그 축은 작업자다 — 검수 제출·본인 영상 접근의 작업자 자격 확인과 담당 작업자 표시 조달에 쓰이며 검수 인가 게이트가 아니다. 검수자는 배정과 무관하게 통과한다.

[★점유 판정] 검수를 시작하면 그 사람이 그 영상을 점유한다. 점유는 작업 이벤트 로그에 검수 시작을 남기는 것으로 표현하고 판정은 ReviewOccupancyResolver 가 조회 시점에 파생으로 내린다 — 전용 컬럼도 전용 표도 두지 않는다. 유예는 배포 설정값이고 기본값은 30분이며 점유를 푸는 별도 동작은 두지 않는다. ⚠ 목록은 행마다 되짚지 않고 영상별 최신 기록을 한 번의 조회로 합쳐 판정한다. ⚠ 점유는 잠금이 아니다 — 만료가 있고 승인 시점 동시성 보호가 실제 방어로 그대로 남으므로 두 축은 서로를 대체하지 않는다.

[★검수 시작 — 상태를 전이하는 갈래는 하나뿐] 검수 대기 영상은 ReviewStateMachine 의 전이 검증을 거쳐 상태를 검수 진행으로 옮기며 점유한다. 상태를 전이하는 갈래는 이 하나뿐이고, 그 밖의 갈래는 모두 상태 전이 없이 점유만 세운다 — 예컨대 같은 사람이 다시 들어오는 경우, 유예가 만료된 검수 진행 영상을 다른 검수자가 이어받는 경우, 수정 뒤 재검토 표시가 선 승인 영상이 그렇다. 즉 검수 시작이 늘 상태 전이를 부르는 것은 아니다. 재검토 표시가 선 승인 영상의 상태를 내리면 관제 조회용 데이터마트 뷰에서 이미 통지한 영상의 행이 사라지므로, 상태를 건드리지 않고 새 상태값도 만들지 않는다.

[★일괄 승인] BulkApprovalService 가 여러 건을 한 번에 승인한다 — 승인에만 두고 반려에는 두지 않는다(건마다 사유가 달라 묶을 수 없다). 승인 로직을 새로 쓰지 않고 단건 경로를 건마다 재사용하므로 성공한 건의 결과는 단건 승인과 완전히 같다. 자격은 유효 점유의 주인이 요청자 본인이고 단건 승인이 허용하는 상태인 건으로 한정하고, 건수 상한을 두고 부분 실패를 허용하며, 승인이 일으키는 연쇄가 한꺼번에 몰리지 않도록 뒤에서 줄 세운다.

근거는 ADR-067.
