## description

검수자(REVIEWER)가 제출된 영상을 승인/반려하는 흐름의 시퀀스 다이어그램. 제출(submit)·검수 시작(start)·승인(approve)·반려(reject) 4개 API 호출과, 승인 트랜잭션 내부에서 일어나는 비식별 신고 게이트 · 라벨 전체 스냅샷 생성 · event_annotation·시계열 메타 자동 승인 · 통합 메타 동결(materialize)을 그린다. 승인 트랜잭션 커밋 이후(AFTER_COMMIT)에 비동기로 이어지는 학습데이터 산출(export)과, 그 산출이 성공한 뒤에만 나가는 관제 완료 통지(TASK_COMPLETED)까지 포함한다. 완료 통지 페이로드는 영상 단위 메타만 싣는 평면 snake_case 객체이며, 필수 필드는 job_id·event_type_cd·evnt_cls_cd·evnt_ctgry_cd·lclgv_cd·lclgv_nm·duration_sec·image_count·gen_ai_yn 이고 여기에 선택 필드 output_ver_no 가 더해진다. 필수 필드는 값이 null 이어도 키를 남기고(키를 빼면 수신측이 전량 거부한다) 선택 필드는 값이 없으면 키 자체를 생략한다 — 이 비대칭은 의도된 것이라 한쪽으로 통일하지 않는다. 최초 승인과 재승인(검수완료 후 수정 → 재검수 → 재승인)은 이벤트 발행 여부가 갈리며, 재승인의 경우 산출·수정 통지(TASK_MODIFIED)는 이 API 호출 안에서 나가지 않고 재검토 표시(REVLT_YN) 해제로 풀리는 디바운스 윈도우가 별도 스케줄 tick 에서 처리한다. 승인 요청 직후에는 비식별화완료여부(검수 워크플로 상태와 같은 자리에 보관되는 Y/N 값, 기본값 Y)를 먼저 판정한다. 그 값이 N 이면 승인이 거부되고 흐름이 거기서 끝나므로 검수 상태 전이·라벨 버전 스냅샷·학습데이터 산출물 재생성·관제 통지가 하나도 발생하지 않는다. 이 판정이 막는 것은 검수 승인뿐이며, 라벨 조회·프레임 이미지·영상 스트리밍·산출물 생성까지 함께 닫는 비식별 누락 신고 게이트와는 별개의 축이다. 이 두 축을 통과하면 상태 전이 유효성을 먼저 판정한다 — 이미 승인된 영상을 재검토 필요 표시 없이 다시 승인하면 409 CONFLICT 이고 그 밖의 허용되지 않은 전이는 400 INVALID_INPUT 이며, 재승인은 이 검증을 건너뛴다. 그 뒤 실제 상태 전이 이전에 라벨 게이트가 판정한다. 라벨이 1건도 없는데 검수자 확인(noLabelConfirmed)이 없으면 409 REVIEW_NO_LABEL 로 막고, 객체가 실제로 없는 영상(negative sample)임을 검수자가 확인하면 통과시키되 그 사유를 승인 이벤트 기록에 남긴다. 반대로 라벨이 있는 영상에 확인을 보내면 400 INVALID_INPUT 이다. REVIEW_NO_LABEL 은 CONFLICT 와 다른 값이라 화면이 동시 승인 충돌·상태 전이 충돌과 코드로 구분해 분기한다. 라벨 게이트는 최초 승인과 재승인 양쪽에 모두 적용된다.
