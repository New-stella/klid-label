    participant C as ReviewController
    participant S as ReviewService
    participant G as LabelAccessGuard(비식별신고게이트)
    participant SM as ReviewStateMachine
    participant V as VersionService
    participant EA as EvntAnnoReviewService
    participant M as MetaService
    participant SNAP as DatasetVideoMetaSnapshotService
    participant BUS as ApplicationEventPublisher
    participant BR as DatasetExportBridge

    W->>C: POST /v1/reviews/{videoId}/submit
    C->>S: submit(videoId, actor)
    S->>SM: verify(ASSIGNED→PENDING)
    SM-->>S: OK
    S->>S: LS_TASK_EVNT_LOG SUBMIT 기록
    S-->>C: PENDING 응답
    C-->>W: 200 OK

    R->>C: POST /v1/reviews/{videoId}/start
    C->>S: startReview(videoId, actor)
    S->>SM: verify(PENDING→IN_REVIEW)
    SM-->>S: OK
    S->>S: IN_REVIEW 전이
    S-->>C: 응답
    C-->>R: 200 OK

    R->>C: POST /v1/reviews/{videoId}/approve
    C->>S: approve(videoId, req, actor)
    S->>S: 비식별화완료여부 확인(검수 워크플로 상태와 같은 자리, Y/N, 기본값 Y)
    alt 비식별화완료여부가 N 이면
        S-->>C: 승인 거부 — 상태 전이 이전에 판정되어 흐름이 여기서 끝난다
        C-->>R: 승인 거부 응답(검수 상태 전이·버전 스냅샷·산출물 재생성·관제 통지 어느 것도 발생하지 않음)
    else 비식별화완료여부가 Y 이면
        Note over S: 이 값이 막는 것은 검수 승인뿐이다 — 라벨 조회·프레임 이미지·<br/>영상 스트리밍·산출물 생성은 닫히지 않는다.<br/>그 통로들까지 함께 닫는 아래의 비식별 누락 신고 게이트와는 별개의 축이다
    end
    S->>G: requireNotUnderDeidentReport(rawSn)
    alt 비식별 신고 구간(DE_IDENT_YN='F')이면
        G-->>S: 412 PRECONDITION_FAILED
        S-->>C: 412 응답(흐름 중단 — 이후 단계 전혀 실행되지 않음)
        C-->>R: 412 Precondition Failed
    else 신고 없음
        G-->>S: 통과
        S->>S: 재승인 여부 판정(currentStatus=APPROVED && REVLT_YN='Y')
        alt 최초 승인
            S->>SM: verify(IN_REVIEW→APPROVED)
            SM-->>S: OK
            S->>S: DATA_STTS_CD ← APPROVED 전이
        else 재승인(REVLT_YN='Y')
            S->>S: 상태 전이 생략(이미 APPROVED, 멱등) + REVLT_YN 표시 해제
        end
        S->>S: LS_TASK_EVNT_LOG APPROVE 기록
        S->>S: flush() — 상태 커밋(낙관적 잠금 충돌 시 409 CONFLICT)
        S->>V: commitApproved(rawSn, actor)
        V-->>S: LS_LABEL_VERSION 스냅샷 생성(SAVE_REASON=APPROVED)
        S->>EA: autoApproveOnVideoApproval(rawSn, actor)
        EA-->>S: event_annotation 검토 APPROVED 전이
        S->>M: autoApproveOnVideoApproval(rawSn, actor)
        M-->>S: 시계열 메타 검토 APPROVED 전이
        S->>SNAP: materialize(rawSn)
        SNAP-->>S: LS_DATASET_VIDEO_META 동결(라벨·event_annotation·메타 통합 스냅샷)
        alt 최초 승인
            S->>BUS: publishEvent(ReviewApprovedEvent)
        else 재승인 & 열린 디바운스 윈도우 있음
            Note over S: 이벤트 미발행 — REVLT_YN 해제로 기존 축적 윈도우가<br/>다음 flush tick 에 자동으로 풀린다(아래 재승인 흐름 참조)
        else 재승인인데 열린 윈도우 없음(방어적 폴백)
            S->>BUS: publishEvent(ReviewApprovedEvent) — 폴백 강제 재생성
        end
        S-->>C: 승인 응답(APPROVED)
        C-->>R: 200 OK
    end

    Note over BUS,CTRL: AFTER_COMMIT — 검수 승인 트랜잭션이 커밋된 이후에만 아래가 실행된다
    BUS->>BR: onReviewApproved(ReviewApprovedEvent)
    BR->>RUN: runApprovalAsync(rawSn)
    RUN->>EXP: export(rawSn, forceRegenerate=true)
    EXP-->>RUN: SUCCEEDED(새 버전 v{n+1} 폴더, 이미지 2벌 전량 재생성)
    RUN->>BUS: publishEvent(DatasetExportCompletedEvent)
    BUS->>N: onExportCompleted(DatasetExportCompletedEvent)
    N->>N: sendCompleted(rawSn) — TASK_COMPLETED 페이로드 조립
    N->>CTRL: TASK_COMPLETED 통지(필수 필드 전부 + 선택 output_ver_no)

    opt 재승인이었고 REVLT_YN 해제로 열린 디바운스 윈도우가 있었다면(다음 flush tick, 별도 스케줄 스레드)
        DEB->>DEB: flushExpiredWindows() tick — 클레임 성공
        DEB->>RUN: runReExportThenNotify(rawSn, true, notifyCallback)
        RUN->>EXP: export(rawSn, true)
        EXP-->>RUN: SUCCEEDED(새 버전 v{n+1} 폴더)
        RUN->>N: notifyCallback 실행 → sendModified(rawSn, changedItems, true)
        N->>CTRL: TASK_MODIFIED 통지
    end

    alt REVIEWER 가 반려를 선택한 경우
        R->>C: POST /v1/reviews/{videoId}/reject
        C->>S: reject(videoId, req, actor)
        S->>SM: verify(IN_REVIEW→REJECTED)
        SM-->>S: OK
        S->>S: LS_DATA_ISSUE 반려사유 기록(계층 연결)
        S->>S: DATA_STTS_CD ← REJECTED 전이
        S->>S: LS_TASK_EVNT_LOG REJECT 기록
        S->>S: flush()
        S-->>C: 반려 응답(REJECTED)
        C-->>R: 200 OK
    end

## description

검수자(REVIEWER)가 제출된 영상을 승인/반려하는 흐름의 시퀀스 다이어그램. 제출(submit)·검수 시작(start)·승인(approve)·반려(reject) 4개 API 호출과, 승인 트랜잭션 내부에서 일어나는 비식별 신고 게이트 · 라벨 전체 스냅샷 생성 · event_annotation·시계열 메타 자동 승인 · 통합 메타 동결(materialize)을 그린다. 승인 트랜잭션 커밋 이후(AFTER_COMMIT)에 비동기로 이어지는 학습데이터 산출(export)과, 그 산출이 성공한 뒤에만 나가는 관제 완료 통지(TASK_COMPLETED)까지 포함한다. 완료 통지 페이로드는 영상 단위 메타만 싣는 평면 snake_case 객체이며, 필수 필드는 job_id·event_type_cd·evnt_cls_cd·evnt_ctgry_cd·lclgv_cd·lclgv_nm·duration_sec·image_count·gen_ai_yn 이고 여기에 선택 필드 output_ver_no 가 더해진다. 필수 필드는 값이 null 이어도 키를 남기고(키를 빼면 수신측이 전량 거부한다) 선택 필드는 값이 없으면 키 자체를 생략한다 — 이 비대칭은 의도된 것이라 한쪽으로 통일하지 않는다. 최초 승인과 재승인(검수완료 후 수정 → 재검수 → 재승인)은 이벤트 발행 여부가 갈리며, 재승인의 경우 산출·수정 통지(TASK_MODIFIED)는 이 API 호출 안에서 나가지 않고 재검토 표시(REVLT_YN) 해제로 풀리는 디바운스 윈도우가 별도 스케줄 tick 에서 처리한다. 승인 요청 직후에는 비식별화완료여부(검수 워크플로 상태와 같은 자리에 보관되는 Y/N 값, 기본값 Y)를 먼저 판정한다. 그 값이 N 이면 승인이 거부되고 흐름이 거기서 끝나므로 검수 상태 전이·라벨 버전 스냅샷·학습데이터 산출물 재생성·관제 통지가 하나도 발생하지 않는다. 이 판정이 막는 것은 검수 승인뿐이며, 라벨 조회·프레임 이미지·영상 스트리밍·산출물 생성까지 함께 닫는 비식별 누락 신고 게이트와는 별개의 축이다.
