## description

검수 승인(완료) 시 영상 단위 메타만 담은 TASK_COMPLETED, 검수 완료된 영상을 고친 뒤 그 수정이 재검수에서 승인될 때 변경 파일명 목록만 담은 TASK_MODIFIED 를 관제서버 inbound SPI 에 비동기 push 한다.

[★수정분의 트리거 = 재검수 승인 (2026-08-07 확정, 구속)] 완료된 영상을 고치면 그 영상은 재검수 대상이 되고, 검수자가 그 수정을 다시 승인한 시점에 산출 재생성과 통지가 돈다. 수정만으로는 아무것도 나가지 않는다 — 학습데이터는 검수를 통과한 것만 확정이기 때문이다. 대가로 재승인 전까지 관제는 직전 승인본을 본다(인지·수용). ⚠ 구 정책 — 검수 완료 후 라벨/메타를 수정한 시점에 바로 통지 — 는 폐기됐다.

[★발송 순서 = export 성공 이후 (구속)] 승인·재승인 양쪽 모두 export 가 SUCCEEDED 된 뒤에 보낸다. export 가 비동기라 통지가 앞서면 관제가 V_COMPLETED_VIDEO.OUTPUT_PATH_NM(개명 전 EXPORT_PATH_NM) 을 조회할 때 구 버전 폴더를 픽업한다. 이벤트 체인: 검수 승인(EVT-006) → export 전량 재생성 → 산출 완료(EVT-009) → 통지 발송. export 가 실패하면 통지를 보류하고 재산출 성공 후 재개한다(유실이 아니라 지연). ⚠ 재-export 트리거(수정 축적·디바운스 flush 포함)는 통지 발송 토글과 무관하게 항상 동작한다 — 그 토글은 발송만 게이팅한다.

[계약] ★BREAKING(2026-07-30) — 구 단일 경로(POST /api/v1/notify) 계약을 폐기하고 notify-completed/notify-updated 2경로 + 평면(flat) snake_case 페이로드로 전면 교체됐다. 양방향 M2M 미운영 — 단방향 outbound + inbound 조회 API 패턴. 페이로드에 PII·토큰·라벨/메타 본문 미포함(요약만). 경로·필드명은 관제 정본과 정합 완료다 — 2026-07-27 조사에서 확인된 경로·페이로드 불일치는 그 뒤 계약 전면 교체로 해소됐다. ⚠ 인증은 아직 미확정이다 — 관제 정본은 x-access-token 헤더를 요구하나 아웃바운드 통지는 인증 헤더를 부착하지 않으며, 그 토큰의 발급 주체가 확정되지 않아 관제 회신을 기다리는 중이다.

[페이로드 계약] TASK_COMPLETED 는 평면 snake_case 필수 필드(job_id·event_type_cd·evnt_cls_cd·evnt_ctgry_cd·lclgv_cd·lclgv_nm·duration_sec·image_count·gen_ai_yn)에 선택 output_ver_no 를 더한 모양이고, TASK_MODIFIED 는 job_id·changed_items{images[]·jsons[]} 에 선택 ver_expln·output_ver_no 를 더한 모양이다. 필드 유무 규약은 비대칭이며 의도된 설계다 — 필수 필드는 값이 null 이어도 키를 남기고(키를 빼면 수신측이 전량 거부한다), 선택 필드는 값이 없으면 키 자체를 생략한다(output_ver_no 가 없으면 산출물 변경 없음으로 읽는다). JSON 키는 수신측 규격명이라 우리 컬럼명과 표기가 다를 수 있다 — evnt_cls_cd 는 컬럼 EVNT_CLSF_CD 에 대응하지만 컬럼명에 맞춰 바꾸지 않는다. changed_items 는 내부 식별자가 아니라 산출 폴더의 실제 파일명(FRM_NO 를 4자리 zero-pad 한 이름 + .jpg/.json)이다. data_info 는 수신측 명세에 키 스키마가 없어 싣지 않는다 — 추정 스키마를 만들면 거부되거나 잘못된 값이 적재된다.

[폐기] 구 서술 — TASK_COMPLETED 에 검수 완료 일시·결과 요약 카운트·요청 ID 를, TASK_MODIFIED 에 변경 프레임 목록(SRC_SN)과 변경 종류를 싣는다 — 는 지금은 그렇게 하지 않는다. 요청 ID 는 페이로드가 아니라 폴백 큐 행의 멱등키이고, 변경 종류 상수는 디바운스 축적 키와 감사 로그용 내부 값이라 통지에 실리지 않는다.

[changed_items 범위] TASK_MODIFIED 는 산출 재생성 여부에 따라 전 프레임(재생성 경로) 또는 빈 목록(디스크 무변경 — 관제가 뷰를 재조회)을 싣는다.

RQ-SFR-08-06 은 R1 범위 외(deprecated)이나 본 통지는 검수완료·버전관리 흐름의 운영 책임으로 유지된다. (R2 UC-009)
