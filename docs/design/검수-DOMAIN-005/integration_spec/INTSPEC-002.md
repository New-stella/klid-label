## change_summary

이벤트 검증(verify) 콜백 규격을 폐기하고 describe(CoT)·describe-sub(VQA) 공용 콜백 수신 규격으로 재작성. results 는 description 단일이며 accuracy·detected 는 verify 전용이라 수신되지 않는다. 콜백 바디에 API 종류 식별자가 없어 request_id 로 축을 역조회한다. 5초 내 2xx·최대 3회 재전송·멱등·순서 무보장·유실 시 회수 수단 없음이라는 벤더 연동 유의사항을 명시했다. 무서명 3계층 방어·멱등 원장·직렬화·원자성은 유지. v4.1.0 — 수신 결과의 내부 귀속을 칸 단위로 확정(5·5-1 절): 묘사 전문은 시계열 서술 전문과 캡션 후보 c1 의 사고 단계 1단계(「상황」 줄 파싱), 추가 질문 응답은 같은 후보의 캡션 본문, 질문 칸은 저작도구 보관 목록에서 조달, 답변·근거 서술·2단계 이후는 공란. 두 창구의 캡션 후보 공유와 도착 순서 무보장 대응, 2026-08-24 확정 대비 반전 경위를 함께 기재했다. 외부 규격 자체는 무변경.

# VLM 시계열 서술 콜백 수신 규격 (저작도구 인바운드)

> 근거: 외부 벤더 확정 계약(KLID 연동 API v1.1.0). 저작도구가 위탁 요청 시 제공한 `callback_url` 로 벤더가 결과를 POST 한다.
> 결정: ① 인증 = **무서명** ② 범위 = 서술 생성 두 축(`describe` = CoT, `describe-sub` = VQA)의 **공용 수신**. 경로는 `/v1/vlm/callback`.

## ★ 이벤트 검증(verify) 은 연동 대상이 아니다
연동하는 위탁 엔드포인트는 `describe`(CoT)·`describe-sub`(VQA) 둘뿐이며 `verify` 는 호출하지 않는다. 따라서 콜백의 `results` 에는 **일치도(accuracy)·탐지결과(detected) 가 없다** — 그 둘은 벤더 규격상 `verify` 전용 응답 필드다. 구 규격이 규정하던 `results.accuracy` 수신·검증·적재와, 그 값이 화면 전용이라 데이터마트 뷰·학습데이터 산출물에 나오지 않는다는 규율은 **규율 대상 자체가 사라져 함께 폐기**한다. 되살리지 말 것.

그보다 앞선 구 규격이 `results` 를 `[{start_sec, end_sec, description}, …]` 구간 배열로 받던 방식도 **폐기 상태 그대로**다. 신·구 양쪽을 받아주는 무단 하위호환은 벤더 버그를 숨기므로 관대한 파싱 없이 거부하고 구조 힌트만 로그로 남긴다.

## 1. 엔드포인트

| 항목 | 값 |
|------|-----|
| Method | POST |
| Path | `/v1/vlm/callback` (저작도구가 `callback_url` 로 벤더에 제공) |
| Content-Type | application/json |
| 인증 | **없음**(벤더가 서명 헤더를 제공하지 않는다) |
| 수신 범위 | `describe`(CoT)·`describe-sub`(VQA) 공용 |

## 1-1. ★ 인증 대체 — 무서명 3계층 방어
벤더가 서명 헤더를 제공하지 않아 서명 검증 미적용은 **확정 설계**다(임시 방편 아님). 대신:
1. **IP allowlist** `webhook.vlm.allowed-ip-cidrs` — 증강 콜백과 달리 미설정 시 완화(경고) 동작이며 fail-closed 가 아니다(증강과의 차이는 재확인 권고).
2. **rate limit + 본문 크기 상한** — 인증 이전 자원 소모 방지.
3. **요청 식별자 발급 게이트** — 저작도구가 발급한 적 없는 `request_id` 는 거부한다.

## 2. 콜백 바디

### 2.1 성공
```json
{
  "request_id": "00000001",
  "status": "completed",
  "results": {
    "description": "한 남성이 전봇대 옆에서 쓰러진 상태로 확인됩니다."
  }
}
```

### 2.2 실패
```json
{
  "request_id": "00000001",
  "status": "failed",
  "error": { "code": "INFERENCE_ERROR", "message": "Video VLM inference failed" }
}
```

실패해도 **콜백은 반드시 전송된다** — 무응답으로 끝나는 경우는 규격에 없다.

### 2.3 응답 (저작도구 → 벤더)
- 200 OK. 바디는 표준 래퍼이며 적용 여부와 요청 식별자를 담는다.

## 3. 필드 정의

| 필드 | 타입 | 필수 | 설명 |
|------|------|:---:|------|
| request_id | String | Y | 위탁 요청 시 저작도구가 발급한 식별자. 콜백 상관관계 키 겸 멱등키. 영숫자·대시·언더스코어 64자 이내 |
| status | String | Y | `completed` \| `failed` — 화이트리스트 |
| results | Object | 조건부 | status=completed 시 필수. **객체 하나**(배열 아님)이며 `description` 단일 필드를 담는다 |
| results.description | String | Y | 자연어 서술 전문. 최대 2000자, 공백만 있으면 거부 |
| error | Object | 조건부 | status=failed 시 필수 |
| error.code | String | Y | 오류 코드 |
| error.message | String | Y | 오류 메시지 |

★ `completed` 인데 `results.description` 이 비어 있으면 **400** 이다 — 적재부에서 터지면 500 이 되므로 입구에서 막는다(fail-secure).

★ 콜백 바디에는 **어느 API 의 결과인지 알려 주는 식별자가 없다.** 축(CoT / VQA) 판별은 오로지 `request_id` 역조회로 한다.

## 4. 수신 규율 (벤더 연동 유의사항)

- **응답 시한** — 콜백을 받으면 **5초 안에 2xx** 를 반환한다. 늦거나 2xx 가 아니면 벤더가 재전송한다(**최대 3회, 각 5초 간격**). 따라서 무거운 후속 작업은 2xx 를 돌려준 뒤에 수행한다.
- **멱등** — 같은 콜백을 여러 번 받을 수 있으므로 `request_id` 기준으로 멱등 처리한다. 이미 처리한 식별자면 본문을 무시하고 2xx 만 반환한다.
- **순서 무보장** — 요청 순서와 콜백 도착 순서가 일치하지 않는다. 요청과 결과의 대응은 `request_id` 로만 판정하고 도착 순서에 의존하지 않는다.
- **유실 시 회수 수단 없음** — 재전송 3회가 모두 실패하면 그 결과는 유실되며, **다시 받아올 조회 API 가 없다.** 재수행은 새 위탁으로만 가능하다.
- **본문 형식 무보장** — `description` 은 자연어 평문이고 형식이 고정돼 있지 않다. 문자열 파싱으로 구조를 뽑아내는 처리에 의존하지 않는다.

## 5. 저작도구 내부 매핑

- **request_id → 영상 · 축**: 콜백 바디에 영상 식별자도 API 종류도 없으므로, 위탁 시 발급한 요청 식별자에 대상 영상과 축(CoT / VQA)을 함께 영속해 둔 멱등 원장으로 역조회한다. 발급된 적 없는 식별자는 거부.
- **status=completed** — 서술 전문을 시계열 서술 축(`vlm.description`)으로 적재한다. 이 값이 검수큐에 들어가며 화면에서 편집 가능하다.
- **이벤트 어노테이션 자동채움 — 칸 단위 귀속 (2026-08-25 확정)**: 수신 결과가 이벤트 어노테이션의 **어느 칸에 들어가는지**를 칸 단위로 못 박는다. 두 창구는 **같은 캡션 후보 `c1` 을 공유**한다.
  - 묘사(`describe`) 응답 서술 전문 → ① 시계열 서술 전문(영상 블록) ② 캡션 후보 `c1` 의 **사고 단계 `1단계`**(전문에서 「상황」 라벨 줄만 파싱한 값).
  - 추가 질문(`describe-sub`) 응답 서술 → 캡션 후보 `c1` 의 **캡션 본문**.
  - **질문 칸** → **저작도구가 보관하는 검증 이벤트 유형별 질문 문구 목록**에서 조달한다(마킹에서 고른 값 → 없으면 그 유형의 첫 번째). **위탁 응답에서 오지 않는다** — 질문 문장은 이벤트별로 벤더 서버가 관리하며 연동 시스템이 지정하지 않는다.
  - **답변 · 근거 서술 · 사고 단계 2단계 이후** → **자동으로 채우지 않는다.** 사람이 확정할 공란이다.
  - **「상황」 파싱** — 묘사 전문은 `- 라벨: 값` 줄 단위로 오므로 「상황」 라벨 줄을 찾아 **그 줄의 줄바꿈까지**를 값으로 쓰고 다음 라벨 줄로 이어붙이지 않는다. 선행 공백·콜론 앞뒤 공백은 관용 처리한다. 같은 라벨이 여러 번 나오면 **첫 번째**를 쓴다. 「상황」 줄이 없으면 **채우지 않는다 — 빈 값도 넣지 않는다.**
  - ⚠ **라벨 목록에 의존하지 않는다** — 규격이 「장소·날씨·상황 등」이라고만 쓰고 전체 목록·순서·필수 여부를 정의하지 않는다. 「상황」 줄 하나만 찾는 방식이라야 항목이 늘거나 순서가 바뀌어도 성립한다.
  - **사고 단계는 `1단계` 키만 만든다** — 2단계 이후 키를 만들지 않는다.
  - **근거 서술은 파싱으로 채우지 않는다** — 자유 서술이라 형식이 고정돼 있지 않다(§4 「본문 형식 무보장」). 「상황」 파싱은 별개다 — 그건 규격 콜백 예시에 형식이 명시된 묘사 축이다.
  - **도착 순서에 의존하지 않는다** — 두 창구의 콜백 도착 순서는 보장되지 않는다. 나중에 도착한 축이 캡션 후보를 통째로 교체해 먼저 도착한 축의 값을 지우면 안 되고, **자기 칸만 채운다.**
  - ⚠ **인지·수용한 잔여 위험** — 지금 위탁 요청 본문에는 우리가 고른 질문을 실을 자리가 없다. 첫 번째가 아닌 질문을 고르면 **기록된 질문과 벤더가 실제로 쓴 질문이 달라진다.** 이를 알고 수용했다(되돌리지 말 것).
  - **보호 경계는 전부 유지한다** — 승인 이력이 있으면 자동채움하지 않음 · 값이 이미 있으면 덮지 않음 · 어노테이션 검토가 종결됐으면 하지 않음 · 중복 콜백 멱등 · 자동채움은 재검수를 발화시키지 않음 · 이벤트 분류 조달값이 없으면 행을 만들지 않음.
  - **기적재분은 백필하지 않는다** — 신규 수신분부터 적용한다.
- **레거시 구간 키 보존**: 구 규격으로 이미 적재된 구간 키(`0-8`·`8-16` …)는 **작업 결과라 보존**하며 화면과 산출물이 계속 읽는다. 삭제·숨김 금지.
- **status=failed** — 적재 없이 해당 위탁을 실패로 종결해 고착을 푼다. 자동 재요청 잡은 없으며 수동 재처리가 필요하다.
- **멱등·직렬화·원자성**: 동일 요청 식별자 재수신은 원장으로 replay 스킵. 동시 콜백은 잠금으로 직렬화한다. 트랜잭션 롤백 시 처리완료 표식도 함께 롤백되어 벤더 재전송을 유도한다.
### 5-1. 이 귀속은 직전 확정을 되돌린 반전이다
2026-08-24 확정은 *"추가 질문 결과는 **답변** 축 초안으로 간다"* 였고, 그때 *"묘사 결과를 캡션·사고 단계 축으로 보낸다"* 는 지시를 명시적으로 폐기했다. 2026-08-25 사업 담당 회신이 그것을 **다시 캡션·사고 단계 축으로 되돌린다** — 추가 질문 응답은 답변이 아니라 캡션 본문이고, 답변 칸은 사람이 확정할 공란이다. 같은 축이 이틀 만에 두 번 뒤집혔으므로, 언제 무엇으로 확정했고 무슨 근거로 바뀌었는지를 남겨 세 번째 반전을 막는다. **되살리지 말 것.**

## 6. 승인된 영상의 서술이 갱신되면 재검수로 되돌린다
이미 승인된 영상의 시계열 서술이 **실제로 달라진 경우에만** 검토행을 미처리로 되돌리고 수정 통지 축을 타게 한다. 값이 같으면 아무것도 하지 않는다(멱등 — 재검수·통지 폭주 방지). 근거: 데이터마트 뷰가 라이브 메타를 조인하므로 상태를 승인으로 둔 채 값만 갱신하면 검수자가 한 번도 보지 않은 서술이 그대로 관제로 나간다. 반려된 검토행도 되돌린다 — 반려 판단은 *바뀌기 전 본문*에 대한 것이라 새 본문에 적용되지 않는다.

## 7. 비식별 신고 구간 재개 흐름
비식별 누락 신고(`DE_IDNTF_YN='F'`) 구간에서는 위탁 자체가 보류되므로 콜백이 발생하지 않는다. 신고 해소 시 보류 기록을 근거로 **재위탁**하고, 그 결과로 본 콜백이 정상 수신된다(멱등 조건: 시계열 메타 0건).
