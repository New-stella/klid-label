## scenario

### then

- 묘사 서술 전문이 vlm.description에 적재되고 검수큐에 진입한다(검수큐는 이 전문뿐)
- 이벤트 어노 초안의 자기 칸만 채워진다(후보 통째 교체 없음)
- 승인 이력·기존 값·종결 시 채우지 않고 중복 콜백은 멱등이며 자동채움은 재검수를 발화하지 않는다
- 검수자가 창에서 검토·수정 후 RVW_STTS_CD를 승인/반려로 전이한다
- 질문 칸은 위탁 시점에 추가 질문 요청 본문(prompt)에 실어 보내고 멱등 원장에 보관한 그 문구로 채워진다 — 결과 수신 시 재조달하지 않아 보낸 질문과 기록된 질문이 같다
- 일치도(accuracy)·검출여부(detected)는 이 경로로 적재되지 않는다 — 판정(verify) 창구 전용 응답 필드이고 그 창구는 연동 대상이 아니다
- 추가 질문 축이 실패해도 마킹의 위탁 상태 표시는 실패로 내려가지 않는다 — 그 표시는 묘사 축 기준이다
- 구 창구 describe-sub 로 이미 받아 적재된 결과는 그대로 보존된다

### when

- 콜백을 적재하고 검수자가 창에서 검토·수정 후 승인/반려한다
- request_id로 위탁 원장을 역조회해 어느 창구의 결과인지 가른다

### given

- 외부 VLM이 두 창구(묘사 describe · 추가 질문 custom)의 시계열 분석을 콜백으로 보낸다
- 두 축은 각각 별개 request_id로 위탁됐고, 콜백 바디에는 어느 창구의 응답인지 가르는 구분자가 없다
- 추가 질문 축에 실어 보낸 질문 문구는 위탁 시점에 멱등 원장(LS_WEBHOOK_IDEMPOTENCY.QSTN_CN)에 보관돼 있다

## statement

외부 VLM이 묘사(describe, POST /v1/videovlm-klid/describe)·추가 질문(custom, POST /v1/videovlm-klid/custom) 두 창구의 분석 결과를 창구별 request_id로 각각 콜백(POST /v1/vlm/callback)으로 보내면(요청·도착 순서 불일치), 콜백 바디에 어느 창구의 응답인지 가르는 구분자가 없으므로 request_id로 위탁 원장을 역조회해 축을 가른다 — 원장 채널 식별자는 창구가 바뀌어도 그대로다. 묘사 결과 서술 전문을 LS_DATA_META(vlm.description)에 적재하고 LS_DATA_META_REVIEW 검수큐에 진입시킨다(검수큐 진입은 이 서술 전문뿐). 같은 결과로 이벤트 어노테이션 초안의 자기 칸만 채우되(「상황」→캡션 후보 c1 CoT 1단계, 추가 질문 답변 서술→같은 후보 캡션 본문, 질문 칸→위탁 시점에 조달해 추가 질문 요청 본문 prompt 에 실은 뒤 멱등 원장(LS_WEBHOOK_IDEMPOTENCY.QSTN_CN)에 보관한 그 문구를 읽어 채우며 결과 수신 시 재조달하지 않는다, 후보 통째 교체 없음), 승인 이력이 있거나 칸에 값이 있거나 어노 검토가 종결됐으면 채우지 않고 중복 콜백은 멱등이며 자동채움은 재검수를 발화시키지 않는다. 콜백 results 는 {description} 단일이라 일치도(accuracy)·검출여부(detected)는 이 경로로 오지 않는다 — 그 둘은 미연동인 판정(verify) 창구 전용 응답 필드다. 추가 질문 축의 실패는 기록만 남기고 마킹의 위탁 상태 표시를 실패로 내리지 않는다 — 그 표시는 묘사 축 기준이다. 검수자가 SCREEN-005 우측 메타 탭의 요약 카드로 여는 「영상 분석 설명 · 이벤트 어노테이션」 창의 왼쪽 칸 「영상 분석 설명」(저장 축은 시계열 메타)에서 검토·수정 후 승인/반려(RVW_STTS_CD 전이)한다. [폐기] 구 추가 질문 창구 POST /v1/videovlm-klid/describe-sub — 외부 분석 서버가 계속 제공하나 연동 대상으로 두지 않는다. 그 창구로 이미 받아 적재된 결과는 보존한다.
