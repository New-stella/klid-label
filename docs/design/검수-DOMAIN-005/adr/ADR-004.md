# 생성형 AI 본체 외부화 — 저작도구는 증강 결과 검수만

## context

1차는 Text2Image/Image2Image/Image2Video/메타데이터 기반 생성 등 생성형 AI 기능과 업로더 검토·등록을 저작도구 내부에 두었다. 고도화는 생성형 AI 모델 학습·파인튜닝·프롬프트·UI/UX를 외부 시스템 책임으로 두고, 저작도구는 외부 증강 결과의 수신·라벨링·검수(SCR-AUG-002)만 보유한다. 이후 생성형 AI API 연동명세서 v1.1(ADR-101, 2026-07-24 관제 확정) 정합 과정에서 증강 위탁 job_id의 발급 주체가 저작도구에서 벤더(외부 생성형 AI 시스템)로 반전되었다 — 명세서 v1.1의 4개 엔드포인트·무인증 계약과 정합했다(2026-07-28). 콜백 경로도 /v1/aug/callback(HMAC 서명)에서 /v1/genai/callback(무서명)으로 전환되었고(2026-07-27), 개발용 콜백 시뮬레이터는 두지 않는다.

## deciders

- 박찬기
- 김현욱

## decision

### chosen_option

본체 외부화 채택(job_id 벤더 발급, 무서명 콜백)

### justification

생성형 AI 본체는 외부 시스템 책임으로 분리하고, 저작도구는 HttpExternalAugmentClient로 위탁 요청을 보내고 /v1/genai/callback(무서명)으로 결과를 수신·검수한다. 증강 job_id는 벤더가 발급한다(구 저작도구 발급 설계 폐기) — 생성형 AI API 연동명세서 v1.1(ADR-101) 계약과 정합한다. 콜백은 벤더 확정 규격이 무서명이라 IP allowlist+rate limit+request_id 게이트로 방어한다. 내부 생성 기능(DFEAT-032~036)은 계속 폐기 상태.

## consequences

### risks

- 외부 증강 시스템 연동 실패 시 증강 데이터 유입 지연
- IP allowlist 미설정 시 무서명 콜백이 스푸핑에 노출될 위험 — fail-closed 설정 필수

### negative

- 생성형 AI 도메인(DOMAIN-008)·생성 DFEAT 폐기
- job_id 발급주체 반전으로 구 설계(저작도구 발급) 코드·문서 정정 필요
- 콜백 서명(HMAC) 제거로 IP allowlist·rate limit 등 보완 통제가 유일한 방어선

### positive

- 책임 경계 명확
- 저작도구 범위 축소
- 생성형 AI API 연동명세서 v1.1(ADR-101) 계약과 정합
- 무서명 규격에 맞춘 실배선 완료로 개발용 시뮬레이터 제거

## considered_options

### 생성형 AI 내장 유지

**cons**:

- 모델 학습/운영 책임 과중
- 범위 밖 책임

**pros**:

- 단일 시스템

- **description**: 저작도구 내부에 생성 기능 유지

### 본체 외부화 + 저작도구 job_id 발급(구 설계, 폐기)

**cons**:

- 생성형 AI API 연동명세서 v1.1(ADR-101) 계약과 불일치(벤더가 job_id를 발급하는 규격)

**pros**:

- 저작도구가 식별자를 통제

- **description**: 증강 위탁 job_id를 저작도구가 발급하고 벤더에 전달

### 본체 외부화 + 벤더 job_id 발급(채택)

**cons**:

- 외부 연동(콜백) 의존
- 무서명 콜백에 대한 보완 통제(IP allowlist 등) 필요

**pros**:

- 연동명세서 v1.1과 정합
- 실배선 완료

- **description**: HttpExternalAugmentClient로 위탁하고 job_id는 벤더가 발급, 콜백은 무서명(/v1/genai/callback)으로 수신
