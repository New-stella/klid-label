## description

검수 승인된 영상에 대해 관제서버로 보내는 outbound TASK_COMPLETED 통지. 영상 단위 메타만 싣는다 — 평면 snake_case 필수 필드(job_id·event_type_cd·evnt_cls_cd·evnt_ctgry_cd·lclgv_cd·lclgv_nm·duration_sec·image_count·gen_ai_yn)에 선택 output_ver_no 를 더한 모양이다. 필수 필드는 값이 null 이어도 키를 남기고(키를 빼면 수신측이 전량 거부한다) 선택 필드는 값이 없으면 키 자체를 생략한다 — output_ver_no 가 없으면 수신측은 산출물 변경 없음으로 읽는다. JSON 키는 수신측 규격명이라 우리 컬럼명과 표기가 다를 수 있다(evnt_cls_cd 는 컬럼 EVNT_CLSF_CD 에 대응하지만 컬럼명에 맞춰 바꾸지 않는다). [폐기] 검수 완료 일시·결과 요약 카운트·요청 ID 를 싣던 방식은 지금은 그렇게 하지 않는다 — 요청 ID 는 페이로드가 아니라 폴백 큐 행의 멱등키다. 라벨·메타 본문은 포함하지 않으며 관제가 필요 시 저작도구 API·데이터마트 View 로 보강한다.

[★발송 시점 — export 성공 이후(2026-07-27 확정)] 승인 즉시가 아니다. export 가 비동기라 통지가 앞서면 관제가 구 버전 폴더를 픽업한다. 따라서 ReviewApproved(EVT-006) → export 전량 재생성 → DatasetExportCompleted(EVT-009) → 본 통지 순서로 직렬화된다. export 가 실패하면 통지를 보류하고 산출 실패 회수기가 재산출 성공 후 재개한다(유실이 아니라 지연).

[토글 경계] authoring.control-notify.enabled 는 본 통지의 발송만 게이팅한다. 재-export 트리거(승인 이벤트 수신·수정 축적·디바운스 flush)는 토글과 무관하게 항상 동작한다.

[계약 상태] 관제팀과 필드 계약은 협의 대상이다(데이터마트 View 재편·파생영상 경로 포함).

#### job_id

작업 식별자 — 영상 단위 ID(RAW_SN)를 문자열로 표기한다.

#### evnt_cls_cd

JSON 키는 수신측 규격명이며 우리 컬럼명 EVNT_CLSF_CD 와 표기가 다르다. 컬럼명에 맞춰 바꾸지 않는다.
