- **description**: 비식별화 완료 여부. 값이 N 인 동안 그 영상의 검수 승인이 거부된다. 기본값 Y 는 이관과 무관한 기존 영상의 승인이 이 값 때문에 막히지 않게 하기 위함이며, 이관 시 원본으로 지정해 들어온 영상만 N 으로 시작한다. N 에서 Y 로 바뀌는 계기는 영상 파일 유무로 갈린다 — 영상 파일을 함께 받은 원본은 저작도구의 비식별이 성공으로 기록되면 Y 가 되고, 프레임만 받아 대상 영상이 없으면 외부에서 비식별한 산출물을 받아 기록하는 별도 행위로 Y 가 된다. 그 기록은 비식별 산출물이 실제로 존재하는지 확인한 뒤에만 성립해야 한다 — 확인 없이 값만 바꾸면 처리되지 않은 산출물이 승인될 수 있다. 이 값은 검수 승인만 막는다 — 라벨 조회·프레임 이미지·영상 스트리밍·산출물 생성은 닫지 않는다. 그 통로들을 함께 닫는 것은 비식별 여부 값 가운데 비식별 누락 신고 상태뿐이다. 이 값이 Y 여도 영상 축 비식별 여부는 미수행일 수 있어 두 축은 별개이며 모순이 아니다.

## description

고도화 검수·영상상태 도메인 물리 ERD (PostgreSQL). 영상 단위(RAW_SN)로 진행상태·검수 반려 이슈를 관리한다. 진실원: backend db/migration V1(baseline — 2026-08-13 스쿼시로 구 V36/V38 등 개별 이력이 통합됨, LS_RAW_DATA_STATUS 전량 정의) + JPA 엔티티 LsRawDataStatus 의 @Column. 코드에 실재하는 컬럼만 반영. PK 식별자 RAW_DATA_ID 는 영상 단위 ID(LS_DATA_RAW.RAW_SN) 를 가리킨다. FK 제약은 klid_system 공유 DB 운영 안정성 정책상 DB 레벨로 선언하지 않으며 본 ERD 에서는 논리적 참조로만 표기. 적재 등록 매핑 테이블은 두지 않는다 — 영상 1건당 1행이라는 사실이 원시영상 테이블 자체와 겹쳐 별도 매핑이 성립하지 않는다. 영상 상태의 참조 상대도 원시영상으로 바로잡았다. [폐기] LS_DATA_ISSUE 는 이 ERD 에서 정의하지 않는다 — 정의는 ERD-023 이 소유한다(설계 결정). 이 ERD 의 책임은 LS_RAW_DATA_STATUS 뿐이다.
