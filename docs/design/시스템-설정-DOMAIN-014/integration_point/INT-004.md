## description

저작도구가 외부 비식별 솔루션(KPST)에 영상 비식별 처리를 위탁하는 outbound 요청. 비식별화는 **파이프라인 선두 단계**로, 영상 적재 직후 자동 트리거되며 성공해야 마킹 단계로 진입한다.

## 실측 계약 (2026-07-27 확인)
- 호출 주체: 저작도구의 비식별 위탁 연동(제출 오케스트레이션 포함)
- `GET /` — 연결 확인(connect)
- `POST /project` — 프로젝트 생성(위탁 제출)
  - 요청 `KpstProjectRequest`: `project_name` · `creator` · `export_path` · `input_path` · `files[]` · `masking_type` · `db_save` · `masking_range` · `exp_quality` · `exp_format`
  - 응답 `KpstProjectResponse`: `result` · `prj_id` (이후 폴링 INT-005 의 키)
- `POST /delete_project_id` — 재위탁 전 stale export 정리(구 산출물 오회수 방지)
- 파일 본문 미전송 — `input_path`/`export_path` 공유 경로로 주고받고 KPST 가 공유 스토리지에 직접 산출

## 활성화 — 프로파일별 실측
토글 `kpst.deid.enabled` 기본 `${KPST_DEID_ENABLED:true}`
| 프로파일 | enabled | base-url | 실질 동작 |
|---|---|---|---|
| 공통 기본값 | true | `https://localhost:9201` | — |
| local | true | `http://klid-mock-server:9400` | **mock-mode=true 로 KPST 미사용** |
| dev | true(상속) | `http://klid-mock-server:9400` | **mock-mode=true 로 KPST 미사용** |
| stg | true(상속) | 오버라이드 없음 | mock-mode 기본 false → **실제 KPST 활성** |
| prd | true | env.template 기본 `https://127.0.0.1:9201`(실배포 시 실주소 교체 필수) | **실제 KPST 활성** |

**mock-mode** `authoring.integration.deidentify.mock-mode`(`${DEIDENTIFY_MOCK_MODE:false}`) — local `true` · dev `true` · stg/prd 오버라이드 없음→`false`. **prd 에서 true 면 기동을 거부한다**(allowlist=local/dev/stg) — fail-closed 설계.

※ 로컬 검증은 내부 mock 모드가 아니라 **목 서버(:9400)를 바라보게 배선**하는 것이 운영 원칙이다(본 프로그램이 자체적으로 결과를 채우면 검증이 무효해짐).
