## description

위탁(INT-004)한 비식별 작업의 진행·완료를 주기 배치(Quartz 잡)가 주기적으로 조회하는 outbound 폴링. KPST 는 콜백을 제공하지 않으므로 폴링이 유일한 완료 감지 수단이다.

## 실측 계약 (2026-07-27 확인)
- `GET {base-url}/retrieve_progress` — **GET 이지만 바디에 JSON 전송**(저수준 HTTP 클라이언트 경로)
- 요청 `KpstProgressRequest`: `reqUserId` · `prjId`
- 응답 `KpstProgressResponse`: `result` · `data{prjCount, prjStatus[]{prjId, prjName, progressRate, dsCount, dsStatus[]{dsId, fileName, procState, progressRate, totalFrame, startTime, endTime}}}`

## procState 해석 (운영 확정)
| 값 | 의미 | 처리 |
|:--:|---|---|
| `2` | 완료 | 산출물 무결성 검증 후 `deIdntfYn='Y'` 전이 |
| `3` / `4` / `99` | 중지 / 삭제중 / 오류 (터미널 실패) | 즉시 `'F'` 종결 |
| `null` / `0` / `1` | 진행중 | 다음 폴링까지 대기 |

## ★ 결과 파일명 규칙 (2026-07-21 실서버 실측 확정)
응답의 `fileName` 은 산출물명이 **아니라 원본 입력파일의 절대경로**이며, 실제 결과물은 `export_path` 아래 **`{stem}-mask{ext}`** 명명으로 생성된다. 과거 이것을 이중 오해(경로 거부 크래시 + 원본명으로 조회)해 완료 건을 `'F'` 로 오종결하는 결함이 있었고, basename 추출 + `-mask` 변환 + 디렉터리 스캔 폴백으로 수정됐다.
- 폴백 규칙: 1차 경로 실패 시 export 디렉터리를 스캔해 **단일 파일이면 채택**, **2개 이상이면 모호 실패로 종결**(잘못된 영상을 비식별본으로 오인하는 PII 사고 방지)

## 완료 판정 가드
도착 파일이 **존재하고 0바이트 초과**해야만 `'Y'` 로 전이한다. 빈 파일을 성공으로 오판하면 비식별 되지 않은 영상이 마킹·라벨링 단계로 흘러들어가므로 PII 방어선이다.

## retry_policy

폴링 주기 `kpst.deid.poll-interval-sec` **30s**, 시도 상한 `poll-max-attempts` **240**, 경과 타임아웃 `poll-timeout-minutes` **180분**. Resilience4j 는 INT-004 와 동일한 `kpstDeid` 설정 공유. ⚠ 타임아웃·터미널 실패 시 `deIdntfYn='F'` 마킹 후 **자동 재시도 없음** — dead-letter 테이블도 없으며 외부 솔루션으로 수동 재비식별 후 resolve 하는 운영 정책이다.
