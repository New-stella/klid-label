## description

등록된 검증 이벤트 유형을 정렬순서 오름차순으로 반환하고, 각 유형에 그 유형의 질문 목록(정렬순서 오름차순)과 관제 이벤트유형 코드 짝을 함께 싣는다. 검수자 전용이다.

[질문 문구를 저작도구가 보관하는 이유] 외부 시계열 분석의 질문 문장은 사업자 서버가 이벤트별로 관리해 우리가 지정할 수도 없고 결과에 실려 오지도 않는다. 그런데도 이벤트 어노테이션의 질문 칸을 채워야 하므로 문구를 지어내지 않고 저작도구가 유형별 목록을 보관해 거기서 조달한다. 이 조회는 운영자가 그 목록을 확인하는 통로다.

[관제 유형 짝은 인입 원장을 읽어 만든다] 관제는 인입 행 하나에 관제 이벤트유형 코드와 검증 이벤트 유형 코드를 함께 실어 보낸다. 두 코드의 대응은 이미 수신 원장 안에 있으므로 별도 매핑표를 두지 않는다 — 사본을 만들면 두 번째 진실원이 되어 원장과 어긋난다. 한 검증 유형에 관제 코드가 여러 개 붙을 수 있고, 짝지어 수신된 적이 없으면 빈 목록이다.

[두 코드 체계는 다르다] 관제 이벤트유형 코드는 관제가 채번한 코드이고, 검증 이벤트 유형 코드는 외부 시계열 위탁 요청에 싣는 값이다. 이 경로는 이벤트유형 관리 경로와 별개이며 그 경로의 응답에 필드를 더하지 않는다.

[이 목록은 허용목록이 아니다] 여기에 없는 검증 이벤트 유형의 영상도 위탁은 그대로 나가고, 수용 여부는 사업자 응답이 정한다. 목록에 없으면 질문 칸이 비어 있을 뿐이다.

[질문이 없는 유형도 반환한다] 질문 목록이 빈 배열인 유형도 목록에서 빠지지 않는다. 그 유형은 어노테이션 질문 칸을 비운 채로 둔다.
