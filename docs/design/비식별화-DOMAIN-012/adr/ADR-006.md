# 비식별 처리 외부 솔루션 연동 — 캔버스 수동 블러 폐기

## context

1차는 캔버스에서 작업자가 수동으로 블러(비식별)를 칠하는 기능을 가졌다. 고도화는 비식별을 외부 비식별 솔루션(KPST) 연동으로 처리한다. 연동 모델은 최초 설계했던 업로드형(저작도구가 원본 파일을 올리고 결과 파일을 내려받는 방식)이 아니라 공유 마운트 no-copy 모델이다 — 저작도구와 외부 솔루션이 동일 NAS 를 공유 마운트하고 input_path/export_path 를 경로로만 주고받으며 파일 본문은 전송하지 않는다. 완료 회수 응답이 돌려주는 fileName 은 원본 입력 경로이고, 실제 산출물 파일명은 벤더가 정하는 {stem}-mask{ext} 패턴이라 영상마다 다르다. 헬스체크 대상도 존재하지 않는 /health 가 아니라 실제 위탁 경로(root)다. 여기에 더해 최초 결정 당시의 운영 정책 3건(위탁 대상 게이팅·결과 회수 방식·실패 후 재처리 방식)이 뒤집혔으며, 확정된 모습은 결정 항목에 적는다.

## decision

### chosen_option

외부 솔루션 연동(공유 마운트 no-copy 모델) 채택

### justification

비식별을 외부 솔루션 연동으로 전환하고 캔버스 수동 블러(DFEAT-013)는 폐기한다. 연동 방식은 업로드형(파일 송수신)이 아닌 공유 마운트 no-copy 모델을 채택한다 — input_path/export_path 를 경로로만 주고받고 파일 본문은 전송하지 않는다. 산출물 파일명은 외부 솔루션이 결정하므로({stem}-mask{ext}, 영상마다 상이) 고정 가정하지 않고 LS_DEIDENT_PROC_LOG.DE_IDNTF_FILE_PATH_NM 값을 진실원으로 삼는다. 헬스체크는 외부 솔루션이 제공하는 실제 위탁 경로(root)를 사용한다. 비식별 실패 시 DE_IDNTF_YN='F' 로 마킹하고 원본은 절대 삭제하지 않는 원 정책은 유지한다. ★ 운영 정책 3건은 다음과 같이 확정한다. ① 위탁 대상 게이팅을 두지 않는다 — PRVC_TYPE_CD 가 PRVC/PSDO 인 영상만 위탁하던 조건부 게이팅은 두지 않고 전체 영상을 비식별한다. 비식별은 파이프라인의 선두 단독 단계로 적재 직후 자동 실행되며, 마킹은 그 산출물인 비식별 영상에서 수행한다. ② 결과 회수에 콜백을 두지 않는다 — 저작도구가 주기 배치로 외부 솔루션의 진행·완료를 폴링해 회수한다. 비식별 완료를 수신하는 콜백 엔드포인트는 두지 않는다. ③ 자동 재비식별 큐를 두지 않는다 — 비식별 실패·비식별 누락 신고 영상을 자동으로 다시 위탁하는 전용 큐는 두지 않으며, 외부 비식별 프로그램에서 사람이 다시 비식별한 뒤 신고 해소 경로로 복귀시킨다.

## brownfield

### notes

### 연동 아키텍처
- 업로드형(파일 송수신)에서 공유 마운트 no-copy 모델로 전면 개편.
- 완료 회수 응답의 fileName 은 원본 입력 경로이며 산출물 파일명이 아니다 — 산출물 경로는 LS_DEIDENT_PROC_LOG.DE_IDNTF_FILE_PATH_NM 값으로 조회한다.
- 헬스체크 대상은 실제 위탁 경로(root).

### 운영 정책 정정
- 위탁 대상 게이팅(PRVC/PSDO 한정) 폐기 → 전체 영상 비식별, 파이프라인 선두 단독 단계.
- 결과 회수는 주기 배치 폴링 단일 경로 — 비식별 완료 콜백은 두지 않는다.
- 자동 재비식별 큐 폐기 → 외부 비식별 프로그램에서 수동 재비식별.

### 2026-09-14 — 후속 예외(ADR-066)
- 출처유형 제외 예외 추가: 배포 설정에 든 출처유형 영상은 선두 비식별 단계에서 외부 위탁 없이 원본 복사로 비식별을 완료한다.
- 전체 영상 비식별 원칙과 위탁 대상 게이팅 폐지는 그대로 유효하다 — 대체가 아니라 예외다.

## consequences

### risks

- [폐기] 비식별 API 실패 시 재시도 큐 적체 — 자동 재비식별 큐를 두지 않으므로 이 적체는 발생하지 않는다. 원본을 절대 삭제하지 않는 방어는 그대로 유지한다.
- 공유 마운트 권한/경로 오설정 시 KPST가 산출물을 엉뚱한 위치에 쓰거나 실패할 위험 — 헬스체크로 위탁 경로 상시 확인 필요
- 자동 재비식별 큐를 두지 않으므로 비식별 실패·신고 영상은 사람이 다시 비식별할 때까지 그 자리에 머문다 — 방치되면 그 영상은 마킹 이후 단계로 나아가지 못한다. 2026-09-09 완화로 신고 축에 한해 이 위험은 소멸했다 — 신고 해소는 재비식별 수행을 전제하지 않으므로, 후보 목록에서 고른 산출물이 무결성 판정을 통과하면 신고 이전부터 있던 산출물이어도 해소가 성립하고 그 영상은 다시 나아간다. 비식별 실패 축은 그대로 남는다 — 위탁이 실패한 영상에는 쓸 수 있는 비식별 산출물이 없어 사람이 외부 비식별 프로그램에서 다시 비식별해야 한다.

### neutral

- 위탁 대상 게이팅을 두지 않고 전체 영상을 비식별한다는 이 결정에 후속 결정 ADR-066 이 출처유형 제외 예외를 더했다. 배포 설정에 든 출처유형의 영상은 선두 비식별 단계를 타되 외부 솔루션에 위탁하지 않고 원본을 비식별 영상 자리에 복사해 비식별을 완료한다. 이 예외는 이 결정을 대체하지 않으며, 개인정보 유형으로 위탁 대상을 가르던 게이팅을 되살리는 것도 아니다 — 판정 축은 영상이 어디서 왔는가다.

### negative

- 수동 블러 DFEAT-013 폐기
- 산출물 파일명을 고정 가정할 수 없어 문자열 조합 대신 LS_DEIDENT_PROC_LOG.DE_IDNTF_FILE_PATH_NM 조회가 필수(설계 복잡도 증가)

### positive

- 비식별 품질·정책 외부 위임
- 대량 자동 처리
- 파일 전송 오버헤드 제거(공유 마운트로 대용량 영상 업/다운로드 불필요)

- **description**: 저작도구와 KPST가 동일 NAS를 공유 마운트하고 input_path/export_path 경로만 주고받는다. KPST가 저작도구 저장소 경로에 직접 산출물을 쓴다.
