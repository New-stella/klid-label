# 검수 승인 학습데이터 export(NIA JSON) 산출을 저작도구 범위로 포함 (ADR-005 supersede)

## context

ADR-005는 '학습데이터셋 내보내기(Export) 범위 외'로 결정했으나, 실제로는 검수 승인 시점에 학습데이터 파일(영상 루트/{RAW_SN}/v{n}/orgnl|deid/ 하위 COCO 기반 프레임별 JSON)을 자동 산출하도록 구현됐다. 검수 승인 export 폴더 경로를 관제/데이터마트가 V_COMPLETED_VIDEO.OUTPUT_PATH_NM(개명 전 EXPORT_PATH_NM)으로 픽업하는 연동도 함께 자리잡았다. 따라서 ADR-005의 '내보내기 범위 외' 결정은 현행 구현과 불일치하므로 export 산출을 저작도구 범위로 재정리한다.

이후 사업 요구사항 원문(버전 비교·복구 + 데이터마트 연계 관리기능의 라벨링 정보 동기화)을 재검토해 '재생성은 최초 승인 시점에만'이라는 정책을 폐기했다. 다만 그 확대의 기준은 **수정 시점이 아니라 재검수 승인 시점**이다(2026-08-07 확정). 승인 후 사람이 콘텐츠를 고치는 모든 경로(예: 라벨 수정·트랙 편집·트랙 병합·버전 롤백·촬영환경 수정·프레임 설명 수정·개인정보 메타 수정·메타 수동 편집·이벤트 어노테이션 저장)는 그 영상을 재검수 대상으로 되돌리고, 검수자가 다시 승인한 시점에 export 를 새 버전(v{n+1})으로 전량 재생성한다. 학습데이터는 검수를 통과한 것만 확정이기 때문이다.

산출 트리는 원본 영상 디렉터리 하위 단일 co-locate 루트({rawSn}/)로 복구됐고, 통지(TASK_COMPLETED/TASK_MODIFIED)는 export 성공(SUCCEEDED) 이후에만 발송되며 실패 시 재산출 성공 시점까지 통지를 지연·재개한다. 재-export 트리거는 authoring.control-notify.enabled 토글과 완전 독립적으로 항상 동작하며(이 토글은 통지 발송만 게이팅), 버전마다 전체 자기완결 + 전 버전 보존(retention 정리 로직 없음, 저장소 증폭 감수)한다.

## decision

### chosen_option

export 산출을 저작도구 범위로 포함 + 승인 후 사람이 콘텐츠를 고치는 수정경로도 재검수 승인 시점에 전량 재생성 확대(채택)

### justification

검수 승인 학습데이터 export를 저작도구 책임으로 포함하고(ADR-005 supersede, 기존 결정 유지), 승인 후 사람이 콘텐츠를 고치는 모든 수정 경로도 export를 새 버전(v{n+1})으로 전량 재생성한다 — 다만 그 시점은 수정 시점이 아니라 그 수정이 재검수에서 승인된 시점이다(2026-08-07 확정). 대상은 개수가 아니라 성질로 정한다 — 사람이 콘텐츠를 고치는 모든 경로가 대상이고 제외는 넷뿐이다: 외부 시계열 콜백 · 비식별 누락 신고 접수 · 운영자 정정 배치 · 이벤트 어노테이션 지연 승인(승인 행위 자체). 판정 기준은 사람이 산출물에 들어가는 내용을 바꿨는가 하나다. 대상 경로 예시 — 라벨 수정·트랙 편집·트랙 병합·버전 롤백·촬영환경(날씨/시간대/계절) 수정·프레임 설명 수정·개인정보 메타 수정(영상 축·프레임 축)·메타 수동 편집·이벤트 어노테이션 저장. 이 열거는 예시이며 전수 목록이 아니다. 통지는 export 성공(SUCCEEDED) 후에만 발송하고, 실패 시 통지를 보류하고 재산출 성공 시점에 재개한다(통지 유실이 아니라 지연). 산출 트리는 원본 영상 디렉터리 하위 단일 co-locate 루트를 유지한다. 재export 트리거는 authoring.control-notify.enabled 토글과 무관하게 항상 동작한다(토글은 통지 발송만 게이팅). 버전마다 전체 자기완결 + 전 버전 보존(retention 정리 로직 없음, 저장소 증폭 감수) — 델타만 두면 복구(rollback) 요구가 성립하지 않기 때문이다. [폐기] 이벤트 어노테이션(시계열 VQA/CoT)을 다루는 저장 경로를 동결본 재갱신 미배선을 이유로 이 확대에서 예외로 두던 결정은 지금은 그렇게 하지 않는다. 재승인 경로에서는 승인이 같은 트랜잭션 안에서 동결본을 먼저 갱신하고 재생성은 그 뒤의 통지 flush 시점에 일어나므로, 산출이 이미 새 동결본을 읽는다. 그 값은 산출 JSON 최상위로 그대로 나가고 콘텐츠 해시 축에도 들어가므로 바뀌면 산출물이 바뀐다 — 따라서 예외 없이 재검수·재생성 대상이다.

## consequences

### risks

- export 키 스키마 변경을 소비하는 관제 측 계약 정합 필요
- export 실패가 누적되면 통지가 계속 지연되어 관제가 최신 상태를 인지하지 못할 위험 — 실패한 산출을 재시도해 회수하는 로직의 신뢰성에 의존

### neutral

- 데이터마트 구축·검색·다운로드는 여전히 외부 책임(export 산출만 저작도구)

### negative

- ADR-005 상태 superseded 전이 필요
- 구 export 키 소비 쪽(image/video 잉여 키)은 키 변경으로 파손 가능
- 재생성 대상 수정경로 전량에서 export 파이프라인 관리 부담 증가
- retention 정리 로직 부재로 저장소 증폭 감수(운영 비용 증가)
- [폐기] 이벤트 어노테이션 수정을 동결본 재갱신 미배선을 이유로 확대에서 예외로 두던 항목 — 지금은 예외를 두지 않는다(재승인 트랜잭션이 동결본을 먼저 갱신한다)

### positive

- 구현 사실과 설계 정합(export 자동 산출 명시)
- 관제/데이터마트 export 폴더 픽업 경로 명확(OUTPUT_PATH_NM — 개명 전 EXPORT_PATH_NM)
- event_annotation 키 분리로 VLM VQA/CoT/caption과 COCO annotations 구조 정리
- 승인 후 수정 시에도 export 파일이 최신 라벨링 정보와 동기화되어 '데이터마트 연계 관리기능' 요구 충족
- 버전별 전체 자기완결 보존으로 복구(rollback) 요구 성립

### 승인 시점에만 재생성(구 정책, 폐기)

**cons**:

- 승인 후 수정분이 export 파일에 반영되지 않아 '데이터마트 연계 관리기능(라벨링 정보 동기화)' 요구 미충족
- 관제가 옛 버전 폴더를 계속 픽업하게 됨

**pros**:

- 재생성 트리거 지점이 단순(승인 1곳)

- **description**: export는 검수 승인 시점에만 산출하고, 승인 후 라벨·메타 수정은 다음 재승인 시점에 반영

### 승인 + 사람이 콘텐츠를 고치는 수정경로 확대 재생성(재검수 승인 시점, 현 채택)

**cons**:

- ADR-005 supersede 처리 필요
- 재생성 대상 수정경로 전량에서 export 파이프라인 관리 부담 증가
- retention 정리 로직 부재로 저장소 증폭 감수

**pros**:

- 구현 사실과 설계 정합
- 관제 픽업 경로(OUTPUT_PATH_NM) 명확
- 승인 후 수정도 데이터마트 동기화 요구 충족
- 버전별 전체 자기완결 보존으로 복구(rollback) 요구 성립

- **description**: 검수 승인 학습데이터 export(COCO 기반 프레임별 JSON) 자동 산출을 저작도구 책임으로 명시하고, 승인 후 사람이 콘텐츠를 고치는 모든 수정경로(예: 라벨수정/트랙편집/트랙병합/버전롤백/촬영환경수정/프레임설명수정/개인정보메타수정/메타수동편집/이벤트어노테이션저장)도 그 수정이 재검수에서 승인된 시점에 새 버전(v{n+1})으로 전량 재생성
