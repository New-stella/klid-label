# 외부 비식별 산출물의 재생 인덱스가 파일 끝에 있으면 완료 직후 무손실로 앞으로 옮긴다

## context

적재된 영상은 외부 비식별 솔루션에 위탁되며([[ADR-006]]), 솔루션은 결과 영상을 저작도구가 지정한 산출 디렉터리에 직접 쓴다. 저작도구는 진행 상태 폴링([[INT-005]])으로 완료를 감지한 뒤 그 산출물의 경로를 비식별 처리 이력에 기록하고, 마킹 화면 재생·프레임 추출·파생 영상 복사·관제 조회가 모두 그 경로를 읽는다.

그런데 솔루션이 내는 산출물은 재생 인덱스(moov)가 파일 끝에 있다. 브라우저는 영상을 부분 요청으로 나눠 읽는데, 인덱스가 끝에 있으면 재생을 시작하기 전에 파일 끝까지 가서 인덱스를 받아와야 하고 버퍼링·구간 이동마다 그 왕복이 반복된다. 그 결과 재생 시작이 늦고 재생 중 끊긴다. 파일을 통째로 읽는 데스크톱 재생기에서는 같은 파일이 끝까지 정상 재생되므로, 파일은 온전하고 인덱스 위치만의 문제다. 재생 인덱스의 위치는 파일 구조라 서버가 부분 응답으로 고칠 수 없다.

근본 해결은 솔루션이 인덱스를 앞에 둔 파일을 내는 것이나, 그 수정에는 기간이 불확실하고 그동안 마킹 작업이 막힌다.

## decision

### chosen_option

완료 직후 인덱스를 무손실로 앞으로 옮긴다

### justification

시점 — 비식별 완료가 확정돼 산출물 경로가 비식별 처리 이력에 기록된 뒤에 수행한다. 그 시점에는 솔루션이 더 이상 그 파일에 쓰지 않는다. 검수 완료 후 재비식별 회차도 같은 완료 경로를 타므로 똑같이 적용된다.

판정 — 산출물의 재생 인덱스가 파일 앞에 있으면 아무것도 하지 않는다(멱등). 벤더가 인덱스를 앞에 둔 파일을 내기 시작하면 이 단계는 자동으로 무동작이 되며, 걷어내지 않아도 무해하다. 재생 인덱스를 판정할 수 없는 파일은 건드리지 않는다.

변환 — 영상·음성 스트림을 다시 인코딩하지 않고 재생 인덱스만 앞으로 옮긴다. 재생 길이·해상도·코덱은 바뀌지 않는다.

교체 — 산출물의 경로와 파일명은 바꾸지 않는다. 비식별 처리 이력에 기록된 경로가 그대로 유효해야 하며, 관제는 그 경로로 산출물을 가져간다. 교체는 원자적이어야 하며, 재생 중인 세션은 교체 전 파일을 끝까지 읽을 수 있어야 한다.

작업용 임시 파일 — 결과 회수는 산출 디렉터리에 산출물이 하나뿐임을 전제하고, 둘 이상이면 어느 것이 결과인지 모호하다며 회수를 실패시킨다. 또 재위탁 시에는 산출 디렉터리를 비운 뒤 위탁한다. 따라서 작업용 임시 파일은 결과 회수가 산출물로 오인하지 않아야 하고, 재위탁과 경합해 새 산출물을 덮거나 지우지 않아야 한다. 비식별 제외 복사([[ADR-066]])가 같은 위치의 임시 파일을 쓰는 것과 달리하는 이유가 이것이다 — 제외 복사는 외부 위탁을 타지 않아 결과 회수를 거치지 않지만, 이 산출물은 결과 회수와 재위탁의 대상이다.

트랜잭션 — 대용량 파일 입출력은 데이터 트랜잭션 밖에서 수행하고, 결과 기록만 짧은 독립 트랜잭션으로 남긴다. 파일을 쓰는 동안 연결을 잡고 있지 않기 위해서다.

실패 — 재배치에 실패하면 원래 산출물을 그대로 두고 실패 사실을 기록한다. 비식별 완료 상태와 기록된 경로는 되돌리지 않는다(fail-open). 재배치 실패는 재생이 불편해질 뿐 데이터는 온전하기 때문이다. 반쯤 쓴 작업용 파일은 정리하고 원래 산출물은 훼손하지 않는다.

동시성 — 여러 영상의 비식별이 한꺼번에 완료돼도 재배치 작업이 몰리지 않도록 동시에 실행되는 수를 제한한다.

바꾸지 않는 것 — 비식별 완료 전이와 그 순서, 결과 회수의 경로 결정 규칙, 관제 조회에 노출되는 경로, 비식별 제외 복사 축은 그대로다. 제외 복사된 영상은 원본을 복사한 것이라 인덱스 위치가 원본과 같으며 이 단계의 대상이 아니다.

벤더와의 관계 — 솔루션이 인덱스를 앞에 둔 파일을 내도록 수정을 요청한다. 이 결정은 그 요청을 대체하지 않고, 수정 전까지의 산출물과 수정이 누락된 경우를 받친다.

## consequences

### risks

- 작업용 임시 파일이 산출 디렉터리에 남으면 다음 결과 회수가 산출물이 모호하다며 실패해 비식별 파이프라인이 막힌다
- 재배치 도중 재위탁이 들어오면 새 산출물과 경합할 수 있다 — 교체는 원자적이어야 하고 재위탁의 산출물을 덮거나 지우지 않아야 한다
- 벤더가 산출물의 컨테이너 형식을 바꾸면 재생 인덱스 판정의 전제가 달라진다 — 판정할 수 없는 파일은 건드리지 않는다
- 동시에 많은 영상이 완료되면 재배치가 누적돼 재생 가능 시점이 더 늦어질 수 있다

### neutral

- 재배치에 실패한 영상은 종전대로 재생이 불안정하지만 데이터는 온전하다
- 비식별 제외 복사된 영상은 이 단계의 대상이 아니다
- 이 결정 이전에 완료된 산출물은 소급해 재배치되지 않는다

### negative

- 변환 중 산출물 크기만큼 디스크를 일시로 더 쓴다
- 비식별 완료 뒤 재생 가능 시점이 재배치 시간만큼 늦어진다
- 비식별 단계에 재배치 실패라는 기록 축이 하나 더 생긴다

### positive

- 비식별 영상이 브라우저에서 재생 시작이 빨라지고 재생 중 끊기지 않는다
- 영상 내용이 바뀌지 않아 비식별 결과의 타당성이 유지된다
- 경로·파일명이 그대로라 관제 계약과 소비처가 무변경이다
- 파생 영상은 비식별 영상을 복사하므로 파생 영상 재생도 함께 좋아진다
- 벤더가 고치면 자동으로 무동작이 되어 따로 걷어낼 필요가 없다

## considered_options

### 완료 직후 인덱스를 무손실로 앞으로 옮긴다

**cons**:

- 변환 중 산출물 크기만큼 디스크를 일시로 더 쓴다
- 비식별 단계에 후처리 단계가 하나 늘어 완료 후 재생 가능 시점이 그만큼 늦어진다

**pros**:

- 파일을 한 번만 고치면 이후 모든 재생이 정상화된다
- 무손실이라 화질·길이·코덱이 그대로다
- 경로·파일명이 그대로라 관제 계약과 모든 소비처가 무변경이다
- 벤더가 고치면 인덱스 판정에서 건너뛰어 자동으로 무동작이 된다
- 파생 영상은 비식별 영상을 복사하므로 파생 영상 재생도 함께 좋아진다

- **description**: 비식별 완료가 확정돼 산출물 경로가 기록된 뒤, 인덱스가 파일 앞에 있지 않으면 영상·음성 스트림을 다시 인코딩하지 않고 인덱스만 앞으로 옮긴 파일로 교체한다.

### 벤더 수정만 기다린다

**cons**:

- 수정 기간이 불확실하고 그동안 마킹 작업이 막힌다
- 이미 생성된 산출물은 고쳐지지 않는다

**pros**:

- 저작도구 변경이 없다
- 외부 산출물을 가공하지 않는다

- **description**: 저작도구는 산출물을 건드리지 않고 솔루션이 인덱스를 앞에 두도록 요청한다.

### 재생 요청 시점에 재패키징한다

**cons**:

- 요청마다 파일 전체를 다시 써야 해 비현실적이다
- 부분 요청의 위치 계산이 원본 파일과 어긋난다

**pros**:

- 저장된 파일을 바꾸지 않는다

- **description**: 파일은 그대로 두고, 재생 요청이 올 때 인덱스를 앞에 둔 형태로 만들어 내보낸다.

### 재인코딩으로 변환한다

**cons**:

- 화질이 바뀌고 비식별 결과가 달라질 수 있다
- 시간과 CPU 부담이 크다

**pros**:

- 인덱스 위치 외의 호환성 문제도 함께 정리할 수 있다

- **description**: 산출물을 브라우저 재생에 맞는 설정으로 다시 인코딩한다.
