# 비식별 대상 판정에 출처유형 제외 축을 둔다 — 설정한 출처유형은 원본 복사로 비식별을 완료한다

## context

적재된 영상은 적재 직후 비식별을 파이프라인 선두 단계로 자동 시작하며, 위탁 대상을 개인정보 유형으로 가르던 게이팅은 두지 않고 전체 영상을 외부 비식별 솔루션에 위탁한다(ADR-006). 그런데 관제가 인입하는 영상 가운데 생성형 AI 로 만든 영상(출처유형 SRC_TYPE='GENERATED')은 실제 인물·번호판이 찍힌 영상이 아니어서 비식별할 대상이 없는데도 같은 위탁 비용과 대기 시간을 치른다.

비식별을 단순히 건너뛸 수는 없다. 비식별 뒤의 단계가 전부 「영상의 비식별여부가 'Y' 이고, 비식별 처리 이력의 최신 성공 행이 비식별 영상 파일 경로를 가리킨다」는 전제 위에 서 있다. 마킹 진입 조건, 마킹 화면의 영상 재생, 원본·비식별 두 벌 프레임 추출, 증강·해상도 파생이 부모의 비식별 영상을 찾는 조회, 관제 조회 뷰가 내보내는 비식별 영상 경로가 그렇다. 건너뛰기만 하면 마킹 진입이 막히고, 재생할 영상이 없고, 산출물의 비식별 벌이 빠지고, 관제가 영상 파일을 찾지 못한다. 또 비식별 영상을 읽을 수 있는 위치는 비식별 영상 쓰기 위치로 한정돼 있어, 원본 경로를 이력에 그대로 적는 방식은 그 위치 검사에서 거부된다.

따라서 어떤 영상을 비식별 대상에서 제외할지와, 제외한 영상이 뒤 단계의 전제를 어떻게 충족할지를 함께 정해야 한다.

## decision

### chosen_option

설정한 출처유형 영상은 외부 위탁 없이 원본을 비식별 영상 자리에 복사하고, 비식별 처리 이력에 요청종류 「비식별 제외」인 성공 행을 남겨 비식별을 완료한다

### justification

대상 판정 — 배포 설정 authoring.deidentify.excluded-src-types(환경변수 DEIDENTIFY_EXCLUDED_SRC_TYPES)에 쉼표로 구분해 적은 출처유형(LS_DATA_RAW.SRC_TYPE)과 일치하는 영상을 비식별 제외 대상으로 판정한다. 기본값은 GENERATED 다. 각 항목은 앞뒤 공백을 떼고 빈 항목은 무시하며, 출처유형과 정확히 일치할 때만 해당한다. 출처유형이 비어 있는 영상은 어떤 설정에서도 제외 대상이 아니다. 설정을 비우면 목록이 비어 모든 영상을 위탁한다 — 설정이 빠진 쪽이 안전측으로 떨어지게 한다.

판정 시점 — 적재(관제 인입 폴링 → 영상 원장 적재 → 적재 이벤트)는 그대로 두고, 판정은 적재 이벤트가 시작시키는 선두 비식별 단계가 그 영상을 처리하는 시점에 한 번 한다. 결과는 영상별 비식별 처리 이력에 고정되며, 설정을 바꿔도 이미 처리된 영상에는 소급하지 않는다. 제외 처리에는 외부 비식별 솔루션이 필요 없으므로 외부 연동이 꺼져 있어도 동작한다.

제외 처리 — 원본 영상 파일이 실재하는 일반 파일인지 확인한 뒤, 비식별 영상 쓰기 위치에 원본 파일명 그대로 일반 파일로 복사한다. 심볼릭 링크·하드 링크는 두지 않는다 — 링크는 원본을 가리켜 비식별 영상과 원본의 격리를 깨고, 재생 경로의 실경로 확인과도 어긋난다. 복사는 같은 위치의 임시 파일에 쓴 뒤 원자적으로 옮긴다. 복사를 마친 뒤 비식별 처리 이력(LS_DEIDENT_PROC_LOG)에 성공 행을 남기되 요청종류코드(REQ_KND_CD)를 EXCLUDED(비식별 제외)로, 비식별 영상 경로를 복사본 경로로 기록하고, 영상의 비식별여부를 'Y' 로, 배치 단계를 마킹 대기(MARKING_READY)로 전이한다. 외부 위탁이 동기로 완료된 경우와 같은 흐름이다. 요청종류코드 값역에 값 하나가 더해질 뿐 신규 상태값·신규 컬럼은 없다.

복사 실패 — 원본 부재·경로 위반·입출력 오류로 복사하지 못하면 영상의 비식별여부를 'F' 로 두고, 비식별 처리 이력에 요청종류 EXCLUDED 인 실패 행을 남기며, 마킹 대기로 전이하지 않는다. 반쯤 쓴 임시 파일은 정리하고 원본은 삭제하거나 수정하지 않는다.

뒤 단계 — 마킹 진입 조건, 마킹 화면 영상 재생, 원본과 비식별 두 벌 프레임 추출, 증강과 해상도 파생의 부모 비식별 영상 조회, 관제 조회 뷰의 비식별 영상 경로는 바뀌지 않는다. 제외 영상도 비식별여부 'Y' 와 이력의 최신 성공 행 경로라는 같은 전제를 충족하기 때문이다. 제외 행은 외부 솔루션 진행 상태를 갖지 않으므로 외부 진행 폴링 대상과 수락 대기 회수 대상에 오르지 않는다.

바꾸지 않는 것 — 개인정보유형코드(PRVC_TYPE_CD)는 바꾸지 않는다. 검수 완료 영상의 재비식별은 이 제외 축을 타지 않고 항상 외부 솔루션에 위탁한다. 제외 처리된 영상에 대한 비식별 누락 신고 접수도 종전과 같다. 출처유형이 잘못 인입된 영상(실제 인물이 찍힌 영상이 제외 출처유형으로 인입된 경우)의 회수 지점은 검수다 — 검수자가 검수 중 비식별이 필요하다고 판단하면 기존과 같이 비식별 누락 신고 → 외부 비식별 솔루션으로 재비식별 → 신고 해소로 회수한다. 승인 이력이 있는 영상은 신고를 받지 않는 기존 정책이 그대로라 승인 이후와 그 파생본은 이 경로 밖이다. 검수 완료 영상의 재비식별은 비식별 여부가 'Y' 인 영상을 받지 않고 제외 처리에 성공한 영상은 모두 'Y' 이므로, 제외 영상의 회수 경로가 아니다.

설정의 자리 — 이 설정은 배포 설정 파일에만 두고 관리 화면의 시스템 설정으로 두지 않는다. 비식별을 우회하는 스위치를 운영 중 재기동 없이 켤 수 없게 하기 위해서다. 기동 시 허용값 검사나 기동 차단은 두지 않으며, 적용 중인 제외 목록을 기동 로그 한 줄로 남긴다. 원천 CCTV 출처유형(ORIGINAL·RELAY)을 넣지 말라는 경고는 설치 설정 문서에 둔다.

종전 결정과의 관계 — 전체 영상을 비식별하고 위탁 대상 게이팅을 두지 않는다는 종전 결정(ADR-006)은 유효하다. 이 결정은 그것을 대체하지 않고 출처유형 제외라는 예외를 더한다. 개인정보 유형으로 위탁 대상을 가르던 게이팅을 되살리는 것이 아니다 — 판정 축은 영상이 어디서 왔는가이며, 그 영상에 비식별할 실제 인물이 애초에 없는지를 가른다. 외부 산출물 이관이 적재 직후 비식별 선두 단계를 자동으로 시작시키지 않는 예외(ADR-048)와는 별개 축이다 — 그 경로는 비식별 단계를 타지 않고, 이 결정의 제외 영상은 비식별 단계를 타되 위탁 대신 복사로 완료한다.

## consequences

### risks

- 관제가 실제 CCTV 영상을 생성형 출처유형으로 잘못 인입하면 마스킹 없는 영상이 마킹 화면·학습데이터 산출물·관제로 흐른다. 출처유형의 정확성은 관제 책임이며, 회수는 검수 단계다 — 검수자가 검수 중 비식별이 필요하다고 판단하면 기존과 같이 비식별 누락 신고 → 외부 재비식별 → 신고 해소로 회수한다. 승인 이력이 있는 영상은 신고를 받지 않는 기존 정책이 그대로라 승인 이후와 그 파생본은 이 경로 밖이다
- 설정에 원천 출처유형을 잘못 넣으면 그 출처유형의 영상 전체가 비식별 없이 흐른다. 기동 검사를 두지 않기로 했으므로 방어는 설치 설정 문서의 경고와 기동 로그뿐이다
- 관제가 비식별여부 'Y' 를 비식별 완료로만 읽고 있으면 제외 영상을 마스킹된 영상으로 오인한다. 뜻이 넓어진 사실을 관제에 먼저 통지해야 한다

### neutral

- 설정 변경은 소급하지 않는다. 이미 제외 처리된 영상은 설정을 비워도 제외 이력을 그대로 가진다
- 개인정보유형코드는 바뀌지 않아, 그 값을 읽는 판정과 산출물의 개인정보 필드는 영향을 받지 않는다
- 검수 완료 영상의 재비식별은 이 결정과 무관하게 언제나 외부 솔루션에 위탁된다

### negative

- 제외 영상 1건마다 원본 크기만큼 저장 공간을 더 쓴다
- 관제 조회 뷰의 비식별여부 'Y' 의 뜻이 「비식별 완료 또는 비식별 제외」로 넓어진다. 관제는 출처유형이나 생성형AI여부로 둘을 가를 수 있으며, 이 변화는 관제에 통지해야 한다
- 비식별 단계에 복사 실패라는 실패 축이 하나 더 생긴다

### positive

- 실제 인물·번호판이 없는 출처유형의 영상이 외부 위탁 비용과 대기 시간 없이 곧바로 마킹 대기로 넘어간다
- 뒤 단계와 관제 조회 뷰의 스키마를 고치지 않는다 — 신규 상태값·신규 컬럼이 없다
- 비식별 영상 읽기 허용 위치를 넓히지 않아 비식별 영상 자리로 원본이 서빙될 수 있는 경로가 새로 열리지 않는다
- 요청종류 「비식별 제외」로 제외 처리된 영상을 비식별 처리 이력에서 가려 낼 수 있다
- 설정을 비우고 재기동하면 그 뒤 처리분은 전부 외부 위탁으로 돌아간다

## considered_options

### 제외 출처유형은 원본을 비식별 영상 자리에 복사하고 성공 이력을 남긴다

**cons**:

- 제외 영상 1건마다 원본 크기만큼 저장 공간을 더 쓴다
- 비식별여부 'Y' 의 뜻이 「비식별 완료 또는 비식별 제외」로 넓어진다

**pros**:

- 뒤 단계가 기대는 비식별여부 값과 비식별 영상 경로가 그대로 충족돼 소비처를 고치지 않는다
- 비식별 영상 읽기 허용 위치를 넓히지 않아 원본 노출 방어가 약해지지 않는다
- 외부 위탁이 동기로 완료된 경우와 같은 흐름이라 마킹 대기 전이와 예약 마킹 적용이 그대로 동작한다
- 이력의 요청종류로 제외 처리된 영상을 나중에 가려 낼 수 있다

- **description**: 배포 설정에 든 출처유형 영상은 외부 솔루션에 위탁하지 않고, 원본 영상을 비식별 영상 쓰기 위치에 원본 파일명 그대로 일반 파일로 복사한 뒤 비식별 처리 이력에 요청종류 「비식별 제외」인 성공 행을 남기고 영상을 비식별 완료로 전이한다.

### 원본 경로를 비식별 이력에 적기만 한다

**cons**:

- 비식별 영상 읽기 허용 위치에 원본 저장소를 넣어야 해, 모든 영상에서 비식별 영상 자리로 원본이 서빙될 수 있는 길이 열린다
- 원본 노출을 막는 위치 검사가 약해진다

**pros**:

- 저장 공간을 더 쓰지 않는다
- 복사 실패라는 실패 축이 생기지 않는다

- **description**: 복사하지 않고 비식별 처리 이력의 비식별 영상 경로 자리에 원본 경로를 적는다.

### 비식별여부에 「해당 없음」 값을 신설한다

**cons**:

- 그 값을 판정에 쓰는 소비처가 많아 모두 고쳐야 하고, 하나라도 빠지면 영상이 조용히 막히거나 원본이 샌다
- 관제 조회 뷰가 내보내는 비식별여부의 값역이 바뀐다

**pros**:

- 비식별을 하지 않았다는 사실을 값이 그대로 말한다
- 저장 공간을 더 쓰지 않는다

- **description**: 제외 영상의 비식별여부를 새 값으로 두고, 뒤 단계가 그 값을 비식별 완료와 같이 취급하게 한다.

### 생성형 영상만 고정으로 제외한다

**cons**:

- 대상 출처유형을 배포마다 바꿀 수 없다
- 대상을 넓히거나 끄려면 배포물을 다시 만들어야 한다

**pros**:

- 설정을 잘못 넣어 원천 영상이 제외되는 사고가 생기지 않는다

- **description**: 제외 대상을 설정 없이 출처유형 GENERATED 하나로 못박는다.
