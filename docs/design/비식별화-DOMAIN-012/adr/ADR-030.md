# 배치 스텝 트랜잭션 경계 규약 — 실행 진입점만 + self-invocation 유지 + 정적 가드

## context

배치 스텝의 @Transactional이 내부 처리 메서드 위임 과정에서 self-invocation으로 프록시가 우회돼 무-트랜잭션 실행되던 구조적 결함이 실기동에서 실측되었다(비식별 프레임 2벌 추출 전면 스킵 등 파이프라인 불통).

## decision

### chosen_option

실행 진입점에만 경계 선언 + self-invocation 유지 + 정적 가드테스트(채택)

### justification

배치 스텝의 @Transactional 경계는 반드시 배치 스텝 인터페이스의 실행 진입점에만 선언(REQUIRES_NEW, controlTransactionManager)하고, 내부 처리 메서드로의 위임은 자기호출로 유지한다(어드바이스 미적용, 동일 트랜잭션 참여). 정적 가드테스트가 전 배치 스텝 구현체의 실행 진입점 경계를 강제한다(신규 스텝 추가 시 동일 결함 재발 방지의 유일한 방어선). 비식별 프레임 판정축도 읽을 수 있는 비식별 영상 루트 목록(구위치∪colocate)을 돌려주는 단일 판정 지점으로 통일한다. 비식별 스텝은 예외적으로 내부 처리 메서드가 자기 프록시 경유 REQUIRES_NEW로 경계를 얻는다(병행호출시 중첩 없음).

## consequences

### risks

- 배치 비동기 실행기의 CallerRunsPolicy 잔여 위험 — 큐 포화 시 AFTER_COMMIT 콜백스레드에서 동기실행되며 트랜잭션 완료 후 리소스 정리 이전이라 원 트랜잭션 리소스가 아직 바인딩된 상태일 수 있음(구조 변경 필요, 별도 이슈로 분리)

### negative

- 비식별 스텝 예외 케이스로 인해 규약이 완전히 균일하지 않음(예외 인지 필요)

### positive

- 배치 파이프라인의 무-트랜잭션 실행 구조적 결함 해소(비식별 프레임 2벌 추출 등 정상화)
- 정적 가드테스트로 신규 스텝 추가 시 동일 결함 재발 방지

## considered_options

### 내부 처리 메서드에 @Transactional 개별 부여(구, 결함)

**cons**:

- 실행 진입점에서 내부 메서드를 self-invocation으로 호출하면 프록시가 우회돼 무-트랜잭션 실행됨(구조적 결함)

**pros**:

- 메서드 단위로 경계를 좋게 가져갈 수 있어 보임

- **description**: 내부 처리 메서드마다 @Transactional을 부여

### 실행 진입점에만 경계 선언 + self-invocation 유지 + 정적 가드테스트(채택)

**cons**:

- 비식별 스텝은 예외적으로 내부 처리 메서드가 자기 프록시 경유 REQUIRES_NEW로 경계를 얻는 특수 케이스 존재

**pros**:

- 프록시 우회 문제 자체가 발생하지 않는 지점(실행 진입점)에서만 경계 선언
- 정적 가드테스트로 신규 스텝 추가 시 동일 결함 재발 차단

- **description**: @Transactional 경계는 반드시 배치 스텝 인터페이스의 실행 진입점에만 선언(REQUIRES_NEW, controlTransactionManager)하고, 내부 처리 메서드로의 위임은 자기호출로 유지(동일 트랜잭션 참여). 정적 가드테스트가 전 배치 스텝 구현체의 실행 진입점 경계를 강제
