## description

비식별 누락 신고·수동 해소 흐름. 작업자가 개인정보 노출을 발견하면 마킹 단계(rawSn 기준, POST /v1/videos/{rawSn}/deident-report) 또는 라벨링 단계(srcSn 기준, POST /v1/labels/{srcSn}/deident-report)에서 신고하고, DeidentReportService 가 작업락 선점 + DE_IDNTF_YN='F' 를 수행한다. ★라벨은 삭제하지 않고 스냅샷도 남기지 않으며 개인정보 3필드(익명·가명·PII 포함여부)도 보존한다 — 신고는 "비식별이 잘못됐다"는 신호일 뿐 사람이 만든 작업 결과를 폐기할 근거가 아니기 때문이다(구 '영상 전체 라벨 스냅샷 후 일괄 삭제'·'개인정보 3필드 리셋' 정책은 각각 2026-07-27·2026-08-04 사용자 확정으로 폐기). 신고 구간의 PII 노출은 삭제가 아니라 게이트가 막는다 — 라벨 조회·저장, 프레임 이미지, 버전 diff·롤백, 개인정보 메타 PUT 은 412, 영상 스트리밍은 404 다(스트리밍만 404 인 것은 그 엔드포인트의 기존 규약이며 응답 코드가 상태 오라클이 되지 않게 하기 위함). 라벨 저장 차단은 412 이며 구 '작업락 409' 는 폐기됐다 — 작업락은 6h 만료 후 회수되는데 'F' 는 resolve 까지 남아 조회 412 ↔ 저장 200 비대칭이 열렸기 때문이다. 신고에는 단계(DCLR_STP_CD, V171)가 있고 해소 후 재개 지점이 그 단계로 갈린다 — MARKING 은 배치 단계가 MARKING_READY 일 때만 접수하고(그 상태는 선두 비식별 성공 직후·마킹 이전이라 프레임 행도 라벨도 아직 없다) 해소 시 배치 단계를 MARKING_READY 로 되감고 활성 마킹을 SKIPPED 로 종결해 재마킹 409(V142 부분 유니크)를 푸는 반면, LABELING 은 배치 단계와 무관하게 접수되지만 검수가 승인된 영상은 접수하지 않으며(412 — 승인된 학습데이터는 되돌리지 않는다. 구 서술 '검수 완료 영상 신고가 정상 동선' 은 2026-08-10 폐기) 프레임 이미지만 다시 뽑아 라벨 좌표를 보존한 채 이어간다(DeidentFrameAttacher.attachDeidentFrames(refreshExisting=true) — 기존 SRC_SN 을 dirty-update 해 라벨 FK 가 끊기지 않으며, FfmpegFrameExtractor 를 쓰면 새 행을 INSERT 해 라벨이 고아가 된다). 마킹 단계 거부는 412 한 종류·문구 한 종류로 통일한다(배치 상태를 구분해 알리면 응답이 영상 처리 단계 오라클이 된다, CWE-209). 파생영상(ORGNL_RAW_SN non-null)은 신고를 아예 접수하지 않고(412) 원본으로 유도하지도 부모 rawSn 을 내려주지도 않으며(원본을 신고해도 파생은 달라지지 않고 파생에 배정된 WORKER 는 원본 접근 권한이 없다) 신고행을 만들지 않아 REVIEWER 알림도 보내지 않는다 — 대신 사유를 정제해 WARN 감사 로그로 남긴다. 신고 접수는 부모 RAW 를 SELECT … FOR UPDATE 로 잠가 동시 증강 콜백과의 PII TOCTOU(CWE-359)를 차단하고, 승인 영상은 접수 자체가 막히므로 신고 시점의 TASK_MODIFIED(META_UPDATED) 발행 분기는 도달 불가가 됐다(2026-08-10 — 구 LABEL_DELETED 는 그보다 앞서 라벨 삭제 정책과 함께 폐기됐다). 승인 경로에도 신고 중 차단이 있어 '승인됨 + 신고 열림' 조합은 앞으로 생기지 않으며, 해소 시 APPROVED 분기는 그 이전에 접수된 건에만 해당한다. 해소(resolve)는 외부 솔루션으로 수동 비식별화를 마친 뒤 POST /v1/deident-reports/{rprtSn}/resolve(WORKER 본인 배정 / REVIEWER 전체)로 호출하며, 비식별 산출물 실재 검증(fail-closed)을 통과한 뒤 OPEN→RESOLVED 조건부 UPDATE 로 원자 클레임하고(2노드 Active-Active 중복 실행 차단, CWE-362) 영향행수 1 을 받은 성공자만 작업락 해제·'F'→'Y' 복원·재개 이벤트를 수행한다. 이벤트는 3종이다 — DeidentGateReopenedEvent(항상, 보류됐던 VLM 위탁 재개) / 수정 통지 이벤트(APPROVED 한정 — 해소 시점에 직접 재산출하지 않고 재검토 표시(REVLT_YN)를 세우며, export 강제 재산출과 관제 재통지는 검수자가 재승인한 시점에 일어난다. 같은 자리를 가리키던 EVT-008 은 발행처가 없는 휴면 확장점이다) / DeidentStageResumeEvent(단계별 재개, AFTER_COMMIT 소비 — 단계 미상 NULL 이면 발행하지 않는다). 배치 단계(DATA_STTS_CD)는 resolve 가 직접 되감지 않아 상태 역행을 만들지 않으며(CWE-664), 스트림 메타 캐시는 신고·해소 양쪽 커밋 후 그 영상 하나만 무효화한다(파생 팬아웃 없음). 자동 재비식별 큐는 폐기됐고 별도 라벨 복원 API 도 없다 — 게이트가 열리면 보존된 라벨을 그대로 쓴다.
