## description

비식별 처리 위탁·수신 흐름. ★대상 게이팅은 폐지됐다 — PRVC_TYPE_CD(PRVC/PSDO/ANONY) 구분 없이 모든 영상을 비식별하며, 비식별은 파이프라인 <선두> 단계로 적재 직후 자동 트리거된다(VideoIngestedEvent → IngestDeidentifyBridge(AFTER_COMMIT) → AsyncDeidentifyRunner(@Async) → DeidentifyStep). ★출처유형 제외 분기(ADR-066 — ADR-006 을 대체하지 않고 예외를 더한다. 개인정보 유형 게이팅을 되살리는 것이 아니다) — 선두 비식별 단계가 영상을 처리하는 시점에 한 번, 영상의 출처유형(LS_DATA_RAW.SRC_TYPE)이 배포 설정 authoring.deidentify.excluded-src-types(기본값 GENERATED)의 제외 목록과 정확히 일치하면 외부 솔루션에 위탁하지 않는다. 원본 영상을 비식별 영상 쓰기 위치에 원본 파일명 그대로 일반 파일로 복사하고(링크를 두지 않는다) LS_DEIDENT_PROC_LOG 에 REQ_KND_CD=EXCLUDED 인 성공 행(PROC_STTS_CD=SUCCEEDED, DE_IDNTF_FILE_PATH_NM=복사본 경로)을 남긴 뒤 DE_IDNTF_YN='Y'·MARKING_READY 로 전이한다 — 외부 솔루션으로 가는 메시지가 없다. 복사에 실패하면 DE_IDNTF_YN='F' 와 REQ_KND_CD=EXCLUDED 인 FAILED 행을 남기고 MARKING_READY 로 전이하지 않으며 원본은 삭제하거나 수정하지 않는다. 제외 행은 외부 진행 상태(POLL_STTS_CD)를 갖지 않으므로 주기 폴링·ACK 대기 유예 만료 회수의 대상이 아니다. 판정 결과는 영상별 이력에 고정돼 설정 변경을 소급하지 않고, 설정이 비면 모든 영상을 위탁한다. 검수 완료 영상의 재비식별은 이 제외 축을 타지 않고 항상 외부 솔루션에 위탁한다. 다만 제외 처리에 성공한 영상은 DE_IDNTF_YN='Y' 라 그 진입점이 이미 비식별됨으로 받지 않으므로 이것은 제외 영상의 회수 경로가 아니다 — 제외 출처유형으로 잘못 인입된 영상(실제 인물이 찍힘)의 회수 지점은 검수이며, 검수 중 비식별 누락 신고 → 외부 솔루션 수동 재비식별 → 신고 해소로 처리하고 제외 판정은 다시 하지 않는다(승인 이력이 있는 영상은 신고 접수 자체가 거부되어 이 경로 밖이다). 이 복사는 자체 복사(mock) 모드 토글이 아니라 출처유형 판정으로 갈리는 별개 분기다. 아래 서술은 제외 목록에 들지 않은 영상에 적용된다. ★실행 분기는 <외부 위탁>과 <설정 오류 예외> 둘뿐이다 — 경로는 외부 위탁으로 단일화됐고 레거시 동기 연동은 제거됐으며, <자체 복사(mock) 산출 경로도 폐지됐다>. 그 모드에는 자체 산출 경로가 없다 — 남은 자리는 판정뿐이다. 막을 산출 지점이 실재하지 않으므로, 남은 토글은 위탁 요청층에서 거부한다. 그 형상에서 비식별은 전건 실패하며 그 사실이 기동 기록과 상태로 드러난다. 활성화 실태는 어느 프로파일에도 설정돼 있지 않다(꺼짐). ⚠ 자체 복사 산출 경로가 다시 생기면 이 배선으로는 막히지 않는다 — 그런 경로를 다시 만든다면 산출 지점에 별도 차단을 함께 넣어야 한다. 위탁 대상이 주입되지 않은 형상도 같은 자리에서 거부한다(폴백 없음). ★KPST 제출은 논블로킹이다 — LS_DEIDENT_PROC_LOG 원장을 POLL_STTS_CD=WAITING + prjId null 로 <선커밋> 한 뒤 createProject 를 비동기 디스패치하므로, 스텝이 확정적으로 말하는 사실은 “제출을 개시했다” 뿐이다(VLM 위탁과 대칭). ACK 수신 시 prjId 기록은 publishOn 이 아니라 명시적 디스패치(SubmitSignalDispatch)로 전용 풀에서만 실행한다 — publishOn 은 풀 포화 시 거부가 시그널을 나른 reactor-netty 이벤트 루프로 흘러 JPA 쓰기를 이벤트 루프에서 실행시킨다. 아무 신호도 오지 않아도(노드 사망 등) 선커밋된 WAITING 원장 행은 DB 에 남으므로, 폴링 잡이 ACK 대기 유예 만료로 그 행을 회수한다(KPST_ACK_MISSING) — <별도 미결 스위퍼를 신설하지 않는다>. ★그 회수는 재위탁이 아니다 — 수락 응답이 없어 프로젝트 식별자 자체가 없으므로 진행 조회를 부르지 않고, 「우리가 수락 응답을 관측하지 못했다」는 뜻의 실패 사유(KPST_ACK_MISSING)를 남겨 원장을 마감한다. <그 종결은 영상의 비식별 여부도 'F' 로 내린다> — 제출 확정 실패(KPST_SUBMIT_FAILED)와 같은 종결 경로를 타기 때문이다. ⚠ 구 서술 폐기 — <원장만 마감하고 영상의 비식별 상태는 그대로 둔다>는 사실과 다르다. ★두 축을 가르는 것은 「영상 상태」가 아니라 <운영 조치>다 — 「외부에서 실패했다」가 아니라 「우리가 관측하지 못했다」는 뜻이므로 외부에는 프로젝트가 실제로 생성돼 있을 수 있다(노드 사망 등). 사람이 외부 상태를 확인해야 하며, 그것이 이 회수를 별도 경로로 가르는 이유다. 영상 상태를 그대로 두는 종결은 다른 쪽이다 — 호출자 트랜잭션 롤백으로 인한 취소 종결(KPST_SUBMIT_CANCELED)은 외부로 나간 것이 없으므로 영상 상태를 내리지 않는다(나가지도 않은 요청이 그 영상을 신고 게이트에 밀어 넣지 않도록 한다). 유예 값은 설정값이다. 4노드 Active-Active 에서 같은 후보를 두 번 폴링/재위탁하지 않도록 처리 전 조건부 UPDATE(tryClaimPoll)로 원자 클레임한다. 수신은 <주기 폴링>이다 — KpstDeidentPollJob 이 retrieveProgress 로 procState 를 판정해 완료 시 결과를 다운로드/확인하고 DE_IDNTF_YN='Y' + procLog SUCCEEDED + DE_IDNTF_FILE_PATH_NM 을 적재한 뒤 DATA_STTS_CD 를 MARKING_READY 로 전이시킨다. <별도 결과 콜백은 없다> — 구 수신 경로 POST /v1/deidentify/result(HMAC 웹훅)은 폐기됐다. 외부가 돌려준 터미널 실패·불완전 산출물이거나 폴링 경과 만료·시도 상한을 초과한 때에는 DE_IDNTF_YN='F' 로 마킹하고 원본은 절대 삭제하지 않으며, <자동 재비식별 큐는 없다> — 작업자/검수자가 외부 솔루션으로 수동 비식별한 뒤 resolve 로 해소한다(UC-016). ⚠ 「타임아웃」이라는 낱말이 두 축에 걸쳐 있다 — 진행 조회를 언제까지 이어갈지 정하는 <폴링 경과 만료>(이 문장의 축)와 수락 응답을 언제까지 기다릴지 정하는 <ACK 대기 유예 만료>(앞 문장의 미결 회수 축)는 서로 다른 것이다. 둘 다 영상을 'F' 로 내리므로 갈리는 것은 결과가 아니라 남는 운영 조치다 — 하나로 읽으면 미결 건에 필요한 외부 상태 확인이 통째로 빠진다. ⚠ 비식별본 파일명은 고정이 아니다 — 우리가 지정하는 것은 디렉터리(export_path)까지이고 파일명은 외부 솔루션이 정한다(KPST={원본stem}-mask{ext}). 따라서 모든 소비자는 경로를 조합·추측하지 말고 LS_DEIDENT_PROC_LOG.DE_IDNTF_FILE_PATH_NM 적재값을 읽어야 한다. 재비식별 진입점은 POST /v1/videos/{rawSn}/redeident(ApprovedRedeidentController) 하나뿐이다 — 아무 일도 하지 않던 구 재처리 placeholder 엔드포인트(POST /v1/deident/{videoId}/reprocess, DeidentController)는 두지 않는다.
