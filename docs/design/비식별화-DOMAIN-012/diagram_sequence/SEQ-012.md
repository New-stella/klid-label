## description

비식별 처리 위탁·수신 흐름. ★대상 게이팅은 폐지됐다 — PRVC_TYPE_CD(PRVC/PSDO/ANONY) 구분 없이 모든 영상을 비식별하며, 비식별은 파이프라인 <선두> 단계로 적재 직후 자동 트리거된다(VideoIngestedEvent → IngestDeidentifyBridge(AFTER_COMMIT) → AsyncDeidentifyRunner(@Async) → DeidentifyStep). ★실행 분기는 <외부 위탁>과 <설정 오류 예외> 둘뿐이다 — 경로는 외부 위탁으로 단일화됐고 레거시 동기 연동은 제거됐으며, <자체 복사(mock) 산출 경로도 폐지됐다>. 그 모드에는 자체 산출 경로가 없다 — 남은 자리는 판정뿐이다. 막을 산출 지점이 실재하지 않으므로, 남은 토글은 위탁 요청층에서 거부한다. 그 형상에서 비식별은 전건 실패하며 그 사실이 기동 기록과 상태로 드러난다. 활성화 실태는 어느 프로파일에도 설정돼 있지 않다(꺼짐). ⚠ 자체 복사 산출 경로가 다시 생기면 이 배선으로는 막히지 않는다 — 그런 경로를 다시 만든다면 산출 지점에 별도 차단을 함께 넣어야 한다. 위탁 대상이 주입되지 않은 형상도 같은 자리에서 거부한다(폴백 없음). ★KPST 제출은 논블로킹이다 — LS_DEIDENT_PROC_LOG 원장을 POLL_STTS_CD=WAITING + prjId null 로 <선커밋> 한 뒤 createProject 를 비동기 디스패치하므로, 스텝이 확정적으로 말하는 사실은 “제출을 개시했다” 뿐이다(VLM 위탁과 대칭). ACK 수신 시 prjId 기록은 publishOn 이 아니라 명시적 디스패치(SubmitSignalDispatch)로 전용 풀에서만 실행한다 — publishOn 은 풀 포화 시 거부가 시그널을 나른 reactor-netty 이벤트 루프로 흘러 JPA 쓰기를 이벤트 루프에서 실행시킨다. 아무 신호도 오지 않아도(노드 사망 등) 선커밋된 WAITING 원장 행은 DB 에 남으므로, 폴링 잡이 ACK 대기 유예 만료로 그 행을 회수한다(KPST_ACK_MISSING) — <별도 미결 스위퍼를 신설하지 않는다>. 2노드 Active-Active 에서 같은 후보를 두 번 폴링/재위탁하지 않도록 처리 전 조건부 UPDATE(tryClaimPoll)로 원자 클레임한다. 수신은 <주기 폴링>이다 — KpstDeidentPollJob 이 retrieveProgress 로 procState 를 판정해 완료 시 결과를 다운로드/확인하고 DE_IDNTF_YN='Y' + procLog SUCCEEDED + DE_IDNTF_FILE_PATH_NM 을 적재한 뒤 DATA_STTS_CD 를 MARKING_READY 로 전이시킨다. <별도 결과 콜백은 없다> — 구 수신 경로 POST /v1/deidentify/result(HMAC 웹훅)은 폐기됐다. 실패나 폴링 상한·타임아웃 초과 시 DE_IDNTF_YN='F' 로 마킹하고 원본은 절대 삭제하지 않으며, <자동 재비식별 큐는 없다> — 작업자/검수자가 외부 솔루션으로 수동 비식별한 뒤 resolve 로 해소한다(UC-016). ⚠ 비식별본 파일명은 고정이 아니다 — 우리가 지정하는 것은 디렉터리(export_path)까지이고 파일명은 외부 솔루션이 정한다(KPST={원본stem}-mask{ext}). 따라서 모든 소비자는 경로를 조합·추측하지 말고 LS_DEIDENT_PROC_LOG.DE_IDNTF_FILE_PATH_NM 적재값을 읽어야 한다. 재비식별 진입점은 POST /v1/videos/{rawSn}/redeident(ApprovedRedeidentController) 하나뿐이다 — 아무 일도 하지 않던 구 재처리 placeholder 엔드포인트(POST /v1/deident/{videoId}/reprocess, DeidentController)는 두지 않는다.
