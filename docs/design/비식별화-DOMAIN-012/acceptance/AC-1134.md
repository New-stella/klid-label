# UC-011 선두 비식별 실패 재시작 거부 — 파생 400·승인 이력/열린 신고/진행 중 위탁 409·동시 요청 1건만 수락·영상 없음 404·작업자 403·재수행 없음 (negative)

## notes

축 판정 — 이 기준은 예외 경로(negative)다. 출처 UC-011 의 대안 흐름 「선두 비식별 실패 후 배치 재시작」 2·3 단계와 「비식별 누락 신고 구간」의 재시작 409 단계에 대응한다.
★'F' 이중 의미 — 영상 비식별 여부 'F' 는 파이프라인 실패와 비식별 누락 신고 두 뜻으로 쓰인다. 열린 신고 사례를 따로 두지 않으면 신고 표식 영상을 파이프라인 실패로 오인해 다시 위탁하는 구현이 통과한다.
★시험을 짤 때 빠지기 쉬운 자리 — ①승인 이력 사례는 재제출 등으로 현재 상태가 승인이 아닌 영상으로도 돌린다(현재 상태로 판정하는 구현이 통과하지 않게) ②동시 요청 사례는 판정을 모두 통과한 두 요청을 실제로 겹쳐 수락이 정확히 1건인지 본다 ③거부 사례마다 선두 비식별 단계 호출 수가 0 인지 본다(응답 코드만 보면 거부 뒤에도 단계를 태우는 구현이 통과한다).

## priority

high

## scenario

### then

- 파생영상이면 400 으로 거부된다
- 승인 이력이 있으면 현재 검수 상태와 무관하게 409 로 거부된다
- 열린 비식별 누락 신고가 있으면 409 로 거부된다
- 진행 중인 비식별 위탁이 있으면 409 로 거부된다
- 409 응답의 메시지는 사유마다 서로 다른 한국어 문구다
- 대상 영상이 없으면 404 로 거부된다
- 작업자가 요청하면 403 으로 거부된다
- 거부된 요청에서는 선두 비식별 단계가 한 번도 수행되지 않고 외부 솔루션 호출도 없으며, 영상 비식별 여부·배치 단계가 요청 전과 같고 이 요청이 만든 작업 잠금이 남지 않는다
- 같은 영상에 대한 동시 요청 두 건 중 정확히 1건만 수락되고 나머지 1건은 409 이며, 선두 비식별 단계는 1회만 수행된다
- 일괄 재시작에서는 거부 사유가 그 건의 실패 결과와 사유로 실리고 요청 전체는 200 이며, 같은 요청의 다른 건은 영향을 받지 않는다

### when

- 건별 재시작 또는 그 영상을 포함한 일괄 재시작을 요청한다
- 두 요청이 같은 영상에 대해 동시에 들어온다(서로 다른 노드 포함)

### given

- 대상 영상은 영상 비식별 여부 'F' · 배치 단계 PENDING 이다
- 그 영상이 파생영상이거나, 승인 이력이 있거나, 열린 비식별 누락 신고가 있거나, 진행 중인 비식별 위탁이 있거나, 같은 영상에 대한 재시작이 이미 수락돼 있다
- 또는 대상 영상이 존재하지 않거나, 요청자가 작업자다

## statement

선두 비식별 실패 영상(영상 비식별 여부 'F' 이고 배치 단계가 PENDING 인 영상)의 배치 재시작 [[API-167]] · [[API-199]] 은 다음 경우 거부하며, 거부된 요청은 선두 비식별 단계를 다시 수행하지 않고 영상 단위 작업 잠금도 남기지 않는다.

파생영상(원본 영상을 참조하는 영상)이면 400 이다. 승인 이력이 있으면 409 이며, 판정은 현재 검수 상태가 아니라 이력으로 한다. 열린 비식별 누락 신고가 있으면 409 다 — 그 'F' 는 파이프라인 실패가 아니라 신고 표식이고, 해소는 외부 솔루션 수동 재비식별 뒤 신고 해소 경로로 한다. 진행 중인 비식별 위탁이 있으면 409 다. 같은 영상에 대한 요청이 이미 수락됐으면 409 이며, 여러 노드에 동시에 요청이 와도 정확히 1건만 수락한다. 409 는 사유마다 서로 다른 한국어 메시지를 싣는다.

대상 영상이 없으면 404 다. 작업자는 요청할 수 없어 403 이다 — 검수자 전용이며 관리자는 역할 계층으로 포함된다.

일괄 재시작에서는 같은 사유가 요청 전체를 실패시키지 않고 그 건의 실패 결과와 사유로 실리며 나머지 건은 진행된다.
