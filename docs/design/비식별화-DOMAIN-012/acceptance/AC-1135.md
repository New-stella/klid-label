# UC-011 선두 비식별 실패 재시작 잠금 해제 — 모든 실패 종결과 제외 복사 성공에서 해제돼 재요청 수락·다른 기능 잠금 유지 (negative)

## notes

축 판정 — 이 기준은 종결 축(negative)이다. 출처 UC-011 의 대안 흐름 「선두 비식별 실패 후 배치 재시작」 7 단계에 대응한다. 우선순위를 critical 로 둔 이유는 해제 누락의 결과가 영구 고착이라 사람이 되돌릴 수단이 저장소 직접 수정뿐이기 때문이다.
★시험을 짤 때 빠지기 쉬운 자리 — ①종결 지점을 하나로 묶어 시험하지 말고 지점마다 따로 돌린다. 종결 경로가 여럿이라 한 지점만 보면 나머지 지점의 누락이 통과한다 ②원본 복사 성공을 반드시 넣는다 — 외부 위탁 완료 지점에서만 해제하는 구현이 이 사례에서만 깨진다 ③다른 기능의 잠금 사례를 넣는다 — 영상 단위로 잠금을 모두 푸는 구현이 이 사례에서만 깨진다 ④해제 여부는 잠금이 사라졌는지와 재요청이 수락되는지를 함께 본다.
수락 응답 미관측 회수와 취소 종결 사례에서 재요청의 수락 여부는 그 종결 뒤 영상이 여전히 재시작 대상 형상인지에 달려 있다 — 취소 종결은 영상 비식별 여부를 바꾸지 않으므로 형상이 유지된다.

## priority

critical

## scenario

### then

- 각 종결 사례마다 이 요청이 잡은 작업 잠금이 해제된다
- 각 종결 사례마다 이어진 재시작 요청이 409 가 아니라 다시 수락된다(재시작 대상 형상이 유지되는 사례에서)
- 원본 복사 성공 사례에서는 외부 위탁 완료 지점을 거치지 않고도 잠금이 해제되고, 영상은 비식별 여부 'Y' · 배치 단계 MARKING_READY 가 된다
- 각 종결의 영상 비식별 여부는 비식별 위탁 예외 기준이 정하는 값과 같다 — 잠금 해제가 그 값을 바꾸지 않는다
- 다른 기능이 잡은 같은 영상의 작업 잠금은 이 재시작이 어떻게 끝나도 해제되지 않는다
- 이 재시작과 무관한 배치 경로의 비식별 종결은 작업 잠금을 새로 만들거나 풀지 않는다

### when

- 다시 수행한 선두 비식별 단계가 외부 제출 실패 · 제출 개시 이전 실패 · 폴링 실패 · 처리 시한 초과 · 수락 응답 미관측 회수 · 취소 종결 · 원본 복사 실패 · 원본 복사 성공 중 하나로 끝난다
- 이어서 같은 영상에 배치 재시작을 다시 요청한다

### given

- 선두 비식별 실패 영상에 대해 배치 재시작이 수락돼 이 요청의 영상 단위 작업 잠금이 잡혀 있다
- 비교 사례로, 다른 기능이 같은 영상에 작업 잠금을 잡고 있는 상태에서 그 기능의 작업이 진행 중이다

## statement

선두 비식별 실패 영상의 배치 재시작 [[API-167]] · [[API-199]] 이 잡은 영상 단위 작업 잠금은 그 재수행이 어떻게 끝나든 해제되어, 같은 영상에 대한 재시작 요청이 다시 수락된다. 풀리지 않으면 그 영상은 이후 모든 재시작 요청이 409 로 거부되어 다시 고착된다 — 이 기준이 막으려는 것이 그 상태다.

해제는 모든 종결에서 일어나야 한다 — 외부 솔루션 제출 실패, 제출을 개시하기 전의 실패, 진행 상태 폴링 실패, 처리 시한 초과, 수락 응답을 관측하지 못해 회수된 종결, 호출자 트랜잭션 롤백에 따른 취소 종결, 출처유형 제외에 따른 원본 복사 실패, 그리고 원본 복사 성공(이 성공은 외부 위탁의 완료 지점을 거치지 않는다). 외부 위탁 성공 시의 해제는 정상 경로 기준([[AC-1133]])이 정한다. 각 종결의 영상 비식별 여부는 비식별 위탁 예외 기준([[AC-1064]])이 정하는 대로이며, 이 기준은 그것을 바꾸지 않는다.

해제는 이 재시작이 잡은 잠금에 한정한다. 같은 영상에 다른 기능(예: 트랙 병합, 검수 완료 영상 재비식별)이 잡은 작업 잠금은 이 재시작의 종결로 풀리지 않는다.
