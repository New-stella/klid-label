# UC-011 비식별 처리 요청 — KPST 위탁(공유마운트 경로만)→폴링 완료 감지→비식별본 저장·원본 유지·이력·출처유형 제외 시 원본 복사로 완료 (happy)

## notes

축 판정 — 이 기준은 정상 경로(happy)다. 제목·is_negative 와 출처 UC-011 의 main_flow 1~5 가 1:1로 대응한다. 그래서 종료 사유별 원장 마감값과 그때의 영상 비식별 여부(외부 터미널 상태·폴링 경과 만료·불완전 산출물·제출 확정 실패·수락 응답 미관측 회수는 'F', 취소 종결만 불변)는 이 자리에 넣지 않았다 — 그 축은 예외 기준(AC-1064)이 이미 정하고 있고, 같은 계약을 두 자리에 옮겨 적으면 다시 갈라진다.
채운 것은 하나다 — 출처 UC-011 이 「제출은 논블로킹」으로 못박은 성질이 정상 경로 기준에는 통째로 빠져 있었다. 그것이 없으면 202 응답이 외부의 수락까지 확정한 것처럼 읽혀, 「수락 응답을 관측하지 못한 건」을 다루는 예외 기준과 같은 계약을 서로 다르게 말하게 된다.
검증 실상 — 추가한 단언(논블로킹 제출 · 202 의 의미 · 수락 관측 기록)을 확인하는 자동 시험은 확인되지 않았다. 그래서 검증 상태를 unverified 로 되돌린다. 남아 있는 마지막 실행 기록(통과)은 추가 이전 단언을 대상으로 한 것이라 그 자체가 거짓은 아니어서 지우지 않고 두되, 추가한 단언까지 덮지는 않는다.
검사하고 그대로 둔 것 — 제목·증빙 두 항목·참조 식별자(slug)에는 거짓 서술이 없다. slug 는 참조 식별자라 검사 대상이지 수정 대상이 아니다.
출처유형 제외 분기(ADR-066) — 정상 경로 축에 성공 분기만 더했다. 제외 복사 실패·제외 행이 폴링과 수락 대기 유예 회수 대상이 아니라는 것·검수 완료 영상 재비식별의 위탁은 예외 기준(AC-1064)에 둔다. 남아 있는 마지막 실행 기록(통과)은 이 분기 추가 이전 단언을 대상으로 한 것이라 추가한 분기 단언까지 덮지 않는다.
재생 인덱스 재배치(ADR-072)를 정상 경로에 더했다 — 출처 UC-011 main_flow 6 에 대응한다. 재배치 실패의 처리는 예외 기준(AC-1064)에 둔다. 추가한 단언을 확인하는 자동 시험은 아직 없다 — 남아 있는 마지막 실행 기록(통과)은 이 단언 추가 이전을 대상으로 한 것이라 추가한 단언까지 덮지 않는다.

## statement

비식별(재)처리를 요청하면(202 Accepted) Resilience4j 정책을 적용한 연동으로 외부 KPST 비식별 솔루션에 위탁하되 공유 마운트를 쓰므로 파일을 올리지 않고 입력 경로만 실어 비식별 프로젝트를 생성한다(POST /project). 주기 폴링(GET /retrieve_progress)으로 완료를 감지하며 결과 파일은 외부 솔루션이 산출 경로에 직접 만들므로 내려받지 않고 통보된 경로를 원장에 그대로 기록한다(파일명 조합·추측 없음, 별도 결과 콜백 없음). 비식별본을 STORAGE_DEIDENTIFIED_PATH에 저장하고 원본은 유지하며 처리 이력(DE_IDNTF_YN 등)을 기록한다. 제출은 논블로킹이다 — 프로젝트 생성 호출의 응답을 동기로 기다리지 않고 대기 상태(WAITING)의 위탁 원장 행을 먼저 확정한 뒤 그 호출을 비동기로 개시한다. 따라서 202 Accepted 가 확정적으로 말하는 사실은 「제출을 개시했다」뿐이고, 외부의 수락 여부는 그 뒤에 관측돼 원장에 기록된다 — 그 기록이 있어야 수락 대기 창과 결과 대기 창이 구분된다. 정상 경로에서는 그 뒤 폴링이 완료를 감지해 위 흐름이 그대로 이어진다. 제출·회수가 정상으로 이어지지 않은 건의 종료 사유와 그때의 영상 비식별 여부는 예외 축(AC-1064)이 정한다.

[출처유형 제외 분기 — ADR-066] 위 위탁 경로는 영상의 출처유형(LS_DATA_RAW.SRC_TYPE)이 배포 설정 authoring.deidentify.excluded-src-types 의 제외 목록에 없거나 출처유형이 비어 있는 영상을 전제로 한다. 출처유형이 제외 목록(기본값 GENERATED)과 정확히 일치하는 영상을 선두 비식별 단계가 처리하면 외부 비식별 솔루션 호출은 0건이고 진행 상태 폴링도 하지 않는다. 대신 원본 영상을 비식별 영상 쓰기 위치에 원본 파일명 그대로 일반 파일로 복사해 원본과 바이트 단위로 같은 복사본을 두고(링크를 두지 않는다), LS_DEIDENT_PROC_LOG 에 PROC_STTS_CD=SUCCEEDED · REQ_KND_CD=EXCLUDED · DE_IDNTF_FILE_PATH_NM=복사본 경로인 행을 남기며, 영상 비식별 여부 'Y' · 배치 단계 MARKING_READY 로 전이한다. 원본은 보존한다. 제외 목록 설정이 비어 있으면 출처유형이 GENERATED 인 영상도 외부 솔루션에 위탁하고, 출처유형이 비어 있는 영상은 어떤 설정에서도 위탁한다. 제외 복사 실패·제외 행의 회수 대상 제외·검수 완료 영상 재비식별의 위탁은 예외 축(AC-1064)이 정한다.

[재생 인덱스 재배치 — ADR-072] 외부 솔루션 위탁으로 비식별 완료가 확정돼 산출 경로가 처리 이력에 기록되면, 기록된 경로의 산출물은 재생 인덱스가 파일 앞에 있는 상태가 된다. 인덱스가 파일 끝에 있던 산출물은 영상·음성 스트림을 다시 인코딩하지 않고 인덱스만 앞으로 옮기며, 경로·파일명·재생 길이·해상도·코덱은 바뀌지 않는다. 인덱스가 이미 앞에 있는 산출물은 건드리지 않는다(멱등). 재배치가 끝난 뒤 산출 디렉터리에는 산출물 외의 작업용 파일이 남지 않는다. 재배치 실패와 인덱스를 판정할 수 없는 파일의 처리는 예외 축(AC-1064)이 정한다. 출처유형 제외 분기의 복사본은 원본을 복사한 것이라 이 단계의 대상이 아니다.
