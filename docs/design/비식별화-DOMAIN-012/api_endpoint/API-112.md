## description

REVIEWER가 검수완료(APPROVED) 영상의 비식별 재수행을 요청한다. 서비스가 전제조건(APPROVED 이력·미검수 아님·이미 정상 비식별(DE_IDNTF_YN='Y')이 아님·락 없음)을 검증하고 작업락을 선점한 뒤 KPST 위탁(REQ_KIND=REDEIDENT)을 시작하며, 실제 완료(프레임 attach + DE_IDNTF_YN='Y')는 폴링 잡이 비동기로 이어받는다. ⚠ 이미 DE_IDNTF_YN='Y' 로 정상 완주한 승인 영상은 이 경로에서도 409(이미 비식별됨)로 배제된다 — 그 가드의 사유는 개인정보가 아니라 프레임 번호 의미 불일치다. 정상 완주한 승인 영상에서 사후에 개인정보 노출이 발견돼도 이 엔드포인트로는 재비식별할 수단이 없다(신고 접수도 검수 승인 이력이 있으면 412 로 막혀 있다 — 발견은 승인 전이 전제). 따라서 본 엔드포인트는 수락 사실만 202 Accepted + status=ACCEPTED로 동기 반환하고 위탁 식별자(procLogSn)를 함께 준다. KPST 프로젝트 아이디는 수락 응답 시점에 존재할 수 없어 내려주지 않으며, 필요하면 처리 로그 일련번호로 원장을 조회한다. 요청 바디 없이 경로변수 + 인증 principal만 사용한다. kpst.deid.enabled=true 환경에서만 빈이 등록된다.
