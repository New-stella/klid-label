배치 재시작 대상 영상 여러 건을 한 번에 재시작한다. 대상 형상은 건별 재시작(API-167)과 같은 둘이다 — ①마킹 이후 배치 단계가 실패로 고착된 영상 ②선두 비식별이 실패해 마킹 준비에 도달하지 못한 영상(비식별 여부가 실패이고 배치 단계가 대기인 영상). 비식별 실패도 배치 실패로 보며, 그것을 위한 별도 창구를 두지 않는다. 목록 화면에서 고른 영상들을 대상으로 하며, 건별 재시작과 같은 판정·같은 재실행 경로·같은 선점 방식을 각 영상에 그대로 적용한다 — 일괄 쪽에 판정을 따로 두지 않는다. 따라서 ②형상의 영상은 적재 직후와 같은 선두 비식별 단계를 다시 수행하도록 접수되고, ①형상의 영상은 종전대로 마킹 이후 단계를 재기동한다. 두 형상이 한 요청에 섞여도 된다. ★건별 사유도 건별 재시작의 거부 사유를 같은 모양(영상 식별자·성공 여부·사유)으로 싣는다 — 비식별 재시도 쪽 거부(파생영상 · 승인 이력 있음 · 열린 비식별 누락 신고 있음 · 진행 중 위탁 있음 · 같은 영상에 대한 동시 요청)도 요청 전체를 실패시키지 않고 그 건의 실패 결과와 사유로 실린다. 영상이 없거나 두 형상 어디에도 들지 않는 영상도 그 건만 사유와 함께 실패로 기록된다. ★ 일부가 거부돼도 나머지는 진행한다(부분 성공). 재기동은 먼저 선점하는 쪽이 이기는 방식이라(①형상은 실패 상태 선점, ②형상은 영상 단위 작업 잠금 선점), 다른 검수자가 그중 한 건을 방금 눌렀다는 이유로 나머지 전부를 되돌리면 사용자가 선택을 반복하게 된다. 영상끼리는 서로 영향을 주지 않으므로 한 건의 거부가 다른 건의 정합성을 해치지 않는다. 이는 전체 성공 또는 전체 실패로 처리하는 일괄 배정과 의도적으로 다른 정책이다 — 배정은 승인된 영상에 배정하면 안 된다는 무결성 조건이 걸려 있지만 재기동에는 그 조건이 없다. 한 요청의 대상 건수에는 상한을 두어 과도한 자원 소모를 막는다(1~100건, 중복은 한 건으로 취급). ★건별 결과는 재기동을 접수했는지 여부이지 파이프라인이 끝났다는 뜻이 아니다 — 선점(①형상은 실패 상태, ②형상은 작업 잠금)까지만 요청 안에서 처리하고 실행은 비동기로 넘긴다. ②형상은 접수 시점에 배치 단계를 처리 중으로 바꾸지 않는다. 완료를 기다리면 대상 건수만큼 시간이 누적돼 클라이언트 타임아웃에 먼저 걸리고, 요청 스레드 하나가 그동안 묶여 다른 요청까지 밀린다. 진행 상황은 목록과 영상 상세의 단계 표시로 확인한다. 자동 재시도·주기 회수는 두지 않는다 — 사람이 요청할 때만 동작한다. 검수자 전용이며 관리자는 역할 계층으로 포함되고, 작업자는 403 이다.
