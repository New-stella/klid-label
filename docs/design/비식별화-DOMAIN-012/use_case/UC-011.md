## description

전체 영상(PRVC/PSDO/ANONY 구분 없이)을 Resilience4j 정책을 적용한 연동으로 외부 KPST 비식별 솔루션에 위탁한다 — 비식별이 파이프라인 선두 단계다(게이팅 폐지).

[위탁·수신] 위탁(경로 참조로 프로젝트 생성) 후 주기 폴링(진행조회)으로 완료를 감지하고 산출 경로를 회수한다(별도 결과 콜백 없음 — 구 수신 경로 POST /v1/deidentify/result 폐기). 비식별본은 STORAGE_DEIDENTIFIED_PATH 에 저장하고 원본은 보존한다.

[★제출은 논블로킹] createProject 를 동기로 기다리지 않고 WAITING 원장 행을 선커밋한 뒤 비동기 디스패치한다(VLM 위탁과 대칭). 스텝이 확정적으로 말하는 사실은 '제출을 개시했다' 뿐이다. 4노드 Active-Active 에서 같은 후보를 둘이 집어 두 번 회수하지 않도록 조건부 UPDATE 원자 클레임으로 막는다 — 원자 클레임 원칙 자체는 두 축 공통이다. ⚠ [폐기] 구 서술 '2노드 중복 재위탁은 조건부 UPDATE 원자 클레임으로 막는다' — 비식별 축은 재위탁을 하지 않으므로 중복되면 안 되는 것은 재위탁이 아니라 회수다.

[★회수 경로는 축마다 다르다] 시계열은 전용 미결 스위퍼가 집어 재위탁하고, 비식별은 전용 스위퍼가 없이 폴링 잡이 ACK 대기 유예 만료로 회수해 실패 코드로 원장을 마감한다(재위탁하지 않는다). 비식별 쪽 회수는 「우리가 ACK 를 관측하지 못했다」는 뜻이지 「외부에서 실패했다」가 아니다 — 다만 그 회수는 제출 확정 실패와 같은 종결 경로를 타므로 원장을 실패로 마감하고 영상 비식별 여부도 'F' 로 내린다. 유예 만료 회수에 별도 종료 사유 코드(KPST_ACK_MISSING)를 두는 까닭은 영상 상태를 달리하기 위해서가 아니라 운영 조치를 가르기 위해서다 — 그 코드가 남았다는 것은 우리 프로세스가 수락 응답을 관측하지 못했다는 뜻이라 외부에는 프로젝트가 실제로 생성돼 있을 수 있어, 사람이 외부 상태를 확인해야 하는 건으로 식별된다. 외부 터미널 상태·폴링 경과 만료·불완전 산출물·제출 확정 실패(KPST_SUBMIT_FAILED)도 같은 종료값을 세우며, 영상 비식별 여부가 불변인 예외는 호출자 트랜잭션 롤백에 따른 취소 종결(KPST_SUBMIT_CANCELED) 하나뿐이다 — 외부로 아무것도 나가지 않았기 때문이다. 제출 신호가 노드와 함께 사라지면 실패 행조차 남지 않아 재시도 큐·실패 회수기가 집지 못하므로, 각 축의 이 회수 경로가 유일하다. ⚠ [폐기] 구 서술 '아무 신호도 오지 않으면 실패 행조차 없으므로 미결 스위퍼가 유일한 회수 경로다' — 비식별 축의 회수 주체는 스위퍼가 아니라 폴링 잡이고, 그 회수는 재위탁이 아니라 실패 코드 마감이다. 되살리지 말 것. ⚠ [폐기] 구 서술 '수락 응답 미관측에 따른 유예 만료 회수는 영상 비식별 상태를 실패로 내리지 않는다' — 코드 실측 결과 거짓이다. 그 회수도 제출 확정 실패와 같은 종결 경로를 타 영상 비식별 여부를 'F' 로 내린다. 되살리지 말 것.

[★실패 처리 — 자동 재시도 큐 없음] 실패 시 DE_IDNTF_YN='F' 마킹 + 원본 절대 삭제 금지. 구 서술의 '재시도'는 자동 재비식별 큐를 뜻하지 않는다 — 그 큐는 폐기됐고, 작업자/검수자가 외부 솔루션으로 **수동 재비식별** 한 뒤 resolve 로 해소한다(UC-016). (R2 UC-011, RQ-SFR-09-01/02)

### 응답 유실

**steps**:

- 수락 응답도 결과 회신도 관측되지 않은 건은 폴링 잡이 ACK 대기 유예 만료로 회수해 실패 코드로 원장을 마감한다 — 비식별 축에는 전용 미결 스위퍼가 없고 재위탁도 하지 않는다. 제출 신호가 노드와 함께 사라지면 실패 행조차 남지 않아 재시도 큐·실패 회수기가 집지 못하므로 이 회수 경로가 유일하다
- 이 회수도 제출 확정 실패와 같은 종결 경로를 타 원장을 실패로 마감하고 영상 비식별 여부를 'F' 로 내린다 — 종료 사유 코드(KPST_ACK_MISSING)를 따로 두는 까닭은 영상 상태를 달리하기 위해서가 아니라 운영 조치를 가르기 위해서다. 그 코드가 남았다는 것은 우리가 수락 응답을 관측하지 못했다는 뜻이라 외부에는 프로젝트가 실제로 생성돼 있을 수 있어, 사람이 외부 상태를 확인해야 하는 건으로 식별된다
- 수락 대기 창(ACK)과 결과 대기 창(콜백)을 구분해 정상 위탁 건을 잘못 회수하지 않는다
- 4노드 Active-Active 에서 같은 후보를 둘이 집어 두 번 회수하지 않도록 조건부 UPDATE 로 원자 클레임한다 — 원자 클레임 원칙 자체는 두 축 공통이다

- **trigger**: 제출 후 아무 신호도 관측되지 않음
