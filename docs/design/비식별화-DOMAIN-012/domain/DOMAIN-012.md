## description

영상의 개인정보 비식별 처리를 외부 비식별 솔루션(KPST) 위탁으로 수행하는 도메인.

[★파이프라인 선두 — 게이팅 폐지] 적재된 모든 영상이 (ANONY 포함) 무조건 비식별 대상이다. 단, 배포 설정 제외 목록(authoring.deidentify.excluded-src-types, 기본값 GENERATED = 생성형 영상)에 든 출처유형(LS_DATA_RAW.SRC_TYPE)은 외부 솔루션에 위탁하지 않고 원본 복사로 비식별 제외 완료한다(ADR-066 — 아래 [출처유형 비식별 제외] 절). 구 서술 'PRVC_TYPE_CD 가 PRVC/PSDO 일 때만 호출'은 폐기됐다. 적재 직후 VideoIngested(EVT-005) 가 커밋 이후(AFTER_COMMIT) 비동기로 비식별 단계를 자동 트리거하며, 성공 시 LsDataRaw.dataSttsCd 가 MARKING_READY 로 전이해 마킹 진입이 열린다. 마킹·라벨링의 대상은 비식별 영상이고 원본은 별도 경로에 보존된다.

[★출처유형 비식별 제외 — ADR-066] 위 「적재된 모든 영상이 비식별 대상」의 예외다. 선두 비식별 단계는 처리 시점에 영상의 출처유형(LS_DATA_RAW.SRC_TYPE)이 배포 설정 authoring.deidentify.excluded-src-types(쉼표 구분 복수, 기본값 GENERATED)에 드는지 1회 판정하고, 결과는 영상별 비식별 처리 이력에 고정한다 — 설정 변경은 소급하지 않는다. 판정 시점은 적재가 아니라 선두 비식별 단계이며 적재 흐름은 그대로다. 제외 대상이면 외부 솔루션에 위탁하지 않고 원본 영상을 비식별 영상 쓰기 위치에 원본 파일명 그대로 일반 파일로 복사(링크 금지)한 뒤, 비식별 처리 이력(LS_DEIDENT_PROC_LOG)에 PROC_STTS_CD=SUCCEEDED · DE_IDNTF_FILE_PATH_NM=복사본 경로 · REQ_KND_CD=EXCLUDED 행을 남기고 DE_IDNTF_YN='Y' · MARKING_READY 로 전이한다(외부 위탁 동기 완료와 같은 흐름). 뒤 단계(마킹 진입 조건·마킹 화면 영상 재생·프레임 원본/비식별 두 벌 추출·증강/해상도 파생의 부모 비식별 영상 조회·관제 조회 뷰의 비식별 영상 경로)는 바뀌지 않고 신규 상태값·컬럼도 없다. 복사 실패(원본 부재·경로 위반·입출력 오류)면 DE_IDNTF_YN='F' · 이력 FAILED(REQ_KND_CD=EXCLUDED) · MARKING_READY 미전이이며 원본은 삭제·수정하지 않는다. 제외 행은 외부 진행 상태(POLL_STTS_CD)를 갖지 않으므로 아래 폴링·ACK 대기 유예 회수의 대상이 아니다. 설정을 비우면 빈 목록이라 모든 영상을 위탁한다(안전측). 이 설정은 배포 설정 파일 전용이며 관리 화면의 시스템 설정(비식별 옵션)으로 두지 않는다 — 비식별 우회를 재기동 없이 켤 수 없게 하기 위해서다. 기동 시 허용값 검사·기동 차단은 없고 적용 목록을 기동 로그로 남긴다. 개인정보 유형(PRVC_TYPE_CD)은 바꾸지 않는다. 검수 완료 영상의 재비식별은 이 제외를 타지 않지만, 비식별 여부가 'Y' 인 영상을 받지 않고 제외 처리에 성공한 영상은 모두 'Y' 이므로 제외 영상의 회수 경로가 아니다 — 제외 출처유형 오표기의 회수 지점은 검수(비식별 누락 신고 → 외부 재비식별 → 신고 해소)이며, 승인 이력이 있는 영상은 기존 정책대로 신고를 받지 않는다. 수용한 위험 — 실제 CCTV 영상이 제외 대상 출처유형으로 잘못 인입되거나 설정에 원천 CCTV 출처유형(ORIGINAL·RELAY)이 기재되면 마스킹 없는 영상이 마킹 화면·산출물·관제로 흐른다. 출처유형의 정확성은 관제 책임이고 회수는 비식별 누락 신고 → 외부 재비식별이다(관제는 기존에도 생성형 AI 서버에서 생성된 영상을 출처유형 GENERATED 로 전달하고 있다 — 2026-09-14 관제 확인). 또한 DE_IDNTF_YN='Y' 의 뜻이 「비식별 완료 또는 제외」로 넓어지나, 관제는 비식별 작업을 하지 않아(비식별 관련 작업은 전부 저작도구로 이관) 이 값으로 판단하는 것이 없어 관제 수정 사항은 없다(2026-09-14 관제 확인).

[★결과 수신 = 폴링(콜백 아님)] 구 서술 '외부 콜백(webhook)으로 결과 수신'은 폐기됐다. 위탁 후 주기 폴링(진행조회)으로 완료를 감지하고 산출물 경로를 기록한다. 산출 파일명은 우리가 정하지 않는다 — mock 은 deidentified.mp4, KPST 실연동은 {원본stem}-mask{ext} 라 영상마다 다르므로 반드시 LS_DEIDENT_PROC_LOG.DE_IDNTF_FILE_PATH_NM 값을 읽고 문자열로 조합·추측하지 않는다.

[★제출은 논블로킹] KPST 비식별 제출은 WAITING 원장 행을 선커밋하고 createProject 를 비동기 디스패치한다. 스텝이 확정적으로 말하는 사실은 '제출을 개시했다' 뿐이며 수락(ACK)은 완료 핸들러가 비동기 기록한다.

[★회수 경로는 축마다 다르다] [폐기] 구 서술 '아무 신호도 없으면 미결 스위퍼가 회수하고, 2노드 Active-Active 에서 같은 후보를 두 번 재위탁하지 않도록 조건부 UPDATE 로 원자 클레임한다' — 폐기한다. 비식별 축에는 전용 미결 스위퍼가 없고 그 회수는 재위탁도 아니다. 회수 경로는 축마다 다르다. 시계열은 전용 미결 스위퍼가 집어 재위탁하고, 비식별은 전용 스위퍼가 없이 폴링 잡이 ACK 대기 유예 만료로 회수해 실패 코드로 원장을 마감한다(재위탁하지 않는다). 비식별 쪽 회수는 '우리가 ACK 를 관측하지 못했다'는 뜻이지 '외부에서 실패했다'가 아니다 — 외부에는 실제로 작업이 생성돼 있을 수 있다. [폐기] 다만 그 전제에 이어 붙였던 구 결론 '그러므로 영상 비식별 상태를 실패로 내리지 않는다' 는 사실과 반대라 폐기한다. ACK 대기 유예 만료 회수는 제출 확정 실패와 같은 종결 경로를 타고, 그 경로가 영상 비식별 여부(DE_IDNTF_YN)를 'F' 로 내린다. 원장을 FAILED 로 마감하면서 영상을 'F' 로 내리는 종결 계기는 외부 터미널 상태·폴링 경과 만료·불완전 산출물·제출 확정 실패(KPST_SUBMIT_FAILED)·ACK 대기 유예 만료 회수(KPST_ACK_MISSING)이며, 영상 상태가 불변인 예외는 호출자 트랜잭션 롤백에 따른 취소 종결(KPST_SUBMIT_CANCELED) 하나뿐이다 — 외부로 아무것도 나가지 않았기 때문이다. ACK 대기 유예 만료 회수를 별도 사유 코드로 분리하는 근거는 영상 상태가 아니라 운영 조치다 — 그 코드가 남았다는 것은 우리 프로세스가 수락 응답을 관측하지 못했다는 뜻이라 외부에는 프로젝트가 실제로 생성돼 있을 수 있어(노드 사망 등), 사람이 외부 상태를 확인해야 하는 건을 식별하려는 분리다. 제출 신호가 노드와 함께 사라지면 실패 행조차 남지 않아 재시도 큐·실패 회수기가 집지 못하므로, 각 축의 이 회수 경로가 유일하다. 4노드 Active-Active 에서 같은 후보를 두 노드가 동시에 집지 않도록 조건부 UPDATE 로 원자 클레임한다.

[실패·재처리] 실패 시 DE_IDNTF_YN='F' 마킹 + 원본 절대 삭제 금지. 자동 재비식별 큐는 폐기됐고 재비식별은 사람이 외부 비식별 프로그램에서 수행한다 — 다만 그것이 해소의 선행 조건은 아니며, 해소는 후보 산출물을 골라 무결성 판정을 통과하면 성립한다(그 축은 fail-closed 다). 이 외부 재비식별·해소 경로는 비식별 누락 신고가 열린 영상의 축이다. 신고 없이 선두 비식별이 실패해 마킹 준비 전인 영상(DE_IDNTF_YN='F' · 배치 단계 PENDING)은 검수자가 기존 배치 재시작(건별 API-167·일괄 API-199)을 눌러 적재 직후와 같은 선두 비식별 단계(외부 위탁 또는 출처유형 제외 원본 복사)를 다시 수행하고, 성공하면 'Y' · MARKING_READY 가 된다. 새 창구는 두지 않고 자동 재시도·스윕·스케줄도 두지 않는다(ADR-006) — 열린 신고·승인 이력·진행 중 위탁·동시 요청은 409, 파생영상은 400 으로 거부한다.

[★비식별 누락 신고] 작업자가 개인정보 노출을 발견하면 신고 → 작업락 + DE_IDNTF_YN='F'. 라벨도 개인정보 판정도 삭제하지 않고 보존한다. 신고 구간에는 조회뿐 아니라 라벨 저장·버전 diff·롤백·개인정보 메타 PUT·이벤트 어노테이션 저장/승인/반려·검수 승인까지 412 로 차단되며(영상 스트리밍만 404), 한 번이라도 검수 승인된 이력이 있는 영상은 신규 신고 접수 자체를 막는다(판정 축은 지금 상태가 아니라 승인 이력). 게이트 판정 범위는 자기 rawSn 행 하나이며 조상/자손 전파는 4라운드 시도 후 철회됐다 — 다시 시도하지 말 것. 파생영상은 신고 체계 바깥이라 접수하지 않고(412) 원본 신고의 영향도 받지 않는다. 검수 완료·통지 건에 대한 관제 접근은 신고 구간에도 차단하지 않는다.

[잔존 책임] 저작도구는 위탁·결과 저장(DFEAT-041)·대상 범위(DFEAT-042)·누락 신고(DFEAT-048)를 보유한다. 비식별 결과의 상세(deep) 검토는 외부 솔루션 프로그램이 수행하며, 저작도구는 그 축을 경량 상태·이력 확인(FEAT-006)으로만 보유한다 — 폐기된 것은 FEAT-006 자체가 아니라 그 상세 검토 UC·화면·API(UC-012·SCREEN-016/017·API-051/052)다.

## ubiquitous_language

### [1]

- **term**: DE_IDNTF_YN
- **meaning**: 비식별 여부. Y=완료(출처유형 비식별 제외 완료 포함 — ADR-066), N=미수행, F=실패 또는 누락 신고 중. 'F' 는 의미가 둘이라 플래그만으로 구분되지 않고 산출물 실재 검증이 fail-closed 로 뒤를 받친다

### [2]

- **term**: DE_IDNTF_SRC_FILE_PATH_NM
- **meaning**: 비식별 프레임 경로 (원본 SRC_FILE_PATH_NM 과 별도). 신규 추출은 frames/raw|deid/{rawSn} 로 분기 저장돼 두 경로가 항상 다르다

### [3]

- **term**: DE_IDNTF_FILE_PATH_NM
- **meaning**: 비식별 영상 파일 경로. 외부 솔루션이 파일명을 정하므로 이 값을 읽어야 하며 조합·추측 금지

### [4]

- **term**: 비식별 누락 신고
- **meaning**: 마킹·라벨링 중 개인정보 노출을 발견해 재비식별을 요청하는 행위. 작업락과 'F' 마킹을 동반한다. 라벨과 개인정보 판정은 지우지 않고 보존한다

### [5]

- **term**: 신고 게이트
- **meaning**: 자기 rawSn 행의 DE_IDNTF_YN='F' 단일 컬럼만 보고 판정하는 프리컨디션. 인가 검사 이후 평가되며 역할 무관이다

### [6]

- **term**: MARKING_READY
- **meaning**: 선두 비식별이 성공해 마킹 진입이 허용된 상태 (출처유형 비식별 제외로 원본 복사가 완료된 경우 포함 — ADR-066)
