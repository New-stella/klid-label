## description

비식별 처리는 여러 패키지에 걸쳐 구현된다.

[위탁] 배치 DeidentifyStep 이 DeidentifyClient 로 외부 비식별 솔루션(KPST)에 위탁한다. ★제출은 논블로킹이다 — WAITING 원장 행을 선커밋하고 createProject 를 비동기 디스패치하며, 응답 기록은 전용 풀에서만 실행한다(publishOn 을 쓰면 풀 포화 시 거부가 reactor-netty 이벤트 루프로 흘러 JPA 쓰기가 이벤트 루프에서 실행된다).

[출처유형 제외] 선두 비식별 단계 DeidentifyStep 은 위탁에 앞서 영상의 출처유형(LS_DATA_RAW.SRC_TYPE)이 배포 설정 authoring.deidentify.excluded-src-types(환경변수 DEIDENTIFY_EXCLUDED_SRC_TYPES, 쉼표 구분, 기본값 GENERATED)의 제외 목록과 정확히 일치하는지 처리 시점에 한 번 판정한다(ADR-066 — ADR-006 의 전체 영상 위탁을 대체하지 않고 더한 예외). 일치하면 DeidentifyClient 를 호출하지 않고 원본 영상을 비식별 영상 쓰기 위치에 원본 파일명 그대로 일반 파일로 복사한 뒤(링크를 두지 않는다), LS_DEIDENT_PROC_LOG 에 REQ_KND_CD=EXCLUDED 인 성공 행(PROC_STTS_CD=SUCCEEDED, DE_IDNTF_FILE_PATH_NM=복사본 경로)을 남기고 영상 비식별 여부 'Y'·배치 단계 MARKING_READY 로 전이한다 — 외부 위탁이 완료된 경우와 같은 흐름이다. 복사에 실패하면(원본 부재·경로 위반·입출력 오류) 비식별 여부를 'F' 로 두고 REQ_KND_CD=EXCLUDED 인 FAILED 행을 남기며 MARKING_READY 로 전이하지 않는다. 반쯤 쓴 임시 파일은 정리하고 원본은 삭제하거나 수정하지 않는다. 제외 행은 외부 진행 상태를 갖지 않으므로 KpstDeidentPollJob 의 진행 폴링·ACK 대기 유예 만료 회수 대상이 아니다. 판정 결과는 영상별 이력에 고정돼 설정 변경이 소급하지 않고, 설정이 비면 모든 영상을 위탁한다. 검수 완료 영상의 재비식별 진입점(ApprovedRedeidentController)은 이 판정을 타지 않고 항상 외부 솔루션에 위탁한다.

[★결과 수신 = 폴링 (구 '콜백' 서술 폐기)] 이전 본문은 '외부 서버가 /v1/deidentify 콜백으로 결과를 회신한다'고 적었으나 실제는 주기 폴링(진행조회)로 완료를 감지한다. 산출 파일명은 외부가 정하므로(mock=deidentified.mp4 / KPST={원본stem}-mask{ext}) LS_DEIDENT_PROC_LOG.DE_IDNTF_FILE_PATH_NM 값을 읽어야 하며 문자열로 조합·추측하지 않는다.

[★재처리 = 수동 (구 '재트라이 메타' 폐기)] 자동 재비식별 큐는 없다. 실패·신고 영상은 DE_IDNTF_YN='F' 로 마킹된 채 외부 비식별 프로그램에서 사람이 다시 처리한다 — 다만 그 재처리는 해소의 선행 조건이 아니다. DeidentReportService.resolve 는 후보 목록에 있는 산출물을 고르고 무결성 판정을 통과하면 OPEN→RESOLVED 전이를 걸며, 신고 이전부터 있던 산출물(지금 쓰고 있는 비식별 영상 포함)도 후보가 된다. 무결성 판정은 통과해야만 성립하는 fail-closed 게이트다.

[선두 비식별 실패 수동 재시작] 선두 비식별 실패 영상(비식별 여부 'F' 이면서 배치 단계가 마킹 준비에 이르지 못한 PENDING)은 새 창구 없이 기존 배치 재시작([[API-167]] 건별 · [[API-199]] 일괄, 검수자 전용)이 받는다. 재시작 창구는 판정과 영상 단위 작업 잠금 선점을 커밋한 뒤 적재 직후와 같은 선두 비식별 단계(IngestDeidentifyBridge / AsyncDeidentifyRunner → DeidentifyStep)를 비동기로 다시 호출한다 — 외부 위탁이냐 출처유형 제외 복사냐는 처리 시점 설정으로 판정하고, 성공하면 비식별 여부 'Y'·MARKING_READY 로 전이한다. 배치 단계를 PROCESSING 으로 선점하지 않고 비식별 여부를 'N' 으로 되돌리지 않는다. 파생영상·승인 이력·열린 비식별 누락 신고(그 'F' 는 신고 표식이라 해소 경로가 따로 있다)·진행 중 위탁·동시 요청은 거부한다. 재시도가 잡은 작업 잠금은 선두 비식별 단계의 모든 종결(외부 완료·제출 실패·폴링 실패·경과 만료·ACK 대기 유예 만료 회수·취소 종결·제출 이전 실패·출처유형 제외 성공과 복사 실패)에서 해제되어 다시 요청할 수 있어야 하며, 같은 영상 잠금을 쓰는 다른 기능(트랙 병합·검수 완료 재비식별)이 잡은 잠금은 풀지 않는다. 사람이 누를 때만 도는 수동 재시작이라 자동 재비식별 큐를 두지 않는다는 결정과 양립하며, 자동 재시도·스윕·스케줄은 두지 않는다.

[해소 시 복구] resolve 는 두 이벤트를 분기 발행한다 — DeidentGateReopenedEvent(EVT-007, 항상: 보류 VLM 위탁 재개용) / 수정 통지 이벤트(APPROVED 일 때만: 재검토 표시(REVLT_YN)를 세우며 export 강제 재산출·관제 재통지는 검수자가 재승인한 시점에 일어난다). EVT-008 은 같은 자리를 가리키던 이름이나 발행처가 없는 휴면 확장점이다.

컴포넌트·관계는 실제 생성자 의존성에서 도출.

- **kind**: container
- **description**: 비식별 서버 호출 어댑터 (common.client, Resilience4j)

### 비식별 서버

- **kind**: system
- **description**: 외부 비식별화 서버

### VideoRepository

- **kind**: container
- **description**: 영상 메타·비식별 상태(LS_DATA_RAW) (video 패키지)

### BatchRetryQueue

- **kind**: container
- **description**: 배치 일반 재시도 큐. 비식별 재처리 전용 큐가 아니며 비식별 축에서는 쓰지 않는다.

### NotificationService

- **kind**: container
- **description**: 알림 서비스 (notification 패키지)

### 배치 재시작 (건별·일괄)

- **kind**: container
- **description**: 영상 배치 재시작 창구(건별 API-167 · 일괄 API-199, 검수자 전용). 선두 비식별 실패 형상(비식별 여부 'F' + 배치 단계 PENDING)이면 마킹 이후 단계 대신 선두 비식별 단계를 다시 태우고, 그 밖의 영상은 기존 재기동을 그대로 한다. 일괄은 건별과 같은 판정을 건마다 적용한다.
