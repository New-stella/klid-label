    end
    Note over HOME,C: [폐기] 데이터마트 영상 목록 조회 단계 — 저작도구는 그 목록을 두지 않는다

    loop 화면의 라벨 건수만큼 순차 저장
        FE->>C: POST /v1/portal/user-labels
        C->>C: 회원별 저장 허가 획득(초과 시 429)

        S->>S: 노출 판정 → 신고 게이트
        S->>S: 형태 허용 목록(BBOX/POLYGON) → 좌표 개수 상한 → 유한성
        S->>S: 정규형 재직렬화로 적재값 확정

        DB-->>S: 저장 결과
        S-->>C: 저장된 작업 라벨(적재된 라벨 마스터 참조·트랙 식별자 포함)
        C-->>FE: 201 Created
    end
    Note over S,DB: 원본 라벨(LS_DATA_LBL)·데이터마트는 수정되지 않는다 — 단방향

    C-->>FE: 200 OK

## description

포털 회원(PORTAL_USER)이 데이터마트 자산의 기존 라벨을 확인·수정하고 본인 작업 데이터로 저장하는 흐름의 시퀀스 다이어그램. 진입, 프레임 단위 라벨 Load, 비식별 프레임 이미지 서빙, 본인 작업 라벨 저장과 재조회를 그린다.

★ 진입이 두 갈래다. 새로쓰기는 Host(포털)가 자기 화면에 그리는 데이터마트 목록에서 영상을 고른 뒤 진입 링크로 라벨링 화면에 들어오고, 이어쓰기는 저작도구 진입 화면의 「내 저장 작업 목록」에서 들어온다. Host 가 소유하는 것은 그 목록 화면과 진입 링크 둘뿐이고, 화면·세션 생성·소재 적재·저장·작업 목록·내려받기는 모두 저작도구가 소유한다. 이어쓰기는 마지막으로 저장한 프레임을 여는데, 그 자리는 본인 저장 작업 목록 조회 응답이 알려 주며 화면이 추측하지 않는다. [폐기] 데이터마트 영상 목록 조회 단계는 저작도구에 두지 않는다 — 그 목록의 소유가 Host 로 이전되면서 조회 창구도 함께 폐기됐다. 보존기간 만료 예정일 고지는 그 창구가 지고 있던 책임이라 본인 저장 작업 목록 조회가 이어받는다.

이 경로에는 모든 조회·저장이 공통으로 통과하는 게이트가 둘 있고 순서가 같다. 첫째는 노출 범위로, 검수 승인(APPROVED)된 영상만 포털에 나가며 미존재 영상도 같은 거부 응답을 받아 실재 여부가 응답 코드로 드러나지 않는다. 둘째는 비식별 누락 신고 게이트로, 신고가 열린 구간에서는 라벨 좌표도 프레임 이미지도 내보내지 않는다 — 좌표는 개인정보의 위치를 특정하는 정보이므로 내부 경로와 같은 단일 판정기를 재사용하고 포털 쪽에서 다시 구현하지 않는다. 게이트가 매 요청 평가되도록 프레임 이미지 응답은 재사용을 허용하지 않는다.

저장은 원본 라벨(LS_DATA_LBL)과 데이터마트를 수정하지 않고 LS_PORTAL_USER_LABEL 에 회원별로 별도 적재하는 단방향이며, 조회는 토큰의 회원 식별자 스코프로만 이뤄져 타인의 작업분이 섞이지 않는다. 프레임 라벨 Load 는 본인 작업분이 있으면 그것만, 없으면 데이터마트 원본 라벨을 초기값으로 돌려준다. ⚠ **[단일 배포 전제 — 재정합 대상]** 「데이터마트 원본 라벨을 초기값으로 돌려준다」에서 그 원본의 조달원은 **저작도구 자신의 DB 에 있는 검수 승인 자산**이며, 이는 저작도구가 **한 벌로 배포되던 전제**다. 2026-08-31 확정(ADR-012)으로 저작도구는 **채널별로 별도 배포**되고 각 배포본이 **자기 별도 DB 에만** 연결하므로 **포털 채널 배포본에는 그 자산이 없다.** 대체 조달은 **관제가 비식별 산출물을 포털로 전달 → 포털이 포털 채널 배포본에 알림 → 그 배포본이 배포물을 자기 DB 에 적재해 서빙**하는 방향이나 **조회 창구가 포털 회신 대기로 미확정**이다. 본인 작업분(포털 전용 저장소) 축과 게이트 두 겹은 이 변경과 무관하게 유효하다.

라벨 형태는 BBOX·POLYGON 만 허용한다. 포털에는 오토라벨링·객체 자동 분할과 추적·키포인트·트랙 번호 변경과 병합·검수·버전관리를 두지 않고, 외부 분석 서버로 나가는 위탁 연동도 두지 않는다. 다만 위탁 연동을 두지 않는다는 것이 데이터마트에서 불러온 메타의 표시·수정까지 막는다는 뜻은 아니다 — 촬영환경·프레임 설명·개인정보 판정·시계열 메타와 이벤트 어노테이션은 포털 작업 화면이 보여주고 회원이 직접 고치며, 그 결과는 라벨과 같은 축으로 포털 전용 저장소에만 단방향으로 쌓인다. 그 메타 축이 이 시퀀스에 등장하지 않는 것은 미제공이어서가 아니라 이 시퀀스가 라벨 작업 축을 그리기 때문이다.

조회 응답은 라벨마다 라벨 마스터 참조와 트랙 식별자를 함께 싣고, 저장 요청은 그 값을 그대로 되돌려 받아 데이터마트 원본이 갖고 있던 분류·트랙 연결이 저장 왕복에서 끊기지 않게 한다. 저장 응답과 본인 작업 라벨 목록도 같은 형태로 두 값을 돌려주며, 담기는 값은 요청에 실려 온 값이 아니라 서버 판정을 거쳐 실제로 적재된 값이다. 이는 보존 장치이지 편집 수단이 아니다 — 화면은 두 값을 표시하지 않고, 트랙 번호 변경·병합은 포털에 두지 않는다.

본인 작업 데이터 다운로드는 이 시퀀스가 그리지 않는다. 대응 엔드포인트가 없어서가 아니라 — 데이터마트 작업 데이터를 내려받는 전용 경로는 이 채널에 있다 — 이 시퀀스의 범위가 영상 선택부터 본인 작업 라벨 저장까지의 라벨 작업 축이기 때문이다. 내려받는 산출물의 구조는 그 다운로드 경로가 정하며 여기에 옮겨 적지 않는다.
