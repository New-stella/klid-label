## description

포털 회원(PORTAL_USER)이 본인 이미지·영상을 직접 올려 수동 라벨링하고 본인 데이터를 내려받는 흐름의 시퀀스 다이어그램. 이미지 다건 업로드, 영상의 재개 가능 업로드와 프레임 추출, 프레임 단위 라벨 전체교체 저장, 라벨 JSON 내보내기와 원본 파일 다운로드를 그린다.

이 경로는 데이터마트 영상 선택 경로와 저장소부터 분리돼 있다. 자산·프레임·라벨은 포털 업로드 전용 테이블(LS_PORTAL_ULD · LS_PORTAL_ULD_FRME · LS_PORTAL_ULD_LBL)과 업로드 세션 테이블(LS_PORTAL_TUS_ULD)에 적재되고 파일도 포털 전용 저장 경로에 기록되며, 내부 배치 파이프라인(비식별·마킹·시계열·오토라벨링)과 데이터마트 적재용 뷰로는 흘러가지 않는다. 회원이 직접 올린 자산이라 비식별 대상이 아니고 비식별 누락 신고 게이트도 적용되지 않는다 — 데이터마트 프레임을 포털로 내보내는 경로와 갈리는 지점이다.

자산 상태는 UPLOADED · PROCESSING · READY · FAILED 로 전이한다. 이미지는 추출할 프레임이 없어 업로드 확정 시점에 곧바로 READY 이며 프레임 한 행이 올린 이미지 자신을 가리킨다. 영상은 업로드 확정 시 UPLOADED 로 적재된 뒤, 업로드 트랜잭션이 커밋된 이후에만 프레임 추출이 시작된다 — 롤백된 업로드가 추출을 깨우지 않게 하기 위해서다. 추출은 시작 시 PROCESSING 으로 원자 전이하고 계산된 프레임을 모두 뽑은 뒤에야 READY 로 확정하며, 중간에 실패하면 부분 파일을 정리하고 FAILED 로 마감한다. 라벨링과 다운로드는 READY 자산에서만 성립한다.

라벨 저장은 프레임 단위 전체교체이고 빈 목록은 그 프레임의 라벨을 모두 지우는 유효한 요청이다. 검증은 삭제보다 먼저 전량 수행해, 일부만 유효한 요청이 기존 라벨을 지운 채 실패하는 일이 없게 한다. 라벨 형태는 BBOX·POLYGON 만 허용하며 오토라벨링·객체 자동 분할과 추적·시계열 메타·검수·버전관리는 이 경로에 없다.

조회·수정·삭제·다운로드는 모두 소유자 스코프로만 이뤄지고, 남의 자산이나 남의 업로드 세션을 가리키는 요청은 존재하지 않는 것과 같은 응답을 받아 실재 여부가 응답으로 드러나지 않는다.
