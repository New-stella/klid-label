## description

소재가 준비된 데이터셋에 든 영상을 페이지로 돌려준다. 데이터셋 소재 화면이 준비 완료를 확인한 뒤 부르며, 사용자는 이 목록에서 영상을 골라 포털 라벨링 화면([[SCREEN-029]])으로 들어간다.

대상은 출처 유형이 PORTAL_DATASET 이고 영상 메타의 데이터셋 번호(portal.dataset_id)가 경로의 datasetId 와 같은 영상이다. 등록 규약은 [[ADR-068]] 이 정한다.

★ 적재 시점이 둘로 갈린다 — 영상과 프레임은 소재가 준비된 뒤 원장에 등록되어 이 목록과 라벨링 화면의 재료가 된다. 라벨·메타·이벤트 어노테이션은 등록 단계에서 사용자 작업물로 쌓지 않는다. 배포본에 실려 온 기존 라벨은 라벨링 화면이 처음 불러오는 원본일 뿐이며, 사용자가 라벨링 화면에서 저장했을 때 비로소 포털 전용 저장소에 그 사용자의 작업물로 쌓인다. 저장하지 않은 영상은 사용자 작업물이 아니므로 내 작업 목록에 실리지 않는다.

★ 등록은 소재 준비 뒤에 이어지는 별도 단계라 준비 완료 직후에는 아직 끝나지 않았을 수 있다 — 그래서 목록과 함께 registrationState 를 싣는다. IN_PROGRESS 면 화면이 기다렸다 다시 부르고, FAILED 면 실패를 알린다. 준비 완료가 곧 등록 완료라고 가정하지 않는다.

★ 등록 상태는 진행 중(IN_PROGRESS)·완료(DONE)·실패(FAILED) 셋이다. 소재는 준비됐는데 등록 표식이 없거나, 진행 중 표식이 10분(소재 조달 상태를 자동으로 확인하는 예산과 같은 기준)보다 오래됐고 실제로 진행 중인 등록 작업이 없으면, 이 창구가 등록을 다시 시작시키고 IN_PROGRESS 로 답한다 — 재기동 등으로 끊긴 등록을 회복하는 경로다. 등록은 클립 식별자 기준 멱등이라 다시 시작해도 행이 늘지 않는다. DONE 이 아니면 지금까지 등록된 영상만 싣는다.

★ 목록은 데이터셋 단위로 공유되지만 lastSavedAt·entrySrcSn 은 요청한 사용자 기준이다 — 다른 사용자의 저장 여부가 섞이지 않는다. 사용자 격리 키는 토큰 주체다.

★ 행의 값은 이렇게 채운다 — frameCount 는 그 영상의 프레임 수, labelCount 는 등록된 원본 라벨 수다(사용자가 저장한 라벨 수가 아니다). entrySrcSn 은 요청 사용자가 그 영상에 저장한 라벨의 마지막 프레임이고, 없으면 첫 프레임, 프레임이 0건이면 비어 있다. lastSavedAt 은 요청 사용자의 세 저작물(저장 라벨·메타 오버레이·이벤트 어노테이션 오버레이) 중 가장 늦은 저장 시각이며, 내 작업 목록([[API-225]])의 저작 시각 판정과 같은 판정을 쓴다 — 따로 셈하면 두 목록이 같은 영상의 저장 여부를 다르게 말한다. 저장한 적이 없으면 비어 있다.

영상 식별자와 프레임 식별자는 원장 식별자라 포털 라벨링 화면의 진입 경로와 같은 축이다. 정렬은 영상 이름 오름차순이다. 영상 이름은 원본 파일명이고, 없으면 클립 식별자다. 페이지 크기는 1~100 이며 기본 20 이다.

★ 등록 영상에는 검수 상태가 없다 — 검수 승인 상태를 꾸며 넣지 않으며, 라벨링 창구는 포털 작업 가능 판정(검수 승인 또는 출처 PORTAL_DATASET, [[ADR-068]])으로 열린다.

소재가 준비되지 않은 데이터셋(가져온 적 없음·진행 중·실패)은 409 로 거부한다 — 화면은 이 창구가 아니라 상태 조회 창구로 그 상태를 판정한다. 등록이 완료되지 않은 것은 409 가 아니라 200 과 registrationState 로 답한다. 토큰이 없거나 만료되면 401, 포털 회원이 아니면 403 이다.
