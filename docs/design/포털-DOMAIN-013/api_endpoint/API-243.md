**인증 축의 정본은 INT-014 가 소유한다.** 계약을 여기에 옮겨 적지 않는다 — 두 곳에 적으면 한쪽만 갱신돼 어긋난다. 이 창구는 그 축을 그대로 따르며, 그 귀결로 **키가 설정되지 않았으면 맞출 값이 없어 이 창구는 닫힌다.** 값이 없을 때 열리는 쪽이 아니라 닫히는 쪽이 기본값이다.

**[갱신] 미확정이 닫혔다 — 근거는 포털 회신이다.** 직전 서술이 미확정이었던 것은 포털 회신에 이 창구가 없어 근거가 없었기 때문이고, 이번에 그 회신이 와서 미확정을 닫은 것이다. **판단이 뒤집힌 것이 아니다.** 이 구분을 지우지 말 것 — 지우면 다음 사람이 「또 뒤집혔다」로 읽는다.

⚠ **[폐기] 「미확정은 아직 정해지지 않았다는 뜻이지 토큰 축이 폐기됐다는 뜻이 아니다. 어느 쪽으로도 단정하지 말 것.」** 그 지시는 확정으로 닫혔다. 이 창구는 API 키 축이다.

⚠ **[폐기] 「아래 헤더 파라미터와 거부 규칙에 적힌 토큰 어휘는 확정 전의 잠정 기재다.」** 그 잠정 기재는 이번에 키 축으로 갈아끼워 닫혔다. 두 폐기 지시를 지우지 않고 남기는 이유는 낡은 지시문이 다음 라운드의 작업 지시로 읽혀 확정된 축을 되돌리기 때문이다.

**성질 하나는 처음부터 확정돼 있었다 — 전 사용자를 가로지르는 집계라 사용자 세션이 없다.** 이 응답은 한 사람의 자료가 아니라 전체를 센 숫자다. ⚠ 다만 **이번 확정의 근거는 포털 회신이지 이 성질이 아니다.** 이 성질에서 곧바로 인증 수단을 도출했던 구 단정이 이미 한 번 폐기된 적이 있으므로 그 구분을 유지한다.

## 주고받는 것
요청은 기준일 하나고 응답은 건수 하나다. 포털이 제시한 규격을 저작도구가 수용한 형태다.

**일자 경계는 한국 표준시 자정이다.** 기준일 하루는 그 시간대의 자정부터 다음 자정 직전까지를 뜻한다.

## 거부 규칙 — 서버간 창구가 함께 쓰는 규칙
| 상황 | 응답 |
|---|---|
| 키 헤더가 없거나 값이 다르다 | 401 인증 실패 |
| [미발생] 주체 축 불일치 — 이 창구에서는 성립하지 않는다 | 403 권한 없음 |
| 요청 값이 형식이나 필수를 어긴다 | 400 검증 실패 |

**이 창구의 인증에는 만료라는 개념이 없다.** 고정 문자열의 값 비교뿐이라 만료로 거부되는 경우가 없다.

403 은 이 창구에서 나오지 않는다. 사전 공유 API 키에는 주체가 없어 주체 축 불일치라는 사유 자체가 성립하지 않는다. 그래도 목록에서 지우지 않고 표기로 남긴다 — 없어진 것과 원래 없는 것은 읽는 쪽에 다르게 읽혀야 한다. 구 서술은 토큰의 부재와 서명 불일치와 만료를 401 사유로, 토큰 주체 축 불일치를 403 사유로 두었다.

⚠ 거부 응답에 내부 경로와 예외 흔적과 저장 구조를 싣지 않는다.

집계할 것이 하나도 없는 날은 오류가 아니다. 건수를 영으로 답한다 — 오류로 답하면 포털 배치가 재시도를 반복하면서도 영원히 값을 얻지 못한다.

## 경로는 초안이다
경로 문자열과 파라미터 이름과 operationId 와 응답 필드 이름은 저작도구가 정의해 포털에 통보할 초안이며 아직 상호 확정 전이다. 포털이 이 값을 받아 호출부를 만든다.

인가 규칙이 다른 창구가 같은 경로 접두를 쓰지 않도록 갈랐다. 사용자 주체로 부르는 창구는 포털 사용자 채널 접두 아래 두고, 사전 공유 키로 부르는 이 서버간 창구는 그 접두 밖의 별도 접두 아래 둔다. 한 접두에 섞으면 나중에 인가 설정이 뭉개진다.

## 식별자 표기
포털은 별개 프로젝트라 산출물 번호 체계가 저작도구와 겹치며 같은 번호가 양쪽에서 서로 다른 것을 가리킨다. 포털 창구를 인용할 때는 소속 프로젝트를 접두로 밝히거나 경로와 역할로 식별한다.

## 집계 대상 — 포털 회원의 작업이다
이 창구가 세는 것은 **포털 회원의 작업**이다. 저작도구 전체를 세지 않는다. 이 지표를 쓰는 쪽이 포털이므로 세는 대상도 포털 회원의 작업이다.

★ **이 확정이 설계를 단순하게 만든다.** 포털 채널 배포본이 **자기 저장소만 세면 된다** — 채널마다 따로 배포된 저작도구의 숫자를 가져와 합칠 필요가 없다. 이 이유를 함께 적어 두지 않으면 다음 사람이 「전체를 세야 하는 것 아닌가」로 되돌린다.

⚠ **닫힌 것은 범위뿐이고 판정 기준은 아직 없다.** 포털 회원의 작업을 무엇으로 식별하는지는 정해지지 않았다. 지어내지 말 것 — 아래 열린 항목이다.

## 열린 항목
- **[갱신] 이 창구의 인증 수단이 확정됐다** — 사전 공유 API 키이며 같은 연동점의 정리 삭제 트리거 창구와 같은 키다(위 「인증」 절). 근거는 포털 회신이다. 미확정으로 두고 토큰이라고도 API 키라고도 단정하지 말라던 구 서술은 이 확정으로 닫혔다. 정본은 INT-014 다.
  - ★ **그 귀결로 같은 경로 접두의 두 창구가 같은 인증 수단과 같은 키를 쓰게 되어 접두 전체를 한 덩어리로 다룰 수 있다.**
  - ⚠ **다만 권한을 부여하는 판정은 창구를 정확히 지목한다.** 이 창구를 실제로 열 때 그 지목 대상을 함께 넓히지 않으면 인가 요구는 걸리는데 권한을 세울 자가 없어 전건 거부된다. 닫히는 방향이라 안전하지만 누락하면 조용히 안 된다.
- **[갱신] 집계 대상 범위는 닫혔다** — 포털 회원의 작업이다(위 「집계 대상」 절). 저작도구 전체를 세는 쪽과 채널별 배포본 합산을 전제하던 구 서술은 폐기다. 되살리지 말 것.
- **포털 회원의 작업을 무엇으로 식별하는지 정해지지 않았다.** 자산의 출처 판별자로 가르는지 소유자 식별자로 가르는지 회신되지 않았다. 어느 쪽으로도 단정하지 말 것.
- 저작 작업 한 건을 무엇으로 세는지(저장 횟수인지 작업 개수인지)가 정해지지 않았다. 범위가 닫혔으므로 이 축은 더 이상 범위를 기다리지 않는다.
- **[대체] 공유 서명키의 구조와 값 교환은 이 창구에 더 이상 해당하지 않는다** — 그 서술은 토큰 축 한정이며(정본 INT-014), 이 창구가 API 키 축으로 확정되면서 적용 범위가 갈렸다. 구 항목은 새 키를 두지 않고 기존 인증 인계 축의 대칭 키를 그대로 쓰되 배포 시점에 그 값을 설정으로 채우는 일이 남았다고 두었다. 이 창구에서 교환할 것은 **API 키 값** 하나로 대체됐다. 지우지 않고 대체 표기로 남긴다 — 해소된 것과 대체된 것은 다르다.
- **[대체] 포털이 말한 그 키가 우리 검증 키와 물리적으로 같은 값인지 묻던 항목도 이 창구에는 해당하지 않는다** — 같은 이유로 토큰 축 한정이다. 이 창구의 키는 저작도구가 생성해 공유하는 별개 값이라 기존 검증 키와의 물리 동일성을 물을 대상이 없다. 구 항목은 같으면 설정 추가조차 없고 다르면 검증 경로에 키를 하나 더 두는 분기가 필요하다고 두었다.
