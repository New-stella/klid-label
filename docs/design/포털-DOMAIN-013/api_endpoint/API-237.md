## description

포털 사용자가 확인·수정·추가한 이벤트 어노테이션을 적재한다. 대상은 자산 출처를 가리지 않는다 — 데이터마트에서 불러온 영상과 본인이 올린 영상 둘 다이며, 포털의 라벨링 화면이 하나로 합쳐져 두 출처를 같은 화면에서 다루기 때문이다. 저장처는 화면이 가르지 않고 서버가 자산 출처로 판정한다 — 화면은 어느 쪽인지 알 필요가 없고 어느 출처든 같은 저장 요청을 보낸다. 데이터마트 자산은 본인 오버레이(LS_PORTAL_USER_EVNT_ANNO)에 적재한다. ★원본(LS_EVNT_ANNO)과 승인 시점 동결본을 수정하지 않는다 — 단방향이라 데이터마트로 되돌아가지 않으며 관제 통지·산출물 재생성을 일으키지 않는다. 그 오버레이의 적재 키는 (포털사용자, 영상)이라 영상당 한 벌이고 다시 저장하면 덮어쓴다. 본인이 올린 자산은 오버레이를 거치지 않고 그 자산의 어노테이션에 그대로 적재한다 — 원본이 본인 것이라 가려 둘 원본이 없다.

★★원본을 수정하지 않기 위해 기존 내부 저장 창구를 재사용하지 않는다. 이벤트 어노테이션을 고치는 내부 창구는 저장하면서 원장을 직접 고치고, 재검토 표시를 세우고, 관제 통지를 발행하고, 승인 시점 동결본에 영향을 준다. 포털이 그 창구를 그대로 부르면 이 창구의 최상위 불변 두 가지를 한 번에 위반한다 — 원본과 동결본을 수정하지 않는다 / 관제 통지와 산출물 재생성을 일으키지 않는다. 이 위반은 중복 구현을 피하려는 가장 자연스러운 판단에서 나오므로 금지로 못박는다. 재사용하는 것은 읽기와 규칙이다 — 본문 구조의 유효성 규칙은 그 규칙을 소유한 쪽을 그대로 쓴다. 복제하면 두 번째 진실원이 되어 소유자가 규칙을 바꾸는 날 포털만 조용히 뒤처지기 때문이며, 읽기 경로에는 부작용이 없다. 재사용하지 않는 것은 저장 동작이다 — 원장 쓰기·재검토 표시·관제 통지·동결본 관련 어느 것도 포털 경로에서 일어나지 않는다.

비식별 누락 신고가 열려 있는 영상은 이 창구도 거부한다(412). 같은 채널의 형제 창구(포털 프레임 라벨 저장·포털 프레임 이미지 서빙·포털 프레임 메타 저장)가 이미 그 구간에서 차단되므로, 이 창구만 열려 있으면 저장만 막고 어노테이션 쪽으로 우회가 성립한다. 응답 코드와 사용자 메시지는 형제 창구와 같은 값을 쓴다 — 형제와 다르면 응답 자체가 영상 상태를 알려 주는 단서가 된다. 포털 사용자가 직접 올린 업로드 자산은 이 게이트의 대상이 아니다 — 내부 파이프라인의 비식별 라이프사이클이 없다.

★무변경 저장은 오버레이 행을 만들지 않는다. 받은 본문이 원본의 현재 본문과 같으면 오버레이 행을 만들지 않고, 이미 있으면 지운다. 무변경 저장이 행을 만들면 그 영상이 저작물을 보유한 행으로 본인 작업 목록에 등재되고 보존기간 기산점까지 서는데, 사용자가 열어 보기만 하고 아무것도 고치지 않았는데 「내 작업물」이 생기고 만료 시계가 도는 것은 틀린 동작이다. 이는 형제 창구의 자동 계산값 승격 차단과 같은 목적이되 판정 단위가 다르다 — 형제 창구는 항목마다 가르지만 이 창구는 구조체 한 벌을 통째로 덮어쓰므로 항목별 판정 단위가 없어 구조체 전체로 판정한다. 같다는 판정을 어떤 방식으로 하는지는 구현이 정하며 사양이 고정하지 않는다. 인지하고 받아들이는 대가로, 사용자가 원본과 똑같은 내용을 일부러 확정해도 본인이 저장했다는 흔적이 남지 않는다.
