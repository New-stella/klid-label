## description

포털 회원이 본인이 올린 영상을 재생한다. 마킹 화면의 재생 원본이며 구간 요청을 지원해 되감기·건너뛰기·배속 재생이 성립한다.

[서빙 대상은 사용자가 올린 원본이다] 이 경로의 자산에는 비식별 단계가 없다 — 가려진 사본이 만들어지지 않으므로 원본을 그대로 서빙한다. 내부 채널 영상 스트리밍이 갖는 「항상 가려진 사본을 서빙하고 그것이 없으면 원본을 감춘다」는 규칙을 이 경로로 옮겨 오지 말 것. 그 규칙은 가려진 사본이 존재한다는 전제 위에 서 있고 이 경로에는 그 전제가 없다.

[상태를 묻지 않는다] 프레임 추출이 끝났는지를 조건으로 걸지 않는다. 마킹이 추출보다 앞서므로 추출 전에 재생할 수 있어야 하고, 추출이 끝난 뒤에도 다시 볼 수 있어야 한다. 재생을 막는 것은 파일이 아직 갖춰지지 않은 경우 하나뿐이다.

[호출 방식은 둘이다] 포털 토큰을 실은 직접 호출과, 서명 주소 발급 창구에서 받은 단기 서명 질의로 하는 호출이다. 재생 요소가 인증 헤더를 싣지 못해 후자가 필요하며, 서명은 발급 시점에 소유자 판정을 거치므로 최종 접근 가능한 주체는 같다.

[본인 자산이 아닌 경우와 없는 자산을 한 코드로 거부한다] 두 경우를 상태코드로 가르면 남의 자산이 있는지 없는지가 응답으로 드러난다. 포털 자산 창구가 이미 쓰고 있는 규칙과 같다.

[응답을 저장하지 않게 한다] 본인 자산이라도 중간 저장소에 남기지 않도록 캐시 금지로 내려보내고, 자산 식별자로 지정된 것 밖의 파일에 닿지 못하도록 경로를 검증한다.
