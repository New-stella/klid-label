### rawSn

- **in**: path

**schema**:

#### type

#### format

int64

- **required**: true
- **description**: 다운로드할 데이터마트 영상 식별자

## description

본인이 저장한 작업 라벨을 기준으로, 프레임 이미지 + 라벨 JSON + 비식별 영상(존재 시)을 ZIP 하나로 묶어 반환한다. 라벨 JSON은 프레임마다 본인 저장분이 있으면 그것을, 없으면 데이터마트 원본 라벨을 담는다(GET 프레임 라벨 병합 정책과 동일 축). 비식별 영상 경로가 없으면 영상 파일 없이 라벨·이미지만 담는다(원본 폴백 금지).

ZIP 내부 구조: {rawSn}/frames/{FRM_NO 4자리 zero-pad}.jpg(비식별 프레임 이미지) + {rawSn}/frames/{FRM_NO 4자리 zero-pad}.json(그 프레임의 어노테이션 문서 — 이미지와 같은 자리에 이름만 다른 짝으로 둔다) + {rawSn}/video.{ext}(비식별 영상, 있을 경우만). 각 어노테이션 문서는 검수 승인 학습데이터 산출물과 같은 NIA COCO 확장 구조를 따른다 — 최상위 키는 info · dataset · licences · video · event · image · annotations · categories · type 이고, 좌표는 annotations 항목의 bbox · polygon · keypoints 로 표현한다. 영상 단위로 라벨을 한 문서에 모아 담던 자체 형태는 두지 않는다. 같은 라벨의 좌표 표현이 두 형태로 갈리면 한쪽만 갱신될 때 조용히 어긋나므로 두 형태를 병존시키지 않는다(설계 결정). 통일하는 또 하나의 근거는 학습데이터 산출 문서가 차후 데이터마트로 다시 읽혀 적재되는 왕복 자산이라는 점이다 — 구조가 다르면 그 경로에 들어갈 수 없다.

어노테이션 문서의 메타 블록(개인정보 관련 필드 · 이벤트 식별자 · 상황 묘사)은 검수 승인 학습데이터 산출물과 같은 조달 규칙을 따르며, 조달처는 검수 승인 시점에 동결된 영상 메타 스냅샷이다. 조달 규칙 자체를 이 엔드포인트가 따로 정의하지 않는다 — 같은 규칙을 두 곳에 적으면 한쪽만 갱신돼 어긋나기 때문이다.

이미지는 비식별본만 담는다. 검수 승인 산출물이 원본과 비식별본을 함께 내는 것과 다르며, 포털 채널의 원본 비노출 규칙이 우선하기 때문이다. 어노테이션 문서의 image · video 블록이 참조하는 경로도 비식별 기준으로 산출하며, 원본 경로는 이 산출물에 싣지 않는다.

데이터마트 노출(검수 완료 APPROVED) 영상만 대상이며, 비식별 누락 신고 구간에는 412. 본인 저장 라벨이 한 건도 없는 경우(작업 시작 전, 또는 보존기간 만료로 삭제된 경우)는 410. 접근 판정은 데이터마트 미노출 거부 → 비식별 신고 구간 거부 → 본인 저장 라벨 없음 순으로 하며, 이 순서는 응답이 그 영상의 상태를 알려주는 오라클이 되지 않게 하는 장치라 바꾸지 않는다.

내려받는 도중 사용자가 중단해 클라이언트가 연결을 끊으면 서버는 남은 전송을 이어가지 않고 그 시점에 멈춘다. 중단은 실패가 아니므로 서버 오류로 다루지 않으며 받다 만 산출물을 남기지도 않는다. 중단한 뒤 다시 받는 것은 새 요청이라 요청량 제한을 그대로 적용받는다. 요청 제한시간은 산출물을 끝까지 받아낼 수 있는 값이어야 한다 — 영상이 포함되면 산출물이 커지므로 일반 조회용 기본 제한시간을 그대로 쓰면 정상적인 대용량 다운로드가 구조적으로 실패한다. 이 값은 설정으로 조정하며, 요청이 지나는 경로 중 가장 작은 상한이 실제 상한이 되므로 경로 전체에서 함께 맞춘다.
