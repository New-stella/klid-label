### notes

포털 채널의 증강이 저작도구 안에서 종결된다는 확정에 맞춰 신설했다. 요청 상태의 개별 값역은 화면 사양이 열어 둔 그대로 두고, 화면이 상태 값으로 분기하지 않도록 결과 도착 여부를 별도 값으로 실었다. 다만 그 하나로는 기다리는 중과 실패가 갈리지 않아 화면이 요구하는 세 구분이 성립하지 않으므로, 단건 조회가 이미 쓰는 실패 사유를 같은 이름과 형태로 목록 행에도 실었다. 그 값은 외부 채널로 그대로 나가므로 사용자에게 보여 줄 수 있는 문장으로 제한한다. 상태 필터와 정렬 파라미터는 확정된 바가 없어 두지 않았다.

## description

포털 회원이 낸 증강 요청을 최근 것부터 페이징해 돌려준다. 포털 증강 화면(SCREEN-044)의 요청 현황 목록이 이 창구를 쓴다.

[본인이 낸 요청만 나온다] 다른 사람이 낸 요청은 목록에 담기지 않는다. 대상은 본인이 올린 영상에 한정되며 데이터마트에서 불러온 영상은 대상이 아니다.

[행이 나르는 것] 요청 일시, 대상 영상, 요청할 때 지정한 생성 조건, 요청 상태, 결과 도착 여부, 실패 사유. 생성 조건을 함께 싣는 것은 같은 영상에 여러 요청이 공존할 때 결과를 구분하는 축이 그 조건이기 때문이다.

[요청 상태의 값역은 이 산출물에서 정하지 않는다] 결과를 기다리는 중인지, 도착했는지, 실패했는지를 구분한다는 데까지가 이 창구가 정하는 바이며 개별 표시 값은 정하지 않는다. 값역이 열려 있으면 화면이 상태 값 자체로 분기할 수 없으므로, 결과가 도착했는지와 실패했는지를 각각 별도 값으로 함께 싣는다.

[실패는 목록 행 자체에서 가려진다] 화면은 기다리는 중·도착·실패 셋을 구분해야 하는데 결과 도착 여부 하나로는 앞의 둘밖에 가르지 못한다. 그래서 실패 사유를 행에 함께 싣는다. 결과 도착 여부가 참이면 도착이고, 거짓이면서 실패 사유가 비어 있으면 기다리는 중이며, 거짓이면서 실패 사유가 차 있으면 실패다. 실패를 가려내려고 행마다 단건 조회를 부르게 하지 않는다.

[실패 사유가 비어 있다는 것은 아직 실패하지 않았다는 뜻이다] 기다리는 중인 요청과 결과가 도착한 요청은 이 자리가 비어 있다. 빈 값을 실패로 읽지 않으며, 실패를 판정하는 축은 이 자리가 차 있는지 하나뿐이다.

[실패 사유는 사용자에게 보여 줄 수 있는 문장이어야 한다] 이 응답은 외부 채널인 포털로 그대로 나간다. 내부 오류 코드, 파일 경로, 데이터 제약 이름, 연동 상대가 돌려준 원문을 그대로 실으면 안 된다. 무엇이 잘못됐는지를 요청한 사람이 읽을 수 있는 문장으로 담으며, 담을 사유를 알 수 없으면 지어내지 말고 일반적인 실패 안내 문장을 쓴다.

[실패한 요청도 조회는 성공이다] 실패는 이 창구의 오류가 아니라 목록이 나르는 사실이다. 성공 응답 안에서 실패한 행으로 표현하며 오류 응답으로 바꾸지 않는다.

[요청이 하나도 없는 것은 정상이다] 빈 목록을 성공으로 돌려주며 오류로 다루지 않는다.

[페이지 크기에 상한을 둔다] 무제한 조회를 막기 위해 페이지 크기를 상한으로 잘라 낸다. 상한을 넘는 값을 보내도 거부하지 않고 상한으로 줄여 처리한다.

[정렬은 고정이다] 요청 일시 내림차순으로 고정하며 정렬 기준을 요청 파라미터로 받지 않는다. 받으면 정렬 키 허용 목록을 따로 유지해야 하는데, 이 목록에는 최근 것부터 보는 것 말고 다른 순서가 필요하지 않다.

[이 창구는 파일을 내보내지 않는다] 결과물을 가리키는 위치와 내려받기 진입은 단건 조회가 담당한다.
