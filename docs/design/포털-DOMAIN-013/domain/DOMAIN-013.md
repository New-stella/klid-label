- 구 서술 '오토라벨링(YOLO/SAM2)·SAM2 분할·SAM2 추적·키포인트(SKELETON)·VLM 시계열·버전관리·검수는 두 경로 모두 제공하지 않는다'는 폐기 3 으로 본문에 남겼다.

### 2026-08-27 — INT-013 v8 cascade
- 포털 회신 수용으로 임베딩 협의가 전부 해소돼, 확정 사양으로 서술할 단계가 아니라던 직전 판단의 전제가 소멸했다. 그래서 비워 뒀던 도메인 본문에 임베딩 진입 경로를 넣었다.
- 진입 경로는 경로 A·B 와 다른 축이라 새 분류 체계를 만들지 않고 공통 절에 두었다. 경로 A·B 는 작업 대상을 가르고 진입 경로는 유입 지점을 가른다.
- 진입 경로가 정하는 것은 화면 축뿐임을 함께 적었다. 서버 인가 판정의 진실원은 토큰 클레임(채널·역할)이며 진입 경로는 클라이언트가 주장하는 값이라 위조할 수 있다.
- 상세 규약(진입점 이름·마운트 경로·번들 서빙·인계 창구)은 INT-013 이 소유하므로 복제하지 않고 가리키기만 했다.

### 2026-09-01 — ADR-013 v13 · INT-013 v16 cascade
- 데이터마트 목록의 소유가 Host(포털)로 이전된 사실을 경로 A 서술에 반영했다. 구 서술은 영상을 고르는 화면까지 저작도구 범위로 읽혔다.
- Host 가 갖는 것은 목록 화면과 저작 화면 진입 링크 둘뿐이고, 저작 화면·세션 생성·소재 적재·저장·본인 저장 작업 목록·내려받기는 저작도구가 소유한다는 경계를 함께 적었다.
- 저작 화면 진입이 두 갈래임을 적었다. 데이터마트 목록에서 들어오면 새로쓰기이고 그 링크는 외부 계약이며, 본인 저장 작업 목록에서 들어오면 이어쓰기이고 이는 내부 이동이다. 진입 규약 상세는 INT-013 이 소유하므로 복제하지 않고 가리켰다.
- 기능 범위는 줄지 않는다는 점을 명시했다. 바뀐 것은 고르는 화면의 주인뿐이며 라벨 확인·수정·저장·내려받기는 그대로다.
- 용어 데이터마트 Load 에도 같은 경계를 덧붙였다.

### 2026-09-01 — ADR-013 v15 cascade
- 저작 저장물(본인이 저작 중 저장한 것)에 대해 저작도구 화면이 소유하는 것을 목록·이어쓰기 진입·결과물 내려받기·만료 예정일 표시 넷으로 적었다.
- 화면 소유와 데이터 공급이 별개 축임을 명시했다. 외부 채널이 요약·연계 목적으로 그 목록을 조회해 가는 것은 계속 가능하되, 목록 조회와 파일 내려받기는 다른 축이라 내려받기는 저작도구 화면에서만 일어난다.
- 본인 저장 작업 목록과 데이터마트 영상 목록이 서로 다른 목록임을 못박았다. 같은 날의 데이터마트 목록 소유 이전(Host)을 뒤집지 않는다.
- 포털 채널의 증강을 저작도구가 자체 수행하며 요청·결과 확인·후속 작업·내려받기 넷이 모두 저작도구 안에서 끝난다고 적었다. 외부 채널이 제공하는 증강 요청 창구는 호출하지 않는다.
- 이 확정은 제공 범위를 넓히는 것이 아니라 주체와 종결 지점을 못박는 것이다. 대상이 업로드 영상 한정인 것과 미제공 목록(오토라벨링·SAM2 인터랙티브 분할·자동추적·키포인트·트랙 rename/merge·검수·버전관리)은 무변경이다.
- 포털 채널 증강 파생물은 포털 자산 계보에 두며 내부 파이프라인 계보에 넣지 않는다. 구체 저장 모델은 이번에 정하지 않아 테이블·컬럼을 적지 않았다.
- 결과 확인·후속 작업·내려받기를 담을 화면 배치는 이 ITEM 이 단정하지 않는다. 도메인 서술에는 책임과 종결 지점만 적었다.

### 2026-09-02 — 포털 증강 파생물 저장 모델 확정
- 앞선 라운드가 미뤄 둔 축을 확정했다. 미룬 근거였던 「포털 자산은 그 원장 밖에 있다」가 흡수(ADR-058)로 사라져 전제가 소멸했다.
- 파생물을 포털 업로드 자산 계보의 행으로 두었다. 공용 영상 원장에 새 행을 만들고 ORGNL_RAW_SN 으로 부모(요청 대상 업로드 영상)를 가리킨다. 결과 확인 창구가 포털 업로드 자산 식별자를 돌려주고 후속 작업·내려받기가 그 창구로 이어지던 기존 사양과 어긋나지 않는다.
- 출처 유형은 PORTAL_ULD 를 그대로 쓴다. 채널 판별 축(출처·소유자)을 흔들지 않아야 보존기간 만료 자동 삭제가 조건 수정 없이 파생물까지 잡는다. AUGMENTED 로 바꾸면 그 조건이 파생물을 놓쳐 비식별을 거치지 않은 본인 자산이 영구히 남고, 새 값을 만들면 포털을 가르는 모든 자리가 두 값을 열거해야 해 한 곳만 잊어도 조회·집계·삭제에서 조용히 샌다. 관제 채널이 파생에 AUGMENTED 를 쓰는 비대칭은 의도이며 일관성을 이유로 맞추지 않는다.
- 소유자(PORTAL_USER_NO)는 부모에서 상속한다. 소유자가 채널을 가르는 축이라 상속하지 않으면 파생 행이 내부 자산으로 읽힌다.
- 파생 깊이 1 은 그대로 두었고 검수 등재 게이트는 예외를 명시해 타지 않게 했다. 포털 경로에는 검수가 없어 게이트가 요구하는 승인 행이 영영 생기지 않으므로, 예외를 적지 않으면 파생물이 화면에서 통째로 사라진다. 해상도 파생이 같은 이유로 예외를 명시한 선례를 따랐다.
- 채택·반려 결정 단계는 두지 않는다. 이미 확정된 축이며 검수가 없기 때문이다.
- 마킹 축은 함께 확정하지 않았다. 산출물에 따라 마킹과 증강이 한 문장에 묶여 있으나 이번에 정해진 것은 증강 쪽뿐이라 본문과 용어 정의에서 갈라 적었다.

## description

외부 채널(포털 회원) 도메인. ★서로 다른 두 경로를 갖으며 기능 경계가 다르다 — 혼동하지 말 것.

[경로 A — 데이터마트 영상 라벨 작업] 관제가 구축해 포털 DB 에 적재한 데이터마트 영상을 대상으로 한다(적재는 관제서버 책임). ★영상을 고르는 데이터마트 목록 화면의 소유는 Host(포털)에 있다 — Host 가 갖는 것은 그 목록 화면과 거기서 저작 화면으로 보내는 진입 링크 둘뿐이고, 저작 화면·세션 생성·소재 적재·저장·본인 저장 작업 목록·내려받기는 저작도구가 소유한다. 저작 화면 진입은 두 갈래다 — 데이터마트 목록에서 들어오면 새로쓰기이고 그 링크는 외부 계약이며, 저작도구가 소유한 본인 저장 작업 목록에서 들어오면 이어쓰기이고 이는 내부 이동이다(진입 규약 상세는 INT-013 이 갖는다). ★저작 저장물(본인이 저작 중 저장한 것)에 대해 저작도구 화면이 소유하는 것은 목록·그 목록에서의 이어쓰기 진입·결과물 내려받기·만료 예정일 표시 넷이다. ⚠ 이 「본인 저장 작업 목록」과 위 「데이터마트 영상 목록」(Host 소유)은 서로 다른 목록이다 — 하나로 합쳐 서술하지 말 것이며, 데이터마트 목록의 소유 이전을 뒤집는 것도 아니다. ★화면 소유와 데이터 공급은 별개 축이다 — 저작도구가 화면을 갖더라도 외부 채널이 요약·연계 목적으로 그 목록을 조회해 가는 것은 계속 가능하다. 다만 목록 조회와 파일 내려받기는 다른 축이며, 내려받기는 저작도구 화면에서만 일어난다. ⚠ 이 이전으로 포털 채널의 기능 범위가 줄지는 않는다 — 바뀐 것은 고르는 화면의 주인뿐이고 라벨 확인·수정·저장·내려받기는 그대로다. ⚠ 구 서술 「데이터마트 영상을 고른다」를 목록 화면까지 저작도구가 소유한다는 뜻으로 읽지 말 것. 이때 Load 하는 기존 라벨·메타는 포털 DB 가 아니라 저작도구 DB 의 검수 승인(APPROVED) 자산(LS_DATA_RAW·LS_DATA_SRC·LS_DATA_LBL)이다 — 저작도구는 포털 DB 를 읽지 않는다. ⚠ **[단일 배포 전제 — 재정합 대상]** 「저작도구 DB 의 검수 승인 자산을 Load 한다」는 저작도구가 **한 벌로 배포되던 전제**다. 2026-08-31 확정(ADR-012)으로 저작도구는 **채널별로 별도 배포**되고 각 배포본이 **자기 별도 DB 에만** 연결하므로 **포털 채널 배포본에는 관제 채널 배포본의 승인 자산이 없다.** 대체 조달은 **관제가 비식별 산출물을 포털로 전달 → 포털이 포털 채널 배포본에 알림 → 그 배포본이 배포물을 자기 DB 에 적재해 서빙**하는 방향이다. ✅ **조회 창구가 확정됐다 (2026-09-03 포털 회신)** — 구 표기 「조회 창구가 포털 회신 대기로 미확정이며 확정 전까지 이 서술을 새 설계의 근거로 쓰지 말 것」은 이 회신으로 **해소**됐다. 소재(파일) 조회 창구는 **[포털]API-132** 이며, 그 응답이 알려주는 **NAS 절대경로**로 배포물을 읽는다 — 조달과 서버간 연동의 상세는 아래 [★서버간 연동] 절과 [[INT-014]] 가 갖는다. ⚠ **「포털 DB 를 읽지 않는다」는 그대로 유효**하며 상호 미접근 확정으로 오히려 강화된다. ⚠ 이 ITEM 의 용어 정의(**데이터마트 Load**)에도 같은 전제가 들어 있다 — 함께 읽을 것. 저장해도 원본·데이터마트는 수정되지 않고 사용자별 작업 데이터(LS_PORTAL_USER_LABEL)로 별도 적재된다(단방향, 마트로 반영 안 됨). 다운로드는 본인 작업 데이터 기준이고 기여도 점수는 없다. 경로 A 가 내보내는 프레임 이미지·라벨은 내부 파이프라인 자산이라, 비식별 누락 신고가 열린 영상이면 412 로 거부되고 그 응답은 Cache-Control: no-store 로 캐시되지 않는다 — 경로 B 의 본인 업로드 자산은 이 게이트의 대상이 아니다.

[경로 B — 본인 자산 업로드 (ADR-013 예외, 2026-07-17)] 포털 사용자가 본인 영상(mp4/mov/avi, 5GB, TUS 재개 업로드)을 직접 올려 수동 라벨링(BBOX/POLYGON 만) 후 본인 데이터를 내려받는다. 업로드 자산·프레임·라벨과 재개 업로드 세션은 공용 원장(LS_DATA_RAW·LS_DATA_SRC·LS_DATA_LBL·LS_TUS_UPLOAD)에 적재되며 포털 채널 전용 테이블을 두지 않는다(ADR-058). 내부 파이프라인(비식별→마킹→배치→검수)·데이터마트 View 로 흘러가지 않는 것은 그대로이나 그 근거가 바뀐다 — 출처 판별자(SRC_TYPE=PORTAL_ULD)와 소유자(PORTAL_USER_NO)로 가르고, 배치는 DB 트리거가 아니라 앱 이벤트로 시작하는데 포털은 자기 이벤트를 쓰므로 발동하지 않으며, 데이터마트 View 는 검수 승인 때만 생기는 동결 메타가 드라이버라 검수가 없는 포털 자산은 구조적으로 도달하지 않는다. 영상은 본인 데이터라 비식별을 적용하지 않으며 고정 간격 프레임 추출(기본 5초, 상한 2000장)만 한다. 상태는 UPLOADED→PROCESSING→READY|FAILED. 포털 사용자가 업로드한 본인 영상에 한해 이벤트구간 마킹과 AI 증강 연동을 제공한다(2026-07-17 본인 자산 업로드 예외의 연장) — 이 둘은 경로 B 전용이라 경로 A 의 데이터마트 영상에는 해당하지 않는다. ★포털 채널의 증강은 저작도구가 자체 수행한다 — 요청(대상 선택·생성 조건·외부 위탁)·결과 확인·후속 작업(증강 결과물에 대한 라벨링 등)·내려받기 넷이 모두 저작도구 안에서 끝나며, 외부 채널(Host)이 제공하는 증강 요청 창구를 호출하지 않는다. ⚠ 이는 제공 범위를 넓히는 것이 아니라 그 연동의 주체와 종결 지점을 못박는 것이며, 대상이 업로드 영상 한정인 것과 아래 미제공 목록은 그대로다. 포털 채널 증강 파생물은 포털 자산 계보에 속하며 내부 파이프라인 계보에 넣지 않는다. ★저장 모델이 정해졌다(2026-09-02 확정) — 파생물은 포털 업로드 자산 계보의 행이며, 공용 영상 원장에 새 행을 만들고 ORGNL_RAW_SN 으로 부모(요청 대상 업로드 영상)를 가리킨다. ①출처 유형은 PORTAL_ULD 를 그대로 쓴다 — 파생이라는 사실은 ORGNL_RAW_SN 이 말하므로 새 값을 만들지 않는다. 채널 판별 축(출처 + 소유자)을 흔들지 않아야 보존기간 만료 자동 삭제가 조건을 한 자도 고치지 않고 파생물까지 잡는다. 출처를 AUGMENTED 로 바꾸면 그 조건이 파생물을 놓쳐 비식별을 거치지 않은 본인 자산이 영구히 남는다. ⚠ 관제 채널은 파생에 AUGMENTED 를 쓰므로 두 채널이 비대칭이며 그것이 의도다 — 「일관성」을 이유로 맞추지 말 것. ②소유자(PORTAL_USER_NO)는 부모에서 상속한다 — 소유자가 채널을 가르는 축이라 상속하지 않으면 파생 행이 내부 자산으로 읽힌다. ③파생 깊이 1 은 그대로다 — 파생 행은 ORGNL_RAW_SN 이 채워져 있어 기존 가드가 재증강을 막는다. ④검수 등재 게이트는 타지 않으며 그 예외를 명시한다 — 그 게이트는 증강 검수 승인 행을 요구하는데 포털 경로에는 검수가 없어 그 행이 영영 생기지 않으므로, 예외를 명시하지 않으면 파생물이 화면에서 통째로 사라진다(해상도 파생이 같은 이유로 예외를 명시한 선례를 따른다). ⑤채택·반려 결정 단계는 두지 않는다(검수가 없다). ⚠ 정해진 것은 증강 파생물의 저장 모델뿐이다 — 경로 B 의 이벤트구간 마킹은 저장 모델이 아직 정해지지 않았으니 함께 확정된 것으로 읽지 말 것.

[★제공 범위 — 라벨 편집 도구] 두 경로 모두 수동 라벨링(BBOX/POLYGON)만 제공한다. 도형 종류는 서버 allowlist 로 강제되며(두 경로가 각각 자기 allowlist 를 갖는다) 그 외 값은 400 으로 거부된다. 좌표 개수도 타입별로 강제된다(BBOX 정확히 2점, POLYGON 3~200점).

[★제공 범위 — 메타·이벤트 어노테이션] 경로 A 로 불러온 데이터마트 영상의 메타(촬영환경·프레임 설명·개인정보 판정·시계열 메타 등 — 예시이며 전수 목록이 아니다)와 이벤트 어노테이션을 포털 작업 화면에 표시하며, 포털 사용자가 직접 수정·추가할 수 있다. 포털에서 고친 값은 포털 전용 저장소에만 적재하며 데이터마트와 원본(영상 메타 동결 스냅샷·이벤트 어노테이션 동결본)은 수정하지 않는다 — 경로 A 의 라벨 저장과 같은 단방향 축이다.

[★미제공 기능 — 폐기된 구 서술 포함] 오토라벨링(YOLO)·SAM2 인터랙티브 분할·SAM2 자동추적·키포인트(SKELETON)·트랙 rename/merge·검수·버전관리는 두 경로 모두 제공하지 않는다(ADR-013). 외부 시계열 분석 서버로 나가는 위탁 연동(호출·콜백)도 제공하지 않는다.
· 폐기 1 — 구 본문의 '오토라벨링 체험(YOLO+SAM2)'은 오류였다.
· 폐기 2 — 그 뒤 남아 있던 'SAM2 분할·추적과 키포인트는 경로 A 에만 부분 노출된다(ADR-013 부분 override)'도 폐기한다. 부분 override 는 존재하지 않는다.
· 폐기 3 — 그 문장이 함께 적고 있던 'VLM 시계열은 두 경로 모두 제공하지 않는다'도 폐기한다. 미제공의 축은 외부 시계열 분석 서버로 나가는 위탁 연동(호출·콜백)이며, 그 결과물인 시계열 메타를 화면에 표시하고 사람이 수정·추가하는 것은 미제공 대상이 아니다(위 제공 범위 참조).
근거는 두 축이 서로 다르다. ①SAM2 — 구 포털 전용 SAM2 핸들러 기반 노출은 ADR-013 위반으로 폐지됐다 — 포털 경로에는 SAM2 핸들러를 두지 않는다(API-130·API-131 도 같은 근거로 폐기). ②키포인트 — 위 두 allowlist 가 BBOX|POLYGON 만 허용해 fail-closed 로 막으며, 구 '포털 키포인트(SKELETON) 허용'은 폐기됐다(레거시로 적재된 SKELETON 행은 로드 시 조용히 스킵).
⚠ 미제공인 SAM2 인터랙티브 분할·자동추적·키포인트와 경로 B 에 제공하는 AI 증강 연동은 성질이 다른 축이라 함께 묶지 않는다. 전자는 포털 사용자가 외부 채널에서 직접 호출하는 추론 엔드포인트라 그 자체가 공격면이 되어 2026-08-03 보안 2차 전수검증에서 HIGH 로 판정됐고 그 판정은 그대로 유효하다. 후자는 서버가 서버로 보내는 비동기 위탁이라 포털 사용자가 외부 추론 엔드포인트를 직접 호출하는 구조가 아니다.
⚠ 내부(INTERNAL) 채널의 SAM2 분할·추적은 SFR-08-01(VOS) 핵심 기능이라 그대로 살아 있다 — 포털 미제공을 저작도구 전체 미제공으로 오독하지 말 것.

[★서버간 연동 — 포털과 저작도구의 서버가 서로의 창구를 직접 호출한다] 브라우저 안에서 두 화면이 함께 실행되는 임베딩 진입(아래 [공통] 참조)과 다른 축이다. 저작도구 WAS 가 포털 기반 구성의 구성자원으로 포털 내부망에 배치되므로 이 축의 호출은 모두 내부망 통신이고 외부 방화벽 경계가 없다. ⚠ 방화벽이 필요 없다는 것은 **포털 연동 축에 한정**한 서술이다 — 관제 연동 축의 방화벽 요건은 이 문장과 무관하며 그대로 유지된다.
· **저작도구가 부르는 것** — AI 사용량 보고는 증강을 실행하기 **전에** 부르는 차단형이고, 계상 단위는 요청 1건당 1이며 프레임 장수나 증강 종류 수와 무관하다. 보고가 성립하지 않으면 증강을 진행하지 않는다(실패를 닫는다). 위탁이 실패하거나 취소되면 그 차감을 되돌린다.
· **저작도구가 여는 것** — 저작 현황 요약 제공([[API-242]]) · 일일 저작 집계 제공([[API-243]] — 포털 배치가 호출해 가져간다) · 배포본 정리 삭제 트리거 수신([[API-244]]).
· **소재 조달** — 포털의 소재(파일) 조회 창구([포털]API-132)가 알려주는 **NAS 절대경로**로 배포물을 읽는다. 한 건의 소재는 배포 묶음 파일 한 건과 영상 0건 이상으로 이루어진다. ⚠ 그 창구의 응답 규격은 포털이 소유하므로 여기에 옮겨 적지 않는다 — 조달처만 가리킨다. 「포털 DB 를 읽지 않는다」는 그대로 유효하며, 우리가 읽는 것은 NAS 파일이지 포털 DB 가 아니다.
· **작업 저장소** — 저작도구에 작업영역 쓰기 권한이 부여되고 포털 소재영역은 읽기 전용으로 분리한다(읽는 자리와 푸는 자리를 가른다). 해제본 보존 기간은 사용자의 저작 최초 저장 시점부터 7일이며, 삭제 트리거를 받아도 즉시 지우지 않고 받은 시점부터 다시 7일 뒤에 지운다 — 즉시 지우면 사용자가 물고 있는 진행 중 작업이 깨진다.
⚠ 이 축의 인증·창구 구성·요청과 응답 계약은 [[INT-014]] 가 소유한다. 여기에 옮겨 적지 않는다 — 두 곳에 적으면 한쪽만 갱신돼 어긋난다.

[공통] 반응형 웹(PC/태블릿/모바일), WCAG 2.1 AA 준수. 인증은 포털 서버 발급 JWT 인계(channel 클레임으로 분기).
포털 채널에는 포털 화면 안의 지정된 자리에 저작도구 화면이 마운트되는 임베딩 진입 경로가 있다 — 포털이 Host, 저작도구가 Remote 다. 이것은 위 경로 A·B 와 다른 축이다: 경로 A·B 는 무엇을 대상으로 작업하는지를 가르고, 이 진입 경로는 사용자가 어디를 통해 들어오는지를 가른다. 진입점 이름·마운트 경로·번들 서빙·인계 창구 같은 상세 규약은 INT-013 이 갖는다.
임베딩으로 진입한 사용자는 포털 권한 사용자로 본다 — 화면 축 한정이다. 포털 채널 산출물은 그 권한 기준으로 화면·메뉴·기능을 게이팅한다. ⚠ 서버 인가 판정의 진실원은 토큰 클레임(채널·역할)이며 진입 경로가 권한을 올리지 않는다. 진입 경로는 클라이언트가 주장하는 값이라 위조할 수 있다.
