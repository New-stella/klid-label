# 관제 채널 토큰 추종과 세션 갱신 — 매 요청 현재 토큰·선제 갱신 1회·401 후 1회 재시도·관제 형식 저장·탭 간 중복 갱신 방지 (happy)

## notes

옛 refresh 토큰을 다시 쓸 때 관제 서버가 세션 전체를 끊는지는 확인되지 않았다. 관제 탭은 저작도구의 탭 간 직렬화를 모르므로 동시 갱신을 완전히 배제할 수 없고, 갱신 직전 저장소 재읽기 비교가 1차 방어다 — 인지·수용한 위험이며 이 수용기준은 그 재읽기 비교까지를 검증한다.

## priority

critical

## scenario

### then

- 새로고침 없이 다음 요청이 바뀐 새 토큰을 싣는다
- 요청을 보내기 전에 저작도구 갱신 중계 창구 [[API-247]] 로 갱신이 한 번 나가고, 동시에 들어온 요청 N건은 그 갱신을 기다렸다가 모두 새 토큰으로 나간다 — 갱신 호출은 N건이 아니라 1회다
- 갱신 호출은 저작도구 갱신 중계 창구 [[API-247]] 로 나가며, access 토큰이 아니라 저장소의 refresh 토큰을 요청 본문에 실어 보낸다
- 401 로 돌아온 요청은 [[API-247]] 로 갱신한 뒤 원 요청을 1회만 재시도하고, 재시도가 성공하면 사용자에게 로그아웃이나 오류가 드러나지 않는다
- [[API-247]] 이 201 로 새 토큰 쌍을 돌려주면 그 쌍을 관제와 같은 키·형식으로 저장한다 — 저장소의 klid-jwt-token 이 새 access 토큰 원문으로, tokenInfo 가 관제지원 웹이 쓰는 것과 같은 13개 필드로, userNm 이 새 토큰의 이름 클레임으로 바뀐다
- tokenInfo 의 expiresAt 과 issuedAt 은 초가 아니라 밀리초(exp×1000 · iat×1000)이고, 접근 불가 메뉴 클레임이 없으면 inAccessibleMenus 는 빈 배열이다
- 저작도구가 저장한 tokenInfo 를 관제지원 웹의 저장 결과와 견주면 필드 집합과 값의 단위가 같다
- 다른 탭이 이미 갱신했으면 이 탭은 갱신 창구를 호출하지 않고 저장소의 새 값을 쓴다
- 거절을 받아도 곧바로 끝내지 않고 저장소의 refresh 토큰을 한 번 더 읽어, 값이 바뀌어 있으면 그 새 토큰으로 계속 동작한다 — 저장소 재읽기는 갱신 직전과 갱신 거절 직후 두 시점에서 일어난다
- 브라우저는 관제 계정 창구([[INT-015]])를 직접 호출하지 않는다 — 선제 갱신과 401 후 재시도 어느 경로에서든 갱신 요청은 저작도구 경로([[API-247]])로만 나가며, 관제 계정 서비스 주소로 향하는 브라우저 요청은 0건이다

### when

- 관제 탭이 토큰을 갱신해 klid-jwt-token 값이 바뀐 뒤 저작도구에서 API 를 요청한다
- 남은 시간이 10분 이하인 상태에서 API 요청을 여러 건 동시에 보낸다
- 요청이 세션 만료로 인한 인증 실패(401)로 돌아온다
- 갱신 직전 저장소의 refresh 토큰이 이 탭이 쥐고 있던 값과 다르다(다른 탭이 이미 갱신했다)
- 관제가 갱신을 오류 응답으로 거절했는데, 그 직후 저장소의 refresh 토큰이 이 탭이 방금 보낸 값과 다르다(다른 탭이 그사이 갱신했다)

### given

- 관제 채널 배포본에서 관제지원 웹 로그인으로 발급된 access 토큰과 refresh 토큰이 같은 출처 브라우저 저장소에 있다(klid-jwt-token · tokenInfo)
- 저작도구는 관제 탭과 별개의 탭에서 열려 있다

## statement

관제 채널로 진입한 저작도구는 요청마다 같은 출처 브라우저 저장소의 현재 access 토큰을 싣고, 세션이 끊기기 전에 저작도구 갱신 중계 창구 [[API-247]] 에 refresh 토큰을 본문으로 보내 토큰을 갱신하며(관제 계정 갱신 창구 [[INT-015]] 는 그 중계 창구가 대신 호출한다), 201 을 받으면 새 토큰 쌍을 관제지원 웹과 같은 키·형식으로 저장소에 쓴다. 브라우저는 관제 계정 창구를 직접 호출하지 않는다 — 갱신 요청은 저작도구 경로로만 나간다. 토큰 인계 창구와 저장 형식의 정본은 [[INT-013]], 결정 근거는 [[ADR-012]] 이며 이 수용기준은 그 계약이 지켜지는지를 검증할 뿐 계약을 복제하지 않는다.

진입 시 복사해 둔 토큰으로 요청하면 관제 탭이 갱신한 뒤에도 옛 토큰을 쥐고 있다가 수명이 지나 인증이 끊긴다 — 그래서 매 요청 저장소의 현재값을 읽는다. 저장 형식이 관제와 한 글자라도 다르면 관제 탭이 저작도구가 쓴 값을 읽고 깨지므로 필드 이름·단위·기본값까지 같아야 한다. 관제 탭과 저작도구 탭이 같은 refresh 토큰으로 동시에 갱신하면 한쪽이 교체된 refresh 토큰을 쥔 채 남으므로, 다른 탭이 이미 갱신했으면 이 탭은 갱신하지 않는다. 그 비교는 갱신 직전 한 번으로 끝나지 않는다 — 관제가 갱신을 거절해 돌아온 직후에도 저장소의 refresh 토큰을 한 번 더 읽어, 그사이 다른 탭이 갱신해 값이 바뀌었으면 세션이 살아 있는 것이므로 그 새 토큰으로 계속한다.
