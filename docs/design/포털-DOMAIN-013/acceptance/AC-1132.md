# 포털 데이터셋 영상 등록 재착수 — 실패 표식만 재착수·완료/진행 중 멱등·소재 미준비 409·목록 응답의 실패 사유·화면 다시 등록 (happy·negative)

## notes

재착수는 멱등 등록에 기대므로 재착수가 겹쳐도 행이 늘지 않는다. 자동 재시작은 두지 않는다 — 구조 불일치는 배포본이 바뀌기 전에는 재착수해도 같은 결과이기 때문이다. 대기열 포화로 접수하지 못한 503 은 이 수용기준의 시나리오에 넣지 않았다(소재 조달 착수와 같은 축이라 그쪽 검증을 따른다).

## priority

high

## scenario

### then

- 데이터셋 X 의 목록은 200 과 등록 상태 FAILED 와 실패 사유 분류로 답하고, 등록을 다시 시작시키지 않는다
- 데이터셋 X 의 재착수는 200 과 등록 상태 IN_PROGRESS 로 답하고 실패 사유는 비어 있다. 등록이 다시 돌아 같은 구성이면 같은 사유의 FAILED 로 끝나며 원장에 데이터셋 X 의 행이 없다
- 읽을 수 있는 구성으로 바뀐 뒤의 재착수는 200 과 등록 상태 IN_PROGRESS 로 답하고, 등록이 DONE 으로 끝나 영상 행이 생기며 그 뒤 목록의 실패 사유는 비어 있다
- 데이터셋 Z 의 재착수는 200 과 등록 상태 DONE 으로 답하고 등록이 다시 돌지 않는다 — 표식의 갱신 시각이 그대로다
- 데이터셋 W 의 재착수는 200 과 등록 상태 IN_PROGRESS 로 답하고 새 등록 작업이 시작되지 않는다
- 데이터셋 V 의 재착수는 409 CONFLICT 로 거부된다
- 토큰 없는 요청은 401 UNAUTHORIZED, 내부 채널 토큰의 요청은 403 FORBIDDEN 으로 거부된다
- 화면은 실패 사유를 사용자가 읽을 수 있는 문구로 보이고 사유 코드를 그대로 찍지 않는다. 「다시 등록」을 누르면 재착수를 부른 뒤 목록을 다시 불러 등록 중 안내가 나타나며, 요청 중에는 버튼이 눌리지 않는다

### when

- 포털 회원이 데이터셋 X 의 영상 목록([[API-253]])을 부른다
- 포털 회원이 데이터셋 X 의 등록 재착수([[API-262]])를 부르고, 등록이 끝난 뒤 영상 목록을 부른다
- 데이터셋 X 의 배포본을 읽을 수 있는 구성으로 바꾼 뒤 다시 등록 재착수를 부르고, 등록이 끝난 뒤 영상 목록을 부른다
- 포털 회원이 데이터셋 Z 의 등록 재착수를 부른다
- 포털 회원이 데이터셋 W 의 등록 재착수를 부른다
- 포털 회원이 데이터셋 V 의 등록 재착수를 부른다
- 토큰 없이, 그리고 내부 채널 토큰으로 데이터셋 X 의 등록 재착수를 부른다
- 데이터셋 소재 조달 화면([[SCREEN-046]])에서 데이터셋 X 의 등록 실패를 보고 「다시 등록」을 누른다

### given

- 포털 채널 배포본이다
- 데이터셋 X 는 소재가 준비 완료인데 등록이 구조 불일치로 실패로 끝났다 — 표식은 실패이고 실패 사유 분류가 기록돼 있으며 원장에 데이터셋 X 의 행이 없다
- 데이터셋 Z 는 소재가 준비 완료이고 등록이 완료됐다
- 데이터셋 W 는 소재가 준비 완료이고 등록 표식이 진행 중이며 실제로 등록 작업이 진행 중이다
- 데이터셋 V 는 소재를 가져온 적이 없다
- 내부 채널(작업자·검수자) 토큰이 따로 있다

## statement

포털 채널 배포본에서 데이터셋 영상 등록이 실패로 끝났으면, 사람이 데이터셋 영상 등록 재착수 [[API-262]] 로 등록을 다시 시작시킬 수 있어야 한다. 재착수는 실패 표식일 때만 등록을 다시 시작시키고 진행 중으로 답한다. 이미 완료면 다시 하지 않고 완료를 답하며, 진행 중이면 새로 시작하지 않고 진행 중을 답한다(멱등). 어느 경우든 응답 코드는 200 이고 구분은 본문의 등록 상태가 싣는다. 소재를 가져온 적이 없거나 소재 조달이 준비 완료가 아니면, 그리고 등록이 배포 설정으로 꺼져 있으면 409 CONFLICT 로 거부한다. 토큰이 없으면 401, 포털 회원이 아니면 403 이다.

목록 조회 [[API-253]] 는 실패 표식을 재시작하지 않는다. 대신 등록 상태 FAILED 와 함께 실패 사유 분류 값을 실어, 데이터셋 소재 조달 화면 [[SCREEN-046]] 이 그 사유를 사용자가 읽을 수 있는 문구로 보이고 「다시 등록」으로 재착수를 부른다. 사유 코드를 그대로 찍지 않으며, 응답 어디에도 내부 경로·표식 파일 이름을 싣지 않는다.

자동으로 되풀이하지 않는다 — 구조 불일치는 재착수해도 같은 사유로 다시 실패하기 때문이다. 배포본이 읽을 수 있는 구성으로 바뀐 뒤의 재착수는 등록을 완료로 끝내고, 그 뒤 목록의 실패 사유는 비어 있다. 등록은 클립 식별자 기준 멱등이라 재착수가 겹쳐 돌아도 영상 행이 늘지 않는다. 결정 근거는 [[ADR-068]] 이다.
