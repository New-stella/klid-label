# 포털 데이터셋 영상 원장 등록 — 소재 준비 뒤 출처 PORTAL_DATASET 등록·재등록 멱등·구조 불일치 실패·원본 이미지 비노출·검수 상태 없음·내부 작업 범위 제외 (happy·negative)

## notes

배포 압축본 구성은 확인된 사실이 아니라 [[ADR-068]] 의 가정이다 — 실제 샘플을 받으면 그 결정과 함께 이 수용기준의 구조 전제를 개정한다. 가정 구조를 따르는 시험용 압축본으로 검증한다.

## priority

critical

## scenario

### then

- 목록이 등록 상태 DONE 과 두 영상 행을 돌려준다 — 각 행의 frameCount 는 배포본에서 등록한 프레임 수이고 labelCount 는 사각 박스·폴리곤 라벨 수이며, 키포인트 라벨은 등록되지 않아 세지 않는다
- 등록된 영상의 출처 유형은 PORTAL_DATASET 이고 영상 메타 portal.dataset_id 가 데이터셋 X 의 번호다. 프레임 원장의 비식별 경로는 비식별 프레임 영역 하위를 가리키고 원본 경로는 비어 있다
- 버전 폴더가 둘인 영상은 번호가 가장 큰 버전의 프레임과 라벨만 등록된다
- 다시 등록한 뒤에도 데이터셋 X 의 영상·프레임·원본 라벨 행 수가 늘지 않는다
- 데이터셋 Y 는 등록 상태 FAILED 와 빈 목록으로 답하고, 영상·프레임·라벨 원장에 데이터셋 Y 의 행이 하나도 없다
- 원본 이미지 폴더의 이미지는 비식별 프레임 영역으로 복사되지 않고, 프레임 이미지 창구와 ZIP 묶음 어디에도 원본 이미지가 담기지 않는다
- 등록된 영상에는 검수 워크플로 상태 행이 없고 검수 승인으로 표시되지 않으며, 관제 조회 뷰에 나타나지 않고 완료·수정 통지와 산출물 재생성이 일어나지 않는다
- 작업보드·배정·통계 조회 결과에 데이터셋 X 의 등록된 영상이 나타나지 않고, 포털 업로드 영상이 제외되던 동작도 그대로다

### when

- 데이터셋 X 의 소재 조달 상태가 준비 완료가 되고 등록이 끝난 뒤 데이터셋 영상 목록([[API-253]])을 부른다
- 데이터셋 X 의 등록된 영상에 대해 영상 원장·프레임 원장·라벨 원장·영상 메타와 저장소의 비식별 프레임 영역을 조회한다
- 등록이 끝난 데이터셋 X 의 등록이 다시 수행된다
- 데이터셋 Y 의 소재 조달 상태가 준비 완료가 된 뒤 데이터셋 영상 목록을 부르고 원장을 조회한다
- 데이터셋 X 의 등록된 영상의 프레임 이미지를 포털 프레임 이미지 창구([[API-111]])로 받고 작업 데이터 ZIP 내려받기([[API-203]])를 받는다
- 데이터셋 X 의 등록된 영상에 대해 검수 워크플로 상태와 관제 조회 뷰를 조회한다
- 내부 채널 토큰으로 작업보드·배정·통계 조회를 부른다

### given

- 포털 채널 배포본에서 포털 회원이 포털 데이터셋 소재 조달([[API-248]])을 착수했다
- 데이터셋 X 의 배포 압축본은 가정한 구조를 따른다 — 영상 2건이 있고, 각 영상의 비식별 이미지 폴더에 프레임 이미지와 같은 이름의 어노테이션 문서가 짝으로 여러 장 있으며, 문서에는 사각 박스·폴리곤·키포인트 라벨이 담겨 있고, 같은 영상 폴더에 원본 이미지 폴더도 함께 들어 있다
- 데이터셋 X 의 한 영상에는 버전 폴더가 둘 있다
- 데이터셋 Y 의 배포 압축본은 가정한 구조와 다르다 — 이미지와 문서의 짝이 없거나, 문서를 NIA 어노테이션 문서로 읽을 수 없거나, 영상 폴더가 하나도 없다
- 내부 채널(작업자·검수자) 토큰이 따로 있다

## statement

포털 채널 배포본에서 데이터셋 소재가 준비 완료가 되면, 같은 백그라운드 작업이 이어서 배포 압축본의 영상·프레임·원본 라벨을 공용 원장에 출처 PORTAL_DATASET 으로 등록해야 한다. 등록 규약의 정본은 [[ADR-068]] 이고, 등록 결과는 데이터셋 영상 목록 [[API-253]] 의 등록 상태와 영상 행으로 드러난다.

배포 압축본은 검수 승인 산출물 구조(영상 폴더 → 버전 폴더 → 비식별 이미지 폴더 안의 프레임 이미지와 같은 이름의 NIA 어노테이션 문서 짝)로 가정한다. 이 구조를 따르면 영상마다 프레임 이미지가 저장소의 비식별 프레임 영역으로 복사되고, 사각 박스·폴리곤 라벨이 원본 라벨로 앉으며(키포인트는 옮기지 않는다), 영상 메타에 데이터셋 번호가 기록된다. 버전 폴더가 여럿이면 번호가 가장 큰 하나만 쓴다. 같은 데이터셋을 다시 등록해도 행이 늘지 않는다 — 클립 식별자가 멱등 키다.

구조가 이 가정과 다르면 추측으로 채우거나 일부만 적재하지 않고 등록 실패로 끝나야 하며 원장에는 그 데이터셋의 행이 남지 않는다. 원본(비식별 이전) 이미지 폴더는 읽지 않으므로 어떤 경로로도 복사·서빙되지 않는다. 등록된 영상에는 검수 승인 상태도 검수 워크플로 상태 행도 만들지 않아 관제 조회 뷰·완료/수정 통지·산출물 재생성이 반응하지 않고, 내부 작업 범위(작업보드·배정·통계) 조회에도 포털 업로드 영상과 같이 나타나지 않는다.
