# 포털 채널 데이터 읽기 Load 정상 흐름

## kind

integration

## notes

시험시나리오 KLID-AT-IT-TS-005. 대외 연동 경계: 포털 DB(외부 채널) 읽기 Load(KLID-AT-II-008 inbound DB READ). 관련 요구사항 RQ-SFR-19(R2 미수록). 핵심 테이블 LS_PORTAL_USER_LABEL. 정상 흐름(happy path)만 수록.

[검증 대상 대응] 본 시험이 검증하는 포털 DB 읽기 Load 흐름은 UC-024(포털 라벨 작업)의 본문—관제→데이터마트→포털 DB 적재 후 저작도구가 Load—와 직접 대응하므로 covers_use_cases 에 UC-024 를 포함한다. 다만 UC-024 자신이 R1 기능요구사항 대응 없음을 명시하므로, 이 시나리오의 검증 대상 자체가 적절한지는 관제 협의가 필요한 별도 판단 사항이다. ⚠ **[재검토 대상 — 검증 대상 자체가 성립하지 않는다]** 이 시나리오는 「포털 DB 에서 영상·라벨·메타를 조회」를 검증하는데 **두 겹으로 성립하지 않는다.** ①저작도구는 그 방향으로 읽은 적이 없다 — 포털 라벨 경로는 저작도구(control) DB 를 쓰며, 포털 DB 는 반대로 내보내던 곳이었다. ②2026-08-31 확정으로 **저작도구와 포털은 서로의 DB 에 접근하지 않는다**(ADR-012). 승인된 산출물이라 본문·단계는 고치지 않고 표기만 남긴다 — **폐기할지, 「배포물을 자기 DB 에 적재한 뒤 조회」로 재작성할지는 별도 판단이 필요**하다. ✅ **조회 창구가 확정됐다 (2026-09-03 포털 회신)** — 구 표기 「그 방향의 조회 창구도 포털 회신 대기다」는 이 회신으로 **해소**됐다. 소재(파일) 조회 창구는 **[포털]API-132** 이며, 그 응답이 알려주는 **NAS 절대경로**로 배포물을 읽는다. 한 건의 소재는 **배포 묶음 파일 한 건과 영상 0건 이상**으로 이루어진다. ⚠ **그 창구의 응답 규격은 포털이 소유하므로 여기에 옮겨 적지 않는다** — 조달처만 가리키고 필드 구성은 [포털]API-132 를 정본으로 본다(복제하면 두 번째 진실원이 되어 한쪽만 낡는다). ⚠ **「포털 DB 를 읽지 않는다」는 그대로 유효**하다 — 우리가 읽는 것은 **NAS 파일**이지 포털 DB 가 아니며, 상호 미접근 확정으로 오히려 강화된다. ⚠ 이 확정은 **재작성 방향의 조달처를 알려줄 뿐 이 시나리오를 되살리지 않는다** — 검증 대상으로 삼은 「포털 DB 에서 영상·라벨·메타를 조회」는 여전히 성립하지 않으며, 폐기할지, 「배포물을 자기 DB 에 적재한 뒤 조회」로 재작성할지는 별도 판단이 필요하다.

✅ **재작성 완료 (2026-09-04)** — 구 표기 「폐기할지, 「배포물을 자기 DB 에 적재한 뒤 조회」로 재작성할지는 별도 판단이 필요하다」는 **재작성으로 확정**되어 해소됐다. 검증 목적(Load 가 정상 동작하는가)은 그대로 두고 조달 경로만 현행으로 바꿨다.
· **폐기된 구 조달 경로** — objective·steps·preconditions 가 검증 대상으로 삼던 「포털 DB(외부 채널)에서 영상·라벨·메타를 별도 데이터소스로 읽기 조회」와 그 사전조건 「포털 DB에 영상·라벨·메타가 적재돼 있고 포털 데이터소스에 연결 가능하다」, 순번1 의 구 행위 「포털 DB 조회」와 구 비고 「JDBC 읽기 전용」은 **폐기**한다. 2026-08-31 확정으로 저작도구와 포털은 서로의 DB 에 접근하지 않으므로 그 경로는 존재하지 않는다.
· **현행 조달 경로** — 소재(파일) 조회 창구는 **[포털]API-132** 이며 그 응답이 알려주는 **NAS 절대경로**로 배포물을 읽는다. 한 건의 소재는 **배포 묶음 파일 한 건과 영상 0건 이상**으로 이루어진다. 읽은 배포물은 저작도구 **자기 DB 에 작업 세션으로 적재**한 뒤 화면이 그것을 조회하므로 표시할 때마다 포털로 왕복하지 않는다.
· ⚠ **폐기 표기를 단계(steps)에 두지 않고 여기에 모았다** — steps 는 시험 산출물 상세표의 각 칸과 1:1 로 대응해 그대로 인쇄되므로, 칸 안에 폐기 문구를 남기면 시험 수행자가 읽을 절차가 흐려진다. 단계·목적·사전조건은 현행만 담고 폐기 사실과 경위는 이 자리에 보존한다.
· ⚠ **그 창구의 응답 규격은 포털이 소유하므로 여기에 옮겨 적지 않는다** — 조달처만 가리킨다. 서버간 연동 축의 인증·창구 구성·계약은 INT-014 가 갖는다.
· ⚠ **순번3(사용자 라벨 단방향 별도 적재)은 조달 경로와 무관해 그대로 둔다.**
