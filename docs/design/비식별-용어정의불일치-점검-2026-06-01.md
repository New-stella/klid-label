# 비식별·개인정보 처리 컬럼 용어 정의 불일치 점검

> 생성일: 2026-06-01 / 작성: claude
> 대상: LogiCraft `KLID-저작도구` 고도화 ERD(010·011·012·015·017) + 사업 용어사전
> 계기: "비식별 영상 프레임 경로가 어느 ERD에 있나" → `SRC_BKUP_FILE_PATH_NM`이 용어상 "백업"인데 실제 "비식별" 용도 → 정의 불일치 발견 → 비식별 영역 전수 점검
> 원칙: **BM(1차) 용어 불간섭** — 충돌난 사전 용어는 1차이므로 수정하지 않고, 고도화용 올바른 표준 용어를 신규 정의

## 1. 점검 결과 — 정의 불일치 7건

| # | 컬럼 (ERD) | 실제 용도 | 사전/표준 정의 | 불일치 유형 |
|:--:|---|---|---|---|
| 1 🔴 | `SRC_BKUP_FILE_PATH_NM` (ERD-012 LS_DATA_SRC) | 비식별 영상에서 추출한 동일 프레임 경로 | id 809 `SRC_BKUP_FILE_PATH`="원천 파일의 **백업본** 경로", gov 단어 BKUP="복원용 백업" | **의미 정반대** (백업=동일본 보존 ↔ 비식별=내용 변형) |
| 2 🟠 | `ORGN_FILE_PATH_NM` (ERD-017), `ORGN_DATA_LBL_SN` (ERD-011) | 원본 영상 경로 / 원본 라벨 | gov ORGN(536)="기원(Origin)", **원본=ORGNL(1881)** | 약어 오용 (ORGN↔ORGNL) |
| 3 🟠 | `DE_IDNTF_YN` (ERD-012) | 비식별 결과 Y/F/N (3값) | 사전 id 653 `DE_IDENT_YN` Y/N (2값) | 약어 철자(IDENT↔IDNTF) + 도메인(2값↔3값). gov 단어 식별=IDNTF 기준 ERD가 더 정합 |
| 4 🟡 | `DATA_RAW_SN` "원천영상식별자" (ERD-017) | 원시영상 PK | RAW=원시인데 논리명 "원천(SRC)" | 논리명-약어 충돌 (ERD-012/010은 "원시영상일련번호") |
| 5 🟡 | `PRVC_YN` (ERD-012) | 개인정보 포함여부 | 사전 id 505 `PRVC_INCL_YN` (INCL 포함) | 약어 누락 (의미는 동일) |

## 2. 구조적 공백 — 비식별 "산출물(경로)" 용어 전무

사전의 비식별 용어(id 651~656)는 **여부·카운트·일시·전송식별자 등 메타 계열에만** 있고, **비식별 결과 파일/프레임 경로 용어가 없다.** 그래서 비식별 프레임 경로를 "백업(BKUP)"이라는 틀린 용어로 메우게 된 근본 원인.

## 3. 조치 — 고도화 비식별 산출물 표준 용어 신규 정의 (BM 불간섭)

본 점검으로 사업 용어사전에 신규 등록한 고도화 표준 용어:

| 용어 | 약어 | 도메인 | 의미 | 대응 컬럼(현 물리명) |
|---|---|---|---|---|
| 비식별원천파일경로명 | `DE_IDNTF_SRC_FILE_PATH_NM` | 내용V1000 | 비식별 영상에서 추출한 동일 프레임(원천) 경로 = 라벨링 대상 비식별 프레임 | LS_DATA_SRC.`SRC_BKUP_FILE_PATH_NM`(1차 레거시명) |
| 비식별파일경로명 | `DE_IDNTF_FILE_PATH_NM` | 내용V1000 | 외부 비식별 솔루션이 반환한 비식별 결과 영상 경로 | LS_DEIDENT_PROC_LOG.`DE_IDNTF_FILE_PATH_NM` |
| 원본파일경로명 | `ORGNL_FILE_PATH_NM` | 내용V1000 | 비식별 처리 대상 원본 영상 경로 (원본=ORGNL, gov 1881) | LS_DEIDENT_PROC_LOG.`ORGN_FILE_PATH_NM`(ORGN 오용) |

> `DE_IDNTF`(비식별)는 gov 표준에 단어가 없으나 사업 관행 약어(id 651 `DE_IDNTF_APLCN_DT` 등)와 정합. 파일경로명은 gov 표준 `FILE_PATH_NM`.

## 4. 후속 — 코드 물리 컬럼명 정정 — 완료(2026-06-01)

§3 용어 정의에 이어 **물리 컬럼명·코드·ERD physical명 정정을 완료**했다. 신규 미배포 상태라 CREATE SQL을 직접 수정(새 ALTER 마이그레이션 없음)하고, 빌드 PASS를 확인했다. 정정 내역:

| 현 물리명 | → 표준 | 위치 | 상태 |
|---|---|---|---|
| `SRC_BKUP_FILE_PATH_NM` | `DE_IDNTF_SRC_FILE_PATH_NM` | LS_DATA_SRC (ERD-012 v3·코드 V4/V52/엔티티) | ✅ 완료 |
| `ORGN_FILE_PATH_NM` | `ORGNL_FILE_PATH_NM` | LS_DEIDENT_PROC_LOG (ERD-017 v3·V21/V29/V30/엔티티) | ✅ 완료 |
| `ORGN_DATA_LBL_SN` | `ORGNL_DATA_LBL_SN` | LS_DATA_AUG_LBL_MAP (ERD-011 v3·V26/엔티티) | ✅ 완료 |
| `DE_IDNTF_YN` allowed_values | Y/F/N 3값 확정 (사전 id 653은 BM 보존) | LS_DATA_RAW | 잔여 (BM 사전 id653 불간섭) |

> ⚠ `DE_IDNTF_SRC_FILE_PATH_NM`은 데이터마트 View(`V_COMPLETED_FRAME`)에도 노출되므로 컬럼명 정정 시 관제팀 협의 필요.

## 5. 결론

- 비식별 프레임 데이터의 저장 위치(테이블/컬럼)는 존재했으나, **"백업"이라는 정의가 틀린 용어**를 쓰고 있었다.
- BM 1차 용어는 보존하고, 고도화용 올바른 비식별 산출물 용어 3종을 신규 정의했다.
- 물리 컬럼명·코드 정정 완료(2026-06-01, 신규 미배포라 CREATE SQL 직접 수정·빌드 PASS·데이터마트 View 반영). 단 `DE_IDNTF_YN` allowed_values Y/F/N 3값 확정은 잔여(BM 사전 id 653 불간섭 보존).
