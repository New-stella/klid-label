# D9 데이터베이스 설계서

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-UC/CO/DC/DCD/SD/SC/AC/EN/ERD/TB/II/IC/IF/UCD/ACT 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. 범위는 시작 ID만 전체형으로(예: `KLID-AT-TB-001~041`). ※ 요구사항(RQ-SFR-NN-NN)·시스템시험(KLID-ST-NNN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 최종적으로 설계된 테이블과 인덱스를 데이터베이스 공간에 매핑시키고 저장공간 등의 물리 모델을 기술한다.

## 작성 방법
> 부서에서 운영하는 데이터베이스 목록을 작성하고, 데이터베이스의 물리적 상세내용을 작성한다.

> **본 산출물의 물리 설계 출처**: Flyway 마이그레이션(`backend/src/main/resources/db/migration` V0~V61)과 JPA `@Column` 매핑(`backend/src/main/java/kr/co/cudo/authoring/**/entity`)에서 실측 도출하였다. 저작도구 소유 `LS_*` 테이블은 **D8/D9 범위 추림 비대상** — 활성 유스케이스가 직접 사용하지 않는 테이블도 전수 기술한다.
>
> **물리 개념 적응 표기(Critical)**: 본 프로젝트 DBMS는 **PostgreSQL**(UTF-8, 표준 SQL DDL)이다. 템플릿의 Storage Group·Bufferpool·인덱스 BP·TS(테이블스페이스)는 DB2 물리 개념이므로 **PostgreSQL 등가물로 적응 표기**한다 — Storage Group/Bufferpool은 PostgreSQL 기본 테이블스페이스(`pg_default`)와 공유버퍼(`shared_buffers`)로, "TS(테이블스페이스)"는 실 물리 분리가 아닌 **도메인 논리 그룹(스키마 내 테이블 묶음)** 으로 매핑한다. 단일 PostgreSQL 인스턴스 운영이므로 별도 물리 테이블스페이스를 만들지 않으며, TS ID는 §2 도메인 그룹 식별용으로만 사용한다.
>
> **대상 합치(Critical)**: 저작도구 소유 활성 테이블은 **41개**다(§1 데이터베이스 목록 = §2 DB정의 TS 행 합 = §3 테이블 명세 41건 = D8 엔티티 41건과 1:1). 관제서버 공유 `MNG_*`(9종)·Quartz `QRTZ_*` 스키마는 인프라 제공(`ddl-auto=validate` 읽기 위주 참조)으로 물리 설계 비대상 — §1에 "공유(READ)" 비고로만 표기한다.
>
> **관련 엔티티 ID 매핑 규칙**: 각 테이블 명세의 "관련 엔티티 ID" 행은 D8 "엔티티 관계 모형 설계서"의 엔티티 ID(`KLID-AT-EN-NNN`)와 **1:1·번호 정렬**한다(테이블 `KLID-AT-TB-NNN` ↔ 엔티티 `KLID-AT-EN-NNN` 동일 번호). 저작도구 소유 전 테이블이 D8 명세 대상이므로 `-` 처리 테이블은 없다.

### 데이터베이스 정의

- **데이터베이스 ID / 데이터베이스명**: 데이터베이스 식별자·명칭을 기입한다.
- **Storage Group / Bufferpool / 인덱스 BP**: DB2 물리 개념을 PostgreSQL 등가물로 적응 표기한다(머리말 참조). Storage Group=`pg_default`, Bufferpool=`shared_buffers`, 인덱스 BP는 데이터와 동일 공유버퍼 사용(미분리).
- **TS ID / TS 용량**: PostgreSQL 물리 테이블스페이스가 아닌 도메인 논리 그룹 식별자와 산정 용량(최대건수×평균 row)을 기술한다.
- **테이블 ID / 테이블명 / 인덱스 ID / 인덱스 용량**: 테이블·인덱스 식별자와 저장공간 크기를 기술한다.

### 테이블 명세

- **테이블 ID / 테이블명 / 데이터베이스명 / TS명**: 테이블 식별자·명칭과 소속 DB·TS 논리 그룹을 기술한다.
- **관련 엔티티 ID**: 본 테이블에 대응하는 D8 엔티티 ID(`KLID-AT-EN-NNN`)를 1:1·번호 정렬로 기입한다.
- **트리거 구성 / 테이블 설명**: DB 트리거 유무(본 시스템은 트리거 미사용 — 상태 전이·통지는 애플리케이션 레이어 처리)와 테이블 목적을 기술한다.
- **초기건수 / 증가량(일) / 보관주기 / 최대건수 / 용량 / 비고**: 운영 메타. 보관주기는 일수 또는 정책으로, 용량은 산정 근거(최대건수×평균 row bytes)를 병기한다.
- **컬럼명 / 컬럼ID / 타입 및 길이 / NOT NULL / PK / FK / IDX / 기본값 / 제약조건**: 각 컬럼의 물리 특성을 PostgreSQL 등가 타입으로 기술한다. VARCHAR만 길이를 표기하고 물리 FK 미설정 ID 참조는 "논리 FK"로 명시한다.

### B. 물리 개념 적응 표기 사유

본 프로젝트 DBMS는 PostgreSQL(단일 인스턴스)이다. 템플릿의 DB2 물리 개념을 다음과 같이 적응했다.

- **Storage Group → `pg_default`**: PostgreSQL 기본 테이블스페이스. 별도 물리 테이블스페이스를 만들지 않는다.
- **Bufferpool / 인덱스 BP → `shared_buffers`**: PostgreSQL은 데이터·인덱스 공통 공유버퍼를 사용하므로 인덱스 전용 BP를 분리하지 않는다.
- **TS(테이블스페이스) → 도메인 논리 그룹**: 실제 물리 분리가 아닌 13개 도메인(ERD) 단위 테이블 묶음 식별용. 모든 테이블은 `pg_default`에 저장된다.
- **타입**: VARCHAR/BIGINT/INTEGER/TIMESTAMP/DECIMAL/BOOLEAN/TEXT/UUID(PostgreSQL). DB2/MariaDB 고유 타입은 사용하지 않는다.

### C. 빈 셀 / 추측 회피 항목

- 모든 컬럼표 9항목은 Flyway 마이그레이션·JPA `@Column` 실측값과 D8 엔티티 명세 동조로 채웠으며, 값이 없는 칸은 `-`로 표기했다.
- **트리거 구성**: 본 시스템은 DB 트리거를 사용하지 않는다(상태 전이·통지·이력은 모두 애플리케이션 레이어 처리). 전 테이블 "없음"으로 표기하고 관련 애플리케이션 처리 사실을 비고에 부기했다.
- **운영 메타(초기건수·증가량·최대건수·용량)**: 핵심 산출물 목표(이미지 10만장 SFR-16 / 영상 5,000건 SFR-17 + 증강 동량)를 상한으로 산정했다. 정확한 운영 수치는 실 운영 데이터 축적 후 보정 필요 — **추정 산정값**임을 명시한다.
- `DDLN_SEQ`(마감정의 PK)는 V1 정의를 유지해 비-IDENTITY로 표기했다(코드 실측).
- `LS_DATA_AUG`의 `LBL_INTGRT_PCT`/`REJECT_RSN`/`DCSN_USER_NO`/`DCSN_DT`는 엔티티 `@Transient`로 검수 상세가 `LS_DATA_AUG_RVW`로 이관되었으나 물리 컬럼은 잔존하므로 "@Transient(물리 잔존)"으로 명시했다.
- 컬럼명(논리명)은 행안부 공통표준용어(`_SN`=일련번호, `FILE_PATH_NM`=파일경로명 등)에 정합하도록 Flyway V60(공공표준)·V61(용어사전 표준)에서 rename 완료된 물리 컬럼ID를 그대로 사용했다.

### D. 범위 제외 / 잔여(비활성) 테이블 메모

- **공유 테이블(물리 설계 비대상)**: 관제서버 `MNG_*` 9종·Quartz `QRTZ_*`는 인프라 제공으로 `ddl-auto=validate` 참조만 하며 §1 데이터베이스 목록에 "공유(READ)"로 표기했다. 포털 DB도 외부 채널 제공으로 Load만 한다.
- **잔여(비활성) 테이블** — 본 산출물 물리 설계(§3) 제외, 본 메모에만 기록:
  - `LS_PJT`·`LS_PJT_DATA_MPNG`·`LS_PJT_DATA_STTS`·`LS_PJT_DDLN`·`LS_PJT_META`·`LS_PJT_USER_AUTHRT`·`LS_PJT_USER_AUTHRT_HSTRY`·`LS_PJT_TASK_EVENT_LOG`: 프로젝트 단위 개념 폐지(작업 단위=영상 1건)에 따라 V34/V35에서 DROP 및 신 테이블(LS_RAW_DATA_*, LS_TASK_*, LS_META, LS_DEADLINE, LS_TASK_EVENT_LOG)로 이관. 활성 엔티티 부재.
  - `LS_DATA_SET`(V8): 후속 설계에서 데이터셋 단위 개념 미사용으로 활성 엔티티 부재.
  - `LS_GITEA_FALLBACK_QUEUE`(V41): 라벨 버전관리를 외부 VCS(Gitea 커밋)에서 DB 스냅샷(`LS_LABEL_VERSION`, V53)으로 전면 전환하면서 대응 JPA 엔티티 제거. 관제 통지 fallback은 `LS_CONTROL_NOTIFY_FALLBACK`(V44, KLID-AT-TB-037)로 별도 운영. 활성 엔티티 부재.
- **데이터마트 적재용 View**(V52): `V_COMPLETED_VIDEO`/`V_COMPLETED_FRAME`/`V_COMPLETED_LABEL`/`V_COMPLETED_LABEL_ATTR`/`V_COMPLETED_META`는 검수 완료 영상만 노출하는 읽기 전용 View로 물리 테이블이 아니어서 §3 테이블 명세 대상에서 제외했다(`CREATE OR REPLACE VIEW` 멱등).
