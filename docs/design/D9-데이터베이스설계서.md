# D9 데이터베이스 설계서

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-DB/TS/TB/ID/CL/EN 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `TB-001`) 약식 표기 금지. ※ 요구사항(RQ-SFR-NN-NN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 최종적으로 설계된 테이블과 인덱스를 데이터베이스 공간에 매핑시키고 저장공간 등의 물리 모델을 기술한다.

## 작성 방법
> 부서에서 운영하는 데이터베이스 목록을 작성하고, 데이터베이스의 물리적 상세내용을 작성한다.

> **생성 출처 / 진실원**: LogiCraft 그래프의 활성 `erd` ITEM 12종(ERD-010~021)에서 테이블→물리 명세를 도출하고, **컬럼명·타입·길이·NULL·PK·FK·기본값은 `backend/src/main/resources/db/migration/*.sql`(Flyway V0~V54)을 정본(authoritative)으로 교차 확인**했다(엔티티 `@Column` 보조 대조). 본 명세의 모든 컬럼은 마이그레이션과 1:1 정합한다. 추측 컬럼은 두지 않으며 부족 칸은 "-".

## 작성 범위 / 진실원

- **DBMS = PostgreSQL** (CLAUDE.md·R1 확정). 템플릿 작성참고의 MariaDB 10.11 / MaxScale / utf8mb4 / InnoDB 전제는 본 프로젝트에 적용하지 않는다(아래 §2 적응 표기). 인코딩 UTF-8, 스키마 `klid_at`.
- **대상 테이블 = 저작도구가 소유·운영하는 활성 `LS_*` 37종**(KLID-AT-TB-001~037). §2 데이터베이스 정의·§3 테이블 명세 모두 동일 37개로 합치한다. 12개 ERD ITEM 의 테이블 집합과도 합치한다(ERD 1건이 다수 테이블을 묶음).
- **범위 외(full 명세 제외)**: 관제서버 소유 공유 `MNG_*` 9종(`ddl-auto=validate` 읽기 전용), Quartz 스케줄러 `QRTZ_*` 11종(PostgreSQLDelegate, 인프라 제공), 데이터마트 적재 View `V_COMPLETED_*`(V52, 읽기 전용 파생). §4 참조 섹션에 목록만 둔다.
- **폐기 테이블**: 1차 `LS_PJT*` 계열 7종은 V34~V37 에서 영상 단위 테이블로 이관 후 V35 에서 `LS_PJT` DROP, `LS_GITEA_FALLBACK_QUEUE` 는 V53 DROP, `LS_PORTAL_USER_VIDEO`(V9)는 ADR-013 으로 미운영 — 모두 대상에서 제외(누락 아님).

> **행안부 표준 적용 현황(검증 샘플)**: `RAW_FILE_PATH_NM`/`ORGNL_FILE_PATH_NM`(행안부 표준용어 FILE_PATH_NM·ORGNL_FILE_PATH_NM, domain 명V300 — **일치**), `REG_DT`/`MDFCN_DT`(등록일시·수정일시, domain 연월일시분초D — **일치**), `EVNT_TYPE_CD`/`LCLGV_CD`/`PRVC_YN`/`DE_IDNTF_YN` 등 표준 약어 정합. `PRVC_TYPE_CD`(개인정보유형코드)·`IDMP_KEY`(멱등키)·`MARK_CN`(마킹내용)·`FRME_INTV_NOCS`(프레임간격수) 등은 행안부 공통표준에 동일 용어/단어가 없는 **사업 표준 약어**(gov 미등재 → "-")다.

## 2. 데이터베이스 정의

> **물리 개념 적응 표기(PostgreSQL)**: 템플릿의 Storage Group·Bufferpool·인덱스 BP·TS 는 DB2 물리 개념이다. PostgreSQL 프로젝트는 등가물로 적응 표기한다 — Storage Group=`pg_default`(기본 테이블스페이스), Bufferpool=인스턴스 공통 `shared_buffers`(별도 인덱스 BP 미구분). 단일 인스턴스 운영(Quartz 클러스터 미적용)이며 MaxScale Read/Write Splitting(MariaDB 전용)은 적용하지 않는다. 아래 TS-001/002 는 논리적 그룹(데이터/이력·로그)이며 물리 분리는 운영 선택.

## 3. 테이블 명세

> 컬럼 ID는 `KLID-AT-CL-{테이블 일련 2자리}-{컬럼 일련 2자리}` 형식이며 본 명세에서는 지면상 컬럼명 우선 표기한다. 모든 컬럼명/타입/길이/제약은 Flyway 마이그레이션 정본과 1:1 정합. PK는 `BIGINT GENERATED BY DEFAULT AS IDENTITY`(예외: `LS_DEADLINE.DDLN_SEQ` 비-IDENTITY, `LS_SYSTEM_CONFIG`/`LS_META`/`LS_WEBHOOK_IDEMPOTENCY` 는 자연키 PK). FK는 운영 정책상 대부분 물리 제약 미설정(공유 DB 안정성 우선) — ID 참조이므로 FK 칸은 "논리(대상)"로 표기한다.
>
> **보관주기**: 본 시스템은 원본·라벨·이력 데이터를 삭제하지 않는 보존 정책이므로 전 테이블 **영구**(일수 미적용) — 원본 삭제 금지 정책 정합. 운영 메타(초기건수·증가량·최대건수·용량)는 SFR-16/17 규모 기준 개략 추정이다.

### 4.2 Quartz 스케줄러 인프라 (QRTZ_*, 11종)

PostgreSQL JobStore(`PostgreSQLDelegate`, BYTEA). 인프라 제공, 저작도구 설계 대상 아님.

### 4.3 데이터마트 적재 View (V52, 읽기 전용 파생)
