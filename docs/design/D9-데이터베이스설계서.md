## 작성 범위 / 진실원

- **DBMS = PostgreSQL** (CLAUDE.md · R1 v1.2 확정). 템플릿 작성참고의 MariaDB 10.11 / MaxScale / utf8mb4 / InnoDB 전제는 본 프로젝트에 적용하지 않는다. 인코딩은 UTF-8, 스키마는 `klid_at`.
- **대상 테이블**(v1.3 확장) = 저작도구가 **소유·운영하는 활성 `LS_*` 테이블 전체**. 활성 JPA 엔티티를 보유한 36종 + 경계 1종(`LS_DATA_SET`, 내보내기 작업)으로, 라벨링 / 버전관리 / 검수 / 비식별 / 시계열 메타 / 증강 / 영상 기반 작업뿐 아니라 작업배정·상태·이력·마킹·포털·배치/관제통지 운영 테이블까지 모두 포함한다. (구 RQ-SFR-09-06/07은 2026-06-02 범위 외 삭제 — `LS_SYSTEM_CONFIG`의 FFmpeg 키 일부가 해당하나 테이블 자체는 활성 운영 대상이므로 본 명세에 포함)
- **대상 건수 합치**: 본 명세 full 컬럼 명세 대상 = 저작도구 소유·운영 활성 `LS_*` **37개 테이블(KLID-AT-TB-001~037)**(v1.1~1.2의 R1 매핑 20개 + v1.3 확장 17개). §2 DB정의(데이터베이스 정의 표)·§3 테이블 명세 모두 동일 37개로 합치한다. 추가로 외부 소유 참조 테이블 `MNG_*` 9종·`QRTZ_*` 11종은 §4 참조·인프라 섹션에 목록·설명만 기재(full 명세 제외).
- **범위 외**(본 명세 full 컬럼 제외): 사용자/권한 등 관제서버 소유 공유 `MNG_*` 9종(`ddl-auto=validate` 읽기 전용 참조)과 Quartz 스케줄러 인프라 `QRTZ_*` 11종(PostgreSQLDelegate, 인프라 제공). 두 그룹은 저작도구의 설계 대상이 아니므로 §4에 목록·간단 설명만 둔다. 데이터마트 적재 View(V52, `V_COMPLETED_*`)는 읽기 전용 파생 객체로 테이블 명세 대상이 아니다.
- **컬럼 진실원** = `backend/src/main/java/.../entity/*.java` 의 `@Column` 매핑 + `backend/src/main/resources/db/migration/V1~V53` Flyway 최종 상태(V3 행안부 표준 rename 반영). 본 문서의 모든 컬럼명·타입·길이·제약은 코드와 1:1 정합한다.

> **행안부 표준 적용 현황(샘플)**: 본 프로젝트의 `LS_*` 컬럼은 이미 행안부 공통표준용어 약어로 명명되어 있다 — `RAW_FILE_PATH_NM`(파일경로명), `DE_IDNTF_YN`(비식별여부), `PRVC_TYPE_CD`(개인정보유형코드), `EVNT_TYPE_CD`(이벤트유형코드), `LCLGV_CD`(지자체코드), `MDFCN_DT`(수정일시), `REG_DT`(등록일시), `LBL_TYPE_CD`(라벨유형코드), `RVW_STTS_CD`(검수상태코드), `LBL_INTGRT_PCT`(라벨정합률). 컬럼명은 코드 기준 그대로 표기하며 추측·임의 rename 하지 않았다.

> PostgreSQL 단일 인스턴스 운영(Quartz 클러스터 미적용 — 단일 인스턴스 서비스 배포). MaxScale Read/Write Splitting은 MariaDB 전용 구성이므로 적용하지 않는다. 조회 부하 분산 필요 시 read replica 도입은 선택 사항(현 설계 범위 외). 테이블스페이스는 PostgreSQL 기본(`pg_default`)에 단일 배치하며, 아래 TS는 논리적 그룹(데이터/이력)으로 구분 관리한다(물리 분리는 운영 시 선택). 용량은 SFR-16(이미지 10만 장) / SFR-17(영상 5,000건, 30초 이상/건) 기준 추정치이며 인덱스는 B-tree 기준 개략 추정.
>
> **용량 산정 근거(대표 예시)**:
> - `LS_DATA_RAW`(원시 영상/이미지): 최대건수 ~120,000행(영상 5천 + 증강 + 이미지 10만) × 평균 row ~40 bytes(식별자·코드·경로 컬럼) ≈ ~5 MB. (SFR-16 이미지 10만 장 + SFR-17 영상 5,000건 기준)
> - `LS_DATA_SRC`(추출 키프레임): 최대건수 ~수백만 행(영상 × 프레임 + 이미지 10만) × 평균 row ~수백 bytes(원본/비식별 경로 페어) ≈ ~2 GB. (SFR-16 이미지 10만 장 기준)

## 3. 테이블 명세

> 컬럼 ID는 `KLID-AT-CL-{테이블 일련 2자리}-{컬럼 일련 2자리}`. 모든 컬럼명/타입/길이/제약은 엔티티 `@Column` + Flyway 최종 상태와 1:1 정합. PK는 `BIGINT GENERATED BY DEFAULT AS IDENTITY`(`@GeneratedValue(IDENTITY)`). FK는 운영 정책상 물리 FK 미설정(공유 DB 안정성 우선)이며 ID 참조이므로 아래 FK 열은 "논리 FK"를 표기한다. `REG_DT`/`MDFCN_DT` 등 일시 컬럼은 PostgreSQL `TIMESTAMP`(엔티티 `LocalDateTime`).

> 보관주기: 본 시스템은 원본·라벨·이력 데이터를 삭제하지 않는 보존 정책이므로 전 테이블 '영구'다(일수 미적용). — 원본 삭제 금지 정책 정합.

> V47 신규. 포털은 오토라벨링/VLM/버전관리/검수/업로드 미제공(ADR-013) — 사용자 라벨만 적재.

## 4. 참조·인프라 테이블 (외부 소유 — full 명세 제외)

본 섹션의 테이블은 저작도구가 **소유·설계하지 않는** 참조/인프라 테이블이다. 컬럼 스키마의 진실원이 외부(관제서버 / Quartz 라이브러리)에 있어 본 저작도구가 변경 권한을 갖지 않으므로, full 컬럼 명세 대신 **목록과 용도만** 기재한다.

### 4.1 관제서버 소유 공유 테이블 `MNG_*` (9종, `ddl-auto=validate` 읽기 전용)

저작도구는 아래 9개 테이블을 **읽기 위주로 참조**한다(JPA `ddl-auto=validate`). 스키마 소유·변경 권한은 관제서버팀에 있으며, 변경 시 Flyway 마이그레이션 전 **관제서버팀 선승인 필수**(CLAUDE.md DB 공유 정책). 저작도구는 물리 DDL을 생성하지 않는다(운영 PG에 관제가 이미 생성, 일부는 `IF NOT EXISTS` 가드만 보유 — V2 참조).

| 테이블 명 | 용도(저작도구 관점) |
|---------|------------------|
| MNG_ACCT_USER | 사용자 계정 — JWT 검증 후 USER_NO 참조(배정·검수자 식별) |
| MNG_ACCT_AUTHRT | 권한(역할) 마스터 — REVIEWER/WORKER 등 역할 코드 참조 |
| MNG_ACCT_USER_AUTHRT | 사용자-권한 매핑 — 역할 기반 접근 제어 참조 |
| MNG_CLIP_MASTER | 클립(영상) 마스터 — VMS_CLIP_ID/VMS_CCTV_ID 등 원천 메타 참조 |
| MNG_CLIP_SCHEDULE_QUE | 클립 스케줄 큐 — 관제 송신 스케줄(연동 deprecated, 참조만) |
| MNG_EX_EVNT_TYPE | 이벤트 유형 마스터 — EVNT_TYPE_CD 코드 참조 |
| MNG_EX_EVNT_TYPE_MAP | 이벤트 유형 매핑 — 이벤트-라벨 프리셋 연계 참조 |
| MNG_EX_LOCAL_GOV | 지자체 마스터 — LCLGV_CD 코드 참조 |
| MNG_RESOURCE_CCTV | CCTV 리소스 — VMS_CCTV_ID 기준 카메라 메타 참조 |

> 제외 사유: 관제서버 소유 스키마로 저작도구가 컬럼을 정의·변경하지 않으며(`validate` 모드), 진실원이 관제서버 DDL이다. 본 설계서의 명세 대상은 저작도구 소유 `LS_*` 테이블이다.

### 4.2 Quartz 스케줄러 인프라 테이블 `QRTZ_*` (11종, PostgreSQL JobStore)

배치 트리거(1건/분)·스케줄링을 위해 Spring Boot Quartz가 PostgreSQL JobStore(`StdJDBCDelegate` 계열 `PostgreSQLDelegate`, BYTEA)로 운영하는 표준 인프라 테이블이다. 스키마는 Quartz 라이브러리가 제공하는 표준 DDL을 그대로 사용하며 저작도구가 컬럼을 설계·변경하지 않는다. 단일 인스턴스 운영(Quartz 클러스터 미적용)이나 표준 테이블 세트는 동일하게 보유한다.

| 테이블 명 | 용도 |
|---------|------|
| QRTZ_JOB_DETAILS | 잡 정의(JobDetail) 저장 |
| QRTZ_TRIGGERS | 트리거 메타 저장 |
| QRTZ_SIMPLE_TRIGGERS | SimpleTrigger 상세 |
| QRTZ_CRON_TRIGGERS | CronTrigger 상세 |
| QRTZ_SIMPROP_TRIGGERS | 속성 기반 트리거(CalendarInterval 등) |
| QRTZ_BLOB_TRIGGERS | BLOB(BYTEA) 직렬화 트리거 |
| QRTZ_CALENDARS | 캘린더(제외 일자 등) 저장 |
| QRTZ_PAUSED_TRIGGER_GRPS | 일시정지된 트리거 그룹 |
| QRTZ_FIRED_TRIGGERS | 발화 중/완료 트리거 상태 |
| QRTZ_SCHEDULER_STATE | 스케줄러 인스턴스 상태(클러스터 점검용) |
| QRTZ_LOCKS | 비관적 잠금(JobStore 동시성 제어) |

> 제외 사유: Quartz 라이브러리 표준 스키마(인프라)로 저작도구의 도메인 설계 대상이 아니다. 진실원은 Quartz 공식 PostgreSQL DDL 스크립트다.

## 5. 작성 참고

- **DBMS**: PostgreSQL, 스키마 `klid_at`, 인코딩 UTF-8. (템플릿 예시의 MariaDB/InnoDB/MaxScale/utf8mb4 전제 미적용.)
- **마이그레이션 진실원**: Flyway 10.13 + `flyway-database-postgresql`, `backend/src/main/resources/db/migration/V0~V54`. V3에서 행안부 공통표준용어 약어 정합(예: `RAW_FILE_PATH_NM`, `DE_IDNTF_YN`, `PRVC_TYPE_CD`, `MDFCN_DT`).
- **명세 대상 합치**: §3 테이블 명세 = 저작도구 소유·운영 활성 `LS_*` **37개(KLID-AT-TB-001~037)** full 컬럼 명세. §4 참조·인프라 = 외부 소유 `MNG_*` 9종 + `QRTZ_*` 11종(목록·용도만). §2 데이터베이스 정의 표도 동일 37개로 합치한다.
- **JPA 정합**: `ddl-auto=validate` 고정. 본 명세 컬럼명은 엔티티 `@Column(name=...)` 와 1:1 일치.
- **키 생성**: PK는 `BIGINT GENERATED BY DEFAULT AS IDENTITY`(`@GeneratedValue(IDENTITY)`).
- **물리 FK 원칙적 미설정**: 공유 DB 운영 안정성 우선 정책으로 LS_* 간 물리 FK는 원칙적으로 정의하지 않고 ID 참조(논리 FK)로 관리한다. **예외**: `LS_LABEL_PRESET_CODE → LS_LABEL_PRESET`은 물리 FK `FK_LS_LABEL_PRESET_CODE_PRESET (PRESET_ID) REFERENCES LS_LABEL_PRESET(PRESET_ID) ON DELETE CASCADE`(V13)를 보유 — 프리셋 삭제 시 하위 코드 일괄 정리.
- **TEXT/대용량 컬럼**: `POINT_CN`, `LABEL_PAYLOAD`는 PostgreSQL `TEXT`. (JSONB 미사용 — 현 코드는 TEXT 직렬화. 검색 최적화 필요 시 JSONB+GIN 전환 검토.)
- **트리거**: 전 테이블 트리거 미사용. 일시 컬럼 갱신은 엔티티 비즈니스 메서드 / `@PrePersist`/`@PreUpdate`로 처리.
- **데이터마트 적재 View**(V52): `V_COMPLETED_VIDEO`/`V_COMPLETED_FRAME`/`V_COMPLETED_LABEL`(+ATTR)/`V_COMPLETED_META` — 검수 완료 영상만 노출하는 읽기 전용 `CREATE OR REPLACE VIEW`(멱등). 테이블 명세 대상 아님.
