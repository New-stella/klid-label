## rationale

엔드포인트 path 가 context-path(/api) 를 미포함하고, security 키 jwt 의 실체(Authorization Bearer JWT)와 채널 격리 규칙이 카탈로그에 정의되지 않아 '엔드포인트만 보고 호출'이 막혔던 문제(예: /v1/notices 404)를 해소한다. 98개 엔드포인트마다 /api·Authorization 헤더를 중복 기재하는 OpenAPI 안티패턴 대신, 전역 규약 1건으로 DRY 하게 명세한다.

※ D5 §3(발주처 비기능 정합) 제외: 본 항목은 저작도구 내부 API 호출 설계규약으로 발주처 요구사항정의서(비기능)에 대응 ID가 없다(구 RQ-SIR-01-01 매핑은 'SIR-01=화면 UX/UI 표준'과 성격 상이로 매핑 불성립, D5 v1.5에서 삭제). 내부 규약·API 적용(API-095/065/084)은 유효하므로 approved 유지하고 sub_id는 부여하지 않는다.

## description

LogiCraft 엔드포인트(API-*) 만 보고 별도 문의 없이 실제 HTTP 호출을 구성하기 위한 전역 규약. 모든 `/v1/**` API 에 적용된다.

## 1. Base URL (servers)
모든 경로 앞에 context-path `/api` 가 붙는다 (`server.servlet.context-path=/api`). LogiCraft `path` 는 `/v1/...` 만 기록하므로 호출 시 `/api` 를 선행해야 한다.

| 환경 | Base URL |
|------|----------|
| local | http://localhost:8080/api |
| dev/검증 | 개발·검증 서버 호스트 + /api |
| stg/prd | 배포 도메인 + /api (CORS_ALLOWED_ORIGINS 로 origin 통제) |

예: 엔드포인트 `GET /v1/notices` → 실제 `GET http://{host}/api/v1/notices`. (`/api` 누락 시 404)

## 2. 인증 스킴 — Bearer JWT
- LogiCraft 엔드포인트의 `security: [{ "jwt": [역할...] }]` 는 Bearer JWT 인증을 뜻한다.
- 런타임 OpenAPI 스킴명은 **`bearerAuth`** (type=http, scheme=bearer, bearerFormat=JWT, 전역 적용). 즉 LogiCraft 키 `jwt` ≡ 런타임 `bearerAuth`.
- 전달: HTTP 헤더 `Authorization: Bearer <JWT>`
- 발급: 저작도구는 토큰을 발급하지 않음 — 관제서버(내부)/포털(외부)이 발급한 토큰을 인계. STATELESS(세션 미사용).
- 클레임: `role`(REVIEWER|WORKER|PORTAL_USER) + `channel`(INTERNAL|PORTAL).
- 실패: 인증 누락/만료 → 401, 역할/채널 불일치 → 403.

curl 예: `curl http://{host}/api/v1/notices -H "Authorization: Bearer <JWT>"`

## 3. 역할 + 채널 접근 규칙
- `security.jwt[]` 의 역할 배열 = 허용 역할. 빈 배열 `[]` = 역할 무관(인증만 요구).
- 채널 격리(R5-1): `/v1/portal/**` 는 PORTAL 채널 토큰(CHANNEL_PORTAL + ROLE_PORTAL_USER)만, 그 외 `/v1/**` 는 INTERNAL 채널만 허용(channel 클레임 없으면 INTERNAL 기본).
- 쓰기 핸들러는 메서드 단위 권한 검사로 추가 강제(예: 게시판 쓰기 = REVIEWER, 조회 = REVIEWER/WORKER).

## 4. 인증 예외 경로
- permitAll: `/health`, `/actuator/health/**`, `/actuator/info`, `/swagger-ui/**`, `/v3/api-docs/**`, `/v1/auth/**`, `/v1/portal/auth/**`
- webhook(JWT 우회, **무서명** 규격 — ADR-031): `/v1/vlm/callback`(외부 VLM 시계열 결과, API-065), `/v1/genai/callback`(생성형 AI 증강 결과, API-165) 2종. 벤더 확정 계약이 무서명이라 HMAC 을 요구하지 않으며(서명 필수 경로 목록은 비어 있다), 대신 무서명 가드(IP allowlist·rate limit·본문 크기 상한) + 게이트 재확인을 거치고 최종 인증은 각 서비스의 request_id 발급 게이트가 담당한다. 증강은 IP allowlist 미설정 시 fail-closed, VLM 은 완화된다. 구 경로 `/v1/deidentify/result`(API-054, 비식별은 KPST 폴링으로 단일화)·`/v1/augments/result`(API-064)·`/v1/aug/callback`(HMAC, 계약 불일치)은 제거·deprecated 됐다.
- 영상 스트림: `Authorization` 헤더 우선, 없으면 단기 서명 쿼리(exp/sig) 검증.
- denyAll(통합 deprecated): `/v1/integration/**`, `/v1/export-api/**`
- dev 전용(prd 부재): `/v1/dev/tokens`·`/v1/dev/batch/**` permitAll, 그 외 `/v1/dev/**` 와 `/actuator/**` 는 REVIEWER.

## 5. 자가서비스 호출 (권장 경로)
실행 중 Swagger UI 가 servers(요청 기준 `/api` 자동) + Authorize(bearerAuth) + Try it out 을 제공한다. `http://{host}/api/swagger-ui/index.html` 에서 토큰 입력 후 직접 호출 가능 — 별도 문의 불필요.

## 6. 응답 / 페이징 규약
- 모든 응답은 `ApiResponse<T>` 래퍼: `{ success, data, message, errorCode }`
- 목록은 페이징: `?page=0&size=20&sort=field,desc` → `data: { content[], totalElements, totalPages, number, size }`
