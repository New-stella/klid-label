# SCREEN-021 전체 구축 현황 리포트 내려받기 — 섹션 5개 실집계와 화면 수치 일치 (happy)

## notes

전체 구축 현황 조회 흐름이 내려받기 단계를 품도록 넓혀 이 기준을 그 흐름에 매달았다. 조회와 내려받기를 갈라 세우지 않은 것은, 화면에서 수치를 읽고 그것을 파일로 받는 것이 한 사람의 이어진 동선이고 이 기준 자체가 「같은 시점 화면이 보여주는 값과 일치한다」를 요구해 둘이 같은 흐름 안에 있어야 검증이 성립하기 때문이다.

## priority

high

## scenario

### then

- 받은 파일이 표 계산 프로그램에서 한글이 깨지지 않고 열린다
- 섹션 블록 다섯이 모두 들어 있고 각 블록이 대괄호로 감싼 제목 행으로 시작한다
- 누적 학습데이터와 처리현황의 수치가 같은 시점 화면의 값과 일치한다
- 처리현황이 네 구간으로 담기고 처리중이 진행중과 검수대기의 합이다
- 일별 작업량에 작업이 없던 날도 0 행으로 남아 날짜가 연속한다
- 이벤트 유형 분포에서 검수완료와 전체가 같은 유형끼리 나란히 놓인다
- 작업자별 현황이 여섯 칸이고 비율 값이 0 부터 100 사이다
- 배정된 작업자가 없어도 오류 없이 내려받아지고 제목 행이 남는다

### when

- 전체 구축 현황 화면에서 리포트 내려받기를 실행한다

### given

- 검수자로 인증되어 있다
- 검수완료 영상과 진행중 영상이 함께 존재한다

## statement

검수자가 전체 구축 현황 화면에서 리포트를 내려받으면, 화면이 보여주는 다섯 축이 한 파일 안에 섹션 블록으로 모두 담긴다. 누적 학습데이터·처리현황·일별 작업량·이벤트 유형 분포·작업자별 현황이 그 다섯이며, 파일 첫 행에는 생성 기준 일시가 들어간다. 각 수치는 같은 시점 화면이 보여주는 값과 일치한다. 처리현황은 화면과 같이 완료·처리중·대기·실패 네 구간으로 접혀 담기며 처리중은 진행중과 검수대기를 합한 값이다. 일별 작업량은 작업이 없던 날도 0 으로 채워 날짜가 끊기지 않고, 이벤트 유형 분포는 데이터가 없는 유형도 0 으로 포함한다. 작업자별 현황의 오토라벨과 반려율은 0 부터 100 까지의 백분율로 담기며 별도로 다시 환산하지 않는다.
