# 시나리오 변경 사항 V2.0

> 작성일: 2026-05-26
> 목적: 기존 배치 파이프라인 + 증강 + 포털 흐름의 설계 변경 정리. 개발 계획 수립 기초 자료.

---

## 1. 마킹 단계 신규 추가

### 1.1 개요

기존 파이프라인: `영상 등록 → VLM 시계열 → 비식별화 → 프레임 추출 → YOLO → SAM2 → 트랙 보간`

**변경 후**: `영상 등록 → ⭐마킹 → VLM 시계열(콜백) → 비식별화 → 프레임 추출(마킹 기반) → YOLO → SAM2 → 트랙 보간`

마킹은 기존 자동 프레임 추출(일정 간격) 앞에 삽입되는 **사전 이벤트 식별 단계**.

### 1.2 마킹 모드 (영상별 설정)

| 모드 | 동작 | 설정값 |
|------|------|--------|
| **자동 모드** | 프레임 간격 설정 → 해당 간격으로 자동 마킹 생성 | `markingIntervalSec` (초 단위 간격) |
| **수동 모드** | 작업자가 영상 재생하면서 이벤트 발생 시점에 키보드 단축키로 마킹 | 키보드 단축키 필요 (예: Space, Enter) |

### 1.3 마킹 결과 데이터 구조

```json
{
  "eventName": "이벤트명 (예: 교통사고, 보행자 침입 등)",
  "videoPath": "NAS 경로 (영상 위치)",
  "marks": [
    { "frameIndex": 150, "timestamp": "00:05:00" },
    { "frameIndex": 300, "timestamp": "00:10:00" },
    { "frameIndex": 450, "timestamp": "00:15:00" }
  ]
}
```

- 마킹 정보는 `분:초:프레임` 또는 `프레임 index`로 전달
- VLM에서 이벤트 발생 부분의 시계열 정보 작성에 사용됨

### 1.4 VLM 연동 (변경)

- **기존**: 배치 파이프라인에서 VLM을 동기/반동기로 호출
- **변경**: CALLBACK 형태로 API 호출 + 비동기로 결과 수신
  - 저작도구 → VLM: 마킹 결과(이벤트명 + 영상 경로 + 마킹 배열) 전달
  - VLM → 저작도구: 콜백으로 시계열 분석 결과 수신 (기존 `VlmResultController` 활용)

### 1.5 파이프라인 변경

마킹 완료 + VLM 시계열 수신 이후:
1. **비식별화** — 원본 영상 전체 비식별 처리
2. **프레임 추출** — 마킹된 위치(프레임 인덱스) 기준으로 원본 + 비식별본 2벌 추출 (기존: 일정 간격 → 변경: 마킹 위치 기반)
3. **오토라벨링** — **원본 기준**으로 YOLO+SAM2 실행. 결과는 원본/비식별본 공유

### 1.6 구현 위치

| 구분 | 위치 | 비고 |
|------|------|------|
| 마킹 UI | **저작도구 FE** | 영상 재생 + 마킹 도구 (자동/수동 모드) |
| 마킹 저장 API | **저작도구 BE** | 마킹 결과를 DB 저장 + VLM 콜백 요청 발송 |
| VLM 콜백 수신 | **저작도구 BE** | 기존 `VlmResultController` 확장 |
| 프레임 추출 변경 | **저작도구 BE** | `FfmpegFrameExtractor` — 마킹 위치 기반 추출로 변경 |

## 2. 프레임 추출 방식 변경

### 2.1 기존 → 변경

| 항목 | 기존 | 변경 |
|------|------|------|
| 추출 기준 | 일정 간격 (배치 설정 `frameIntervalSec`) | **마킹된 프레임 인덱스** 기준 |
| 추출 대상 | 원본 + 비식별본 동시 | 동일 (유지) |
| 오토라벨링 기준 | 원본 + 비식별본 각각 | **원본만 실행, 결과를 비식별본과 공유** |

### 2.2 오토라벨링 결과 공유 로직

- YOLO/SAM2는 **원본 이미지**에만 실행
- 라벨 좌표(bbox, polygon)는 원본과 비식별본이 동일 해상도이므로 그대로 적용
- `LS_DATA_LBL.SRC_SN`은 원본 프레임 SRC_SN 기준으로 저장
- 비식별본 프레임은 별도 `SRC_SN`이지만 동일 `FRAME_NO`로 매핑 → 라벨 공유

## 3. 증강 = 새 영상 개념

### 3.1 기존 → 변경

| 항목 | 기존 | 변경 |
|------|------|------|
| 증강 결과 | 기존 영상에 증강 이미지 추가 | **새 영상(RAW_SN) 생성** |
| JSON 정보 | - | 원본 영상의 JSON 정보(라벨/메타) 복사 |
| 해상도 변경 증강 | - | 이미지 해상도만 변경하여 저장 (라벨 재계산 불필요) |
| 검수 상태 | - | **미검수(PENDING) 상태**로 시작 |
| 작업 플로우 | - | 작업자 배정 → 수정 → 검수 (기존 플로우 동일) |
| 관제서버 통지 | 기존 영상 ID로 통지 | **새 영상 ID(RAW_SN)로 별도 완료 통지** |

### 3.2 증강 흐름 (변경 후)

```
1. REVIEWER가 원본 영상에 증강 요청 (WINTER/NIGHT/RAIN/RESOLUTION 4종)
2. ExternalAugmentClient → 외부 증강 서비스 요청 (기존 흐름 유지)
3. 콜백 수신 (AugmentResultController)
4. ⭐ 새 영상(LS_DATA_RAW) 생성 — 원본 RAW_SN과 다른 새 RAW_SN
5. ⭐ 원본 영상의 라벨/메타 JSON 복사 → 새 영상에 적용
6. ⭐ 해상도 변경 증강: 이미지 해상도만 변경하여 저장
7. ⭐ 새 영상 상태: PENDING (미검수)
8. REVIEWER가 새 영상에 작업자 배정
9. WORKER가 라벨 수정 → 검수 제출
10. REVIEWER 검수 승인 → TASK_COMPLETED 통지 (새 영상 ID로)
```

### 3.3 DB 영향

- `LS_DATA_RAW`: 증강 결과를 새 행으로 INSERT. 원본 RAW_SN 참조 컬럼 필요 (`PARENT_RAW_SN` 또는 `AUG_SOURCE_RAW_SN`)
- `LS_DATA_AUG`: 기존 테이블에 원본↔증강 매핑 유지
- `LS_DATA_SRC`: 증강 영상의 프레임도 별도 행으로 생성
- `LS_DATA_LBL`: 원본 라벨 복사 → 새 SRC_SN으로 INSERT

## 4. 포털향 변경

### 4.1 기존 → 변경

| 항목 | 기존 | 변경 |
|------|------|------|
| 데이터 소스 | 저작도구 DB 직접 조회 | **관제서버 → 데이터마트 → 포털 DB 적재** 후 조회 |
| 라벨링 화면 | 포털 전용 간편 라벨링 | 기존 저작도구 라벨링 데이터를 **Load**하여 표시 |
| 저장 방식 | 포털 사용자 데이터 직접 저장 | **원본 데이터 수정 없이 사용자 작업 데이터로 추가 적재** |
| 다운로드 | 본인 업로드 데이터 한정 | 데이터마트에서 전달된 데이터도 포함 |

### 4.2 포털 데이터 흐름

```
1. 관제서버가 완료된 영상 데이터를 데이터마트로 전달
2. 데이터마트가 포털 DB에 적재 (저작도구 직접 관여 X — 관제서버 책임)
3. 포털 사용자가 영상 선택
4. 저작도구가 포털 DB에서 해당 영상의 라벨/메타 데이터 Load
5. 라벨링 화면에 기존 데이터 표시
6. 사용자가 수정 → 저장
7. ⭐ 저장 시 원본 데이터를 수정하지 않고, 사용자별 작업 데이터로 별도 적재
8. 사용자가 다운로드
```

### 4.3 DB 영향

- 포털 사용자 작업 데이터 테이블 필요 (기존 `LS_PORTAL_USER_VIDEO` 확장 또는 신규)
- 원본 라벨과 포털 사용자 라벨을 분리 저장하는 구조 필요
- 포털 DB에서 데이터마트 적재 데이터를 읽는 Repository 필요 (`@PortalRepo`)

## 5. 기존 배치 파이프라인 변경 요약

### 5.1 기존 파이프라인 (V1.x)

```
영상 등록 → VLM 시계열(동기) → 비식별화(무조건) → FFmpeg(일정 간격) → YOLO → SAM2 → 트랙 보간
```

### 5.2 변경 파이프라인 (V2.0)

```
영상 등록 → ⭐마킹(자동/수동) → VLM 시계열(콜백 비동기) → 비식별화 → FFmpeg(마킹 위치 기반) → YOLO(원본만) → SAM2 → 트랙 보간
                                                                                         ↓
                                                                              오토라벨 결과 = 원본/비식별 공유
```

### 5.3 영향받는 기존 컴포넌트

| 컴포넌트 | 변경 내용 |
|---------|---------|
| `BatchOrchestrator` | 마킹 단계 추가 (VLM 이전), 프레임 추출 로직 변경 |
| `FfmpegFrameExtractor` | 일정 간격 → 마킹 위치 기반 추출 |
| `VlmTimeseriesStep` | 동기 → 콜백 비동기로 전환 |
| `YoloAutolabelStep` | 원본만 실행, 비식별본에 결과 공유 |
| `AugmentResultService` | 증강 결과를 새 영상으로 등록 + 라벨 복사 |
| `PortalLabelService` | 포털 DB에서 데이터마트 데이터 Load + 사용자 작업 데이터 별도 적재 |
| `ControlNotifyService` | 증강 영상도 별도 RAW_SN으로 완료 통지 |

## 6. 신규 개발 필요 항목 요약

### 6.1 BE 신규

| # | 항목 | 우선순위 | 비고 |
|:-:|------|:-------:|------|
| 1 | 마킹 도메인 (Entity + Service + Controller) | HIGH | 자동/수동 마킹 저장, 영상별 마킹 모드 설정 |
| 2 | 마킹 → VLM 콜백 요청 API | HIGH | 마킹 완료 시 VLM에 콜백 형태로 요청 |
| 3 | `FfmpegFrameExtractor` 변경 | HIGH | 마킹 위치 기반 프레임 추출 |
| 4 | `YoloAutolabelStep` 변경 | MEDIUM | 원본만 실행 + 비식별본 공유 로직 |
| 5 | 증강 결과 → 새 영상 생성 로직 | HIGH | `AugmentResultService` 확장 — 새 RAW_SN + 라벨 복사 |
| 6 | `LS_DATA_RAW` 증강 원본 참조 컬럼 | MEDIUM | `PARENT_RAW_SN` 추가 (Flyway) |
| 7 | 포털 데이터마트 데이터 Load 서비스 | MEDIUM | `@PortalRepo`로 데이터마트 적재 데이터 조회 |
| 8 | 포털 사용자 작업 데이터 별도 적재 | MEDIUM | 원본 미수정, 사용자별 라벨 저장 |
