## 1. 사용자 인터페이스 구조도

본 도구는 **2개 채널 + 1개 진입점**으로 구성된다.
- **INTERNAL 채널**: 저작도구 내부 사용자(REVIEWER / WORKER)용. `AppLayout`(LNB + GNB) 적용
- **PORTAL 채널**: 외부 포털사용자(PORTAL_USER)용. `PortalLayout`(모바일 친화, LNB 없음)
- **공통**: `/ingress` (관제·포털서버 JWT 인계), `/forbidden`, `/role-claim` (role 자가 부여)

```text
[Public]
├─ /ingress                        세션 진입(SessionIngressPage)
├─ /forbidden                      403
└─ /role-claim                     역할 자가 부여 (인증만 필요)

[INTERNAL 채널 — AppLayout]
└─ /
   ├─ /dashboard                   대시보드 (REVIEWER, WORKER)
   ├─ /video
   │   ├─ /video/completed         완료 영상 목록
   │   ├─ /video/status            처리 상태 목록
   │   └─ /video/:id               영상 상세
   ├─ /task
   │   ├─ /task                    내 작업 목록
   │   └─ /task/assign             작업 배정 (REVIEWER 전용)
   ├─ /label/:id                   라벨링 캔버스 (풀스크린, AppLayout 밖)
   ├─ /auto/:videoId               오토라벨 요약
   ├─ /auto/:videoId/meta          시계열 메타 검토
   ├─ /deident
   │   ├─ /deident                 비식별 영상 목록
   │   └─ /deident/:videoId        비식별 영상 상세 (재처리 트리거)
   ├─ /review
   │   ├─ /review                  검수 목록 (REVIEWER)
   │   ├─ /review/pending          검수 대기 (alias)
   │   └─ /review/:id              검수 상세 (REVIEWER)
   ├─ /history/:videoId            버전 이력
   ├─ /stat
   │   ├─ /stat                    워커 통계
   │   ├─ /stat/worker             워커 통계 (alias)
   │   └─ /stat/overall            전체 통계 (REVIEWER 전용)
   ├─ /augment
   │   ├─ /augment                 증강 요청
   │   ├─ /augment/request         증강 요청 (alias)
   │   └─ /augment/result/:jobId   증강 결과 상세
   └─ /manage
       ├─ /manage/users            사용자 관리 (REVIEWER)
       ├─ /manage/settings         시스템 설정 (REVIEWER)
       ├─ /manage/presets          라벨 프리셋 (REVIEWER)
       └─ /manage/*                기타 관리

[PORTAL 채널 — PortalLayout]
└─ /portal
   ├─ /portal                      포털 홈 (업로드 + 내 영상)
   └─ /portal/label/:id            포털 간편 라벨링
```

> **가드 적용**: 모든 INTERNAL/PORTAL 경로에 `ChannelGuard` + `RoleGuard` 이중 적용. PORTAL 사용자가 INTERNAL 경로 진입 시 → `/forbidden`.

## 3. 화면 상세 설계

> 본 절은 대표 화면 14건을 상세 기술한다. (전체 26개 화면 중 비반복 핵심)

### 3.1 KLID-AT-SC-001 세션 진입(SessionIngress)

| 화면 ID | KLID-AT-SC-001 | 화면명 | 세션 진입(SessionIngress) |
|---|---|---|---|
| **관련 유스케이스 ID** | KLID-AT-UC-013 | **관련 시퀀스도 ID** | KLID-AT-SD-007 |
| **화면유형** | 입력(쿼리 파라미터 처리) | **메뉴경로** | `/ingress` (외부 진입점) |

**화면 개요**: 관제서버·포털서버가 본 도구로 redirect 하면서 `?token=...` 으로 JWT 를 전달. 토큰을 SecurityContext 에 등록하고 채널·역할에 따라 적합한 시작 화면으로 자동 이동.

**입출력 항목**

| 항목명 | 컨트롤명 | 타입 및 길이 | 속성 | Validation |
|---|---|---|---|---|
| token | hidden | String(<=4096) | I/H | 필수, JWT 형식, HS256 |
| issuer | hidden | String | I/H | 허용 issuer만 |
| 이동 안내 텍스트 | label | - | O | "이동 중입니다…" |
| 오류 안내 | label | - | O | 401 시 표시 |

**처리 내용**:
1. URL 파라미터에서 `token` 추출 → `JwtAuthenticationFilter` 사전 검증 (KLID-AT-SD-007)
2. 통과 시 `channel`(INTERNAL/PORTAL) + `role` 분기 → INTERNAL+REVIEWER → `/dashboard`, INTERNAL+WORKER → `/task`, PORTAL_USER → `/portal`
3. 실패 시 `/forbidden` 으로 redirect + 발급자 로그인 URL 안내

**기술적 고려사항**: token 길이 4KB 초과 시 query → POST body 로 fallback. CSP `default-src 'self'`.
