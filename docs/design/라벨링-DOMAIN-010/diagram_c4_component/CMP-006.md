## description

검수 승인(APPROVED) 시점에 영상 단위 라벨 전체 스냅샷(JSON)을 LS_LABEL_VERSION 에 저장하고(VERSION_HASH SHA-256), 검수완료 버전 간 diff 계산·롤백을 제공한다. VersionController(/v1)가 VersionService 를 호출하고, ReviewService 가 승인 시 VersionService 를 호출한다.

[★롤백 시맨틱] 새 버전을 적층하는 것이 아니라 대상 스냅샷 행을 재활성화한다 — 롤백 결과 페이로드가 대상 스냅샷 그 자체라 해시가 같아 (DATA_SRC_SN, VERSION_HASH) UNIQUE 에 걸리기 때문이다. SAVE_REASON_CD='ROLLBACK' 코드는 폐기됐고 롤백 행위는 LS_DATA_LBL_HSTRY 에 기록한다. 본문을 작업본으로 복원할 때 LBL_SN·AI 메타·TRCK_ID 를 보존하며, 현재 active 가 이미 대상 스냅샷이면 no-op 이다.

[★비교축이 둘이다] 두 버전 비교는 GET /v1/versions/{version}/diff?compareWith= 이고, 버전 1건과 현재 작업본(LS_DATA_LBL) 비교는 별도 sub-resource GET /v1/versions/{version}/diff-with-working 이다. 승인 버전이 1건뿐인 프레임은 전자로는 비교 대상이 없어 변경 내역을 아예 볼 수 없었기 때문이며, 구 동작 '1건 선택 = 목록상 직전 버전과 비교' 는 폐기됐다. 작업본 payload 는 승인 스냅샷과 동일한 방식으로 생성하고 저장하지 않는다(어긋나면 수정이 없는데 diff 가 나온다). 손상 스냅샷은 신규 경로에서만 400 이고 기존 /diff 의 장애격리(파싱 실패 → 빈 리스트)는 유지한다 — 의도된 차이라 통일하지 않는다.

[★비교축 확장] 판정 항목은 id·lblTypeCd·label·labelId·points·trackId 여섯이다. 구 동작(lblTypeCd·label·points 셋만)은 폐기됐다 — 트랙 병합처럼 시스템이 스스로 export 재생성·관제 재통지까지 한 변경이 diff 에선 '변경 없음'으로 보였다. 비교기를 두 경로가 공유하므로 /diff 의 판정 결과도 함께 바뀐다(계약은 무변경). AI 메타(autoLblYn·confScore·lblSrcCd)와 labelName·color 는 의도적 제외다.

[게이트] 비식별 누락 신고(DE_IDNTF_YN='F') 구간에는 diff·롤백이 412 로 차단된다(역할 무관).

컴포넌트·관계는 실제 생성자 의존성에서 도출.
