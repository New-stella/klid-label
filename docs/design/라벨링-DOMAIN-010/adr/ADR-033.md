# 라벨 변경이력 재설계 — 저장이벤트=diff + full-replace + 되돌리기

## context

'라벨 1건=1행' 이력 모델(LBL_SN/CHG_KIND_CD)이 저장 시 부분 upsert만 반영해 빠진 라벨이 실제로 삭제되지 않던 결함이 있었고, 이력이 지나치게 세분화돼 추적성이 낮았다.

## decision

### chosen_option

저장이벤트=diff + full-replace + 되돌리기(채택)

### justification

라벨 변경이력을 '저장 이벤트 1회=1이벤트+diff'(ADD_CNT/MDFCN_CNT/DEL_CNT/CHG_DTL_CN JSON)로 재설계한다. 저장은 프레임 전체 교체(full-replace)로 빠진 라벨을 실제로 삭제한다. 저장 이벤트 단위 되돌리기(작업본 복원, 즉시DB저장 아님, 승인 전에도 동작)를 신규 제공한다. 무변경 저장은 pointCn 정규화 비교(3포맷)로 판정해 이력 오염을 방지하며, 공유 삭제 repo에 clearAutomatically 사용을 금지한다(PII 방어 무력화 위험).

## considered_options

### '라벨 1건=1행' 이력 모델 + 부분 upsert(구, 결함)

**cons**:

- 부분 upsert만 반영돼 빠진 라벨이 실제로 삭제되지 않음
- 이력이 지나치게 세분화돼 추적성 낮음

**pros**:

- 변경 단위가 세밀

- **description**: 라벨 변경마다 LBL_SN/CHG_KIND_CD 행을 개별 기록하고 저장은 부분 upsert

### 저장이벤트=diff + full-replace + 되돌리기(채택)

**cons**:

- 무변경 저장을 오탐하지 않도록 pointCn 정규화 비교(3포맷) 로직 필요

**pros**:

- 빠진 라벨이 실제로 삭제되어 저장 시맨틱이 정확함
- 저장 이벤트 단위 추적성·되돌리기 제공

- **description**: 저장 이벤트 1회=1이벤트+diff(ADD_CNT/MDFCN_CNT/DEL_CNT/CHG_DTL_CN JSON)로 재설계. 저장은 프레임 전체 교체(full-replace)로 빠진 라벨을 실제로 삭제. 저장 이벤트 단위 되돌리기(작업본 복원) 신규 제공
