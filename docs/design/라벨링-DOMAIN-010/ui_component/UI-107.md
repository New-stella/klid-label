- **description**: 라벨링(SCREEN-005). 창 오른쪽 칸에서 필드와 캡션·근거 후보(cN)를 입력하고 후보를 추가·삭제한다. 근거 후보마다 「화면에서 지정」을 두며, 저장은 창 공통 「저장」 버튼으로 한다. 근거의 프레임은 쉼표로 구분해 입력하고, 적은 번호는 번호마다 칩 하나로 함께 보이며 칩을 누르면 뒤 화면이 그 프레임으로 이동한다. 이동하면 창은 접히며 접힘 띠의 「펼치기」로 되돌린다. 이 영상에 없는 번호는 눌러도 이동하지 않고 「{번호} — 이 영상에 없는 프레임 번호라 이동하지 않았습니다.」를 알린다(Toast).

## description

이벤트 어노테이션(이벤트 분류·질의·답변·캡션 후보·사고 단계·근거 후보)을 편집하거나 읽기 전용으로 보여 주는 패널. 영상 전체에 해당하는 값이라 프레임을 넘겨도 내용이 같다.

배치: 우측 메타 탭이 아니라 「영상 분석 설명 · 이벤트 어노테이션」 비모달 창(FloatingWindow)의 오른쪽 칸에 둔다(왼쪽 칸은 TimeseriesSidePanel). 칸 머리에 제목 「이벤트 어노테이션」·범위 표시 「영상 전체」·한 줄 설명을 두고, 바뀐 값이 있으면 칸 머리에 「저장 안 됨」을 표시한다. 칸 설명은 라벨링 「학습데이터에 함께 저장되는 사건 판단 정보입니다. 이벤트 분류만 꼭 채우고, 나머지는 확인한 만큼 채웁니다.」, 검수 「학습데이터에 함께 저장되는 사건 판단 정보입니다.」다. 우측 메타 탭의 패널 자리는 요약 카드(TimeseriesAnnotationSummaryCard)가 대신하며, 필드·섹션별 팝업은 두지 않는다.

편집 규칙(라벨링 — 유지): 이벤트 분류는 필수다. 후보 키는 cN 이며 「+ 캡션 추가」「+ 근거 추가」로 후보를 추가하고 후보별 「삭제」로 지운다. 캡션 후보는 캡션 문장(여러 줄 입력)과 사고 단계 3칸을 갖는다. 근거 후보는 근거 문장·프레임·객체 번호·객체 분류 이름·객체 박스 필드를 가지며 이 필드들의 입력 파싱 규칙은 그대로다. 프레임은 입력 칸에 쉼표로 구분해 적고, 적은 번호는 입력 칸 아래에 번호마다 칩 하나로 함께 보이며 칩을 누르면 뒤 화면이 그 번호의 프레임으로 이동하고 창은 접히며 접힘 띠의 「펼치기」로 되돌린다. 칩 구성과 동작은 검수와 같다 — 「프레임」을 칩들 앞에 한 번만 두고 칩마다 되풀이하지 않으며, 여러 번호를 한 덩어리로 묶지 않고, 이 영상에 없는 번호는 이동 표식(↗)을 두지 않고 흐리게 「{번호} · 이 영상에 없음」으로 보여 누를 수 있는 칩과 구분하며 눌러도 이동하지 않고 「{번호} — 이 영상에 없는 프레임 번호라 이동하지 않았습니다.」를 알린다(Toast). 「현재 프레임 추가」「선택 객체 추가」 두 동작도 그대로다 — 객체 번호는 트랙 ID → 서버 ID → 클라이언트 ID 순으로, 객체 분류 이름은 라벨명으로, 객체 박스는 외접 박스를 정수로 반올림해 채우고 프레임을 함께 담으며, 담으려는 객체 번호가 이미 있으면 객체 세 필드를 건너뛴다.

근거 지정: 근거 후보마다 「화면에서 지정」 버튼과 설명 「창을 잠시 숨기고 화면에서 프레임·객체를 골라 담습니다」를 둔다. 누르면 창을 숨기고 근거 지정 띠(AnnotationWindowStrip)가 뜨며, 띠에서 위 두 동작으로 담은 뒤 「완료」를 누르면 창이 돌아와 그 근거 후보에 반영된다. 「취소」는 이번에 담은 것만 버린다. 반영 직후 그 후보 안에 「방금 「화면에서 지정」으로 담은 값입니다(프레임 {n}개 · 객체 {m}개). 저장해야 반영됩니다.」를 표시한다.

저장: 패널 자체 저장 버튼을 두지 않는다 — 창 아래 공통 「저장」 하나로 영상 분석 설명과 함께 저장한다. 바뀐 칸만 저장하고 두 칸이 모두 바뀌면 둘 다 저장한다. 한쪽만 실패하면 실패한 칸 머리에 표시하고, 성공한 칸의 「저장 안 됨」은 해제한다.

표기: 이벤트 분류는 이름 + 코드로 보인다(예 「교통사고 car_accident」, 코드는 흐리게). 이름은 영상 상세 응답의 전체 검증 이벤트 유형 목록(allVrfcEvntTypes, API-043)에서 코드로 찾으며 라벨링·검수 모두 같은 목록을 쓴다. 목록에 없는 코드는 코드만 보인다. 후보는 「캡션 1」「근거 1」처럼 이름으로 보이고 옆에 저장 키 c1 을 흐리게 병기한다 — 번호는 저장 키의 숫자이며 목록 순번으로 다시 매기지 않는다. 캡션 문장은 받은 원문 텍스트 그대로 표시하고 그 아래에 「외부 분석 답을 받은 그대로 보여 줍니다 — 굵게·목록 기호(**, ###)를 어떻게 보일지는 사업자 회신 후 정합니다.」 주석을 둔다. 근거가 없을 때 라벨링은 「아직 근거가 없습니다. 「+ 근거 추가」로 만든 뒤 「화면에서 지정」으로 프레임·객체를 담아 주세요.」, 검수는 「근거가 없습니다.」를 보인다.

도움말: 각 필드 라벨 아래에 도움말을 회색 글씨로 항상 표시하고, 입력 칸에는 입력 안내를 둔다. 칸 머리의 물음표 아이콘 버튼으로 끄고 켜며 그 선택은 브라우저에 기억한다. 기본은 도움말이 보이는 상태다. 메타 탭 패널의 도움말과는 별개로 기억하며 기본값도 서로 반대다 — 창은 넓어 설명을 늘 두어도 값을 밀어내지 않지만 그 패널은 좁아 밀어내기 때문이고, 의도된 차이이므로 통일하지 않는다. 글자 없이 아이콘만 두므로 버튼에는 보조기기가 읽을 이름을 반드시 준다 — 도움말이 보이는 동안에는 「도움말 숨기기」, 숨긴 동안에는 「도움말 보기」다. 필드별 문구는 다음과 같다.
- 이벤트 분류(필수): 도움말 「이 영상에서 확인하려는 사건의 종류입니다.」
- 질의: 도움말 「외부 분석에 물어본 질문입니다. 분석을 요청할 때 보낸 문구가 들어 있습니다.」
- 답변: 도움말 「사람이 적는 최종 답입니다.」 · 입력 안내 「이 영상에서 사건이 발생했는지와 그렇게 판단한 이유를 적어 주세요.」
- 캡션(구역): 도움말 「사건을 설명하는 문장 후보입니다. 여러 개를 둘 수 있습니다.」
- 캡션 문장: 도움말 「외부 분석에 물어본 질문의 답이 처음에 채워집니다.」 · 입력 안내 「사건을 한두 문장으로 설명해 주세요.」
- 사고 단계: 도움말 「이 문장에 이르기까지의 생각을 순서대로 적습니다.」 · 입력 안내 1단계 「외부 분석이 적은 상황 설명으로 채워집니다.」 / 2단계 「1단계 다음으로 확인한 내용을 적어 주세요.」 / 3단계 「최종 판단에 이른 이유를 적어 주세요.」
- 근거(구역): 도움말 「판단의 근거가 된 프레임과 객체입니다.」
- 근거 문장: 도움말 「이 프레임·객체가 판단의 근거인 이유입니다.」 · 입력 안내 「이 프레임·객체가 왜 근거인지 적어 주세요.」
- 프레임: 도움말 라벨링 「근거가 보이는 프레임 번호입니다. 여러 개면 쉼표로 구분합니다. 적은 번호는 아래 칩으로 보이며 누르면 그 프레임으로 이동하고 창은 잠시 접힙니다.」 / 검수 「근거가 보이는 프레임 번호입니다. 누르면 그 프레임으로 이동하고 창은 잠시 접힙니다.」
- 객체 번호: 도움말 「근거가 되는 객체(라벨)의 번호입니다. 여러 개면 쉼표로 구분합니다.」
- 객체 분류 이름: 도움말 「객체 번호와 같은 순서로 적습니다.」
- 객체 박스: 도움말 라벨링 「사각형의 왼쪽 위·오른쪽 아래 좌표를 한 줄에 하나씩 x1,y1,x2,y2 로 적습니다.」 / 검수 「객체를 감싸는 사각형의 왼쪽 위·오른쪽 아래 좌표입니다.」
- 검수 화면의 객체(객체 번호와 분류 이름을 합친 칸): 도움말 「근거가 되는 객체(라벨)의 번호와 분류 이름입니다.」

검수(읽기 전용): 입력 컨트롤을 그리지 않고 값만 보인다. 빈 값은 「아직 채우지 않았습니다」로 표시한다. 근거의 프레임은 「프레임」을 앞에 한 번만 두고 그 뒤에 번호마다 칩을 하나씩 나란히 보인다 — 「프레임」 「3 ↗」 「104 ↗」처럼 보이며 접두를 칩마다 되풀이하지 않는다. 칩 하나가 프레임 하나를 가리키며 칩마다 이동할 수 있음을 나타내는 표식(↗)을 함께 보인다. 여러 번호를 한 덩어리로 묶지 않는다 — 묶으면 눌렀을 때 어느 프레임으로 가는지 알 수 없다. 칩을 누르면 뒤 화면이 그 칩의 번호로 이동하고 창은 접히며 접힘 띠의 「펼치기」로 되돌린다. 이 영상에 없는 번호는 칩에 「{번호} · 이 영상에 없음」으로 보인다 — 이동 표식(↗)을 두지 않고 흐리게 보여 누를 수 있는 칩과 구분하며, 눌러도 이동하지 않고 「{번호} — 이 영상에 없는 프레임 번호라 이동하지 않았습니다.」를 알린다(Toast).

## accessibility_notes

읽기 전용 모드는 입력 컨트롤을 렌더하지 않아 탭 순서에 편집 요소가 끼지 않는다. 근거의 프레임 칩은 번호마다 하나씩 두고 키보드로 누를 수 있는 조작으로 둔다 — 앞에 한 번만 두는 「프레임」은 글자이며 조작이 아니다. 라벨링에서는 프레임 입력 칸과 칩이 함께 있으므로 초점 순서를 입력 칸 다음에 칩으로 둔다. 이 영상에 없는 번호의 칩은 이동할 수 없음을 보조기기에도 알려 누를 수 있는 칩과 구분한다. 도움말은 라벨 아래 텍스트로 두어 스크린리더도 읽는다. 도움말을 끄고 켜는 물음표 아이콘 버튼은 글자 없이 아이콘만 두므로 보조기기가 읽을 이름을 반드시 주고, 지금 도움말이 보이는 상태인지도 함께 알린다. 칩의 이동 표식(↗)은 보조 표기이며 이동할 수 있다는 사실은 칩의 이름으로도 알려 표식만으로 정보를 전달하지 않는다. 이벤트 분류 코드와 저장 키를 흐리게 보이는 것은 보조 표기이며, 이름과 후보 이름은 글자로 함께 적어 흐린 표기만으로 정보를 전달하지 않는다. 창 안 입력에 포커스가 있는 동안에는 뒤 화면의 캔버스 단축키가 동작하지 않는다.
