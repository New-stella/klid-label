# VLM 시계열 메타 검토

## goal

외부 VLM 콜백으로 적재된 시계열 메타를 검수큐에서 검토·수정·승인한다

## main_flow

### [1]

- **step**: 1
- **actor**: 외부 VLM 서비스
- **action**: 묘사(describe)·추가 질문(describe-sub) 두 창구의 분석 결과를 창구별 request_id 로 각각 콜백(POST /v1/vlm/callback) 전송한다 — 요청 순서와 도착 순서는 일치하지 않는다

### [2]

- **step**: 2
- **actor**: 시스템
- **action**: 묘사 결과의 서술 전문을 LS_DATA_META(vlm.description)에 적재하고 LS_DATA_META_REVIEW 검수큐에 진입시킨다 — 검수큐에 진입하는 것은 이 서술 전문뿐이다

### [3]

- **step**: 3
- **actor**: 시스템
- **action**: 같은 결과로 이벤트 어노테이션 초안의 자기 칸만 채운다 — 묘사 전문 중 「상황」 항목은 캡션 후보 c1 의 CoT 1단계로, 추가 질문의 답변 서술은 같은 후보의 캡션 본문으로 넣고, 질문 칸은 저작도구가 보관하는 유형별 질문 문구 목록에서 조달한다. 두 축이 후보를 공유하므로 후보를 통째로 교체하지 않는다

### [4]

- **step**: 4
- **actor**: 시스템
- **action**: 승인 이력이 있거나 해당 칸에 값이 이미 있거나 어노테이션 검토가 종결됐으면 채우지 않는다. 중복 콜백은 멱등으로 처리하고, 자동채움 자체는 재검수를 발화시키지 않는다

### [5]

- **step**: 5
- **actor**: 검수자(REVIEWER)
- **action**: 라벨링 캔버스 화면(SCREEN-005) 우측 시계열 메타 패널에서 시계열 메타를 검토하고 필요 시 수정한다

### [6]

- **step**: 6
- **actor**: 검수자(REVIEWER)

## description

저작도구의 VLM 연동은 외부 VLM 서비스 호출로 시계열 정보를 획득하는 연동만 보유한다(VLM 본체는 외부 책임). VLM 서버가 콜백(POST /v1/vlm/callback)으로 결과 전송 → 결과를 LS_DATA_META 에 적재 + 검수큐(LS_DATA_META_REVIEW) 진입 → REVIEWER 가 라벨링 캔버스(SCREEN-005) 우측 시계열 메타 패널에서 검토·수정한다. ⚠ 구 전용 화면 'SCR-AUTO-002'(SCREEN-015, /auto/:videoId/meta)는 진입점 없는 orphan 이라 폐기(deprecated)되었고 SCREEN-005 로 완전 대체되었다. 승인(RVW_STTS_CD='APPROVED')된 메타만 V_COMPLETED_META 로 데이터마트에 노출된다.

[★위탁 규격 — UC-019(마킹) 쪽 제출 입력과 대칭] 위탁 엔드포인트는 묘사(describe) POST /v1/videovlm-klid/describe 와 추가 질문(describe-sub) POST /v1/videovlm-klid/describe-sub 둘이다. 각각 별도 request_id 로 위탁하며, 콜백 바디에 어느 API 의 응답인지 식별하는 필드가 없으므로 request_id 로 위탁 원장을 역조회해 구분한다. 콜백 results 는 배열이 아니라 객체이며 {description} 단일이다 — 일치도(accuracy)와 검출여부(detected)는 검증(verify) 전용 응답 필드라 이 연동으로는 오지 않는다. 프레임 지정은 마킹 본문에서 프레임 인덱스를 얻으면 frame_selected 모드로 그것을 싣고, 하나도 얻지 못하면 frame_interval 모드로 내린다(빈 목록은 규격 위반이라 거부된다) — 마킹 모드는 그 인덱스를 누가 골랐는지만 가른다(수동이면 작업자가 지정한 프레임, 자동이면 간격으로 자동 선택된 프레임)(정렬·중복제거하며 상한 600, 음수 불가). 그리고 추출 간격이나 장수를 지정하는 필드는 두지 않는다 — 간격·장수는 외부 서비스가 관리한다. event_type(관제 인입값)은 미수신·미허용이어도 위탁을 막지 않고 그대로 실어 보내며 수용 여부는 벤더 응답이 정한다(거부되면 SKIP_REASON_SUBMIT_FAILED 로 기록하고 마킹을 VLM_REQUESTED→VLM_FAILED 로 전이시킨다). metaKey 규격은 서술 전문 키 vlm.description(≤2000, 검수큐 진입+편집 가능)을 두고, 레거시 구간 키(구 구간별 응답이 남긴 것)는 삭제하지 않고 읽기 전용으로 병기한다. 일치도 키(vlm.accuracy)는 두지 않는다 — 그 값이 수신되지 않으므로 화면 전용·검수큐 미진입·데이터마트 export 비대상이라는 규정도 규율할 대상이 없다.

[★결과 활용 — 이벤트 어노테이션 초안 자동채움] 두 창구의 결과는 이벤트 어노테이션의 서로 다른 칸에 들어간다. 묘사(describe) 전문은 종전대로 영상 서술 칸(video.vd_description)을 채우고, 여기에 더해 그 전문 중 「상황」 항목만 뽑아 캡션 후보 c1 의 CoT 1단계(event.caption.c1.cot 의 "1단계" 키)를 채운다. 추가 질문(describe-sub)의 답변 서술은 같은 캡션 후보의 캡션 본문(event.caption.c1.caption_text)을 채우고, 질문 칸(event.question)은 저작도구가 보관하는 검증 이벤트 유형별 질문 문구 목록에서 조달한다(마킹에서 고른 값, 없으면 그 유형의 첫 번째). ⚠ 구 서술 폐기 — "추가 질문 결과는 답변(answer) 칸 초안으로 간다" 는 두지 않는다. 답변 칸은 자동으로 채우지 않고 사람이 확정한다.

[「상황」 파싱과 채우지 않는 칸] 묘사 전문은 "- 장소: 주택가 골목" "- 날씨: 흐림" "- 상황: …" 처럼 라벨 줄 단위로 오므로, 「상황」 라벨 줄을 찾아 그 줄의 줄바꿈까지를 값으로 쓰고 다음 라벨 줄로 이어붙이지 않는다. 규격이 라벨의 전체 목록·순서·필수 여부를 정의하지 않으므로 목록에 의존하지 않고 「상황」 줄 하나만 찾는다 — 항목이 늘거나 순서가 바뀌어도 성립한다. 「상황」 줄이 없으면 채우지 않는다(빈 값을 넣지 않는다). CoT 는 1단계 키만 만들고 그 이후 단계 키는 만들지 않는다 — 사람이 입력할 공란이다. 질문 문장은 이벤트별로 외부 서비스가 관리하며 연동 시스템이 지정할 수 없고 응답에도 실려 오지 않으므로, 이벤트유형별 문구를 지어내지 않고, 저작도구가 보관하는 검증 이벤트 유형별 질문 문구 목록에서 조달한다(마킹에서 고른 질문이 있으면 그 값, 없으면 그 유형의 첫 번째 질문, 유형이나 등록된 질문이 없으면 비워 둔다). 근거 서술(evidence)은 채우지 않는다 — 자유 서술이라 프레임·객체 지시로 쪼개려면 문자열 파싱이 필요한데 규격이 그 서술의 형식은 고정돼 있지 않으니 파싱에 의존하지 말라고 못 박는다(위 「상황」 파싱은 규격 콜백 예시에 형식이 명시된 묘사 축이라 별개다).

[두 축의 부분 채움 — 도착 순서 무보장] 두 창구는 같은 캡션 후보 c1 을 공유하고 요청 순서와 콜백 도착 순서가 일치하지 않으므로, 각 축은 후보를 통째로 교체하지 않고 자기 칸만 채운다 — 나중에 도착한 축이 먼저 도착한 축의 값을 지우지 않는다. 자동채움은 신규 수신분에만 적용하고 기적재분은 소급해 채우지 않는다. 보호 경계는 그대로다 — 승인 이력이 있으면 자동채움하지 않고, 값이 이미 있으면 덮지 않으며, 어노테이션 검토가 종결됐으면 하지 않고, 중복 콜백은 멱등이며, 자동채움은 재검수를 발화시키지 않고, 이벤트 분류 조달값이 없으면 행을 만들지 않는다.

[★위탁은 논블로킹 제출] 시계열 위탁 단계는 .block(45s) 로 파이프라인 스레드를 붙잡지 않고 subscribe() 로 제출만 개시한다(구 방식은 외부가 느려지면 core 2 짜리 배치 풀이 통째로 마른다). 수락(ACK) 여부는 완료 핸들러가 비동기로 원장·LS_BATCH_PROC_LOG 에 기록한다.

[미결 회수 — 임계가 두 개] ACK 창(stale-timeout, 기본 30분 — 수락 응답조차 못 본 건)과 콜백 창(callback-timeout, 기본 360분 — 벤더 분석은 영상 길이에 따라 수십 분 걸린다)을 구분한다. 하나로 덮으면 정상 위탁을 빼앗는다.

[신고 구간 보류·재위탁] 외부로 나가는 media.path 가 비식별본인데 신고는 바로 그 비식별본의 마스킹 실패를 뜻하므로, 신고 구간에는 위탁을 실패가 아니라 보류(SKIPPED + 사유 적재)한다. 보류는 스스로 재개되지 않으므로 해소 시 DeidentGateReopenedEvent(EVT-007) 를 신호로 그 SKIPPED 기록을 근거 삼아 재위탁한다(멱등 조건: 시계열 메타 0건). 이 배선이 없으면 시계열 메타가 영구 결손된다.
