## description

저작도구의 VLM 연동은 외부 VLM 서비스 호출로 시계열 정보를 획득하는 연동만 보유한다(VLM 본체는 외부 책임). VLM 서버가 콜백(POST /v1/vlm/callback)으로 결과 전송 → 결과를 LS_DATA_META 에 적재 + 검수큐(LS_DATA_META_REVIEW) 진입 → REVIEWER 가 라벨링 캔버스(SCREEN-005) 우측 시계열 메타 패널에서 검토·수정한다. ⚠ 구 전용 화면 'SCR-AUTO-002'(SCREEN-015, /auto/:videoId/meta)는 진입점 없는 orphan 이라 폐기(deprecated)되었고 SCREEN-005 로 완전 대체되었다. 승인(RVW_STTS_CD='APPROVED')된 메타만 V_COMPLETED_META 로 데이터마트에 노출된다.

[★위탁 규격 — UC-019(마킹) 쪽 제출 입력과 대칭] 위탁 엔드포인트는 POST /v1/videovlm/verify 하나이며 콜백 results 는 배열이 아니라 객체 {accuracy, description} 이다. framerate 는 FPS 가 아니라 '몇 프레임당 1장'(추출 간격, LS_MARKING.FRME_INTV_NOCS)이며 mode 무관 필수(값 없거나 0 이하면 설정 vlm.client.frame-policy.framerate 기본 25 폴백)다. event_type(관제 인입값)은 미수신·미허용이어도 위탁을 막지 않고 그대로 실어 보내며 수용 여부는 벤더 응답이 정한다(거부되면 SKIP_REASON_SUBMIT_FAILED 로 기록하고 마킹을 VLM_REQUESTED→VLM_FAILED 로 전이시킨다). metaKey 규격은 vlm.description(서술 전문 ≤2000, 검수큐 진입+편집 가능)·vlm.accuracy(일치도 0~1, 화면 전용·검수큐 미진입·데이터마트 export 대상 아님) 2종이며 레거시 구간 키(구 describe 응답이 남긴 것)는 삭제하지 않고 읽기 전용으로 병기한다.

[★위탁은 논블로킹 제출] 시계열 위탁 단계는 .block(45s) 로 파이프라인 스레드를 붙잡지 않고 subscribe() 로 제출만 개시한다(구 방식은 외부가 느려지면 core 2 짜리 배치 풀이 통째로 마른다). 수락(ACK) 여부는 완료 핸들러가 비동기로 원장·LS_BATCH_PROC_LOG 에 기록한다.

[미결 회수 — 임계가 두 개] ACK 창(stale-timeout, 기본 30분 — 수락 응답조차 못 본 건)과 콜백 창(callback-timeout, 기본 360분 — 벤더 분석은 영상 길이에 따라 수십 분 걸린다)을 구분한다. 하나로 덮으면 정상 위탁을 빼앗는다.

[신고 구간 보류·재위탁] 외부로 나가는 media.path 가 비식별본인데 신고는 바로 그 비식별본의 마스킹 실패를 뜻하므로, 신고 구간에는 위탁을 실패가 아니라 보류(SKIPPED + 사유 적재)한다. 보류는 스스로 재개되지 않으므로 해소 시 DeidentGateReopenedEvent(EVT-007) 를 신호로 그 SKIPPED 기록을 근거 삼아 재위탁한다(멱등 조건: 시계열 메타 0건). 이 배선이 없으면 시계열 메타가 영구 결손된다.
