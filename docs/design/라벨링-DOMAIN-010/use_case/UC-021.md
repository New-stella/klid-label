# 라벨 편집·임시저장

## goal

배정받은 영상의 프레임에 라벨(바운딩박스/폴리곤/세그멘테이션)과 객체 속성값을 편집하고 작업본을 임시저장한다

## actor

라벨링 작업자(WORKER)

## title

라벨 편집·임시저장

## status

approved

## priority

must

## frequency

상시(고빈도) — 라벨링 작업의 본체라 작업자가 배정받은 영상을 작업하는 내내 프레임마다 반복한다.

## main_flow

### [1]

- **step**: 1
- **actor**: 라벨링 작업자(WORKER)
- **action**: 라벨링 화면에 진입한다 — 본인 배정 검사가 접근을 검증한다(타인 배정 403)

### [2]

- **step**: 2
- **actor**: 라벨링 작업자(WORKER)
- **action**: konva.js 캔버스에서 바운딩박스/폴리곤/세그멘테이션을 생성·수정한다 (LS_LABEL 마스터 코드 기반)

### [3]

- **step**: 3
- **actor**: 라벨링 작업자(WORKER)
- **action**: 객체별 속성값을 입력한다 (LS_LABEL_ATTR 정의 기반)

### [4]

- **step**: 4
- **actor**: 시스템
- **action**: 저장 시 작업본을 LS_DATA_LBL 전체 교체(full-replace, 프레임에 없는 라벨은 실삭제)로 upsert + LS_DATA_LBL_ATTR_VAL 저장한다 (버전 스냅샷 미생성 — 임시저장) 이 저장은 평상시 경로인 프레임 단위 작업본 갱신이며, 조회 응답의 낙관적 동시성 토큰(labelVersion)을 그대로 실어 보낸다. 생략하면 서버가 동시성을 검사하지 않아, 그사이 다른 세션이 이 프레임의 라벨을 바꿨더라도 전량 교체 저장이 그 변경을 조용히 지운다. 검수 승인으로 만들어진 산출 버전을 불러온 뒤의 저장은 이 프레임 단위 방식 대신 영상 전체를 한 번에 확정하는 별도 흐름을 따른다(UC-008).

## description

2계층 분리(Critical): ①작업 임시저장 — 저장 시 현재 작업본을 LS_DATA_LBL에 전체 교체(full-replace)한다(프레임에 없는 라벨은 실제 삭제된다, 부분 upsert 아님 — ADR-033). 되돌리기는 저장 이벤트 단위 diff 이력(GET /v1/frames/{srcSn}/label-history)을 통해 이전 저장본으로 복원할 수 있으며, FE undo/redo(세션 내)와는 별개 개념이다. 학습데이터 버전이 아니며 LS_LABEL_VERSION 스냅샷 미생성. ②학습데이터 버전(확정)은 검수 승인 시점(UC-007). 객체 단위 속성값은 LS_LABEL_ATTR 정의 기반으로 LS_DATA_LBL_ATTR_VAL에 저장. 라벨 코드는 LS_LABEL 마스터 검증. 접근 제어: 본인 배정 검사(CWE-639 IDOR 방어). 캔버스는 konva.js, 단축키·복사/붙여넣기(+10 offset·경계 clamp) 지원. 이미 승인된 영상을 수정하면 그 영상은 재검수 대상이 되고, 검수자가 다시 승인한 시점에 TASK_MODIFIED 통지가 발행된다(UC-009 연계).

## alternate_flows

### 타인 배정 접근

**steps**:

- 403 거부 (CWE-639)

- **trigger**: 본인 배정이 아닌 프레임 편집 시도

### APPROVED 영상 수정

**steps**:

- 동일 작업 ID 유지로 저장되고 그 영상은 재검토 대상(LS_RAW_DATA_STATUS.REVLT_YN='Y')으로 표시된다. 즉시 재생성·통지가 나가지 않으며, 검수자가 그 수정을 다시 승인하는 시점에 export 가 새 버전으로 재생성되고 TASK_MODIFIED 통지가 발행된다(UC-009 연계)

- **trigger**: 검수 완료된 영상의 라벨 수정

### 비식별 누락 신고 구간

**steps**:

- 신고 구간(DE_IDNTF_YN='F') 영상은 라벨 조회(GET)와 저장(PUT /v1/frames/{srcSn}/labels) 를 모두 412 로 차단한다 — 게이트는 인가 검사 이후·락 검사 보다 먼저 평가하며 역할 무관이다
- 409 는 신고와 무관한 락(트랙 병합 등 일시적 충돌)에만 남는다

- **trigger**: 대상 영상이 비식별 재처리 대기 상태

### 값 검증 실패

**steps**:

- 좌표 범위·필수 속성·라벨 코드 정합 검증에 실패하면 저장을 거부하고 조치 가능한 오류 메시지를 안내한다

- **trigger**: 라벨 값이 업무규칙을 위반

### 저장 충돌(동시 편집)

**steps**:

- 저장을 409 로 거부한다 — 그대로 전량 교체 저장을 진행하면 다른 사용자가 방금 저장한 라벨이 조용히 삭제되기 때문이다
- 최신 라벨을 불러와 화면을 갱신할지, 지금 화면의 미저장 변경을 그대로 유지할지 선택하게 한다
- 최신 라벨을 불러오면 미저장 변경은 사라지고, 지금 화면을 유지하면 다시 저장을 시도할 수 있다

- **trigger**: 저장 요청에 실은 동시성 토큰(labelVersion)이 그 프레임의 현재 값과 다르다 — 그사이 다른 세션이 먼저 저장했다
