## description

검수자(REVIEWER)가 이벤트유형별 라벨 프리셋(LS_LABEL_PRESET)을 조회·등록·수정·복제·삭제하는 흐름의 시퀀스 다이어그램. 프리셋의 성질은 조회 경로에서 가장 잘 드러난다 — 프리셋 코드는 라벨명과 형태를 스냅샷으로 저장하지 않고 LBL_ID 로 라벨 마스터를 실시간으로 붙여 파생하므로, 마스터에서 라벨명·형태·색상을 바꾸면 신규·기존 프리셋 표시에 즉시 반영된다. 코드가 참조하는 LBL_ID 는 목록 전체를 한 번에 조회해 붙인다.

저장 경로의 판정은 셋이다. 매핑 이벤트유형은 유효 이벤트유형 키여야 하고(그 밖의 값 400), 빈값은 이벤트 무관 프리셋으로 허용한다. 프리셋 이름은 중복 시 409 다. labelIds 는 활성 마스터에 있어야 하며 미존재·비활성이 하나라도 있으면 400 이다. 이벤트 매핑은 프리셋과 일대일이라, 다른 프리셋이 이미 가져간 이벤트로 저장하면 저장 시점의 유일 제약 위반이 409 로 바뀌어 돌아온다.

수정은 매핑값이 실제로 바뀐 경우에만 매핑 검증을 다시 한다 — 매핑을 그대로 둔 편집까지 매번 검증하면, 나중에 제외 대상이 된 이벤트유형에 이미 매핑돼 있던 프리셋이 이름·설명만 고치려 해도 통째로 편집 불가가 되기 때문이다. 복제는 코드 목록만 물려받고 이벤트 매핑은 비운 채 만들며 (일대일이라 그대로 복사하면 반드시 충돌한다) 이름이 겹치면 번호를 올려 가며 비어 있는 이름을 찾는다. 삭제는 대상이 없어도 오류를 내지 않는 멱등 동작이다.

형태(BBOX·POLYGON)는 라벨 마스터가 소유하므로 요청에서 받지 않고 응답에는 마스터에서 파생한 읽기 전용 값으로만 실린다. 마스터에 연결되지 않은 코드는 오류로 올리지 않고 미연결로 표시한다.
