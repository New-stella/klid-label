## description

검수자(REVIEWER)가 이벤트유형별 라벨 프리셋을 조회·등록·수정·삭제하는 흐름의 시퀀스 다이어그램. 프리셋의 성질은 조회 경로에서 가장 잘 드러난다 — 프리셋 코드는 라벨명과 형태를 스냅샷으로 저장하지 않고 LBL_ID 로 라벨 마스터를 실시간으로 붙여 파생하므로, 마스터에서 라벨명·형태·색상을 바꾸면 신규·기존 프리셋 표시에 즉시 반영된다. 코드가 참조하는 LBL_ID 는 목록 전체를 한 번에 조회해 붙인다.

프리셋은 이벤트유형 1건에 대한 라벨 세트이며 이름과 설명을 갖지 않는다 — 식별 축은 이벤트유형 하나이고, 사람이 읽는 이름은 이벤트유형 마스터의 표시명을 응답에 실어 제공한다.

저장 경로의 판정은 셋이다. 매핑 이벤트유형은 필수이며 등록된 전체 이벤트유형이어야 한다 — 필터 옵션 축이 아니라 등록 여부로 판정하는 이유는, 필터에서 제외된 대분류의 유형도 영상이 들어오면 오토라벨이 돌아야 하고 그러려면 그 유형의 프리셋을 만들 수 있어야 하기 때문이다. 그 이벤트에 이미 프리셋이 있으면 409 로 어느 이벤트인지 알린다. labelIds 는 활성 마스터에 있어야 하며 미존재·비활성이 하나라도 있으면 400 이다. 저장 시점의 유일 제약 위반도 409 로 바꾸어 돌려준다.

수정은 매핑값이 실제로 바뀐 경우에만 매핑 검증을 다시 한다 — 매핑을 그대로 둔 편집까지 매번 검증하면, 나중에 제외 대상이 된 이벤트유형에 이미 매핑돼 있던 프리셋이 라벨만 고치려 해도 통째로 편집 불가가 되기 때문이다. 삭제는 존재하면 지우고 없으면 아무것도 하지 않는 멱등이다.

저장 경로에는 부수효과가 하나 더 있다. 등록·수정이 성공하면 그 이벤트 유형에 대해 보류돼 있던 오토라벨 묶음의 재개가 촉발된다. 재개는 보류 이력이 있고 지금은 프리셋이 실효한다는 두 조건을 모두 만족할 때만 일어나며, 뒤 조건이 멱등을 담당한다 — 이미 재개된 영상을 다시 촉발해도 중복 적재되지 않는다. 재개는 응답을 지연시키지 않고, 재개가 실패해도 프리셋 저장은 되돌아가지 않는다. 삭제는 재개를 촉발하지 않는다 — 프리셋이 사라지면 오히려 보류 조건이 성립하기 때문이다.

담긴 라벨이 전부 AI 검출 클래스에 미매핑이어도 저장은 성공한다 — 거부하지 않고 그 프리셋이 오토라벨링에 적용되지 않는다는 것만 경고한다. 목록 조회가 내려주는 실효 여부도 이 보류 판정을 재사용해 조달하며 이 흐름이 다시 판정하지 않는다.
