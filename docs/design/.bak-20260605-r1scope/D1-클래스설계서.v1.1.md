# D1 클래스 설계서

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-UC/DC/DCD/SD/UCD 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. ※ 요구사항(RQ-SFR-NN-NN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 소프트웨어 관점이나 설계 관점에서의 클래스 모형을 작성한다.

## 작성 방법
> 설계 클래스를 도출하기 위하여 우선 유스케이스별로 시퀀스도를 작성하며, 여기에서 도출된 객체 및 클래스를 연관관계를 이용하여 유스케이스별로 클래스도를 작성한다. 설계 클래스도에서는 클래스명, 속성 및 오퍼레이션을 명확하고 구체적으로 표현하여야 하고 각각의 클래스는 상세한 명세를 기술한다.

### 2-1. KLID-AT-SD-002 — 증강 영상 생성 요청

| 시퀀스도 ID | KLID-AT-SD-002 | 시퀀스도명 | 증강 영상 생성 요청 |

| 주요 액터 | 검수자(REVIEWER) | 주요 클래스 | AugmentController, AugmentRequestService, LsRawDataStatusRepository, ExternalAugmentClient |

```mermaid
sequenceDiagram
    autonumber
    actor RV as 검수자(REVIEWER)
    participant AC as AugmentController

    participant DB as PostgreSQL (LS_RAW_DATA_STATUS)

    AC->>ARS: request(req, actor)
    ARS->>ARS: requireReviewer(actor)

    DB-->>ARS: 상태 목록

        ARS->>EX: requestAugment(videoIds, types) (best-effort)
        EX-->>ARS: ack (실패 시 warn 로그만)

    end
```

### 2-4. KLID-AT-SD-005 — 객체 자동 추적

```mermaid
sequenceDiagram
    autonumber
    actor WK as 라벨링 작업자(WORKER)
    participant LC as LabelController
```
