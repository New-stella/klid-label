# 이관 이력 목록은 서버가 고정한 시간순으로만 쪽 단위로 돌아온다

## notes

지금 볼 것을 고르는 일은 정렬이 아니라 걸러내기가 맡는다는 것이 이 기준의 근거다. 쪽 번호나 한 쪽의 크기가 계약이 정한 범위를 벗어났을 때 어떻게 되는지는 이 기준이 아니라 거부 축의 기준이 맡는다.

## priority

high

## scenario

### then

- 이력이 시간순으로 정렬돼 돌아온다.
- 이관 상태가 정렬 우선순위로 끼어들지 않아, 실패한 이관이 시간과 무관하게 앞으로 당겨지거나 뒤로 밀리지 않는다.
- 요청은 정렬 기준을 고르지 못하고, 서버가 고정한 기준 하나로만 돌아온다.
- 목록은 항상 쪽 단위로 돌아오며 전체 건수와 전체 쪽 수, 현재 쪽 번호와 한 쪽의 크기가 함께 돌아온다.
- 이관 상태로 좁혀도 정렬 기준은 달라지지 않는다.

### when

- 이관 이력 목록을 조회한다.
- 이관 상태로 목록을 좁혀 조회한다.

### given

- 이관이 여러 차례 이뤄졌고 그중 일부는 실패로 끝났다.
- 지금 볼 것을 고르는 일은 정렬이 아니라 걸러내기가 맡는다.

## statement

이관 이력 목록은 항상 쪽 단위로 돌아오고 정렬은 시간순 하나로만 하며, 이관 상태가 정렬 우선순위로 끼어들지 않고 요청이 정렬 기준을 고르지 못한다.
