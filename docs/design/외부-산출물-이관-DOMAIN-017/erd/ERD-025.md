## description

이벤트유형·카테고리 마스터(LS_EVNT_TYPE, LS_EVNT_CTGRY) 물리 ERD. 저작도구 소유이며 영상 이벤트 타입의 단일 진실원(SoT)이다.

[조달처 반전] 구 조달처는 관제 공유 마스터 2종(MNG_EX_EVNT_TYPE + MNG_EX_EVNT_TYPE_MAP)이었으나, 관제 2차에서 적재 주체가 반전(ADR-042)되어 이벤트유형코드·이벤트명·이벤트분류코드가 전부 인입 평면값(LS_DATA_INGEST)으로 들어온다. 남의 스키마를 조회하지 않고 인입 소비 시점에 미등록 유형코드를 자동 등록(원자 upsert)한다. 이미 등록된 유형은 인입값으로 덮어쓰지 않는다(운영자 정정 보호). 신규 수동 생성 경로는 없다 — 등록의 유일한 출처는 인입이다.

[축은 유형(type)이다] 어노테이션 계약(export JSON NiaVideo)의 event_id/event_name 이 영상당 단일 유형 값이기 때문이다. 구 구현은 (대분류+카테고리) 키로 dedup 해 상세 유형들을 하나의 이름으로 뭉갰고, 관제가 실어 보낸 유형별 이름이 표시될 자리가 없었다.

[관제 칸과 운영자 칸 분리 — 핵심 설계] EVNT_NM 은 관제 수신 유형명이라 인입이 갱신하고, OPTR_INDCT_NM 은 운영자 표시명이라 관리 API(PATCH /v1/manage/event-types) 전용이며 관제가 절대 쓰지 않는다. 각자 자기 칸만 쓰므로 '사람이 고쳤다'는 표식 컬럼이 필요 없고, 운영자가 표시명을 지우면 관제값으로 자연 복귀하며 관제 원본이 유실되지 않는다.

[표시명 4단 폴백] COALESCE(운영자 표시명, 관제 수신 유형명, 카테고리명, 유형코드). 판정 단일 원천은 EventTypeDisplayNamePolicy(Java resolve / native SQL SQL_COALESCE) 한 곳이며 복제 금지 — 필터 옵션·코드/라벨 맵·관리 화면·승인 시점 동결(export event_name)이 전부 같은 결과를 내야 한다. 관제 마스터에는 유형별 이름이 애초에 없었고 사람이 읽는 이름은 카테고리 레벨에만 있었으므로, 이관 직후 같은 카테고리의 유형들이 같은 이름으로 보이는 것은 결함이 아니라 정상 상태다.

[★물리 FK 미선언 — 의도된 설계, 되돌리지 말 것] LS_EVNT_TYPE.(EVNT_CLSF_CD, EVNT_CTGRY_CD) 는 LS_EVNT_CTGRY 복합 PK 와 같은 값이지만 물리 FK 를 선언하지 않는다. 이벤트유형은 인입 소비 시점에 자동 등록되는데, FK 가 있으면 관제가 아직 등록되지 않은 카테고리코드를 보내는 순간 그 INSERT 가 FK 위반으로 실패하고 — 예외가 흡수되더라도 — 그 유형이 영구 미등록으로 남는다. 결과적으로 그 영상은 이벤트 필터에서 사라지고 라벨이 원문 코드로 떨어진다. 정합성 문제도 생기지 않는다: 표시명 4단 폴백이 카테고리명 부재를 이미 정상 케이스로 처리하기 때문이다(3순위가 없으면 4순위인 유형코드로 내려간다). 고아 카테고리코드는 오류가 아니라 '아직 카테고리명을 모르는 상태'이며 관제가 카테고리를 보내오면 그때 이름이 붙는다. 즉 참조 무결성을 지키려다 데이터가 아예 안 들어오는 교환이 된다.

[표시명 그룹 축 — 2026-08-05 확정] 위 폴백 때문에 필터 드롭다운에 같은 이름이 여러 번 노출됐다(dev 실측: 침수(범람)x3, 교통사고x3, 화재x2). 표시명이 같은 유형코드를 옵션 1건으로 접고(대표코드=그룹 내 최소 코드), 대표·비대표 어느 코드로 필터해도 그룹 전체를 매칭한다. 필터 파라미터는 이벤트 코드를 유지한다 — 이름을 파라미터로 올리면 LS_LABEL_PRESET.EVNT_TYPE_CD(varchar(20) UNIQUE)에 한글이 들어가지 않고 표시명 변경이 북마크·프리셋을 깨뜨린다. 영구 병합이 아니며, 관제가 EVNT_NM 을 보내거나 운영자가 표시명을 지정하면 그룹이 자동으로 쪼개진다.

(V168 신설) + JPA 엔티티 LsEvntType / LsEvntCtgry. 표시명 해석과 그룹 판정은 단일 지점에서만 수행한다(복제 금지).
