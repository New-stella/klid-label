# 영상 적재 (관제 인입 테이블 직접 INSERT → 폴링 적재)

## goal

관제서버가 학습용 영상 메타를 저작도구 인입 테이블(LS_DATA_INGEST)에 평면 1행으로 직접 INSERT 하면, 저작도구 폴링 배치가 미처리 행을 집어 LS_DATA_RAW 에 적재하고 배치 파이프라인(비식별 선두) 대상으로 등록한다

## actor

관제서버

## title

영상 적재 (관제 인입 테이블 직접 INSERT → 폴링 적재)

## status

## priority

## frequency

주기적(기본 60초) — 관제지원시스템이 인입 원장에 넣은 미처리 행을 폴링 배치가 주기마다 가져간다. 인입량은 관제지원시스템의 등록 속도에 따라 갈린다.

## main_flow

### [1]

- **step**: 1
- **actor**: 관제서버
- **action**: 학습용 영상 메타를 LS_DATA_INGEST 에 평면 1행으로 INSERT 한다(VMS_CLIP_ID 유니크로 중복 송신 방어). 처리상태는 넣지 않아도 DEFAULT 'PENDING' 이 부여된다

### [2]

- **step**: 2
- **actor**: 시스템(배치)
- **action**: 폴링 배치가 PENDING 이면서 재시도 시각이 도래한 행(NXTM_RTRY_DT IS NULL OR <= 현재)을 RCPTN_DT·RCPTN_SN 순서로 조회해 원자 클레임한다

### [3]

- **step**: 3
- **actor**: 시스템
- **action**: 경로의 영상 파일이 NAS 에 실재하는지 검증한다 — '행이 보인다 ≠ 파일이 있다'이며 관제 INSERT 시점과 파일 배치 시점은 어긋날 수 있다

### [4]

- **step**: 4
- **actor**: 시스템
- **action**: LS_DATA_RAW 에 영상 1건을 등록하고 작업 상태를 PENDING 으로 초기화한다. 이벤트유형은 인입 EVNT_TYPE_CD 를 우선 사용하며, 인입 행의 PRCS_STTS_CD 를 종결 처리하고 RAW_SN 을 기록한다

### [5]

- **step**: 5
- **actor**: 시스템(배치)
- **action**: VideoIngested 이벤트가 트랜잭션 커밋 후(AFTER_COMMIT) 비식별화 솔루션 비동기 위탁을 일으켜 비식별(선두) 단계부터 배치 파이프라인이 자동 진행된다

## description

영상 적재는 관제서버가 저작도구 소유 인입 테이블 LS_DATA_INGEST 에 <직접 INSERT> 하는 방식이다(ADR-042). 관제가 자기 쪽 조인(v2_video_assets ⋈ v2_video_metadata ⋈ resource_cctvs) 결과를 평면 1행으로 넣어주므로 저작도구 쪽 조인은 0 이다. 구 방식(관제와 공유하는 MNG_* 테이블을 주기 배치가 READ 해 픽업)은 폐기됐다 — 관제 2차 실DB(PostgreSQL klid)에 MNG_* 가 한 개도 없고(전면 개명·재설계), 246 dev 의 MNG_* 행수는 전부 dev-seed 시드값과 일치해 관제 유입이 0건이었기 때문이다. 수신 연동 API·양방향 M2M 인증은 여전히 미사용한다. 인입 행은 감사 추적을 위해 <영구 보존>하며(삭제하면 '분명히 넣었다' 분쟁에 대조 근거가 없고 중복 INSERT 감지도 못 한다), 적재 결과는 LS_DATA_INGEST.RAW_SN 으로 역추적한다(FK 미설정). 다만 dev 환경의 관리화면 업로드도 인입 행을 INSERT 하므로 <본 UC 경로로 적재된 원본 영상은 인입 행을 갖는다> — 이것이 조회 시 인입 조인이 성립하는 근거다. 포털 사용자 업로드는 본 UC 범위 외이다 — 같은 영상 원장에 적재되지만 출처 판별자(SRC_TYPE=PORTAL_ULD)로 갈리고(ADR-058), 인입 원장을 거치지 않으므로 그렇게 적재된 영상에도 인입 행이 없다. 외부에서 이미 라벨링이 끝난 산출물을 가져와 적재하는 외부 산출물 이관 경로도 본 UC 범위 외이며, 그 경로는 인입 원장을 거치지 않고 영상을 직접 적재하므로 그렇게 적재된 원본 영상에는 인입 행이 없다(ADR-048). 적재 자체는 출처유형과 무관하게 같다. 다만 적재 뒤 선두 비식별 단계는 출처유형이 배포 설정의 비식별 제외 목록(기본값 GENERATED)에 들면 외부 위탁 없이 원본을 비식별 영상 자리에 복사해 비식별을 완료한다(ADR-066) — 전체 영상 비식별 원칙(ADR-006)을 대체하지 않고 예외를 더한 것이다.

## alternate_flows

### 대상 없음

**steps**:

- 무처리로 종료한다

- **trigger**: 배치 주기에 PENDING 인입 행이 없음

### 파일 미도착

**steps**:

- 실패로 처리하지 않고 미처리(PENDING)로 둔다
- 최초 관측 시각을 PRCS_DT 에 기록해 대기 예산의 앵커로 삼는다(관제가 준 RCPTN_DT 는 과거 시각일 수 있어 사용하지 않는다)
- NXTM_RTRY_DT 를 뒤로 밀어(backoff) 고착 행이 FIFO 앞자리를 잠식하지 못하게 한다
- 대기 상한 초과 시 종결하고 관측 로그를 남긴다

- **trigger**: 인입 행은 있으나 NAS 에 영상 파일이 아직 없음

### 중복 INSERT

**steps**:

- UK_LS_DATA_INGEST_CLIP 유니크 제약이 중복을 차단한다(영상 1건당 인입 1행)

- **trigger**: 관제가 같은 VMS_CLIP_ID 로 재송신

### 비식별 실패

**steps**:

- 영상 상태를 실패로 표시하고 원본을 보존하며 재처리 대상으로 둔다

- **trigger**: 비식별화 솔루션 오류

### 재큐

**steps**:

- POST /v1/control-ingests/{rcptnSn}/requeue 또는 일괄 재큐 API 로 PRCS_STTS_CD 를 PENDING 으로 되돌리고 PRCS_DT·NXTM_RTRY_DT 를 비워 대기 예산을 리셋한다

- **trigger**: 관리자가 적재 실패 건을 다시 돌림

### 비식별 제외 출처유형

**steps**:

- 인입 폴링·영상 원장 적재·출처유형 복사·적재 이벤트 발행은 주 흐름과 같다 — 제외 여부는 적재를 바꾸지 않는다
- 선두 비식별 단계가 외부 비식별화 솔루션에 위탁하지 않는다(외부 호출 0)
- 원본 영상을 비식별 영상 쓰기 위치에 원본 파일명 그대로 일반 파일로 복사한다(링크로 대신하지 않는다)
- 비식별 처리 이력(LS_DEIDENT_PROC_LOG)에 성공 행(PROC_STTS_CD=SUCCEEDED · REQ_KND_CD=EXCLUDED · DE_IDNTF_FILE_PATH_NM=복사본 경로)을 남긴다
- 영상 비식별여부를 'Y' 로, 배치 단계를 마킹 대기(MARKING_READY)로 전이한다 — 외부 위탁이 동기 완료된 경우와 같은 흐름이며 이후 마킹·프레임 추출 단계는 바뀌지 않는다
- 제외 행은 외부 진행 상태(POLL_STTS_CD)를 갖지 않으므로 외부 솔루션 진행 상태 폴링·수락 대기 유예 회수 대상이 아니다
- 설정을 바꿔도 이미 선두 비식별 단계를 지난 영상에는 소급하지 않으며, 설정이 비어 있으면 모든 영상을 외부 비식별화 솔루션에 위탁한다

- **trigger**: 적재된 영상의 출처유형(LS_DATA_RAW.SRC_TYPE)이 배포 설정의 비식별 제외 목록(authoring.deidentify.excluded-src-types, 기본값 GENERATED)에 들어 있음 — 판정은 적재 시점이 아니라 선두 비식별 단계 처리 시점에 1회 하고, 결과는 영상별 비식별 처리 이력에 고정한다(ADR-066)

### 비식별 제외 복사 실패

**steps**:

- 영상 비식별여부를 'F' 로 표시하고 비식별 처리 이력에 실패 행(PROC_STTS_CD=FAILED · REQ_KND_CD=EXCLUDED)을 남긴다
- 마킹 대기(MARKING_READY)로 전이하지 않는다
- 원본 영상을 삭제하거나 수정하지 않는다

- **trigger**: 비식별 제외 대상 영상의 원본 복사가 실패함(원본 부재·경로 위반·입출력 오류)
