## description

관제 인입 영상이 LS_DATA_RAW 에 영속된 직후 발행되어 파이프라인 선두의 비식별화를 트리거한다. 관제 인입 경로로 적재된 영상은 개인정보 유형과 무관하게 (ANONY 포함) 모두 비식별 대상이며, 유형별 게이팅은 폐지됐다. 단 출처유형 제외 예외가 있다(ADR-066) — 배포 설정 authoring.deidentify.excluded-src-types(기본 GENERATED)에 든 출처유형(LS_DATA_RAW.SRC_TYPE)의 영상도 본 이벤트는 똑같이 발행하며, 판정은 발행 시점이 아니라 소비 측 선두 비식별 단계가 그 영상을 처리하는 시점에 한 번 한다. 제외 대상이면 외부 비식별 위탁 대신 원본 영상을 비식별 영상 쓰기 위치에 일반 파일로 복사하고, 비식별 처리 이력에 요청종류 EXCLUDED 인 성공 행을 남겨 비식별 제외로 완료한다. 이것은 개인정보 유형별 게이팅을 되살리는 것이 아니다 — 판정 축은 영상이 어디서 왔는가다.

[발행] 영상 적재 트랜잭션 안에서 발행한다.
[소비] 적재 트랜잭션 커밋 이후(AFTER_COMMIT) 두 소비자가 각각 비동기로 받는다 — 선두 비식별 위탁, 그리고 영상 기술메타 추출.
소비가 AFTER_COMMIT 이어야 하는 이유: 적재 트랜잭션이 커밋되기 전에 비식별이 시작하면 대상 행을 읽지 못한다.

[상태 흐름] 적재 PENDING → (선두 비식별 성공) MARKING_READY → (마킹 완료 → 잔여 배치) COMPLETED. 비식별 제외로 완료된 영상도 같은 흐름이다 — 원본 복사가 끝나면 비식별여부 'Y' 로 MARKING_READY 에 전이한다. 복사에 실패하면 비식별여부 'F' 로 두고 요청종류 EXCLUDED 인 실패 행을 남기며 MARKING_READY 로 전이하지 않는다.

[★ADR-042 이후 적재 주체 반전] 관제서버가 LS_DATA_INGEST 에 직접 INSERT 하고 저작도구 폴링 배치가 원자 클레임해 적재한다(구 관제 공유 마스터 스캔 방식 폐기). 발행 지점(LS_DATA_RAW 영속 직후)은 불변이다.

[한계 — 의도된 것] 저작도구가 스스로 비식별을 수행하지 않는 적재 경로는 본 이벤트를 발행하지 않는다. 아래는 전수 목록이 아니라 현재 알려진 경로이며 앞으로 늘어날 수 있다.
- 증강·해상도 파생 적재 경로 — 파생은 부모의 비식별본을 복사해 만들어져 재비식별 대상이 아니다.
- 외부 산출물 이관 적재 경로(ADR-048) — 가져오기 자체가 비식별 선두 단계를 자동으로 시작시키지는 않는다. 그 뒤를 정하는 것은 가져올 때 사람이 지정한 값과 영상 파일을 함께 주었는지다. 비식별이 끝났다고 지정해 가져온 산출물은 이미 처리된 것이라 다시 돌릴 이유가 없어 본 이벤트를 발행하지 않는다. 원본이라고 지정했으나 영상 파일이 없어 프레임만 가져온 산출물은 저작도구가 비식별할 대상 영상을 가지고 있지 않아 본 이벤트를 발행하지 않으며, 그 경우의 비식별은 외부에서 처리한 산출물을 받아 기록하는 별도 행위가 담당한다. 다만 원본이라고 지정하고 영상 파일을 함께 가져온 산출물은 이 열거의 예외다 — 저작도구가 비식별할 대상 영상을 가지고 있으므로 본 이벤트 축의 비식별 단계를 그 영상에 태운다.
