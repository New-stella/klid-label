### 2026-09-07 — 허용 저장소 범위 판정이 루트의 실제 자리도 시작점으로 인정
- 이 창구가 받는 마킹 산출물 폴더 위치의 범위 판정이 탐색·검사·적재와 같은 규칙을 쓴다는 것과, 허용 루트의 표기와 실제 자리를 둘 다 시작점으로 인정한다는 것을 본문에 명시. 근거 결정 ADR-065.
- 거부 축(상위 이동 표기·허용 범위 밖 위치·허용 범위 안의 이름이 실제로는 범위 밖을 가리키는 바로가기)은 하나도 완화하지 않았다.
- 폴더 안 항목의 바로가기를 건너뛰는 규칙은 별개 축이라 손대지 않았다. 그것은 폴더 내부 항목을 다루는 자리이고 이번 축은 허용 루트 자체를 읽는 자리다.
- 이 창구 신설 자체의 근거 결정은 ADR-053 이다. 근거를 적는 자리가 하나뿐이라 최신 결정으로 갱신했을 뿐, 신설 근거가 폐기된 것은 아니다.

## description

주어진 폴더와 그 아래를 재귀로 훑어 마킹 문서와 영상의 짝을 찾고, 무엇이 몇 건 들어오는지와 건별 검사 결과를 돌려준다. 이 단계에서는 아무것도 저장하지 않는다. 같은 요청을 여러 번 보내도 결과가 같다.

짝짓기 기준은 폴더 구조가 아니라 마킹 문서가 스스로 적어 둔 영상 파일 이름이다. 문서와 영상이 서로 다른 자리에 놓여 있어도 같은 이름을 찾으면 짝이 된다. 같은 이름의 영상이 둘 이상이면 어느 쪽인지 정할 수 없으므로 그 항목은 짝을 찾지 못한 것으로 다룬다.

허용 저장소 범위 판정은 폴더 탐색·검사·적재와 완전히 같은 규칙을 따른다. 이 창구가 자기 허용 목록을 따로 갖지 않는다 — 목록이 두 벌이 되면 한쪽만 넓어져 한 창구에서 막히는 위치가 다른 창구에서 열린다. 판정은 허용 저장소 루트의 표기와 루트가 실제로 가리키는 자리를 둘 다 허용 범위의 시작점으로 인정한다. 그래서 폴더 탐색이 돌려준 위치를 그대로 이 창구에 보내도 통과한다 — 허용 저장소 루트 자체가 바로가기라서 그 값이 설정에 적힌 표기와 달라지는 경우에도 마찬가지다. 사람은 같은 폴더 선택 창으로 이 축의 위치도 고르기 때문에 여기서만 다른 규칙을 쓰면 고른 값이 이 창구에서만 거부된다. 넓어진 것은 시작점을 읽는 방식뿐이다 — 상위로 거슬러 올라가는 표기는 그대로 거부하고, 허용 범위 밖을 가리키는 위치도 그대로 거부하며, 허용 범위 안의 이름이라도 실제로는 범위 밖을 가리키는 바로가기면 그대로 거부한다. 바로가기가 없는 형상에서는 판정 결과가 종전과 완전히 같다. 이 축은 허용 범위의 시작점을 읽는 방식에 관한 것이며, 아래의 폴더 안 항목을 다루는 규칙과는 다른 자리다.

훑는 깊이와 항목 수에는 상한이 있다. 상한에 걸리면 조용히 자르지 않고 일부만 훑었다는 사실을 함께 알린다. 폴더 안의 바로가기는 따라가지 않고 건너뛴다. 따라가면 허용된 저장소 범위 밖을 읽게 되기 때문이다.

이 창구는 외부 산출물을 가져오는 화면에서 받아들일 산출물의 종류로 이벤트 마킹을 골랐을 때 부른다. 화면에서 종류를 고를 뿐이며 창구는 종류마다 그대로 나뉘어 있다.
