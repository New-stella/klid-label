# 관제 데이터 참조 전면 제거 — MNG_* 9종 삭제 + LS_DATA_INGEST 평면 수신

## context

ADR-016 은 '관제와 저작도구가 공유 DB(MNG_*)를 사용하고 관제가 영상을 학습용으로 설정하면 저작도구 주기배치가 픽업한다'를 전제했다. 그 전제가 실측으로 무너졌다. ① dev DB 의 모든 MNG_* 행수가 시드값과 정확히 일치 — 관제 유입 0건이다. ② 관제 2차 실DB(PostgreSQL klid)에는 MNG_* 가 한 개도 없다(전면 개명·재설계됨: MNG_CLIP_MASTER→v2_video_assets, MNG_CLIP_EVNT_LST→v2_video_metadata, MNG_RESOURCE_CCTV→resource_cctvs). ③ MNG_ACCT_USER 를 채우는 코드가 저작도구 쪽에도 없다(쓰기 경로 0, MngAcctWriteGuardTest 가 금지). 즉 9종 전부 '코드는 읽는데 아무도 채우지 않는' 상태였다. 특히 MNG_EX_LOCAL_GOV 는 0행이라 관제 통지 lclgv_nm 과 데이터셋 sidoNm/sggNm 이 이미 항상 null 이었고, LS_DATA_RAW 57건 대 MNG_CLIP_MASTER 6건으로 51건이 fileFmt 매칭 불가였다.

## deciders

- 프로젝트 PM (ck.park)

## decision

### chosen_option

MNG_* 9종 전부 삭제 + LS_DATA_INGEST 평면 수신(채택)

### justification

저작도구는 관제서버 데이터를 참조하지 않는다. 영상 관련 정보는 전부 LS_DATA_INGEST(관제가 직접 INSERT, V147 37컬럼 + V166 4컬럼)로 평면 수신하고, MNG_* 9종은 개명이 아니라 전부 삭제한다. 대체 매핑 — MNG_CLIP_MASTER.FILE_FMT→인입 FILE_FMT(기존), MNG_CLIP_EVNT_LST 의 EVNT_TYPE_CD 해석→인입 EVNT_TYPE_CD(V166 신설), MNG_RESOURCE_CCTV 의 CCTV명·좌표→인입 CCTV_NM(기존)·WGS84_LAT/LOT(V147 선존), MNG_EX_LOCAL_GOV 의 SIDO_NM+SGG_NM→인입 RGN_NM(기존), MNG_EX_EVNT_TYPE/_MAP 의 코드→라벨·필터 목록→인입 EVNT_NM + LS_DATA_RAW distinct 도출, MNG_ACCT_USER→저작도구 소유 사용자 테이블(별도 ADR). 조회 패턴은 LEFT JOIN LS_DATA_INGEST i ON i.RAW_SN = COALESCE(r.ORGNL_RAW_SN, r.RAW_SN) 하나로 통일한다 — 파생영상은 자기 인입 행이 없지만 파생 깊이가 1 로 고정이라 1단계 폴백으로 충분하고, 관제 인입 경로와 개발 환경 업로드 경로로 적재된 원본은 인입 행을 갖는다. 다만 원본 축에도 인입 행이 없는 예외가 있다 — 외부 산출물 이관(ADR-048) 경로로 적재된 영상은 인입 원장을 거치지 않으므로 파생이 아닌 원본인데도 인입 행이 없고, COALESCE 폴백이 자기 식별자로 떨어져도 그 식별자를 가진 인입 행이 존재하지 않아 조인이 공집합이 된다. 조인 패턴 자체는 그대로 두고 이 예외를 전제로 읽는다. LS_DATA_RAW 에는 관제 수신값을 복사하지 않는다(신설 0개) — 수정될 일이 없는 읽기 전용 사실을 가변 작업 마스터에 이중 저장하지 않는다. 다만 개인정보 3필드만은 파생에서 인입 조인을 제외한다(CASE WHEN r.ORGNL_RAW_SN IS NULL): 파생의 개인정보 판정은 비식별 축이며 copyPrivacyMetaFrom 이 생성 시점에 이미 계승했으므로 결손이 아니다. 신설 컬럼은 폴백 없이 전환한다 — 폴백 마스터를 남기면 삭제 목적이 무산된다.

## consequences

### risks

- 자동마킹 400 회귀 — MNG_CLIP_EVNT_LST 로 EVNT_TYPE_CD 를 해석해 고쳤던 결함이라, 인입 EVNT_TYPE_CD 신설(V166)이 삭제보다 반드시 선행돼야 한다. 회귀 가드 = MarkingEventTypeAfterControlIngestIT
- 마이그레이션 SQL 을 테스트가 다시 읽어 재실행하는 구조 2곳(V164EvntTypeBackfillIT·V75MigrateLsUserRoleMigrationTest) — 원본 파일은 체크섬 때문에 수정 금지이므로 테스트를 고쳐야 한다
- 테스트 시드 SQL 이 MNG_* 에 DELETE/INSERT 를 수행 — 정리 누락 시 통합테스트 전량이 시드 단계에서 실패
- ddl-auto=validate 가 무동작이라 삭제·전환 누락이 기동으로 잡히지 않는다 — 소스 스캔 가드 테스트로만 검출 가능

### negative

- 관제가 EVNT_TYPE_CD 를 송신하기 전까지 해당 값 null — 관제 협의 항목으로 남음
- 이벤트유형 필터에 아직 적재되지 않은 유형은 노출되지 않음(사용자 수용)
- 구버전 jar 롤백 시 DROP 된 테이블이 없어 4노드 기동이 실패할 수 있음 — 각 DROP 마이그레이션에 재생성 SQL 전문을 주석으로 동반(V162 규약)
- 외부 산출물 이관 경로로 적재된 원본은 인입 조인이 공집합이라, 인입에서 조달하던 이벤트 분류·이벤트 범주·지자체 정보와 관제가 보낸 개인정보 판정값이 그 영상에서는 비어 있다. 그 값을 무엇으로 채울지는 이 결정의 범위가 아니며 아직 정해지지 않았다.

### positive

- 관제 스키마 변경이 저작도구 기동·조회를 깨뜨리는 결합이 소멸
- 관제 협의 표면이 인입 테이블 1개로 축소
- 데이터마트 뷰는 V101 이 이미 동결 스냅샷 기반이라 영향 없음(뷰 재정의·관제 뷰 계약 무영향)
- '코드는 읽는데 아무도 채우지 않는' 죽은 마스터 9종이 정리됨

## considered_options

### MNG_* 를 LS_ 로 개명해 우리 소유로 전환(구안, 폐기)

**cons**:

- '아무도 채우지 않는 마스터'가 이름만 바꿔 그대로 남음
- 관제 데이터 참조를 없앤다는 목적을 달성하지 못함

**pros**:

- 변경 범위가 rename 수준으로 작음
- 기존 조회 코드 구조 보존

- **description**: 테이블 이름만 LS_ 접두로 바꿔 소유권을 저작도구로 가져오고 구조는 유지한다.

### 관제 2차 PG 직접 조회(듀얼 데이터소스)

**cons**:

- 관제 스키마 변경에 상시 결합
- 네트워크·권한·트랜잭션 경계가 복잡
- 관제 일정에 종속

**pros**:

- 관제 진실원을 실시간 참조

- **description**: 저작도구가 관제 PostgreSQL(v2_video_assets 등)을 별도 데이터소스로 직접 조회한다.

### MNG_* 9종 전부 삭제 + LS_DATA_INGEST 평면 수신(채택)

**cons**:

- 관제가 신설 컬럼을 송신하기 전까지 해당 값은 null(폴백 마스터를 남기지 않음)
- 이벤트유형 필터가 적재된 영상 distinct 기준이라 미적재 유형은 노출되지 않음

**pros**:

- 저작도구가 관제 데이터를 참조하는 지점이 0 이 됨
- 관제 협의 대상이 인입 테이블 하나로 국한되고 작업 테이블(LS_DATA_RAW)은 저작도구 단독 소유로 자유롭게 변경 가능
- CCTV 제원을 영상마다 중복 저장해 카메라 교체·방위각 재설정 시 과거 영상 어노테이션 오염을 차단
- 인입 행 영구 보존으로 수신 감사 추적·중복 INSERT 감지 가능

- **description**: 관제가 자기 쪽 조인(v2_video_assets ⋈ v2_video_metadata ⋈ resource_cctvs) 결과를 평면 1행으로 저작도구 소유 LS_DATA_INGEST 에 직접 INSERT 한다. 저작도구는 그 행을 폴링 적재하고, 조회 시에는 LS_DATA_INGEST 를 조인해 이름·포맷·좌표를 얻는다. 사용자 정보는 관제가 브라우저 localStorage 에 넣어주는 값으로 받는다.
