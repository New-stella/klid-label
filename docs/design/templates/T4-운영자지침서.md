# T4 운영자 지침서

## 작성 목적
> 개발한 시스템을 운영자가 효과적으로 운영할 수 있도록 시스템 운영에 필요한 정보와 절차를 기술한다.

## 작성 방법
> 시스템의 운영 환경, 배포 절차, 모니터링 방법, 장애 대응 절차 등을 체계적으로 기술하여 운영자가 시스템을 안정적으로 운영할 수 있도록 한다.

## 항목 설명

- **시스템 개요**: 시스템 구성도, HW/SW 환경, 네트워크 구성 등 운영에 필요한 전체 구성 정보를 기술한다.
- **운영 절차**: 시스템 시작/종료, 배포, 백업/복구, 배치 작업 관리 등 일상 운영 절차를 기술한다.
- **모니터링**: 시스템 상태 모니터링 항목, 로그 관리 방법, 성능 지표 확인 방법을 기술한다.
- **장애 대응**: 장애 유형별 대응 절차, 비상 연락망, 장애 이력 관리 방법을 기술한다.
- **보안 관리**: 접근 통제, 데이터 보안, 감사 로그 관리 방법을 기술한다.

## 작성 시 참고사항

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID`
> - 서브시스템 ID (저작도구): `AT`
> - 산출물 파일명: `KLID_AT_운영자지침서_Rev {버전}`
> - 본 산출물에서 참조하는 ID:
>   - 컴포넌트 ID: `KLID-AT-CO-NNN` (D3 참조)
>   - 데이터베이스 ID: `KLID-AT-DB-NNN` (D9 참조)
>
> - 시스템 구성: Spring Boot(backend) + FastAPI(ai-server) + React(frontend) + MariaDB + MaxScale
> - 환경별 접속 정보: CLAUDE.md의 환경별 접속 정보 테이블 참조
> - 배포 절차: `./gradlew bootJar` -> JAR 배포, `uvicorn` 기동, `npm run build` -> 정적 파일 배포
> - 배치 관리: Quartz 스케줄러 Job 모니터링, 실패 재처리 정책
> - 모니터링: Actuator `/actuator/health`, Micrometer + Prometheus 메트릭, Logback JSON 로그
> - 장애 대응: Resilience4j 서킷브레이커 상태, ai-server GPU 자원 모니터링, DB 커넥션 풀
> - 보안: JWT 토큰 검증, 비식별 데이터 암호화 저장, 로그 마스킹(MaskingPatternLayout)
