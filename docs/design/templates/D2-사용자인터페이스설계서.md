# D2 사용자 인터페이스 설계서

## 작성 목적
> 시스템이 제공하는 사용자 인터페이스의 전체 구조와 메뉴 형식, 화면 목록과 화면의 상세 설계 내역을 기술한다.

## 작성 방법
> 전체 시스템에 대한 사용자 인터페이스의 구조를 사용자에게 제공하는 메뉴 형식으로 기술하고, 화면 및 출력으로 구분하여 목록을 작성하며, 화면의 상세 설계의 내용을 화면별로 기술한다.

### 3. 화면 상세 설계

> 화면별로 반복 작성한다. **모든 항목이 하나의 `<table>` 안에 들어가야 한다** — 화면 와이어프레임·입출력 항목·처리 내용·기술적 고려사항 모두 같은 표의 `<td colspan="4">` 셀에 포함시킨다. (HWPX 양식 호환)

```html
<table>
<tr><td width="15%">화면 ID</td><td width="35%">{ID}</td><td width="15%">화면명</td><td width="35%">{화면명}</td></tr>
<tr><td>관련 유스케이스 ID</td><td colspan="3">{UC-ID}</td></tr>
<tr><td>관련 시퀀스도 ID</td><td colspan="3">{SD-ID}</td></tr>
<tr><td>화면유형</td><td>{입력·조회·갱신·삭제}</td><td>메뉴경로</td><td><code>{경로}</code></td></tr>
<tr><td>화면개요</td><td colspan="3">{화면 목적 및 기능}</td></tr>
<tr><td colspan="4">

(화면 와이어프레임 — HTML/CSS 또는 이미지)

</td></tr>
<tr><td colspan="4" align="center"><b>입출력 항목</b></td></tr>
<tr><td colspan="4">

| 항목명 | 컨트롤명 | 타입 및 길이 | 속성 | Validation Check |
|---|---|---|---|---|
| ... | ... | ... | ... | ... |

*속성: I:Input, O:Output, R:ReadOnly, E:Editable, H:Hidden*

</td></tr>
<tr><td colspan="4" align="center"><b>처리 내용</b></td></tr>
<tr><td colspan="4">

- (처리 흐름 bullet)

</td></tr>
<tr><td colspan="4" align="center"><b>기술적 고려사항</b></td></tr>
```

> 속성: Input(I), Output(O), ReadOnly(R), Editable(E), Hidden(H)

## 항목 설명

### ■ 사용자 인터페이스 구조도
> 전체 시스템에 대하여 한 개를 작성한다. 최상위레벨에서 Top-down으로 작성되며, 시스템의 규모가 큰 경우 서브시스템으로 나누어 작성할 수 있다.

### ■ 사용자 인터페이스 목록
- **화면 ID**: 화면별로 유일한 ID를 부여하여 기입한다.
- **화면명**: 화면을 식별할 수 있는 명칭을 기입한다.
- **관련 유스케이스 ID**: 본 산출물이 관련되는 "유스케이스 명세서"의 유스케이스 ID를 기입한다.
- **출력물 ID**: 출력물이 있을 경우 출력물별로 유일한 ID를 부여하여 기입한다.
- **출력물명**: 출력물을 식별할 수 있는 명칭을 기입한다.

### ■ 화면상세설계
- **화면 ID**: 관련된 화면ID를 기입한다.
- **화면명**: 관련된 화면명을 기입한다.
- **관련 유스케이스 ID**: 본 산출물이 관련되는 "유스케이스 명세서"의 유스케이스 ID를 기입한다.
- **관련 시퀀스도 ID**: 본 산출물이 관련되는 "클래스 설계서"의 시퀀스도 ID를 기입한다.
- **화면유형**: 화면 데이터 처리 방식에 따라 입력, 조회, 갱신, 삭제 등으로 표시한다.
- **메뉴 경로**: 메뉴 경로를 파악하기 위하여 메뉴의 깊이를 표시한다.
- **화면 개요**: 화면의 목적 및 기능에 대하여 간략하게 기술한다.
- **항목명**: 화면의 입출력 항목을 식별할 수 있는 명칭을 기입한다.
- **컨트롤명**: 화면을 구현하는 컨트롤의 명칭을 기술한다.
- **타입 및 길이**: 항목의 데이터 타입과 최대 길이를 기술한다.
- **속성**: 항목의 속성을 Input(I), Output(O), ReadOnly(RO), Editable(E), Hidden(H) 중 선택하여 두문만(앞글자)을 기술한다.
- **Validation Check**: 항목의 입력 오류를 체크할 수 있는 입력 범위를 기술한다.
- **처리 내용**: 화면이 처리하는 업무 내용을 기술하며, 관련 시퀀스도 ID를 기재한다.
- **기술적 고려사항**: 화면을 구현하기 위하여 필요한 기술적 요소에 대한 고려사항을 기술한다.

## 작성 시 참고사항

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID`
> - 서브시스템 ID (저작도구): `AT`
> - 산출물 파일명: `KLID_AT_사용자인터페이스설계서_Rev {버전}`
> - 본 산출물에서 사용하는 ID:
>   - 화면 ID: `KLID-AT-SC-NNN` (예: `KLID-AT-SC-001`)
>   - 관련 유스케이스 ID: `KLID-AT-UC-NNN` (R2 참조)
>   - 관련 시퀀스도 ID: `KLID-AT-SD-NNN` (D1 참조)
>
> - 화면 ID는 `KLID-AT-SC-NNN` 형식으로 부여한다. (예: `KLID-AT-SC-001`)
> - **화면 레이아웃(와이어프레임)은 필수** — CBD 작성 사례(PDF p.42)처럼 실제 화면 캡처 또는 와이어프레임을 화면개요 아래에 삽입한다. md 파일에서는 **PlantUML Salt** 문법(`@startsalt`/`@endsalt`)으로 와이어프레임을 작성한다.
> - 본 프로젝트의 화면 목록은 `frontend/src/router/index.tsx`의 라우트 정의에서 추출한다. (27개 화면)
> - 각 화면의 UI 구조는 `frontend/src/pages/*.tsx` 페이지 컴포넌트의 JSX 구조를 분석하여 파악한다.
> - 기존 설계 문서 `docs/design/D2_사용자인터페이스설계서_v1.0.md`에 전체 27개 화면 상세 설계(입출력 항목, 처리 내용, 기술적 고려사항)가 815줄로 작성되어 있으므로 이를 참조한다.
> - 사용자 인터페이스 구조도는 채널별(INTERNAL/PORTAL/공통)로 메뉴 트리를 작성한다.
> - 출력물은 CSV 리포트, Gitea Diff Patch, 브라우저 인쇄, 증강 이미지 묶음 등이 해당된다.
> - 화면유형은 "조회"(목록/상세), "입력"(폼 제출), "갱신"(수정), "삭제" 중 복합 가능 (예: "조회·갱신").
> - 속성 표기 시 복합 속성은 슬래시로 구분한다 (예: I/E = Input+Editable, I/O = Input+Output).
> - PlantUML Salt 와이어프레임 예시:
> ```plantuml
> @startsalt
> {
>   {/ <b>대시보드 | 영상 관리 | 작업 배정 }
>   --
>   { 처리 현황 카드 | 완료 카드 | 실패 카드 }
>   ---
>   {#
>     영상 SN | CCTV명 | 상태 | 등록일
>     9001 | cctv-01 | COMPLETED | 2026-05-26
>   }
> }
> @endsalt
> ```
