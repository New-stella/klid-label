# T6 인수시험 시나리오

## 작성 목적
> 개발된 시스템에 대해 운영 환경으로 전환을 위한 준비를 완료하고, 운영환경과 동일한 환경하에서 당초 사용자가 요구한 사항을 시스템이 전체적으로 만족시키는지를 사용자 주도로 평가하게 하여 그 시험 결과에 대한 승인 여부를 결정하도록 한다.

## 작성 방법
> 인수시험은 PM이나 PM에게 권한을 할당 받은 위임자의 주도로 이루어지며, 실제 시스템을 잘 알고 있는 개발 담당자들이 시험을 준비하고 진행하여야 한다. 사용자 요구사항 정의서 기반으로 인수시험 시나리오를 작성하고 시험 절차와 만족기준을 기술한다.

## 항목 설명

- **시험 유형**: 기능시험, 성능시험, 보안시험 등 시험의 유형을 기입한다.
- **관련 요구사항 ID**: 본 산출물이 관련되는 "사용자 요구사항 정의서"의 요구사항 ID를 기술한다.
- **시험 시나리오 ID**: 인수시험 시나리오에 대한 유일한 ID를 부여하여 기입한다.
- **시험 시나리오**: 시험에 대한 간략한 설명을 기술한다.
- **시험 절차**: 시험 시나리오별 시험을 수행하는 절차를 기술한다.
- **만족기준**: 시험 수행 후 수행결과에 대한 만족수준 값을 기술한다.
- **시험결과**: 인수시험 결과서로 활용될 때 실제 시험을 수행한 결과를 기술한다.
- **비고**: 기타 참조할 만한 사항을 기술한다.

## 작성 시 참고사항

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID`
> - 서브시스템 ID (저작도구): `AT`
> - 산출물 파일명: `KLID_AT_인수시험시나리오_Rev {버전}`
> - 본 산출물에서 참조하는 ID:
>   - 관련 요구사항 ID: `RQ-AT-NNN` (기능), `RQ-{비기능코드}-NNN` (비기능) — R1 참조
>
> - 인수시험은 발주자(지방정부) 주도로 운영 환경에서 수행한다.
> - 기능시험: R1(사용자 요구사항 정의서)의 요구사항별로 시나리오를 작성한다.
> - 주요 인수시험 시나리오 예시:
>   - 영상 업로드 ~ 배치 파이프라인 ~ 오토라벨링 완료까지 전체 플로우
>   - 라벨링 작업 배정 ~ 편집 ~ 검수 승인까지 워크플로우
>   - 포털 사용자 진입 ~ 간편 라벨링 ~ 다운로드
>   - 비식별 처리 ~ 비식별 이미지 확인
>   - 시스템 성능: 이미지 10만장 목표, 영상 5,000건 목표 검증
> - 만족기준은 계약서 또는 요구사항 정의서의 검수 기준을 그대로 사용한다.
