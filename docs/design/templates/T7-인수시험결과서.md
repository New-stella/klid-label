# T7 인수시험 결과서

## 작성 목적
> 인수시험 시나리오에 따라 수행한 인수시험의 결과를 기술하고, 시스템 인수 승인 여부를 결정하기 위한 근거를 제공한다.

> 인수시험 시나리오에 따라 시험을 수행하고 시험 결과를 기술하며, 만족기준 대비 실제 결과를 비교하여 인수 승인 여부를 판정한다. 발견된 결함에 대한 조치 사항도 함께 기록한다.

## 항목 설명

### 시험 결과 요약
> 시험 유형별 전체 시나리오 수와 Pass/Fail 비율을 요약한다.

### 시험 상세 결과
> T6(인수시험 시나리오)의 양식을 그대로 사용하되, "시험결과" 컬럼을 실제 수행 결과로 채운다.

### 결함 목록 및 조치 사항
- **결함 ID**: 발견된 결함에 대한 유일한 ID를 부여한다.
- **시험시나리오 ID**: 결함이 발견된 시나리오 ID를 기입한다.
- **결함 내용**: 결함의 상세 내용을 기술한다.
- **심각도**: 치명(Critical), 주요(Major), 경미(Minor), 개선(Enhancement) 중 선택한다.
- **조치 사항**: 결함에 대한 수정 내용을 기술한다.
- **조치 완료일**: 수정이 완료된 날짜를 기입한다.
- **재시험 결과**: 수정 후 재시험 결과(Pass/Fail)를 기입한다.

### 인수 판정
- **판정 결과**: 인수 승인 / 조건부 승인 / 인수 불가 중 선택한다.
- **판정 사유**: 판정 결과에 대한 사유를 기술한다.

## 작성 시 참고사항

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID`
> - 서브시스템 ID (저작도구): `AT`
> - 산출물 파일명: `KLID_AT_인수시험결과서_Rev {버전}`
> - 본 산출물에서 참조하는 ID:
>   - 관련 요구사항 ID: `RQ-AT-NNN` / `RQ-{비기능코드}-NNN` — R1 참조
>
> - T6(인수시험 시나리오)의 시험결과 컬럼을 채워 완성한다.
> - 결함 심각도 기준:
>   - 치명(Critical): 시스템 운영 불가, 데이터 손실
>   - 주요(Major): 주요 기능 사용 불가, 성능 기준 미달
>   - 경미(Minor): 일부 기능 제한, UI 표시 오류
>   - 개선(Enhancement): 사용성 개선 제안
> - 인수 판정 기준: 치명 결함 0건, 주요 결함 수정 완료, 요구사항 충족률 기준 충족
> - 발주자/수주자 양측 서명으로 인수 절차를 완료한다.
