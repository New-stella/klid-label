# D9 데이터베이스 설계서

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-UC/CO/DC/DCD/SD/SC/AC/EN/ERD/TB/II/IC/IF/UCD/ACT 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. 범위는 시작 ID만 전체형으로(예: `KLID-AT-UC-001~013`). ※ 요구사항(RQ-SFR-NN-NN)·시스템시험(KLID-ST-NNN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 최종적으로 설계된 테이블과 인덱스를 데이터베이스 공간에 매핑시키고 저장공간 등의 물리 모델을 기술한다.

## 작성 방법
> 부서에서 운영하는 데이터베이스 목록을 작성하고, 데이터베이스의 물리적 상세내용을 작성한다.

### 2. 데이터베이스 정의

> **작성 품질 규칙(CBD 적합성)**: ① Storage Group·Bufferpool·인덱스 BP·TS는 DB2 물리 개념이다 — **PostgreSQL 프로젝트는 등가물(`pg_default`, `shared_buffers` 등)로 적응 표기하고 적응 사실을 명시**한다(미작성·공란 금지). ② 본 명세 대상 테이블 건수를 §3 테이블 명세 및 §작성 범위와 **합치**시킨다(예: "대상 LS_* N개 = DB정의 N개 = 테이블명세 N개"). ③ TS 용량은 산정 근거(최대건수×평균 row)를 병기한다.

> **물리 개념 적응 표기(PostgreSQL)**: 본 산출물의 데이터베이스는 PostgreSQL이므로 DB2 물리 개념을 다음 등가물로 적응 표기한다 — **Storage Group → `pg_default`(PostgreSQL 기본 테이블스페이스)**, **Bufferpool → `shared_buffers`(공유 버퍼)**, **인덱스 BP → `shared_buffers`(인덱스도 동일 공유 버퍼 사용)**, **TS(테이블스페이스) → `pg_default` 단일 논리 테이블스페이스**. PostgreSQL은 DB2와 달리 객체별 버퍼풀을 분리 지정하지 않고 인스턴스 공통 `shared_buffers`를 사용한다.

> **TS 용량 산정**: TS 용량 = Σ(테이블별 최대건수 × 평균 row bytes). LS_* 41개 테이블 합산 추정 ≈ **1.6GB**(최대건수 가정 기준, 인덱스 포함 ≈ 1.9GB). 최대 용량 기여 상위 = LS_DATA_LBL(라벨, 최대 ~1,000,000행, ≈ 700MB) · LS_DATA_LBL_AI_INFO(~1,000,000행, ≈ 250MB) · LS_DATA_SRC(프레임) · LS_LABEL_VERSION(스냅샷 페이로드). 인덱스 용량은 각 테이블 PK + 보조 인덱스 합산으로 산정한다. (TB-040 LS_TUS_UPLOAD 는 재개 가능 업로드 세션 임시 데이터로 용량 기여 미미 ≈ 0.3MB. TB-041 LS_DATA_LBL_HSTRY 는 ≈ 45MB.)
>
> **합치 확인(CBD 적합성)**: 대상 LS_* **41개** = §2 DB정의 테이블 매핑 **41개** = §3 테이블 명세 **41개**(KLID-AT-TB-001~041). 데이터마트 적재용 **View 4종**(KLID-AT-VW-001·002·003·005, VW-004 결번)은 §4 View 명세에 별도 기술한다(물리 테이블 아님 — TS 용량 비기여, CREATE OR REPLACE 멱등). 공유 MNG_*/QRTZ_* 스키마는 물리 설계 비대상이라 본 정의·명세에서 제외한다.
>

### 데이터베이스 정의

- **데이터베이스 ID**: 데이터베이스 ID를 기입한다.
- **데이터베이스명**: 데이터베이스 명칭을 기입한다.
- **Storage Group**: 데이터베이스내의 객체에서 사용할 Default Storage Group명을 기술한다.
- **Bufferpool**: 데이터베이스내의 테이블 스페이스에서 사용할 Default Bufferpool명을 기술한다.
- **인덱스 BP**: 데이터베이스내의 Index에서 사용할 Default Bufferpool명을 기술한다.
- **TS ID**: 테이블 스페이스의 식별자를 기술한다.
- **TS 용량**: 테이블 스페이스의 할당용량을 표시한다.
- **테이블 ID**: 테이블의 식별자를 기술한다.
- **테이블명**: 테이블 명칭을 기술한다.
- **인덱스 ID**: 인덱스 식별자를 기술한다.
- **인덱스 용량**: 인덱스의 저장공간의 크기를 산정하여 기술한다.
- **비고**: 예외사항 및 추가사항을 기술한다.

### 테이블 명세

- **테이블 ID**: 테이블의 식별자를 기술한다.
- **테이블명**: 테이블 명칭을 기술한다.
- **데이터베이스명**: 데이터베이스 명칭을 기입한다.
- **TS명**: 테이블 스페이스의 명칭을 기술한다.
- **관련 엔티티 ID**: 본 테이블에 대응하는 "엔티티 관계 모형 설계서"(D8)의 엔티티 ID를 기입한다(1:1).
- **트리거 구성**: 테이블에 트리거가 구성되어 있을 경우 트리거 로직을 기술한다.
- **테이블 설명**: 테이블의 목적 및 역할을 간략하게 기술한다.
- **초기건수**: 테이블이 최초 생성될 때 보유한 데이터의 건수를 기재한다.
- **증가량(일)**: 일정주기별 데이터 발생건수를 기술한다.
- **보관주기(일별)**: 해당 테이블내 데이터의 보관주기를 기술한다.
- **최대건수**: 테이블이 관리되는 기간(보관주기)내에 발생이 예상되는 최대 데이터 건수를 기술한다.
- **용량**: 데이터 보관 최대 건수와 데이터의 길이를 고려하여 산정한 데이터 용량을 기술한다.
- **비고**: 기타 고려사항 등을 기술한다.
- **컬럼명**: 테이블 컬럼의 내용과 특성을 인식할 있는 명칭을 기술한다.
- **컬럼 ID**: 테이블 컬럼 ID를 기술한다.
- **타입 및 길이**: 컬럼의 타입과 최대 허용 길이를 기술한다.
- **NOT NULL**: 필수항목 여부를 기술한다.
- **PK(Primary Key)**: 주키를 의미한다.
- **FK(Foreign Key)**: 외래키를 의미한다.
- **INX(Index)**: 인덱스를 의미한다.
- **기본값**: 속성의 기본값이 있는 경우에 그 값을 기재한다.
- **제약조건**: 속성의 특이한 제약조건이 있는 경우 기재한다.

### View 명세 (데이터마트 적재용)

- **View ID**: View 의 식별자를 기술한다(`KLID-AT-VW-NNN`).
- **View명**: View 명칭을 기술한다(`V_COMPLETED_*`).
- **데이터베이스명**: View 가 속한 데이터베이스/스키마 명칭을 기입한다.
- **기준 테이블**: View 가 조인·평면화하는 기준 LS_* 테이블과 조인 관계를 기술한다(⋈ INNER JOIN, ⟕ LEFT JOIN).
- **View 설명**: View 의 목적과 평면화 대상·노출 정책을 간략히 기술한다.
- **노출 조건**: View 가 row 를 노출하는 필터 조건(검수 완료·메타 승인 등)을 기술한다.
- **출력 컬럼 / 원천 컬럼**: View 가 노출하는 컬럼명과 그 원천 테이블 컬럼을 매핑해 기술한다. 물리 rename(V60/V61) 으로 변경된 컬럼은 데이터마트 소비 컨트랙트 보존을 위해 기존 출력명으로 alias 한다.

## 작성 시 참고사항

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID`
> - 서브시스템 ID (저작도구): `AT`
> - 산출물 파일명: `KLID_AT_데이터베이스설계서_Rev {버전}`
> - 본 산출물에서 사용하는 ID:
>   - 데이터베이스 ID: `KLID-AT-DB-NNN` (예: `KLID-AT-DB-001`)
>   - TS(테이블스페이스) ID: `KLID-AT-TS-NNN` (예: `KLID-AT-TS-001`)
>   - 테이블 ID: `KLID-AT-TB-NNN` (예: `KLID-AT-TB-001`)
>   - View ID: `KLID-AT-VW-NNN` (예: `KLID-AT-VW-001` — 데이터마트 적재용 View)
>   - 인덱스 ID: `KLID-AT-ID-NNN` (예: `KLID-AT-ID-001`)
>   - 관련 엔티티 ID: `KLID-AT-EN-NNN` (D8 참조)
>
> - 데이터베이스: `klid_system` DB 내 `klid_at` 스키마 (**PostgreSQL** — UTF-8, 표준 SQL DDL. DB2/MariaDB 물리 개념은 PostgreSQL 등가물로 적응 표기)
> - 저작도구 소유 LS_* 41개 전용 테이블(KLID-AT-TB-001~041)의 물리 설계와 데이터마트 적재용 View 4종(KLID-AT-VW-001·002·003·005, VW-004 결번 — V114 재편)의 명세를 기술한다. TB-001~040은 D8 엔티티(KLID-AT-EN-001~040)와 번호 정렬 1:1 매핑되며, TB-041(LS_DATA_LBL_HSTRY)은 D8 EN-046(데이터라벨이력, 뷰 채번 EN-041~045 이후 신설분)에 대응한다(View 는 물리 테이블 아님 — 엔티티 비대상).
> - 공유 MNG_*(관제 공유 클립/계정)·QRTZ_*(Quartz JobStore) 스키마는 인프라가 제공하고 저작도구는 validate/연동만 하므로 물리 설계 비대상 — 데이터베이스 목록에 "공유(READ)" 비고로만 표기한다.
> - 단일 PostgreSQL 인스턴스 기준으로 작성한다(읽기 분산/클러스터 구성 없음 — Quartz도 단일 인스턴스 JobStore).
