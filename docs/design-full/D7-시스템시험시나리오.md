# D7 시스템시험 시나리오

> **ID 표기 규칙(공통)**: 시스템시험 시나리오 ID는 프로젝트 공식 체계 `KLID-ST-NNN`(예: `KLID-ST-001`)으로 표기한다. 관련 유스케이스·화면 등 AT 체계 ID는 **전체 형식 `KLID-AT-XX-NNN`**(예: `KLID-AT-UC-001`, `KLID-AT-SC-005`)으로 표기하며 약식 표기를 금지한다. 관련 요구사항 ID는 **R1 사용자요구사항정의서(제출본)에 실존하는 ID** — 기능 `RQ-SFR-NN-NN`, 비기능 `NFR-NNN` — 만 기재한다.

## 작성 목적
> 시스템의 포괄적인 비기능 요구사항에 대한 시험을 수행하기 위하여 시험 항목, 시험 절차 및 기준을 설정하기 위한 시나리오를 작성한다.

## 작성 방법
> 성능, 부하, 볼륨, 보안 등 시험 유형별로 시스템시험을 수행하기 위해 시나리오에 대한 시험 절차를 작성하고 시험 만족기준과 시험결과를 작성한다.

> **본 산출물의 시나리오 범위**: 시스템시험 시나리오는 R2 활성 유스케이스 13건(`KLID-AT-UC-001~011`, `KLID-AT-UC-013`, `KLID-AT-UC-016`)의 **사용자 관점 종단(end-to-end) 시나리오**를 기반으로 도출한다. 각 시나리오는 R2 기본 시나리오·대안 시나리오 및 유스케이스 검수기준(AC)을 시험 절차·만족기준으로 변환하였으며, 정상 흐름 외 주요 대안/예외(권한 403, 입력 검증 400, 상태 충돌 409, 외부 연동 실패/재시도)를 포함한다.
> **블록 구성**: 템플릿 양식에 따라 시험 유형별 블록(① 기능 종단 — UC 기반 / ② 성능 / ③ 부하 / ④ 볼륨 / ⑤ 보안)을 반복 작성한다. ① 기능 종단 블록은 본 도구의 사용자 관점 검수기준 검증을 위한 블록이며, ②~⑤는 비기능 요구사항(NFR) 정량 검증 블록이다.
> **만족기준**: 비기능 블록은 정량 측정치(응답시간·처리율·누적 건수·노출 0건 등 수치+단위)로 기술한다. 기능 종단 블록은 유스케이스 종료조건·검수기준 충족 여부(상태 전이·코드·결과 보존)로 판정한다.
> **시험결과**: 설계 단계에서는 공란으로 유지하며, 시스템 시험결과서로 활용될 경우 실제 시험 수행 결과를 기입한다.
> **시험 환경·자동화 도구**: 총괄시험계획(D6) 참조. 외부 연동(생성형 AI·비식별 솔루션·관제서버)은 시험용 스텁/목 엔드포인트로 대체하고, 실제 외부 연동은 통합 시험 단계에서 검증한다(D6).

## 작성 시 참고사항

> - **근거 정합**: 본 산출물의 모든 기능 종단 시나리오는 R2 유스케이스 명세서(`KLID-AT-UC-001~011`, `013`, `016`)의 기본/대안 시나리오·종료조건·검수기준(`KLID-AT-AC-*`)에서 도출하였으며, 화면 연계는 D2 사용자 인터페이스 설계서(`KLID-AT-SC-*`)를 따른다. 근거 없는 시나리오는 작성하지 않았다.
> - **요구사항 정합**: 관련 요구사항 ID는 R1 사용자요구사항정의서(제출본)에 실존하는 ID(`RQ-SFR-NN-NN`·`NFR-NNN`)만 사용하였으며 R3 요구사항추적표와 정합한다.
> - **시험 환경·도구**: 시험 환경 구성·자동화 도구·외부 연동 스텁/목 정책은 총괄시험계획(D6)을 참조한다. 외부 연동(생성형 AI·비식별 솔루션·관제서버·ai-server)은 시험 단계에서 스텁/목으로 대체하고 실연동은 통합 시험 단계에서 검증한다.
