## 1. 이 창구가 서 있는 자리

관제지원에서 학습데이터가 포털로 넘어오는 경로는 세 단계다.

| 단계 | 주체 | 내용 |
|:-:|---|---|
| ① | 관제 채널 저작도구 | 검수 승인 → 관제로 완료 통지 |
| ② | 관제 | 그 자산을 포털로 전달(압축 파일) |
| ③ | **포털** | **포털 채널 저작도구에 자산 수신을 알린다 ← 이 창구** |

저작도구는 이 신호를 받아 **구 데이터마트 해제본 정리의 유예를 세기 시작**한다.

⚠ 포털 채널 저작도구가 관제 채널 저작도구의 DB 나 API 를 직접 물어 승인 자산을 가져오지 않는다.
중계자는 관제이며, 승인 자산이 포털로 흐르는 경로는 위 셋뿐이다.

## 2. 창구

| 항목 | 값 |
|---|---|
| 메서드·경로 | **`POST /v1/portal-system/dataset-cleanups`** |
| operationId | `receivePortalDatasetCleanupTrigger` |
| 요청 Content-Type | `application/json` |
| 인증 헤더 | **`x-api-key`** — 사전 공유 고정 문자열 |
| 인증 | **키 값 일치만** 본다 (아래 §4). 토큰을 함께 실어도 판정에 들어오지 않는다 |

⚠ **경로 접두가 `/v1/portal-system` 인 것은 의도다.** 사용자 주체로 부르는 창구는
`/v1/portal` 접두 아래 있고, **서버가 부르는 창구는 그 밖의 별도 접두** 아래 둔다.
한 접두에 섞으면 인가 설정이 뭉개진다. (같은 접두를 쓰는 창구: 일일 저작 집계 제공)

### 2.1 요청 본문

```json
{
  "datasetCode": "DS-2026-001",
  "version": "v3"
}
```

| 속성 | 타입 | 필수 | 상한 | 설명 |
|---|---|:-:|:-:|---|
| `datasetCode` | string | ✅ | **20자** | 정리 대상을 가리키는 학습데이터셋 코드 |
| `version` | string | ✅ | **50자** | 포털이 새로 받은 버전. 이 버전이 들어오면 그보다 **이전**의 올드 해제본이 정리 대상이 된다 |

- 둘 다 **빈 문자열·공백만인 값은 거부**한다(400).
- `version` 은 **문자열로 보존**하며 숫자로 해석하지 않는다.
- ⚠ **상한 20/50 은 잠정이다** — 아래 §6-①.

### 2.2 응답

응답 본문은 저작도구 표준 래퍼를 쓴다. **평문 객체가 아니다** — 포털 파서가 이 모양을 전제해야 한다.

```json
{ "success": true, "data": null, "message": null, "errorCode": null }
```

| 코드 | 언제 | 비고 |
|:-:|---|---|
| **202** | 트리거를 접수했다 | **첫 수신 · 재수신 · 알지 못하는 데이터셋이 전부 이 응답이다** |
| **400** | 데이터셋 코드나 버전이 없거나 형식을 어겼다 | |
| **401** | **키가 없거나 값이 다르다.** 만료 개념이 없다 | |
| **403** | **이 창구에서는 발생하지 않는다** — 주체가 없어 그 사유가 성립하지 않는다. 키가 아니면 401 이다 | |

⚠ 거부 응답에 **내부 경로·예외 흔적·저장 구조**(테이블명·컬럼명·제약명·스택)를 싣지 않는다.
오류 원인을 코드와 메시지 이상으로 알 수 없는 것은 의도다.

## 3. 동작 규약 — 포털이 알아야 할 것

### 3.1 ★ 같은 트리거를 다시 보내도 안전하다 (멱등)

같은 `(datasetCode, version)` 으로 다시 보내면 **같은 202** 로 답하고 **아무 일도 하지 않는다.**
유예 시작 시각은 **처음 받은 시각 그대로**이며 재수신으로 밀리지 않는다.

> 왜 밀지 않는가 — 밀면 중복 수신이 반복될 때마다 정리가 무한히 미뤄져 **영영 일어나지 않는다.**

⇒ **포털은 응답을 못 받았을 때 안심하고 재전송해도 된다.** 중복 차감·중복 처리가 없다.

### 3.2 ★ 알지 못하는 데이터셋도 202 다

이 배포본에 해제된 적 없는 데이터셋 코드나 버전이 와도 **오류가 아니라 202** 다.

> 왜 — 오류로 답하면 포털이 지울 것도 없는 신호를 계속 재전송하게 된다. 그리고 대상 유무를
> 응답으로 드러내면 그것이 존재 여부를 탐색하는 수단이 된다.

⇒ **202 는 "접수했다"이지 "지울 대상이 있었다"가 아니다.** 그 구분을 응답으로 알 수 없다.

### 3.3 ★ 받은 즉시 지우지 않는다

트리거를 **받은 시점부터 유예를 센 뒤** 올드 해제본을 지운다.

> 왜 — 사용자가 그 해제본을 물고 저작하는 중일 수 있고, 받자마자 지우면 그 작업이 그 자리에서 깨진다.

유예 기간의 값은 이 창구가 아니라 **보존 규칙(`DFEAT-055`)** 이 소유한다.

## 4. 인증 — 사전 공유 API 키

| 항목 | 값 |
|---|---|
| 헤더 | **`x-api-key`** |
| 값 | 사전에 나눠 가진 **고정 문자열** |
| 검증 | **키 값의 상수시간 비교.** 서명·만료·주체 클레임이 없다 |
| 키 생성 | **저작도구가 생성**해 안전한 채널로 포털에 공유한다(포털 요청 수용) |

⚠ **관제지원 수신 채널이 쓰는 키와 섞지 않습니다** — 연동 축마다 별도 키가 원칙이고, 한 축이
유출돼도 다른 축으로 번지지 않게 합니다(포털이 명시 요청한 내용을 그대로 수용).

### ★ 키가 아니면 401 입니다 — 토큰을 함께 실어도 마찬가지입니다

이 창구는 **키로만** 가릅니다. 포털 사용자 토큰을 함께 실어도 그것이 판정에 들어오지 않으며,
키가 없거나 값이 다르면 **401** 입니다.

> 구현상 이 경로에서는 앞선 인증을 지우고 키만 봅니다. 그래서 「인증은 됐고 권한이 없다」(403)로
> 새지 않고, **키가 틀렸다는 사실이 응답에 그대로 남습니다.**

### ★★ 키가 설정되지 않으면 창구가 닫힙니다

저작도구 쪽 설정이 비어 있으면 **어떤 요청도 통과하지 못합니다**(전건 401). 값이 없을 때 열리는
것이 아니라 **닫히는** 방향이라 안전합니다 — 배포에서 키 주입을 잊었을 때 무인증으로 열려 있는
것보다 아예 안 받는 편이 낫기 때문입니다.

⚠ **그 대가**: 포털이 호출을 시작했는데 저작도구 쪽 키가 비어 있으면 **전건 거부**가 되고,
포털에는 「키가 틀렸다」로 보입니다. §6-② 가 그래서 실동작의 선행 조건입니다.

## 5. 저작도구가 하는 일 (참고)

접수한 트리거는 접수 원장 `LS_DATST_ARNGMT_TRGR` 에 한 행으로 남고, 그 행의 **수신일시**가
정리 유예의 기산점이 된다. `(데이터셋코드, 버전)` 유일 제약이 재수신 멱등의 근거이며,
판정을 조회가 아니라 **삽입문 자체**에 걸어 두 트리거가 동시에 도착해도 기산점이 갈리지 않게 한다.

### 아직 남은 것

| # | 항목 | 없으면 |
|:-:|---|---|
| ① | **`x-api-key` 값 교환** | **창구가 안 열린다**(전건 401). 저작도구가 생성해 공유 예정 |
| ② | **운영 진입 주소(base-url)** | 호출할 곳이 없다. 인프라 확정 시 공유 |
| ③ | **TLS 여부** | 인프라 축 |

⇒ **①이 채워지기 전까지 이 창구는 전 환경에서 닫혀 있습니다.** 결함이 아니라 의도한 fail-closed 입니다.

### 포털 요청 4번(재시도 분기)에 대한 회신 — **동의합니다**

| 응답 | 포털 처리 | 저작도구 의견 |
|---|---|---|
| `400` 형식 오류 | 재시도 안 함 | 동의 — 같은 요청은 다시 보내도 같은 결과 |
| `401` 키 오류 | 재시도 안 함(설정 오류) | 동의 |
| `403` | 재시도 안 함 | 동의. 다만 **이 창구에서는 발생하지 않습니다** |
| `5xx`·타임아웃 | 재시도 | 동의 — **멱등이라 안전합니다**(§3.1) |

### ⚠ 저작도구가 되묻습니다 — **일일 저작 집계 창구도 `x-api-key` 입니까?**

이번 회신은 이 창구만 다뤘습니다. 같은 접두(`/v1/portal-system/`)를 쓸 **일일 저작 집계** 창구는
인증 수단이 **미확정**으로 남아 있습니다. 그 답에 따라 저작도구의 인가 배선이 갈립니다.

## 7. 이 창구가 하지 않는 것 (범위 밖)

| 항목 | 상태 |
|---|---|
| **신규 데이터마트 조달**(포털 소재 조회 창구 호출 · 압축 해제 · 적재) | **미구현** — 그 창구는 포털 소유이고 응답 스키마가 회신되지 않았다 |
| **실제 해제본 삭제 실행** | **미구현** — 지울 대상인 해제본 저장소가 아직 서지 않았다. 이번 창구는 트리거를 접수해 기산점을 남기는 데까지다 |

⇒ 현재 이 창구는 **"받아서 기록한다"** 까지다. 위 둘은 후속 작업이며, ①의 응답 스키마 회신이
선행 조건이다.
