# 시계열 위탁 토글 폐지 + VLM 일괄 스킵 축 — 구현 스펙

> 도메인: DOMAIN-003 영상·프레임 수집 / 키트: `docs/design/영상프레임-수집-DOMAIN-003/` (last sync 2026-08-19 s2)
> 설계 진실원: `ADR-049` · `API-212` · `API-213` · `API-214` · `API-201` · `API-060`(DOMAIN-007)

## 배경 (ADR-049 context)

외부 시계열 위탁이 설정 토글로 꺼지면 위탁 단계가 **외부 호출 없이 즉시 건너뛴 것으로 처리되고 아무 기록도 남지 않는다.**
그런데 공통 기본값이 비활성이고 온프렘 배포 템플릿도 비활성이며 stg/prd 프로파일에는 활성화 설정 자체가 없다
⇒ **납품본이 시계열이 꺼진 채로 나가고 그 사실이 산출물에도 이력에도 드러나지 않는다.**

## 요구사항 (R)

- **R1** `vlm.client.enabled` 토글과 그에 딸린 조용한 SKIPPED NO-OP 분기를 폐지한다. 연동되어 있지 않으면 위탁은 **실패**한다. (`ADR-049` decision)
- **R2** 미연동 판정은 **연동 주소 주입 여부**로 한다 — `vlm.client.url` 이 비면 `VlmUrlPolicy` 검증을 생략하고 **기동은 성공**시킨다. (사용자 확정 2026-08-19)
  - 근거: 「미연동 시 기동 거부」는 `ADR-049` 가 **기각**한 안이다(벤더 연동 확정 전 배포 불가 + 시계열 외 전 기능 동반 차단).
- **R3** 벤더 미연동 구간의 운영은 **사람이 사유를 남기고 누르는 단계 스킵**으로 처리한다. 단건은 이미 있으므로 이 작업은 **일괄 축만** 더한다. (`ADR-049`)
- **R4** 일괄 축은 **스킵·해제·재수행 셋 모두**에 둔다. 스킵만 일괄이면 벤더 연동 시점에 수천 건을 손으로 되돌려야 한다. (`API-212`/`213`/`214`)
- **R5** 일괄 축의 대상 묶음은 **`VLM` 하나**다. 오토라벨을 일괄로 열면 산출물 품질 축을 사람이 대량으로 건너뛸 수 있게 된다. 단건 경로는 종전대로 두 묶음을 모두 받는다. (`ADR-049`, `API-212` parameters.stage.enum)
- **R6** 일괄 요청 계약은 **기존 일괄 재처리(`API-199`)를 그대로 따른다** — 상한 100 · 중복 1건 취급 · 요청 순서 보존 · 부분 성공. 한 건도 처리되지 못해도 **200**. (`API-212`~`214`)
- **R7** 검수 **승인 이력이 있는 영상도 `VLM` 묶음은 재수행을 허용**한다. 오토라벨은 예외가 아니다. (`API-201`, `ADR-049`)
- **R8** 증강 외부 연동이 미연동(`authoring.augment.external.mode=noop`)이면 증강 **요청 접수 자체를 503 으로 거부**한다. noop 동작 자체는 유지한다. (`API-060`)
- **R9** 문서(위키·테스트케이스)를 같은 커밋에서 동기화한다.

### 제외 (out of scope)

- 단건 스킵/해제/재수행 신설 — **이미 전부 구현돼 있다**(`API-198`/`200`/`201`).
- 미연동 시 기동 거부 — `ADR-049` 기각안.
- 증강 noop 자체 제거 — 이전 세션이 철회한 안.
- 검수 화면의 「시계열 건너뜀」 표시·승인 확인단계·승인 차단 — 사용자가 세 안 모두 검토 후 **"지금은 그대로 둔다"**로 확정.
- 범용 단계 스킵 확대(프레임추출·오토라벨 일괄).

## 구현 중 확정 (키트 ↔ 실코드 불일치 판정)

### D1 — 일괄 스킵·해제의 「이미/아님」 처리: **단건과 동일**(성공)으로 간다

`API-212`/`213` 의 **example** 은 실패 사유로 "이미 건너뛴 작업 묶음입니다."·"건너뛴 상태가 아닙니다."를 보여주며,
이는 `API-198` 의 409·`API-200` 의 404 를 전제한다. **그러나 실코드는 둘 다 그 동작이 아니다**:

- `BatchStageSkipService.skip` — **append-only 로 항상 성공**. javadoc 이 이유를 명시("사유가 바뀌었을 수 있고 그 변경 이력 자체가 감사 대상").
- `BatchStageSkipService.clearSkip` — 스킵 상태가 아니면 **멱등 no-op 성공**("그렇지 않으면 해제 버튼을 두 번 누른 것만으로 의미 없는 감사 행이 쌓인다").

`API-212`/`213` 의 **본문 규범**은 *"단건 스킵과 판정·기록 규칙이 같고 대상만 목록으로 받는다"* / *"단건 해제와 같다"* 이므로,
**규범을 따르고 example 을 드리프트로 판정**한다. example 대로 만들면 같은 조건에서 단건과 일괄이 다르게 동작하는
비대칭이 새로 생긴다(이 저장소의 반복 결함 패턴).

⇒ 일괄 경로의 건별 실패는 **영상 없음(404)·파생영상(400)·예상 밖 오류**에서만 발생한다.
⇒ `API-198`·`API-200`·`API-212`·`API-213` 의 응답 서술·example 정정을 **Phase 5 mc-logi-update 권고**에 올린다.

### D2 — 미연동 판정의 실제 지점

`enabled` 를 읽는 main 코드는 **정확히 3곳**이다:
1. `WebClientConfig.vlmWebClient` — `if (enabled) urlPolicy.validate(baseUrl)` **한 줄에만** 쓰인다
2. `VlmClient` — 생성자 필드 + `submitTimeseries` 조기반환(`VlmTimeseriesResponse.skipped`) + `isEnabled()`
3. `VlmTimeseriesStep.doSubmit` — `if (!vlmClient.isEnabled())` NO-OP 분기(수동 스킵 게이트 **다음**, 영상 존재 확인 **앞**)

⇒ R2 는 1번을 `if (StringUtils.hasText(baseUrl)) validate` 로 바꾸고, 2·3번의 분기를 **제거**하는 것으로 성립한다.

### D3 — 배포 템플릿의 URL 기본값이 R2 를 무력화한다

`deploy/onprem/config/backend/env.template` 과 `application.properties.template` 이 `VLM_SERVICE_URL=http://127.0.0.1:9400`
(**비어 있지 않은 평문·루프백**)을 배포한다. 이 값이 남아 있으면 stg/prd 의 strict 정책에 걸려
**빈 생성 실패 → 기동 차단**이 되어 `ADR-049` 기각안과 같은 결과가 된다.
⇒ 두 템플릿의 값을 **빈 값**으로 바꾸고, 벤더 연동 시 채우라는 주석을 남긴다.

### D4 — 증강 미연동 여부를 접수 경로가 알 수단이 없다

`AugmentRequestService` 는 `ExternalAugmentClient` 를 주입받지 않고, 그 인터페이스에도 `isEnabled()` 류가 없다.
빈 타입 검사는 AOP 프록시 때문에 취약하다.
⇒ 프로퍼티를 읽는 **판정 단일 원천 컴포넌트**를 신설한다(전례: `GenAiIntegrationWiringGuard` 가
`@Value("${authoring.augment.external.mode:http}")` 로 같은 값을 읽는다). `noop` 이면 접수 거부.

## 운영 지침 (문서에 반드시 남길 것)

`LsMarking.markVlmRequested()` 는 **`PENDING` 에서만** 전이한다. 토글이 폐지되면 미연동 시 위탁이 실패하고
마킹이 `VLM_REQUESTED → VLM_FAILED`(**종결 상태**)로 간다. 그 뒤 벤더가 붙어 재수행해도 **마킹 표시는 실패로 남는다.**
⇒ **벤더 미연동 구간에는 반드시 먼저 스킵한다.** 스킵 없이 돌려 실패시키지 않는다.
(단 차단은 아니다 — 시계열 메타 적재·검수큐 진입·R13 재검수·산출물 재생성은 마킹 상태와 무관하게 정상 동작한다.)

## 수용 기준 (검증 가능한 단언)

- A1 `vlm.client.enabled` 를 읽는 main 코드가 **0건**이다.
- A2 `vlm.client.url` 이 빈 값이어도 애플리케이션이 **기동한다**(prd 프로파일 포함).
- A3 `vlm.client.url` 이 채워져 있으면 종전대로 `VlmUrlPolicy` 가 검증하고 위반 시 기동이 차단된다.
- A4 미연동 상태에서 위탁하면 **기존 실패 경로로 실패**한다(새 실패 경로·조용한 SKIPPED 없음).
- A5 `SKIP_REASON_DISABLED` 상수가 존재하고 `RESUMABLE_SKIP_REASONS` 구성이 변하지 않았다.
- A6 승인 이력이 있는 영상의 단건 재수행이 `VLM` 은 **수락**되고 `AUTOLABEL` 은 **400** 이다.
- A7 일괄 3 API 가 `VLM` 외 stage 를 **400** 으로 거부한다.
- A8 일괄 3 API 가 빈 목록·101건·원소 0 이하를 **400** 으로 거부한다.
- A9 일괄 3 API 가 중복을 1건으로 축약하고 요청 순서를 보존한다.
- A10 일괄 3 API 가 전건 실패해도 **200** 이고 `successCount`/`failureCount` 가 결과 목록과 일치한다.
- A11 일괄 3 API 가 WORKER 에 **403**, 미인증에 **401** 이다.
- A12 건별 실패 사유에 스택트레이스·DB 제약명·내부 경로가 없다.
- A13 증강 외부 모드가 `noop` 이면 요청 접수가 **503** 이고, `http` 면 종전대로 동작한다.
- A14 증강 503 게이트가 기존 게이트(파생 400 · 미검수 · 신고 412)의 판정을 바꾸지 않는다.
