### 캔버스 이미지 서빙 (`GET /v1/frames/{srcSn}/image`)

FE 는 `useImageBlob` 이 axios(Bearer)로 fetch → blob URL → konva Image 로 넘긴다(`<img src>` 직접 호출은 토큰 미첨부로 401).

| 항목 | 계약 |
|------|------|
| 기본 서빙 대상 | **비식별(DEID) 프레임**(`DE_IDNTF_SRC_FILE_PATH_NM`) — 라벨링은 비식별 영상의 프레임으로 수행한다. **단, 비식별 경로가 없는 레거시 ANONY 프레임은 원본으로 폴백된다**(아래 행 — 의도된 하위호환. 백필 전까지 이 프레임들은 원본이 서빙된다) |
| 원본(RAW) | **REVIEWER 가 `?raw=true` 를 명시**할 때만. WORKER 의 `raw=true` 는 무시하고 DEID 강제 |
| 비식별 경로가 없을 때 | PRVC/PSDO(민감) → **404**("비식별 처리 미완료", 원본 폴백 금지) / ANONY(레거시) → **원본 폴백**. ⚠ **2026-07-31부터 관제 적재 영상의 기본 개인정보유형이 `ANONY`→`PRVC` 로 바뀌었으므로 이 원본 폴백은 사실상 닫혔다**(의도된 fail-closed — 마스킹 전 원본 노출 차단, CWE-359) → [05 §5.4](05-video-management.md) |
| 파생(증강·해상도) 프레임 | 원본 픽셀이 실재하지 않아 `SRC_FILE_PATH_NM=null` 이므로 **비식별 경로로 서빙**된다(구 구현은 무조건 404 → 캔버스 백지) |
| 신고 구간 | `DE_IDNTF_YN='F'` → **412**(역할 무관). 순서는 ①인가(403) → ②게이트(412) → ③경로 해석 고정 |
| 캐시 | `Cache-Control: no-store` (게이트가 매 요청 평가되어야 함) |

판정·검증은 `FrameImageService` **단일 원천**이며 `GET /v1/videos/{rawSn}/frames/{frameNo}/image` 와 같은 코드를 쓴다(컨트롤러는 위임만).
`GET /v1/frames/{srcSn}/deid-image` 는 **원본 폴백이 절대 없는 엄격 계약**으로 별도 유지된다.
FE 는 이미지 로드 실패 시 캔버스 영역에 안내를 표시한다(과거에는 아무 표시 없이 백지였다).

### 10.2.0 저장 진입점은 하나다 — 캔버스 상단 옵션바 + `Ctrl+S` (2026-08-06 사용자 확정, 구속 · 위치는 2026-08-08 이관)

구 동작은 **헤더 우측 `[저장]` 버튼과 좌측 도구바 저장 아이콘이 같은 `handleSave` 를 부르는 중복 진입점**이었다. 헤더 버튼을 없애 하나로 줄였고(`LabelHeader.tsx`), 그 하나가 놓이는 곳은 **캔버스 상단 옵션바**다(`CanvasOptionBar` → `SaveCommitButton`). 단축키 `Ctrl+S`(`edit.save`)는 그대로다.

- ⚠ **구 서술 "좌측 도구바로 일원화" 는 폐기** — **삭제 · 실행 취소 · 다시 실행 · 저장은 좌측 도구바(`ToolBar`)에 두지 않고 캔버스 상단 옵션바 소관**이다. 양쪽에 두지 않는 이유는 진입점이 둘이면 잠금·진행중 판정이 한쪽만 갱신돼 조용히 열린 구멍이 생기기 때문이며, 헤더/도구바 중복 저장이 그 사례였다.

- **헤더에 남은 것은 버튼이 아니라 상태다** — `저장 중...` / `● 편집 중` / `✓ 저장됨`(`LabelHeader.tsx(LabelHeader)`, `data-testid="label-save-status"`). 우선순위는 **진행 > 미저장 > 저장됨**이다(저장은 항상 dirty 에서 시작하므로 dirty 를 먼저 보면 진행 표시가 영영 뜨지 않는다). ⚠ 구 헤더 버튼 라벨이 담당하던 `저장 중...` 을 여기로 **이관**한 것이라 제거하면 진행 피드백이 증발한다.
- **영상 잠금(`LOCKED_FOR_REDEIDENT`)은 호출부가 옵션바에 전달해야 한다** — 저장 버튼이 자체 판정하는 `editBlocked`(busy)와 **다른 축**이라 버튼 혼자서는 알 수 없다. `LabelingPage` 가 `locked={isLocked}` 로 `CanvasOptionBar` 에 넘기고 옵션바가 저장 버튼으로 전달한다. 전달이 빠지면 잠긴 영상에서 저장 버튼이 활성으로 보인다(누르면 `handleSave` 가 토스트로 막지만, 눌리는데 아무 일도 없는 화면이 된다). 저장 진행은 `saving` → 버튼 스피너 + `aria-busy`.
- ⚠ **헤더에 `[저장]` 을 다시 넣지 말 것.** 회귀 가드 `LabelHeader.test.tsx(★헤더에는_저장_버튼이_없다_중복_진입점_제거_회귀가드)`.

**선행 수정 — 도구바 스크롤 계약**(구 미해결 결함 TC-FE-306 해소): 도구바는 `overflow-hidden` 조상(`LabelingPage` 의 `flex flex-1 overflow-hidden`) 안의 flex 아이템인데 자체 스크롤 계약이 없어, 짧은 뷰포트(≈690px 이하)에서 **맨 끝 버튼이 잘려 영구히 클릭 불가**였다. 당시에는 그 맨 끝이 `저장` 이라 진입점을 줄이기 전에 반드시 고쳐야 했고, **저장이 옵션바로 옮겨간 뒤에도 계약은 유지**한다 — 도구·보기 조작 버튼이 넘칠 때 같은 결함이 재발한다.

- 버튼 목록에 `TOOLBAR_SCROLL_CLASS`(`flex-1` + `min-h-0` + `overflow-y-auto` + `overflow-x-hidden`)를 적용한다 — `min-h-0` 이 없으면 콘텐츠 높이가 하한이라 overflow 가 아예 발동하지 않는다.
- **툴팁은 `createPortal` 로 body 에 분리**하고 버튼 rect 기준 뷰포트 좌표(`position: fixed`)로 그린다. `overflow-y` 를 non-visible 로 두면 `overflow-x` 도 auto 로 강제되므로, 툴팁이 상자 안에 있으면 **스크롤을 얻는 대가로 툴팁이 잘리는** 새 회귀가 난다. 스크롤 시에는 좌표가 낡으므로 툴팁을 닫는다.
- ⚠ **jsdom 은 레이아웃을 계산하지 않아 잘림을 폭·높이로 단언하면 항상 통과하는 거짓 가드**가 된다. 회귀 가드는 구조 계약만 고정한다(`ToolBarScrollContract.test.tsx`).

### 10.2.1 도구 클릭 → 라벨 선택 → 드로잉 (2026-08-03 사용자 확정, 구속)

도형 도구를 **클릭·전환하는 시점**에 라벨 선택 모달(`LabelPickerModal`)이 뜨고, **라벨을 고른 뒤에야 캔버스 드로잉이 시작**된다.

| 항목 | 규칙 |
|------|------|
| 대상 도구 | 새 라벨을 만드는 도구만 — **바운딩 박스 · 폴리곤 · AI 분할 · 스켈레톤**(`LABEL_REQUIRED_TOOLS`). 선택·팬·AI 추적(선택 객체 라벨을 그대로 전파)·마스크 편집·삭제/실행 취소/저장 액션은 모달을 띄우지 않는다 |
| 노출 시점 | **도구 전이 1회**. 도형 하나 그릴 때마다 다시 뜨지 않으며(연속 작업 시 마지막 선택 라벨 유지), 이미 활성인 같은 도구 버튼을 다시 누르면 라벨을 바꿀 수 있다 |
| 취소 | ESC·닫기·취소 버튼 → **도구를 활성화하지 않고 이전 도구로 복귀**(라벨 없이 드로잉이 시작되지 않는다) |
| 목록 출처 | **라벨 마스터 전체**(`GET /v1/manage/labels`)의 활성(`useYn='Y'`) 라벨, `sortNo asc → labelId asc`. ⚠ **프리셋(`LS_LABEL_PRESET_CODE`)은 오토라벨링 전용이라 이 목록의 소스가 아니다** |
| 검색 | 마스터 전체라 건수가 많을 수 있어 이름 검색(표시명·원문 모두 매칭)을 제공 |
| 단축키 | 모달이 열린 상태에서 **1~9** 로 순번 라벨 선택(검색창 입력 중에는 미발화) |
| 상태 | 단일 출처는 기존 `useLabelStore.activeLabelId`(신규 전역 상태 없음). 판정은 `useToolLabelPicker` **한 곳**이라 툴바 클릭·키보드 단축키 어느 경로로 도구가 바뀌어도 동일하게 동작한다 |

**좌측 상시 라벨 패널(구 `LabelSidebar`)은 폐지**됐다. 거기 있던 1~9 라벨 선택은 위 모달로 이전했고(패널이 없으면 전역 1~9 는 아무 시각 피드백 없이 다음 도형의 라벨을 바꾸는 조용한 상태 변경이라 `SHORTCUT_KEYMAP` 에서도 제거), **키포인트(COCO-17) 배치 가이드(`KeypointGuide`)는 우측 패널 상단(탭 위 상시 영역)으로 이동**해 어느 탭을 보고 있어도 배치 중에는 계속 보인다.

### 10.2.2 라벨명 표시 = 라벨 마스터 등록명 그대로 (2026-08-03 사용자 재확정, 구속)

라벨명은 **라벨 마스터(`LS_LABEL`)에 등록된 이름을 그대로 표시**한다. 코드에 둔 한글 사전으로 치환하지 않는다.

- **근거**: 코드 사전은 라벨 마스터와 어긋나는 **두 번째 진실원**이 되고, 사전에 있는 라벨만 한글이라 화면이 오히려 뒤섞인다. 한글로 보이길 원하면 **운영자가 마스터에서 이름을 한글로 등록**하면 된다 — 마스터가 단일 진실원이라는 프로젝트 원칙과 정합한다.
- **표시 지점은 여전히 공용 함수 `resolveLabelDisplayName`(`features/label/utils/labelDisplayName.ts`) 하나만** 쓴다. 규칙이 "원문 통과 + 빈값만 `-`"로 얇아졌어도, 지우면 지점마다 필드 선택·빈값 처리가 갈려 같은 라벨이 화면마다 다르게 보인다.
- 마스터에 연결되지 않아 이름이 없는 값(레거시 `className` 원문만 있는 경우)도 **그 값을 그대로** 표시한다(임의 대체·'미연결' 문구 없음).

적용 지점: 라벨 선택 모달 · 우측 '객체' 목록(`ObjectClassTree`) · 객체 속성 라벨 드롭다운/읽기 필드(`ObjectAttributePanel`) · 라벨 변경 이력(`LabelChangeDetail`) · AI 탐지 팝업(`AiToolModal`) · 포털 업로드 라벨링 라벨 분류 select.

- ⚠ **구 "한글 우선 표시(사전 14건)" 규칙은 폐기**됐다(직전 커밋 `d8a7a2cc`). `COCO_LABEL_KO`(`constants/cocoClasses.ts`)는 **라벨 관리 화면의 COCO 매핑 select 옵션 표시 전용**으로 남아 그 파일 밖으로 export 되지 않으며, 구 `labelColors.getLabelDisplayName`(`PERSON`→'사람' 등)도 폐지됐다. 따라서 마스터에 `car`·`VEHICLE` 로 등록된 라벨이 **화면에도 그대로 `car`·`VEHICLE` 로 보이는 것이 의도된 동작**이다 — 결함으로 되돌려 사전 치환을 되살리지 말 것. 회귀 가드: `utils/__tests__/labelDisplayName.test.ts`.
- ⚠ **표시 전용 경계는 유지**된다. 저장·전송되는 값(`LS_DATA_LBL` 로 가는 `className`, 이벤트 어노테이션 `obj_label`, AI 추적 요청 `label`)은 이 함수를 거치지 않는다 — 회귀 가드 `labelDisplayNameNoPayloadLeak.test.tsx`.
- 라벨 마스터 **관리 화면**(`/manage/labels`)은 원문 이름을 편집·삭제 확인하는 화면이며, 이제 다른 화면도 같은 이름을 보여준다.

### 10.2.3 보기 조작 — 회전 · 그리드 · 영역 확대 (2026-08-08 신설)

좌측 도구바의 구분선 아래에 **보기 조작**이 모여 있다(왼쪽 90° 회전 · 오른쪽 90° 회전 · 화면 맞춤 · 영역 확대 · 그리드 표시). 이 중 **회전 2종 · 영역 확대 · 그리드 표시가 신설**됐다(구 도구바에는 '화면 맞춤'만 있었다).

세 가지 모두 **표시 전용**이라 저장되는 라벨 좌표를 바꾸지 않는다 — 서버에 저장하지도 않고, 화면을 벗어나면 초기값(회전 0° · 그리드 OFF · 영역 확대 OFF)으로 돌아간다.

| 조작 | 동작 | 편집과의 관계 |
|------|------|--------------|
| **왼쪽/오른쪽 90° 회전** | `0°→90°→180°→270°` 4단계 순환. 이미지와 라벨을 함께 돌려 **보여주기만** 한다(회전이 이미지 좌표계가 아니라 뷰 좌표계에 걸리므로 이미지↔캔버스 환산식은 그대로다) | **회전 중에는 그리기가 잠긴다** — 선택 도구를 뺀 **도구 버튼**(바운딩 박스 · 폴리곤 · AI 분할 · 스켈레톤)이 비활성되고(툴팁이 "회전 중에는 사용할 수 없습니다" 로 사유를 말한다) 캔버스도 라벨·오버레이의 포인터 입력을 끊는다. 회전 버튼을 누르면 활성 도구가 **선택 도구로 되돌아간다** |
| **영역 확대** | 켠 뒤 캔버스를 드래그하면 그 사각형이 화면을 채우도록 배율·위치가 옮겨진다. 되돌리기는 바로 위 **화면 맞춤** | **라벨을 만들지 않는다** — 모드가 켜져 있는 동안 드로잉 경로를 봉인한다. 도구를 고르면 모드가 자동 해제된다 |
| **그리드 표시** | 이미지 기준 100px 격자 오버레이를 켜고 끈다(확대·축소하면 화면상 간격도 함께 변한다) | 히트테스트에 관여하지 않는 순수 오버레이라 편집을 막지 않는다 |

- **회전 중 편집 입력을 봉인하는 이유**: 포인터 입력 경로가 **회전되지 않은 화면 좌표**를 전제로 설계돼 있어, 회전한 채로 입력을 받으면 사용자가 찍은 위치와 다른 좌표가 저장된다.
- **회전 잠금 판정은 도구 종류에만 걸린다** — 잠금 대상은 **도구 버튼**이고, 액션 버튼인 `AI 탐지` 는 **회전 중에도 활성**이다(그 요청이 캔버스 포인터 좌표를 쓰지 않기 때문). 즉 "AI 도구"라고 뭉뚱그리면 안 된다 — AI 분할은 도구라서 잠기고 AI 탐지는 액션이라서 잠기지 않는다. ⚠ **AI 추적은 이 목록에 없다**(2026-08-18 정합) — 도구바 버튼이 아니라 우측 객체 패널의 실행 버튼이라 회전 잠금 대상이 아니다(그 요청도 캔버스 포인터 좌표를 쓰지 않는다). 장시간 작업 중 비활성(§10.6 busy)은 이와 **별개 축**이라 액션 버튼에도 걸린다.
- **영역 확대는 회전 중에도 쓸 수 있다** — 드래그 사각형을 회전 이전 좌표로 되돌려 계산하므로 회전각과 무관하게 같은 결과가 나온다.
- **배율 상하한과 팬 범위는 기존 줌 정책을 그대로 공유**한다(같은 규칙의 두 번째 진실원을 만들지 않는다). **가로·세로 어느 한 변이 12px 미만인 드래그는 무시**해 오클릭 한 번으로 화면이 극단 확대되는 것을 막는다.
- 회전 버튼 툴팁에는 **현재 각도**가 함께 나오고, 영역 확대·그리드 표시는 눌림 상태(`aria-pressed`)를 노출한다. 회전은 일회성 액션이라 눌림 상태를 갖지 않는다(누름 상태 없는 버튼을 토글로 오안내하지 않기 위함).
- 장시간 작업 중(§10.6 busy)에는 도구 전환과 함께 **보기 조작도 비활성**된다.
- 세 값은 **라벨링 화면이 단독 보유**한다 — 도구바(토글)와 캔버스(표시)가 같은 값을 봐야 하므로 공통 상위가 단일 보유자여야 한다. 셋 다 선택적이라 값을 넘기지 않는 호출부(포털 업로드 라벨링 등)에는 버튼이 노출되지 않고 동작도 도입 전과 같다.

### 10.2.4 온디맨드 자동 추적 — "AI 자동 추적" 패널 (2026-08-18 신설, SCREEN-005·UC-034)

우측 **객체 목록 아래(트랙 편집 영역)**에 배선된 실행·검토 패널(`AutoTrackPanel`)이다. 내부 라벨링(`/label/:id`)은 백엔드로 [11 §11.2](11-ai-assisted.md) 의 온디맨드 YOLO 추적(`POST /v1/frames/{srcSn}/yolo-track`)을 그대로 쓴다.

⚠ **구 서술 폐기(2026-09-15)** — *"내부 라벨링 전용이다(포털 라벨링은 오토라벨·추적을 제공하지 않아
ADR-013 에 따라 진입점 자체가 없다)"* 는 **더 이상 사실이 아니다.** 포털 라벨링(`/portal/label/:id`)도
이 패널을 노출한다(2026-09-15 · `ADR-013` v24). 다만 **포털은 별도 신설 창구**
`POST /v1/portal/frames/{srcSn}/yolo-track` 를 쓴다(인가·입력 이미지 해석만 갈아끼우고 추론 본체·응답
계약은 내부와 동일) — 상세는 [11 §11.2 「포털 전용 AI 보조 창구」](11-ai-assisted.md) · [16 §16.3b](16-portal.md).

- **우측 객체 패널의 "AI 추적"(선택한 객체 하나를 따라가는 실행 버튼, §10.2 표 `Sam2TrackTool` · §10.2.5)과 이름·동작이 다르다** — "AI 자동 추적"은 **시작 객체를 고르지 않고** 현재 프레임부터 뒤따르는 프레임까지 한 번에 검출·추적한다. ⚠ 구 서술 "좌측 도구바의 AI 추적" 은 **폐기**(2026-08-18 정합 — 도구바에 그 버튼을 두지 않는다).
- 결과 적용은 **검토 후 수락(기본값)** · **자동 반영** 2모드. 실행 직전 라디오로 고르며 그 선택은 **그 실행 1회에만** 적용되고 다음 실행은 다시 기본값으로 돌아간다.
- 수락·제외의 단위는 **트랙**이다. 어느 모드든 결과는 작업본에만 올라가고 확정은 §10.2.0 의 저장으로 한다(저장 전 미확정).
- 응답의 라벨 마스터 식별자(`labelId`)를 화면이 **그대로** 실어 저장한다 — 검출 클래스명으로 마스터를 다시 찾지 않는다. 마스터에 연결되지 않은 검출은 반영하지 않고 안내한다.
- 이 작업은 §10.6 busy 축의 **`AI_AUTO_TRACK`** 종류다(구 5종에서 6종으로 확장).
- 상세(모드 전환·안내 문구 근거 등)는 [11 §11.2](11-ai-assisted.md) 참조 — 여기서는 화면 배선만 요약한다(중복 서술 지양).

### 10.2.5 AI 추적의 진입점 — 우측 객체 패널 (2026-08-18 정합, 구속)

**AI 추적은 좌측 도구바에 두지 않는다.** 사양 SCREEN-005 §좌측 도구바의 버튼은 **선택/이동 · 바운딩 박스 · 폴리곤 · AI 분할 · 키포인트 · AI 탐지 여섯**이며 AI 추적은 그 목록에 없고, §라벨링 캔버스가 *"AI 추적은 우측 패널 '객체' 탭에서 대상 객체를 펼쳤을 때 노출되는 버튼으로 실행한다"* 고 못박는다.

| 항목 | 규칙 |
|------|------|
| 실행 위치 | 우측 객체 패널의 **선택 객체 속성**(`ObjectAttributePanel` → `Sam2TrackTool`). 버튼 표기는 **「AI 추적」** |
| 노출 조건 | **선택 객체가 있으면 상시**. 도구 모드(`ToolType.TRACK`)로 게이트하지 않는다 |
| 단축키 | `Shift+T` 는 **유지**(사양 §단축키 안내). 도구 모드를 켤 뿐 실행하지는 않는다 |
| AI 탐지 다이얼로그 | '트랙으로 실행'도 **유지** — 추적 형태·라벨을 기억한 상태를 켠다(§11) |
| 포털 차단 | 호출부(`LabelingPage`)가 포털 채널에서 `track` 컨텍스트를 **넘기지 않는다**(ADR-013) |

- **왜 도구바 버튼을 뺐나** — AI 추적은 *이미 그려진 객체 하나를 뒤 프레임으로 전파*하는 행위라 "무엇을 추적할지"가 정해진 뒤에야 성립한다. 도구바에 모드 버튼을 두면 **모드를 켜야 우측 실행 버튼이 나타나는 2단 동선**이 되는데, 사용자는 이미 객체를 고른 상태라 그 모드 전환이 무엇을 위한 것인지 알 수 없다.
- ⚠ **도구 모드 게이트를 되돌리면 실행 진입점이 통째로 사라진다** — 도구바 버튼이 없으므로 단축키·다이얼로그를 모르는 사용자에게는 버튼이 영영 뜨지 않는다. 회귀 가드 `ObjectAttributePanel.trackShape.test.tsx(도구가_TRACK이_아니어도_선택객체가_있으면_AI추적_버튼이_보인다)` · `ToolBar.test.tsx(AI_추적_버튼은_좌측_도구바에_두지_않는다)`.
- ⚠ **포털 차단축이 바뀌었다** — 구 구현은 도구바·단축키 차단 + 도구 모드 게이트에 기대고 있었는데, 게이트가 사라진 지금 **`track` 컨텍스트 미전달이 유일한 화면측 차단**이다(서버의 포털 전용 `sam2-track` 경로 부재가 2중 방어). 회귀 가드 `ObjectAttributePanel.trackShape.test.tsx(track_컨텍스트가_없으면_AI추적_버튼을_노출하지_않는다_포털_차단축)`.
  ⚠ **구 표현 폐기(2026-09-15)** — *"서버의 포털 전용 SAM2 경로 제거"* 라는 표현을 **"`sam2-track` 경로 부재"로 좁힌다.** §16.3b 확정으로 SAM2 경로 중 **분할(`sam2-segment`)은 포털 전용 창구로 재도입**됐다 — 서버 방어가 아직 유효한 것은 **선택 객체 추적(`sam2-track`)뿐**이며, 이 절(10.2.5)이 다루는 「AI 추적」(선택 객체 하나를 따라가는 `Sam2TrackTool`)이 바로 그 축이다. 「AI 자동 추적」(§10.2.4, 여러 객체를 한 번에 묶는 `yolo-track`)과 혼동하지 말 것 — 그쪽은 포털에 제공된다.
- **표기 「자동추적」은 폐기**(2026-08-18) — 우측 패널에 「AI 자동 추적」(§10.2.4)이 함께 보이는데 같은 낱말을 쓰면 무엇을 누르는지 구분되지 않는다. 사양이 두 이름을 겹치지 않게 구분하라고 명시한다.

| 항목 | 내용 |
|------|------|
| 응답 `data` | `confThreshold`(정수, `YOLO_CONF_THRESHOLD` 축) · `simplifyTolerance`(실수, `POLYGON_SIMPLIFY_TOLERANCE` 축) — 둘 다 슬라이더 **프리필 전용**이라 값이 없으면 생략됨. **+ `waitBudgets`**(2026-08-18 추가 — 작업 종류별 대기 예산 4종, §10.6 「대기 예산은 종류별로 서버가 소유한다」. 이 항목은 슬라이더 프리필이 아니라 요청 제한시간의 근거라 **값이 없어도 생략되지 않고 항상 실린다** — 구 서술 "두 개뿐"은 폐기) |
| 값이 없을 때 | 저장값 부재·비숫자·타입 불일치 어느 쪽이든 **그 항목을 응답에서 생략**(`NON_NULL`). 화면이 자체 상수로 폴백하며 서버는 상수를 지어내지 않는다 |
| 운영 메타 | 마지막 수정자·수정일시 **미포함** |
| 쓰기 대응물 | **없음**. 설정 변경은 종전대로 검수자 전용 `PUT /v1/manage/configs/{key}`(SC-025)가 담당 |
| 인가 | 1차 `SecurityConfig` 의 `/v1/**` 매처(INTERNAL 채널) + 2차 `@PreAuthorize("hasAnyRole('REVIEWER','WORKER')")` — 서명 스트림 컨텍스트는 배제. 포털 토큰 403, 미인증 401 |

- **왜 신설했나**: 기존 시스템 설정 목록 조회(`GET /v1/manage/configs`)는 검수자 전용이라 작업자 라벨링 진입마다 403 이 쌓였고, 그 호출을 역할로 막고 나니 **작업자는 저장된 기본값을 아예 받지 못해** 코드 상수로 떨어졌다. 그 조회의 읽기 권한만 넓히는 안은 **채택하지 않았다** — 응답에 운영 파라미터 전량과 **마지막 수정자 계정 식별자**가 함께 실려 작업자에게 불필요한 정보가 나간다.
- 저장·타입·파싱 판정은 `SystemConfigService` 의 것을 그대로 재사용하고 키 문자열도 `ConfigKeys` 상수를 참조한다(판정 복제 금지).
- 코드: `sysconfig/controller/AiDefaultsController`, `sysconfig/service/AiDefaultsService`, `sysconfig/dto/AiDefaultsResponse`, FE `features/sysconfig/hooks/useAiDefaults.ts`(역할 게이트 없음) — LogiCraft `API-193`

## 10.6 장시간 작업 중 편집 차단 · 진행 표시 · 취소 (2026-07-31)

라벨링 화면의 장시간 작업이 도는 동안 **편집이 전면 차단되고, 무엇이 진행 중인지 화면에 보이며, 취소로 즉시 빠져나올 수 있다.** FE 전용이며 API·DB 변경은 없다.

### 대상 작업(busy) — 6종 단일 축

> ⚠ **`AI_AUTO_TRACK` 은 2026-08-18 추가**됐다(§10.2.4, 온디맨드 자동 추적 패널) — 구 5종에서 6종으로 확장. 이전 문서·리포트의 "5종"은 그 시점 기준 서술이다.

| 종류 | 표시 문구 | 트리거 |
|------|----------|--------|
| `AI_DETECT` | AI 탐지 진행 중 | AI 도구 팝업 실행 |
| `AI_SEGMENT` | AI 분할 진행 중 | 클릭/박스 프롬프트 · 즉시 그리기 프리뷰 |
| `AI_TRACK` | AI 추적 진행 중 | 추적 실행(선택 객체 하나를 따라감 — §10.2.4 「AI 자동 추적」과 다른 진입점) |
| `AI_AUTO_TRACK` | AI 자동 추적 진행 중 | §10.2.4 자동 추적 패널 실행 |
| `SAVE` | 저장 중 | 라벨 저장(내부·포털·포털 업로드) |
| `LOAD` | 불러오는 중 | 라벨 재조회(불러오기) |

- 여섯 종류가 **하나의 배타 축**을 공유한다 — 하나가 도는 동안 다른 하나는 시작되지 않는다.
- 문구는 `features/label/busyPolicy.ts` **단일 소스**에서 파생한다. 사용자 문구에 모델명(YOLO/SAM/SAM2)은 쓰지 않는다.
- busy 는 **작업이 속한 프레임**에 묶인다. 프레임/영상을 옮기면 이전 프레임의 작업이 새 화면을 잠그지 않고, 그 뒤 도착한 응답도 반영되지 않는다.

### 차단 — "요청 거부"가 아니라 **입력 차단**

판정은 `useIsEditBlocked`(렌더) / `isEditBlockedNow`(실시간) **한 쌍**이며, 두 값이 갈리면 **막히는 쪽**을 택한다(fail-closed). 배선된 진입점:

| 영역 | 차단 대상 |
|------|----------|
| 캔버스 | 새 도형 그리기, 기존 라벨 선택·이동·삭제(입력 단계에서 차단 — 드래그가 시작되지 않는다) |
| 좌측 도구바(`ToolBar`) | 도구 전환·보기 조작 버튼 전부 비활성 |
| 캔버스 상단 옵션바(`CanvasOptionBar`) | 삭제·실행 취소·다시 실행·저장·배율 조작 비활성 (⚠ 구 서술 "툴바 — 도구 전환·삭제·실행 취소·저장" 은 폐기 — 편집 액션 4종은 좌측 도구바에 없다, §10.2.0) |
| 프레임 이동 | 슬라이더 · 필름스트립 · 이전/다음 버튼 · 단축키 전부 |
| 실행 버튼 | 저장 · 검수제출 · AI 실행(팝업 포함) |
| 우측 패널 | 객체 속성 편집, 객체 목록의 선택·삭제 |
| 단축키 | 전 키맵. **ESC 만 예외이며 "취소"로 동작**한다 |
| 그 밖 | 되돌리기(revert) · 버전 롤백 · 비식별 누락 신고 |

- **예외 1 — AI 분할 클릭 누적**: 오버레이가 아직 뜨지 않은 지연 창(<300ms)에서는 클릭이 그대로 누적되고 확정은 큐에 들어간다(작업이 끝나면 누적점 전체로 실행). 화면에 아무 단서가 없는 구간에서 조작을 삼키면 이유 없이 사라진 것으로 보이기 때문이다. 오버레이가 뜬 뒤에는 누적하지 않는다.
- **예외 2 — 메타 편집은 busy 와 독립**(의도된 설계): 촬영환경 · 개인정보 메타 · 프레임 설명 · 이벤트 어노테이션 · 시계열 메타 검수는 진행 중에도 편집·저장된다. 라벨 작업본(`labels`/dirty)과 공유 상태가 없고 각자 별도 쿼리 키만 무효화하므로 정합성이 깨지는 경로가 없다. 회귀 테스트로 고정돼 있으며, 이 테스트가 깨지면 회귀가 아니라 **정책 변경**이다.

### 진행 표시 — 300ms 초과부터

- 캔버스 위 오버레이(`BusyOverlay`)에 **작업명 + 경과 초 + 취소 버튼**을 표시한다.
- **짧은 작업(<300ms)에는 표시하지 않는다** — 즉시 그리기처럼 클릭마다 짧은 요청이 나가는 경로에서 오버레이가 깜빡이면 화면이 고장난 것처럼 보인다.
- 접근성: `role="status" aria-live="polite" aria-busy="true"`, 오버레이가 뜨면 취소 버튼으로 포커스 이동(포커스 트랩은 만들지 않음), 경과 초는 라이브 리전에서 제외(매초 낭독 방지). 모달이 열려 있으면 포커스를 가져가지 않는다.
- 백드롭이 포인터 이벤트를 흡수한다 — 시각적 차단과 물리적 차단이 일치한다.

### 취소 시맨틱 (중요, 2026-08-18 정정 — 구 서술 "서버 처리를 중단시키지 않는다" 폐기)

- ⚠ **구 서술은 폐기됐다** — *"취소는 클라이언트에서 결과를 폐기하는 것이고, 서버 처리를 중단시키지 않는다"* 는 **더 이상 사실이 아니다. 지금은 서버 추론도 실제로 끊는다.** 근거는 실험이다 — "클라이언트가 연결을 끊으면 서버도 알아서 끊는다"는 이 실행 환경에서 성립하지 않았다(비동기 처리 중 유휴 구간에서 클라이언트가 정상 종료해도 서버 쪽에 아무 통지가 가지 않고, 동기 처리 중에는 관측 수단 자체가 없다). 그래서 명시적인 취소 통로를 만들었다.
- **작동 방식**: 추론을 요청할 때 화면이 매번 새 취소 식별자를 만들어 헤더로 함께 싣는다. 취소 버튼(또는 Enter/Space·ESC)을 누르면 **같은 식별자를 지정하는 별도 취소 요청**을 서버로 보내고, 서버는 그 식별자로 등록해 둔 진행 중 추론 연결을 실제로 끊는다.
- **취소는 오류가 아니라 정상 종료다.** 취소로 끝난 원 추론 요청은 잠금 충돌(409)이나 외부 연동 실패(502)와 **다른 전용 응답 코드**로 끝나며, 화면은 이를 오류 안내로 띄우지 않는다.
- ⚠ **알려진 한계 둘**: ①취소 등록은 **그 요청을 받은 노드 안에서만** 유효하다 — 여러 노드로 운영할 때 취소 요청이 다른 노드로 가면 그 추론을 찾지 못하고, 못 끊었다고 정직하게 알린다. ②취소가 보장하는 것은 **이 시스템이 ai-server 와 맺은 연결을 끊는 데까지**이며, 그 연결을 받은 ai-server 가 계산을 즉시 멈추는지는 그쪽 몫이다.
- 대상은 이 화면의 **온디맨드 추론(AI 탐지·AI 분할·AI 추적·AI 자동 추적)뿐**이며, **배치 파이프라인 오토라벨은 대상이 아니다.**
- 취소 후 뒤늦게 도착하는 응답은 **세대 토큰으로도** 폐기된다(다른 노드가 처리해 서버 쪽 취소가 닿지 않았거나, 취소와 응답 도착이 경합하는 좁은 창에 대한 클라이언트 쪽 안전망) — 같은 프레임이어도 반영되지 않는다.
- 수단: 취소 버튼 **마우스 클릭** · 버튼 포커스에서 **Enter/Space** · **ESC**. ESC 는 오버레이·캔버스·전역 단축키 어디서 눌려도 **같은 헬퍼 하나**를 거쳐 1회만 취소·안내한다(중복 안내 없음). 단, 전역 ESC 는 라벨링 단축키가 배선된 화면(내부·포털 라벨링) 기준이고, **포털 업로드 라벨링에는 라벨링 단축키가 없어 ESC 는 오버레이에 포커스가 있을 때만 동작**한다. 오버레이가 뜨면 취소 버튼으로 포커스가 이동하지만, 그 뒤 백드롭이나 화면 다른 곳을 클릭하면 포커스가 빠져 ESC 가 듣지 않는다 — 그때는 취소 버튼 클릭으로 취소한다.
- 오버레이가 뜨기 전(지연 창)의 ESC 취소는 화면에 흔적이 없으므로 **토스트로 안내**한다.
- ESC 취소는 대기 중인 AI 분할 **확정 큐도 함께 비운다** — 취소했는데 그 작업이 뒤늦게 발사되면 정반대 동작이다. 누적점 자체는 지우지 않는다(사용자가 지운 적이 없다).
- 해제 누락 방지: 성공·실패·예외 어느 경로로 끝나도 해제되고, **작업 종류별 대기 예산 + 여유**(2026-08-18 정정 — 아래 「대기 예산은 종류별로 서버가 소유한다」 참고)로 자동 해제된다(화면 영구 잠금 방지). 구 서술 "최대 5분(모든 작업 공통 고정값)"은 폐기됐다.

### 대기 예산은 종류별로 서버가 소유한다 (2026-08-18 신설)

**요청 제한시간·작업잠금 fail-safe 상한은 더 이상 화면의 고정 상수가 아니다.** 네 종류(AI 탐지·AI 분할·AI 추적·AI 자동 추적) 각각의 예산이 다르며, 값은 서버가 계산해 내려준다 — 서버의 재시도 횟수·백오프가 바뀌면 그 값에서 자동으로 다시 도출되는 값이라, 화면이 이를 자기 상수로 베껴 두면 서버 쪽 재시도 예산이 바뀌는 순간 조용히 어긋나 **정상 동작이 "AI 실패"로 보이는** 결함이 된다.

- 화면은 §10.5.1 의 읽기 전용 경로(`GET /v1/ai-defaults`)로 이 예산을 받는다(슬라이더 초기값과 같은 응답에 실린다).
- 운영자가 **절대 상한**을 시스템 설정에서 조정할 수 있다. 다만 그 상한에는 **하한**이 있다 — 서버가 한 프레임짜리 요청을 정당하게 완주하는 데 필요한 최소 시간보다 낮게 잡으면 정상 요청도 완주 전에 잘려 결과가 조용히 사라지는 원래 결함이 되살아나므로, 그런 값은 저장이 거부되고 이미 저장된 값이 하한 아래로 남아 있어도 읽는 시점에 다시 하한으로 끌어올려 적용한다.
- 절대 상한의 기본값·최댓값 근거는 **앞단(프록시)이 응답을 기다려 주는 시간**이다 — 그보다 긴 계획은 서버가 세워도 이룰 수 없다.
- 서버 값을 받지 못했을 때만 화면이 자체 폴백 상수로 동작한다(정상 상태에서는 쓰이지 않는다).
- **프레임을 훑는 두 추적 경로(AI 추적·AI 자동 추적)는 요청 하나 전체에 별도의 wall-clock 예산**을 두고, 그 예산이 다하면 그때까지의 성공분을 보존한 채 **어디까지 처리했는지**를 응답에 담아 돌려준다. 화면은 그 지점부터 자동으로 이어 보낸다 — 그 결과 한 요청에 실리는 프레임 수가 크게 늘어 왕복·재시드 횟수가 줄고 추적 품질에 유리하다. ⚠ 이어 보낸 조각에서는 추적기가 리셋돼 객체 식별자가 새로 매겨지므로, 화면은 조각을 구분해 표기하고 서로 다른 조각의 번호를 합치지 않는다.

### 범위 밖

- **크로스탭·다중 사용자 동시성은 이 차단의 대상이 아니다.** FE busy 는 **같은 탭 안**에서만 성립하며, 다른 탭·다른 사용자와의 충돌은 서버 낙관적 잠금(라벨 저장 409 → 충돌 다이얼로그)이 담당한다.
- 배치 파이프라인 진행 표시, 마킹·검수 화면은 이 규칙의 대상이 아니다.

### 적용 화면 — 세 화면의 경계

| 화면 | 경로 | 데이터 | busy 종류 |

## 10.7 프레임 폐기·복원 (R4·R5, 2026-08-11)

작업자·검수자가 학습데이터 산출물에서 특정 프레임을 빼고 싶을 때(예: 흔들린 프레임, 라벨링 대상이 아닌 장면) **논리 폐기**한다 — 프레임 행·이미지 파일·라벨은 그대로 보존되고 표시만 바뀐다. 복원(재사용)도 같은 축의 역방향이다.

- **진입점은 캔버스 상단 옵션바의 [프레임 폐기]/[프레임 복원] 토글 하나뿐이다.** 별도 확정 버튼이 없고, **저장을 눌러야 확정된다**(D8) — 화면에서 한 조작과 서버 상태가 어긋나지 않게 하기 위해서다. 토글은 다른 편집과 같은 dirty 축에 들어가 저장 전에는 "아직 저장하지 않았습니다" 안내가 함께 뜬다.
- **저장 계약에 실린다** — 별도 엔드포인트가 아니라 기존 라벨 저장 요청의 선택 필드다.
  - 프레임 단위 저장: `PUT /v1/frames/{srcSn}/labels` body의 `dscdYn`(`'Y'`/`'N'`, 선택). **값이 없으면(생략) 현재 값을 그대로 둔다** — 폐기를 건드리지 않은 저장이 폐기 상태를 조용히 되돌리지 않는다.
  - 영상 단위 확정 저장(§13.8.2): `edits[].dscdYn`. 값을 생략하면 회차 스냅샷의 값을 쓴다.
- **캔버스 표시**: 현재 프레임이 폐기 상태면 캔버스 위에 안내 배너가 뜨고, 편집(도형 그리기·이동·삭제)은 잠기지만 **토글·저장은 열어 둔다** — 둘 다 막으면 폐기를 되돌릴 방법이 없다. 필름스트립은 폐기된 형제 프레임에 표식을 남긴다(다른 프레임의 라벨 응답에 실리는 `dscdYn`을 근거로 갱신되므로, 폐기 여부를 실어 보낸 저장은 그 영상의 라벨 캐시를 광역 무효화한다).
- **감사**: 폐기·복원 각각 `LS_TASK_EVNT_LOG`에 `FRAME_DISCARD`/`FRAME_RESTORE` 1건(누가·언제·어느 프레임)을 남긴다.
- **데이터마트 노출에서 제외**: `V_COMPLETED_VIDEO`·`V_COMPLETED_FRAME` 뷰가 `COALESCE(DSCD_YN,'N') <> 'Y'`를 판정 조건으로 공유한다(애플리케이션 술어·엔티티 판정과 같은 기준). 폐기는 논리 폐기라 뷰가 라이브 `LS_DATA_SRC`를 읽으므로 **복원하면 다시 나타난다** — 별도 복원 배선이 필요 없다. 산출 원장(`LS_DATASET_EXPORT`)도 폐기분을 뺀 프레임 수로 기록되고 학습데이터 이미지 세트·JSON에서도 제외된다.
- 코드: `label/service/FrameDiscardApplier`(상태 전이 + 감사의 **단일 적용 지점**) · `batch/entity/LsDataSrc`(`DSCD_YN`) · FE `features/label/components/CanvasOptionBar.tsx`·`FrameFilmstrip.tsx`.

### 10.7.1 한번이라도 검수 완료된 영상은 새로 폐기·복원할 수 없다 (P2b, 2026-08-11 사용자 확정, 구속)

**400**(역할 무관). 판정은 [12 §12.2.1](12-review-assignment.md)의 `ReviewApprovalGate.hasEverApproved` — **지금 상태가 아니라 이력**이다.

- **왜 이력인가**: 검수 승인 후 재검수 재제출로 상태가 `PENDING`으로 내려간 구간이 있다. 지금 상태만 보는 판정은 그 구간에 프레임을 새로 폐기·복원할 수 있게 열어 두는데, 이미 산출되어 외부로 나간 회차에서 프레임이 빠지거나 되살아나면 그 회차의 산출물과 어긋난다(데이터마트를 그 회차로 되돌리면 걷어낸 프레임이 되살아나거나, 반대로 있던 프레임이 사라진다).
- **회차 적용은 예외다** — 「시작 버전 선택」(§13.8.1~2)으로 불러온 회차를 그대로 확정 저장하는 경우는 막지 않는다. 그 회차의 폐기 상태는 이미 승인·통지된 것이라 **새로 바꾸는 게 아니라 그 시점으로 되돌아가는 것**이기 때문이다. 막으면 확정 저장이 라벨만 적용하고 폐기 상태는 현재값으로 남아 "한 영상 = 한 회차" 불변식이 깨진다.
- **판정은 "필드가 왔는가"가 아니라 "값이 회차와 다른가"다.** 화면은 폐기를 건드리지 않아도 회차 값을 그대로 실어 보내므로(§13.8.1의 왕복 계약), 필드 존재로 판정하면 라벨만 고친 정상 저장까지 막힌다. 반대로 경로(프레임 단위/영상 단위) 단위로 항상 열어 두면 회차를 한 번 불러오는 것만으로 차단이 우회된다. **비교 기준선은 회차 스냅샷 값이고, 그 회차를 알 수 없는 프레임(`resolved=false`)은 라이브 현재 값(`LS_DATA_SRC.DSCD_YN`)이다.** ⚠ 구 판정(*"스냅샷이 없으면 비교 기준이 없으므로 값과 무관하게 새 조작으로 본다"*)은 **폐기**됐다 — 불러오기는 그런 프레임에도 현재 값을 그대로 실어 "이 세트를 그대로 확정 저장해도 no-op" 을 보장하는데(§13.8.1), 스냅샷 하나만 기준으로 삼으면 값이 같아도 막혀 **아무것도 바꾸지 않은 저장이 400** 이 됐다. **폐기한 프레임은 라벨이 0건이라 언제나 `resolved=false`** 이므로, 프레임 폐기를 쓴 영상은 확정 저장이 사실상 항상 거부됐다(로컬 실증). 라이브를 기준선으로 두면 회차 적용 예외(위 항목)와 우회 차단이 함께 성립한다.
- **신고(412)와 코드가 다른 이유**: 이 저장소의 전례는 412=해소되면 되는 일시 조건(비식별 신고 구간), 400=되돌아가지 않는 영구 조건(파생영상 차단)이다. "한번이라도 승인"은 영구 조건이라 재시도 여지가 없다 — 신고와 폐기 차단이 같은 "이력" 축을 공유하면서도 응답 코드가 갈리는 것은 사유의 성질이 다르기 때문이다(의도된 비대칭) → [08 §8.4](08-deidentification.md).
- **잔여 위험(인지·수용, 되돌리지 말 것)**: 승인 후 잘못 폐기된 프레임은 되돌릴 수단이 없다 — 프레임 축·영상 축·REVIEWER 권한 어느 경로로도 복원이 400이고, 폐기 이전 회차가 아예 없으면(첫 승인에서 이미 폐기 상태로 동결) 되돌아갈 회차 자체가 없다. 그 프레임은 학습데이터 산출물에서 영구 누락된다. REVIEWER 정정 override 안은 검토 후 채택하지 않았다("승인된 학습데이터는 되돌리지 않는다"에 예외를 두지 않는다) — 발견은 승인 전에 이뤄지는 것이 전제다.
- 회귀 가드: 폐기 쓰기 통로가 `FrameDiscardApplier.apply` 한 곳뿐임을 정적으로 고정한다(게이트가 한 곳이라 다른 경로로 그 컬럼을 쓰면 그대로 샌다).
