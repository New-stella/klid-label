## 1. 문서 개요

### 1.1 목적

본 문서는 학습데이터 저작도구의 사용자 인터페이스(UI) 및 사용자 경험(UX)에 대한 설계 기준을 정의한다. 화면 레이아웃, 컴포넌트 구성, 사용자 플로우, 상호작용 규칙을 명세하여 개발 단계에서의 구현 기준으로 활용한다.

### 1.2 범위

| 채널 | 대상 사용자 | 진입 방식 |
|------|-------------|-----------|
| 관제지원시스템 (내부) | 라벨링 작업자, 검수자 | 관제서버 세션 인계 (JWT) |
| AI 영상학습 사용자 포털 (외부) | 데이터 기여자, 외부 AI 연구자 | 포털 서버 세션 인계 (JWT) |

두 채널 모두 저작도구 자체 로그인 화면 없음. 상위 시스템(관제서버 / 포털 서버)에서 발급한 JWT 토큰을 인계받아 진입한다. 세션 만료 시 각 상위 시스템 로그인 페이지로 리다이렉트한다.

### 1.3 관련 SFR

| SFR | 기능명 |
|-----|--------|
| SFR-07 | 데이터 증강 |
| SFR-08 | 저작도구 핵심 기능 (오토라벨링 결과 확인·VLM 객체 검증·외부 메타 검토 UI·증강 연동·배경영상 요청·생성된 영상 라벨링 흡수) |
| SFR-09 | 비식별화 결과 확인 |
| SFR-15 | AI 영상학습 사용자 포털 |
| SFR-16 | 이미지 학습데이터셋 |
| SFR-17 | 영상 학습데이터셋 |
| QUR-03 | 검수 품질관리 |

본체가 외부 시스템인 SFR-03(시계열 메타데이터)·SFR-06(생성형 AI)·SFR-11(영상 합성 모델)은 요구사항정의서에서 제외되며, 저작도구 잔존 책임(VLM 객체 검증·외부 메타 검토·증강 연동·배경영상 요청·생성 영상 라벨링)은 모두 SFR-08에 흡수된다.

### 1.4 화면 ID 체계

```
SCR-[도메인코드]-[3자리 순번]

도메인코드:
  VIDEO  : 영상 목록 / 처리 현황 / 영상 상세 (메인 진입점)
  DASH   : 대시보드
  PRESET : 프리셋 관리
  TASK   : 작업 관리
  LABEL  : 라벨링 도구
  AUTO   : 오토라벨링 결과 확인·메타데이터
  HIST   : 히스토리·버전관리
  REVIEW : 검수 워크플로우
  DEIDENT: 비식별화 결과 확인
  STAT   : 통계
  AUG    : 데이터 증강
  EXPORT : 내보내기
  GEN    : 배경영상 생성
  PORTAL : 포탈 진입
  MANAGE : 관리 (사용자 관리·시스템 설정 — 검수자 전용)
```

```
┌────────────────────────────────────────────────────────────────────┐
│  [로고: AI 학습데이터 저작도구]  영상  |  작업관리  |  통계  |  관리          │

"영상" 그룹은 `/video/*` 경로로 영상 처리 현황 메뉴를 제공한다 (별도 처리 현황 화면은 V1.x에서 제거되어 표 내부 컬럼으로 통합).

## 4. 화면 설계

### 4-1. 세션 인계 · 진입

저작도구는 자체 로그인 화면을 제공하지 않는다. 관제서버 또는 포털 서버가 발급한 JWT 토큰을 URL 파라미터 또는 쿠키로 수신하여 사용자를 식별하고 **영상 목록**(메인 진입점, `/video/completed`)으로 이동시킨다.

| 상황 | 처리 |
|------|------|
| 유효한 토큰 수신 | role 클레임 확인 → 메인 진입점으로 이동 |
| 토큰 없음·만료 | 상위 시스템(관제서버 또는 포털) 로그인 페이지로 리다이렉트 |
| 권한 없는 메뉴 접근 | 403 페이지 표시 + 메인 진입점 링크 안내 |

---

### 4-2. 영상 목록 (메인 진입점)

영상 목록은 메인 진입점이며, 경로는 `/video/completed`이다. 행 액션에 **✨ 배경영상 요청**이 포함되며 모든 영상에 노출된다 (REVIEWER 권한). 클릭 시 `BackgroundGenerateModal`이 열린다.

#### SCR-VIDEO-001 : 영상 처리 현황 (V1.x)

> V1.x 라벨 변경: "영상 목록" → **"영상 처리 현황"**. 별도 처리 현황 화면(SCR-VIDEO-002)을 제거하고 본 화면 표 내부에 **"처리 단계" 컬럼**을 통합한다. 행 액션은 [상세] 단일.
>
> **V1.x 후속 (2026-05-07)**: '처리 상태'·'처리 단계' 두 컬럼이 단일 **'처리 단계'** 컬럼으로 통합되었다 — 진행 상태(대기/처리중/완료/실패)는 칩의 **색상 톤**으로 표현된다. 모든 stage가 DONE인 영상은 단일 단계 배지가 아닌 **'완료'** 라벨(success 톤)로 단순 표시된다.

#### SCR-TASK-002 : 작업 배정 (REVIEWER 전용 / single + bulk 모드)

작업 배정 권한은 REVIEWER가 단독 보유한다. AssignModal은 작업자 선택만 받으며, 우선순위 / 기한 / 메모 입력 폼은 두지 않는다.

**모달 모드 (V1.x)**

| 모드 | 진입 경로 | 설명 |
|------|-----------|------|
| `single` (`assign`) | 작업 목록 행 [배정] | 단일 task 배정 |
| `single` (`reassign`) | 작업 목록 행 [재배정] | 기존 배정 변경 (이력 기록) |
| `bulk` | 작업 목록 액션바 [N개 일괄 배정] | 선택된 영상 N개에 동일 작업자/검수자를 단일 트랜잭션으로 배정 (V1.x 신규) |

**모달 동작 명세**

- 검수자 칸은 모달을 연 REVIEWER 본인으로 자동 지정된다(별도 선택 UI 없음).
- **작업자 기본값 (V1.x 후속)**: 비어있으면 **현재 로그인 사용자(`currentUser.id`)** 가 자동 선택된다. bulk 모드는 항상 `currentUser.id`가 기본 선택. 사용자가 dropdown으로 변경한 값은 그대로 유지된다.
- single 모드: 기존 task의 assigneeId를 갱신하고 `LS_PJT_USER_AUTHRT_HSTRY` 이력 INSERT. **V1.x 후속 — 단일 배정도 bulk 모드 1건 호출로 통합** (핸들러 멱등 처리).
- bulk 모드:
  - 모달 상단에 대상 영상 요약 (앞 3개 배지 + "외 N건")
  - 안내 문구: "선택된 모든 영상에 동일한 작업자/검수자가 배정됩니다. 이미 동일 배정인 영상은 변경되지 않습니다."
  - API: `POST /api/v1/tasks/bulk-assign` (멱등 처리). 응답 `{ assigned, skipped, total, tasks }`
  - **V1.x 후속**: task가 없는 영상은 신규 task가 생성됨 (작업 목록의 영상-기반 데이터 소스와 정합)
  - 토스트: `"{N}건 일괄 배정 완료"` (N은 assigned + skipped 합계)
- 저장 중 작업자/검수자 select는 비활성화 (이중 클릭 방어).

```

#### SCR-DEIDENT-001 : 비식별화 처리 결과 목록 (V1.x 제거)

> **V1.x 정책 변경**: 비식별 처리는 배치 파이프라인의 **자동 단계가 아닌 내보내기(포털 전송) 시 옵션 호출**로 운영된다. 이에 따라 별도의 비식별 결과 검토 화면(SCR-DEIDENT-001)은 제거되었다. 비식별 옵션 토글 및 처리는 SCR-EXPORT-001 내보내기 화면에서 수행한다.

  - **이미 내보낸 영상 포함 (V1.x 후속)** — 기본 OFF. ON 시 `forceReexport: true`로 요청
- 전송 대상 정보: 포털 endpoint(`https://portal.example.com/api/v1/datasets/import`)를 카드 형태로 노출

**비식별 정책 정정 (V1.x 후속)**

비식별은 매 전송 시도마다 실행되는 단발 행위이며, 영상이 영구적으로 '비식별 실패' 영구 속성을 가지지 않는다. 매 시도마다 비식별이 실행되고, 실패 시 그 시도의 사유로만 영상의 `lastExportFailureReason='비식별 실패'`가 기록된다. 영상의 `exportStatus = 'FAILED'`는 다음 시도에 자연스럽게 재선택 가능하다(`forceReexport`와 무관). mock 시뮬레이션 플래그(`DEIDENT_FAIL_SIMULATION`)는 외부 API에 노출되지 않는다.
