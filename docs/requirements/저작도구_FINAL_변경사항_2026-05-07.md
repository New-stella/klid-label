### 3.2 § 4.4.3a 검수 이슈 관리 — 신규 섹션

**변경 사유**: mock delta #1, #2, #3, #4, #5, #6 — 캔버스 좌표 기반 이슈 마킹의 전체 흐름·정책을 명문화

**전체 내용** (이 섹션은 V1.x에서 신규 추가됨):

> #### 4.4.3a 검수 이슈 관리
>
> 검수자는 라벨링된 결과의 문제 지점을 **캔버스 좌표 단위로 마킹**하여 이슈를 등록한다.
>
> **이슈 마킹 흐름**:
> 1. **이슈 추가 모드 토글** — 우측 패널의 [🚩 이슈 추가 모드] 버튼으로 모드 진입
> 2. **캔버스 클릭** — 빈 영역 또는 라벨링된 객체(bbox/polygon) 위 어느 곳이든 클릭 가능. 클릭 위치에 임시 점선 마커가 즉시 표시되고 코멘트 모달이 오픈됨
> 3. **코멘트 저장/취소** — 저장 시 정식 마커(빨간 원 + 🚩)로 전환되며 우측 패널 항목으로 추가. 취소 시 임시 마커 사라짐
>
> **이슈 좌표 저장**:
> - 각 이슈는 `frameNo` 외에 `x`, `y` 좌표를 함께 저장한다 (캔버스 원본 픽셀 기준).
> - 좌표는 결과보기(읽기 전용 모드) 진입 시에도 보존되어 다른 검수자가 이전 마킹 위치를 그대로 확인 가능하다.
>
> **승인 차단 정책 (Critical)**:
> - 등록된 이슈가 1건 이상이면 [✅ 승인] 버튼은 비활성화되며 "⚠️ 등록된 이슈 N건 — 승인할 수 없습니다. 반려를 진행하세요." 안내가 표시된다.
> - 클라이언트 UI 차단과 더불어 서버에서도 가드한다(이슈가 있는 검수의 승인 API 호출 시 거부).
>
> **마커 ↔ 패널 양방향 동기화**:
> - 캔버스 마커 클릭 시 우측 패널의 해당 이슈 항목이 강조 표시되고 자동 스크롤된다.
> - 우측 패널 항목 클릭 시 캔버스의 해당 마커가 강조된다.

### 4.4 § 4.5 `LS_DATA_ISSUE` — 검수 이슈 캔버스 좌표 (V1.x) — 신규 섹션

**변경 사유**: mock delta #1, #6 — 캔버스 좌표 마킹을 위한 컬럼 정식 추가

**전체 내용 (이 섹션은 V1.x에서 신규 추가됨)**:

> ### 4.5 `LS_DATA_ISSUE` — 검수 이슈 캔버스 좌표 (V1.x) ★
>
> 검수자가 캔버스에서 문제 지점을 좌표 단위로 마킹할 수 있도록 좌표 컬럼을 신규 추가한다. 등록된 좌표는 결과보기(읽기 전용 모드) 진입 시에도 보존되어 검수 이력 추적용으로 활용한다.
>
> | 추가 컬럼 | 타입 | NULL | 기본값 | 설명 |
> |-----------|------|:----:|--------|------|
> | `X_COORD` | DECIMAL(10,4) | ✓ | NULL | 이슈 마킹 X 좌표 (캔버스 원본 픽셀 기준) |
> | `Y_COORD` | DECIMAL(10,4) | ✓ | NULL | 이슈 마킹 Y 좌표 (캔버스 원본 픽셀 기준) |
>
> **추가 이유**
>
> - 요구사항정의서 §4.4.3a 검수 이슈 관리 — 캔버스 좌표 기반 마킹 흐름 지원.
> - 결과보기에서 이전 검수자의 마킹 위치 보존 → 검수 이력 추적 가능.
> - optional 컬럼으로 정의하여 좌표 없이 등록된 기존 이슈와의 호환성을 유지한다.
>
> ```sql
> ALTER TABLE LS_DATA_ISSUE
>     ADD COLUMN X_COORD DECIMAL(10,4) NULL COMMENT '이슈 마킹 X 좌표 (캔버스 원본 픽셀 기준)',
>     ADD COLUMN Y_COORD DECIMAL(10,4) NULL COMMENT '이슈 마킹 Y 좌표';
> ```
>
> | 항목 | 값 |
> |------|----|
> | 마이그레이션 버전 | V1.x__add_issue_coords.sql |
> | 협의 필요 | 관제서버팀 (klid_system 공유 테이블) |
> | 호환성 | optional 컬럼 — 기존 좌표 없는 이슈 그대로 호환 |
>
> > **참고**: 본 컬럼 추가는 관제서버팀과 사전 협의가 필요하다. Flyway 마이그레이션 작성 시 `klid_system` 공유 테이블이므로 ALTER 시점 조정 필요.

> - **bbox**: 박스의 **좌상단 외부**(top: y - 18px)에 라벨 텍스트 배치. 박스 안쪽을 가리지 않아 검수자가 박스 영역의 객체를 그대로 확인 가능.
> - **polygon**: 다각형의 **무게중심**(centroid)에 라벨 텍스트 배치. 부정형 도형이라도 라벨이 도형 안쪽에 안정적으로 위치.
> - 양 정책은 CVAT 등 표준 라벨링 도구 관행과 일치.

## V1.x — 후속 UX 개선 및 데이터 모델 정정 (2026-05-07)

V1.x 발주처 피드백 4건 반영 직후 시연 검토를 거치며 발견한 UX 결함과 데이터 모델 결함을 보완. 동일 일자에 mock에 11건의 후속 변경이 추가 반영되었으며, 본 절은 그 변경 내역을 4종 FINAL 문서에 정합화한 결과를 정리한다.

### 1. 메뉴/네비게이션

- **영상 처리 현황**: '처리 상태'·'처리 단계' 두 컬럼을 단일 **'처리 단계'** 칩으로 통합 (status는 색상 톤으로 표현됨 — 진행/완료/실패/대기 구분)
- 모든 stage가 DONE이면 **'완료' 라벨**(success 톤)로 단순화. 진행 중·실패·대기는 기존대로 stage 이름 표시
- 검수 메뉴 라벨 **'검수 대기' → '검수 목록'**
- 검수 메뉴 그룹 **'검수' → '작업'** (사이드바에서 작업 목록과 동일 그룹에 노출)

### 2. 작업 목록 — 데이터 모델 전환

- 데이터 소스: **task 기반 → 처리 완료 영상 기반(left-join task)** 으로 전환
- 처리 완료(stages 모두 DONE) 영상은 task 유무와 무관하게 모두 행으로 노출
- task 없는 영상: 작업자 **'미배정'**, 검수자 **'미등록'** 라벨로 표시. 체크박스 선택 가능
- bulk-assign 핸들러: task가 없으면 **신규 task 생성**, 있으면 갱신 (멱등 유지)
- 단일 배정도 bulk 모드 1건 호출로 통합 처리
- 상태 필터에 **`UNASSIGNED`(미배정)** 옵션 추가
- 시드: 처리 완료 + task 미생성 영상 3건(video-0031~0033) 제공
- 이벤트 컬럼: 다른 화면(Dashboard, BatchCompletedList, VideoDetail)과 동일한 **EventTypeBadge 색상 매핑** 적용

### 3. 배정 모달 기본값

- 작업자(assignee) 기본값: 비어있으면 **현재 로그인 사용자(`currentUser.id`)** 자동 설정
- bulk 모드: 항상 `currentUser.id` 기본 선택
- 사용자가 dropdown으로 변경한 값은 그대로 유지

### 4. 내보내기 — 이력 상태 + 가드

- VideoDto 신규 필드: **`exportStatus`** (`NEVER` / `EXPORTED` / `FAILED`), **`exportedAt`**, **`lastExportFailureReason`**
- ExportRequest 신규 필드: **`forceReexport`**
- ExportResponse 신규 필드: **`failedDueDeident`**, **`skippedAlreadyExported`**, **`blockedNotApproved`**
- 이미 내보낸(`EXPORTED`) 영상은 기본 disabled. **"이미 내보낸 영상 포함"** 토글로 강제 재전송 가능
- **검수 완료(taskStatus=COMPLETED) 영상만 내보내기 가능** — 핸들러 0번째 가드, `forceReexport`와 무관
- 응답 토스트 "비식별 실패 N건 (다시 시도 가능)" / "이미 내보낸 N건 스킵" / "검수 미완료 N건 차단"

### 5. 비식별 정책 정정 (영구 속성 폐기)

- 비식별은 **매 전송 시도마다 실행되는 단발 행위**. 영상이 영구적으로 '비식별 실패' 속성을 가지지 않음
- 실패 시 그 시도의 사유로만 영상의 `lastExportFailureReason='비식별 실패'`로 기록됨
- 영상의 `exportStatus = 'FAILED'` 상태는 다음 시도에 자연스럽게 재선택 가능 (`forceReexport` 무관)
- mock 시뮬레이션 플래그(`DEIDENT_FAIL_SIMULATION`)는 외부 API에 노출되지 않음 — 핸들러 내부에서만 참조
- 이전 V1.x에서 `VideoDto.deidentified` 영구 필드 제거 결정과 정합 — 그 결정을 강화한다

### 6. 검색·필터·페이징 (수백 건 영상 처리)

- **내보내기 영상 선택 영역**: 검색(영상명/CCTV/id) + 이벤트 필터 + 전송 상태 필터(전체/미전송/이미 전송/전송 실패) + **100건 client-side 페이징** + URL `q`/`eventType`/`exportFilter` 동기화
- 선택 카운트 헤더, indeterminate 헤더 체크박스
- 빈 상태 3분기: 검수완료 0건 / 필터 결과 0건 / 표시 0건
- **증강 요청**: 카드 그리드 → **테이블 리스트** 로 재구성. 컬럼: 체크박스 / 영상명·CCTV / 이벤트(EventTypeBadge) / 녹화일 / 검수 완료 일시. 검색 + 이벤트 필터 + 100건 페이징 + URL 동기화

### 7. 증강 요청 — 검수 완료 가드

- `taskStatus === 'COMPLETED'` 영상만 목록에 노출 (미승인은 목록 자체에서 제외)
- 다중 선택 + 헤더 indeterminate + "[N개 영상 증강 요청]" 액션바
- 핸들러 가드: 전부 미승인 → 422, 일부 미승인 → 승인 영상만 처리

### 8. UI 디테일

- '최근 요청 이력' 5초 polling 시 깜빡임 수정 (첫 로딩만 skeleton, 이후 polling은 silent 갱신)

### 9. 영향 통계 (V1.x 후속)

- 화면 카탈로그: **22개 유지** (SCR 정의 갱신만)
- 시연 시나리오: **8개 유지** (본문만 갱신)
- 신규 DTO 필드: VideoDto 3개(`exportStatus` / `exportedAt` / `lastExportFailureReason`), ExportRequest 1개(`forceReexport`), ExportResponse 3개(`failedDueDeident` / `skippedAlreadyExported` / `blockedNotApproved`)
- 신규 DB 컬럼: `LS_DATA_VIDEO`(또는 영상 메타 테이블) 3컬럼 — `EXPORT_STATUS_CD`, `LAST_EXPORTED_AT`, `LAST_EXPORT_FAIL_REASON`
- 비즈니스 규칙: 검수 완료 가드(내보내기·증강 양쪽), 멱등 신규 task 생성(작업 목록), 멱등 비식별 시도별 사유 기록

### 10. 후속 작업 (V1.x 후속)

- **DB 마이그레이션 (V1.x 후속)**:
  - `V1.x__add_export_status_columns.sql` — 영상 메타 테이블에 `EXPORT_STATUS_CD` / `LAST_EXPORTED_AT` / `LAST_EXPORT_FAIL_REASON` 추가
- **백엔드 API**:
  - `POST /api/v1/export` 핸들러에 0번째 가드 추가(검수 완료 영상만), 응답 객체에 `failedDueDeident` / `skippedAlreadyExported` / `blockedNotApproved` 카운트 포함
  - `POST /api/v1/augments/request` 핸들러에 검수 완료 가드 추가
  - bulk-assign 핸들러: task 없으면 신규 생성(멱등) — 작업 목록의 영상-기반 데이터 소스와 정합
- **프론트엔드**:
  - 작업 목록을 영상-기반 데이터 소스로 재구성, '미배정'/'미등록' 표시, UNASSIGNED 필터
  - 내보내기/증강 양쪽 영상 선택 영역에 검색·필터·페이징·URL 동기화
  - 내보내기 "이미 내보낸 영상 포함" 토글
  - 배정 모달 기본값 = 현재 사용자
- **시연 가이드 정합성**: `docs/review-guide.md` 시나리오 ①·③·④·⑤ 본문 갱신 — 시나리오 번호는 변경하지 않음
