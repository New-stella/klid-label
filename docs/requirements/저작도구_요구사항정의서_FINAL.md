## 1. 문서 개요

### 1.1 목적

본 문서는 "AI 기반 지방정부 CCTV 관제지원시스템 구축(2차)" 사업 중 학습데이터 저작도구 모듈의 기능 요구사항, 개발 범위, 일정을 체계적으로 정의한다. 제안요청서(SFR)에 명시된 기능 요구사항과 WBS 상세 태스크를 기반으로 작성되었으며, 설계·개발·테스트 전 단계에서 기준 문서로 활용된다.

저작도구는 독립적인 로그인 체계를 갖추지 않고 관제서버의 세션을 인계받아 동작하는 통합 채널로 운영된다. 영상 유입 및 전처리(프레임 추출 + 오토라벨링)는 관제서버 배치 파이프라인이 담당하며, 저작도구는 배치 처리가 완료된 영상 목록에서 시작하는 구조다.

### 1.2 적용 범위

- 관제지원시스템 내 학습데이터 저작도구 기능 고도화
- AI 영상학습 사용자 포털의 저작도구 외부 서비스 연동
- 저작도구와 직·간접으로 연관된 SFR 및 QUR-03 전 기능

### 2.2 저작도구 위치 및 역할

저작도구는 추진전략 "다. AI CCTV 관제지원시스템 및 저작도구 기능 고도화"의 핵심 구성요소로, 시계열 메타데이터 검토·관리, 라벨링 정확도 향상, 학습데이터 버전 관리, 학습데이터셋 내보내기를 담당한다. 데이터마트 구축·검색·다운로드는 외부제공 시스템 책임으로 분리된다.

저작도구는 관제지원시스템(내부 채널)과 사용자 포털(외부 채널) 두 채널로 제공된다. **두 채널 모두 별도 로그인 화면을 갖지 않으며, 각 채널의 상위 시스템(관제서버 / 포털 서버)으로부터 세션을 인계받아 진입한다.** 내부 채널은 관제서버가 완료한 배치 처리 결과(프레임 추출 + 오토라벨링)를 수신하여 검수·가공 작업을 수행한다.

### 2.3 전체 시스템 구조

```
[지자체 CCTV]
      ↓ 영상 수신
[관제서버]
  ① 라벨링 필요 여부 판별
  ② 라벨링 대상 영상 목록 → 저작도구에 전달

          ↓ (세션 없이 서버 자동 실행)

[저작도구 — 배치 파이프라인 (백그라운드)]
  ③ 라벨링 대상 영상 배치 처리 (1건/분, 인증 불필요)
      └ VLM 시계열 메타 (외부 시스템 호출, 단계 진행 표시만)
      └ FFmpeg 프레임 추출 (1프레임/분)
      └ YOLO 오토라벨링 자동 수행
      └ SAM2 세그멘테이션 자동 수행

  (V1.x — 처리 단계 순서: VLM → FRAME_EXTRACT → YOLO → SAM2)
  (V1.x — 비식별 처리는 단계에서 제거되어 내보내기(포털 전송) 시 옵션으로 호출됨)
  (시계열 메타데이터 자동 생성은 외부 시스템 책임)

          ↓ (사용자 진입 시 세션 인계 — JWT)

[저작도구 — 사용자 화면]
  ④ 배치 완료 영상 목록 진입점 제공
  ⑤ 검수자 → 작업자 배정
  ⑥ 작업자 라벨 정밀 검수·수정
  ⑦ 검수자 최종 승인
  ⑧ 증강 → 내보내기 (V1.x — 비식별 처리는 내보내기 옵션으로 통합. 포털 서버 전송 단일 채널)

[포털 서버]
      ↓ 세션 인계 (JWT / SSO)
[저작도구 — 외부 채널 (포털 진입 모드)]
  ① 포털 서버 세션으로 사용자 식별 (회원가입·로그인 없음)
  ② 간편 라벨링 도구 (기능 제한 적용)
  ③ 다운로드 권한·기한 관리는 포털 자체 책임 — 저작도구는 다운로드 UI 미제공
```

### 2.4 역할 정의

| 역할 | 코드 | 주요 권한 |
|------|------|-----------|
| 검수자 | REVIEWER | **사용자 관리·시스템 설정**, 작업자 배정·재배정·배정 이력 조회, 검수 승인/반려 |
| 라벨링 작업자 | WORKER | 라벨 수정·검수 제출 |
| 포털 회원 | PORTAL_USER | 이미지/영상 업로드, 간편 라벨링 체험 (다운로드는 포털 자체 책임이며 저작도구는 다운로드 UI 미제공, 기여도 점수 없음) |

검수자(REVIEWER)는 모든 관리·검수 권한을 보유하는 통합 역할이다. UI에서는 '검수자'로 호칭하며, 관리 화면 URL은 `/manage/*`로 통일한다.

## 4. 상세 요구사항

### 4.3 SFR-07 | 생성형 AI를 활용한 데이터 증강 기능 자동화 개발

**정의**: 생성형 AI를 활용해 학습데이터 증강

**세부 요구사항**

① 데이터 증강 자동화
- 관제지원시스템 생성형 AI를 활용하여 날씨·계절·시간 변화가 적용된 학습데이터 자동 생성 (WINTER / NIGHT / RAIN / RESOLUTION 4종)

② 라벨 무결성 유지
- 증강 전후 라벨을 보존하여 라벨 무결성 유지

③ 증강 결과 확인 및 선택
- 증강 완료 데이터를 사용자에게 제시하고 학습데이터 활용 여부 선택 기능 개발
- 증강 결과 항목별 상태값 운영: **`PENDING` / `ACCEPTED` / `REJECTED`**
- `REJECTED` 선택 시 **거부 사유** 입력 필드 제공 (자유 텍스트, 작업자/검수자 식별 + 일시 기록)
- `ACCEPTED` 항목만 학습데이터셋(NAS 저장 대상)에 포함 (외부제공 시스템과의 동기화는 외부 잡 책임)
- 동일 원본 이미지 1건에 증강 4종(WINTER/NIGHT/RAIN/RESOLUTION) 결과를 묶어 비교·선택 UI 제공
- 활용 여부 결정 이력은 라벨 히스토리와 별도 테이블로 관리하여 회수·재검토 가능

④ 증강 요청 — 검수 완료 가드 + 리스트 재구성 (V1.x 후속)
- 증강 요청 화면은 **카드 그리드 → 테이블 리스트**로 재구성한다 (영상 수백 건 검색·필터 용이).
- **검수 완료(`taskStatus === 'COMPLETED'`) 영상만 노출**한다 — 미승인 영상은 목록 자체에서 제외되며, 핸들러도 가드한다 (전부 미승인 → 422, 일부 미승인 → 승인 영상만 처리).
- 컬럼 구성: 체크박스 / 영상명·CCTV / 이벤트(EventTypeBadge) / 녹화일 / 검수 완료 일시.
- 다중 선택 + 헤더 indeterminate + "[N개 영상 증강 요청]" 액션바.
- 검색(영상명/CCTV/id) + 이벤트 필터 + 100건 client-side 페이징 + URL `q`/`eventType` 동기화.

**산출물**: 서비스/기능 아키텍처 구성도, 공정 산출물, 추진계획서, 결과서

### 4.4 SFR-08 | 학습데이터 저작도구 고도화 기능 구현 [핵심]

**정의**: 학습데이터 제작 편의성 및 효율성 증대를 위한 저작도구 추가기능 개발

#### 4.4.1 인증 및 진입 방식

저작도구는 내부·외부 채널 모두 별도 로그인·회원가입 없이, 단일 세션 체계(공통 JWT 발급 서버)를 통해 관제서버 및 포털 서버가 발급한 토큰을 인계받아 진입한다.

**세션 체계**
- 관제서버(내부)와 포털 서버(외부) 모두 **동일한 JWT 발급 서버** 사용
- 저작도구는 채널 구분 없이 단일 토큰 검증 로직으로 처리
- 토큰 내 역할(role) 클레임으로 내부/외부 채널 및 권한 분기

**DB 연동 체계**
- 내부 채널(관제서버 연동): 저작도구는 **관제서버 DB를 공유** 사용
- 외부 채널(포털 연동): 저작도구는 **포털 DB를 공유** 사용
- 저작도구 전용 독립 DB 인스턴스 없음
- 저작도구 관련 테이블은 각 DB 내 별도 스키마(예: `authoring`)로 구분 관리

**내부 채널 (관제지원시스템)**
- 관제서버 세션 토큰을 수신하여 사용자 인증 처리
- 세션 만료 시 관제서버 로그인 페이지로 리다이렉트

**외부 채널 (포털 진입 모드)**
- 포털 서버 세션 토큰을 수신하여 외부 사용자 식별
- 저작도구 내 회원가입·로그인 UI 미제공
- 세션 만료 시 포털 서버 로그인 페이지로 리다이렉트
- 기여도, 일일 사용량 등 사용자 권한 정보는 포털 서버로부터 수신

#### 4.4.2 영상 유입 및 전처리

관제서버는 라벨링 대상 판별까지 담당하고, 배치 처리(프레임 추출 + 오토라벨링)는 저작도구가 수행한다.

**관제서버 담당 (저작도구 외부)**
- 지자체 CCTV로부터 영상 수신
- 라벨링 필요 여부 자동 판별
- 라벨링 대상 영상 목록을 저작도구에 전달

**저작도구 담당**

*배치 파이프라인 (백그라운드 서버 프로세스 — 세션·인증 불필요)*
- 관제서버로부터 수신한 라벨링 대상 영상을 자동 처리: **1건/분**
- 처리 단계 순서 (V1.x):
  1. **VLM 시계열 메타** — 외부 시스템 호출. 외부 시스템에서 시계열 메타·객체 자연어 설명 등을 생성하고, 저작도구는 단계 진행 상태(진행 중/완료/실패)와 메타 검토 UI(SCR-AUTO-002)만 보유
  2. **FFmpeg 프레임 추출** (1프레임/분)
  3. **YOLO 기반 오토라벨링** 자동 수행
  4. **SAM2 세그멘테이션** 자동 수행
- 비식별화 처리는 본 파이프라인에서 **자동 호출하지 않는다 (V1.x 정책)**. 비식별은 §4.4.6 학습데이터 내보내기에서 옵션으로 호출되며, 옵션 ON일 때 비식별 서버 API를 통해 마스킹 후 포털로 전송한다.
- 익명정보 영상의 비식별 호출 생략 정책은 옵션 호출 단계에서도 동일하게 적용된다 (영상 메타 `PRVC_TYPE_CD`가 `ANONY`인 경우 비식별 호출 생략).

*사용자 화면 (세션 인계 후 진입)*
- 배치 완료 영상 목록을 진입점으로 제공
- 배치 처리 진행 상태 모니터링 화면 제공
- 각 영상의 오토라벨링 결과 및 메타데이터 확인·수정 기능

#### 4.4.3 작업 배정

- 검수자는 작업 목록(`/task`)에서 작업자를 지정하여 배정 (배정 진입점은 영상 목록이 아닌 **작업 목록**으로 일원화 — V1.x)
- 작업 목록은 **처리 완료된 영상을 기반(left-join task)** 으로 노출한다 (V1.x 후속). 처리 완료(STAGES 모두 DONE) 영상은 task 유무와 무관하게 모두 행으로 표시되며, task가 없는 영상은 작업자 **'미배정'** / 검수자 **'미등록'** 라벨로 노출되고 배정 대상으로 선택 가능하다.
- 작업자 현재 진행 작업 수 조회 후 배정 가능
- 검수자는 배정 이력 조회 및 재배정 권한도 함께 보유
- 상태 필터에 **`UNASSIGNED`(미배정)** 옵션을 제공한다 (V1.x 후속). 이벤트 컬럼은 다른 화면과 동일한 EventTypeBadge 색상 매핑을 따른다.
- **메뉴 라벨 정정 (V1.x 후속)**: 검수 메뉴 라벨은 '검수 대기' → **'검수 목록'** 으로 변경되고, 메뉴 그룹은 '검수' → **'작업'** 으로 이동되어 사이드바에서 작업 목록과 동일 그룹에 노출된다.

**다중 일괄 배정 (V1.x)**

- 작업 목록에 **이벤트 유형 필터**, 행 단위 **체크박스**, 헤더 단위 **현재 페이지 전체 선택**(indeterminate 상태 포함) 컴포넌트를 제공한다.
- 1개 이상의 영상이 선택되면 표 위에 "{N}개 선택됨 / [N개 일괄 배정]" 액션바가 노출된다.
- 일괄 배정 모달은 작업자(필수) / 검수자(REVIEWER 본인 자동 지정) 만 받으며, 저장 시 단일 트랜잭션으로 모든 task의 배정을 갱신한다. 작업자 기본값은 **현재 로그인 사용자(`currentUser.id`)** 로 자동 설정된다(V1.x 후속). 사용자가 dropdown으로 변경한 값은 그대로 유지된다.
- 일괄 배정 API는 **멱등 처리**된다 — 이미 동일 배정인 task는 변경되지 않고 `skipped` 카운트에 포함되어, 동일 요청을 여러 번 호출해도 최종 상태가 동일하다. **task가 없는 영상은 신규 task가 생성**되며(V1.x 후속 — 영상-기반 데이터 소스와의 정합), 단일 배정도 bulk 모드 1건 호출로 통합 처리된다.
- 일괄 배정 응답: `{ assigned, skipped, total, tasks }` 형태. 토스트는 `"{N}건 일괄 배정 완료"` 형식.

#### 4.4.6 학습데이터 내보내기 (포털 전송 — V1.x)

- 내보내기는 **포털 서버 단일 채널**로 전송한다 (V1.x — 기존 NAS 저장 옵션 제거).
- 화면 메뉴 라벨은 "내보내기" 유지, 화면 부제는 "포털 서버로 학습데이터셋을 전송합니다".
- 포털 endpoint: `https://portal.example.com/api/v1/datasets/import` (환경별 구성).
- 포맷: `COCO` / `YOLO` / `CVAT` / `PASCAL_VOC`.
- 옵션:
  - **라벨 포함** / **이미지 포함** (기본 ON)
  - **비식별 처리** — 기본 **ON**. 체크 해제 시 원본 그대로 전송. ON일 때 내보내기 잡이 비식별 서버 API 호출 후 마스킹된 산출물을 포털로 전송한다.
- 액션 버튼 라벨: **[포털 전송 실행]**.
- 토스트: `"{N}건 포털 전송 시작됨"` (성공) / `"포털 전송 실패"` (실패).
- 내보내기 요청 body 필수 필드: `format`, `videoIds`, `options`, `deidentify`, `targetServer: 'PORTAL'`. **`forceReexport`** (boolean, 기본 false)는 V1.x 후속 추가 옵션으로, true이면 이미 전송된 영상에 대해서도 강제 재전송을 허용한다.
- 내보내기 산출물의 외부제공(데이터마트 등록·배포·다운로드)은 외부제공 시스템이 담당.
- LabelEditor 저장·검수 승인은 그대로 동작하며, 외부제공 시스템과의 동기화는 시스템 간 별도 잡으로 처리.

**내보내기 — 검수 완료 가드 (V1.x 후속)**

- 내보내기는 **검수 승인된 영상만 가능**하다. 영상의 `taskStatus === 'COMPLETED'` (검수 승인 상태) 인 영상만 대상 목록에 노출되며, 미승인 영상은 화면에 표시되지 않는다.
- 핸들러는 0번째 가드로 검수 미완료 영상을 차단한다 (`forceReexport`와 무관). 응답 객체에 `blockedNotApproved` 카운트 + 안내 문구 "내보내기는 검수 완료(승인)된 영상만 가능합니다"를 포함한다.
- 빈 상태 메시지: "검수 완료된 영상이 없습니다" (검수 완료 영상 0건일 때).

**내보내기 — 이력 상태 추적 (V1.x 후속)**

- 영상은 전송 이력 상태를 영구 보존한다 — `exportStatus` ∈ `{ NEVER, EXPORTED, FAILED }`, `exportedAt` (DATETIME, NULL 허용), `lastExportFailureReason` (VARCHAR, NULL 허용).
- 이미 내보낸(`EXPORTED`) 영상은 기본 disabled 처리되며, 화면의 **"이미 내보낸 영상 포함"** 토글로 강제 재전송이 가능하다 (요청 시 `forceReexport: true`).
- 영상의 `exportStatus === 'FAILED'` 상태는 다음 시도에 자연스럽게 재선택 가능하다(`forceReexport`와 무관) — 시도가 실패한 영상은 다시 미전송 후보로 노출된다.
- 응답 객체에 `failedDueDeident`(비식별 실패 카운트), `skippedAlreadyExported`(이미 전송된 영상 스킵 카운트), `blockedNotApproved`(검수 미완료 차단 카운트)를 포함한다.

**내보내기 — 비식별 정책 정정 (V1.x 후속)**

- 비식별은 **매 전송 시도마다 실행되는 단발 행위**이며, 영상이 영구적으로 '비식별 실패' 영구 속성을 가지지 않는다. 영상의 `deidentifyStatus` 같은 영구 필드는 두지 않는다.
- 매 전송 시도마다 비식별이 실행되고, 실패 시 그 시도의 사유로만 영상의 `lastExportFailureReason='비식별 실패'`가 기록된다. 영상의 `exportStatus = 'FAILED'`는 다음 시도에 재선택 가능하다.
- 응답 토스트: "비식별 실패 N건 (다시 시도 가능)" 형식.
- mock 시뮬레이션 플래그(`DEIDENT_FAIL_SIMULATION`)는 외부 API에 노출되지 않는다 — 핸들러 내부에서만 참조한다.

**내보내기 — 검색·필터·페이징 (V1.x 후속)**

- 영상 선택 영역은 영상 수백 건을 다루기 위해 다음 컴포넌트를 제공한다:
  - **검색 input** (영상명 / CCTV / id) + URL `q` 동기화
  - **이벤트 필터** dropdown + URL `eventType` 동기화
  - **전송 상태 필터** (전체 / 미전송 / 이미 전송 / 전송 실패) + URL `exportFilter` 동기화
  - **100건 client-side 페이징** (Pagination 컴포넌트 재사용)
  - 선택 카운트 헤더, indeterminate 헤더 체크박스
- 빈 상태 3분기: 검수완료 0건 / 필터 결과 0건 / 표시 0건

#### 4.4.7 보류 항목

### 4.5 SFR-09 | 영상 및 이미지 개인정보 비식별 처리 기능 개발

**정의**: 개인정보보호를 위해 영상 및 이미지 내 포함된 개인정보 비식별 처리 기능 구현

V1.x에서 비식별 처리는 **배치 파이프라인의 자동 단계가 아닌, 학습데이터 내보내기(포털 전송) 시의 옵션 호출**로 운영된다. 별도의 비식별 결과 검토 화면(SCR-DEIDENT-001/002)은 두지 않는다 (V1.x — 기존 화면 제거). 단, 영상 메타정보의 개인정보 유형이 익명정보인 경우 비식별 서버 호출을 생략한다.

**세부 요구사항**

① 내보내기 옵션 기반 조건부 비식별 처리 (V1.x)
- 트리거: 학습데이터 내보내기(포털 전송) 시 사용자가 **"비식별 처리"** 옵션을 선택할 때 (기본 ON)
- 처리 조건: 영상 메타정보의 개인정보 유형이 **개인정보** 또는 **가명정보**인 경우에만 비식별 서버 API 호출
- 익명정보로 분류된 영상은 비식별 서버 호출 없이 원본만 전송
- 발주기관 제공 비식별화 솔루션 API 연동 (내보내기 잡에서 자동 호출)
- 원본 이미지와 비식별 처리 이미지는 NAS 저장 시점이 아닌 **포털 전송 시점에 마스킹 처리**된다.

② 비식별 처리 이력관리
- 비식별 처리 여부(옵션 ON/OFF), 처리 일시, 개인정보 유형을 내보내기 잡 단위로 이력 관리
- 별도의 비식별 결과 비교 UI는 V1.x에서 제거 (SCR-DEIDENT-001/002)

③ 개인정보 유형별 공개대상 분류체계
- 개인정보 / 가명정보 / 익명정보 분류 체계 구축
- 분류는 영상 메타정보(관제서버에서 전달)를 기준으로 적용

④ 개인정보 보호대책
- 영상 암호화 저장, 텍스트 개인정보 필터

비식별 결과 표시 항목 정리: "블러 박스 수(detected count)"는 **미사용** — 비식별 서버 응답에 표준 컬럼 없음. 내보내기 잡 단위로 비식별 옵션 호출 여부(Y/N)와 처리 일시만 표기한다.

**산출물**: 서비스/기능 아키텍처 구성도, 공정 산출물, 추진계획서, 결과서

### 4.8 SFR-15 | AI 영상학습 사용자 포털 구축

**정의**: 외부 사용자가 저작도구를 체험할 수 있는 테스트용 포털 서비스 구축

**포털 사용자 정책**
- 포털은 실제 학습데이터 구축이 아닌 **체험·테스트 목적**으로 제공
- 기여도 점수 없음
- 저작도구 자체 회원가입·로그인 없음 — 포털 서버 세션 인계
- 포털 사용자의 다운로드 권한 부여·기한 관리·다운로드 UI는 **포털 자체 책임**
- 저작도구는 다운로드 카드·D-day 배지·다운로드 기한 표시·만료 처리 UI를 제공하지 않음
- 영상 단위 다운로드 기한(`DOWNLOAD_DDLN_DT`) 등의 정책은 포털 영역 정책

**세부 요구사항**

① 포털 진입 및 인증
- 포털 서버 세션을 인계받아 저작도구 포털 진입 모드 활성화
- 회원가입·로그인·마이페이지는 포털 서버 담당, 저작도구 미구현

② 저작도구 체험 기능 제공
- 사용자 보유 이미지·영상 업로드 → 간편 라벨링 도구 사용 (웹 기반)
- 저작도구 핵심 기능(바운딩박스·폴리곤·세그멘테이션) 체험 가능
- **오토라벨링(YOLO + SAM2) 체험 가능**
- VLM 메타데이터·버전관리·검수 워크플로우 등은 미제공

③ 데이터 다운로드 — 포털 책임으로 이관
- 다운로드 권한·기한·UI 모두 **포털 자체 시스템에서 관리**
- 저작도구는 라벨링 결과 산출물을 포털과의 약속된 저장 위치(또는 API)에 제공만 하고, 다운로드 인터페이스는 노출하지 않음
- 영상 단위 다운로드 기한·D-day 표시·만료 알림 등의 정책은 포털 시스템 내부 규약

④ 포털 공통 환경

### 4.11 QUR-03 | 학습데이터 품질 요구사항

**정의**: 학습데이터 품질에 관한 요구사항

> **저작도구 연관 사유**: 저작도구는 학습데이터 "제작" 단계의 핵심 도구로, QUR-03의 "수집→제작→검수" 전 단계 품질 관리 기준이 직접 적용된다.

**세부 요구사항**

① 단계별 품질 관리 기준 수립
- 수집 → 전처리(관제서버 배치) → 라벨 수정(저작도구) → 검수 → 승인 각 단계별 기준 수립

② 작업자별 품질 관리
- 작업자 반려율, 라벨 수정 빈도 등 통계 관리
- 검수자 대시보드에서 작업자별 품질 지표 확인

검수자가 작업자 배정 주체이므로, 배정 이력·검수 이력 모두 검수자 단위로 추적·관리한다.

③ 검수 완료 영상만 후속 잡 가능 (V1.x 후속)

품질 보장을 위해 검수 승인된 영상만 후속 잡(내보내기 / 증강 요청)의 대상이 된다. 미승인 영상은 화면 목록 자체에서 제외되며, 백엔드 핸들러도 0번째 가드로 차단한다. 응답 객체에 `blockedNotApproved` 카운트를 포함한다.

**산출물**: 품질관리계획(사업수행계획서), 공정 산출물

### 5.1 내부 채널 (관제지원시스템)

```
[관제서버]
  │  ① CCTV 영상 수신
  │  ② 라벨링 필요 여부 판별
  │  ③ 라벨링 대상 영상 목록 → 저작도구에 전달
  ↓
[저작도구 — 배치 파이프라인] ← 세션 없이 서버 자동 실행
  │  ④ 라벨링 대상 영상 배치 처리 (1건/분, 인증 불필요)
  │      └ VLM 시계열 메타 (외부 시스템 호출, 단계 진행 표시만)
  │      └ FFmpeg 프레임 추출 (1프레임/분)
  │      └ YOLO 오토라벨링 자동 수행
  │      └ SAM2 세그멘테이션 자동 수행
  │      (V1.x — 비식별 처리는 단계에서 제거되어 내보내기 옵션으로 호출됨)
  ↓
  [세션 인계 (JWT/SSO)] ← 사용자가 화면 진입 시
  ↓
[저작도구 — 사용자 화면]
  │  ⑤ 배치 완료 영상 목록 진입점 제공
  │
  ├── 검수자: 작업 목록에서 처리 완료 영상 다중 선택 → 일괄 배정 (V1.x — 멱등 처리)
  │
  └── 작업자: 배정된 영상 선택 → 라벨링 도구 진입
                │
                ├── 오토라벨링 결과 검토 (관제서버 배치 결과 확인)
                ├── 라벨 수정·추가·삭제
                ├── 시계열 메타데이터 검토·수정
                └── 저장 → Gitea 자동 커밋 (버전 생성)
                          ↓
              [검수 제출]
                ↓
[검수자: 라벨 검수]
  ├── 승인 → 데이터셋 포함 확정
  └── 반려 → 작업자 재작업 → 재제출
                ↓ (승인 후)
[데이터 증강 (선택)]
  ↓
[내보내기 → 포털 서버 전송]   ← V1.x — 비식별 처리 옵션 ON일 때 마스킹 후 전송. 마트 등록은 외부제공 시스템 책임
```

## 5A. 운영 정책 부록

본 절은 요구사항 본문은 보존한 상태에서, mock 데이터 및 DB 설계서 정합에 맞춰 도출된 운영 정책을 정리한다. SFR 원문은 그대로이며, 화면·도메인 구체화 정책만 추가된다.

### 5A.1 도메인 카탈로그 — 이벤트 6종 확정

저작도구가 다루는 이벤트 카탈로그는 **6종**으로 확정한다. 이는 SFR-08 라벨링 분류 마스터의 공통 기준이다. 데이터마트 메타데이터 분석은 외부제공 시스템 영역으로 이관된다.

| 코드 | 이벤트명 | 비고 |
|------|---------|------|
| FALL | 쓰러짐 | 자체 AI 모델: 쓰러짐 탐지 |
| VIOLENCE | 폭력 | 자체 AI 모델: 폭력 감지 |
| TRAFFIC_ACCIDENT | 교통사고 | 자체 AI 모델: 교통사고 감지 |
| ABNORMAL_BEHAVIOR | 이상행동(유괴) | 자체 AI 모델: 이상상황 탐지 |
| FLOOD | 침수 | 자체 AI 모델: 침수 탐지 |
| WILDFIRE | 산불 | 자체 AI 모델: 산불 감지 |

이벤트는 위 6종으로 고정하며, 신규 추가 시 별도 마스터 변경 절차가 필요하다.

### 5A.2 메뉴/IA 구성 (V1.x)

사이드바 LNB 그룹 명칭 및 경로는 UI/UX 설계서와 정합한다.

| 항목 | 값 | 비고 |
|------|------|------|
| 그룹명 | **"영상"** | 사용자 인지 명확화 |
| 경로 prefix | **`/video/*`** | 라우터 prefix |
| 메뉴: 영상 처리 현황 | `/video/completed` | V1.x — 기존 "영상 목록"에서 라벨 변경. 표 내부에 "처리 단계" 컬럼 통합 |
| 메뉴: 비식별 결과 | (V1.x 제거) | 비식별 자동 단계 → 내보내기 옵션 변경에 따라 메뉴 제거 |
| 메뉴: 배경영상 | (V1.x 제거) | 영상 합성 본체 외부 이관(V1.8) — 행 액션 / 결과 페이지 모두 제거 |
| 메뉴: 처리 현황 모니터링 | (V1.x 제거) | 영상 처리 현황 표의 "처리 단계" 컬럼으로 통합 |

**영상 행 액션 정리 (V1.x)**: 영상 처리 현황의 행 액션은 **[상세 ▶]** 단일 버튼만 남긴다 (기존 [배정] / [배경영상] 제거). 작업 배정은 작업 목록(`/task`)으로 진입점이 일원화된다.

### 5A.3 권한 정책

| 항목 | 정책 |
|------|------|
| REVIEWER (관리·검수 통합 역할) | 사용자 관리, 시스템 설정, 작업자 배정·재배정, 배정 이력 조회, 검수 승인/반려, 검수 데이터 조회·관리 |
| 대시보드 KPI / 내 작업 현황 카드 | **WORKER 전용** — REVIEWER 화면에는 미노출 |
| WORKER | 라벨 수정·검수 제출 |
| PORTAL_USER | 본인 업로드 데이터 한정 라벨링 체험 |

### 5A.4 시스템 설정 정책 (3섹션 분리)

시스템 설정 화면을 책임 범위별로 3개 섹션으로 분리한다.

| 섹션 | 항목 | DB 영속화 | 비고 |
|------|------|----------|------|
| 편집 가능 | FFmpeg `threads`, FFmpeg `outputFps`, 배치 `interval`, 배치 `concurrency` | **O** (`LS_SYSTEM_CONFIG`) | 4개 키만 저작도구에서 직접 관리 |
| read-only | 외부 연동 상태 (관제/포털/비식별/Gitea/AI Server) | X | 실시간 actuator/health 조회 |
| placeholder | 시스템 초기화 / 배치 큐 초기화 / 캐시 삭제 등 위험 액션 | X | 별도 운영 도구로 이관 예정. 화면에서는 비활성 안내만 |

**FFmpeg 출력 해상도(`FFMPEG_RESOLUTION`)는 미관리** — 학습데이터 좌표 정밀도 보존을 위해 원본 해상도를 그대로 사용한다. CCTV별 해상도가 필요한 경우 `MNG_RESOURCE_CCTV.RESOLUTION` 마스터를 참조한다.

### 5A.5 통계 정책

본 도구는 **지속 데이터 수집 시스템**이며, "10만장 / 5,000건 목표 채우면 종료" 모델이 아니다. 따라서 화면에서 목표 대비 N% 형태의 비율 표시는 사용하지 않는다.

| 항목 | 정책 |
|------|------|
| 대시보드 OverallStats | **누적 카운트만 표시** |
| SFR-16/17 산출물 목표 (10만장 / 5,000건) | **사업 KPI로만 보존**, 화면 미노출 |
| 이벤트별 분포(카운팅) | **대시보드/통계 화면에 노출** (5A.1 카탈로그 6종) |

### 5A.6 도메인 정리 (DB 정합)

다음 항목은 DB 컬럼 부재 또는 운영 부담으로 본 범위에서 제외된다. SFR 본문에는 영향 없음.

| 도메인 | 항목 | 사유 |
|--------|------|------|
| Task (작업) | priority / memo / deadline | DB 컬럼 없음. 작업 배정은 영상 단위 + REVIEWER 배정만 단순 모델 |
| Issue (검수 이슈) | 반려 우선순위 / 자동 재배정 | 미사용 |
| Deidentify (비식별 결과) | 블러 박스 수 / 결과 비교 화면 | (V1.x) 비식별 자동 단계 제거 — 내보내기 옵션 호출만 남김. 별도 결과 검토 UI 미제공 |
| Version (버전관리) | 커밋 통계 (added/modified/removed) | Gitea API 매번 조회 부담. 커밋 해시·일시만 보존 |
| User (사용자) | avatarColor | DB 컬럼 없음 → FE에서 `user.id` 해시로 결정 |
| WorkerStat | modifyRate (수정률) | 측정 컬럼 없음 |
| Video (영상) | frameCount / thumbnailUrl | SFR-08 원문 매핑 없음. 자체 추출은 보류 (4.4.7 참조) |
| Video (영상) | deidentified 플래그 | (V1.x) DTO에서 제거 — 비식별은 매 전송 시도마다 실행되는 단발 행위이며 영상이 영구적인 '비식별 실패' 속성을 가지지 않는다(V1.x 후속 정정). 실패는 시도별 사유로 `lastExportFailureReason`에 기록될 뿐이며, 영구 컬럼/플래그는 두지 않는다 |
| BatchStage | DEIDENTIFY | (V1.x) stage 코드에서 제거. 처리 단계는 `VLM → FRAME_EXTRACT → YOLO → SAM2` 4단계로 운영 |

**도메인 추가 항목 (V1.x)**

| 도메인 | 항목 | 설명 |
|--------|------|------|
| Issue (검수 이슈) | **좌표(x, y)** | 캔버스 원본 픽셀 기준. optional. mock V1.x부터 지원. `LS_DATA_ISSUE.X_COORD/Y_COORD` 컬럼 추가. 검수 마킹 좌표를 영구 저장하여 결과보기에서 마커 그대로 표시 |
| Task (작업) | **bulk-assign API** | `POST /api/v1/tasks/bulk-assign` 엔드포인트. 멱등 처리. 응답 `{ assigned, skipped, total, tasks }` |
| Export (내보내기) | **deidentify (옵션)** | `ExportRequest.deidentify` (boolean, 기본 true). 포털 전송 시 비식별 마스킹 여부 |
| Export (내보내기) | **targetServer** | `ExportRequest.targetServer` 현재 `'PORTAL'`만 지원 |

DB 컬럼: `EXPORT_STATUS_CD` / `LAST_EXPORTED_AT` / `LAST_EXPORT_FAIL_REASON` (DB 설계서 §4.8 참조) |

| Augment (증강) | **검수 완료 가드 (V1.x 후속)** | 증강 요청은 `taskStatus === 'COMPLETED'` 영상만 가능. 핸들러 가드: 전부 미승인 → 422, 일부 미승인 → 승인 영상만 처리 |
