# 생성형 영상 비식별 제외 — 알림 및 확인 요청

> 작성: 2026-09-14 | 저작도구 측 → 관제지원 측
> 대상: 관제가 `LS_DATA_INGEST` 에 넣는 `SRC_TYPE` 값 · 관제가 조회하는 `V_COMPLETED_VIDEO`
> 관련: `docs/관제-저작도구-데이터연동-규격서-20260805.md` §3-2(`SRC_TYPE` 허용값) · §5-1(`V_COMPLETED_VIDEO`)

## 배경

생성형 AI 로 만든 영상(`SRC_TYPE='GENERATED'`)에는 실제 사람이나 번호판이 찍혀 있지 않아
비식별이 필요 없습니다. 지금까지 저작도구는 출처와 관계없이 모든 영상을 외부 비식별 솔루션에
맡겨 왔는데, 앞으로는 **생성형 영상을 외부 비식별 솔루션에 맡기지 않습니다.**

## 바뀌는 것

| 항목 | 지금 | 바뀐 뒤 (`SRC_TYPE='GENERATED'` 영상) |
|---|---|---|
| 외부 비식별 솔루션 위탁 | 함 | **하지 않음** |
| 비식별 영상 파일 | 솔루션이 만든 마스킹 영상 | **원본 영상을 비식별 영상 자리에 복사한 파일**(파일명은 원본과 같음) |
| `V_COMPLETED_VIDEO.DE_IDNTF_YN` | `Y` = 비식별 완료 | `Y` (그대로) |
| `V_COMPLETED_VIDEO.DE_IDNTF_FILE_PATH_NM` | 마스킹 영상 경로 | **복사본 경로** |
| 마킹·검수·산출물·완료 통지 | — | 다른 영상과 **같음** |

- 뷰의 컬럼·계약은 **바뀌지 않습니다.** 컬럼 추가·삭제·이름 변경이 없습니다.
- 그 밖의 출처유형(`ORIGINAL` · `RELAY` · `USER_ULD` 등)은 **지금과 똑같이** 외부 비식별을 거칩니다.
- 이미 처리된 영상은 소급해서 바뀌지 않습니다.

## 확인 요청 1 — `DE_IDNTF_YN='Y'` 의 뜻이 넓어집니다

`DE_IDNTF_YN='Y'` 가 이제 **「비식별 완료」 또는 「비식별이 필요 없어 제외」** 를 뜻합니다.
생성형 영상의 `DE_IDNTF_FILE_PATH_NM` 은 마스킹된 영상이 아니라 원본의 사본입니다.

관제 쪽에서 `DE_IDNTF_YN='Y'` 를 「마스킹을 거친 영상」으로 해석해 쓰는 곳(예: 외부 공개·포털 전달
판단)이 있다면 알려 주십시오. 두 경우의 구분은 같은 뷰의 **`GEN_AI_YN`** 으로 할 수 있습니다
(`SRC_TYPE` 이 `GENERATED` 이면 `Y`).

## 확인 요청 2 — `SRC_TYPE='GENERATED'` 의 정확성

이 판단은 전적으로 관제가 넣어 주는 `SRC_TYPE` 값에 기댑니다. **실제 CCTV 영상이 `GENERATED` 로
잘못 들어오면 마스킹 없이 처리됩니다.** 저작도구는 검수 단계에서 검수자가 발견해 비식별 누락
신고로 회수하지만, 검수가 승인된 뒤에는 회수할 수 없습니다.

`SRC_TYPE='GENERATED'` 는 **생성형 AI 로 만든 영상에만** 넣어 주시기를 요청드립니다.
그렇게 운영하실 수 있는지 회신 부탁드립니다.

## 회신 부탁드리는 내용

1. 관제 쪽에 `DE_IDNTF_YN='Y'` 를 마스킹 여부로 해석하는 로직이 있는지 (있다면 `GEN_AI_YN` 병용 가능 여부)
2. `SRC_TYPE='GENERATED'` 를 생성형 AI 영상에만 넣는 운영이 가능한지

## 회신 (2026-09-14, 관제지원 측)

1. 비식별 관련 작업은 전부 저작도구로 이관되어 관제에서 작업하는 내용이 없습니다. 확인 요청 1은 관제와 무관합니다.
2. 생성형 AI 서버로부터 생성된 작업은 기존에도 `SRC_TYPE='GENERATED'` 로 전달하고 있습니다.
