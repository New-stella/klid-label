>

> 테이블 9종을 저작도구가 전부 사용 중단했으므로(V165~V169), **여기 적힌 변경 금지 요청은 모두 철회**합니다.

> 신규 협의 항목(관제가 채워 보내야 하는 컬럼 등)이 거기 있습니다.

> 특히 "저작도구가 `ddl-auto=validate` 로 매핑한다"는 전제는 더 이상 성립하지 않습니다.

> 목적: 관제지원시스템 v2 전환 시 공유 테이블 수정 과정에서 **저작도구(klid-label)가 운영 런타임에 의존하고 있어 변경하면 안 되는(= 사전협의 필수)** 테이블·컬럼을 명시한다.
> 기준: **실제 운영(production) 런타임 경로만** 본문에 둔다. dev·배포타임 전용 시드 도구는 §기타로 분리(운영 BE 의존 아님).
> 근거: 저작도구 백엔드의 실제 JPA 매핑(`@Table`/`@Column`/복합키) + native SQL + 호출 컨트롤러·프로파일 정적 분석.

## 변경 규칙 (왜 보호해야 하는가)

저작도구는 관제 소유 공유테이블(`MNG_*`)을 Hibernate `ddl-auto=validate`로 매핑한다.

| 관제팀이 하려는 변경 | 저작도구 영향 |
|------|------|
| 컬럼 **추가** | ✅ 안전 (validate는 여분 컬럼 무시) |
| **매핑된 컬럼** drop / rename / 타입변경 | ⛔ 저작도구 **기동 불가** (validate 실패) |
| 테이블 drop / rename | ⛔ 기동 불가 |
| **PK / 복합키 구조** 변경 | ⛔ 치명 (식별·조인·라벨 도출 깨짐) |
| 저작도구가 **WRITE하는 테이블** 스키마 변경 | ⛔ 기동 불가 + UPDATE/DELETE/INSERT문 동반 실패 |

> ⚠️ native 조인(`MNG_RESOURCE_CCTV`)은 validate가 아닌 **런타임 SQL** 의존이라, 컬럼명을 바꾸면 기동은 되고 조회 시점에 터진다(더 늦게 발견됨).

## 핵심 결론 (먼저 읽으세요)

**(2026-06-29 역할 분리 리팩토링 반영)** 관제팀이 v2로 공유 DB(klid_system)를 바꿀 때, **저작도구 운영 런타임이 관제 공유 테이블에 데이터를 쓰는(write) 경우는 이제 0건**이다. 모든 의존 테이블은 운영에서 **READ-ONLY**(validate + 조회)이며, 컬럼·PK **스키마만** 보호하면 된다.

- 과거 쓰기 대상이던 `MNG_ACCT_USER`(useYn) / `MNG_ACCT_USER_AUTHRT`(역할)는 **저작도구 자체 `LS_USER_ROLE` 테이블로 역할을 분리**하면서 쓰기가 제거됐다(§2). `MNG_ACCT_USER`는 READ만.
- **(2026-08 갱신, V165)** 참조가 0 이 된 `MNG_ACCT_USER_AUTHRT`·`MNG_ACCT_AUTHRT` 2종은 **저작도구 스키마에서 DROP 됐다**. 이 둘은 이름만 `MNG_` 접두일 뿐 **저작도구가 자기 스키마에 직접 만든 스텁**(관제 실DB 의 공유 테이블 아님)이라 관제팀 승인 대상이 아니며, 관제 연동 계약(데이터마트 뷰·완료/수정 통지)에도 영향이 없다. **관제팀이 보호할 공유 테이블은 9개가 아니라 7개**(아래 표의 취소선 제외)다.
- 따라서 가장 신경 쓸 것은 **복합키 PK 구조(§3)** 와 **`MNG_RESOURCE_CCTV` native 조인키(§4)** 의 스키마 보호다.

## 2. ✅ 관제 계정 테이블 — 역할 분리 완료(이제 완전 READ 또는 미사용)

> **(2026-06-29 갱신)** 과거 저작도구가 `MNG_ACCT_USER`(useYn UPDATE) / `MNG_ACCT_USER_AUTHRT`(역할 DELETE+INSERT)에 쓰던 구조를 **역할 분리 리팩토링으로 제거**했다. 이유: 실제 관제 역할 마스터(MNG_ACCT_AUTHRT)에는 SYSTEM_ADMIN/PLTF_MANAGER/LEARN_MANAGER만 있고 REVIEWER/WORKER가 없어, 저작도구가 외래 코드를 관제 계정 권한 테이블에 INSERT하던 정합성 결함이 있었다.

### ① MNG_ACCT_USER — 이제 완전 READ
- **용도**: 관제 계정/사용자 마스터. 저작도구는 **라벨링 작업자(WORKER)·검수자(REVIEWER) 사용자 목록을 조회(READ)** 해 작업 배정 대상으로만 쓴다.
- **변경**: useYn 활성/비활성 토글 기능 제거(관제 책임 이관) → 저작도구는 이 테이블에 **더 이상 쓰지 않음**(엔티티 `@Immutable`). useYn은 작업자 목록 필터로 **읽기만** 한다.
- 매핑(존재 필수) 컬럼(READ): `USER_NO`(PK), `USER_ID`, `USER_NM`, `USER_EMAIL`, `USE_YN`, `REG_DT`, `UPD_DT`
- v2에서 이 컬럼/PK 변경 시 → 저작도구 사용자 조회·작업자 목록 깨짐(쓰기 충돌은 더 이상 없음).

### ② ~~MNG_ACCT_USER_AUTHRT~~ / ~~MNG_ACCT_AUTHRT~~ — **삭제 완료(V165, 2026-08)**
- **변경**: 저작도구 라벨링 역할(REVIEWER/WORKER/PORTAL_USER)은 저작도구 소유 신규 테이블 **`LS_USER_ROLE`(USER_NO→ROLE_CD)** 로 이전. 역할 부여/변경/조회·인가 해석이 모두 LS_USER_ROLE 기준으로 동작한다. 이 두 테이블에 대한 저작도구의 INSERT/DELETE/조회는 **0건**이 된 뒤(엔티티·리포지토리 삭제), **V165 가 저작도구 스키마에서 테이블 자체를 DROP** 했다(엔티티 `MngAcctAuthrt`·dev 시드·테스트 픽스처 동반 제거).
- **관제 영향 없음**: 이 둘은 이름만 `MNG_` 접두일 뿐 **저작도구가 자기 스키마에 `V1` 로 직접 CREATE 한 스텁**이며 관제 실DB 의 공유 테이블이 아니다(아래 § MNG_ACCT_AUTHRT 의 "dev 시드 스텁" 각주 참조). 관제 자체 역할 데이터는 관제 정책대로 운영하면 되고, 데이터마트 뷰·완료/수정 통지 계약에도 영향이 없다.
- 부트스트랩: 저작도구 첫 역할 부여는 `POST /v1/auth/role-claim`(관리자 PW)으로 LS_USER_ROLE에 기록 → 이후 REVIEWER가 배정.

> 결과: **관제 계정 마스터(MNG_ACCT_*)에 대한 저작도구 운영 쓰기는 이제 0건.** 관제팀은 이 두 테이블을 (스키마 검증 대상인 MNG_ACCT_USER의 매핑 컬럼만 빼면) 저작도구 제약 없이 다룰 수 있다.

## 3. 🟠 복합키 PK 구조 변경 금지 (운영 READ — 스키마 보호)

저작도구가 운영에서 조회만 하지만, PK 구조가 바뀌면 식별·조인·라벨 도출이 깨진다.

### MNG_EX_EVNT_TYPE_MAP
- **용도**: 이벤트 분류 코드 매핑 테이블. 저작도구가 마킹/라벨링 화면에서 **이벤트 코드를 한글 카테고리 라벨로 변환**해 표시·매칭하는 데 쓴다(프리셋·업로드 이벤트 검증을 관제 카테고리 기반으로 전환).
- 보호 PK: `CD_TYPE, EVNT_CLS_CD, EVNT_CTGRY_CD, DTL_EVNT, EVNT_TYPE_CD` (5컬럼)
- 보호 일반컬럼: `EVNT_NM`(라벨 소스), `USE_YN`
- ⚠️ 저작도구가 `DTL_EVNT=''`, `EVNT_TYPE_CD=''` **빈문자열 행 전제**로 카테고리 라벨을 도출하므로, PK 의미/제약 변경 시 라벨이 깨진다.

### MNG_CLIP_MASTER
- **용도**: 관제가 보유한 클립(영상) 마스터. 저작도구 배치가 **학습용으로 설정된 영상(`JOB_DMND_YN`)을 주기적으로 픽업해 적재**하는 입구. 영상 파일경로·길이·지자체·CCTV 식별자를 여기서 읽는다.
- 보호 PK: `EVNT_ID, CLIP_TYPE_CD`
- 보호 일반컬럼: `CLIP_ID, LCLGV_CD, FILE_NM, FILE_PATH, FILE_FMT, VDO_LEN_SEC, CLIP_STTS_CD, CRT_DT, ULD_CMPT_DT, JOB_DMND_YN, VMS_CCTV_ID` + **(V147 추가 매핑)** `FILE_SZ, JOB_DMND_PRNMNT_YN, CRT_TYPE`
- 픽업 조건: `JOB_DMND_YN` + `FILE_PATH`
- ℹ️ V147 로 ERD-024 정본 **16컬럼 전부를 매핑**했다(저작도구는 여전히 READ 전용, 쓰기 0건). 관제 스키마를 바꾼 것이 아니라 로컬/테스트 stub 을 실제 관제 스키마에 맞춘 것이며, 실 관제 테이블에는 컬럼이 이미 있어 마이그레이션이 no-op 이다. 다만 **매핑이 늘어난 만큼 `ddl-auto=validate` 보호 대상도 늘었다** — 위 컬럼의 drop/rename/타입변경 시 저작도구 기동이 실패한다.

### MNG_CLIP_EVNT_LST
- **용도**: 클립별 이벤트 목록. 저작도구가 영상 적재 시 **해당 영상의 이벤트 타입과 발생시각(`SHT_DT`)을 도출**하는 데 쓴다.
- 보호 PK: `EVNT_ID, EVNT_TYPE_CD`
- 보호 일반컬럼: `SHT_DT` + **(V147 추가 매핑)** `EVNT_NM, LCLGV_CD, SESN_CD, WTHR_CD, HR_TYPE_CD, PRVC_TYPE_CD, IDNTF_YN, CLCT_PATH, CLCT_SRC` (= ERD-024 에 기록된 12컬럼 전부. 실 테이블의 그 밖의 컬럼은 여전히 미매핑)
- ⚠️ **저작도구가 해석·적재하는 컬럼이 늘었다 (2026-07-31 — 구 "읽기만 하고 쓰지 않는다" 서술 폐기)**. 아래 3컬럼은 영상 적재 시 저작도구 테이블 `LS_DATA_RAW` 에 **값으로 적재**되므로, **코드값 체계를 바꾸면 사전 협의가 필요**하다.
  | 관제 컬럼 | 저작도구 적재 대상 | 채택 규칙 |
  |---|---|---|
  | `HR_TYPE_CD` | `LS_DATA_RAW.DAY_NGT_CD` | `DAY`/`NGT` 와 **그대로 일치할 때만** 채택. 그 외·미제공은 null(미상) |
  | `SESN_CD` | `LS_DATA_RAW.SESN_CD` | `SPRING`/`SUMMER`/`FALL`/`WINTER` 와 **그대로 일치할 때만** 채택. 그 외·미제공은 null(미상) |
  | `PRVC_TYPE_CD` | `LS_DATA_RAW.PRVC_TYPE_CD` | `ANONY`/`PRVC`/`PSDO` 만 채택. 그 외·미제공은 **`PRVC`**(관제가 값을 주지 않으므로 "개인정보 있음"으로 본다) |
- 🔴 **`PRVC_TYPE_CD` 폴백 변경은 데이터마트 뷰 노출값에 영향이 있습니다 (협의 항목, 2026-07-31)** — 폴백이 `ANONY`→`PRVC` 로 바뀌면서 **`V_COMPLETED_VIDEO.PRVC_TYPE_CD` 가 `ANONY`→`PRVC`, `PRVC_YN` 이 `N`→`Y` 로 뒤집힙니다**(V138 뷰). **신규 적재분부터 적용되며 기존 행은 백필하지 않습니다.** 사유·확인 요청 항목은 `관제팀-연동정합-확인요청-20260727.md` **§D-3** 참조.
- ℹ️ **`WTHR_CD` 는 소비하지 않는다** — 관제 코드값과 저작도구 표시명(맑음/흐림/비/눈/안개)의 **대응표가 없어** 날씨는 저작도구에서 직접 입력받기로 확정했다(2026-07-31). 이 컬럼 값을 바꿔도 저작도구에 영향이 없다.
- ℹ️ **`MNG_*` 테이블 자체에 대한 쓰기는 여전히 0건**이다(READ 전용). 위 "적재"는 관제 테이블이 아니라 저작도구 소유 테이블(`LS_DATA_RAW`)에 값을 복사하는 것을 뜻한다.
- ⚠️ MASTER 와 동일하게 `ddl-auto=validate` 보호 대상이 확대됐다 — 위 매핑 컬럼의 drop/rename/타입변경 시 저작도구 기동이 실패한다.

## 4. 🟡 단일키 READ-ONLY — 컬럼 drop/rename/타입변경만 주의

### MNG_RESOURCE_CCTV

- **삭제 근거**: v2(dev 246)의 MNG_ACCT_AUTHRT에 REVIEWER/WORKER/PORTAL_USER만 들어있던 것은 **저작도구 dev 시드가 만든 스텁**이며 실제 관제 마스터가 아니었다. 즉 저작도구가 자기 스키마에 만든 자기 객체이므로, 런타임 참조 0 을 확인한 뒤 V165 로 DROP 했다. **관제팀 보호 대상 아님.**

## 5. ⚪ ~~MNG_CLIP_SCHEDULE_QUE~~ → LS_CLIP_SCHEDULE_QUE — 소유권 정리 완료 (관제 무관)

> **2026-08 해소 (V162)**: 아래에서 권장했던 "소유·스키마를 저작도구 쪽으로 확정" 을 실제로 적용했다.
> 테이블을 `LS_CLIP_SCHEDULE_QUE` 로 개명하고, 이름 오인 때문에 V146 에서 누락됐던
> `RAW_SN → LS_DATA_RAW (ON DELETE CASCADE)` FK 를 보강했다. **이 테이블은 더 이상 관제 공유 목록이
> 아니며 관제팀 협의 대상이 아니다.** 아래 내용은 정리 이전 상태의 기록이다.
> ⚠ 아래 「매핑 컬럼」의 영문 서술형 이름 7종은 V5(2026-08)에서 표준용어로 개명됐다 —
> `JOB_TYPE`→`JOB_TYPE_CD` · `STATUS`→`STTS_CD` · `RETRY_COUNT`→`RTRY_NMTM` · `REGISTERED_AT`→`REG_DT` ·
> `STARTED_AT`→`BGNG_DT` · `COMPLETED_AT`→`CMPTN_DT` · `LAST_ERROR`→`LAST_ERR_MSG_CN`.

- **용도**: 저작도구의 **배치 라벨링 작업 큐**. 이름은 `MNG_`이지만 관제 클립 스케줄과 무관하게 저작도구가 자체 운영하는 큐다.
- 운영 Quartz 스케줄러(`BatchQuartzJob`, prd 활성)가 매 tick `SELECT ... FOR UPDATE`로 **폴링(읽기)** 한다.
- INSERT(enqueue)는 현재 **테스트 코드에서만** 호출되어 운영에서는 row가 쌓이지 않음 → UPDATE(markInProgress)도 사실상 미실행(**dormant**).
- 단 엔티티가 validate 대상이므로 **테이블·매핑 컬럼은 반드시 존재**해야 BE가 부팅된다.
- 매핑 컬럼: `QUE_SN`(PK, IDENTITY), `RAW_SN`, `JOB_TYPE`, `STATUS`, `RETRY_COUNT`, `REGISTERED_AT`, `STARTED_AT`, `COMPLETED_AT`, `LAST_ERROR`
- ⚠️ **소유권 정리 권장**: 사실상 저작도구 전용 큐이므로, v2에서 관제가 이 테이블을 다른 용도로 재정의/삭제하면 저작도구 부팅(validate)부터 깨진다. v2 전환 시 **이 테이블의 소유·스키마를 저작도구 쪽으로 확정**하는 것을 권장.

## 6. ⚪ ~~CM_CODE~~ — 저작도구 소유로 판명 후 제거 완료 (관제 무관)

> **2026-08 해소**: 이 테이블은 관제 공유 자산이 아니라 **저작도구가 자체 CREATE 한 코드 마스터**였다.
> 소유 접두를 붙여 `LS_COM_CD` 로 개명한 뒤(V2), **사용처 0 으로 판정되어 삭제**했다(V4).
> **저작도구 마이그레이션은 더 이상 이 테이블을 만들지도 INSERT 하지도 않는다** — 아래에서 요구했던
> "공유 klid_system 적용 시 사전 협의"는 **불필요해졌다.** 아래 내용은 정리 이전 상태의 기록이다.

- **용도**: 공통 코드 마스터. 저작도구는 `GROUP_CODE='DATA_STTS_CD'`(작업/검수 상태: PENDING/IN_REVIEW/APPROVED/REJECTED/BATCH_QUEUED) 코드값과 정합을 맞췄다. 런타임 조회는 없고 시드 INSERT만 존재했다.
- 참조 컬럼: `GROUP_CODE`(PK), `CODE`(PK), `CODE_NM`, `CODE_DC`, `USE_YN`, `SORT_ORDR`
- ⚠️ 관제가 자체 공통코드 테이블을 별도로 운영한다면 **이 항목과 무관**하다. 저작도구는 작업/검수 상태코드를 애플리케이션 상수로 관리한다.

## 기타 — dev / 배포타임 전용 (운영 BE 런타임 의존 아님, 참고용)

아래는 MNG_*에 INSERT/DELETE를 하지만 **운영 백엔드 런타임 경로가 아니다.** v2 운영 영향 평가에서 제외해도 된다.

### (a) DevSeedRunner — `@Profile("local")` 전용
- **용도**: 로컬 개발 환경에서 관제 DB가 없을 때 테스트용 사용자·영상·이벤트 데이터를 채우는 시더.
- `dev/DevSeedRunner.java` (`@Profile("local")` + `@ConditionalOnProperty`, prd/dev/stg 미등록). `db/seed/dev-seed.sql` 실행.
- local 시드 대상: MNG_ACCT_USER, MNG_RESOURCE_CCTV, MNG_CLIP_MASTER, MNG_CLIP_EVNT_LST, MNG_EX_EVNT_TYPE, MNG_EX_EVNT_TYPE_MAP (+ 저작도구 소유 LS_USER_ROLE·LS_LABEL·LS_DATA_INGEST)
  - ※ 구 `MNG_ACCT_AUTHRT`/`MNG_ACCT_USER_AUTHRT` 시드는 V165 로 테이블이 삭제되면서 함께 제거됐다(역할은 `LS_USER_ROLE` 시드가 담당).
- → **로컬 개발 DB 한정.** 운영/공유 DB에 실행되지 않음.

### (b) seed-mng-event-type.sh — 배포타임 수동 스크립트 (온프렘 독립 DB 모드 한정)
- **용도**: 온프렘 설치 시 공유 klid_system이 아닌 **독립 PostgreSQL**을 쓸 때, 관제에서 이벤트 타입 코드를 1회 부트스트랩 복사하는 운영자용 스크립트.
- `deploy/onprem/scripts/seed-mng-event-type.sh`. 멱등(`ON CONFLICT DO NOTHING`).
- 쓰기 대상은 **저작도구 소유 온프렘 PostgreSQL**뿐. 관제 공유 DB는 **읽기(SELECT)만** 한다.
- 대상: MNG_EX_EVNT_TYPE, MNG_EX_EVNT_TYPE_MAP
- → 관제 공유 테이블에 쓰지 않음. v2 영향 없음.

## 한 줄 요약

역할 분리 리팩토링 후 **저작도구가 관제 공유 테이블에 운영 런타임으로 쓰는 것은 0건**이다(과거 `MNG_ACCT_USER`/`MNG_ACCT_USER_AUTHRT` 쓰기는 저작도구 자체 `LS_USER_ROLE`로 분리·제거). 참조가 0 이 된 `MNG_ACCT_AUTHRT`·`MNG_ACCT_USER_AUTHRT` 2종은 **저작도구 자체 스텁이라 V165(2026-08)로 DROP** 됐다 — 관제팀 보호 대상에서 제외.
관제팀이 보호해야 할 것은 **저작도구가 READ/validate 하는 컬럼·PK 스키마**뿐이다 — 특히 복합키 4종(§3, `MNG_EX_EVNT_TYPE_MAP` 5컬럼 등)과 `MNG_RESOURCE_CCTV.VMS_CCTV_ID/CCTV_NM`(native 조인, §4).
`MNG_CLIP_SCHEDULE_QUE`는 저작도구 자체 큐로 확인되어 `LS_CLIP_SCHEDULE_QUE` 로 개명(V162)돼 관제 공유 목록에서 빠졌고, `CM_CODE` 역시 저작도구 소유로 판명돼 `LS_COM_CD` 개명(V2) 후 **삭제**(V4)됐다. dev-seed/seed-mng-event-type 의 MNG_* 쓰기는 local/배포타임 도구로 운영 의존이 아니다.
