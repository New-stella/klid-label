## 1.1 목적

학습 저작도구(Authoring Tool)는 지자체 CCTV 영상에서 추출한 프레임 이미지를 기반으로 **AI 학습용 어노테이션 데이터를 제작·관리·검수**하는 핵심 서브시스템이다. 작업자가 이미지에 라벨을 부착하고 검수자가 품질을 검증하는 전 과정을 관리하며, 최종적으로 AI 모델 학습에 투입 가능한 정제 데이터셋을 생성한다.

> ℹ️ 위 문단은 통합설계서 §1 요약이며 3종 1차 PDF에는 이 수준의 목적 서술이 없다(원문 미확인). `02-관리자매뉴얼.txt`의 §1 개요는 "본 문서는 AI CCTV 관제 학습 저작도구 시스템의 관리자 사용법에 대하여 기술합니다." 한 문장뿐이다(`02-관리자매뉴얼.txt 1.개요`).

- **발주사**: KLID 한국지역정보개발원 / **수행사**: SweetK
  - 근거(1차 PDF 확인): `01-UIUX설계서.txt` "UI Guide 화면 ID 정의" — 화면 ID 구성요소 "①수행사 SweetK ②발주사 KLID 한국지역정보개발원".
- **대상 AI**: 침수 탐지(UperNet + ViT-Adapter) 등

> ⚠ **원문 미확인** — "대상 AI: 침수 탐지(UperNet + ViT-Adapter) 등" 문구는 3종 1차 PDF(스토리보드·관리자매뉴얼·UI설계서V1.1) 어디에도 등장하지 않는다(`UperNet`·`ViT-Adapter`·`침수 탐지` 키워드 전수 검색 0건). 3종 PDF는 라벨링 도구를 "AI Tool"·"Auto Labeling"이라는 화면 기능명으로만 서술하며 내부 모델명을 언급하지 않는다(`02-관리자매뉴얼.txt 4.3.4·4.3.5`). 이 문구는 `docs/v1-wiki/sources/` 분석본(통합설계서 등) 근거로 남겨두며, 삭제하지 않는다.

## 1.2 전체 시스템 위상

```
지자체 통합관제센터 (서울 관악구 / 경기 안양시 / 강원 원주시 / 제주 등)
        ↓ 이벤트 + 클립영상
지자체 중계서버
        ↓
Ingest Server (수신 · 검증 · 초기 처리)
        ↓
control-hub 관제지원시스템
    ├─ Clip NAS (클립영상 저장)
    ├─ 메타데이터 DB (이벤트·인덱스)
    ├─ 비식별화 서버
    └─ ★ 학습 저작도구 ★   ← 본 위키의 대상
            ↓
        AI 학습 데이터셋 → 침수·화재·교통 탐지 AI 모델
```

> ⚠ **원문 미확인** — 이 위상도의 `지자체 통합관제센터`·`중계서버`·`Ingest Server`·`control-hub`·`Clip NAS`·`메타데이터 DB`·`비식별화 서버`(시스템 컴포넌트로서) 용어는 3종 1차 PDF에 전혀 등장하지 않는다(전수 grep 0건). 3종 PDF에서 확인되는 것은 "비식별화"가 **저작도구 화면 안의 라벨링 작업 기능**(작업자가 얼굴·번호판 등을 수동으로 블러 처리)이라는 점뿐이며, 별도 "비식별화 서버"의 존재·위치는 확인되지 않는다(`02-관리자매뉴얼.txt 4.3.3 라벨링 작업 기능_비식별화` — "영상에 찍힌 사람의 얼굴이나 자동차 번호판, 전화번호 등 개인정보들을 비식별화하는 작업은 라벨..."). 이 다이어그램은 삭제하지 않고 유지하되(통합설계서·아키텍처설계서 근거로 추정), 1차 corpus로는 검증 불가함을 명시한다.

## 1.3 저작도구 핵심 파이프라인

```
영상/이미지 등록 (클립·이미지 목록에 노출)
    ↓
프로젝트 배정 시 프레임 분할 (관리자가 배정 화면에서 FPS·분할단위(초당/분당/시간당/전체) 설정 → "변환대기"→"변환중"→"배정대기")
    ↓
작업자 라벨링(가공) — 1단계 (바운딩박스 / 폴리곤 / 스켈레톤, AI Tool·Auto Labeling 보조, 밝기/대비는 라벨러가 작업 중 수동 조정 가능)
    ↓
1차 검수 → 승인 or 반려  (기본 프로세스는 "1단계 가공 → 1차 검수"까지이며 더 줄일 수 없음)
    ↓
(선택) 2차 검수 → 승인 or 반려   (검수는 "검수 추가"로 최대 2단계까지 구성 가능)
    ↓
(선택) 2단계 가공 → 1차 검수 → 2차 검수   ("단계 추가"로 가공 단계도 최대 2단계까지 구성 가능)
    ↓
데이터 증강 (선택, 5종: 밝게 / 어둡게 / 좌우반전 / 좌우반전_밝게 / 좌우반전_어둡게 — 최종완료된 라벨링 데이터 대상)
    ↓
프로젝트 완료 처리 (버전 설명 필수 입력 → 라벨러 접근 차단, 데이터를 현재 기준으로 묶어 업로드/관리)
```

> ⚠ **구 서술 폐기(2026-08-19 원문 실측)** — 이전 버전은 다음과 같이 적고 있었다:
> *"클립영상 수신 → 프레임 자동 추출(FFmpeg Batch, 1회/분) → 이미지 전처리(리사이징, 밝기/대비 자동 보정) → 작업자 라벨링 → 1차 검수 → 2차 검수 → 데이터 증강(선택) → 데이터마트 등록/AI 모델 학습 투입"*.
> 이 서술 중 다음은 1차 PDF 원문과 다르거나 확인되지 않는다.
> - **"프레임 자동 추출(FFmpeg Batch, 1회/분)"**: 원문은 프레임 분할이 **관리자가 영상/이미지를 프로젝트에 배정하는 시점에 수동으로 트리거**되며, FPS·분할단위(초당/분당/시간당/전체)를 관리자가 직접 설정하는 방식이다. "FFmpeg"·"1회/분"·자동 배치 주기는 3종 PDF 어디에도 없다. 근거: `02-관리자매뉴얼.txt 5.2 영상/이미지 프로젝트 배정` — "영상의 경우 프로젝트 배정 시 프레임으로 나눠진 다음 배정되기 때문에 실제 작업자가 데이터를 받을 수 있기까지 시간이 소요됩니다." · "분할 기준 설정: 분할 단위(초당/분당/시간당/전체), 프레임 수".
> - **"이미지 전처리(리사이징, 밝기/대비 자동 보정)"**: 원문에서 밝기/대비 조정은 **자동 전처리가 아니라 라벨러가 작업·검수 중 필요할 때 수동으로 쓰는 조정 기능**이다("이미지 조절 패널", KLID-AI-SC-005). "리사이징"·"자동 보정"은 3종 PDF에 없다. 근거: `02-관리자매뉴얼.txt` — "라벨러는 작업 또는 검수 과정에서 이미지의 밝기와 대비를 조정하여 어두운 영상이나 화질이 낮..." (4.3.2 라벨링 작업 기능_서포트 기능 절).
> - **"1차 검수 → 2차 검수"가 고정 2단계**: 원문은 검수·가공 단계 수를 **프로젝트 생성 시 관리자가 구성**하는 값이며, 기본값은 **"1단계 가공 → 1차 검수"까지**(2차 검수 없음)이고, "검수 추가"로 검수를 최대 2단계까지, "단계 추가"로 가공을 최대 2단계까지 늘릴 수 있다. 최대 구성 시 "1단계의 가공 → 1차 검수 → 2차 검수 → 2단계의 가공 → 1차 검수 → 2차 검수"가 된다. "1차/2차 검수"는 고정 파이프라인이 아니라 프로젝트별 선택 구성이다. 근거: `02-관리자매뉴얼.txt 3.1 프로젝트 생성` — "기본 데이터 작업 프로세스는 '1단계의 가공 → 1차 검수'이며, 더 짧게 줄이는 것은 불가능합니다. '검수 추가' 버튼을 클릭하면 검수 과정을 추가할 수 있으며, 검수는 최대 2단계까지 설정 가능합니다. '단계 추가' 버튼을 클릭하면 가공 단계를 추가할 수 있으며, 단계 또한 최대 2단계까지 구성할 수 있습니다."
> - **"데이터마트 등록 / AI 모델 학습 투입"**: 3종 PDF에서 "데이터마트"·"모델 학습 투입"이라는 표현은 발견되지 않는다(전수 grep 0건). 확인되는 마지막 단계는 **"프로젝트 완료 처리"**(관리자가 버전 설명을 입력하고 확정하면 라벨러 접근이 차단되고 "프로젝트의 데이터를 현재 기준으로 묶어서 업로드하거나 관리"한다는 문구)뿐이며, 그 데이터가 구체적으로 "데이터마트"로 가는지는 원문에 명시되지 않는다(원문 미확인). 근거: `02-관리자매뉴얼.txt 3.2.1 프로젝트 완료 처리`.
>
> 위 항목들은 `docs/v1-wiki/sources/` 분석본(2차 자료)에서 유래한 것으로 보이며 틀린 내용은 아닐 수 있으나, 1차 corpus 3종으로는 검증되지 않아 정정했다.

### AI 모델 구성

| AI 기능 | 모델 / 방식 |
|---------|-----------|
| 오토 라벨링 (객체 탐지) | YOLO |
| 클릭 세그멘테이션 | SAM (Segment Anything Model) |

| 하이퍼파라미터 튜닝 | Random Search |
| 성능 평가 | Confusion Matrix, mAP, IoU |

> ⚠ **원문 미확인(2026-08-19)** — "YOLO"·"SAM"·"UperNet"·"ViT-Adapter"·"mmseg"·"mmcv"·"Random Search"·"Confusion Matrix"·"mAP"·"IoU" 모두 3종 1차 PDF에 없다(전수 grep 0건). 3종 PDF는 해당 기능을 모델명이 아니라 화면 기능명으로만 서술한다 — "AI Tool"(객체 일부만 클릭해도 자동으로 테두리를 잡아주는 기능, `02-관리자매뉴얼.txt 4.3.4`), "Auto Labeling"(사람·자전거·자동차·오토바이·버스·트럭 등 일부 객체를 자동 라벨링, `02-관리자매뉴얼.txt 4.3.5`). 이 표는 코드규격서·통합설계서 등 별도 문서(`docs/v1-wiki/sources/` 분석본) 근거로 보이며, 1차 corpus로는 검증 불가하다.

> **v2 참고**: `klid-label`(v2)는 **Spring Boot(Java 17) + PostgreSQL** 메인 + **FastAPI ai-server(YOLO/SAM2/VLM 추론 전용)** 구조이며, MySQL/Redis/Kafka는 사용하지 않는다. 침수 모델 등 AI 모델 본체는 v2 범위 외(외부 시스템 책임).

## 1.5 설계 핵심 원칙 (v1)

1. **프로젝트 기반 분리** — 프로젝트별 독립 공간으로 다중 학습 프로젝트 병렬 운영
2. **자동화 파이프라인** — 프레임 분할(관리자 배정 시 FPS 설정) → AI 보조 라벨링
3. **다중 라벨링 지원** — 바운딩박스/폴리곤/스켈레톤 + Track(트랙 연결)
4. **AI 보조** — Auto Labeling(오토 라벨링) + AI Tool(클릭 시 자동 테두리 잡기)
5. **품질 관리 체계** — 작업자 → 검수자(1~2단계, 프로젝트별 구성) → 승인/반려 + 이력
6. **생성형 AI 연동** — 실데이터 부족 시 데이터 증강/생성
7. **보안 강화** — GPKI 인증, 데이터 암호화, XSS 방지
