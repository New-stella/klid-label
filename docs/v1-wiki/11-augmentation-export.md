## 11.1 데이터 증강 (Augmentation)

완료되지 않은 프로젝트의 **최종완료 라벨링 데이터**에 대해 5종 증강 처리. (관리자매뉴얼 v1.1에서 추가된 기능)

| 증강 종류 | 처리 내용 |
|----------|----------|
| 밝게 | Brightness + |
| 어둡게 | Brightness - |
| 좌우반전 | Horizontal Flip |
| 좌우반전 + 밝게 | Horizontal Flip + Brightness + |
| 좌우반전 + 어둡게 | Horizontal Flip + Brightness - |

### 증강 상태 흐름

```
증강가능 → 대기 → 진행중 → 완료 / 부분성공 / 실패
```

| 상태 | 설명 |
|------|------|
| 증강가능 | 최종완료 데이터 있고 프로젝트 미마감 |
| 대기 | 증강 요청 후 큐 대기 |
| 진행중 | 처리 중 |
| 완료 | 전체 성공 |
| 부분성공 | 일부만 성공 |
| 실패 | 전체 실패 |

### 증강 관리 (완료되지 않은 프로젝트)
1. 증강 열 "완료" 버튼 → 팝업
2. 선택: **원시데이터번호**(최종 완료), **원천데이터번호**(프레임 분할 데이터), **증강종류**(5종)
3. 증강 결과 이미지 표시 (클릭 시 원본 표시)

| 옵션 | 설명 |
|------|------|
| 밝기 | 밝게/어둡게/좌우반전_밝게/좌우반전_어둡게에서 조정 (기본값 ±60) |
| 수정 | 밝기 수정 후 선택 원천데이터-증강옵션 재시작 |
| 삭제 | 해당 증강 데이터 삭제 |

> **완료된 프로젝트는 증강 불가** → 완료취소 후 옵션 수정 가능.

### 자동 재처리 (DB)
`LS_DATA_AUG`: `AUG_STTS_CD`(상태), `ERROR_CD`/`ERROR_MSG`(에러), `RTRY_CNT`(재시도 횟수), `LAST_TRY_DT`(최종 시도), `BRGT_OFST`(밝기 보정값), `AUG_IMG_FILE_PATH`. → 자동 재처리 메커니즘 지원. `UK_AUG_UNIQUE`로 중복 방지. ([15](15-database.md))

## 11.2 학습 데이터 내보내기

> ⚠ **원문 미확인(2026-08-19)** — 아래 흐름(용도 선택 → 학습 용도/데이터마트 등록 → 신규·기존 데이터셋)과 "데이터 분류 기준" 표는 **1차 PDF 3종(화면정의서·관리자매뉴얼 Rev.1.0·UI설계서 D2 V1.1) 어디에도 나오지 않는다** — `용도`·`버전 상승`·`마트용`·`마트 등록`·`기존 데이터셋`·`데이터마트` 키워드로 3개 파일 전문을 검색했으나 0건(관리자매뉴얼의 TOC에도 "내보내기"·"데이터셋" 절이 없다). `sources/` 분석본(DB설계서 V1.4 분석·통합설계서, 진실원 아님) 기준으로 추정 정리된 내용으로 보인다. 원본 HWP 또는 데이터베이스설계서 V1.4 원문 확인 전까지 1차 사실로 인용하지 말 것.
> 다만 관리자매뉴얼에는 "구축 완료된 학습 데이터셋은 **데이터 마켓**에 공개되어 사람들이 이용할 수 있기 때문에…"(§4.3.3 라벨링 작업 기능_비식별화, `02-관리자매뉴얼.txt`)라는 표현이 있다 — 아래 표의 "데이터마트"와 정확히 같은 개념인지는 원문만으로 단정할 수 없다.

```
데이터 업로드
    ↓ 용도 선택
    ├── [학습 용도] → 학습 영상 경로로 파일 이동 → 기존 영상 학습 로직 처리
    └── [데이터마트 등록]
            ├── 신규 데이터셋: 데이터셋 목록 추가 → 마트용 경로 이동 → 마트 등록
            └── 기존 데이터셋 추가: 기존에 추가 → 버전 상승 → 마트 재등록
```

### 데이터 분류 기준

| 분류 항목 | 분류 기준 |
|----------|----------|
| 데이터 유형 | 이미지 / 영상 / AI 모델 |
| 데이터 가공 유형 | 원천 / 학습 |
| 개인정보 처리 | 비식별화 여부 (`PRVC_YN`) |

DB: `LS_PJT`의 `PJT_DSET_STTS_CD`(데이터셋 상태)/`PJT_DSET_START_DT`, `LS_PJT_DATA_STATS`의 `DATA_SET_STTS_CD`, `UK_DATA_SET_UNIQUE`(데이터셋 고유 식별).

> **v2 참고**: v2에서 **데이터마트는 외부 제공 시스템 책임(범위 외)**. 저작도구는 라벨링·검수·버전관리까지만 담당하고, 검수 완료 영상을 `klid_at` 스키마의 4종 View(`V_COMPLETED_*`)로 노출 → 관제서버가 통지 수신 후 마트로 UPSERT. v1의 "데이터마트 등록"은 v2 저작도구 책임이 아니다.
