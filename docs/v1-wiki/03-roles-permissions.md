## 3.1 역할 분류

3종 1차 PDF는 권한 구분을 **"공통 / 라벨러 / 관리자"** 2대 그룹(+공통)으로 분류한다(화면 ID 구성요소 "④ 권한 구분 값(공통, 라벨러, 관리자)", `01-UIUX설계서.txt` UI Guide 화면 ID 정의). 동일 아이디로 여러 권한을 **중복 보유** 가능하다(`02-관리자매뉴얼.txt 2.권한 관리` — "권한을 중복으로 보유할 수 있습니다"; `01-UIUX설계서.txt` — "프로젝트 담당자가 작업자나 검수자 권한도 부여 가능", "동일 프로젝트에서도 여러 권한을 가질 수 있음").

역할 이름은 5개로 확인된다 — **슈퍼 관리자, 프로젝트 담당자, 업로더, 검수자, 작업자**. 이는 사용자 권한 부여 시 실제로 선택하는 값(`02-관리자매뉴얼.txt 3.5 사용자 확인 및 추가` — "권한: 사용자 권한 중 하나 선택(전체, 프로젝트 담당자, 업로더, 검수자, 작업자 중 선택)")과, 관리자 그룹을 정의하는 문장(`02-관리자매뉴얼.txt 2.권한 관리` — "관리자는 슈퍼 관리자/프로젝트 담당자/업로더로 나눠져 있으며")을 합친 것이다.

### 라벨러 그룹

| 역할 | 핵심 권한 |
|------|----------|
| **작업자** | 배정된 프레임 라벨링(가공) 수행, 완료 후 검수자에게 제출 |
| **검수자** | 작업자 제출 결과를 프레임 단위로 검토, 승인/반려. 프로젝트 설정에 따라 1단계·2단계(1차/2차) 검수에 배정될 수 있음(아래 3.1.1 참고) |
| **업로더** | 영상·이미지 업로드 및 AI 생성 데이터 등록(11. 업로드/생성 메뉴) |

> ⚠ **구 서술 폐기(2026-08-19 원문 실측)** — 이전 버전은 "검수자(1차)"·"검수자(2차)"를 **별도 역할**로 나누어 적고 있었다. 원문에는 그런 역할 명이 없다. 사용자 권한 선택지는 "검수자" 단일 값이며(근거는 위 3.5 인용), 1차/2차는 **프로젝트별로 구성하는 검수 단계**를 가리키는 표현이다. 근거: `02-관리자매뉴얼.txt 3.1 프로젝트 생성` — "'검수 추가' 버튼을 클릭하면 검수 과정을 추가할 수 있으며, 검수는 최대 2단계까지 설정 가능합니다"; `03-UI설계서V1.1.txt` — "한 단계의 작업자, 검수자(N차)는 초기 배정 시 한번에 선택해야지 배정 진행 가능"(N차라는 표기 자체가 1차/2차가 역할명이 아니라 배정 시점의 단계 변수임을 보여준다). "1차 검수자"·"2차 검수자"라는 표현 자체는 원문에도 등장하지만(`03-UI설계서V1.1.txt` — "1차 검수자가 승인한 작업을 2차 검수자가 반려했을 경우..."), 이는 "검수자 역할을 1단계/2단계 어느 검수에 배정했는지"를 가리키는 **문맥적 지칭**이지 권한 카탈로그상의 별도 역할이 아니다. → 3.1.1 참고.

### 3.1.1 검수 단계(1차/2차)는 역할이 아니라 프로젝트 구성

- 프로젝트의 기본 데이터 작업 프로세스는 **"1단계 가공 → 1차 검수"**까지이며 더 줄일 수 없다(`02-관리자매뉴얼.txt 3.1`).
- "검수 추가"로 검수 단계를 최대 2단계(1차·2차)까지, "단계 추가"로 가공 단계를 최대 2단계까지 늘릴 수 있다. 최대 구성은 "1단계의 가공 → 1차 검수 → 2차 검수 → 2단계의 가공 → 1차 검수 → 2차 검수"이다(`02-관리자매뉴얼.txt 3.1`).
- 사용자 추가 시에는 "권한(검수자)"과 별개로 "단계(1단계/2단계)"를 선택해 배정한다(`02-관리자매뉴얼.txt 3.5` — "단계: 프로젝트 생성 시 설정한 단계 중 하나 선택(1단계, 2단계 중 선택)").
- 검수 흐름 규칙(원문 확인): "2차 검수자에게 반려된 건은 1차 검수자가 작업자에게 반려 불가능"(`02-관리자매뉴얼.txt` 작업 흐름 절) / "1차 검수자가 승인한 작업을 2차 검수자가 반려했을 경우, 1차 검수자는 해당 작업물을 작업자에게 반려할 수 [있다]" / "2차 검수자가 최종 승인한 작업을 관리자가 반려했을 경우, 2차 검수자는 해당 작업을 1차 검수자에게 반려할 [수 있다]"(`03-UI설계서V1.1.txt`).

### 관리자 그룹

| 역할 | 핵심 권한 |
|------|----------|
| **슈퍼 관리자** | 전체 시스템 접근, 프로젝트 전체 관리, 사용자 관리 (권한 부여 없이 모든 화면 접근, 아이디 노출 안 됨) |
| **프로젝트 담당자** | 할당받은(자신이 생성한) 프로젝트만 생성·관리·권한 부여 |
| **업로더** | AI 동영상·이미지 생성 및 업로드 |

> ⚠ **구 서술 폐기(2026-08-19 원문 실측)** — 이전 버전은 관리자 그룹의 업로더를 **"업로더(관리자)"**로 표기해 라벨러 그룹의 "업로더"와 별개 역할처럼 보이게 했다. 원문상 "업로더"는 **단일 역할/권한**이며, 관리자 계정 분류(`02-관리자매뉴얼.txt 2.권한 관리` — "관리자는 슈퍼 관리자/프로젝트 담당자/업로더로 나눠져")와 사용자 권한 선택지(3.5의 "검수자, 작업자"와 나란한 "업로더")에 **같은 이름으로 등장**한다. 다만 원문 자체에 애매함이 남아있다 — 화면 ID 분류(④ 권한 구분값)는 "공통/라벨러/관리자" 2그룹뿐인데, 업로더의 실제 화면은 라벨러측 IA(작업자/검수자와 같은 "학습 저작도구" 메뉴 구조, 대시보드·프로젝트·게시판·연습장·업로드/생성)를 그대로 쓰면서도(`01-UIUX설계서.txt` — 섹션 제목 "작업자/검수자/업로더 메뉴 구조도"), 관리자매뉴얼은 업로더를 "관리자" 부류에 넣어 설명한다. 즉 **업로더는 관리자·라벨러 어느 쪽 기본 역할과도 결합 가능한 권한 오버레이**로 읽힌다(예: 프로젝트 담당자+업로더 조합이 명시적으로 언급됨, `02-관리자매뉴얼.txt` — "프로젝트 담당자는 '업로드/생성' 메뉴에 접근하기 위해서는 업로더 권한이 있어야 한다"). 표를 두 그룹으로 나눈 기존 구조는 유지하되(원문의 관리자매뉴얼 표 구조를 따름), "관리자 그룹의 업로더"와 "라벨러 그룹의 업로더"가 서로 다른 역할이 아님을 명시한다.

> ⚠ **구 서술 폐기(2026-08-19 원문 실측)** — 이전 버전은 검수자의 "업로드/생성" 접근을 **"-"(불가)**로, 작업자만 "O(권한 시)"로 표기해 비대칭이었다. 원문에는 라벨러 그룹(작업자/검수자/업로더)의 메뉴별 접근을 명시한 표 자체가 없다 — 이 매트릭스는 IA 구조도(`01-UIUX설계서.txt` — "작업자/검수자/업로더 메뉴 구조도(IA)": 대시보드·프로젝트·게시판·연습장·업로드/생성 5개 메뉴를 "작업자/검수자" 박스 하나로 묶고, "해당 메뉴는 권한을 가진 사람만 보이고, 권한이 없는 [사람의] 경우 메뉴 자체가 안보이도록 진행"이라는 일반 규칙만 명시)와 "권한 중복 보유 가능" 원칙(3.1 참고)에서 **추정**한 것이다. 업로드/생성 메뉴가 업로더 권한 보유 여부에 조건부라는 점은 작업자·검수자에게 동일하게 적용되는 것으로 읽는 것이 원문과 더 정합적이라 대칭으로 정정했다. 다만 이 정정 자체도 **명시적 원문 문장으로 확정된 것은 아니며**(추정), 확정 표는 이번 3종 PDF에 없다는 점을 유의할 것(정보 부족).
>
> ⚠ 게시판 "(열람 전용)" 주석은 라벨러 그룹 전체(작업자/검수자/업로더)에 공통 적용됨을 명시했다(구 서술은 업로더에만 붙어 있었음) — 근거: `02-관리자매뉴얼.txt 9.2 게시글 작성` — "'저장' 클릭 시 작성한 게시글은 저장만 된 상태로, 관리자들만 확인 가능합니다. '등록' 클릭 시... 라벨러들도 해당 게시글을 확인할 수 있게 됩니다."(게시글 작성·삭제는 관리자 전용, 라벨러는 발행된 글만 열람).

## 3.3 권한 조합 규칙

- **작업자 + 업로더 / 검수자 + 업로더**: 5개 메뉴(대시보드·프로젝트·게시판·연습장·업로드/생성) 모두 접근 — 업로더 권한이 더해지면 기본 4개 메뉴에 업로드/생성이 추가된다(3.2 정정 참고).
- **검수자는 1차/2차로 나뉜 별도 역할이 아니다** — "검수자" 권한을 프로젝트의 1단계 또는 2단계 검수에 배정하는 것이며, 같은 사람이 여러 프로젝트에서 1차·2차를 각각 맡을 수 있다(3.1.1 참고).
- **프로젝트 담당자의 다중 권한**: 특정 프로젝트에서는 담당자, 다른 프로젝트에서는 작업자/검수자 동시 보유 가능(`01-UIUX설계서.txt` — "프로젝트 담당자가 작업자나 검수자 권한도 부여 가능").
- **프로젝트 담당자 → 업로드/생성 메뉴**: "업로더" 권한 필수(`02-관리자매뉴얼.txt` — "프로젝트 담당자는 '업로드/생성' 메뉴에 접근하기 위해서는 업로더 권한이 있어야 한다").
- **업로더는 관리자·라벨러 어느 기본 역할과도 결합 가능한 권한**이다(3.1의 "구 서술 폐기" 항목 참고) — "업로더(라벨러 전용)"·"업로더(관리자 전용)"처럼 이원화된 개념이 아니다.
- **슈퍼 관리자**: 권한 부여 없이 전체 화면 접근, 아이디 비노출(`02-관리자매뉴얼.txt` — "슈퍼관리자의 경우 권한을 부여받지 않아도 모든 화면에 접근 가능하기 때문에 아이디 노출 안됨").
- **단계 자동 배정**: 프로젝트 담당자·업로더는 1단계 추가 시 자동으로 2단계에도 추가(단계 "전체"로 반영) — `02-관리자매뉴얼.txt 3.1`(생성 직후) · `3.5`(사용자 추가 시) 양쪽에서 확인.

## 3.4 권한 기반 UI 원칙

- 권한 없는 메뉴는 **메뉴 자체 미노출**(비활성화 아님) — `01-UIUX설계서.txt` IA 구조도 주석: "해당 메뉴는 권한을 가진 사람만 보이고, 권한이 없는 [경우] 메뉴 자체가 안보이도록 진행".
- 권한 조합에 따라 접근 가능한 메뉴가 동적으로 변경.
