## 3.1 역할 분류

시스템은 **라벨러 그룹**과 **관리자 그룹**으로 구분되며, 동일 아이디로 여러 권한을 **중복 보유** 가능하다.

### 라벨러 그룹

| 역할 | 핵심 권한 |
|------|----------|
| **작업자** | 배정된 프레임 라벨링 수행, 완료 후 검수 요청 제출 |
| **검수자(1차)** | 작업자 제출 결과 검토, 승인/반려 |
| **검수자(2차)** | 1차 검수 완료 결과 최종 검토, 승인/반려 |
| **업로더** | 영상·이미지 업로드 및 AI 생성 데이터 등록 |

### 관리자 그룹

| 역할 | 핵심 권한 |
|------|----------|
| **슈퍼 관리자** | 전체 시스템 접근, 프로젝트 전체 관리, 사용자 관리 (권한 부여 없이 모든 화면 접근, 아이디 노출 안 됨) |
| **프로젝트 담당자** | 할당받은(자신이 생성한) 프로젝트만 생성·관리·권한 부여 |
| **업로더(관리자)** | AI 동영상·이미지 생성 및 업로드 |

## 3.2 메뉴별 접근 권한 매트릭스

### 라벨러 그룹

| 메뉴 | 작업자 | 검수자 | 업로더 |
|------|:------:|:------:|:------:|
| 대시보드 | O | O | - |
| 프로젝트 관리 | O | O | - |
| 게시판 | O | O | O |
| 연습장 | O | O | O |
| 업로드/생성 | O(권한 시) | - | O |

### 관리자 그룹

| 메뉴 | 슈퍼 관리자 | 프로젝트 담당자 | 업로더 |
|------|:----------:|:--------------:|:------:|
| 대시보드 | O (전체) | △ (담당 프로젝트) | - |
| 프로젝트 관리 | O | △ | - |
| 영상/이미지 관리 | O | O | - |
| 업로드/생성 데이터 관리 | O | O | - |
| 게시판 | O | O | O |
| 연습장 | O | O | O |
| 업로드/생성 | O | O(업로더 권한 시) | O |

> **범례**: O = 완전 접근, △ = 제한 접근(할당 프로젝트만), - = 접근 불가

## 3.3 권한 조합 규칙

- **작업자 + 업로더**: 5개 메뉴 모두 접근 (대시보드·프로젝트·게시판·연습장·업로드/생성)
- **프로젝트 담당자의 다중 권한**: 특정 프로젝트에서는 담당자, 다른 프로젝트에서는 작업자/검수자 동시 보유 가능
- **프로젝트 담당자 → 업로드/생성 메뉴**: "업로더" 권한 필수
- **업로더(라벨러)**: 게시판(열람 전용)·연습장·업로드/생성만 접근
- **슈퍼 관리자**: 권한 부여 없이 전체 화면 접근, 아이디 비노출
- **단계 자동 배정**: 프로젝트 담당자·업로더는 1단계 추가 시 자동으로 2단계에도 추가(단계 "전체"로 반영)

## 3.4 권한 기반 UI 원칙

- 권한 없는 메뉴는 **메뉴 자체 미노출**(비활성화 아님)
- 권한 조합에 따라 접근 가능한 메뉴가 동적으로 변경

## 3.5 권한 관련 데이터 (DB)

| 테이블 | 용도 |
|--------|------|
| `LS_USER_ROLE` | 역할 코드/명(`ROLE_CD`, `ROLE_NM`, `USE_YN`) |
| `LS_USER_MENU` | 계층형 메뉴 구조(`UP_MENU_SN`, `MENU_URL`, `MENU_DEPTH`) |
| `LS_PJT_USER_AUTHRT` | 프로젝트별 사용자 권한 매핑(`AUTHRT_CD`, `STG_SN`) |
| `LS_PJT_USER_AUTHRT_HSTRY` | 권한 변경 이력 |

상세 컬럼은 [15 데이터베이스](15-database.md) 참고.

> **v2 참고**: v2는 **ADMIN 역할 없이 모든 관리 권한을 `REVIEWER`(검수자)에 통합**하고, `WORKER`(라벨링 작업자), `PORTAL_USER`(포털 회원) 3개 역할로 단순화했다. v1의 슈퍼관리자/프로젝트담당자/업로더/1·2차 검수자 세분화 및 GPKI 로그인은 v2에 없다(v2는 관제/포털 JWT 인계, 독립 로그인 UI 없음).
