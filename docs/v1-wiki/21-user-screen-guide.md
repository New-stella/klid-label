## 21.2 메뉴 구조 · 권한 (화면 진입 맥락)

**라벨러(작업자/검수자/업로더)**: `대시보드 / 프로젝트(로그인 첫 화면) / 게시판 / 연습장 / 업로드·생성`. "업로드/생성"은 **업로더 권한자만** 메뉴 노출(권한 없으면 메뉴 자체 숨김).

**관리자/프로젝트 담당자**: `대시보드 / 프로젝트 관리 / 영상·이미지 관리 / 업로드·생성 데이터 관리 / 사용자 관리 / 게시판 / 업로드·생성`. 대시보드·프로젝트 관리는 2Depth(**담당 프로젝트** = 내가 담당자 / **작업 프로젝트** = 내가 작업자·검수자, 라벨러 화면과 동일).

## 21.3 라벨링 작업 화면군 (작업자)

라벨링 캔버스는 하나의 화면(Storyboard 02-02-04~14)이며, D2는 이를 기능 단위 SC-003~008로 쪼갠다. **v2 konva.js 라벨링 캔버스 포팅의 1차 원형**이다.

### 화면 레이아웃 (Storyboard 기준)

```
┌ 상단 툴바: ← 도움말(?) | [관리자 확인 요청] | ⏮ « ‹ [프레임#] › » ⏭ | 슬라이더+영상명 | ⛶ | ↶↷ | [저장] [제출]
├ 좌측 세로 도구바: 선택 · 회전 · 초기화 · 영역확대 · AI Tool · 오토라벨링 · 바운딩박스/폴리곤 · 스켈레톤 · 블러 · 그리드
├ 중앙 상단: 프레임 썸네일 스트립(가로 스크롤) — 현재=크게 / 반려=주황 / 확인요청=빨강 / 저장=연두
├ 중앙: 캔버스(작업 영역)
└ 우측 패널: 탭 [객체/라벨] [메타] [이슈사항]  +  [이미지](밝기/대비) · [투명도](투명도/작업투명도)
```

### SC-003 · 라벨링 도구

- **유형** 조회/등록/수정 · **경로** [작업자] 프로젝트 > 선택 > 라벨링 도구 · **UC** KLID-AI-UC-006 · **SD** SD-006
- **개요**: 바운딩박스·폴리곤·스켈레톤·블러·그리드로 어노테이션 작업.

**입출력 항목 (라벨 저장 payload)**

| 항목 | 컨트롤명 | 타입 | 속성 |
|---|---|---|---|
| 프로젝트/원시/원천/라벨 일련번호 | pjtSn · dataRawSn · dataSrcSn · lblSn | number(20) | R/H 필수 |
| 트랙 사용/프레임/ID | trckUseYn · trckFrmYn · trckId | string | I/E/H |
| 좌표 | point | string(4000)/json | I/E/H 필수 |
| 속성 | atrb | string(4000)/json | I/E/H 필수 |
| 순서 | sortSeq | number(11) | I/E/H 필수 |

**처리 로직**: 도구 클릭 시 세부 박스(라벨 선택 + 번호 자동 부여 + 일반/트랙 선택). 색상은 관리자가 라벨 정의 시 설정한 색. 폴리곤은 첫 점과 만나면 종료. 블러는 클릭 시 커서가 원형으로 바뀌고 영역 클릭으로 처리, 재클릭 시 비활성. 그리드는 클릭 시 이미지에 격자 표시.

**조작 절차(매뉴얼)**: 바운딩박스 = 아이콘 → 팝업(라벨, 일반/트랙) → 시작점 클릭 후 대각선 끝점 클릭(2회). 폴리곤 = 시작점 → 테두리 따라 클릭 → 시작점 재클릭. 스켈레톤 = 시작점·끝점 2회 클릭으로 생성 후 포인트 위치 조정. 속성은 **우측 객체 탭**에서 선택.

> ⚠ **기술 고려(D2)**: 이미지 리사이즈·회전으로 좌표가 틀어질 수 있으므로 **모든 연산은 원본 이미지 해상도·좌표계 기준**으로 처리해야 한다. → v2에서도 유지되는 핵심 불변식.

### SC-004 · 객체 추적 및 복사

- **유형** 조회/등록/수정 · **경로** [작업자] > 선택 > 객체 추적 및 복사 · **UC** UC-010/UC-013 · **SD** SD-009/SD-012
- **개요**: 프레임 간 이동 경로 자동 계산(트래킹) + 기존 라벨·속성·위치 복사. 입출력 payload는 SC-003과 동일 + `pjtHlpCn`(도움말).

**4대 기능**

1. **트랙(객체 추적)**: 한 프레임에서 바운딩박스/폴리곤 생성 시 **뒷 프레임 전체에 동일 위치 자동 생성**. 마지막 프레임 위치 변경 시 그 사이값을 **선형 보간**으로 계산. **작업자가 직접 수정한 프레임은 보간 대상에서 제외**(예: 1·2 프레임을 직접 작업하면 간격이 커도 자동 수정 안 함).
2. **AI Tool**: 바운딩박스(default)/폴리곤 + 라벨/속성 선택 → 작업영역 객체 클릭 → 객체/라벨 생성 → **'생성' 클릭 시 최종 확정**(인식 중 화면 비활성, 연달아 클릭 불가). Storyboard 참고 이미지는 CVAT UI(Segment Anything 2.0 / Interactors·Detectors·Trackers 탭) 기반.
3. **오토 라벨링**: 작업(박스/폴리곤) → 항목(사람 default/자동차/자전거) → 라벨 → 일반/트랙. **매 프레임 실행 필요**. 매뉴얼은 대상 객체를 사람·자전거·자동차·오토바이·버스·트럭으로 확장 표기.
4. **복사/붙여넣기**: `Ctrl+C/V`. 완전 동일 객체 존재 시 좌표를 **우로 10·아래로 10** 이동시켜야 함(D2 기술 고려).

**트랙 번호 변경(머지)**: 우측 객체 '⋮ > 변경'. 객체가 가려졌다 다시 나타났을 때 앞 트랙과 하나로 연결(최종 데이터셋 추출에 반영).

> ⚠ **기술 고려(D2)**: 트래킹·AI Tool·오토라벨링은 처리 시간이 길므로 **로딩바 등 진행 표시** 필요.
> 상세: [08 AI 보조 라벨링](08-ai-assisted-labeling.md#84-track-모드).

### SC-007 · 학습데이터 저장

- **제출**: 마지막 프레임에만 노출. **모든 프레임이 1회 이상 저장 + 관리자 확인요청 미완료 프레임 없음**일 때만 활성. 클릭 → "해당 작업을 제출하시겠습니까?" → 확인 시 검수자에게 전달 + 다음 영상 이동.

### SC-009 · 검수 작업 (검수자)

- **유형** 조회/등록/수정 · **UC** UC-007 · **SD** SD-007
- 검수 화면 = 작업자 화면 + 상단 [승인][반려][제출]. 검수자도 **직접 수정 가능**, **프레임 단위로 승인/반려**.

**반려**: 사유 팝업(라디오: 바운딩박스/폴리곤/스켈레톤 가이드라인 미흡). 반려 시 프레임 테두리 주황. **반려 내역은 누적**되다 최종 '제출' 시 영상 반려 확정 → 작업자에게 전달.

**다단계 반려 규칙**
- 1차 승인 → 2차 반려 시, **1차 검수자는 작업자에게 반려 불가**(반려 버튼 비활성).
- 2차 최종 승인 → 관리자 반려 시, **2차 검수자는 1차에게 반려 불가**.

**검수 기준(예시)**: 바운딩박스는 객체 전체를 감싸되 여백 최소화(작으면 불량). 폴리곤은 가시 영역 외곽선 따라(다른 객체 포함 시 불량).

## 21.7 SC 미부여 관리자 화면 (매뉴얼 기준)

D2 SC 번호가 없으나 매뉴얼·화면정의서에 존재하는 관리자 전용 화면.

### 프로젝트 증강 처리 (매뉴얼 §3.2.2)

- **대상**: 완료 상태가 **아닌** 프로젝트의 **최종완료 라벨링 데이터**. 완료 프로젝트는 증강 불가(완료취소 후 가능).
- **증강 5종**: 밝게 / 어둡게 / 좌우반전 / 좌우반전+밝게 / 좌우반전+어둡게.
- **밝기 슬라이더**: 최초 기본 **밝게 +60 / 어둡기 -60**(매뉴얼 §3.2.2 확인). 슬라이더 값의 범위(구 서술 "-255~255")는 `01-UIUX설계서.txt`·`02-관리자매뉴얼.txt`·`03-UI설계서V1.1.txt` 어디에도 나오지 않아 **원문 미확인**으로 되돌린다.
- 증강 상태: 증강가능 → 대기 → 진행중 → 완료(/부분성공/실패). 증강 관리 팝업에서 원시/원천데이터번호·증강종류·상태 확인, 옵션 수정/삭제.

> 상세: [11 데이터 증강·내보내기](11-augmentation-export.md).

### 업로드/생성 데이터 관리 (매뉴얼 §6)

업로더 업로드 or AI 생성(1차 검수 완료) 데이터 목록. **프로젝트 배정 전 반드시 '등록'** → 영상/이미지 관리로 이동해야 배정 가능. [생성 정보 탭] 프롬프트+참고 이미지(I2I/I2V), [메타데이터 수정 탭]. 이벤트 유형은 현재 **침수만** 지원.

### 관리자 확인 요청 처리 (매뉴얼 §3.6)

담당 프로젝트 데이터 클릭 → 라벨러 화면과 동일. 라벨러가 확인 요청한 프레임 진입 시 상단이 **[확인 및 재배정]·[폐기]**로 변경. 재배정 = 사유/’문제 없음’ 입력 후 라벨러에 재배정. 폐기 = 프레임을 삭제 처리(매뉴얼 §3.6)하며, **전체 프레임 수에서 제외**된다(매뉴얼 §3.3 "전체 프레임 수: 프레임 중 ‘폐기’를 제외한 프레임 수"로 교차 확인). ⚠ 폐기 확인 팝업 문구("복구할 수 없습니다" 등)는 1차 원본 3종 텍스트 추출본에서 확인되지 않아 **원문 미확인**.

### 사용자 관리 (Storyboard 03-05-01)

진행 프로젝트 셀렉트 + 검색(ID/이름) + 사용자 권한 일괄 삭제. 남은 작업 있으면 삭제 불가. 계정은 쿠도 API 수신.

### 게시판 (매뉴얼 §9, Storyboard 02-03/03-06)

목록(제목/내용 검색) + 상단 고정(📌) + 작성/수정/삭제(관리자). 상태: 저장(관리자만 확인) → 등록(발행, 라벨러 확인). 발행 취소 = '저장' 단계로. 수정은 '재발행'(등록자명·등록일·조회수 리셋).

### 연습장 (SC-016 / 매뉴얼 §10)

라벨링 툴과 동일 레이아웃 + [저장]만. **하드코딩 이미지**로 체험(이미지 변경은 코드 수정 필요). 작업 내용은 **관리자도 확인 불가**.

(v2에서는 **파이프라인 선두 자동 비식별**로 재설계됨 — [18](18-v1-v2-comparison.md) 참조.)
