## 6.1 이벤트 및 클립 수신 구조

| 구성 요소 | 역할 |
|----------|------|
| Ingest Server | 지자체 중계서버로부터 이벤트 JSON(RestAPI) 및 클립 영상 수신 |
| 룰셋(Rule Set) | 수신 이벤트 중 필요한 이벤트 필터링 |
| 수집 스케줄 | 이벤트별 클립 영상 수집 시간 정의 |
| 전송 스케줄 | control-hub로의 전송 시간 정의 |

클립 영상은 중계서버 → Ingest → **Clip NAS**에 저장. Admin 페이지에서 이벤트 목록 조회/삭제/상세/재전송 요청/원본 요청, 이벤트 유형별·영상 유형별·조건별 검색 가능. *(요구사항: RQ-SFR-10-01~04)*

## 6.2 프레임 자동 추출 (FFmpeg Batch)

인터페이스: `KLID-AI-II-001`(요청) / `II-002`(상태 응답) — **Batch, 1회/분** ([14](14-interfaces-api.md))

```
[배치 프로그램] 1분마다 데이터 변환 매핑 테이블 조회
    ↓ (원본 영상 경로, 요청 FPS, 프로젝트 ID)
이미지변환 API 요청 → 원본 파일 존재 여부 검증
    ↓
프로젝트 ID 디렉토리 생성
    ↓
FFmpeg로 지정 FPS에 따라 프레임 추출
    (파일명: frame_0001.png, frame_0002.png ... 자동 증가)
    ↓
매핑 테이블 상태 업데이트 (완료 / 실패 + 오류 로그)
```

### 추출 요청 파라미터 (II-001)

| 파라미터 | 설명 |
|----------|------|
| 원시데이터 고유번호 | 원본 영상 식별자 |
| 비디오 추출 여부 | Boolean |
| 실제 영상 파일 경로 | 스토리지 경로 |
| 추출 시작/종료 시간 | 구간 설정 |
| 프레임 추출 방식 | FPS 또는 타임스탬프 |
| 조건 값 | 방식에 따른 세부 값 |

### 상태 응답 파라미터 (II-002)

원시데이터 고유번호 · 상태/오류 메시지 · 전체 프레임 수 · 현재 추출 프레임 수(진행률)

## 6.3 이미지 자동 분류

추출된 프레임은 원본 클립의 메타데이터(**이벤트 유형, 시간대, 날씨, 계절, 위치** 등)를 기반으로 자동 분류·저장된다. 분류 기준 코드는 `LS_DATA_SRC`의 `EVNT_TYPE_CD`/`HR_TYPE_CD`/`WTHR_CD`/`SESN_CD`/`LCLGV_CD` ([15](15-database.md)).

## 6.4 이미지 전처리

| 기능 | 설명 |
|------|------|
| **자동 리사이징** | 사전 정의 해상도 기준 자동 조정 |
| **밝기/대비 자동 보정** | 로드 시 전체 Brightness·Contrast 분석 후 최적값 자동 계산 |
| **사용자 수동 조정** | 라벨링 화면 우하단 슬라이더로 실시간 조정 (-100~100) |
| **투명도 조정** | 전체/선택 라벨 투명도 개별 조정 (0~100) |
| **Circle 크기 조정** | 라벨 포인트 크기 슬라이더 |

> ⚠️ **좌표계 원칙**: 모든 좌표 연산은 반드시 **원본 이미지의 해상도·좌표계** 기준으로 처리. 이미지 회전·사이즈 변경은 좌표에 영향을 주므로 원본 기준 변환 필수. (UI설계서 §2.2 기술 고려사항)

## 6.5 영상/이미지 프로젝트 배정

화면: `SKKLID-UI-03-03-01 ~ 04` (영상/이미지 관리)

### 목록·검색
포함 데이터: 관제지원시스템 전달분 + 업로드/생성 데이터 관리에서 "등록"된 AI 생성/업로더 업로드분.

검색 필터: 검색어 · 적용 프로젝트 · 이벤트 유형 · 이벤트명
상세검색: 날씨 · 시간대(주간/야간) · 계절 · 개인정보 포함여부 · 비식별화 여부 · AI 생성 여부 · 사용자 업로드 여부 · 생성일

상세 팝업: "기본 정보" 탭(파일크기·영상길이, 수정 불가) + "메타데이터 수정" 탭(수정/저장), 동영상 재생.

### 배정 절차
1. 체크박스 선택(중복 가능) → "프로젝트 배정" → 프로젝트 선택 팝업(단일) → "선택"
2. **프레임 분할 기준 팝업**(이미지만 배정 시 생략)

## 6.6 프레임 분할 (배정)

상단 정보: 영상/이미지명 · 영상 길이 · 초당 프레임 기준(FPS, 원본)

| 필드 | 설명 |
|------|------|
| 분할 단위 | 초당 / 분당 / 시간당 / 전체 |
| 프레임 수 | 숫자만 |

**규칙**: 분할 프레임 수는 원본 FPS보다 작아야 함 / 분당 분할은 1분 이상 영상 / 시간당 분할은 1시간 이상 영상.

"업로드" → 프레임 분할 → 프로젝트 배정. 영상 처리는 자원 집중 → **1건씩 배치 처리** 구현 필수.

### 데이터 상태 흐름

```
변환 대기 → 변환중 → (변환오류) → 배정대기
```
- **배정대기** 상태에서만 라벨러에게 작업 배정 가능
- 프레임 번호: `F`(실제 추출 번호), `I`(분할 시 순차 번호)

## 6.7 관련 데이터 (DB)

`LS_DATA_SRC`(원천 데이터·메타), `LS_PJT_DATA_MPNG`(프로젝트-데이터 매핑), `LS_PJT_DATA_STTS`(상태·변환 프레임 수·FPS 유형), `LS_PJT_STG_PRC`(가공 처리·`TRSF_FRM_CNT`/`FPS_TYPE_CD`). 상세 → [15](15-database.md).

> **v2 참고**: v2 파이프라인은 **⭐마킹(자동=프레임 간격/수동=단축키) → 외부 VLM 시계열(콜백) → 비식별화 → FFmpeg(원본+비식별 2벌) → YOLO(원본만) → SAM2 → 트랙 보간** 순으로, Quartz 1건/분 처리. v1의 "프로젝트 배정 시 프레임 분할" 대신 v2는 마킹 위치 기반 추출을 사용한다.
