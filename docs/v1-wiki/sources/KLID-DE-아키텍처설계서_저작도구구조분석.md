## 1. 시스템 아키텍처 개요

### 1.1 control-hub 중심 도메인 기반 아키텍처

시스템 전체는 **control-hub**를 중심으로 여러 도메인으로 구성됩니다.

| 도메인 | 역할 |
|--------|------|
| **Ingest Server Domain** | 지자체 중계서버로부터 이벤트 정보 및 클립 영상 수신 |
| **Clip Domain** | 클립 영상 저장 및 관리 |
| **ExServer Manager Domain** | Ingest 서버 관리 및 연동 |
| **Account Domain** | 사용자 계정 및 권한 관리 (gpki 인증 연동) |
| **DataSet Domain** | 학습 데이터셋 구성 및 관리 |
| **Resource-Mng Domain** | 리소스 관리 및 운영 현황 관리 |
| **Business-Support Domain** | 지자체 업무지원 서비스 |

### 1.2 데이터 흐름

```
지자체 통합관제센터 (서울시 관악구 / 경기도 안양시 / 강원도 원주시 / 제주특별자치도 등)
        ↓ (이벤트 및 클립 영상)
지자체 중계서버
        ↓
Ingest Server (수신 · 검증 · 초기 처리)
        ↓
control-hub 관제지원시스템
    ├─ Clip NAS (클립 영상 저장)
    ├─ 메타데이터 DB (이벤트, 인덱스 정보)
    ├─ 비식별화 서버 (영상 비식별화 처리)
    └─ 저작도구 (학습 데이터 제작)
        ↓
AI 플랫폼 / 학습 데이터셋 관리
```

## 3. 저작도구 (Authoring Tool) 구조 및 설계

저작도구는 CCTV 영상에서 추출한 프레임 이미지를 기반으로 **AI 학습용 데이터를 제작·관리**하는 핵심 모듈입니다.

### 3.1 주요 기능 구성

```
저작도구 (Authoring Tool)
│
├─ [프로젝트 관리]
│   ├─ 프로젝트 생성 / 수정 / 삭제
│   ├─ 프로젝트별 독립 작업 공간 및 설정
│   ├─ 라벨(Class) 및 속성(Attribute) 관리
│   └─ 사용자 권한 관리 (관리자 / 작업자 / 검수자)
│
├─ [영상 수집 및 프레임 추출]
│   ├─ 클립 영상 목록 조회 및 필터링
│   ├─ 프로젝트 배정 (체크박스 선택)
│   ├─ 프레임 자동 추출 (FFmpeg 기반)
│   └─ 이미지 자동 분류 및 저장
│
├─ [이미지 전처리]
│   ├─ 해상도 자동 리사이징
│   ├─ 밝기 / 대비 자동 보정
│   └─ UI 기반 수동 조정
│
├─ [라벨링 도구]
│   ├─ 바운딩 박스 (Bounding Box)
│   ├─ 폴리곤 (Polygon)
│   ├─ 키포인트 (Keypoint)
│   ├─ 속성 입력 (라디오박스 / 텍스트)
│   ├─ 객체 복사 / 붙여넣기
│   └─ Track 모드 (선형보간 자동 생성)
│
├─ [AI 보조 라벨링]
│   ├─ 오토 라벨링 (YOLO 기반 객체 탐지)
│   └─ 클릭 세그멘테이션 (SAM 방식)
│
├─ [검수 관리]
│   ├─ 작업자: 이미지 설명 및 라벨 작성 / 제출
│   ├─ 검수자: 승인 / 반려 처리
│   └─ 이력 관리 (작업 제출, 검수 승인, 반려 사유 등)
│
├─ [진행 현황 관리]
│   ├─ 프로젝트별 작업 현황 시각화
│   └─ 작업 건수 / 배정 / 완료 / 반려 / 승인 현황 대시보드
│
└─ [학습 데이터 내보내기]
    ├─ 데이터 유형별 분류 (이미지 / 영상 / AI 모델)
    ├─ 가공 유형별 분류 (원천 / 학습)
    └─ 데이터마트 등록
```

## 4. 아키텍처 요구사항 및 구현 방안

### 4.1 이벤트 수신 기능 (RQ-SFR-10-01)

**요구사항**: 각 지자체 관제 센터 운영 시스템들로부터 이벤트 및 클립 영상 수집

**구현 방안**:
- 업체에서 제공하는 API를 이용한 이벤트 및 저장 영상 연계 개발
- **RestAPI 형식 + JSON 포맷** 적용 연동
- 이벤트 중 필요한 이벤트들은 **룰셋(Rule Set)** 에 따라 처리
- 이벤트에 따른 클립 영상 수집은 **수집 스케줄**에 따라 정의된 시간에 처리
- 중앙 관제 지원 시스템으로의 전송도 **전송 스케줄**에 따라 정해진 시간에 전송

### 4.2 클립 영상 저장 및 관리 (RQ-SFR-10-02)

**요구사항**: 지자체별 통합관제센터 CCTV 클립영상 통합 수집 구축

**구현 방안**:
- Ingest 서버를 통해 수신한 이벤트 정보는 **Admin 페이지**에서 목록 조회 가능
- Admin에서 목록 조회 / 삭제 / 상세 조회 / 클립 영상 재전송 요청 / 원본 영상 요청 기능 구현
- 이벤트 목록의 이력 및 통계 관리 기능 구현
- 지자체 CCTV 연계자료 외 타 경로 수집 클립 영상 관리(업로드 등) 기능 개발
- 영상 인덱스 정보 생성 및 관리 기능
- 클립 영상 관리 기준 및 이벤트 유형별 분류 체계 마련

### 4.3 클립 영상 검색 및 조회 (RQ-SFR-10-03)

**요구사항**: 클립 영상 검색 및 상세 확인 기능

**구현 방안**:
- 클립 영상은 지자체 중계서버에서 Ingest 서버를 통해 관제지원시스템의 **클립 NAS**에 저장 관리
- 저장된 클립 영상은 Admin 페이지 이벤트 목록을 통해 이벤트 유형별 / 영상 유형별 / 기타 조건으로 검색 및 상세 확인 가능

### 4.4 사용자 및 권한 관리 (RQ-SFR-10-04)

**요구사항**: 저작도구 내 프로젝트별 권한 관리 — 사용자 및 권한 관리 기능 개발

## 5. 저작도구 세부 기능 설계

### 5.1 클립 영상 → 프레임 이미지 자동 추출

**목적**: 수신한 클립 영상을 프레임 단위 이미지로 변환하여 학습 데이터 생성

**처리 흐름**:

```
1. 주기적 배치 프로그램이 데이터 변환 매핑 테이블 조회
   (원본 영상 경로, 요청 FPS, 프로젝트 ID 등 포함)
        ↓
2. 변환 대기 상태의 레코드에 대해 이미지변환 API 요청 전송
   (파라미터: 영상 경로, 추출 방식(FPS/타임스탬프), 프로젝트 ID)
        ↓
3. API 서버: 원본 영상 파일 존재 여부 검증
             지정 프로젝트 ID 디렉토리 생성
        ↓
4. FFmpeg 라이브러리로 요청 FPS에 따라 프레임 추출
   (파일명: frame_0001.png, frame_0002.png ... 자동 증가)
        ↓
5. 매핑 테이블 상태 업데이트 (완료 / 실패 + 오류 로그)
```

**이미지 분류 자동화**:
- 추출된 프레임 이미지는 원본 클립 영상의 메타데이터(이벤트 유형, 시간대, 날씨, 세션 정보 등)를 기반으로 자동 분류
- 분류된 이미지는 라벨링 기준 또는 카테고리별로 구분하여 저장

### 5.2 이미지 전처리 기능

| 기능 | 설명 |
|------|------|
| **자동 리사이징** | 사전 정의된 해상도 기준에 따라 이미지 자동 조정 |
| **밝기/대비 자동 보정** | 이미지 로드 시 전체 밝기(Brightness), 대비(Contrast) 분석 후 최적 보정값 자동 계산 |
| **사용자 수동 조정** | 보정값을 UI 조정 패널에 기본값으로 설정하여 실시간 조정 가능 |
| **색상 조정** | 색상(Color), 이미지 크기 자동 조정 기능 |

### 5.3 라벨링 도구

#### 기본 라벨링 유형

| 라벨링 방식 | 활용 목적 |
|------------|----------|
| **바운딩 박스 (Bounding Box)** | 객체 탐지 (Object Detection) |
| **폴리곤 (Polygon)** | 세밀한 객체 영역 분할 |
| **키포인트 (Keypoint)** | 관절, 포즈 탐지 등 |

#### 속성(Attribute) 관리

- 라벨(Class) 추가 시 속성 항목을 하위로 입력 가능
- 속성 입력 형식: **라디오박스(Radio Box)** + **텍스트 입력**
- 프로젝트 관리 화면 내 라벨/속성 관리 기능 제공 (생성 / 수정 / 삭제)

#### 객체 복사 / 붙여넣기

- 단축키 이벤트 리스너 구현 (현재 선택된 라벨 객체 대상)
- 복사 정보: 좌표(x, y, w, h 또는 polygon points), 클래스명, 속성값 포함
- 동일 위치 중복 객체 방지 — 기본 좌표 offset(+10px) 적용하여 새 위치 배치
- 붙여넣기된 객체는 새로운 라벨 ID로 저장

#### Track 모드 (연속 이미지 라벨링)

- 트랙 모드 활성화 시 라벨 간 연속성 관리
- 트랙으로 생성된 라벨 사이의 프레임은 **선형보간(Linear Interpolation)** 알고리즘으로 자동 계산 및 라벨 생성
- 다음 프레임에 라벨 유지 기능 구현

### 5.4 AI 보조 라벨링

#### 오토 라벨링 (Auto Labeling)

- 기반 모델: **YOLO** 정의 클래스 중 CCTV에서 활용 가능한 객체 탐지로 구성
- 동작 방식:
  1. 오토 라벨링 버튼 클릭
  2. 탐지할 유형 선택
  3. 저작도구 라벨과 매칭
  4. 오토 라벨링 연산 중 Loading 화면 표시
  5. 객체 탐지 완료 시 자동 라벨링 생성

#### 클릭 세그멘테이션 (Click Segmentation)

- SAM(Segment Anything Model) 방식 적용
- 동작 방식:
  1. 오토 세그멘테이션 버튼 클릭
  2. 탐지할 유형 선택 후 저작도구 라벨과 매칭
  3. 탐지 객체가 올바르지 않은 경우 — 클릭 취소 또는 추가 클릭으로 재탐지
  4. 여러 번 클릭 시 첫 클릭을 베이스로 연결하여 닫힌 폴리곤 생성
  5. 연결 불가능한 영역 선택 시 객체 탐지 오류 발생
  6. 탐지 완료 후 완료 버튼 클릭으로 학습 라벨 생성

### 5.5 이미지 설명(캡셔닝) 작업

- 저작도구는 이미지 설명 작성을 위한 메타데이터 입력 기능 제공
- 작업자는 할당된 이미지에 대해 시각적 내용을 설명하는 문장 작성
- 검수자는 작성된 이미지 설명이 기준에 적합한지 검토 후 승인 또는 반려

### 5.6 검수 관리 기능

**작업자 역할**:
- 할당된 이미지에 라벨 작업 후 제출

**검수자 역할**:
- 작성된 라벨 및 이미지 설명 검토
- 승인 / 반려 처리

**이력 관리 항목**:
- 작업자 작업 제출 이력
- 작업 내역
- 검수자 승인 이력
- 반려 이력 및 반려 사유
- 관리자 확인 요청 이력
- 학습 라벨 데이터 / 원천 데이터 / 학습 메타 데이터 변경 이력 (전체)

### 5.7 진행 현황 시각화

**프로젝트별 현황 UI**:
- 전체 작업 건수
- 배정 수
- 작업 완료 수
- 반려 수
- 관리자 확인 요청 수

**영상당 작업 현황**: 진행 상태 시각화 제공

### 5.8 프로젝트 기반 학습 데이터셋 설계

```
프로젝트 설계 구조
│
├─ 프로젝트별 독립 작업 공간 및 설정값
├─ 프로젝트 ID 기준: 모든 작업(Task), 이미지, 라벨, 사용자 할당 데이터 연계
├─ 라벨링 유형 정의 (바운딩 박스 / 폴리곤 / 키포인트)
├─ 대상 객체 종류 정의
└─ 작업자 역할 정의
```

**영상분석 유형별 라벨링 기준**:

| 분석 유형 | 라벨링 기법 |
|----------|------------|
| 객체 탐지 | 바운딩 박스, 폴리곤 |
| 모션 탐지 | Track 기능 (동일 객체 연속 식별) |
| 재난 탐지 | 유형별 최적 기법 정의 |

## 6. 생성형 AI 연동 기능

- 생성된 이미지 / 영상 클릭 시 생성에 사용된 이미지 및 프롬프트 이력 표시
- 등록 버튼으로 학습 데이터의 원시 데이터로 전환하여 학습 데이터로 활용

## 8. 학습 데이터 내보내기 및 데이터마트 등록

**데이터 업로드 흐름**:

```
데이터 업로드
    ↓
용도 선택
├─ [학습 용도] → 학습 영상 경로로 파일 이동 → 기존 영상 학습 로직 처리
└─ [데이터마트 등록]
    ├─ 신규 데이터셋: 데이터셋 목록 추가 → 마트용 경로로 이동 → 마트 등록
    └─ 기존 데이터셋 추가: 기존 데이터셋에 추가 → 버전 상승 → 마트 재등록
```

| 데이터 가공 유형 | 원천 / 학습 |
| 개인정보 처리 | 비식별화 여부 |

## 요약

본 설계서는 **AI 기반 지자체 CCTV 관제지원시스템**의 아키텍처를 정의하며, 특히 저작도구는 다음과 같은 핵심 설계 원칙을 따릅니다.

1. **프로젝트 기반 분리**: 프로젝트별 독립 공간으로 다중 학습 프로젝트 병렬 운영 지원
2. **자동화 파이프라인**: FFmpeg 기반 프레임 추출 → 자동 분류 → AI 보조 라벨링으로 작업 효율 극대화
3. **다중 라벨링 지원**: 바운딩 박스, 폴리곤, 키포인트, Track 모드 등 다양한 라벨링 방식 제공
4. **AI 보조 기능**: YOLO 오토 라벨링 + SAM 클릭 세그멘테이션으로 라벨링 작업 시간 단축
5. **품질 관리 체계**: 작업자 → 검수자 → 승인/반려 이력 관리로 데이터 품질 보증
6. **생성형 AI 연동**: 실데이터 부족 시 데이터 증강으로 학습 데이터 보강
7. **보안 강화**: GPKI 인증, 데이터 암호화, XSS 방지 등 다층 보안 아키텍처
