## 3. 주요 사항

### 3.1 시스템 개요
- AI CCTV 관제 영상에서 객체 탐지, 추적, 라벨링을 위한 학습 데이터 제작 저작도구
- 작업자/검수자/관리자의 3단계 계층 구조
- 프레임 기반 작업 진행 방식
- 라벨링, 바운딩박스, 폴리곤, 스켈레톤, 키포인트 등 다양한 가공 유형 지원

### 3.2 권한 구분 (역할별)
1. **라벨러/작업자**: 데이터 가공 및 작업 수행
2. **검수자**: 1차/2차 검수 및 승인/반려
3. **관리자/프로젝트담당자**: 프로젝트 관리, 사용자 관리, 데이터 관리
4. **업로더**: 이미지/동영상 업로드 및 AI 기반 생성

## 4. 메뉴 구조 (Information Architecture)

### 4.1 작업자/검수자 메뉴 구조

```
학습 저작도구 (메인 화면)
├── 대시보드
│   └── 월별/일별 작업통계
├── 프로젝트
│   ├── 프로젝트 목록 (배정/작업중/반려/관리자확인요청)
│   └── 프로젝트별 작업 리스트
├── 게시판
│   ├── 게시글 목록
│   └── 게시글 상세보기
├── 연습장
│   └── 가공 작업 체험 (임시 저장만 가능)
└── 업로드/생성 (권한자만 표시)
    ├── 파일 업로드
    └── AI 이미지 생성

* 메인 화면: 로그인 시 보이는 화면
* 권한 없는 메뉴는 메뉴 자체가 노출되지 않음
```

### 4.2 관리자/프로젝트 담당자 메뉴 구조

```
학습 저작도구 (메인 화면)
├── 대시보드
│   ├── 담당 프로젝트 (프로젝트담당자만)
│   │   └── 전체 리스트/통계
│   └── 작업 프로젝트
│       └── 내 작업 리스트/통계
├── 프로젝트 관리
│   ├── 담당 프로젝트
│   ├── 프로젝트 생성
│   │   ├── 프로젝트 정보
│   │   ├── 단계 설정
│   │   ├── 라벨 생성
│   │   └── 권한 부여
│   └── 프로젝트 상세
│       ├── 프로젝트 정보 수정
│       └── 권한 재배정
├── 사용자 관리
│   └── 사용자 등록/관리
├── 영상/이미지 관리
│   ├── 영상/이미지 목록
│   └── 영상/이미지 상세
├── 데이터 관리
│   └── 업로드/생성 데이터 관리
├── 게시판
│   ├── 게시글 목록
│   └── 게시글 작성/수정
└── 업로드/생성 (관리자는 항상 표시)
    ├── 파일 업로드
    └── AI 이미지 생성

* 프로젝트담당자: 본인이 권한을 가진 프로젝트만 노출
* 관리자: 전체 프로젝트/데이터 접근 가능
```

## 6. 작업 흐름 (Workflow)

### 6.1 전체 작업 흐름도

```
작업자 → 검수자(1차) → 검수자(2차) → 관리자 → 작업 완료
```

### 6.2 작업자 작업 방식

**프레임별 작업 진행**

1. **관리자 확인 요청 (실시간)**
   - 프레임을 관리자 확인 요청으로 보내면 해당 프레임은 관리자에게 전달
   - 해당 프레임은 작업 불가능 (볼 수는 있음)
   - 관리자 확인 요청 프레임은 실시간으로 돌아오고, 보내기 처리 가능

2. **모든 프레임 저장 후 제출**
   - 관리자 확인 요청 프레임이 없고, 모든 프레임이 저장 처리되어야 검수자에게 제출 가능

3. **반려된 프레임 재작업**
   - 클립에서 반려된 프레임만 작업 가능
   - 승인된 프레임은 볼 수 있으나 작업 불가능

### 6.3 프레임 테두리 색상 표기 체계

| 색상 | 상태 | 의미 |
|------|------|------|
| **주황색** | 반려된/반려한 프레임 | 다시 작업해야 하는 상태 |
| **빨간색** | 관리자 확인 요청 | 관리자에게 확인 요청 중 |
| **연두색** | 저장된 프레임 | 정상 처리된 상태 |
| *(모두 연두색)* | 제출 가능 | 모든 프레임이 연두색일 때만 제출 가능 |

### 6.4 검수자(1차) 작업 방식

**프레임별 작업 진행**

1. **관리자 확인 요청 실시간 처리**
   - 작업자가 보낸 관리자 확인 요청 프레임 실시간 처리 가능

2. **개별 반려**
   - 반려는 개별로 하나씩 처리 가능
   - 마지막 프레임에서 '제출' 클릭해야 영상이 작업자에게 반려 완료

3. **반려/승인 처리**
   - 관리자 확인 요청 프레임이 없을 때 반려 완료 및 검수 완료 처리 가능

4. **2차 검수자 반려 제약**
   - 2차 검수자에게 반려된 건은 1차 검수자가 작업자에게 반려 불가능

### 6.5 검수자(2차) 작업 방식

**프레임별 작업 진행**

1. **관리자 확인 요청 실시간 처리**
   - 작업자가 보낸 관리자 확인 요청 프레임 실시간 처리 가능

2. **승인/반려 처리**
   - 관리자 확인 요청 프레임이 없을 때 반려 완료 및 검수 완료 처리 가능

### 6.6 관리자 작업 방식

**프레임별 실시간 처리**

1. **관리자 확인 요청 프레임 처리**
   - 작업자가 보낸 관리자 확인 요청 프레임 실시간 처리 가능

2. **다른 프레임 확인만 가능**
   - 관리자 확인 요청 프레임 외에 다른 프레임도 확인 가능하나 수정 불가능

3. **작업 이동 시 실시간 처리 불가**
   - 작업을 옮길 때는 프레임별 실시간 처리 불가능

## 10. 프로젝트 생성 및 관리 화면 (관리자)

### 10.1 프로젝트 생성 프로세스

**단계별 진행**

1. **프로젝트 정보 입력 (SKKLID-UI-03-02-04)**
   - 프로젝트명
   - 설명
   - 기간
   - 예산 정보

2. **단계 설정 (SKKLID-UI-03-02-09)**
   - 1단계: 데이터 가공 (1명의 작업자)
   - 2단계: 검수 (1차 검수자 1명 이상 + 2차 검수자 1명 이상)

3. **라벨 생성 (SKKLID-UI-03-02-04 ~ 08)**
   - 라벨명
   - 라벨 ID (영어, 숫자만 입력)
   - 가공 유형: 선택(default), 바운딩박스, 폴리곤, 스켈레톤, 키포인트
   - 색상 선택 (스켈레톤 제외)
   - 속성 입력

4. **권한 부여 (SKKLID-UI-03-02-10 ~ 11)**
   - 단계별 라벨러 선택
   - 한 단계의 작업자, 검수자는 초기 배정 시 한번에 선택
   - 1단계와 2단계는 따로 배정

2. **프레임 상태 관리**
   - 색상 기반 상태 표시 (주황색/빨간색/연두색)
   - 모든 프레임이 연두색(저장)이 되어야 제출 가능

3. **다단계 검수 구조**
   - 1차 검수자 → 2차 검수자로의 단계별 검수
   - 2차 검수자에게 반려된 건은 1차 검수자가 작업자에게 재반려 불가

4. **권한 기반 UI 표시**
   - 업로드/생성 등 일부 메뉴는 권한자만 표시
   - 권한 없으면 메뉴 자체가 노출되지 않음

### 14.2 AI 기능

1. **AI Tool (라벨링 자동화)**
   - 바운딩박스 또는 폴리곤으로 자동 라벨링

2. **오토 라벨링**
   - 선택한 항목에 대해 자동 라벨링 처리

3. **AI 이미지 생성**
   - Text to Image (프롬프트 기반)
   - Image to Image (참조 이미지 기반)
   - Image to Video (참조 이미지 기반)

4. **메타데이터 기반 생성**
   - 메타데이터 선택 시 자동 프롬프트 생성

### 14.3 라벨 생성 옵션

1. **가공 유형**
   - 선택(default): 단순 선택형 라벨
   - 바운딩박스: 사각형 영역 표시
   - 폴리곤: 자유형 다각형 표시
   - 스켈레톤: 관절 기반 골격 표시
   - 키포인트: 특정 포인트 표시

2. **스켈레톤 특수성**
   - 색상 선택 항목 없음
   - 키포인트 정의 필요
   - 각 관절(노드)에 이름 지정

3. **속성(Attributes)**
   - 라벨과 연관된 속성 입력 가능
   - 작업자 화면에 선택 옵션으로 노출
   - 프로젝트 생성 시 정의

### 14.4 데이터 상태 분류

**작업자 관점**
- 배정 완료: 신규 배정
- 임시 저장: 저장된 프레임
- 검수 요청: 검수자에게 제출
- 검수 반려: 반려된 상태
- 임시 승인: 임시 승인된 프레임
- 관리자 확인 요청: 관리자 확인 대기 중

**업로드/생성**
- 업로드: 파일 업로드
- 생성: AI 기반 생성

**데이터 형태**
- Image: 이미지
- Video: 동영상

### 14.6 기타 주요 사항

1. **권한 부여 방식**
   - 한 단계의 작업자, 검수자(N차)는 초기 배정 시 한번에 선택
   - 1단계와 2단계는 따로 배정 가능
   - 프로젝트담당자가 작업자/검수자 권한도 부여 가능

2. **프로젝트 완료 처리**
   - 프로젝트가 '완료' 처리될 경우
   - 사용자(라벨러)의 프로젝트 화면에서 해당 프로젝트 미노출

3. **데이터 배정 정책**
   - 기존 데이터 10개 이하: 새로 15개 배정
   - 기존 데이터 11개 이상: 배정 불가 (기존 데이터 먼저 처리 필요)
   - 배정할 데이터가 15개 이하: 남은 데이터 전체 배정

4. **우선순위 배정**
   - 1단계-가공, 2단계-가공 권한 모두 보유: 1단계-가공 우선
   - 1단계-가공, 1단계-검수 권한 모두 보유: 1단계-가공 우선

5. **페이지 재진입**
   - 연습장: 재진입 시 저장된 화면 노출
   - 대시보드: 재진입 시 default 프로젝트로 자동 이동

## 17. 종합 분석 및 결론

### 17.1 시스템의 특징

1. **복합 권한 관리**
   - 작업자/검수자/관리자의 3단계 구조
   - 프로젝트담당자의 중간 관리자 역할
   - 업로더의 AI 기반 데이터 생성 기능

2. **유연한 작업 흐름**
   - 프레임 단위 작업
   - 실시간 관리자 확인 요청
   - 반려/승인의 명확한 상태 표시

3. **AI 기반 자동화**
   - AI Tool을 통한 라벨링 자동화
   - 텍스트/이미지 기반 이미지/동영상 생성
   - 메타데이터 기반 자동 프롬프트 생성

4. **포괄적인 프로젝트 관리**
   - 상세한 통계 기능
   - 권한별 작업량 추적
   - 프로젝트별 데이터 현황 관리

### 17.2 주요 사용자 시나리오

**작업자 시나리오**
1. 로그인 → 대시보드 확인
2. 프로젝트 선택 → 배정된 데이터 조회
3. 데이터 작업 (라벨링/바운딩박스 등)
4. 저장 또는 관리자 확인 요청
5. 모든 프레임 완료 → 검수자에게 제출

**검수자 시나리오**
1. 로그인 → 대시보드 확인
2. 프로젝트 선택 → 검수 대기 데이터 조회
3. 프레임별 검수 (승인/반려)
4. 반려 사유 입력 또는 승인 처리
5. 검수 완료

**관리자 시나리오**
1. 로그인 → 대시보드 (담당/작업 프로젝트)
2. 프로젝트 생성 (라벨, 권한 부여)
3. 사용자 관리
4. 작업자의 관리자 확인 요청 실시간 처리
5. 통계/현황 조회

### 17.3 추가 개선 사항 (문서 내용)

1. **단축키 정리**
   - 추후 단축키 상세 정리 필요 (문서에 명시)

2. **Google Form 참고**
   - 라벨 설정 관련 화면은 Google Form 참고 (SKKLID-UI-03-02-05, 06)

3. **하드코딩 요소**
   - 연습장 이미지는 하드코딩 (변경 시 코드 수정 필요)
