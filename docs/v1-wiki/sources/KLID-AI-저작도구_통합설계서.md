## 1. 시스템 개요

### 1.1 목적

학습 저작도구(Authoring Tool)는 지자체 CCTV 영상에서 추출한 프레임 이미지를 기반으로 **AI 학습용 어노테이션 데이터를 제작·관리·검수**하는 핵심 서브시스템이다. 작업자가 이미지에 라벨을 부착하고 검수자가 품질을 검증하는 전 과정을 관리하며, 최종적으로 AI 모델 학습에 투입 가능한 정제 데이터셋을 생성한다.

### 1.2 전체 시스템 위상

```
지자체 통합관제센터 (서울 관악구 / 경기 안양시 / 강원 원주시 / 제주 등)
        ↓ 이벤트 + 클립영상
지자체 중계서버
        ↓
Ingest Server  ──────────────────────────────────────────────────┐
        ↓                                                         │
control-hub 관제지원시스템                                         │
    ├─ Clip NAS (클립영상 저장)                                    │
    ├─ 비식별화 서버                                               │
    └─ ★ 학습 저작도구 ★  ←──────────────────────────────────────┘
            ↓
        AI 학습 데이터셋 → 침수·화재·교통 탐지 AI 모델
```

### 1.3 저작도구 핵심 파이프라인

```
클립영상 수신
    ↓
프레임 자동 추출 (FFmpeg Batch)
    ↓
이미지 전처리 (리사이징, 밝기/대비 자동 보정)
    ↓
작업자 라벨링 작업 (바운딩박스 / 폴리곤 / 스켈레톤 / AI Tool)
    ↓
1차 검수 → 승인 or 반려
    ↓
2차 검수 → 승인 or 반려
    ↓
데이터 증강 (선택: 밝기·반전 5종)
    ↓
데이터마트 등록 / AI 모델 학습 투입
```

## 2. 사용자 역할 및 권한

### 2.1 역할 분류

시스템은 **라벨러(운영자)**와 **관리자** 두 그룹으로 구분되며, 각 그룹 내에 세부 역할이 존재한다. 동일 아이디로 여러 권한의 중복 보유가 가능하다.

#### 라벨러 그룹

| 역할 | 핵심 권한 |
|------|----------|
| **작업자** | 배정된 프레임에 라벨링 작업 수행, 완료 후 검수 요청 제출 |
| **검수자(1차)** | 작업자 제출 결과 검토, 승인 또는 반려 처리 |
| **검수자(2차)** | 1차 검수 완료 결과 최종 검토, 승인 또는 반려 처리 |
| **업로더** | 영상·이미지 업로드 및 AI 생성 데이터 등록 |

#### 관리자 그룹

| 역할 | 핵심 권한 |
|------|----------|
| **슈퍼 관리자** | 전체 시스템 접근, 프로젝트 전체 관리, 사용자 관리 |
| **프로젝트 담당자** | 할당받은 프로젝트만 생성·관리, 권한 부여 |
| **업로더(관리자)** | AI 동영상·이미지 생성 및 업로드 |

### 2.2 메뉴별 접근 권한

#### 라벨러 그룹

| 메뉴 | 작업자 | 검수자 | 업로더 |
|------|:------:|:------:|:------:|
| 대시보드 | O | O | - |
| 프로젝트 관리 | O | O | - |
| 게시판 | O | O | O |
| 연습장 | O | O | O |
| 업로드/생성 | O(권한 시) | - | O |

#### 관리자 그룹

| 메뉴 | 슈퍼 관리자 | 프로젝트 담당자 | 업로더 |
|------|:----------:|:--------------:|:------:|
| 대시보드 | O (전체) | △ (담당 프로젝트) | - |
| 프로젝트 관리 | O | △ | - |
| 영상/이미지 관리 | O | O | - |
| 업로드/생성 데이터 관리 | O | O | - |
| 게시판 | O | O | O |
| 연습장 | O | O | O |
| 업로드/생성 | O | O(업로더 권한 시) | O |

> **슈퍼 관리자**: 권한 부여 없이 모든 화면 접근 가능, 아이디 노출 안 됨  
> **프로젝트 담당자**: 자신이 생성한 프로젝트만 수정 가능

### 2.3 프로젝트 내 권한 조합

프로젝트 담당자는 특정 프로젝트에서는 담당자 권한, 다른 프로젝트에서는 동시에 작업자·검수자 권한 보유 가능. 업로더는 게시판(열람 전용), 연습장, 업로드/생성 메뉴만 접근 가능.

## 4. 프로젝트 관리

### 4.1 프로젝트 생성 (5단계)

프로젝트는 학습 데이터셋 구축의 기본 단위이며, 모든 데이터·라벨·사용자는 프로젝트 ID 기준으로 연계된다.

#### Step 1. 기본 정보 입력

| 필드 | 필수 | 제약 |
|------|:----:|------|
| 프로젝트명 | O | - |
| 프로젝트 아이디 | O | 영문·숫자만, 중복체크 필수 |
| 프로젝트 설명 | X | 목록에 노출 |
| 목표 데이터 수량 | O | 숫자만 |
| 도움말 | X | 라벨러 화면에서 표시 |

#### Step 2. 메타 생성

라벨링 시 프레임에 입력할 메타데이터 항목 정의.

| 항목 | 설명 |
|------|------|
| 메타 아이디 | 영문·숫자만 |
| 질의문 | 라벨러에게 보여줄 질문 |
| 입력 형식 | 텍스트 입력 or 라디오 버튼 |

#### Step 3. 라벨 생성

| 필드 | 필수 | 설명 |
|------|:----:|------|
| 라벨명 | O | 라벨러가 사용할 범주명 |
| 라벨 아이디 | O | 영문·숫자만 |
| 라벨 형태 | O | 바운딩박스 / 폴리곤 / 스켈레톤 중 선택 |
| 라벨 색상 | X | 라벨러 화면 표시 색상 (HEX) |
| 속성 | X | 라디오 버튼 또는 텍스트 형식 세부 분류 |

**스켈레톤 라벨 추가 설정** (라벨 형태 = 스켈레톤일 때만):

| 필드 | 설명 |
|------|------|
| 포인트명 | 머리, 왼쪽어깨 등 관절명 |
| 포인트 ID | 영문·숫자만 |
| 포인트 색상 | 각 포인트 색상 지정 |

스켈레톤 작성 도구: 수정/편집 · 파일 업로드 · 포인트 · 이동 · 선 그리기 · 삭제

#### Step 4. 단계 설정

기본 프로세스: `1단계 가공 → 1차 검수 → 2차 검수`

| 확장 옵션 | 구성 |
|----------|------|
| 검수 추가 | 1단계 가공 → 1차 검수 (최소) |
| 단계 추가 | 1단계 가공 → 1차 검수 → 2단계 가공 → 2차 검수 (최대 2단계) |

#### Step 5. 권한 부여

- "사용자 추가" → 작업자 아이디 선택(중복 가능) + 권한 선택
- 권한 삭제·수정, 비고 더블클릭 입력
- 건너뛰기 후 프로젝트 상세에서 추가 가능
- 프로젝트 담당자·업로더는 단계 추가 시 2단계에 자동 추가

### 4.2 프로젝트 완료 처리

| 액션 | 결과 |
|------|------|
| **완료** 버튼 클릭 + 버전 설명 입력 | 작업자 접근 차단, 상태 → 마감 |
| **완료취소** 버튼 클릭 + 버전 상향 | 작업자 재접근 허용, 상태 → 진행 |

### 4.3 영상/이미지 배정

- 리스트 체크박스 선택 → "프로젝트 배정" 클릭 → 프로젝트 선택 팝업 → 단일 선택 후 배정 확정
- 영상 처리는 시스템 자원 집중 소모 → **1건씩 배치 처리**로 구현 필수
- 데이터 보유 10개 이하인 경우 "작업배정" 버튼으로 최대 1개 자동 배정

### 4.4 데이터 자동 배정 정책

작업자가 보유 데이터 10개 이하일 때 "작업배정" 버튼 클릭 → 프로젝트에서 최대 1개 클립 자동 배정.

## 5. 영상 수집 및 프레임 추출

### 5.1 이벤트 및 클립 수신 구조

| 구성 요소 | 역할 |
|----------|------|
| Ingest Server | 지자체 중계서버로부터 이벤트 JSON(RestAPI) 및 클립 영상 수신 |
| 룰셋(Rule Set) | 수신 이벤트 중 필요한 이벤트 필터링 처리 |
| 수집 스케줄 | 이벤트에 따른 클립 영상 수집 시간 정의 |
| 전송 스케줄 | control-hub로의 전송 시간 정의 |

### 5.2 프레임 자동 추출 (FFmpeg Batch)

인터페이스 ID: `KLID-AI-II-001 / II-002` (Batch, 1회/분)

```
[배치 프로그램] 1분마다 데이터 변환 매핑 테이블 조회
    ↓ (원본 영상 경로, 요청 FPS, 프로젝트 ID)
이미지변환 API 요청 전송 → 원본 파일 존재 여부 검증
    ↓
프로젝트 ID 디렉토리 생성
    ↓
FFmpeg로 지정 FPS에 따라 프레임 추출
    (파일명: frame_0001.png, frame_0002.png ... 자동 증가)
    ↓
매핑 테이블 상태 업데이트 (완료 / 실패 + 오류 로그)
```

**추출 방식 파라미터**:

| 파라미터 | 설명 |
|----------|------|
| 원시데이터 고유번호 | 원본 영상 식별자 |
| 비디오 추출 여부 | Boolean |
| 실제 영상 파일 경로 | 스토리지 경로 |
| 추출 시작/종료 시간 | 구간 설정 |
| 프레임 추출 방식 | FPS 또는 타임스탬프 |

**상태 응답 (II-002)**:

### 7.4 라벨링 도구 유형별 상세

#### 바운딩 박스 (Bounding Box)

- 용도: 객체 탐지, 기본 위치 표시
- 방법: 시작점 클릭 → 마우스 이동 → 대각선 끝점 클릭 (2회 클릭으로 완성)
- 우측 객체 탭에서 속성 정보 선택

#### 폴리곤 (Polygon)

- 용도: 정밀한 객체 영역 분할
- 방법: 시작점 클릭 → 테두리를 따라 다점 클릭 → 시작점 재클릭으로 닫힘
- 편집: Shift+클릭으로 점 수정, Ctrl+클릭으로 점 삭제

#### 스켈레톤 (Skeleton)

- 용도: 사람 관절 포즈 탐지
- 방법: 시작점 클릭 → 대각선 끝점 클릭 → 스켈레톤 자동 생성 → 각 포인트 위치 조정
- 포인트명은 프로젝트 설정 시 정의됨

#### 블러 (Blur) / 비식별화

- 용도: 얼굴, 번호판, 전화번호 등 개인정보 보호
- 방법: 비식별화 아이콘 클릭 → 브러쉬/지우개 크기 설정 → 대상 영역 드래그
- **반드시 다른 라벨링 전에 먼저 수행**

#### 그리드 (Grid)

- 용도: 정확한 좌표 선택 지원용 보조선
- 방법: 그리드 아이콘 클릭 시 이미지에 격자 노출

## 8. AI 보조 라벨링

### 8.1 AI Tool (클릭 세그멘테이션 — SAM 방식)

인터페이스 ID: `KLID-AI-II-003 ~ II-006` (Online, 수시)

라벨러가 객체 일부만 클릭해도 자동으로 객체 경계를 탐지하는 AI 기반 도구.

**동작 방식**:
1. 좌측 AI Tool 아이콘 클릭
2. 라벨링 형태 및 라벨명 선택
3. 라벨링할 객체의 일부분 클릭
4. 객체가 완전히 포함될 때까지 추가 클릭
5. 우측 객체 탭에서 "생성" 버튼 클릭

**버튼 모드**:
- **일반**: 해당 프레임에만 라벨 생성
- **트랙**: 최초 프레임부터 마지막 프레임까지 자동 추적 생성. 마지막 프레임에서 위치·크기 수정 시 '트래킹' 버튼 활성화 → 중간 프레임 자동 재계산 (사용자 직접 수정 프레임 제외)

### 8.2 Auto Labeling (오토 라벨링 — YOLO 방식)

특정 객체(사람, 자전거, 자동차, 오토바이, 버스, 트럭 등)를 자동으로 탐지하여 라벨 생성.

**동작 방식**:
1. 좌측 Auto Labeling 아이콘 클릭
2. 라벨링 형태, 객체 종류, 라벨명 선택
3. 자동 라벨링 완료 → 우측 객체 탭에서 속성만 선택

**버튼 모드**:
- **일반**: 해당 프레임에만 라벨 생성
- **트랙**: 연속 프레임 자동 추적, 트래킹 버튼으로 중간 프레임 재계산

### 8.3 트랙 모드 (선형보간 자동화)

인터페이스 ID: `KLID-AI-II-007` (Online, 수시)

연속된 프레임에 등장하는 객체를 효율적으로 라벨링하는 핵심 기능.

```
[최초 프레임] 트랙 라벨 생성
        ↓ 자동으로 모든 프레임에 동일 위치/크기 라벨 생성
[중간 프레임들] 자동 라벨 (수정 가능)
        ↓
[마지막 프레임] 위치/크기 수정 → '트래킹' 버튼 활성화
        ↓
선형보간(Linear Interpolation) 알고리즘으로 중간 프레임 자동 재계산
```

**트랙 관리**:

| 기능 | 설명 |
|------|------|
| 트랙 고유 번호 | 생성 시 자동 배정, 상단 표시 |
| 삭제 아이콘 | 해당 프레임부터 뒤 프레임의 트랙 라벨 삭제 (객체 소멸 시) |
| 변경 버튼 | 트랙 번호 변경으로 가려졌다 재등장한 객체를 하나의 트랙으로 연결 |

**트랙 데이터 구조** (II-007):
```json
{
  "tracking_list": [
    {
      "tracking_id": "string",
      "frame_no": number,
      "image_path": "string",
      "coordinates": { "x": number, "y": number, "width": number, "height": number },
      "is_track_frame": boolean
    }
  ]
}
```

## 9. 검수 워크플로우

### 9.1 전체 흐름

```
[작업자] 라벨링 작업
    ↓ 모든 프레임 저장 완료 (모두 연두색)
    ↓ 제출
[1차 검수자] 프레임별 검토
    ↓ 승인 or 반려
[2차 검수자] 최종 검토
    ↓ 승인 → 작업 완료
    ↓ 반려 → 1차 검수자에게 반환 (단, 2차 반려 건은 1차가 작업자에게 재반려 불가)
```

### 9.2 프레임 테두리 색상 체계

| 색상 | 상태 | 의미 |
|------|------|------|
| **연두색** | 저장됨 | 정상 처리된 프레임 |
| **주황색** | 반려됨 | 재작업 필요 프레임 |
| **빨간색** | 관리자확인요청 | 관리자에게 확인 요청 중 |
| *(모두 연두색)* | 제출 가능 | 모든 프레임이 연두색일 때만 검수 제출 가능 |

### 9.3 역할별 작업 제약

#### 작업자

- 관리자 확인 요청 프레임이 없고 **모든 프레임 저장** 완료 시 제출 가능
- 반려된 프레임만 재작업 가능 (승인된 프레임은 볼 수만 있음)
- 관리자 확인 요청 프레임은 처리 후 실시간으로 반환

#### 검수자(1차)

- 반려는 개별 프레임 단위로 처리
- 마지막 프레임에서 '제출' 클릭 시 반려 완료
- 2차 검수자에게 반려된 건은 작업자에게 재반려 불가

#### 검수자(2차)

- 관리자 확인 요청 프레임 없을 때 반려/검수 완료 처리 가능

#### 관리자

- 관리자 확인 요청 프레임만 처리 가능
- 다른 프레임은 확인 가능하나 수정 불가

### 9.4 이력 관리 항목

| 이력 유형 | 설명 |
|----------|------|
| 작업자 작업 제출 이력 | 제출 일시, 작업자 ID |
| 검수자 승인 이력 | 승인 일시, 검수자 ID |

| 관리자 확인 요청 이력 | 요청·처리 이력 |
| 학습 라벨 / 원천 / 메타 데이터 변경 이력 | 전체 변경 내역 (감사 추적용) |

## 11. 데이터 증강 및 내보내기

### 11.1 데이터 증강 (Augmentation)

완료되지 않은 프로젝트의 최종완료 라벨링 데이터에 대해 5종 증강 처리.

| 증강 종류 | 처리 내용 |
|----------|----------|
| 밝게 | Brightness + |
| 어둡게 | Brightness - |
| 좌우반전 | Horizontal Flip |
| 좌우반전 + 밝게 | Horizontal Flip + Brightness + |
| 좌우반전 + 어둡게 | Horizontal Flip + Brightness - |

**증강 상태 흐름**:
```
증강가능 → 대기 → 진행중 → 완료 / 부분성공 / 실패
```

| 상태 | 설명 |
|------|------|
| 증강가능 | 최종완료 데이터 있고 프로젝트 미마감 |
| 대기 | 증강 요청 후 큐 대기 |
| 진행중 | 처리 중 |
| 완료 | 전체 성공 |
| 부분성공 | 일부만 성공 |
| 실패 | 전체 실패 |

DB 테이블: `LS_DATA_AUG` — 에러코드, 에러메시지, 재시도횟수(`RTRY_CNT`), 최종시도일시 포함 → 자동 재처리 메커니즘 지원.

### 11.2 학습 데이터 내보내기

```
데이터 업로드
    ↓ 용도 선택
    ├── [학습 용도] → 학습 영상 경로로 파일 이동 → 기존 영상 학습 로직 처리
    └── [데이터마트 등록]
            ├── 신규 데이터셋: 데이터셋 목록 추가 → 마트용 경로로 이동 → 마트 등록
            └── 기존 데이터셋 추가: 기존 데이터셋에 추가 → 버전 상승 → 마트 재등록
```

**데이터 분류 기준**:

| 분류 항목 | 분류 기준 |
|----------|----------|
| 데이터 유형 | 이미지 / 영상 / AI 모델 |
| 데이터 가공 유형 | 원천 / 학습 |
| 개인정보 처리 | 비식별화 여부 (`PRVC_YN`) |

## 12. 생성형 AI 연동 (업로드/생성)

### 12.1 AI 이미지/동영상 생성

실데이터 부족 시 생성형 AI로 학습 데이터 보강.

| 생성 방식 | 설명 |
|----------|------|
| Text to Image | 프롬프트 입력으로 이미지 생성 |
| Image to Image | 기존 이미지 기반으로 변형 이미지 생성 |
| Image to Video | 이미지 기반 동영상 생성 |
| 메타데이터 기반 생성 | 계절·날씨·시간대·비식별 여부 등 메타 조건으로 데이터 증강 |

**생성 파라미터**:

| 파라미터 | 타입 | 설명 |
|----------|------|------|
| 적용 프로젝트 | String | 프로젝트 ID |
| 날씨 | String | 맑음 / 흐림 / 비 / 눈 등 |
| 계절 | String | 봄 / 여름 / 가을 / 겨울 |
| 비식별 여부 | Boolean | PII 처리 여부 |
| 생성시작일 | Date | 데이터 생성 시작 날짜 |

**생성 결과 응답**:

| 파라미터 | 타입 | 설명 |
|----------|------|------|
| 영상/이미지명 | String | 파일명 |
| 이벤트 유형 | String | 이벤트 타입 |
| 생성일 | DateTime | 생성 일시 |
| 시간대 | String | 야간 / 주간 등 |
| 개인정보 포함 여부 | Boolean | PII 여부 |
| AI 생성 여부 | Boolean | 합성 데이터 식별 (`AI_CRT_YN`) |

### 12.2 생성 데이터 관리 흐름

1. 업로더가 AI 생성 또는 파일 업로드
2. 관리자가 "업로드/생성 데이터 관리" 메뉴에서 검토
3. 승인 후 학습 데이터 원시데이터로 등록 → 이후 프로젝트 배정 가능

| 클릭 세그멘테이션 | SAM (Segment Anything Model) |
| 침수 탐지 모델 | UperNet + ViT-Adapter |
| 하이퍼파라미터 튜닝 | Random Search |
| 성능 평가 지표 | Confusion Matrix, mAP, IoU |

### 16.3 코드 관리 정책

**브랜치 전략**:

| 브랜치 | 역할 |

**배포 전략**:

### 17.2 작업자 리스트 정렬 우선순위

```
반려 > 작업중 > 배정 > 관리자 확인 요청 > 보류 → 이후 날짜 순 → 동일 날짜 시 ID 내림차순
```

### 17.3 날짜 선택

- 표기 형식: `YYYY-MM-DD`
- 직접 입력 불가, 캘린더(date picker) 선택만 가능
- 시작일 > 종료일인 경우 자동 변경

### 17.4 공통 UI 원칙

- 권한 없는 메뉴는 **메뉴 자체 미노출** (비활성화 아님)
- 선택박스 디폴트: 항목명 또는 '선택' 표시
- 입력박스 클릭 시 안내문구 사라지고 커서 노출
