## 2.1 control-hub 중심 도메인 아키텍처

시스템 전체는 **control-hub**를 중심으로 여러 도메인으로 구성된다.

| 도메인 | 역할 |
|--------|------|
| **Ingest Server Domain** | 지자체 중계서버로부터 이벤트 정보 및 클립 영상 수신 |
| **Clip Domain** | 클립 영상 저장 및 관리 |
| **ExServer Manager Domain** | Ingest 서버 관리 및 연동 |
| **Account Domain** | 사용자 계정 및 권한 관리 (GPKI 인증 연동) |
| **DataSet Domain** | 학습 데이터셋 구성 및 관리 |
| **Resource-Mng Domain** | 리소스 관리 및 운영 현황 관리 |
| **Business-Support Domain** | 지자체 업무지원 서비스 |

데이터 흐름은 [01 §1.2](01-system-overview.md#12-전체-시스템-위상) 참고.

## 2.2 서브시스템(프로그램) 구성

| 서브시스템 | 프로그램 ID | 환경 | 역할 |
|----------|-----------|------|------|
| 저작도구 WEB | `KLID-AI-PF-001` | WEB | 사용자 인터페이스, 대시보드 |
| 저작도구 API | `KLID-AI-PF-002` | API | REST API, 인증, 외부 연동 |
| 저작도구 BATCH | `KLID-AI-PF-003` | BATCH | 프레임 추출, 대량 처리, 통계 집계 |
| 저작도구 핵심 | `KLID-AI-PF-004` | - | ML 모델 관리, 데이터 전처리, 특성 추출 |
| 영상분할 | `KLID-AI-PF-005` | - | 객체 탐지, 시맨틱/인스턴스 분할, 트래킹 (GPU) |
| 오토라벨링 | `KLID-AI-PF-006` | - | YOLO 기반 자동 분류, 신뢰도 점수 계산 |

### 환경별 특징

- **WEB(PF-001)**: 브라우저 기반 반응형 웹. 프로젝트 관리/업로드/라벨링 작업 관리/통계.
- **API(PF-002)**: REST API 기반. 마이크로서비스. 데이터 조회·저장, 실시간 처리 요청, 인증/권한, 외부 연동.
- **BATCH(PF-003)**: 스케줄링 기반 자동 처리. 프레임 추출, 대량 라벨링, 데이터 정제·검증, 통계 집계.

## 2.3 저작도구 기능 구성 (기능 트리)

```
저작도구 (Authoring Tool)
├─ 프로젝트 관리           → 05
│   ├─ 생성/수정/삭제, 독립 작업 공간
│   ├─ 라벨(Class)·속성(Attribute) 관리
│   └─ 사용자 권한 관리(관리자/작업자/검수자)
├─ 영상 수집 및 프레임 추출 → 06
│   ├─ 클립 목록 조회·필터링, 프로젝트 배정
│   ├─ 프레임 자동 추출(FFmpeg)
│   └─ 이미지 자동 분류·저장
├─ 이미지 전처리           → 06
│   ├─ 해상도 자동 리사이징, 밝기/대비 자동 보정
│   └─ UI 기반 수동 조정
├─ 라벨링 도구             → 07
│   ├─ 바운딩박스/폴리곤/키포인트(스켈레톤)
│   ├─ 속성 입력, 객체 복사/붙여넣기
│   └─ Track 모드(선형보간)
├─ AI 보조 라벨링          → 08
│   ├─ 오토 라벨링(YOLO)
│   └─ 클릭 세그멘테이션(SAM)
├─ 검수 관리               → 09
├─ 진행 현황 관리          → 10
└─ 학습 데이터 내보내기    → 11
```

## 2.4 패키지 / 클래스 구조

```
KLID-AI System
├── Common (공통)
│   └── CmCodeController       — 공통 코드 관리
├── User Management (사용자)
│   └── UserController         — 인증·권한 관리
├── Data Management (데이터)
│   ├── VideoImageData         — 영상/이미지 데이터 관리
│   └── ProjectData            — 프로젝트 데이터 관리
├── Project (프로젝트)
│   └── Project                — 프로젝트 CRUD
└── Processing (처리)
    ├── AutoLabeling           — YOLO 기반 자동 라벨링
    ├── Prompt                 — 생성형 AI 프롬프트
    └── VideoSegmentation      — 비디오 분할/추출
```

### 주요 클래스 관계 (클래스설계서)

- **상속**: 데이터 관리 클래스들은 공통 기본 클래스에서 상속
- **의존성**: `UserController`(인증/권한), `CmCodeController`(공통 코드)
- **연관**: 프로젝트 ↔ 프로젝트 데이터(1:N), 영상/이미지 ↔ 프롬프트(N:M), 프로젝트 ↔ 오토라벨링(1:1)

### 주요 시퀀스 도메인 (클래스설계서 §1)

클립 영상 검색 · 프레임 자동 추출 · 이미지 생성/분류 관리 · 수집 이미지 자동조절(밝기/대비) · 이미지 설명 작성 · 학습용 데이터 제작 · 검수 관리 · 라벨/속성 관리 · 객체 추적/복사 · 진행상황/이력 · 테스트 제작 · 오토 라벨링 · 생성형 프롬프트

### 설계 기술 특징

1. **Controller-based Architecture** — 도메인별 Controller 패턴
2. **Data-driven Design** — 데이터 중심 설계
3. **Modular Design** — 기능별 독립 모듈
4. **Reusability** — 공통코드·기본 클래스로 재사용성 극대화

## 2.5 배포 · 코드 관리 (코드규격서)

**브랜치 전략**: `main`(프로덕션) / `develop`(통합) / `feature/*` / `hotfix/*`
**코드 리뷰**: 모든 변경 PR 필수, 최소 2명 승인, 자동 테스트 통과
**배포**: 개발=자동(main), 스테이징=수동 승인, 프로덕션=관리자 승인 + 롤백 계획
**빌드 프로세스**: 컴파일/검증 → 단위 테스트 → 정적 분석(Lint, SonarQube) → 통합 테스트 → 아티팩트 생성
**제출**: Git 버전관리 + Docker 패키징 + requirements.txt/package.json + 라이선스 명시

> **v2 참고**: v2는 모노레포(단일 git, backend/ + ai-server/ + frontend/), Spring Boot 레이어드 아키텍처(Controller→Service→Repository). v1의 `*Controller` 단일 클래스 집약 구조와 다르다. v1 PF-005/006(영상분할·오토라벨링)에 해당하는 추론은 v2에서 `ai-server`(YOLO/SAM2)로 분리되어 stateless로 운영된다.

## 2.6 컴포넌트 설계서 비고

컴포넌트설계서(V1.0)는 **"지능형 스마트 선별관제 시스템"** 명의의 상위/선행 문서로, 영상 수집·AI 분석·데이터 관리·UI·시스템 관리 5개 컴포넌트와 마이크로서비스/이벤트-드리븐/계층화 아키텍처 패턴을 정의한다. 원본 HWP의 다이어그램은 텍스트 추출이 불완전하다(원본 참조 필요). 상세 메타는 [17 원본 문서 카탈로그](17-source-documents.md) 참고.
