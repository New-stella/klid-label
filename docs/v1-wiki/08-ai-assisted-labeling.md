## 8.1 AI Tool (클릭 세그멘테이션)

인터페이스: `KLID-AI-II-003 ~ II-006` (Online, 수시) — **원문 미확인**(위 안내 참고). 화면: `SKKLID-UI-02-02-04~09` 연속 스토리보드 내(개별 화면ID를 05로 단정할 근거는 OCR 열 뒤섞임으로 확정 못함 — 확인 불가로 남김).

라벨러가 객체 일부만 클릭해도 자동으로 객체 경계를 탐지.

**동작** (근거: `02-관리자매뉴얼.txt 4.3.4` · `03-UI설계서V1.1.txt` SC-004 "(3) AI Tool"):
1. 좌측 AI Tool 아이콘 클릭 → 라벨링 형태(바운딩박스 default / 폴리곤)·라벨명(속성 포함)을 고르는 팝업 노출
2. 원하는 항목 선택 후 라벨링할 객체의 일부분 클릭
3. 객체가 완전히 포함될 때까지 포함되지 않은 부분을 계속 클릭 (객체 클릭 후 인식하는 동안 화면 비활성화, 연달아 클릭 불가능, 생성 전까지 라벨·속성 변경 불가능)
4. 우측 객체 탭에서 "생성" 클릭 (완료) — "취소" 클릭 시 해당 객체/라벨 삭제
5. 일반/트랙 선택 → 트랙 모드에서 AI Tool 로 생성한 라벨의 "번호"를 변경하면 다음 프레임에 일괄 적용

> ⚠ **구 서술 폐기(2026-08-19 원문 실측)** — *"연결 불가능한 영역 선택 시 객체 탐지 오류 발생 (아키텍처설계서 §5.4)"* 는 1차 원문 3종 어디에도 없다(§5.4 라는 절 자체가 이번 대조 대상 3종에 없음) — 확인 불가로 남긴다.
> 화면 순서 참고(SAM 방식이라는 명칭 자체도 세 원문에 등장하지 않으며, 이 위키가 판단해 붙인 별칭이다 — 삭제하지 않되 "클릭 기반 세그멘테이션"으로만 원문에서 확인됨을 명시).

## 8.2 Auto Labeling (오토 라벨링)

인터페이스: `KLID-AI-II-003 ~ II-006` (AUTO-LABEL, Online) — **원문 미확인**. 화면: `SKKLID-UI-02-02-04~09` 연속 스토리보드 내(정확한 개별 화면ID 확인 불가).

> ⚠ **탐지 가능 객체 종류가 원문 간 서로 다르다 — 병기하지 말고 불일치로 표기한다.** `02-관리자매뉴얼.txt 4.3.5`는 *"사람, 자전거, 자동자(원문 오탈자로 추정 — 자동차), 오토바이, 버스, 트럭 등 일부 객체"* 라고 6종을 적는다. 반면 `01-UIUX설계서.txt`(화면ID `SKKLID-UI-02-02-09` 인근, 오토 라벨링 세부 기능 박스 주석)와 `03-UI설계서V1.1.txt`(SC-004 "(4) 오토 라벨링")는 **서로 일치**하는 다음 문구를 적는다: *"항목(단일선택): 사람(default), 자동차, 자전거 선택"* — **3종뿐**이다. 세 원문 중 2종(스토리보드+UI설계서)이 서로 일치하고 매뉴얼만 6종을 적어, 매뉴얼 쪽이 향후 확장 계획을 앞서 적었거나 매뉴얼 개정 시점에 범위가 넓어졌을 가능성이 있으나 **어느 쪽이 최종 확정인지는 이번 원문만으로 판정 불가**.

**동작** (근거: `02-관리자매뉴얼.txt 4.3.5` · `03-UI설계서V1.1.txt` SC-004 "(4) 오토 라벨링"):
1. 좌측 Auto Labeling 아이콘 클릭 → 라벨링 형태(바운딩박스 default/폴리곤)·탐지 객체 종류·라벨명을 고르는 팝업 노출
2. 원하는 항목 선택(순서: 작업 클릭 → 항목 클릭 → 라벨 선택 → 트랙/일반 선택) → 자동으로 선택 객체의 라벨링 완료
3. 우측 객체 탭에서 속성 정보만 직접 선택하면 작업 완료
4. 트랙 모드에서 오토 라벨링 후 "번호"를 변경하면 다음 프레임에 일괄 적용
5. ⚠ `03-UI설계서V1.1.txt` SC-004 는 "오토 라벨링은 매 프레임 진행해야 함"이라는 문구를 별도로 못박고 있다. 바로 앞 §8.3 의 "트랙" 모드 설명(첫/마지막 프레임만 설정하면 중간이 자동 계산됨)과 어떻게 양립하는지는 원문만으로 명확히 갈리지 않는다 — **원문 미확인**으로 남기고 두 문장을 그대로 병기한다(하나를 임의로 삭제하지 않음).

## 8.3 일반 / 트랙 버튼 모드

AI Tool · Auto Labeling · 바운딩박스 · 폴리곤 공통(근거: `02-관리자매뉴얼.txt` 4.3.4·4.3.5·4.3.6·4.3.7 각 절이 동일한 "일반"/"트랙" 버튼 설명을 반복):

| 모드 | 동작 |
|------|------|
| **일반** | 해당 프레임에만 라벨 생성 (연속되지 않은 객체를 라벨링할 때 사용) |
| **트랙** | 최초 프레임~마지막 프레임 자동 추적 생성. 마지막 프레임에서 위치/크기 수정 시 '트래킹' 버튼 활성화 → 첫 프레임과 마지막 프레임 사이 프레임들의 라벨을 자동 계산해 위치/크기 변경 (**사용자가 직접 작업(수정)한 프레임은 자동으로 계산되지 않음**) |

> ⚠ **구 서술 정정 — 스켈레톤 포함 여부가 원문 간 다르다.** `02-관리자매뉴얼.txt` 4.3.8(스켈레톤)에는 일반/트랙 버튼 설명이 **없다**(스켈레톤 절 전체에 "일반"·"트랙" 단어 자체가 등장하지 않는다). 반면 `03-UI설계서V1.1.txt` SC-003(라벨링 도구)은 스켈레톤에도 "일반/트랙 버튼으로 생성 방식 선택 (트랙 O)"라고 명시적으로 트랙 지원을 적는다. 이 위키의 "AI Tool·Auto Labeling·바운딩박스·폴리곤 공통"(스켈레톤 제외) 서술은 매뉴얼 쪽과는 맞지만 UI설계서와는 어긋난다 — 두 원문이 갈리는 지점이라 **어느 쪽이 최종인지 확정 불가**로 남긴다. 근거: `02-관리자매뉴얼.txt 4.3.8` · `03-UI설계서V1.1.txt` SC-003.

## 8.4 Track 모드

화면: `SKKLID-UI-02-05-08`(→ [07 §7.8 객체 추적 및 복사](07-labeling-tools.md)와 동일 기능의 다른 이름). 인터페이스 `KLID-AI-II-007` — **원문 미확인**(§8.1 안내 참고).

연속 프레임에 등장하는 객체를 효율적으로 라벨링하는 핵심 기능.

```
[최초 프레임] 트랙 라벨 생성
        ↓ 모든 프레임에 동일 위치/크기 라벨 자동 생성
[중간 프레임들] 자동 라벨 (수정 가능)
        ↓
[마지막 프레임] 위치/크기 수정 → '트래킹' 버튼 활성화
        ↓
중간 프레임 자동 재계산
```

> ⚠ **구 서술 폐기(2026-08-19 원문 실측)** — *"선형보간(Linear Interpolation)"* 이라는 기술 용어는 1차 원문 3종 어디에도 등장하지 않는다. 원문(`02-관리자매뉴얼.txt` 4.3.10 · `03-UI설계서V1.1.txt` SC-004 "(2) 트랙 기능")은 "자동으로 계산하여 변경"이라고만 서술하고 보간 알고리즘 명칭을 특정하지 않는다. 동작 자체(첫/끝 값으로 중간 값을 자동 산출)는 선형보간과 부합해 보이나, **원문이 이 용어를 쓰지 않으므로 확정 사실로 표기하지 않는다** — 절 제목에서도 "(선형보간)"을 뗐다.

### 트랙 관리

| 기능 | 설명 |
|------|------|
| 트랙 고유 번호 | 생성 시 자동 배정, 상단 표시 |
| 삭제 아이콘 | 해당 프레임부터 뒤 프레임의 트랙 라벨 삭제 (객체 소멸 시) |
| 변경 버튼 | 트랙 번호 변경으로 가려졌다 재등장한 객체를 하나의 트랙으로 연결 (예: 사람이 차에 가려졌다 재등장) |

### 트랙 데이터 구조 (II-007, 원문 미확인 — 위 안내 참고)

```json
{
  "tracking_list": [
    {
      "tracking_id": "string",
      "frame_no": number,
      "image_path": "string",
      "coordinates": { "x": number, "y": number, "width": number, "height": number },
      "is_track_frame": boolean
    }
  ]
}
```

대응 DB 컬럼: `LS_DATA_LBL_HSTRY`의 `TRCK_USE_YN`, `TRCK_FRM_YN`, `TRCK_ID` ([15](15-database.md)).

## 8.5 베스트 프랙티스

> ⚠ **구 서술 폐기(2026-08-19 원문 실측)** — *"운영자매뉴얼 §9.4"* 는 존재하지 않는다. `02-관리자매뉴얼.txt` 의 "9." 는 "게시판"이며 하위 절은 9.1~9.3(게시판 목록 조회/게시글 작성/게시글 내용 조회 및 수정)뿐이다 — 별도 "베스트 프랙티스" 절 자체가 원문에 없다. 아래 항목 중 "트래킹" 권고 1건만 원문 문장(4.3.10)으로 확인되고, 나머지는 여러 절에 흩어진 내용을 이 위키가 요약한 것이라 절 인용을 제거한다.

- **Auto Labeling**: 사람·자동차 등 자동 가능 객체에 우선 적용 — 이 위키의 요약이며 원문에 "우선 적용" 권고 문장 자체는 없음(§8.2 참고)
- **AI Tool**: 객체 일부만 클릭 → 자동 테두리 감지 — §8.1 동작 설명의 재요약
- **트래킹**: 동일 객체 연속 프레임 → 첫·마지막 프레임만 설정 후 자동 계산. 트랙 설정 전에는 가급적 수정 작업 미수행 권장 — 근거: `02-관리자매뉴얼.txt 4.3.10`("트래킹 기능을 적용하기 전에는 가급적 라벨을 작업을 진행하지 않는 것이 좋습니다")

> **v2 참고**: v2는 추론을 **`ai-server`(YOLO/SAM2)** stateless 서비스로 분리하고 Spring Boot가 `AiServerClient`로 오케스트레이션(Resilience4j 타임아웃/서킷). YOLO/SAM2는 **원본 이미지에만 실행**하고 비식별본과 결과 공유. 트랙 보간은 CVAT 알고리즘 Java 포팅(portable-modules/01).
