## 4.1 라벨러/작업자 메뉴

> 원문: `01-UIUX설계서.txt`(작업자/검수자/업로더 메뉴 구조도 IA, "주요 사항" 절)

```
학습 저작도구
└── 작업자 / 검수자
    ├── 대시보드 — 월별/일별 작업통계
    ├── 프로젝트 (= 메인 화면, 로그인 시 바로 이 화면으로 이동)
    │   ├── 프로젝트 목록 (배정 / 작업중 / 반려 / 관리자확인요청 — 프로젝트별 건수 열)
    │   └── 프로젝트별 작업 리스트 → 라벨링 작업 화면
    ├── 게시판 — 게시글 목록 / 상세
    ├── 연습장 — 가공 작업 체험 (임시 저장만)
    └── 업로드/생성 [권한자만 노출]
        ├── 파일 업로드
        └── AI 이미지/동영상 생성
```

- 권한이 없는 작업자에게는 "업로드/생성" 메뉴 자체가 보이지 않는다(원문: "해당 메뉴는 권한을 가진 사람만 보이고, 권한이 없는 작업자의 경우 메뉴 자체가 안보이도록 진행").
- IA 다이어그램 제목은 "작업자/검수자/업로더 메뉴 구조도"이지만, 다이어그램 2단 노드 자체는 "작업자 / 검수자"만 표기하고 업로더는 "업로드/생성" 메뉴 권한자로만 등장한다(별도 3단 분기 없음).

> ⚠ **구 서술 폐기(2026-08-19 원문 실측)** — *"학습 저작도구 (메인 화면 = 로그인 시 첫 화면)"* 처럼 최상위 루트 자체를 "메인 화면"으로 표기한 것은 부정확하다. 원문 IA는 "학습 저작도구 → 작업자/검수자" 아래에 대시보드·프로젝트·게시판·연습장·업로드/생성 5개 메뉴를 나열하고, 그중 **"프로젝트" 노드에만 "메인 화면 : 로그인 시 보이는 화면" 주석이 붙어 있다.** 실제로 화면 `SKKLID-UI-02-02-01`의 화면명 자체가 **"라벨러 로그인 > (메인) 프로젝트"**이고, 해당 화면 세부 설명에도 "-. 작업자로 로그인 시 해당 화면으로 바로 이동"이라고 명시한다. 즉 **로그인 직후 첫 화면은 대시보드가 아니라 "프로젝트"(메인 프로젝트 리스트)다.** 근거: `01-UIUX설계서.txt`(주요 사항 IA 구조도 + 화면 `SKKLID-UI-02-02-01`).

## 4.2 관리자/프로젝트 담당자 메뉴

> 원문: `01-UIUX설계서.txt`(관리자/프로젝트 담당자 메뉴 구조도 IA) · `02-관리자매뉴얼.txt` §2(권한 관리)

```
학습 저작도구
└── 관리자 / 프로젝트 담당자 (관리자는 전체 메뉴 접근 가능)
    ├── 대시보드 (= 메인 화면, 로그인 시 첫 화면)
    │   ├── 담당 프로젝트 (프로젝트담당자만 노출) — 배정받은 프로젝트 전체 리스트/통계
    │   └── 작업 프로젝트 — 내가 작업자/검수자로 있는 프로젝트 리스트/통계 (작업자 화면의 '프로젝트'와 동일 화면)
    ├── 프로젝트 관리 — 담당 프로젝트 목록 / 생성 / 상세
    ├── 영상/이미지 관리 — 목록·상세 / 프로젝트 배정
    ├── 업로드/생성 데이터 관리 — 업로더 데이터 검토·등록
    ├── 사용자 관리 — 사용자 등록 및 관리
    ├── 게시판 — 공지 작성/관리
    └── 업로드/생성 — AI 동영상/이미지 생성
```

- GNB 노출 순서는 화면 `SKKLID-UI-03-05-01`(사용자 관리) 상단 GNB 스크린샷 원문 기준: 대시보드 → 프로젝트 관리 → 영상/이미지 관리 → 업로드/생성 데이터 관리 → 사용자 관리 → 게시판 → 업로드/생성.
- `02-관리자매뉴얼.txt` §2 "관리자 계정 접근 권한" 표: 슈퍼관리자는 전 메뉴(대시보드·프로젝트관리·영상/이미지관리·업로드/생성데이터관리·게시판·연습장·업로드/생성) 접근. 프로젝트 담당자는 대시보드·프로젝트관리(권한 부여받은 프로젝트만)·영상/이미지관리·업로드/생성데이터관리·게시판·연습장. 업로더는 게시판·연습장·업로드/생성만. "프로젝트 담당자는 '업로드/생성' 메뉴 접근을 위해 업로더 권한이 별도로 있어야 한다."

> ⚠ **구 서술 보강(2026-08-19 원문 실측)** — 기존 트리에 **"연습장"이 누락**돼 있었다. `02-관리자매뉴얼.txt` §2 접근 권한 표에는 연습장이 슈퍼관리자·프로젝트담당자·업로더 전원(O/O/O) 접근 가능한 메뉴로 명시돼 있고, 목차 10장도 "연습장 (라벨러와 동일)"이라고 적어 작업자 화면과 완전히 같은 화면을 공유함을 밝힌다. 위 트리에 "연습장" 노드를 추가했다. 다만 `01-UIUX설계서.txt`의 **관리자 전용 IA 다이어그램 자체에는 연습장 노드가 그려져 있지 않다**(라벨러 IA 쪽에만 그려짐) — 공용 메뉴라 관리자 전용 다이어그램에서는 생략된 것으로 추정되나 원문에 그 이유가 명시돼 있지는 않다(확인 불가).
> ⚠️ **두 1차 원문 간 메뉴 구조 자체가 불일치한다 — 어느 한쪽으로 단정하지 않는다(2026-08-19 원문 재확인).** `01-UIUX설계서.txt`의 "관리자/프로젝트 담당자 메뉴 구조도 (IA)" 다이어그램은 최상위 메뉴를 **"대시보드 – 프로젝트 관리 – 영상/이미지 관리 – 업로드/생성 데이터 관리 – 사용자 관리 – 게시판 – 업로드/생성"** 7개로 그리며(다이어그램 원문 그대로), "사용자 관리"는 화면 `SKKLID-UI-03-05-01`(화면명: "관리자 로그인 > 사용자 관리")로도 실재가 확인된다. 반면 **`02-관리자매뉴얼.txt`는 이 메뉴 자체가 없다** — 목차 11개 장(1.개요~11.연습장) 어디에도 "사용자 관리" 챕터가 없고, §2 "관리자 계정 접근 권한" 표도 정확히 **대시보드/프로젝트관리/영상이미지관리/업로드생성데이터관리/게시판/연습장/업로드생성 7행**뿐이라 "사용자 관리" 행 자체가 없다(대신 "사용자 확인 및 추가"가 §3.5로 "프로젝트 관리_담당 프로젝트"의 **하위 기능**으로만 존재 — 프로젝트별 배정 사용자 관리이지 전역 메뉴가 아니다). 이는 단순 누락이 아니라 **두 문서가 그리는 관리자 메뉴 구조 자체가 다르다**는 뜻이며, 어느 쪽이 최종 확정본인지는 이번 3-PDF 세트만으로 판정할 수 없다(위 트리는 `01-UIUX설계서.txt` 쪽을 따랐을 뿐 매뉴얼 쪽을 오류로 단정하는 것이 아니다). 근거: `01-UIUX설계서.txt`(IA 다이어그램 + 화면 `SKKLID-UI-03-05-01`) · `02-관리자매뉴얼.txt`(목차 + §2 권한 표 + §3.5).

## 4.3 화면 ID 명명 규칙

> 원문: `01-UIUX설계서.txt` "UI Guide_화면 ID 정의" (화면 `SKKLID-UI-01-01-01` 직후)

```
SK  KLID  -  UI  -  XX        -  XX        -  XX
①    ②      ③     ④          ⑤          ⑥

① 수행사        SweetK
② 발주사        KLID 한국지역정보개발원
③ 문서 구분      User Interface
④ 권한 구분 값    (공통, 라벨러, 관리자)   ← 첫 번째 XX
⑤ 메뉴 구분 값                          ← 두 번째 XX
⑥ 메뉴 하위 페이지의 구분 값               ← 세 번째 XX
```

**④ 첫 번째 XX (권한 구분 값)**: `01`=공통(UI Guide) · `02`=라벨러/작업자 · `03`=관리자/프로젝트담당자

**⑤ 두 번째 XX (메뉴 구분 값)**: `01`=대시보드 · `02`=프로젝트/작업 · `03`=게시판(라벨러) / 영상·이미지 관리(관리자) · `04`=연습장(라벨러) / 업로드·생성 데이터 관리(관리자) · `05`=업로드/생성(라벨러) / 사용자 관리(관리자) · `06`=게시판(관리자, 원문에 실재하나 04.4까지는 별도 그룹으로 누락돼 있었음)

**⑥ 세 번째 XX (메뉴 하위 페이지의 구분 값)**: 해당 메뉴 내 화면 순번(01부터 순차 부여, 결번이나 재사용 사례 있음 — 4.4 참고)

> ⚠ **구 서술 폐기(2026-08-19 원문 실측)** — 옛 표는 두 자리를 "메뉴 구분"·"메뉴 하위 페이지 구분"·"세부 화면 순번" 3단으로만 나누고, 첫 번째 XX를 "메뉴 구분"이라 불렀다. 원문 "화면 ID 정의" 절은 ID를 **①수행사·②발주사·③문서구분·④권한구분값·⑤메뉴구분값·⑥메뉴 하위 페이지의 구분값** 6개 마커로 정의하며, `SKKLID`는 ①②가 합쳐진 것, `UI`는 ③, 그리고 뒤의 세 자리 숫자가 각각 ④권한구분값·⑤메뉴구분값·⑥메뉴 하위 페이지 구분값이다. 즉 **첫 번째 XX는 "메뉴 구분"이 아니라 "권한 구분 값(공통/라벨러/관리자)"**이고, **두 번째 XX가 실제 "메뉴 구분 값"**(대시보드/프로젝트/게시판 등)이며, **세 번째 XX가 "메뉴 하위 페이지의 구분 값"**(세부 화면 순번)이다. 각 자리에 들어가는 구체적 값 매핑 자체(01=UI Guide/라벨러/관리자, 01=대시보드…)는 옛 서술과 결과적으로 같으므로 값 표는 유지하고 **명칭만 정정**했다. 근거: `01-UIUX설계서.txt`("화면 ID 정의" 절, 화면 `SKKLID-UI-01-01-01` 뒤).
