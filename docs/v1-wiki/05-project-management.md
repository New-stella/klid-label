# 05. 프로젝트 관리

> 출처: 통합설계서 §4, 관리자매뉴얼 §4, 화면정의서 §10, UI설계서 §3
> 관련: [03 역할·권한](03-roles-permissions.md) · [06 영상·프레임](06-video-frame-pipeline.md) · [11 증강·내보내기](11-augmentation-export.md)
> ⚠ 2026-08-19 원문(`02-관리자매뉴얼.txt` §3.1~3.5, `01-UIUX설계서.txt` 화면 `SKKLID-UI-02-02-03`) 전수 대조로 일부 항목을 정정했다. 대조한 관리자매뉴얼은 표지에 "2025.12" 작성, 재개정 이력에 `1.0`(2025.10.30 초안)·`1.1`(2025.11.12, 라벨링 단축키 안내 + 증강기능 추가) 2개 행이 있으나 **본문 각 페이지 하단 워터마크는 전부 "Version 1.0"으로 고정 표기**돼 있다 — 두 표기가 서로 다르며 어느 쪽이 최종본 버전인지는 원문만으로 확정할 수 없다(확인 불가, 다른 담당에게 넘기는 발견: "Rev.1.1" 인용이 있는 문서가 있으면 이 각주를 참고).

프로젝트는 학습 데이터셋 구축의 기본 단위이며, 모든 데이터·라벨·사용자는 **프로젝트 ID(`PJT_SN`) 기준**으로 연계된다.

> **v2 참고**: v2에는 프로젝트 단위 개념이 없다. 작업 식별자는 **영상 1건(`LS_DATA_RAW.RAW_SN`)**. 이 페이지의 프로젝트 생성/배정 흐름은 v1 전용이다.

## 5.1 프로젝트 생성 (5단계)

화면: `SKKLID-UI-03-02-04 ~ 11`

### Step 1 · 기본 정보 입력

| 필드 | 필수 | 제약 |
|------|:----:|------|
| 프로젝트명 | O | - |
| 프로젝트 아이디 | O | 영문·숫자만, **중복체크 필수** |
| 프로젝트 설명 | X | 목록에 노출 |
| 목표 데이터 수량 | O | 숫자만 |
| 도움말 | X | 라벨러 화면에 표시 |

### Step 2 · 메타 생성

라벨링 시 프레임에 입력할 메타데이터 항목을 정의("메타 추가하기").

| 항목 | 설명 |
|------|------|
| 메타 아이디 | 영문·숫자만 |
| 질의문 | 라벨러에게 보여줄 질문 |
| 선택 항목 | 라벨러가 선택할 옵션 |
| 입력 형식 | **텍스트** 입력 또는 **라디오 버튼** |

생성된 메타는 라벨러 화면의 [메타 탭](07-labeling-tools.md#76-메타-탭)에 노출된다.

### Step 3 · 라벨 생성

| 필드 | 필수 | 설명 |
|------|:----:|------|
| 라벨명 | O | 라벨러가 사용할 범주명 |
| 라벨 아이디 | O | 영문·숫자만 |
| 라벨 형태 | O | 바운딩박스 / 폴리곤 / 스켈레톤 중 선택 |
| 라벨 색상 | X | 색상 선택(팝업) — 스켈레톤은 라벨 단위 색상 대신 포인트별 색상 사용 |
| 속성(Attribute) | X | 라디오 버튼 또는 텍스트 형식 세부 분류 |

**속성 예시**: 라벨 "자동차" → 속성 "대형/중형/소형". 속성은 우측 [객체 탭](07-labeling-tools.md#75-객체-탭-우측-패널)에서 선택.

**스켈레톤 추가 설정** (라벨 형태 = 스켈레톤일 때, `03-02-07`):

| 필드 | 설명 |
|------|------|
| 포인트명 | 머리, 왼쪽어깨 등 관절명 (필수) |
| 포인트 ID | 영문·숫자만 (필수) |
| 포인트 색상 | 각 포인트 색상 |

스켈레톤 작성 도구: 수정/편집 · 파일 업로드(JPG/JPEG/PNG) · 포인트(우클릭 명명) · 이동 · 선 그리기 · 삭제

> ⚠ **구 서술 폐기(2026-08-19 원문 실측)** — *"라벨 색상 | X | HEX (스켈레톤은 색상 없음)"* 중 "HEX" 표기는 원문 텍스트로 확인되지 않는다(`02-관리자매뉴얼.txt`·`01-UIUX설계서.txt`·`03-UI설계서V1.1.txt` 3종 전체에 "HEX" 문자열 0건). 관리자매뉴얼 §3.1은 "라벨 색상 : 라벨러가 해당 라벨 작업을 진행할 때 노출되는 색상 선택"이라고만 적는다. 색상 입력 형식(HEX·팔레트 등)은 확인 불가로 남기고 "색상 선택(팝업)"으로만 표기했다. "스켈레톤은 (단일) 색상 없음"이라는 취지는 유지했는데, 스켈레톤 선택 시 라벨 자체의 색상 필드 대신 포인트별 "포인트 색상"이 별도로 존재하기 때문이다(관리자매뉴얼 §3.1 스켈레톤 정보 목록 — 포인트명/포인트ID/포인트색상). 근거: `02-관리자매뉴얼.txt` §3.1.

### Step 4 · 단계 설정

기본(최소) 프로세스: `1단계 가공 → 1차 검수` (이보다 줄이는 것 불가). 전 확장 옵션을 다 적용한 최대 구성은 `1단계 가공 → 1차 검수 → 2차 검수 → 2단계 가공 → 1차 검수 → 2차 검수`.

| 확장 옵션 | 구성 |
|----------|------|
| 검수 추가 | 1단계 가공 → 1차 검수 (최소, 기본값) ~ → 1차 → 2차 검수 (검수 최대 2단계) |
| 단계 추가 | 1단계 가공 → 1차 검수 → 2단계 가공 → 1차 → 2차 검수 (가공 최대 2단계) |

> ⚠ **구 서술 폐기(2026-08-19 원문 실측)** — *"기본 프로세스: 1단계 가공 → 1차 검수 → 2차 검수 (이보다 줄이는 것 불가)"*는 사실과 다르며, 바로 아래 "확장 옵션" 표가 "1단계 가공 → 1차 검수"를 "최소"라고 부르는 것과도 자체 모순이었다. 관리자매뉴얼 §3.1 원문: "기본 데이터 작업 프로세스는 '1단계의 가공 → 1차 검수' 이며, 더 짧게 줄이는 것은 불가능합니다." 즉 **최소 단위는 1차 검수까지이며 2차 검수는 '검수 추가' 옵션으로 확장해야만 생긴다.** 근거: `02-관리자매뉴얼.txt` §3.1.

### Step 5 · 권한 부여

- "사용자 추가" → 작업자 아이디 선택(중복 가능) + 권한 선택(단일)
- 권한 삭제·수정, 비고 열 더블클릭 입력, "저장"
- **"건너뛰기"** 후 프로젝트 상세의 "사용자 확인 및 추가"에서 언제든 추가
- 프로젝트 담당자·업로더는 1단계 추가 시 자동으로 2단계 추가
- 슈퍼관리자는 권한 부여 불필요

## 5.2 프로젝트 완료 처리

화면: 담당 프로젝트 목록의 완료여부 열

| 액션 | 절차 | 결과 |
|------|------|------|
| **완료** | "완료" 클릭 + **버전 설명 필수 입력** → 확인 | 작업자 접근 차단, 상태 → **마감**, 버튼 → "완료 취소" |
| **완료취소** | "완료취소" 클릭 + **버전을 기존보다 높게 수정** → 확인 | 작업자 재접근 허용, 상태 → **진행**, 버튼 → "완료" |

완료 데이터는 보존되어 필요 시 다시 열 수 있다. 증강은 완료 프로젝트에서 불가 → 완료취소 후 진행([11](11-augmentation-export.md)).

## 5.3 데이터 배정

### 관리자 배정 (영상/이미지 → 프로젝트)
[06 영상/이미지 프로젝트 배정](06-video-frame-pipeline.md#65-영상이미지-프로젝트-배정) 참고. 영상은 프레임 분할 후 "배정대기" 상태에서만 작업 배정 가능. 영상 처리는 자원 집중 → **1건씩 배치 처리** 구현 필수.

### 데이터 배정 (작업자/검수자 지정)
화면: 프로젝트 → "작업배정"

1. 필터: **단계**(1/2단계), **데이터 상태**(대기/가공완료/1차 검수완료), **배정 수량**(숫자)
2. "배정" → 라벨러 설정 팝업 → **작업자·검수자 모두 선택** → 저장
3. 관리자 배정 시 **작업자~검수자까지 한번에 설정 필수**

### 데이터 자동 배정 (작업자 셀프)
화면: `SKKLID-UI-02-02-03`("(메인) 프로젝트 > 프로젝트A" 2p) 하단 "작업 배정" 버튼

작업자 보유 데이터(관리자 확인 요청 제외) **10개 이하**일 때 "작업 배정" 버튼 클릭 → **최대 15개까지** 신규 클립 자동 배정. 보유 데이터가 **11개 이상**이면 배정 실패 팝업("기존 데이터를 먼저 작업해 주신 후 작업 배정 버튼을 클릭해 주세요.")이 뜨고 배정되지 않는다. 배정 대상이 15개 이하로 남았으면 남은 전체를 배정하고, 배정할 데이터가 아예 없으면 "배정할 데이터가 없습니다." 팝업이 뜬다. 우선순위: 한 작업자가 1단계-가공/2단계-가공 권한을 모두 가지면 **1단계-가공을 우선 배정**(1단계-가공 작업이 없을 때만 2단계-가공 배정), 1단계-가공/1단계-검수 권한을 모두 가지면 **1단계-가공을 우선 배정**(1단계-가공 작업이 없을 때만 1단계-검수 배정).

> ⚠ **구 서술 폐기(2026-08-19 원문 실측)** — *"프로젝트에서 최대 1개 클립 자동 배정"*은 사실과 다르다. 바로 아래 부연 문단이 스스로 "10개 이하 → 새로 15개 배정"이라고 적어 본문과 모순돼 있었다. 원문(화면 `SKKLID-UI-02-02-03`)에 따르면 자동 배정 단위는 "1개 클립"이 아니라 **최대 15개(클립 단위)**다. 근거: `01-UIUX설계서.txt`(화면 `SKKLID-UI-02-02-03`).

## 5.4 사용자 확인 및 추가 (프로젝트 상세)

- 필터: 단계(전체/1/2), 권한(담당자/업로더/검수자/작업자)
- 셀렉트 박스로 권한 직접 수정, 삭제 아이콘, 저장
- 사용자 추가: 아이디(중복 가능) + 단계 + 권한(단일) 선택 → 저장
- 담당자·업로더는 단계가 "전체"로 반영

## 5.5 관련 데이터 (DB)

`LS_PJT`(마스터·증강/데이터셋 상태 포함), `LS_PJT_LBL`(라벨 설정), `LS_PJT_META`(메타), `LS_PJT_STG_PRC`(가공 단계), `LS_PJT_STG_IGI`(검수 단계·정산 단가), `LS_PJT_USER_AUTHRT`(권한), `LS_PJT_DDLN`(마감 이력·버전), `LS_PJT_DATA_MPNG`(데이터 매핑), `LS_PJT_DATA_STTS`(상태 추적). 상세 → [15](15-database.md).
