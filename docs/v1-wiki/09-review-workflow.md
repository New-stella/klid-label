# 09. 검수 워크플로우

> 출처: 통합설계서 §9, 화면정의서 §6·9.2, 운영자매뉴얼 §3.3.12~13, 관리자매뉴얼 §4.8
> 관련: [07 라벨링 도구](07-labeling-tools.md) · [10 대시보드·통계](10-dashboard-statistics.md)

화면: `SKKLID-UI-02-02-16 ~ 19` (검수).

## 9.1 전체 흐름

```
[작업자] 라벨링 작업
    ↓ 모든 프레임 저장 완료 (모두 연두색) → 제출
[1차 검수자] 프레임별 검토 → 승인 or 반려
    ↓
[2차 검수자] 최종 검토
    ↓ 승인 → 작업 완료
    ↓ 반려 → 1차 검수자에게 반환
         (단, 2차 반려 건은 1차가 작업자에게 재반려 불가)
```

작업자 → 검수자(1차) → 검수자(2차) → 관리자 → 작업 완료.

## 9.2 프레임 테두리 색상 체계

| 색상 | 상태 | 의미 |
|------|------|------|
| **연두색** | 저장됨 | 정상 처리된 프레임 |
| **주황색** | 반려됨 | 재작업 필요 프레임 |
| **빨간색** | 관리자확인요청 | 관리자에게 확인 요청 중 |
| *(모두 연두색)* | 제출 가능 | 모든 프레임이 연두색일 때만 검수 제출 가능 |

> 현재 보고 있는 프레임은 약간 크게 표시.

## 9.3 역할별 작업 제약

### 작업자
- 관리자 확인 요청 프레임이 없고 **모든 프레임 저장** 완료 시 제출 가능
- 반려된 프레임만 재작업 가능 (승인된 프레임은 볼 수만 있음)
- 관리자 확인 요청 프레임은 처리 후 실시간 반환
- **자동 저장**: 프레임 이동 시 자동 저장. 수동 저장(Ctrl+S)도 가능
- 제출 버튼은 마지막 프레임에서만 노출

### 검수자(1차)
- 반려는 개별 프레임 단위 처리
- 마지막 프레임에서 '제출' 클릭 시 반려/검수 완료
- 모든 프레임이 승인/반려 처리되어야 제출 가능 (제출 전 변경 가능)
- **2차 검수자에게 반려된 건은 작업자에게 재반려 불가**

### 검수자(2차)
- 관리자 확인 요청 프레임 없을 때 반려/검수 완료 처리 가능

### 관리자
- 관리자 확인 요청 프레임만 처리 가능
- 다른 프레임은 확인 가능하나 수정 불가
- 작업을 옮길 때는 실시간 처리 불가

## 9.4 관리자 확인 요청

화면: `SKKLID-UI-03-02-14~15` (확인 및 재배정)

작업자/검수자가 문의·문제 프레임을 관리자에게 보내는 기능.

**요청 (작업자/검수자)**:
- 용도: 작업 중 문의, 프레임 추출 문제로 폐기 요청 등
- 방법: "관리자 확인 요청" 버튼 → 사유 입력/선택 → "확인"
- 결과: 관리자에게 전달 + 이슈 탭 기재. 해당 프레임은 작업 불가(볼 수는 있음)

**관리자 처리**:
| 액션 | 결과 |
|------|------|
| **확인 및 재배정** | 문제 없음 확인 → 사유 입력/"문제 없음" → 프레임 재배정 + 이슈탭 기재 |
| **폐기** | 프레임 삭제 처리 → 작업 대상에서 제외 |

> 관리자가 "작업 프로젝트"에서 직접 라벨링할 때는 관리자 확인 요청 기능 사용 불가(직접 판단).

## 9.5 검수자 반려

- 용도: 작업자가 라벨링을 잘못 진행했을 경우
- 방법: "반려" 버튼 → 반려 사유 입력/선택 → "확인"
- 결과: 저장 후 데이터 제출 시 작업자에게 전달, 이슈 탭 기재

## 9.6 이력 관리 항목

| 이력 유형 | 설명 |
|----------|------|
| 작업자 작업 제출 이력 | 제출 일시, 작업자 ID |
| 검수자 승인 이력 | 승인 일시, 검수자 ID |
| 반려 이력 | 반려 사유, 반려 일시 |
| 관리자 확인 요청 이력 | 요청·처리 이력 |
| 라벨/원천/메타 데이터 변경 이력 | 전체 변경 내역(감사 추적) |

## 9.7 데이터 상태 분류 / 우선순위

작업자 리스트 정렬 우선순위:
```
반려 > 작업중 > 배정 > 관리자 확인 요청 > 보류 → 이후 날짜 순 → 동일 날짜 시 ID 내림차순
```

데이터 상태 플로우(관리자매뉴얼 §16.2):
```
배정대기 → 배정 → 가공완료 → 1차 검수완료 → (선택) 2차 검수완료 → 최종완료
```

리스트 항목: 단계-작업, 남은 작업/전체 프레임 수, 작업자 남은 작업(배정완료·검수반려), 검수자 남은 작업(검수요청·검수반려), 데이터 상태, 배정일.

## 9.8 관련 데이터 (DB)

`LS_DATA_LBL_HSTRY`(라벨 변경 이력), `LS_DATA_ISSUE`(이슈·반려 상세 코드), `LS_DATA_SRC_HSTRY`/`LS_DATA_META_HSTRY`(원천/메타 변경 이력), `LS_PJT_STG_IGI`(검수 단계 설정). 상세 → [15](15-database.md).

> **v2 참고**: v2는 **REVIEWER가 WORKER에게 배정**하는 단일 검수 체계(1·2차 구분 없음)이며, 검수 승인(`APPROVED`)이 곧 작업 완료 → 관제서버로 `TASK_COMPLETED` outbound 통지. v1의 1차/2차 검수자 분리·관리자 폐기 흐름은 v2에 없다.
