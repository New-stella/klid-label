## 2. 무엇을 보는 건가요?

본 화면은 **실제 동작하는 시스템이 아닌, 발주처 시연을 위한 UI 프로토타입(목업)** 입니다.

### 목적
- 최종 시스템에서 사용자가 보게 될 **화면 구성·정보 배치·플로우**를 사전에 합의
- 요구사항정의서 / DB설계서 / UI-UX설계서의 **반영 여부 시각적 검증**
- 본 개발 진입 전 **이해관계자 피드백 수렴**

### 범위 (V1.x 기준)
- **포함**: SFR-08 (저작도구 핵심 기능), SFR-09 (비식별화 — 내보내기 시 옵션), SFR-15 (포털), QUR-03 (검수 품질관리)
- **외부 시스템 책임으로 이관**: SFR-03 (시계열 메타 자동 추출), SFR-06 (생성형 AI 본체), SFR-11 (영상 합성 모델), SFR-13 (데이터마트)
- 저작도구는 외부 시스템과의 **인터페이스(요청·검토 UI)** 만 보유

### 처리 파이프라인 (V1.x)

배치 파이프라인의 처리 단계 순서는 **`VLM(시계열 메타) → 프레임 추출 → YOLO → SAM2`** 4단계로 운영된다. VLM은 외부 시스템 호출이지만 mock에서는 stage 진행 표시의 첫 단계로 노출된다. 비식별 처리는 단계에서 제거되어 **내보내기(포털 전송) 시 옵션**으로 호출된다.

## 4. 주요 워크플로우 (시연 시나리오)

> 아래 8개 시나리오는 사용자가 화면에서 **누르고 보고 입력하는 동작**만으로 작성했습니다. **굵은 글씨는 화면에 표시되는 메뉴·버튼·라벨**이며, 그대로 따라 누르면 동일한 결과가 나옵니다. 모든 메뉴는 화면 **왼쪽 사이드바**에서 펼칠 수 있습니다.
>
> 시나리오 ①~④는 **핵심 라벨링 워크플로우** (시연 메인), ⑤~⑧은 **부가 영역 검토용** (필요한 부분만 골라 시연)입니다.

### 시나리오 ① 검수자: 작업 일괄 배정 → 검수 → 승인 (약 4분)

> 시작 전: 화면 우상단 역할 메뉴에서 **검수자**를 선택합니다.

1. 왼쪽 사이드바에서 **작업** 그룹의 **작업 목록** 메뉴를 클릭합니다. → **처리 완료된 영상**이 task 유무와 무관하게 모두 표시됩니다 (V1.x 후속 — 영상 기반 left-join). task가 아직 없는 영상은 **작업자 '미배정' / 검수자 '미등록'** 라벨로 노출되며, 그 영상도 체크박스로 선택할 수 있습니다.
2. 상단 필터 영역의 **이벤트** 드롭다운에서 임의 이벤트(예: 침수)를 골라 결과를 좁힙니다. (상태 필터에 **'미배정(UNASSIGNED)'** 옵션도 있어 task 없는 영상만 모아 볼 수 있습니다.)
3. 표 좌측의 **체크박스**로 영상을 다중 선택합니다. (헤더의 **"현재 페이지 전체 선택"** 체크박스 또는 indeterminate 상태도 사용 가능)
4. 1개 이상 선택되면 표 위에 **`{N}개 선택됨` 액션바**가 나타납니다. 우측 **[N개 일괄 배정]** 버튼을 클릭합니다. → **작업 일괄 배정** 모달이 열립니다.
5. 모달의 **작업자** 드롭다운은 **현재 로그인 사용자**가 기본 선택되어 있습니다 (V1.x 후속). 그대로 또는 다른 사용자로 변경한 뒤 **[저장]** → 알림 영역에 **"{N}건 일괄 배정 완료"** 토스트가 뜨고 모달이 닫힙니다. (검수자 칸은 본인으로 자동 지정 / 이미 동일 배정인 영상은 멱등 처리되어 스킵 / **task 없던 영상은 신규 task가 생성됨**)
6. 왼쪽 사이드바에서 **작업** 그룹의 **검수 목록** 메뉴를 클릭합니다 (V1.x 후속 — '검수 대기' → '검수 목록' / 메뉴 그룹 '검수' → '작업').
7. 상태가 **검수대기**인 영상 행의 **[검수시작 ▶]** 버튼을 클릭합니다. → 검수 화면이 열립니다.
8. 화면 우측 패널의 **[🚩 이슈 추가 모드]** 버튼을 클릭한 뒤, 가운데 캔버스를 클릭합니다.
   - 클릭 즉시 그 위치에 **점선 빨간 임시 마커**가 보이고 **이슈 추가** 팝업이 열립니다.
   - 빈 영역뿐 아니라 **라벨링된 객체(차량·사람·자전거 등) 위**에도 클릭 가능합니다 (그 라벨이 잘못됐다는 표시 용도).
   - 코멘트 입력 후 **[저장]** → 정식 마커(빨간 원 + 🚩)로 전환 + 우측 패널 항목 추가
   - **[취소]** → 임시 마커 사라짐
9. 화면 하단의 **[✅ 승인]** 버튼을 누르고, 확인 팝업의 **[승인]** 을 누릅니다. → 알림이 뜨면서 자동으로 **대시보드** 화면으로 이동합니다.
   - **참고**: 등록된 이슈가 1건 이상이면 [✅ 승인] 버튼은 비활성화되며 "⚠️ 등록된 이슈 N건 — 승인할 수 없습니다. 반려를 진행하세요." 안내가 표시됩니다.

> 반려를 시연하려면 9번에서 **[❌ 반려]** 를 누르고, 팝업에 사유를 입력한 뒤 **[반려]** 를 누릅니다. (사유는 필수)
>
> **반려 후 결과보기**: 검수 목록에서 반려된 검수의 **[결과보기 ▶]** 버튼을 누르면 등록했던 이슈 마커가 캔버스에 그대로 표시됩니다 (검수 이력 추적용).

### 시나리오 ② 작업자: 라벨 편집 → 저장 → 버전 비교 (약 3분)

> 시작 전: 화면 우상단 역할 메뉴에서 **라벨링 작업자**를 선택합니다.
>
> ⚠️ 시연 팁: 현재 mock은 **작업 목록**의 **[작업]** 버튼이 알림창만 표시하고 라벨링 화면으로 자동 이동하지 않습니다(추후 구현 예정). 따라서 라벨링 화면은 **브라우저 주소창에 `/label/video-0001` 을 직접 입력**해서 진입해 주세요.

1. 주소창에 `/label/video-0001` 을 입력하여 **라벨링 화면**에 진입합니다. (가운데 캔버스, 좌측 도구 모음, 우측 객체·속성 패널, 하단 프레임 스트립이 한 화면에 배치됨)
2. 캔버스 위에서 마우스로 **사각형 박스를 드래그**하여 객체를 그리거나, 우측 **객체 목록**에서 항목을 골라 속성을 수정합니다.
3. 화면 하단의 **프레임 스트립** 중 다른 프레임 썸네일을 클릭하면 그 프레임으로 이동합니다. → 필요한 만큼 추가 라벨링.
4. 화면 상단 우측의 **[저장]** 버튼을 누릅니다. → **"저장됨 · 버전 기록됨"** 알림이 뜹니다.
5. 화면 상단의 **[히스토리]** 버튼을 누릅니다. → **버전관리** 화면이 열립니다.
6. 좌측 **커밋 목록**에서 임의 **두 커밋의 체크박스**를 체크합니다. → 우측 영역에 두 버전 간 차이(diff)가 즉시 표시됩니다.
7. (선택) 우측 영역의 **[이 버전으로 롤백]** 버튼을 누른 뒤 사유 입력 후 **[롤백 실행]** → 알림 표시.

### 시나리오 ③ 검수자: 데이터 증강 요청 → 결과 검증 (약 4분)

> 역할: **검수자**

1. 왼쪽 사이드바에서 **데이터** 그룹의 **증강 요청** 메뉴를 클릭합니다. → **검수 완료(검수 승인)된 영상만 테이블 리스트로 표시**됩니다 (V1.x 후속 — 카드 그리드 → 리스트 재구성). 미승인 영상은 목록 자체에서 제외됩니다.
2. **1단계 — 증강 유형 선택**: 화면에 표시되는 4장의 카드(**겨울 / 야간 / 비 / 해상도 향상**) 중 1개 이상을 눌러 토글합니다. (선택된 카드는 강조 표시)
3. **2단계 — 대상 영상 선택**: 상단 **검색**(영상명/CCTV/id) + **이벤트 필터**로 좁힌 뒤, 행 좌측 체크박스로 다중 선택합니다. 헤더 체크박스는 indeterminate 상태로 표시됩니다. 표 위에 **[N개 영상 증강 요청]** 액션바가 나타납니다. (영상 수백 건 대비 100건 client-side 페이징 제공)
4. 화면 하단의 진행률 요약("선택: N종 × M건 = 예상 X건")을 확인하고 **[증강 요청]** 버튼을 누릅니다. → 자동으로 **증강 결과** 화면으로 이동합니다.
5. 결과 화면 상단에 **처리 중...** 배너가 보이면 **5초마다 자동 갱신**되며 진행률 바가 차오릅니다.
6. 처리가 끝나면:
   - 상단에 **라벨 무결성 점수**가 색상과 함께 표시됩니다(95 이상 초록 / 85 이상 노랑 / 그 미만 빨강).
   - 영상별 섹션마다 **12 프레임 그리드**(상단 원본·하단 증강 결과)가 표시되고, 그리드 아래로 **좌우 비교 영역**이 보입니다.
7. 결과 카드 하단의 **[학습데이터로 활용]** 버튼을 누릅니다. → 알림이 뜨고 카드의 배지가 **활용**으로 바뀝니다.
   - 또는 **[거부]** 를 누르고 팝업에서 사유를 입력 후 **[거부 확정]** → 배지가 **거부** 로 바뀝니다.

### 시나리오 ④ 검수자: 학습데이터셋 포털 전송 (약 2분)

> 역할: **검수자**. 저작도구는 학습데이터셋을 **포털 서버로 전송**하는 단일 채널만 운영합니다 (V1.x — NAS 저장 옵션 제거).

1. 왼쪽 사이드바에서 **데이터** 그룹의 **내보내기** 메뉴를 클릭합니다. → 화면 헤더에 부제 **"포털 서버로 학습데이터셋을 전송합니다"** 가 보이고, 가운데 3단계 폼·우측에 **출력 미리보기** 패널이 표시됩니다. **검수 완료(검수 승인)된 영상만 표시**됩니다 (V1.x 후속 — 검수 미완료 영상은 목록 자체에서 제외). 검수 완료 영상이 0건이면 "검수 완료된 영상이 없습니다" 빈 상태가 표시됩니다.
2. **1단계 — 형식**: **COCO / YOLO / CVAT / PASCAL_VOC** 라디오 중 하나를 클릭합니다. → 우측 미리보기에 해당 형식의 샘플 출력이 즉시 갱신됩니다.
3. **2단계 — 대상 영상**: 영상 표 상단의 **검색**(영상명/CCTV/id) + **이벤트 필터** + **전송 상태 필터**(전체/미전송/이미 전송/전송 실패)로 좁힌 뒤(필터 상태는 URL에 동기화됨), 행 좌측의 체크박스 또는 헤더의 indeterminate 체크박스로 일괄 선택합니다. 영상 수백 건은 100건 페이징으로 분할됩니다.
   - 각 행에는 전송 상태 배지(**미전송 / 이미 전송 / 전송 실패**)가 표시됩니다 (V1.x 후속).
   - 이미 내보낸 영상은 기본 disabled. 화면 옵션의 **"이미 내보낸 영상 포함"** 토글을 켜면 강제 재전송 가능합니다 (`forceReexport: true`).
4. **3단계 — 옵션**: **라벨 포함 / 이미지 포함 / 비식별 처리(개인정보 마스킹) / 이미 내보낸 영상 포함** 체크박스를 확인합니다. **비식별 처리는 기본 ON**, **이미 내보낸 영상 포함은 기본 OFF** 입니다. 비식별 체크 해제 시 원본 그대로 전송됩니다.
5. 옵션 하단의 **전송 대상** 안내에서 포털 서버 endpoint(`https://portal.example.com/api/v1/datasets/import`)를 확인합니다.
6. 우측 미리보기 패널 하단의 **[포털 전송 실행]** 버튼을 누릅니다. → **"{N}건 포털 전송 시작됨"** 토스트가 뜨고 영상 선택이 자동 해제됩니다.
   - **시도별 결과 토스트** (V1.x 후속): 비식별 일부 실패 시 "비식별 실패 N건 (다시 시도 가능)" / 이미 전송된 영상 스킵 시 "이미 내보낸 N건 스킵" / 검수 미완료 차단 시 "검수 미완료 N건 차단" 형식의 카운트가 표시됩니다.
   - 비식별 실패는 **시도별 사유**입니다 — 영상이 영구적으로 '비식별 실패'를 가지지 않으며, 상태가 '전송 실패(FAILED)'로 기록되어 다음 시도에 재선택 가능합니다.

### 시나리오 ⑤ 검수자: 영상 처리 현황 + 영상 상세 검토 (약 3분)

> 역할: **검수자**. 외부 배치(VLM 메타 → 프레임 추출 → YOLO → SAM2)가 어떻게 진행되고, 그 결과를 검수자가 어떻게 확인하는지를 보여주는 시나리오입니다.

1. 왼쪽 사이드바에서 **영상** 그룹의 **영상 처리 현황** 메뉴를 클릭합니다. → 영상 표가 표시되며, 단일 **"처리 단계"** 컬럼에서 각 영상의 진행 상황을 한 칩으로 확인할 수 있습니다 (V1.x 후속 — 기존 '처리 상태'·'처리 단계' 두 컬럼이 단일 컬럼으로 통합, 색상 톤이 상태 표현).
2. 처리 단계가 진행 중인 영상은 **진행 톤(파랑·보라)**, 완료(모든 stage DONE)는 **초록 '완료'** 라벨로 단순 표시(V1.x 후속), 실패는 **빨강**, 대기는 **회색**으로 구분됩니다. VLM 메타 단계는 신규 진입 단계이므로 **보라 톤**으로 별도 표시됩니다.
3. 처리 완료 영상 행의 **[상세 ▶]** 버튼을 누릅니다. → **영상 상세** 화면이 열립니다.
4. 상단의 **CCTV 메타 정보** (위치·녹화일·길이·이벤트 유형·개인정보 유형)를 확인합니다.
5. 화면 중간의 탭 메뉴에서 **오토라벨 결과** 탭을 클릭합니다. → 처리 정보(총 라벨 수·오토라벨 수·비율·처리 상태), 신뢰도 분포(0.9+/0.7-0.9/<0.7), 라벨별 분포 차트가 표시됩니다.
6. (선택) **프레임 미리보기** 탭을 클릭하면 영상 프레임 썸네일이 표시됩니다.
7. **[목록으로]** 또는 사이드바에서 다음 화면으로 이동합니다.

> **시계열 메타데이터(SCR-AUTO-002)** 탭은 V1.7 정책으로 **외부 시스템에서 자동 생성**되며 저작도구는 검토·수정 UI만 별도 제공합니다. 본 mock의 영상 상세 화면에는 표시되지 않습니다.

### 시나리오 ⑥ 검수자: 대시보드 + 통계 (성과 가시성, 약 2분)

| **비식별 처리** | 내보내기 화면의 옵션 체크박스만 토스트로 시뮬레이션 — 실제 마스킹 처리는 일어나지 않음. mock 전용 플래그 **`DEIDENT_FAIL_SIMULATION`** 으로 일부 영상에서만 비식별 실패가 시뮬레이션되며(영구 속성 아님 — 시도별 사유로만 기록), 다음 시도에 재선택 가능 | **포털 전송 시 내보내기 잡이 비식별 서버 API 호출 후 마스킹된 산출물을 포털로 전송** (단계가 아닌 옵션) |
| **포털 전송** | 토스트와 carousel만 시뮬레이션 (실제 전송 없음) | 포털 서버 endpoint(`/api/v1/datasets/import`)로 실제 데이터셋 전송 |
| **데이터 영속성** | 새로고침 시 초기 상태로 리셋 | DB(klid_system) 영구 저장 |
| **외부 연동** | 모두 mock 응답 | 관제서버·포털·비식별 서버·Gitea·ai-server 실 호출 |
| **생성형 AI 영상 합성** | 화면·요청 인터페이스 모두 미제공 (V1.x 제거) | **외부 시스템 책임** — 결과 영상은 별도 시스템에서 생성 후 재유입 (V1.8 정책) |
| **데이터마트** | 화면 없음 | **외부제공 시스템 책임** — 저작도구는 학습데이터셋 내보내기까지만 담당 (V1.4 정책) |

### 시연 중 흔히 겪는 오해
- **"버튼 눌렀는데 시간이 너무 빨라요"** → mock이라 즉시 반환됩니다. 실제 시스템에서는 비동기·대기 표시가 적용됩니다.
- **"권한이 없는 화면도 보여요"** → 역할 전환은 mock이 단순히 메뉴를 바꿔주는 수준입니다. 실제는 서버 권한 검증.
- **"통계 숫자가 매번 같아요"** → mock 고정 데이터입니다. 실제는 DB 집계.
- **"비식별 메뉴는 어디 있나요?"** → V1.x에서 비식별은 **자동 단계가 아닌 내보내기 옵션**으로 변경되어 별도 메뉴가 없습니다. 내보내기 화면의 비식별 처리 체크박스로 제어합니다.
- **"검수 대기 메뉴가 안 보여요"** → V1.x 후속에서 라벨이 **'검수 목록'**으로 변경되고, 메뉴 그룹이 **'검수' → '작업'**으로 이동되어 사이드바의 작업 그룹 안에 노출됩니다.
- **"내보내기 화면에 영상이 적게 보여요"** → V1.x 후속에서 **검수 완료(승인)된 영상만** 노출됩니다. 미승인 영상은 목록에서 제외됩니다. 또한 이미 내보낸 영상은 기본 disabled이며, **"이미 내보낸 영상 포함"** 토글로 강제 재전송 가능합니다.
- **"비식별 실패한 영상이 다음에 안 보여요"** → 비식별은 **시도별 사유**입니다 (영구 속성 X). 실패한 영상은 상태가 '전송 실패(FAILED)'로 기록되며 다음 시도에 자연스럽게 재선택 가능합니다.

## 6. 검토 포인트 체크리스트

검토자는 아래 항목 중 본인 관심사에 해당하는 것을 중심으로 확인 후 피드백 부탁드립니다.

### 6.1 비기술 이해관계자 (발주처·기획)
- [ ] **요구사항 충족** — 요구사항정의서의 SFR/QUR 항목이 화면에 모두 반영되어 있는지
- [ ] **업무 흐름 자연스러움** — 배정→라벨링→검수→증강→포털 전송 5단계가 실제 업무 절차와 맞는지
- [ ] **용어 일관성** — '검수자'·'작업자'·'관리자' 용어가 화면 전반에 일관되게 쓰이는지
- [ ] **정보 누락 여부** — 결재·통계·관리 화면에 필요한 정보가 빠지지 않았는지
- [ ] **외부 시스템 인터페이스** — 증강 검토·외부 메타 검토·포털 전송 흐름이 의도대로 분리되어 있는지

### 6.2 내부 검수·QA 팀
- [ ] **화면 ID ↔ 설계서 매핑** — UI-UX 설계서 화면 ID(SCR-*)가 mock에 모두 구현되었는지 (3장 표 참고)
- [ ] **상태 전이** — 영상/작업/검수 상태 코드가 DB 설계서와 일치하는지 (`BATCH_COMPLETED`, `PENDING`, `REVIEW_PENDING` 등)
- [ ] **권한별 화면** — 역할(REVIEWER/WORKER/PORTAL_USER) 전환 시 메뉴가 올바르게 변하는지
- [ ] **반응형** — 포털(`/portal/*`)이 모바일/태블릿에서 정상 표시되는지
- [ ] **접근성** — 키보드 탐색·스크린리더 친화성·색상 대비 (WCAG 2.1 AA 기준)
- [ ] **에러/빈 상태** — 빈 목록·실패·로딩 상태가 화면별로 표시되는지

### 6.3 시연 시 데모 동선
1. 대시보드(`/dashboard`)에서 전체 그림 소개
2. 작업 목록(`/task`)에서 이벤트 필터 + 미배정 영상 + 다중 일괄 배정 시연 (작업자 기본값 = 현재 사용자)
3. 라벨링(`/label/:id`)에서 캔버스·도구 시연 (5분)
4. 버전관리(`/history/:id`) → diff·롤백
5. 검수 목록(`/review`) → 검수 화면 → 이슈 추가 + 승인 (V1.x 후속 — 메뉴 그룹 '작업')
6. 영상 처리 현황(`/video/completed`) → 단일 처리 단계 컬럼 확인 (모두 완료 시 '완료' 라벨)
7. 증강 요청(`/augment/request`) → 검수 완료 영상 리스트 → 다중 선택 → 결과 → 카드 승인
8. 내보내기(`/export`) → 검색·전송 상태 필터 → 포털 전송 시연 (비식별 처리 옵션 ON, '이미 내보낸 영상 포함' 토글)
9. 시스템 설정(`/manage/settings`) → 외부 연동 상태 확인 + Q&A
