## do_rules

- 본문 17px 이상 + line-height 1.6 이상으로 가독성을 확보한다.
- 모든 인터랙티브 요소에 focus ring 3px + 2px offset 을 명시한다(focus-visible 한정).
- 버튼·링크·입력의 hit area 를 최소 44x44px 로 보장한다.
- 에러는 색만 쓰지 말고 아이콘과 텍스트를 함께 표시한다(색각 이상 배려).
- 상태 배지는 색과 함께 한글 라벨을 항상 표기한다.
- 폼 라벨은 label[for] 로 입력과 명시 연결하고, 도움말은 aria-describedby 로 잇는다.
- 타이포는 typography_use ladder 의 step 을 의미대로 배정한다 — 폼 라벨·배지는 label, 도움말·캡션은 caption, 읽고 편집하는 텍스트는 body 계열이다.
- 간격·radius·shadow 는 토큰 값만 사용하고 임의 px 를 직접 입력하지 않는다.
- 표 헤더 배경은 secondary 스케일의 가장 옅은 단계를 쓴다 — 페이지 배경과 같은 색을 쓰면 열 구조가 먼저 읽히지 않는다.
- 표의 행 hover 표면은 #FFFBEB 를 쓴다 — 긴 표에서 커서가 짚은 행을 확실히 알린다. 회색 계열은 표면 배경과 겹쳐 구분이 약하다.
- 카드 표면에는 shadow.sm 만 쓴다 — md·lg 는 오버레이·팝오버 전용이다.
- 회색 표면(neutral 0~20단) 위의 보조 텍스트는 neutral 50단이 아니라 60단 이상을 쓴다 — 50단은 흰 배경에서만 AA 를 통과하고(4.51) 회색 표면 위에선 미달이다(neutral 0 위 4.13, 보조색 0 위 4.01). 60단은 세 배경 모두 통과한다(5.60~6.30).
- 범주 구분색(이벤트 유형·라벨 형태·역할처럼 우열 없이 서로 대등한 분류)은 semantic 이 선점한 대역을 피해 8슬롯 팔레트에서만 고른다 — 기준색은 순서대로 #2B7FFF · #AD46FF · #00B8DB · #00BBA7 · #615FFF · #F6339A · #62748E · #E12AFB 이고, 배경은 각 색 스케일의 가장 옅은 두 단계(50·100), 전경은 700 단계를 쓴다. 이벤트·라벨 형태·역할 세 축이 이 한 팔레트를 공유하며 축마다 별도 색표를 만들지 않는다. 슬롯 번호는 우열이나 순서를 뜻하지 않는다. 반대로 상태·성패·경고 전달에는 쓰지 않는다 — 그건 semantic 색이 담당하며, semantic 이 선점한 빨강·호박·초록 대역을 범주색으로 끌어오면 error·warn 신호가 무뎌진다.

## dont_rules

- 장식적 일러스트·그라데이션·neumorphism 을 쓰지 않는다 — 정보 우선.
- Brand 색을 큰 면적 배경으로 채우지 않는다(대비·피로감).
- Pill 버튼을 기본으로 쓰지 않는다 — 격식이 떨어진다. pill 은 status badge 전용.
- 본문에 weight 300 이하를 쓰지 않으며, Pretendard 외 한글 폰트를 혼용하지 않는다.
- 색만으로 상태를 구분하지 않는다 — 항상 아이콘 또는 텍스트를 동반한다.
- Auto-play 영상·캐러셀을 쓰지 않는다(접근성 가이드 위배). 단 라벨링 대상 영상의 사용자 조작 재생은 이에 해당하지 않는다.
- 클릭 가능한 요소를 div 로 만들지 않는다 — button 또는 a 를 쓴다.
- 공통 컴포넌트가 있는 요소를 화면에서 raw 마크업으로 다시 만들지 않는다 — 토큰 갱신이 전파되지 않는다.

## known_gaps

- 색상 팔레트는 KRDS 공식 토큰 CSS 정본(--krds-color-light-*)에서 그대로 가져온 값이다(2026-08-06 교체). 구 팔레트(#0F4C97 계열 6종)는 정본에 한 건도 등장하지 않는 출처 미기록 값이었다. design_system 스키마에 source/reference 필드가 없어 출처는 이 overview_md·known_gaps 에만 기록된다.
- typography_use 의 15단 ladder 수치는 아직 우리 도출값이다. KRDS 원문은 --krds-pc-font-size-* 로 step 별 크기를 실제로 명시하며(display 60/44/36, heading 40/32/24/19/17/15, body 19/17/15/13, label 19/17/15/13 px 상당), tokens.typography.body.base_size 17px 은 KRDS body-medium(1.7rem)과 일치한다. 그러나 label 14px 은 KRDS label 계열(19/17/15/13) 어디와도 맞지 않고 headline 18px x1.2 도 KRDS heading 단계와 다르다. ladder 를 KRDS 단계로 전환하는 것은 tailwind 토큰 재매핑으로 코드 850곳에 파급되므로 별건으로 남긴다.
- button 과 nav-link 의 크기 17px 은 KRDS label-medium(1.7rem=17px)과 일치함이 정본 대조로 확인됐다(구 known_gap 해소). 다만 굵기 500 은 우리 결정이다 — KRDS 는 --krds-typo-font-weight 로 Regular/Bold 2종만 규정한다.
- responsive_breakpoints 는 KRDS 실사용 미디어쿼리에 767 / 1023 / 1280 이 존재함을 확인해 현재 값(tailwind md 768 / xl 1280)과 정합함을 검증했다. 다만 KRDS 공식 문서가 breakpoint 표를 규범으로 명시하는지는 미확인이다.
- KRDS 토큰은 rem 단위이며 1rem=10px(root font-size 62.5%)로 추정된다 — --krds-number-* 스케일(0.2/0.4/0.6/0.8/1rem)이 2/4/6/8/10px 로 떨어지고 body-medium 1.7rem 이 17px 과 맞아떨어지기 때문이다. 그러나 html{font-size:62.5%} 선언 자체는 수신한 CSS 에서 확인하지 못했다. 이 ITEM 이 px 로 적은 수치는 그 전제 위에 있다.
- desktop_grid_cols 와 max_content_width_px 는 근거를 확인하지 못해 비워 뒀다. 내부 저작도구는 콘텐츠 폭을 제한하지 않는 편이 유리하다는 판단만 layout.notes 에 적었다.
- 팔레트 교체로 대비 실측이 전면 재검증 대상이 됐다. 주조색은 정본이 구 값보다 밝아 대비 여유가 줄었다 — #256EF4 는 흰 배경에서 4.55:1 로 AA(4.5:1)를 통과하나 여유가 거의 없고(구 #0F4C97 은 8.40:1), primary-5(#ECF2FE) 위에서는 4.05:1 로 본문 기준 미달이다(UI 요소 3:1 기준은 통과). 흰 글자 on primary 는 4.55:1, hover(#0B50D0)는 6.83:1 로 통과한다. 이는 KRDS 가 정한 값이므로 수용하되, 본문 텍스트를 primary 표면 위에 올리지 않는 것으로 회피한다.
- semantic warn 토큰이 #C25700 에서 KRDS 정본 #9E6A00 으로 바뀌었으나 같은 성격의 한계가 남는다 — 흰 배경 4.65:1 로 AA 를 통과하지만 warn 표면(#FFF3DB) 위 4.23:1, gray-5 위 4.26:1 로 미달이다. 앱의 상태 배지 다수가 이 조합이므로 배지 전경/배경 조합 재점검이 필요하다(별건).
- 코드의 회색은 stock Tailwind gray 이며 tokens.colors.neutral(KRDS gray 계열 #6D7882)과 다르다. 전 화면 파급이라 별건으로 남겨 뒀던 이 전환을 지금 진행한다.
- 행 hover 표면 #FFFBEB 는 KRDS 정본 팔레트에 없는 값이다. 표 안에서 커서가 짚은 행을 알리려면 표면 배경과 구분되는 색이 필요한데 정본에 그 용도의 토큰이 없어 채택했다. 정본에 대응 토큰이 생기면 교체한다.
- 범주 구분색 8슬롯은 KRDS 정본 팔레트에 없는 값이다. 정본은 primary·secondary·neutral·semantic(info·warn·error·success) 만 정의하는데, 이벤트 유형 8종·라벨 형태 5종·역할 3종처럼 우열 없이 대등한 분류를 가를 색이 그 안에 없다. semantic 에 억지로 배정하면 「작업자는 위험」처럼 읽히지 않아야 할 의미가 생기므로 별도 대역을 채택했다. 행 hover 표면(#FFFBEB)과 같은 처리이며, 정본에 데이터 시각화용 팔레트가 생기면 교체한다. 8색 모두 옅은 배경 위에서 WCAG AA(4.5:1)를 통과한다 — 최저 4.71:1. 대체 대상이던 호박(4.52:1)·주황(4.56:1)보다 여유가 넓다.

## color_usage

### [1]

- **token**: primary
- **use_for**: GNB, 주요 액션 버튼, 활성 메뉴, 링크, 포커스 링, 진행 바.
- **avoid_for**: 넓은 면적의 배경 채움. 대비와 눈 피로 때문에 금지한다. 강조는 면적이 아니라 위계로 만든다.

### [2]

- **token**: secondary
- **use_for**: 본문 내 링크, 보조 강조 요소, 표 헤더 배경(가장 옅은 단계).
- **avoid_for**: 주요 액션 버튼. primary 와 경쟁해 어느 쪽이 주행동인지 흐려진다.

### [3]

- **token**: neutral
- **use_for**: 본문·보조 텍스트, 테두리, 구분선, 비활성 상태, 표면 배경.
- **avoid_for**: 성공·실패 같은 의미 전달. 의미는 semantic 색이 담당한다.

### [4]

- **token**: success
- **use_for**: 검수 승인, 배치 완료, 저장 성공.
- **avoid_for**: 단순 강조나 장식. 의미가 맞을 때만 쓴다.

### [5]

- **token**: warn
- **use_for**: 검토 중, 주의가 필요한 상태, 되돌릴 수 있는 경고.
- **avoid_for**: 확정 실패. 그건 error 다.

### [6]

- **token**: error
- **use_for**: 검수 반려, 배치 실패, 입력 검증 실패, 파괴적 액션.
- **avoid_for**: 단순 강조. 빨강의 경고 신호가 무뎌진다.

### [7]

- **token**: info
- **use_for**: 안내 배너, 도움말 강조. primary 와 같은 색이므로 액션이 아님이 문맥으로 분명할 때만 쓴다.
- **avoid_for**: 클릭 가능해 보여야 하는 요소. primary 와 구분되지 않는다.

## description

대한민국 정부 디자인시스템(KRDS) 공식 토큰 기반 공공서비스용 디자인 시스템. KRDS light 팔레트(주조색 #256EF4) + Pretendard GOV, WCAG AA 강제, 큰 hit area 와 명확한 focus ring 으로 고령층·접근성 우선.

## overview_md

대한민국 정부 디자인시스템(KRDS)을 학습데이터 저작도구에 적용한 디자인 시스템. 색상 토큰은 **KRDS 공식 토큰 CSS 정본**(https://www.krds.go.kr/resources/css/token/krds_tokens.css — `--krds-color-light-*`, 2026-08-06 수신)에서 그대로 가져왔으며 주조색 #256EF4 + Pretendard GOV + WCAG AA 강제가 정체성이다. 장식보다 정보 위계와 가독성이 절대 우선한다.

다만 이 시스템의 적용 대상은 민원·고지 페이지가 아니라 **장시간 연속 작업하는 내부 저작도구**다. 라벨링 캔버스·검수 목록·배치 현황처럼 한 화면에 정보 밀도가 높은 영역이 많다. 그래서 KRDS 의 접근성 하한(본문 크기·대비·포커스 링·터치 타깃)은 그대로 지키되, 밀집 패널에서도 크기 예외를 두지 않고 ladder step 을 의미대로 배정한다 — 좁으면 글자를 줄이지 말고 열 수를 줄인다. **앱에 다크 표면은 없다**(2026-08-06 다크 테마 폐지 확정). 유일한 예외는 영상 프레임을 얹는 미디어 매트와 그 위 오버레이(프레임번호 배지·모달 스크림)뿐이다.

이 ITEM 이 진실원이며 코드가 이를 따른다. 같은 사업의 관제서버 프로젝트 DS-001 도 동일한 KRDS 정본 값을 사용하므로, 사업 전체에서 색상 축이 한 값으로 정렬돼 있다.

## iteration_guide

- 새 컴포넌트는 먼저 카탈로그(ui_component)에서 같은 역할이 있는지 찾고, 있으면 재사용한다. 없을 때만 신설한다.
- 색은 tokens 의 base hex 만 쓰고, 톤 변형이 필요하면 같은 scale 안에서만 이동한다. 새 hex 를 도입하지 않는다.
- 타이포는 typography_use ladder 의 step 만 쓴다. 표에 없는 크기를 임의로 만들지 않는다.
- 밀집 작업 패널이라도 크기 예외를 두지 않는다 — 그 요소가 어떤 step 인지 정하고 그 값을 쓴다. 세로 밀도는 44px 터치 타깃이 지배하므로 글자를 줄여도 이득이 작고, 대신 가로 잘림만 심해진다. 좁으면 크기를 낮추지 말고 열 수를 줄인다.
- spacing / radius / shadow / motion 은 tokens 표의 값만 쓴다.
- semantic 색(success/warn/error/info)은 의미가 맞을 때만 쓰고 단순 강조에 쓰지 않는다.
- 화면은 라이트 단일 기준이다 — 다크 변형 컴포넌트를 만들지 않는다. 영상 프레임을 얹는 매트와 그 위 오버레이만 예외로 어두운 색을 쓴다.
- 접근성 속성(role, aria-*, label 연결)은 컴포넌트가 기본 제공하고, 화면이 매번 다시 붙이게 하지 않는다.

## shape_principle

Radius 4-8px 의 단정한 라운드. 카드·입력·버튼 모두 6-8px 로 통일하고, pill(full) 은 status badge 에만 예외적으로 허용한다. 둥근 정도가 클수록 격식이 떨어진다는 공공서비스 통념을 따른다.

## font_substitutes

본문·제목은 KRDS 지정 **Pretendard GOV**(정부 전용 서브셋, 오픈소스)를 웹폰트로 직접 서빙한다. 코드·수치 병기용 D2Coding 도 오픈소스이며 동일하게 자체 서빙한다(폐쇄망 대응 — CDN 의존 금지). 미탑재 환경 폴백은 Pretendard → 시스템 한글 산세리프(Apple SD Gothic Neo, Noto Sans KR) 순이며, 폴백 상황에서도 한글 본문에 다른 계열 폰트를 혼용하지 않는다.

## key_characteristics

- Brand 블루 #256EF4 — 정부 디자인시스템 정본 주조색. 흰 배경 대비 4.55:1 로 AA 를 통과하나 여유가 없어 본문 텍스트를 primary 표면 위에 올리지 않는다
- Pretendard 본문 17px 이상 + line-height 1.6 이상 — 고령층·장시간 작업 가독성
- WCAG 2.1 AA 이상 대비 강제 (본문 4.5:1, 큰 텍스트 3:1)
- Focus ring 3px outline + 2px offset, focus-visible 한정 — 키보드 접근성
- Hit area 최소 44x44px — 모바일 터치 및 접근성 가이드
- Radius 4-8px 단정한 라운드, pill(full) 은 status badge 전용
- 색만으로 상태를 구분하지 않는다 — 항상 아이콘 또는 텍스트 동반
- 장식·그라데이션·일러스트 최소 — 정보 전달 우선

## whitespace_principle

정보 위계 우선. 섹션 사이 40-64px 여백으로 작업 단계를 구분하고, 카드 안쪽 24px, 폼 필드 사이 16-24px 을 둔다. 답답함보다 명확함이 우선이다. 라벨링·검수의 우측 작업 패널처럼 한 화면에서 많은 항목을 동시에 봐야 하는 영역은 예외적으로 8-16px 까지 좁히되, 터치 타깃 44px 하한은 그 안에서도 유지한다. 밀도는 글자 크기를 낮춰서가 아니라 여백과 레이아웃으로 확보한다.

## responsive_breakpoints

### mobile

- **width**: < 768px
- **key_changes**: LNB 를 숨기고 오버레이로 전환. 표는 카드형으로 스택. 라벨링 캔버스 등 정밀 작업 화면은 이 폭을 지원 대상으로 보지 않는다.

### tablet

- **width**: >= 768px
- **key_changes**: LNB 노출, 2열 레이아웃 허용. 포털 사용자 화면의 주 대상 폭.

### desktop

- **width**: >= 1280px
- **key_changes**: 라벨링·검수의 3분할(사이드바 + 캔버스 + 우측 패널) 레이아웃. 내부 작업자 화면의 기준 폭.
