## description

작업목록 KPI 카드용 워크플로 상태별 건수를 필터 결과 전체 기준으로 반환한다(현재 페이지가 아니다). 변경 전에는 FE 가 현재 페이지 20건 안에서 집계해 숫자가 틀렸다.

[필터] 목록(GET /v1/tasks/board)과 동일하게 status/q/eventTypeCd/workerId 가 적용된다.

[★ workStatus 무시] workStatus 는 전달돼도 무시한다 — KPI 카드 자체가 workStatus 선택지이므로 이미 좁혀진 집합 위에서 세면 항상 1개 카드만 값을 갖는다. 목록과 같은 쿼리스트링을 그대로 보내도 안전하다.

[★ FE 연동 지침 — 미배정 카드] 미배정 카드 클릭 시 status=UNASSIGNED 가 아니라 workStatus=UNASSIGNED 를 보낸다. UNASSIGNED 는 두 축에서 서로 다른 집합을 뜻한다 — status=UNASSIGNED 는 배치 상태 필터를 끄고 미배정 전체를, workStatus=UNASSIGNED 는 현재 배치 상태 필터 안의 미배정만 반환한다. unassigned 버킷은 후자를 세므로 카드 클릭에서 status 를 바꾸면 카드 숫자와 목록 totalElements 가 어긋난다(예: 카드 3 ↔ 목록 13).

[★ inProgress = PENDING] inProgress 는 BoardWorkStatus.IN_PROGRESS 가 아니라 PENDING(배정됨 · 검수 미제출)을 센다. 시스템은 IN_PROGRESS 라는 값을 아예 반환하지 않으며(워크플로 ASSIGNED → PENDING), 필드명은 화면 카드 라벨이 '작업중'이기 때문이다. 변경 전 FE 가 IN_PROGRESS 를 세고 있어 REVIEWER 시각에서 0 으로 고정도던 결함이 있었다.

[불변식] total == unassigned + inProgress + reviewPending + completed + rejected. 화면 카드는 5종(전체/미배정/작업중/검수요청/반려)만 쓰지만 completed 를 빼면 카드 합과 총건수가 어긋나 '숫자가 틀렸다'는 오인을 부르므로 함께 반환한다.

[스냅샷] 목록과 별도 요청이므로 각 값은 조회 시점 스냅샷이다(대시보드성 KPI — 강한 정합성을 요구하지 않는다).
