## description

작업목록 KPI 카드용 워크플로 상태별 건수를 필터 결과 전체 기준으로 반환한다(현재 페이지가 아니다).

[필터] 목록(GET /v1/tasks/board)과 동일하게 status/q/eventTypeCd/workerId 가 적용된다.

[★ 제외분 배제] 제외 표시가 붙은 영상은 이 집계에서 빠진다. 집계는 목록과 같은 조건 조립을 공유하므로, 목록이 제외분을 빼면 집계도 같이 줄어야 한다 — 조건이 갈리면 목록은 줄었는데 카드 숫자는 그대로인 어긋남이 생긴다.

[★ 제외 판정을 두는 자리] 제외 판정은 조회 조건에만 붙이고 버킷 판정식은 건드리지 않는다. 그래야 아래 불변식이 유지된다 — 판정식에 제외를 섞으면 어느 버킷에도 들지 않는 행이 생겨 버킷 합이 총건수와 달라진다.

[★ 제외됨 건수] 응답에 excludedCount 한 키가 더해져 제외 표시가 붙은 건수를 함께 싣는다. 필터 범위 안에서 센다(필터를 무시한 전체가 아니다) — 화면이 그 숫자를 눌러 제외분만 보는 목록으로 전환하므로 숫자와 누른 결과가 일치해야 한다. 0건이어도 실린다 — 빠지면 화면이 「제외된 것이 없다」와 「제외 기능이 없다」를 구분해 보여 주지 못한다. 기존 집계 키의 이름·타입·뜻은 그대로이고 키 하나가 느는 것이다. 이 이름은 영상 처리 현황·작업 목록·검수 목록 세 목록에서 같다.

[★ workStatus 무시] workStatus 는 전달돼도 무시한다 — KPI 카드 자체가 workStatus 선택지이므로 이미 좁혀진 집합 위에서 세면 항상 1개 카드만 값을 갖는다. 목록과 같은 쿼리스트링을 그대로 보내도 안전하다.

[★ FE 연동 지침 — 미배정 카드] 미배정 카드 클릭 시 status=UNASSIGNED 가 아니라 workStatus=UNASSIGNED 를 보낸다. UNASSIGNED 는 두 축에서 서로 다른 집합을 뜻한다 — status=UNASSIGNED 는 배치 상태 필터를 끄고 미배정 전체를, workStatus=UNASSIGNED 는 현재 배치 상태 필터 안의 미배정만 반환한다. unassigned 버킷은 후자를 세므로 카드 클릭에서 status 를 바꾸면 카드 숫자와 목록 totalElements 가 어긋난다(예: 카드 3 ↔ 목록 13).

[★ FE 연동 지침 — 제외됨 건수] 「제외됨 건수」를 눌러 제외분 보기로 전환할 때는 workStatus 를 빼고 요청한다. excludedCount 는 workStatus 축을 무시하고 세지만(나머지 필터는 그대로 적용된다) 목록은 그 축을 적용하므로, workStatus 를 켠 채 전환하면 전환 결과가 누른 숫자보다 적어진다. 축을 빼고 보내면 누른 숫자와 전환 결과가 일치한다. 집계 쪽을 workStatus 에 맞춰 좁히지는 않는다 — 그러면 그 축에 가려진 제외분이 숫자에서 빠져 감춰진 것이 있다는 사실 자체가 드러나지 않는다.

[★ inProgress = PENDING] inProgress 는 BoardWorkStatus.IN_PROGRESS 가 아니라 PENDING(배정됨 · 검수 미제출)을 센다. 시스템은 IN_PROGRESS 라는 값을 아예 반환하지 않으며(워크플로 ASSIGNED → PENDING), 필드명은 화면 카드 라벨이 '작업중'이기 때문이다. 변경 전 FE 가 IN_PROGRESS 를 세고 있어 REVIEWER 시각에서 0 으로 고정되던 결함이 있었다.

[불변식] total == unassigned + inProgress + reviewPending + completed + rejected. 화면 카드는 5종(전체/미배정/작업중/검수요청/반려)만 쓰지만 completed 를 빼면 카드 합과 총건수가 어긋나 '숫자가 틀렸다'는 오인을 부르므로 함께 반환한다. excludedCount 는 이 합의 항이 아니다 — 제외분은 total 에서도 이미 빠져 있어 별개 축이다.

[스냅샷] 목록과 별도 요청이므로 각 값은 조회 시점 스냅샷이다(대시보드성 KPI — 강한 정합성을 요구하지 않는다).
