# 라벨 버전 저장·이력 추적

## goal

## description

검수 승인(APPROVED) 시점에 영상 단위 라벨 전체 스냅샷(JSON)을 LS_LABEL_VERSION.LABEL_PAYLOAD에 적재하고 VERSION_HASH(payload SHA-256)로 식별한다(SAVE_REASON_CD='APPROVED'). 라벨 저장 시점에는 버전을 생성하지 않으며 — 학습데이터로 확정된 단위(검수완료)만 버전 대상이다. 외부 VCS(Gitea) 미사용 DB 스냅샷 방식. ★변경이력 모델 재정의(ADR-033, 2026-07-30) — 이와 별개로 '라벨 1건=1행' 부분 upsert 이력에서 '저장 이벤트 1회=1이벤트+diff(ADD/MDFCN/DEL_CNT, CHG_DTL_CN JSON)'로 전환됐다(V114, LS_DATA_LBL_HSTRY). 라벨 저장 시점에는 버전을 생성하지 않고 검수 승인 시점에만 학습데이터 버전(LS_LABEL_VERSION)이 생성된다는 2계층 구분은 그대로 유지된다 — 변경된 것은 '저장 이벤트' 자체의 이력 기록 방식이다(UC-021의 되돌리기 기능이 이 이력을 사용한다). ★검수 승인은 영상 1건을 한 트랜잭션으로 확정하되 스냅샷 행은 라벨을 가진 프레임마다 1건씩 쌓인다 — 한 영상이 한 행이 아니라 라벨 보유 프레임 수만큼이며, 같은 스냅샷인지는 프레임과 페이로드 해시의 짝으로 식별한다.

## preconditions

- 대상 영상의 라벨이 검수 제출되어 검수 대기 상태다
- REVIEWER로 인증되어 있다
- 이 흐름의 트리거인 검수 승인이 거부되지 않아야 한다. 검수 워크플로 상태와 같은 자리에 보관되는 비식별화 완료 여부가 미완료이면 승인 자체가 막혀 이 흐름이 시작되지 않는다. 외부에서 이미 라벨링이 끝난 산출물을 가져와 원본으로 지정해 들여온 영상만 미완료로 시작하고, 그 밖의 영상은 완료가 기본값이라 종전과 같이 진행된다.

## postconditions

- 검수 승인된 라벨 스냅샷이 VERSION_HASH로 식별되어 DB에 적재된다
- 승인이 거부된 경우에는 버전 스냅샷도 변경이력도 남지 않고 대상 영상은 검수 대기 상태 그대로 유지된다

## alternate_flows

### 비식별 미완료로 승인이 거부되어 버전이 생성되지 않음

**steps**:

- 시스템은 검수 상태를 전이하기 전에 먼저 비식별화 완료 여부를 판정한다.
- 미완료이면 승인을 거부하고 주 흐름의 다음 단계로 넘어가지 않는다.
- 따라서 라벨 전체 스냅샷 적재도, 해시에 의한 버전 식별도, 변경이력 기록도 일어나지 않는다. 학습데이터 산출물 재생성과 관제 통지도 함께 발생하지 않는다.
- 이 값이 막는 것은 검수 승인뿐이다. 라벨 조회와 프레임 이미지와 영상 스트리밍은 이 값으로 닫히지 않는다. 그 통로들까지 함께 닫는 것은 비식별 누락 신고이며, 이 값과는 별개의 축이다.
- 비식별이 끝나 그 값이 완료로 바뀐 뒤 검수자가 다시 승인하면 주 흐름이 그대로 진행되어 버전 스냅샷이 생성된다.

- **trigger**: 검수자가 승인을 시도했으나 대상 영상의 비식별화 완료 여부가 미완료다
