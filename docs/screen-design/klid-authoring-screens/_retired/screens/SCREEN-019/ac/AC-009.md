# 검수 완료 후 수정 통지(TASK_MODIFIED)

## priority

high

## scenario

### then

- 수정이 발생하면 그 영상에 재검토 표시(LS_RAW_DATA_STATUS.REVLT_YN='Y')가 세워져 재검수 대상이 되고, 검수자가 그 수정을 다시 검수해 승인해 표시가 해제된 시점에 export 를 새 버전 폴더 v{n+1} 로 전량 재생성한다(이미지 2벌 포함·승인 경로와 동일 산출). 대상은 개수가 아니라 성질로 정해진다 — 사람이 콘텐츠를 고치는 모든 경로가 대상이고 제외는 넷뿐이다(외부 시계열 콜백·비식별 누락 신고 접수·운영자 정정 배치·이벤트 어노테이션 지연 승인). 판정 기준은 사람이 산출물에 들어가는 내용을 바꿨는가 하나다. 예시는 라벨·트랙 편집/병합·버전 롤백·촬영환경·프레임 설명·개인정보 메타(영상 축·프레임 축)·메타 수동 편집·이벤트 어노테이션 저장이다. 재-export 트리거는 authoring.control-notify.enabled 토글과 무관하게 항상 동작한다. 수정 후 재승인 전까지 관제는 직전 승인본을 보며 그 구간의 최신 내용은 관제에 없다 — 학습데이터는 검수를 통과한 것만 확정이므로 인지하고 수용한 선택이다
- export 가 SUCCEEDED 된 뒤에 관제 통지 연동(dead-letter·재등록 큐·Resilience4j)이 TASK_MODIFIED 를 push 한다 — 요청 식별자(UUID)는 통지 본문·헤더 어디에도 실리지 않는 폴백 원장 내부 키이고, 관제 쪽 중복 판정 축은 job_id 다 — export 가 비동기라 통지가 앞서면 관제가 구 버전 폴더를 픽업한다
- 페이로드는 다음으로 구성된다 — job_id(RAW_SN) + changed_items(images·jsons) + ver_expln(선택) + output_ver_no(선택). changed_items 는 내부 식별자(SRC_SN)가 아니라 산출 폴더의 실제 파일명({FRM_NO 4자리 zero-pad}.jpg/.json) 리스트이며, 범위는 export 재생성 동반 여부로 갈린다(동반이면 전 프레임 이미지·JSON, 재생성이 없으면 빈 리스트 — 어느 경우든 통지 자체는 발송된다). 마지막 수정 일시 · 변경 종류 · 변경 요약 카운트 · 요청 ID 는 지금은 보내지 않는다(변경 종류는 내부 디바운스 축적 키·감사 기록 전용, 요청 식별자는 폴백 큐 내부 키다). PII·토큰·라벨/메타 본문·절대 경로는 포함하지 않는다(파일 이름만)
- ver_expln 은 optional 이라 null 이면 키를 생략한다 — 관제 dataset_versions.ver_expln 이 NOT NULL 이라 명시적 null 을 보내는 것보다 미전송이 안전하다(TASK_COMPLETED 의 required 키 유지와 정반대인 의도된 비대칭). 판정 단일 원천은 버전 설명 산출 정책 한 곳이다
- 관제서버가 통지 수신 후 조회 API 로 상세를 가져가 UPSERT 한다
- output_ver_no(산출 폴더 버전 번호)도 optional 이라 값이 없으면 키를 생략한다 — 관제는 키 없음을 "산출물 변경 없음 → 재픽업 불요" 로 읽으며, 값의 유무는 changed_items 와 같은 축(export 재생성 동반 여부)에서 갈린다
- 재검토 표시는 수정이 발행한 수정 통지 이벤트(needsRecheck)를 소비해 세우고, 그 표시가 서 있는 동안 통지 축적 원장이 flush 후보 조회와 클레임 UPDATE 두 곳에서 축적분을 제외해 통지를 보류한다. 재승인이 승인 처리에서 표시를 해제하면 축적 윈도우가 풀린다 — 재승인은 ReviewApprovedEvent 를 발행하지 않으므로(중복 방지) 재생성과 TASK_MODIFIED 는 디바운서가 내고, 최초 승인만 그 이벤트로 강제 재생성 후 TASK_COMPLETED 를 낸다

### when

- 검수자가 그 수정을 다시 검수해 승인하면 변경 파일명 목록(changed_items.images·jsons)을 구성해 통지한다

### given

- 대상 영상(RAW_SN)이 검수 완료(APPROVED) 이력을 보유한다
- 검수 완료 후 라벨/메타 수정이 발생한다

### and_examples

#### [1]

- **case**: export 재생성 실패
- **result**: 통지를 보류하고 실패 회수기가 재산출 성공 후 발송을 재개한다(유실이 아니라 성공 시점으로 지연)

#### [2]

- **case**: 통지 전송 실패
- **result**: dead-letter/재등록 큐 적재 후 재시도

#### [3]

- **case**: 동일 트랜잭션·짧은 시간 내 다수 변경
- **result**: 재검토 표시가 서 있는 동안 만료 flush 를 보류하고, 재승인으로 표시가 해제된 뒤 다음 flush tick 에 영상 1건 단위로 1회 통지한다 — 수정 횟수와 무관하게 재승인 1건이 새 버전 폴더 1개와 통지 1건에 대응한다

#### [4]

- **case**: [폐기] 검수 완료 영상의 비식별 누락 신고 접수
- **result**: 지금은 그렇게 하지 않는다 — 승인 이력이 있는 영상은 비식별 누락 신고 접수 자체가 412 로 거부되므로(승인 이력 판정, 역할 무관) 이 경로에 도달하지 않는다. 이 구간에 대한 TASK_MODIFIED(META_UPDATED) 발행 분기를 두지 않는다

## statement

검수 완료(APPROVED) 후 라벨/메타를 수정하면 그 영상은 재검수 대상이 되고, 검수자가 그 수정을 다시 승인한 시점에 export 를 새 버전으로 재생성하고 그 성공 이후에 수정 요약만 담은 TASK_MODIFIED 를 멱등 발행한다
