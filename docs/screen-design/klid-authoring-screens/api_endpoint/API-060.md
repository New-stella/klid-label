## description

검수 완료된 영상에 대해 외부 증강 시스템에 증강을 요청한다. 검수자 전용이다.

[검수 완료 영상만 대상이다] 미검수 영상이 섞여 있으면 400 으로 거부하며 어느 영상이 막혔는지 응답에 함께 담는다.

[생성 조건 5필드는 전부 필수이며 허용 코드로 닫혀 있다] 시간·계절·날씨·지형·심각도를 입력하면 외부 규격의 최상위 구조화 생성 조건으로 전달되고, 자유 지시문과 분리한 형태로 요청 원문이 보관된다. 계약이 정한 허용 코드 밖의 값은 거부한다 — 구 서술(자유 문자열이라 서버가 값 자체를 좁히지 않는다)은 폐기다. 다섯 항목을 전부 필수로 받는 것은 우리 규칙이며 계약은 최소 한 항목만 요구한다 — 하나라도 비면 벤더가 어떤 기본값으로 채울지 알 수 없어 결과가 비결정적이 되므로 더 엄격한 쪽을 택했다. 증강 종류는 이 조건에서 파생하지 않고 별도 목록으로 받는다. 그 값이 종류 판정에 흘러가면 산출물 경로가 조작될 수 있기 때문이다.

[이벤트 유형과 세부 유형은 요청자가 고르지 않는다] 외부 규격이 필수로 요구하는 값이라 요청 본문에서 받지 않고 서버가 중립 값 ETC 로 고정해 싣는다. 우리 증강은 이미 이벤트가 기록된 영상의 프레임 이미지만 바꾸는 것이라 어떤 장면을 만들지 정할 필요가 없고, 그 값은 배경에 장면을 만들어 넣는 외부 규격의 축이기 때문이다. ETC 는 벤더와 협의가 끝난 값이지만 우리가 보유한 규격서 판본에는 아직 없다 — 규격서가 개정되면 대조가 필요하다.

[증강 종류는 단일 값이다] 겨울·야간·우천은 요청자가 고르지 않는다 — 생성 조건으로 지정하는 값이라 종류 목록은 AUGMENT 하나만 받는다.

[같은 조건으로 몇 번이든 다시 요청할 수 있다] 생성 결과가 매번 다르므로 원하는 결과가 나오지 않으면 동일 조건 재요청이 정당한 동선이다. 서버는 중복을 막지 않으며 연타 방지는 화면이 책임진다. 그 결과 같은 영상·같은 종류의 파생이 여러 건 공존할 수 있어, 결과를 구분하는 축은 요청 시 보관된 생성 조건 원문이다.

[파생본에서는 요청할 수 없다] 파생 깊이는 1 로 고정돼 있어 이미 파생인 영상은 400 으로 거부된다.

[외부 증강 시스템이 연동되지 않은 환경에서는 접수하지 않는다] 연동이 설정되지 않았으면 요청 시점에 503 으로 거부한다. 구 동작은 접수만 하고 외부로 보내지 않아, 요청은 진행 중으로 보이다가 한참 뒤 만료 회수로 실패 종결됐다. 가짜 결과를 만들지는 않으므로 데이터가 오염되지는 않았으나, 그 환경에서 증강을 쓸 수 없다는 사실을 요청자가 즉시 알 수 없었다. 미연동은 요청자가 해소할 수 있는 조건이 아니라 배포 환경 구성이므로, 신고 구간 거부(412)와 같은 코드를 쓰지 않는다.
이 거부는 인가와 형식 검증 뒤, 파생 차단 뒤, 그리고 데이터 조회 앞에서 판정한다 — 인가 뒤여야 권한 없는 요청자에게 연동 여부가 드러나지 않고, 파생 차단 뒤여야 되돌릴 수 없는 조건이 먼저 안내되며, 조회 앞이어야 어차피 거부할 요청이 데이터 왕복을 태우지 않는다. 그 결과 미연동 환경에서는 미검수·신고 구간·프레임 미추출 거부가 이 거부에 가려 나타나지 않는다 — 외부가 연동되지 않았으면 어느 경우든 증강이 일어날 수 없으므로 의도된 순서다.
