# 마킹에서 도출된 VLM 위탁 입력(frame_policy·event_type)

## notes

근거: UC-019(VLM 시계열 위탁 절) · DOMAIN-011 정책(논블로킹 제출·frame_policy 도출·event_type 비차단). 판정 지점: 위탁 요청 조립 시점의 frame_policy·event_type 도출 로직과 마킹 단계 신고 접수 조건 가드.

## priority

high

## scenario

### then

- frame_policy.mode 는 'frame_selected' 이고 selected_frames 는 정렬·중복제거 후 0 이상 최대 600건으로 제한되어 초과분이 절단된다 (음수 프레임 인덱스는 싣지 않는다)
- event_type 은 관제 인입값(LS_DATA_INGEST.VRFC_EVNT_TYPE_CD)을 그대로 실어 위탁하며 화이트리스트 검증으로 사전 차단하지 않는다
- frame_policy 에 framerate 를 두지 않는다 — 추출 간격·장수 세부값은 외부 분석 서버가 관리하고 연동 측은 mode 와 selected_frames 만 지정한다
- 위탁은 describe(POST /v1/videovlm-klid/describe)와 describe-sub(POST /v1/videovlm-klid/describe-sub) 두 건으로 제출되며 각 요청에 서로 다른 request_id 가 부여된다

### when

- 마킹이 완료되어 VLM 시계열 위탁 요청이 조립된다

### given

- 수동 마킹으로 620개 프레임이 선택되었다 (중복·비정렬 포함)

### and_examples

#### [1]

- **case**: 마킹 본문에서 쓸 수 있는 프레임 인덱스를 하나도 얻지 못하는 경우(마킹 부재·본문 파싱 실패·유효 인덱스 0건)
- **result**: frame_policy.mode 는 'frame_interval' 로 내려가고 selected_frames 는 싣지 않는다 — 빈 배열은 규격 위반이라 거부되고, 추출 간격은 외부 분석 서버가 정한다. 마킹 모드(수동·자동)로 가르지 않는다: 모드는 그 인덱스를 누가 골랐는지만 구분하며 도출 방법은 같다

#### [2]

- **case**: 배치 단계가 MARKING_READY 가 아닌 상태에서 마킹 단계 비식별 신고(POST /v1/videos/{rawSn}/deident-report) 시도
- **result**: 412 PRECONDITION_FAILED 로 거부되고 처리 단계(PROCESSING/COMPLETED/FAILED/PENDING)를 구분해 알리지 않는 단일 문구로 응답한다

#### [3]

- **case**: 위탁 제출 직후 스텝이 반환하는 것
- **result**: 제출 개시만 확인하고 즉시 반환한다 — 외부 응답을 기다리며 파이프라인 스레드를 점유하지 않으며, 이 시점에 수락 여부는 보장되지 않는다

#### [4]

- **case**: 수락(ACK) 기록 시점
- **result**: 상관키와 마킹 상태를 선커밋한 뒤 완료 핸들러가 전용 실행 경로에서 원장을 ISSUED 에서 ACCEPTED 로 비동기 전이시킨다

#### [5]

- **case**: 제출 후 수락도 실패도 신호가 오지 않는 경우
- **result**: 미결 스위퍼가 회수한다 — 수락 응답조차 못 본 건(ISSUED)과 수락 후 콜백이 없는 건(ACCEPTED)에 서로 다른 대기 창을 적용하며, 후보는 처리 전 조건부 갱신으로 원자 선점해 두 노드가 같은 건을 두 번 재위탁하지 않는다

## statement

마킹 완료 시 frame_policy(마킹 본문에서 프레임 인덱스를 얻으면 frame_selected 모드로 그 인덱스를 정렬·중복제거하여 0 이상 최대 600건으로 제한해 싣고, 하나도 얻지 못하면 frame_interval 모드로 내린다 — 빈 selected_frames 는 규격 위반이라 거부된다)와 event_type(관제 인입값 그대로, 검증·차단 없음)이 도출되어 외부 시계열 분석 위탁의 논블로킹 제출 입력이 되며, 위탁은 describe(POST /v1/videovlm-klid/describe)와 describe-sub(POST /v1/videovlm-klid/describe-sub) 두 건으로 각각 별도 request_id 를 부여해 제출된다. 배치 단계가 MARKING_READY 가 아닌 상태에서의 마킹 단계 비식별 신고는 412 로 거부된다.
