# 버전 diff 비교·롤백 복구

## priority

high

## scenario

### then

- ① 1건 선택 = 버전 스냅샷 ↔ 현재 작업본(LS_DATA_LBL) 비교. 작업본 payload 는 승인 스냅샷과 동일 방식(같은 직렬화 경로·LBL_SN 오름차순·1MB 초과 폴리곤 단순화 포함)으로 생성해 오탐을 막고 저장하지 않는다
- ② 2건 선택 = 두 DB 스냅샷(LABEL_PAYLOAD)을 앱에서 비교한다
- ③ 비교축은 id·lblTypeCd·label·labelId·points·trackId 6개다(구 3축 lblTypeCd·label·points 는 폐기 — 트랙 병합처럼 시스템이 스스로 TASK_MODIFIED 를 발행한 변경이 '변경 없음'으로 나오던 결함). AI 메타(autoLblYn/confScore/lblSrcCd)·labelName/color 는 의도적 제외
- ④ 변경 0건은 빈 목록이 아니라 '변경 없음' 안내로 표시된다
- ⑤ 롤백은 대상 스냅샷 행을 재활성한다 — 새 버전 행을 적층하지 않는다(구 SAVE_REASON_CD='ROLLBACK' 적층 폐기)
- ⑥ 라벨 본문을 작업본(LS_DATA_LBL)으로 실제 복원하며 LBL_SN·AI 메타(AUTO_LBL_YN/신뢰도/출처)·TRCK_ID 까지 보존 복원한다(점유된 PK 만 신규 발급 폴백)
- ⑦ 롤백 행위(누가·언제·어느 VERSION_HASH 로)를 LS_DATA_LBL_HSTRY 에 기록한다

### when

- 버전 1건을 선택하면 GET /v1/versions/{version}/diff-with-working 으로 현재 작업본과의 차이를 요청한다
- 버전 2건을 선택하면 GET /v1/versions/{version}/diff?compareWith={fromHash} 로 두 스냅샷의 차이를 요청한다
- POST /v1/versions/{version}/rollback(body srcSn)으로 복구한다

### given

- 대상 프레임(SRC_SN)에 1건 이상 라벨 버전 스냅샷이 존재하고 인증되어 있다

### and_examples

#### [1]

- **case**: 동일 페이로드 버전(VERSION_HASH 동일)
- **result**: 변경 없음 안내

#### [2]

- **case**: 멱등 롤백 — 현재 active 가 이미 대상 스냅샷
- **result**: no-op (라벨 재작성·이력·통지 모두 없음)

#### [3]

- **case**: 손상 스냅샷(items 가 명시적 배열이 아님)으로 작업본 비교 요청
- **result**: 400 — 빈 결과는 화면에서 '변경 없음'으로 오인되므로 거부. 기존 /diff 의 장애격리(파싱 실패 시 빈 리스트)는 유지하며 통일하지 않는다

#### [4]

- **case**: 비식별 누락 신고 구간(DE_IDNTF_YN='F') 영상의 diff·롤백
- **result**: 412 PRECONDITION_FAILED

#### [5]

- **case**: 검수 완료 후 복구
- **result**: export 새 버전 재생성 + UC-009 TASK_MODIFIED 통지 트리거

## statement

버전 1건 선택 시 스냅샷과 현재 작업본을, 2건 선택 시 두 스냅샷을 비교해 diff를 산출하고, 복구 시 대상 스냅샷 행을 재활성해 라벨 본문을 작업본으로 복원한다(새 버전 적층 없음)
