# 해상도 변경 파생영상 생성·좌표 재계산

## priority

high

## scenario

### then

- ① 산출 크기가 원본과 같아지는 프리셋만 건너뛰고 나머지 프리셋마다 새 파생영상(RAW_SN, ORGNL_RAW_SN=원본)을 PENDING(생성 중)으로 예약한다 — 업스케일(확대)도 허용한다(구 targetH>=srcH 400 거부 가드 제거)
- ② 비디오 파일은 원본(비식별) 복사이며 재인코딩하지 않는다. 프레임 이미지셋만 목표 해상도로 리스케일한다(축소·확대 모두)
- ③ 라벨/이미지 좌표를 가로·세로에 같은 균일 배율(종횡비 보존)로 재계산해 파생영상에 적재한다 — 축마다 다른 배율을 두지 않으며 오프셋 가산이 없어 그 배율만으로 원본 좌표가 완전히 역산된다(BBOX/POLYGON/세그멘테이션/키포인트 전 종류)
- ④ 저장모델은 증강과 통합된다 — LS_DATA_AUG(AUG_TYPE_CD=RESL_1080P/RESL_720P/RESL_480P) + LS_DATA_AUG_LBL_MAP(COORD_RECALC_YN/SCALE_X/SCALE_Y) 에 적재하고 중복은 부분 유니크 인덱스 UK_LS_DATA_AUG_RESL(V125)로 방지한다(구 전용 테이블 LS_RESOLUTION_EXPORT·LS_RESOLUTION_LBL_MAP 은 V126 에서 폐기)
- ⑤ finalize 성공 시 ACCEPTED(생성 완료)로 확정하고 실패 시 예약행을 삭제한다 — 1건 이상 성공=201 / 전부 실패=500 / 대상 프리셋 전부 스킵=400
- ⑥ 응답에 내부 파일 경로를 포함하지 않는다(CWE-209)
- ⑦ 파생영상은 미검수(PENDING)로 배정·라벨 확인·검수 흐름에 진입하되 accept/reject(활용 여부 판단)는 차단된다(내부 생성물)
- ⑧ 프리셋의 두 수치는 산출 프레임의 고정 크기가 아니라 상한이다 — 원본의 짧은 변을 프리셋의 짧은 값에 맞추는 배율을 구하고, 그 배율로 계산한 긴 변이 프리셋의 긴 값을 넘을 때만 긴 변이 상한에 맞도록 배율을 낮춘다. 720p 프리셋 기준 산출 크기는 1920x1080 → 1280x720, 1440x1080 → 960x720(짧은 변 기준), 640x480 → 960x720(업스케일 허용), 1080x1920 → 720x1280(세로 영상), 2560x1080 → 1280x540(긴 변 상한에 걸려 배율이 낮아진 경우)이다
- ⑨ 산출 프레임에 패딩을 두지 않는다 — 산출 이미지의 어느 픽셀도 채움색으로 채워지지 않으며, 산출 프레임 크기는 원본 종횡비에 따라 달라진다 실제로 산출된 이미지 파일의 크기가 ⑧ 이 규정한 크기와 같아야 한다 — 계산된 크기와 파일의 크기가 어긋나면 라벨 좌표가 이미지 경계를 벗어난다.

### when

- REVIEWER가 표준 해상도 프리셋(RESL_1080P/RESL_720P/RESL_480P, 미지정 시 3종 전체)으로 POST /v1/videos/{rawSn}/resolution 을 요청한다

### given

- 원본 영상과 라벨이 존재하고 대상이 파생영상이 아니다(ORGNL_RAW_SN=null — 파생 깊이 1 고정)
- 원본의 비식별 영상과 비식별 프레임이 존재한다
- REVIEWER로 인증되어 있다
