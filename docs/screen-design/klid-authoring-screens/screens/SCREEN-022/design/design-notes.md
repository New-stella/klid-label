### 본 상태로 고른 시나리오

**겨울 선택 + 영상 #3187 선택 + 생성 조건 5필드 중 지형 미입력**. 이유는 골격이 처리 요청 버튼을
`state: disabled` 로 못박고, 동시에 "생성 조건 미입력 경고 문구" 컴포넌트를 두었기 때문이다. 이 둘이
같이 성립하는 유일한 상태가 이것이라 본 상태로 삼았고, 나머지 상태(미선택 · 해상도 변경 · 전부 유효 ·
50자 초과 · 조회 상태 4종 · 토스트 2종)는 참고 패널로 분리했다.

### 골격에 없어 그리지 않은 것

- **요청 취소·재시도·미리보기** — 골격에 없다. 이력 카드는 결과 화면으로 가는 이동만 한다.
- **뒤로가기 버튼** — 하단 바의 `취소`(이전 화면으로)가 그 역할이라 따로 두지 않았다.
- **생성 모델 설정·프롬프트 튜닝** — 증강은 외부 시스템에 위탁하는 것이고 저작도구는 요청·수신·검수만
  한다. 모델 쪽 조작은 이 화면의 책임이 아니다.
- **결과 편집** — 결과는 원본과 다른 새 영상으로 만들어지고 그 검수는 다른 화면 몫이다. 이 화면은 요청까지다.

## § 디자인 결정 (골격이 규정하지 않은 부분)

### 1. ★수행 주체 표기를 화면에 두지 않는다 (사용자 확정)

초안은 처리 종류 카드마다 `외부 생성 시스템에 위탁` / `저작도구가 직접 수행` 칩을 붙이고 페이지
설명에도 같은 대목을 적었으나, **사용자 확정으로 전부 걷어냈다.** 근거는 **작업자가 고르는 것은
처리 종류이지 그것이 어디서 수행되는지가 아니기 때문**이다 — 수행 주체는 요청 결과를 달라지게 하지
않으므로 선택을 돕지 못하고, 카드 한 장에 판단에 쓰이지 않는 줄을 하나 더 얹을 뿐이다. 화면 문구·칩·
전용 CSS 를 모두 제거했고 죽은 규칙을 남기지 않았다.

⚠ **개인정보 안내의 "그대로 외부 생성 시스템으로 전달되고 요청 기록에 남습니다" 는 남긴다.** 이건
수행 주체 표기가 아니라 **입력값이 어디로 나가는지 알리는 경고**이고, 골격이 그 컴포넌트 note 에서
"입력값은 정규화 후 그대로 외부 생성형 AI 서비스로 전송된다는 사실을 함께 알린다" 고 명시적으로
요구한 문구다. 성격이 달라 함께 지우지 않는다.

카드를 2×2 로 놓는 배치는 그대로 둔다 — 칩이 빠져도 한 줄 4칸(1440 기준 254px)에서는 설명 문장이
3줄로 감겨 읽기 어렵다. 칩이 사라지면서 생긴 아래쪽 빈 띠는 카드 하한 높이를 92px → 84px 로 낮춰
없앴고, 480px 미만에서는 체크 표시를 아랫줄로 내리던 규칙을 걷고 아이콘·체크 칸만 줄여 선택되지 않은
카드에 빈 줄이 남지 않게 했다.

### 2. 단계 번호를 시각화했다

골격 섹션 이름이 `Step 1` · `Step 2` 로 순서를 규정한다. 두 카드가 크기만 다르게 놓이면 순서가 읽히지
않으므로 원형 번호(`.step-no`)를 붙였다. 번호는 primary 면 위 흰 글자(4.55:1)로, 화면에서 유일하게
채워진 primary 면 두 곳(번호·주버튼) 중 하나다.

### 3. 생성 조건은 **셀렉트로 좁히지 않았다** — 자유 입력 그대로

골격이 "선택지가 아니다 — 셀렉트로 좁히지 않는다" 고 명시한다. 5필드 모두 `input[type=text]` 이고
placeholder 는 값을 강제하지 않는 **예시**(`예: 해 질 무렵`)로만 뒀다. 허용값 목록은 골격에도 API 명세에도
없으므로 만들지 않았다(§ 미해결 참조).

### 4. 검사 결과를 필드마다 따로 붙이고, 글자 수는 상시로 보인다

골격 검증 규칙 3종 중 화면에 드러나는 것은 ①공백만 입력 거부 ②50자 이내 두 가지다. 오류 문구는
골격이 준 그대로(`필수 입력입니다.` / `50자 이내로 입력하세요.`) 쓰고, 필드마다 개별로 붙였다.
글자 수 카운터(`0/50`)를 상시 노출한 것은 50자 한도를 **넘긴 뒤에 알리는 것보다 넘기기 전에 보이는 편이**
고쳐 쓰는 비용이 작기 때문이다. 오류가 뜬 필드는 색만이 아니라 아이콘 + 문장을 함께 준다(do_rule).

### 5. 개인정보 안내를 **입력 지점 안**에 상시로 뒀다

골격이 "생성 조건 5필드 입력 블록 내에 상시 노출" 을 요구한다. 페이지 상단이 아니라 입력 바로 위에
둔 것은, 이 문구가 지켜져야 하는 순간이 **타이핑하는 순간**이기 때문이다. 문구에는 "입력값이 정규화 후
그대로 외부 생성 시스템으로 전달되고 요청 기록에 남는다" 는 사실을 함께 적었다 — 왜 적으면 안 되는지를
알아야 지켜진다. variant 는 골격대로 `outline` 이되 경계와 아이콘만 warn 톤으로 올려 같은 outline 인
"처리 종류를 하나 선택하세요"(중립)와 무게를 갈랐다.

### 6. 처리 종류를 네이티브 radio 로 구현했다 (로빙 tabindex 를 흉내 내지 않음)

골격 note 는 `role=radiogroup` + 로빙 tabindex + 화살표 탐색을 요구한다. 시안에서는 `fieldset[role=radiogroup]`
안에 **네이티브 `input[type=radio]`** 를 넣었다 — 네이티브 라디오는 그 자체로 `role=radio`, 그룹 내 Tab
1스톱, 화살표 키 이동을 브라우저가 제공하므로 요구가 그대로 충족된다. **게시 렌더가 `tabindex` 를 지우는
축을 아예 밟지 않는다**는 이점도 있다(§ 게시 렌더 참조). 구현 라이브러리가 커스텀 위젯을 쓸 경우에만
로빙 tabindex 가 필요해진다.

### 7. 하단 바를 **요청 동선 안에서만** 붙게 했다

`.action-bar` 는 `.request-flow` 안에 두어 그 묶음 안에서만 `position: sticky` 로 붙는다. 화면 최하단까지
붙게 두면 아래 참고 패널 내용을 계속 가린다. 실제 구현에서도 이 바가 덮는 대상은 "지금 요청 중인 폼"
까지여야 한다.

### 8. 선택된 표 행은 배경 + 좌측 강조선 두 축으로 알린다

행 hover 는 `#FFFBEB`(do_rule 지정값)이고 선택 행은 `--p-0` 이라 색이 비슷한 계열이 아니어서 섞이지
않는다. 여기에 좌측 3px primary 선을 더해 색만으로 구분하지 않게 했다(do_rule). 라디오 자체(20px)는
44px 클릭 영역(`.radio-hit`)으로 감쌌고, 영상명 칸 전체를 `label[for]` 로 만들어 이름을 눌러도 선택된다.

### 9. 이력 카드는 증강 배지와 해상도 파생 배지를 **모양으로** 갈랐다

골격이 "해상도 파생은 별도 톤으로 구분, 증강 없이 해상도 파생만 있으면 '파생' 배지 병기" 를 요구한다.
증강 3종은 채워진 pill(`.badge-info`), 해상도는 **점선 경계의 빈 pill**(`.derivative-badge`)로 두어 톤뿐
아니라 형태가 다르다 — 색만으로 구분하지 않기 위해서다. 상태 `COMPLETED` 는 성공을 단정하지 않는
중립 문구 `처리 종료`로 적었다(UI-072 계약).

### 10. 화면 글자에서 구현 식별자를 걷어냈다

`WINTER/NIGHT/RAIN` → 겨울/야간/우천, `RESL_1080P` → 1080p, `PENDING/ACCEPTED` → 생성 중/생성 완료,
`REQUESTED/IN_PROGRESS/COMPLETED/FAILED` → 요청됨/처리 중/처리 종료/실패. 데이터 값인 영상번호(`#3187`)와
해상도 표기(`1920 × 1080`)만 원문 그대로 둔다.

## § 접근성 검증 (WCAG)

- **렌더 트리의 모든 텍스트 노드를 기계로 전수 측정 — 224건 전건 통과, 미달 0건**(1440 · 360 동일).
  사람이 고른 조합만 잰 것이 아니라 computed color × 유효 배경으로 전부 쟀다.
- 회색 표면(`--n-0`) 위 보조 텍스트는 전부 neutral 60단 이상(do_rule 준수).
- **비활성 주버튼을 흐림(opacity)이 아니라 채도를 뺀 면으로 처리**했다 — `--n-2` 면 위 `--n-7` 글자 = 5.98:1.
- **경계가 유일한 식별 수단인 컨트롤**(입력·셀렉트·보조버튼·해상도 행·종류 카드)은 `--n-5`(4.51:1)로
  올렸다. `--n-4` 는 흰 면 위 2.82:1 로 WCAG 1.4.11(3:1) 미달이다.
- **빵부스러기 링크 hit area 44×44 확보**(시각 크기 불변 · `min-*` + 음수 margin), 표 라디오도 `.radio-hit`
  44×44 로 감쌌다.
- 색만으로 상태를 전달하는 자리가 없다 — 선택 카드는 체크 아이콘, 오류는 아이콘+문장, 파생 배지는
  점선 형태, 상태 배지는 점+한글 라벨을 함께 쓴다.
- 폼은 `label[for]` 연결 + 오류에 `aria-describedby`/`aria-invalid`/`role=alert`, 표에 `caption`(sr-only),
  라디오그룹에 `fieldset[role=radiogroup]` + `legend`.

### 768px 이하에 남는 "입력칸 캐럿 스크롤" 1건 — 성격과 판단

- 대상은 참고 패널 ②-① 의 **"50자를 넘겼을 때"** 시연 입력(`p-terrain-long`) 하나다. 값이 51자(644px)라
  좁은 폭의 입력 상자를 넘는다.
- **한도 초과를 보여 주려면 값이 한도를 넘어야 하므로 구조적으로 피할 수 없다.** 이 패널을 1열 전폭으로
  두어 1440·1280 에서는 0건이고, 그 아래 폭에서만 남는다.
- 텍스트 입력은 값이 상자를 넘으면 내부에서 가로로 스크롤되므로 **내용이 사라지지 않는다** — `clip4` 는
  이것을 '진짜 잘림' 과 분리해 따로 세며, 진짜 잘림은 6개 폭 전부 0건이다.

### `overflow.mjs` 의 "밖으로나간요소" 에 대하여

768px 이하에서 28~60건이 잡히지만 **전부 `.table-scroll`(가로 스크롤 컨테이너) 안의 표 요소**이고
문서 폭 넘침은 6개 폭 모두 0건이다. 기준본 SCREEN-032 도 360px 에서 같은 형태로 56건이 잡힌다 —
표를 좁은 화면에서 스크롤시키는 관례의 정상 결과다.

## § 미해결 · 정보 부족

- **생성 조건 5필드의 기본값 문자열이 골격에 없다.** 골격은 "겨울은 계절과 날씨, 야간은 시간대, 우천은
  날씨" 에 기본값이 채워진다고만 정하고 **어떤 문자열인지는 규정하지 않는다.** 시안은 겨울 선택 상태를
  `계절=겨울` · `날씨=눈 내림` 으로 그렸고 그 두 칸에 "고른 종류에 맞춰 채워 뒀습니다" 도움말을 달았다.
  **이 문자열 두 개는 시안의 임시값이며 확정값이 아니다** — 구현 전에 정해야 한다.
- **허용값 목록은 만들지 않았다.** 골격이 "선택지가 아니다" 라고 명시하므로 placeholder 는 예시로만 뒀고,
  그 예시 문구(`예: 해 질 무렵` 등)도 규정된 값이 아니라 시안이 고른 표현이다.
- **이벤트 select 의 실제 항목이 골격에 없다.** 골격 옵션은 `전체` + `고정 이벤트 유형들` 이다. 시안은 이
  저장소의 다른 시안이 쓰는 표기(화재·침수(범람)·교통사고·쓰러짐·폭력·이상행동(유괴))를 빌려 채웠고,
  실제 목록은 서버가 내려주는 이벤트 유형에 달렸다.
- **파생 생성 결과의 실패 건을 어떻게 보일지 미정.** API-092 응답의 `derivatives` 에는 **성공한 것만** 담기고
  실패 목록이 없다. 시안은 요약 문구에 `(1건 실패)` 로만 적었고 어느 프리셋이 실패했는지는 표시하지
  못한다 — 실패 프리셋을 알리려면 응답 확장이 필요하다.
- **API-179**(해상도 파생 확정 상태 조회)를 화면에서 쓰는 자리가 골격 섹션에 없다. 결과 표의 상태 갱신에
  쓰일 것으로 보이나 골격이 어느 컴포넌트에 물리는지 규정하지 않아 시안에서 별도 자리를 만들지 않았다.
- **웹폰트 소스 미정** — `@font-face` 없이 family 선언 + 시스템 한글 산세리프 폴백만 뒀다.
- 스크린리더 읽기 순서·탭 순서 미측정.
