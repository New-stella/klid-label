## § 골격 대조 — 섹션·컴포넌트 전수

| 골격 | 컴포넌트 | 시안에서 그린 자리 |
|---|---|---|
| ① 안내 헤더 · role=header · layout=stack | `Heading`(관리자 등록) | 카드 상단 `h2.auth-title`(title-lg) |
| | `SubText`(Custom, 이 시스템에는 아직 관리자가 없습니다. 배포 시 설정한 공유 패스워드로 본인을 최초 관리자로 등록하세요.) | 그 아래 `.auth-sub`(body-md, neutral 60단) |
| ② 역할 선택 · role=main · layout=form | `Alert`(variant=info, 관리자 권한이 부여됩니다) | 구분선 아래 `.alert.alert-info[role=status]` — 아이콘 + `.alert-title` + `.alert-text` |
| ③ 권한 부여 폼 · role=main · layout=form | `Input`(관리자 패스워드, type=password, autoComplete=new-password, binds_to=adminPassword) | `.field` + `label[for]` + `input[type=password][autocomplete=new-password]` |
| | `Alert`(state=hidden, variant=destructive, 실패 시에만 role=alert) | 기본 상태에서는 **없음**. 참고 영역 ③ 에 노출 상태를 그렸다 |
| | `Button`(관리자로 등록, variant=primary, triggers_api=API-007) | 카드 하단 `button.btn-primary.btn-block` |

- 골격의 `state: hidden` 을 그대로 지켜 **기본 화면에는 실패 Alert 를 그리지 않았다.** 숨김 컴포넌트를
  대표 상태에 그려 넣으면 "항상 보이는 영역"으로 오해된다.
- `triggers_api: API-007` 은 제출 버튼에만 걸려 있고, 시안의 다른 요소는 어떤 호출도 암시하지 않는다.
- ② 의 **섹션 이름은 `역할 선택` 그대로이나 그 안에 선택지는 없다.** 이름은 골격이 소유하므로 시안이
  임의로 바꾸지 않았다 — 바꾸려면 SCREEN-002 ITEM 을 먼저 고쳐야 한다.

⚠ **구 대조 폐기 — 되살리지 말 것.** 이 표는 *"② 역할 선택 · `RadioGroup`(binds_to=role, options 2종)
→ 카드형 라디오 2개"* 와 *"① `Heading`(권한 부여 필요) / `SubText`(관리자에게 받은 패스워드로 역할을
부여받으세요.)"* 를 들고 있었다. **부여 역할은 관리자 고정이라 고를 것이 없고**, 이 창구가 열려 있는
시점에는 안내해 줄 관리자도 아직 없다. 라디오 자리는 안내 배너로 바뀌었고 화면 이름은 「관리자 등록」이다.

⚠ **로컬 골격 파일이 시안보다 낡았다** — 같은 폴더의 `SCREEN-002.md` 는 아직 라디오 2택 ·
`권한 부여 필요` · *"검수자에게 받은 패스워드"* 를 규정한다. 이 표는 **현재 시안(`design/design.html`)과
같은 세대인 `wireframe.html`** 을 기준으로 적었다. 화면 키트를 SYNC 하면 골격 파일이 따라온다.

### 골격에 없어 그리지 않은 것

- **역할 설명 링크·도움말 페이지** — 골격에 없다.
- **패스워드 표시 토글(eye 아이콘)** — 골격에 없고, 관리자 공유 패스워드라 화면에 평문 노출 경로를
  임의로 만들지 않았다.
- **취소·뒤로가기** — 골격에 없다. 이 화면은 역할이 없으면 다른 곳으로 갈 수 없는 게이트다.

## § 디자인 결정 (골격이 규정하지 않은 부분)

### 1. 셸 밖 화면이라 기준본의 `page-head + breadcrumb` 관례를 쓰지 않았다

기준본 SD-004 는 셸 안 페이지라 breadcrumb 이 화면 콘텐츠지만, 이 화면은 상단·좌측 메뉴가 없고
가리킬 상위도 없다. 화면명·경로는 **시안 표지(`.sheet-head`)** 로 분리해 문서 메타임을 드러냈다.

★ 구현 시 **`.sheet-head` 와 `.state-frame`·`.state-caption` 은 화면에 그리지 않는다.**

### 2. 세 섹션을 카드 3장이 아니라 카드 1장 안의 3블록으로 묶었다

골격은 섹션 3개지만 사용자에게는 **한 번에 끝내는 하나의 폼**이다. 카드를 셋으로 쪼개면 단계가
셋인 것처럼 읽혀 실제보다 무겁게 느껴진다. 대신 안내 헤더와 폼 사이에 구분선(`.auth-divider`)을
넣어 섹션 경계는 남겼다.

### 3. 선택지가 사라진 자리를 비우지 않고 「무엇이 부여되는가」를 알리는 배너로 채웠다

부여 역할은 **관리자 고정**이라 고를 것이 없다. 그렇다고 그 자리를 빈칸으로 두면 사용자는 자신이
무엇을 얻는지 모른 채 제출하게 된다 — 되돌릴 수 없는 등록인데 결과가 화면에 없는 셈이다. 그래서
같은 자리에 `Alert`(info)를 두고 **부여 역할 + 등록 뒤에 일어나는 일**(창구가 닫히고 이후 역할 부여는
관리자가 사용자 관리 화면에서 한다)을 적었다.

- 강조 수준은 **경고가 아니라 정보**다. 막는 자리가 아니라 알리는 자리이므로 `role="status"` 를 쓰고
  `role="alert"` 는 실패 안내(참고 영역 ③)에만 남겼다.
- 색만으로 구분하지 않는다 — 아이콘 + 제목 + 본문 3요소라 색각 이상에서도 성격이 읽힌다
  (DS dont_rule: 색만으로 상태 구분 금지).

⚠ **구 결정 폐기 — 되살리지 말 것.** 이 자리는 *"라디오를 카드형으로 만들고 역할 설명을 덧붙였다
(작업자=라벨 제작·검수 요청 / 검수자=배정·검수 승인·관리, 선택 카드 292×105, 선택 상태를 테두리 색 +
안쪽 1px 링 + 배경 tint 3중으로 표시)"* 였다. 선택지를 되살리면 **사용자가 고른 값과 실제 부여 역할이
갈린다** — 서버는 요청의 역할 값을 읽지 않고 관리자를 부여한다.

### 4. 대표 상태를 "입력한 뒤"로 잡았다

초기 진입은 패스워드 공백 + 제출 비활성이지만, 그 상태를 대표로 그리면 화면의 주행동이 무엇인지
보이지 않는다. 대표 프레임은 정보량이 가장 많은 **입력 완료 상태**로 두고, 비활성 초기 상태는 참고
영역 ① 로 뺐다. 기준본이 확립한 "대표 1종 + 변형은 참고 영역" 관례를 그대로 따른 것이다.

### 5. 실패 문구를 표로 정리했다

골격은 응답별 문구 5종을 산문으로 규정한다. 산문으로 두면 구현자가 어느 문구가 어느 응답인지
매번 되짚어야 하므로 **응답 × 문구** 2열 표로 옮겼다. 403 은 정상 동선에서 도달하지 않는다는 골격의
단서도 표 아래 각주로 남겼다 — 지우면 다음 사람이 "쓰이지 않는 문구"로 보고 없앨 수 있다.

### 6. 제출 진행 중에는 문구를 바꾸지 않고 스피너만 넣었다

골격은 "진행 중이면 제출 비활성"만 규정하고 문구 변경은 규정하지 않는다. 그래서 라벨은
`권한 부여 확인` 그대로 두고 앞에 18px 스피너만 붙였다. (문구를 바꾸는 SCREEN-004 와 다른 것은
그쪽 골격이 `'발급 중…'` 을 **명시**하기 때문이다 — 두 화면의 차이는 의도된 것이다.)

### 검증 중 고친 것 1건

`.input:disabled` 의 글자색이 `neutral[5]` × `neutral[0]` = **4.13:1** 로 AA 미달이었다. DS `do_rules` 가
바로 이 수치를 지목해 금지한 조합("50단은 흰 배경에서만 통과하고 회색 표면 위에선 미달이다 —
neutral 0 위 4.13")이라 `neutral[6]`(5.77:1)로 올렸다. 비활성 컨트롤은 WCAG 대비 요구 대상이 아니지만
DS 가 명시적으로 금지한 조합이므로 예외를 두지 않았다.

### 그 밖의 접근성 처리

- `label[for]` 로 입력과 명시 연결, 도움말은 `aria-describedby` 로 연결(DS do_rule).
- 부여 역할 안내는 `role="status"` — 진행을 막지 않는 알림이라 보조기술이 현재 작업을 끊지 않고 읽는다.
- 실패 안내는 `role="alert"`, 성공 안내는 `role="status"`.
- 주요 버튼 글자 대비가 4.55:1 로 AA 하한에 가깝다 — DS `known_gaps` 가 기록한 정본 주조색의 성질이며
  DS 가 정한 값이므로 수용한다(임의로 더 진한 색을 만들지 않는다).

`iteration_guide`: "좁으면 크기를 낮추지 말고 열 수를 줄인다").

## § 관례 이탈 · 미해결

- ✅ **해소됨 — 화면 노출 텍스트의 영문 역할 코드.** 구 시안은 라디오 라벨이 골격 `options` 값
  그대로라 `작업자 (WORKER)` / `검수자 (REVIEWER)` 를 노출했고, 확정 관례(화면 노출 텍스트에 영문
  구현 식별자 금지)와 어긋나 있었다. 선택지 자체가 사라지면서 함께 없어졌다 — 현재 시안의 노출
  텍스트에 영문 역할 코드는 없다.
- ⚠️ **② 섹션 이름 `역할 선택` 은 그대로다** — 그 안에 선택지가 없으므로 이름과 내용이 어긋난다.
  섹션 이름은 골격 소유라 시안이 바꿀 수 없다. 정리하려면 SCREEN-002 ITEM 을 먼저 고쳐야 한다
  (LogiCraft 먼저 → 코드 순서).
- ⚠️ **320px 이하는 미검증 폭이다** — 플레이스홀더가 320px 에서 넘친다(263px vs 218px). 같은 안내가
  입력 아래 도움말로 반복되므로 정보 손실은 없다. DS `responsive_breakpoints` 가 하한을 규정하지
  않아 지원 폭 자체가 미확정이다.
