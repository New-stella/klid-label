# 비식별 처리 상태·이력 확인

## goal

영상 단위로 비식별 처리 상태(DE_IDNTF_YN)와 배치 비식별 단계(DEIDENTIFY) 진행을 화면에서 확인하고, 비식별 누락을 신고·해소한다. 처리 이력(LS_DEIDENT_PROC_LOG)은 폴링 완료 시점에 기록된다.

## main_flow

### [1]

- **step**: 1
- **actor**: 검수자(REVIEWER)
- **action**: 영상 상세 화면 또는 처리 현황 화면에서 비식별 상태(DE_IDNTF_YN)와 배치 단계(DEIDENTIFY)를 확인한다 — 개인정보 유무는 목록·상세 어느 곳에도 표시하지 않는다

### [2]

- **step**: 2
- **actor**: 라벨링 작업자(WORKER)
- **action**: 비식별 누락(얼굴/번호판 미블러 등)을 발견하면 마킹 단계(POST /v1/videos/{rawSn}/deident-report — 배치 단계가 MARKING_READY 일 때만) 또는 라벨링 단계(POST /v1/labels/{srcSn}/deident-report — 배치 단계 무관)에서 신고한다 (LS_DEIDENT_REPORT OPEN + DCLR_STP_CD 단계 기록, WORKER 는 본인 배정 영상만)

### [3]

- **step**: 3
- **actor**: 시스템
- **action**: 작업락 선점 + DE_IDNTF_YN='F' 마킹만 수행하고 라벨과 개인정보 3필드(익명·가명·PII 포함여부)는 삭제·리셋하지 않고 보존한다

### [4]

- **step**: 4
- **actor**: 시스템
- **action**: 신고 구간 동안 라벨 조회·저장, 라벨 객체 속성값 조회·저장, 버전 diff·롤백, 프레임 이미지, 포털 라벨 조회·저장·포털 프레임 이미지, 개인정보 메타 PUT(영상축·프레임축), 이벤트 어노테이션 저장·승인·반려, 검수 승인, 관제 조회 API 라벨 본문을 412 로 차단하고 영상 스트리밍을 404 로 차단한다(인가 검사 이후 평가하는 프리컨디션·역할 무관). 게이트가 걸린 미디어 응답은 Cache-Control: no-store 이다

### [5]

- **step**: 5
- **actor**: 작업자/검수자
- **action**: 외부 솔루션으로 수동 비식별화를 수행한다 (자동 재비식별 큐 폐기)

### [6]

- **step**: 6
- **action**: POST /v1/deident-reports/{rprtSn}/resolve 로 신고를 해소한다(WORKER 본인 배정/REVIEWER 전체) — OPEN→RESOLVED 조건부 UPDATE 로 원자 클레임하고 영향행수 1 을 받은 성공자만 작업락 해제·'F'→'Y' 복원·재개 이벤트를 수행한다(2노드 Active-Active 중복 방지). OPEN 이 아니면 409

### [7]

- **step**: 7
- **actor**: 시스템
- **action**: 신고 단계(DCLR_STP_CD)에 따라 재개 지점을 정한다 — MARKING 은 배치 단계를 MARKING_READY 로 되감고 활성 마킹을 SKIPPED 로 종결해 마킹부터 다시, LABELING 은 기존 LS_DATA_SRC 행을 dirty-update 해 프레임 이미지만 재추출하고(SRC_SN 보존 → 라벨 FK 유지) 보존된 라벨로 라벨링을 이어간다. 단계 미상(NULL)은 백필하지 않고 재개 이벤트도 발행하지 않는다

### [8]

- **step**: 8
- **actor**: 외부 비식별 SW
- **action**: 배치 비식별(KPST 폴링)이 완료/실패하면 DE_IDNTF_YN 을 Y/F 로 갱신하고 LS_DEIDENT_PROC_LOG 에 이력을 기록한다

## description

저작도구가 보유한 비식별 가시성 + 수동 비식별 신고·해소 UC. 검수자가 영상 상세(SCREEN-009)·처리 현황(SCREEN-008) 화면에서 비식별 상태를 확인한다.

[★개인정보 유무는 표시하지 않는다 (2026-08-05 확정)] 관제가 개인정보 유무를 실제로 송신하지 않아 인입 원장의 3컬럼이 전 행 NULL 이며, 화면이 보던 값은 관제값이 아니라 적재 시 고정되는 레거시 컬럼이었다. 구 서술 '개인정보 분류(PrivacyBadge) 표시'는 폐기되고 FE 컴포넌트도 삭제됐다. ⚠ 라벨링 화면의 개인정보 메타 패널은 사람이 직접 입력하는 별개 축이라 그대로다.

[신고 접수] 마킹 단계(rawSn 기준, POST /v1/videos/{rawSn}/deident-report) 또는 라벨링 단계(srcSn 기준, POST /v1/labels/{srcSn}/deident-report)에서 접수하고 신고 단계를 DCLR_STP_CD(V171)에 기록한다. 접수 시 작업락을 선점하고 DE_IDNTF_YN='F' 로 마킹한다.

[★라벨도 개인정보 판정도 지우지 않는다 — 구 정책 2건 폐기] ①'영상 전체 라벨을 LS_LABEL_VERSION(SAVE_REASON_CD=DEIDENT_REPORT, 비활성) 스냅샷 후 일괄 삭제' → 2026-07-27 폐기. 신고는 '비식별이 잘못됐다'는 신호일 뿐 라벨 작업 결과를 폐기할 근거가 아니며, 그 스냅샷은 DATA_SRC_SN=NULL(영상 스코프)이라 srcSn 스코프 조회·롤백 진입점이 없는 write-only 이력이었다. 스냅샷도 남기지 않는다. ②'개인정보 3필드를 프레임 축(LS_DATA_SRC, V130)·영상 축(LS_DATA_RAW, V163) 둘 다 null 로 리셋' → 2026-08-04 폐기. 같은 취지로 사람이 입력한 판정도 라벨과 같은 작업 결과이므로 보존하고 resolve 후 기존 판정을 그대로 이어서 진행한다(stale 우려는 신고 구간 export 보류 + 해소 후 재승인 시점의 재산출·재통지가 막는다). 리셋 감사 이벤트 타입(PRIVACY_META_RESET)은 신규 발생 0 이지만 과거 행 판독을 위해 존치한다.

[차단] 신고 구간에는 라벨 조회·저장, 라벨 객체 속성값 조회·저장, 버전 diff·롤백, 프레임 이미지, 포털 라벨 조회·저장·포털 프레임 이미지, 개인정보 메타 PUT(영상축·프레임축), 이벤트 어노테이션 저장·승인·반려, 검수 승인, 관제 조회 API 라벨 본문이 412 로 차단되고 영상 스트리밍은 404 로 차단된다(스트리밍만 404 인 것은 '비식별 유효하지 않으면 원본 노출 금지 → 404' 라는 그 엔드포인트의 기존 규약에 맞춘 것이며, 신고 여부에 따라 404/412 로 갈리면 응답 코드가 영상 상태 오라클이 된다 — CWE-209). ⚠ 구 서술 '저장·수정은 작업락으로 409 차단' 은 2026-08-04 폐기 — 작업락은 6h 만료 후 회수되는데 'F' 는 resolve 까지 남아 조회 412 ↔ 저장 200 비대칭이 열렸고, full-replace 계약상 items:[] 저장이 기존 라벨을 전량 삭제했다. 게이트는 락 검사보다 먼저 평가해 412 로 통일한다. 게이트가 걸린 미디어 응답은 Cache-Control: no-store 이며, FE 는 게이트가 닫히는 변화에 removeQueries 로 캐시를 제거한다(invalidateQueries 로는 staleTime 내 재진입에서 캐시된 라벨 좌표가 그려진다).

[통지] 승인 이력이 있는 영상은 접수 자체가 412 로 막히므로, 신고 시점에 수정 통지를 발행하던 분기는 도달 불가가 되어 제거됐다. 검수 완료·통지 건에 대한 관제 접근은 신고 구간에도 차단하지 않는다.

[해소·단계별 재개] 외부 솔루션으로 수동 비식별화를 마친 뒤 POST /v1/deident-reports/{rprtSn}/resolve(WORKER 본인 배정/REVIEWER 전체)를 호출한다. resolve 는 OPEN→RESOLVED 조건부 UPDATE 로 원자 클레임하고(구 findById→상태비교는 read-then-write 라 두 노드가 동시 통과해 무거운 프레임 재추출이 2회 기동했다) 영향행수 1 을 받은 성공자만 후속 작업을 수행한다. 산출물 실재 검증을 통과해야 성립하는 fail-closed 게이트다. 'F'→'Y' 복원으로 게이트가 자동 해제되어 보존된 기존 라벨을 그대로 재사용한다(별도 복원 API 없음). 자동 재비식별 큐는 폐기됐다.
★재개 지점은 신고 단계로 갈린다(V171) — MARKING 은 배치 단계를 MARKING_READY 로 되감고 활성 마킹(PENDING/VLM_REQUESTED)을 SKIPPED 로 종결해 재마킹 409 를 푼다. LABELING 은 기존 LS_DATA_SRC 행을 갱신(dirty-update)해 SRC_SN 을 보존하므로 라벨 FK 가 끊기지 않는다 — 새 행을 INSERT 하는 최초 추출 경로를 재사용하면 기존 라벨이 고아가 되므로 쓰지 않는다. 비식별 영상 경로는 LS_DEIDENT_PROC_LOG.DE_IDNTF_FILE_PATH_NM 적재값을 읽고(조합·추측 금지) 프레임 위치는 VDO_FRM_NO(영상 내 실제 위치)로 추출한다 — FRM_NO(추출 순번)로 추출하면 비식별 영상 맨 앞을 뽑아 붙인다. 단계 미상(NULL, 컬럼 신설 이전 신고)은 백필하지 않고 재개 이벤트도 발행하지 않는다. 이벤트 3종: DeidentGateReopenedEvent(항상, VLM 위탁 재개) · 수정 통지 이벤트(APPROVED 한정 — 해소 시점엔 재검토 표시만 세우고 산출물 재생성과 재통지는 재승인 시점. 같은 자리를 가리키던 EVT-008 은 발행처가 없는 휴면 확장점이다) · DeidentStageResumeEvent(단계별 재개, AFTER_COMMIT — 복원 커밋 전에 도는 재개 작업이 자기 게이트에 스스로 막힌다).

[마킹 단계 신고의 접수 조건] 마킹 단계 신고는 배치 단계가 MARKING_READY 일 때만 접수한다(그 외 412). 그 상태는 선두 비식별 성공 직후·마킹 이전이라 프레임 행도 라벨도 아직 없어 재마킹이 파괴할 작업 결과가 없고, 검수 완료 영상의 강등 충돌도 없다. 거부는 412 한 종류·문구 한 종류이며 PROCESSING/COMPLETED/FAILED/PENDING 을 구분해 알리지 않는다(응답이 처리 단계 오라클이 되지 않게 — CWE-209). 화면은 MARKING_READY 가 아니면 마킹 화면 진입 자체를 막아 편집기도 신고 버튼도 열지 않는다 — 사유를 다 적고 제출한 뒤에야 거부되는 동선이 없고, 그 상태의 신고는 라벨링 화면이 담당한다. 라벨링 단계 신고는 배치 단계와 무관하다. 단 검수가 승인된 이력이 있는 영상은 접수하지 않는다(412) — 판정 축은 지금 상태가 아니라 승인 이력이다.

[파생영상 제외] 파생본(ORGNL_RAW_SN non-null)은 신고를 접수하지 않고(412) 원본의 신고도 파생에 전파되지 않는다 — 파생본을 다시 비식별할 수단이 없기 때문이며 원본으로 유도하지도 않는다(파생 배정 WORKER 는 원본 접근 권한이 없다).

## alternate_flows

### 이미 잠금·중복 신고

**steps**:

- 작업락 UNIQUE 제약 최후 방어, 409 CONFLICT 반환

- **trigger**: 이미 재비식별 진행 중(LOCKED_FOR_REDEIDENT) 인 영상에 재신고

### 이미 처리된 신고 resolve

**steps**:

- 409 CONFLICT 반환 (재-resolve 차단) — OPEN→RESOLVED 조건부 UPDATE 의 영향행수 0 으로 판정한다

- **trigger**: OPEN 이 아닌(RESOLVED/DISMISSED) 신고 resolve 재호출

### 마킹 단계 신고의 접수 조건 불충족

**steps**:

- 412 PRECONDITION_FAILED — 상태를 구분해 알리지 않는 단일 문구로 안내한다(응답이 처리 단계 오라클이 되지 않게 — CWE-209)
- 화면은 마킹 대기가 아니면 마킹 화면 진입 자체를 막아 편집기도 신고 버튼도 열지 않는다 — 그 상태의 비식별 누락 신고는 라벨링 화면이 담당한다

- **trigger**: 배치 단계가 MARKING_READY 가 아닌 상태에서 마킹 단계 신고

### 파생영상 신고

**steps**:

- 412 로 거부하고 사유만 안내한다 — 원본으로 유도하지 않고 부모 rawSn 도 내려주지 않는다
- 신고 행을 만들지 않으므로 REVIEWER 알림도 보내지 않고, 발견 사실은 로그 인젝션 방지를 위해 정제한 뒤 WARN 감사 로그로 남긴다

- **trigger**: 증강·해상도 파생본(ORGNL_RAW_SN non-null) 신고

### 타인 배정 영상 신고·해소

**steps**:
