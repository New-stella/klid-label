# 비식별 처리 요청·결과 저장

## priority

critical

## scenario

### then

- KpstDeidentifyClient(Resilience4j)가 영상 업로드 후 비식별 프로젝트를 생성해 위탁한다 — 제출은 논블로킹이며 WAITING 원장 행을 선커밋한 뒤 비동기 디스패치한다(파이프라인 스레드를 붙잡지 않는다)
- 주기 폴링(KpstDeidentPollJob)이 진행을 조회해 완료를 감지하고 결과를 회수한다(별도 결과 콜백 없음)
- 비식별본이 STORAGE_DEIDENTIFIED_PATH 에 저장되고 원본은 그대로 유지된다. 결과 파일 경로는 솔루션이 통보한 값을 LS_DEIDENT_PROC_LOG.DE_IDNTF_FILE_PATH_NM 에 그대로 기록한다(파일명 조합·추측 금지 — mock=deidentified.mp4 / KPST={원본stem}-mask{ext})
- 처리 이력(DE_IDNTF_YN 등)이 영상 단위로 기록되고 성공 시 LS_DATA_RAW.DATA_STTS_CD 가 MARKING_READY 로 전이해 비식별 영상 대상 마킹이 허용된다

### when

- 적재 완료(VideoIngestedEvent → IngestDeidentifyBridge, AFTER_COMMIT)를 신호로 선두 비식별이 자동 시작하거나, REVIEWER 가 비식별 재처리를 요청한다(202 Accepted)

### given

- 대상 영상이 적재되어 있다 — PRVC_TYPE_CD 게이팅 없이 전체 영상(PRVC/PSDO/ANONY)이 비식별 대상이다
- 재처리를 수동 요청하는 경우 REVIEWER 로 인증되어 있다
- 외부 KPST 비식별 솔루션이 가용하다

### and_examples

#### [1]

- **case**: 비식별 API 실패
- **result**: DE_IDNTF_YN='F' 마킹 + 원본 절대 삭제 금지. 자동 재비식별 큐는 폐기됐고 외부 솔루션 수동 재비식별 후 resolve 로 해소한다(AC-016)

#### [2]

- **case**: 수락 응답도 결과 회신도 관측되지 않음
- **result**: 미결 스위퍼가 유일한 회수 경로로 동작한다 — ACK 창(기본 30분)과 콜백 창(기본 360분)을 구분해 정상 위탁을 빼앗지 않고, 2노드 중복 재위탁은 조건부 UPDATE 원자 클레임으로 막는다

#### [3]

- **case**: 비식별 누락 신고 구간(DE_IDNTF_YN='F')
- **result**: 외부 위탁을 개시하지 않고 보류한다

## statement

전체 영상(ANONY 포함, 게이팅 없음)을 외부 비식별 솔루션에 위탁해 비식별본을 별도 경로에 저장하고 원본을 보존한다
