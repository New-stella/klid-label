# 이벤트유형 관리 화면 질문 목록 입력 판정 — 비었거나 공백뿐·상한 초과·개행/제어문자는 저장 전에 그 질문 행 옆에서 막히고 안내를 배너 한 줄로 합치지 않는다 (negative)

## notes

길이 상한 값과 허용 문자 집합의 단일 원천은 저장 창구 [[API-220]] 다 — 이 수용기준은 그 값을 숫자나 패턴으로 복제하지 않는다.

서버가 거절했을 때의 표시 규칙과, 서버 검증이 백스톱으로 그대로 남는다는 단언은 짝이 되는 별도 수용기준이 소유한다. 화면이 먼저 판정한다는 이 단언만으로는 서버가 막아 준 경우의 화면이 정해지지 않는다.

## priority

high

## scenario

### then

- 저장 창구를 부르기 전에 화면이 먼저 판정해 그 질문 행 옆에 안내를 보인다
- 안내는 잘못된 질문마다 그 행에 붙고, 배너 한 줄에 전부 이어 붙지 않는다
- 어느 질문을 고쳐야 하는지가 안내가 붙은 자리로 드러난다
- 한 행이라도 판정을 통과하지 못하면 저장 요청을 보내지 않는다
- 잘못된 값을 고치면 그 행의 안내가 사라지고 저장할 수 있다 — 막힌 상태가 영구히 남지 않는다
- 화면의 판정 기준은 저장 창구 [[API-220]] 가 소유한 기준보다 느슨하지 않다 — 창구가 거절할 값을 화면이 통과시키지 않는다

### when

- 어떤 질문 문구를 비우거나 공백만 남긴다
- 어떤 질문 문구를 길이 상한보다 길게 입력한다
- 어떤 질문 문구에 개행이나 제어문자를 넣는다
- 둘 이상의 질문이 동시에 잘못된 상태에서 저장을 시도한다
- 잘못된 질문 문구를 올바른 값으로 고친다

### given

- 검수자가 [[SCREEN-038]] 에서 한 검증 이벤트 유형의 질문 목록을 편집하고 있다
- 질문 목록에는 질문이 여러 개 있을 수 있고 배열의 순서가 곧 정렬순서다
- 질문 문구의 허용 문자와 길이 상한은 저장 창구 [[API-220]] 가 소유한다

## statement

[[SCREEN-038]] 의 검증 이벤트 유형 질문 목록은 잘못된 질문 문구를 저장 창구로 보내기 전에 화면이 먼저 판정해 막는다. 판정 대상은 질문 문구가 비었거나 공백만으로 이루어진 경우, 길이 상한을 넘는 경우, 개행이나 제어문자를 담은 경우다. 상한 값과 허용 문자의 단일 원천은 저장 창구 [[API-220]] 이며 이 수용기준은 그 값을 복제하지 않는다.

안내가 붙는 자리가 이 수용기준의 본체다. 여러 질문이 동시에 잘못됐을 때 안내를 배너 한 줄에 전부 이어 붙이면, 사용자는 어느 질문의 무엇을 고쳐야 하는지 알 수 없다. 그래서 안내는 잘못된 질문마다 그 행 옆에 따로 붙어, 고쳐야 할 자리가 그 자리에서 드러난다.

막힘은 영구 상태로 남지 않는다 — 잘못된 값을 고치면 그 행의 안내가 사라지고 저장할 수 있다. 질문 목록 저장은 그 유형의 목록 전체를 한 번에 교체하는 조작이므로, 한 행이라도 판정을 통과하지 못하면 저장 요청 자체를 보내지 않는다.
