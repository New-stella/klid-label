# 이벤트유형 관리 화면 질문 목록 저장 거부 표시 — 서버 응답 문구·필드 경로·배열 순번을 그대로 내보내지 않고, 서버 검증은 백스톱으로 남아 화면을 거치지 않은 호출도 거절하며 부분 반영을 남기지 않는다 (negative)

## notes

이 수용기준은 「화면이 먼저 판정한다」는 단언과 짝이며 그것으로 대체되지 않는다 — 화면 판정만 결박하면 서버가 막아 준 경우에도 충족되어, 사용자가 내부 구조 표기를 보는 상태가 그대로 남는다.

질문 문구의 허용 문자와 길이 기준 자체는 저장 창구 [[API-220]] 가 소유한다. 거부 응답의 문구를 사람이 읽는 표기로 바꾸는 책임은 화면에 있으며, 그 목적은 사용자가 고쳐야 할 질문을 짚을 수 있게 하는 것이다.

## priority

critical

## scenario

### then

- 저장 창구는 화면을 거치지 않은 호출도 거절한다 — 화면 판정이 생겼다고 서버 검증을 거두지 않는다
- 화면은 거절 응답의 문구와 그 안에 담긴 필드 경로·배열 순번을 사용자에게 그대로 내보내지 않는다
- 사람이 읽는 위치 표기로 바꾸어 보이거나, 그럴 수 없으면 일반 안내와 해당 질문 행 강조로 내려간다
- 거절된 저장은 그 유형의 질문 목록을 부분적으로 바꾸지 않고 교체 전 목록을 그대로 둔다

### when

- 화면의 사전 판정을 거치지 않은 저장 요청이 저장 창구에 직접 닿는다
- 저장 창구가 그 요청을 검증 실패로 거절한다
- 화면이 그 거절 응답을 받아 사용자에게 결과를 알린다

### given

- 검증 이벤트 유형의 질문 목록을 통째로 교체하는 저장이 일어난다
- 저장 창구 [[API-220]] 는 질문 문구의 허용 문자와 길이를 검증한다
- 화면에는 저장 전에 같은 값을 먼저 판정하는 절차가 있다

## statement

[[SCREEN-038]] 의 질문 목록 저장에서 저장 창구 [[API-220]] 가 거절하더라도, 그 응답 문구와 그것이 담은 필드 경로·배열 순번은 사용자 화면에 그대로 나타나지 않는다. 사람이 읽는 위치 표기(몇 번째 질문인지)로 바꾸어 보이거나, 그렇게 바꿀 수 없으면 일반 안내와 해당 질문 행 강조로 내려간다. 사용자가 보아야 하는 것은 어느 질문의 무엇을 고쳐야 하는지이며, 내부 구조 표기는 그 답이 되지 못한다.

★서버 검증은 그대로 남는다 — 화면을 거치지 않고 저장 창구를 직접 부르면 여전히 거절된다. 화면이 먼저 막는 것과 서버가 막는 것은 서로를 대신하지 않는다. 화면 판정이 생겼다고 서버 검증을 거두면 창구를 직접 부르는 경로가 열리고, 반대로 서버 검증만 두면 사용자가 보는 자리와 문구가 정해지지 않는다.

거부된 저장은 부분 반영으로 끝나지 않는다. 질문 목록 저장은 그 유형의 목록 전체를 한 번에 교체하는 조작이므로, 거절된 요청은 일부 질문만 저장된 상태를 남기지 않고 교체 전 목록을 그대로 둔다.
