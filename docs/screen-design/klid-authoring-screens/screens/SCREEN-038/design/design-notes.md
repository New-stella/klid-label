### 골격에 없어 그리지 않은 것

- **추가·삭제 버튼** — 골격이 "생성·삭제 기능을 두지 않는다"고 못박는다. 대신 **왜 없는지**를 마지막 참고
  패널에 남겨, 다음에 이 화면을 보는 사람이 빠뜨린 기능으로 오해하지 않게 했다.
- **검색·필터·페이지네이션** — 골격에 없다. "등록된 이벤트유형 전체를 한 화면에 표로 보여준다"가 규정이라
  나누지 않았다.
- **유형코드·관제 원본·카테고리의 편집 조작** — 읽기 전용이라 조작을 붙이지 않았다.

## § 디자인 결정 (골격이 규정하지 않은 부분)

### 1. 표시명 출처 칩 — 4단 폴백을 표에서 바로 읽게 한다

골격은 표시명이 서버에서 4단(운영자 지정명 → 관제 수신명 → 카테고리명 → 유형코드)으로 해석돼 내려온다고
규정하고, 화면은 그 값을 그대로 표시해야 한다고 못박는다. 그런데 값만 보면 **같은 이름이 여러 행에 보이는
이유**를 알 수 없다 — 이 화면이 만들어진 계기가 바로 그 현상이다.

그래서 표시명 아래에 **출처 칩**(`운영자 지정` / `관제 수신명` / `카테고리명` / `유형코드 그대로`)을 달았다.
칩은 화면이 폴백을 **다시 계산한 결과가 아니라** 서버가 함께 내려준 표기라는 전제로 그렸다 — 화면에서
재계산하면 판정이 갈라진다는 골격 경고를 어기지 않기 위해서다. 구현 시 이 값이 서버 응답에 없으면
칩을 빼거나 응답에 출처 필드를 추가해야 한다(⚠ 계약 확인 필요 — 아래 미해결).

### 2. 표시명 지정이 필터 그룹을 가르는 조작임을 상단에서 먼저 알린다

골격 purpose 의 핵심 부작용인데 표만 봐서는 드러나지 않는다. 운영자가 이름을 바꾼 뒤 다른 화면의
필터가 달라진 것을 나중에 발견하면 원인을 찾기 어렵다. 그래서 **상단 안내 배너**(info)로 먼저 알리고,
참고 패널 ②에서 "지정 전 1건 → 지정 후 2건" 으로 접기가 쪼개지는 모습을 그림으로 보였다.

### 3. 숨김 행은 글자를 흐리게 하지 않는다

비수집 유형도 목록에 남는다(다시 켜려면 보여야 하므로). 흔한 처리인 `opacity` 낮추기는 **읽을 수 없게
만들어** 오히려 다시 켜기 어렵게 한다. 표면만 한 단계 낮추고(`--n-0`) 글자는 대비를 유지했으며, 상태는
토글 배지의 색·아이콘·한글 라벨 셋이 함께 말한다(색만으로 상태를 구분하지 않는다는 do_rule).

### 4. 수집 토글에 확인 단계를 두지 않았다

골격 note 가 "되돌리기가 같은 버튼 한 번이기 때문"이라고 근거를 준다. 그래서 확인 다이얼로그를 만들지
않았고, 대신 현재 값이 무엇인지가 한눈에 보이도록 `aria-pressed` 두 상태를 색·아이콘·라벨로 분명히 갈랐다.

### 5. 유형코드는 고정폭 글꼴로 둔다

`EV01000101` 처럼 자릿수가 같은 코드가 세로로 늘어서므로, 자리가 맞아야 비슷한 코드끼리 묶어 읽힌다
(typography ladder 의 `mono` step).

## § 접근성 검증 (WCAG — 동봉 `scripts/contrast_checker.py`)

- **본문 4.5:1 / 큰글씨·UI 3:1 기준으로 58조합 측정 — 본문·배지·버튼 전건 통과.**
- 회색 표면 위 보조 텍스트는 전부 neutral 60단 이상(do_rule 준수) — `--n-6` on `--n-0` = 5.77:1.
- 토글 knob 흰 아이콘: 노출 `--su-5` 위 4.57:1 / 숨김 `--n-4` 위 3.08:1 — 그래픽 기준 3:1 통과.
- **빵부스러기 링크 hit area 를 44×44 로 확보**했다. 시각 높이·폭은 기준본과 같게 두고 `min-height`·
  `min-width` 를 키운 뒤 음수 margin 으로 되당겨, **클릭 영역만** 주변 여백으로 넓혔다.
- **수집 토글은 실제 44px** 로 뒀다. 감싸는 요소로 44px 를 만들면 클릭 가능한 면은 여전히 36px 이라
  규칙을 채우지 못한다.

### ★ 이번 회차에 메운 검사기 사각 3건

1. **`placeholder.mjs` 가 닫힌 모달 안 입력을 '넘침' 으로 오보고했다** — `display:none` 이면 `clientWidth=0`
   이라 가용폭이 `-32px` 가 되어 전부 OVERFLOW 로 찍혔다. **측정 불가와 넘침은 다른 사실**이므로
   `placeholder2.mjs` 에서 SKIP 으로 분리하고, `--open` 으로 오버레이를 펴서 실제로 재도록 고쳤다.
   그러지 않았으면 9건의 가짜 결함을 고치려다 멀쩡한 폼을 흔들 뻔했다.
2. **`clip.mjs` 가 `.sr-only`(1×1 로 접은 스크린리더 텍스트)를 '잘림' 으로 셌다** — 설계상 접은 것이라
   결함이 아니다. `clip2.mjs` 에서 `clientWidth<=1` 을 분리했다.
3. **`hitarea.mjs` 가 툴팁 트리거(`tabindex` 배지)를 조작으로 세고, 오버레이 안 컨트롤은 아예 못 봤다** —
   `hitarea3.mjs` 에서 비조작을 분리하고 오버레이를 펴서 측정 대상을 57건 → 94건으로 넓혔다.

> 세 사각 모두 **"0건" 이 아니라 "무엇을 못 보는가"** 를 물어서 드러났다.

  치환이 0 이라는 것은 **문자가 바뀐 자리가 한 곳도 없다**는 뜻이므로 한글 손상이 원리적으로 불가능하다.

### ★ 게시 렌더가 지우는 속성 6종 (실측 · 이번 회차 발견 2종 포함)

| 삭제 대상 | 건수(3화면) | 성격 |
|---|---|---|
| `stroke-width` | 93 | **시각 손상** — 없어지면 SVG 기본값 1 로 그려져 아이콘이 얇아진다 |
| HTML 주석 | 31 | 내용 아님 — 무해 |
| `scope` | 27 | 표 접근성 정보 손실 (이전 회차에 이미 관측) |
| `tabindex` | 6 | **신규 발견** — 키보드로 툴팁에 닿을 수 없게 된다 |
| `maxlength` | 4 | **신규 발견** — 입력 길이 제한이 사라진다 |
| `inputmode` | 2 | 모바일 키패드 힌트 손실 (이전 회차에 이미 관측) |

**보존되는 것**: `role`·`aria-*`·`class`·`id`·`for`·`type`·`value`·`placeholder`·`stroke`·`fill`.

**`stroke-width` 만 이번에 되살렸다** — 같은 값을 CSS 로도 선언했다(CSS 는 원문 그대로 보존되는 것이
왕복 대조로 확인됨). 게시본을 브라우저로 열어 계산 스타일을 재 확인했다 — 로컬 속성 값 분포와 정확히
일치한다. HTML 속성은 그대로 남겨 로컬 원본이 자기완결이 되게 했다(presentation attribute 는 CSS 보다
우선순위가 낮아 값이 같으면 충돌하지 않는다).

⚠ 나머지 5종은 **CSS 로 대체할 수 없는 정보**라 게시본에서 복원 불가다. **로컬 원본이 진실원**이며
구현은 로컬 파일을 따라야 한다.

## § 미해결 · 확인 필요

- **표시명 출처 필드의 API 계약 미확인** — 출처 칩은 서버가 해석 단계를 함께 내려준다는 전제로 그렸다.
  현재 목록 응답에 그 필드가 있는지 확인하지 못했다. 없으면 ①응답에 추가하거나 ②칩을 빼야 한다.
  **화면에서 폴백을 재계산해 채우는 방식은 골격이 금지**하므로 선택지가 아니다.
- **인라인 편집의 키보드 동선 미검증** — 편집 진입·저장·취소의 포커스 이동 순서를 재지 않았다.
- 스크린리더 읽기 순서·탭 순서 미측정.
