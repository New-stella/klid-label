# 포털 증강 화면

## purpose

포털 회원(PORTAL_USER)이 본인이 올린 영상에 대해 낸 증강 요청의 현황을 보고, 도착한 결과물을 확인하고, 그 결과물에 라벨링 등 후속 작업을 이어서 하러 가고, 작업을 마친 결과물을 내려받는 화면. 증강은 요청·결과 확인·후속 작업·내려받기 넷이 모두 저작도구 안에서 끝나며 이 화면이 뒤의 세 단계를 담는다. 요청을 거는 자리는 이 화면이 아니라 포털 업로드 화면(SCREEN-033)의 자산별 액션이므로 같은 행위의 진입을 여기에 다시 두지 않고, 대상 영상을 고르러 가는 링크만 둔다. 증강은 서버가 외부로 보내는 비동기 위탁이라 요청한 즉시 결과가 나오지 않는다 — 요청 현황 목록은 결과 대기 중인지, 도착했는지, 실패했는지를 셋으로 구분해 보여 대기 구간이 화면에 드러나게 한다. 셋을 가르는 근거는 목록 행이 함께 나르는 결과 도착 여부와 실패 사유다. 도착 여부가 참이면 결과 도착, 거짓이면서 실패 사유가 비어 있으면 결과 대기 중, 거짓이면서 실패 사유가 차 있으면 실패이며, 어느 것에도 해당하지 않으면 결과 대기 중으로 둔다. 목록 하나로 이 구분이 서므로 실패를 가려내려고 행마다 결과 확인 창구를 부르지 않는다. 결과 도착을 다시 확인하는 대상은 결과 대기 중인 요청뿐이며 실패한 요청은 재조회하지 않는다. 결과물에 대한 후속 작업은 포털 라벨링 화면(SCREEN-029)이 수행하고 이 화면은 그리로 가는 진입만 갖는다. 대상은 본인이 올린 영상에 한정되며 데이터마트에서 불러온 영상은 대상이 아니다. 이 경로에는 검수가 없어 결과물을 채택·반려로 가르는 결정 단계를 두지 않는다. 결과물은 요청한 본인에게만 제공되며 데이터마트와 원본을 수정하지 않는다. 접근: PORTAL_USER.

- 포털 채널의 증강이 저작도구 안에서 종결된다는 상위 확정에 맞춰 신설했다. 요청·결과 확인·후속 작업·내려받기 넷 가운데 뒤의 세 단계를 담을 화면이 없어 생긴 공백을 메운다.
- 증강 요청 진입은 만들지 않았다 — 포털 업로드 화면(SCREEN-033)의 자산별 액션이 이미 그 자리를 갖고 있어 같은 행위의 진입을 둘로 만들지 않는다. 대상 영상을 고르러 가는 링크만 둔다.
- 후속 작업인 라벨링은 포털 업로드 라벨링 화면(SCREEN-034)이 수행하고 이 화면은 진입만 갖는다.
- 소비 창구를 연결했다 — 요청 현황은 요청 목록 조회 창구를, 결과 확인은 요청 단건 조회 창구를 부른다. 내려받기 두 갈래는 이미 있던 포털 자산 창구를 그대로 쓴다(라벨 내보내기·원본 파일). 요청을 거는 창구는 이 화면이 아니라 포털 업로드 화면이 부른다.
- 요청 상태의 개별 표시 값은 확정되지 않아 정하지 않았다.
- 증강 파생물의 저장 모델은 2026-09-02 에 확정됐다(ADR-058) — 공용 영상 원장의 새 행이며 부모 참조로 요청 대상 영상을 가리키고 출처 유형과 소유자는 업로드 자산 것을 그대로 쓴다. 이 화면 본문에 그 모델을 담지는 않는다.
- 만료 임박 안내는 두지 않는다.
