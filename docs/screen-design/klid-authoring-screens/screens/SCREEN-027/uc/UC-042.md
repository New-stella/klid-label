# 파일 업로드로 영상 한 건 투입

## goal

관제 인입을 기다리지 않고 손에 있는 영상 한 건을 저작도구에 직접 올려 처리에 태우고, 그 영상이 마킹 대기에 이르렀는지 결과 패널에서 확인해 다음 걸음으로 이어 간다.

### [8]

### [9]

## brownfield

### notes

이 흐름이 없어 파일 업로드 화면의 수용기준 두 건이 어느 사용 사례에도 매달리지 않은 채 떠 있었다. 기존 흐름들과의 경계는 누가·몇 건을·어느 창구로다 — 기계가 원장에 넣고 배치가 가져가는 축과 사람이 폴더째 넘기는 축은 각각 다른 흐름이 이미 맡고 있고, 이 흐름은 사람이 화면에서 한 건씩 올리는 자리다.

## description

관리자가 관리자 패스워드 확인으로 단기 유효창을 연 뒤 파일 업로드 화면에서 영상 파일 한 건과 인입 메타데이터를 채워 올린다. 적재 경로를 두 갈래 중에 고르며 두 경로는 입력 폼이 완전히 같고 보내는 곳과 그 뒤 흐름만 갈린다 — 파이프라인 즉시 실행은 영상과 메타를 한 번에 보내 곧바로 처리에 태우고, 관제 인입 재현은 인입 원장에 적재해 주기 배치가 가져가게 한다. 실행할 단계를 고르는 기능은 두지 않으며 즉시 실행의 흐름은 업로드 다음 비식별 다음 마킹 대기 정지로 고정이고 비식별은 예외 없이 항상 실행된다. 영상 기술메타는 비워 두면 서버가 올린 파일에서 직접 읽어 채우고 영상 길이는 아예 입력하지 않는다. 고른 경로에서 서버로 전달되지 않는 입력 묶음은 화면이 그 사실을 알려 저장됐다고 오해하지 않게 한다. 마킹이 끝난 영상 묶음을 폴더째 한 번에 들여오는 일은 이 흐름의 대상이 아니다 — 그것은 입력이 서버 내부 폴더 경로라 산출물 가져오기가 맡는다.

## preconditions

- 관리자로 인증되어 있다

- 이 통로를 여는 운영 설정이 켜져 있어 화면과 주소가 열려 있다
- 올릴 영상 파일 한 건이 허용하는 형식과 용량 안에 있다

## alternate_flows

### 관제 인입 재현으로 조각 전송

**steps**:

- 시스템이 전송 세션을 만들고 그 시점에 인입 대기 행이 함께 생긴다
- 시스템이 영상을 조각으로 나눠 보내며 끊기면 그 지점부터 이어 보낸다
- 주기 배치가 인입 대기 행을 가져간 뒤에 영상 식별자가 생긴다

- **trigger**: 적재 경로로 관제 인입 재현을 골랐다

### 유효창 없이 시작

**steps**:

- 시스템이 업로드 시작을 거부한다
- 시스템이 권한이 모자란 것인지 유효창이 없는 것인지 구분해 알리지 않는다
- 관리자가 관리자 페이지에서 패스워드를 확인해 유효창을 다시 연다

- **trigger**: 관리자 단기 유효창이 없거나 만료됐다

### 허용 밖 입력으로 거부

**steps**:

- 시스템이 잘못된 요청·크기 초과·충돌 중 해당하는 사유로 거부한다
- 영상은 적재되지 않고 파이프라인도 시작되지 않는다
- 화면이 서버가 보낸 거부 문구를 그대로 보여준다

- **trigger**: 필수 항목이 빠졌거나 형식·확장자·용량이 허용 밖이거나 이미 쓰인 영상 클립 식별자다
