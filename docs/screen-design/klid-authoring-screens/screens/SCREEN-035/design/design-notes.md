  빠짐 없이 옮기되, 사라지는 것 2개와 남는 것 2개를 아이콘 색으로 갈라 적었다.

### 골격에 없어 그리지 않은 것

- **검색·필터·페이지네이션** — 골격에 없다. 라벨 마스터는 전량을 정렬 순서대로 보여준다.
- **정렬 순서 드래그 변경** — 골격은 정렬 순서를 숫자 입력으로 규정한다.
- **삭제 되돌리기** — 골격이 "이 화면에는 되돌리는 동선을 두지 않는다"고 명시한다. 대신 되살릴 수 없다는
  사실을 확인 모달에 경고로 남겼다.

## § 디자인 결정 (골격이 규정하지 않은 부분)

### 1. AI 탐지 클래스 매핑을 목록에서 보이게 했다 — 열은 늘리지 않았다

골격 purpose 는 이 매핑이 오토라벨·프리셋 동작의 축이라고 규정하는데, 목록 컬럼 5개에는 없다. 어떤 라벨이
아직 매핑되지 않았는지는 **운영자가 가장 먼저 알아야 할 상태**인데 모달을 하나씩 열어야만 알 수 있다.

그래서 **열을 추가하지 않고 라벨명 칸의 보조줄**로 칩을 달았다(`AI 탐지 person` / `AI 탐지 미매핑`).
골격이 정한 컬럼 구성은 그대로다.

⚠ 칩에 실린 `person`·`car` 는 **외부 표준(탐지 클래스 목록)의 데이터 값**이지 구현 식별자가 아니다.
운영자가 모달에서 직접 고르는 값이며 기준본 SD-004 도 같은 성격의 값을 화면에 그대로 표시한다.

### 2. 라벨 표시 색상은 '데이터' 라서 시안에서도 데이터로 다뤘다

라벨 색은 운영자가 지정하는 임의의 `#RRGGBB` 이지 디자인 토큰이 아니다. 그런데 시안에 임의 hex 를
쓰면 raw hex 검출에 걸려 **디자인 색과 데이터 색이 뒤섞인다.** 그래서 예시 색을 **전부 DS 토큰 값에서
골라** 썼다(`#DE3412`=error-5, `#256EF4`=primary-5 …). 덕분에 이 파일의 hex 105건이 전부 토큰으로
추적되면서도 화면은 실제 데이터처럼 보인다. **실제 운영에서는 이 값들이 임의 색으로 바뀐다.**

색상 칸에는 스와치와 코드 텍스트를 **항상 함께** 뒀다 — 색만으로 정보를 전달하지 않는다는 do_rule.

### 3. 여기서 바꾼 값이 프리셋으로 즉시 번진다는 사실을 상단에서 알린다

골격 purpose 의 첫 문장이자 이 화면에서 가장 되돌리기 어려운 성질이다. 운영자가 "내 화면만 고치는 것"
으로 오해하면 운영 중 프리셋이 통째로 흔들린다. 표 위 배너(info)로 먼저 알렸다.

### 4. 아이콘 버튼에 이름 툴팁을 붙였다

골격이 관리 열 3개를 `IconButton` 으로 규정한다. 아이콘만으로는 '속성'과 '수정'이 갈리지 않으므로
호버·포커스에 이름을 띄웠다. `aria-label` 은 별도로 부여해 스크린리더가 항상 읽는다.

### 5. 남는 폭은 라벨명이 아니라 '관리' 열이 흡수한다

라벨명 열이 남는 폭을 먹으면 넓은 화면에서 이름과 형태 사이가 400px 넘게 벌어져 한 행을 읽는 데
시선이 화면을 가로지른다. 라벨명을 고정폭으로 두고 관리 열을 늘렸다 — 그 열은 버튼이 오른쪽 끝
정렬이라 늘어나도 빈 여백만 커지고 읽기에 영향이 없다.

### 6. 화면과 서버의 허용 범위가 다른 두 항목을 참고 패널에 명시했다

골격은 라벨명(화면 50 / 서버 64)과 색상(화면 대소문자 허용 / 서버 대문자만)이 서로 다르다고 규정한다.
이건 구현자가 놓치기 쉬운 비대칭이라 표로 남겼다. 화면이 통과시켜도 서버가 막을 수 있으므로 폼 상단
오류 슬롯도 함께 그렸다.

## § 접근성 검증 (WCAG — 동봉 `scripts/contrast_checker.py`)

- **본문 4.5:1 / 큰글씨·UI 3:1 기준으로 58조합 측정 — 본문·배지·버튼 전건 통과.**
- **측정으로 2건을 고쳤다**:
  - 색상 스와치 경계 `--n-3`(2.01:1) → **`--n-4`(3.08:1)**. 밝은 라벨 색이 흰 표면에 묻히면 이 경계가
    스와치의 존재를 알리는 유일한 수단이 된다.
  - 위험 아이콘 버튼 경계 `--e-3`(2.46:1) → **`--e-5`(4.56:1)**. 아이콘 버튼은 글자가 없어 경계가 버튼
    박스를 알리는 주 수단인데, 같은 파일의 기본 `.icon-btn` 이 `--n-5`(4.51:1)를 써서 **한 파일 안에서
    버튼 경계 정책이 갈려 있었다**.
- **빵부스러기 링크 hit area 를 44×44 로 확보**(시각 크기 불변 · `min-*` + 음수 margin).

## § 역등록 기록 (Phase 5)

| SD | render_id | surface | action | 렌더 URL |
|---|---|---|---|---|
| **SD-022** | `main` | `page` | add → replace | `/uploads/designs/4ece2c3f-8e99-46f5-9580-71108a76e578/SD-022/main.html` (+ `main.css`) |

- **render_id·surface 를 와이어프레임과 동일**(`main` / `page`)하게 맞춰 비교 뷰에서 짝지어지며, SD 는
  screen_spec 과 별 ITEM 이라 와이어프레임을 덮어쓰지 않는다.
- **왕복 바이트 대조 — 치환(replace) opcode 0건 · 미설명 잔차 0건 · CSS 원문 해시 일치.**
  치환이 0 이라는 것은 **문자가 바뀐 자리가 한 곳도 없다**는 뜻이므로 한글 손상이 원리적으로 불가능하다.
- **ITEM 한글 필드 12/12 완전일치**(제목·본문 제목·설명·렌더 라벨). 한글을 손으로 치지 않고
  키트 `.md` 와 SD-017 값에서 **추출해 조립**했다.

### ★ 게시 렌더가 지우는 속성 6종 (실측 · 이번 회차 발견 2종 포함)

| 삭제 대상 | 건수(3화면) | 성격 |
|---|---|---|
| `stroke-width` | 93 | **시각 손상** — 없어지면 SVG 기본값 1 로 그려져 아이콘이 얇아진다 |
| HTML 주석 | 31 | 내용 아님 — 무해 |
| `scope` | 27 | 표 접근성 정보 손실 (이전 회차에 이미 관측) |
| `tabindex` | 6 | **신규 발견** — 키보드로 툴팁에 닿을 수 없게 된다 |
| `maxlength` | 4 | **신규 발견** — 입력 길이 제한이 사라진다 |
| `inputmode` | 2 | 모바일 키패드 힌트 손실 (이전 회차에 이미 관측) |

**보존되는 것**: `role`·`aria-*`·`class`·`id`·`for`·`type`·`value`·`placeholder`·`stroke`·`fill`.

**`stroke-width` 만 이번에 되살렸다** — 같은 값을 CSS 로도 선언했다(CSS 는 원문 그대로 보존되는 것이
왕복 대조로 확인됨). 게시본을 브라우저로 열어 계산 스타일을 재 확인했다 — 로컬 속성 값 분포와 정확히
일치한다. HTML 속성은 그대로 남겨 로컬 원본이 자기완결이 되게 했다(presentation attribute 는 CSS 보다
우선순위가 낮아 값이 같으면 충돌하지 않는다).

⚠ 나머지 5종은 **CSS 로 대체할 수 없는 정보**라 게시본에서 복원 불가다. **로컬 원본이 진실원**이며
구현은 로컬 파일을 따라야 한다.

## § 미해결 · 확인 필요

- **AI 탐지 클래스 목록의 화면 표기 미확정** — 시안은 탐지 클래스 값을 원문 그대로 보여준다. 우리말
  병기가 필요한지, 병기한다면 그 대응표를 누가 소유하는지 정해지지 않았다.
- **사이드 시트가 열린 채 라벨을 삭제한 경우의 전이 미표현** — 골격은 "패널이 자동으로 닫힌다"고
  규정하지만 정적 시안이라 그 전이를 그리지 못했다. 문장으로만 시트 하단에 남겼다.
- **속성 삭제 확인 절차 미정** — 골격은 라벨 삭제에만 확인 모달을 규정하고 속성 삭제에는 규정이 없다.
  시안은 골격대로 확인 없이 두었으나 실제로 되돌릴 수 없는 조작이라 확인이 필요한지 정해야 한다.
- 스크린리더 읽기 순서·탭 순서 미측정.
