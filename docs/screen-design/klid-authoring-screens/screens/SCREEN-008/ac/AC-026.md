# 인입 중복 방어·파일 미도착 백오프

## notes

근거: UC-018 대체 흐름(중복 INSERT·파일 미도착·재큐). 판정 지점: LS_DATA_INGEST UK_LS_DATA_INGEST_CLIP 제약 · 주기 폴링의 backoff 로직 · 재큐 API.

## priority

high

## scenario

### then

- UK_LS_DATA_INGEST_CLIP 유니크 제약 위반으로 INSERT 가 거부되어 중복 행이 생기지 않는다

### when

- 관제서버가 같은 VMS_CLIP_ID='CLIP-001' 로 재송신한다

### given

- LS_DATA_INGEST 에 VMS_CLIP_ID='CLIP-001' 행이 이미 존재한다

### and_examples

#### [1]

- **case**: 인입 행은 존재하나 RAW_FILE_PATH_NM 경로에 파일이 아직 없음
- **result**: 배치가 실패 처리하지 않고 PENDING 으로 두며 최초 관측 시각을 PRCS_DT 에 기록한다(관제가 준 RCPTN_DT 는 과거 시각일 수 있어 앵커로 쓰지 않는다)

#### [2]

- **case**: 고착 행의 FIFO 잠식 방지
- **result**: NXTM_RTRY_DT 를 뒤로 밀어(backoff) 처리한다

#### [3]

- **case**: 대기 상한 초과
- **result**: 종결 처리하고 관측 로그를 남긴다

#### [4]

- **case**: 운영자(REVIEWER)의 수동 재큐
- **result**: POST /v1/control-ingests/{rcptnSn}/requeue 로 PRCS_STTS_CD 를 PENDING 으로 되돌리고 PRCS_DT·NXTM_RTRY_DT 를 비워 대기 예산을 리셋한다

## statement

동일 VMS_CLIP_ID 로 재송신된 인입 행은 유니크 제약으로 거부되고, NAS 에 파일이 아직 도착하지 않은 인입 행은 실패 처리되지 않고 PENDING 으로 남아 NXTM_RTRY_DT 백오프로 재시도된다.
