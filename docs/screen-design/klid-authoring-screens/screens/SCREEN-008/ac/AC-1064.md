# UC-011 비식별 위탁 예외 — 연동 실패 F·원본 보존·수동 재비식별·응답 유실 폴링 회수 F 마감·취소 종결만 상태 불변·신고 구간 보류·제외 복사 실패 F·제외 행 회수 대상 아님·제외 출처유형 오표기는 검수 중 신고로 회수 (negative)

## notes

[폐기] 「수락 응답 미관측(ACK 대기 유예 만료)에 따른 회수는 영상의 비식별 상태를 실패로 내리지 않는다」 — 코드 실측으로 거짓임이 확인돼 정정했다. 유예 만료 회수는 제출 확정 실패와 같은 종결 경로를 타고 그 경로가 영상 비식별 여부를 'F'로 내린다. 되살리지 말 것.
유예 만료 회수를 종결 사유 코드(KPST_ACK_MISSING)로 따로 두는 근거는 영상 상태가 아니라 운영 조치다 — 그 코드가 남았다는 것은 우리 프로세스가 수락 응답을 관측하지 못했다는 뜻이라 외부에는 프로젝트가 실제로 생성돼 있을 수 있고, 사람이 외부 상태를 확인해야 하는 건을 식별하려는 분리다.
영상 비식별 여부를 내리지 않는 종료는 취소 종결(KPST_SUBMIT_CANCELED, 호출자 트랜잭션 롤백) 하나뿐이며 근거는 외부로 아무것도 나가지 않았다는 것이다. 외부 터미널 상태·폴링 경과 만료·불완전 산출물·제출 확정 실패는 모두 'F'로 내린다.
검증 실상 — 정정된 단언을 확인하는 자동 시험은 확인되지 않았다. 검증 상태를 unverified로 되돌렸고, 정정 이전 단언에 대해 기록돼 있던 마지막 실행 기록(통과)은 함께 걷어냈다. 증빙에 남은 화면 시나리오 문서 항목은 거짓 서술을 담고 있지 않아 그대로 둔다.
참조 식별자(slug)에 남은 옛 어휘는 참조가 끊기지 않도록 유지한다.
출처유형 제외 분기(ADR-066)의 예외를 이 기준에 더했다 — 복사 실패·제외 행의 회수 대상 제외·출처유형 오표기 영상의 검수 중 신고 회수. 제외 분기의 성공 경로는 정상 경로 기준(AC-1063)에 둔다. 제외 출처유형 목록을 관리 화면 시스템 설정 경로로 바꿀 수 없다는 사양은 비식별 옵션 설정 축이라 이 기준에 두지 않는다.
[폐기] 「출처유형이 제외 목록에 든 검수 완료 영상의 재비식별은 제외 축을 타지 않고 외부 솔루션에 위탁한다」 — 제외 처리에 성공한 영상은 비식별 여부가 'Y' 라 검수 완료 재비식별 창구(API-112)가 이미 비식별됨으로 받지 않으므로 그 단언이 성립하는 대상이 없었다. 오표기의 회수 지점은 검수 중 비식별 누락 신고이며 그 단언으로 바꿨다. 검수 완료 재비식별을 제외 영상의 회수 경로로 되살리지 말 것.

## scenario

### then

- 연동 실패는 DE_IDNTF_YN='F'·원본 보존·이력 기록, 자동 재큐 없이 수동 재비식별+resolve
- 응답 유실은 폴링이 주기적으로 재클레임해 실패로 종결하고 영상 비식별 여부를 'F'로 내린다(별도 스위퍼를 두지 않는다 · ACK 대기 유예와 콜백 창 구분 · 원자 클레임 · 종결 사유 KPST_ACK_MISSING). 회수된 건은 재위탁되지 않는다
- 신고 구간은 외부 위탁을 개시하지 않고 보류한다
- 취소 종결(KPST_SUBMIT_CANCELED)은 원장만 FAILED로 마감하고 영상 비식별 여부는 그대로 둔다
- 제외 복사 실패는 영상 비식별 여부 'F' · LS_DEIDENT_PROC_LOG 에 PROC_STTS_CD=FAILED · REQ_KND_CD=EXCLUDED 행 · MARKING_READY 미전이 · 반쯤 쓴 임시 파일 정리 · 원본 삭제·수정 없음
- REQ_KND_CD=EXCLUDED 인 처리 이력 행은 외부 진행 상태 폴링과 수락 대기(ACK) 유예 만료 회수의 대상에 오르지 않는다
- 출처유형이 제외 목록에 든 영상이 검수 중 비식별 누락 신고로 접수되면 기존 신고·외부 솔루션 수동 재비식별·신고 해소 경로로 처리되고 제외 판정은 다시 하지 않는다

## statement

외부 호출이 실패하면 DE_IDNTF_YN='F'로 마킹하고 원본을 보존하며(원본 절대 삭제 금지) LS_DEIDENT_PROC_LOG에 실패 상태·오류를 기록한다 — 자동 재비식별 큐는 없고 작업자/검수자가 외부 솔루션으로 수동 재비식별한 뒤 resolve로 해소한다(UC-016). 수락 응답도 결과 회신도 관측되지 않은 건은 폴링이 주기적으로 다시 집어 실패로 종결하며(별도 스위퍼를 두지 않는다 — 폴링이 이미 클레임·시한·종결을 갖춘 회수기다. 회수된 건은 재위탁되지 않고 위 수동 재비식별 경로로 간다)(그 회수는 우리가 수락 응답을 관측하지 못했다는 뜻이지 외부에서 실패했다는 뜻이 아니다. 그럼에도 종결 경로는 제출 확정 실패와 같아 원장을 FAILED로 마감하고 영상 비식별 여부를 'F'로 내린다 — 종결 사유를 KPST_ACK_MISSING으로 따로 남기는 것은 영상 상태를 달리 하려는 것이 아니라, 외부에는 프로젝트가 실제로 생성돼 있을 수 있어 사람이 외부 상태를 확인해야 하는 건을 식별하려는 운영 조치다. 이 축의 유일한 회수 경로는 폴링이다), ACK 대기 유예와 결과 대기 창(콜백)을 구분해 정상 위탁을 잘못 회수하지 않고 4노드 Active-Active에서 조건부 UPDATE로 원자 클레임해 두 번 재위탁하지 않는다. 호출자 트랜잭션 롤백으로 취소 종결(KPST_SUBMIT_CANCELED)된 건만 외부로 아무것도 나가지 않았으므로 원장만 FAILED로 마감하고 영상 비식별 여부는 그대로 둔다. 대상 영상이 비식별 재처리 대기(DE_IDNTF_YN='F')면 외부 위탁을 개시하지 않고 보류한다.

[출처유형 제외 분기의 예외 — ADR-066] 출처유형(LS_DATA_RAW.SRC_TYPE)이 배포 설정 authoring.deidentify.excluded-src-types 의 제외 목록에 든 영상의 원본이 없거나 경로 위반·입출력 오류로 복사할 수 없으면, 영상 비식별 여부를 'F' 로 두고 LS_DEIDENT_PROC_LOG 에 PROC_STTS_CD=FAILED · REQ_KND_CD=EXCLUDED 인 행을 남기며 배치 단계를 MARKING_READY 로 전이하지 않는다. 반쯤 쓴 임시 파일은 정리하고 원본은 삭제하거나 수정하지 않는다. REQ_KND_CD=EXCLUDED 인 처리 이력 행은 외부 진행 상태를 갖지 않으므로 외부 진행 상태 폴링과 수락 대기(ACK) 유예 만료 회수의 대상에 오르지 않는다 — 그 회수로 실패 마감되거나 그 때문에 영상 비식별 여부가 'F' 로 내려가는 일은 없다. 출처유형이 제외 목록에 든 영상이 실제로는 인물이 찍힌 영상이라(출처유형 오표기) 검수 중 비식별 누락 신고로 접수되면, 기존 신고·외부 솔루션 수동 재비식별·신고 해소 경로로 처리되고 제외 판정은 다시 하지 않는다 — 원본 복사로 해소하지 않는다. 오표기의 회수 지점은 검수이며, 승인 이력이 있는 영상은 기존 정책대로 신고 접수 자체가 거부되므로 승인 이후와 그 파생본은 이 경로 밖이다. 검수 완료 재비식별(API-112)은 제외 판정을 거치지 않지만 이미 비식별 여부가 'Y' 인 영상을 받지 않고 제외 처리에 성공한 영상은 모두 'Y' 이므로, 그 창구는 제외 영상의 회수 경로가 아니다.
