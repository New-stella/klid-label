### 골격이 못박은 규칙 — 지켰다

- **가장 마지막 버전이 기본 선택.** `#ver-3` 라디오에 `checked` 를 두고 선택 표면(`--p-0` + 1px inset ring)을 입혔다.
- **한 번에 하나만 고른다 — 두 버전 비교 방식을 두지 않는다.** 그래서 체크박스가 아니라 **라디오**다.
  UI-066 VersionList 가 가진 `checkedHashes`(버전 간 비교) 축은 이 화면에 **그리지 않았다**.
- **목록의 프레임 수는 그 버전에서 실제로 변경된 프레임만.** 라벨을 `변경 프레임 12` 로 적고,
  목록 아래에 "바뀌지 않은 프레임은 직전 버전의 내용이 그대로 유효합니다"를 캡션으로 붙였다.
- **② 렌더 순서 미선택 → 로딩 → 오류 → 결과.** 참고 패널 B 를 그 순서 그대로 4칸으로 배열했고,
  **오류(③)와 변경 없음(④)을 다른 색·다른 아이콘·다른 문장**으로 갈랐다 — 오류는 error 계열
  (`변경이 없는 것이 아니라 조회에 실패한 상태입니다`), 변경 없음은 info 계열(체크 아이콘)이다.
- **② 의 비교 축 6개**를 캡션에 그대로 적었다(라벨 식별자 · 도형 종류 · 라벨 이름 · 라벨 마스터 연결 · 좌표 · 추적 식별자).
  **신뢰도 등 자동 인식 값은 축으로 넣지 않았다.** 추적 식별자를 넣는 이유도 한 줄로 적었다.
- **② 는 비교 대상을 표시한다.** `.compare-bar` 로 `버전 3 → 현재 작업본` 을 칩 두 개 + 화살표로 고정 표시한다.
- **③ Dialog 는 조건부**라 본문이 아니라 참고 패널에 뒀다.
- **불러오기는 서버에 아무것도 쓰지 않는다 / 저장 단위는 영상 전체.** 푸터 왼쪽 고정 문구로 항상 보이게 했다 —
  버튼을 누르기 전에 읽히는 자리다.

### 골격에 없어 그리지 않은 것

- **모달 닫기(X) 버튼.** 골격에 없다. 나가는 길은 두 버튼(이 버전으로 시작 / 현재 작업본으로 시작)이다.
- **뒤로가기·빵부스러기·페이지 헤더.** 라우트가 없는 모달이고 셸 밖이라 해당 없다.
- **두 버전 간 비교(체크박스·기준/비교 배지), 롤백 버튼, 버전 검색·필터·페이징.** 골격에 없다.
- **저장 버튼.** 저장은 이 모달이 아니라 라벨링 캔버스의 기능이다 — 문구로만 언급했다.
- **변경 목록의 shape 요약(좌표 4개·점 개수 등)과 이전/이후 값.** 골격 note 가 지정한 행 구성은
  종류·프레임 식별자·객체 식별자·라벨 이름 넷뿐이라 그 넷만 그렸다(아래 § 미해결 참조).
- **다시 시도 버튼.** 조회 실패 안내에 붙일 법하지만 골격에 없어 만들지 않았다.
  그래서 이 화면에는 `.btn-sm`(36px)이 **한 곳도 없다** — 모든 버튼이 44px 하한을 지킨다.

## § 디자인 결정 (골격이 규정하지 않은 부분)

### 1. 스크림 위에 뜬 모달로 그렸고, 뒤 화면은 지어내지 않았다

DS 는 "앱에 다크 표면은 없다 — 유일한 예외는 미디어 매트와 그 위 오버레이(모달 스크림)"라고 못박는다.
이 화면은 그 예외에 해당하므로 어두운 무대 위에 모달을 얹었다.

다만 **스크림 뒤 라벨링 캔버스의 내용은 그리지 않았다.** 중립 매트(`--n-3`) 위에
`rgba(--n-10, 0.72)` 스크림을 덮어 "밝은 앱 위에 딤이 깔린 상태"만 표현하고,
무대 상단에 "모달 뒤는 라벨링 캔버스입니다 — 이 시안에서는 그 내용을 그리지 않고 중립 표면으로 둡니다"를
적어 두었다. 색은 새 hex 가 아니라 `--n-10` 의 투명도 변형(`--n-10-rgb`)이며 SCREEN-005 와 같은 방식이다.

모달 표면에는 **`--shadow-lg`** 를 썼다 — DS `elevation_levels` 가 lg 를 "모달, 드로어 등 화면 전체를
막고 뜨는 표면"으로 규정한다. 참고 패널 안의 확인 창도 같은 lg 다(카드가 아니라 모달이므로).

시안 최상단에는 SCREEN-002 의 `sheet-route` 칩을 빌려 **`라우트 없음`** 이라고 적었다.
없는 경로를 지어내는 대신 이 화면이 어떤 표면인지를 그 자리에서 밝힌다.

### 2. 목록을 라디오로 만들었다 — 두 축이 섞이지 않게

UI-066 VersionList 는 "행 클릭(단일 선택)"과 "체크박스(최대 2건, 버전 간 비교)" 두 축을 가진 컴포넌트다.
이 화면의 골격은 **두 버전 비교를 두지 않는다**고 명시하므로, 체크박스가 없는 형태로 그려야 한다.
그래서 컨트롤 자체를 **라디오 그룹**으로 삼았다 — 브라우저가 "여럿 중 하나"를 보장하고,
화살표 키 이동·`checked` 기본값이 스크립트 없이 성립하며, 체크박스 축이 화면에 생길 여지가 없다.

### 3. 변경 목록을 표로 그렸다

행마다 네 값(종류·프레임·객체·라벨)이 열로 정렬돼야 훑기 쉽다. 표 헤더는 do_rule 대로
secondary 최옅은 단계(`--s-0`), 행 hover 는 do_rule 지정값 `#FFFBEB` 다.
좁은 폭에서는 열을 뭉개지 않고 **표만 가로로 밀어 본다**(`.table-scroll` + `min-width: 420px`).
`colspan` 은 쓰지 않았다 — 빈 상태는 표 안이 아니라 별도 안내(참고 패널 B)로 낸다.

⚠ `.table-scroll` 의 `position: relative` 는 장식이 아니라 필수다. 안쪽 `.sr-only` caption 의 담는 블록이
문서 최상단이 되면 스크롤 컨테이너가 잘라내지 못해 문서 전체가 가로로 늘어난다(기준본 SCREEN-021 실측 사례).

### 4. 변경 종류를 색·아이콘·글자 3중으로 표기했다

DS `dont_rules` 는 색만으로 상태를 구분하지 말라고 못박고, UI-067 DiffViewer 도 같은 규칙을 갖는다.
`추가`(success 계열 + `+` 아이콘) · `수정`(warn 계열 + 연필 아이콘) · `삭제`(error 계열 + `−` 아이콘)로
세 단서를 겹쳤다. 색을 지워도 정보가 하나도 사라지지 않는다.

### 5. 확인 창은 warn 이 아니라 error 계열이다

DS `color_usage` 는 warn 을 "되돌릴 수 있는 경고", error 를 "파괴적 액션"으로 가른다.
저장하지 않은 편집이 사라지는 것은 되돌릴 수 없으므로 error 계열을 썼다.
확인 창의 버튼 두 개(`돌아가기` / `편집을 버리고 불러오기`)는 골격 목록에 없는 요소지만,
골격이 "확인을 받는다"고 규정한 이상 확인·취소 쌍 없이는 그 동작이 성립하지 않는다.
**문구는 시안 결정**이며, 확정 문구가 정해지면 교체 대상이다.

### 6. 조회 실패 상태에서 주버튼을 잠갔다

목록 조회가 실패하면 고를 버전이 없으므로 `이 버전으로 시작` 은 대상이 없다. 참고 패널 A ② 에서
주버튼을 비활성으로 두고 `현재 작업본으로 시작` 만 남겼다 — 골격이 "어느 버전도 고르지 않고 지금 작업본
그대로 시작하는 길을 함께 둔다"고 규정한 그 길이 이 상황의 유일한 출구이기 때문이다.
비활성 표현은 흐림(`opacity`)이 아니라 채도를 뺀 면이다 — 흐리면 글자 대비가 함께 무너진다.

### 7. 미선택 상태를 '드문 경우'로 명시했다

골격은 렌더 순서에 미선택을 포함하지만, 같은 골격이 "목록에 들어오면 가장 마지막 버전이 기본으로
골라져 있다"고도 규정한다. 두 서술이 모순은 아니다 — 정상 동선에서는 지나치기 어려운 경계 상태다.
그래서 참고 패널 B ① 에 그리되 "정상 동선에서는 이 자리를 보기 어렵습니다"를 덧붙였다.

### 8. 좁은 폭에서 두 열을 세로로 쌓는다

1023px 이하에서 목록·변경 내용 2열을 1열로 쌓고, 열 사이 세로 구분선을 가로 구분선으로 바꾼다.
340px 열을 유지하면 변경 목록이 짓눌리기 때문이다. 767px 이하에서는 푸터 버튼을 가로로 꽉 채운다.
어느 폭에서도 **글자 크기를 낮추지 않고 여백과 열 수만 조정**했다(DS `iteration_guide`).

## § 접근성 검증 (WCAG)

**본문 4.5:1 / 큰글씨·UI 3:1 기준으로 89조합 측정 — 1440·360 두 폭 모두 미달 0건.**

- 1차 도구(`contrast.mjs`)가 `.stage-note` 를 **1.63:1 미달**로 보고했으나 **도구 오탐**이었다.
  그 텍스트는 `::before` 스크림(`--n-10` 72%) **위**에 얹히는데 도구의 '유효 배경'은 투명이 아닌
  첫 조상(`--n-3` 매트)이라 스크림을 보지 못한다. 실제 칠해진 픽셀을 샘플링하니 `rgb(63, 66, 69)` 로
  **8.24:1 통과**였다(`pixelbg.mjs` — 글자를 투명화한 뒤 1픽셀 스크린샷의 PNG IDAT 을 직접 디코드).
  ⚠ 이 사각은 반대 방향으로도 열려 있다 — **밝은 오버레이가 어두운 조상을 덮으면 통과로 오보고**된다.
  오버레이를 쓴 화면은 도구의 통과 결과도 그대로 신뢰하지 않는다.

설계에서 지킨 원칙:

- **모달 시맨틱** — `role="dialog"` + `aria-modal="true"` + `aria-labelledby`(제목) + `aria-describedby`(부제).
- **선택 컨트롤은 네이티브 radio** — 화살표 키 이동·단일 선택 보장이 브라우저 몫이라 스크립트가 없어도 성립한다.
  `label[for]` 로 입력과 명시 연결하고, 그룹 이름은 `legend`(sr-only)로 준다.
- **hit area** — 버전 행·모든 버튼·스켈레톤 행에 44px 하한을 뒀다. 이 화면에는 `.btn-sm`(36px)이 없다.
- **focus ring** — `outline: 3px` + `offset: 2px`, `focus-visible` 한정. 버전 행은 `:has(:focus-visible)` 로
  라디오 포커스를 행 전체에 전달한다.
- **색 단독 금지** — 변경 종류는 색 + 아이콘 + 글자, 최신 배지는 색 + 점 + `최신` 글자.
- **오류와 빈 상태의 구분** — 색뿐 아니라 아이콘(경고 삼각 vs 체크 원)과 문장이 다르다.
  오류 배너는 `role="alert"`, 변경 없음은 `role="status"` 로 소리로도 갈린다.
- **표 시맨틱** — `thead th[scope="col"]` + `caption`(sr-only)으로 비교 대상을 문장으로 실었다.
- **비활성 주버튼** — 흐림이 아니라 `--n-2` 면 위 `--n-7` 글자로 대비를 유지했다.
- **모션** — 스켈레톤 펄스는 `prefers-reduced-motion: reduce` 에서 끈다.
- **회색 표면 위 보조 텍스트**는 전부 neutral 60단 이상(do_rule 준수).

### ⚠ 기준 미달로 남긴 것 (근거와 함께)

| 항목 | 값 | 판단 |
|---|---|---|
| 참고 영역 점선 `2px dashed --n-4` | 낮음 | 확정 관례·기준본 동일 조합. 컨트롤 경계가 아니다 |
| 빈 상태 장식 아이콘 `--n-4` | 낮음 | `aria-hidden` 장식이며 같은 정보를 제목·설명이 글자로 전달한다. 기준본 동일 관례 |

- **render_id·surface 를 와이어프레임과 동일**(`main` / `page`)하게 맞춰 비교 뷰에서 짝지어지며,

- **왕복 바이트 대조 — 미설명 치환 0 · 미설명 삭제 0 · 미설명 삽입 0 · CSS 원문 해시 일치 True.**
- 치환 12건의 내역: **SVG 속성명 소문자화 12건**(`viewBox`→`viewbox` 계열 — 서버가
  HTML 을 재직렬화하며 생기고 브라우저가 읽을 때 되돌리므로 화면은 달라지지 않는다) +
  **지워지는 속성이 조각째 사라지며 치환으로 잡힌 것 0건**(성격은 삭제와 같다).
  ⚠ 구 판정 기준 *"치환이 0 이어야 한다"* 는 이 저장소에서 이미 폐기됐다 — 정상 게시에서도 치환이 난다.
  판정은 **"치환 양쪽에 한글이 없고 전부 위 두 부류로 분류되는가"** 로 한다.
- 치환·삭제·삽입 어느 조각에도 **한글이 없다** — 그러므로 이 게시에서 한글 손상은 원리적으로 불가능하다.

### 게시본이 지우는 것 (이 화면 실측)

| 삭제 대상 | 이 화면 건수 | 성격 |
|---|---|---|
| `stroke-width` | 12 | **시각** — 없어지면 SVG 기본값 1 로 그려져 아이콘이 얇아진다. **CSS 로 되살렸다** |
| `scope` | 4 | 표 접근성 정보 손실 — CSS 로 대체 불가 |
| `title` | 7 | 말줄임된 전체 문구를 띄우는 길 손실 — CSS 로 대체 불가 |
| HTML 주석 | 0 | 내용 아님 — 무해 |

**보존되는 것**: `role`·`aria-*`·`class`·`id`·`for`·`type`·`name`·`value`·`placeholder`·`checked`·
`disabled`·`stroke`·`fill`, 그리고 **CSS 원문 전체**(해시 일치).

### 지우는 것을 미리 피한 마크업

`optgroup` 0건 · `details` 0건 · `summary` 0건 — 게시 서버가 **요소째 지우고 자식만 남기는**(unwrap) 축이 따로 있어 처음부터 쓰지 않았다.
`optgroup` 은 묶음 라벨의 한글이 사라지고, `details`/`summary` 는 자식이 전부 남는 대신 **접기 동작이
사라져** 영구 펼침이 된다. ⚠ **시안·게시본 한정 제약이며 구현 제약이 아니다** — 실제 앱에서는 두 요소가
시맨틱상 낫다.

⚠ 시각에 영향을 주는 획 관련 속성은 같은 값을 **CSS 로도 선언**해 게시본에서 되살렸다. 나머지는
CSS 로 대체할 수 없는 정보라 게시본에서 복원되지 않는다 — **로컬 원본이 진실원**이며 구현은 로컬
파일을 따라야 한다.

## § 미해결 · 정보 부족

- **변경 목록 행 구성이 골격과 카탈로그에서 갈린다.** 골격 note 는 "종류·프레임 식별자·객체 식별자·**라벨 이름**"
  넷을 보여준다고 하는데, UI-067 DiffViewer 설명은 "**라벨명·labelId·trackId 는 화면에 렌더하지 않는다**"고
  하고 대신 이전/이후 shape 요약(BBOX 좌표 4개, POLYGON 점 개수 등)을 넣는다. 시안은 **골격을 따랐다**
  (요소의 존재 여부는 확정된 화면 사양이 기준). 두 문서 중 하나가 정정돼야 한다.
- **API-182 응답에 라벨 이름 필드가 없다.** 그 응답의 항목은 `type`·`before`·`after`·`frameId`·`objectId` 뿐이라,
  위 골격 note 대로 라벨 이름을 그리려면 조달처가 더 필요하다. 시안은 라벨 이름 열을 그렸으나
  **어디서 오는 값인지는 확인하지 못했다.**
- **변경 목록의 정렬 기준이 골격에 없다.** 시안은 종류(추가→수정→삭제) 묶음으로 배열했으나 근거가 없다.
  프레임 순인지 종류 순인지 확정이 필요하다.
- **변경 건수 상한 표기가 없다.** API-182 는 "최대 500건(초과 시 절단)"인데 골격·응답 어디에도 절단 여부를
  알리는 신호가 없다. 시안은 절단 안내를 그리지 않았다 — 지어내지 않기 위해 비웠다.
- **승인자 표시명이 없을 때의 대체 표기.** API-197 은 "해석에 실패하면 비어 있고 화면은 사번으로 대체한다"고만
  하고 사번을 어떤 모양으로 보일지는 규정하지 않는다. 시안은 표시명이 있는 경우만 그렸다.
- **영상 식별자를 화면에 어떻게 부르는지 확정되지 않았다.** 시안은 `영상 1024` 로 적었으나
  골격에 표기 규칙이 없다.
- **모달을 닫는 경로가 골격에 없다.** 두 버튼 외에 바깥 클릭·Esc 로 닫히는지, 닫히면 어느 상태로
  시작하는지가 규정돼 있지 않다. 시안은 닫기 컨트롤을 만들지 않았다.
- **저장하지 않은 편집이 있는지 판정하는 기준**(어떤 편집을 세는지)이 골격에 없다. 확인 창은
  "있을 때만" 뜬다는 조건만 그렸다.
- **웹폰트 소스 미정** — `@font-face` 없이 family 선언 + 시스템 한글 산세리프 폴백만 뒀다.
- 스크린리더 읽기 순서·탭 순서, 포커스 트랩 동작은 미측정이다.
