# 검수 승인·반려

## goal

작업자가 제출한 영상 단위 작업을 검수하여 승인 또는 반려한다. 승인 = 작업 완료

### [2]

### [4]

- **step**: 4
- **actor**: 검수자(REVIEWER)
- **action**: 또는 반려 — 반려 사유를 LS_DATA_ISSUE에 기록하고 reject 이벤트 기록, WORKER 재작업

## description

검수 완료 = 작업 완료. REVIEWER 가 승인하면 LS_RAW_DATA_STATUS.DATA_STTS_CD 가 APPROVED 로 전이된다 — 검수 워크플로의 종결값은 APPROVED 이고 이 축에서 COMPLETED 로 전이하는 경로는 없다(배치 완료는 ASSIGNED 로 복귀시킬 뿐이다). 같은 이름의 COMPLETED 는 축이 다르다 — LS_DATA_RAW.DATA_STTS_CD 의 COMPLETED 는 배치 단계 완료값이고, 검수 응답 status 의 COMPLETED 는 APPROVED 를 표시용으로 매핑한 값이다.

[★승인 연쇄 — 순서 보강] ①버전 스냅샷 생성(UC-007 include, SAVE_REASON_CD=APPROVED) ②export 폴더 새 버전 전량 재생성(이미지 2벌 포함) ③**export 가 SUCCEEDED 된 뒤에** outbound TASK_COMPLETED 통지(UC-009). 구 서술은 승인이 곧 통지를 발행하는 것처럼 읽혔으나, 통지가 export 보다 먼저 나가면 관제가 구 버전 폴더를 픽업한다. export 실패 시 통지는 보류되고 회수기가 재산출 성공 후 재개한다.

[반려] 반려 사유를 LS_DATA_ISSUE(REJECTION 스레드)에 기록하고 WORKER 가 재작업→재제출한다(1인 승인까지 반복 — 2차 검수 폐기 ADR-002, 관리자 확인요청도 폐기 ADR-003).

[승인 후 수정] 동일 작업 ID 를 유지한 채 재검수되며 재승인 시 새 버전이 쌓인다. 수정 경로는 그 영상을 재검수 대상으로 표시할 뿐이고, export 새 버전 재생성과 TASK_MODIFIED 발송은 검수자가 그 수정을 다시 승인한 시점에 일어난다.

제출/승인/반려 이벤트는 LS_TASK_EVNT_LOG 기록(ReviewService submit/approve/reject).
