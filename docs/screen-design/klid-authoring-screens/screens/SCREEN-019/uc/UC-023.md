## description

검수 완료 = 작업 완료. REVIEWER 가 승인하면 LS_RAW_DATA_STATUS.DATA_STTS_CD 가 APPROVED 로 전이된다 — 검수 워크플로의 종결값은 APPROVED 이고 이 축에서 COMPLETED 로 전이하는 경로는 없다(배치 완료는 ASSIGNED 로 복귀시킬 뿐이다). 같은 이름의 COMPLETED 는 축이 다르다 — LS_DATA_RAW.DATA_STTS_CD 의 COMPLETED 는 배치 단계 완료값이고, 검수 응답 status 의 COMPLETED 는 APPROVED 를 표시용으로 매핑한 값이다.

[★승인 연쇄 — 순서 보강] ①버전 스냅샷 생성(UC-007 include, SAVE_REASON_CD=APPROVED) ②export 폴더 새 버전 전량 재생성(이미지 2벌 포함) ③**export 가 SUCCEEDED 된 뒤에** outbound TASK_COMPLETED 통지(UC-009). 구 서술은 승인이 곧 통지를 발행하는 것처럼 읽혔으나, 통지가 export 보다 먼저 나가면 관제가 구 버전 폴더를 픽업한다. export 실패 시 통지는 보류되고 회수기가 재산출 성공 후 재개한다.

[반려] 반려 사유를 LS_DATA_ISSUE(REJECTION 스레드)에 기록하고 WORKER 가 재작업→재제출한다(1인 승인까지 반복 — 2차 검수 폐기 ADR-002, 관리자 확인요청도 폐기 ADR-003).

[승인 후 수정] 동일 작업 ID 를 유지한 채 재검수되며 재승인 시 새 버전이 쌓인다. 수정 경로는 그 영상을 재검수 대상으로 표시할 뿐이고, export 새 버전 재생성과 TASK_MODIFIED 발송은 검수자가 그 수정을 다시 승인한 시점에 일어난다.

제출/승인/반려 이벤트는 LS_TASK_EVNT_LOG 에 기록한다.

### 검수완료 후 수정

**steps**:

- 동일 작업 ID 유지 — 그 영상에 재검토 표시가 서고 재검수 대상이 된다(이 시점에는 export 재생성도 통지도 없다)
- 재검수에서 다시 승인되면 새 버전 스냅샷이 쌓이고(UC-007) export 새 버전 전량 재생성과 TASK_MODIFIED 통지가 나간다(UC-009)

- **trigger**: APPROVED 영상의 라벨/메타 수정

### 비식별 미완료 영상의 승인 거부

**steps**:

- 비식별화완료여부는 검수 워크플로 상태와 같은 자리에 보관되며 값은 Y 또는 N 이다. 그 값이 N 이면 승인이 거부된다.
- 이 거부는 상태 전이보다 먼저 판정되므로, 거부될 때는 검수 상태 전이도 버전 스냅샷도 export 새 버전 재생성도 통지도 전혀 생기지 않는다.
- 비식별화완료여부가 Y 로 바뀐 뒤의 승인 시도는 주 흐름 그대로 정상 진행된다.
- 영상 파일을 함께 받아 온 원본은 저작도구가 비식별 단계를 수행하고 그 비식별이 성공으로 기록되는 시점에 Y 가 된다.
- 영상 파일 없이 프레임만 받아 온 경우에는 외부에서 비식별한 산출물을 받아 그것을 기록하는 별도 행위로 Y 가 된다.
- 이 값이 막는 것은 검수 승인뿐이다. 라벨 조회·프레임 이미지·영상 스트리밍·산출물 생성은 이 값으로 닫히지 않는다. 그 통로들까지 함께 닫는 것은 비식별 여부 값 가운데 비식별 누락 신고 상태이며, 이 값과는 별개의 축이다.
- 이 값의 기본값은 Y 다. 외부 산출물 이관과 무관한 기존 영상이 이 값 때문에 승인이 막히면 안 되기 때문이며, 외부에서 이미 라벨링이 끝난 산출물을 가져오는 경로로 원본이라고 지정해 들어온 영상만 N 으로 시작한다.

- **trigger**: 검수자가 승인하려는 영상의 비식별화완료여부가 N
