# 검수 완료 후 수정 통지(TASK_MODIFIED)

## priority

high

## scenario

### then

- 수정 경로(라벨·트랙 편집/병합·버전 롤백·촬영환경·프레임 설명·프레임 개인정보 메타)가 export 를 새 버전 폴더 v{n+1} 로 전량 재생성한다(이미지 2벌 포함·승인 경로와 동일 산출). 재-export 트리거는 authoring.control-notify.enabled 토글과 무관하게 항상 동작한다
- export 가 SUCCEEDED 된 뒤에 ControlNotifyClient(요청 ID 멱등·dead-letter·재등록 큐·Resilience4j)가 TASK_MODIFIED 를 push 한다 — export 가 @Async 라 통지가 앞서면 관제가 구 버전 폴더를 픽업한다
- 페이로드는 수정 요약만 포함한다 — 이벤트 타입 + 작업 ID(RAW_SN) + 마지막 수정 일시 + 변경 프레임 목록(SRC_SN + LABEL_ADDED|LABEL_UPDATED|LABEL_DELETED|META_UPDATED) + 변경 요약 카운트 + 요청 ID + ver_expln. PII·토큰·라벨/메타 본문은 포함하지 않는다
- ver_expln 은 optional 이라 null 이면 키를 생략한다 — 관제 dataset_versions.ver_expln 이 NOT NULL 이라 명시적 null 을 보내는 것보다 미전송이 안전하다(TASK_COMPLETED 의 required 키 유지와 정반대인 의도된 비대칭). 판정 단일 원천은 VersionExplanationPolicy
- 관제서버가 통지 수신 후 조회 API 로 상세를 가져가 UPSERT 한다

### when

- 변경 프레임 목록(SRC_SN+변경 종류)·요약 카운트를 구성해 통지한다

### given

- 대상 영상(RAW_SN)이 검수 완료(APPROVED) 이력을 보유한다
- 검수 완료 후 라벨/메타 수정이 발생한다

### and_examples

#### [1]

- **case**: export 재생성 실패
- **result**: 통지를 보류하고 DatasetExportFailureRecoverer 가 재산출 성공 후 발송을 재개한다(유실이 아니라 성공 시점으로 지연)

#### [2]

- **case**: 통지 전송 실패
- **result**: dead-letter/재등록 큐 적재 후 재시도

#### [3]

- **case**: 동일 트랜잭션·짧은 시간 내 다수 변경
- **result**: 디바운스 후 영상 1건 단위 1회 통지

#### [4]

- **case**: 검수 완료 영상의 비식별 누락 신고 접수
- **result**: TASK_MODIFIED(META_UPDATED) 발행 — 해소 후 export 재산출 + 재통지

## statement

검수 완료(APPROVED) 후 라벨/메타를 수정하면 그 영상은 재검수 대상이 되고, 검수자가 그 수정을 다시 승인한 시점에 export 를 새 버전으로 재생성하고 그 성공 이후에 수정 요약만 담은 TASK_MODIFIED 를 멱등 발행한다
