### 골격에 없어 그리지 않은 것

- **기간 필터·조회 버튼·새로고침** — 골격에 없다. 기간은 응답이 정한 창(30일 / 12개월)이 전부다.
- **정렬 가능한 표 헤더** — 골격 ⑥은 4열 표만 규정한다. 정렬 토글은 UI-080 `WorkerStatsTable`(SCREEN-021 전용)의 계약이라 이 화면으로 끌어오지 않았다.
- **페이지네이션** — 12행 고정이라 골격에 없다(그래서 페이저 검사 결과가 0건이다).
- **작업자별 비교·순위** — 이 화면은 대상 1명이다.

### 화면 노출 값이 골격·API 와 일관되게 맞물리는지

시안에 실은 표본값은 API-056 예시(`completed 42 · rejected 2 · labelCount 580 · rejectRate 0.045 ·
autoLabelRate 0.65 · inProgress 3`)에서 가져왔고, 아래가 **서로 맞도록** 만들었다 — 시안 안에서 숫자가
어긋나면 읽는 사람이 어느 쪽이 사양인지 판단할 수 없다.

- 월별 표 12행 합계 = 완료 **42** · 반려 **2** · 라벨 수 **580** (KPI 와 일치)
- 반려율 = 2 ÷ (42 + 2) = **4.5%** (API 정의 `REJECTED/(APPROVED+REJECTED)` 그대로)
- 일별 차트 30일 합계 **34건** ≤ 누적 완료 42건 (30일 창 밖 완료분이 있는 정상 관계)

## § 디자인 결정 (골격이 규정하지 않은 부분)

### 1. 차트를 스크립트 없이 그리기 위해 "값 단계 클래스"로 길이를 만들었다

막대 길이는 인라인 `style` 이 아니라 값 그대로의 단계 클래스(`.bar-h-0` ~ `.bar-h-4`)다. 최댓값 4건을
100% 로 두고 25% 씩 나눈다. 인라인 스타일을 쓰지 않은 이유는 두 가지다 — ① 게시 렌더가 표현 속성을
건드리는 축이 있어 시각이 CSS 밖에 있으면 안전하지 않고 ② 값이 데이터에서 오는 것임이 클래스 이름으로
드러나 구현이 매핑을 그대로 옮길 수 있다.

### 2. 축과 눈금을 직접 표기했다 — 툴팁에 의존하지 않는다

- **세로축**: 0·1·2·3·4 눈금 라벨 + 25% 간격 가로 눈금선(`repeating-linear-gradient`). 기준선(0)만 `--n-4` 로 진하게 두어 축임을 구분했다.
- **가로축**: 30개 열 중 5일 간격 6개 지점에 눈금과 날짜(`07-15 … 08-09`). **라벨을 열 하나에 중앙 정렬하면 열 폭(최소 17px)보다 넓어 이웃을 덮거나 스크롤 컨테이너에 잘린다.** 그래서 눈금 라벨은 5개 열을 묶어(`grid-column: span 5`) **좌측 정렬**하고 왼쪽 끝에 눈금 획을 붙였다 — 어느 열부터인지가 획으로 특정된다.
- **막대 값**: 30개 전부 막대 위에 숫자로 직접 표기했다. 값이 한 자리라 최소 열 폭에서도 들어간다.
- **기간 전체**는 차트 위에 `2026-07-15 ~ 2026-08-13` 로 적었다. 가로축 눈금이 5일 간격이라 마지막 날짜가 눈금에 없기 때문이다.

### 3. 0건인 날과 "데이터가 없는 날"을 눈으로 구분시켰다

값이 0이면 막대 높이가 0이라 아무 표시도 남지 않는다. 그러면 **그날 완료가 0건인 것**과 **그날 자체가
집계에 없는 것**이 화면에서 같아진다. 그래서 0건인 날은 기준선 위 2px 표식(`--n-5`)과 숫자 `0` 을 남겼다.
데이터 자체가 0건일 때는 참고 패널 ③처럼 **막대가 하나도 없고 축만 남는다** — 두 상태가 다르게 보인다.

### 4. 차트는 좁은 폭에서 열을 솎지 않고 좌우로 접는다

일자를 솎아내면 "최근 30일 추이"가 다른 화면이 된다(골격 ⑤의 대상은 30일 전부다). 그래서
`.chart-plotwrap` 을 가로 스크롤로 두고 최소 폭 `620px` 을 유지했으며, **세로축 눈금은 스크롤 밖 고정
칸**에 두어 스크롤 중에도 값 기준이 사라지지 않게 했다. 768px 까지는 스크롤 없이 딱 들어가고(계산상
`768 − 48(화면 패딩) − 48(카드 패딩) − 44(축) − 8(간격) = 620`), 그 아래에서만 스크롤이 생긴다.
767px 이하에서는 축 칸을 32px, 차트 높이를 152px 로 줄여 세로 점유를 낮췄다.

### 5. 비율 2종에 게이지 막대를 붙였다

`65.0%` 와 `4.5%` 는 숫자만으로는 서로의 크기가 즉시 읽히지 않는다. 값 아래 8px 트랙을 두어 비율을
길이로도 보이게 했다. 게이지는 값의 중복 표현이라 스크린리더에는 `role="img"` + `aria-label` 하나로만
노출한다.

### 6. 반려율 임계 초과는 색 + 아이콘 + 한글 문구 세 겹으로 알린다

골격 ④는 "반려율 10% 초과 시 빨간색 강조"만 규정한다. DS do_rule 이 **"색만으로 상태를 구분하지
않는다"** 를 강제하므로 강조 상태에 경고 아이콘과 '주의' 배지를 함께 뒀다(참고 패널 ② 가운데). 색은
`--e-6`(값) / `--e-5`(게이지) / `--e-0`+`--e-7`(배지)로 전부 error 스케일 안에서 움직인다.

### 7. 조회 대상 작업자명(WorkerNameSub)을 렌더하기로 했다

골격 note 는 "select 가 이름을 이미 보여주므로 생략하는 구현도 있다"고 적는다. **렌더하는 쪽을
택했다** — 이 화면은 스크롤이 길고(차트·12행 표) 아래로 내려가면 선택 상자가 시야에서 사라지는데,
그 상태에서 지표가 누구 것인지 화면 어디에도 남지 않는다. 제목 아래 secondary 칩 한 줄로 두어 제목과
한 덩어리로 읽히게 했다. 생략하는 구현도 골격상 유효하다.

### 8. 역할 분기와 미선택 상태는 본문이 아니라 참고 패널에 뒀다

본문 기본 렌더는 **검수자가 작업자를 고른 상태**다. 이 화면에서 데이터가 가장 많이 보이는 상태이고,
검수자 전용인 선택 상자까지 함께 그릴 수 있는 유일한 상태이기 때문이다. 동시에 성립하지 않는 두 상태
— 작업자(WORKER) 시점(제목 '나의 통계', 선택 상자 없음)과 검수자 미선택(섹션 ② EmptyState) — 는
참고 패널 ①에 나란히 뒀다. 골격이 "미선택 안내가 아래 KPI/보조지표/차트/표 **전체를 대체한다**"고
규정하므로 본문에 함께 그리면 거짓 화면이 된다.

### 9. 반려 열의 `0` 도 빨간색으로 뒀다 (골격 문면 그대로)

골격 ⑥은 "반려 컬럼은 빨간색"이다. 반려가 0건인 달까지 빨갛게 두면 문제없는 달이 경고처럼 보인다는
판단이 있었으나, **골격이 진실원이므로 문면대로 전부 적용**하고 이 우려만 § 5에 남긴다.

### 10. 표에 세로 정렬 규칙을 부여했다

월은 좌측 + mono(자릿수 정렬), 완료·반려·라벨 수는 우측 + `tabular-nums`. 숫자를 좌측 정렬하면 자릿수가
다른 값끼리 크기 비교가 안 된다. 숫자 포맷은 골격의 "ko-KR locale 포맷" 규정대로 천단위 구분을 쓴다
(표본값이 세 자리 이하라 화면에는 구분 기호가 드러나지 않는다).

| DS do_rule 44×44 | 미달 **0건** |

조작 요소는 4건(빵부스러기 링크 3 + select 1)뿐이다. 이 화면에는 버튼이 없어 `.btn-sm`(36px) 예외를
쓸 자리도 없었다. 빵부스러기 링크는 기준본과 같은 방식(min-height 44 + 음수 margin 되당김)으로
시각 높이를 유지한 채 클릭 영역만 넓혔다.

### 그 밖

- 차트는 `role="img"` 로 묶지 않고 **`<ol>` 목록**으로 두고 항목마다 `sr-only` 로 `7월 15일 1건` 을 실었다. 축·값 라벨은 `aria-hidden` 이라 중복 낭독이 없고, 차트 앞 `sr-only` 문단이 합계·최댓값을 먼저 알린다.
- 표에는 `caption`(sr-only)으로 열 구성과 정렬 순서를 적었다. ⚠️ `scope` 는 게시본에서 삭제되므로 의미를 거기에 걸지 않았다.
- 색만으로 정보를 전달하는 자리가 없다 — 반려율 강조는 아이콘+문구, 상태 배지는 점+한글 라벨, 차트는 단일 계열이라 색 구분 자체가 없다.
- 스켈레톤 애니메이션은 `prefers-reduced-motion: reduce` 에서 멈춘다.
- ⚠️ 스크린리더 실주행·탭 순서는 측정하지 않았다.

1. **최댓값(4건) 막대의 값 라벨이 잘려 보이지 않았다.** `.chart-plotwrap` 이 `overflow-x: auto` 라 **세로축도 함께 `auto` 로 계산되어**(한 축이 visible 이 아니면 나머지 축의 visible 은 auto 가 된다) 플롯 위로 나간 라벨이 잘렸다. 패딩을 그리드 전체가 아니라 **스크롤 컨테이너 안쪽**으로 옮기고, 세로축 칸은 같은 값만큼 `margin-top` 으로 내려 눈금선 높이를 맞췄다.
2. **표 셀 색상 3종이 적용되지 않았다.** `.cell-reject`(빨강)·`.cell-month`·`.cell-empty` 가 `.data-table tbody td`(명시도 0,1,2)에 밀려 무시되고 있었다 — 즉 **골격이 규정한 "반려 열은 빨간색"이 렌더에서 빠져 있었다.** 선택자를 `.data-table tbody td.cell-*` 로 올려 해소했다. 정적 검사(대비·잘림·넘침)는 전부 통과 상태였고 **렌더 육안 확인에서만 드러났다.**

| surface | 파일 | 크기 | 비고 |

- ITEM `static_renders` 의 surface 는 `main`(page) **1종뿐**이라 오버레이 surface 파일은 만들지 않았다.
  이 화면의 골격에는 모달·드로어 컴포넌트가 없다.
- **웹폰트 소스 미정** — `@font-face` 를 두지 않았다. `Pretendard GOV` → `Apple SD Gothic Neo` /
  `Noto Sans KR` 시스템 한글 산세리프 폴백만 선언했고, mono 는 `D2Coding` → 시스템 mono 다.
  폰트 파일 경로가 정해지면 `--font-body` 선언 위에 `@font-face` 를 추가하면 된다.
- **게시 렌더 보정**: 게시본이 `stroke-width` 속성을 지우므로 CSS 에 `svg { stroke-width: 2 }`
  (+ `.icon-lg` 예외 1.5)를 선언했다. HTML 속성도 그대로 남겨 로컬 원본이 자기완결이 되게 했다 —
  presentation attribute 는 CSS 보다 우선순위가 낮고 값이 같아 충돌하지 않는다.
  `scope`·`tabindex`·`maxlength`·`inputmode`·`accept`·`multiple`·빈 속성에는 시각·의미를 걸지 않았고,
  `selected` 는 빈 속성으로 쓰지 않고 `selected="selected"` 로 적었다.

### 게시본이 지우는 것 (이 화면 실측)

| 삭제 대상 | 이 화면 건수 | 성격 |

## § 미해결 · 정보 부족

1. **「검수 완료 주 수치 + 전체 병기」 두 축이 이 화면 골격에 없다 — 임의로 만들지 않았다.**
   프로젝트 규칙은 통계의 주 수치를 검수 완료 기준으로 하고 전체를 병기하도록 하지만, SCREEN-020 의
   골격과 API-056 응답에는 **작업자 배정분의 상태별 건수**(완료=APPROVED / 진행중 / 반려)만 있고
   "전체"에 해당하는 별도 필드가 없다. 완료 KPI 는 이미 검수 승인 기준이므로 축이 뭉개진 것은 아니지만,
   병기할 전체 수치의 **정의와 조달처를 확인하지 못해** 화면에 넣지 않았다. 필요하다면 골격 ③에 항목을
   추가하고 API 에 필드를 늘리는 것이 먼저다.
2. **`autoLabelRate` 의 분모가 명시돼 있지 않다.** API-056 은 "자동 라벨 비율 (0.0~1.0, 분모 0 → 0.0)"
   이라고만 적는다. 그래서 반려율 카드에는 산식(`반려 2건 ÷ 완료·반려 합계 44건` — API 정의 그대로)을
   적었지만 오토라벨 카드에는 산식을 적지 않고 설명 문구만 뒀다. 분모가 확정되면 같은 형식으로 맞춘다.
3. **반려 열의 `0` 을 빨갛게 두는 것이 맞는지.** 골격 문면대로 적용했으나(§ 2-9), 반려가 없는 달까지
   경고색으로 보인다. 0만 중립색으로 낮추려면 골격 ⑥ 문면을 먼저 고쳐야 한다.
4. **KPI 단위 표기는 시안의 결정이다.** 완료·진행중·반려는 '건', 총 라벨 수는 '개'로 뒀다.
   골격·API 에 단위 규정이 없어 화면 관례(SCREEN-011 의 건/장)를 따랐다.
5. **작업자 선택 목록의 정렬·페이징 미확인.** 골격 note 는 `useUsers role=WORKER size=100` 만 적는다.
   100명을 넘길 때의 동작(검색·더 보기)이 규정돼 있지 않아 시안은 단순 목록으로 뒀다.
6. **차트 세로축 눈금 수를 4단으로 고정했다.** 표본 최댓값이 4건이라 0~4 로 그렸을 뿐이고, 실제로는
   최댓값에 따라 눈금 간격이 정해져야 한다. **그 규칙(올림 단위·최대 눈금 수)이 골격에 없다** — 값 단계
   클래스(`.bar-h-*`)도 그래서 5단만 만들어 뒀다. 구현 시 규칙을 정하고 클래스를 그에 맞게 늘려야 한다.
7. **차트 막대의 개별 값 안내(호버 툴팁) 유무 미정.** 이 시안은 값을 전부 직접 표기해 툴팁 없이도
   읽히게 했으나, 툴팁을 함께 둘지는 골격에 없다.
8. 스크린리더 실주행·키보드 탭 순서는 측정하지 않았다.
