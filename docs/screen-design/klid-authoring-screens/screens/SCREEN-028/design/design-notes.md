- **페이지네이션** — API-115 는 `page`/`size`/`sort` 를 받고 섹션 설명도 페이징을 언급하지만, **골격

## § 디자인 결정 (와이어프레임·골격이 규정하지 않은 부분)

### 1. 빵부스러기를 두지 않고 hero 밴드가 page-head 를 겸한다

와이어프레임에는 `SCREEN-028 / 포털 홈 화면` 빵부스러기가 그려져 있지만 그건 와이어프레임 생성기가
모든 화면에 붙이는 골격 표기다. **실제 화면에서는 두지 않는다** — 포털 채널 셸(SHELL-002)은 좌측 주
메뉴가 없고(`sidenav.enabled=false`) `/portal` 은 채널의 최상위라 위로 올라갈 자리가 없다. 한 칸짜리
빵부스러기는 위치 정보를 더하지 않고 줄만 하나 늘린다. **최상위 화면이라 「뒤로가기」 버튼도 두지 않는다.**

대신 hero 섹션이 제목 + 설명을 담아 셸 안 내부 화면의 `page-head` 역할을 그대로 한다. 그래서 이
화면에는 제목이 하나뿐이며, hero 아래에 페이지 제목을 다시 두지 않았다.

### 2. hero 는 단색 neutral 밴드 — 페이지보다 한 단 진하게

골격 description 이 "단색 neutral 배경 hero (그라데이션·brand 대면적 금지)" 를 명시한다. 페이지 배경이
이미 `--n-0` 이라 hero 를 같은 값으로 두면 밴드가 사라지므로 **한 단 진한 `--n-1`** 을 쓰고 아래를
`--border` 로 맺었다. 흰색은 neutral 스케일 밖이라 쓰지 않았고, primary 계열 면 채우기는 DS
`dont_rules` 가 금지한다.

제목은 ladder 의 **display-lg(37px/800)** 를 썼다 — "랜딩·안내 페이지 대제목" 이라는 그 step 의 용도가
포털 진입 화면과 정확히 맞는다. 767px 이하에서는 **display-sm(26px/700)** 으로 한 단 내린다. 사다리 밖
크기를 새로 만들지 않고 step 만 바꾼 것이다.

### 3. '라벨링 완료 0건' 에 왜 항상 0인지를 적었다

골격 note 는 "현재 0 고정 — 집계 연동은 후속" 이다. 그런데 화면에 0만 떠 있으면 포털 이용자는 **자기가
한 작업이 반영되지 않았다**고 읽는다. 그래서 값 아래에 "집계 연동 전이라 0으로 표시됩니다." 를 캡션으로
붙였다. 값 자체는 색이 아니라 `--n-6` 으로 눌러 다른 지표와 무게를 갈랐다(색 단독 구분이 아니라 캡션
문장이 정보를 전달한다).

### 4. 이용 방법 카드는 면을 칠하지 않고 좌측 선으로 세웠다

이 화면의 주행동이라 다른 카드와 구분돼야 하는데, brand 색으로 면을 채우는 것은 DS `dont_rules` 위반이다.
`border-left: 4px --p-5` 로 위계만 세우고 면은 흰색을 유지했다. 강조는 면적이 아니라 위계로 만든다는
`color_usage.primary.avoid_for` 의 지침 그대로다.

`시작하기 ▶` 의 `▶` 는 문자가 아니라 SVG 삼각형으로 그렸다 — 글꼴에 따라 모양·굵기가 들쭉날쭉해지는
기호 문자를 UI 요소로 쓰지 않기 위해서다. `aria-hidden` 이라 스크린리더는 "시작하기" 만 읽는다.

### 5. 영상 카드는 세로 스택이 아니라 좌·우 배치로 폈다

골격이 2열 그리드를 규정하는데, LNB 가 없는 포털은 1440px 에서 카드 한 장이 660px 이 넘는다. 제목·이벤트·
건수를 세로로 쌓으면 오른쪽이 통째로 빈다. 그래서 **좌측(제목 + 이벤트 배지) / 우측(프레임 건수 + 진입
화살표)** 으로 나눴고, 479px 이하에서만 세로로 접는다. 화살표는 이 카드가 다른 화면으로 넘어간다는
신호이며, 카드 전체가 `<a>` 라 어디를 눌러도 진입한다.

### 6. 이벤트명이 없는 영상은 '-' 를 값 자리에 그대로 둔다

골격이 "이벤트명(없으면 '-')" 이라고 규정한다. 배지를 빈 채로 남기면 값이 없는 것인지 로딩 중인지
구분되지 않으므로, 배지 대신 `이벤트명 -` 을 회색 텍스트로 두고 스크린리더에는 "이벤트명 없음" 으로
읽히게 했다(`sr-only`). 값이 있는 카드와 줄 위치가 같아 목록을 세로로 훑을 때 어긋나지 않는다.

### 7. 이벤트 배지 색은 한 톤(secondary)으로만 그렸다

이벤트 유형별 색 매핑은 **UI-016 EventTypeBadge 가 소유**하며 이 화면이 정하는 것이 아니다. 시안에서
유형마다 색을 임의로 배정하면 카탈로그와 어긋난 두 번째 매핑표가 생기므로, 색은 "상태가 아니라 보조
표시" 라는 UI-016 설명대로 기본 톤(`--s-0`/`--s-7`) 하나로 그렸다. 실제 구현은 컴포넌트의 매핑을 따른다.

### 8. 영상 0건일 때 목록과 '시작하기' 가 함께 잠기는 것을 한 자리에 묶었다

두 상태는 **같은 값(`totalVideos`)에서 나오므로 따로 일어나지 않는다.** 참고 패널 ②에 빈 목록 문구 +
0건 칩 + 잠긴 버튼을 함께 그려 그 사실을 보이게 했고, 골격 note 의 `aria-disabled` 선택 이유(네이티브
`disabled` 는 Tab 순서에서 빠진다)를 안내 배너로 적었다.

### 9. 로딩은 텍스트 + 골격형 카드 2장으로 보였다

골격 description 은 "로딩 중 안내 텍스트" 만 규정한다. 텍스트만 두면 목록 자리가 통째로 비어 레이아웃이
튀므로, 안내 문장(`role="status"`)에 카드 형태의 스켈레톤을 곁들여 들어올 내용의 모양을 미리 잡았다.

  **골격(SCREEN-028) 축에서 먼저 정해야 하며**, 두기로 하면 확정 관례(40×40 / font 14px)로 그린다.

  운영 데이터의 제목 길이·표기가 이 형태인지 확인하지 못했다. 길면 카드에서 줄바꿈된다.
- **이벤트명 표시값** — 응답 예시는 영문 코드(`INTRUSION`)를 담고 있는데 화면에는 UI-016 이 해석한 한글
  라벨이 떠야 한다. 해석 주체(서버/컴포넌트)가 어디인지 이 키트만으로는 확정하지 못해 시안은 한글
  라벨을 가정했다.
- **'라벨링 완료' 집계 연동 시점** — 골격이 "후속" 이라고만 한다. 연동되면 캡션 문장을 걷어내야 한다.

### 게시본이 지우는 것 (이 화면 실측)

파일을 따라야 한다.
