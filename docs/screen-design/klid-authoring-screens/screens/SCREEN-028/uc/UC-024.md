# 포털 라벨 작업 (조회·수정·다운로드)

## goal

데이터마트 영상을 대상으로 기존 라벨과 메타·이벤트 어노테이션을 확인·수정·추가하고 사용자별 작업 데이터로 저장·다운로드한다

## frequency

## main_flow

### [1]

- **step**: 1
- **actor**: 포털 회원(PORTAL_USER)
- **action**: Host(포털) 화면의 데이터마트 영상 목록에서 대상을 고르고, Host 가 건네는 진입 링크로 저작도구 포털 작업 화면에 들어온다(새로쓰기). 저작도구는 이 목록을 그리지 않는다 — 이어쓰기 진입은 대안 흐름에 둔다.

### [2]

- **step**: 2
- **actor**: 시스템
- **action**: 기존 저장 라벨과 촬영환경·프레임 설명·개인정보 판정·시계열 메타, 이벤트 어노테이션을 Load 하여 포털 작업 화면에 표시한다. 다섯 축의 저장 모양은 셋으로 갈린다 — 시계열 메타는 메타 원장의 키와 값, 이벤트 어노테이션은 구조체, 촬영환경·프레임 설명·개인정보 판정은 원장의 컬럼이다. 컬럼 축 셋의 값은 수동 저장값이 있으면 그 값이고 없으면 자동 계산한 값(프리필)인 유효값이라, 값이 있다고 해서 사람이 고른 값이라는 뜻이 아니다. Load 는 원본 값과 함께 그 값의 출처를 알려 준다 — 사람이 직접 고른 값인지, 저장값이 없어 자동 계산된 값인지, 출처 구분이 없는 축의 저장값인지, 원본에 값 자체가 없는지. 그 출처는 화면에 표시하지 않고, 화면이 사람이 손대지 않은 자동 계산값을 저장 요청에 담지 않기 위한 전송 판정에만 쓴다. 본인이 덮었는가는 그와 다른 축이며 둘은 다른 것을 말한다 — 가림 표시는 화면에 보이고 출처는 보이지 않는다.

### [3]

- **step**: 3
- **actor**: 포털 회원(PORTAL_USER)
- **action**: 라벨을 확인·수정하고 저장한다 — LS_PORTAL_USER_LABEL에 사용자별 적재(원본·마트 미수정)

### [4]

- **step**: 4
- **actor**: 포털 회원(PORTAL_USER)
- **action**: 표시된 촬영환경·프레임 설명·개인정보 판정·시계열 메타와 이벤트 어노테이션을 확인하고, 필요하면 수정하거나 새로 추가한다. 원소를 가리킬 때는 축과 메타 키를 쌍으로 쓴다 — 개인정보 세 항목이 영상 축과 프레임 축 양쪽에 같은 이름으로 있어, 메타 키만으로 다루면 영상 값과 프레임 값이 섞인다.

### [5]

- **step**: 5
- **actor**: 시스템
- **action**: 수정·추가된 메타와 이벤트 어노테이션을 포털 전용 저장소에 사용자별로 적재한다 — 데이터마트와 원본 동결본은 수정하지 않는다(단방향, 마트 반영 안됨). 자동 계산된 값은 사람의 판정으로 승격되지 않는다 — 사용자가 직접 고치지 않은 항목이 그대로 되돌아와도 받은 값이 원본의 현재 유효값과 같으면 저장하지 않는다. 화면 규율에만 기대지 않고 서버가 독립으로 막는다.

### [6]

- **step**: 6
- **actor**: 포털 회원(PORTAL_USER)
- **action**: 「내 저장 작업 목록」에서 본인 작업 데이터를 내려받는다. 목록의 각 행은 만료 예정일을 함께 보여주며, 사용자는 그 날짜를 보고 내려받을 시점을 정한다. 보존기간 이내에만 내려받을 수 있고, 지나면 저장 행과 파일이 함께 삭제된다. 기산점은 그 사용자의 저작 최초 저장 시점이다 — 자산을 받은 시점도 화면에 진입한 시점도 기산점이 아니다. 보존일수와 삭제 규칙 자체는 포털 작업 데이터 보존기간 만료 자동 삭제 기능(DFEAT-055)이 소유하며 이 흐름은 그것을 가리키기만 한다. 저장 행이 삭제된 뒤 다시 작업을 시작하면 그때의 저작 최초 저장 시점이 새 기산점이 된다.

### [7]

- **step**: 7
- **actor**: 시스템
- **action**: 본인 저장 작업 목록의 모집단과 만료 삭제는 세 저작물 축이다 — 저장 라벨, 메타 오버레이, 이벤트 어노테이션 오버레이. 목록에는 세 저작물 중 어느 하나라도 보유한 (사용자, 영상)이 실리므로 라벨은 만들지 않고 메타만 고친 영상도 실린다. 보존기간이 지나면 셋이 함께 삭제되며, 6단계가 말하는 기산점인 저작 최초 저장 시점은 세 저작물을 통틀어 가장 이른 저장 시각이다.

## description

포털은 데이터마트 영상 선택 전용 채널(ADR-013 — 오토라벨링(YOLO), 사용자가 직접 호출하는 추론(SAM2 인터랙티브 분할·자동추적·키포인트), 외부 시계열 분석 서버로 나가는 위탁 연동(호출·콜백), 버전관리·검수 미제공). 관제서버→데이터마트→포털 DB 적재(관제 책임). 이 화면이 Load 하는 프레임·라벨은 저작도구 DB 의 검수 승인(APPROVED) 자산(LS_DATA_RAW·LS_DATA_SRC·LS_DATA_LBL)이며 포털 DB 를 읽지 않는다. ⚠ **[단일 배포 전제 — 재정합 대상]** 「저작도구 DB 의 검수 승인 자산을 Load 한다」는 저작도구가 **한 벌로 배포되던 전제**다. 2026-08-31 확정(ADR-012)으로 저작도구는 **채널별로 별도 배포**되고 각 배포본이 **자기 별도 DB 에만** 연결하므로 **포털 채널 배포본에는 관제 채널 배포본의 승인 자산이 없다.** 대체 조달은 **관제가 비식별 산출물을 포털로 전달 → 포털이 포털 채널 배포본에 알림 → 그 배포본이 배포물을 자기 DB 에 적재해 서빙**하는 방향이다. ✅ **조회 창구가 확정됐다 (2026-09-03 포털 회신)** — 구 표기 「조회 창구가 포털 회신 대기로 미확정이며 확정 전까지 이 서술을 새 설계의 근거로 쓰지 말 것」은 이 회신으로 **해소**됐다. 소재(파일) 조회 창구는 **[포털]API-132** 이며, 그 응답이 알려주는 **NAS 절대경로**로 배포물을 읽는다. 한 건의 소재는 **배포 묶음 파일 한 건과 영상 0건 이상**으로 이루어진다. ⚠ **그 창구의 응답 규격은 포털이 소유하므로 여기에 옮겨 적지 않는다** — 조달처만 가리키고 필드 구성은 [포털]API-132 를 정본으로 본다(복제하면 두 번째 진실원이 되어 한쪽만 낡는다). ⚠ **「포털 DB 를 읽지 않는다」는 그대로 유효**하다 — 우리가 읽는 것은 **NAS 파일**이지 포털 DB 가 아니며, 상호 미접근 확정으로 오히려 강화된다. ⚠ [폐기] 「포털 DB 는 반대 방향으로, 저작도구가 동결 영상 메타를 아웃박스 기반 단방향 복제로 써 넣는 대상이다」는 폐기됐다 — 2026-08-31 「저작도구와 포털은 서로의 DB 에 접근하지 않는다」 확정(구속)으로 그 복제가 폐기되고 데이터 교환은 API 로 설계한다(2026-08-31 코드도 철거됐다 — 판단 정본은 INT-009). 「포털 DB 를 읽지 않는다」는 그대로 유효하다. 저장 시 원본·데이터마트를 수정하지 않고 사용자별 작업 데이터로 LS_PORTAL_USER_LABEL 에 별도 적재한다(단방향, 마트 반영 안됨). 다운로드는 사용자 작업 데이터 기준·본인 데이터 기간 내. 반응형 웹(PC/태블릿/모바일), WCAG 2.1 AA. JWT 는 포털 서버 발급이며 동일 검증 로직(channel 클레임 분기)을 쓴다.

★ 진입은 두 갈래다. 새로쓰기는 Host(포털)가 자기 화면에 그리는 데이터마트 영상 목록에서 대상을 고른 뒤 진입 링크로 저작도구 포털 작업 화면에 들어오고, 이어쓰기는 저작도구 진입 화면의 「내 저장 작업 목록」에서 들어와 이어서 작업하러 들어갈 수 있는 대상 프레임을 연다 — 마지막으로 저장한 라벨의 프레임이 있으면 그것이고, 없으면 첫 프레임이며, 프레임 자체가 없거나 진입이 허용되지 않으면 그 자리가 비어 이어쓰기로 들어갈 수 없다. 그 자리는 본인 저작 작업 목록 조회(API-225) 응답이 알려 주며 화면이 추측하지 않는다. Host 가 소유하는 것은 그 목록 화면과 진입 링크 둘뿐이고, 화면·세션 생성·소재 적재·저장·작업 목록·내려받기는 모두 저작도구가 소유한다. [폐기] 저작도구가 데이터마트 영상 목록을 조회해 그리는 단계는 두지 않는다 — 그 목록의 소유가 Host 로 이전되면서 조회 창구(API-115)도 함께 폐기됐다. 보존기간 만료 예정일 고지는 그 창구가 지고 있던 책임이라 본인 저작 작업 목록 조회가 이어받는다. 내려받기의 출발 지점도 「내 저장 작업 목록」이며, 사용자는 각 행이 함께 보여주는 만료 예정일을 보고 내려받을 시점을 정한다 — 보존기간이 지나면 저장 행과 파일이 함께 삭제되어 복구되지 않는다.

미제공의 축은 외부 시계열 분석 서버로 나가는 위탁 연동이며, 그 결과물인 시계열 메타를 화면에 표시하고 사람이 수정·추가하는 것은 미제공 대상이 아니다. 데이터마트에서 로드한 영상의 촬영환경·프레임 설명·개인정보 판정·시계열 메타와 이벤트 어노테이션을 포털 작업 화면에 표시하며, 포털 회원이 직접 확인·수정·추가할 수 있다. 고친 값은 라벨과 같은 축으로 포털 전용 저장소에만 적재하고 데이터마트와 원본 동결본을 수정하지 않는다(단방향). 포털 업로드 영상 경로(UC-027)는 별개 축이며 본 UC 는 데이터마트 로드 경로만 다룬다.

[폐기] SAM2 분할·추적(sam2-segment·sam2-track)을 포털에 예외적으로 노출한다 — 그 예외는 철회됐고 포털 전용 SAM2 경로는 두지 않는다. 사용자가 직접 호출하는 추론 엔드포인트(SAM2 인터랙티브 분할·자동추적·키포인트)는 포털 채널에 열지 않으며, FE 도 채널 분기를 두지 않는다. ADR-013 의 예외는 포털 자산 업로드(UC-027)이며 SAM2 예외는 없다.

⚠ 본 UC 는 R1 기능 요구사항 대응이 없어 R2 유스케이스명세서 문서 범위에서는 제외되나, ITEM 자체는 유효한 활성 유스케이스다(SCREEN-028·SCREEN-029 가 이를 실현한다).

## alternate_flows

### 타인 작업 데이터 접근

**steps**:

- 사용자별 격리 — 403 거부
- 타인의 메타 오버레이 조회·수정도 같은 사용자별 격리로 거부된다 — 축마다 다르게 대할 근거가 없으므로 응답은 저장 라벨 축과 같은 403 이다
- 타인의 이벤트 어노테이션 오버레이 조회·수정도 같은 사용자별 격리로 같은 403 으로 거부된다
- 남의 것을 물었을 때와 아예 없는 것을 물었을 때의 응답이 구분되지 않는다 — 「없다」와 「있지만 네 것이 아니다」가 갈리면 그 구분 자체가 남의 저작물이 있는지 알아내는 탐색 수단이 된다
- 실재 여부 비노출은 세 저작물 축 모두에 적용된다 — 화면의 오류 안내 문구도 두 상태를 서로 다르게 가르지 않는다. 가르면 서버가 감춘 것이 화면 층에서 풀린다

- **trigger**: 다른 사용자의 작업 데이터 조회/다운로드 시도

### 이어쓰기 진입 — 내 저장 작업 목록

**steps**:

- 저작도구가 본인 저작 작업 목록(API-225)을 조회해 영상 단위 행과 이어서 작업하러 들어갈 수 있는 대상 프레임·만료 예정일을 함께 내려준다
- 화면은 그 응답이 알려 준 대상 프레임을 연다 — 여는 자리를 화면이 추측하지 않는다
- 이후는 주 흐름 2단계부터 동일하다
- 그 목록의 모집단은 세 저작물 축이라, 라벨을 만들지 않고 메타나 이벤트 어노테이션만 고친 영상도 이어쓰기 대상으로 실린다
- 그 목록의 모집단은 두 출처 축이다 — 본인이 올린 업로드 자산은 내 자산이므로 전부 실리고, 데이터마트 영상은 세 저작물 중 어느 하나라도 보유한 것만 실린다
- 데이터마트에서 영상을 고르는 목록은 포털이 자기 화면에서 제공하며, 거기서 고른 영상은 라벨링 화면으로 바로 들어간다 — 저작도구 홈은 이어서 할 작업 자리다
- 출처에 따라 이어서 작업하러 들어가는 자리가 갈린다 — 그 자리 역시 목록 응답이 알려 주므로 화면이 출처를 보고 추측하지 않는다
- 내려받을 수 있는 것도 출처에 따라 갈린다 — 본인 저작물이 없는 행에는 내려받을 것이 없다
- 만료 규칙도 출처에 따라 갈린다 — 데이터마트 행은 데이터마트 채널 규칙을 따르고, 업로드 행은 업로드 채널 규칙을 따른다. 업로드 행에 만료가 없는 것이 아니라 업로드 자산에는 자기 보존 규칙이 있다
- 화면이 여는 자리는 네 갈래로 정해진다 — 마지막으로 저장한 라벨의 프레임을 열고, 그런 라벨이 없으면 첫 프레임을 열며, 프레임 자체가 없으면 열 자리가 없고, 검수 승인 상태를 잃어 진입이 허용되지 않는 데이터마트 영상도 열 자리가 없다
- 그 자리 값을 저장 이력이 있는지 판정하는 데 쓰지 않는다 — 저작물이 하나도 없는 업로드 행에도 첫 프레임이 실리므로, 값이 있다는 것을 저장 이력으로 읽으면 정반대 판정이 된다
- 목록의 기본 정렬은 마지막 저장 시각 내림차순이되, 아직 아무 저작물도 없어 그 값이 없는 업로드 행은 자산이 생긴 시각으로 자리를 정한다
- 값이 없는 것으로 보아 끝으로 밀면 방금 올린 자산이 마지막 쪽으로 가라앉아, 업로드 자산은 작업 여부와 무관하게 전부 실린다는 규칙이 사실상 무력해진다
- 목록이 보여주는 저장 시각은 값이 없으면 비어 있다 — 자리를 정하려고 쓴 값을 표시값으로 채우지 않는다. 표시 값과 정렬 값이 다른 것이 의도이며 한쪽으로 통일하지 않는다
- 그 자리가 비어 있는 행이 곧 이어서 작업할 수 없는 행이다 — 그 행은 목록에 그대로 남고 내려받기와 만료 예정일도 그대로 보이며, 이어서 작업만 미리 막힌다
- 그 자리가 비는 사유는 둘이지만(열 프레임이 없음·진입이 허용되지 않음) 한 값으로만 말하므로 화면이 두 사유를 가르지 못한다 — 인지·수용한 대가이며 공통 문구를 쓴다

- **trigger**: 포털 회원이 저작도구 진입 화면의 「내 저장 작업 목록」에서 이어서 작업하기를 고른다

### 고치지 않은 값이 그대로 되돌아옴

**steps**:

- 받은 값이 원본의 현재 유효값과 같으면 저장하지 않는다 — 자동 계산된 값이 사람의 판정으로 승격되지 않는다
- 화면 규율에만 기대지 않고 서버가 독립으로 판정한다
- 축과 메타 키 쌍으로 원소를 식별해 판정하므로 영상 축 값과 프레임 축 값이 섞이지 않는다

- **trigger**: 사용자가 직접 고치지 않은 항목이 저장 요청에 그대로 실려 온다

### 비식별 누락 신고가 열린 영상

**steps**:

- 메타 조회·메타 저장·이벤트 어노테이션 저장이 모두 거부된다 — 라벨과 같은 채널 규칙이다
- 거부 응답의 코드는 창구가 소유하므로 이 흐름에 적지 않는다
- 포털 사용자가 직접 올린 업로드 자산은 이 거부 대상이 아니다 — 내부 파이프라인의 비식별 라이프사이클이 없다

- **trigger**: 대상 영상에 비식별 누락 신고가 열려 있는 상태에서 메타를 조회하거나 메타·이벤트 어노테이션을 저장하려 한다

### 무변경 저장 — 내 작업물이 만들어지지 않는다

**steps**:

- 오버레이 행을 만들지 않고, 이미 있으면 지운다
- 판정 단위는 두 축이 다르다 — 메타는 항목마다 따로 판정하고, 이벤트 어노테이션은 구조체 한 벌을 통째로 판정한다
- 그래서 그 영상은 본인 저작 작업 목록에 등재되지 않고 보존기간도 기산되지 않는다 — 열어 보기만 하고 아무것도 고치지 않았는데 목록에 오르거나 기산점이 서는 것은 틀린 동작이기 때문이다
- 인지·수용한 대가 — 사용자가 원본과 똑같은 내용을 일부러 확정해도 저장했다는 흔적이 남지 않는다

- **trigger**: 받은 값이 원본의 현재 값과 같아 실제로 고친 것이 없다

### 이어서 작업할 수 없는 행

**steps**:

- 그 행을 목록에서 빼지 않는다 — 빼면 삭제 대상인 작업물이 화면에서 사라져 사용자가 자기 작업물이 없어지는 것을 볼 수조차 없다
- 이어서 작업만 누를 수 없는 상태로 두고, 왜 못 누르는지 평이한 문구로 함께 보여 준다
- 내려받기는 함께 막지 않는다 — 진입 가부와 내려받기 가부는 다른 축이며, 내려받기 가부는 본인 저작물 보유 여부로만 정한다. 라벨 건수는 그 판정 축이 아니다 — 라벨 없이 메타나 이벤트 어노테이션만 고친 행에도 내려받을 저작 저장물이 있다
- 그 행의 만료 예정일도 그대로 보인다 — 그것이 그 행을 목록에 남기는 이유다
- 화면이 미리 막는 것은 서버의 진입 가드를 대신하지 않는다 — 가드를 걷어내면 주소를 직접 쳐서 들어갈 수 있다

- **trigger**: 목록의 어떤 행이 이어서 작업하러 들어갈 수 없는 상태다 — 업로드 자산이 마킹·추출 전이라 열 프레임이 하나도 없거나, 데이터마트 영상이 검수 승인 상태를 잃어 진입이 거부된다
