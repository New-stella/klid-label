# UC-024 포털 작업 데이터 격리 — 타인 작업 데이터 조회/다운로드 403 (negative)

## notes

## scenario

### then

- 사용자별 격리로 403 거부된다
- 타인의 메타 오버레이 조회·수정도 사용자별 격리로 거부된다 — 응답은 저장 라벨 축과 같다
- 타인의 이벤트 어노테이션 오버레이 조회·수정도 사용자별 격리로 거부된다 — 응답은 저장 라벨 축과 같다
- 남의 것을 물었을 때와 아예 없는 것을 물었을 때의 응답이 구분되지 않는다 — 실재 여부가 드러나면 그 구분이 남의 저작물을 찾아내는 탐색 수단이 된다
- 실재 여부 비노출은 세 저작물 축 모두에 적용된다
- 타인의 메타 오버레이와 이벤트 어노테이션 오버레이의 내려받기도 조회·수정과 같은 사용자별 격리로 거부되며 응답도 저장 라벨 축과 같다
- 세 저작물 각각의 조회·저장·내려받기 경로가 모두 같은 격리 키로 갈린다 — 한 경로라도 그 키로 갈리지 않으면 이 기준은 충족되지 않는다
- 격리 키는 인계 토큰의 주체다 — 요청 바디나 질의 파라미터로 사용자가 주장한 신원을 격리 키로 삼지 않는다

### when

- 타인 작업 데이터를 조회하거나 다운로드한다
- 타인의 메타 오버레이를 조회하거나 수정한다
- 타인의 이벤트 어노테이션 오버레이를 조회하거나 수정한다
- 아예 존재하지 않는 작업 데이터를 조회해 타인 것을 물었을 때의 응답과 견준다
- 타인의 메타 오버레이와 이벤트 어노테이션 오버레이를 각각 내려받으려 한다

### given

- 다른 포털 사용자의 작업 데이터가 있다
- 그 사용자에게는 저장 라벨뿐 아니라 메타 오버레이와 이벤트 어노테이션 오버레이도 있다
- 그 사용자의 세 저작물에는 각각 조회·저장·내려받기 경로가 있다

## statement

다른 사용자의 작업 데이터를 조회/다운로드하려 하면 사용자별 격리로 403 거부한다. 격리 대상은 포털 사용자의 저작물 셋 전부다 — 저장 라벨, 촬영환경·프레임 설명·개인정보 판정·시계열 메타를 담는 포털 전용 메타 오버레이, 이벤트 어노테이션 오버레이. 따라서 타인의 메타 오버레이와 타인의 이벤트 어노테이션 오버레이도 조회·수정이 같은 사용자별 격리로 거부되며, 축마다 다르게 대할 근거가 없으므로 응답도 저장 라벨 축과 같다. 아울러 남의 것을 물었을 때와 아예 없는 것을 물었을 때의 응답이 서로 구분되지 않아야 한다 — 「없다」와 「있지만 네 것이 아니다」가 갈리면 그 구분 자체가 남의 저작물이 있는지 알아내는 탐색 수단이 된다. 이 비구분 성질도 세 저작물 축 모두에 적용된다. 격리 키는 인계 토큰의 주체이며, 사용자가 요청 바디나 질의 파라미터로 주장한 신원을 격리 키로 삼지 않는다. 세 저작물 각각의 조회·저장·내려받기 경로가 모두 그 키로 갈려야 한다.
