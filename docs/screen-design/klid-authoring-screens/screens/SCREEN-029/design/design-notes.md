## § 메타 탭 신설 — 다섯 축을 노출한다 (2026-09-02 사용자 확정)

종전 시안에는 메타를 담는 자리가 **하나도 없었다.** 화면 골격도 시계열 메타를 AI 보조(분할·추적·
오토라벨)와 한 묶음에 넣어 **미노출**로 적고 있었는데, 승인된 `UC-024` step2·4·5 와 `AC-1068` 은
**촬영환경 · 프레임 설명 · 개인정보 판정 · 시계열 메타 · 이벤트 어노테이션** 다섯 축의 표시·수정·추가·
포털 전용 적재를 요구한다. **범주 오류였다** — 미제공의 축은 외부 시계열 분석 서버로 나가는
위탁 연동(호출·콜백)이고, 그 결과물을 화면에 보이고 사람이 고치는 것은 그 축이 아니다.

### 새로 디자인하지 않았다 — 내부 라벨링 화면의 어휘를 따랐다

내부 화면이 같은 문제를 이미 **탭**으로 풀고 있었다. 그래서 우측 패널을 **'객체 / 메타' 2탭**으로
가르고(포털에는 이슈 탭이 없다) 메타 탭 안에 **내부와 같은 순서**로 세로 나열했다 —
촬영환경 → 영상축 개인정보 → 프레임 설명 → 프레임축 개인정보 → 시계열 메타 → 이벤트 어노테이션.

> ⚠ **처음에는 독립 side 패널로 붙였다가 되돌렸다.** 캔버스 옆에 고정 패널이 둘 서면 작도 폭을
> 뺏는다. 사양(`SCREEN-029`)도 탭 구조로 함께 고쳤다.

### 판단

| 무엇 | 왜 |
|---|---|
| **축 칩(영상/프레임)을 패널마다 단다** | 개인정보 패널이 **이름이 같은 채로 둘** 선다. 축을 빼면 같은 것이 두 번 나온 것으로 읽힌다. 두 값이 달라도 모순이 아니다 — 영상 어딘가엔 있지만 이 프레임엔 없을 수 있다 |
| **출처 칩은 객체 목록 것을 그대로 쓴다** | 무엇이 원본이고 무엇이 내 손을 탄 것인지 가르는 축이 라벨과 같다. 새 어휘를 만들지 않았다 |
| **고칠 수 없는 값에 입력 모양을 주지 않는다** | 읽기 전용 메타와 영상 기술 메타가 그렇다. 입력처럼 보이면 눌러 보고 나서야 못 고치는 걸 알게 된다 |
| **빈 칸을 지어내지 않는다** | 사람이 확정할 자리(답변·근거)는 값을 채우지 않고 비어 있다고 알린다. 채우면 이미 정해진 값으로 읽힌다 |
| **프리필을 두지 않는다** | 내부 화면은 자동 생성값을 1회 프리필하지만 포털에는 **그 원천이 없다** — 외부 시계열 분석 위탁 연동이 이 채널에 없어서다 |
| **참고 패널에서도 실제 폭(304px)으로 그렸다** | 전폭으로 펴면 메타 격자가 여러 열로 보여 사실과 달라진다. 실제로는 1열로 접힌다. 남는 폭에는 이 탭을 읽는 규칙을 적었다 |

### 저장 방향 — 라벨과 같은 단방향

저장은 **포털 전용 오버레이에만** 쌓인다(`LS_PORTAL_USER_META` · `LS_PORTAL_USER_EVNT_ANNO`).

## § 디자인 시스템 전환 — DS-001(관제 축) → DS-002(외부 채널 축)

이 화면은 **포털 채널에만 선다.** 연동 사양이 *"포털 채널은 그 채널의 디자인 시스템을 전면
채택한다 — 주색만이 아니라 형태·타이포·간격·그림자·컨트롤 높이까지 그대로 따른다"* 를 못박고
있으므로, 관제 축으로 그릴 자리가 아니었다. 바뀐 축은 아래 여덟이다.

| 축 | 관제 축(DS-001) | 외부 채널 축(DS-002) |
|---|---|---|
| 주색 | `#256ef4` | **코발트 `#2e45dc`** · hover `#2336b8` |
| 중립 | KRDS gray (`#6d7882` 계열) | **slate 쿨톤** (`#64748b` 계열) |
| 본문 기준 | 17px | **15px** |
| 굵기 상한 | 800 | **600** — 위계는 크기와 색으로 만든다 |
| 모서리 | 4 / 6 / 8 | 태그 6 · 입력·페이저 8 · 타일 12 · 표면 16 · 패널 24 · **명령(버튼)은 캡슐** |
| 그림자 | 카드에 항상 sm | **기본 없음** — 평면이 출발점, 띄우는 것이 예외 |
| 표 헤더 | 굵기로 죽임 | **색으로 죽임**(14/500 + slate-500) — 굵기를 색보다 먼저 올리지 않는다 |
| 자간 | 0 | **-0.5px**(본문에 한 번, 사다리 각 칸에 되풀이하지 않는다) |

**토큰 이름은 그대로 두고 값만 바꿨다.** `--n-*`·`--p-*`·`--sp-*` 는 스케일 위치를 가리키는
이름이라 값만 갈아끼우면 되고, 그 편이 수백 곳의 사용처를 건드리는 것보다 안전하다.
⚠ **`--radius-*` 만은 이름이 가리키는 역할이 바뀌었다** — `sm`=6(사각 태그) · `md`=8(입력·페이저
셀) · `lg`=16(표면)이고, 이 사다리에만 있는 12·24 는 `--radius-tile`·`--radius-panel` 로 더했다.

**모양은 실측으로 확정했다.** 버튼이 캡슐인 것과 페이저 셀이 8인 것은 원칙 문장만으로 갈리지
않아, 그 채널이 실제로 쓰는 스타일시트에서 2차 층이 버튼 라운드를 `max` 로, 굵기 상한을 600 으로,
본문 자간을 -0.5px 로 덮는 선언을 직접 확인했다.

> ⚠ **두 축은 토큰 이름이 같고 값이 다르다.** 특히 그 채널의 원본 디자인시스템 기본 주색은
> **관제 축과 같은 `#256ef4`** 인데 그 위에 브랜드 코발트를 덮어쓴다. **이름으로 같은 색이라고
> 판단하면 조용히 다른 색이 뜬다.**

> ⚠ **DS-002 는 상대 정의의 사본이다.** 값을 우리 쪽에서 고치면 두 번째 진실원이 된다.

### 이 시스템을 그대로 따르지 않은 자리 — 컨트롤 경계

이 시스템은 입력 보더를 slate-300 으로 둔다. 그런데 그 값은 **흰 면 위 1.47:1** 이라
WCAG 1.4.11(3:1)에 미달한다. **경계가 유일한 식별 수단인 컨트롤**에서는 slate-500(4.76:1)로
올렸고(`--border-strong`), 그 근거를 토큰 선언 옆에 남겼다.

## § 디자인 결정 (골격이 규정하지 않은 부분)

### 1. 「× 닫기」와 「뒤로가기」를 하나로 합쳤다

골격 ①은 `× 닫기`(dirty>0 시 저장확인 모달, 아니면 이전 화면)를 두고, 배치 확정 관례는 작업 화면에
`뒤로가기`(투명 배경·경계 있는 텍스트 버튼, 44px)를 두라고 한다. **둘은 같은 동작**이다.
아이콘 ×와 텍스트 버튼을 나란히 두면 같은 행위의 진입점이 둘이 되어, 골격이 다른 자리에서
반복해 못 박은 원칙(*"같은 동작의 진입점을 둘로 두지 않는다"*)과 충돌한다.

그래서 헤더 바 맨 왼쪽 — 골격이 `× 닫기` 를 두라고 한 바로 그 자리 — 에 `뒤로가기` 를 한 개만 뒀다.
아이콘은 ×가 아니라 왼쪽 화살표로 바꿨다. 이 화면은 오버레이가 아니라 셸 안의 한 페이지라
"닫는다"보다 "이전 화면으로 돌아간다"가 실제로 일어나는 일이다.

### 2. ★ "저장해도 원본은 안 바뀐다"를 세 겹으로 알린다 — 이 시안의 핵심 결정

포털 저장은 **단방향**이다. 데이터마트 원본을 고치지 않고 사용자별 작업 데이터로만 쌓이며,
그 결과가 데이터마트로 되돌아가지도 않는다. 그런데 화면은 여느 라벨링 화면과 똑같이 생겼기 때문에
**"내가 고쳤으니 원본이 바뀌었겠지"** 가 자연스러운 오해다. 배너 한 줄로 끝내면 스크롤 위로 밀려
사라지므로, 사용자가 그 사실을 알아야 하는 **세 순간에 각각** 배치했다.

| 순간 | 자리 | 문구 |
|---|---|---|
| 화면에 들어올 때 | 상단 info 배너 | 저장해도 원본 데이터는 바뀌지 않습니다 — 내 작업 데이터로만 따로 쌓입니다 |
| 저장을 누르기 직전 | 저장 버튼 바로 옆 상시 캡션 | 저장하면 내 작업 데이터에만 쌓이고 데이터마트 원본은 그대로입니다 |
| 저장할지 말지 결정할 때 | 닫기 확인 모달 각주 | 저장해도 데이터마트 원본은 바뀌지 않습니다 |

헤더 우측의 `내 작업 데이터에만 저장` 배지는 이 세 겹의 상시 요약이다.

### 3. 객체마다 「원본 / 수정 / 추가」 출처를 표시한다

포털 라벨 목록은 **데이터마트 원본 + 본인 작업분을 병합**한 결과다. 둘이 섞여 보이면
"어디까지가 원래 있던 것이고 어디부터가 내가 만든 것인지" 알 수 없고, 저장이 무엇을 남기는지도
흐려진다. 그래서 행마다 칩을 붙이고 목록 상단에 범례 + `저장 대상은 수정·추가한 것입니다.` 를 뒀다.

- `원본` — 불러온 그대로 (neutral)
- `수정` — 내가 고친 것 (warn)
- `추가` — 내가 새로 그린 것 (primary)

내부 라벨링 화면(SCREEN-005)의 `수동 / 자동(AI) / 보간` 출처 마크와 **다른 축**이다. 포털에는
AI 생성물이 없고, 대신 "원본이냐 내 것이냐"가 유일하게 의미 있는 구분이다.

### 4. 프레임 썸네일에 「내 작업 데이터를 저장해 둔 프레임」을 표시한다

포털 사용자는 한 영상에서 여러 프레임을 오간다. 어느 프레임에 이미 내 작업본이 있는지 모르면
같은 프레임을 다시 그리거나, 저장했다고 착각하고 지나친다. 초록 테두리 + 체크 마크로 알리고,
색만으로 구분하지 않도록 마크와 함께 캡션(`초록 테두리는 내 작업 데이터를 저장해 둔 프레임입니다.`)을
붙였다. SCREEN-005 의 `문의 있음`·`폐기됨` 상태는 포털에 없어 쓰지 않았다.

### 5. 비활성 버튼에는 사유를 글자로 붙였다

`다시실행` 은 스택이 비면 비활성인데, 흐려진 버튼만 보면 왜 눌리지 않는지 알 수 없다.
`되돌린 작업이 없습니다` 캡션을 옆에 두고 `aria-describedby` 로 이었다(DS dont_rule — 색만으로
상태를 구분하지 않는다). 확대·축소도 상·하한에 닿으면 같은 방식으로 처리한다.

### 6. 프레임 이미지 자리는 배치 확정 관례(참고 영역 규격)로 그렸다

실제 이미지가 없는 시안이므로 프레임 자리를 `n-0` 면 + 4면 `2px dashed n-4` 로 뒀다. 다크 매트는
DS 가 인정한 유일한 다크 표면 예외라 그대로 유지하고, 그 위에 자리 표시 상자를 얹는 구성이다.
자리 표시 문구는 도형이 몰리는 화면 가운데를 피해 **좌상단 반투명 칩**에 담았다 — 가운데 두면
바운딩박스에 가려 읽히지 않는다.

### 7. 상태 화면 4종을 참고 패널에 남겼다

골격 ⑧이 규정한 3종(로딩 / 조회 실패 / 잘못된 프레임 번호)에 **객체 0건 빈 상태**를 더했다.
빈 상태는 골격에 없지만, 로딩 중과 "정말 아무것도 없음"이 같은 화면으로 보이면 사용자가 기다린다.
앞의 3종은 작업 영역 자리를 통째로 대신하고, 빈 상태는 우측 객체 목록 안에서만 바뀐다 —
그 차이를 패널 캡션에 적었다.

### 8. 반응형 — 좁은 폭에서 캔버스를 맨 위로 올린다

포털은 외부 이용자가 개인 기기로 들어오므로 320px 까지 지원한다. 열을 접는 순서는 다음과 같다.

| 폭 | 배치 |
|---|---|
| ≥1280 | `도구(192) · 라벨(176) · 캔버스 · 객체(304)` 4열 |
| 1024–1279 | `도구/라벨` 을 한 열로 쌓고 `캔버스 · 객체` 3열 |
| 768–1023 | `도구/라벨 · 캔버스` 2열 + 객체 패널을 아래 전폭으로 |
| <768 | 1열 — **캔버스 → 도구 → 라벨 → 객체** 순. 도구·라벨은 `auto-fit` 격자로 가로 배치 |
| <360 | 도구·라벨을 1열로 되돌리고 여백을 `sp-xs`~`sp-sm` 으로 좁힌다 |

글자 크기는 어느 폭에서도 낮추지 않았다(DS iteration_guide — *"좁으면 크기를 낮추지 말고 열 수를 줄인다"*).

## § 게시 렌더 대비

`svg { stroke-width: 2 }` 를 CSS 에 선언하고 `.alert-icon`(1.8) · `.icon-lg`(1.6) 는 개별 선택자로 예외를 뒀다.
게시 렌더 sanitizer 가 HTML 의 `stroke-width` **속성을 삭제**하기 때문이다. HTML 속성은 그대로 남겨
로컬 원본이 자기완결이 되게 했다(presentation attribute 는 CSS 보다 우선순위가 낮아 충돌하지 않는다).

같은 이유로 `scope` · `inputmode` · `tabindex` · `maxlength` 에 시각·의미를 기대지 않았다 —
이 시안은 그 넷을 **한 번도 쓰지 않는다**. 아이콘 전용 버튼의 이름은 `aria-label`(보존됨)로,
비활성 사유는 `aria-describedby` + 화면에 보이는 캡션으로 전달한다.

### 게시본이 지우는 것 (이 화면 실측)

| 삭제 대상 | 이 화면 건수 | 성격 |
|---|---|---|
| `stroke-width` | 42 | **시각** — 없어지면 SVG 기본값 1 로 그려져 아이콘이 얇아진다. CSS 로 되살렸다 |
| `stroke-linecap` | 31 | **시각** — 없어지면 획 끝이 잘린 모양(butt)이 된다. CSS 로 되살렸다 |
| `stroke-linejoin` | 34 | **시각** — 없어지면 모서리가 뾰족해진다(miter). CSS 로 되살렸다 |
| HTML 주석 | 20 | 내용 아님 — 무해 |

**보존되는 것**: `role`·`aria-*`·`class`·`id`·`for`·`type`·`value`·`placeholder`·`stroke`·`fill`, 그리고 **CSS 원문 전체**.

⚠ 시각에 영향을 주는 획 관련 속성은 같은 값을 **CSS 로도 선언**해 게시본에서 되살렸다. 나머지는
CSS 로 대체할 수 없는 정보라 게시본에서 복원되지 않는다 — **로컬 원본이 진실원**이며 구현은 로컬
파일을 따라야 한다.

## § 미해결 · 확인 필요

- **`데이터마트 영상 #3187 · 12번째 프레임` 보조 문구의 출처 미확인** — 골격 ①은 `프레임 #srcSn` 만
  규정한다. 포털 사용자가 어느 영상의 몇 번째 프레임인지 알아야 프레임 띠와 대응이 되므로 넣었으나,
  포털 라벨 조회 응답(API-110)에 영상 식별자와 프레임 순번이 함께 오는지 확인하지 못했다.
  없으면 문구를 빼거나 응답에 추가해야 한다.
- **`원본 / 수정 / 추가` 판정 근거 미확인** — 병합 응답이 각 라벨의 출처(데이터마트 원본인지 본인
  작업분인지)를 구분해 내려주는지 확인하지 못했다. 구분값이 없으면 「디자인 결정 3」이 성립하지 않는다.
- **프레임 썸네일의 「내 작업본 있음」 표시 근거 미확인** — 형제 프레임 정보에 본인 작업 데이터 유무가
  실려 오는지 확인하지 못했다. 없으면 별도 조회가 필요하거나 이 표시를 뺀다.
- **라벨 단축키 번호의 상한 미정** — 시안은 1~5 로 그렸다. 사용 중인 라벨이 10종을 넘을 때
  번호를 어디까지 매길지 골격에 규정이 없다.
- **회전 중 도구 잠금의 시각 표현 미작성** — 골격은 *"회전 중에는 그리기 도구를 잠근다"* 라고만 하고,
  시안은 그 사실을 캡션으로만 알린다. 잠긴 상태의 도구 버튼 표현(비활성 + 사유)은 별도 상태 시안이 필요하다.
- 스크린리더 읽기 순서·탭 순서 미측정.
