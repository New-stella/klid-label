### 골격에 없어 그리지 않은 것

- **뒤로가기 버튼** — 골격에 없다. 상위로 가는 길은 빵부스러기가 맡는다(확정 관례상 뒤로가기는 둘 때만 규격이 정해져 있고, 없는 조작을 새로 만들지 않는다).

## § 디자인 결정 (골격이 규정하지 않은 부분)

### 1. 「생성 결과」축과 「사람의 결정」축을 시각적으로 갈랐다

골격이 두 축을 분리하라고 못박는다 — 생성이 성공했다는 사실과 검수자가 그걸 쓰기로 했다는 사실은 별개다.
그래서 **머리말의 잡 상태 배지(완료/처리 중/실패)** 와 **항목마다의 결정 카드(결정 대기/채택됨/반려됨/취소됨)** 를
서로 다른 층·다른 모양으로 뒀다. 결정 카드는 왼쪽 4px 강조선으로 상태를 알리고(대기 primary · 채택 success ·
반려 error · 취소 neutral), 잡 상태는 pill 배지 하나로만 둔다. 같은 배지 모양을 두 축에 쓰면
"완료" 와 "채택됨" 이 한 덩어리로 읽힌다.

또 결정 카드 본문에 **"어느 쪽도 원본 영상과 이미 만들어진 파생 영상 자체를 바꾸지 않습니다"** 를 적었다.
이 문장이 없으면 채택·반려가 영상을 만들거나 지우는 조작으로 오해된다.

### 2. 같은 (영상 × 종류) 재요청을 탭 이름과 생성 조건 두 곳에서 구분되게 했다

골격상 같은 조합이 여러 건 있을 수 있고, 그 둘을 가르는 유일한 단서는 **요청할 때 보낸 생성 조건**이다.
그래서 ① 탭 이름을 `겨울 #1 · 채택` / `겨울 #2 · 결정 대기` 로 순번과 결정 상태까지 붙이고
② 각 탭 맨 위에 생성 조건 5필드를 **접지 않고 항상 펼쳐** 뒀다. 조건을 접어 두면 두 탭이 같은 화면으로 보인다.
겨울 #1 은 `낮·눈·약함`, 겨울 #2 는 `해질 무렵·폭설·강함` 으로 값을 서로 다르게 그려 그 차이가 눈에 들어오게 했다.
종류당 항목이 1건인 그룹(`우천`, `해상도 720p`)은 골격 규칙대로 종류명만 남겼다.

### 3. 프레임 쌍 축과 결과 항목 축 페이저를 다른 자리·다른 이름으로 뒀다

두 페이저는 규격이 같아 나란히 두면 어느 쪽이 무엇을 넘기는지 알 수 없다. 프레임 쌍 페이저는
**각 탭 안 그리드 바로 밑**에, 항목 페이저는 **모든 영상 그룹이 끝난 카드 맨 아래 구분선 위**에 두고
"항목 페이지를 넘기면 프레임 쌍은 첫 페이지로 돌아갑니다" 라는 문장을 붙였다. 골격이 규정한 리셋 동작을
사용자가 겪기 전에 알 수 있게 하려는 것이다.

### 4. 증강 이미지 생성률의 '무엇을 센 값인가' 를 지표 옆에 붙였다

이름이 품질 지표처럼 읽히기 쉬워 골격이 명칭을 못박은 항목이다. 그래서 수치 옆에
**"라벨을 검사한 값이 아닙니다 — 이미지가 만들어졌는지만 셉니다"** 와 모수(이 페이지 42쌍 중 40쌍),
그리고 등급 구간(95/85)을 함께 적었다. 등급은 색만 쓰지 않고 `우수` 라는 낱말 배지를 같이 뒀다.

### 5. 썸네일 자리와 '만들지 못한 자리' 를 갈랐다

빈 썸네일은 확정 관례대로 **점선 상자**(n-0 배경 + 4면 2px dashed n-4)로 뒀다 — 점선은 "그림이 들어올 자리" 라는 뜻이다.
반대로 증강 이미지가 **만들어지지 않은 칸**은 점선을 실선으로 바꾸고 error 톤으로 채워 사유(`생성 실패`)를 적었다.
거기는 자리가 아니라 결과이기 때문이다. 칸 아래에는 경고 아이콘을 더해 색만으로 구분하지 않게 했다.

### 6. 해상도 파생 탭에 '왜 결정 카드가 없는지' 를 적었다

골격은 해상도 파생에 결정 카드를 노출하지 않는다고만 규정한다. 그런데 다른 탭에는 있고 이 탭에만 없으면
사용자는 화면이 덜 그려진 것으로 본다. 그래서 결정 카드 자리에 중립 배너로
**"저작도구가 직접 만든 내부 결과물이라 사람이 쓸지 말지를 정하지 않습니다"** 를 두고,
같은 배너에 파생 영상 보기 링크를 남겨 동선이 끊기지 않게 했다.

### 7. 반려는 사유 없이 확정되지 않게 보이고, 취소는 사유 없이도 되게 보였다

골격상 반려 사유는 필수, 취소 사유는 선택이다. 두 대화상자를 같은 뼈대로 그리되
반려는 **확인 버튼을 비활성 상태로 그려** 사유가 있어야 눌린다는 사실을 열자마자 보이게 했고,
취소는 활성 상태에 도움말로 "적지 않아도 취소할 수 있습니다" 를 달았다.
비활성 버튼은 흐리게 하지 않고 채도를 뺀 면(`--n-2` 위 `--n-7`)으로 처리했다 — 흐리면 글자 대비가 함께 무너진다.

### 8. 취소의 되돌릴 수 없음과 부분 취소를 확인 전에 알린다

골격이 요구한 두 사실(되돌릴 수 없음 · 여러 건으로 나뉘어 위탁되어 일부만 취소될 수 있음)을 확인 대화상자
맨 위 경고 배너에 적었고, 결과 알림에서도 "정상 결과이므로 다시 시도하지 않아도 됩니다" 를 명시했다.
부분 취소를 실패로 오해해 재시도를 반복하는 것을 막기 위한 문장이다.

### 9. 반려 이후 폐기 생명주기를 4값 표로 폈다

골격은 폐기 일시·실삭제 예정 일시·실삭제 여부·복구 가능 여부 4가지를 요구한다. 문장으로 풀면 길어져
warn 배너 안에 4칸 키-값으로 폈다. **이미 지워진 항목은 복구 버튼을 아예 그리지 않는다**(참고 ③ 변형 ②) —
복구 가능 여부는 서버 값을 그대로 쓰고, 눌러도 반드시 실패하는 버튼은 만들지 않는다는 골격 규칙 그대로다.

### 10. 상태 코드 원문을 화면에 쓰지 않았다

`PROCESSING`·`COMPLETED`·`FAILED`·`WINTER`·`NIGHT`·`RAIN`·`RESOLUTION`·`PENDING`·`ACCEPTED`·`REJECTED` 는
모두 한글 표현으로 바꿔 적었다(처리 중·완료·실패·겨울·야간·우천·해상도·결정 대기·채택됨·반려됨).
`480p`·`720p` 는 데이터 값이자 외부 표준 표기라 그대로 뒀다.

## § 접근성 검증 (WCAG 2.1 AA)

- **텍스트 대비 전수 측정 — 1440px 405건 / 360px 405건, 미달 0건.**
  사람이 고른 조합만 잰 것이 아니라 렌더 트리의 모든 텍스트를 computed color × 유효 배경으로 기계 측정했다.
- 회색·유색 표면 위 보조 텍스트는 전부 neutral 60단 이상(do_rule 준수). `--n-5` 를 글자색으로 쓴 자리는 없다.
- **색만으로 상태를 구분하지 않는다** — 결정 상태는 배지 낱말, 생성 실패 칸은 경고 아이콘, 지표 등급은 `우수` 낱말을 함께 둔다.
- **비활성 버튼을 흐림(opacity)이 아니라 채도를 뺀 면으로 처리** — `--n-2` 면 위 `--n-7` 글자 = 5.98:1.
- **빵부스러기 링크 hit area 44×44 확보**(시각 크기 불변 · `min-*` + 음수 margin).
- 진행률 바에 `role="img"` + 백분율을 담은 `aria-label` 을 붙여 보조기술이 수치를 읽게 했다.
- 대화상자는 `role="dialog"` + `aria-modal` + `aria-labelledby`, 사유 입력은 `label[for]` + `aria-describedby` 연결.

## § 미해결 · 확인 필요

1. **빵부스러기 현재 위치 라벨을 골격 문구대로 쓰지 않았다.** 골격 컴포넌트 라벨은 `데이터 증강 / 잡 #{jobId}`
   인데, 같은 골격의 purpose 가 **"jobId 는 임시값이라 이동·식별에 쓰지 않고 원본 영상 번호를 쓴다"** 고
   못박는다. 두 서술이 어긋나 있어, 화면에 임시값을 노출하지 않는 쪽(`증강 결과 확인 · 영상 #3187`)을 택했다.
   **골격 쪽 문구 정정이 필요한지 확인이 필요하다.**
2. **작업 요약의 '작업 ID' 가 무엇을 가리키는지** — purpose 대로라면 원본 영상 번호와 같은 값이라
   `#3187` 로 그렸다. 두 칸(작업 ID·영상 번호)이 늘 같은 값이면 한 칸으로 줄이는 편이 낫지만
   골격이 5칸을 규정하므로 그대로 뒀다.
3. **영상 그룹 부제(`종로구 교차로-07 · 2026-07-30 녹화`)의 출처 미확인** — 골격은 "영상 번호로 그룹핑" 만
   규정한다. 검수자가 어느 현장인지 알아보도록 넣었으나 결과 조회 응답에 그 값이 있는지 확인하지 못했다.
   없으면 부제를 빼거나 응답에 추가해야 한다.
4. **결정 카드의 검수자 이름 표기** — 골격은 검수자·검수일시가 동반된다고만 적는다. 이름을 그대로 보일지
   식별자만 보일지는 정해지지 않았다. 시안은 이름을 그렸다.
5. **진행 상태 조회 간격·한도의 실제 값** — 골격이 "서버가 알려 준다 / 0 이면 더 조회하지 않는다" 로만
   규정해 화면에 수치를 적지 않았다. 사용자에게 남은 대기 시간을 알려야 하는지는 정보 부족이다.
6. **부분 취소 결과 문구의 수치 출처** — `24건 중 16건` 은 예시다. 서버가 취소 성공/실패 건수를 각각
   내려주는지 확인하지 못했다.
7. 스크린리더 읽기 순서·탭 순서 미측정. 특히 영상 그룹이 여럿일 때 탭 그룹 사이 이동 순서는 확인이 필요하다.
