# 증강 영상 활용 여부 검수

## priority

high

## scenario

### then

- 판단 결과가 LS_DATA_AUG_RVW.RVW_STTS_CD 에 검수자(RVW_ID)·검수일시(RVW_DT)·반려사유(RJCT_RSN)와 함께 기록된다 — 생성 결과 축 AUG_PROC_STTS_CD(웹훅 소유: 생성 성공 ACCEPTED / 실패 REJECTED / 취소 CANCELED)는 건드리지 않는다
- 작업목록·배정 등재 게이트는 리뷰 축(RVW_STTS_CD='ACCEPTED')으로 판정한다 — 생성 결과 축으로 게이팅하면 생성 성공만으로 전부 통과해 기능이 무의미해진다
- 반려된 파생은 즉시 작업 대상에서 빠지고, 유예기간(설정값·기본 7일) 경과 후 배치가 DB 행과 생성 파일을 삭제한다(파생·반려·유예경과 3조건을 최종 DELETE SQL 자체에 박음)

### when

- GET /v1/augments 에서 결과를 조회하고(요청 시 입력한 생성 조건 PROMPT_CN 이 함께 표시된다) POST /v1/augments/{id}/accept 또는 POST /v1/augments/{id}/reject(사유 필수)를 호출한다

### given

- 증강 결과가 새 영상(파생)으로 등록되어 있고 아직 활용 여부 판단이 내려지지 않았다(리뷰 행 미결정)
- REVIEWER로 인증되어 있다

### and_examples

#### [1]

- **case**: 이미 판단이 끝난 결과에 재결정 시도
- **result**: 409 CONFLICT (리뷰 행 '재결정 금지' 불변식)

#### [2]

- **case**: 반려 사유 누락
- **result**: 400 거부

#### [3]

- **case**: 해상도 파생(AUG_TYPE_CD=RESL_*)
- **result**: 내부 생성물이라 accept/reject 차단. 리뷰 행이 영영 생기지 않으므로 등재 게이트에 통과 예외를 명시적으로 박는다(안 박으면 작업목록에서 전부 사라진다)

#### [4]

- **case**: 게이트 도입 이전 생성된 파생(NEW_RAW_SN·리뷰 행 부재)
- **result**: 그랜드퍼더링 — 신규 파생부터 게이트 적용(이미 배정된 WORKER 의 고아 배정 방지)

#### [5]

- **case**: 유예기간 내 복구(POST /v1/augments/{id}/restore)
- **result**: 폐기 표식 해제 + 리뷰 PENDING 재오픈으로 다시 채택/반려를 고를 수 있고, 되돌린 이력(누가·언제·왜)을 남긴다. 유예 경과 후 실삭제된 건은 409

#### [6]

- **case**: NEW_RAW_SN 이 NULL 인 그랜드퍼더링 증강
- **result**: 실삭제 대상에서 완전 제외(어느 파생을 지울지 알 수 없음) — 감사 로그에 '수동 정리 필요'만 남긴다

## statement

REVIEWER가 증강 결과를 확인해 사용(accept)·폐기(reject)를 결정하며, 그 판단은 생성 결과 축과 분리된 리뷰 축(LS_DATA_AUG_RVW.RVW_STTS_CD)에 기록되고 채택된 파생만 작업목록·배정에 등재된다
