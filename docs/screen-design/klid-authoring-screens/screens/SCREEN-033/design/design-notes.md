## § 디자인 시스템 전환 — DS-001(관제 축) → DS-002(외부 채널 축)

이 화면은 **포털 채널에만 선다.** 연동 사양이 *"포털 채널은 그 채널의 디자인 시스템을 전면
채택한다 — 주색만이 아니라 형태·타이포·간격·그림자·컨트롤 높이까지 그대로 따른다"* 를 못박고
있으므로, 관제 축으로 그릴 자리가 아니었다. 바뀐 축은 아래 여덟이다.

| 축 | 관제 축(DS-001) | 외부 채널 축(DS-002) |
|---|---|---|
| 주색 | `#256ef4` | **코발트 `#2e45dc`** · hover `#2336b8` |
| 중립 | KRDS gray (`#6d7882` 계열) | **slate 쿨톤** (`#64748b` 계열) |
| 본문 기준 | 17px | **15px** |
| 굵기 상한 | 800 | **600** — 위계는 크기와 색으로 만든다 |
| 모서리 | 4 / 6 / 8 | 태그 6 · 입력·페이저 8 · 타일 12 · 표면 16 · 패널 24 · **명령(버튼)은 캡슐** |
| 그림자 | 카드에 항상 sm | **기본 없음** — 평면이 출발점, 띄우는 것이 예외 |
| 표 헤더 | 굵기로 죽임 | **색으로 죽임**(14/500 + slate-500) — 굵기를 색보다 먼저 올리지 않는다 |
| 자간 | 0 | **-0.5px**(본문에 한 번, 사다리 각 칸에 되풀이하지 않는다) |

**토큰 이름은 그대로 두고 값만 바꿨다.** `--n-*`·`--p-*`·`--sp-*` 는 스케일 위치를 가리키는
이름이라 값만 갈아끼우면 되고, 그 편이 수백 곳의 사용처를 건드리는 것보다 안전하다.
⚠ **`--radius-*` 만은 이름이 가리키는 역할이 바뀌었다** — `sm`=6(사각 태그) · `md`=8(입력·페이저
셀) · `lg`=16(표면)이고, 이 사다리에만 있는 12·24 는 `--radius-tile`·`--radius-panel` 로 더했다.

**모양은 실측으로 확정했다.** 버튼이 캡슐인 것과 페이저 셀이 8인 것은 원칙 문장만으로 갈리지
않아, 그 채널이 실제로 쓰는 스타일시트에서 2차 층이 버튼 라운드를 `max` 로, 굵기 상한을 600 으로,
본문 자간을 -0.5px 로 덮는 선언을 직접 확인했다.

> ⚠ **두 축은 토큰 이름이 같고 값이 다르다.** 특히 그 채널의 원본 디자인시스템 기본 주색은
> **관제 축과 같은 `#256ef4`** 인데 그 위에 브랜드 코발트를 덮어쓴다. **이름으로 같은 색이라고
> 판단하면 조용히 다른 색이 뜬다.**

> ⚠ **DS-002 는 상대 정의의 사본이다.** 값을 우리 쪽에서 고치면 두 번째 진실원이 된다.

### 이 시스템을 그대로 따르지 않은 자리 — 컨트롤 경계

이 시스템은 입력 보더를 slate-300 으로 둔다. 그런데 그 값은 **흰 면 위 1.47:1** 이라
WCAG 1.4.11(3:1)에 미달한다. **경계가 유일한 식별 수단인 컨트롤**에서는 slate-500(4.76:1)로
올렸고(`--border-strong`), 그 근거를 토큰 선언 옆에 남겼다.

## § 폐기 — 이미지 업로드는 이 화면에 없다

**신규 이미지 접수는 닫혔다.** 메뉴 정의가 *"[폐기] 이미지 업로드는 두지 않는다(신규 접수만 닫히고
이미 접수된 이미지 자산의 조회·내려받기·삭제는 유지된다)"* 로 못박고 있고, 화면 골격도 섹션이
**영상 업로드(TUS)·업로드 자산 목록 둘뿐**이다.

시안에서 걷어낸 것 — **이미지 업로드 섹션 전체**(드롭존·다중 선택 입력·고른 파일 목록·검증 오류
배너·업로드 버튼)와 **그 상태를 보이던 참고 패널 하나**.

★ **목록의 이미지 행은 남긴다.** 폐기된 것은 *접수*이지 *보유 자산*이 아니다. 이미 올린 이미지는
조회·라벨링·삭제가 그대로이므로 목록에 이미지 행이 계속 있고, 유형 칩도 '이미지'로 뜬다.
**행이 남아 있는 것을 잔재로 오인해 지우지 말 것** — 지우면 보유 자산에 도달할 길이 사라진다.

⚠ **AI 증강 요청은 이미지 행에 두지 않는다**(골격 note 명시). 시안도 영상 4행에만 뒀다.

> ⚠ **이 시안은 이 사실을 반영하지 못한 채 한동안 서 있었다.** 디자인 시스템 전환 라운드에서
> 렌더를 보고도 못 짚었고, 사용자가 지적해 발견했다. **시안을 손볼 때는 토큰만 보지 말고 골격
> 섹션 목록과 한 번 대조할 것** — 이 저장소에서 시안은 사양보다 늦게 따라오는 쪽이다.

### 골격에 없어 그리지 않은 것

- **자동 라벨링·자동 분할·「시계열」·검수·버전 관리** — 포털 경로에는 제공되지 않는다. 상단 안내에 그 사실만 적고 조작은 두지 않았다.
- **비식별 처리 표시** — 본인 데이터라 비식별을 하지 않는다. 상태 흐름에 그 단계가 없다.
- **이미지 업로드 폼** — 폐기됐다(위 § 폐기 절). 다만 **이미 접수된 이미지 자산은 목록에 남아** 조회·라벨링·삭제가 유지되므로 목록에는 이미지 행이 그대로 있다.
- **유형 필터·검색·정렬** — 골격 목록 섹션에 필터 컴포넌트가 없다.
- **업로드 취소 조작** — 골격이 "진행 중 취소 불가 표시"를 규정한다(아래 § 관찰 1).
- **삭제 확인 대화상자** — 골격이 브라우저 기본 확인창을 쓴다고 못박는다. 브라우저가 그리는 것이라 시안 대상이 아니다(아래 § 관찰 2).

## § 디자인 결정 (골격이 규정하지 않은 부분)

### 1. "이 경로가 무엇이 아닌지" 를 맨 위에서 먼저 알린다

골격 purpose 의 절반은 **하지 않는 것**(내부 파이프라인 분리 · 자동 라벨링 없음 · 검수 없음 · 버전 관리 없음)이다.
그런데 화면 어디에도 그 사실이 드러나지 않으면, 포털 이용자는 "올려두면 알아서 라벨이 붙겠지" 로 기다리게 된다.
상단 info 배너로 ①본인만 본다 ②자동 처리가 없다 ③영상은 프레임 준비가 끝나야 라벨링할 수 있다 를 한 문단으로 묶었다.

### 2. 드롭존을 '참고 표면' 과 같은 규격으로 그렸다

확정 관례의 참고(placeholder) 표면(`n-0` 배경 + 4면 `2px dashed n-4`)은 **아직 내용이 놓이지 않은 자리**를 뜻한다.
파일을 받는 빈 자리가 정확히 그 의미라 같은 규격을 그대로 썼다. **이 규격에서 벗어난 dashed 변형(비활성 톤 등)을
만들지 않았다** — 만들면 파선 표면이 무엇을 뜻하는지가 화면마다 갈린다. 그래서 "올리는 중" 상태는 파선 드롭존을
흐리는 대신 **실선 파일 표시로 자리를 바꿨다**.

파일 입력은 숨기지 않고 **드롭존 전면에 투명하게 깔았다.** 숨김 입력 + 가짜 버튼 조합은 실제로 눌리는 영역이 버튼만
남아, 44px 규칙을 만족해도 큰 표면을 겨냥한 사용자의 클릭이 빗나간다. 지금은 눌리는 영역과 보이는 영역이 일치한다.

### 3. [폐기] 고른 파일을 누르기 전에 그대로 보여준다

⚠ **이미지 다중 선택을 전제한 결정이라 함께 폐기됐다.** 영상은 한 번에 한 편이라 고른 파일이 하나뿐이고,
그 하나는 입력 자리에 파일명·크기·상태로 그대로 보인다. 기록을 남기는 이유는 이미지 접수가 되살아날 경우
같은 판단(숫자만 보여주지 않는다)이 다시 필요하기 때문이다.

### 4. 진행률은 퍼센트만 두지 않고 보낸 용량을 병기했다

영상은 최대 5GB다. 68% 만으로는 "얼마나 더 기다려야 하나" 를 가늠할 수 없어 `2.23 GB / 3.28 GB` 를 함께 적었다.
버튼 안에도 진행률을 실어(골격 note), 스크롤로 진행률 바가 가려져도 조작 자리에서 상태를 읽을 수 있게 했다.

### 5. "멈출 수 없다" 와 "이어서 올린다" 를 한 자리에 붙였다

골격은 진행 중 취소 불가를 규정하는데, 그것만 적으면 창을 닫으면 처음부터 다시 올려야 한다는 오해가 생긴다.
재개 가능 업로드라는 성질이 바로 그 불안을 해소하므로 **자물쇠 안내 한 문장 안에 둘을 같이 적었다** —
"멈출 수 없다 / 보낸 만큼은 남는다 / 같은 파일을 다시 고르면 이어진다".

### 6. 목록 상태를 배지 하나로 끝내지 않고 '다음에 무슨 일이 일어나는지' 를 덧붙였다

`업로드됨`·`처리중` 은 이용자가 아무것도 할 수 없는 상태다. 배지만 있으면 기다려야 하는지 잘못된 것인지 알 수 없어
상태 아래 한 줄을 붙였다 — 업로드됨 "처리 차례를 기다립니다" / 처리중 "프레임을 뽑는 중입니다" /
실패 "지운 뒤 다시 올려 주세요". 실패 행에는 파일명 아래 사유도 함께 적었다.

### 7. 처리중 행은 좌측 강조선으로 알리고 행 배경을 물들이지 않았다

같은 행에 상태 배지가 있어 행 배경까지 같은 계열로 물들이면 배지가 배경에 묻혀 알약 형태를 잃는다.
기준본 SD-021(SCREEN-032)이 같은 이유로 택한 처리를 그대로 따랐다(처리중 = info 선 / 실패 = error 선).

### 8. 비활성 '삭제' 에 "왜 지금은 안 되는가" 를 붙였다

골격 note 가 처리중 행의 비활성 + 툴팁을 규정한다. 비활성 버튼 자체는 마우스 이벤트를 받지 않으므로
감싸는 요소에 툴팁을 달았고, 문구는 마크업에 실려 있어 스크린리더도 읽는다(`role="note"`).

### 9. 실패 사유를 원문 그대로 쓰지 않았다

응답의 실패 사유는 내부 예외 이름만 담는다. 그대로 노출하면 화면에 영문 구현 식별자가 실린다.
"영상을 읽지 못해 프레임을 뽑지 못했습니다" 처럼 **한글 안내로 옮겨 그렸다.** 구현 시 사유 → 문구 매핑이 필요하다.

### 10. 좁은 폭에서는 파일명을 줄이지 않고 줄바꿈해 전문을 보인다

한 줄 말줄임(`text-overflow: ellipsis`) 자체는 표준 관례이고 이 저장소의 기존 시안도 쓰는 형태라 넓은 폭에서는
그대로 뒀다. 다만 **이 화면에서 잘리는 꼬리는 확장자**다. 제외된 행의 거부 사유가 바로 "지원하지 않는 형식"이라,
320px 에서 `screen-capture.gif` 가 `screen-capt…` 로 보이면 **왜 거부됐는지 화면에서 사라진다.**

그래서 `480px` 이하에서 `.file-name` 을 `white-space: normal` + `word-break: break-all` 로 풀어 전문을 보이게 하고,
행은 `flex-wrap` 으로 크기·상태 표식을 다음 줄로 내렸다(아이콘 폭만큼 들여써 파일명과 세로로 맞춘다).
세로 공간은 남고 목록 길이도 짧아 행 높이가 늘어나는 대가가 작다.

`title` 속성으로 전체 파일명을 보완하는 방법은 **쓰지 않았다** — 이 폭은 사실상 터치 환경이라 hover 툴팁이 뜨지 않고,
게시본 sanitizer 가 지우는 속성 계열이기도 하다.

### 11. 업로드 영역은 '올리는 중' 순간으로 그렸다

고르기 전 모습은 참고 패널에 따로 뒀다 — 올리는 중에는 파일 고르는 자리가 고른 파일 표시로 바뀌기 때문이다.
⚠ 종전에는 이미지·영상 두 영역을 서로 다른 순간으로 나란히 그렸는데, **이미지 업로드가 폐기되어 그 대비가 사라졌다.**

## § 관찰 — 골격과 다른 자료 사이의 어긋남 (임의로 정하지 않고 기록만)

1. **"진행 중 취소 불가"(골격 섹션 ② 설명) ↔ 소비 API 목록에 세션 취소 엔드포인트(API-171)가 있다.**
   시안은 **골격을 따라 취소 조작을 두지 않았다.** 취소를 화면에 열지 여부는 골격 쪽 확정이 필요하다.
2. **삭제 확인은 브라우저 기본 확인창**(골격 note)이라 시안 대상이 아니다. 공통 확인 대화상자(UI-005 ConfirmDialog)로
   바꿀지는 골격 결정 사항이며, 이 시안은 화면에 그 자리를 만들지 않았다.
3. **프레임 추출 간격 수치는 골격·API 어디에도 없다.** "일정 간격" 으로만 적었다 — **정보 부족**이라 수치를 지어내지 않았다.
4. **골격 섹션명은 "영상 업로드 (TUS)"** 지만 화면 제목은 **"영상 업로드"** 로 그렸다. 재개 가능 업로드라는 성질은
   프로토콜 이름 대신 "연결이 끊겨도 이어서 올립니다" 로 적었다(화면 노출 텍스트에 영문 구현 식별자 비노출).

## § 접근성 검증 (WCAG — 동봉 `scripts/contrast_checker.py`)

- **실제로 쓴 조합 43건(중복 제거) 측정 — 그중 글자색 × 배경 25건은 본문 4.5:1 기준 전건 통과.**
  최저치가 `#fff on --p-5` 4.55:1(DS 정본 주조색의 구조적 하한)이고, 나머지 본문 텍스트는 5.62:1 이상이다.
- 나머지 18건은 아이콘·경계·채움·면 같은 **비텍스트** 조합으로 UI 3:1 기준으로 판정했다 — 통과 11건 / 미달 7건(아래 표).
- 회색 표면 위 보조 텍스트는 전부 neutral 60단 이상(do_rule 준수) — `n-0` 위 5.77:1, `#FFFBEB`(행 hover) 위 6.08:1.
- **비활성 주버튼을 흐림(opacity)이 아니라 채도를 뺀 면으로 처리**했다 — `--n-2` 면 위 `--n-7` 글자 = 5.65:1 로 AA 통과.
- 상태는 색만으로 구분하지 않는다 — 배지마다 **한글 라벨 + 점**, 실패·오류에는 아이콘까지 동반한다(do_rule).
- 진행률 채움 대 트랙 3.70:1, 페이저 경계 3.08:1, 드롭존 안 '파일 고르기' 경계 4.13:1 — UI 3:1 기준 통과.

### 게시본이 지우는 것 (이 화면 실측)

| 삭제 대상 | 이 화면 건수 | 성격 |
|---|---|---|
| `stroke-width` | 34 | **시각** — 없어지면 SVG 기본값 1 로 그려져 아이콘이 얇아진다. CSS 로 되살렸다 |
| `scope` | 7 | 표 접근성 정보 손실 — CSS 로 대체 불가 |
| `tabindex` | 1 | 키보드 도달 순서 손실 — CSS 로 대체 불가 |
| `accept` | 2 | 파일 선택 형식 제한 손실 — CSS 로 대체 불가 |
| `multiple` | 1 | 파일 여러 개 선택 허용 손실 — CSS 로 대체 불가 |
| HTML 주석 | 11 | 내용 아님 — 무해 |

**보존되는 것**: `role`·`aria-*`·`class`·`id`·`for`·`type`·`value`·`placeholder`·`stroke`·`fill`, 그리고 **CSS 원문 전체**.

⚠ 시각에 영향을 주는 획 관련 속성은 같은 값을 **CSS 로도 선언**해 게시본에서 되살렸다. 나머지는
CSS 로 대체할 수 없는 정보라 게시본에서 복원되지 않는다 — **로컬 원본이 진실원**이며 구현은 로컬
파일을 따라야 한다.
