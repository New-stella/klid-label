### 골격이 못박은 금지 사항 — 지켰다

- **② 완료율은 텍스트로만.** `role="progressbar"`·`<progress>` 요소를 쓰지 않았다. 완료율은 pill 배지 **글자**다.
- **③ 개별 카드 5개·grid-cols-5 가 아니다.** 카드 **1개** 안에 스택 바 + 범례 4항목으로 그렸고,
  '전체'는 카드가 아니라 섹션 헤더 우측 텍스트다.
- **⑤ 고정 6종이 아니다.** 서버가 내려주는 카테고리를 그대로 순회하는 구조로 그렸고 **0건 유형도 목록에 남긴다**
  (`납치(유괴) 0건 · 0%`). 개수가 달라져도 레이아웃이 성립하도록 행 단위 반복만 쓴다.

### 골격에 없어 그리지 않은 것

- **기간·유형 필터, 조회 조건 폼** — 골격에 필터 섹션이 없다. 리포트 다운로드도 기간 선택 없이 `MONTH` 고정이다.
- **드릴다운 링크(작업자 상세·영상 목록으로 이동)** — 골격에 링크가 없다.
- **추이 선그래프·전월 대비 증감(trend)** — 골격에 없는 지표라 추가하지 않았다. `KpiCard` 의 `trend` prop 도 쓰지 않았다.
- **평균·최댓값 같은 요약 지표** — 차트에서 눈으로 읽히는 값이지만 골격이 규정한 지표가 아니라 문장으로 만들지 않았다.

## § 디자인 결정 (골격이 규정하지 않은 부분)

### 1. 차트 계열색을 두 축으로 갈랐다 — semantic 은 의미가 맞는 곳에만

DS `color_usage` 는 success/warn/error 를 "의미가 맞을 때만" 쓰라고 못박는다. 그래서

- **처리현황 4구간**은 골격 note 가 지정한 대로 semantic 을 그대로 썼다(완료=success · 처리중=info · 대기=neutral · 실패=error).
  여기서는 색이 곧 의미다.
- **이벤트 유형 분포**는 의미 없는 분류라 semantic 을 쓰면 "화재=빨강이니 실패인가" 같은 오독을 만든다.
  `primary → secondary → neutral` 스케일을 훑는 **단색 램프 9단**(`--cat-1`~`--cat-9`)으로 두었다.
  새 hex 를 만들지 않고 기존 스케일 안에서만 이동했다.

두 경우 모두 **색은 보조 단서일 뿐**이다 — 라벨·건수·비율%를 항상 글자로 병기했고, 파이에는 범례를,
분포 리스트에는 라벨을 직접 붙였다. 색을 지워도 정보가 하나도 사라지지 않는다.

### 2. 값을 직접 적었다 — 툴팁으로 숨기지 않았다

recharts 판은 Tooltip(호버)으로 값을 보여주지만, 이 시안은 무 JS 이고 호버는 키보드·터치에서 닿지 않는다.
그래서 **축 눈금(0/20/40/60/80)을 왼쪽에 고정하고, x축 눈금이 붙은 날의 값을 막대 위에 직접 적었다**
(골격의 `xAxisInterval=5` 와 같은 간격 — 6일마다). 나머지 25일 값은 `sr-only` 문장으로 전부 실어
스크린리더에서는 30개 값이 모두 읽힌다.

값 글자는 막대 **안**이 아니라 **위 흰 바탕**에 얹었다. 안에 두면 주조색 면 위 어두운 글자가 되어
대비가 1.91:1 로 무너진다(실측 후 옮김).

### 3. 좁은 폭에서 차트를 뭉개지 않고 밀어 본다

30개 막대를 320px 에 우겨 넣으면 막대 하나가 3px 가 되어 아무것도 읽히지 않는다. 그래서
**y축 눈금 열은 제자리에 고정하고 그림면만 가로 스크롤**한다(`.chart-scroll` + `.chart-plot { min-width: 560px }`).
표도 같은 방식(`.table-scroll` + `min-width: 720px`)이라 화면 안에서 축소 규칙이 한 가지로 통일된다.

- 480px 이하에서는 **분포 리스트의 비율 막대를 접는다** — 그 폭에서 막대는 20px 도 못 되어 정보가 없고,
  라벨·건수·비율% 세 값은 그대로 남기 때문에 잃는 것이 없다.
- 768px 이하에서는 파이를 리스트 **위로** 올린다(2열 → 1열).

⚠ `.chart-scroll`·`.table-scroll` 의 `position: relative` 는 장식이 아니라 **필수**다. 안쪽 `.sr-only`
(`position:absolute`)의 담는 블록이 문서 최상단이 되면 스크롤 컨테이너가 잘라내지 못해 **문서 전체가
가로로 263px 늘어난다**(320px 실측 → 수정). 구현에서 이 선언을 지우면 같은 결함이 재발한다.

### 4. 스택 바에 `role="progressbar"` 를 쓰지 않았다

`progressbar` 는 `aria-valuenow` 하나만 실을 수 있어 4구간 중 3구간이 소리로 사라진다.
`role="img"` + `aria-label` 로 네 구간을 한 문장에 담고, 눈으로는 범례가 같은 값을 전달한다.

### 5. 반려율 강조에 '높음' 글자를 붙였다

골격·카탈로그는 "반려율이 10을 초과하면 강조색"이라고만 규정한다. 색만으로 상태를 구분하지 말라는
DS `dont_rules` 를 지키려면 글자가 필요하므로 **`12.6% 높음`** 처럼 라벨을 덧붙였다.
값이 없는 칸은 카탈로그가 말한 자리표시 기호 `—` 를 그대로 쓴다.

### 6. 정렬 가능한 헤더와 그렇지 않은 헤더를 눈으로 갈랐다

라벨·검수·오토라벨만 `button` 이고 작업자·진행·반려율은 일반 텍스트다. 정렬 가능한 헤더에는
현재 방향(`↓`)을, 아직 정렬 축이 아닌 헤더에는 눌러 볼 수 있다는 표시(`↕`)를 둔다.
방향은 화살표 **글자**이며 `aria-sort` 와 `sr-only` 문장을 함께 실어 색·모양에 의존하지 않는다.

### 7. 빈 상태에서도 자리 높이를 유지한다

차트가 0건일 때 영역이 접히면 값이 도착하는 순간 아래 카드가 통째로 밀려 화면이 튄다.
`.empty-box.h-chart { min-height: 200px }` 로 차트가 차지하던 높이를 그대로 둔다.
처리현황은 골격이 "4구간 합이 0이면 바를 렌더하지 않는다"고 못박았으므로 **막대·범례를 아예 그리지 않고**
안내 문구로 대신하는 모습을 참고 패널에 뒀다.

### 8. '전체 통계 조회 실패' 배너에 리포트 다운로드와의 관계를 적었다

두 기능은 API 가 다르다(API-057 조회 / API-058 다운로드). 배너만 보면 사용자는 화면 전체가 죽었다고
읽으므로 "리포트 다운로드는 통계 조회와 별개라 이 상태에서도 시도할 수 있습니다"를 덧붙였다.

## § 접근성 검증 (WCAG)

- **본문 4.5:1 / 큰글씨·UI 3:1 기준으로 190조합 측정 — 1440·360 두 폭 모두 미달 0건.**
- 회색 표면(`--n-0`) 위 보조 텍스트는 전부 neutral 60단 이상(do_rule 준수).
  표 헤더(`--s-0`) 위 정렬 화살표도 50단(4.01:1 미달)에서 **60단으로 올렸다**(실측 후 수정).
- **차트 값 글자를 주조색 막대 밖으로 옮겼다** — 막대 안에서는 1.91:1 이었다(실측 후 수정).
- 색만으로 구분하는 곳이 없다 — 처리현황·이벤트 분포·반려율 모두 글자를 동반한다.
- 비활성 주버튼(내려받는 중)은 흐림(`opacity`)이 아니라 채도를 뺀 면으로 처리했다 — `--n-2` 면 위 `--n-7` 글자 = 5.98:1.
- 빵부스러기 링크 hit area 를 44×44 로 확보(시각 크기 불변 · `min-*` + 음수 margin).
- 정렬 헤더 버튼도 44px 높이를 확보했다.

## § 미해결 · 정보 부족

- **일별 작업량의 단위·산식이 골격에 없다.** 골격은 `dailyCounts[].date/count` 만 규정하고 무엇을 세는지
  (완료 건인지, 검수완료 기준인지, 이미지인지 영상인지) 말하지 않는다. 시안은 y축에 `(건)` 만 적고
  **'검수완료 기준' 같은 수식어를 붙이지 않았다.** 확정되면 카드 헤더에 기준 표기를 한 줄 더해야 한다.
- **이벤트 유형 분포의 단위도 골격에 없다.** 검수완료 기준이라는 것만 규정돼 있어 시안은 `건` 으로 적고
  합계를 누적 영상의 검수완료 수(3,180)와 맞춰 두었다. 이미지 장 수 기준이라면 단위와 합계가 달라진다.
- **처리현황 4구간의 모집단이 영상인지 이미지인지 골격에 없다.** 시안은 '전체 4,620건'을 누적 영상 전체와
  같게 두어 화면 안에서 앞뒤가 맞게 했지만, 실제 응답이 다른 모집단이면 두 섹션의 숫자가 어긋나 보인다.
- **범례·스택 바의 구간 순서가 골격 안에서 두 가지로 적혀 있다.** 컴포넌트 목록은 `완료 · 처리중 · 실패 · 대기`
  순이고 섹션 description 은 `완료/처리중/대기/실패` 순이다. 시안은 **description 순서**를 따랐다
  (실제 배치를 서술한 쪽이 더 구체적이라고 판단). 확정 필요.
- **`categoryKey` 오름차순의 실제 코드값을 모른다.** 시안의 유형 나열 순서는 코드 오름차순을 가정한 예시이며
  실제 코드 체계에 따라 순서가 달라진다. 표시명 그룹 정책(같은 표시명끼리 접기)도 화면에서는 이미 접힌
  결과만 받는 전제로 그렸다.
- **리포트 CSV 의 파일명·열 구성은 화면 밖이다.** 골격은 "고정 prefix + ISO 날짜, 사용자 입력 미반영"까지만
  규정한다. 시안은 파일명을 노출하지 않는다.
- **웹폰트 소스 미정** — `@font-face` 없이 family 선언 + 시스템 한글 산세리프 폴백만 뒀다.
- 스크린리더 읽기 순서·탭 순서 미측정. 파이 조각의 `sr-only` 대체 텍스트도 "값은 오른쪽 목록에 있다"고만
  안내하며 조각별 수치를 중복해 읽지 않는다.
