REVIEWER가 이벤트유형별 라벨 프리셋(LS_LABEL_PRESET_CODE)을 CRUD하고 라벨 마스터(LBL_ID)와 연결한다.

## main_flow

### [1]

- **step**: 1
- **actor**: 검수자(REVIEWER)
- **action**: 프리셋 관리 화면(/manage/presets)에서 프리셋 카드 목록을 조회한다(GET = API-037, 클라이언트 측 페이지네이션 9건/페이지)

### [2]

- **step**: 2
- **actor**: 검수자(REVIEWER)
- **action**: '프리셋 추가' 버튼으로 편집 모달을 신규 모드로 연다

### [3]

- **step**: 3
- **actor**: 검수자(REVIEWER)
- **action**: 프리셋 이름(필수 1~64자)·설명(0~500자)·매핑 이벤트 타입(서버 동적 조회, 빈 값=미매핑)·라벨(활성 라벨 마스터 체크박스 멀티셀렉트, 1~20개)을 입력한다 — 형태(BBOX/POLYGON)는 마스터가 소유해 읽기 전용으로만 표시되고 프리셋별 토글은 불가능하다

### [4]

- **step**: 4
- **actor**: 시스템
- **action**: 저장 시 신규는 POST(API-038), 수정은 PUT(API-039)을 호출하며 라벨은 labelId 배열만 전송한다 — 프리셋은 라벨명·형태를 스냅샷 저장하지 않고 LBL_ID FK로 마스터를 실시간 join 하므로 마스터 변경이 신규·기존 프리셋 모두에 즉시 반영된다

### [5]

- **step**: 5
- **actor**: 시스템
- **action**: 매핑 이벤트가 이미 다른 프리셋에 매핑돼 있거나(1:1 매핑) 프리셋 이름이 중복이면 409 CONFLICT 를 반환하고 서버 메시지를 토스트로 안내한다

### [6]

- **step**: 6
- **actor**: 검수자(REVIEWER)
- **action**: 카드의 '삭제' 버튼과 확인 다이얼로그로 프리셋을 삭제한다(DELETE = API-040, 되돌릴 수 없음을 안내)

## description

REVIEWER가 이벤트유형별 라벨 프리셋(LS_LABEL_PRESET_CODE)을 카드 그리드에서 조회하고 신규/수정/삭제한다. 프리셋은 라벨명·형태를 스냅샷 저장하지 않고 LBL_ID FK 로 라벨 마스터를 실시간 join 하므로(UC-028 이 관리하는 마스터와 단일 진실원을 공유) 마스터에서 라벨명·형태·색상을 바꾸면 신규·기존 프리셋 표시에 즉시 반영된다. 형태(BBOX/POLYGON)는 마스터가 소유해 프리셋에서 개별 토글할 수 없다(구 코드 칩별 형태 체크박스는 폐기). 매핑 이벤트 타입은 1:1 매핑이며 이미 다른 프리셋에 매핑된 이벤트나 중복 이름으로 저장하면 409 를 반환한다. 마스터와 매칭되지 않는 레거시 코드는 오류로 상승시키지 않고 '미연결'로 표시하며 저장 시 자동 제외한다.
