# 라벨 프리셋 CRUD 관리

## goal

REVIEWER가 이벤트유형별 라벨 프리셋을 관리한다 — 이벤트유형 1건에 오토라벨 대상 라벨 세트를 지정하고 라벨 마스터(LBL_ID)와 연결한다.

## main_flow

### [1]

- **step**: 1
- **actor**: 검수자(REVIEWER)
- **action**: 프리셋 관리 화면(/manage/presets)에서 프리셋 카드 목록을 조회한다(GET = API-037, 클라이언트 측 페이지네이션 9건/페이지)

### [2]

- **step**: 2
- **actor**: 검수자(REVIEWER)
- **action**: '프리셋 추가' 버튼으로 편집 모달을 신규 모드로 연다

### [3]

- **step**: 3
- **actor**: 검수자(REVIEWER)
- **action**: 매핑 이벤트유형(필수 — 등록된 전체 유형에서 선택)과 라벨(활성 라벨 마스터 체크박스 멀티셀렉트, 1~20개)을 선택한다. 프리셋은 이름과 설명을 갖지 않는다 — 식별 축은 이벤트유형코드 하나다. 형태(BBOX/POLYGON)는 마스터가 소유해 읽기 전용으로만 표시되고 프리셋별 토글은 불가능하다

### [4]

- **step**: 4
- **actor**: 시스템
- **action**: 저장 시 신규는 POST(API-038), 수정은 PUT(API-039)을 호출하며 라벨은 labelId 배열만 전송한다 — 프리셋은 라벨명·형태를 스냅샷 저장하지 않고 LBL_ID FK로 마스터를 실시간 join 하므로 마스터 변경이 신규·기존 프리셋 모두에 즉시 반영된다

### [5]

- **step**: 5
- **actor**: 시스템
- **action**: 매핑 이벤트에 이미 프리셋이 있으면 409 CONFLICT 를 반환하고 어느 이벤트인지 서버 메시지를 토스트로 안내한다. 이벤트를 지정하지 않으면 400 으로 거부한다

### [6]

- **step**: 6
- **actor**: 검수자(REVIEWER)
- **action**: 카드의 '삭제' 버튼과 확인 다이얼로그로 프리셋을 삭제한다(DELETE = API-040, 되돌릴 수 없음을 안내)

## description

REVIEWER가 이벤트유형별 라벨 프리셋을 카드 그리드에서 조회하고 신규/수정/삭제한다. 프리셋은 이벤트유형 1건에 대한 오토라벨 대상 라벨 세트이며 이름·설명을 갖지 않는다 — 식별 축은 이벤트유형코드 하나이고 사람이 읽는 이름은 이벤트유형 마스터의 표시명이 제공한다. 라벨은 라벨명·형태를 스냅샷 저장하지 않고 LBL_ID FK 로 라벨 마스터를 실시간 join 하므로(UC-028 이 관리하는 마스터와 단일 진실원을 공유) 마스터에서 라벨명·형태·색상을 바꾸면 신규·기존 프리셋 표시에 즉시 반영된다. 형태(BBOX/POLYGON)는 마스터가 소유해 프리셋에서 개별 토글할 수 없다. 매핑 이벤트는 1:1 이라 이미 프리셋이 있는 이벤트로 저장하면 409 로 거부한다.

## tech_considerations

- 라벨 코드 직접 입력(Enter)·빠른 추가 10종 UI는 폐기되었다 — 라벨은 마스터 체크박스 멀티셀렉트로만 선택한다
- 프리셋은 이름과 설명을 갖지 않는다 — 식별 축은 이벤트유형코드 하나이며, 사람이 읽는 이름은 이벤트유형 마스터의 표시명을 서버가 응답에 실어 제공한다. 화면이 이벤트 목록으로 이름을 역해석하지 않는다
- 이벤트 선택 목록은 등록된 전체 유형을 쓴다 — 필터 옵션 목록은 제외 대분류를 감추므로 그것을 쓰면 해당 유형의 프리셋을 만들거나 고칠 수 없게 된다. 필터 화면은 종전대로 필터 옵션을 쓴다
- 프리셋 복제는 두지 않는다 — 이벤트유형 1건에 프리셋 1건이라 복제할 자리가 없다
