# 시스템 운영 설정 관리

## goal

REVIEWER가 시스템 설정 화면에서 배치 처리·AI 탐지 추론·라벨링 정밀도·비식별 옵션 파라미터를 조회·수정하고 외부 연동(비식별 서버·AI 추론 서버·데이터베이스) 헬스를 실시간 모니터링하며, 관리자 페이지에서 연동 서버 주소를 조회·수정하고 되돌릴 수 없는 위험 액션을 확인 절차를 거쳐 수행한다. 앞의 축은 검수자 권한만으로 되고, 뒤의 축은 검수자 권한에 관리자 단기 유효창이 가산되어야 한다.

### [2]

- **step**: 2
- **actor**: 검수자(REVIEWER)
- **action**: 배치 처리(처리 주기·동시 처리 수)/AI 탐지 추론(Confidence Threshold·IoU 임계값)/라벨링 정밀도(인식 민감도·경계 세밀함)/비식별 옵션 카드 중에서 값을 수정한다 — 카드별 독립 폼이며 값이 실제로 바뀐 카드만 저장 버튼이 활성화된다

### [3]

- **step**: 3
- **actor**: 시스템
- **action**: 저장 시 카드 안에서 실제로 바뀐 키에 한해서만 개별 PUT 요청(API-069)을 보낸다(일괄 저장 API 없음)

### [4]

- **step**: 4
- **actor**: 시스템
- **action**: 서버가 타입·범위를 검증하며 범위를 벗어나면 저장을 거부한다(필드별로 구분되지 않는 공통 실패 토스트로 안내)

### [5]

- **step**: 5
- **actor**: 검수자(REVIEWER)
- **action**: 연동 서버 주소를 바꾸거나 관리자 공유 패스워드를 교체하려면 관리자 페이지로 이동해, 진입 시 관리자 공유 패스워드를 제출해 단기 유효창을 연다(POST = API-194). 이 유효창은 어느 한 화면 전용이 아니라 관리 기능 공통 진입이다. 남은 유효 시간이 화면에 보이고 만료되면 다시 잠겨 패스워드를 다시 확인해야 한다

### [6]

- **step**: 6
- **actor**: 검수자(REVIEWER)
- **action**: 관리자 페이지의 연동 서버 주소 관리 화면에서, 유효창이 살아 있는 동안 비식별 서버·AI 추론 서버·외부 시계열 분석 벤더·관제 통지 수신처 주소를 재입력 없이 수정해 저장한다(PUT = API-069, 관리자 세션 토큰을 X-Admin-Session 헤더에 싣는다). 시스템 설정 화면에 남은 배치 처리·AI 탐지 추론·라벨링 정밀도·비식별 옵션 카드는 유효창 없이 검수자 권한만으로 저장된다. 유효창이 유효한지 판정하는 일은 단일 지점이 소유하며, 이 저장 창구는 요구가 설정 키 단위로 갈려 표식을 쓰지 않고 그 판정 지점을 직접 부른 뒤 주소 값 검증과 비식별 축 신뢰 관문을 차례로 태운다

### [7]

- **step**: 7
- **actor**: 검수자(REVIEWER)
- **action**: 시스템 설정 화면 우측 패널에서 5초 주기 폴링으로 외부 연동(비식별 서버/AI 추론 서버/데이터베이스) 상태를 읽기 전용으로 확인한다(GET = API-090)

### [8]

- **step**: 8
- **actor**: 검수자(REVIEWER)
- **action**: 관리자 페이지의 위험 액션 영역에서 위험 액션(시스템 초기화(개발 전용)/배치 큐 초기화/캐시 삭제) 버튼을 클릭하면 확인 다이얼로그가 열리고, 확인을 눌러야만 실행된다

### [9]

- **step**: 9
- **actor**: 검수자(REVIEWER)
- **action**: 관리자 페이지에서 관리자 공유 패스워드를 교체할 때는 유효창이 살아 있는 상태에서 현재 패스워드를 다시 입력해 본인을 확인한 뒤 새 패스워드를 제출한다. 교체가 끝나면 그 전에 발급된 유효창은 본인의 것까지 모두 무효가 되어 새 패스워드로 다시 열어야 한다

## description

REVIEWER가 배치 처리(처리 주기·동시 처리 수)/AI 탐지 추론(Confidence Threshold·IoU 임계값)/라벨링 정밀도(인식 민감도·경계 세밀함) 설정 카드와 비식별 옵션을 시스템 설정 화면에서 조회·수정하고, 외부 연동(비식별 서버·AI 추론 서버·데이터베이스) 헬스를 같은 화면에서 5초 주기 폴링으로 읽기 전용 모니터링한다. 연동 서버 주소 조회·수정과 되돌릴 수 없는 위험 액션(시스템 초기화·배치 큐 초기화·캐시 삭제) 실행은 관리자 페이지가 담당하며, 위험 액션은 확인 절차를 거쳐서만 실행한다. 저장은 카드별 독립 폼이며 일괄 저장 API 가 없어 실제로 바뀐 키에 한해서만 개별 PUT 요청을 보낸다. 화면이 표시하는 범위와 서버가 허용하는 범위가 완전히 일치하지 않는 필드가 있으며 최종 판정은 서버 값이다. 어느 필드가 어떻게 어긋나는지는 기술 고려사항에 적는다.

연동 서버 주소는 비식별 서버(kpst.deid.base-url)·AI 추론 서버(authoring.integration.ai-server.base-url)·외부 시계열 분석 벤더(vlm.client.url)·관제 통지 수신처(authoring.control-notify.url)를 대상으로 하며 데이터베이스 접속 정보는 대상이 아니다. 설정 키는 애플리케이션 속성명을 그대로 쓴다 — 별도 키명을 만들면 그 매핑표가 두 번째 진실원이 된다. 설정에 값이 있으면 그 값을, 없으면 배포 기본값을 쓰며 행이 없는 것이 정상 상태라 저장 전까지는 목록 조회에 그 키가 나타나지 않는다. 반영은 재기동 없이 다음 호출부터이고, 값을 바꾼 노드에서는 즉시 다른 노드에서는 설정 캐시 수명만큼 늦게 반영된다. 연동 서버 주소는 관리자 페이지에 속해 진입 시 관리자 공유 패스워드로 단기 유효창을 열어야 저장되며, 검수자 권한만으로는 저장되지 않는다. 그 유효창은 연동 서버 주소 전용이 아니라 운영·관리 성격의 쓰기에 공통으로 요구되는 진입이며, 사용자 역할 부여·변경이나 영상 업로드 시작처럼 관리자 페이지 밖의 관리 행위에도 같은 유효창이 쓰인다. 다만 유효창을 요구하는 축은 연동 서버 주소와 위험 액션이고, 시스템 설정 화면에 남은 배치 처리·AI 탐지 추론·라벨링 정밀도·비식별 옵션은 검수자 권한만으로 저장된다. 「유효창이 주소 설정 변경에만 효력이 있다」는 폐기된 서술이며, 「토큰이 주소에만 쓰인다」와 「관리자 페이지에서 주소에 요구한다」는 서로 다른 말이다. 조회는 유효창 없이 검수자 권한만으로 되고, 유효창은 어느 경우에도 역할을 승격시키지 않는다. 유효 시간이 끝나면 다시 잠기고 관리자 공유 패스워드를 다시 확인해야 이어서 바꿀 수 있다. 저장 값에는 빈 값 거부·길이 상한·주소 형식·스킴(http 또는 https)·호스트 존재·자격증명을 담은 표기 거부만 걸리고 주소 대역으로는 막지 않는다 — 망 통제는 인프라 계층이 담당한다.

관리자 공유 패스워드 자체도 관리자 페이지에서 교체한다. 교체 요건은 검수자 권한과 유효한 관리자 유효창에 더해 현재 패스워드 재확인이다 — 유효창만으로 바꿀 수 있으면 유효창을 얻은 것이 곧 자격을 통째로 얻은 것이 된다. 저장은 해시만 하며 평문은 어디에도 두지 않고 평문과 해시 모두 로그와 응답에 남기지 않는다. 자격은 일반 설정 저장소가 아니라 자격 전용 저장 위치에 두며, 그 위치가 아직 비어 있으면 배포 기본값으로 되돌아가 판정해 한 번도 교체하지 않은 최초 상태에서도 관리 기능에 들어갈 수 있다. 둘 다 없으면 어떤 패스워드도 통과하지 않는다. 교체가 끝나면 그 전에 발급된 유효창은 교체를 수행한 본인의 것까지 모두 무효가 되어, 이어서 관리 행위를 하려면 새 패스워드로 유효창을 다시 연다.

UC-006(라벨링 정밀도 조절의 1회성 AI Tool 모달 override 메커니즘)·UC-013(비식별 옵션 항목 자체)과 서로 다른 관점에서 시스템 설정 화면을 다루며 서로를 대체하지 않는다.

## alternate_flows

### 허용 범위 밖 값 저장 시도

**steps**:

- 서버가 저장을 거부하고 화면은 공통 실패 토스트를 노출한다(필드별 구분 없음)

- **trigger**: 서버 허용 범위를 벗어난 값으로 저장 요청

### 변경 없는 카드 저장 시도

**steps**:

- 저장 버튼이 비활성화되어 요청 자체가 발생하지 않는다

- **trigger**: 카드 내 값이 하나도 바뀌지 않음

### 위험 액션 취소

**steps**:

- 아무 액션도 실행되지 않고 다이얼로그만 닫힌다

- **trigger**: 관리자 페이지의 위험 액션 확인 다이얼로그에서 취소를 선택

### 관리자 유효창 없이 연동 주소 저장 시도

**steps**:

- 저장이 거부되며(403) 상태코드와 오류 코드로는 검수자 권한 거부와 구분되지 않되 안내 문구는 다르다 — 유효창 거부에는 다시 인증할 자리를 안내하며 그 문구는 없음·만료·위조·타인 발급 어느 쪽이든 하나로 같다
- 관리자 페이지는 유효창이 닫힌 것으로 보고 주소 카드를 다시 잠근다

- **trigger**: 관리자 페이지에서 유효창을 열지 않았거나 만료된 상태에서 연동 서버 주소를 저장

### 연동 주소 값 위반

**steps**:

- 저장이 거부되며(400) 거부 사유에 입력 원문이나 해석 결과를 싣지 않는다
- 관리자 페이지는 주소 형식 위반과 인증 만료를 갈라 안내한다

- **trigger**: 빈 값·길이 초과·형식 오류·http 와 https 가 아닌 스킴·호스트 없음·자격증명을 담은 표기로 관리자 페이지에서 연동 서버 주소를 저장

### 관리자 유효창 만료 후 이어서 조작

**steps**:

- 저장이 거부되고 관리자 페이지는 해당 카드를 다시 잠근다
- 이어서 바꾸려면 관리자 공유 패스워드를 다시 제출해 유효창을 새로 연다

- **trigger**: 관리자 페이지에서 유효창이 살아 있는 동안 시작한 관리 조작을 유효 시간이 끝난 뒤에 이어서 저장

### 관리자 패스워드 교체 시 현재 패스워드 불일치

**steps**:

- 교체가 거부되고 기존 패스워드와 이미 발급된 유효창은 그대로 유지된다
- 거부 응답에 입력값이나 저장된 자격을 싣지 않는다

- **trigger**: 유효창은 살아 있으나 현재 패스워드를 틀리게 입력한 채 관리자 페이지에서 관리자 패스워드 교체를 제출

## tech_considerations

- 화면 슬라이더 표시 범위와 서버 허용 범위가 완전히 일치하지 않는 필드가 있다(예: IoU 임계값 — 화면 25~80 vs 서버 30~80, 25~29 구간은 화면에서 입력 가능하나 서버가 거부한다)
- 연동 주소는 판정 축이 둘이다 — 기동 시점의 배포 기본값을 판정하는 축은 그대로 남아 있어 운영 프로파일에서 위반하면 기동이 막히지만, 관리자 페이지에서 저장하는 값에는 그 판정이 다시 적용되지 않는다. 같은 주소가 경로에 따라 다르게 판정되는 것은 결함이 아니라 대상이 다른 두 축이다
- 비식별 서버 주소에만 관문이 하나 더 있다 — 운영 배포에서는 알려진 목·시뮬레이터 호스트명으로 저장할 수 없다. 이 관문의 판정 축은 호스트명이지 주소 대역이 아니다
- 관리자 단기 유효창은 관리 기능 공통 진입이라 관리자 페이지 밖의 관리 행위에도 요구된다 — 「관리자 페이지에서 연동 서버 주소에 요구한다」와 「토큰이 주소에만 쓰인다」를 같은 말로 읽지 말 것. 뭉뚱그리면 시스템 설정 화면에 남은 설정 카드에까지 유효창을 걸거나 반대로 연동 서버 주소까지 풀게 된다
- 유효 여부 판정은 서버가 소유한다 — 화면에 남은 시간이 보이더라도 그것은 안내이고, 클라이언트가 스스로 아직 유효하다고 정하지 못한다
- 표면이 갈렸다고 계약이 갈린 것은 아니다 — 연동 서버 주소 저장은 관리자 페이지로 옮겨간 뒤에도 같은 설정 저장 계약(PUT = API-069)을 그대로 쓰고 관리자 세션 토큰을 헤더에 싣는다. 옮겨간 것은 진입 표면이지 저장 지점·검증 순서·거부 코드가 아니다
- 권한 경계는 축으로 읽는다 — 검수자 권한만으로 되는 축은 배치 처리·AI 탐지 추론·라벨링 정밀도·비식별 옵션 설정과 외부 연동 헬스 모니터링이고(예시이며 전수 열거가 아니다), 유효창이 가산되는 축은 연동 서버 주소와 위험 액션이다. 표면이 갈렸으므로 이 경계를 화면 이름이 아니라 축으로 판정한다
- 유효창이 유효한지 판정하는 일은 단일 지점이 소유하고 어느 창구도 그 판정을 복제하지 않는다. 보통은 창구가 요구를 표식으로 선언하고 그 선언을 판정 지점에 넘기는 것이 공통 배선의 몫이지만, 설정 저장 창구는 요구가 설정 키 단위로 갈리는 자리라 표식을 쓰지 않는다 — 표식은 창구 전체에 걸려 유효창을 요구하지 않아야 할 설정 키의 저장까지 함께 막기 때문이다. 그래서 이 창구만은 표식 없이 판정 지점을 직접 부르고 공통 배선이 끼어들지 않는다. 판정을 수행 계층으로 내리는 안은 기각됐다
- 거부 응답은 상태코드와 오류 코드로는 두 사유를 구분하지 않되 안내 문구는 다르다 — 유효창이 없거나 끝난 경우에는 다시 인증할 자리를 안내한다. 그러지 않으면 막힌 사람이 스스로 돌아올 길이 없다. 유효창 거부의 문구는 없음·만료·위조·타인 발급 어느 쪽이든 하나로 같으며 유효창의 상태값을 싣지 않는다. 그 대가로 두 요청을 견주면 자기 자신의 역할 상태를 짐작할 수 있다는 것은 인지하고 받아들였다
