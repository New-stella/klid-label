# 개인정보 비식별화 처리·검수·누락 신고

## priority

high

## scenario

### then

- (위탁) 비식별이 성공하면 DE_IDNTF_YN 이 'Y' 로 갱신되고 LS_DEIDENT_PROC_LOG 에 처리 이력이 영상 단위로 기록된다. 원본 영상 경로는 그대로 보존된다
- (신고) 신고가 접수되면 상태가 OPEN 으로 기록되고 그 영상의 조회·저장이 차단된다. 라벨과 개인정보 판정은 지우지 않고 보존한다
- (해소) 수동 비식별화 후 해소하면 상태가 OPEN 에서 RESOLVED 로 전이하고 차단이 풀려 보존된 라벨을 그대로 다시 쓴다

### when

- 전체 영상을 외부 비식별 솔루션에 위탁해 처리한다
- 마킹 또는 라벨 작업 중 비식별 누락을 신고한다
- 외부 솔루션에서 수동으로 다시 비식별한 뒤 그 신고를 해소한다

### given

- 영상이 적재되어 있다
- 외부 비식별 솔루션이 가용하고 저작도구와 같은 저장소를 공유한다

### and_examples

#### [1]

- **case**: 비식별 처리가 실패
- **result**: 비식별 완료 여부를 'F' 로 기록하고 원본은 절대 삭제하지 않는다. 자동으로 다시 위탁하는 큐가 없으므로 사람이 외부 솔루션에서 다시 비식별한 뒤 해소 경로로 복귀시킨다

#### [2]

- **case**: 검수 승인 이력이 있는 영상 또는 파생영상에 누락 신고
- **result**: 412 — 접수하지 않으며 신고 행도 만들지 않는다

#### [3]

- **case**: 이미 해소되었거나 기각된 신고를 다시 해소
- **result**: 409 — 원자 클레임이라 두 노드가 동시에 호출해도 한 번만 성공한다
