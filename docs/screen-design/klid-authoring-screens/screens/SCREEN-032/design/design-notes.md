- **검색·기간 필터** — 골격에 상태 탭만 있다.

- **자동 재비식별 버튼** — 골격이 "자동 재비식별 큐는 두지 않는다"고 못박는다. 해소는 외부 솔루션 작업
  **이후** 사람이 결과를 고르는 조작이므로, 다이얼로그가 그 동선의 전부다.

## § 디자인 결정 (골격이 규정하지 않은 부분)

### 1. 신고 단계 배지에 "해소하면 무엇이 재개되는가" 를 붙였다

골격 note 가 "단계별 툴팁으로 해소 시 무엇이 재개되는지 안내한다" 고 요구한다. 세 단계는 **해소 후 결과가
서로 다르다** — 마킹은 처리 단계를 되감아 마킹부터 다시, 라벨링은 프레임만 다시 뽑고 라벨 좌표 보존,
미상은 자동 재개 없음. 배지 글자만으로는 그 차이를 알 수 없어 호버·포커스 툴팁으로 문장을 붙였다.

툴팁 문구는 **마크업에 실려 있어 스크린리더도 읽는다**(`role="note"`). 배지에 `tabindex="0"` 을 준 것은
키보드 사용자가 그 문장에 도달할 수 있게 하기 위해서다 — 조작 버튼이 아니므로 44px 타깃 대상은 아니다.

배지 모양도 상태 배지(pill)와 갈랐다 — 신고 단계는 **상태가 아니라 분류**라 사각(`--radius-sm`)으로 두어
같은 행의 `미처리`/`처리완료` pill 과 역할이 섞이지 않게 했다.

### 2. 신고 구간에 무엇이 잠기는지 상단에서 먼저 알린다

골격 purpose 는 잠금 범위를 길게 규정하는데(재생·프레임 이미지·라벨 조회/저장·개인정보 판정),
표에는 그 사실이 드러나지 않는다. REVIEWER 가 "이 신고를 왜 빨리 처리해야 하나" 를 알아야 하므로
상단 배너(warn)로 요약했다. 동시에 **라벨과 판정이 보존된다**는 사실도 함께 적었다 — 그걸 모르면
"작업이 날아갔겠구나" 로 오해해 불필요한 재작업을 지시하게 된다.

### 3. 미처리 행은 좌측 강조선으로 알리고 행 배경을 물들이지 않았다

같은 행에 `미처리`(warn pill)가 있어 행 배경까지 warn 계열로 물들이면 배지가 배경에 묻혀 알약 형태를
잃는다. 기준본 SD-004 의 `.group-row[data-state]` 가 같은 이유로 택한 처리를 그대로 따랐다.

### 4. 해소가 성립하지 않는 3가지 경우를 참고 패널로 남겼다

골격 note 는 서버 안전장치 3종(후보 재열거 검증 / 신고 시각 이후 수정 / 동시 해소 차단)을 규정하지만
이는 **화면이 미리 막을 수 없는 조건**이다. 사용자는 "눌렀는데 안 됐다" 만 겪게 되므로, 어떤 경우에 그런지
미리 알 수 있도록 참고 패널에 적었다. 구현 시 실패 안내 문구의 근거가 된다.

### 5. 사유는 줄이지 않고 그대로 흐르게 뒀다

작업자가 쓴 문장이 곧 판단 근거다. 말줄임하면 REVIEWER 가 매번 펼쳐 봐야 하므로 열 폭 안에서
낱말 단위(`word-break: keep-all`)로 감기게 두고, 행 높이가 달라지는 것을 받아들였다.

## § 역등록 기록 (Phase 5)

| SD | render_id | surface | action | 렌더 URL |
|---|---|---|---|---|
| **SD-021** | `main` | `page` | add → replace | `/uploads/designs/4ece2c3f-8e99-46f5-9580-71108a76e578/SD-021/main.html` (+ `main.css`) |

- **render_id·surface 를 와이어프레임과 동일**(`main` / `page`)하게 맞춰 비교 뷰에서 짝지어지며, SD 는
  screen_spec 과 별 ITEM 이라 와이어프레임을 덮어쓰지 않는다.
- **왕복 바이트 대조 — 치환(replace) opcode 0건 · 미설명 잔차 0건 · CSS 원문 해시 일치.**
  치환이 0 이라는 것은 **문자가 바뀐 자리가 한 곳도 없다**는 뜻이므로 한글 손상이 원리적으로 불가능하다.
- **ITEM 한글 필드 12/12 완전일치**(제목·본문 제목·설명·렌더 라벨). 한글을 손으로 치지 않고
  키트 `.md` 와 SD-017 값에서 **추출해 조립**했다.

### ★ 게시 렌더가 지우는 속성 6종 (실측 · 이번 회차 발견 2종 포함)

| 삭제 대상 | 건수(3화면) | 성격 |
|---|---|---|
| `stroke-width` | 93 | **시각 손상** — 없어지면 SVG 기본값 1 로 그려져 아이콘이 얇아진다 |
| HTML 주석 | 31 | 내용 아님 — 무해 |
| `scope` | 27 | 표 접근성 정보 손실 (이전 회차에 이미 관측) |
| `tabindex` | 6 | **신규 발견** — 키보드로 툴팁에 닿을 수 없게 된다 |
| `maxlength` | 4 | **신규 발견** — 입력 길이 제한이 사라진다 |
| `inputmode` | 2 | 모바일 키패드 힌트 손실 (이전 회차에 이미 관측) |

**보존되는 것**: `role`·`aria-*`·`class`·`id`·`for`·`type`·`value`·`placeholder`·`stroke`·`fill`.

**`stroke-width` 만 이번에 되살렸다** — 같은 값을 CSS 로도 선언했다(CSS 는 원문 그대로 보존되는 것이
왕복 대조로 확인됨). 게시본을 브라우저로 열어 계산 스타일을 재 확인했다 — 로컬 속성 값 분포와 정확히
일치한다. HTML 속성은 그대로 남겨 로컬 원본이 자기완결이 되게 했다(presentation attribute 는 CSS 보다
우선순위가 낮아 값이 같으면 충돌하지 않는다).

⚠ 나머지 5종은 **CSS 로 대체할 수 없는 정보**라 게시본에서 복원 불가다. **로컬 원본이 진실원**이며
구현은 로컬 파일을 따라야 한다.
