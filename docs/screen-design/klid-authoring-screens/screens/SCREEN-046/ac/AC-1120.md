# 포털 데이터셋 등록 영상의 포털 작업 창구 통과 — 검수 상태 없이 조회·저장·AI 보조·내려받기 허용·원본 라벨 불변·승인 영상 무회귀 (happy·negative)

## priority

high

## scenario

### then

- 영상 V 에 대한 조회·이미지·메타·이벤트 어노테이션·AI 보조 요청이 모두 200 으로 응답한다
- 저장이 200 으로 응답하고, 다시 조회한 라벨은 갑의 저장본이며, 원장의 원본 라벨 두 건은 저장 전과 같다
- 갑의 내 작업 목록에 영상 V 가 데이터마트 출처 행으로 실리고 이어서 작업 진입이 열린다
- ZIP 에는 비식별 프레임 이미지와 같은 이름의 어노테이션 문서만 있고 영상 파일은 없으며, 문서의 영상 블록 파일명·초당 프레임 수는 등록 영상 메타 값이고 등록되지 않은 값은 비어 있다
- 영상 W 의 응답은 변경 전과 같고, 영상 U 는 「포털에서 작업할 수 없는 영상입니다.」 문구의 403 으로 거부된다

### when

- 갑이 프레임 F 의 라벨 조회·이미지·메타 조회·이벤트 어노테이션 조회와 AI 탐지·AI 분할을 부른다
- 갑이 프레임 F 에 라벨 한 건을 고쳐 저장하고 메타와 이벤트 어노테이션을 저장한다
- 갑이 프레임 F 의 라벨을 다시 조회하고, 원장의 원본 라벨을 조회하고, 내 작업 목록을 부른다
- 갑이 영상 V 의 작업 데이터 ZIP 을 내려받는다
- 갑이 영상 W 에서 같은 창구들을 부르고, 영상 U 의 프레임 라벨 조회를 부른다

### given

- 포털 채널 배포본이며 포털 회원 갑의 토큰이 있다
- 데이터셋 X 의 등록이 끝나 영상 V(출처 PORTAL_DATASET, 검수 워크플로 상태 행 없음)의 프레임 F 에 원본 라벨이 두 건 있다
- 검수 승인 영상 W 와, 검수 승인도 데이터셋 등록도 업로드 자산도 아닌 영상 U 가 있다

## statement

포털 채널 배포본에서 포털 데이터셋에서 등록한 영상(출처 PORTAL_DATASET)은 검수 승인 상태가 없어도 포털 작업 가능 영상으로 판정되어, 프레임 라벨 조회 [[API-110]] · 프레임 이미지 [[API-111]] · 라벨 저장 [[API-082]] · 프레임 메타 [[API-234]]·[[API-235]] · 이벤트 어노테이션 [[API-236]]·[[API-237]] · AI 보조 [[API-255]]·[[API-257]]·[[API-254]] · 작업 데이터 ZIP 내려받기 [[API-203]] 를 통과해야 한다. 결정 근거는 [[ADR-068]] 이다 — 포털향에는 검수·승인 흐름이 없어 그 영상은 승인이 아니라 출처로 허용된다.

사용자가 저장한 값은 포털 전용 오버레이에만 쌓이고 등록된 원본 라벨은 바뀌지 않으며, 저장한 사용자의 내 작업 목록 [[API-225]] 에 그 영상이 실리고 이어서 작업 진입이 열린다. ZIP 묶음에는 비식별 프레임 이미지와 프레임별 어노테이션 문서만 담기고 영상 파일은 없으며, 문서의 영상·이미지 블록은 등록 영상 메타와 프레임 원장 값으로 채워지고 없는 값은 비어 있다.

비식별 누락 신고 게이트는 그대로 함께 걸리고, 검수 승인 영상의 기존 동작과 응답은 바뀌지 않는다. 검수 승인 영상도 데이터셋 등록 영상도 본인 업로드 자산도 아닌 영상은 「포털에서 작업할 수 없는 영상입니다.」 문구의 403 으로 거부된다.
