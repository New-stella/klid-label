### X-Admin-Session

- **in**: header

**schema**:

#### type

string

- **required**: true
- **description**: 관리자 설정 세션이 발급한 단기 유효창 토큰. 업로드 시작에는 검수자 권한에 더해 이 토큰을 요구하며, 없거나 만료됐으면 403 이다. 이어 올리기·취소·진행 위치 조회·프로토콜 능력 조회에는 요구하지 않는다.

## description

TUS 1.0 재개 가능 업로드 세션을 생성한다. 응답은 201 + Location: /v1/uploads/{uploadId} 헤더(본문 없음). 인입 메타는 요청 본문(JSON)으로 받는다 — 이 창구는 본문의 미디어 형식이 JSON 일 때만 요청을 받아들인다. ⚠ 1차 영상 적재 경로가 아니다 — 1차 적재는 관제가 인입 원장(LS_DATA_INGEST)에 직접 등록한 행을 저작도구 주기 배치가 폴링해 수행한다. 이 세션은 내부 관리 화면의 대용량 영상 적재 통로다.

★ 본문으로 메타를 받는 것은 재개 가능 업로드 규약에서 의도적으로 벗어난 것이며 결손이 아니다. 그 규약의 세션 생성은 본래 메타를 헤더에 싣고 본문은 비우는 것을 전제하는데, 관제가 보내는 인입 항목을 그대로 재현하려면 관제일지 항목 하나만으로도 헤더 상한을 넘긴다. 그래서 이 창구만 본문으로 받는다. 본문에 첫 조각을 싣는 확장을 제공하지 않으므로 규약과 충돌하지 않으며, 같은 이유로 능력 광고에도 그 확장을 싣지 않는다 — 광고하면 표준 클라이언트가 본문에 조각을 실어 보내 이 계약이 깨진다. 표준 방식(헤더 수신)으로 되돌리지 말 것 — 되돌리면 기존 소비자가 전부 깨지고 헤더 상한 문제가 되살아난다. 전송 총량은 여전히 규약 헤더로 받는다(전송 크기는 규약의 소관이고 인입 메타가 아니다). 본문 수신은 이 창구의 계약이며 다른 업로드 창구에 그대로 적용되지 않는다.

세션을 만드는 시점에 인입 대기 행이 함께 생긴다. 업로드가 끝났다고 해서 곧바로 적재되는 것은 아니므로, 응답에 인입 처리 상태 표시를 함께 실어 보낸다 — 폴링 적재가 꺼진 형상이면 그 사실이 이 표시로 드러난다.

이 세션 생성은 운영·관리 성격의 쓰기라 검수자 권한만으로는 열리지 않는다. 유효한 관리자 단기 유효창을 함께 요구하며, 유효창은 권한을 대체하지 않고 가산된다 — 검수자 권한은 그대로 필요하다. 유효창은 X-Admin-Session 헤더로 싣는다. 없거나 만료됐으면 403 이고, 권한 부족과 구분해 알리지 않는다.

요구하는 지점은 이 시작 한 곳뿐이다. 이어 올리기·취소·진행 위치 조회·프로토콜 능력 조회에는 요구하지 않는다. 대용량 자료 전송은 유효창보다 오래 걸리므로 매 조각마다 요구하면 전송이 끊기기 때문이다. 그런데도 안전한 것은, 전송 식별자가 사실상 허가증이 되는 자리에 소유자 판정이 이미 서 있기 때문이다 — 이어 올리기 경로는 그 전송의 소유자만 진행할 수 있어, 식별자를 알아도 소유자가 아니면 이어 쓸 수 없다. 그리고 그 소유자는 유효창을 연 바로 그 사람이다. 둘 다 같은 자격 주체를 기준으로 판정하기 때문이며, 소유자 판정 규칙 자체는 이 요구와 함께 새로 생긴 것이 아니라 이미 있던 것이다.

포털 채널 이용자가 자신의 자산을 올리는 업로드는 이 요구의 대상이 아니다 — 그것은 관리 행위가 아니라 그 이용자 본인의 데이터다.
