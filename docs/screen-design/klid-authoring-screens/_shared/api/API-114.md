###### description

재생 요소가 요청하는 상대 URL (/api/v1/videos/{rawSn}/stream?exp=...&sig=...). 쿼리에 실린 만료·서명은 재생 구간의 인증 판정에 쓰이지 않는다(재생 인증은 klid_stream_nonce 쿠키로 판정한다). 이 값은 API 기준 경로이며 배포 접두(컨텍스트 경로)를 포함하지 않는다. 발급 측은 자신이 배포된 컨텍스트를 알 수 있더라도 이 값에는 배포 접두를 붙이지 않으며, 배포 접두를 결합하는 책임은 소비 측 한 곳에만 둔다. 최종 요청 주소는 소비 측이 자신이 아는 배포 접두를 이 값 앞에 붙여 만든다. 발급 측과 소비 측이 모두 접두를 붙이면 요청이 배포 접두를 두 번 가진 경로로 나가 이 API 의 경로 공간을 벗어나고 영상이 재생되지 않는다. 앱이 베이스 경로 아래에 서비스되는 배포에서만 드러나는 조건이다.

#### description

성공 — 재생 URL + 만료시각. ApiResponse 래퍼. 이때 URL 과 함께 클라이언트 바인딩 쿠키 klid_stream_nonce 를 Set-Cookie 로 발급한다. 이 쿠키가 재생 구간(부분 요청 포함)의 유일한 인증 수단이며 브라우저가 스트림 요청에 자동으로 실어 보낸다. 값은 서버 비밀과 발급 대상 사용자로 봉인된 형태이며, 서버는 매 스트림 요청에서 봉인을 검증해 발급자를 복원하고 그 발급자로 영상 단위 인가를 다시 판정한다. 속성은 HttpOnly, SameSite=Lax, Max-Age 3600초이며 Path 는 스트림 경로로 한정한다. Secure 는 배포 설정으로 결정하며 기본은 부여하지 않는다. 요청에 이미 유효한 쿠키가 있으면 그대로 재사용하고, 없거나 봉인 검증에 실패하면 새로 발급한다.

## description

인증된 내부 사용자(REVIEWER/WORKER)가 호출하면 영상 스트림 URL 을 반환하고, 재생 구간의 인증에 쓰이는 클라이언트 바인딩 쿠키 klid_stream_nonce 를 함께 발급한다. <video> 엘리먼트가 Authorization 헤더를 못 붙여 401이 나는 문제를 우회하기 위한 것으로, JWT 본문은 URL에 노출되지 않는다. 서버 서명 시크릿 미설정 시 503.

재생 구간의 인증 판정([[ADR-071]]) — 스트림 요청(부분 요청 포함)의 인증은 이 쿠키 하나로 판정한다. 서버는 쿠키의 봉인을 서버 비밀로 검증해 발급자를 복원하고, 그 발급자로 영상 단위 인가(검수자는 전체, 작업자는 본인 배정분)를 매 요청의 진입부에서 다시 판정한다. 쿠키가 없거나 봉인 검증에 실패하거나 다른 사용자에게 발급된 쿠키이면 거부한다(fail-closed). URL 에 실리는 만료·서명은 재생 구간의 인증 판정에 쓰이지 않는다. 서명 발급 수단은 남아 있으나 판정에는 쓰지 않는다. 비식별이 완료되지 않은 영상의 재생 거부, 비식별 누락 신고가 열린 영상의 재생 차단, 원본 재생은 검수자가 명시할 때만 허용한다는 조건은 인증 판정 방식과 무관하게 그대로 적용된다.

보안 근거 — 주소에는 재생 권한을 주는 비밀이 실리지 않으므로 URL 만 확보한 제3자는 재생할 수 없다. 발급자 바인딩은 쿠키 봉인이 수행하므로 다른 사용자에게 발급된 쿠키로는 재생할 수 없다(CWE-284). 쿠키가 유효해도 영상 단위 인가를 매 요청 다시 판정하므로 권한 밖 영상은 거부된다. HttpOnly 는 스크립트가 쿠키를 읽어 탈취하는 경로를 차단하고, SameSite=Lax 는 크로스사이트 요청에 쿠키가 부착되지 않게 한다(동일 오리진 재생은 정상). Path 를 스트림 경로로 한정하는 것은 다른 API 요청에 불필요하게 실려 나가지 않게 하기 위함이다. Secure 는 HTTPS 로 서비스되는 배포에서 켜는 것을 권장하나, 평문 HTTP 로 서비스되는 배포에서 부여하면 브라우저가 쿠키를 저장하지 않아 재생 요청의 인증이 전량 실패한다.

응답의 url 은 API 기준 경로이며 배포 접두(컨텍스트 경로)를 포함하지 않는다. 발급 측은 자신이 배포된 컨텍스트를 알 수 있더라도 이 값에는 배포 접두를 붙이지 않는다. 배포 접두를 결합하는 책임은 소비 측 한 곳에만 두며, 최종 요청 주소는 소비 측이 자신이 아는 배포 접두를 그 값 앞에 붙여 구성한다. 이 URL 은 인증 헤더를 실을 수 없는 재생 요소가 그대로 사용하는 값이라, 소비 측이 배포 접두를 붙이지 않으면 요청이 이 API 의 경로 공간을 벗어나 같은 오리진에 배치된 다른 시스템의 경로로 나가고 영상이 재생되지 않는다. 반대로 발급 측과 소비 측이 모두 접두를 붙이면 요청이 배포 접두를 두 번 가진 경로로 나가 이 API 의 경로 공간을 벗어나고, 영상이 재생되지 않는다. 앱이 베이스 경로 없이 루트에 서비스되는 배포에서는 접두가 비어 있어 이 두 어긋남이 드러나지 않으므로, 베이스 경로 아래에 서비스되는 배포에서만 나타나는 조건임에 주의한다. 발급된 URL 로 재생이 실패했을 때 소비 측은 재발급과 재시도를 무한히 반복하지 않는다. 재시도 횟수에 상한을 두고 상한에 이르면 중단해 사용자에게 실패를 알리며, 구체적 상한값은 구현 판단에 맡긴다.
