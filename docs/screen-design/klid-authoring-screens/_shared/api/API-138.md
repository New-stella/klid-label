## description

검수 상태 4종 건수를 필터 결과 전체 기준으로 반환한다(현재 페이지가 아니다). 페이지 단위로 세면 숫자가 틀리므로 집계는 서버가 한다.

[필터] q 는 검수 목록과 동일하게 반영된다.

[★ status 무시] status 는 전달돼도 무시한다 — KPI 카드 자체가 status 선택지이므로 이미 status 로 좁혀진 집합 위에서 세면 항상 1개 카드만 값을 갖는다.

[★ sort 미수용] sort 는 파라미터로 받지 않는다 — 목록과 동일한 쿼리스트링(sort 포함)을 그대로 보내도 무시될 뿐 400 이 아니다(목록의 정렬 폴백 정책과 동일한 취지).

[불변식] total == pending + inReview + approved + rejected. 집계 대상이 검수 워크플로 상태 4종으로 한정되고 버킷도 같은 4종이라 구조적으로 성립한다 — 검수 대상이 아닌 배치·작업 상태는 어느 버킷에도 합산되지 않는다. 검수 상태가 5종으로 늘어나면 total 만 조용히 과소집계되므로, 버킷에 매핑되지 않은 상태가 들어오면 응답을 만들지 않고 즉시 실패한다.

[★제외분 배제(2026-09-15 확정, ADR-069)] 제외 표시가 선 영상은 이 집계에서 빠진다. 이 집계는 검수 목록 창구와 같은 조건 조립을 공유하므로, 목록이 제외분을 빼면 집계도 같이 줄어야 한다 — 둘이 갈리면 화면의 카드 숫자와 그 카드를 눌러 얻는 목록이 어긋난다. ★구동 대상은 영상 원장이 아니라 검수 워크플로 상태다. 제외 표시는 영상 원장(ERD-012)이 가지므로 영상 쪽을 상관 조회해 판정한다 — 직접 이어붙이면 행이 증식해 건수가 부풀려진다. ★제외 판정은 조회 조건에만 붙이고 버킷 판정식은 건드리지 않는다. 위 불변식이 버킷 판정식에 걸려 있어, 거기에 제외 조건을 섞으면 어느 버킷에도 들어가지 않는 행이 생겨 합계가 total 과 어긋난다.

[★제외됨 건수(2026-09-15 확정, ADR-069)] excludedCount 를 키 하나로 더한다. 기존 집계 키의 이름·타입·뜻은 그대로이고 키가 하나 느는 것뿐이다. ★필터 범위 안에서 센다 — 화면이 그 숫자를 눌러 제외분 목록으로 전환하므로 숫자와 누른 결과가 일치해야 한다. 0건이어도 실린다 — 0건일 때 빠지면 화면이 「제외된 것이 없다」와 「그 기능이 없다」를 구분해 보여 주지 못한다. 이 값은 위 불변식의 항이 아니다 — 배제된 건을 센 것이라 4종 버킷 어디에도 합산되지 않으며 total 에도 들어가지 않는다. 이름은 세 목록(영상 목록·작업 목록·검수 목록) 공통이다 — 한 개념이 창구마다 다른 이름으로 나가면 화면이 세 이름을 모두 알아야 한다.

[★이 축에 제외분이 실제로 도달한다] 배정이 있으면 제외가 거부되고, 검수 목록에 뜨려면 제출을 거쳐야 하므로 대개 배정이 있다. 다만 반려된 배정은 해제할 수 있고(해제를 거부하는 것은 검수 대기·검수 중·승인 셋이다) 그 뒤 제외가 가능하다 — 즉 반려 상태를 통해 실제로 도달한다. 방어적 조건이 아니라 실제로 걸리는 조건이다.

[스냅샷] 목록과 별도 요청이므로 각 값은 조회 시점 스냅샷이다.
