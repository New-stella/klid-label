## description

배정 목록을 페이징해 조회한다. 검수자는 전체 배정을, 작업자는 본인 배정만 조회한다 — workerId 는 REVIEWER 만 유효하다. WORKER 요청에서는 무시되고 본인 배정으로 범위가 고정된다(403 아님).

[필터는 전체 기준] 검색어·워크플로 상태·이벤트유형 필터는 현재 페이지가 아니라 전체 데이터셋 기준으로 적용되며 totalElements 도 필터 결과 기준이다. 이벤트유형은 표시명이 같은 유형이 한 그룹이라 그룹 내 어느 코드를 보내도 그룹 전체가 조회된다.

[정렬 키 allowlist — strict] regDt(기본 desc)·assignedAt·rawDataId·videoId·assignmentId·id 만 허용하고 밖의 키는 400 이다. assignedAt/videoId/id 는 응답 필드 이름 별칭이고 실제 엔티티 필드는 regDt/rawDataId/assignmentId 3개뿐이라 정렬 항목 개수 상한도 3이다. ★ 검수목록(GET /v1/reviews)은 반대로 lenient(200 폴백)이며 일관성을 이유로 통일하지 말 것(ADR-038).

[제외된 영상 배제 — 방어적] 제외 표시가 선 영상은 이 목록에서도 뺀다(ADR-069). 이 창구가 구동하는 대상은 영상 원장이 아니라 배정 행이므로, 제외 판정은 배정 행에 영상을 직접 이어 붙여서 하지 않고 그 영상 쪽을 상관 조회해서 한다 — 직접 이어 붙이면 배정 한 건이 여러 행으로 늘어난다.

★ 그런데 이 목록에는 제외된 영상이 구조적으로 나타날 수 없다. 배정이 있는 영상은 제외가 거부되고, 이 목록은 배정 행이 있어야 나오기 때문이다. 그럼에도 판정을 붙이는 이유는 거부가 뚫렸을 때의 마지막 방어다 — 비용은 조건 하나뿐이고, 붙이지 않았다가 거부 판정에 구멍이 나면 제외한 영상이 작업자 화면으로 샌다. 「도달 불가하니 빼자」로 되돌리지 말 것.

[싣지 않는 것] 이 창구에는 「제외됨 건수」도 「제외분만 보기」도 싣지 않는다. 제외·복원은 검수자 이상의 권한이라 작업자는 수행할 수 없고, 제외된 영상이 이 목록에 나타날 일도 없다 — 실으면 항상 0이고 아무도 쓰지 못하는 값이 된다.

⚠ [알려진 한계] 이 축의 화면 지표는 서버 집계가 아니라 화면이 현재 페이지의 행을 세는 방식이다(작업자는 검수자용 집계 창구를 부를 수 없다). 목록이 줄면 지표도 줄지만 전체 기준이 아니라 페이지 기준이며, 이번 변경이 그것을 고치지 않는다.

인가 축·정렬 키 정책(미등록 키 400 strict)·기존 필터와 페이지 기본값은 전부 그대로다.
