## description

## 방향 — 「사람」이 부르는 자리다
이 창구는 사람이 부르는 자리다. 데이터셋 소재 조달 화면([[SCREEN-046]])의 데이터셋 영상 구역이 등록 실패를 보일 때, 사용자가 「다시 등록」을 눌러 부른다. 등록 규약과 표식의 뜻은 [[ADR-068]] 이 소유하며 여기에 복제하지 않는다. 인가 축은 소재 조달 착수([[API-248]])와 같은 「사람」 축이다 — 포털 채널 토큰과 포털 회원 역할을 함께 요구한다.

## ★ 실패 표식일 때만 다시 시작한다
표식이 실패면 등록을 다시 착수시키고 진행 중으로 답한다. 완료면 다시 하지 않고 완료를 답한다. 진행 중이면 — 이 서버에서 실제로 진행 중이거나 진행 중 표식이 신선하면 — 새로 시작하지 않고 진행 중을 답한다. 표식이 없거나 진행 중 표식이 오래됐으면 목록 조회([[API-253]])와 같은 회복 판정을 거친다. 등록은 클립 식별자 기준 멱등이라 겹쳐 돌아도 행이 늘지 않는다.

## ★ 언제나 200 — 상태 구분은 본문이 싣는다
조달 착수([[API-248]])가 202 인 것과 달리, 이 창구는 현재 상태를 즉시 알 수 있어 200 으로 답한다. 재착수를 접수했건 이미 완료였건 진행 중이었건 코드는 같고, 구분은 본문의 registrationState 가 싣는다. 재착수가 접수됐을 때 registrationFailureReason 은 비어 있다. 진행은 목록 조회로 본다.

## ★ 자동으로 되풀이하지 않는다
구조 불일치는 재착수해도 같은 사유로 다시 실패한다. 그래서 목록 조회는 실패 표식을 재시작하지 않고, 이 창구도 사람이 누를 때만 일한다. 화면은 목록 응답의 실패 사유를 보고 다시 눌러 볼 가치가 있는지 알린다 — 입출력 실패처럼 일시적인 사유는 재착수가 뜻이 있고, 짝 불일치나 문서 판독 불가처럼 구조에서 온 사유는 배포본이 바뀌기 전에는 결과가 같다.

## 응답에 내부 경로·표식 파일 이름을 싣지 않는다
해제본 경로도 저장소 루트도 상태 표식 파일의 이름도 응답에 담지 않는다 — 소재 조달 착수와 같은 금지다. 담는 것은 등록 상태와 실패 사유 분류 값뿐이다.

## 대기열이 차면 접수하지 않는다
등록 작업을 맡길 자리가 없으면 선점을 되돌리고 503 으로 거절한다. 선점을 남긴 채 거절하면 그 데이터셋은 아무도 일하지 않는데 진행 중으로 굳어 다음 회복 판정 전까지 다시 시작할 수 없다. 소재 조달 착수가 같은 이유로 같은 코드를 쓴다.

## 거부 — 소재가 준비되지 않았거나 등록이 꺼져 있다
소재 조달 상태가 준비 완료가 아니면(가져온 적 없음·진행 중·실패) 409 로 거부한다 — 등록할 소재가 없기 때문이다. 등록이 배포 설정으로 꺼져 있어도 409 다 — 다시 시작시킬 수 없는 상태를 진행 중으로 꾸며 답하지 않는다. 토큰이 없거나 만료되면 401, 포털 회원이 아니면 403 이다.

## ⚠ 열린 항목 — 객체 수준 인가가 없다
로그인한 포털 회원이면 어떤 데이터셋 번호로도 재착수가 된다 — 소재 조달 착수와 같은 공백이며 해소 방향도 그쪽 결정을 따른다. 추정으로 잇는 규칙을 만들지 말 것.
