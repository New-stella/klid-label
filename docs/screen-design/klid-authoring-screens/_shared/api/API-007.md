### 2026-08-27 — 관리자 공유 패스워드의 원천 이동 (ADR-046)
- 이 창구가 대조하는 관리자 공유 패스워드의 원천이 배포 설정에서 자격 전용 저장 위치의 해시로 옮겨갔다. 저장 위치에 값이 없으면 배포 설정값으로 되돌아가 판정하고, 둘 다 없으면 어떤 패스워드도 통과하지 않는다.
- 관리자가 그 패스워드를 교체하면 이 창구가 대조하는 값도 함께 바뀐다. 두 창구가 같은 원천을 보기 때문이다.
- 자가 부여 가능 역할의 화이트리스트는 이번 변경 대상이 아니다. 이 결정은 새 역할을 만들지 않으므로 목록에 더하거나 뺄 것이 없다.
- 이미 역할을 보유한 사용자 거절, 속도 제한 축과 판정 순서, 사용자 마스터 자동등록, 응답 스키마와 상태코드 계열도 그대로다.

## description

인증됐으나 role 클레임이 없는 사용자가 관리자 공유 패스워드와 함께 본인에게 WORKER 또는 REVIEWER 역할을 자가 부여하고 새 access token 을 즉시 발급받는 온보딩 API다. '관제/포털 채널 분기'가 아니라 단일 전제(actor.channel==INTERNAL && actor.role==null) 충족 여부로 승인·거절을 가른다 — 요청 role 이 PORTAL_USER 면 400, 그 전제를 벗어나면(PORTAL 채널 사용자 포함, 또는 이미 role 을 보유한 사용자) 409 로 거절한다. 자가 부여할 수 있는 역할은 WORKER·REVIEWER 화이트리스트로 제한되며, 그 밖의 역할이 요청되면 403 으로 거절한다 — 현재 역할 집합에서는 PORTAL_USER 가 앞선 400 검사에 먼저 걸려 이 분기에 도달하지 않으나, 역할 집합이 넓어질 때 새 역할이 자동으로 자가 부여 대상이 되지 않게 하는 기본 거부 장치다. 관리자 패스워드는 자격 전용 저장 위치에 보관된 BCrypt 해시와 상수시간으로 비교해 검증한다 — 저장 위치에 값이 없으면 배포 설정값으로 되돌아가 판정하고, 둘 다 없으면 어떤 패스워드도 통과하지 않는다. 관리자가 그 패스워드를 교체하면 이 창구가 대조하는 값도 함께 바뀐다. 시도 횟수는 계정 축 + 엔드포인트 전역 축으로 제한한다(429). security 표에 나열된 REVIEWER/WORKER/PORTAL_USER 는 성공 조건이 아니라 정반대다 — 이 중 하나라도 이미 보유한 인증 사용자는 모두 409 로 거절된다. 이 API 를 성공적으로 호출할 수 있는 유일한 대상은 아직 아무 역할도 보유하지 않은(내부 채널, role 미배정) 사용자뿐이다.
