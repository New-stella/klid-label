## description

REVIEWER 작업 목록. 영상(LS_DATA_RAW)을 페이징해 LABELER 배정 정보와 함께 반환한다(미배정 영상 포함, task 측 필드 null). 검수자를 영상에 배정하는 절차를 두지 않으므로 응답 항목에 검수자 축이 없다(ADR-067).

[정렬 — 시간축 단일] 기본 등록일(regDt) 최신순이며 상태 우선순위 정렬(구 ORDER BY CASE: 반려>검수대기>배정>미배정>완료)은 폐기됐다. '지금 처리할 것'은 정렬이 아니라 workStatus 필터·KPI 카드로 표현한다(CVAT·Label Studio 관행). 배정 화면에 검수 축 우선순위가 섞여 미배정 건이 진행중 건보다 아래로 밀리던 문제를 해소한 변경이다.

[정렬 키 allowlist — strict] regDt/capturedAt/shtDt/rawSn/videoId 만 허용하고 밖의 키는 400 이다(변경 전 이 엔드포인트는 Pageable 을 그대로 받아 잘못된 키가 500 이었으므로 400 이 개선). 항목 개수 상한 3(고유 컬럼 수 파생), 같은 컬럼 중복은 첫 지정만 적용. ★ 검수목록(GET /v1/reviews)은 반대로 lenient(200 폴백)이며 일관성을 이유로 통일하지 말 것(ADR-038).

[두 상태 축] status(배치 상태)와 workStatus(워크플로 상태)는 독립 축이며 AND 결합된다. 신규 파라미터는 모두 optional 이고 BE 기본값이 불변이라 기존 호출은 파라미터 변경 없이 동일 결과를 반환한다(회귀 방어로 고정됨).

[필터·집계 서버 이관] q 는 DB WHERE 단계에서 적용되어 totalElements 가 필터 결과 기준으로 정확하다. KPI 집계는 GET /v1/tasks/board/summary 로 분리.

[제외분 배제 — 기본 동작] 이 목록의 기본은 제외 표시가 붙지 않은 영상만 보는 것이다(ADR-069). 제외된 영상은 목록에서 빠지고 totalElements 도 함께 줄어든다. 같은 화면이 함께 쓰는 KPI 집계(GET /v1/tasks/board/summary)와 이벤트 유형 옵션(GET /v1/tasks/board/event-types)도 같은 조건에서 줄어든다 — 조건이 갈리면 목록은 줄었는데 집계는 그대로인 어긋남이 생긴다. ★ 집계에는 「버킷 합 = 전체 건수」 불변식이 걸려 있다. 제외 판정은 조회 조건에만 붙이고 버킷 판정식은 건드리지 않는다 — 그래야 그 불변식이 유지된다.

[제외분만 보기 — excludedOnly] 제외된 영상을 보려면 excludedOnly 를 보낸다. 선택 항목이며 보내지 않으면 종전과 같은 응답이라 기본값이 바뀌지 않는다. 불리언인 것이 결정이다 — 값역으로 두면 다음 사람이 「둘 다 보기」를 더할 자리가 열리고, 표시분과 제외분이 섞이면 어느 것이 제외분인지 행마다 구분해야 한다. 영상 처리 현황(GET /v1/videos)·작업 목록·검수 목록 세 목록이 같은 이름을 쓴다.

[제외됨 건수는 이 창구가 갖지 않는다] 「제외됨 건수」는 KPI 집계 창구(GET /v1/tasks/board/summary)가 소유하며 이 목록 응답에는 싣지 않는다. 같은 숫자를 두 창구가 함께 실으면 진실원이 둘이 되어, 한쪽만 고쳐졌을 때 어느 쪽이 맞는지 가릴 수 없다. 이 화면은 그 집계를 이미 함께 부르므로 목록 응답에 같은 숫자를 다시 실을 이유도 없다. ★ 판정 규칙은 「집계 창구가 있으면 집계가 소유하고, 없으면 페이지 응답이 갖는다」이다 — 집계 창구가 없는 영상 처리 현황(GET /v1/videos)만 그 숫자를 페이지 응답에 둔다.

[이번 변경이 건드리지 않는 것] 정렬 키 정책(strict)·배치 상태 축 기본값·워크플로 상태 축 필터·KPI 카드 구성·페이지 기본값·기존 필터는 그대로다.
