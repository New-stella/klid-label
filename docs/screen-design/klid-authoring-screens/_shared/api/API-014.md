## description

검수자가 검수를 승인한다. 승인 = 작업 완료다. 검수자 전용.

[승인 → 산출 → 통지 가 한 세트이며 순서가 계약이다] 승인하면 그 영상의 라벨 전체 스냅샷이 버전으로 동결되고 학습데이터 산출 폴더(JSON 과 이미지)가 만들어진다. 완료 통지는 그 산출이 성공한 뒤에만 나간다 — 상태 전이 시점이 아니다. 산출은 비동기라 통지가 먼저 나가면 관제가 아직 만들어지지 않았거나 구버전인 폴더를 픽업한다.

[산출이 실패하면 통지는 보류된다] 유실이 아니라 지연이다. 재산출이 성공하면 그 시점에 통지가 재개된다.

[승인 후 수정은 재승인이 트리거다] 완료된 영상의 라벨·메타를 고치면 그 영상은 다시 검수 대상이 되고, 검수자가 그 수정을 다시 승인한 시점에 이 세트가 다시 돌아 산출 폴더가 새 버전으로 전량 재생성된 뒤 수정 통지가 나간다. 수정만으로는 산출도 통지도 일어나지 않는다 — 학습데이터는 검수를 통과한 것만 확정이기 때문이다. 작업 식별자는 그대로이고 새 식별자를 발급하거나 버전을 올리지 않는다.

[비식별 신고 구간에는 승인 자체가 거부된다] 승인이 라벨 스냅샷을 동결하는데 그 동결이 게이트를 거치기 때문이다(412).

[★재승인 — 이 엔드포인트를 재검토 필요 영상에 다시 호출하는 것(2026-08-08 확정)] 이미 APPROVED 인 영상에 재검토 필요 표시(needsRecheck=true)가 서 있으면 이 엔드포인트를 다시 호출해 승인할 수 있다. 이때 ①작업 상태 전이는 일어나지 않는다 — status/dataSttsCd 는 이미 COMPLETED/APPROVED 이므로 그대로 유지된다 ②응답의 needsRecheck 가 false 로 바뀐다 ③그 사이 축적된 변경분을 실어 학습데이터 산출 폴더 재생성과 관제 수정 통지(TASK_MODIFIED)가 이 시점에 발생한다(EVT-006). 재검토 필요 표시가 서 있지 않은 채로 이미 APPROVED 인 영상을 다시 승인 요청하면 기존과 동일하게 409 CONFLICT 로 거부된다 — 이 구분이 재승인 허용과 기존 거부를 가른다. 최초 승인의 동작·응답 스키마·권한은 이 정책으로 바뀌지 않는다.
