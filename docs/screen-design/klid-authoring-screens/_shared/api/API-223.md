## description

관리자 공유 패스워드를 교체한다. 요구는 셋이 함께 성립해야 한다 — 관리자 역할, 열려 있는 관리 기능 유효창, 그리고 현재 패스워드 재확인이다.

현재 패스워드를 다시 받는 이유는 세션 탈취가 곧 자격 완전 탈취가 되지 않게 하기 위해서다. 유효창만으로 바꿀 수 있으면 잠깐 열린 창을 가로챈 사람이 자격 자체를 갈아 치워 정당한 운영자를 잠글 수 있다.

교체가 성공하면 그 전에 발급된 모든 유효창이 무효가 된다 — 자기 자신이 방금 쓴 세션도 포함된다. 별도의 무효화 장부를 두지 않고 세션 서명이 현재 패스워드에 의존하게 만들어 자연히 검증에 실패하도록 한다. 이어서 관리 기능을 쓰려면 새 패스워드로 다시 진입해야 한다.

새 패스워드는 되돌릴 수 없는 방식으로만 저장하고 평문은 어디에도 두지 않는다. 현재 패스워드도 새 패스워드도 응답과 로그에 다시 나타나지 않으며, 실패 사유에도 값을 실어 보내지 않는다.

저장 위치는 목록 조회로 값이 드러나는 일반 설정 저장소가 아니라 자격 전용 저장 위치다. 그 위치에 값이 아직 없는 최초 상태에서는 배포 설정값이 현재 패스워드 역할을 하며, 교체가 성공하면 그 뒤로는 저장 위치의 값이 판정을 맡는다.

속도 제한은 유효창 발급과 같은 축에서 관리한다. 판정 순서는 인가, 유효창 유효성, 속도 제한, 현재 패스워드 대조 순이다.

이 창구는 관리 기능 진입 요구가 걸린다는 사실을 스스로 표식으로 선언한다. 유효한지 판정하는 일은 단일 지점이 소유하며 이 창구는 그 판정을 복제하지 않는다 — 표식을 읽어 판정 지점에 넘기는 것은 공통 배선의 몫이다.
