> change_summary: 이 창구가 불리는 시점에 두 자리를 더하고, 응답을 반영하는 조건을 하나 밝힌다. 직전 리비전은 재확보 호출을 「화면을 다시 불러올 때」로만 적어, 인계 토큰 값이 같으면 다시 묻지 않아도 되는 것으로 읽혔다. 확정된 흐름에서는 그렇지 않다 — 확보 결과의 재사용은 세션에 종속되므로 세션이 한 번 끊겼다 같은 토큰으로 다시 서면 앞서 받은 응답을 재사용하지 않고 다시 부른다. 즉 이 창구는 인계 토큰 하나당 한 번이 아니라 세션 하나당 한 번이다. 또 이 조회가 실패해 역할을 확인하지 못했다는 안내가 떠 있을 때 사람이 다시 시도하면 다시 부르되, 실패했다고 스스로 되풀이해 부르지는 않는다(자동 반복은 장애 구간에 이 창구로 조회를 몰리게 한다). 응답 쪽에는 도착 시점에 그 조회를 시작한 세션이 그대로인지 확인한 뒤에만 반영한다는 조건을 적었다 — 앞 세션의 응답이 늦게 도착해 새 세션에 실리면 진행 중인 확보의 대기가 조기에 풀려 확보를 마치기 전에는 역할 판정에 도달하지 않는다는 순서가 무너지고, 세션이 없어진 뒤에 확인 실패를 남기면 다음 진입이 근거 없이 오류로 떨어진다. 설명 끝에 두 문단을 덧붙이기만 했고 기존 문장은 한 글자도 건드리지 않았다 — 응답 계약(역할 값역·이름과 역할의 조달원·null 의 뜻)·보안 정의·상태코드·매개변수·예시·링크는 어느 것도 손대지 않았다.

## description

현재 세션 주체의 식별자와 진입 채널, 그리고 저작도구가 보관한 역할과 이름을 조회한다 — 인가에 쓰는 역할의 진실원은 인계 토큰의 역할 클레임이 아니라 저작도구가 보관한 값이고, 화면 상단이 표시하는 이름의 진실원도 이 응답이며 토큰의 이름 클레임은 보조다. 저작도구는 독립 로그인 없이 관제/포털 발급 JWT를 인계받아 진입. 인증된 JWT 이면 역할과 무관하게 접근 가능하다(역할 미배정 사용자 포함) — security 표에 나열된 역할은 접근 제한 목록이 아니라 이 API 를 호출하는 대표 사용자 예시다.

역할 미배정 사용자가 스스로 무권한임을 확인하는 창구다. 다만 그 사용자가 도달하는 창구는 이것 하나가 아니다 — 최초 관리자 등록 창구의 개폐를 묻는 조회(GET /v1/auth/role-claim/availability)와 그 등록 창구(POST /v1/auth/role-claim)에도 도달하며, 셋 다 막으면 아무도 처음 들어올 수 없다. 그 등록 창구는 관리자가 한 명도 없는 동안에만 열리는 부트스트랩 전용이고 부여 역할은 관리자로 고정이라, 역할이 없는 진입자를 어디로 보낼지는 「역할 없음」 하나가 아니라 「역할 없음」과 「창 열림」 두 조건이 정한다.

관리자 단기 유효창은 요구하지 않는다 — 인증된 토큰만으로 된다. 이 창구를 유효창으로 막으면 역할이 없는 사용자가 자신이 무권한임을 확인할 길이 사라져 온보딩 자체가 끊긴다.

이 창구는 최초 진입에 한 번 부르고 마는 자리가 아니다 — 화면을 다시 불러올 때마다 인가 역할을 여기에 다시 물어 확보한다. 이 응답이 알려 준 역할은 그 화면이 살아 있는 동안만 유효한 값이고 인계 토큰과 함께 보존되지 않기 때문이다. 이 재확보 호출은 채널을 가리지 않으며, 역할에 따른 도착지 판정은 그 응답이 온 뒤에 내린다.

다시 부르는 시점은 화면을 다시 불러올 때만이 아니다. 세션이 갈렸다가 다시 설 때도 부른다 — 인계 토큰 값이 같더라도 세션이 한 번 끊겼다 다시 서면 앞서 받은 응답을 재사용하지 않고 이 창구를 다시 부른다. 즉 이 창구는 인계 토큰 하나당 한 번이 아니라 세션 하나당 한 번이다. 사람이 재시도를 요청할 때도 부른다 — 이 조회가 실패해 역할을 확인하지 못했다는 안내가 떠 있을 때 사람이 다시 시도하면 이 창구를 다시 부른다. 다만 실패했다고 스스로 되풀이해 부르지는 않는다. 자동으로 반복하면 장애 구간에 이 창구로 조회가 몰린다.

이 응답을 반영하는 조건이 하나 더 있다. 응답이 도착했을 때 그 조회를 시작한 세션이 그대로인지 확인한 뒤에만 반영한다. 앞 세션의 응답이 늦게 도착해 새 세션에 앞 세션의 역할이 실리면 진행 중인 확보의 대기가 조기에 풀려, 확보를 마치기 전에는 역할 판정에 도달하지 않는다는 순서가 무너진다. 실패 응답도 같다 — 세션이 없어진 뒤에 확인 실패를 남기면 다음 진입이 근거 없이 오류로 떨어진다.
