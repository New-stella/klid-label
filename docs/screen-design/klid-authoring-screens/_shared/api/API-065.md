## description

외부 VLM 서버가 시계열 서술 결과를 콜백으로 전송한다(KLID 연동 API v1.2.0 정합).

[results 는 배열이 아니라 객체다] 시계열 서술 전문(description, 최대 2000자) 한 항목이다. 일치도와 탐지 여부 항목은 이벤트 검증 호출 전용 응답이라 이 콜백으로 들어오지 않는다. 구간별 항목을 배열로 받던 구 규격은 폐기됐다 — 요구가 '시계열을 전문 한 건으로 보여주고 편집 가능하게'였기 때문이다. 벤더가 구 배열을 보내면 관대하게 받아주지 않고 400 으로 거부한다. 무단 하위호환은 벤더 쪽 버그를 숨긴다.

[두 축을 공용으로 수신한다] 서술 생성 호출과 질의응답 호출 두 축의 결과가 같은 콜백으로 들어온다. 콜백 본문에 어느 축의 결과인지 알려주는 항목이 없어, 위탁 시 발급한 요청 식별자로 원장에서 축을 역조회해 그 축의 키로 적재한다.

[적재 규정 — 어느 칸에 넣는가] 서술 생성 호출의 결과는 영상 단위 시계열 메타로 upsert 되어 검수 큐에 들어가고(이벤트 어노테이션의 영상 서술 칸 video.vd_description 이 그 값을 조달한다), 같은 서술에서 「상황」 항목만 뽑아 캡션 후보 첫 항목의 추론 단계 첫 칸(event.caption.c1.cot 의 '1단계')에도 초안으로 넣는다. 질의응답 호출의 결과는 그 캡션 후보의 서술 칸(event.caption.c1.caption_text)에 초안으로 넣고, 그 축의 질문 문장은 질문 칸(event.question)에 채운다. 일치도는 적재하지 않는다 — 이 콜백으로 오지 않는 값이다. 이미 적재된 구 구간 키 행과 기존 일치도 행은 작업 결과라 삭제하지 않고 읽기 전용으로 함께 보여준다.

[「상황」 파싱 규칙] 서술 전문은 '- 라벨: 값' 형태의 줄 묶음으로 오며 그 형식은 확정 계약의 콜백 예시에 명시돼 있다. 「상황」 라벨이 붙은 줄을 찾아 그 줄의 줄바꿈까지를 값으로 쓰고 다음 라벨 줄을 이어붙이지 않는다. 라벨 목록에 의존하지 않는다 — 계약이 항목을 예시로만 들 뿐 전체 목록·순서·필수 여부를 정의하지 않으므로, 「상황」 줄 하나만 찾는 방식이라야 항목이 늘거나 순서가 바뀌어도 성립한다. 「상황」 줄이 없으면 채우지 않는다 — 빈 값을 넣지 않는다. 추론 단계는 첫 칸만 만들고 그다음 칸은 만들지 않는다. 나머지 단계는 사람이 입력한다.

[초안 채움의 보호 경계] 두 축이 같은 캡션 후보를 공유하는데 도착 순서가 보장되지 않으므로, 후보를 통째로 교체하지 않고 자기 칸만 채운다 — 나중에 도착한 축이 먼저 도착한 축의 값을 지우지 않는다. 값이 이미 있는 칸은 덮지 않는다. 승인 이력이 있는 영상과 어노테이션 검토가 종결된 영상은 자동으로 채우지 않는다. 같은 요청 식별자의 중복 콜백은 멱등이다. 자동 채움은 재검수를 발화시키지 않는다. 이벤트 분류 조달값이 없으면 어노테이션 행을 만들지 않는다. 이 규정 이전에 적재된 건은 소급해 채우지 않고 새로 수신하는 건부터 적용한다.

[질문 문장과 근거 서술] 질문 문장은 이벤트별로 외부 서버가 관리하며 우리가 지정하지도 응답으로 받지도 않는다. 따라서 이벤트 유형별 문구를 지어내지 않고, 저작도구가 보관하는 검증 이벤트 유형별 질문 문구 목록에서 조달한다. ★조달은 <위탁 시점>에 일어난다 — 그때 조달한 문구를 요청 본문에 실어 보내고 그 전문을 원장에 보관하며, 이 콜백을 받을 때는 재조달하지 않고 그 보관값을 읽는다(재조달하면 질문 목록이 전체 교체된 사이에 보낸 질문과 기록된 질문이 갈린다). 조달 규칙은 마킹에서 고른 질문이 있으면 그 값, 없으면 그 유형의 첫 번째 질문을 쓴다 — 유형이 미수신이어도 마킹에서 고른 질문이 있으면 그 질문을 쓰고, 실을 문구를 하나도 얻지 못할 때만 비워 둔다. 마킹 화면을 거친 영상은 검증 이벤트 유형과 질문이 반드시 있다 — 유형 선택이 노출된 영상은 유형을 고르지 않으면 마킹을 완료할 수 없고, 자동 마킹도 그 유형의 첫 번째 질문을 자동으로 고른다. 그래서 이 갈래는 마킹 화면을 거치지 않는 경로와 이 규칙 이전에 저장된 기존 행에만 남는다. 답변(answer) 칸은 자동으로 채우지 않는다 — 사람이 확정한다. 근거 서술(evidence) 칸도 채우지 않는다. 그 값은 자유 서술이라 파싱에 기대지 말라고 확정 계약이 못 박는다. 질의응답 결과를 답변 칸 초안으로 넣던 구 규정은 두지 않는다 — 그 축의 결과가 가는 자리는 캡션 후보의 서술 칸이다.

[무서명 콜백을 3계층으로 방어한다] 벤더 규격상 콜백에 서명 헤더가 없어 서명 검증을 요구할 수 없다. 대신 ①호출 IP 허용목록(운영·검증 환경은 명시 설정을 강제한다) ②실패 IP 분당 횟수 제한과 본문 크기 상한 ③위탁 시 저작도구가 발급한 요청 식별자만 처리하는 게이트로 막는다. 콜백 본문에 영상 식별자가 없어 요청 식별자로 원장에서 역조회한다.

[연동 유의사항] 콜백을 받으면 5초 안에 2xx 를 반환한다. 벤더는 2xx 를 받지 못하면 5초 간격으로 최대 3회 재전송하므로 그 재전송을 견뎌야 한다. 이미 처리한 요청 식별자는 본문을 다시 해석하지 않고 2xx 로 응답한다. 위탁 순서와 콜백 도착 순서는 일치하지 않으므로 대응은 오직 요청 식별자로 한다. 서술은 자연어 평문이라 본문 전체의 의미를 문자열 파싱으로 재구성하는 처리에 의존하지 않는다 — 확정 계약이 형식을 명시한 「상황」 줄 하나를 뽑는 것만 그 예외이며, 그 파싱이 실패해도 서술 전문 적재는 그대로 유지된다.

[상태별 처리] completed 는 결과를 적재하고 대기 중이던 마킹을 완료로 전이한다. failed 는 적재 없이 오류만 남기고 마킹을 실패로 전이해 고착을 푼다. 같은 요청 식별자를 다시 받으면 멱등 스킵하며 응답의 적용 여부 필드로 그 사실을 알린다.

[전부 한 트랜잭션이다] 요청 식별자 원장의 처리 완료 표시까지 같은 트랜잭션이라, 중간에 실패하면 함께 롤백되어 벤더 재전송으로 복구된다. 다만 어노테이션 초안 채움은 그 경계 밖이다 — 초안 채움이 실패해도 서술 전문 적재와 요청 식별자 처리 완료 표시를 되돌리지 않는다.
