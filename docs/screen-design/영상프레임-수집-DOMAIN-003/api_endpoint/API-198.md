## description

★단위는 개별 단계가 아니라 작업 묶음이다 — 시계열(VLM)과 오토라벨(AI 탐지 · AI 분할 · 트랙 보간)이며, 오토라벨은 쪼개서 부분 수행하지 않는다. 뒤 단계가 앞 결과를 입력으로 받고 보간이 그 산출물을 재계산하므로 일부만 수행하면 산출물끼리 어긋나기 때문이다. 보간을 묶음 밖에 두면 어떤 재수행에서도 보간이 무조건 돌아 사람이 손댄 보간 라벨을 지운다 — 묶음이 그 사고를 구조적으로 없앤다.
실패한 배치 단계를 건너뛰고 파이프라인을 진행시킨다. ★대상은 그 묶음이 실패한 영상뿐이다 — 정상 진행 중이거나 이미 끝난 묶음은 이 경로로 건너뛸 수 없다. 정상 영상을 미리 골라 건너뛰는 길은 두지 않는다. 그렇게 두면 이미 들어와 있는 영상만 덮어 뒤에 들어오는 영상은 매번 다시 골라야 하고, 근거 없이 정상 영상을 건너뛸 수도 있기 때문이다. 미연동 구간을 통째로 덮는 몫은 전체 설정이 맡아 배치가 위탁 단계에 진입하기 직전 자동으로 표식을 남긴다. 두 입구가 남기는 표식은 같은 이력에 같은 종류로 쌓이며 사유 본문으로만 구분된다. 대상은 시계열과 오토라벨 두 묶음이며, 건너뛰어도 데이터가 영구히 사라지지 않기 때문에 허용한다 — VLM 을 건너뛰면 영상 서술이 사람이 직접 쓴 전문으로 폴백하고, 오토라벨을 건너뛰면 프레임은 남고 작업자가 처음부터 라벨링한다. 사유는 필수이며 배치 이력에 남는다. 산출물 내용이 달라지는 조작이라(시계열 서술 없음 · 자동 라벨 없음) 나중에 그 영상의 시계열이 왜 비어 있는지 되짚을 수 있어야 하기 때문이다. ★ 이때 남기는 사유 값은 비식별 신고가 해소될 때 재개 대상으로 집히는 보류 사유와 반드시 구분되는 별도 값이어야 한다. 같은 값을 쓰면 훗날 재개 절차가 그 기록을 집어 사람이 내린 결정을 뒤집고 외부에 다시 위탁한다. 건너뛰기는 해제할 수 있으며 해제는 같은 하위 리소스의 DELETE 가 담당한다. 다만 재수행이 건너뛴 상태를 직접 수락하므로 되살리려고 해제를 먼저 부를 필요는 없다.
★「그 묶음이 실패한 상태인가」의 판정은 묶음마다 다르며, 그것이 정상이다. 오토라벨은 진행 기록이 실패로 남으면 실패다. 반면 시계열 위탁은 논블로킹 제출이라 실패해도 예외가 위로 올라가지 않고 뒤 단계가 그대로 완주하므로 진행 기록이 실패가 되지 않는다 — 시계열은 위탁 결과를 끝내 받지 못했다는 기록(제출 실패 · 수락 응답 미수신 · 콜백 미수신)으로만 실패를 읽는다. 두 축을 하나로 통일하면 시계열 건너뛰기가 영영 열리지 않는다. 스스로 재개되는 보류 사유는 실패로 읽지 않는다 — 그것까지 실패로 보면 정상 영상을 건너뛰는 통로가 다시 열려 이 게이트의 존재 이유가 사라진다.
⚠ 알려진 한계 — 외부 벤더가 실패를 결과로 회신한 영상은 이 판정에 잡히지 않아 건너뛸 수 없다. 그 회신은 배치 진행 기록을 남기지 않고 마킹 상태만 바꾸기 때문이다. 마킹 상태를 판정에 더하면 잡히지만, 재개가 성공한 뒤에도 그 상태가 종결값으로 남아 실제보다 넓게 허용하게 되므로 덜 허용하는 쪽을 골랐다. 필요해지면 판정 지점 한 곳만 넓히면 된다.
