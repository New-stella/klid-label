## scenario

### then

- 발급처(iss)를 검증한다 — iss 클레임이 없는 경우를 통과시킨다. iss 가 있는데 허용목록 밖이면 여전히 거부한다. 시크릿 서명검증과 exp(만료) 필수는 그대로 유지한다
- 채널 표식으로 내부/포털이 갈린다(표식 없으면 내부)
- 내부 채널이면 저작도구가 보관한 역할로 인가를 해석한다 — userId 클레임으로 저작도구 마스터 LS_ACNT_USER.USER_ID 로 조회한다. 다중 매칭이거나 0건 매칭이면 fail-closed 로 무권한 처리한다(CWE-639). 기존 숫자 sub(USER_NO) 식별 경로는 그대로 두고 바꾸지 않는다
- 역할 없는 내부 진입자는 작업자로 자동 등록되고 배정 대상 목록에 나타난다(기존 역할 미덮음). 단 개발용 로그인이 발급하는 표준 계정은 이 자동 등록 대상이 아니라 역할 없는 상태로 남는다
- 관리자는 검수자 자리를 계층으로 물려받되 작업자 전용 자리는 열리지 않는다
- 세션 만료 시 각 상위 시스템 로그인 화면으로 되돌아간다
- 내부 채널에서 비숫자 sub 를 userId 로 저작도구 마스터 LS_ACNT_USER.USER_ID 에서 유일 해석하면, principal 의 주체 식별자(sub)가 해석된 userNo(문자열)로 정규화되어 이후 per-user 스코핑·소유권·감사·작업 잠금이 raw 로그인 ID 가 아니라 실제 userNo 를 본다. 숫자 sub(USER_NO, 내부·포털) 경로는 정규화 전후 값이 같아 동작이 동일하다(회귀 없음)

## statement
