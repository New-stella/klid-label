## scenario

### then

- 목록이 서버 페이징 20건/페이지·등록 순서로 조회된다(API-001)
- 검색·필터 확정 시에만 서버 재조회되고 1페이지로 리셋된다
- 계정 활성 배지는 외부 소유 읽기 전용으로 표시만 된다
- 고른 축의 값만 PATCH(API-004)로 전송되고 유효창이 가산 요구된다
- 서버가 허용 역할 화이트리스트로 재검증하고 성공 시 즉시 반영·목록 최신화한다
- 역할을 바꾼 사람이 개인 단위로 변경 기록에 남는다
- 역할과 표시 이름은 각각 고를 수 있고, 보내지 않은 축은 그대로 둔다
- 표시 이름은 앞뒤 공백과 제어문자를 걷어낸 뒤 판정한다
- 정규화한 표시 이름이 이미 저장된 값과 같으면 아무것도 바뀌지 않고 수정일시도 밀리지 않는다
- 표시 이름만 고치는 쓰기에도 같은 관리자 유효창이 요구된다(조회에는 불필요)
- 검수자·작업자는 이 쓰기를 열지 못한다
- 바뀐 표시 이름은 저장값을 읽는 자리(사용자 목록·작업 배정·검수 화면·이력 작성자 표시)에 반영된다
- 본인 화면 상단의 이름은 인계 토큰의 이름을 먼저 쓰므로 바뀌지 않는다(보관값은 토큰에 이름이 없을 때만 조달된다)
- 표시 이름 수정은 수정일시만 남기고 수정자 칸을 두지 않는다

### when

- 목록을 조회·검색·필터하고, 수정 모달에서 역할을 골라 저장한다
- 같은 수정 모달에서 표시 이름만 고쳐 저장하거나, 역할과 표시 이름을 함께 고쳐 저장한다
- 이미 저장된 것과 같은 표시 이름을 다시 보내 저장한다

### given

- 관리자 역할로 인증되어 있다
- 역할·표시 이름 변경 시 유효한 관리자 단기 유효창이 열려 있다(조회에는 불필요)

## statement

관리자(ADMIN)가 /admin/users(SCREEN-024)에서 사용자 목록을 조회하고(GET /v1/users=API-001, 서버 페이징 20건/페이지, 등록 순서 고정) 이름·이메일 부분일치 검색과 역할 필터(전체/관리자/검수자/작업자/포털)를 확정하면 서버가 재조회해 1페이지로 리셋한다. 행의 계정 활성 배지는 외부(관제) 소유 읽기 전용이다. '수정' 모달에서 역할이나 표시 이름을 골라 저장하면 고른 축의 값만 PATCH /v1/users/{userNo}(API-004)로 보내며, 이 쓰기는 유효한 관리자 단기 유효창을 함께 요구한다(역할을 대체하지 않고 가산, 승격 아님). 서버가 허용 역할 화이트리스트로 재검증하고 성공 시 즉시 반영·목록 최신화하며 바꾼 사람을 개인 단위로 기록한다. 두 축은 각각 고를 수 있고 보내지 않은 축은 그대로 둔다. 표시 이름은 앞뒤 공백과 제어문자를 걷어낸 뒤 판정하므로, 정규화한 결과가 이미 저장된 값과 같으면 아무것도 바뀌지 않고 수정일시도 밀리지 않는다. 이 쓰기는 표시 이름만 고치는 경우에도 같은 관리자 유효창을 요구하며 관리자만 열 수 있다. 바뀐 표시 이름은 저장값을 읽는 자리(사용자 목록·작업 배정·검수 화면·이력 작성자 표시)에 반영되지만, 본인 화면 상단의 이름은 인계 토큰의 이름을 먼저 쓰므로 바뀌지 않는다(보관값은 토큰에 이름이 없을 때만 조달된다). 표시 이름 수정은 수정일시만 남기고 수정자 칸을 두지 않는다.
