## description

사용자 정보를 부분 수정한다. 이 창구에서 쓰기 가능한 것은 역할뿐이며, 계정 활성 여부는 외부 시스템(관제서버) 소유값이라 이 화면에서는 읽기 전용이다.

역할을 바꾸는 것은 운영·관리 성격의 쓰기이므로 관리자 역할에 더해 유효한 관리자 단기 유효창을 함께 요구한다. 유효창은 관리자 역할을 대체하지 않고 가산된다 — 역할은 그대로 필요하며 유효창이 역할을 승격시키지도 않는다. 지정할 수 있는 역할은 ADMIN·REVIEWER·WORKER·PORTAL_USER 이며, 마지막 남은 ADMIN 을 다른 역할로 내리는 요청은 409 로 거절한다 — ADMIN 이 0명이 되면 부트스트랩 창구가 다시 열리기 때문이다. 이 판정은 조회 후 갱신이 아니라 갱신 문장 자체가 조건을 함께 판정해야 한다. 두 노드가 서로를 동시에 내리면 각자 조회 시점에는 둘 다 통과해 결과적으로 ADMIN 이 사라진다. 관리자 설정 세션이 발급한 단기 토큰을 X-Admin-Session 헤더로 함께 보내고, 토큰이 없거나 만료됐으면 403 이다. 상태코드와 오류 코드로는 두 거부 사유가 구분되지 않는다 — 관리자 역할이 없어서인지 유효창이 없어서인지 그 값만으로는 알 수 없다. 다만 안내 문구는 다르다. 유효창이 없거나 끝난 경우에는 다시 인증할 수 있는 자리를 안내하고, 관리자 역할이 없는 경우에는 권한이 없다고만 말한다. 그러지 않으면 막힌 사용자가 왜 막혔는지 알 수 없어 재인증 동선 자체가 성립하지 않는다. 그 대가는 인지하고 받아들인다 — 두 요청을 비교하면 자신의 역할 상태를 짐작할 수 있으나, 짐작 대상이 자기 자신의 역할이고 그 대가로 얻는 것은 막힌 사용자가 스스로 회복할 길이다. 유효창 거부의 문구는 실패 사유가 무엇이든 같다 — 토큰이 없든, 유효기간이 끝났든, 위조됐든, 다른 사람의 것이든 한 가지 문구다. 그 안에서 갈리면 응답이 유효창의 상태를 알려주는 창이 된다. 거부 응답에 남은 시간이나 발급 여부 같은 유효창의 상태값을 싣지 않는다.

유효창이 유효한지 판정하는 일은 단일 지점이 소유한다 — 어느 창구도 그 판정을 복제하지 않으며, 판정 규칙이 바뀔 때 고칠 자리가 하나다. 어느 요청에 이 요구가 걸리는지는 창구가 스스로 선언하고, 그 선언을 읽어 판정 지점에 넘기는 것은 공통 배선의 몫이다. 창구가 들고 있는 것은 요구가 걸린다는 선언뿐이고 판정 자체가 아니므로 이것은 판정의 복제가 아니다. 판정을 수행 계층으로 내리는 안은 채택하지 않는다 — 그러면 수행 계층이 요청 헤더를 알아야 해 계층 규칙과 충돌하고, 결국 창구에서 값을 넘겨주는 배선이 다시 생겨 같은 자리로 돌아온다. 경계해야 할 실패 양식은 그대로 유효하다 — 역할을 바꾸는 진입점이 새로 생겼는데 그 선언이 조용히 빠지는 것. 선언은 사람이 붙이는 것이라 빠뜨려도 아무 신호가 나지 않으므로, 그 부재를 사람의 주의력이 아니라 기계가 잡는 정적 검사를 둔다.

유효창 토큰은 발급받은 사람에게 묶여 있어 다른 사람의 것을 쓸 수 없고, 요청 자체는 여전히 본인 자격으로 인증된다. 그래서 공유 패스워드로 연 유효창이어도 변경 기록에는 실제 행위자가 개인 단위로 남는다.

같은 자원의 조회에는 이 요구를 두지 않는다. 사용자 목록·상세 조회뿐 아니라 다른 업무 화면이 작업자 목록을 읽는 경로도 검수자 권한만으로 된다 — 조회까지 막으면 작업 배정 흐름이 끊긴다.
