## description

포털 라벨링 화면의 AI 자동 추적 창구다. 정렬된 프레임 시퀀스를 추론 서버의 객체 추적 경로로 프레임마다 보내 객체 검출(label/labelId/points/score/trackId)을 받는다. frameIndex 는 0-base 이고 첫 프레임에서 추적기를 리셋하며, 추적 세션은 시작 프레임이 속한 영상 단위로 격리한다. 순수 조회 프록시라 결과를 저장하지 않는다 — 화면이 결과를 작업본에 올린 뒤 기존 포털 라벨 저장 창구로 확정한다. 대상 영상은 데이터마트에서 불러온 영상과 포털 사용자가 직접 올린 영상 둘 다다.

★요청·응답 본문은 내부 AI 자동 추적 창구([[API-123]])와 같은 계약이다. 시간 예산 절단(truncated)과 이어 보내기 값(resume), 빈 후속 프레임 목록을 정상 요청으로 받는 규칙, 이어 보내면 추적기가 리셋되어 객체 식별자가 새로 매겨진다는 성질, 절단 사실을 응답 메시지 문구로 싣지 않는 규칙, 취소 식별자 헤더와 취소 전용 응답 코드까지 그 창구의 서술이 그대로 적용된다. 단 취소 요청은 포털 취소 창구([[API-258]])로 보낸다 — 내부 취소 창구 [[API-204]] 와 같은 계약이지만 그 창구는 내부 채널 전용이라 포털 토큰으로는 닿지 않는다. 한쪽 계약만 고치면 같은 라벨링 코어가 채널에 따라 다르게 동작하므로 두 창구의 본문 계약은 함께 움직인다.

내부 창구를 포털 채널에 여는 대신 이 창구를 따로 둔다 — 두 채널은 인가 주체가 다르고([[ADR-012]]), 내부 창구가 전제하는 본인 배정 검증·비식별 신고 거부·재비식별 작업락이 포털 자산에는 성립하지 않기 때문이다. 제공 결정은 [[ADR-013]] 이 담는다. 이 창구는 포털 회원 역할과 포털 채널 토큰으로만 호출할 수 있고, 반대로 포털 토큰으로 내부 창구를 부르는 것은 계속 거부된다. 소비 화면은 [[SCREEN-029]] 이고 흐름은 [[UC-034]] 를 따른다.

[인가] 시작 프레임과 후속 프레임 전부를 하나씩 포털 작업 대상으로 판정한다. 포털 작업 가능 영상(검수 완료 영상 또는 포털 데이터셋에서 등록한 영상)의 프레임이거나 본인이 올린 자산의 프레임이면 통과한다. 프레임 행이 없으면 404, 남의 자산이거나 포털 작업 가능 영상이 아닌 영상이면 403 이며 두 경우를 같은 문구로 돌려준다 — 문구가 갈리면 응답이 남의 자산이 실재한다는 단서가 된다. 후속 프레임이 시작 프레임과 다른 영상에 속하면 400 이다 — 한 요청으로 여러 영상의 프레임을 섞지 못하게 한다. 경로의 srcSn 과 본문의 srcSn 이 다르면 400 이다.

[입력 이미지] 추론 입력은 포털 화면이 그 프레임에 서빙하는 이미지와 같은 파일이며, 출처별 포털 프레임 이미지 서빙과 같은 경로 판정을 쓴다. 판정을 따로 만들지 않는 이유는 서빙과 추론 입력이 갈리면 사용자에게 보이지 않는 픽셀이 추론 서버로 나가는 경로가 생기기 때문이다. 이미지 파일이 없으면 404, 허용 경로 밖이면 403 이다.

[비식별] 비식별 누락 신고 거부(412)와 재비식별 작업락(409)은 이 창구에 두지 않는다. 포털에는 비식별 파이프라인이 없고, 입력은 이미 사용자에게 보이는 이미지와 같은 파일이다.

[요청량] 외부 채널이라 사용자별 요청량 제한을 두고 초과하면 429 로 즉시 거부한다(대기하지 않는다). 한도는 포털 AI 탐지·AI 분할·AI 자동 추적 세 실행 창구가 사용자마다 하나를 공유한다. 한도는 자동 추적의 이어 보내기 연속 호출(예산 절단 후 남은 프레임을 잇는 요청)을 끊지 않을 만큼으로 정한다 — 이어 보내기가 한도에 걸리면 추적이 중간에 끊겨 사용자가 처음부터 다시 실행하게 된다. 포털 사용자 요청은 내부 작업자와 같은 추론 자원을 쓰므로 이 한도가 한 사용자의 연타가 내부 추론까지 막는 것을 완화한다.

[대기 상한] 화면은 포털 AI 기본값 조회 창구([[API-256]])가 내려주는 작업 종류별 대기 예산으로 이 실행의 대기 상한을 구하며, 그 값은 내부 채널과 같다.
