## description

검수 상태 4종 건수를 필터 결과 전체 기준으로 반환한다(현재 페이지가 아니다). 페이지 단위로 세면 숫자가 틀리므로 집계는 서버가 한다.

[필터] q 는 검수 목록과 동일하게 반영된다.

[★ status 무시] status 는 전달돼도 무시한다 — KPI 카드 자체가 status 선택지이므로 이미 status 로 좁혀진 집합 위에서 세면 항상 1개 카드만 값을 갖는다.

[★ sort 미수용] sort 는 파라미터로 받지 않는다 — 목록과 동일한 쿼리스트링(sort 포함)을 그대로 보내도 무시될 뿐 400 이 아니다(목록의 정렬 폴백 정책과 동일한 취지).

[불변식] total == pending + inReview + approved + rejected. 집계 대상이 검수 워크플로 상태 4종으로 한정되고 버킷도 같은 4종이라 구조적으로 성립한다 — 검수 대상이 아닌 배치·작업 상태는 어느 버킷에도 합산되지 않는다. 검수 상태가 5종으로 늘어나면 total 만 조용히 과소집계되므로, 버킷에 매핑되지 않은 상태가 들어오면 응답을 만들지 않고 즉시 실패한다.

[스냅샷] 목록과 별도 요청이므로 각 값은 조회 시점 스냅샷이다.
