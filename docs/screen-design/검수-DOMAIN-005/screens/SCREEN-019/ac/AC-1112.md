# UC-023 검수 시작 충돌 — 타인 점유는 점유자 이름과 함께 거절, 동시 경합의 결말은 갈래마다 다르다 (negative)

## priority

high

## scenario

### then

- 타인 점유이면 상태와 무관하게 거절되고 응답에 점유자의 표시 이름이 실린다
- 사용자 식별자·역할·소속처럼 요청자가 알 필요 없는 정보는 실리지 않는다
- 상태를 전이하는 갈래의 동시 경합이면 한 건만 성공하고 밀린 쪽은 충돌로 안내되며 점유자의 표시 이름은 실리지 않는다
- 두 사유는 안내 문구로 구분되고 안내 없이 다른 오류로 새지 않는다
- 유예가 지나 점유가 풀리면 같은 영상의 검수 시작이 다시 받아들여진다
- 상태를 건드리지 않는 갈래의 동시 경합이면 둘 다 성공 응답을 받고 나중에 누른 검수 시작이 점유를 가져간다
- 그 갈래에서 밀린 쪽은 거절되지 않으며, 목록을 다시 보면 실제 점유자가 드러나고 일괄 승인을 시도하면 자격 판정에서 걸린다
- 승인 시점의 동시성 보호가 그대로 살아 있어 데이터 정합은 이 경합과 무관하게 지켜진다

### when

- 검수 시작을 요청한다

### given

- 검수를 시작하려는 영상을 다른 사람이 유효하게 점유 중이거나, 두 사람이 같은 영상의 검수 시작을 동시에 누른다

## statement

검수 시작이 막히는 사유는 둘이고, 동시 경합의 결말은 갈래마다 다르다. 첫째, 다른 사람이 그 영상을 유효하게 점유 중이면 상태와 무관하게 거절한다 — 점유 판정이 상태 판정보다 앞선다. 이때 응답에 점유자의 표시 이름을 실어 누가 보고 있는지 알리고, 사용자 식별자·역할·소속처럼 요청자가 알 필요 없는 정보는 싣지 않는다. 유예가 지나 점유가 풀리면 같은 영상의 검수 시작이 다시 받아들여진다. 둘째, 두 사람이 같은 영상의 검수 시작을 거의 같은 순간에 누르면 결말이 갈래마다 다르다. 상태를 전이하는 갈래(검수 대기 → 검수 진행)에서는 상태 원장의 동시성 보호가 뒤늦은 쪽을 거절하고 충돌로 안내한다 — 승인·반려가 같은 상황에서 쓰는 것과 같은 방식이며 안내 없이 다른 오류로 새지 않는다. 상태를 전이하는 갈래는 이 하나뿐이고, 그 밖의 갈래는 모두 상태를 건드리지 않아 그 보호가 걸릴 자리가 없다 — 상태를 내리지 않는 것이 이 설계의 핵심이기 때문이다. 예컨대 같은 사람이 다시 들어오는 경우, 유예가 만료된 검수 진행 건을 다른 사람이 이어받는 경우, 재검수 대기 상태인 승인 건이 그렇다. 상태를 건드리지 않는 갈래에서는 나중에 누른 검수 시작이 점유를 가져가고, 밀린 쪽은 성공 응답을 받지만 점유의 주인이 아니다. 밀린 쪽은 목록을 다시 보면 실제 점유자가 드러나 화면이 스스로 정정하고, 일괄 승인을 시도하면 자격 판정에서 걸린다. 거절이 나가는 갈래에서 밀린 쪽에는 점유자의 표시 이름을 싣지 않는다. 점유 충돌과 경합 패배는 사유가 달라 안내 문구로 구분한다. 데이터 정합은 이 경합과 무관하게 지켜진다 — 승인 시점의 동시성 보호가 그대로 살아 있고, 점유는 잠금이 아니라 표시라 둘은 서로를 대체하지 않는다. 한쪽이 이미 유효한 점유를 갖고 있으면 그것은 경합이 아니라 정상 거절이며, 경합이 성립하는 창은 둘 다 점유를 확인한 뒤 둘 다 기록하기 전까지로 매우 좁다. 거절이 나가는 갈래는 스레드를 겹치지 않고도 재현된다 — 두 요청이 같은 상태를 읽은 뒤 한쪽을 먼저 확정시키면 뒤늦은 쪽이 결정적으로 거절되므로 자동으로 검증한다. 상태를 건드리지 않는 갈래는 나중이 이기는 것이 기대 동작이라, 밀린 쪽이 거절받지 않는 것이 정상임을 함께 확인한다.
