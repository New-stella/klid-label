# 포털 서버 Apache(httpd.conf) 수정 요청 — 저작도구 MF Remote 서빙

> 작성일: 2026-09-10
> 대상: 포털 인프라 담당
> 기준 파일: 2026-09-10 전달본 `httpd.conf` (`/authoring/`·`/authoring-api/` 로 개명된 판)
> 검증 방법: 이 문서의 모든 「실측」은 ①개발망 <개발망 호스트> 직접 조회 ②같은 설정을
> 로컬 Apache 2.4.62 에 올려 재현 ③포털 Host 를 실제로 띄워 저작도구 번들과 결합 — 셋으로 얻었다.

## 1. ★차단 — `/authoring-api/` 가 접두어를 뗀다

### 현재 (전달본 110~112행)

```apache
ProxyPass        /authoring-api/ balancer://klid-authoring-was/
ProxyPassReverse /authoring-api/ balancer://klid-authoring-was/
```

대상 끝의 `/` 때문에 `/authoring-api/` 부분이 **잘려서** WAS 로 간다.

### 왜 문제인가

저작도구 WAR 는 **웹 컨텍스트에 그 접두어를 포함해서** 배포된다(`WEB-INF/jboss-web.xml` 의
`context-root`, Jenkins `klid 저작도구 was` 잡의 `KLID_WEB_CONTEXT`). 접두어를 떼면 WAS 가
컨텍스트 밖 경로를 받아 **전건 404** 다.

### 실측

같은 설정을 로컬 Apache 에 올리고, 컨텍스트를 가진 WAS 를 흉내낸 스텁에 붙여 측정했다.

| 프록시 형태 | WAS 가 실제로 받은 경로 | 결과 |
|---|---|---|
| 접두어 제거 (전달본) | `/actuator/health/liveness` | **404** |
| 접두어 유지 | `/authoring-api/actuator/health/liveness` | **200** |

그리고 **지금 개발망에서 돌고 있는 설정은 「접두어 유지」** 다 — 2026-09-10 조회에서
`http://<개발망 호스트>:38081/author-api/actuator/health/liveness` 가 **200 `{"status":"UP"}`** 을
돌려주었다. 즉 전달본을 그대로 적용하면 **현재 정상 동작 중인 API 가 죽는다.**

### 요청

```apache
ProxyPass        /authoring-api/ balancer://klid-authoring-was/authoring-api/
ProxyPassReverse /authoring-api/ balancer://klid-authoring-was/authoring-api/
```

> ⚠ **저작도구 쪽에서 함께 바꿔야 하는 값이 있다.** 접두어를 `/author-api/` → `/authoring-api/`
> 로 개명하시면 저희가 WAR 웹 컨텍스트와 프론트 API 주소를 같이 맞춥니다(§6).
> **한 곳만 바뀌면 아무 신호 없이 조용히 깨집니다** — WAS 는 정상 기동하고 배포도 성공하며
> 화면까지 뜨는데 API 만 전건 404 입니다.

## 2. ★결정 필요 — 번들 서빙 경로 이름

### 무엇이 어긋났나

| | 전달본 httpd / 빌드 요청 문서 | **포털 프론트(Host) 실제 코드** |
|---|---|---|
| 번들 서빙 경로 | `/authoring/` | **`/label-remote/`** |
| 노출 모듈 이름 | `./App` | **`./PortalApp`** |
| Host 의 remote 참조 | 절대 URL `https://<개발망 호스트>:38444/...` | **상대경로**(같은 origin 전제) |

포털 Host 는 **2026-09-09 에 MF 배선을 완료**했고(`feat(authoring-mf): 저작도구 MF Host 배선을
마치고 …`), 그 코드는 `/label-remote/remoteEntry.js` 를 참조한다. 이 값들은 2026-08-26 에
포털팀이 정해 저작도구에 통보한 계약값이며, 저작도구 설계 `INT-013` 의 정본이기도 하다.

빌드 요청 문서는 *"포털 프론트가 Host 설정을 붙이면"* 이라고 앞으로 할 일처럼 적었는데,
**이미 끝나 있다.** 인프라 담당자와 포털 프론트 담당자 사이의 정보 격차로 보인다.

### 실측 — 어느 이름이든 저작도구는 재빌드 없이 동작한다

포털 Host 를 실제로 띄우고, 저작도구 번들(자산 base 는 `/label-remote/` 로 구운 것)을
`/authoring/` 에서 서빙해 결합시켰다.

| 확인 항목 | 결과 |
|---|---|
| 진입 파일 | ✅ `/authoring/remoteEntry.js` |
| 청크 | ✅ `/authoring/assets/*.js` — **`/label-remote/` 요청 0건** |
| CSS | ✅ `/authoring/assets/*.css` 링크 정상 주입 |
| 화면 렌더·라우팅 | ✅ 정상 |
| React 중복 경고 | ✅ **0건** (singleton 협상 성공) |

Vite 가 청크를 자기 모듈 위치 기준(`import.meta.url`)으로 풀기 때문에 **번들이 서빙 위치에
묶이지 않는다.** 그래서 이건 기술 제약이 아니라 **이름을 어디에 맞출지의 결정**이다.

### 비용 비교

| | **A. `/label-remote/` 로 통일** (권장) | **B. `/authoring/` 로 통일** |
|---|---|---|
| 인프라 | Alias 문자열 1개 | 없음 |
| 포털 Host | **변경 0** | 상수 **2곳**(`vite.config.ts` · `remote-preflight.ts`) + 재배포 |
| 저작도구 | **변경 0** | 계약 상수 1곳 + 빌드 가드 문구 + Jenkins |
| 설계 정본 | 변경 0 | `INT-013` 개정 |

**A 를 권한다** — 양쪽이 이미 그 값으로 구현·검증을 마쳤고 바꿀 것이 Alias 문자열 하나뿐이다.
다만 B 도 기술적으로 막힘없이 되므로, **포털 프론트 담당자와 합의해 하나로 정하면 된다.**
아래 설정 예시는 `{서빙경로}` 로 표기했다.

## 3. ★캐시 헤더 — 빠지면 배포할 때마다 포털 화면이 깨진다

MF 번들은 두 종류로 갈린다.

- `remoteEntry.js` — **파일명에 해시가 없다**(Host 가 주소를 알아야 하므로 붙일 수 없다).
  내용이 바뀌어도 주소가 그대로라, 캐시를 두면 브라우저가 **옛 진입 파일**을 계속 쓴다.
  그 파일이 가리키는 청크는 이미 지워져 있어 **저작도구 영역이 아니라 포털 화면이 통째로 깨진다.**
- `assets/*` — 파일명에 해시가 박혀 있다. 내용이 바뀌면 주소가 바뀌므로 **장기 캐시가 안전**하고,
  안 걸면 청크 수십 개를 매 진입마다 다시 받는다.

```apache
<IfModule mod_headers.c>
    # (기존 전역 no-store 블록 «아래»에 둔다)

    # 해시 붙은 청크 — 길게
    <LocationMatch "^/{서빙경로}/assets/">
        Header unset Pragma
        Header unset Expires
        Header set Cache-Control "public, max-age=31536000, immutable"
    </LocationMatch>

    # 진입 파일만 재검증. ★ 반드시 위 블록보다 «뒤»에 와야 한다
    #   (같은 종류의 컨테이너는 설정 파일에 적힌 순서대로 적용된다)
    <Location "/{서빙경로}/remoteEntry.js">
        Header unset Pragma
        Header unset Expires
        Header set Cache-Control "no-cache, must-revalidate"
    </Location>
</IfModule>
```

> `no-cache` 는 「캐시 금지」가 아니라 「쓰기 전에 서버에 물어본다」는 뜻이라, 안 바뀌었으면
> 304 로 끝난다 — `no-store` 보다 싸고 목적(최신성 보장)에는 충분하다.

### 실측 (이 순서로 걸었을 때)

| 대상 | Content-Type | Cache-Control |
|---|---|---|
| `remoteEntry.js` | `text/javascript` | `no-cache, must-revalidate` ✅ |
| `assets/*.js` | `text/javascript` | `public, max-age=31536000, immutable` ✅ |
| `assets/*.woff2` | `font/woff2` | `public, max-age=31536000, immutable` ✅ (기존 `<FilesMatch>` 가 이미 처리) |
| 없는 청크 | — | **404** ✅ |

## 4. 권장 — 같이 손보면 좋은 것

### 4-1. 압축(`mod_deflate`) — 실측 4배 차이

개발망 응답에 `Content-Encoding` 이 없다. 저작도구 포털 채널 번들 실측:

| 항목 | 크기 |
|---|---|
| CSS 1개 | **870,476 B** |
| JS 47개 | 약 1.4 MB |
| 폰트 2,164개 | 약 50 MB (한글 서브셋) |

같은 CSS 를 gzip 켜고 측정하면 **243,917 B (72% 감소)** 다.

```apache
# LoadModule 에 mod_filter 도 함께 필요하다
LoadModule filter_module  modules/mod_filter.so
LoadModule deflate_module modules/mod_deflate.so

<IfModule mod_deflate.c>
    AddOutputFilterByType DEFLATE text/html text/css application/javascript text/javascript application/json
</IfModule>
```

### 4-2. `ProxyTimeout` — 대용량 업로드

포털 업로드는 영상 5GB 까지 받는다. 전역 120초는 짧으니 워커 단위로 늘리는 편이 안전하다.

```apache
<Proxy balancer://klid-authoring-was>
    BalancerMember http://127.0.0.1:49080 route=authoring01 timeout=600
    ProxySet lbmethod=byrequests
</Proxy>
```

### 4-3. 시스템간 창구 IP 제한

포털은 자기 `/api/internal/` 에 `Require ip` 를 걸어 두었는데, 반대 방향(포털 → 저작도구)
창구에는 없다. 대칭으로 걸어 주기 바란다.

```apache
<Location "/{API접두어}/v1/portal-system/">
    # 기존 `/api/internal/` 블록의 «같은 목록»을 그대로 쓴다.
    #   (등록 파트너망 주소는 이 문서에 옮겨 적지 않는다 — 운영 문서 IP 평문 금지 규칙)
    Require ip <파트너망 #1>
    Require ip <파트너망 #2>
    Require ip <파트너망 #3>
    Require ip <파트너망 #4>
    # 개발 로컬 테스트용 루프백. ⚠ 상용엔 넣지 말 것.
    Require ip 127.0.0.1
    Require ip ::1
</Location>
```

### 4-4. `/authoring-repo/` 제거 요청

저작도구는 **이미지·영상을 전부 백엔드 경유로** 낸다 — 프레임 이미지는 인증 헤더를 붙여
받고, 영상 재생은 단기 서명 주소를 발급받아 쓴다. Apache 가 NAS 를 직접 열면 그 접근 판정이
통째로 우회된다(개인정보 노출 경로). **저작도구는 이 경로를 사용하지 않는다.**

### 4-5. 사소한 것

- 번들 `<Directory>` 에 `Options -Indexes +FollowSymLinks` 로 명시하면 더 안전하다
  (현재 `mod_autoindex` 가 로드돼 있지 않아 실질 위험은 없다).
  ⚠ `Options -Indexes FollowSymLinks` 처럼 `+`/`-` 를 섞으면 **아파치가 기동하지 못한다**
  (`Either all Options must start with + or -`). 로컬에서 실제로 확인했다.
- 맨 끝 `RewriteEngine On` 은 규칙이 하나도 없어 아무 일도 하지 않는다. 정리하거나 그대로 둬도 무해하다.
- 저작도구 MF 산출물에는 `index.html` 이 함께 들어간다. 남겨두면 `/{서빙경로}/` 를 직접 열었을 때
  반쪽 화면이 뜬다 — 무시해도 되고, 배포 시 빼도 된다(Host 는 그 파일을 쓰지 않는다).

## 5. 최종 반영본 (복붙용)

`{서빙경로}` 와 `{API접두어}` 는 §2·§1 에서 정한 값으로 바꾼다.
(권장 조합 — 서빙경로 `label-remote` · API접두어 `authoring-api`)

```apache
# ── 로드밸런서 ──────────────────────────────────────────────────────────────
<Proxy balancer://klid-authoring-was>
    # timeout=600 — 대용량 업로드(영상 5GB)·긴 배치 응답. 전역 ProxyTimeout 120 을 이 워커만 늘린다.
    BalancerMember http://127.0.0.1:49080 route=authoring01 timeout=600
    ProxySet lbmethod=byrequests
</Proxy>

# ── 저작도구 백엔드 — ★ 접두어를 «그대로 넘긴다»(제거하지 않는다) ─────────────
#   WAR 웹 컨텍스트가 이 접두어를 포함해 구워진다. 제거하면 API 가 전건 404 다.
#   확인: curl http://localhost:38081/{API접두어}/actuator/health/liveness  (인증 없이 열려 있다)
ProxyPass        /{API접두어}/ balancer://klid-authoring-was/{API접두어}/
ProxyPassReverse /{API접두어}/ balancer://klid-authoring-was/{API접두어}/

# ── 시스템간 창구(포털 → 저작도구) — 등록 파트너망만 ─────────────────────────
<Location "/{API접두어}/v1/portal-system/">
    # 기존 `/api/internal/` 블록의 «같은 목록»을 그대로 옮긴다.
    #   (주소 값은 이 문서에 적지 않는다 — 운영 문서 IP 평문 금지)
    Require ip <등록 파트너망 #1~#4 — 기존 /api/internal/ 과 동일>
    Require ip 127.0.0.1
    Require ip ::1
</Location>

# ── 저작도구 MF Remote 번들 호스트 ──────────────────────────────────────────
#   포털 SPA 안(/workspace/authoring)에 런타임 마운트되는 번들이다. 사용자 진입 주소가 아니다.
#   같은 origin 이라 CORS 불필요.
Alias /{서빙경로}/ "/opt/apache2_custom/www/author/"

# ── 번들 Directory — 정적 서빙만. ★ SPA fallback 을 걸지 않는다 ──────────────
#   MF 는 remoteEntry.js·해시 청크를 «URL 로 직접» 로드한다. 없는 청크에 index.html 을
#   200 으로 돌려주면 «자바스크립트 자리에 HTML»이 와서, 브라우저가 원인을 알 수 없는
#   구문 오류를 낸다. 없는 파일은 그냥 404 가 맞다.
<Directory "/opt/apache2_custom/www/author">
    Options -Indexes +FollowSymLinks
    AllowOverride None
    Require all granted
</Directory>

# ── 캐시 (기존 전역 no-store 블록 «아래»에) ──────────────────────────────────
<IfModule mod_headers.c>
    <LocationMatch "^/{서빙경로}/assets/">
        Header unset Pragma
        Header unset Expires
        Header set Cache-Control "public, max-age=31536000, immutable"
    </LocationMatch>
    # ★ 반드시 위 블록보다 «뒤»에
    <Location "/{서빙경로}/remoteEntry.js">
        Header unset Pragma
        Header unset Expires
        Header set Cache-Control "no-cache, must-revalidate"
    </Location>
</IfModule>

# ── 압축 ────────────────────────────────────────────────────────────────────
LoadModule filter_module  modules/mod_filter.so
LoadModule deflate_module modules/mod_deflate.so
<IfModule mod_deflate.c>
    AddOutputFilterByType DEFLATE text/html text/css application/javascript text/javascript application/json
</IfModule>
```

**제거 대상**: `Alias /authoring-repo/` 와 그 `<Directory>`·`<Location>`·`<LocationMatch>` 블록.

## 6. 저작도구 쪽에서 함께 맞추는 값

접두어를 `/authoring-api/` 로 확정하시면 저희가 아래를 같은 시점에 맞춘다.
**세 값이 같이 움직여야 한다.**

| # | 대상 | 값 |
|:-:|---|---|
| 1 | WAR 웹 컨텍스트 (Jenkins `klid 저작도구 was` 의 `KLID_WEB_CONTEXT`) | `/authoring-api` |
| 2 | 프론트 API 주소 (Jenkins `klid portal 저작도구 web` 빌드 시점 `VITE_API_BASE_URL`) | `/authoring-api/v1` |
| 3 | 백엔드가 응답 본문에 담아 내리는 절대 주소 접두어 (`PUBLIC_API_BASE_PATH`) | `/authoring-api/v1` |

> ③ 이 별도로 필요한 이유: 영상 재생 서명 주소·프레임 이미지 주소는 백엔드가 **응답 본문에**
> 절대 경로로 담아 내려주고 브라우저가 그것을 `<video src>`·`<img src>` 에 그대로 문다.
> 종전에는 `/api/v1/...` 로 하드코딩돼 있어서, 포털 앞단에서 그 요청이 **포털 자신의 WAS** 로
> 날아가 영상이 전부 깨진다. 설정으로 받도록 이번에 고쳤고, 미설정 시 종전값(`/api/v1`)이라
> 관제 향 동작은 바뀌지 않는다.

## 7. 배포 후 검증 순서

```bash
# ① 진입 파일 — 200 + 자바스크립트 + no-cache
curl -sI http://<개발망 호스트>:38081/{서빙경로}/remoteEntry.js | grep -Ei 'HTTP/|content-type|cache-control'

# ② ★없는 청크 — 404 여야 한다. 200 + text/html 이면 SPA fallback 이 아직 덮고 있는 것
curl -sI http://<개발망 호스트>:38081/{서빙경로}/assets/no-such-chunk.js | head -1

# ③ 해시 청크 — immutable
curl -sI http://<개발망 호스트>:38081/{서빙경로}/assets/<실제파일명>.js | grep -i cache-control

# ④ ★API 접두어 — 200 이어야 한다. 404 면 프록시가 접두어를 떼고 있는 것
curl -s http://<개발망 호스트>:38081/{API접두어}/actuator/health/liveness

# ⑤ 압축 — Content-Encoding: gzip
curl -sI -H 'Accept-Encoding: gzip' http://<개발망 호스트>:38081/{서빙경로}/assets/<실제CSS>.css | grep -i content-encoding
```

②와 ④가 이번 수정의 핵심 검사다. 나머지는 성능·운영 항목이다.

## 8. 아직 합의되지 않은 것 (인프라 범위 밖 · 기록용)

| 항목 | 상태 |
|---|---|
| 진입 payload 전달 통로 | 포털이 `/workspace/authoring?datasetId=…` 로 보내는데 저작도구가 읽지 않는다. 파일 절대경로는 주소에 실을 수 없어 **props 이름·형태를 양쪽이 같이 정해야** 한다 |
| `react-router` 공유 여부 | 양쪽 모두 공유하지 않기로 했다(버전이 다르다). 한 문서에서 브라우저 history 를 누가 소유하는지가 미결 |
| 스타일 격리 | 격리 책임은 저작도구. 개발망 첫 로드에서 포털 KRDS 화면 시각 회귀를 함께 본다 |
