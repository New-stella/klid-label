# [요청] 저작도구 WAS 설정값 1건 추가 — 포털 연동 키

> 요청일 2026-09-10 · 대상 **저작도구 개발망 WAS(포털 향)** · 소요 **약 5분** · **재기동 1회 필요**
> 요청자: 저작도구 개발 · 수신: 인프라 담당

---

## 1. 무엇을 / 왜

저작도구 설정 파일에 **한 줄**을 추가하고 **JBoss 를 재기동**해 주십시오.

```
PORTAL_CLEANUP_API_KEY=local-development-only-secret-key-change-me-32bytes
```

**왜 필요한가** — 포털이 학습데이터 버전업 시 저작도구로 보내는 알림이 **지금 전부 실패(401)** 하고
있습니다. 두 시스템이 나눠 갖기로 한 인증 키가 **저작도구 쪽에 주입된 적이 없어**, 저작도구가
설계대로 「키 없음 → 거부」로 닫아 두고 있는 상태입니다. 애플리케이션 결함이 아니라 **설정 누락**이며,
위 한 줄이 들어가면 해소됩니다.

포털 측 실패 로그 (2026-09-10 15:43):
```
POST …/authoring-api/v1/portal-system/dataset-cleanups → status=401
```

---

## 2. ★ 대상 확인 — 아파치가 아니라 JBoss 입니다

해당 장비에 세 가지가 함께 떠 있습니다. **고칠 것은 JBoss 하나**입니다.

| 포트 | 정체 | 이번 작업 |
|---|---|---|
| 38444 | 포털 웹(HTTPS) | 해당 없음 |
| 38081 | **아파치** — 저작도구 진입 | ❌ 건드리지 않음 · 재기동도 하지 않음 |
| **49080** | **JBoss EAP 8.1 — 저작도구 백엔드** | ✅ **설정 추가 + 재기동** |

아파치 밸런서가 루프백으로 넘기고 있어 두 프로세스가 같은 장비에 있습니다
(`BalancerMember http://127.0.0.1:49080 route=authoring01`). 멤버는 **1대뿐**입니다.

⚠ **아파치를 재기동할 필요가 없습니다.** 설정을 읽는 것은 JBoss 위의 애플리케이션입니다.

---

## 3. 작업 절차

### ① 설정을 어디서 읽는지 확인 (변경 없음 · 먼저 실행)

```bash
ps -ef | grep '[j]boss' | tr ' ' '\n' | grep -E 'spring.config.additional-location|jboss.home.dir'
```

- **`-Dspring.config.additional-location=file:/etc/klid/` 가 보이면** → ②로 진행
- **안 보이면** → ②를 하지 마시고 **이 명령의 출력을 회신**해 주십시오. 형상이 달라 다른 자리에
  넣어야 하며, 잘못된 파일에 넣으면 **아무 반응 없이 그대로 실패**합니다.

### ② 설정 추가

```bash
sudo cp -a /etc/klid/application.properties \
          /etc/klid/application.properties.bak.$(date +%Y%m%d%H%M)

echo 'PORTAL_CLEANUP_API_KEY=local-development-only-secret-key-change-me-32bytes' \
  | sudo tee -a /etc/klid/application.properties >/dev/null

sudo grep -n '^PORTAL_CLEANUP_API_KEY=' /etc/klid/application.properties
```

⚠ 파일에 **이미 같은 키가 있으면** 덧붙이지 마시고 그 줄의 값만 바꿔 주십시오
(같은 키가 두 줄이면 뒤엣것이 이깁니다 — 헷갈립니다).

⚠ **WAS 실행 계정이 이 파일을 읽을 수 있어야 합니다.** 못 읽으면 **WAS 는 정상 기동하는데
애플리케이션만 설정 없이 뜨는** 형태로 드러납니다.
```bash
sudo -u <WAS 실행 계정> head -c1 /etc/klid/application.properties >/dev/null && echo "읽기 OK"
```

### ③ JBoss 재기동

```bash
systemctl list-units --type=service | grep -iE 'jboss|eap'    # 유닛명 확인
sudo systemctl restart <유닛명>
```

### ④ 검증 — 로그 한 줄

```bash
JH=$(ps -eo args= | tr ' ' '\n' | grep -m1 -- '-Djboss.home.dir=' | cut -d= -f2-)
grep 'PortalSystemApiKey' "$JH/standalone/log/server.log" | tail -3
```

**기대 출력**
```
[PortalSystemApiKey] 정리 트리거 창구의 사전 공유 키가 설정됐습니다.
```

| 실제 출력 | 뜻 |
|---|---|
| `…설정됐습니다` | ✅ 성공 |
| `…설정되지 않았습니다` | 값이 안 읽혔다 — ①의 경로 재확인 필요 (회신 요망) |
| **아무 줄도 없음** | 배포된 애플리케이션이 구판이다 — 재배포 필요 (회신 요망) |

### ⑤ 왕복 확인 (선택)

```bash
curl -i -sS -X POST http://localhost:38081/authoring-api/v1/portal-system/dataset-cleanups \
  -H 'Content-Type: application/json' \
  -H 'x-api-key: local-development-only-secret-key-change-me-32bytes' \
  -d '{"datasetCode":"DS-FLOOD-2025-01","version":"11.0.0"}'
```
**202** 면 완료입니다. ⚠ 이 명령은 **그 장비 위에서** 실행해야 합니다 — 외부에서 부르면
아파치의 접근 제한에 걸려 **403** 이 납니다(정상 동작입니다).

---

## 4. 롤백

②에서 뜬 백업으로 되돌리고 재기동하면 원상복구됩니다.

```bash
sudo cp -a /etc/klid/application.properties.bak.<타임스탬프> /etc/klid/application.properties
sudo systemctl restart <유닛명>
```

되돌리면 **지금과 같은 상태(포털 알림 401)** 로 돌아갈 뿐, 다른 기능에는 영향이 없습니다.

---

## 5. 영향 범위

- **이 값은 포털 알림 수신 창구 하나에만 쓰입니다.** 다른 기능·화면·DB 와 무관합니다.
- 값이 잘못돼도 **그 창구만 계속 401** 일 뿐 애플리케이션은 정상 동작합니다(닫히는 방향).
- **재기동 중 저작도구 접속이 잠시 끊깁니다** — 사용이 적은 시간대를 권합니다.

---

## 6. 값 취급

- 위 값은 **개발망 임시 키**입니다. 운영 반영 시에는 별도로 생성한 값으로 교체합니다.
- 이 키는 **저작도구가 발급해 포털에 공유**하는 축입니다. 다른 연동(포털이 발급하는 소재 조회 키,
  토큰 서명 키)과 **같은 값을 돌려쓰지 않습니다.**
- 접근 로그·모니터링에 이 헤더 값이 남지 않도록 마스킹돼 있습니다.

---

## 7. 회신 요망

| 상황 | 회신해 주실 것 |
|---|---|
| 정상 완료 | ④의 `설정됐습니다` 줄 |
| ①에서 `spring.config` 가 안 보임 | ① 명령의 **전체 출력** |
| ④에서 아무 줄도 없음 | 애플리케이션 배포 시각 / WAR 파일 타임스탬프 |
| `/etc/klid/application.properties` 가 없음 | 그 사실과 ① 출력 |

작업 후 저작도구 측에서 포털에 **동일 키 설정을 요청**해야 최종적으로 연동이 성립합니다
(양쪽 값이 같아야 통과). 그 부분은 저희가 진행합니다.
