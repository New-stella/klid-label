# R3 요구사항 추적표

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-UC/CO/DC/DCD/SD/SC/AC/EN/ERD/TB/II/IC/IF/UCD/ACT 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. 범위는 시작 ID만 전체형으로(예: `KLID-AT-UC-001~013`). ※ 요구사항(RQ-SFR-NN-NN)·시스템시험(KLID-ST-NNN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 시스템의 요구사항을 도출하여 개발의 각 단계별로 작성한 산출물이 일관성을 가지는지를 추적할 수 있도록 각 단계별 산출물의 추적성을 관리하기 위하여 작성한다.

## 작성 방법
> 사용자 요구사항 정의서로부터 시작하여 분석, 설계, 구현, 시험의 각 단계별 산출물에 ID를 식별하고 전단계 산출물과 후속단계 산출물간의 연계관계에 매핑 작업을 하여 산출물이 단계별 연관관계가 끊어지지 않고 추적할 수 있도록 한다.

## 항목 설명
> 전체 시스템에 대하여 한 개의 표로 작성하며, 각 산출물의 ID와 이름을 기술한다.

- 분석 단계: 요구사항 ID/명, 유스케이스 ID/명
- 설계 단계: 화면 ID, 컴포넌트 ID, 테이블 ID
- 구현 단계: 프로그램 파일 ID, 단위시험 ID
- 시험 단계: 통합시험 시나리오 ID, 시스템시험 시나리오 ID

## 작성 시 참고사항

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID`
> - 서브시스템 ID (저작도구): `AT`
> - 산출물 파일명: `KLID_AT_요구사항추적표_Rev {버전}`
> - 본 산출물에서 참조하는 ID:
>   - 요구사항 ID: `RQ-AT-NNN` (기능), `RQ-{비기능코드}-NNN` (비기능) — R1 참조
>   - 유스케이스 ID: `KLID-AT-UC-NNN` — R2 참조
>   - 화면 ID: `KLID-AT-SC-NNN` — D2 참조
>   - 컴포넌트 ID: `KLID-AT-CO-NNN` — D3 참조
>   - 테이블 ID: `KLID-AT-TB-NNN` — D9 참조
>   - 단위시험 ID: `KLID-AT-UT-NNN` — D11 참조
>   - 통합시험 시나리오 ID: `KLID-IT-TS-NNN` — D10 참조
>   - 시스템시험 ID: `KLID-ST-NNN` — D7 참조
>
> - R1(사용자 요구사항 정의서)의 요구사항 ID를 시작점으로 하여 R2(유스케이스), D1(클래스), D2(화면), D3(컴포넌트), D9(데이터베이스), I1(프로그램 코드), D11(단위시험), D10(통합시험), D7(시스템시험)까지 추적 체인을 연결한다.
> - 본 프로젝트에서는 `docs/requirements/` 의 요구사항 목록과 `backend/src/main/java/` 패키지 구조, `db/migration/` Flyway 파일을 교차 참조하여 매핑한다.
> - 하나의 요구사항이 여러 유스케이스/컴포넌트에 매핑될 수 있으므로 1:N 관계를 허용한다.
> - 빈 셀이 있으면 추적성이 끊긴 것이므로 반드시 확인하여 보완한다.
