# D2 사용자 인터페이스 설계서

> **ID 표기 규칙(공통)**: 본 산출물의 모든 ID(KLID-AT-UC/CO/DC/DCD/SD/SC/AC/EN/ERD/TB/II/IC/IF/UCD/ACT 등)는 **전체 형식 `KLID-AT-XX-NNN`** 으로 표기한다. 끝부분만(예: `UC-001`) 약식 표기 금지. 범위는 시작 ID만 전체형으로(예: `KLID-AT-UC-001~013`). ※ 요구사항(RQ-SFR-NN-NN)·시스템시험(KLID-ST-NNN) 등 타 체계 ID는 각 체계 원형 유지.

## 작성 목적
> 시스템이 제공하는 사용자 인터페이스의 전체 구조와 메뉴 형식, 화면 목록과 화면의 상세 설계 내역을 기술한다.

## 작성 방법
> 전체 시스템에 대한 사용자 인터페이스의 구조를 사용자에게 제공하는 메뉴 형식으로 기술하고, 화면 및 출력으로 구분하여 목록을 작성하며, 화면의 상세 설계의 내용을 화면별로 기술한다.

### 3. 화면 상세 설계

> **⟳ 화면별로 1개씩 반복 작성한다.** **모든 항목이 하나의 `<table>` 안에 들어가야 한다** — 화면 와이어프레임·입출력 항목·처리 내용·기술적 고려사항 모두 같은 표의 `<td colspan="4">` 셀에 포함시킨다. (HWPX 양식 호환)
> **작성 품질 규칙(CBD 적합성)**: ① 입출력 항목 속성 약어는 `I`(Input)·`O`(Output)·`RO`(ReadOnly)·`E`(Editable)·`H`(Hidden) — **ReadOnly는 반드시 `RO`**(`R` 금지). ② §2.2 출력물ID가 있으면 대응 화면의 **처리내용에 출력물ID를 인용**하여 추적을 연결한다. ③ 관련 유스케이스ID·시퀀스도ID 셀에는 **ID만** 적고 부연 설명은 화면개요로 옮긴다. ④ 처리내용에 관련 시퀀스도ID(D1 참조)를 기재한다.

```html
<table>
<tr><td width="15%">화면 ID</td><td width="35%">{ID}</td><td width="15%">화면명</td><td width="35%">{화면명}</td></tr>
<tr><td>관련 유스케이스 ID</td><td colspan="3">{UC-ID}</td></tr>
<tr><td>관련 시퀀스도 ID</td><td colspan="3">{SD-ID}</td></tr>
<tr><td>화면유형</td><td>{입력·조회·갱신·삭제}</td><td>메뉴경로</td><td>{최상위 메뉴 &gt; 중간 메뉴 &gt; 화면명} (예: 영상 &gt; 완료 영상 &gt; 영상 상세)</td></tr>
<tr><td>화면개요</td><td colspan="3">{화면 목적 및 기능}</td></tr>
<tr><td colspan="4">

(화면 와이어프레임 — HTML/CSS 또는 이미지)

</td></tr>
<tr><td colspan="4" align="center"><b>입출력 항목</b></td></tr>
<tr><td colspan="4">

| 항목명 | 컨트롤명 | 타입 및 길이 | 속성 | Validation Check |
|---|---|---|---|---|
| ... | ... | ... | ... | ... |

*속성: I:Input, O:Output, R:ReadOnly, E:Editable, H:Hidden*

</td></tr>
<tr><td colspan="4" align="center"><b>처리 내용</b></td></tr>
<tr><td colspan="4">

- (처리 흐름 bullet)

</td></tr>
<tr><td colspan="4" align="center"><b>기술적 고려사항</b></td></tr>
<tr><td colspan="4">

- (기술 고려사항 bullet)

</td></tr>
</table>
```

#### 화면 와이어프레임 작성 방법 (HTML/CSS 권장)

마크다운 안에 **인라인 HTML/CSS**로 와이어프레임을 작성한다. 외부 의존 없이 GitHub/VS Code preview에서 그대로 렌더링되고, HWPX 변환 시(pandoc 등) 인라인 이미지로 자동 포함된다.

기본 라이트 UI 패턴(공통 레이아웃 내부):

```html
<div style="background:#f9fafb;color:#1f2937;border:1px solid #e5e7eb;font-family:sans-serif;font-size:11px;">
  <div style="display:flex;height:480px;">
    <!-- 좌측 LNB (다크) -->
    <div style="width:240px;background:#1f2937;color:#d1d5db;padding:12px;">
      <div style="font-size:10px;color:#9ca3af;margin-bottom:8px;">메뉴</div>
      <div style="padding:6px 8px;background:#374151;border-radius:4px;">현재 메뉴</div>
    </div>
    <!-- 우측 본문 -->
    <div style="flex:1;display:flex;flex-direction:column;">
      <!-- 상단 바 -->
      <div style="height:56px;background:white;border-bottom:1px solid #e5e7eb;padding:0 16px;display:flex;align-items:center;">
        <span style="font-size:14px;font-weight:600;">페이지 제목</span>
      </div>
      <!-- 페이지 본문 -->
      <div style="flex:1;padding:16px;background:#f9fafb;overflow:auto;">
        <!-- 콘텐츠 -->
      </div>
    </div>
  </div>
</div>
```

다크 UI 패턴(풀스크린 캔버스 화면):

```html
<div style="background:#1f2937;color:#d1d5db;border:1px solid #374151;font-family:sans-serif;font-size:11px;">
  <!-- 헤더 -->
  <div style="height:36px;background:#1f2937;border-bottom:1px solid #374151;display:flex;align-items:center;padding:0 10px;gap:8px;">
    <span>✕</span>
    <span style="color:#9ca3af;">제목</span>
    <span style="flex:1;"></span>
    <span style="background:#2563eb;color:white;padding:2px 8px;border-radius:3px;">저장</span>
  </div>
  <!-- 본문 (다중 컬럼) -->
  <div style="display:flex;height:280px;">
    <div style="width:56px;background:#111827;border-right:1px solid #374151;">도구바</div>
    <div style="flex:1;background:#0f172a;display:flex;align-items:center;justify-content:center;color:#475569;">캔버스 영역</div>
    <div style="width:220px;background:#1f2937;border-left:1px solid #374151;">우측 패널</div>
  </div>
</div>
```

작성 규칙:
- **인라인 CSS만 사용** (외부 stylesheet 의존 금지)
- **실제 화면 구조 기반** (너비/높이/배치를 실제 화면과 일관되게 픽셀 단위로 표현)
- **컴포넌트 이름 라벨 명시** (페이지 헤더, KPI 카드, 데이터 테이블, 배정 모달 등)
- **조건부 렌더링은 주석** (`<!-- [REVIEWER 한정] -->`, `<!-- [선택: 이력 패널] -->`)
- 너무 복잡하지 않게 핵심 영역만 (한 화면당 40~80줄)
- 라이트 UI: `#f9fafb`(배경) / `#e5e7eb`(테두리) / `white`(카드) / `#2563eb`(액션)
- 다크 UI: `#1f2937`(헤더) / `#111827`(도구바) / `#0f172a`(캔버스) / `#374151`(보더)
- 포털 UI: `#fff7ed`(배경) / 오렌지 그라데이션(`#f97316` ~ `#ea580c`)

## 항목 설명

### ■ 사용자 인터페이스 구조도
> 전체 시스템에 대하여 한 개를 작성한다. 최상위레벨에서 Top-down으로 작성되며, 시스템의 규모가 큰 경우 서브시스템으로 나누어 작성할 수 있다.

### ■ 사용자 인터페이스 목록
- **화면 ID**: 화면별로 유일한 ID를 부여하여 기입한다.
- **화면명**: 화면을 식별할 수 있는 명칭을 기입한다.
- **관련 유스케이스 ID**: 본 산출물이 관련되는 "유스케이스 명세서"의 유스케이스 ID를 기입한다.
- **출력물 ID**: 출력물이 있을 경우 출력물별로 유일한 ID를 부여하여 기입한다.
- **출력물명**: 출력물을 식별할 수 있는 명칭을 기입한다.

### ■ 화면상세설계
- **화면 ID**: 관련된 화면ID를 기입한다.
- **화면명**: 관련된 화면명을 기입한다.
- **관련 유스케이스 ID**: 본 산출물이 관련되는 "유스케이스 명세서"의 유스케이스 ID를 기입한다.
- **관련 시퀀스도 ID**: 본 산출물이 관련되는 "클래스 설계서"의 시퀀스도 ID를 기입한다.
- **화면유형**: 화면 데이터 처리 방식에 따라 입력, 조회, 갱신, 삭제 등으로 표시한다.
- **메뉴 경로**: 사용자가 화면에 도달하기까지의 **GUI 메뉴 트리 깊이**를 `>` 로 구분해 표시한다 (예: `수신 > 총액결제 > 원화자금이체 > 원화자금이체신청`). **API URL path (예: `/api/v1/orders`)나 라우트 path (예: `/video/:id`)가 아니다** — 사용자가 보고 클릭하는 메뉴 라벨을 1.사용자 인터페이스 구조도(Level 1~4)와 일관되게 작성한다.
- **화면 개요**: 화면의 목적 및 기능에 대하여 간략하게 기술한다.
- **항목명**: 화면의 입출력 항목을 식별할 수 있는 명칭을 기입한다.
- **컨트롤명**: 화면을 구현하는 컨트롤의 명칭을 기술한다.
- **타입 및 길이**: 항목의 데이터 타입과 최대 길이를 기술한다.
- **속성**: 항목의 속성을 Input(I), Output(O), ReadOnly(RO), Editable(E), Hidden(H) 중 선택하여 두문만(앞글자)을 기술한다.
- **Validation Check**: 항목의 입력 오류를 체크할 수 있는 입력 범위를 기술한다.
- **처리 내용**: 화면이 처리하는 업무 내용을 기술하며, 관련 시퀀스도 ID를 기재한다.
- **기술적 고려사항**: 화면을 구현하기 위하여 필요한 기술적 요소에 대한 고려사항을 기술한다.

## 작성 시 참고사항

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID`
> - 서브시스템 ID (저작도구): `AT`
> - 산출물 파일명: `KLID_AT_사용자인터페이스설계서_Rev {버전}`
> - 본 산출물에서 사용하는 ID:
>   - 화면 ID: `KLID-AT-SC-NNN` (예: `KLID-AT-SC-001`)
>   - 관련 유스케이스 ID: `KLID-AT-UC-NNN` (R2 참조)
>   - 관련 시퀀스도 ID: `KLID-AT-SD-NNN` (D1 참조)
>
> - 화면 ID는 `{SUBSYSTEM}-SC-NNN` 형식으로 부여한다 (예: `KLID-AT-SC-001`).
> - **화면 레이아웃(와이어프레임)은 필수** — 화면개요 아래에 인라인 HTML/CSS 와이어프레임을 표 안의 `<td colspan="4">` 셀로 삽입한다. 상세 작성 방법은 위 "화면 와이어프레임 작성 방법" 섹션 참조.
> - 화면 목록은 프로젝트의 라우트 정의(`frontend/src/router/*` 또는 동등 파일)에서 추출한다.
> - 각 화면의 UI 구조는 페이지 컴포넌트의 JSX 구조를 분석하여 파악한다.
> - 사용자 인터페이스 구조도는 채널별(INTERNAL/PORTAL/공통)로 메뉴 트리를 작성한다.
> - 출력물은 CSV 리포트, Diff Patch, 브라우저 인쇄, 이미지 묶음 등이 해당된다.
> - 화면유형은 "조회"(목록/상세), "입력"(폼 제출), "갱신"(수정), "삭제" 중 복합 가능 (예: "조회·갱신").
> - 속성 표기 시 복합 속성은 슬래시로 구분한다 (예: I/E = Input+Editable, I/O = Input+Output).
