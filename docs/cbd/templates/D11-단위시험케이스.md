# D11 단위시험 케이스

## 작성 목적
> 단위 프로그램 및 컴포넌트를 설계한 개발자가 컴포넌트 명세서에 정의된 바와 같이 설계한 컴포넌트 프로그램의 오류를 검출할 목적으로 배포하는 컴포넌트 단위로 시험하기 위한 시험 설계를 기술한다.

## 작성 방법
> 개발자가 설계한 컴포넌트 단위로 작성하며 컴포넌트별 시험케이스를 작성한다.

## 항목 설명

- **단위시험 ID**: 단위 컴포넌트(프로그램)별 유일한 ID를 부여하여 기입한다.
- **설명**: 단위 컴포넌트(프로그램)에 대한 간략한 설명을 기입한다.
- **관련 컴포넌트 ID**: 본 산출물이 관련되는 "컴포넌트 설계서"의 컴포넌트 ID를 기술한다.
- **관련 프로그램 ID**: 본 산출물이 관련되는 프로그램 ID를 기술한다.
- **케이스 ID**: 단위 컴포넌트(프로그램)에 수행할 시험 케이스별 식별자를 부여하여 기술한다.
- **케이스명**: 시험 케이스의 명칭을 기입한다.
- **작업권한**: 적용하는 사용자 권한을 표기한다.
- **시험 데이터**: 해당 시험 케이스를 실행하는데 필요한 시험 데이터를 기술한다. (실제 데이터 값이 아닐 경우는 조건을 표시할 수 있다.)
- **시험항목 및 처리절차**: 시험 데이터를 입력하여 시험하는 단계와 단계별 처리 절차 및 방법을 기술한다.
- **예상결과 및 검증방법**: 케이스 수행 시 기대하는 결과와 그 검증 수단(화면 표시 확인, DB 조회 확인 등)을 기술한다. (작성 사례 기준 컬럼)
- **시험결과**: 설계단계에서는 기술하지 않으며, 시험결과서로 활용될 경우 실제 시험을 수행한 결과를 기술한다.

## 작성 시 참고사항

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID`
> - 서브시스템 ID (저작도구): `AT`
> - 산출물 파일명: `KLID_AT_단위시험케이스_Rev {버전}`
> - 본 산출물에서 사용하는 ID:
>   - 단위시험 ID: `KLID-AT-UT-NNN` (예: `KLID-AT-UT-001`)
>   - 관련 컴포넌트 ID: `KLID-AT-CO-NNN` (D3 참조)
>   - 관련 프로그램 ID: D3 내부 클래스 ID `KLID-AT-IC-NNN` 또는 구현 클래스명(예: `LabelService`)
>
> - 단위시험은 컴포넌트(도메인 패키지) 단위로 작성하며, 각 Service/Controller의 주요 메서드를 시험 대상으로 한다.
> - 본 프로젝트의 단위시험은 JUnit 5 + Testcontainers(PostgreSQL)로 실행한다.
> - 시험 데이터는 `@DisplayName("한글_서술형")` 형태의 테스트 메서드명과 매핑한다.
> - 작업권한은 REVIEWER / WORKER / PORTAL_USER 중 해당하는 역할을 기입한다.
> - 시험결과 컬럼은 설계 단계에서 비워두고, I2(단위시험 결과서)에서 채운다.
