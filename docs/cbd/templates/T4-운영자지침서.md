# T4 운영자 지침서

## 작성 목적
> 개발한 시스템을 운영자가 효과적으로 관리와 운영을 할 수 있도록 시스템 관리 및 운영에 대한 지침을 기술한다.

## 작성 방법
> 개발 시스템의 관리 및 운영 측면에서 시스템의 지속적인 관리가 가능하도록 상세하게 작성하며 이해하기 쉽고 구체적인 언어표현을 사용한다. 운영자지침서의 경우 시스템의 특성에 따라 기술하는 항목이 차이가 많이 발생할 수 있으므로 내용이 빠지지 않도록 관련항목을 수정하여 사용한다.

## 항목 설명

- **개요**: 시스템의 운영자 측면의 전체적인 개요를 기술한다.
- **시스템 설치**: 하드웨어, 소프트웨어, 네트워크를 포함한 시스템의 구성, 시스템 설치 절차 등의 내용을 화면 캡처를 이용하여 운영자가 쉽게 사용할 수 있도록 기술한다.
- **시스템 운용**: 자료 관리, 백업 관리, 장애 내역 및 복구 절차 등의 내용을 화면 캡처를 이용하여 운영자가 쉽게 사용할 수 있도록 기술한다.
- **사용 지침**: 시작 및 종료 방법과 공통적인 내용을 화면 캡처를 이용하여 운영자가 쉽게 사용할 수 있도록 기술한다.
- **기능별 사용법**: 기능 이름, 기능 설명, 주의 사항, 오류 메시지 및 해결 방법 등을 빠짐없이 완전하고 일관된 언어표현으로 화면 캡처를 이용하여 이해하기 쉽게 기술한다.
- **부록**: 기타 필요사항 등을 제공한다.

## 작성 시 참고사항

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID`
> - 서브시스템 ID (저작도구): `AT`
> - 산출물 파일명: `KLID_AT_운영자지침서_Rev {버전}`
> - 본 산출물에서 참조하는 ID:
>   - 컴포넌트 ID: `KLID-AT-CO-NNN` (D3 참조)
>   - 데이터베이스 ID: `KLID-AT-DB-NNN` (D9 참조)
>
> - 시스템 구성(§2.1): Spring Boot(backend) + FastAPI(ai-server) + React(frontend) + PostgreSQL — CLAUDE.md의 환경별 접속 정보 테이블 참조
> - 설치 절차(§2.2): `./gradlew bootJar` → JAR 배포, `uvicorn` 기동, `npm run build` → 정적 파일 배포, Flyway 마이그레이션 자동 실행
> - 자료 관리(§3.1): 영상/프레임 저장 경로(STORAGE_RAW_PATH/STORAGE_DEIDENTIFIED_PATH), 영상 암호화 저장, 로그 마스킹(MaskingPatternLayout)
> - 백업 관리(§3.2): PostgreSQL 백업 정책, 영상 파일 백업, Quartz Job 정의(QRTZ_*)
> - 장애 내역 및 복구(§3.3): Resilience4j 서킷브레이커 상태, ai-server GPU 자원·헬스체크, DB 커넥션 풀, 배치 실패 재처리 정책, Actuator `/actuator/health` + Micrometer/Prometheus 메트릭
> - 기능별 사용법(§5): 관리 화면(`/manage/*`) 기준 — 사용자 관리, 시스템 설정, 작업 배정, 영상 적재(TUS) 등 REVIEWER 운영 기능
