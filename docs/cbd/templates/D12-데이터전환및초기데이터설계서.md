# D12 데이터 전환 및 초기데이터 설계서

## 작성 목적
> 초기 데이터 구축 시 단시일에 대량의 데이터를 이행함에 있어 신속하고 안정적인 데이터 이행을 위하여 체계적인 절차를 수립하여 구축 시 발생할 문제점을 사전에 차단하기 위한 계획을 수립한다.

## 작성 방법
> 업무그룹별 전환계획이 필요한 경우와 전체 미니프로젝트를 통합하여 전환하는 경우를 구분하여 계획을 수립한다. 업무그룹별로 전환하는 경우에는 전체적인 전환 완전성을 검증한다.

## 작성 시 참고사항

> **ID 체계 (프로젝트 공식)**
> - 프로젝트 ID: `KLID`
> - 서브시스템 ID (저작도구): `AT`
> - 산출물 파일명: `KLID_AT_데이터전환및초기데이터설계서_Rev {버전}`
> - 본 산출물에서 참조하는 ID:
>   - 데이터베이스 ID: `KLID-AT-DB-NNN` (D9 참조)
>   - 테이블 ID: `KLID-AT-TB-NNN` (D9 참조)
>
> - 본 프로젝트는 관제서버 기존 DB(`klid_system`)에 저작도구 전용 스키마(`klid_at`)를 추가하는 구조이므로, 기존 MNG_* 테이블은 전환 대상이 아니라 공유 대상이다.
> - 초기 데이터: 공통코드(MNG_COMM_CD 등), 시스템 설정값, Quartz 스케줄러 초기 Job 정의
> - Flyway 마이그레이션(`V1__*` ~ 최신 — 고정 버전 번호 하드코딩 금지)이 자동으로 스키마를 생성하므로, 데이터 전환은 초기 코드성 데이터 INSERT 중심으로 기술한다.
> - 전환 검증: Flyway migration 성공 여부, JPA `ddl-auto=validate` 기동 검증, 초기 데이터 건수 확인
> - 비상대책: Flyway 롤백 전략, DB 백업/복원 절차를 포함한다.
