# T6 인수시험 시나리오

> 출처: CBD.pdf §III.4.6 (문서 p166~170). 단계명=시험.

## 양식 구조

D10 통합시험 시나리오와 동일 구조이되 **시나리오 헤더가 관련 요구사항 ID**:
1. **시험 시나리오**: 헤더(시험시나리오 ID/명/설명/**관련 요구사항 ID**) + | 시험케이스 ID | 시험케이스 설명 | 시험 절차 | 시나리오 설명 | 비고 |
2. **시험케이스**: 헤더(차수/시험시나리오 ID/시험케이스 ID) + | 시험 절차{순번, 업무처리내용} | 시험항목 | 사전조건 | 입력자료 | 예상결과 | 화면ID | 시험결과 | 비고 |

## 작성 목적 (원문)
각 응용 프로그램의 단위 프로그램 내에서의 작업 흐름 연계, 단위 프로그램간의 상호 연동 및 대내외 인터페이스를 포함한 사용자 요구사항을 만족하는지를 **발주자가 최종 인수를 위하여 검증**한다.

## 작성 방법 (원문)
**요구사항 ID를 기준으로** 시험시나리오와 시험케이스를 기술한다.

## 항목 설명 (원문 요지)
- 시험 시나리오 ID(유일)/명/설명(간략).
- **관련 요구사항 ID**: "사용자 요구사항 정의서"의 요구사항 ID.
- 시험 케이스 ID/설명, 시험 절차(케이스별 수행 절차), 시나리오 설명(절차 단계별 실행 시나리오 / 기타 고려사항).
- 시험 케이스: 차수(수행 횟수)/시나리오 ID/케이스 ID, 순번/업무처리 내용, 시험항목(시험 데이터·수행내용), 사전조건, 입력자료, 예상결과, 화면 ID, **시험결과(시험결과서로 활용될 경우 기술)**, 비고.

## 작성 사례 요점
- `LL_IT_TS_030 | 결제 조회 | … | 관련 요구사항ID SS_RFO_010-05` — 통합시험과 같은 시나리오 본문이라도 헤더 추적 기준이 **요구사항 ID**.

## 주의 / KLID 적용
- 인수시험 = **요구사항 ID 기준** 추적(발주자 인수 관점) — UC 기준인 D10/T1과 구분. 테스터는 고객(D6 비교표).
- KLID: 관련 요구사항 ID는 R1 실존 `RQ-SFR-NN-NN`(기능 전수 커버) + 비기능 인수 항목은 `NFR-NNN`.
