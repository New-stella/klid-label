# T3 사용자 지침서

> 출처: CBD.pdf §III.4.3 (문서 p147~152). 단계명=시험.

## 양식 구조 (자유 목차형)

```
1. 개요
2. 사용 지침 (2.1 설치 방법 / 2.2 시작 및 종료 방법 / 2.3 공통 사항)
3. 기능별 사용법
  3.1 기능 이름 (3.1.1 기능 설명 / 3.1.2 주의 사항 / 3.1.3 오류 메시지 및 원인)
부록
```

## 작성 목적 (원문)
개발한 시스템을 사용자가 효과적으로 사용할 수 있도록 기능적인 설명과 기타 예외처리에 대한 지침을 기술한다.

## 작성 방법 (원문)
개발 시스템의 기능 및 예외처리 사항을 **빠짐없이** 기술하며, 이해하기 쉽고 구체적인 언어표현을 사용한다. 사용자지침서의 경우 시스템의 특성에 따라 기술하는 항목이 차이가 많이 발생할 수 있으므로 내용이 빠지지 않도록 **관련항목을 수정하여 사용**한다.

## 항목 설명 (원문)
- **개요**: 시스템의 사용자 측면의 전체적인 개요.
- **사용 지침**: 설치방법, 시작·종료 방법과 공통적인 내용을 **화면 캡처를 이용하여** 사용자가 쉽게 사용할 수 있도록 기술.
- **기능별 사용법**: 기능 이름, 기능 설명, 주의 사항, **오류 메시지 및 원인** 등을 빠짐없이 완전하고 일관된 언어표현으로 화면 캡처를 이용하여 기술.
- **부록**: **오류 메시지 및 처리 절차, 용어 및 색인** 등을 제공.

## 작성 사례 요점
- 기능 설명은 화면 캡처 + ①②③ 번호 마커로 영역별 조작 설명(조회/등록/수정 절차).
- 오류 메시지 표: | 오류 메시지 | 원인 | 처리 방법 |. 부록: 오류 메시지·처리 절차 표 + 용어 표(용어/설명/별칭).

## 주의 / KLID 적용
- 화면 캡처 필수 기조. 기능 단위 = 화면/메뉴 단위로 3.x 반복. KLID 역할(REVIEWER/WORKER/PORTAL_USER)별 접근 기능 구분 명시 권장.
