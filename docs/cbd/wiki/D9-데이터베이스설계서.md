# D9 데이터베이스 설계서

> 출처: CBD.pdf §III.2.9 (문서 p89~95)

## 양식 구조

1. **데이터베이스 목록**: | 데이터베이스 ID | 명칭 | 주관부서 | 비고 |
2. **데이터베이스 정의** (DB별):
   - 헤더: 데이터베이스 ID | 데이터베이스명 | Storage Group / Bufferpool | 인덱스 BP
   - 본문: | TS ID | TS 용량 | 테이블 ID | 테이블 명 | 인덱스 ID | 인덱스 용량 | 비고 |
3. **테이블 명세** (테이블별):
   - 헤더: 테이블ID | 테이블명 / 데이터베이스명 | TS명 / 트리거 구성 / 테이블 설명
   - 운영 메타: | 초기건수 | 증가량(일) | 보관주기 | 최대건수 | 용량 | 비고 |
   - 컬럼: | 컬럼명 | 컬럼ID | 타입 및 길이 | Not Null | PK | FK | IDX | 기본값 | 제약조건 |

## 작성 목적 (원문)
최종적으로 설계된 테이블과 인덱스를 데이터베이스 공간에 맵핑시키고 저장공간 등의 **물리 모델**을 기술한다.

## 작성 방법 (원문)
부서에서 운영하는 데이터베이스 목록을 작성하고, 데이터베이스의 물리적 상세내용을 작성한다.

## 항목 설명 (원문 전 항목)

### 데이터베이스 목록
- 데이터베이스 ID(실제 물리적으로 구현하는 DB ID) / 명칭(주로 관리하는 데이터를 대표하는 명칭) / 주관부서(관리 책임 부서) / 비고.

### 데이터베이스 정의
- 데이터베이스 ID/명. **Storage Group**(DB내 객체에서 사용할 Default Storage Group명), **Bufferpool**(테이블 스페이스 Default), **인덱스 BP**(Index Default Bufferpool).
- **TS ID**(테이블 스페이스 식별자) / **TS 용량**(할당용량) / 테이블 ID/명 / 인덱스 ID / **인덱스 용량**(저장공간 크기 산정) / 비고(예외·추가사항).

### 테이블 명세
- 테이블 ID/명 / 데이터베이스명 / TS명.
- **트리거 구성**: 트리거가 구성되어 있을 경우 트리거 로직.
- 테이블 설명: 목적·역할 간략 기술.
- **초기건수**: 최초 생성 시 보유 데이터 건수 / **증가량(일)**: 일정주기별 데이터 발생건수 / **보관주기(일별)**: 데이터 보관주기 / **최대건수**: 보관주기 내 발생 예상 최대 건수 / **용량**: 최대 건수×데이터 길이 고려 산정 / 비고.
- 컬럼명(내용·특성 인식 명칭) / **컬럼 ID** / 타입 및 길이(최대 허용) / NOT NULL / PK / FK / INX / 기본값 / 제약조건.

## 작성 사례 요점
- 목록: `JJ_DB_040 중계거래DB 운영부`, `JJ_DB_050 상품DB 판매부`.
- 정의: `JJ_DB_050 상품DB | Storage Group JJ_PROD_010 | Bufferpool BP2 | 인덱스 BP BP0` + `JJ_TS_140 400MB JJ_TB_040 고객 JJ_IDX_140 100MB`.
- 테이블 명세: `JJ_TB_040 고객 | 상품DB | JJ_TS_110 | 트리거 없음 | 설명…` + 운영 메타 `5,000 | 50 | 영구 | 100,000 | 300MB` + 컬럼 `ID Cust_ID CHAR(7) Y Y - XAW040(IDX) / 비밀번호 PSWD VARCHAR(16) N`.

## 주의 / KLID 적용
- **운영 메타(초기건수·증가량·보관주기·최대건수·용량) 전 테이블 필수** — 용량 산정 근거 포함.
- Storage Group/Bufferpool/TS는 **DB2 물리 용어** — 실제 DBMS 등가물로 적응 표기 (KLID PostgreSQL: tablespace·스키마(`klid_at`) 등). DB2/MariaDB 용어 그대로 복사 금지.
- 공유 스키마(MNG_*/QRTZ_*)는 물리 설계 비대상 — 목록에 "공유(READ)" 비고만. 관련 엔티티 ID 행(D8 EN과 1:1)·행안부 표준 용어 검증은 KLID 추가 규칙.
