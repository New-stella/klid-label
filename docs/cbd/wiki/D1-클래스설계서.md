# D1 클래스 설계서

> 출처: CBD.pdf §III.2.1 (문서 p22~28)

## 양식 구조

1. **설계 클래스 목록** (유스케이스별 작성): | 설계 클래스 ID | 설계 클래스명 | 관련 유스케이스 ID |
2. **시퀀스도** (유스케이스별 작성): 헤더 | 시퀀스도 ID | 시퀀스도명 | 관련 유스케이스 ID | 주요 액터 | 주요 클래스(객체) | + 다이어그램
3. **설계 클래스도** (유스케이스별 작성): 헤더 | 설계 클래스도 ID | 설계 클래스도명 | 관련 유스케이스 ID | + 다이어그램
4. **설계 클래스 정의** (클래스별 작성): 헤더(설계 클래스 ID/명) +
   - 속성: | 속성명 | 가시성 | 타입 | 기본값 | 설명 |
   - 오퍼레이션: | 오퍼레이션명 | 가시성 | 파라미터 | 반환타입 | 설명 |

## 작성 목적 (원문)
소프트웨어 관점이나 설계 관점에서의 클래스 모형을 작성한다.

## 작성 방법 (원문)
설계 클래스를 도출하기 위하여 **우선 유스케이스별로 시퀀스도를 작성하며, 여기에서 도출된 객체 및 클래스를 연관관계를 이용하여 유스케이스별로 클래스도를 작성한다.** 설계 클래스도에서는 클래스명, 속성 및 오퍼레이션을 명확하고 구체적으로 표현하여야 하고 각각의 클래스는 상세한 명세를 기술한다.

## 항목 설명 (원문 요지)

- **설계 클래스 목록** — *유스케이스별로 작성한다*: 설계 클래스 ID(유일 ID)/명, 관련 유스케이스 ID("유스케이스 명세서" ID).
- **시퀀스도** — *유스케이스별로 작성한다*: 시퀀스도 ID(유일)/명, 관련 유스케이스 ID, 주요액터(관련 액터들), 주요 클래스(관련 클래스들).
- **설계 클래스도** — *유스케이스별로 작성한다*: 설계 클래스도 ID(유일)/명, 관련 유스케이스 ID.
- **설계 클래스 정의** — *클래스별로 작성한다*: 설계 클래스ID/명. 속성(정확한 명칭/가시성 유형/타입/기본값(있는 경우)/의미와 역할). 오퍼레이션(정확한 명칭/가시성/파라미터(있는 경우)/반환타입(반환값 제공 시)/의미와 역할).

## 작성 사례 요점
- 목록: `EBA001CodAction | 원화자금이체신청 | SS_UC_010` — 사례에선 클래스 ID 자리에 클래스명(영문)을 쓰기도 함.
- 시퀀스도: `SS_SD_010-01 | 원화자금이체신청 | SS_UC_010-01`, 주요 액터(책임자·주전산기·담당자) + 주요 객체(공통코드정보·신청정보·사용자번호정보).
- 설계 클래스도: `SS_DCD_010-01 | Process Sale | SS_UC_010-01`.
- 설계 클래스 정의: `SS_DC_010-01 | EBA001CodAction`, 속성(기관코드 public string, 신청상태 — 설명에 상태값 열거), 오퍼레이션(perform public, 파라미터 `request: HttpServletRequest, response: HttpServletResponse`, 반환 Object).

## 주의 / KLID 적용
- **반복 단위가 핵심**: §1 목록·§2 시퀀스도·§3 클래스도 = **유스케이스별** 반복(전역 통합 1개 금지), §4 정의 = **클래스별** 반복. UC 1건 ↔ SD/DCD 1건.
- KLID: DCD 번호 = 실현 UC 번호와 정렬(UC 결번 시 DCD 결번), 공통 클래스는 동일 `KLID-AT-DC-NNN`으로 교차 등장. D8 엔티티의 "관련 클래스 ID"는 본 산출물 DC ID와 동일 체계여야 함.
