# D2 사용자 인터페이스 설계서

> 출처: CBD.pdf §III.2.2 (문서 p29~36)

## 양식 구조

1. **사용자 인터페이스 구조도** (전체 시스템 1개, Top-down): 사례는 업무영역(Level 1)~Level 4 메뉴 계층 표.
2. **사용자 인터페이스 목록**
   - 2.1 화면: | 화면 ID | 화면명 | 관련 유스케이스 ID |
   - 2.2 출력물: | 출력물 ID | 출력물명 | 관련 유스케이스 ID |
3. **화면 상세 설계** (화면별 작성):
   - 헤더: 화면ID | 화면명 / 관련 유스케이스 ID / **관련 시퀀스도 ID** / 화면유형 | 메뉴경로 / 화면개요
   - [화면 이미지/와이어프레임]
   - 입출력 항목: | 항목명 | 컨트롤명 | 타입 및 길이 | 속성 | Validation Check |
   - 처리 내용 / 기술적 고려사항

## 작성 목적 (원문)
시스템이 제공하는 사용자 인터페이스의 전체 구조와 메뉴 형식, 화면 목록과 화면의 상세 설계 내역을 기술한다.

## 작성 방법 (원문)
전체 시스템에 대한 사용자 인터페이스의 구조를 사용자에게 제공하는 메뉴 형식으로 기술하고, 화면 및 출력으로 구분하여 목록을 작성하며, 화면의 상세 설계의 내용을 화면별로 기술한다.

## 항목 설명 (원문 요지)

- **사용자 인터페이스 구조도**: 전체 시스템에 대하여 한 개를 작성한다. **최상위레벨에서 Top-down으로** 작성되며, 시스템 규모가 큰 경우 서브시스템으로 나누어 작성할 수 있다.
- **사용자 인터페이스 목록**: 화면 ID(유일)/화면명, 관련 유스케이스 ID. 출력물 ID(있는 경우)/출력물명.
- **화면상세설계**:
  - 화면 ID/화면명: 관련 화면 ID·명
  - 관련 유스케이스 ID: "유스케이스 명세서"의 ID
  - **관련 시퀀스도 ID**: "**클래스 설계서**"의 시퀀스도 ID를 기입한다
  - 화면유형: 화면 데이터 처리 방식에 따라 **입력, 조회, 갱신, 삭제** 등으로 표시
  - 메뉴 경로: 메뉴 경로 파악을 위하여 메뉴의 깊이를 표시
  - 화면 개요: 화면의 목적 및 기능을 간략하게 기술
  - 항목명: 화면 입출력 항목 명칭 / 컨트롤명: 화면을 구현하는 컨트롤 명칭 / 타입 및 길이: 데이터 타입과 최대 길이
  - **속성**: Input(I), Output(O), ReadOnly(RO), Editable(E), Hidden(H) 중 선택하여 **두문만(앞글자)** 기술
  - Validation Check: 항목의 입력 오류를 체크할 수 있는 입력 범위
  - **처리 내용**: 화면이 처리하는 업무 내용을 기술하며, **관련 시퀀스도 ID를 기재한다**
  - 기술적 고려사항: 화면 구현에 필요한 기술적 요소 고려사항

## 작성 사례 요점
- 구조도: 업무 영역(Level 1) → Level 2 → Level 3 → Level 4 메뉴 트리 표.
- 목록: `SS_SC_010-01 원화자금이체신청 | SS_UCD_010-01`, 출력물 `SS_PR_010-01 … 인쇄`.
- 상세: 메뉴경로 "수신/총액결제/원화자금이체/원화자금이체신청", 입출력 항목 `거래일자 | sTrDate | Char(8) | I/R | 필수항목, 입력불가`, 처리 내용에 이벤트별 흐름("현단말기에서 승인(SS_SD_010-01)" — 시퀀스도 ID 인용), 기술적 고려사항(모니터링 환경 차이 등).

## 주의 / KLID 적용
- **관련 시퀀스도 ID 는 필수 헤더 행** + **처리 내용에 시퀀스도 ID 인용** — 비워두기 금지(KLID D2 작성 품질 규칙과 동일 근거).
- 속성 코드는 I/O/RO/E/H 약어 표기(복합 가능: `I/R`, `IO/E`).
- KLID: 관리 화면 URL `/manage/*`, 화면은 R1 UC 매핑 화면만 수록.
