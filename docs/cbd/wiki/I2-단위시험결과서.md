# I2 단위시험 결과서

> 출처: CBD.pdf §III.3.2 (문서 p130~133). 단계명=구현.

## 양식 구조

D11 단위시험 케이스와 **동일 구조** + 시험결과 기입:
- 헤더 블록: 단위시험 ID / 설명 / 관련 컴포넌트 ID | 관련프로그램 ID
- 케이스 행: | 케이스 ID | 케이스명 | 작업권한 | 시험데이터 | 시험항목 및 처리절차 | 예상결과 및 검증방법 | **시험결과** |
- 사례의 시험결과 세부 컬럼: **수행자 | 수행일 | 결과(pass/fail) | 결함내용 | 결함조치여부**

## 작성 목적 (원문)
단위시험 케이스에 따라 수행한 단위시험의 수행 결과를 기술한다.

## 작성 방법 (원문)
작성한 단위시험 케이스에 따라 시험을 수행하고 시험 결과를 기술하며 **예상결과와 비교하여 단위시험의 판정 결과**를 작성한다.

## 항목 설명 (원문)
설계단계 산출물인 "단위시험 케이스"를 **현행화**하여 시험을 수행 후, 시험결과(**수행일, 수행자, 결과, 결함내용, 결함조치완료여부**)를 기록한다.

## 작성 사례 요점
- `KK_UT_TS_030` 블록 재사용. `TC_01_010 | … | 홍길동 | 10.26 | pass | - | -`, `TC_01_020 | … | 홍길동 | 10.26 | **fail** | 별첨1 참조 | 10.27 완료` — 결함내용은 별첨 참조 가능, 조치완료일 기재.

## 주의 / KLID 적용
- D11을 그대로 현행화(케이스 변경 시 D11도 갱신) — 결과 5요소(수행일/수행자/결과/결함내용/조치완료여부) 누락 금지.
- fail 케이스는 결함 조치 후 완료 기록까지가 산출물 완성 조건.
