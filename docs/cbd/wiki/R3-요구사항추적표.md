# R3 요구사항 추적표

> 출처: CBD.pdf §III.1.3 (문서 p19~21)

## 양식 구조

전체 시스템에 대하여 **한 개의 가로 매트릭스 표**. 컬럼은 단계별 산출물 ID 사슬:

| 단계 | 산출물 | 컬럼 |
|---|---|---|
| 분석 | 사용자 요구사항 명세서 | 요구사항 ID, 요구사항명 |
| 분석 | 유스케이스 명세서 | 유스케이스 ID, 유스케이스명 |
| 설계 | 사용자 인터페이스 설계서 | 화면 ID |
| 설계 | 컴포넌트 설계서 | 컴포넌트 ID |
| 설계 | 데이터베이스 설계서 | 테이블 ID |
| 구현 | 프로그램 코드 | 파일 ID |
| 구현 | 단위시험 결과서 | 단위시험 ID |
| 시험 | 통합시험 결과서 | 시나리오 ID |
| 시험 | 시스템시험 결과서 | 시나리오 ID |

## 작성 목적 (원문)
시스템의 요구사항을 도출하여 개발의 각 단계별로 작성한 산출물이 일관성을 가지는지를 추적할 수 있도록 각 단계별 산출물의 추적성을 관리하기 위하여 작성한다.

## 작성 방법 (원문)
사용자 요구사항 정의서로부터 시작하여 분석, 설계, 구현, 시험의 각 단계별 산출물에 ID를 식별하고 전단계 산출물과 후속단계 산출물간의 연계관계에 맵핑 작업을 하여 산출물이 단계별 연관관계가 끊어지지 않고 추적할 수 있도록 한다.

## 항목 설명 (원문)
전체 시스템에 대하여 한 개의 표로 작성하며, 각 산출물의 ID와 이름을 기술한다.

## 작성 사례 요점
- 1행 사슬 예: `SS_RF01001 원화자금이체신청` → `SS_UCD_010-01` → 화면 `SS_SC_010` → 컴포넌트 `SS_CO_040` → 테이블 `SS_TB_020` → 프로그램 `SS_DP_010` → 단위시험 `SS_UT_TS_010` → 통합 `SS_IT_TS_010` → 시스템 `SS_ST_010`.
- 요구사항·UC는 ID+명 병기, 이후 단계는 ID만.

## 주의 / KLID 적용
- 매핑 단절 셀은 만들지 않는 것이 원칙("끊어지지 않고 추적") — 불가피한 단절은 `-` + 사유 부록 관리(KLID 컨벤션).
- KLID 사슬: `RQ-SFR-NN-NN` → `KLID-AT-UC-NNN` → `KLID-AT-SC-NNN` / `KLID-AT-CO-NNN` / `KLID-AT-TB-NNN` → 프로그램/단위시험/통합·시스템시험 ID.
