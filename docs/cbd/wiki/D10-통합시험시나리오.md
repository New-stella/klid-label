# D10 통합시험 시나리오

> 출처: CBD.pdf §III.2.10 (문서 p95~100)

## 양식 구조

1. **시험 시나리오** (시나리오별 블록):
   - 헤더: 시험시나리오 ID / 시험시나리오명 / 시험시나리오설명 / **관련 유스케이스ID**
   - 케이스 행: | 시험케이스 ID | 시험케이스 설명 | 시험 절차 | 시나리오 설명 | 비고 |
2. **시험케이스** (케이스별 블록):
   - 헤더: 차수 / 시험시나리오 ID / 시험케이스 ID
   - 행: | 시험 절차{순번, 업무처리내용} | 시험항목 | 사전조건 | 입력자료 | 예상결과 | 화면ID | 시험결과 | 비고 |

## 작성 목적 (원문)
각 응용 프로그램의 단위 프로그램 내에서의 작업 흐름 연계, 단위 프로그램간의 상호 연동 및 대내외 인터페이스를 포함한 사용자 요구사항을 만족하는지를 검증한다.

## 작성 방법 (원문)
시험시나리오별로 통합 시험 케이스를 기술하고 시험 예상결과와 시험결과를 비교 할 수 있도록 한다.

## 항목 설명 (원문 전 항목)

### 시험 시나리오
- **시험 시나리오 ID**: 통합 시험 시나리오 유일 ID / **시험 시나리오명** / **시험 시나리오 설명**(간략).
- **관련 유스케이스 ID**: "유스케이스 명세서"의 유스케이스 ID.
- **시험 케이스 ID**: 시나리오에 포함된 케이스 식별자 / **시험 케이스 설명**(간략).
- **시험 절차**: 케이스별 시험 수행 절차 / **시나리오 설명**: 시험 절차의 각 단계별 실행 시나리오. (※ 원문에 "시나리오 설명" 항목이 중복 기재되어 두 번째는 "기타 고려사항 등" — 비고 성격)

### 시험 케이스
- **차수**: 시나리오별 시험을 수행한 횟수.
- **시험 시나리오 ID** / **시험 케이스 ID**.
- **순번**: 케이스별 업무 처리 순서번호 / **업무처리 내용**.
- **시험항목**: 시험 데이터 및 시험 수행내용.
- **사전조건**: 시험 수행 사전 조건 / **입력자료**: 시험을 위해 입력하는 값.
- **예상결과**: 성공 수행 시 예상 결과 / **화면 ID**: 시험을 수행하는 화면 ID.
- **시험결과**: **설계단계에서는 기술하지 않으며**, 통합 시험결과서로 활용될 경우 실제 결과 기술.
- **비고**.

## 작성 사례 요점
- 시나리오: `LL_IT_TS_030 | 결제 조회 | 자금결제내역을 조회 한다 | SS_UCD_010-01` + 케이스 `LL_IT_TC_030 실시간조회 | 1.실시간 자금결제 조회 2.결제리스크 조회 | 자금결제내역 및 결제리스크의 실시간 모니터링`.
- 케이스: 차수 `1차`, 순번 1(실시간 자금결제 조회 — 입력자료 【거래일자】시험일자 【자금종류】"1" 【금융기관】"9999" 【이체시스템】"1", 예상결과 "해당 데이터 결과 조회", 화면ID `LL_UC_020`), 순번 2(결제리스크 조회…). 시험결과 공란.

## 주의 / KLID 적용
- 통합시험 = **유스케이스 단위**(관련 유스케이스 ID) — D7(요구사항 ID 기준 비기능)과 구분.
- **시험결과 설계단계 공란** → T1 통합시험 결과서에서 현행화.
- 차수(시험 수행 횟수) 개념 존재 — 재시험 시 차수 증가.
