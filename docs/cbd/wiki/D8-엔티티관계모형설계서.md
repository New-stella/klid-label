# D8 엔티티 관계 모형 설계서

> 출처: CBD.pdf §III.2.8 (문서 p83~88)

## 양식 구조

1. **엔티티 관계도(ERD)**: 헤더 | ERD ID | ERD 명 | + 다이어그램
2. **엔티티 명세서** (엔티티별 작성):
   - 헤더: 엔티티 ID | 엔티티명 / **관련 클래스 ID** | **관련 클래스명** / 엔티티 설명
   - 속성: | 속성명 | 동의어 | 타입 | 길이 | NOT NULL(Y/N) | PK(Y/N) | FK(Y/N) | INX(Y/N) | 기본값 | 제약조건 |

## 작성 목적 (원문)
시스템의 요구사항을 만족하기 위한 주요 엔티티 및 엔티티간의 관계를 표현하고 엔티티에 대한 명세를 기술한다.

## 작성 방법 (원문)
**논리적 데이터 모델링**을 통한 엔티티 관계 모형도(ERD)를 작성하여 엔티티를 식별한다. 작성한 엔티티 관계 모형도와 **개념적 클래스도를 비교하여 볼 필요가 있다. ERD에서는 엔티티가 모두 속성을 가져야하나 개념 클래스는 속성이 없는 기능만을 가진 클래스가 존재할 수 있다.** 식별한 엔티티는 각각 상세한 명세를 작성한다.

## 항목 설명 (원문 전 항목)
- **ERD ID / ERD 명**: ERD별 유일 ID / 이름.
- **엔티티 ID / 엔티티명**: 엔티티별 유일 ID / 도출된 엔티티 명칭.
- **엔티티 설명**: 간단한 설명.
- **속성명**: 엔티티 속성의 내용과 특성을 인식할 수 있는 명칭.
- **동의어**: 동일한 의미로 사용되지만 하나의 용어로 표준화되지 못한 속성명.
- **타입**: 속성의 타입을 문자, 숫자, 날짜 등으로 기술.
- **길이**: 속성의 최대 허용 길이.
- **NOT NULL**: 필수항목 여부.
- **PK**(Primary Key) / **FK**(Foreign Key) / **INX**(Index).
- **기본값**: 있는 경우 그 값.
- **제약조건**: 특이한 제약조건이 있는 경우.

## 작성 사례 요점
- ERD: `JJ_ERD_040 | 거래중계` — 엔티티 박스(속성 나열)와 관계선.
- 엔티티 명세: `JJ_EN_110 | 기관거래 | 관련 클래스 ID JJ_DC_090 | 관련 클래스명 기관거래 | 설명: 외부 기관과의 송수신되는 거래내역을 저장` + 속성(거래일자 CHAR 8 Y Y / 일련번호 INTEGER 8 Y Y / 기관코드 CHAR 4 Y).

## 주의 / KLID 적용
- **관련 클래스 ID/명은 헤더 필수 행** — D1 설계 클래스 ID(`KLID-AT-DC-NNN`)와 **동일 체계**로 매핑(독자 번호 부여 금지). D1 미정의 엔티티는 `- ※` + 사유.
- 속성 표는 10컬럼 전부 채움(동의어·INX 포함). KLID는 추가로 관련 유스케이스 ID 행을 둬 R1→R2→D1→D8→D9 추적 사슬 유지.
- 논리 모델(타입: 문자/숫자/날짜 수준) — 물리 컬럼·DBMS 타입은 D9 영역.
