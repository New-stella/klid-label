# I3 DB 생성 스크립트 (데이터베이스 테이블) (CBD 표준 산출물 위키)

> ※ 양식 제목은 "DB 생성 스크립트". 담당 호칭 "데이터베이스 테이블"은 산출물 분류 명칭.

## 1. 작성 목적 (PDF 원문)

설치할 목적의 물리 데이터베이스 테이블의 명세와 테이블, 초기데이터 등을 생성하기 위한 생성 스크립트를 작성한다.

## 2. 작성 방법 (PDF 원문)

데이터베이스 테이블 및 생성 스크립트의 목록을 기술하고, 하드웨어 배치도 상의 데이터베이스 설치 위치를 표시하며 **테이블 생성 스크립트를 DDL로** 작성한다.

## 4. 항목 설명 (PDF 원문 — 전 항목)

목록:

- **관련 서브시스템**: 본 생성 스크립트에 관련되는 서브시스템명을 기입한다.
- **생성 스크립트 ID**: 테이블 생성 스크립트 ID를 부여하여 기입한다.
- **생성 스크립트명**: 테이블 생성 스크립트의 명칭을 기입한다.
- **데이터베이스 ID**: 생성 스크립트에 관련된 데이터베이스 ID를 기입한다.
- **데이터베이스명**: 생성 스크립트에 관련된 데이터베이스 이름을 기입한다.
- **테이블 ID**: 생성 스크립트에 포함된 테이블 ID를 기입한다.
- **테이블 명**: 생성 스크립트에 포함된 테이블 이름을 기입한다.
- **인덱스 ID**: 생성 스크립트에 포함된 인덱스 ID를 기입한다.
- **인덱스 명**: 생성 스크립트에 포함된 인덱스 이름을 기입한다.
- **트리거**: 테이블별로 관련된 트리거가 있으면 트리거의 내용을 기술한다.
- **설치 위치**: 테이블이 설치될 **하드웨어 명칭 또는 모델명**을 기술한다.

## 5. 작성 사례 요점 (PDF 작성 사례)

| 관련 서브시스템 | 생성 스크립트 ID | 스크립트명 | DB ID | DB명 | 테이블 ID / 테이블명 | 인덱스 ID / 인덱스명 | 트리거 | 설치 위치 |
|-----------------|------------------|------------|-------|------|----------------------|----------------------|--------|-----------|
| POS | JJ_DDL_040 | Produt.ddl | JJ_DB_050 | 상품DB | JJ_TS_040 상점 / JJ_TS_050 카탈로그 / JJ_TS_060 상품명세 | JJ_IDX_040 주소Index | 상품Table DDL | POS.PROD… |

- **스크립트 1건이 복수 테이블 포함 가능** (JJ_TS_040/050/060 → 단일 스크립트 JJ_DDL_040).
- ID 네이밍: `JJ_DDL_040`(생성 스크립트), `JJ_DB_050`(DB), `JJ_TS_0NN`(테이블), `JJ_IDX_040`(인덱스).
- 트리거 칸에 "상품Table DDL" 식으로 관련 내용 기재, 설치 위치는 물리 노드명(`POS.PROD…`).
- §2·§3은 스크립트 파일 제출로 갈음.

## 6. 함정 / 주의

- **D8/D9 → I3 사슬**: I3는 D8 ERD·D9 DB 설계서 기반 DDL 산출물. 테이블/컬럼/인덱스 정의가 설계서와 어긋나면 정합성 결함 — 설계 변경 시 I3 DDL도 동반 갱신.
- 5개 상위 헤더(생성스크립트·DB·테이블·인덱스 각 ID/명)의 ID/명 2컬럼 구조를 축약하지 말 것.
- 설치 위치는 논리 위치가 아닌 **하드웨어 명칭/모델명** — 배치도와 일치시킬 것.
- DDL 본문·초기데이터는 §2·§3 스크립트 파일 제출로 갈음 (목록 표에 SQL 전문 붙여넣지 않음).
- 단계명은 "구현" 고정.

## 7. KLID 프로젝트 적용 메모

- KLID는 **Flyway 마이그레이션**(`backend/src/main/resources/db/migration/`, PostgreSQL 표준 DDL)이 §2(DB생성 스크립트)·§3(코드 및 초기 데이터 생성 스크립트)의 실체. 목록 표에 마이그레이션 파일(`V*.sql`)을 생성 스크립트 ID로 매핑한다.
- 데이터베이스/스키마는 `klid_at`(저작도구 전용). 테이블 ID/명은 저작도구 전용 `LS_*` 테이블을 대상으로 기재한다.
- 공유 `MNG_*` 테이블은 관제서버 소유(JPA `ddl-auto=validate`, READ 위주)이므로 I3 생성 스크립트 대상에서 제외 — 변경 시 관제서버팀 선승인 필수. (Quartz `QRTZ_*`도 인프라 제공분.)
- 설치 위치는 단일 인스턴스 서비스 배포 환경의 PostgreSQL 노드(local/dev/stg/prd)로 기재.
- 테이블/인덱스 ID는 D8 ERD·D9 DB 설계서 식별자 및 KLID 추적 코드(`KLID-AT-XX-NNN`)와 정합되게 부여.
- 승인자 등 정보 부족 항목은 비워두고 보완 필요로 표시.
