# T7 인수시험 결과서 (CBD 표준 산출물 위키)

## 1. 작성 목적 (PDF 원문)

> 총괄시험 계획서와 인수시험 시나리오에 따라서 수행한 시험 결과를 기술한다.

핵심: T7은 **총괄시험 계획서 + 인수시험 시나리오(T6)**를 근거로 실제 인수시험을 수행하고 그 결과를 기록하는 산출물이다.

## 2. 작성 방법 (PDF 원문)

> **사용자 요구사항의 시스템 반영여부를 시험**하고 시험결과를 작성한다.

- 사용자 요구사항이 시스템에 정확히 반영되었는지를 시험하여, 시나리오 각 케이스의 "시험결과" 컬럼을 채운다.

## 4. 항목 설명 (PDF 원문 — 전 항목 누락 금지)

> T7의 항목 설명은 PDF에서 2개 항목으로 요약되며, 세부 컬럼 의미는 T6(인수시험 시나리오) 항목 설명을 따른다.

### ◼ 시험 시나리오
- "인수시험 시나리오"의 시험 시나리오를 **현행화**하고, 인수시험을 수행한다.

### ◼ 시험 케이스
- "인수시험 시나리오"의 시험 케이스를 **현행화**하여 시험을 수행 후, **시험결과를 기록한다.**

> 즉 T7 고유 작성 행위 = ① 시나리오/케이스를 현행화(최신 상태 반영) → ② 시험 수행 → ③ 시험결과 컬럼 기록.
> 각 컬럼(시험시나리오 ID/명/설명, 관련 요구사항 ID, 시험케이스 ID/설명, 시험절차, 순번, 업무처리내용, 시험항목, 사전조건, 입력자료, 예상결과, 화면ID, 시험결과, 비고)의 정의는 **T6 §4 항목 설명 참조**.

## 6. 함정 / 주의

- **T6와 동일 양식·다른 행위**: 양식은 인수시험 시나리오(T6)와 동일하다. T7의 본질은 "현행화 + 수행 + 결과 기록"이며, 시나리오를 그대로 복붙하지 말고 최신 상태로 현행화한 뒤 결과를 채워야 한다.
- **성공·실패 모두 증빙 중심**: 시험결과는 "예상결과와 동일", "오류발생"처럼 판정을 적되 반드시 **증빙 화면(화면N 참조)**을 동반한다. 단순 "OK/NG"만 적지 않는다.
- **시험팀·근거·환경 사슬**: 인수시험(T6/T7)은 **고객(발주자) + 프로젝트 시험팀**이 **계약서 및 합의된 사용자 요구사항 정의서**를 기준으로 **운영환경**에서 수행한다. 근거 문서는 총괄시험 계획서 + 인수시험 시나리오(T6).
- **실패 항목 처리**: 오류 발생 케이스는 조치 후 재시험하며, 재시험 시 **차수(1차→2차…)를 증가**시켜 재기록한다.
- 요구사항 ID 기준 추적이므로, 전 요구사항이 인수시험 결과로 커버·판정되었는지 확인한다.

## 7. KLID 프로젝트 적용 메모

- 사용자 요구사항 반영여부의 **최종 검증** 산출물 — 실패 항목은 조치 후 재시험(차수 증가) 기록. 발주자(고객) 주도 시험이므로 결과 표현은 증빙 중심(화면 참조)으로 작성.
- **시험팀·근거·환경 사슬**: 인수시험은 고객 + 프로젝트 시험팀이 계약서·합의된 사용자 요구사항 정의서를 기준으로 운영환경에서 수행하며, 그 결과를 T7에 기록한다.
- KLID 관련 요구사항 ID는 R1 실존 `RQ-SFR-NN-NN` + `NFR-NNN`을 매핑하여 추적한다(T6와 동일 체계).
- KLID 인수시험 결과 코드 체계 권장: **`KLID-AT-T7-NNN`** (T6 시나리오 `KLID-AT-T6-NNN`과 1:1 대응). 시험결과 증빙 화면은 KLID 화면 정의(SCR-*) 캡처/번호로 참조한다.
