# D4 인터페이스설계서 (CBD 표준 산출물 위키)

> 출처: NIA CBD 가이드(2011.12) docs/CBD.pdf 인쇄면 p.54~59 (PDF 페이지 57~62). 가이드 §2.4 "인터페이스 설계서".
> ※ 양식 헤더 박스의 산출물명은 "인터페이스 **정의서**"로 인쇄되어 있으나(작성 사례 헤더 동일), 목차·산출물 코드(D4) 명칭은 "인터페이스 **설계서**"다. 두 표기가 원문에 혼재한다.

## 1. 작성 목적 (PDF 원문)

> 시스템의 내.외부 인터페이스를 식별하고 인터페이스의 명세를 기술한다.

## 2. 작성 방법 (PDF 원문)

> 식별된 인터페이스를 송신측과 수신측으로 구분하여 기술하고 송.수신간의 인터페이스 방식을 기술하며, 데이터 송신 시스템과 수신 시스템간의 데이터 저장소와 속성 등의 상세 내역을 기술한다.

## 4. 항목 설명 (전 항목 — PDF 원문, 누락 금지)

### 인터페이스 목록
- **송신 인터페이스번호**: 송신 시스템의 인터페이스 일련번호를 기입한다.
- **송신 일련번호**: 한 개 송신단위에서 여러 개의 서브시스템으로 동시에 전송되는 경우에는 순차적으로 기술한다.
- **송신 시스템명**: 송신 시스템이름을 기술한다.
- **송신 프로그램 ID**: 송신에 해당하는 프로그램 ID를 기입한다.
- **전달 처리형태**: 인터페이스를 처리하는 형태를 기술한다. Batch / Online 등.
- **전달 인터페이스방식**: 통신 프로토콜 및 통신 기술 방식을 기술한다.
- **전달 발생빈도**: 인터페이스 발생빈도를 기술한다. "회수/주기"의 형식으로 기술한다.
- **수신 상대 담당자**: 수신 시스템의 업무담당자명을 기술한다.
- **수신 프로그램 ID**: 수신과 관련된 프로그램 ID를 기입한다.
- **수신시스템명**: 인터페이스 수신 시스템명을 기술한다.
- **수신 일련번호**: 수신 시스템의 동일 인터페이스가 여러 시스템에서 동시에 수신을 받는 경우에 순차적으로 번호를 부여한다.
- **관련 요구사항 ID**: 해당 인터페이스와 관련된 분석단계의 "사용자 요구사항 정의서"의 요구사항 ID를 기입한다.
- **비고**: 특이사항 등을 기입한다.
- ⚠ **수신번호**: 항목 설명 본문에는 없으나 **작성 사례 표에 컬럼으로 존재**(상대 시스템 채번, 예: `RZ-AI-09`, `ZX-RZ-103`). 미보유 시 `-`.

### 인터페이스 명세
- **인터페이스 번호**: 송신 시스템의 인터페이스 일련번호를 기입한다.
- **데이터송신시스템 시스템명**: 송신 시스템명을 기술한다.
- **데이터송신시스템 데이터저장소명**: 인터페이스 송신과 관련된 엔티티 또는 파일명을 기술한다.
- **데이터송신시스템 속성명**: 관련 엔티티의 속성명 또는 파일의 항목명을 기술한다.
- **데이터송신시스템 데이터타입**: 엔티티 속성 또는 항목 타입을 기술한다.
- **데이터송신시스템 길이**: 데이터의 길이를 기술한다.
- **송신 프로그램 ID**: 송신에 해당하는 프로그램 ID를 기입한다.
- **데이터수신시스템 데이터저장소명**: 인터페이스 송수신과 관련된 엔티티 또는 파일명을 기술한다.
- **데이터수신시스템 속성명**: 관련 엔티티의 속성명 또는 파일의 항목명을 기술한다.
- **데이터수신시스템 데이터타입**: 엔티티 속성 또는 항목 타입을 기술한다.
- **데이터수신시스템 길이**: 데이터의 길이를 기술한다.
- **데이터수신시스템 시스템명**: 수신 시스템명을 기술한다.
- **수신 프로그램 ID**: 수신에 해당하는 프로그램 ID를 기입한다.

## 6. 함정 / 주의

- **수신번호 컬럼 누락 주의**: 항목 설명에는 없고 작성 사례 표에만 존재한다. 목록 표 작성 시 빠뜨리기 쉽다 (2026-06-05 정합 반영).
- **명세 표는 요청/응답 페어링이 아니라 속성 매핑**이다. 동기 응답·수락 확인 등은 비고나 별도 명세로 보강한다.
- 헤더 박스 산출물명 표기(정의서/설계서) 혼재 — 문서 코드는 D4.
- 관련 요구사항 ID는 실존 요구사항 ID만 기입. 외부 미연동으로 담당자가 없으면 "미정"으로 두지 말고 사유 명시.
- **데이터타입 표기 (Critical)**: `데이터타입` 칸은 **실제 DB/SQL 데이터 타입 1개**를 적는다 — `VARCHAR`·`CHAR`·`BIGINT`·`INT`·`NUMERIC`·`TIMESTAMP`·`DATE`·`BOOLEAN`, 구조형(JSON 객체·배열)=`JSONB`, 바이너리 본문=`BYTEA`(경로/URL이면 `VARCHAR`). PDF 작성사례(§5) `접수일자 | CHAR | 8`처럼 **타입과 길이는 별도 칸**(길이는 `길이` 칸). 가능하면 **D9 물리 타입(엔티티 속성 타입)과 정합**시킨다.
  - ❌ **금지**: 한글 논리 라벨(`문자`/`숫자`/`날짜`/`이진`/`논리`)·괄호 주석(`문자(경로/URL)`·`이진(multipart)`)·복합 표기(`숫자 배열`·`객체(JSON)`·`목록`). 길이를 타입 칸에 붙이지 않는다.
  - ✅ **형식 뉘앙스는 속성명·비고로**: 경로/URL·업로드·배열 등은 **속성명**(예: '영상 경로', '바운딩박스 좌표')이나 비고로 표현하고, 타입 칸엔 SQL 타입만.
  - **송신↔수신 타입 대칭**: 같은 데이터의 송신·수신 타입을 다르게 적지 않는다.

## 7. KLID 프로젝트 적용 메모

- **수신번호 컬럼 누락 주의** (항목 설명에 없고 사례에만 있음 — 2026-06-05 정합 반영).
- 관련 요구사항 ID는 R1 실존 ID만(RQ-SFR + NFR), 외부 미연동 담당자는 "미정 — 연동 시 확정".
- 인터페이스번호 **KLID-AT-II-NNN**, REST/JSON·JDBC 방식, 멱등 헤더·HMAC 콜백 보호는 비고/하단 주석으로 기술.
- KLID 인터페이스 식별 후보 (송신/수신 + 방식 + 요구사항 ID 매핑):
  - **KLID-AT-II-001 비식별 호출**: 저작도구 → 비식별 서버, Online/REST(WebClient), 수시, DEIDENTIFY_API_URL.
  - **KLID-AT-II-002 ai-server 추론**: 저작도구 → ai-server, Online/HTTP, 배치 1건/분, YOLO/SAM2/VLM.
  - **KLID-AT-II-003 VLM 콜백 수신**: VLM 서버 → 저작도구, Online/REST `POST /v1/vlm/result`, 콜백.
  - **KLID-AT-II-004 관제 완료/수정 통지**: 저작도구 → 관제서버 inbound SPI, Online/REST(ControlNotifyClient), `TASK_COMPLETED`/`TASK_MODIFIED`, 영상 단위 디바운스 1회. 멱등(요청 ID)·인계 토큰/IP 화이트리스트 보호 — 비고 기재.
  - **KLID-AT-II-005 관제 학습용 영상 적재**: 관제 공유 DB(MNG_*) READ, Batch/JDBC(ControlTrainingVideoScanJob), 1건/분.
