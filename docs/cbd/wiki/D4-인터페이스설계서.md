# D4 인터페이스 설계서

> 출처: CBD.pdf §III.2.4 (문서 p45~49). ※ 양식 헤더 박스의 산출물명은 "인터페이스 **정의서**"로 인쇄되어 있으나 목차·체계상 명칭은 "인터페이스 설계서".

## 양식 구조

### 1. 인터페이스 목록 (그룹 헤더: 송신 / 전달 / 수신)

| 그룹 | 컬럼 |
|---|---|
| 송신 | 인터페이스번호, 일련번호, 송신시스템명, 프로그램 ID |
| 전달 | 처리형태, 인터페이스방식, 발생빈도 |
| 수신 | 상대 담당자 확인, 프로그램 ID, 수신시스템명, 일련번호, **수신번호** |
| - | 관련 요구사항 ID, 비고 |

### 2. 인터페이스 명세 (인터페이스별 1표, 행 = 전달 속성 1건)

| 그룹 | 컬럼 |
|---|---|
| - | 인터페이스 번호 |
| 데이터송신시스템 | 시스템명, 데이터저장소명, 속성명, 데이터타입, 길이 |
| - | 송신 프로그램 ID |
| 데이터수신시스템 | 데이터저장소명, 속성명, 데이터타입, 길이, 시스템명 |
| - | 수신 프로그램 ID |

## 작성 목적 (원문)
시스템의 내.외부 인터페이스를 식별하고 인터페이스의 명세를 기술한다.

## 작성 방법 (원문)
식별된 인터페이스를 송신측과 수신측으로 구분하여 기술하고 송.수신간의 인터페이스 방식을 기술하며, 데이터 송신 시스템과 수신 시스템간의 데이터 저장소와 속성 등의 상세 내역을 기술한다.

## 항목 설명 (원문 전 항목)

### 인터페이스 목록
- **송신 인터페이스번호**: 송신 시스템의 인터페이스 일련번호.
- **송신 일련번호**: 한 개 송신단위에서 여러 개의 서브시스템으로 **동시에 전송되는 경우에는 순차적으로** 기술.
- **송신 시스템명** / **송신 프로그램 ID**.
- **전달 처리형태**: 인터페이스를 처리하는 형태. **Batch / Online** 등.
- **전달 인터페이스방식**: 통신 프로토콜 및 통신 기술 방식.
- **전달 발생빈도**: **"회수/주기"의 형식**으로 기술.
- **수신 상대 담당자**: 수신 시스템의 업무담당자명.
- **수신 프로그램 ID** / **수신시스템명**.
- **수신 일련번호**: 수신 시스템의 동일 인터페이스가 여러 시스템에서 동시에 수신받는 경우 순차 번호.
- **관련 요구사항 ID**: 분석단계 "사용자 요구사항 정의서"의 요구사항 ID.
- **비고**: 특이사항.
- ⚠ **수신번호**: 항목 설명에는 없으나 **작성 사례 표에 존재** — 수신 시스템 측 인터페이스 번호(상대 시스템 채번, 예: `RZ-AI-09`). 미보유 시 `-`.

### 인터페이스 명세
- **인터페이스 번호**: 송신 시스템의 인터페이스 일련번호.
- **데이터송신시스템** 시스템명 / 데이터저장소명(송신 관련 **엔티티 또는 파일명**) / 속성명(엔티티 속성명 또는 파일 항목명) / 데이터타입 / 길이.
- **송신 프로그램 ID**.
- **데이터수신시스템** 데이터저장소명 / 속성명 / 데이터타입 / 길이 / 시스템명.
- **수신 프로그램 ID**.

## 작성 사례 요점
- 목록: `IR_II_01 | 1 | 창구통합접수시스템 | P_AI31101 | Online | Tmax | 수시 | 홍길동 | s_rg60101 | 발착중계운송관리시스템 | 1 | RZ-AI-09 | REQ-IF-RG001` / `IR_II_02 … X.25 | 100회/일 … 수신번호 ZX-RZ-103`. 인터페이스방식엔 기술 스택(Tmax, X.25)을 직접 기재.
- 명세(IR_II_01): 송신 저장소 `국내등기접수정보(PRRWT0110)` 속성(접수일자 CHAR 8 / 접수송달증번호 CHAR 10 / 등기용국기호 CHAR 6) ↔ 수신 저장소 `접수송달증정보(마스터)(PTRMT0040)` **동일 속성 좌우 대조**. 송신 프로그램 ID는 행마다 반복(P_AI31101), 수신 프로그램 ID도 행마다(s_rg60101).
- **의미**: 행 = 전달되는 데이터 속성 1건. 송신측 저장소의 속성이 수신측 저장소의 어느 속성으로 적재되는지의 매핑(요청|응답 페어링이 아님). 동기 응답·수락 확인은 비고로.

## 주의 / KLID 적용
- **수신번호 컬럼 누락 주의** (항목 설명에 없고 사례에만 있음 — 2026-06-05 정합 반영).
- 관련 요구사항 ID는 R1 실존 ID만(RQ-SFR + NFR), 외부 미연동 담당자는 "미정 — 연동 시 확정".
- KLID: 인터페이스번호 `KLID-AT-II-NNN`, REST/JSON·JDBC 방식, 멱등 헤더·HMAC 콜백 보호는 비고/하단 주석으로 기술.
