# D11 단위시험 케이스

> 출처: CBD.pdf §III.2.11 (문서 p101~104)

## 양식 구조 (단위시험=컴포넌트 단위 블록 반복)

- 헤더 블록: 단위시험 ID / 설명 / 관련 컴포넌트 ID | 관련프로그램 ID
- 케이스 행: | 케이스ID | 케이스명 | 작업권한 | 시험 데이터 | 시험항목 및 처리절차 | **예상결과 및 검증방법** | 시험결과 |

## 작성 목적 (원문)
단위 프로그램 및 컴포넌트를 설계한 개발자가 컴포넌트 명세서에 정의된 바와 같이 설계한 컴포넌트 프로그램의 오류를 검출할 목적으로 배포하는 **컴포넌트 단위로 시험하기 위한 시험 설계**를 기술한다.

## 작성 방법 (원문)
개발자가 설계한 **컴포넌트 단위로 작성하며 컴포넌트별 시험케이스를 작성**한다.

## 항목 설명 (원문 전 항목)
- **단위시험 ID**: 단위 컴포넌트(프로그램)별 유일 ID.
- **설명**: 단위 컴포넌트(프로그램)에 대한 간략한 설명.
- **관련 컴포넌트 ID**: "컴포넌트 설계서"의 컴포넌트 ID.
- **관련 프로그램 ID**: 관련되는 프로그램 ID.
- **케이스 ID**: 케이스별 식별자 / **케이스명**: 케이스 명칭.
- **작업권한**: 적용하는 사용자 권한.
- **시험 데이터**: 케이스 실행에 필요한 시험 데이터. (실제 데이터 값이 아닐 경우는 **조건을 표시**할 수 있다.)
- **시험항목 및 처리절차**: 시험 데이터를 입력하여 시험하는 단계와 단계별 처리 절차 및 방법.
- **시험결과**: **설계단계에서는 기술하지 않으며**, 시험결과서 활용 시 실제 결과 기술.
- ⚠ **예상결과 및 검증방법**: 항목 설명에는 없으나 **양식·사례 표에 존재** — 기대 결과 + 검증 수단(화면 표시 확인·SQL DB 확인 등) 병기.

## 작성 사례 요점
- 헤더: `KK_UT_TS_030 | 커뮤니티사용자와 커뮤니티관리자가 업무 영역별 게시판에 게시물을 등록/수정/삭제/조회 한다. -게시판, FAQ, Q&A 유형 모두 포함… | 관련 컴포넌트 KK_CO_110 | 관련 프로그램 UI.OSZBI.1.1.1`.
- 케이스: `TC_01_010 | 게시판목록 조회-일반 | 전체 | 게시물데이터(오늘, 이전일 데이터) | 1.메뉴에서 화면 선택 2.초기화면에 게시판목록 Display 확인: 오늘일자가 게시기간에 포함된 것… | 화면에 목록 디스플레이 + SQL로 DB확인 SELECT * FROM 게시판 WHERE ~~ | (공란)`.
- `TC_01_020 게시판목록 조회-데이터없음 | 데이터없음 | … | 해당데이터 없음 메시지 표기 + SQL로 DB확인` — **정상/예외 케이스 분리** 패턴.

## 주의 / KLID 적용
- **예상결과 및 검증방법 컬럼 누락 주의** (항목 설명에 없음 — 표에는 있음).
- 작업권한 = KLID 역할(REVIEWER/WORKER/PORTAL_USER). 관련 컴포넌트 ID는 D3 실존 `KLID-AT-CO-NNN`, 관련 프로그램 ID는 `KLID-AT-IC-NNN` 또는 구현 클래스명.
- **시험결과 설계단계 공란** → I2 단위시험 결과서에서 현행화. KLID 실행: JUnit 5 + Testcontainers(PostgreSQL).
