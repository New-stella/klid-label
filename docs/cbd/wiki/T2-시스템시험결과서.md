## 4. 항목 설명 (전 항목 — PDF 원문)

- **(작성 방법 항목 설명)**: 설계단계 산출물인 "시스템시험 시나리오"를 **현행화**하여 시험을 수행 후, **시험결과를 기록**한다.

### 본문 표 컬럼별 의미 (양식·사례 기준)
- **시험 유형**: 성능/부하/볼륨/보안 등 시스템시험 유형 분류.
- **관련 유스케이스ID**: 연관 유스케이스 식별자 (사례 값 `SS_UCD_010-01`). D7과의 추적은 요구사항 ID 기준일 수 있음(§6).
- **시험시나리오 ID**: 시나리오 식별자 (예: JJ_ST_050, JJ_ST_060).
- **시험시나리오**: 시나리오명 (예: "출하실적 리포트 조회 기능").
- **시험절차**: 시험 수행 절차 (예: "100개의 품목에 대하여 총 출하한 …건(30일 × N개/1일) 출하를 등록한 후 30일(N건) 조회, 1일(N건) 조회에 대한 출하실적 리포트 조회 기능 실행").
- **만족기준**: 통과 기준 — 지표(●)와 세부조건(◆)으로 구조화. 예: `●응답 시간 ◆30,000건 데이터 조회: 40초 ◆7,000건 조회: 10초 ◆1,000건 조회: 2초 ●CPU 사용률 ◆… ●메모리 사용량 …`.
- **시험결과**: 만족기준 지표(●/◆)별 **실측치 대응 기재**. 예: `●응답 시간 ◆30,000건: 20.12초 ◆7,000건: 5.44초 ◆1,000건: 0.95초 ●CPU 사용률 — 출하실적 조회(30,000건) 시 서버 CPU 사용률 최대 33%까지 증가 후 작업 완료 후 이전 상태 유지 ●메모리 사용량 …`. 또는 "만족기준 준수(상세내용 별첨2 참조)".
- **비고**: 부가 기재 (예: "자동화도구 사용 결과 / 만족기준 준수(상세 결과는 별첨2 참조)").

## 5. 작성 사례 요점 (실제 값/패턴)

PDF 작성 사례 발췌:
- **JJ_ST_050** (D7 시나리오 재사용): 시험결과 = "만족기준 준수(상세내용 별첨2 참조)". → 증빙 별첨 패턴.
- **JJ_ST_060**: 시험결과에 측정치 직접 기재 —
  - 응답시간: 30,000건 = 20.12초 / 7,000건 = 5.44초 / 1,000건 = 0.95초
  - CPU 사용률: 30,000건 조회 실행 시 서버 CPU 사용률 최대 33%까지 증가하였다가 작업 완료 후 이전 상태 유지
  - 메모리 사용량: (출하실적 조회 시 메모리량 …)
- **핵심 패턴**: 만족기준의 지표(●)·세부조건(◆)별로 **실측치를 1:1 대응**시켜 기재. 길거나 그래프성이면 "별첨N 참조"로 증빙 연결.
- 만족기준 예: `3,000건 조회 시 최대 50MB 이내`, `30,000건 조회 시 최대 40%(CPU)` 등 정량 기준.

## 6. 함정 / 주의

- **표기 불일치(⚠)**: 가이드 내에서 T2 양식·사례는 상단 블록을 **"관련 유스케이스ID"**(사례 값 `SS_UCD_010-01`)로 표기하지만, 설계단계 **D7(시스템시험 시나리오)**의 동일 블록은 **"관련 요구사항ID"**로 표기된다. 두 산출물의 추적 키가 명목상 어긋남 → KLID에서는 D7과의 추적 일관성을 위해 정책 필요(§7).
- **현행화 사슬(Critical)**: T2는 **D7 시스템시험 시나리오**(설계단계)를 **현행화**하여 동일 ID·시나리오·만족기준을 유지한 채 **시험결과만 채우는** 산출물. 사슬: `D7(시스템시험 시나리오, 설계) → 시스템시험 수행 → T2(시스템시험 결과서, 시험단계, 결과 현행화)`.
- 만족기준과 시험결과는 **지표(●/◆) 구조를 동일하게 미러링**해야 비교 가능 — 결과만 별도 서술하면 통과 판정 추적 어려움.
- 정량 측정치는 단위(초/%/MB/건) 명시 필수. 그래프·캡처는 별첨으로.
- 헤더박스 식별 코드는 **T2**, 단계명 = "시험".

## 7. KLID 프로젝트 적용 메모

> 기존 KLID 적응(D7 현행화·표기 불일치 정책·실측치 대응 기재) 보존 + 본 단계 추가.

### KLID 적응 보존
- ⚠ 가이드 내 표기 불일치: D7 블록 헤더는 "관련 요구사항ID", T2 양식·사례는 "관련 유스케이스ID"(사례 값 `SS_UCD_010-01`). KLID는 **D7과의 추적 일관성을 위해 관련 요구사항 ID(NFR/RQ-SFR) 유지 + 필요 시 UC 병기**를 권장.
- 시험결과는 만족기준 지표별 실측치 대응 기재(별첨 증빙 가능).

### KLID 도메인 적용 (시험 유형별 후보)
- **성능/응답시간**: 라벨 저장(`LS_DATA_LBL` upsert), 검수 승인 스냅샷(`LS_LABEL_VERSION`), View 4종(`V_COMPLETED_*`) 조회 응답시간. Micrometer/Prometheus 메트릭(API 응답시간·배치 처리량·외부 API 호출)을 만족기준 지표로 사용.
- **부하/볼륨**: 산출물 목표 규모 기준 — 이미지 학습데이터 10만장(SFR-16), 영상 5,000건(SFR-17). 대량 프레임/라벨 조회 시 페이징·N+1 가드 검증.
- **배치 처리량**: Quartz 1건/분(`ControlTrainingVideoScanJob`), ai-server(YOLO/SAM2) GPU 처리 시간, 비식별 선두 단계 처리 시간.
- **보안**: JWT 검증(`JwtAuthenticationFilter`), 역할 기반 접근(REVIEWER/WORKER/PORTAL_USER), 비식별 미완료 스트리밍 차단, 통지 페이로드 PII·토큰 미포함, 로그 마스킹(MaskingPatternLayout). OWASP/Fortify/CodeQL 통과를 만족기준에 반영.
- **외부 API 회복성**: Resilience4j(타임아웃/재시도/서킷) — 비식별·ai-server·VLM 호출의 타임아웃(VLM 45s, AI 60s) 만족 여부.
