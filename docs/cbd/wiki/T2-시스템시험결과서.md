# T2 시스템시험 결과서

> 출처: CBD.pdf §III.4.2 (문서 p143~146). 단계명=시험.

## 양식 구조

D7 시스템시험 시나리오와 동일 구조 + 시험결과 기입:

| 시험 유형 | (성능/부하/볼륨/보안 등) |
|---|---|
| **관련 유스케이스ID** | ⚠ 양식·사례 표기 — D7은 "관련 요구사항ID" |

| 시험시나리오 ID | 시험시나리오 | 시험절차 | 만족기준 | **시험결과** | 비고 |
|---|---|---|---|---|---|

## 작성 목적 (원문)
총괄시험 계획서와 시스템시험 시나리오에 따라서 수행한 시험 결과를 기술한다.

## 작성 방법 (원문)
성능, 부하, 볼륨, 보안 등 시험 유형별로 시스템시험을 수행하고 시험 예상결과와 시험결과를 비교한다.

## 항목 설명 (원문)
설계단계 산출물인 "시스템시험 시나리오"를 **현행화**하여 시험을 수행 후, 시험결과를 기록한다.

## 작성 사례 요점
- `JJ_ST_050`(D7 시나리오 재사용): 시험결과 "만족기준 준수(상세내용 별첨2 참조)". `JJ_ST_060`: 시험결과에 측정치 직접 기재 — "●응답시간 ◆30,000건: 20.12초 ◆7,000건: 5.44초 ◆1,000건: 0.95초 ●CPU 사용률 — 출하실적 조회 기능 실행(30,000건 조회) 시 서버의 CPU 사용률은 최대 33%까지 증가하였다가 해당 작업이 완료된 후에는 이전 상태를 유지함 ●메모리 사용량 …".
- 만족기준의 지표(●/◆)별로 **실측치를 대응 기재**하는 패턴.

## 주의 / KLID 적용
- ⚠ 가이드 내 표기 불일치: D7 블록 헤더는 "관련 요구사항ID", T2 양식·사례는 "관련 유스케이스ID"(사례 값은 `SS_UCD_010-01`). KLID는 **D7과의 추적 일관성을 위해 관련 요구사항 ID(NFR/RQ-SFR) 유지 + 필요 시 UC 병기**를 권장.
- 시험결과는 만족기준 지표별 실측치 대응 기재(별첨 증빙 가능).
