## API 사양 요약

| 항목 | 값 |
|------|---|
| URL | `GET /api/v1/export-api/datasets/{rawSn}?merge={true\|false}` |
| 인증 | `X-M2M-Token` 헤더 (scope=LEARNING_DATA) |
| 인가 | `M2M_LEARNING_DATA` 권한 (CONTROL 토큰으로 우회 불가) |
| 성공 | `200 OK` + `ApiResponse<DatasetResponse>` |
| 실패 | `401` (토큰 누락/오류/scope 불일치) · `404` (영상 없음) · `400` (rawSn 파싱 실패, Spring 기본) |

## 잔여 위험

- **LS_DATA_META UK 제약**: 현재 UK 는 `(RAW_SN, META_KEY)` — 같은 META_KEY 의 RAW/DEID 충돌 row 는 DB 가 거부한다. 외부 응답의 분리/병합은 정상 시나리오(서로 다른 key)에서만 의미가 있다. 만약 운영 중 동일 key 가 두 출처에서 모두 산출되어야 한다면 V24 마이그레이션으로 UK 를 `(RAW_SN, META_KEY, META_TYPE_CD)` 로 확장해야 하며, **klid_system 공유 DB 변경이므로 관제서버팀 선승인 필요**.
- **LsDataSet 엔티티 보존**: 기존 `LS_DATA_SET` 테이블은 VideoQueryService → VideoExportProjection → `findLatestExportsByRawSns` 경로에서 영상 목록 화면용으로 여전히 native query 참조 중이다. 엔티티/Repository 는 유지하되, SCR-EXPORT 의 controller/service/quartz/dto/writer 는 모두 제거됨.
- **FE 영향**: `/v1/exports/**` 호출이 FE 어딘가에 남아 있으면 404. FE 측 SCR-EXPORT 제거 작업이 별도 위임됨.
