# CBD 산출물 생성 입력값

설계 원장에서 **도출되지 않는** 칸의 값을 둔다. 레시피가 스스로 *"스키마에 축이 없다"* 고 말하는
자리들이며, 그런 칸은 원천 항목을 아무리 채워도 채워지지 않는다.

## 이것은 원장이 아니라 원장의 **재료**다

레시피가 실제로 읽는 이관 원장은 **`convert-service` 레포의 `overlays/`** 에 있다. 여기 있는 것은
그 원장을 만들 때 쓰는 입력이다. **값을 두 곳에 두면 한쪽만 고쳐지므로** 이 구분을 지운 채
「원장」이라 부르지 말 것.

## 왜 레포에 두나

값의 출처인 승인된 제출본(hwpx)은 **레포 밖 사용자 로컬**에 있다. 다른 기계에서 체크아웃하면
그 파일이 없어 값을 다시 뜰 수 없다. 그래서 **뜬 결과를 레포에 둔다.**

## 파일

| 파일 | 담은 것 |
|---|---|
| `D5-아키텍처-원장재료.json` | 제출본에서 셀 단위로 뜬 값 + `_현재형상_갱신`(실측 정정, 근거 병기) |
| `D11-단위시험절차서-초안.md` | 단위시험 케이스 원문. 생성기가 `--draft` 로 문다 |

### ★`D11-단위시험절차서-초안.md` 는 **이 사본이 정본이다**

같은 파일이 `workspace/klid/docs/design/` 에도 있는데 **그 자리는 git 밖**이라 다른 기계에서
체크아웃하면 없다. 그래서 레포로 들여왔다. **생성할 때 `--draft` 로 이 경로를 준다.**

⚠ **두 벌이 갈리는 것이 이 파일의 유일한 위험이다.** 레포 밖 사본을 고치면 산출물은 바뀌는데
레포는 그대로이고, 다음 사람이 체크아웃하면 그 변경이 통째로 없다. 아래 검사가 그것을 본다.

각 파일의 `_읽는법` 에 **무엇을 · 어디서 떠서 · 안 채우면 무엇이 마커가 되는지**가 있다.

## 쓰기 전에

**제출본 값을 그대로 옮기지 말 것.** 감리를 통과했다는 것이 지금도 맞다는 뜻은 아니다.
어느 칸이 낡았는지는 `_현재형상_갱신` 이 왼쪽(제출본)·오른쪽(실측)으로 갈라 놓았다.

**일부러 비운 칸이 있다** — 두 출처가 어긋나 확인되지 않은 값이다. 마커와 그 이유가 산출물에
나가는 것이 지어낸 값보다 낫다.

## 값을 고쳤으면 돌린다

```bash
python3 docs/cbd-inputs/verify.py
```

값 키에 폐기된 값이 새어 들어갔는지 본다. **양성 대조가 함께 있다** — 「폐기 값 0건」만 세면
훑는 축이 틀렸을 때도 0건이 나와 조용히 통과하므로, 현행 값이 실제로 잡히는지를 같은 훑기로
함께 확인한다. 안 잡히면 파일이 깨끗한 게 아니라 **검사기가 눈먼 것**이다.

⚠ 실제로 그 양성 대조가 처음 짠 검사기의 눈먼 자리를 잡았다. 「`_` 로 시작하면 설명」이라는
규칙을 썼다가 값 컨테이너 하나를 통째로 건너뛰어 **값을 하나도 안 보고 있었다.**

절차와 함정은 `docs/rules/cbd-generation.md`.
