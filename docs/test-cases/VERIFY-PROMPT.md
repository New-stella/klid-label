## 1. ★ 대전제 — 실동작 기준 (타협 불가)

> **"코드가 그렇게 보인다"가 아니라 "실제로 그렇게 동작한다"를 판정한다.**

1. **목업서버 기동 필수** — 외부 연동(비식별 KPST · VLM · 증강)은 **전부 `mock-server`(:9400)가 대행**한다. 실벤더를 호출하지 않는다.
2. **로컬은 무조건 목업서버를 바라본다** — 내부 목 모드(`DEIDENTIFY_MOCK_MODE=true` 류)로 외부 호출을 건너뛰는 우회는 금지.
3. **자체 채움(self-fill) = 결함** — 본 프로그램이 **외부 응답 없이 값을 만들어 넣거나 하드코딩 기본값으로 메꾸면 FAIL**. 값은 항상 외부 연동 응답에서 와야 한다.
   *(이 프로젝트의 반복 결함 패턴이다. 내부 목 모드로 값을 자체 생성하면 로컬에서는 통과하지만 실환경에서 외부 계약이 어긋난 걸 전혀 못 잡는다.)*
4. **배치를 실제로 구동**한다 — 파이프라인(비식별→마킹→VLM→프레임추출→오토라벨링→보간)이 흐르는 정상 시나리오를 만들어 그 위에서 판정한다.
5. **풀스택 기동** — PostgreSQL + backend + ai-server + mock-server + frontend.

### 착수 전 환경 게이트
`docs/검증결과/{날짜}/{회차}/_raw/stack-bringup.md` 확인:
- 없으면 → **먼저 §3-1 로 풀스택을 띄우고 배선을 실측 기록**
- 있으면 → 기동 상태·배선 O/X 를 읽고, **배선 X 인 연동에 걸린 케이스 판정에 반드시 반영**
- 스택이 안 뜨거나 배선이 깨져 정상 시나리오를 못 만들면 → **임의로 정적 판정으로 후퇴하지 말고 사용자에게 보고하고 지시를 받는다**

   - **★3 좌표 검증 2축** — 사용자 저장 = **400 거부** / AI 검출 응답 = **clamp + 퇴화 스킵**. 통일 대상 아님

   - **★5 영상 목록(`GET /v1/videos`) 필터 오류 처리 비대칭** — 검색어 100자 초과·날짜 형식 오류·`from>to` = **400** / **미등록 `eventTypeCd` = 400 아닌 0건**. "비일관"으로 보고하지 말 것
   - **#1 포털 SAM2 노출** = 문서가 정본, 정책 위반 → **결함(FAIL)** 유지. 단 전송 픽셀이 비식별본으로 바뀌어 심각도는 완화됨

   - 나머지 미확정 항목 = `확인필요` 표기, **사실만 기록**(임의 확정 금지)

## 5. 검증 방법 (케이스 1건마다)

| 순서 | 방법 |
|:--:|------|
| 1 | **실동작 확인 (최우선)** — 스택에 실제 요청을 보내거나 파이프라인을 태워 기대결과가 나오는지 확인. **응답 원문·DB 상태·목업서버 로그**를 근거로 |
| 2 | **정적 대조** — 근거 칸의 **파일**을 열어 기대결과와 대조. 해당 판정이 **그 파일에 없으면** Grep 으로 실제 위치를 찾아 **근거 드리프트로 집계**(카탈로그 정합성 결함). ⚠ 근거는 **파일 단위**이며 라인번호를 적지 않습니다 — 라인이 없다고 드리프트로 집계하지 마세요(2026-08-05 확정). 정정이 필요한 경우는 **파일이 이름 변경·삭제·이동됐거나 판정 주체가 다른 클래스로 옮겨간 때**뿐입니다 |
| 3 | **테스트 커버 확인** — 기존 자동 테스트를 Grep 해 `파일:메서드명` 기록 + `_raw/test-baseline.md` 에서 통과 여부 대조 |
| 4 | **외부 연동 케이스** — 목업서버를 **실제로 경유**했는지 확인. 경유 없이 값이 채워졌으면 **self-fill 결함(FAIL)** |

### 판정값
| 값 | 의미 |
|----|------|
| **PASS** | 실동작으로 기대결과 확인 (또는 정적 대조가 확실하고 실동작이 뒷받침) |
| **FAIL** | 기대결과와 다름 = 결함. **self-fill 도 여기** |
| **PARTIAL** | 일부만 충족 / 방어가 불완전 |
| **BLOCKED** | 풀스택으로도 재현 불가(외부 실벤더 필요·2노드 필요 등) — **사유 필수**. ⚠ "환경 안 띄워서 못 봄"은 BLOCKED 가 **아니라** 환경을 띄워 해결할 일 |
| **N/A** | 전제가 코드에 없음 — 미구현 갭이면 FAIL 승격 판단 후 사유 기록 |
| **확인필요** | UNCERTAINTIES 미확정 — 사실만 기록 |

### ★★ 확증편향 금지 — 이 검증의 성패가 여기서 갈린다

**"코드가 있으니 PASS" 는 검증이 아니다. 실패 모드는 거짓 PASS 다.**
기대결과의 단언을 하나씩 **반증 시도**한다 — 경계값·null·예외경로·fail-open·우회 경로를 실제 분기와 실동작으로 확인한다.
**근거 없는 PASS 를 남발하면 이 검증 전체가 무가치해진다.**

> 실증 사례: A 클러스터(인증/권한) 152건은 정적 대조만으로는 **전부 PASS** 였다. 반증 과정에서 HMAC 필터 URL 인코딩 우회(CWE-436), 공유 정적 패스워드 권한상승(CWE-269), 로그 마스킹 미연결(테스트는 통과하는데 실제 파이프라인엔 미배선) 같은 HIGH 결함이 나왔다.

## 6. 작업 분할·모델 배정

- 클러스터 파일의 `## ` 섹션 헤딩으로 **2~5분할해 병렬 서브에이전트**로 실행 (케이스 40~60건/에이전트가 적정)
- 각 에이전트는 **결과 파일 1개만 생성**, 그 외 **모든 파일 수정 금지**(프로덕션·테스트·설정·문서 전부)
- 에이전트 최종 응답은 **20줄 이내 요약만** 요구 (표 원문 붙여넣기 금지 — 메인 컨텍스트 보호)
- 실동작 확인을 위한 **HTTP 요청·DB 조회·로그 조회는 허용**, **빌드/테스트 실행과 파일 수정은 금지**

### 모델 배정 (혼합 — 균일 배정 금지)
| 구간 | 모델 | 이유 |
|------|:----:|------|
| 정적 대조 대다수 | **sonnet** | 독해·대조 작업. 체급 차이가 판정 품질에 거의 반영 안 됨 |
| **보안 필터 · 동시성/Race · 상태전이 · 외부연동 계약** | **opus** | 거짓 PASS 위험 구간. "적극적 반증"에 체급 차이가 실제로 남 |
| 환경 기동 · baseline 실행 | **sonnet** | 명령 실행·파싱 |

> ⚠ 모델을 생략하면 세션 모델(보통 opus)을 상속해 비용이 샌다 — **항상 명시**한다.

### 구간별 반증 포인트 (에이전트 프롬프트에 반드시 포함)
- **인증/인가**: 우회 경로, fail-open catch, 권한 자가부여·상속으로 인한 수직 상승(CWE-269/862), IDOR(CWE-639)
- **서명/HMAC**: 상수시간 비교, replay 방지(nonce·시간창), **URL 인코딩·경로 정규화 불일치로 필터 스킵**(CWE-436)
- **외부 연동**: 목업 미경유 self-fill, 타임아웃·재시도·서킷브레이커 실동작, 계약 필드 불일치, 실패 시 fail-closed 여부
- **배치/동시성**: race, 중복 실행(Quartz 클러스터), 부분 실패 시 상태 정합, 트랜잭션 경계, PII 노출
- **상태전이**: 불법 전이 차단, 되돌리기, 동시 전이, 배치 상태와 작업/검수 상태의 **책임 분리**
- **PII/스트리밍**: 비식별 미완료 영상의 원본 노출, 경로 조작(CWE-22), 원본/비식별 경로 분리
- **예외/로깅**: 스택트레이스·내부경로 유출(CWE-209), PII·토큰 마스킹 **실제 적용 여부**, Log Injection(CWE-117)
- **쿼리**: N+1, 무페이징 전체조회, 인덱스 부재

## 7. 이슈 기록 형식 (Critical — 수정 작업의 입력)

FAIL / PARTIAL / 확인필요 **전건**에 대해 아래 6요소를 **빠짐없이** 기록한다.
수정 후 다음 회차에 이 블록으로 해소 여부를 대조하므로 **축약 금지**.

```markdown
### [{클러스터}-ISSUE-{nn}] {TC-ID} — {한 줄 제목}
- **심각도**: CRITICAL / HIGH / MEDIUM / LOW
- **기대 동작(기대효과)**: 이 케이스가 보장해야 하는 것 + 왜 필요한지
- **현재 동작(이슈 내용)**: 실제 동작 (file:line + 코드 스니펫 3~5줄, 실동작이면 요청/응답·DB상태·로그 근거)
- **재현/확인 경로**: 어떤 입력·조건에서 드러나는지 (실행 가능한 curl/SQL 우선)
- **영향**: 보안/데이터정합/기능 관점 영향 (보안이면 CWE 번호)
- **수정 방향(제안)**: 어디를 어떻게 (⚠ **구현은 하지 않는다**)
```
이슈 ID 는 에이전트별 시작번호를 나눠 부여(part1=01~, part2=21~, part3=41~ …) — **병렬 충돌 방지**.

> **⚠ 판정 셀 표기 규칙 (집계 정확도)**: 결과 표의 판정 컬럼에는 **`PASS` / `FAIL` / `PARTIAL` / `BLOCKED` / `N/A` / `확인필요` 여섯 토큰 중 하나만** 넣는다. `PASS(LIVE)`·`PASS(정적)`·`**PASS**` 처럼 꾸미면 회차 집계가 어긋난다(1차에서 실제로 발생). 실동작/정적 구분은 **`근거 확인` 컬럼에 `[실동작]` / `[정적]` 접두로** 적는다.

## 8. 클러스터 완료 처리

1. `_raw/{X}-part*.md` 를 `cat` 으로 `{X}-result.md` 에 병합 — **메인 컨텍스트에 내용을 싣지 말 것**
2. 이슈 블록을 `ISSUES.md` 에 누적 (클러스터 헤딩 + 심각도순)
3. **컨텍스트 점검** — 클러스터 경계에서 컨텍스트 사용률이 높으면(대략 60% 이상) **정지하고 사용자에게 보고**:
   완료 클러스터 · 판정 집계 · 주요 결함 3~5건 · 다음 클러스터 · 재개 방법.
   사용자가 compact 후 재개를 지시한다. **임의로 계속 진행하지 않는다.**
4. 여유가 있고 `all` 모드면 다음 클러스터 자동 진행

## 9. 전 클러스터 완료 시 — `SUMMARY.md`

- 클러스터별 집계표(총/PASS/FAIL/PARTIAL/BLOCKED/N/A/확인필요) + 전체 합계·PASS율
- **심각도순 결함 TOP** (CRITICAL·HIGH 전건)
- **★ self-fill 결함 전용 섹션** — 외부 연동을 안 타고 자체 채운 경로 (이 프로젝트의 핵심 관심사)
- BLOCKED 사유별 묶음 = 다음 회차에 필요한 환경
- **근거 드리프트 목록** = 카탈로그 자체의 정합성 결함
- UNCERTAINTIES 중 이번 검증으로 **사실이 확정된 항목** → 원본 갱신 제안

그 뒤 사용자에게 다음 단계를 묻는다: 결함 수정 착수 / 카탈로그 정정 / 종료.

## 10. 절대 규칙

1. **이 작업은 검증 전용 — 코드를 고치지 않는다.** 결함은 기록만 하고, 수정은 사용자 지시로 **별도 사이클**에서 수행한다.
   *(근거: 검증 중 코드가 바뀌면 앞뒤 판정 기준이 어긋나 회차 결과를 신뢰할 수 없다.)*
   - 예외: **검증 환경 구성**(목업 배선 설정 등)은 착수 전에 한해 허용. 단 **설정으로 안 되고 코드를 고쳐야만 목업을 볼 수 있다면 그것 자체가 결함**이므로 고치지 말고 기록하고 보고한다.
2. 검증 에이전트에게 **빌드/테스트 실행 금지**를 명시(baseline 담당 1개만 예외).
3. **PASS 판정에는 반드시 확인한 근거**(실동작 응답 또는 코드 인용)를 남긴다. 근거 없는 PASS 금지.
4. **환경을 안 띄운 채 정적 판정으로 후퇴하지 않는다.** 못 띄우면 사용자에게 보고.
5. 결과 파일 외 **어떤 파일도 에이전트가 수정하지 못하게** 프롬프트에 못박는다.

## 11. 이 프로젝트의 알려진 함정 (실측으로 확인된 것 — 반복 금지)

| 함정 | 내용 |
|------|------|
| **gradle 캐시** | `./gradlew test` 만 돌리면 `:test UP-TO-DATE` 로 **실제 실행이 안 된다** → `cleanTest test` 필수 |
| **gradle 동시 실행** | 테스트 에이전트 2개 이상 동시 실행 시 test-results XML 충돌로 **위양성 실패** → baseline 1개만 |
| **macOS** | `timeout` 명령이 없다 → 백그라운드 실행 + 폴링으로 대체 |
| **ai-server pytest** | 시스템 python 에 pytest 미설치 → `.venv/bin/python` 사용 |
| **DB 스키마** | 문서엔 `klid_at` 인데 **실제 적재는 `public`** 스키마 |
| **VLM 설정 키** | `vlm.client.url` 이며 `base-url` 과 **다른 키** |
| **KPST 응답** | `retrieve_progress` 의 `fileName` 은 **원본 입력 경로**이고 결과물은 `export_path` 의 `{stem}-mask{ext}` — 혼동하면 완료를 실패(`'F'`)로 오종결 |
| **PostgreSQL unique 위반** | 트랜잭션 **전체를 abort** 시켜 같은 tx 안에서 재시도 불가 → 별도 tx + `saveAndFlush` 필요 |
| **mock-server** | `MOCK_OUTPUT_BASE` 미설정 시 fail-closed · `retrieve_progress` 는 GET + body |
| **프레임 경로** | 원본/비식별이 `{base}/frames/raw|deid/{rawSn}` 로 분기돼야 함. deid 경로 NULL 로 export 가 PARTIAL 되던 회귀 이력 있음 |
